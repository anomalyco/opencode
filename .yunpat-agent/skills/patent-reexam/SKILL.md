# 复审请求工作流

本 Skill 引导完成专利复审请求的分析与撰写，严格遵循审查指南第四部分第四章要求。

## 适用场景

收到驳回决定后，申请人可在驳回决定发文日起 **3 个月内**向专利复审委员会提出复审请求。

## 工作流步骤

### 步骤 1/4：驳回决定解析

调用 `reexam_response`（action: `parse`），传入驳回决定内容。

提取关键信息：
- 申请号、申请人、发明名称
- 驳回类型（全部/部分）
- 驳回理由列表（类型、涉及权利要求、引用对比文件）
- 审查员核心论点
- 可复审的法律依据
- 复审期限

**⚠️ 人机交互点**：确认解析结果完整准确。

### 步骤 2/4：复审可行性分析

调用 `reexam_response`（action: `analyze`），评估复审可行性。

分析维度：
- 驳回理由是否存在**事实认定错误**？
- 驳回理由是否存在**法律适用错误**？
- 是否有充分的**修改空间**克服驳回？

输出：
- 每个驳回理由的复审可行性（高/中/低）
- 最优复审策略（修改权利要求 / 争辩 / 修改+争辩）
- 预期成功率
- 风险提示

系统自动检索复审相关法规、先例和审查指南。

**⚠️ 人机交互点**：确认分析结论和策略方向。

### 步骤 3/4：复审请求书撰写

调用 `reexam_response`（action: `draft`），撰写复审请求书。

结构：
```
复审请求书

一、请求事项
  （请求撤销驳回决定，对修改后的权利要求重新审查）

二、事实与理由
  针对每个驳回理由逐一论述：
  1. 审查员观点
  2. 请求人的意见
  3. 法律依据和论据
  4. 修改说明

三、权利要求修改说明
  逐条说明修改内容、依据和效果

四、结论
```

要求：
- 法律依据引用准确（专利法、实施细则、审查指南）
- 论证逻辑严密
- 规范法律文书用语

**⚠️ 人机交互点**：逐条审阅修改。

### 步骤 4/4：权利要求修改

调用 `reexam_response`（action: `revise_claims`），生成复审版权利要求。

输出：
- 修改对照表（原文 vs 修改后 + 修改依据）
- 修改后的完整权利要求书
- 修改说明（每处修改的原始依据、如何克服驳回、保护范围变化）

**⚠️ 人机交互点**：所有修改必须经用户**逐条批准**。

**🔍 质量检查**：修改完成后调用 `patent_check`（action: `quality`, document_type: `reexamination`）验证质量。

## 输出规范

最终产出复审请求文件（Markdown 格式），包含：
- 复审请求书
- 权利要求修改对照表
- 修改后的完整权利要求书
- 质量评估报告

⚠️ 所有产出均为**草案**状态，需经专业审校后提交。

## 重要提醒

- **复审期限**：驳回决定发文日起 3 个月，逾期不可补正
- 修改不超范围（A33），必须基于原始申请文件
- 复审请求费：发明 400 元，实用新型 300 元
- 涉及未公开发明内容的操作需用户明确审批
