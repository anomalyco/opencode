# 专利申请文件撰写工作流

本 Skill 引导完成一份完整的专利申请文件撰写，严格遵循审查指南和专利法第 26 条要求。

## 工作流步骤

### 步骤 1/5：发明理解

调用 `patent_draft`（action: `understand`），传入技术交底书内容。

- 提取发明三元组：技术问题 → 技术方案 → 技术效果
- 识别必要技术特征和可选技术特征
- 确定发明类型（装置/方法/系统/组合物）

**⚠️ 人机交互点**：展示三元组摘要（<300字），等待用户确认理解是否准确。用户可修改后继续。

### 步骤 2/5：现有技术检索

调用 `patent_draft`（action: `search`），传入交底书内容。

- 自动提取检索关键词，在专利数据库中检索相关现有技术
- 展示检索结果表格（专利名称、申请号、申请日、相关度）
- 定位发明点与区别特征

**⚠️ 人机交互点**：确认检索充分性。用户可补充/排除对比文件。

### 步骤 3/5：说明书撰写

调用 `patent_draft`（action: `specification`），传入交底书和检索结果。

按以下结构撰写：
1. 技术领域（50-100字）
2. 背景技术（300-500字）
3. 发明内容（800-1500字）：技术问题 + 技术方案 + 有益效果
4. 具体实施方式（1500-3000字）：至少 2 个实施例
5. 附图说明（如有）

**⚠️ 人机交互点**：逐章节展示，用户逐章节确认/修改。

**🔍 质量检查点**：撰写完成后调用 `patent_check`（action: `quality`, document_type: `specification`），自动 7 维度评估。得分 <7.5 自动修复。

### 步骤 4/5：权利要求撰写

调用 `patent_draft`（action: `claims`），传入说明书和交底书。

撰写要求：
- 独立权利要求保护范围适中（不过宽不过窄）
- 从属权利要求 3-5 层分层布局
- 使用规范专利术语
- 符合 A26.4（说明书支持）

**⚠️ 人机交互点**：展示权利要求书，用户确认保护范围。权利要求范围的任何修改需用户明确批准。

**🔍 质量检查点**：调用 `patent_check`（action: `quality`, document_type: `claims`）。

### 步骤 5/5：摘要与整合

1. 调用 `patent_draft`（action: `abstract`）撰写摘要（300字左右）
2. 调用 `patent_draft`（action: `integrate`）将说明书+权利要求+摘要整合为完整文件

**🔍 最终质量检查**：调用 `patent_check`（action: `consistency`）检查权利要求与说明书的一致性。

## 输出规范

最终产出完整专利申请文件（Markdown 格式），包含：
- 发明名称
- 技术领域
- 背景技术
- 发明内容
- 附图说明
- 具体实施方式
- 权利要求书
- 摘要

⚠️ 所有产出均为**草案**状态，需经专业审校后提交。

## 重要提醒

- 不决定权利要求保护范围策略（用户决策）
- 不签署法律文件
- 不直接提交申请
- 涉及未公开发明内容的操作需用户明确审批
- 引用的法条必须准确标注条款号
