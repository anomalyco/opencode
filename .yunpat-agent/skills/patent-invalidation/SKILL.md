# 专利无效宣告工作流

本 Skill 引导完成专利无效宣告请求或答辩，严格遵循审查指南第四部分第三章和第五章要求。

## 适用场景

| 角色 | 说明 |
|------|------|
| 攻方（无效请求人） | 认为授权专利不符合授权条件，请求宣告无效 |
| 守方（专利权人） | 应对无效宣告请求，维护专利权有效 |

## 工作流步骤

### 步骤 1/4：目标专利权利要求解析

调用 `invalidation_response`（action: `parse`），传入目标专利的权利要求书。

提取信息：
- 独立权利要求数量和保护范围
- 前序部分和特征部分
- 必要技术特征和可选技术特征清单
- 从属权利要求分层结构
- 保护范围宽窄评估
- 潜在无效攻击点

**⚠️ 人机交互点**：确认解析结果。

### 步骤 2/4：无效理由分析

调用 `invalidation_response`（action: `analyze`），分析无效理由适用性。

评估以下无效理由（实施细则第 65 条）：

| 无效理由 | 法条 | 说明 |
|---------|------|------|
| 新颖性不足 | A22.2 | 单独对比 |
| 创造性不足 | A22.3 | 三步法 |
| 公开不充分 | A26.3 | 技术事实分析 |
| 权利要求不支持 | A26.4 | 说明书与权利要求对比 |
| 修改超范围 | A33 | 申请文件对比 |
| 不符合单一性 | A31 | 特定技术特征分析 |

系统自动检索相关法规、判决和复审无效先例。

**⚠️ 人机交互点**：确认策略方向。

### 步骤 3/4：撰写无效文件

根据角色选择：

#### 攻方：无效宣告请求书
调用 `invalidation_response`（action: `attack`），撰写：
```
无效宣告请求书

一、请求事项
二、无效宣告的理由和证据
  理由一：[类型]
    1. 法律依据
    2. 证据目录
    3. 逐权利要求对比分析
三、结论
```

#### 守方：无效答辩意见
调用 `invalidation_response`（action: `defend`），撰写：
```
意见陈述书（无效答辩）

一、答辩总览
二、逐条答辩
  针对每个无效理由：
    1. 请求人论点
    2. 专利权人意见
    3. 法律依据和论据
    4. 证据反驳
三、权利要求修改说明（如需）
四、结论
```

**⚠️ 人机交互点**：逐条审阅。如修改权利要求，需用户**逐条批准**。

### 步骤 4/4（可选）：证据检索

调用 `invalidation_response`（action: `evidence`），检索现有技术证据。

- 自动从权利要求中提取检索关键词
- 在专利数据库中检索相关现有技术
- 验证证据日期（必须在目标专利申请日之前）
- 标注证据用途（现有技术 ✅ / 申请日后 ⚠️）

**🔍 质量检查**：完成后调用 `patent_check`（action: `quality`, document_type: `invalidation`）验证。

## 输出规范

最终产出（Markdown 格式）：
- **攻方**：无效宣告请求书 + 证据清单
- **守方**：意见陈述书 + 权利要求修改对照表（如修改）

⚠️ 所有产出均为**草案**状态，需经专业审校后提交。

## 重要提醒

- 无效宣告请求期限：专利授权公告日起任何时间（无期限限制）
- 无效请求费：发明 3000 元，实用新型 1500 元
- 证据必须真实、合法、相关
- 攻方需在请求日起 1 个月内补充证据
- 修改权利要求不超范围（A33）
- 涉及未公开发明内容的操作需用户明确审批
