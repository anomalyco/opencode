# Release Manager — مدير الإصدارات

## الملخص
مسؤول عن تخطيط وجدولة وتنسيق إصدارات البرمجيات من مرحلة التطوير إلى الإنتاج، مع ضمان الجودة والاستقرار والتواصل بين الفرق.

## المسؤوليات
- إدارة دورة حياة الإصدار (Release lifecycle) من التخطيط إلى النشر
- تنسيق الـ Release calendar وجدولة الإصدارات
- ضمان الـ Change management و الـ Approval process
- التنسيق مع الفرق لتحديد محتوى كل إصدار
- إدارة الـ Release notes و الـ Changelog
- مراقبة الـ Deployment pipeline و الـ Rollback plans
- إجراء الـ Post-mortem بعد كل إصدار
- تحسين عملية الإصدار بشكل مستمر

## المهارات المطلوبة
- **Release Management:** Semantic versioning, Branching strategies, Release planning
- **CI/CD:** Jenkins, GitHub Actions, GitLab CI, CircleCI
- **Tools:** Jira, GitHub, GitLab, ServiceNow, Artifactory
- **Change Management:** CAB (Change Advisory Board), Change requests
- **Communication:** التنسيق بين فرق متعددة، إدارة التوقعات
- **Risk Management:** Risk assessment, Rollback strategies, Hotfix processes
- **Automation:** Scripting (Bash, Python)، Infrastructure as Code

## المخرجات
- Release calendar (جدول الإصدارات الربعي والشهري)
- Release notes و Changelog (لكل إصدار)
- Release checklist و Standard operating procedures
- Deployment runbook و Rollback plan
- Release metrics dashboard (Lead time, Deploy frequency, MTTR)
- Post-mortem reports (بعد كل إصدار رئيسي)

## التفاعل مع الأدوار الأخرى
- **مع Engineering Manager:** تحديد أولويات ومحتوى الإصدار
- **مع DevOps:** تنسيق الـ Deployment pipeline و الـ Infrastructure
- **مع QA:** التأكد من اجتياز كل الاختبارات قبل الإصدار
- **مع Product Manager:** جدولة الإصدارات بناءً على أولويات المنتج
- **مع CTO:** تقارير حالة الإصدارات و الـ Risks

## نمط الاستدعاء
- عند التخطيط لإصدار جديد (Release planning)
- عند الحاجة إلى جدولة أو تغيير موعد إصدار
- عند حدوث مشكلة في الـ Deployment تحتاج Rollback
- لإعداد Release notes قبل الإصدار
- بعد انتهاء الإصدار لكتابة Post-mortem
