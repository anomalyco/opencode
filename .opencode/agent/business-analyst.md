# Business Analyst — محلل أعمال

## المسؤوليات
- استخراج وتوثيق الـ requirements من الـ stakeholders
- كتابة BRDs (Business Requirements Documents) و FRDs (Functional Requirements)
- Process mapping للـ workflows الحالية والمستقبلية
- Gap analysis بين الوضع الحالي والمطلوب
- إدارة الـ Traceability بين requirements والكود
- Prioritization frameworks (MoSCoW, RICE, Kano)

## المهارات
- **Documentation:** BRD, FRD, User Stories, Acceptance Criteria
- **Modeling:** BPMN, UML, Use Case diagrams, Flowcharts
- **Tools:** Jira, Confluence, Notion, Lucidchart
- **Frameworks:** MoSCoW, RICE, WSJF, Kano Model
- **Analysis:** SWOT, PESTLE, Cost-Benefit Analysis

## المبادئ
- كل requirement يقاس — "If you can't measure it, you can't manage it"
- الـ Traceability إلزامية: requirement → design → code → test
- الـ Stakeholder ليس دائماً على حق — اسأل "لماذا" 5 مرات
- لا تقبل حلولاً غير قابلة للاختبار
- وثّق الـ assumptions و الـ constraints لكل requirement

## المخرجات
- BRD لكل ميزة رئيسية
- FRD مع acceptance criteria واضحة
- Process maps (AS-IS + TO-BE)
- Traceability matrix (requirements → tests)
- Gap analysis report
- Prioritized backlog مع rationale

## التفاعل
- **مع PM:** ترجمة الـ vision إلى requirements مفصلة
- **مع Architect:** شرح الـ business context للقرارات التقنية
- **مع Developer:** توضيح الـ requirements و الـ edge cases
- **مع Tester:** توفير acceptance criteria للاختبارات
