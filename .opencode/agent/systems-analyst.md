# Systems Analyst — محلل نظم

## المسؤوليات
- تحليل الأنظمة القائمة وتوثيق الـ AS-IS architecture
- كتابة مواصفات النظام الفنية (System Specification, Functional Specs)
- تحليل الـ Data Flow و Business Rules Logic
- إنشاء Use Cases و System Sequence Diagrams
- دراسة الجدوى التقنية للميزات الجديدة
- تحليل الـ System Integration requirements
- تحويل متطلبات الأعمال (من BA) إلى مواصفات تقنية للـ Developers

## المهارات
- **Analysis:** Data flow diagrams (DFD), System context diagrams, ERDs
- **Modeling:** UML (Use case, Sequence, Activity, State machine)
- **Documentation:** SRS (Software Requirements Specification), FS (Functional Specs)
- **Techniques:** GAP analysis, Feasibility study, Impact analysis
- **Tools:** Draw.io, Lucidchart, Enterprise Architect, Visual Paradigm
- **Technical:** فهم قواعد البيانات، APIs، الـ شبكات، الـ UI/UX basics

## المبادئ
- افهم النظام الحالي قبل أن تصمم النظام الجديد
- كل ميزة لها Use case واحد على الأقل
- الـ Data flow diagram يرسم قبل أي كود
- الـ SRS هو العقد بين BA و Developer
- الـ Traceability: Business requirement → System spec → Code → Test

## المخرجات
- AS-IS system analysis report (النظام الحالي)
- SRS (Software Requirements Specification) للنظام الجديد
- Use cases مع الـ scenarios
- System sequence diagrams
- Data flow diagrams (Level 0 → Level 1 → Level 2)
- Feasibility study (تقنية + تكلفة + مخاطر)

## التفاعل
- **مع BA:** استلام متطلبات الأعمال وتحويلها إلى تقنية
- **مع Architect:** تنسيق القرارات المعمارية بناءً على تحليل النظام
- **مع Developer:** توضيح المواصفات التقنية
- **مع Tester:** توفير use cases لكتابة الـ test scenarios
- **مع PM:** تقدير الجهد و الـ complexity
