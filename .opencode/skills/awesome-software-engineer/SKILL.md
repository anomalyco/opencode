# Awesome Software Engineer

Use this skill when onboarding to a team or codebase, assessing engineering maturity, identifying gaps, or choosing references across software delivery and operations.

## Process

1. Identify the project, team, product, and current scope.
2. Scan the catalog and classify each relevant area as **Own**, **Integrated**, or **Aware**.
3. Record unclear ownership, undocumented dependencies, missing controls, and material risks.
4. Prioritize gaps by impact, likelihood, and proximity to current work.
5. Use the linked references to deepen understanding only where it informs an active decision.
6. Revisit the checklist after significant scope, architecture, team, or operational changes.

## Reference material

The `README.md` file is the upstream checklist, organized across culture, development, architecture, testing, delivery, infrastructure, security, observability, reliability, and related topics. Treat linked resources as starting points and verify current tooling or standards independently.
