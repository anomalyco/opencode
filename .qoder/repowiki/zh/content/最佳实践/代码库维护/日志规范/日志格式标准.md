## 结构化日志字段定义

根据代码库中的日志实现，所有日志必须遵循统一的结构化格式，确保机器可解析性。日志包含以下核心字段：

- **时间戳**：ISO 8601格式的时间戳，精确到秒，用于标识日志事件发生的时间点
- **日志级别**：表示日志的严重程度，用于区分不同类型的日志信息
- **模块标识**：通过"service"字段标识日志来源的服务或模块，便于追踪日志来源
- **会话ID**：作为上下文标签注入，用于跨服务追踪用户会话
- **消息内容**：日志的主要描述信息，应简洁明了地描述事件
- **附加元数据**：通过"extra"字段携带的额外上下文信息，如用户ID、请求ID等

这些字段的设计确保了日志的标准化和可分析性，便于ELK等日志采集系统进行索引、搜索和可视化分析。

## 上下文注入与可追踪性

为了实现日志的可追踪性，系统通过上下文注入机制将关键标识信息嵌入到日志中。这种机制允许跨多个服务和组件追踪特定用户会话或业务流程。

### 上下文标签注入

日志系统支持通过`tag`方法将上下文信息注入到日志记录器中：

```typescript
const logger = Log.create({ service: "order-service" })
  .tag("sessionId", sessionId)
  .tag("userId", userId)
  .tag("orderId", orderId)
```

一旦标签被注入，所有后续的日志记录都会自动包含这些上下文信息，无需在每次日志调用时重复传递。

### 作用域内上下文管理

系统还提供了`provide`方法，用于在特定代码块的作用域内提供上下文：

```typescript
Log.provide(
  { sessionId, userId },
  () => {
    // 此代码块内的所有日志调用都会自动包含sessionId和userId
    processOrder()
  }
)
```

这种方法确保了在复杂业务流程中，即使跨越多个函数调用，上下文信息也能保持一致和完整。

### 可追踪性优势

通过上下文注入实现的可追踪性具有以下优势：
- **跨服务追踪**：使用会话ID可以在分布式系统中追踪用户请求的完整路径
- **问题诊断**：当出现问题时，可以通过用户ID或会话ID快速定位相关日志
- **性能分析**：通过请求ID追踪单个请求在系统中的处理时间和路径
- **安全审计**：记录用户操作的完整上下文，便于安全事件调查

## 日志级别规范

系统定义了标准化的日志级别，用于区分不同严重程度的事件。日志级别遵循从低到高的严重性顺序：

### DEBUG
用于开发和调试目的的详细信息，包含详细的系统状态和执行流程。在生产环境中通常不启用。

### INFO
记录系统正常运行的关键事件，如服务启动、配置加载、重要业务操作完成等。用于监控系统健康状况。

### WARN
表示潜在问题或非关键性错误，系统仍能正常运行，但可能需要关注。例如资源使用接近阈值、降级模式启用等。

### ERROR
记录导致功能失败的错误事件，需要立即关注和处理。包括异常抛出、服务调用失败、数据一致性问题等。

日志级别通过`Level`枚举类型定义，并在系统启动时可配置最低输出级别，高于或等于该级别的日志才会被记录。

## 日志输出实现机制

日志系统的实现机制确保了高性能和可靠性，同时支持灵活的配置和扩展。

### 日志初始化

系统通过`init`函数进行日志系统初始化，可以配置日志级别、输出目标等参数：

```typescript
await Log.init({
  level: "INFO",
  dev: process.env.NODE_ENV === "development",
  print: false
})
```

初始化过程还包括日志文件的创建和旧日志文件的清理，确保磁盘空间的有效利用。

### 性能优化

日志系统在实现中考虑了性能优化：
- **时间差计算**：每条日志记录包含与上一条日志的时间差，便于分析处理延迟
- **批量写入**：日志写入操作经过优化，减少I/O操作频率
- **内存缓存**：频繁使用的日志记录器实例被缓存，避免重复创建开销

### 错误处理

系统对日志记录过程中的潜在错误进行了妥善处理：
- **异常格式化**：错误对象会被递归格式化，包含完整的错误链信息
- **空值处理**：自动过滤undefined和null值，避免日志污染
- **异步安全**：日志写入操作设计为异步安全，不会阻塞主执行流程
