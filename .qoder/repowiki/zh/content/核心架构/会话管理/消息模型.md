## 简介
opencode消息模型是系统中用于表示对话交互的核心数据结构。该模型支持多种消息类型，包括用户输入、AI响应、工具调用、工具结果和系统事件。消息模型设计为可扩展且类型安全，使用Zod进行运行时类型验证，并通过版本化支持向后兼容。消息系统与总线（Bus）事件系统集成，实现组件间的松耦合通信。

## 消息数据结构
opencode消息模型采用分层设计，将消息分为核心信息（info）和内容部分（parts）。核心信息包含消息的基本元数据，而内容部分则包含实际的消息内容。

### 用户消息
用户消息由`User`类型定义，包含以下字段：
- `id`: 消息唯一标识符
- `sessionID`: 所属会话ID
- `role`: 角色，固定为"user"
- `time.created`: 消息创建时间戳

### AI响应消息
AI响应消息由`Assistant`类型定义，包含以下字段：
- `id`: 消息唯一标识符
- `sessionID`: 所属会话ID
- `role`: 角色，固定为"assistant"
- `time.created`: 消息创建时间戳
- `time.completed`: 消息完成时间戳（可选）
- `error`: 错误信息（可选）
- `system`: 系统提示数组
- `modelID`: 使用的模型ID
- `providerID`: 服务提供商ID
- `mode`: 模式
- `path`: 工作路径信息
- `summary`: 是否为摘要消息
- `cost`: 成本
- `tokens`: 令牌使用统计

### 消息内容部分
消息内容部分由`Part`联合类型定义，支持多种内容类型：

#### 文本部分
```typescript
TextPart = {
  type: "text"
  text: string
  synthetic?: boolean
  time?: {
    start: number
    end?: number
  }
  metadata?: Record<string, any>
}
```

#### 推理部分
```typescript
ReasoningPart = {
  type: "reasoning"
  text: string
  metadata?: Record<string, any>
  time: {
    start: number
    end?: number
  }
}
```

#### 工具部分
工具部分包含工具调用的完整状态机：
```typescript
ToolPart = {
  type: "tool"
  callID: string
  tool: string
  state: ToolState
  metadata?: Record<string, any>
}
```

其中`ToolState`是一个判别联合类型，包含四种状态：
- `pending`: 待处理状态
- `running`: 运行中状态
- `completed`: 已完成状态
- `error`: 错误状态

#### 文件部分
```typescript
FilePart = {
  type: "file"
  mime: string
  filename?: string
  url: string
  source?: FilePartSource
}
```

#### 其他部分类型
还包括`SnapshotPart`（快照部分）、`PatchPart`（补丁部分）、`AgentPart`（代理部分）、`StepStartPart`（步骤开始部分）和`StepFinishPart`（步骤结束部分）。

## 消息ID生成策略
消息ID的生成由`Identifier`模块负责，采用基于时间戳的单调递增ID生成算法，确保ID的全局唯一性和有序性。

### ID格式
ID采用`{prefix}_{timestamp}_{random}`的格式：
- `prefix`: 类型前缀，如"msg"表示消息
- `timestamp`: 6字节的时间戳和计数器组合
- `random`: 随机生成的字符

### 生成算法
ID生成算法确保在相同毫秒内生成的ID也是有序的：

```typescript
function create(prefix: keyof typeof prefixes, descending: boolean, timestamp?: number): string {
  const currentTimestamp = timestamp ?? Date.now()

  if (currentTimestamp !== lastTimestamp) {
    lastTimestamp = currentTimestamp
    counter = 0
  }
  counter++

  let now = BigInt(currentTimestamp) * BigInt(0x1000) + BigInt(counter)
  now = descending ? ~now : now

  const timeBytes = Buffer.alloc(6)
  for (let i = 0; i < 6; i++) {
    timeBytes[i] = Number((now >> BigInt(40 - 8 * i)) & BigInt(0xff))
  }

  return prefixes[prefix] + "_" + timeBytes.toString("hex") + randomBase62(LENGTH - 12)
}
```

### API接口
提供两个主要的ID生成函数：
- `ascending(prefix)`: 生成升序ID（时间上较早的ID较小）
- `descending(prefix)`: 生成降序ID（时间上较早的ID较大）

这种设计使得消息可以按ID进行自然排序，同时支持会话ID等需要降序排列的场景。

## 时间戳处理与消息排序
消息模型使用毫秒级时间戳进行时间管理，并通过ID和时间戳的组合实现可靠的消息排序。

### 时间戳字段
消息包含以下时间戳字段：
- `time.created`: 消息创建时间
- `time.completed`: 消息完成时间（仅AI响应）
- `time.start`: 内容部分开始时间
- `time.end`: 内容部分结束时间

### 消息排序机制
消息排序采用多级排序策略：

1. **按ID排序**: 由于ID包含时间戳信息，按ID字符串排序即可获得大致的时间顺序
2. **按时间戳排序**: 对于精确排序，使用`time.created`字段

在会话中获取消息列表时，系统会自动进行排序：

```typescript
export async function messages(sessionID: string) {
  const result = [] as MessageV2.WithParts[]
  // ... 读取消息
  result.sort((a, b) => (a.info.id > b.info.id ? 1 : -1))
  return result
}
```

对于内容部分的排序，同样使用ID进行排序：

```typescript
result.sort((a, b) => (a.id > b.id ? 1 : -1))
```

这种排序机制确保了即使在分布式环境中，消息也能保持一致的顺序。

## 消息元数据设计
消息元数据设计为可扩展的结构，支持多种上下文信息的存储。

### 核心元数据字段
消息的核心元数据包含在`Info`类型中，主要包括：
- **来源标识**: `sessionID`字段标识消息所属的会话
- **优先级**: 通过消息处理状态隐式表示优先级
- **状态**: 通过`error`字段和工具状态表示消息处理状态
- **扩展属性**: 通过`metadata`字段支持任意扩展属性

ToolStateRunning = {

系统设计了灵活的扩展属性机制：
- `metadata`字段允许在各个层级添加自定义元数据
- `providerMetadata`字段用于存储服务提供商特定的元数据
- `system`字段用于存储系统提示信息

这种设计使得消息模型既能满足核心功能需求，又能支持未来功能的扩展。

## 消息处理流程与渲染
消息系统通过事件驱动架构实现消息的处理和渲染。

### 消息处理流程
消息处理遵循以下流程：

1. **创建消息**: 通过`Identifier.create()`生成ID，构造消息对象
2. **存储消息**: 使用`Storage.write()`将消息持久化
3. **发布事件**: 通过`Bus.publish()`发布消息更新事件
4. **处理事件**: 订阅者接收事件并更新UI状态

```typescript
export async function updateMessage(msg: MessageV2.Info) {
  await Storage.write(["message", msg.sessionID, msg.id], msg)
  Bus.publish(MessageV2.Event.Updated, {
    info: msg,
  })
  return msg
}
```

### 消息渲染
消息渲染由前端组件负责，主要特点包括：
- **增量渲染**: 支持流式渲染，AI响应可以逐步显示
- **缓存机制**: 使用`PartCache`缓存已渲染的消息，提高性能
- **状态指示**: 显示工具调用状态、思考块等视觉反馈

### 事件系统
消息系统定义了以下事件：
- `message.updated`: 消息更新事件
- `message.removed`: 消息删除事件
- `message.part.updated`: 消息部分更新事件
- `message.part.removed`: 消息部分删除事件

这些事件使得系统各组件可以响应消息变化，实现松耦合的架构。

## 消息序列化与反序列化
消息系统提供了完整的序列化和反序列化支持，确保跨平台和跨版本的兼容性。

### 序列化
消息通过JSON进行序列化，所有字段都经过类型验证：
- 使用Zod模式进行运行时类型检查
- 复杂类型（如联合类型）通过判别字段正确序列化
- 时间戳统一使用毫秒级数字

### 反序列化
反序列化过程包括：
1. 从存储读取JSON数据
2. 使用Zod模式验证数据完整性
3. 构造类型安全的消息对象

```typescript
const read = await Storage.read<MessageV2.Info>(["message", sessionID, messageID])
```

### 版本兼容性
系统通过`fromV1()`函数支持从旧版本消息格式的迁移：

```typescript
export function fromV1(v1: Message.Info) {
  // 转换逻辑
}
```

这种设计确保了系统升级时的消息兼容性，避免了数据迁移的复杂性。

### 跨平台兼容性
消息格式设计考虑了跨平台需求：
- 使用标准JSON格式
- 时间戳使用UTC毫秒数
- 字符串使用UTF-8编码
- 数字使用标准浮点数

## 实际使用示例
以下是消息模型的实际使用示例。

### 创建用户消息
```typescript
const userMessage: MessageV2.User = {
  id: Identifier.ascending("msg"),
  sessionID: "ses_123",
  role: "user",
  time: {
    created: Date.now(),
  },
}
```

### 创建AI响应消息
```typescript
const assistantMessage: MessageV2.Assistant = {
  id: Identifier.ascending("msg"),
  sessionID: "ses_123",
  role: "assistant",
  time: {
    created: Date.now(),
  },
  system: ["system prompt"],
  modelID: "model-123",
  providerID: "provider-123",
  mode: "build",
  path: {
    cwd: "/project",
    root: "/project",
  },
  cost: 0.1,
  tokens: {
    input: 100,
    output: 200,
    reasoning: 50,
    cache: {
      read: 10,
      write: 5,
    },
  },
}
```

### 添加文本内容部分
```typescript
const textPart: MessageV2.TextPart = {
  id: Identifier.ascending("prt"),
  messageID: assistantMessage.id,
  sessionID: assistantMessage.sessionID,
  type: "text",
  text: "Hello, world!",
}
```

### 添加工具调用
```typescript
const toolPart: MessageV2.ToolPart = {
  id: Identifier.ascending("prt"),
  messageID: assistantMessage.id,
  sessionID: assistantMessage.sessionID,
  type: "tool",
  callID: "call_123",
  tool: "read",
  state: {
    status: "running",
    input: { files: ["README.md"] },
    time: {
      start: Date.now(),
    },
  },
}
```

### 更新消息状态
```typescript
// 更新工具状态为已完成
toolPart.state = {
  status: "completed",
  input: { files: ["README.md"] },
  output: "File content...",
  title: "Read README",
  time: {
    start: toolPart.state.time.start,
    end: Date.now(),
  },
}

await updatePart(toolPart)
```

### 查询会话中的所有消息
```typescript
const messages = await Session.messages("ses_123")
messages.forEach(msg => {
  console.log(`Message ${msg.info.id}:`, msg.info.role)
  msg.parts.forEach(part => {
    console.log(`  Part ${part.type}:`, part)
  })
})
```
