## 简介
`IntelligentFileRestorer` 类中的 `calculateImportanceScore` 函数是智能文件恢复系统的核心算法，用于评估文件在上下文压缩后恢复的重要性。该算法综合考虑了五个关键维度：时间因素、操作频率、操作类型、文件类型和项目关联度，通过加权求和的方式计算出一个0-100分的综合评分，以确定文件恢复的优先级。

## 核心评分算法
`calculateImportanceScore` 函数是整个评分系统的核心，它调用五个子评分函数，根据预设的权重对各维度评分进行加权求和，最终得出文件的综合重要性评分。

该函数的实现逻辑如下：
1. 初始化总评分 `totalScore` 为0
2. 依次调用五个子评分函数获取各维度评分
3. 将各维度评分乘以其对应的权重并累加到总评分
4. 对最终评分进行四舍五入并限制在0-100分范围内

各维度的权重配置如下：
- 时间因素：35%
- 操作频率：25%
- 操作类型：20%
- 文件类型：15%
- 项目关联度：5%

## 子评分函数详解

### 时间因素评分
`calculateTemporalScore` 函数评估文件的时效性，基于文件的最后访问时间计算评分。该函数采用时间衰减模型，越近期访问的文件得分越高。

评分策略：
- 1小时内访问：100分（满分）
- 6小时内访问：90分
- 24小时内访问：75分
- 超过24小时：采用指数衰减公式 `75 * e^(-0.1 * (hours - 24))`，最低不低于10分

这种设计确保了最近活跃的文件能够获得更高的恢复优先级。

### 操作频率评分
`calculateFrequencyScore` 函数评估文件的操作频繁程度，综合考虑总操作次数和近期操作频率。

评分策略：
- 基于总操作次数（读、写、编辑）的评分，每操作一次加5分，最高80分
- 基于最近一小时内操作次数的加成，每次加10分，最高20分加成
- 总分不超过100分

这种设计既考虑了文件的长期使用频率，也强调了近期活跃度的重要性。

### 操作类型评分
`calculateOperationScore` 函数评估文件的操作类型，不同操作类型具有不同的权重。

评分策略：
- 写操作：每次15分（权重最高）
- 编辑操作：每次10分
- 读操作：每次3分（权重最低）
- 如果最后一次操作是写操作，额外加25分
- 如果最后一次操作是编辑操作，额外加15分

这种设计反映了写操作通常比读操作更重要，且最近的写操作表明文件正处于活跃修改状态。

### 文件类型评分
`calculateFileTypeScore` 函数根据文件扩展名评估其重要性，将文件分为代码文件、配置文件和文档文件三类。

评分策略：
- **代码文件**：最高优先级
  - `.js`, `.ts`: 100分
  - `.py`: 90分
  - `.java`, `.cpp`, `.c`: 85分
- **配置文件**：中等优先级
  - `.json`: 70分
  - `.yaml`, `.yml`: 65分
  - `.xml`: 55分
- **文档文件**：较低优先级
  - `.md`: 40分
  - `.txt`: 30分
  - `.pdf`: 20分
- 未知类型：默认30分

这种分类确保了源代码等关键开发文件能够获得更高的恢复优先级。

### 项目关联度评分
`calculateProjectRelevanceScore` 函数评估文件与当前项目的关联程度。

评分策略：
- 基础分：50分
- 在 `/src/` 或 `\\src\\` 目录中：+30分
- 在 `/components/` 或 `/modules/` 目录中：+20分
- 在 `/test/` 或 `/spec/` 目录中：+10分
- 关键文件（如 `package.json`, `go.mod`, `Dockerfile`, `README.md` 等）：+25分

这种设计确保了项目核心目录和关键配置文件能够获得更高的评分。

## 评分归一化与加权求和
所有子评分函数返回的评分均为0-100分的标准化分数，确保了不同维度评分的可比性。核心评分函数通过加权求和的方式将各维度评分整合为综合评分：

```
综合评分 = Σ(各维度评分 × 权重)
```

最终评分经过 `Math.min(100, totalScore)` 限制，确保不会超过100分，并通过 `Math.round()` 进行四舍五入。

权重配置存储在 `scoringWeights` 对象中，可以在构造函数中进行配置，提供了良好的可扩展性。

## 计算示例
假设有一个文件 `src/components/Button.tsx`，其元数据如下：
- 最后访问时间：30分钟前
- 操作次数：读5次，写3次，编辑2次
- 最后操作：写操作
- 路径：`/src/components/Button.tsx`
- 文件名：`Button.tsx`

各维度评分计算：
1. **时间因素评分**：100分（30分钟内）
2. **操作频率评分**：`min(80, 10*5) + min(20, 10*10) = 50 + 20 = 70分`
3. **操作类型评分**：`3*15 + 2*10 + 5*3 + 25 = 45 + 20 + 15 + 25 = 100分`
4. **文件类型评分**：100分（`.tsx`文件）
5. **项目关联度评分**：`50 + 30 + 20 = 100分`

综合评分计算：
```
100×0.35 + 70×0.25 + 100×0.20 + 100×0.15 + 100×0.05 = 
35 + 17.5 + 20 + 15 + 5 = 92.5 ≈ 93分
```

该文件将获得93分的高分，极有可能被选中恢复。

## 权重配置与可扩展性
评分权重通过 `scoringWeights` 配置对象进行管理，该对象在 `IntelligentFileRestorer` 构造函数中初始化，允许在实例化时进行自定义配置。

```javascript
this.scoringWeights = {
  temporal: 0.35,      // 时间因素权重 35%
  frequency: 0.25,     // 频率因素权重 25%
  operation: 0.20,     // 操作类型权重 20%
  fileType: 0.15,      // 文件类型权重 15%
  project: 0.05        // 项目关联度权重 5%
};
```

这种设计具有良好的可扩展性：
1. 可以通过构造函数参数调整权重，适应不同场景的需求
2. 可以添加新的评分维度，只需扩展 `scoringWeights` 对象并实现相应的子评分函数
3. 权重配置支持序列化和反序列化，便于持久化和状态恢复

权重配置直接影响文件选择结果，增加某个维度的权重会使该维度更重要的文件获得更高的综合评分，从而更可能被选中恢复。
