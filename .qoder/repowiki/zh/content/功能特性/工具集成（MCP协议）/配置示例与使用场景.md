## MCP协议配置概述

MCP（Model Context Protocol）协议是系统集成外部工具和服务的核心机制。通过在`opencode.json`配置文件中定义MCP服务器，可以实现与代码分析工具、版本控制系统和CI/CD流水线的无缝集成。系统支持两种类型的MCP服务器连接：本地和远程。

MCP服务器配置位于`opencode.json`文件的`mcp`字段下，采用区分联合（discriminated union）模式，根据`type`字段的值来区分本地和远程服务器配置。这种设计提供了灵活的配置选项，包括服务器URL、传输协议选择、认证凭据、超时设置等。

## 本地MCP服务器配置

本地MCP服务器通过执行本地命令来启动。配置需要指定要运行的命令及其参数，以及可选的环境变量。当系统启动时，会自动执行指定的命令来启动MCP服务器。

```json
{
  "mcp": {
    "my-local-mcp-server": {
      "type": "local",
      "command": ["bun", "x", "my-mcp-command"],
      "enabled": true,
      "environment": {
        "MY_ENV_VAR": "my_env_var_value"
      }
    }
  }
}
```

在上述配置中：
- `type`字段设置为`"local"`，表示这是一个本地MCP服务器
- `command`字段是一个字符串数组，包含要执行的命令和其参数
- `enabled`字段控制服务器是否在启动时自动启用
- `environment`字段允许设置运行命令时的环境变量

本地MCP服务器的启动过程由系统自动管理。系统会使用`StdioClientTransport`创建与本地进程的通信通道，并通过标准输入/输出进行数据交换。如果服务器启动失败，系统会记录错误日志并发布错误事件。

## 远程MCP服务器配置

远程MCP服务器通过HTTP连接进行通信。配置需要指定服务器的URL，以及可选的请求头信息用于认证。系统支持多种传输协议，包括StreamableHTTP和SSE（Server-Sent Events），并会自动尝试所有可用的协议以建立连接。

```json
{
  "mcp": {
    "my-remote-mcp-server": {
      "type": "remote",
      "url": "https://my-mcp-server.com",
      "enabled": true,
      "headers": {
        "Authorization": "Bearer MY_API_KEY"
      }
    }
  }
}
```

在上述配置中：
- `type`字段设置为`"remote"`，表示这是一个远程MCP服务器
- `url`字段指定远程服务器的完整URL
- `enabled`字段控制服务器是否在启动时自动启用
- `headers`字段允许设置发送到服务器的HTTP请求头，常用于认证

系统会尝试使用多种传输协议连接到远程服务器，优先尝试`StreamableHTTP`，如果失败则尝试`SSE`。这种多协议支持提高了连接的可靠性。如果所有协议都连接失败，系统会记录错误日志并发布错误事件。

## 完整JSON Schema示例

以下是一个完整的MCP服务器配置示例，涵盖了所有可用的配置选项：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "code-analysis-server": {
      "type": "local",
      "command": ["bun", "run", "code-analysis-server.js"],
      "enabled": true,
      "environment": {
        "NODE_ENV": "production",
        "ANALYSIS_TIMEOUT": "30000"
      }
    },
    "version-control-server": {
      "type": "remote",
      "url": "https://vc-server.example.com/api/mcp",
      "enabled": true,
      "headers": {
        "Authorization": "Bearer YOUR_ACCESS_TOKEN",
        "Content-Type": "application/json"
      }
    },
    "ci-cd-integration": {
      "type": "remote",
      "url": "https://ci-cd.example.com/mcp",
      "enabled": false,
      "headers": {
        "X-API-Key": "YOUR_API_KEY",
        "User-Agent": "OpenCode-Agent/1.0"
      }
    }
  }
}
```

此配置示例展示了三个MCP服务器：
1. `code-analysis-server`：本地代码分析服务器，使用Bun运行JavaScript文件
2. `version-control-server`：远程版本控制服务器，使用Bearer Token进行认证
3. `ci-cd-integration`：远程CI/CD集成服务器，当前被禁用

## 典型使用场景

### 集成代码分析工具

通过配置本地MCP服务器，可以集成各种代码分析工具，如静态代码分析器、代码格式化工具和代码质量检查工具。例如：

```json
{
  "mcp": {
    "eslint-analyzer": {
      "type": "local",
      "command": ["npx", "eslint", "--format", "json"],
      "environment": {
        "ESLINT_CONFIG": "./.eslintrc.json"
      }
    }
  }
}
```

### 集成版本控制系统

通过配置远程MCP服务器，可以与Git服务器、GitHub、GitLab等版本控制系统集成，实现代码提交、分支管理和代码审查等功能。

```json
{
  "mcp": {
    "github-integration": {
      "type": "remote",
      "url": "https://api.github.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_GITHUB_TOKEN",
        "Accept": "application/vnd.github.v3+json"
      }
    }
  }
}
```

### 集成CI/CD流水线

通过配置远程MCP服务器，可以与Jenkins、GitLab CI、CircleCI等CI/CD系统集成，实现自动化构建、测试和部署。

```json
{
  "mcp": {
    "jenkins-integration": {
      "type": "remote",
      "url": "https://jenkins.example.com/mcp",
      "headers": {
        "Authorization": "Basic YOUR_BASE64_ENCODED_CREDENTIALS"
      }
    }
  }
}
```

## 操作指南

### 添加新的MCP服务器

系统提供了命令行工具来简化MCP服务器的添加过程。使用`opencode mcp add`命令可以交互式地添加新的MCP服务器：

```bash
opencode mcp add
```

该命令会引导用户完成以下步骤：
1. 输入MCP服务器名称
2. 选择服务器类型（本地或远程）
3. 根据选择的类型，输入相应的配置信息（命令或URL）
4. 对于远程服务器，验证URL的有效性并测试连接

### 验证连接状态

系统在启动时会自动尝试连接所有启用的MCP服务器。连接状态可以通过以下方式验证：
- 查看系统日志中的连接信息
- 使用`opencode status`命令查看MCP服务器状态
- 在运行时通过API查询MCP客户端状态

### 调试配置问题

当MCP服务器连接出现问题时，可以采取以下步骤进行调试：
1. 检查配置文件语法是否正确
2. 验证命令或URL是否有效
3. 检查网络连接是否正常
4. 查看系统日志获取详细的错误信息
5. 使用`opencode debug mcp`命令进行专门的MCP调试

## 常见错误诊断与修复

### 网络连接失败

**症状**：远程MCP服务器连接超时或拒绝连接
**诊断方法**：
- 使用`ping`或`curl`测试服务器可达性
- 检查防火墙设置
- 验证URL是否正确

**修复建议**：
- 确认服务器正在运行并监听正确的端口
- 检查网络路由和防火墙规则
- 尝试使用不同的网络环境

### 认证错误

**症状**：服务器返回401或403错误
**诊断方法**：
- 检查请求头中的认证信息
- 验证令牌或密钥的有效期
- 检查权限设置

**修复建议**：
- 更新过期的认证令牌
- 确认认证头的格式正确
- 检查服务器端的权限配置

### 协议不匹配

**症状**：连接建立后立即断开或无法交换数据
**诊断方法**：
- 检查服务器支持的MCP协议版本
- 验证传输协议兼容性
- 查看详细的握手过程日志

**修复建议**：
- 确认客户端和服务器使用兼容的MCP协议版本
- 尝试不同的传输协议（StreamableHTTP或SSE）
- 更新客户端或服务器到最新版本
