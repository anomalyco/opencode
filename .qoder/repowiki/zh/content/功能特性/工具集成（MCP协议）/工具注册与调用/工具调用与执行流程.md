## 引言

本文档全面解析MCP工具的调用执行流程，从用户发起请求到结果返回的全过程。系统通过统一的工具框架支持多种工具类型和集成方式，包括内置工具、自定义工具和MCP协议工具。文档详细说明了统一调用接口的设计理念，如何抽象本地工具与远程MCP工具的差异，以及参数序列化、上下文注入、异步执行、结果反序列化等关键步骤。同时，文档强调了执行过程中的错误传播机制、超时控制和资源清理策略，确保系统稳定性。

## 异步执行与并发控制

### 并发控制策略

系统通过`maxConcurrent`参数限制最大并发执行数，防止系统资源耗尽。当并发数达到上限时，新请求会被放入队列等待，直到有执行槽位空闲。

```mermaid
flowchart TD
A([新请求]) --> B{并发数 < 上限?}
B --> |是| C[直接执行]
B --> |否| D[加入等待队列]
C --> E[执行完成]
D --> F{队列非空且并发数 < 上限?}
F --> |是| G[从队列取出请求]
F --> |否| H[等待]
G --> I[执行请求]
I --> J[通知Promise]
J --> K[从队列移除]
K --> F
E --> L[释放槽位]
L --> F
```

### 异步执行模式

系统采用Promise-based异步执行模式，确保非阻塞的执行流程。每个工具执行请求返回一个Promise，调用方可以使用async/await语法或then/catch方法处理结果。

```mermaid
sequenceDiagram

Engine->>Engine : processQueue()

Engine->>Queue : resolve(结果)
Queue-->>Caller : Promise resolve(结果)
end
```

### 异步调用模式

异步调用模式适用于复杂、耗时的工具操作。调用方立即获得Promise，可以在等待结果的同时执行其他任务，提高系统响应性。

```mermaid
sequenceDiagram
participant Caller as 调用方
participant Engine as 执行引擎
Caller->>Engine : execute(request)
Engine-->>Caller : 返回Promise
Engine->>Engine : 执行工具
Engine-->>Caller : Promise resolve(结果)
```

### 适用场景对比

| 特性 | 同步调用 | 异步调用 |
|------|----------|----------|
| 阻塞性 | 是 | 否 |
| 响应性 | 低 | 高 |
| 复杂度 | 低 | 高 |
| 适用场景 | 简单快速操作 | 复杂耗时操作 |
| 错误处理 | 直接抛出 | Promise catch |
| 资源利用 | 低效 | 高效 |
