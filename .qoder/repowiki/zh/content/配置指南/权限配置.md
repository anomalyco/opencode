## 权限控制系统概述

OpenCode的权限控制系统是一个多层安全验证机制，旨在确保AI agent在执行操作时遵循严格的安全策略。系统通过六层验证流程，从输入验证到输出过滤，全面保护系统安全。

```mermaid
graph TD
A[UI输入验证] --> B[消息路由验证]
B --> C[工具调用验证]
C --> D[参数内容验证]
D --> E[系统资源访问控制]
E --> F[输出内容过滤]
```

## 权限配置结构

权限配置主要通过配置文件中的`permission`字段定义，支持全局配置和特定agent的权限设置。配置结构采用JSON格式，定义了不同操作类型的权限策略。

```json
{
  "permission": {
    "edit": "ask",
    "bash": {
      "*": "allow",
      "rm -rf": "ask",
      "sudo": "deny"
    },
    "webfetch": "allow"
  }
}
```

## 权限级别与类型

系统定义了三种核心权限级别：允许(allow)、询问(ask)和拒绝(deny)。这些级别应用于不同的操作类型，如文件编辑、命令执行和网络访问。

```mermaid
classDiagram
class PermissionLevel {
+ALLOW : string
+ASK : string
+DENY : string
}
class OperationType {
+READ : string
+WRITE : string
+EXECUTE : string
+NETWORK : string
}
PermissionLevel <|-- OperationType : "applies to"
```

## 权限校验执行流程

权限校验采用六层验证机制，每层都有特定的验证职责。当任何一层验证失败时，操作将被阻止并记录安全违规。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Security as "安全系统"
participant Permission as "权限检查器"
Client->>Security : 发起操作请求
Security->>Security : UI输入验证
Security->>Security : 消息路由验证
Security->>Permission : 工具调用验证
Permission-->>Security : 返回权限结果
Security->>Security : 参数内容验证
Security->>Security : 系统资源访问控制
Security->>Security : 输出内容过滤
Security-->>Client : 返回最终结果
```

## 安全配置最佳实践

实施最小权限原则是确保系统安全的关键。建议为不同类型的agent配置适当的权限级别，避免过度授权。

```mermaid
flowchart TD
A[确定操作需求] --> B{是否需要此权限?}
B --> |是| C[配置最低必要权限]
B --> |否| D[拒绝权限]
C --> E[定期审查权限配置]
D --> E
E --> F[更新权限策略]
```
