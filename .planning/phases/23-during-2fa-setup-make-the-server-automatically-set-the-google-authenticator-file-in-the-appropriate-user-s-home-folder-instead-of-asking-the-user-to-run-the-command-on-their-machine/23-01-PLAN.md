  <name>Task 1: Add broker IPC support for OTP setup file creation</name>
  <files>packages/opencode-broker/src/auth/otp.rs, packages/opencode-broker/src/ipc/protocol.rs, packages/opencode-broker/src/ipc/handler.rs</files>
  <action>
Implement a privileged write path for `~/.google_authenticator` using the broker:
- Add a new IPC method (e.g., `setupotp`) with params including `session_id` and `secret` (avoid passing raw home/uid/gid from the server; resolve via `UserSessionStore`).
- In `otp.rs`, add a `write_google_authenticator(home, uid, gid, secret)` helper that:
  - Uses the same file content format as `getGoogleAuthenticatorSetupCommand()` (TOTP_AUTH, RATE_LIMIT 3 30, WINDOW_SIZE 3, DISALLOW_REUSE) with no backup codes.
  - Refuses to overwrite existing `.google_authenticator` and returns a typed error/result (e.g., already_configured).
  - Writes atomically (temp file + rename), sets mode 0400, and chowns to the target user.
  - Returns structured error codes for permission denied, invalid home, and write failure.
- In `handler.rs`, map `setupotp` to the write helper and return explicit `error_code` values in the response data.
- Update protocol response types to include `error_code` and `already_configured`/`written` flags for the setup flow.
- Add unit tests for file creation behavior using a temp dir; allow EPERM to skip chown-sensitive assertions without failing.
Avoid new dependencies; reuse existing nix/libc utilities already used for PTY ownership.
  </action>
  <verify>Run `cargo test` in `packages/opencode-broker`.</verify>
  <done>The broker can create `.google_authenticator` with correct ownership and returns structured status codes without overwriting existing files.</done>
</task>
