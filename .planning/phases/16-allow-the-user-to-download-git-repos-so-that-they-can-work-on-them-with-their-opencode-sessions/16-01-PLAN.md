Add a configurable workspace root and repo/clone API support to the opencode server:

1. **Config: workspace root**
   - Extend `Config.Info` with a `workspace` block (e.g., `{ root?: string }`).
   - Default to a stable location under the user's home (e.g., `~/opencode` or `Global.Path.home` + "/opencode") if unset.
   - Ensure config is returned via `GET /config` so the UI can display the root path.

2. **Repo module**
   - Create `packages/opencode/src/repo/repo.ts` with a `Repo` namespace:
     - Zod schema for repo metadata (id, path, name, created/updated timestamps).
     - Storage helpers using `Storage` (similar to `Project` patterns).
     - Helper to extract repo name from clone URL (mirror Ralphcity behavior).
     - Clone helper that runs `git clone --recurse-submodules` and supports optional branch selection.
     - Dirty check helper (`git status --porcelain`) used before branch switch.
   - Add audit logging via `Log.create({ service: "repo" })` for clone/download actions:
     - Include username/uid if available from auth context, repo URL, destination path, and timestamp.
     - Log both start and completion/failure.

3. **Repo routes**
   - Add `packages/opencode/src/server/routes/repo.ts` using Hono:
     - `GET /repo` -> list repos.
     - `POST /repo` -> add existing local repo path (validate is git repo).
     - `POST /repo/clone` or `GET /repo/clone-progress` (SSE) -> clone with progress events (mirror Ralphcity `clone-progress` semantics with `progress`, `complete`, `clone_error` events).
     - `GET /repo/:id/branches` -> list branches for repo.
     - `POST /repo/:id/checkout` -> switch branch with dirty warning support (return a structured error if uncommitted changes exist).
   - Register the new routes in `packages/opencode/src/server/server.ts` (e.g., `.route("/repo", RepoRoutes())`).

4. **Behavior requirements**
   - Clone includes full `.git` directory and submodules.
   - Clone destination is under the workspace root.
   - Branch selection supported pre-clone (optional `branch` param) and post-clone (checkout endpoint).
   - Dirty working tree warning is returned as a structured error that the UI can render.
     </action>
     <verify>
5. `GET /repo` returns a JSON array and succeeds for authenticated users.
6. `POST /repo/clone` streams progress events and completes with `complete` event on success.
7. `POST /repo/:id/checkout` returns a warning/blocked response when repo is dirty.
8. `GET /config` includes `workspace.root` when set.
   </verify>
