**UX-04 — Replace setTimeout 800ms onboarding race in app.tsx (lines ~129-138):**

Current code:
```tsx
onMount(() => {
  if (wasOnboardingShown()) return
  // Give sync a moment to populate connected providers
  setTimeout(() => {
    const connected = globalSync.data.provider.connected
    if (connected.length === 0) {
      dialog.show(() => <DialogOnboarding />)
    }
  }, 800)
})
```

Replace with a reactive `createEffect` that watches `globalSync.data.provider` and triggers once when the provider list is first populated (not empty array from initial state, but the actual server response):

```tsx
onMount(() => {
  if (wasOnboardingShown()) return

  // Use a one-shot effect that fires when provider data is first loaded
  const dispose = createRoot((dispose) => {
    createEffect(() => {
      const providers = globalSync.data.provider
      // Wait until sync has actually loaded provider data
      // Check if the provider object has been populated (not just initial empty state)
      if (!providers) return
      const connected = providers.connected
      if (connected.length === 0) {
        dialog.show(() => <DialogOnboarding />)
      }
      // Dispose after first meaningful check
      dispose()
    })
    return dispose
  })
})
```

Alternative simpler approach — use `createEffect` with `on()` to watch the connected array reactively and fire once:

```tsx
onMount(() => {
  if (wasOnboardingShown()) return

  let checked = false
  createEffect(() => {
    const connected = globalSync.data.provider.connected
    if (checked) return
    // Skip the initial empty array before sync loads
    // provider.connected starts as [] and stays [] if no provider, or becomes [...] if connected
    // We need to know when sync has finished its initial load
    // Check if sync.ready or similar signal exists
    checked = true
    if (connected.length === 0) {
      dialog.show(() => <DialogOnboarding />)
    }
  })
})
```

IMPORTANT: Read app.tsx fully to understand what signals are available from `globalSync` — there may be a `ready` or `initialized` signal that indicates the sync state has been populated from the server. If such a signal exists, use it as the gate instead of the timeout. The key requirement is: do NOT show the onboarding dialog before the provider list has actually been fetched from the server.

Look for patterns like `globalSync.ready`, `globalSync.data.initialized`, or similar in the sync context. If none exists, use a `createEffect` that watches `globalSync.data.provider.connected` and fires on the first change from the initial value.
