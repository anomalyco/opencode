# Plan 02: Config.Info Schema Extension + Directory Injection

## Objective

Extend `Config.Info` with a `workflow` key and wire workflow paths into `Config.directories()` so the existing `loadCommand()` / `loadAgent()` machinery auto-scans workflow plugin directories. This is the integration point that makes installed workflow commands appear in the TUI slash-command list.

## Tasks

<task id="T1">
<title>Add workflow.paths to Config.Info schema and inject into directories</title>
<read_first>
- packages/opencode/src/config/config.ts — read lines 1-200 to locate Config.Info schema definition and Config.state directories assembly. Use offset/limit when reading to avoid token overflow.
</read_first>
<action>
In `packages/opencode/src/config/config.ts`, make two targeted edits:

**Edit 1: Add `workflow` field to `Config.Info` Zod schema**

Locate the `export const Info = z.object({` definition (search for `skills:` or `plugin:` fields as landmarks). Add the `workflow` field alongside existing optional config keys:

```typescript
workflow: z.object({
  paths: z.array(z.string()).optional().describe("Installed workflow plugin directories"),
}).optional(),
```

Place it after the `skills` field if one exists, or near other extension points. The field must be added inside the `z.object({...})` block of `Config.Info` — not outside it.

**Edit 2: Inject workflow paths into directories inside Config.state**

Find the section in `Config.state` where `directories` is assembled (research confirms it uses `ConfigPaths.directories()` then iterates). After the existing directory list is built and before the `for (const dir of unique(directories))` loop that calls `loadCommand()`, insert:

```typescript
// Inject installed workflow plugin paths into directory scan
for (const item of cfg.workflow?.paths ?? []) {
  const expanded = item.startsWith("~/")
    ? path.join(os.homedir(), item.slice(2))
    : item
  directories.push(expanded)
}
```

This mirrors the `skills.paths` pattern (research pattern 1). `os` is already imported at the top of the file (`import os from "os"` — verify; add if missing).

**Important constraints:**
- Do NOT change any other fields in `Config.Info`
- Do NOT modify the `mergeConfigConcatArrays` function unless `workflow.paths` needs array merge (it does — add it alongside `plugin` and `instructions` handling)
- Config uses `.strict()` in some validators — verify the Info schema mode. If it's `z.object(...).strict()`, the new field is safe inside the object. If it's `.passthrough()`, also fine. Do not change the strictness mode.
- After editing, run `bun tsc --noEmit` from `packages/opencode/` to verify no type errors
</action>
