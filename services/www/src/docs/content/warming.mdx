---
title: "Warming"
---

Session warming keeps a session's prompt cache alive while you pause between
prompts. Just before the provider's cache entry expires, OpenCode resends the
session's last model request with a one-token output limit, so the provider
reads the cached prompt again and restarts its lifetime. Warming is disabled by
default.

Enable warming in any [OpenCode configuration file](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}
```

With this configuration, OpenCode refreshes a session's cache at 90% of its
lifetime: every 4.5 minutes for a five-minute cache. It keeps doing so for up to
30 minutes after the latest model request while a turn runs, and for up to 15
minutes after the turn ends.

## Which models are warmed

Warming applies to providers that cache prompts at explicit markers with a
short lifetime, such as Anthropic models and Anthropic-compatible endpoints.
OpenCode doesn't warm:

- providers that cache implicitly, such as OpenAI and Gemini. Their caches don't
  charge extra to write, keep a prompt for longer on their own, or don't
  guarantee a hit, so a refresh rarely pays for itself.
- requests whose thinking budget is fitted to the output limit. Lowering the
  limit would change the thinking settings, and with them the cached prompt.
- subagent sessions. Their parent stays warm while it waits on them.

## Options

Use the object form to change the interval or the windows:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "interval": "auto",
    "duration": "1 hour",
    "idle": "10 minutes",
  },
}
```

| Field | Default | Purpose |
| --- | --- | --- |
| `interval` | `"auto"` | Time from a model request to the refresh of its cache. `"auto"` uses 90% of the cache lifetime the request was sent with. |
| `duration` | `"30 minutes"` | How long after the latest model request to keep warming while the turn runs, for example while a long tool call or subagent works. |
| `idle` | `"15 minutes"` | How long after a turn ends to keep warming. |

`prompt` is deprecated and ignored: refreshes resend the last request instead
of adding a prompt.

A model's or provider's `cache.warming` setting overrides the top-level
`warming`:

```jsonc title="opencode.jsonc"
{
  "warming": true,
  "providers": {
    "anthropic": { "settings": { "cache": { "warming": { "idle": "5 minutes" } } } },
  },
}
```

## Cache lifetime

`"auto"` uses the lifetime in the model's [`cache.ttl`](/config), or five
minutes when none is set. A one-hour cache outlives the default windows, so it
isn't refreshed unless you raise `duration` and `idle` past 54 minutes.

```jsonc title="opencode.jsonc"
{
  "warming": { "duration": "2 hours", "idle": "2 hours" },
  "providers": {
    "anthropic": { "settings": { "cache": { "ttl": "1h" } } },
  },
}
```

A fixed `interval` such as `"4 minutes"` is used as given. It must be shorter
than `duration`; otherwise OpenCode skips warming and logs a warning.

## Timing

A cache entry's lifetime starts when the provider reads the prompt, so the
interval counts from when each request was sent, not from when its response
finished.

```text
00:00    model request sent
00:02    response finishes; the turn ends
04:30    refresh
09:00    refresh
13:30    refresh
15:02    idle window ends; warming stops
```

Any new model request restarts the interval and both windows. OpenCode doesn't
refresh while a model request is running. If a response streams for so long
that the cache entry has expired by the time it ends, OpenCode doesn't refresh
it: the next request writes a new entry anyway.

## When warming stops

Besides the windows above, OpenCode stops warming a session when:

- a refresh reads nothing from the cache or writes to it. The entry was already
  gone, and every further refresh would rewrite the whole prompt.
- a refresh fails.
- the session is compacted, because the next request sends a different prompt.

The next model request starts warming again.

## Requests

A refresh resends the session's last model request unchanged: the same
instructions, tools, messages, and provider options, with the output limited
to one token. It does not admit input, add messages to history, run tools, or
mutate durable session state, and its response is discarded.

## Costs

Refreshes are real provider requests. Each one bills a cache read of the whole
prompt and one output token, and counts against rate limits.

- A refresh pays for itself only if you come back before the next one is due
  often enough. That chance falls the longer a session sits idle, which is why
  the idle window is shorter than the active one.
- With the defaults, an idle session gets at most three refreshes: at 4.5, 9 and
  13.5 minutes.

## Disabling

Set `warming` to `false` to disable it explicitly. Omitting the field also
leaves warming disabled.

```jsonc title="opencode.jsonc"
{
  "warming": false,
}
```
