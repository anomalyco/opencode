Configure your ACP client to launch `opencode acp`. For example, add OpenCode to Zed's
`~/.config/zed/settings.json`:

```json
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

Other ACP clients use the same executable and `acp` argument, but their configuration file and field names may differ.
If a graphical client cannot find `opencode`, set `command` to the absolute path reported by `which opencode`.

## Authentication

ACP authentication uses the provider credentials already available to OpenCode. Sign in from a terminal before starting
the ACP client:

```bash
opencode auth login
```

OpenCode's only auth method is `opencode-login`, and `authenticate` does not collect credentials. A prompt that fails
because a provider needs authentication returns ACP's `auth_required` error.

When the client sets `clientCapabilities._meta["terminal-auth"]: true`, the auth method includes the login command:

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "_meta": { "terminal-auth": { "command": "opencode", "args": ["auth", "login"], "label": "OpenCode Login" } }
}
```

ACP's standard terminal auth, `clientCapabilities.auth.terminal` with a `type: "terminal"` auth method, is not supported
yet.

## Troubleshooting

Running `opencode acp` directly appears to wait because it expects ACP messages on stdin. Start it through an ACP client
for normal use.

If the client reports that the process exited or returned invalid protocol output, enable ACP and private-server logs on
stderr:

```bash
opencode --print-logs acp
```

Add `--print-logs` before `acp` in the client's argument list while diagnosing the problem. Stdout remains reserved for
ACP messages.

## Protocol reference

This section is for ACP client authors. See the [Agent Client Protocol](https://agentclientprotocol.com) for the
messages themselves.

### Transport

The client starts `opencode acp` as a child process and exchanges newline-delimited JSON-RPC messages over stdin and
stdout using ACP protocol version 1.

The command starts a private OpenCode server for that ACP process. It does not connect to the shared background service,
and it does not expose an ACP network port. The process can serve multiple ACP sessions and runs until the client closes
stdin.

### Capabilities

OpenCode's `initialize` response includes these agent capabilities:

```json
{
  "loadSession": true,
  "mcpCapabilities": { "http": true, "sse": false },
  "promptCapabilities": { "embeddedContext": true, "image": true },
  "sessionCapabilities": {
    "additionalDirectories": {},
    "close": {},
    "delete": {},
    "fork": {},
    "list": {},
    "resume": {}
  }
}
```

It reads these client capabilities:

| Capability                     | Effect                                                       |
| ------------------------------ | ------------------------------------------------------------ |
| `elicitation.form`             | Questions are asked as [forms](#questions).                  |
| `session.compaction`           | Compaction uses ACP's [compaction updates](#compaction).     |
| `_meta["terminal-auth"]: true` | The auth method includes a [login command](#authentication). |

### Sessions

The client supplies the working directory when it creates a session. OpenCode uses that directory's configuration,
including its models, agents, commands, skills, instructions, plugins, and MCP servers.

- `session/load` replays the saved messages. `session/resume` and `session/fork` do not.
- Loading or resuming a session requires the session's own directory as `cwd`; a different `cwd` is rejected with an
  invalid params error. A fork keeps the source session's directory.
- `session/list` returns up to 100 sessions per page and accepts a `cwd` filter and a `cursor`.
- Closing a session interrupts active work and detaches it, but keeps the saved session. Deleting a session removes it;
  deleting one that does not exist succeeds.
- A session runs one prompt at a time. A second `session/prompt` fails while the first is active.

`session/cancel` and a `$/cancel_request` for the prompt both end the prompt with `stopReason: "cancelled"`. Pending
permission requests are rejected. Tool calls that don't finish after a cancel are reported as `failed`.

#### Additional directories

Pass `additionalDirectories` on `session/new`, `session/load`, `session/resume`, or `session/fork`:

```json
{ "cwd": "/work/app", "additionalDirectories": ["/work/shared"], "mcpServers": [] }
```

- Each entry must be an absolute path without `*` or `?`.
- OpenCode allows external directory access inside each root. Read, edit, and shell permission rules still apply.
- Each request's list replaces the session's previous list, as the
  [additional directories RFD](https://agentclientprotocol.com/rfds/additional-directories) specifies.
- The grants are stored on the OpenCode session, so they apply when it is used from another OpenCode client. Child
  sessions copy them when they are created.

`session/list` returns each session's stored list in `additionalDirectories`.

### Config options

New sessions use the directory's default model and primary agent. Session responses include these config options:

| ID       | Category        | Values                                                                          |
| -------- | --------------- | ------------------------------------------------------------------------------- |
| `model`  | `model`         | Enabled models as `provider/model`. A `/variant` suffix also selects an effort. |
| `effort` | `thought_level` | The model's variants and `default`. Only when the model has variants.           |
| `mode`   | `mode`          | Visible primary agents.                                                         |

`session/set_config_option` takes string values. `session/set_mode` also selects the agent. OpenCode sends
`config_option_update` when the available models or agents change, or when another client changes the session's model
or agent.

```json
{ "sessionId": "ses_123", "configId": "model", "value": "anthropic/claude-sonnet-4" }
```

### Content

Prompts can contain text, images, embedded resources, and resource links. Audio blocks are ignored.

| Block                                           | Handling                                                                    |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| `text`                                          | Sent to the model.                                                          |
| `text` for `assistant` only                     | Sent to the model as separate context, not as part of the user's message.   |
| `text` for `user` only                          | Kept out of the model's input.                                              |
| `image` with `data`                             | Attached to the prompt.                                                     |
| `image` with only `uri`                         | Handled like a resource link.                                               |
| `resource` with `text`                          | Inlined as text, prefixed with the resource's path or URI.                  |
| `resource` with `blob`                          | Attached when it has a `mimeType`; dropped otherwise.                       |
| `resource_link` to `file://`                    | Attached. A missing or unreadable file falls back to a Markdown link.       |
| `resource_link` to `zed://` with a `path` query | Attached as the file at `path`.                                             |
| `resource_link` to another URI                  | Sent as a Markdown link, for example `[spec](https://example.com/spec.md)`. |

The audience comes from the block's `annotations`. An `image` with neither `data` nor `uri` is rejected.

```json
{ "type": "text", "text": "Open file: src/app.ts", "annotations": { "audience": ["assistant"] } }
```

### Commands

OpenCode sends `available_commands_update` with the directory's commands and the built-in `compact` command when a
session is attached, and again when the commands change.

```json
{
  "sessionUpdate": "available_commands_update",
  "availableCommands": [{ "name": "compact", "description": "Compact the session" }]
}
```

A prompt that starts with the `/name` of an available command runs that command, with the rest of the text as
arguments. Other text starting with `/` is sent as a normal prompt. `/compact` runs [compaction](/compaction).

### MCP servers

Clients may pass stdio and HTTP MCP servers on `session/new`, `session/load`, `session/resume`, and `session/fork`.
OpenCode adds them to the session's directory for the life of the `opencode acp` process, so other sessions in that
directory can use them. HTTP headers are passed through, and OAuth is not used. MCP over SSE is not advertised, and MCP
over ACP is not supported.

```json
{ "type": "http", "name": "docs", "url": "https://mcp.example.com", "headers": [] }
```

### Permissions

Permission requests offer three options. Requests that change files include `diff` content when OpenCode can preview
the change.

```json
[
  { "optionId": "once", "kind": "allow_once", "name": "Allow once" },
  { "optionId": "always", "kind": "allow_always", "name": "Always allow" },
  { "optionId": "reject", "kind": "reject_once", "name": "Reject" }
]
```

### Questions

When the client advertises `elicitation.form`, OpenCode asks questions with `elicitation/create` in form mode. The
request includes `toolCallId` when that tool call was sent as a `session/update` for this session.

```json
{
  "mode": "form",
  "sessionId": "ses_123",
  "toolCallId": "call_1",
  "message": "Which package manager?",
  "requestedSchema": {
    "type": "object",
    "properties": { "pm": { "type": "string", "oneOf": [{ "const": "bun", "title": "Bun" }] } },
    "required": ["pm"]
  }
}
```

- Forms that might collect secrets are never sent.
- A field that accepts a typed answer next to its options adds an optional `<key>_custom` string property. A non-empty
  custom answer wins over the selection.
- Declining or cancelling the form cancels the question.

When a question can't be shown, OpenCode cancels it and tells the model to continue without an answer.

### Compaction

When the client advertises `session.compaction`, OpenCode reports compaction with ACP's
[session compaction](https://agentclientprotocol.com/rfds/session-compaction) updates (Preview): `compaction_update` and
`compaction_summary_chunk`. Loading a session replays each settled compaction as one terminal update.

```json
{
  "sessionUpdate": "compaction_update",
  "compactionId": "msg_123",
  "status": "completed",
  "summary": [{ "type": "text", "text": "..." }]
}
```

Other clients, and all child session compactions, get the [compaction marker](#compaction-marker) instead.

### Usage

The prompt response includes `usage`, from the draft
[end-turn usage](https://agentclientprotocol.com/rfds/end-turn-token-usage) RFD. It sums the prompt's model calls in
this session, not its child sessions.

```json
{ "stopReason": "end_turn", "usage": { "inputTokens": 1200, "outputTokens": 340, "totalTokens": 1540 }, "_meta": {} }
```

Before the response, OpenCode sends `usage_update`, from the
[session usage](https://agentclientprotocol.com/rfds/session-usage) RFD, when the model's context size is known.
`cost` is the session's total in USD.

```json
{ "sessionUpdate": "usage_update", "used": 1540, "size": 200000, "cost": { "amount": 0.012, "currency": "USD" } }
```

### OpenCode extensions

OpenCode adds these `_meta` keys. Clients that don't recognize them can ignore them.

#### Child sessions

While a prompt runs, updates from its child sessions are sent as `session/update` on the parent session. They carry
`_meta["opencode/child-session"]`, tool call IDs are prefixed with `<childSessionId>:`, and tool call titles are
prefixed with the child's title when it has one.

```json
{
  "sessionUpdate": "tool_call",
  "toolCallId": "ses_child:call_1",
  "title": "Explore the codebase: src/app.ts",
  "_meta": {
    "opencode/child-session": { "id": "ses_child", "parentID": "ses_123", "depth": 1, "title": "Explore the codebase" }
  }
}
```

| Field      | Type     | Description                                          |
| ---------- | -------- | ---------------------------------------------------- |
| `id`       | `string` | The child session.                                   |
| `parentID` | `string` | The child's parent session.                          |
| `depth`    | `number` | 1 for a direct child, 2 for its child, and so on.    |
| `title`    | `string` | The child session's title. Omitted when it has none. |

Permission requests from a child session carry the same key on `toolCall._meta`. Once the prompt ends, child session
updates are no longer sent, but their permission requests and questions still reach the client.

#### Retry status

When a model call fails and OpenCode schedules a retry, it sends `session_info_update` with `_meta["opencode/retry"]`.
When the retry starts, it sends `"opencode/retry": null`. Clear any retry status when the prompt response arrives.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": {
    "opencode/retry": {
      "attempt": 1,
      "nextRetryAt": "2026-10-02T12:00:05.000Z",
      "error": { "type": "provider.rate-limit", "message": "Rate limit exceeded", "status": 429 }
    }
  }
}
```

| Field         | Type     | Description                                                                          |
| ------------- | -------- | ------------------------------------------------------------------------------------ |
| `attempt`     | `number` | The retry attempt number.                                                            |
| `nextRetryAt` | `string` | ISO 8601 time of the next attempt.                                                   |
| `error`       | `object` | `type` and `message`, plus `status` and `response.body` when the provider sent them. |

#### Compaction marker

Clients without `session.compaction` receive compaction progress as `session_info_update` with
`_meta["opencode/compaction"]`. Child session compactions always use the marker.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": { "opencode/compaction": { "status": "started", "messageId": "msg_123", "reason": "auto" } }
}
```

| Field       | Type     | Description                                                              |
| ----------- | -------- | ------------------------------------------------------------------------ |
| `status`    | `string` | `started`, `completed`, or `failed`. A cancelled compaction is `failed`. |
| `messageId` | `string` | Pairs a compaction's start with its end. Treat it as an opaque key.      |
| `reason`    | `string` | `auto` or `manual`.                                                      |
| `error`     | `object` | With `failed`. Same shape as the [retry](#retry-status) `error`.         |

The marker carries no summary. An automatic compaction can fail without a `started` marker. Loading a session replays
each settled compaction as one `completed` or `failed` marker.
