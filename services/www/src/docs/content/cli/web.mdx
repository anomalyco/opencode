title: "Web"
description: "Run OpenCode in the browser."
---

OpenCode ships with a web UI that is served from the same server that powers the
TUI. It's available by default and password protected.

## Access

```bash
$ opencode pair

  Open a link to connect. Links work once and expire in 5 minutes.

  http://127.0.0.1:49374/auth/connect/...

  █▀▀▀▀▀█ ...
```

Opening a link in a browser signs it in with a session cookie and loads the web
UI. Scanning the QR code from the OpenCode app, or pasting the link into its
server address field, connects the app the same way. Sessions last 30 days;
changing the server password signs every session out.

### Over SSH

When the server listens only on localhost, forward its port from your machine
and open the printed link locally:

```bash
$ ssh -L 49374:127.0.0.1:49374 my-server
```

By default the server listens only on localhost. Its port depends on the
platform:

| Platform              | Default port |
| --------------------- | ------------ |
| macOS, Linux, and WSL | 49374        |
| Windows               | 28894        |

Windows reserves ports from 49152 up, and WSL mirrored networking reserves
another block below that. Print the current address with
`opencode service status`:

```bash
$ opencode service status
http://127.0.0.1:49374
```

You can change this config with the `opencode service` command.

### Remote access

To connect from anywhere, pair through an [OpenTunnel](https://github.com/anomalyco/opentunnel)
remote address:

```bash
$ opencode pair --remote
```

The first time it turns remote access on, it asks before going ahead:

```text
▲  This will expose your OpenCode server to the internet.
│  Traffic is end-to-end encrypted, and access requires your server password.
│  To pair locally instead, run `opencode pair` without the --remote flag.
│
◆  Expose your server to the internet?
│  ● Yes / ○ No
```

Without an interactive terminal, the command fails unless you pass `--yes` to
accept. Once accepted, later runs skip the prompt, even after remote access has
been turned off with `opencode service set remote false`.

## Configure

Configure the shared background service with `opencode service set`:

```bash
# Listen on every network interface
$ opencode service set hostname 0.0.0.0

# Use a fixed port instead of the channel default
$ opencode service set port 49374

# Replace the generated password
$ opencode service set password "a-long-secret"

# Allow a web client served from another origin
$ opencode service set cors https://app.example.com,https://other.example.com

# Pass an environment variable to the server process
$ opencode service set env OPENCODE_LOG_LEVEL DEBUG
```

Changing a setting stops the background server. Start it again to apply the new config:

```bash
$ opencode service start
```

## Standalone

`opencode serve` runs the same server in the foreground instead of through the
shared background service. Set `OPENCODE_PASSWORD` to keep its password stable
across restarts; otherwise each launch generates a new password.

```bash
$ OPENCODE_PASSWORD="a-long-secret" opencode serve --hostname 0.0.0.0 --port 4096
server listening on http://0.0.0.0:4096
```

`opencode service set password` configures only the background service. It does
not set the password for `opencode serve`.

Use it when you want to:

- Run OpenCode on a shared, always-on, or remote host, then connect clients with
  `opencode --server <url>`.
- Control the hostname, port, and CORS origins for a single process.
- Run under a supervisor like systemd, Docker, or another environment that expects
  a foreground process.
- Keep a dedicated server instead of the shared background service.

Connect a client to it with `--server`:

```bash
$ opencode --server http://127.0.0.1:4096
```

### Docker

The image entrypoint is `opencode`, which opens the TUI without a subcommand.
Pass `serve` to run a foreground server, and bind to `0.0.0.0` inside the container
so the published port can reach it:

```bash
export OPENCODE_PASSWORD="a-long-secret"
docker run --rm \
  -p 127.0.0.1:4096:4096 \
  -e OPENCODE_PASSWORD \
  -v opencode-data:/root/.local/share/opencode \
  -v "$PWD:/workspace" \
  -w /workspace \
  ghcr.io/anomalyco/opencode:2.0.32 \
  serve --hostname 0.0.0.0 --port 4096
```

This publishes the server only on the Docker host's loopback interface. The project
is mounted at `/workspace`; the named data volume preserves sessions when the
container is removed. With the image's default root user, data lives in
`/root/.local/share/opencode`. If `OPENCODE_DB` points outside that volume, persist
its containing directory too.

From another terminal with the same `OPENCODE_PASSWORD`, verify the authenticated
API:

```bash
curl --fail --user "opencode:$OPENCODE_PASSWORD" http://127.0.0.1:4096/api/info
```

For the older `2.0.0` image, use `/api/location` instead of `/api/info`.
