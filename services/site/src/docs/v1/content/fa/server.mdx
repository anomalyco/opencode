فرمان `opencode serve` یک سرور HTTP بدون رابط کاربری راه‌اندازی می‌کند. کلاینت OpenCode از طریق API این سرور که مشخصات OpenAPI دارد با آن ارتباط برقرار می‌کند.

---

### نحوهٔ استفاده

```bash
opencode serve [--port <number>] [--hostname <string>] [--cors <origin>]
```

#### گزینه‌ها

| گزینه | توضیحات | پیش‌فرض |
| --------------- | ----------------------------------- | ---------------- |
| `--port` | پورتی که سرور روی آن گوش می‌دهد | `4096` |
| `--hostname` | نام میزبانی که سرور روی آن گوش می‌دهد | `127.0.0.1` |
| `--mdns` | فعال‌سازی کشف سرویس با mDNS | `false` |
| `--mdns-domain` | نام دامنهٔ دلخواه برای سرویس mDNS | `opencode.local` |
| `--cors` | مبدأهای مجاز اضافی برای درخواست‌های مرورگر | `[]` |

گزینهٔ `--cors` را می‌توانید چند بار به فرمان بدهید.

```bash
opencode serve --cors http://localhost:5173 --cors https://app.example.com
```

---

### احراز هویت

برای محافظت از سرور با احراز هویت پایهٔ HTTP، متغیر `OPENCODE_SERVER_PASSWORD` را تنظیم کنید. نام کاربری پیش‌فرض `opencode` است و با `OPENCODE_SERVER_USERNAME` تغییر می‌کند. این تنظیمات هم برای `opencode serve` و هم برای `opencode web` اعمال می‌شوند.

```bash
OPENCODE_SERVER_PASSWORD=your-password opencode serve
```

---

### نحوهٔ کار

با اجرای `opencode`، هم رابط ترمینالی و هم سرور راه‌اندازی می‌شوند. رابط ترمینالی کلاینتی است که با سرور ارتباط دارد. سرور مشخصات OpenAPI 3.1 را منتشر می‌کند و [SDK](/docs/sdk) نیز از همین مشخصات تولید می‌شود.

:::tip
برای کار با OpenCode از داخل برنامه، به سرور آن متصل شوید.
:::

این معماری به چند کلاینت اجازه می‌دهد با OpenCode کار کنند و برنامه‌ها نیز بتوانند آن را کنترل کنند.

برای راه‌اندازی سروری مستقل، `opencode serve` را اجرا کنید. اگر رابط ترمینالی OpenCode از قبل باز باشد، `opencode serve` یک سرور تازه راه می‌اندازد.

---

#### اتصال به سرور موجود

رابط ترمینالی هنگام شروع، نام میزبان و پورت را به‌طور تصادفی تعیین می‌کند. برای اینکه بتوانید به سرور آن وصل شوید، این دو مقدار را با [گزینه‌های](/docs/cli) `--hostname` و `--port` تعیین کنید.

از مسیر [`/tui`](#tui) می‌توانید رابط ترمینالی را از طریق سرور کنترل کنید، مثلاً متن درخواستی را از پیش بنویسید یا اجرا کنید. افزونه‌های [محیط توسعه](/docs/ide) OpenCode هم از همین روش استفاده می‌کنند.

---

## مشخصات API

سرور مشخصات OpenAPI 3.1 را در مسیر زیر منتشر می‌کند.

```
http://<hostname>:<port>/doc
```

برای نمونه، `http://localhost:4096/doc` را باز کنید. از این مشخصات برای تولید کلاینت یا بررسی نوع درخواست و پاسخ استفاده کنید. می‌توانید آن را در مرورگر Swagger نیز ببینید.

#### پارامترهای پرس‌وجوی `/find/file`

- `query` (الزامی): رشتهٔ جست‌وجو با تطبیق تقریبی
- `type` (اختیاری): محدود کردن نتایج به `"file"` یا `"directory"`
- `directory` (اختیاری): تعیین ریشه‌ای دیگر برای جست‌وجوی پروژه
- `limit` (اختیاری): حداکثر تعداد نتایج، از ۱ تا ۲۰۰
- `dirs` (اختیاری): گزینهٔ قدیمی، با مقدار `"false"` فقط فایل‌ها برگردانده می‌شوند.
