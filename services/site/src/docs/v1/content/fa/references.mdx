منابع مرجع به OpenCode امکان می‌دهند به پوشه‌های بیرون از پروژهٔ جاری دسترسی داشته باشد. می‌توانید هنگام کار، مستندات، کتابخانه‌های مشترک، مثال‌ها یا مخزن دیگری را در اختیارش بگذارید.

منابع را در `opencode.json` یا `opencode.jsonc` با یک نام مستعار تعریف کنید.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and documentation conventions",
    },
    "sdk": {
      "repository": "anomalyco/opencode-sdk-js",
      "branch": "main",
      "description": "Use for JavaScript SDK implementation details",
    },
  },
}
```

---

## پوشه‌های محلی

برای معرفی یک پوشهٔ محلی، `path` را تعیین کنید.

```jsonc title="opencode.jsonc"
{
  "references": {
    "docs": {
      "path": "../docs",
    },
  },
}
```

مسیر را می‌توانید به شکل‌های زیر بنویسید.

- نسبت به فایل پیکربندی‌ای که منبع در آن تعریف شده است
- مطلق، مانند `/home/user/docs`
- نسبت به پوشهٔ خانگی کاربر، مانند `~/docs`

می‌توانید مسیر را به شکل کوتاه و با یک رشته نیز بنویسید.

```jsonc title="opencode.jsonc"
{
  "references": {
    "docs": "../docs",
  },
}
```

## مخزن‌های Git

برای معرفی مخزن Git از `repository` استفاده کنید. OpenCode نسخه‌ای از مخزن را در حافظهٔ نهان محلی مخزن‌ها نگه می‌دارد و پوشهٔ حاوی فایل‌های استخراج‌شده را در اختیار پروژه می‌گذارد.

```jsonc title="opencode.jsonc"
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

فیلد `repository` نشانی Git، مسیر به شکل میزبان/مسیر و صورت کوتاه `owner/repo` در GitHub را می‌پذیرد. فیلد اختیاری `branch` شاخه یا مرجع Git را تعیین می‌کند. بدون `branch`، شاخهٔ پیش‌فرض مخزن انتخاب می‌شود.

اگر به تعیین شاخه، توضیحات یا گزینهٔ دیگری نیاز ندارید، می‌توانید فقط یک رشته بنویسید.

```jsonc title="opencode.jsonc"
{
  "references": {
    "effect": "Effect-TS/effect",
  },
}
```

:::note
OpenCode مخزن‌های مرجع را به‌صورت ناهمگام به‌روز می‌کند. پس از تعریف مخزن جدید، ممکن است کمی طول بکشد تا کلون کردن یا به‌روزرسانی آن تمام شود.
:::

## توضیح کاربرد منبع

در `description` بنویسید که عامل چه زمانی باید از این منبع استفاده کند.

```jsonc title="opencode.jsonc"
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when implementing UI components or design tokens",
    },
  },
}
```

OpenCode منابع دارای توضیح را در زمینهٔ کاری عامل قرار می‌دهد. توضیحی کوتاه و مشخص بنویسید تا عامل بتواند میان منابع مشابه تمایز بگذارد. منابع بدون توضیح را همچنان می‌توان از طریق تکمیل خودکار یا مستقیماً انتخاب کرد، اما خودکار به عامل معرفی نمی‌شوند.

## پنهان کردن از تکمیل خودکار

برای پنهان کردن یک منبع از فهرست تکمیل خودکار `@` در رابط ترمینالی، `hidden` را روی `true` بگذارید.

```jsonc title="opencode.jsonc"
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal implementation details",
      "hidden": true,
    },
  },
}
```

`hidden` فقط بر تکمیل خودکار اثر دارد. اگر منبع پنهان‌شده توضیح داشته باشد، همچنان در زمینهٔ کاری عامل قرار می‌گیرد.

## استفاده از منابع مرجع

منابع تعریف‌شده در تکمیل خودکار `@` رابط ترمینالی دیده می‌شوند. برای پیوست کردن پوشهٔ ریشهٔ منبع `@alias` را بنویسید. برای جست‌وجوی فایل‌های داخل آن، `@alias/` را بنویسید.

```text
Compare this implementation with @sdk/src/client.ts
```

اگر برای منبعی توضیح بنویسید، عامل‌ها مسیر نهایی و توضیح آن را نیز در زمینهٔ سیستمی خود دریافت می‌کنند. در نتیجه، عامل می‌تواند هنگام نیاز بدون پیوست دستی از سوی شما منبع را بررسی کند.

OpenCode به پوشه‌های مرجع به‌طور خودکار مجوز دسترسی به پوشهٔ خارجی می‌دهد. مجوزهای معمول ابزارها همچنان اعمال می‌شوند. برای مثال، تعریف پوشه به‌عنوان منبع به عاملی که اجازهٔ ویرایش ندارد، اجازهٔ ویرایش فایل نمی‌دهد.

## فیلدهای پیکربندی

| فیلد | محلی | Git | توضیحات |
| ------------- | ----- | --- | ------------------------------------------------ |
| `path` | بله | خیر | پوشهٔ مرجع محلی |
| `repository` | خیر | بله | نشانی Git، میزبان/مسیر یا مقدار `owner/repo` در GitHub |
| `branch` | خیر | بله | شاخه یا مرجع اختیاری Git |
| `description` | بله | بله | توضیح زمان استفاده از منبع |
| `hidden` | بله | بله | پنهان کردن منبع از تکمیل خودکار `@` در رابط ترمینالی |

نام مستعار منبع نمی‌تواند خالی باشد یا شامل `/`، فاصلهٔ سفید، بک‌تیک یا ویرگول لاتین باشد.
