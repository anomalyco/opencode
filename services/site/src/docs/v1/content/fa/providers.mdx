OpenCode با [AI SDK](https://ai-sdk.dev/) و [Models.dev](https://models.dev) از **بیش از ۷۵ ارائه‌دهندهٔ مدل زبانی** پشتیبانی می‌کند. امکان اجرای مدل‌های محلی هم وجود دارد.

برای افزودن یک ارائه‌دهنده، این دو مرحله را انجام دهید.

1. با فرمان `/connect` کلیدهای API ارائه‌دهنده را وارد کنید.
2. ارائه‌دهنده را در پیکربندی OpenCode تنظیم کنید.

---

### اطلاعات دسترسی

کلیدهای API که با `/connect` وارد می‌کنید، در `~/.local/share/opencode/auth.json` ذخیره می‌شوند.

---

### پیکربندی

تنظیمات ارائه‌دهندگان را در بخش `provider` پیکربندی OpenCode تغییر دهید.

---

#### نشانی پایه

با گزینهٔ `baseURL` نشانی پایهٔ هر ارائه‌دهنده را تغییر دهید. این گزینه برای سرویس‌های پراکسی یا نقاط پایانی سفارشی کاربرد دارد.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

---

#### پنهان کردن مدل‌ها

با `blacklist` می‌توانید برخی مدل‌های یک ارائه‌دهنده را از فهرست `/models` پنهان کنید تا مدل‌های ناخواسته در فهرست انتخاب شما نباشند.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "blacklist": ["claude-opus-5-5"]
    }
  }
}
```

گزینهٔ معکوس، `whitelist`، همهٔ مدل‌ها را جز موارد فهرست‌شده پنهان می‌کند.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "whitelist": ["claude-sonnet-5-5"]
    }
  }
}
```

هر دو گزینه آرایه‌ای از شناسهٔ مدل‌ها می‌گیرند. همان شناسه‌هایی را وارد کنید که در فهرست `/models` می‌بینید.

- `blacklist` مدل‌های فهرست‌شده را از فهرست انتخاب حذف می‌کند.
- `whitelist` فقط مدل‌های فهرست‌شده را نگه می‌دارد و بقیه را پنهان می‌کند.
- می‌توانید هر دو را به کار ببرید. ابتدا `whitelist` مجموعه را محدود می‌کند، سپس `blacklist` موارد مشخصی را از آن حذف می‌کند.

## OpenCode Models

OpenCode Models مجموعهٔ مدل‌هایی است که تیم OpenCode ارائه می‌دهد و سازگاری آن‌ها را با OpenCode آزمایش و تأیید کرده است. [راهنمای OpenCode Models](https://opencode.ai/docs/console/) را ببینید.

:::tip
اگر تازه شروع کرده‌اید، پیشنهاد می‌کنیم با OpenCode Models کار کنید.
:::

1. در رابط ترمینالی `/connect` را اجرا کنید، `OpenCode` را انتخاب کنید و به [opencode.ai/auth](https://opencode.ai/auth) بروید.

   ```txt
   /connect
   ```

2. وارد حساب شوید، اطلاعات پرداخت را اضافه و کلید API را کپی کنید.

3. کلید API را جای‌گذاری کنید.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. برای دیدن مدل‌های پیشنهادی ما، `/models` را در رابط ترمینالی اجرا کنید.

   ```txt
   /models
   ```

این سرویس مانند سایر ارائه‌دهندگان کار می‌کند و استفاده از آن کاملاً اختیاری است.

### Amazon Bedrock

برای استفاده از Amazon Bedrock در OpenCode، مراحل زیر را انجام دهید.

1. در کنسول Amazon Bedrock به **Model catalog** بروید و دسترسی به مدل‌های موردنظر را درخواست کنید.

   :::tip
   برای استفاده باید در Amazon Bedrock به مدل موردنظر دسترسی داشته باشید.
   :::

2. **احراز هویت** را با یکی از روش‌های زیر تنظیم کنید.

   ***

   #### متغیرهای محیطی (شروع سریع)

   هنگام اجرای OpenCode یکی از این متغیرهای محیطی را تنظیم کنید.

   ```bash
   # Option 1: Using AWS access keys
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # Option 2: Using named AWS profile
   AWS_PROFILE=my-profile opencode

   # Option 3: Using Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   یا آن‌ها را به پروفایل bash اضافه کنید.

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### فایل پیکربندی (پیشنهادی)

   برای تنظیمات ماندگار یا ویژهٔ پروژه، از `opencode.json` استفاده کنید.

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **گزینه‌های در دسترس**
   - `region` منطقهٔ AWS، مانند `us-east-1` یا `eu-west-1`
   - `profile` نام پروفایل AWS از فایل `~/.aws/credentials`
   - `endpoint` نشانی سفارشی نقطهٔ پایانی VPC (نام دیگر گزینهٔ عمومی `baseURL`)

   :::tip
   گزینه‌های فایل پیکربندی بر متغیرهای محیطی اولویت دارند.
   :::

   ***

   #### تنظیمات پیشرفتهٔ نقاط پایانی VPC

   اگر برای Bedrock از نقاط پایانی VPC استفاده می‌کنید، این تنظیمات را به کار ببرید.

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   گزینهٔ `endpoint` همان گزینهٔ عمومی `baseURL` با نام‌گذاری AWS است. اگر هم `endpoint` و هم `baseURL` تعیین شده باشند، `endpoint` اولویت دارد.
   :::

   ***

   #### روش‌های احراز هویت
   - **`AWS_ACCESS_KEY_ID` و `AWS_SECRET_ACCESS_KEY`**: در کنسول AWS کاربر IAM بسازید و کلیدهای دسترسی آن را ایجاد کنید.
   - **`AWS_PROFILE`**: از پروفایل‌های نام‌دار در `~/.aws/credentials` استفاده کنید. ابتدا با `aws configure --profile my-profile` یا `aws sso login` آن‌ها را آماده کنید.
   - **`AWS_BEARER_TOKEN_BEDROCK`**: در کنسول Amazon Bedrock یک کلید API بلندمدت بسازید.
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` و `AWS_ROLE_ARN`**: برای EKS IRSA (نقش‌های IAM برای حساب‌های سرویس) یا دیگر محیط‌های Kubernetes با هویت فدرال OIDC. وقتی از annotationهای حساب سرویس استفاده می‌کنید، Kubernetes این متغیرها را خودکار به محیط اضافه می‌کند.

   ***

   #### ترتیب اولویت احراز هویت

   Amazon Bedrock اطلاعات احراز هویت را به‌ترتیب زیر انتخاب می‌کند.
   1. **توکن حامل** از متغیر محیطی `AWS_BEARER_TOKEN_BEDROCK` یا فرمان `/connect`
   2. **زنجیرهٔ اطلاعات دسترسی AWS** شامل پروفایل، کلیدهای دسترسی، اطلاعات دسترسی مشترک، نقش‌های IAM، توکن‌های هویت وب (EKS IRSA) و فرادادهٔ نمونه

   :::note
   اگر توکن حامل را با `/connect` یا `AWS_BEARER_TOKEN_BEDROCK` تعیین کنید، بر همهٔ روش‌های احراز هویت AWS، از جمله پروفایل‌ها، اولویت دارد.
   :::

3. با فرمان `/models` مدل موردنظر را انتخاب کنید.

   ```txt
   /models
   ```

:::note
برای پروفایل استنتاج سفارشی، نام مدل و ارائه‌دهنده را در کلید بنویسید و مقدار `id` را ARN قرار دهید تا حافظهٔ نهان درست عمل کند.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

با [Atomic Chat](https://atomic.chat) می‌توانید در OpenCode از مدل‌های محلی استفاده کنید. این برنامهٔ دسکتاپ مدل‌های زبانی محلی را از طریق سرور API سازگار با OpenAI ارائه می‌کند. نشانی پیش‌فرض آن `http://127.0.0.1:1337/v1` است.

```json title="opencode.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (local)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

در این نمونه:

- `atomic-chat` شناسهٔ ارائه‌دهندهٔ سفارشی است. هر رشتهٔ دلخواهی را می‌توانید برای آن انتخاب کنید.
- `npm` بستهٔ مورد استفادهٔ ارائه‌دهنده را تعیین می‌کند. برای API سازگار با OpenAI از `@ai-sdk/openai-compatible` استفاده می‌شود.
- `name` نامی است که برای ارائه‌دهنده در رابط کاربری نمایش داده می‌شود.
- `options.baseURL` نشانی سرور محلی است. نام میزبان و درگاه را با تنظیمات Atomic Chat خود مطابقت دهید.
- `models` شناسهٔ مدل‌ها را به نام نمایشی آن‌ها نگاشت می‌کند. هر شناسه باید با `id` بازگردانده‌شده از `GET /v1/models` برابر باشد. با اجرای `curl http://127.0.0.1:1337/v1/models` شناسهٔ مدل‌های بارگذاری‌شده در Atomic Chat را فهرست کنید.

:::tip
اگر فراخوانی ابزار درست کار نمی‌کند، مدلی بارگذاری‌شده با پشتیبانی مناسب از فراخوانی ابزار انتخاب کنید، مانند گونه‌ای از Qwen-Coder یا DeepSeek-Coder.
:::

### Azure OpenAI

:::note
اگر خطای «I'm sorry, but I cannot assist with that request» می‌بینید، در منبع Azure خود فیلتر محتوا را از **DefaultV2** به **Default** تغییر دهید.
:::

1. در [پرتال Azure](https://portal.azure.com/) یک منبع **Azure OpenAI** بسازید. به این موارد نیاز دارید:
   - **Resource name**: نام منبع بخشی از نشانی API شما خواهد بود (`https://RESOURCE_NAME.openai.azure.com/`).
   - **API key**: یکی از دو مقدار `KEY 1` یا `KEY 2` منبع شما

2. در [Azure AI Foundry](https://ai.azure.com/) یک مدل مستقر کنید.

   :::note
   برای کارکرد درست OpenCode، نام استقرار باید با نام مدل یکسان باشد.
   :::

3. فرمان `/connect` را اجرا و **Azure** را جست‌وجو کنید.

   ```txt
   /connect
   ```

4. کلید API خود را وارد کنید.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

5. نام منبع را در متغیر محیطی زیر تعیین کنید.

   ```bash
   AZURE_RESOURCE_NAME=XXX opencode
   ```

   یا آن را به پروفایل bash اضافه کنید.

   ```bash title="~/.bash_profile"
   export AZURE_RESOURCE_NAME=XXX
   ```

6. با اجرای `/models` مدل مستقرشده را انتخاب کنید.

   ```txt
   /models
   ```

#### Microsoft Entra ID (Azure CLI)

می‌توانید از نشست Azure CLI خود به‌جای کلید API استفاده کنید. [Azure CLI را نصب کنید](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli)، `az login` و سپس `/connect` را اجرا کنید، **Azure** و بعد **Microsoft Entra ID (Azure CLI)** را انتخاب کنید. هنگام درخواست، نام منبع Azure را وارد کنید. اگر منبع به مستأجر دیگری تعلق دارد، از `az login --tenant TENANT_ID` استفاده کنید.

نام منبع Azure OpenAI یا Foundry را با باز کردن آن در [پرتال Azure](https://portal.azure.com/) یا [Microsoft Foundry](https://ai.azure.com/) ببینید. این نام ابتدای نشانی نقطهٔ پایانی نیز هست؛ برای نمونه `my-models` در `https://my-models.openai.azure.com/` یا `https://my-models.services.ai.azure.com/`. اگر هویت شما مجوز فهرست کردن منابع را دارد، با فرمان زیر می‌توانید نام منابع و گروه‌های آن‌ها را ببینید.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

OpenCode از APIهای مدیریتی Azure پرس‌وجو نمی‌کند و استقرارها را خودکار نمی‌یابد. مدلی انتخاب کنید که نام آن در فهرست با نام استقرار برابر باشد یا نام استقرار را صریحاً تعیین کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "azure": {
      "models": {
        "gpt-6-luna": {
          "id": "gpt-production"
        }
      }
    }
  }
}
```

نقش لازم برای استنتاج را به هویت خود اختصاص دهید: **Cognitive Services OpenAI User** برای مدل‌های Azure OpenAI و **Cognitive Services User** برای دیگر مدل‌های Foundry. OpenCode توکن را از طریق Azure CLI، حتی در نسخه‌های پیش از ۲٫۵۴٫۰، تازه می‌کند. فقط پس از انقضای نشست CLI باید دوباره وارد شوید.

### DigitalOcean

[موتور استنتاج DigitalOcean](https://docs.digitalocean.com/products/inference/) به مدل‌های باز مانند GPT-OSS، Llama، Qwen و DeepSeek دسترسی می‌دهد. [مسیریاب‌های استنتاج](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/) سفارشی می‌توانند هر درخواست را بر اساس کار موردنظر به ارزان‌ترین، سریع‌ترین یا مناسب‌ترین مدل بفرستند.

OpenCode دو روش احراز هویت دارد.

- **OAuth (پیشنهادی)**: با حساب DigitalOcean وارد شوید. OpenCode مستقیماً از توکن API شما برای استنتاج استفاده می‌کند و مسیریاب‌های استنتاج حسابتان را می‌یابد.
- **Model Access Key**: کلیدی را که از قبل در کنسول DigitalOcean دارید، وارد کنید.

#### OAuth (پیشنهادی)

1. فرمان `/connect` را اجرا و **DigitalOcean** را جست‌وجو کنید.

   ```txt
   /connect
   ```

2. **Login with DigitalOcean** را انتخاب کنید.

   ```txt
   ┌ Select auth method
   │
   │ Login with DigitalOcean
   │ Paste Model Access Key
   └
   ```

3. مرورگر برای صدور مجوز OpenCode باز می‌شود. وارد حساب شوید و درخواست را تأیید کنید.

   :::note
   OpenCode محدوده‌های OAuth با نام `genai:read` و `inference:query` را درخواست می‌کند. توکن API حساب DigitalOcean مستقیماً برای استنتاج به کار می‌رود و کلید جداگانه‌ای برای دسترسی به مدل ساخته نمی‌شود.
   :::

   :::note
   مسیریاب‌های استنتاج فقط پس از ورود با OAuth در فهرست مدل‌ها ظاهر می‌شوند. وارد کردن دستی Model Access Key آن‌ها را پیدا نمی‌کند.
   :::

4. فرمان `/models` را اجرا کنید. مسیریاب‌های استنتاج در فهرست مدل‌ها با قالب `router:` نمایش داده می‌شوند.

   ```txt
   /models
   ```

5. برای یافتن مسیریاب‌های تازه، دوباره `/connect` را اجرا و **DigitalOcean** را انتخاب کنید.

#### استفاده از Model Access Key

برای وارد کردن مستقیم کلید، این مراحل را انجام دهید.

1. در بخش Inference از [کنسول DigitalOcean](https://cloud.digitalocean.com/)، صفحهٔ **Manage** را باز کنید و کلیدی تازه بسازید.

2. `/connect` را اجرا و **DigitalOcean** و سپس **Paste Model Access Key** را انتخاب کنید.

   ```txt
   ┌ Enter your DigitalOcean Model Access Key
   │
   │
   └ enter
   ```

   :::note
   این روش مسیریاب‌های استنتاج را خودکار شناسایی نمی‌کند. برای مشاهدهٔ آن‌ها در فهرست مدل‌ها، از OAuth وارد شوید.
   :::

3. با فرمان `/models` یک مدل انتخاب کنید.

   ```txt
   /models
   ```

#### متغیر محیطی

همچنین می‌توانید Model Access Key را در متغیر محیطی قرار دهید.

```bash frame="none"
export DIGITALOCEAN_ACCESS_TOKEN=your-model-access-key
```

#### مسیریاب‌های استنتاج

با مسیریاب استنتاج، سیاست انتخاب از چند مدل را تعریف کنید تا برای هر درخواست ارزان‌ترین، سریع‌ترین یا مناسب‌ترین مدل انتخاب شود. پس از ورود با OAuth، هر مسیریاب به شکل `router:<router-name>` در فهرست مدل‌های OpenCode نمایش داده می‌شود.

مدل مسیریاب را می‌توانید مانند هر مدل دیگری انتخاب کنید. OpenCode درخواست را می‌فرستد و DigitalOcean بر اساس سیاست مسیریاب، مدل اصلی را انتخاب می‌کند. [راهنمای مسیریاب‌های استنتاج](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/) را ببینید.

##### گیت‌لب خودمیزبان

:::note[ملاحظات انطباق]
OpenCode برای کارهایی مانند ساخت عنوان نشست از مدل کوچک استفاده می‌کند. مدل پیش‌فرض gpt-5-nano است که OpenCode میزبانی می‌کند. برای محدود کردن OpenCode به نمونهٔ گیت‌لب خودتان، تنظیمات زیر را در `opencode.json` بنویسید.

  "small_model": "gitlab/duo-chat-haiku-4-5"

برای نمونه‌های خودمیزبان GitLab:

```bash
export GITLAB_INSTANCE_URL=https://gitlab.company.com
export GITLAB_TOKEN=glpat-...
```

اگر نمونهٔ شما از درگاه AI اختصاصی استفاده می‌کند:

```bash
GITLAB_AI_GATEWAY_URL=https://ai-gateway.company.com
```

یا این مقادیر را به پروفایل bash اضافه کنید.

```bash title="~/.bash_profile"
export GITLAB_INSTANCE_URL=https://gitlab.company.com
export GITLAB_AI_GATEWAY_URL=https://ai-gateway.company.com
export GITLAB_TOKEN=glpat-...
```

:::note
مدیر GitLab شما باید این کارها را انجام دهد.

1. [GitLab Duo را فعال کند](https://docs.gitlab.com/user/duo_agent_platform/turn_on_off/#turn-gitlab-duo-on-or-off)؛ برای کاربر، گروه یا کل نمونه.
2. در GitLab 18.8 و جدیدتر [Agent Platform را فعال کند](https://docs.gitlab.com/user/duo_agent_platform/turn_on_off/#turn-gitlab-duo-agent-platform-on-or-off) یا در GitLab 18.7 و قدیمی‌تر [قابلیت‌های بتا و آزمایشی را فعال کند](https://docs.gitlab.com/user/duo_agent_platform/turn_on_off/#turn-on-beta-and-experimental-features).
3. در نسخهٔ Self-Managed، [نمونه را پیکربندی کند](https://docs.gitlab.com/administration/gitlab_duo/configure/gitlab_self_managed/).
   :::

##### OAuth برای نمونه‌های خودمیزبان

برنامهٔ OAuth گیت‌لب که همراه OpenCode است فقط در gitlab.com وجود دارد. برای OAuth در نمونهٔ خودمیزبان، در Settings → Applications برنامه‌ای بسازید. نشانی بازگشت را `http://127.0.0.1:8080/callback` و محدوده را `api` قرار دهید و تیک **Confidential** را بردارید، چون PKCE به کلاینت عمومی نیاز دارد.

سپس شناسهٔ برنامه را در متغیر محیطی قرار دهید.

```bash
export GITLAB_OAUTH_CLIENT_ID=your_application_id_here
```

##### مدل‌های گردش‌کار GitLab Duo Agent Platform (DAP)

مدل‌های گردش‌کار DAP مسیر اجرای دیگری دارند. فراخوانی ابزار را به‌جای گفت‌وگوی معمول عامل، از سرویس Duo Workflow Service یا DWS گیت‌لب عبور می‌دهند. وقتی مدل `duo-workflow-*` انتخاب شود، OpenCode مراحل زیر را انجام می‌دهد.

1. مدل‌های در دسترس را از فضای نام GitLab شما پیدا می‌کند.
2. اگر چند مدل موجود باشد، فهرستی برای انتخاب نمایش می‌دهد.
3. انتخاب مدل را روی دیسک نگه می‌دارد تا OpenCode در اجراهای بعدی سریع‌تر راه‌اندازی شود.
4. درخواست‌های اجرای ابزار را از سامانهٔ مجوز ابزارهای OpenCode عبور می‌دهد.

مدل‌های گردش‌کار DAP با الگوی `duo-workflow-*` نام‌گذاری می‌شوند و OpenCode فهرست آن‌ها را هنگام اجرا از نمونهٔ GitLab شما می‌گیرد.

:::note
مدل‌های گردش‌کار فقط زمانی شناسایی می‌شوند که اطلاعات ورود با `/connect` ذخیره شده باشد، چه از طریق OAuth و چه با توکن دسترسی شخصی. تنظیم متغیر محیطی `GITLAB_TOKEN` به‌تنهایی آغازگر این فرایند نیست.
:::

برای ارائه‌دهندگان بیشتر و قابلیت‌هایی مانند حافظهٔ نهان و محدودسازی نرخ درخواست، [مستندات Helicone](https://docs.helicone.ai) را ببینید.

#### تنظیمات اختیاری

اگر OpenCode مدل یا قابلیت Helicone را خودکار پیکربندی نمی‌کند، می‌توانید آن را دستی تعریف کنید.

شناسهٔ مدل‌هایی را که می‌خواهید اضافه کنید از [فهرست مدل‌های Helicone](https://helicone.ai/models) بگیرید.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Model ID (from Helicone's model directory page)
          "name": "GPT-4o", // Your own custom name for the model
        },
        "claude-sonnet-4-5-20250929": {
          "name": "Claude Sonnet 4.5",
        },
      },
    },
  },
}
```

#### سرآیندهای سفارشی

Helicone برای قابلیت‌هایی مانند حافظهٔ نهان، پیگیری کاربران و مدیریت نشست از سرآیندهای سفارشی پشتیبانی می‌کند. آن‌ها را با `options.headers` به تنظیمات ارائه‌دهنده اضافه کنید.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### پیگیری نشست‌ها

ویژگی [Sessions](https://docs.helicone.ai/features/sessions) در Helicone درخواست‌های مرتبط مدل زبانی را گروه‌بندی می‌کند. با افزونهٔ [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session) هر گفت‌وگوی OpenCode را خودکار به‌عنوان یک نشست در Helicone ثبت کنید.

```bash
npm install -g opencode-helicone-session
```

افزونه را به پیکربندی اضافه کنید.

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

افزونه سرآیندهای `Helicone-Session-Id` و `Helicone-Session-Name` را به درخواست‌ها اضافه می‌کند. در صفحهٔ Sessions در Helicone، هر گفت‌وگوی OpenCode به‌صورت نشستی جدا نمایش داده می‌شود.

##### سرآیندهای رایج Helicone

| سرآیند | توضیحات |
| -------------------------- | ------------------------------------------------------------- |
| `Helicone-Cache-Enabled` | فعال‌سازی حافظهٔ نهان پاسخ (`true` یا `false`) |
| `Helicone-User-Id` | پیگیری معیارها به تفکیک کاربر |
| `Helicone-Property-[Name]` | افزودن ویژگی‌های سفارشی مانند `Helicone-Property-Environment` |
| `Helicone-Prompt-Id` | مرتبط کردن درخواست با نسخهٔ متن درخواست |

فهرست کامل را در [راهنمای سرآیندهای Helicone](https://docs.helicone.ai/helicone-headers/header-directory) ببینید.

- `name` نامی است که برای ارائه‌دهنده در رابط کاربری نمایش داده می‌شود.
- `options.baseURL` نشانی نقطهٔ پایانی سرور محلی است.
- `models` شناسهٔ مدل‌ها را به تنظیمات آن‌ها نگاشت می‌کند. نام مدل در فهرست انتخاب مدل نمایش داده می‌شود.

:::tip
اگر فراخوانی ابزار کار نمی‌کند، `num_ctx` را در Ollama افزایش دهید. برای شروع مقداری بین ۱۶ تا ۳۲ هزار را امتحان کنید.
:::

#### استقرار Poolside

اگر سازمان شما نمونهٔ Poolside خودش را اجرا می‌کند، آن را به‌عنوان ارائه‌دهندهٔ سفارشی سازگار با OpenAI تنظیم کنید. کلید API یا توکن دریافتی از مدیر Poolside را در `~/.secrets/poolside-key` ذخیره کنید. یک شناسهٔ یکتای ارائه‌دهنده و شناسهٔ مدل‌های موجود در استقرار خود را وارد کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "poolside-deployment": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Poolside deployment",
      "options": {
        "baseURL": "https://poolside.example.com/openai/v1",
        "apiKey": "{file:~/.secrets/poolside-key}"
      },
      "models": {
        "<served-model-id>": {
          "name": "Poolside deployment model",
          "reasoning": true,
          "interleaved": {
            "field": "reasoning_content"
          }
        }
      }
    }
  }
}
```

به‌جای `poolside.example.com` نام میزبان استقرار و به‌جای `<served-model-id>` شناسهٔ یکی از مدل‌های بازگردانده‌شده از مسیر `/openai/v1/models` را بنویسید. مدل‌های در دسترس و رفتار استدلال آن‌ها به تنظیمات همان استقرار بستگی دارد.

:::tip
برای استفادهٔ مستقیم از عامل‌های Poolside در ترمینال، می‌توانید [Poolside Agent CLI](https://github.com/poolsideai/pool) را نیز نصب کنید.
:::

### Snowflake Cortex

[Snowflake Cortex](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api) مدل‌های پیشرفته مانند Claude و GPT-5 شرکت OpenAI را با API سازگار با OpenAI در دسترس می‌گذارد. تمام استنتاج در محدودهٔ زیرساخت Snowflake انجام می‌شود و هزینه با اعتبار Snowflake محاسبه می‌شود. برای نرخ هر مدل، [جدول مصرف خدمات Snowflake](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf) را ببینید.

اگر حساب Snowflake ندارید، [برای دورهٔ آزمایشی رایگان ثبت‌نام کنید](https://signup.snowflake.com/?utm_source=opencode&utm_medium=docs&utm_campaign=cortex-provider).

OpenCode برای کدنویسی، ویرایش فایل و اجرای فرمان به فراخوانی ابزار متکی است. در Snowflake Cortex فقط مدل‌های دو خانوادهٔ Claude و OpenAI این قابلیت را دارند. به همین دلیل این ارائه‌دهنده در OpenCode به همین دو خانواده محدود است.

OpenCode دو روش احراز هویت دارد.

- **OAuth در مرورگر (پیشنهادی)**: با ارائه‌دهندهٔ هویت سازمان یا SSO وارد شوید. نیازی به نگهداری اطلاعات محرمانهٔ ورود ندارید و توکن‌ها خودکار تازه می‌شوند.
- **توکن حامل دستی**: یک PAT یا JWT را از کنسول Snowflake وارد کنید.

#### OAuth در مرورگر (پیشنهادی)

1. فرمان `/connect` را اجرا و **Snowflake Cortex** را جست‌وجو کنید.

   ```txt
   /connect
   ```

2. **Login with Snowflake (External Browser)** را انتخاب کنید.

   ```txt
   ┌ Select auth method
   │
   │ Login with Snowflake (External Browser)
   │ Paste PAT or bearer token manually
   └
   ```

3. هنگام درخواست، [شناسهٔ حساب](https://docs.snowflake.com/en/user-guide/admin-account-identifier) خود را وارد کنید، مثلاً `myorg-myaccount` یا `xy12345.us-east-1`.

   ```txt
   ┌ Snowflake Account Identifier
   │
   │
   └ enter
   ```

4. برای محدود کردن دسترسی نشست می‌توانید نقش Snowflake مانند `SYSADMIN` را وارد کنید. اگر خالی بگذارید، نقش پیش‌فرض شما استفاده می‌شود.

5. ورود را در مرورگری که باز می‌شود کامل کنید. OpenCode نتیجهٔ OAuth را خودکار دریافت و توکن را ذخیره می‌کند. نیازی به کپی کردن دستی نیست.

6. با فرمان `/models` یک مدل انتخاب کنید.

   ```txt
   /models
   ```

:::note
OAuth مرورگر از قابلیت امنیتی داخلی Snowflake به نام `SNOWFLAKE$LOCAL_APPLICATION` استفاده می‌کند که به‌تدریج برای همهٔ حساب‌ها فعال می‌شود. برای جزئیات، [مستندات](https://docs.snowflake.com/en/user-guide/oauth-local-applications) را ببینید. برای بررسی دسترسی حساب خود، فرمان زیر را اجرا کنید.

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

اگر نتیجه خالی است، تا زمان فعال شدن قابلیت در حساب خود از روش **توکن حامل دستی** استفاده کنید.
:::

#### توکن حامل دستی

اگر ترجیح می‌دهید توکن را مستقیماً وارد کنید یا `SNOWFLAKE$LOCAL_APPLICATION` هنوز در حساب شما در دسترس نیست، این مراحل را انجام دهید.

1. در حساب Snowflake یک [توکن دسترسی برنامه‌ای (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) بسازید.

2. `/connect` را اجرا کنید، **Snowflake Cortex** را بیابید و **Paste PAT or bearer token manually** را انتخاب کنید.

3. هنگام درخواست، [شناسهٔ حساب](https://docs.snowflake.com/en/user-guide/admin-account-identifier) را وارد کنید.

4. توکن PAT را جای‌گذاری کنید.

5. با فرمان `/models` یک مدل انتخاب کنید.

   ```txt
   /models
   ```

#### متغیر محیطی

برای CI یا محیط بدون رابط کاربری، پیش از اجرای OpenCode یک PAT یا JWT تعیین کنید.

```bash
export SNOWFLAKE_ACCOUNT=myorg-myaccount
export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` فقط PAT یا JWT می‌پذیرد. احراز هویت مرورگر با OAuth فقط از طریق `/connect` آغاز می‌شود و با متغیر محیطی قابل تنظیم نیست. برای سازگاری با پیکربندی‌های قدیمی، `SNOWFLAKE_CORTEX_PAT` نیز پذیرفته می‌شود.
:::

فهرست مدل‌ها خودکار فراهم می‌شود. برای `opencode.json` همین پیکربندی کوتاه کافی است.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "snowflake-cortex/claude-sonnet-5",
  "small_model": "snowflake-cortex/claude-haiku-4-5"
}
```

## ارائه‌دهندهٔ سفارشی

برای افزودن ارائه‌دهندهٔ **سازگار با OpenAI** که در `/connect` فهرست نشده است، مراحل زیر را انجام دهید.

:::tip
در OpenCode می‌توانید از هر ارائه‌دهندهٔ سازگار با OpenAI استفاده کنید. بیشتر ارائه‌دهندگان جدید API سازگار با OpenAI دارند.
:::

1. فرمان `/connect` را اجرا کنید و در انتهای فهرست **Other** را انتخاب کنید.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. برای ارائه‌دهنده یک شناسهٔ یکتا وارد کنید.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   شناسه‌ای انتخاب کنید که به خاطر بسپارید. در فایل پیکربندی به آن نیاز دارید.
   :::

3. کلید API ارائه‌دهنده را وارد کنید.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in opencode.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. در پوشهٔ پروژه فایل `opencode.json` را بسازید یا به‌روز کنید.

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI Provider Display Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   گزینه‌های پیکربندی عبارت‌اند از:
   - **npm**: بستهٔ AI SDK مورد استفاده. برای ارائه‌دهندگان سازگار با OpenAI و مسیر `/v1/chat/completions` از `@ai-sdk/openai-compatible` استفاده کنید. اگر مدل یا ارائه‌دهنده مسیر `/v1/responses` را به کار می‌برد، `@ai-sdk/openai` را بدهید.
   - **name**: نام نمایشی در رابط کاربری
   - **models**: مدل‌های در دسترس
   - **options.baseURL**: نشانی نقطهٔ پایانی API
   - **options.apiKey**: در صورت استفاده نکردن از روش احراز هویت، می‌توانید کلید API را اینجا تعیین کنید.
   - **options.headers**: برای تعیین سرآیندهای سفارشی به‌صورت اختیاری

   نمونهٔ زیر گزینه‌های پیشرفته‌تر را نشان می‌دهد.

5. با اجرای `/models`، ارائه‌دهندهٔ سفارشی و مدل‌های آن را در فهرست انتخاب می‌بینید.

---

##### مثال

در این نمونه، `apiKey` و `headers` و گزینهٔ `limit` مدل تعیین شده‌اند.

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI Provider Display Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

جزئیات پیکربندی:

- **apiKey**: با نحو متغیر `env` تعیین می‌شود. [راهنمای متغیرهای محیطی](/docs/config#env-vars) را ببینید.
- **headers**: سرآیندهای سفارشی که همراه هر درخواست ارسال می‌شوند.
- **limit.context**: حداکثر تعداد توکن‌های ورودی که مدل می‌پذیرد.
- **limit.output**: حداکثر تعداد توکن‌هایی که مدل می‌تواند تولید کند.

با فیلدهای `limit`،‏ OpenCode ظرفیت باقی‌ماندهٔ زمینه را محاسبه می‌کند. برای ارائه‌دهندگان استاندارد، این مقادیر خودکار از models.dev دریافت می‌شوند.

## عیب‌یابی

اگر در پیکربندی ارائه‌دهنده به مشکل خوردید، این موارد را بررسی کنید.

1. **تنظیم احراز هویت**: `opencode auth list` را اجرا کنید و ببینید اطلاعات دسترسی ارائه‌دهنده به پیکربندی اضافه شده است یا خیر.

   این بررسی دربارهٔ ارائه‌دهندگانی مانند Amazon Bedrock که برای احراز هویت به متغیر محیطی متکی‌اند صدق نمی‌کند.

2. برای ارائه‌دهندهٔ سفارشی، این موارد را در پیکربندی OpenCode بررسی کنید.
   - شناسهٔ ارائه‌دهنده در فرمان `/connect` باید با شناسهٔ آن در پیکربندی OpenCode یکسان باشد.
   - بستهٔ npm باید با ارائه‌دهنده مطابقت داشته باشد. برای نمونه، برای Cerebras از `@ai-sdk/cerebras` استفاده کنید. برای دیگر ارائه‌دهندگان سازگار با OpenAI و مسیر `/v1/chat/completions`، از `@ai-sdk/openai-compatible` و برای مدل‌های دارای مسیر `/v1/responses` از `@ai-sdk/openai` استفاده کنید. اگر یک ارائه‌دهنده ترکیبی از این مدل‌ها را دارد، با `provider.npm` می‌توانید بسته را برای هر مدل جداگانه تعیین کنید.
   - در فیلد `options.baseURL` نشانی درست نقطهٔ پایانی API را وارد کنید.
