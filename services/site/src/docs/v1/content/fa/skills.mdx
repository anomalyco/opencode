title: مهارت‌های عامل

---

با مهارت‌ها می‌توانید دستورالعمل‌هایی را در مخزن یا پوشهٔ خانگی خود نگه دارید تا OpenCode بارها از آن‌ها استفاده کند. عامل فهرست مهارت‌ها را می‌بیند و هنگام نیاز با ابزار داخلی `skill` متن کامل هر مهارت را می‌خواند.

---

## محل فایل‌ها

برای هر مهارت، پوشه‌ای هم‌نام آن بسازید و فایل `SKILL.md` را در آن قرار دهید. OpenCode این مسیرها را جست‌وجو می‌کند.

- پیکربندی پروژه: `.opencode/skills/<name>/SKILL.md`
- پیکربندی سراسری: `~/.config/opencode/skills/<name>/SKILL.md`
- مسیر سازگار با Claude در پروژه: `.claude/skills/<name>/SKILL.md`
- مسیر سراسری سازگار با Claude: `~/.claude/skills/<name>/SKILL.md`
- مسیر مشترک عامل‌ها در پروژه: `.agents/skills/<name>/SKILL.md`
- مسیر سراسری مشترک عامل‌ها: `~/.agents/skills/<name>/SKILL.md`

---

## نحوهٔ پیدا کردن مهارت‌ها

در پروژه، OpenCode از پوشهٔ کاری فعلی به سمت ریشهٔ درخت کاری Git پیش می‌رود. در این مسیر فایل‌های مطابق با `skills/*/SKILL.md` در `.opencode/` و فایل‌های مطابق با `.claude/skills/*/SKILL.md` یا `.agents/skills/*/SKILL.md` را بارگذاری می‌کند.

تعریف‌های سراسری نیز از مسیرهای `~/.config/opencode/skills/*/SKILL.md`، `~/.claude/skills/*/SKILL.md` و `~/.agents/skills/*/SKILL.md` بارگذاری می‌شوند.

---

## نوشتن فرادادهٔ آغاز فایل

هر فایل `SKILL.md` باید با فراداده‌ای به قالب YAML آغاز شود. فیلدهای زیر برای تعریف مهارت در دسترس‌اند.

- `name` (الزامی)
- `description` (الزامی)
- `license` (اختیاری)
- `compatibility` (اختیاری)
- `metadata` (اختیاری، نگاشت رشته به رشته)

OpenCode فیلدهای ناشناخته را نادیده می‌گیرد. در OpenCode 1، فرادادهٔ مهارت در کنترل فرمان‌های اسلش یا انتخاب خودکار مهارت نقشی ندارد.

---

## اعتبارسنجی نام‌ها

مقدار `name` باید شرایط زیر را داشته باشد.

- بین ۱ تا ۶۴ نویسه باشد.
- فقط از حروف کوچک لاتین و رقم تشکیل شود. برای جدا کردن بخش‌ها می‌توان یک خط تیره گذاشت.
- با `-` آغاز یا تمام نشود.
- شامل دو خط تیرهٔ متوالی (`--`) نباشد.
- با نام پوشهٔ حاوی `SKILL.md` یکسان باشد.

عبارت باقاعدهٔ معادل به این شکل است.

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

---

## محدودیت طول

مقدار `description` باید بین ۱ تا ۱۰۲۴ نویسه باشد. کاربرد مهارت را دقیق بنویسید تا عامل بتواند آن را درست انتخاب کند.

---

## نمونهٔ مهارت

فایل `.opencode/skills/git-release/SKILL.md` را با محتوای زیر بسازید.

```markdown
---
name: git-release
description: تهیهٔ نسخه‌های انتشار و فهرست تغییرات با قالبی یکسان
license: MIT
compatibility: opencode
metadata:
  audience: maintainers
  workflow: github
---

## کارهایی که انجام می‌دهم

- نوشتن پیش‌نویس یادداشت‌های انتشار از روی درخواست‌های ادغام پذیرفته‌شده
- پیشنهاد شمارهٔ نسخهٔ بعدی
- آماده کردن فرمان `gh release create` برای کپی و اجرا

## زمان استفاده

هنگام آماده‌سازی یک انتشار با برچسب Git، از این مهارت استفاده کن.
اگر روش شماره‌گذاری نسخه روشن نیست، دربارهٔ آن سؤال کن.
```

---

## توضیحات ابزار

OpenCode در توضیحات ابزار `skill` نام و شرح هر مهارتِ در دسترس را فهرست می‌کند.

```xml
<available_skills>
  <skill>
    <name>git-release</name>
    <description>تهیهٔ نسخه‌های انتشار و فهرست تغییرات با قالبی یکسان</description>
  </skill>
</available_skills>
```

عامل برای خواندن مهارت، ابزار را به این شکل فراخوانی می‌کند.

```
skill({ name: "git-release" })
```

## تنظیم مجوزها

در `opencode.json` با تعریف مجوزهای مبتنی بر الگو تعیین کنید که عامل‌ها به کدام مهارت‌ها دسترسی داشته باشند.

```json
{
  "permission": {
    "skill": {
      "*": "allow",
      "pr-review": "allow",
      "internal-*": "deny",
      "experimental-*": "ask"
    }
  }
}
```

| مجوز | رفتار |
| ---------- | ----------------------------------------- |
| `allow` | مهارت بلافاصله بارگذاری می‌شود. |
| `deny` | مهارت از دید عامل پنهان می‌ماند و درخواست دسترسی رد می‌شود. |
| `ask` | پیش از بارگذاری از کاربر تأیید گرفته می‌شود. |

می‌توانید در الگوها از نویسهٔ عام استفاده کنید. برای نمونه، `internal-*` با `internal-docs` و `internal-tools` مطابقت دارد.

---

## تنظیم مجوز برای هر عامل

برای هر عامل می‌توانید مجوزهایی متفاوت با پیش‌فرض‌های سراسری تعیین کنید.

**برای عامل سفارشی**، در فرادادهٔ آغاز فایل عامل بنویسید.

```yaml
---
permission:
  skill:
    "documents-*": "allow"
---
```

**برای عامل داخلی**، در `opencode.json` بنویسید.

```json
{
  "agent": {
    "plan": {
      "permission": {
        "skill": {
          "internal-*": "allow"
        }
      }
    }
  }
}
```

---

## غیرفعال کردن ابزار مهارت

برای عامل‌هایی که نباید از مهارت‌ها استفاده کنند، این ابزار را به‌کلی غیرفعال کنید.

**برای عامل سفارشی**:

```yaml
---
tools:
  skill: false
---
```

**برای عامل داخلی**:

```json
{
  "agent": {
    "plan": {
      "tools": {
        "skill": false
      }
    }
  }
}
```

با غیرفعال شدن این ابزار، بخش `<available_skills>` به‌کلی حذف می‌شود.

---

## عیب‌یابی بارگذاری

اگر مهارتی نمایش داده نمی‌شود، این موارد را بررسی کنید.

1. نام فایل `SKILL.md` باید با حروف بزرگ نوشته شده باشد.
2. فرادادهٔ آغاز فایل باید هر دو فیلد `name` و `description` را داشته باشد.
3. هر مهارت باید در میان تمام مسیرها نامی یکتا داشته باشد.
4. مجوزها را بررسی کنید. عامل مهارت‌هایی را که مجوز `deny` دارند نمی‌بیند.
