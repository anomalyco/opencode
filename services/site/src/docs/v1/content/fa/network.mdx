در شبکه‌های سازمانی می‌توانید برای OpenCode از متغیرهای محیطی استانداردِ پراکسی و گواهی‌های سفارشی استفاده کنید.

---

## پراکسی

برای تنظیم پراکسی در OpenCode، متغیرهای زیر را در محیط اجرا مقداردهی کنید.

```bash
# پراکسی HTTPS (پیشنهادی)
export HTTPS_PROXY=https://proxy.example.com:8080

# پراکسی HTTP (اگر HTTPS در دسترس نیست)
export HTTP_PROXY=http://proxy.example.com:8080

# برای اتصال به سرور محلی از پراکسی استفاده نکنید (ضروری)
export NO_PROXY=localhost,127.0.0.1
```

:::caution
رابط ترمینالی با یک سرور محلی HTTP ارتباط دارد. برای جلوگیری از حلقهٔ مسیریابی، این ارتباط را از پراکسی عبور ندهید.
:::

می‌توانید پورت و نام میزبان سرور را با [گزینه‌های خط فرمان](/docs/cli#run) تنظیم کنید.

---

### احراز هویت

اگر پراکسی به احراز هویت پایه نیاز دارد، نشانی آن باید نام کاربری و گذرواژه را داشته باشد.

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

:::caution
گذرواژه را مستقیم در کد یا فایل تنظیمات ننویسید. آن را از متغیر محیطی یا مخزن امن اطلاعات ورود بخوانید.
:::

اگر پراکسی به احراز هویت پیشرفته‌ای مانند NTLM یا Kerberos نیاز دارد، می‌توانید از یک درگاه مدل زبانی استفاده کنید که از همان روش پشتیبانی کند.

---

## گواهی‌های سفارشی

اگر سازمان شما برای اتصال‌های HTTPS از مرجع صدور گواهی (CA) اختصاصی استفاده می‌کند، مسیر گواهی آن را به OpenCode بدهید تا آن را معتبر بشناسد.

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

این تنظیم هم برای اتصال از طریق پراکسی و هم برای دسترسی مستقیم به API کاربرد دارد.
