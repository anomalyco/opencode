---
title: قواعد
description: تعیین دستورالعمل‌های اختصاصی برای OpenCode.
---

با ساخت فایل `AGENTS.md` می‌توانید مانند قواعد Cursor، دستورالعمل‌های دلخواه را به OpenCode بدهید. این دستورالعمل‌ها در زمینهٔ کاری مدل زبانی قرار می‌گیرند و رفتار آن را با پروژهٔ شما هماهنگ می‌کنند.

---

## راه‌اندازی اولیه

برای ساخت فایل `AGENTS.md`، فرمان `/init` را در OpenCode اجرا کنید.

:::tip
فایل `AGENTS.md` پروژه را در Git ثبت کنید.
:::

فرمان `/init` فایل‌های مهم مخزن را بررسی می‌کند و اگر پاسخ نکته‌ای از کد مشخص نباشد، ممکن است چند سؤال تکمیلی بپرسد. سپس راهنمای کوتاه و ویژهٔ پروژه را در `AGENTS.md` می‌نویسد یا به‌روز می‌کند.

این راهنما بر اطلاعاتی تمرکز دارد که عامل احتمالاً در نشست‌های بعدی لازم خواهد داشت.

- فرمان‌های ساخت پروژه، تحلیل ایستا و اجرای آزمون‌ها
- ترتیب اجرای فرمان‌ها و مراحل بررسی متمرکز، در مواردی که اهمیت دارند
- معماری و ساختار مخزن، در مواردی که از نام فایل‌ها مشخص نمی‌شوند
- قراردادهای ویژهٔ پروژه، نکات راه‌اندازی و مشکلات رایج هنگام کار
- ارجاع به دستورالعمل‌های موجود مانند قواعد Cursor یا Copilot

اگر فایل `AGENTS.md` از قبل وجود داشته باشد، `/init` همان فایل را بهبود می‌دهد و محتوای آن را کورکورانه بازنویسی نمی‌کند.

---

## مثال

می‌توانید فایل را دستی هم بسازید. نمونهٔ زیر نشان می‌دهد چه اطلاعاتی را می‌توان در `AGENTS.md` قرار داد.

```markdown title="AGENTS.md"
# پروژهٔ چندبسته‌ای SST v3

این مخزن چندبسته‌ای با SST v3 و TypeScript ساخته شده است. مدیریت بسته‌ها با workspaceهای Bun انجام می‌شود.

## ساختار پروژه

- `packages/` - شامل بسته‌های فضای کاری، از جمله functions، core و web
- `infra/` - تعریف زیرساخت هر سرویس در فایلی جداگانه (storage.ts، api.ts و web.ts)
- `sst.config.ts` - پیکربندی اصلی SST با importهای پویا

## استانداردهای کدنویسی

- در TypeScript حالت strict را فعال کن.
- کد مشترک را با تنظیم درست exports در `packages/core/` قرار بده.
- توابع را در `packages/functions/` قرار بده.
- فایل‌های زیرساخت را بر اساس وظیفه در `infra/` جدا کن.

## قراردادهای مخزن چندبسته‌ای

- برای وارد کردن ماژول مشترک از نام بسته در فضای کاری استفاده کن، مانند `@my-app/core/example`.
```

دستورالعمل‌های این نمونه ویژهٔ پروژه‌اند و در اختیار همهٔ اعضای تیم قرار می‌گیرند.

---

## انواع قواعد

OpenCode فایل `AGENTS.md` را از چند محل می‌خواند. هر محل کاربرد متفاوتی دارد.

### قواعد پروژه

برای قواعد ویژهٔ پروژه، `AGENTS.md` را در ریشهٔ پروژه قرار دهید. این قواعد فقط هنگام کار در همان پوشه یا زیرپوشه‌های آن اعمال می‌شوند.

### قواعد سراسری

در فایل `~/.config/opencode/AGENTS.md` می‌توانید قواعدی تعیین کنید که در همهٔ نشست‌های OpenCode اعمال شوند.

این فایل در Git ثبت نمی‌شود و با تیم به اشتراک گذاشته نمی‌شود. جای مناسبی برای دستورالعمل‌های شخصی شما به مدل زبانی است.

### سازگاری با Claude Code

اگر از Claude Code مهاجرت می‌کنید، OpenCode در نبود فایل‌های خودش این فایل‌های Claude Code را هم می‌خواند.

- **قواعد پروژه**: فایل `CLAUDE.md` در پوشهٔ پروژه، اگر `AGENTS.md` وجود نداشته باشد.
- **قواعد سراسری**: فایل `~/.claude/CLAUDE.md`، اگر `~/.config/opencode/AGENTS.md` وجود نداشته باشد.
- **مهارت‌ها**: پوشهٔ `~/.claude/skills/`. جزئیات را در [راهنمای مهارت‌های عامل](/docs/skills/) ببینید.

برای غیرفعال کردن سازگاری با Claude Code، یکی از متغیرهای محیطی زیر را تنظیم کنید.

```bash
export OPENCODE_DISABLE_CLAUDE_CODE=1        # Disable all .claude support
export OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1 # Disable only ~/.claude/CLAUDE.md
export OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1 # Disable only .claude/skills
```

## ترتیب اولویت

OpenCode هنگام راه‌اندازی به‌ترتیب زیر به دنبال فایل‌های قواعد می‌گردد.

1. **فایل‌های محلی** با پیمایش پوشه‌ها از پوشهٔ جاری به سمت بالا (`AGENTS.md` و `CLAUDE.md`)
2. **فایل سراسری** در `~/.config/opencode/AGENTS.md`
3. **فایل Claude Code** در `~/.claude/CLAUDE.md`، مگر اینکه غیرفعال باشد

در هر دسته، نخستین فایل منطبق اولویت دارد. برای نمونه، اگر هم `AGENTS.md` و هم `CLAUDE.md` وجود داشته باشند، فقط `AGENTS.md` استفاده می‌شود. به همین ترتیب، `~/.config/opencode/AGENTS.md` بر `~/.claude/CLAUDE.md` اولویت دارد.

## دستورالعمل‌های سفارشی

فایل‌های دستورالعمل دلخواه را در `opencode.json` پروژه یا فایل سراسری `~/.config/opencode/opencode.json` معرفی کنید. به این ترتیب شما و همکارانتان می‌توانید قواعد موجود را بدون تکرار آن‌ها در AGENTS.md به کار ببرید.

مثال:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines.md", ".cursor/rules/*.md"]
}
```

با نشانی اینترنتی می‌توانید دستورالعمل‌ها را از وب بارگذاری کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["https://raw.githubusercontent.com/my-org/shared-rules/main/style.md"]
}
```

مهلت دریافت دستورالعمل از راه دور ۵ ثانیه است.

محتوای همهٔ فایل‌های دستورالعمل با فایل‌های `AGENTS.md` شما ترکیب می‌شود.

---

## ارجاع به فایل‌های بیرونی

OpenCode ارجاع‌های فایل در `AGENTS.md` را خودکار دنبال نمی‌کند. برای در اختیار گذاشتن فایل‌های دیگر دو روش دارید.

### استفاده از opencode.json

روش پیشنهادی، تعیین فیلد `instructions` در `opencode.json` است.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["docs/development-standards.md", "test/testing-guidelines.md", "packages/*/AGENTS.md"]
}
```

### دستورالعمل صریح در AGENTS.md

با نوشتن دستورالعمل صریح در `AGENTS.md`، می‌توانید از OpenCode بخواهید فایل‌های بیرونی را بخواند. نمونهٔ زیر این روش را نشان می‌دهد.

```markdown title="AGENTS.md"
# قواعد پروژهٔ TypeScript

## بارگذاری فایل‌های بیرونی

مهم: وقتی با ارجاع به یک فایل مانند @rules/general.md روبه‌رو شدی، تنها در صورت نیاز به آن برای کار جاری، فایل را با ابزار Read بخوان.

Instructions:

- همهٔ فایل‌های مرجع را از پیش بارگذاری نکن. هر فایل را هنگامی بخوان که واقعاً به آن نیاز داری.
- پس از بارگذاری فایل، محتوای آن را دستورالعملی الزامی بدان که بر پیش‌فرض‌ها اولویت دارد.
- در صورت نیاز، ارجاع‌های داخل فایل‌های مرجع را هم دنبال کن.

## راهنمای توسعه

برای شیوهٔ کدنویسی و توصیه‌های TypeScript: @docs/typescript-guidelines.md
برای معماری مؤلفه‌های React و الگوهای هوک‌ها: @docs/react-patterns.md
برای طراحی REST API و رسیدگی به خطاها: @docs/api-standards.md
برای روش‌های آزمون و میزان پوشش موردنیاز: @test/testing-guidelines.md

## راهنمای عمومی

فایل زیر را همین ابتدا بخوان. دستورالعمل‌های آن برای همهٔ کارها کاربرد دارند: @rules/general-guidelines.md.
```

با این روش می‌توانید:

- قواعد را در فایل‌های جدا و قابل استفادهٔ مجدد بنویسید.
- با پیوند نمادین یا زیرماژول Git، قواعد را میان پروژه‌ها به اشتراک بگذارید.
- AGENTS.md را کوتاه نگه دارید و برای جزئیات به راهنماهای دیگر ارجاع دهید.
- فایل‌ها را فقط زمانی در اختیار OpenCode بگذارید که کار مشخصی به آن‌ها نیاز دارد.

:::tip
در مخزن‌های چندپروژه‌ای یا پروژه‌هایی با استانداردهای مشترک، استفاده از الگوهای glob مانند `packages/*/AGENTS.md` در `opencode.json` نگهداری قواعد را آسان‌تر می‌کند.
:::
