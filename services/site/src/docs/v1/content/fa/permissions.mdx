---
title: مجوزها
description: تعیین کارهایی که برای اجرا به تأیید نیاز دارند.
---

OpenCode با تنظیم `permission` تعیین می‌کند که هر عملیات خودکار اجرا شود، نیاز به تأیید داشته باشد یا مسدود شود.

از نسخهٔ `v1.1.1`، تنظیم بولی قدیمی `tools` منسوخ و در `permission` ادغام شده است. برای سازگاری با پیکربندی‌های قبلی، `tools` همچنان پشتیبانی می‌شود.

---

## نتیجهٔ قواعد

هر قاعده یکی از این سه نتیجه را دارد.

- `"allow"` اجرای بدون تأیید
- `"ask"` درخواست تأیید از کاربر
- `"deny"` جلوگیری از اجرا

---

## حالت خودکار

OpenCode را با `--auto` اجرا کنید تا درخواست‌های مجوزی که صریحاً ممنوع نشده‌اند، به‌طور خودکار تأیید شوند.

```bash
opencode --auto
```

این حالت را می‌توانید با [`opencode run`](/docs/cli#run) نیز به کار ببرید.

```bash
opencode run --auto "این ماژول را بازآرایی کن"
```

قواعد صریح `"deny"` همچنان اعمال می‌شوند. حالت خودکار فقط روی درخواست‌هایی اثر دارد که در حالت عادی به تأیید نیاز دارند.

در فهرست فرمان‌های رابط ترمینالی، **Enable auto-approve permissions** یا **Disable auto-approve permissions** را انتخاب کنید. در حالت خودکار، نشان کم‌رنگ `auto` کنار نام عامل فعلی در کادر ورودی دیده می‌شود.

---

## پیکربندی

می‌توانید با `*` مجوز کلی تعیین کنید و برای ابزارهای مشخص استثنا بنویسید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "*": "ask",
    "bash": "allow",
    "edit": "deny"
  }
}
```

همچنین می‌توانید همهٔ مجوزها را هم‌زمان تعیین کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": "allow"
}
```

## قواعد جزئی با ساختار شیء

برای بیشتر مجوزها می‌توانید یک شیء بنویسید تا نتیجه بر اساس ورودی ابزار تعیین شود.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "npm *": "allow",
      "rm *": "deny",
      "grep *": "allow"
    },
    "edit": {
      "*": "deny",
      "packages/web/src/content/docs/*.mdx": "allow"
    },
    "webfetch": "ask"
  }
}
```

قواعد با تطبیق الگو بررسی می‌شوند و **آخرین قاعدهٔ منطبق اولویت دارد**. معمولاً قاعدهٔ فراگیر `"*"` در آغاز و قواعد خاص‌تر پس از آن قرار می‌گیرند.

در OpenCode 1، گزینهٔ `webfetch` فقط `"allow"`، `"ask"` یا `"deny"` را می‌پذیرد و از اشیای حاوی الگوی نشانی وب پشتیبانی نمی‌کند.

### نویسه‌های عام

الگوهای مجوز از قواعد سادهٔ زیر پیروی می‌کنند.

- `*` با صفر یا چند نویسه مطابقت دارد.
- `?` دقیقاً با یک نویسه مطابقت دارد.
- دیگر نویسه‌ها فقط با خودشان مطابقت دارند.

### گسترش مسیر پوشهٔ خانگی

برای اشاره به پوشهٔ خانگی، الگو را با `~` یا `$HOME` آغاز کنید. این قابلیت به‌ویژه برای قواعد [`external_directory`](#external-directories) کاربرد دارد.

- `~/projects/*` -> `/Users/username/projects/*`
- `$HOME/projects/*` -> `/Users/username/projects/*`
- `~` -> `/Users/username`

### پوشه‌های خارجی

با `external_directory` به ابزارها اجازه دهید با مسیرهایی بیرون از پوشه‌ای که OpenCode در آن اجرا شده است کار کنند. این مجوز شامل هر ابزاری می‌شود که مسیر می‌گیرد، مانند `read`، `edit`، `glob`، `grep` و بسیاری از فرمان‌های `bash`.

گسترش مسیر خانگی مانند `~/...` فقط شیوهٔ نوشتن الگو را کوتاه می‌کند. مسیر بیرونی بخشی از فضای کاری فعلی نمی‌شود و همچنان باید آن را با `external_directory` مجاز کنید.

این نمونه دسترسی به همهٔ محتویات `~/projects/personal/` را مجاز می‌کند.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    }
  }
}
```

پوشه‌های مجاز این بخش همان پیش‌فرض‌های فضای کاری جاری را دارند. چون [پیش‌فرض `read` برابر با `allow` است](#defaults)، خواندن مسیرهای `external_directory` هم مجاز است، مگر اینکه آن را تغییر دهید. برای محدود کردن ابزار در این مسیرها، قاعده‌ای صریح بنویسید. برای مثال، ویرایش را مسدود و خواندن را مجاز نگه دارید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    },
    "edit": {
      "~/projects/personal/**": "deny"
    }
  }
}
```

فقط مسیرهای مورداعتماد را در فهرست بگذارید و در صورت نیاز برای ابزارهایی مانند `bash` قواعد اجازه یا منع اضافه کنید.

## مجوزهای موجود

نام بیشتر مجوزها همان نام ابزار مربوط است. دو مجوز دیگر نقش حفاظتی دارند.

- `read` برای خواندن فایل، با تطبیق مسیر فایل
- `edit` برای همهٔ تغییرات فایل، شامل `edit`، `write` و `patch`
- `glob` برای یافتن فایل، با تطبیق الگوی glob
- `grep` برای جست‌وجوی محتوا، با تطبیق عبارت باقاعده
- `bash` برای اجرای فرمان پوسته، با تطبیق فرمان تجزیه‌شده مانند `git status --porcelain`
- `task` برای اجرای زیرعامل، با تطبیق نوع آن
- `todowrite` برای به‌روز کردن فهرست کارهای نشست
- `skill` برای بارگذاری مهارت، با تطبیق نام آن
- `lsp` برای اجرای پرس‌وجوهای LSP (فعلاً بدون قواعد جزئی)
- `question` برای پرسش از کاربر هنگام اجرا
- `webfetch` برای دریافت یک نشانی وب (یک قاعده برای همهٔ نشانی‌ها)
- `websearch` برای جست‌وجو در وب
- `external_directory` هنگامی بررسی می‌شود که ابزاری با مسیری بیرون از پوشهٔ کاری پروژه کار کند.
- `doom_loop` وقتی اعمال می‌شود که یک ابزار سه بار پیاپی با ورودی یکسان فراخوانی شود.

## پیش‌فرض‌ها

اگر مجوزی تعیین نکنید، OpenCode بیشتر عملیات را مجاز می‌داند.

- پیش‌فرض بیشتر مجوزها `"allow"` است.
- پیش‌فرض `doom_loop` و `external_directory` برابر `"ask"` است.
- پیش‌فرض `read` برابر `"allow"` است، اما خواندن فایل‌های `.env` به تأیید نیاز دارد.

```json title="opencode.json"
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "ask",
      "*.env.*": "ask",
      "*.env.example": "allow"
    }
  }
}
```

---

## رفتار درخواست تأیید

هنگام درخواست تأیید، رابط کاربری سه انتخاب نشان می‌دهد.

- `once` فقط همین درخواست را تأیید می‌کند.
- `always` درخواست‌های آیندهٔ منطبق با الگوهای پیشنهادی را تا پایان نشست فعلی OpenCode مجاز می‌کند.
- `reject` درخواست را رد می‌کند.

ابزار الگوهای مشمول `always` را پیشنهاد می‌دهد. برای نمونه، ابزار bash معمولاً یک پیشوند امن مانند `git status*` را پیشنهاد می‌کند.

## عامل‌ها

می‌توانید مجوزهای هر عامل را جداگانه تعیین کنید. قواعد عامل با پیکربندی سراسری ترکیب می‌شوند و اولویت بالاتری دارند. [راهنمای مجوزهای عامل](/docs/agents#permissions) را ببینید.

:::note
برای نمونه‌های بیشترِ تطبیق الگو، بخش [قواعد جزئی با ساختار شیء](#granular-rules-object-syntax) را ببینید.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git commit *": "deny",
      "git push *": "deny",
      "grep *": "allow"
    }
  },
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git *": "allow",
          "git commit *": "ask",
          "git push *": "deny",
          "grep *": "allow"
        }
      }
    }
  }
}
```

مجوزهای عامل را می‌توانید در Markdown هم تعیین کنید.

```markdown title="~/.config/opencode/agents/review.md"
---
description: بازبینی کد بدون ویرایش
mode: subagent
permission:
  edit: deny
  bash: ask
  webfetch: deny
---

فقط کد را تحلیل کن و تغییرات پیشنهادی را توضیح بده.
```

:::tip
برای فرمان‌هایی که آرگومان می‌گیرند، از الگو استفاده کنید. `"grep *"` فرمان `grep pattern file.txt` را مجاز می‌کند، درحالی‌که `"grep"` به‌تنهایی آن را مسدود می‌کند. فرمانی مانند `git status` در حالت معمول کار می‌کند، اما برای اجرای آن با آرگومان باید الگویی مانند `"git status *"` را صریحاً مجاز کنید.
:::
