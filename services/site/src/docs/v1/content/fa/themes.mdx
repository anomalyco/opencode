OpenCode چندین پوستهٔ آماده دارد. می‌توانید پوسته‌ای هماهنگ با رنگ‌های ترمینال انتخاب کنید یا پوستهٔ خودتان را بسازید.

پوستهٔ پیش‌فرض OpenCode، `opencode` است.

---

## پیش‌نیازهای ترمینال

برای نمایش کامل رنگ‌های پوسته، ترمینال باید از **truecolor** (رنگ ۲۴ بیتی) پشتیبانی کند. این قابلیت در بیشتر ترمینال‌های جدید فعال است، اما گاهی باید آن را تنظیم کنید.

- **بررسی پشتیبانی**: فرمان `echo $COLORTERM` را اجرا کنید. خروجی باید `truecolor` یا `24bit` باشد.
- **فعال‌سازی truecolor**: متغیر محیطی `COLORTERM=truecolor` را در پروفایل پوستهٔ فرمان تنظیم کنید.
- **سازگاری ترمینال**: مطمئن شوید شبیه‌ساز ترمینال از رنگ ۲۴ بیتی پشتیبانی می‌کند. iTerm2، Alacritty، Kitty، Windows Terminal و نسخه‌های جدید GNOME Terminal از آن پشتیبانی می‌کنند.

بدون truecolor، ممکن است رنگ‌های پوسته با دقت کمتری یا با نزدیک‌ترین رنگ از مجموعهٔ ۲۵۶ رنگی نمایش داده شوند.

## پوستهٔ سیستم

پوستهٔ `system` رنگ‌هایش را خودکار با ترمینال هماهنگ می‌کند. برخلاف پوسته‌های با رنگ ثابت، پوستهٔ _system_ این‌گونه کار می‌کند.

- **طیف خاکستری** را بر اساس رنگ پس‌زمینهٔ ترمینال تولید می‌کند تا کنتراست مناسب باشد.
- **رنگ‌های ANSI** استاندارد (۰ تا ۱۵) را برای رنگ‌آمیزی نحوی کد و اجزای رابط به کار می‌برد تا با رنگ‌بندی ترمینال هماهنگ باشند.
- **ظاهر اصلی ترمینال** را حفظ می‌کند. مقدار `none` برای رنگ متن و پس‌زمینه باعث می‌شود رنگ‌های پیش‌فرض ترمینال به کار بروند.

این پوسته در موارد زیر مناسب است.

- می‌خواهید ظاهر OpenCode با ترمینال هم‌خوان باشد.
- رنگ‌بندی ترمینال را شخصی‌سازی کرده‌اید.
- ترجیح می‌دهید همهٔ برنامه‌های ترمینالی ظاهر یکسانی داشته باشند.

## انتخاب پوسته

با فرمان `/theme` فهرست پوسته‌ها را باز کنید و پوسته‌ای انتخاب کنید. نام پوسته را می‌توانید در `tui.json` هم تعیین کنید.

```json title="tui.json" {3}
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "tokyonight"
}
```

## پوسته‌های سفارشی

در OpenCode می‌توانید پوسته‌ها را با قالب JSON بسازید و تغییر دهید.

---

### ترتیب بارگذاری

پوسته‌ها به‌ترتیب زیر بارگذاری می‌شوند. اگر پوسته‌ای هم‌نام در چند مسیر باشد، مسیری که دیرتر بارگذاری می‌شود اولویت دارد.

1. **پوسته‌های داخلی** که همراه فایل اجرایی ارائه می‌شوند.
2. **پوشهٔ پیکربندی کاربر** در `~/.config/opencode/themes/*.json` یا `$XDG_CONFIG_HOME/opencode/themes/*.json`
3. **ریشهٔ پروژه** در `<project-root>/.opencode/themes/*.json`
4. **پوشهٔ کاری جاری** در `./.opencode/themes/*.json`

اگر در چند مسیر پوسته‌ای هم‌نام وجود داشته باشد، پوستهٔ مسیر با اولویت بالاتر استفاده می‌شود.

---

### ساخت پوسته

برای ساخت پوسته، در یکی از پوشه‌های پوسته‌ها یک فایل JSON بسازید.

برای پوستهٔ سراسری کاربر:

```bash no-frame
mkdir -p ~/.config/opencode/themes
vim ~/.config/opencode/themes/my-theme.json
```

برای پوستهٔ مخصوص پروژه:

```bash no-frame
mkdir -p .opencode/themes
vim .opencode/themes/my-theme.json
```

---

### قالب JSON

در JSON پوسته می‌توانید رنگ‌ها را به شکل‌های زیر تعریف کنید.

- **رنگ هگزادسیمال** مانند `"#ffffff"`
- **رنگ ANSI** مانند `3` (از ۰ تا ۲۵۵)
- **ارجاع به رنگ** مانند `"primary"` یا نامی که خودتان تعریف کرده‌اید
- **حالت تیره و روشن** مانند `{"dark": "#000", "light": "#fff"}`
- **بدون رنگ** با `"none"`، برای استفاده از رنگ پیش‌فرض ترمینال یا شفافیت

---

### تعریف رنگ‌ها

در بخش اختیاری `defs` می‌توانید رنگ‌هایی نام‌گذاری کنید و در بخش‌های مختلف پوسته به آن‌ها ارجاع دهید.

---

### پیش‌فرض‌های ترمینال

برای هر رنگ می‌توانید مقدار ویژهٔ `"none"` را بنویسید تا رنگ پیش‌فرض ترمینال استفاده شود. این روش برای ساخت پوسته‌ای هماهنگ با ترمینال کاربرد دارد.

- `"text": "none"` رنگ پیش‌فرض متن ترمینال را به کار می‌برد.
- `"background": "none"` رنگ پیش‌فرض پس‌زمینهٔ ترمینال را به کار می‌برد.
