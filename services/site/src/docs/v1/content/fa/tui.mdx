رابط تعاملی ترمینالی OpenCode یا TUI به شما امکان می‌دهد در پروژه‌های خود با مدل زبانی کار کنید.

با اجرای OpenCode، رابط ترمینالی برای پوشهٔ جاری باز می‌شود.

```bash
opencode
```

همچنین می‌توانید آن را برای پوشهٔ کاری مشخصی اجرا کنید.

```bash
opencode /path/to/project
```

پس از ورود به رابط ترمینالی، درخواست خود را به شکل پیام بنویسید.

```text
خلاصه‌ای کوتاه از کد پروژه بده.
```

---

## ارجاع به فایل‌ها

با `@` در پیام به فایل ارجاع دهید. OpenCode با تطبیق تقریبی نام، فایل را در پوشهٔ کاری جاری جست‌وجو می‌کند.

:::tip
برای اشاره به فایل در پیام از `@` استفاده کنید.
:::

```text "@packages/functions/src/api/index.ts"
در @packages/functions/src/api/index.ts احراز هویت چطور انجام می‌شود؟
```

محتوای فایل خودکار به گفت‌وگو افزوده می‌شود.

[منابع مرجع](/docs/references) تعریف‌شده نیز در تکمیل خودکار `@` ظاهر می‌شوند. با `@alias` ریشهٔ منبع را به زمینهٔ کاری اضافه کنید یا با `@alias/` فایل‌های داخل آن را پیدا کنید.

```text "@docs/README.md"
تنظیمات ما را با @docs/README.md مقایسه کن.
```

## فرمان‌های پوسته

برای اجرای یک فرمان پوسته، پیام را با `!` آغاز کنید.

```bash frame="none"
!ls -la
```

خروجی فرمان به‌عنوان نتیجهٔ ابزار به گفت‌وگو افزوده می‌شود.

---

## فرمان‌ها

در رابط ترمینالی، با نوشتن `/` و سپس نام فرمان می‌توانید عملیاتی را سریع اجرا کنید. برای مثال:

```bash frame="none"
/help
```

بیشتر فرمان‌ها میان‌بر صفحه‌کلید هم دارند. پیشوند پیش‌فرض میان‌برها `ctrl+x` است. [راهنمای میان‌برها](/docs/keybinds) را ببینید.

فرمان‌های اسلش در دسترس در ادامه آمده‌اند.

---

### connect

یک ارائه‌دهنده به OpenCode اضافه می‌کند. ارائه‌دهنده را از فهرست انتخاب و کلید API آن را وارد کنید.

```bash frame="none"
/connect
```

---

### compact

نشست جاری را فشرده می‌کند. _نام دیگر_: `/summarize`

```bash frame="none"
/compact
```

**میان‌بر:** `ctrl+x c`

---

### editor

ویرایشگر خارجی تعیین‌شده در متغیر محیطی `EDITOR` را برای نوشتن پیام باز می‌کند. [راهنمای تنظیم ویرایشگر](#editor-setup) را ببینید.

```bash frame="none"
/editor
```

**میان‌بر:** `ctrl+x e`

---

### exit

از OpenCode خارج می‌شود. _نام‌های دیگر_: `/quit` و `/q`

```bash frame="none"
/exit
```

**میان‌بر:** `ctrl+x q`

---

### export

گفت‌وگوی جاری را به Markdown صادر می‌کند و در ویرایشگر تعیین‌شده در متغیر محیطی `EDITOR` باز می‌کند. [راهنمای تنظیم ویرایشگر](#editor-setup) را ببینید.

```bash frame="none"
/export
```

**میان‌بر:** `ctrl+x x`

---

### help

پنجرهٔ راهنما را باز می‌کند.

```bash frame="none"
/help
```

---

### init

برای ساختن یا به‌روزرسانی `AGENTS.md` شما را راهنمایی می‌کند. [راهنمای قواعد](/docs/rules) را ببینید.

```bash frame="none"
/init
```

---

### models

مدل‌های در دسترس را فهرست می‌کند.

```bash frame="none"
/models
```

**میان‌بر:** `ctrl+x m`

---

### new

نشست تازه‌ای باز می‌کند. _نام دیگر_: `/clear`

```bash frame="none"
/new
```

**میان‌بر:** `ctrl+x n`

---

### redo

آخرین پیام لغوشده را دوباره اعمال می‌کند. این فرمان فقط پس از `/undo` در دسترس است.

:::tip
تغییرات مربوط به فایل‌ها هم دوباره اعمال می‌شوند.
:::

این قابلیت برای مدیریت تغییرات فایل‌ها از Git استفاده می‌کند، بنابراین **پروژه باید مخزن Git باشد**.

```bash frame="none"
/redo
```

**میان‌بر:** `ctrl+x r`

---

### sessions

نشست‌ها را فهرست می‌کند و امکان جابه‌جایی میان آن‌ها را می‌دهد. _نام‌های دیگر_: `/resume` و `/continue`

```bash frame="none"
/sessions
```

**میان‌بر:** `ctrl+x l`

---

### themes

پوسته‌های در دسترس را فهرست می‌کند.

```bash frame="none"
/themes
```

**میان‌بر:** `ctrl+x t`

---

### thinking

نمایش بخش‌های استدلال در گفت‌وگو را تغییر می‌دهد. اگر مدل از استدلال گسترده پشتیبانی کند، با فعال کردن این گزینه می‌توانید فرایند استدلال آن را ببینید.

:::note
این فرمان فقط **نمایش** بخش‌های استدلال را کنترل می‌کند. برای تغییر قابلیت استدلال مدل، با `ctrl+t` بین گونه‌های مدل جابه‌جا شوید.
:::

```bash frame="none"
/thinking
```

---

### undo

آخرین پیام کاربر و همهٔ پاسخ‌های پس از آن را از گفت‌وگو حذف می‌کند و تغییرات مربوط به آن‌ها را در فایل‌ها برمی‌گرداند.

:::tip
تغییرات انجام‌شده روی فایل‌ها نیز برگردانده می‌شوند.
:::

این قابلیت برای مدیریت تغییرات فایل‌ها از Git استفاده می‌کند، بنابراین **پروژه باید مخزن Git باشد**.

```bash frame="none"
/undo
```

**میان‌بر:** `ctrl+x u`

---

### update

وجود نسخهٔ تازهٔ OpenCode را بررسی و آن را نصب می‌کند. اگر نسخهٔ تازه‌تری از OpenCode 1 موجود باشد، پنجرهٔ به‌روزرسانی آن را نصب می‌کند. اگر همین حالا آخرین نسخهٔ ۱ را دارید، ارتقا به OpenCode 2 را پیشنهاد می‌دهد. OpenCode بدون اقدام شما به‌روزرسانی نصب نمی‌کند.

```bash frame="none"
/update
```

## تنظیم ویرایشگر

فرمان‌های `/editor` و `/export` از ویرایشگر تعیین‌شده در متغیر محیطی `EDITOR` استفاده می‌کنند.

<Tabs>
  <TabItem label="Linux/macOS">
    ```bash
    # Example for nano or vim
    export EDITOR=nano
    export EDITOR=vim

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    export EDITOR="code --wait"
    ```

    برای دائمی کردن تنظیم، آن را به پروفایل پوسته، مانند `~/.bashrc` یا `~/.zshrc`، اضافه کنید.

  </TabItem>

  <TabItem label="Windows (CMD)">
    ```bash
    set EDITOR=notepad

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    set EDITOR=code --wait
    ```

    برای دائمی کردن تنظیم، از **System Properties** > **Environment Variables** استفاده کنید.

  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    $env:EDITOR = "notepad"

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    $env:EDITOR = "code --wait"
    ```

    برای دائمی کردن تنظیم، آن را به پروفایل PowerShell اضافه کنید.

  </TabItem>
</Tabs>

از جمله ویرایشگرهای رایج:

- `code` - Visual Studio Code
- `cursor` - Cursor
- `windsurf` - Windsurf
- `nvim` برای ویرایشگر Neovim
- `vim` برای ویرایشگر Vim
- `nano` برای ویرایشگر Nano
- `notepad` برای Notepad ویندوز
- `subl` - Sublime Text

:::note
برخی ویرایشگرها مانند VS Code باید با گزینهٔ `--wait` اجرا شوند.
:::

بعضی ویرایشگرها برای معطل نگه‌داشتن فرایند فراخوان به آرگومان خط فرمان نیاز دارند. با `--wait` اجرای فرمان تا بسته شدن ویرایشگر ادامه پیدا نمی‌کند.

## پیکربندی

رفتار رابط ترمینالی را در `tui.json` یا `tui.jsonc` تغییر دهید.

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "opencode",
  "leader_timeout": 2000,
  "keybinds": {
    "leader": "ctrl+x",
    "command_list": "ctrl+p"
  },
  "scroll_speed": 3,
  "scroll_acceleration": {
    "enabled": false
  },
  "diff_style": "auto",
  "cursor": {
    "style": "block",
    "blinking": true
  },
  "mouse": true,
  "attention": {
    "enabled": true,
    "notifications": true,
    "sound": true,
    "volume": 0.4,
    "sound_pack": "opencode.default",
    "sounds": {
      "error": "./sounds/error.mp3"
    }
  }
}
```

پیکربندی سرور و محیط اجرا جداگانه در `opencode.json` قرار دارد.

تنظیم `keybinds` با پیش‌فرض‌های داخلی ادغام می‌شود، پس کافی است فقط میان‌برهایی را بنویسید که تغییر می‌دهید.

### گزینه‌ها

- `theme` پوستهٔ رابط را تعیین می‌کند. [راهنمای پوسته‌ها](/docs/themes) را ببینید.
- `keybinds` میان‌برهای صفحه‌کلید را تغییر می‌دهد. [راهنمای میان‌برها](/docs/keybinds) را ببینید.
- `leader_timeout` مدت انتظار پس از فشردن کلید پیشوند را تعیین می‌کند. پیش‌فرض آن `2000` است.
- `scroll_acceleration.enabled` شتاب پیمایش به سبک macOS را فعال می‌کند. حرکت‌های پیاپی سریع، سرعت پیمایش را بالا می‌برند و حرکت‌های آهسته دقیق می‌مانند. **در صورت فعال بودن، بر `scroll_speed` اولویت دارد.**
- `scroll_speed` سرعت فرمان‌های پیمایش در رابط ترمینالی است. کمترین مقدار `0.001` است، مقدار اعشاری پذیرفته می‌شود و پیش‌فرض `3` است. **اگر `scroll_acceleration.enabled` برابر `true` باشد، این گزینه نادیده گرفته می‌شود.**
- `diff_style` نحوهٔ نمایش تفاوت فایل‌ها را تعیین می‌کند. `"auto"` با عرض ترمینال هماهنگ می‌شود و `"stacked"` همیشه نمای تک‌ستونه دارد.
- `cursor` مکان‌نمای ترمینال در کادرهای ورودی را کنترل می‌کند. پیش‌فرض `style` برابر `"block"` است و می‌تواند `"underline"`، `"line"` یا `"default"` باشد. پیش‌فرض `blinking` برابر `true` است. وقتی `style` روی `"default"` باشد، مکان‌نمای پیش‌فرض ترمینال بازمی‌گردد و `blinking` اثری ندارد.
- `mouse` دریافت رویدادهای ماوس در رابط ترمینالی را کنترل می‌کند (پیش‌فرض `true`). با غیرفعال کردنش، انتخاب و پیمایش با ماوس طبق رفتار اصلی ترمینال انجام می‌شود.
- `attention` اعلان‌های دسکتاپ و صداهای رابط ترمینالی را تنظیم می‌کند. پیش‌فرض غیرفعال است.

با `OPENCODE_TUI_CONFIG` می‌توانید مسیر دلخواهی برای پیکربندی رابط ترمینالی تعیین کنید.

### اعلان‌ها

رابط ترمینالی می‌تواند هنگام پرسش، درخواست مجوز، خطای نشست یا پایان آن به شما اطلاع دهد. با `attention.enabled` این قابلیت را فعال کنید. رویدادهای داخلی صدا پخش می‌کنند. برای رویدادهایی که به زیرعامل مربوط نیستند، تنها زمانی اعلان دسکتاپ درخواست می‌شود که ترمینال در کانون نباشد.

- `enabled` همهٔ اعلان‌ها و صداها را فعال می‌کند. پیش‌فرض `false` است.
- `notifications` در صورت فعال بودن اعلان‌ها، ارسال اعلان دسکتاپ از طریق ترمینال را مجاز می‌کند. پیش‌فرض `true` است.
- `sound` در صورت فعال بودن اعلان‌ها، پخش صدا را مجاز می‌کند. پیش‌فرض `true` است.
- `volume` بلندی پیش‌فرض صدا از `0` تا `1` است. پیش‌فرض `0.4` است.
- `sound_pack` شناسهٔ مجموعه‌صداست. پیش‌فرض `opencode.default` است.
- `sounds` فایل‌های صدای `default`، `question`، `permission`، `error`، `done` یا `subagent_done` را تغییر می‌دهد. مسیرها می‌توانند مطلق، به‌شکل نشانی `file://` یا نسبت به `tui.json` باشند.

## شخصی‌سازی

با فهرست فرمان‌ها (`ctrl+p`) می‌توانید بخش‌های مختلف ظاهر رابط ترمینالی را تغییر دهید. پس از راه‌اندازی مجدد هم این تنظیمات حفظ می‌شوند.

---

#### نمایش نام کاربری

برای تغییر نمایش نام کاربری در پیام‌های گفت‌وگو، این کار را انجام دهید.

- در فهرست فرمان‌ها «username» یا «hide username» را جست‌وجو کنید.
- تنظیم خودکار ذخیره می‌شود و در نشست‌های بعدی رابط ترمینالی باقی می‌ماند.
