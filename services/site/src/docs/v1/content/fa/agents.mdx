عامل‌ها دستیارهای هوش مصنوعی‌اند که می‌توانید آن‌ها را برای کار یا روند مشخصی تنظیم کنید. برای هر عامل می‌توانید دستورالعمل، مدل و مجموعهٔ ابزار مناسب کارش را انتخاب کنید.

:::tip
برای تحلیل کد و بررسی پیشنهادها بدون تغییر دادن فایل‌ها از عامل Plan استفاده کنید.
:::

در طول نشست می‌توانید عامل اصلی را تغییر دهید یا با `@` یک عامل را فراخوانی کنید.

---

## انواع عامل

OpenCode دو نوع عامل دارد: عامل اصلی و زیرعامل.

---

### عامل‌های اصلی

عامل اصلی دستیار مستقیمی است که گفت‌وگو را با آن پیش می‌برید. با کلید **Tab** یا میان‌بر تنظیم‌شدهٔ `switch_agent` میان عامل‌های اصلی جابه‌جا شوید. مجوزها دسترسی به ابزارها را تعیین می‌کنند. برای نمونه، Build به همهٔ ابزارها دسترسی دارد و Plan محدودتر است.

:::tip
در طول نشست با کلید **Tab** عامل اصلی را عوض کنید.
:::

OpenCode دو عامل اصلی داخلی به نام‌های **Build** و **Plan** دارد که در ادامه معرفی می‌شوند.

---

### زیرعامل‌ها

زیرعامل دستیار تخصصی‌ای است که عامل اصلی می‌تواند برای کاری مشخص فراخوانی کند. شما هم می‌توانید با **نوشتن @ و نام زیرعامل** در پیام، مستقیماً آن را فراخوانی کنید.

دو زیرعامل داخلی OpenCode، یعنی **General** و **Explore**، در ادامه معرفی می‌شوند.

---

## عامل‌های داخلی

OpenCode دو عامل اصلی و سه زیرعامل داخلی دارد.

---

### کار با Build

_حالت_: `primary`

Build عامل اصلی **پیش‌فرض** است و همهٔ ابزارها در آن فعال‌اند. برای کارهای توسعه‌ای که به دسترسی کامل به فایل‌ها و فرمان‌های سیستم نیاز دارند از این عامل استفاده کنید.

---

### کار با Plan

_حالت_: `primary`

عاملی محدود برای تحلیل و برنامه‌ریزی است. وقتی می‌خواهید مدل کد را بررسی کند، تغییر پیشنهاد دهد یا برنامهٔ کار بنویسد، بدون اینکه کد را تغییر دهد، از Plan استفاده کنید.

رفتار پیش‌فرض Plan چنین است.

- ویرایش، نوشتن و اعمال وصله را جز در فایل‌های برنامهٔ کار به قالب Markdown در `.opencode/plans/` و پوشهٔ `plans/` زیر پوشهٔ داده‌های OpenCode رد می‌کند. برای سایر ویرایش‌ها حتی درخواست تأیید هم نمی‌کند.
- ابزار `question` را مجاز می‌کند تا بتواند برای روشن شدن ابهام‌ها از شما سؤال بپرسد.
- ابزار `bash` را محدود نمی‌کند. فرمان‌ها از پیکربندی [مجوزهای](/docs/permissions) شما پیروی می‌کنند.

اگر `OPENCODE_EXPERIMENTAL_PLAN_MODE` فعال باشد، Plan برنامهٔ کار را در پروژه‌های Git در `.opencode/plans/` و در سایر موارد در پوشهٔ `plans/` زیر پوشهٔ داده‌های OpenCode ذخیره می‌کند.

پیش‌فرض‌های Plan پیش از تنظیم سراسری `permission` اعمال می‌شوند و آخرین قاعدهٔ منطبق اولویت دارد. بنابراین قواعدی مانند `"edit": "allow"` یا `"*": "allow"` بر Plan هم اثر می‌گذارند. برای مسدود کردن همهٔ ویرایش‌ها و درخواست تأیید برای فرمان‌ها، مجوزها را مستقیماً برای این عامل تعیین کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  },
  "agent": {
    "plan": {
      "permission": {
        "edit": "deny",
        "bash": "ask"
      }
    }
  }
}
```

---

### کار با General

_حالت_: `subagent`

عامل همه‌منظوره برای بررسی پرسش‌های پیچیده و انجام کارهای چندمرحله‌ای. به همهٔ ابزارها جز `todowrite` دسترسی دارد و در صورت نیاز می‌تواند فایل تغییر دهد. از آن برای اجرای موازی چند کار مستقل استفاده کنید.

---

### کار با Explore

_حالت_: `subagent`

عاملی سریع و فقط‌خواندنی برای بررسی کد است. نمی‌تواند فایل‌ها را تغییر دهد. برای یافتن سریع فایل‌ها با الگو، جست‌وجوی کلیدواژه در کد یا پاسخ به پرسش‌های مربوط به پروژه مناسب است.

---

### عامل compaction

_حالت_: `primary`

عامل سیستمی پنهان است که زمینهٔ طولانی را به خلاصه‌ای کوتاه‌تر تبدیل می‌کند. هنگام نیاز خودکار اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

### عامل title

_حالت_: `primary`

عامل سیستمی پنهان است که عنوانی کوتاه برای نشست می‌سازد. خودکار اجرا می‌شود و در رابط قابل انتخاب نیست.

---

### عامل summary

_حالت_: `primary`

عامل سیستمی پنهان است که نشست‌ها را خلاصه می‌کند. خودکار اجرا می‌شود و در رابط قابل انتخاب نیست.

---

## نحوهٔ استفاده

1. برای جابه‌جایی میان عامل‌های اصلی در یک نشست، کلید **Tab** یا میان‌بر تنظیم‌شدهٔ `switch_agent` را بزنید.

2. زیرعامل‌ها به دو روش فراخوانی می‌شوند.
   - **خودکار**، به انتخاب عامل اصلی بر اساس توضیحات زیرعامل و نوع کار.
   - دستی، با **نوشتن @ و نام زیرعامل** در پیام، مانند نمونهٔ زیر.

     ```txt frame="none"
     @general help me search for this function
     ```

3. **جابه‌جایی میان نشست‌ها**: وقتی زیرعامل‌ها نشست فرزند می‌سازند، با `session_child_first` (پیش‌فرض **\<Leader>+Down**) از نشست والد وارد نخستین فرزند شوید.

4. در نشست فرزند، میان‌برهای زیر در دسترس‌اند.
   - `session_child_cycle` (پیش‌فرض **Right**) برای رفتن به نشست فرزند بعدی
   - `session_child_cycle_reverse` (پیش‌فرض **Left**) برای رفتن به نشست فرزند قبلی
   - `session_parent` (پیش‌فرض **Up**) برای بازگشت به نشست والد

   به این ترتیب می‌توانید میان گفت‌وگوی اصلی و کار تخصصی زیرعامل‌ها جابه‌جا شوید.

## پیکربندی

با پیکربندی می‌توانید عامل‌های داخلی را تغییر دهید یا عامل خودتان را بسازید. دو روش برای این کار وجود دارد.

---

### JSON

عامل‌ها را در فایل پیکربندی `opencode.json` تعریف کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-sonnet-5-5",
      "prompt": "{file:./prompts/build.txt}",
      "permission": {
        "edit": "allow",
        "bash": "allow"
      }
    },
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-haiku-5-5",
      "permission": {
        "edit": "deny",
        "bash": "deny"
      }
    },
    "code-reviewer": {
      "description": "بررسی کد از نظر رعایت اصول کدنویسی و یافتن مشکلات احتمالی",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-5-5",
      "prompt": "کد را بازبینی کن. روی امنیت، کارایی و امکان نگهداری کد تمرکز کن.",
      "permission": {
        "edit": "deny"
      }
    }
  }
}
```

---

### Markdown

عامل را در فایل Markdown هم می‌توانید تعریف کنید. فایل را در یکی از این مسیرها قرار دهید.

- سراسری: `~/.config/opencode/agents/`
- ویژهٔ پروژه: `.opencode/agents/`

```markdown title="~/.config/opencode/agents/review.md"
---
description: بررسی کیفیت کد و رعایت اصول کدنویسی
mode: subagent
model: anthropic/claude-sonnet-5-5
temperature: 0.1
permission:
  edit: deny
  bash: deny
---

در حالت بازبینی کد هستی. روی این موارد تمرکز کن:

- کیفیت کد و رعایت اصول کدنویسی
- ایرادهای احتمالی و حالت‌های مرزی
- تأثیر تغییرات بر کارایی
- ملاحظات امنیتی

بدون تغییر دادن مستقیم کد، بازخورد بده و راه بهبود را توضیح بده.
```

نام فایل Markdown نام عامل خواهد بود. برای نمونه، `review.md` عاملی با نام `review` می‌سازد.

## گزینه‌ها

گزینه‌های پیکربندی عامل در ادامه آمده‌اند.

---

### توضیحات

در `description` به‌اختصار بنویسید عامل چه کاری انجام می‌دهد و چه زمانی باید از آن استفاده کرد.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "description": "بررسی کد از نظر رعایت اصول کدنویسی و یافتن مشکلات احتمالی"
    }
  }
}
```

تعیین این گزینه **الزامی** است.

---

### دما

با گزینهٔ `temperature` میزان تصادفی بودن و خلاقیت پاسخ‌های مدل زبانی را تعیین کنید.

مقدار کمتر پاسخ را متمرکزتر و قابل‌پیش‌بینی‌تر می‌کند و مقدار بیشتر تنوع و خلاقیت را افزایش می‌دهد.

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "temperature": 0.1
    },
    "creative": {
      "temperature": 0.8
    }
  }
}
```

دما معمولاً بین ۰٫۰ و ۱٫۰ است.

- **۰٫۰ تا ۰٫۲**: پاسخ‌های بسیار متمرکز و قابل‌پیش‌بینی، مناسب تحلیل کد و برنامه‌ریزی
- **۰٫۳ تا ۰٫۵**: پاسخ‌های متعادل با کمی خلاقیت، مناسب کارهای معمول توسعه
- **۰٫۶ تا ۱٫۰**: پاسخ‌های خلاقانه‌تر و متنوع‌تر، مناسب ایده‌پردازی و بررسی گزینه‌ها

```json title="opencode.json"
{
  "agent": {
    "analyze": {
      "temperature": 0.1,
      "prompt": "{file:./prompts/analysis.txt}"
    },
    "build": {
      "temperature": 0.3
    },
    "brainstorm": {
      "temperature": 0.7,
      "prompt": "{file:./prompts/creative.txt}"
    }
  }
}
```

اگر دما تعیین نشود، OpenCode از پیش‌فرض مدل استفاده می‌کند؛ معمولاً صفر برای بیشتر مدل‌ها و ۰٫۵۵ برای مدل‌های Qwen.

---

### حداکثر گام‌ها

حداکثر تعداد گام‌هایی را تعیین کنید که عامل پیش از پاسخ صرفاً متنی می‌تواند انجام دهد. برای کنترل هزینه می‌توانید تعداد عملیات عامل را از این راه محدود کنید.

اگر سقف تعیین نشود، عامل به کار ادامه می‌دهد تا مدل تصمیم به توقف بگیرد یا کاربر نشست را متوقف کند.

```json title="opencode.json"
{
  "agent": {
    "quick-thinker": {
      "description": "استدلال سریع با تعداد گام‌های محدود",
      "prompt": "سریع استدلال کن و مسئله‌ها را با کمترین تعداد گام حل کن.",
      "steps": 5
    }
  }
}
```

پس از رسیدن به سقف، یک دستور سیستمی ویژه از عامل می‌خواهد خلاصهٔ کار انجام‌شده و پیشنهادهایش برای کارهای باقی‌مانده را بنویسد.

:::caution
فیلد قدیمی `maxSteps` منسوخ شده است. از `steps` استفاده کنید.
:::

---

### غیرفعال کردن

برای غیرفعال کردن عامل، مقدار `true` را تعیین کنید.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "disable": true
    }
  }
}
```

---

### دستورالعمل

با تنظیم `prompt` فایل دستور سیستمی دلخواه عامل را معرفی کنید. این فایل باید شامل دستورالعمل‌های ویژهٔ وظیفهٔ عامل باشد.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "prompt": "{file:./prompts/code-review.txt}"
    }
  }
}
```

مسیر نسبت به محل فایل پیکربندی تفسیر می‌شود. این روش هم برای پیکربندی سراسری و هم برای پیکربندی پروژه کار می‌کند.

---

### مدل

با `model` مدل ویژه‌ای برای عامل تعیین کنید. می‌توانید برای برنامه‌ریزی مدلی سریع‌تر و برای پیاده‌سازی مدلی توانمندتر انتخاب کنید.

:::tip
اگر مدلی تعیین نکنید، عامل‌های اصلی از [مدل سراسری](/docs/config#models) و زیرعامل‌ها از مدل عامل اصلی فراخوان خود استفاده می‌کنند.
:::

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "model": "anthropic/claude-haiku-5-5"
    }
  }
}
```

شناسهٔ مدل در پیکربندی به شکل `provider/model-id` است. برای نمونه، در [OpenCode Models](https://opencode.ai/docs/console/)، شناسهٔ GPT-6.1 Sol برابر `opencode/gpt-6.1-sol` است.

---

### ابزارها (منسوخ‌شده)

گزینهٔ `tools` **منسوخ شده است**. برای پیکربندی تازه، به‌روزرسانی یا کنترل دقیق‌تر، از فیلد [`permission`](#permissions) عامل استفاده کنید.

این گزینه ابزارهای در دسترس عامل را تعیین می‌کند. برای فعال یا غیرفعال کردن هر ابزار مقدار `true` یا `false` را بدهید. در تنظیم `tools` عامل، `true` معادل مجوز `{"*": "allow"}` و `false` معادل مجوز `{"*": "deny"}` است.

```json title="opencode.json" {3-6,9-12}
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

:::note
پیکربندی مخصوص عامل بر پیکربندی سراسری اولویت دارد.
:::

در تنظیمات قدیمی `tools` نیز با نویسهٔ عام می‌توانید چند ابزار را هم‌زمان کنترل کنید. برای نمونه، همهٔ ابزارهای یک سرور MCP را این‌گونه غیرفعال کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "readonly": {
      "tools": {
        "mymcp_*": false,
        "write": false,
        "edit": false
      }
    }
  }
}
```

[راهنمای ابزارها](/docs/tools) را بخوانید.

### مجوزها

با مجوزها تعیین کنید عامل چه کارهایی انجام دهد. هر کلید مجوز یکی از این مقادیر را می‌گیرد.

- `"ask"` پیش از اجرای ابزار تأیید می‌گیرد.
- `"allow"` همهٔ عملیات را بدون تأیید مجاز می‌کند.
- `"deny"` ابزار را غیرفعال می‌کند.

کلیدهای مجوز در دسترس به شرح زیرند.

| کلید | ابزارهای تحت کنترل |
| -------------------- | ---------------------------------------------------------------- |
| `read` | `read` |
| `edit` | `write`, `edit`, `apply_patch` |
| `glob` | `glob` |
| `grep` | `grep` |
| `list` | `list` |
| `bash` | `bash` |
| `task` | `task` |
| `todowrite` | `todowrite` |
| `external_directory` | هر ابزاری که فایلی را بیرون از درخت کاری پروژه می‌خواند یا می‌نویسد |
| `webfetch` | `webfetch` |
| `websearch` | `websearch` |
| `lsp` | `lsp` |
| `skill` | `skill` |
| `question` | `question` |
| `doom_loop` | درخواست‌های بازیابی هنگامی که به نظر می‌رسد عامل از ادامهٔ کار مانده است |

کلیدهای `read`، `edit`، `glob`، `grep`، `list`، `bash`، `task`، `external_directory`، `lsp` و `skill` یا مقدار کوتاه (`"allow" | "ask" | "deny"`) می‌گیرند یا برای کنترل دقیق‌تر، شیئی که الگوها را به عملیات نگاشت می‌کند. سایر کلیدها فقط مقدار کوتاه را می‌پذیرند.

:::note
کلیدهای مجوز به‌صورت الگوهای دارای نویسهٔ عام با نام ابزار تطبیق داده می‌شوند. برای ابزارهای داخلی، سفارشی و MCP نحو یکسان است. برای نمونه، `"mymcp_*": "deny"` همهٔ ابزارهای یک سرور MCP را مسدود می‌کند و `"mymcp_search": "ask"` فقط یک ابزار را هدف می‌گیرد.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  }
}
```

مجوزها را می‌توانید برای هر عامل تغییر دهید.

```json title="opencode.json" {3-5,8-10}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  },
  "agent": {
    "build": {
      "permission": {
        "edit": "ask"
      }
    }
  }
}
```

برای عامل‌هایی که با Markdown تعریف می‌شوند نیز می‌توانید مجوز تعیین کنید.

```markdown title="~/.config/opencode/agents/review.md"
---
description: بازبینی کد بدون ویرایش
mode: subagent
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
    "grep *": allow
  webfetch: deny
---

فقط کد را تحلیل کن و تغییرات پیشنهادی را توضیح بده.
```

می‌توانید برای فرمان‌های مشخص bash مجوز تعیین کنید.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git push": "ask",
          "grep *": "allow"
        }
      }
    }
  }
}
```

در اینجا الگوی glob هم پذیرفته می‌شود.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git *": "ask"
        }
      }
    }
  }
}
```

برای تعیین مجوز همهٔ فرمان‌ها، از نویسهٔ عام `*` استفاده کنید. آخرین قاعدهٔ منطبق اولویت دارد، پس ابتدا `*` و سپس قواعد خاص‌تر را قرار دهید.

```json title="opencode.json" {8}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status *": "allow"
        }
      }
    }
  }
}
```

[راهنمای مجوزها](/docs/permissions) را ببینید.

---

### حالت

با `mode` حالت عامل را تعیین کنید. گزینهٔ `mode` مشخص می‌کند عامل به چه شکل قابل استفاده است.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "mode": "subagent"
    }
  }
}
```

گزینهٔ `mode` می‌تواند `primary`، `subagent` یا `all` باشد. اگر `mode` تعیین نشود، پیش‌فرض آن `all` است.

---

### پنهان کردن

با `hidden: true` زیرعامل را از فهرست تکمیل خودکار `@` پنهان کنید. این گزینه برای زیرعامل‌های داخلی مناسب است که فقط عامل‌های دیگر باید از طریق ابزار Task فراخوانی کنند.

```json title="opencode.json"
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

این گزینه فقط نمایش به کاربر را تغییر می‌دهد. اگر مجوزها اجازه دهند، مدل همچنان با ابزار Task به زیرعامل پنهان دسترسی دارد.

:::note
فقط دربارهٔ عامل‌های `mode: subagent` کاربرد دارد.
:::

---

### مجوزهای فراخوانی زیرعامل

با `permission.task` تعیین کنید عامل از طریق ابزار Task کدام زیرعامل‌ها را می‌تواند فراخوانی کند. برای تطبیق نام‌ها، الگوی glob پذیرفته می‌شود.

```json title="opencode.json"
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

اگر `deny` تعیین شود، توضیحات ابزار Task دیگر نام آن زیرعامل را نشان نمی‌دهد و مدل برای فراخوانی آن تلاش نمی‌کند.

:::tip
قواعد به‌ترتیب بررسی می‌شوند و **آخرین قاعدهٔ منطبق اولویت دارد**. در نمونهٔ بالا، `orchestrator-planner` هم با `*` (منع) و هم با `orchestrator-*` (اجازه) منطبق است. چون `orchestrator-*` پس از `*` آمده است، نتیجه `allow` می‌شود.
:::

:::tip
کاربر همیشه می‌تواند هر زیرعامل را مستقیماً از فهرست تکمیل خودکار `@` فراخوانی کند، حتی اگر مجوز Task عامل آن را ممنوع کرده باشد.
:::

---

### رنگ

با گزینهٔ `color` رنگ نمایش عامل در رابط کاربری را تغییر دهید.

یک رنگ هگزادسیمال معتبر مانند `#FF5733` یا یکی از رنگ‌های پوسته را بدهید: `primary`، `secondary`، `accent`، `success`، `warning`، `error` یا `info`.

```json title="opencode.json"
{
  "agent": {
    "creative": {
      "color": "#ff6b6b"
    },
    "code-reviewer": {
      "color": "accent"
    }
  }
}
```

### Top P

با `top_p` می‌توانید تنوع پاسخ را تنظیم کنید. این گزینه راه دیگری برای کنترل تصادفی بودن پاسخ به‌جای تنظیم دماست.

```json title="opencode.json"
{
  "agent": {
    "brainstorm": {
      "top_p": 0.9
    }
  }
}
```

مقدار آن بین ۰٫۰ و ۱٫۰ است. مقدار کمتر پاسخ را متمرکزتر و مقدار بیشتر آن را متنوع‌تر می‌کند.

### گزینه‌های دیگر

گزینه‌های دیگر پیکربندی عامل **مستقیماً به ارائه‌دهنده فرستاده می‌شوند** و به‌عنوان گزینه‌های مدل به کار می‌روند. بدین ترتیب می‌توانید از قابلیت‌ها و پارامترهای اختصاصی ارائه‌دهنده استفاده کنید.

برای نمونه، در مدل‌های استدلالی OpenAI می‌توانید میزان استدلال را تعیین کنید.

```json title="opencode.json" {6,7}
{
  "agent": {
    "deep-thinker": {
      "description": "عاملی برای حل مسئله‌های پیچیده با میزان استدلال زیاد",
      "model": "openai/gpt-6.1-sol",
      "reasoningEffort": "high",
      "textVerbosity": "low"
    }
  }
}
```

گزینه‌های اضافی به مدل و ارائه‌دهنده وابسته‌اند. برای پارامترهای در دسترس، مستندات ارائه‌دهنده را ببینید.

:::tip
برای دیدن مدل‌های در دسترس، `opencode models` را اجرا کنید.
:::

## ساخت عامل

برای ساخت عامل، فایل Markdown را در `.opencode/agents/` پروژه یا برای استفادهٔ سراسری در `~/.config/opencode/agents/` قرار دهید. نام فایل نام عامل می‌شود. در فرادادهٔ آغاز فایل، توضیح، حالت، مدل و مجوزها را تعیین کنید. قالب فایل در بخش [Markdown](#markdown) آمده است.

با `opencode agent create` نیز می‌توانید عامل را به‌صورت تعاملی بسازید. برای دیدن عامل‌هایی که OpenCode بارگذاری کرده است، `opencode agent list` را اجرا کنید.

---

## موارد استفاده

هر عامل را می‌توان برای کاری مشخص تنظیم کرد، مانند نمونه‌های زیر.

- **عامل Build**: انجام همهٔ کارهای توسعه با دسترسی به تمامی ابزارها
- **عامل Plan**: تحلیل و برنامه‌ریزی بدون تغییر کد
- **عامل Review**: بازبینی کد با دسترسی فقط‌خواندنی و ابزارهای مستندات
- **عامل Debug**: بررسی مشکل با ابزارهای bash و خواندن فایل
- **عامل Docs**: مستندنویسی با دسترسی به فایل‌ها و بدون اجرای فرمان‌های سیستم

- نمونه‌های کد
