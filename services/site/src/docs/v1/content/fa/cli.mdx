با اجرای OpenCode در خط فرمان بدون آرگومان، به‌طور پیش‌فرض [رابط ترمینالی](/docs/tui) باز می‌شود.

```bash
opencode
```

فرمان‌های این صفحه را نیز می‌توانید برای کنترل OpenCode از برنامه یا اسکریپت اجرا کنید.

```bash
opencode run "توضیح بده closure در JavaScript چطور کار می‌کند."
```

### tui

رابط کاربری ترمینالی OpenCode را راه‌اندازی می‌کند.

```bash
opencode [project]
```

#### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| ------------------------------------------- | ----- | ----------------------------------------------------------------------- |
| <nobr><code>{"--continue"}</code></nobr> | `-c` | ادامهٔ آخرین نشست |
| <nobr><code>{"--session"}</code></nobr> | `-s` | شناسهٔ نشستی که باید ادامه یابد |
| <nobr><code>{"--fork"}</code></nobr> |         | ساخت شاخه‌ای از نشست هنگام ادامه (همراه `--continue` یا `--session`) |
| <nobr><code>{"--prompt"}</code></nobr> |         | متن درخواست |
| <nobr><code>{"--model"}</code></nobr> | `-m` | مدل به شکل provider/model |
| <nobr><code>{"--agent"}</code></nobr> |         | عامل مورد استفاده |
| <nobr><code>{"--auto"}</code></nobr> |         | تأیید خودکار درخواست‌های مجوز که صریحاً ممنوع نشده‌اند |
| <nobr><code>{"--port"}</code></nobr> |         | پورتی که سرور روی آن گوش می‌دهد |
| <nobr><code>{"--hostname"}</code></nobr> |         | نام میزبانی که سرور روی آن گوش می‌دهد |
| <nobr><code>{"--mdns"}</code></nobr> |         | فعال‌سازی کشف سرویس با mDNS |
| <nobr><code>{"--mdns-domain"}</code></nobr> |         | نام دامنهٔ سفارشی mDNS |
| <nobr><code>{"--cors"}</code></nobr> |         | مبدأهای اضافی مجاز مرورگر برای CORS |

## فرمان‌ها

خط فرمان OpenCode فرمان‌های زیر را نیز می‌پذیرد.

---

### agent

عامل‌های OpenCode را مدیریت می‌کند.

```bash
opencode agent [command]
```

---

#### create

یک عامل با پیکربندی دلخواه می‌سازد.

```bash
opencode agent create
```

این فرمان برای ساخت عامل، نوشتن دستور سیستمی و تعیین مجوزها شما را راهنمایی می‌کند. هر مجوزی که صریحاً ندهید، در فرادادهٔ آغاز فایل عامل ممنوع می‌شود.

##### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| ------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <nobr><code>{"--path"}</code></nobr> |         | پوشهٔ پیکربندی که فایل در زیرپوشهٔ `agents/` آن قرار می‌گیرد. پیش‌فرض، بسته به پاسخ شما، پوشهٔ سراسری یا `.opencode` است. |
| <nobr><code>{"--description"}</code></nobr> |         | شرح کاری که عامل باید انجام دهد |
| <nobr><code>{"--mode"}</code></nobr> |         | حالت عامل: `all`، `primary` یا `subagent` |
| <nobr><code>{"--permissions"}</code></nobr> |         | فهرست مجوزهای داده‌شده با ویرگول لاتین (پیش‌فرض: همه). گزینه‌ها: `bash`، `read`، `edit`، `glob`، `grep`، `webfetch`، `task`، `todowrite`، `websearch`، `lsp` و `skill`. مواردی که ذکر نشوند ممنوع‌اند. نام دیگر: `--tools` |
| <nobr><code>{"--model"}</code></nobr> | `-m` | مدل مورد استفاده به شکل `provider/model` |

اگر `--path`، `--description`، `--mode` و `--permissions` را همگی تعیین کنید، فرمان بدون تعامل با کاربر اجرا می‌شود.

#### list

همهٔ عامل‌های در دسترس را فهرست می‌کند.


### attach

یک ترمینال را به سرور در حال اجرای OpenCode که با `serve` یا `web` راه‌اندازی شده است متصل می‌کند.

```bash
opencode attach [url]
```

با این روش می‌توانید رابط ترمینالی را به سرور راه دور OpenCode متصل کنید. برای نمونه:

```bash
# سرور را برای دسترسی از وب یا موبایل راه‌اندازی کنید
opencode web --port 4096 --hostname 0.0.0.0

# در ترمینال دیگری، رابط ترمینالی را به سرور در حال اجرا وصل کنید
opencode attach http://10.20.30.40:4096
```

#### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--dir"}</code></nobr> |         | پوشهٔ کاری آغاز رابط ترمینالی |
| <nobr><code>{"--continue"}</code></nobr> | `-c` | ادامهٔ آخرین نشست |
| <nobr><code>{"--session"}</code></nobr> | `-s` | شناسهٔ نشستی که باید ادامه یابد |
| <nobr><code>{"--fork"}</code></nobr> |         | ساخت شاخه‌ای از نشست هنگام ادامه (همراه `--continue` یا `--session`) |
| <nobr><code>{"--password"}</code></nobr> | `-p` | گذرواژهٔ احراز هویت پایه (پیش‌فرض از `OPENCODE_SERVER_PASSWORD`) |
| <nobr><code>{"--username"}</code></nobr> | `-u` | نام کاربری احراز هویت پایه (پیش‌فرض از `OPENCODE_SERVER_USERNAME` یا مقدار `opencode`) |

### auth

اطلاعات دسترسی و ورود به حساب ارائه‌دهندگان را مدیریت می‌کند.

```bash
opencode auth [command]
```

---

#### login

OpenCode از فهرست ارائه‌دهندگان [Models.dev](https://models.dev) استفاده می‌کند. با `opencode auth login` می‌توانید کلید API هر ارائه‌دهندهٔ دلخواه را تنظیم کنید. اطلاعات دسترسی در `~/.local/share/opencode/auth.json` ذخیره می‌شود.

```bash
opencode auth login
```

هنگام راه‌اندازی، OpenCode ارائه‌دهندگان را از فایل اطلاعات دسترسی بارگذاری می‌کند. کلیدهای تعریف‌شده در متغیرهای محیطی یا فایل `.env` پروژه نیز بررسی می‌شوند.

##### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| ---------------------------------------- | ----- | ---------------------------------------------------- |
| <nobr><code>{"--provider"}</code></nobr> | `-p` | شناسه یا نام ارائه‌دهنده برای ورود |
| <nobr><code>{"--method"}</code></nobr> | `-m` | نام روش ورود برای عبور از مرحلهٔ انتخاب روش |

---

#### list

ارائه‌دهندگانی را که اطلاعات ورودشان در فایل ذخیره شده است فهرست می‌کند.

```bash
opencode auth list
```

شکل کوتاه فرمان:

```bash
opencode auth ls
```

#### logout

با پاک کردن اطلاعات ورود یک ارائه‌دهنده از فایل، از حساب آن خارج می‌شود.

```bash
opencode auth logout
```

### mcp

سرورهای پروتکل زمینهٔ مدل را مدیریت می‌کند.

```bash
opencode mcp [command]
```

---

#### add

یک سرور MCP به پیکربندی اضافه می‌کند.

```bash
opencode mcp add
```

این فرمان مراحل افزودن سرور محلی یا راه دور MCP را به‌شکل تعاملی پیش می‌برد.

---

#### list

همهٔ سرورهای MCP تعریف‌شده و وضعیت اتصال آن‌ها را فهرست می‌کند.

```bash
opencode mcp list
```

شکل کوتاه فرمان:

```bash
opencode mcp ls
```

---

#### auth

احراز هویت در سرور MCP مجهز به OAuth.

```bash
opencode mcp auth [name]
```

اگر نام سرور را ندهید، از شما می‌خواهد از میان سرورهایی که از OAuth پشتیبانی می‌کنند انتخاب کنید.

فهرست سرورهایی که از OAuth پشتیبانی می‌کنند و وضعیت احراز هویت آن‌ها را هم می‌توانید ببینید.

```bash
opencode mcp auth list
```

شکل کوتاه فرمان:

```bash
opencode mcp auth ls
```


### models

مدل‌های در دسترس ارائه‌دهندگان پیکربندی‌شده را فهرست می‌کند.

```bash
opencode models [provider]
```

در این فهرست، شناسهٔ تمام مدل‌های در دسترس ارائه‌دهندگان شما به شکل `provider/model` نمایش داده می‌شود.

برای یافتن نام دقیق مدل و استفاده در [پیکربندی](/docs/config/) از این فرمان استفاده کنید.

برای محدود کردن فهرست به یک ارائه‌دهنده می‌توانید شناسهٔ آن را بدهید.

```bash
opencode models anthropic
```

#### گزینه‌ها

| گزینه | توضیحات |
| --------------------------------------- | ------------------------------------------------------------ |
| <nobr><code>{"--refresh"}</code></nobr> | به‌روزرسانی حافظهٔ نهان مدل‌ها از models.dev |
| <nobr><code>{"--verbose"}</code></nobr> | نمایش جزئیات بیشتر مدل از جمله فراداده‌ای مانند هزینه |

با `--refresh` فهرست ذخیره‌شدهٔ مدل‌ها را تازه کنید. اگر ارائه‌دهنده مدل تازه‌ای اضافه کرده است، با این گزینه آن را در OpenCode خواهید دید.

```bash
opencode models --refresh
```

### run

با دریافت مستقیم متن درخواست، OpenCode را به‌صورت غیرتعاملی اجرا می‌کند.

```bash
opencode run [message..]
```

برای اسکریپت‌نویسی، خودکارسازی یا گرفتن پاسخی سریع بدون باز کردن رابط ترمینالی کامل مناسب است. برای نمونه:

```bash "opencode run"
opencode run کاربرد context را در Go توضیح بده
```

می‌توانید به نمونهٔ در حال اجرای `opencode serve` هم متصل شوید تا برای هر بار اجرا منتظر راه‌اندازی مجدد سرورهای MCP نمانید.

```bash
# در یک ترمینال، سرور را بدون رابط کاربری راه‌اندازی کنید
opencode serve

# در ترمینال دیگری، با فرمان زیر به آن سرور وصل شوید
opencode run --attach http://localhost:4096 "کاربرد async/await را در JavaScript توضیح بده"
```

#### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--command"}</code></nobr> |         | فرمان موردنظر؛ متن پیام به‌عنوان آرگومان آن استفاده می‌شود. |
| <nobr><code>{"--continue"}</code></nobr> | `-c` | ادامهٔ آخرین نشست |
| <nobr><code>{"--session"}</code></nobr> | `-s` | شناسهٔ نشستی که باید ادامه یابد |
| <nobr><code>{"--fork"}</code></nobr> |         | ساخت شاخه‌ای از نشست هنگام ادامه (همراه `--continue` یا `--session`) |
| <nobr><code>{"--model"}</code></nobr> | `-m` | مدل به شکل provider/model |
| <nobr><code>{"--agent"}</code></nobr> |         | عامل مورد استفاده |
| <nobr><code>{"--file"}</code></nobr> | `-f` | فایل‌های پیوست پیام |
| <nobr><code>{"--format"}</code></nobr> |         | قالب خروجی: default برای نمایش قالب‌بندی‌شده یا json برای رویدادهای خام JSON |
| <nobr><code>{"--title"}</code></nobr> |         | عنوان نشست؛ اگر تعیین نشود، نسخهٔ کوتاه‌شدهٔ متن درخواست استفاده می‌شود. |
| <nobr><code>{"--attach"}</code></nobr> |         | اتصال به سرور در حال اجرای OpenCode (برای نمونه http://localhost:4096) |
| <nobr><code>{"--password"}</code></nobr> | `-p` | گذرواژهٔ احراز هویت پایه (پیش‌فرض از `OPENCODE_SERVER_PASSWORD`) |
| <nobr><code>{"--username"}</code></nobr> | `-u` | نام کاربری احراز هویت پایه (پیش‌فرض از `OPENCODE_SERVER_USERNAME` یا مقدار `opencode`) |
| <nobr><code>{"--dir"}</code></nobr> |         | پوشهٔ اجرا یا در صورت اتصال، مسیر روی سرور راه دور |
| <nobr><code>{"--port"}</code></nobr> |         | پورت سرور محلی (پیش‌فرض یک پورت تصادفی) |
| <nobr><code>{"--variant"}</code></nobr> |         | گونهٔ مدل برای تعیین میزان استدلال ویژهٔ ارائه‌دهنده |
| <nobr><code>{"--thinking"}</code></nobr> |         | نمایش بخش‌های استدلال |
| <nobr><code>{"--auto"}</code></nobr> |         | تأیید خودکار درخواست‌های مجوز که صریحاً ممنوع نشده‌اند |

### serve

سرور OpenCode را بدون رابط کاربری برای دسترسی به API راه‌اندازی می‌کند. شرح کامل رابط HTTP را در [مستندات سرور](/docs/server) ببینید.

```bash
opencode serve
```

این سرور HTTP قابلیت‌های OpenCode را از طریق API و بدون رابط ترمینالی ارائه می‌کند. برای فعال کردن احراز هویت پایهٔ HTTP، متغیر `OPENCODE_SERVER_PASSWORD` را تنظیم کنید. نام کاربری پیش‌فرض `opencode` است.

#### گزینه‌ها

| گزینه | توضیحات |
| ------------------------------------------- | ------------------------------------------ |
| <nobr><code>{"--port"}</code></nobr> | پورتی که سرور روی آن گوش می‌دهد |
| <nobr><code>{"--hostname"}</code></nobr> | نام میزبانی که سرور روی آن گوش می‌دهد |
| <nobr><code>{"--mdns"}</code></nobr> | فعال‌سازی کشف سرویس با mDNS |
| <nobr><code>{"--mdns-domain"}</code></nobr> | نام دامنهٔ سفارشی mDNS |
| <nobr><code>{"--cors"}</code></nobr> | مبدأهای اضافی مجاز مرورگر برای CORS |

### acp

سرور پروتکل ارتباط با عامل (ACP) را راه‌اندازی می‌کند.

```bash

```

این سرور ACP با قالب nd-JSON از طریق ورودی و خروجی استاندارد ارتباط برقرار می‌کند.

#### گزینه‌ها

| گزینه | توضیحات |
| ------------------------------------------- | ------------------------------------------ |
| <nobr><code>{"--cwd"}</code></nobr> | پوشهٔ کاری |
| <nobr><code>{"--port"}</code></nobr> | پورتی که سرور روی آن گوش می‌دهد |
| <nobr><code>{"--hostname"}</code></nobr> | نام میزبانی که سرور روی آن گوش می‌دهد |
| <nobr><code>{"--mdns"}</code></nobr> | فعال‌سازی کشف سرویس با mDNS |
| <nobr><code>{"--mdns-domain"}</code></nobr> | نام دامنهٔ سفارشی mDNS |
| <nobr><code>{"--cors"}</code></nobr> | مبدأهای اضافی مجاز مرورگر برای CORS |

### plugin

افزونه نصب می‌کند و پیکربندی را به‌روز می‌کند.

```bash
opencode plugin <module>
```

نام دیگر فرمان:

```bash
opencode plug <module>
```

#### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| -------------------------------------- | ----- | ------------------------------- |
| <nobr><code>{"--global"}</code></nobr> | `-g` | نصب در پیکربندی سراسری |
| <nobr><code>{"--force"}</code></nobr> | `-f` | جایگزینی نسخهٔ موجود افزونه |

#### paths

مسیرهای سراسری داده‌ها، پیکربندی، حافظهٔ نهان و وضعیت را نشان می‌دهد.

```bash
opencode debug paths
```

این فرمان همهٔ مسیرهای سراسری را چاپ می‌کند. برای دیدن مسیر پایگاه داده بنویسید:

```bash
opencode db path
```

#### سایر فرمان‌های اشکال‌زدایی

| فرمان | توضیحات |
| ------------------------------------------- | -------------------------------------------------------- |
| `opencode debug info` | نمایش نسخه، سیستم‌عامل، ترمینال و افزونه‌های تعریف‌شده |

| `opencode debug file search <query>` | جست‌وجوی مسیر فایل‌ها |
| `opencode debug rg files` | فهرست فایل‌ها با ripgrep؛ گزینه‌های `--glob` و `--limit` را می‌پذیرد. |
| `opencode debug rg search <pattern>` | جست‌وجوی محتوای فایل‌ها؛ گزینه‌های `--glob` و `--limit` را می‌پذیرد. |
| `opencode debug lsp diagnostics <file>` | دریافت گزارش تشخیصی LSP برای فایل |

| `opencode debug lsp document-symbols <uri>` | دریافت نمادهای یک سند |
| `opencode debug snapshot track` | ثبت وضعیت فعلی نسخهٔ لحظه‌ای |
| `opencode debug snapshot patch <hash>` | نمایش فایل‌های تغییرکرده برای هش یک نسخهٔ لحظه‌ای |
| `opencode debug snapshot diff <hash>` | نمایش تفاوت فایل‌ها برای هش یک نسخهٔ لحظه‌ای |
| `opencode debug startup` | چاپ زمان‌بندی مراحل راه‌اندازی |

### uninstall

OpenCode را همراه با همهٔ فایل‌های مربوط حذف می‌کند.

```bash
opencode uninstall
```

#### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| ------------------------------------------- | ----- | ------------------------------------------- |
| <nobr><code>{"--keep-config"}</code></nobr> | `-c` | نگه داشتن فایل‌های پیکربندی |
| <nobr><code>{"--keep-data"}</code></nobr> | `-d` | نگه داشتن داده‌های نشست و نسخه‌های لحظه‌ای |
| <nobr><code>{"--dry-run"}</code></nobr> |         | نمایش مواردی که قرار است حذف شوند، بدون انجام حذف |
| <nobr><code>{"--force"}</code></nobr> | `-f` | عبور از درخواست‌های تأیید |

### upgrade

OpenCode را به آخرین نسخه یا نسخه‌ای مشخص ارتقا می‌دهد.

```bash
opencode upgrade [target]
```

برای ارتقا به آخرین نسخه:

```bash
opencode upgrade
```

برای ارتقا به نسخه‌ای مشخص:

```bash
opencode upgrade v0.1.48
```

برای ارتقا به OpenCode 2 و حذف OpenCode 1:

```bash
opencode upgrade --major
```

#### گزینه‌ها

| گزینه | شکل کوتاه | توضیحات |
| -------------------------------------- | ----- | ----------------------------------------------------------------- |
| <nobr><code>{"--method"}</code></nobr> | `-m` | روش نصب اولیه: curl، npm، pnpm، bun یا brew |
| <nobr><code>{"--major"}</code></nobr> |         | ارتقا به OpenCode 2 و حذف OpenCode 1 |
