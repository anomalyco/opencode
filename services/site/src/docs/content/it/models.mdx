Scegli un modello per la sessione corrente con `/models`:

```text
/models
```

OpenCode elenca i modelli presenti su [models.dev](https://models.dev), quelli delle integrazioni dei provider e quelli della tua configurazione. Il selettore
mostra solo i modelli abilitati il cui provider è disponibile nel progetto corrente. Collega i provider in
[Provider](/providers).

## Selezione

Scegli un modello da `/models`, così non devi conoscere in anticipo il provider o l'ID del modello. La scelta vale per la sessione corrente
e non cambia la tua configurazione.

```text
anthropic/claude-sonnet-5-5
```

La disponibilità dipende dal progetto:

- Il modello deve essere abilitato.
- Il suo provider deve essere disponibile nel progetto corrente.
- Le credenziali e la configurazione di un altro progetto non vengono trasferite automaticamente.

## Esecuzioni

Usa `--model` per scegliere un modello per una singola esecuzione da riga di comando senza cambiare il valore predefinito configurato:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Anche agenti e comandi possono scegliere il proprio modello. Vedi [Agenti](/agents) e [Comandi](/commands).

## Predefiniti

Imposta `model` in `opencode.json` o `opencode.jsonc` per scegliere quale modello usare per impostazione predefinita nelle nuove attività:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Il modello configurato diventa il modello predefinito del catalogo se è abilitato e il suo provider è disponibile. In caso contrario, OpenCode
usa il più recente tra i modelli supportati e disponibili.

- Un modello già selezionato per una sessione ha la precedenza sul valore predefinito configurato.
- Cambiare il modello di una sessione non riscrive il file di configurazione.
- Il campo `model` di primo livello al momento conserva solo il provider e il modello predefiniti, non la variante.

Vedi [Configurazione](/config) per le posizioni e la precedenza della configurazione.

## Modelli gratuiti

Imposta `OPENCODE_DISABLE_FREE_MODELS=1` (o `true`) sul processo del server per nascondere i [modelli gratuiti di OpenCode](/console/models#free-models):

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

Per il server in background condiviso:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

Un modello è gratuito se appartiene a `opencode` o `opencode-go` e non ha costi di input. Questi modelli spariscono dal catalogo e non possono essere usati come predefiniti.
Se provi a selezionarne uno esplicitamente, ricevi `Model unavailable`. Se non hai effettuato l'accesso, il provider `opencode` non compare.
Collega un account OpenCode Console o imposta `OPENCODE_API_KEY` per rendere di nuovo disponibili i suoi modelli a pagamento.

Per bloccare i modelli gratuiti per tutti in un'organizzazione, usa invece una policy. Vedi [Enterprise](/enterprise#block-free-models).

## Varianti

Le varianti sono opzioni con un nome, che spesso regolano l'intensità del ragionamento o il budget di token di un modello. Aggiungi `#variant` quando ne selezioni
una per un'esecuzione, una sessione, un agente o un comando:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

I nomi delle varianti provengono dai metadati correnti del modello nel catalogo. Non tutti i modelli offrono le varianti `low`, `high` e `max`.
Se indichi una variante sconosciuta, OpenCode non riesce a risolvere il modello e restituisce un errore.

Definisci nuove varianti, o sostituisci quelle del catalogo con lo stesso ID, nell'array `variants` del modello:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Ogni variante può contenere `settings`, `headers` e `body`. OpenCode applica i suoi valori dopo quelli del provider e del modello.

Per sostituire le varianti di ragionamento di un modello, definisci i parametri in `capabilities.reasoning` nel
formato v2 di [models.dev](https://models.dev). OpenCode genera le varianti per il pacchetto del modello a partire da questi parametri:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| Campo       | Scopo                                                                      |
| ----------- | -------------------------------------------------------------------------- |
| `supported` | Se il modello ragiona. `false`, o `true` senza controlli, non aggiunge varianti. |
| `toggle`    | Aggiunge una variante `none` che disattiva il ragionamento.                |
| `effort`    | Livelli di intensità del ragionamento da offrire. `default` mantiene il valore predefinito del provider e non aggiunge varianti. |
| `budget`    | Token di ragionamento `min` e `max` facoltativi. Ignorati quando `effort` è impostato. |

OpenCode applica le varianti elencate in `variants` dopo quelle generate da `capabilities.reasoning`.

## Opzioni

Le voci di provider e modello possono personalizzare le richieste con `settings`, `headers` e `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Campo      | Scopo                                                              |
| ---------- | ------------------------------------------------------------------ |
| `settings` | Opzioni del pacchetto del provider come `baseURL` o `reasoningEffort`. |
| `headers`  | Header HTTP aggiuntivi della richiesta.                            |
| `body`     | Campi del corpo della richiesta specifici del provider.            |

OpenCode applica prima i valori del provider, poi quelli del modello e per ultima la variante selezionata.

- Gli oggetti annidati `settings` e `body` vengono uniti.
- Gli array e i valori scalari successivi sostituiscono quelli precedenti.
- I nomi degli header vengono confrontati senza distinzione tra maiuscole e minuscole.
- Le opzioni sono specifiche del provider e possono essere ignorate o rifiutate da un altro pacchetto di provider.

## Alias

Usa `modelID` per assegnare a un modello API un ID di catalogo più leggibile:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Qui `openai/coding-default` è il riferimento selezionabile e `gpt-6.1-sol` viene inviato al provider. Per un modello che non è
già nel catalogo, OpenCode assume:

- Strumenti con input JSON, testo e immagini in input, testo in output. Gli strumenti accettano input in formato libero solo se `capabilities.freeform` elenca il formato.
- Un limite di contesto di 200,000 token e un limite di output di 32,000 token.
- Un limite di input non specificato.

OpenCode riconosce `text`, `regex` e `lark`. Ignora gli altri formati indicati da models.dev senza escludere il modello o i suoi strumenti. Se il proxy attraverso cui accedi a un modello del catalogo rifiuta gli strumenti con input in formato libero, imposta `capabilities.freeform` su `[]` per quel modello.

Questi valori sono di ripiego: OpenCode non rileva le funzionalità effettive del modello. Se conosci i valori corretti di `capabilities` e `limit`, impostali:
i valori espliciti hanno la precedenza. La compattazione automatica usa `limit.input`, senza superare `limit.context`. Vedi
[Finestra](/compaction#window). Aggiungi `disabled: true` per nascondere un modello dal catalogo dei modelli disponibili:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Ragionamento

Per un modello compatibile con OpenAI che trasmette il ragionamento in un campo personalizzato del messaggio dell'assistente, imposta
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode riconosce `reasoning`, `reasoning_content` e `reasoning_text`, e accetta anche un'altra stringa specifica del
provider. Legge il ragionamento trasmesso da quel campo e ripristina il campo quando rimanda al modello i messaggi precedenti dell'assistente.
Vedi [Compatibilità](#compatibility) per il campo correlato `requireReasoning`.

## Cache dei prompt

OpenCode inserisce automaticamente i breakpoint della cache dei prompt nelle route note per richiederli, come quelle di Anthropic. Se i modelli Claude passano attraverso un proxy compatibile con OpenAI, come LiteLLM, OpenCode non può rilevare che servono i breakpoint `cache_control` di Anthropic. Imposta `compatibility.cacheFormat` per quei modelli Claude:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

OpenCode contrassegna così l'ultima definizione di strumento, il prompt di sistema e il messaggio più recente con
`cache_control: { "type": "ephemeral" }`, che usa la durata predefinita di cinque minuti della cache dell'endpoint. Usa `"alibaba"`
per i modelli Alibaba Model Studio, che accettano gli stessi marker ma li ignorano sulle definizioni degli strumenti. Imposta
`compatibility.cacheFormat` sul provider se tutti i suoi modelli accettano lo stesso formato. Vedi
[Compatibilità](#compatibility) per gli altri campi.

### Durata della cache

OpenCode non invia una durata della cache per impostazione predefinita, quindi ogni provider usa il proprio valore predefinito, ad esempio cinque minuti su
Anthropic. Imposta `settings.cache.ttl` su un provider o modello per richiederne una diversa. Un'impostazione del modello sovrascrive quella del
provider.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

`ttl` accetta un numero e un'unità: `ms`, `s`, `m`, `h` o `d`, ad esempio `"5m"`, `"1h"` o `"24h"`. OpenCode lo invia così com'è,
quindi usa un valore che il provider accetta:

| API | Campo della durata |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` su ogni marker della cache. Anthropic accetta `"5m"` e `"1h"`. |
| Bedrock Converse | `ttl` su ogni `cachePoint`. I modelli Claude più vecchi che mettono in cache solo per cinque minuti ignorano `"1h"`. |
| OpenAI Chat e Responses | `"24h"` va in `prompt_cache_retention`; gli altri valori vanno in `prompt_cache_options.ttl`. |

I provider che usano la cache automaticamente senza marker, come Gemini, ignorano il valore. In genere il costo di scrittura nella cache aumenta con la durata.
Anthropic addebita 2× il prezzo di input per una scrittura in cache della durata di un'ora e 1.25× per una di cinque minuti.

Con `interval: "auto"`, il [warming](/warming) può programmare le richieste in base alla durata della cache.

## Compatibilità

`compatibility` descrive le particolarità delle richieste e delle risposte dell'API che espone il modello, ad esempio quale campo contiene
il ragionamento o se l'endpoint accetta `prompt_cache_key`. Ogni modello usa una sola API. Hanno effetto solo i campi che quell'API legge.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

La `compatibility` del provider si applica a ogni modello di quel provider. La `compatibility` del modello la sovrascrive campo per
campo: OpenCode parte dai valori che [models.dev](https://models.dev) pubblica per l'API del modello (`reasoningField`,
`maxTokensField` e `mediaInput`, più `supportsEffortUpdates` e `supportsSystemUpdates` quando models.dev indica che l'API supporta queste funzionalità), poi applica la configurazione del modello. I campi non impostati mantengono il valore predefinito o il rilevamento
integrati del pacchetto del provider. `supportsThinkingBlockBinding`, `supportsEffortUpdates` e `supportsSystemUpdates` sono
solo del modello.

| Campo | Cosa fa | Letto da | Valori e predefinito |
| --- | --- | --- | --- |
| `reasoningField` | Campo del messaggio dell'assistente che contiene il ragionamento. OpenCode controlla prima questo campo quando legge il ragionamento in streaming e lo usa per inviare al modello il ragionamento precedente. | OpenAI Chat | Qualsiasi nome di campo tranne `role`, `content`, `refusal` o `tool_calls`. Se non lo imposti, OpenCode usa il campo rilevato nello stream oppure, se non ne rileva uno, `reasoning_content`. |
| `requireReasoning` | Invia il campo del ragionamento su ogni messaggio precedente dell'assistente, come stringa vuota quando non c'era ragionamento. | OpenAI Chat | `true` o `false`. Il valore predefinito è `true` quando `reasoningField` è impostato o il modello è DeepSeek, altrimenti `false`. |
| `maxTokensField` | Campo del corpo che porta il limite di token di output. | OpenAI Chat | `max_completion_tokens` o `max_tokens`. Se non impostato, rileva `max_tokens` per i provider che lo richiedono, come DeepSeek, Moonshot, Together AI, Z.AI e Cerebras, altrimenti `max_completion_tokens`. |
| `requireFinishReason` | Se lo stream termina senza `finish_reason`, segnala un errore di risposta incompleta. Con `false` accetta comunque la risposta come completa. | OpenAI Chat | `true` o `false`. Il valore predefinito è `true`. |
| `requireAssistantAfterTool` | Inserisce un messaggio dell'assistente tra un risultato di uno strumento e il successivo messaggio utente, per gli endpoint che rifiutano quell'ordine. | OpenAI Chat | `true` o `false`. Il valore predefinito è `true` per gli ID modello della famiglia Mistral, altrimenti `false`. |
| `supportsPromptCacheKey` | Se l'endpoint accetta il campo `prompt_cache_key` nel corpo. | OpenAI Chat, OpenAI Responses, Mistral | `true` o `false`. OpenAI Chat invia la chiave solo quando è `true`, cosa che alcuni pacchetti di provider impostano per impostazione predefinita. Le altre API la inviano a meno che non sia `false`. |
| `streamUsage` | Richiede i dati sull'utilizzo dei token nello stream con `stream_options.include_usage`. | OpenAI Chat | `true` o `false`. Il valore predefinito è `true`. |
| `cacheFormat` | Sintassi dei marker della cache dei prompt accettata dall'endpoint. Sovrascrive il posizionamento automatico dei punti di interruzione del provider. `alibaba` salta le definizioni degli strumenti. | Ogni API con marker della cache dei prompt, comprese OpenAI Chat, Anthropic Messages e Bedrock Converse | `anthropic` o `alibaba`. Se non impostato, usa il valore predefinito del provider. Vedi [Cache dei prompt](#prompt-caching). |
| `supportsThinkingBlockBinding` | Chiede all'API di scartare i blocchi di ragionamento il cui contesto precedente è cambiato invece di rifiutare la richiesta. | Anthropic Messages, Bedrock Converse | `true` o `false`. Se non impostato, rileva Claude 5.1 e successivi. |
| `supportsEffortUpdates` | Invia le variazioni di intensità del ragionamento come aggiornamenti dei singoli messaggi, così la cache dei prompt resta valida. Altrimenti l'intensità cambia per tutta la richiesta. | Anthropic Messages, OpenAI Responses | `true` o `false`. Se non impostato, rileva Claude Opus 5, Claude 5.1 e successivi, e GPT-6 e successivi. |
| `supportsSystemUpdates` | Invia i messaggi di sistema aggiunti a metà conversazione come messaggi di sistema nativi. Altrimenti vengono racchiusi come testo nel successivo turno utente. | Anthropic Messages | `true` o `false`. Se non impostato, rileva Claude Opus 4.8 e Claude 5 e successivi. |
| `mediaInput` | Dove vanno immagini e altri media in una richiesta di decisione. | System One | `assets` (immagini referenziate dallo stato), `state` (inline nello stato) o `root` (elenchi di primo livello `images`, `audio` e `videos`). Se non impostato, usa il valore predefinito del provider. |

## Locali

OpenCode rileva automaticamente i modelli di Ollama, LM Studio e vLLM ai rispettivi indirizzi locali predefiniti. Puoi anche
configurare manualmente qualsiasi server compatibile con OpenAI.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Con Ollama in ascolto su `http://127.0.0.1:11434`, seleziona uno dei modelli rilevati con l'ID provider `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode aggiorna l'elenco in background e legge da Ollama le informazioni sul contesto e sul supporto alle immagini e agli strumenti.
Esclude i modelli che producono solo embedding.

Per un altro host o una porta diversa, imposta l'URL compatibile con OpenAI di Ollama. Per rilevare i modelli, OpenCode continua a usare l'API nativa di Ollama con lo stesso prefisso di percorso:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Ometti `apiKey` quando l'endpoint non richiede autenticazione bearer.
- Disattiva il rilevamento automatico con `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Con un server LM Studio senza autenticazione su `http://127.0.0.1:1234`, seleziona uno dei modelli rilevati con l'ID provider `lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode aggiorna l'elenco in background e legge da LM Studio le informazioni sul contesto e sul supporto alle immagini e agli strumenti.
Esclude i modelli di embedding.

Per un altro host o una porta diversa, imposta l'URL compatibile con OpenAI. OpenCode continua a rilevare i modelli automaticamente:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Ometti `apiKey` quando l'autenticazione di LM Studio è disattivata.
- Disattiva il rilevamento automatico con `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Con vLLM in ascolto su `http://127.0.0.1:8000`, seleziona uno dei modelli rilevati con l'ID provider `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode controlla `/health`, aggiorna `/v1/models` in background, usa il valore di `max_model_len` restituito dal server come limite di
contesto e include solo le schede dei modelli il cui proprietario è `vllm`.

I modelli rilevati dichiarano il supporto al testo in input e in output, ma non alle immagini né agli strumenti. vLLM abilita le chiamate agli strumenti con flag del server come `--enable-auto-tool-choice` e `--tool-call-parser`, che il rilevamento automatico non legge.

Per un altro endpoint o un server autenticato, imposta il suo URL compatibile con OpenAI:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Ometti `apiKey` quando l'autenticazione è disattivata.
- Disattiva il rilevamento automatico con `"plugins": ["-opencode.provider.vllm"]`.
- OpenCode supporta i proxy con un prefisso nel percorso. Ad esempio, con `https://example.com/vllm/v1` controlla `/vllm/health` e rileva i modelli da
  `/vllm/v1/models`.

### Compatibili

Per un altro server compatibile con OpenAI, definisci il suo pacchetto di provider, l'endpoint e almeno un modello:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Indica il nome effettivo del modello sul server, i suoi limiti, i tipi di input e output e se supporta gli strumenti. OpenCode non può verificare che i
valori di ripiego di un modello personalizzato siano corretti. Se l'endpoint richiede una chiave, aggiungi `apiKey` a `settings` con un riferimento a una
variabile d'ambiente come `"apiKey": "{env:LOCAL_API_KEY}"`. Non includere segreti nei commit.

## Riferimenti

I selettori dei modelli usano `provider/model` con un `#variant` facoltativo:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| Parte      | Regola                                                     |
| ---------- | ---------------------------------------------------------- |
| Provider   | Termina al primo `/`; non può contenere `/` o `#`.         |
| Modello    | Può contenere altri caratteri `/`; non può contenere `#`.  |
| Variante   | Segue `#` quando presente.                                 |
| Maiuscole  | Gli ID di provider e modello distinguono maiuscole e minuscole. |

Usa gli ID del catalogo invece dei nomi visualizzati dei provider. I campi `model` di primo livello, degli agenti e dei comandi accettano la forma a stringa qui sopra
o un oggetto esteso:

```jsonc
{
  "model": {
```

La forma estesa è utile per configurazioni generate o programmatiche.

## Avvertenze

Tieni presenti queste regole quando configuri i modelli:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- Un oggetto di selezione usa `model`; una voce del catalogo di un provider usa `modelID` per l'ID inviato al provider.
- Sebbene la forma di selezione di primo livello accetti una variante, il valore predefinito del catalogo V2 non la conserva. Seleziona le varianti per una
  sessione, un'esecuzione, un agente o un comando.
- Le opzioni dei modelli sono specifiche del provider. Un altro pacchetto di provider può ignorarle o rifiutarle.
- I dati del catalogo, le credenziali e la configurazione valgono per la singola Location. Un modello disponibile in un progetto può non esserlo
  in un altro.
- I file di configurazione normalmente si ricaricano automaticamente. Una richiesta al modello già in corso mantiene le impostazioni con cui è partita.
