---
title: "Agenti"
description: "Definisci agenti riutilizzabili in Markdown o nella configurazione, ciascuno con il proprio system prompt, modello, permessi e modalità."
---

Crea un file Markdown per aggiungere un agente riutilizzabile. Questo esempio aggiunge un revisore in sola lettura che l'agente principale può avviare per le revisioni del codice:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-5-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Chiedi al tuo agente principale di usarlo:

```text
Use the reviewer subagent to review my current changes.
```

Un agente combina un system prompt, una preferenza di modello, permessi e dettagli di visualizzazione in un profilo assistente con un nome.

## Posizioni

Salva gli agenti Markdown a livello globale per tutti i progetti o dentro un progetto:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode cerca le directory `.opencode` del progetto risalendo dalla directory corrente fino alla radice del file system. Un percorso annidato diventa parte dell'ID dell'agente:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Formati

### Markdown

Il frontmatter accetta gli stessi campi di una voce di configurazione `agents`. Il corpo Markdown diventa il prompt `system` dell'agente:

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

I campi frontmatter di V1 sono deprecati. Vedi [File degli agenti](/migrate-v1#agent-files) per come vengono letti i file che li usano ancora.

### JSONC

Definisci gli agenti sotto `agents` in qualsiasi [file di configurazione di OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Selezione

Imposta l'agente principale usato quando una sessione non ne ha selezionato uno:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

Il valore predefinito selezionato deve esistere, essere visibile e supportare l'uso come principale. Altrimenti OpenCode usa `build`, poi il primo agente visibile utilizzabile come principale. Cambiare questa impostazione non sostituisce l'agente memorizzato su una sessione esistente.

## Modalità

Imposta `mode` in base a dove deve essere eseguito l'agente:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Modalità | Comportamento |
| --- | --- |
| `primary` | Viene eseguito come agente principale di una sessione. È il valore predefinito per un nuovo agente personalizzato. |
| `subagent` | Viene eseguito solo in una sessione figlia tramite lo strumento `subagent`. |
| `all` | Viene eseguito come agente principale o come subagente. |

I subagenti lavorano sempre in background, ciascuno nella propria sessione figlia e con un contesto nuovo. L'agente padre riceve un resoconto quando un subagente torna inattivo e al termine di ogni ciclo di lavoro successivo. I permessi `subagent` dell'agente padre stabiliscono quali agenti può avviare; ciascun subagente usa i permessi della propria configurazione.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Agenti integrati

OpenCode include questi agenti visibili:

| Agente | Modalità | Scopo |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Agente di coding predefinito. Gli strumenti e l'accesso fuori dallo spazio di lavoro sono consentiti per impostazione predefinita; le letture sensibili dei file di ambiente richiedono approvazione. |
| **Plan** (`plan`) | `primary` | Esplora e pianifica senza modificare i normali file del progetto. Può scrivere i file di piano di OpenCode quando richiesto, e i comandi shell restano controllati dai permessi. |
| **General** (`general`) | `subagent` | Gestisce ricerca e lavoro in più passi con ampio accesso agli strumenti, ma non può avviare altri subagenti. |
| **Explore** (`explore`) | `subagent` | Cerca e legge codice o fonti web senza modificare file. |

Sovrascrivi un agente integrato usando lo stesso ID:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Gli agenti nascosti `compaction`, `title` e `summary` svolgono manutenzione e non possono essere selezionati direttamente. V2 non ha un agente `scout` integrato.

## Unione

Le definizioni degli agenti si uniscono nell'ordine di configurazione. I valori scalari successivi sostituiscono quelli precedenti, le mappe di richiesta si uniscono per chiave e le regole di permesso si aggiungono:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

I `permissions` globali si applicano prima delle regole specifiche dell'agente, quindi le regole successive dell'agente possono affinarli.

## Opzioni

### Descrizione

`description` spiega lo scopo dell'agente. Aggiungila ai subagenti perché OpenCode la mostra al modello che sceglie quale agente avviare:

```yaml
description: Reviews database migrations for safety
```

### Modalità

`mode` accetta `primary`, `subagent` o `all`. Se omesso su un nuovo agente personalizzato, il valore predefinito è `primary`:

```yaml
mode: all
```

### Modello

`model` usa `provider/model` con un `#variant` facoltativo:

```yaml
model: anthropic/claude-sonnet-5-5#high
```

La configurazione JSON accetta anche la forma estesa:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-5-5",
        "variant": "high",
      },
    },
  },
}
```

- Un subagente usa il modello configurato, oppure eredita il modello della sessione padre quando non ne è configurato nessuno.
- Una sessione memorizza il modello selezionato separatamente. Selezionare un agente principale per ID non cambia quel modello.

### Prompt di sistema

`system` imposta il system prompt dell'agente. Un valore non vuoto sostituisce il prompt di base del provider per quell'agente:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

Le istruzioni del progetto, le skill, i riferimenti e le altre fonti di istruzioni vengono comunque aggiunti. In un agente Markdown, metti questo testo nel corpo del documento invece che in un campo frontmatter `system`.

### Permessi

`permissions` è un elenco ordinato di regole corrispondenti:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Campo | Significato |
| --- | --- |
| `action` | Strumento o azione di permesso. I caratteri jolly sono supportati. |
| `resource` | Percorso, comando, ID agente o altro valore confrontato dall'azione. I caratteri jolly sono supportati. |
| `effect` | `allow`, `ask` o `deny`. |

Vince l'ultima regola corrispondente, quindi metti le regole ampie prima delle eccezioni. Le azioni comuni includono:

| Azione | Copre |
| --- | --- |
| `shell` | Comandi shell |
| `edit` | Strumenti di modifica, scrittura e patch |
| `subagent` | Agenti figli |
| `read`, `glob`, `grep` | Strumenti di ricerca locale |
| `webfetch`, `websearch` | Strumenti web |
| `skill` | Caricamento delle skill |

Per le risorse `read`, `edit` e `external_directory`, OpenCode espande `~` e `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Le risorse shell restano testo grezzo del comando e non espandono quei valori.

### Passi

`steps` imposta un numero massimo positivo di passi del modello:

```yaml
steps: 8
```

All'ultimo passo, OpenCode rimuove gli strumenti e chiede al modello un riepilogo testuale. Un nuovo input dell'utente azzera il conteggio dei passi.

### Visibilità

`hidden` rimuove un agente dagli elenchi normali, dalla scoperta interattiva e dal catalogo dei subagenti:

```yaml
hidden: true
```

Questo controlla la visibilità, non la sicurezza. Usa i permessi per limitare il comportamento.

### Colore

`color` imposta il colore dell'interfaccia dell'agente usando un valore esadecimale a sei cifre:

```yaml
color: "#ff6b6b"
```

### Disattivazione

`disabled` rimuove un agente integrato o personalizzato in quel punto del caricamento della configurazione:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Richieste

`request` accetta overlay di header e corpo JSON per agente:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  Il session runner di V2 conserva questi valori ma non li invia ancora con le richieste ai modelli. Configura le impostazioni
  di richiesta attive sul provider, sul modello o sulla variante del modello.
</Callout>

Non usare campi legacy di primo livello come `temperature`, `top_p`, `prompt`, `permission`, `tools`, `disable` o `maxSteps` nella nuova configurazione degli agenti V2.
