---
title: "API dei provider"
description: "Chiama i provider collegati al tuo spazio di lavoro tramite il gateway di Console con una chiave di Console."
---

Ogni [provider](/console/providers) collegato al tuo spazio di lavoro ha un URL dedicato sul gateway di Console.
OpenCode lo usa automaticamente dopo `/connect`. Usa direttamente l'URL per accedere agli stessi provider dai tuoi strumenti.
Console aggiunge la credenziale del provider prima di inoltrare la richiesta, così la credenziale non lascia mai lo spazio di lavoro.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v4.1-flash",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

## URL del provider

Copia il **Console API URL** dalla pagina del provider in **Providers**.

```text
https://opencode.ai/inference/custom/<connection_id>
```

## Autenticazione

Sostituisci `<token>` con una [chiave di account di servizio](/console/api#service-accounts) creata in Console. Console la sostituisce con
la credenziale della connessione prima di inoltrare.

```text
Authorization: Bearer <token>
```

Console legge la chiave anche dagli header `x-api-key`, `api-key` o `x-goog-api-key`. Puoi quindi usare gli SDK dei provider
configurandoli con l'URL dell'API di Console.

## Endpoint

Aggiungi il percorso API del provider al Console API URL. Console inoltra la richiesta all'URL di base della connessione e
restituisce la risposta del provider invariata.

| Formato              | Percorso                          |
| -------------------- | --------------------------------- |
| Chat Completions     | `/chat/completions`               |
| Responses API        | `/responses`                      |
| Anthropic Compatible | `/messages`                       |
| Google Generative AI | `/models/<model>:generateContent` |
| Embeddings           | `/embeddings`                     |

Invia l'ID del modello come appare nella pagina del provider. Quando un modello ha un ID API diverso a monte, Console lo riscrive.
Le richieste per modelli non abilitati sulla connessione vengono rifiutate.

### Chat Completions

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v4.1-flash",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

### Responses API

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../responses" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-6.1-sol",
    "input": "Say hi"
  }'
```

### Anthropic Compatible

`max_tokens` è obbligatorio.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../messages" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "max_tokens": 1024,
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

### Google Generative AI

Il modello e il metodo fanno parte del percorso. Sostituisci `:generateContent` con `:streamGenerateContent` per trasmettere la
risposta in streaming.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../models/gemini-4-argon:generateContent" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{ "parts": [{ "text": "Say hi" }] }]
  }'
```

## Utilizzo

Le richieste vengono conteggiate nei [budget](/console/budgets) usando il prezzo impostato su ogni modello. Il provider
ti addebita i token.
