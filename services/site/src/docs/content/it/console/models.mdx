OpenCode Console offre un elenco di modelli testati e verificati dal team di OpenCode. Accedi, aggiungi crediti e ottieni una
chiave API per usarli con OpenCode o un altro agente di coding.

Console funziona come qualsiasi altro provider in OpenCode. È **completamente opzionale**, e puoi usare qualsiasi altro provider
al suo posto. Per un abbonamento con utilizzo incluso, vedi [OpenCode Go](/console/go).

## Come funziona

1. Accedi alla [console](https://opencode.ai/console), aggiungi i dettagli di fatturazione e i crediti, e copia la tua chiave API.
2. Esegui `/connect` nella TUI, scegli il provider a consumo di OpenCode e incolla la tua chiave API.

   ```text
   /connect
   ```

3. Esegui `/models` per vedere i modelli disponibili e selezionarne uno.

   ```text
   /models
   ```

Paghi per ogni richiesta e puoi aggiungere crediti al tuo account.

## Endpoint

Puoi anche accedere ai modelli direttamente tramite i seguenti endpoint API. I modelli chat del piano Free richiedono OpenCode;
usa modelli a pagamento o [Go](/console/go) da altri client.

Ogni modello è elencato con la sua API nativa, ma ogni modello testuale funziona anche tramite le altre API, che Console
traduce. Vedi [URL di base](/console/harnesses#base-urls) per l'insieme completo.

### Jev

Jev è un modello System One di TypeSafe AI per decisioni strutturate e veloci. Invece di generare testo, valuta uno `state` rispetto a domande tipizzate e restituisce valori e probabilità che il tuo codice può usare direttamente. Supporta domande sì/no (`noul`), a scelta multipla (`choice`) e basate su rubriche (`score`).

Usa la tua chiave API di OpenCode Console con l'endpoint `https://opencode.ai/inference/systemone/v1/systemone`. Questo esempio verifica se una richiesta di supporto è urgente:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Puoi porre più domande in un'unica richiesta. Jev le valuta in parallelo e restituisce ogni risposta sotto l'ID della domanda corrispondente:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Usa `jev-1.13-free` per usare il modello gratuito a tempo limitato, che esegue Jev 1.13. Vedi la [documentazione di TypeSafe AI](https://docs.typesafe.ai/) per i dettagli sui tipi di domanda e i campi di risposta.

### GPT 6 Luna Decision e Gemini Decision 1

`gpt-6-luna-decision` e `gemini-decision-1` accettano la stessa richiesta System One di Jev, sullo stesso endpoint. Passa immagini, audio, video e PDF in `state` come parti in stile chat (`image_url`, `input_audio`, `video_url`, `file`). GPT 6 Luna Decision accetta testo e immagini; Gemini Decision 1 accetta anche audio, video e PDF.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### Modelli di immagini

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` e `grok-imagine-image-2.0` generano e modificano immagini. Non sono modelli chat, quindi non compaiono mai in `/models` né nell'endpoint dei modelli,
e `opencode/<model-id>` non li seleziona. Chiamali sulla loro API nativa con una chiave di Console, oppure lascia che lo strumento
[`generate_image`](/tools#image-generate) di OpenCode usi un modello di immagini impostando
`experimental.image_generate.model`, ad esempio `opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google accetta i suoi `contents` e `generationConfig` nativi, e xAI le sue opzioni native come `resolution` e
`quality`. OpenAI Images e xAI Images accettano anche modifiche su `/images/edits`.

### Modelli di embedding

`text-embedding-3-small`, `qwen3-embedding-8b` e gli altri modelli di embedding della tabella sopra trasformano il testo in
vettori. OpenCode non li usa per la chat, quindi non compaiono mai in `/models`, e il piano gratuito non li include.
[Go](/console/go#embedding-models) ne include alcuni. Chiamali sull'API Embeddings di OpenAI con una chiave di Console.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` accetta una stringa o un array di stringhe. `data` restituisce un vettore per input, nello stesso ordine.
- `dimensions` accorcia i vettori sui modelli che lo supportano, come `text-embedding-3-small`.
- `encoding_format: "base64"` restituisce i vettori codificati in base64 invece che come float.
- Ogni input deve rientrare nella finestra di contesto del modello.
- La risposta riporta `usage.cost` come qualsiasi richiesta di inferenza. Vedi [Costo](/console/api/inference#cost).

I vettori di modelli diversi non sono confrontabili, quindi genera gli embedding dei tuoi documenti e delle tue query con lo stesso modello. Un
[provider collegato](/console/api/providers#endpoints) serve i propri modelli di embedding su `/embeddings`.

## Contesto

Ci sono molti modelli disponibili, ma solo pochi funzionano bene come agenti di coding. I provider variano anche per configurazione,
prestazioni e qualità, quindi un modello accessibile tramite un gateway come OpenRouter può comportarsi diversamente.

<Callout type="tip">Abbiamo testato un gruppo selezionato di modelli e provider che funzionano bene con OpenCode.</Callout>

Per creare questo catalogo, abbiamo:

1. Testato un gruppo selezionato di modelli e parlato con i loro team di come eseguirli al meglio.
2. Lavorato con i provider per assicurarci che i modelli fossero serviti correttamente.
3. Fatto benchmark di ogni combinazione modello/provider per produrre un elenco che ci sentiamo di consigliare.

Console è un gateway di IA che ti dà accesso a questi modelli.

## Obiettivi

Abbiamo creato Console per:

1. Fare **benchmark** dei migliori modelli e provider per gli agenti di coding.
2. Offrire le opzioni di **massima qualità** senza ridurre le prestazioni o instradare verso provider più economici.
3. Trasferire i **cali di prezzo** vendendo a costo, con un ricarico solo per coprire le commissioni di elaborazione.
