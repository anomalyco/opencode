OpenCode Console 提供一份经过 OpenCode 团队测试和验证的模型列表。登录、充值额度并获取 API 密钥，即可在 OpenCode 或其他编程代理中使用这些模型。

Console 在 OpenCode 中的用法与其他提供商相同。它**完全是可选的**，你也可以改用任何其他提供商。需要包含用量的订阅，请参阅 [OpenCode Go](/console/go)。

## 工作原理

1. 登录 [Console](https://opencode.ai/console)，添加账单信息和额度，然后复制你的 API 密钥。
2. 在 TUI 中运行 `/connect`，选择 OpenCode 按量付费提供商，然后粘贴 API 密钥。

   ```text
   /connect
   ```

3. 运行 `/models` 查看可用模型并选择一个。

   ```text
   /models
   ```

费用按请求收取，你可以随时为账号充值额度。

## 端点

你也可以通过以下 API 端点直接访问这些模型。免费层级对话模型只能在 OpenCode 中使用；其他客户端请使用付费模型或 [Go](/console/go)。

每个模型都以其原生 API 列出，但所有文本模型也能通过 Console 转换的其他 API 使用。完整列表请参阅[基础 URL](/console/harnesses#base-urls)。

### Jev

Jev 是 TypeSafe AI 的 System One 模型，用于快速做出结构化决策。它不生成文本，而是根据带类型的问题评估 `state`，返回代码可以直接使用的值和概率。它支持是/否（`noul`）、多选（`choice`）和基于评分标准（`score`）的问题。

使用 OpenCode Console API 密钥和 `https://opencode.ai/inference/systemone/v1/systemone` 端点。以下示例检查一个支持请求是否紧急：

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

可以在一个请求中提出多个问题。Jev 会并行评估，并在对应的问题 ID 下返回每个答案：

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

使用 `jev-1.13-free` 可以使用限时免费的模型，它运行 Jev 1.13。问题类型和响应字段的详情请参阅 [TypeSafe AI 文档](https://docs.typesafe.ai/)。

### GPT 6 Luna Decision 与 Gemini Decision 1

`gpt-6-luna-decision` 和 `gemini-decision-1` 在同一端点上接受与 Jev 相同的 System One 请求。请在 `state` 中以聊天风格的 part（`image_url`、`input_audio`、`video_url`、`file`）传入图片、音频、视频和 PDF。GPT 6 Luna Decision 接受文本和图片；Gemini Decision 1 还接受音频、视频和 PDF。

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### 图片模型

`gpt-image-2.5-sunburst`、`gemini-nano-banana-2.1` 和 `grok-imagine-image-2.0` 可以生成和编辑图片。它们不是对话模型，因此不会出现在 `/models` 或模型端点中，`opencode/<model-id>` 也无法选择它们。请使用 Console 密钥在它们的原生 API 上调用，或者通过设置 `experimental.image_generate.model`（例如 `opencode/gpt-image-2.5-sunburst`），让 OpenCode 的 [`generate_image`](/tools#image-generate) 工具使用图片模型。

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google 使用其原生的 `contents` 和 `generationConfig`，xAI 使用其原生选项，例如 `resolution` 和 `quality`。OpenAI Images 和 xAI Images 还支持在 `/images/edits` 进行编辑。

### 嵌入模型

`text-embedding-3-small`、`qwen3-embedding-8b` 以及上表中的其他嵌入模型会把文本转换为向量。OpenCode 不会用它们进行对话，因此它们永远不会出现在 `/models` 中，免费层级也不包含它们。[Go](/console/go#embedding-models) 包含其中的一部分。请使用 Console 密钥在 OpenAI 的 Embeddings API 上调用它们。

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` 接受字符串或字符串数组。`data` 会按相同顺序为每个输入返回一个向量。
- 在支持该功能的模型上，`dimensions` 会缩短向量，例如 `text-embedding-3-small`。
- `encoding_format: "base64"` 会返回 base64 编码的向量，而不是浮点数。
- 每个输入都必须适合模型的上下文窗口。
- 响应会像其他推理请求一样报告 `usage.cost`。请参阅[费用](/console/api/inference#cost)。

不同模型的向量无法比较，因此请使用同一个模型嵌入文档和查询。[已连接的提供商](/console/api/providers#endpoints)会在 `/embeddings` 上提供其自己的嵌入模型。

你可以通过[团队](/console/workspaces)与团队共享 Console 模型。所有者和管理员可以[邀请成员](/console/members)、在 **Models** 标签页中选择启用哪些模型、设置[预算](/console/budgets)，以及接入[自己的提供商](/console/providers)。

## 背景

可用的模型很多，但真正适合作为编程代理的只有少数几个。不同提供商在配置、性能和质量上也各不相同，因此通过 OpenRouter 这类网关访问的模型，表现可能与直接访问不同。

<Callout type="tip">我们测试了一组与 OpenCode 配合良好的精选模型和提供商。</Callout>

为了建立这份目录，我们：

1. 测试了一组精选模型，并与各模型团队交流了最佳运行方式。
2. 与提供商合作，确保模型被正确提供。
3. 对每个模型/提供商组合进行基准测试，整理出一份我们愿意推荐的列表。

Console 是一个 AI 网关，让你可以使用这些模型。

## 目标

我们构建 Console 的目标是：

1. 为编程代理**基准测试**最好的模型和提供商。
2. 提供**最高质量**的选项，不降低性能，也不路由到更便宜的提供商。
3. 按成本价销售，把**降价**回馈给你，只加收覆盖支付手续费的部分。
4. **没有锁定**：可以在任何编程代理中使用 Console，也可以在 OpenCode 中使用其他提供商。
