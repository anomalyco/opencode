Standart proxy değişkenlerini ayarlayın ve loopback adreslerini kapsam dışında bırakın. OpenCode, CLI ile arka plan hizmeti
arasında yerel HTTP bağlantıları kullanır. Bu nedenle CLI ortamında proxy ayarlarsanız loopback adreslerini hariç tutmanız gerekir.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` HTTP hedeflerini, `HTTPS_PROXY` HTTPS hedeflerini yönetir. Proxy URL'si her iki değişkende de `http://`
kullanabilir. `NO_PROXY`, doğrudan bağlanan ana bilgisayarların ve adreslerin virgülle ayrılmış listesidir.

## Hizmet

Kabuktan dışa aktarılan değişkenler, arka plan hizmetini yalnızca o kabuktan başlattığınızda etkiler. Hizmetin sonraki
başlatmalarda da aynı ağ ayarlarını kullanması için değişkenleri yönetilen hizmet yapılandırmasına kaydedin.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Yönetilen bir ortam değişkenini değiştirmek çalışan hizmeti durdurur. `service start` onu yeni ortamla yeniden başlatır.
Kabuk bir proxy ayarlıyorsa `NO_PROXY` değişkenini CLI kabuğunda da tutun; çünkü yönetilen hizmet değişkenleri CLI sürecine
değil sunucu sürecine uygulanır.

Kalıcı hale getirilmiş bir değişkeni `service unset env` ile kaldırın:

```bash
opencode service unset env HTTPS_PROXY
```

## Kimlik doğrulama

URL kimlik bilgilerini kabul eden bir proxy için kullanıcı adını ve parolayı kimlik doğrulama gerektiren her proxy URL'sine
ekleyin. `@`, `:` ve `/` gibi karakterleri her iki kimlik bilgisinde de yüzde kodlamasıyla yazın.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Arka plan hizmeti için tam URL'yi kalıcı hale getirin. Değer özel hizmet yapılandırmasında saklanır ve
`opencode service get env` tarafından gösterilir; bu nedenle bu çıktıyı paylaşmayın.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Sertifikalar

Proxy veya hedef, özel bir sertifika yetkilisi tarafından imzalanmış bir sertifika kullanıyorsa `NODE_EXTRA_CA_CERTS`
değişkenini bir PEM dosyasına ayarlayın. Ek yetkililer, süreç başladığında çalışma zamanı güven deposuna eklenir.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Dosya yolunu arka plan hizmeti için kalıcı hale getirin, ardından hizmeti yeniden başlatın:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Antivirüs ve HTTPS denetimi

Antivirüs "HTTPS taraması" veya "şifreli bağlantı taraması" (Kaspersky, Avast, ESET ve diğerleri) ve kurumsal SSL denetim
proxy'leri sunucunun sertifikasını kendi sertifikalarıyla değiştirir. OpenCode bunu reddeder ve istekler şu gibi hatalarla
başarısız olur:

```text
self signed certificate in certificate chain
SELF_SIGNED_CERT_IN_CHAIN
CERT_NOT_YET_VALID
CERT_SIGNATURE_FAILURE
```

Bunu iki yoldan biriyle düzeltin:

- Antivirüs ayarlarında `opencode.ai` ve `*.opencode.ai` adreslerini HTTPS taramasından hariç tutun. Doğrudan bir sağlayıcıya
  bağlanıyorsanız `api.anthropic.com` gibi sağlayıcınızın API ana bilgisayarını da ekleyin.
- Denetim sertifika yetkilisini PEM dosyası olarak dışa aktarın ve [Sertifikalar](#certificates) bölümünde gösterildiği gibi
  `NODE_EXTRA_CA_CERTS` ile güvenilir hale getirin.

## İstemci sertifikaları

Karşılıklı TLS gerektiren bir ağ geçidine sahip sağlayıcıda `settings.tls` ayarlayın. Model istekleri sertifikayı sunar ve
TLS el sıkışması sertifikayı yalnızca isteyen sunuculara gönderir.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "company": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.company.example/v1",
        "tls": {
          "cert": "{file:/etc/company/client.pem}",
          "key": "{file:/etc/company/client.key}",
          "passphrase": "{env:CLIENT_KEY_PASSPHRASE}",
        },
      },
    },
  },
}
```

- `cert` ve `key` PEM metnidir. Bunları dosyalardan okumak için `{file:...}` kullanın. Okunamayan bir dosya `tls` ayarını
  tanımsız bırakır.
- `passphrase` yalnızca şifrelenmiş bir anahtar için gerekir.
- Bun ve Node derlemelerinde çalışır. Cloudflare Workers üzerindeki bir sunucu `fetch` ile istemci sertifikası sunamaz.
- İstemci sertifikası içeren istekler yönlendirmeleri izlemez; böylece sertifika başka bir ana bilgisayara sunulmaz.

O sağlayıcının her model isteği sertifikayı sunar: sohbet, sıkıştırma, görsel ve karar modelleri. `tls` kullanan bir sağlayıcı
WebSocket yerine HTTP kullanır. webfetch gibi araçlar, uzak MCP sunucuları ve eklenti kurulumları sertifikayı sunmaz.

## Ön plan

`--standalone` ve `serve` kendi süreçlerinin ortamını kullanır. `opencode service set env` bu süreçleri yapılandırmaz.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Aynı deseni ön planda çalışan bir sunucuya uygulayın:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Doğrulama

Ayarları uyguladıktan sonra CLI'nin arka plan hizmetine ulaşabildiğini denetleyin:

```bash
opencode api get /api/info
```

Durum kontrolü başarılıysa yerel istemci hizmete erişebiliyor demektir. Hizmetin dış bağlantılarda proxy ve sertifika
yolu ayarlarını doğrulamak için sağlayıcıya normal bir istek gönderin.
