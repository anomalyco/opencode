Bir eklentinin sunucu parçası OpenCode sunucusunda çalışır. OpenCode'un davranışını değiştirir ve özellikler ekler:
araçlar, kancalar, entegrasyonlar, komutlar ve agent'lar. Bir eklenti paketinin nasıl düzenlendiği, yüklendiği ve
yayımlandığı için [Genel bakış](/build/plugins) bölümüne bakın.

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

## Yaşam döngüsü

`setup`, eklenti yüklendiğinde çalışır. Eklenti devreden çıkarıldığında çalışacak bir temizleme işlevi döndürebilir.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### Bağlam

Eklenti bağlamı esasen bir [OpenCode sunucu istemcisidir](/build/client). Okuma ve eylem yöntemleri istemciyle aynı
girdileri ve yanıtları kullanır. Dönüşümler, çalışma zamanı kancaları, yeniden yüklemeler, kayıtlar ve eklenti seçenekleri
için eklentiye özgü yöntemler ekler.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location`, bu eklenti örneğinin yüklendiği konumu açıklar. `directory`, isteğe bağlı `workspaceID` ve `project` üst
verisini (`id`, `directory` ve `canonical`) içerir. Hem Promise hem de Effect eklentilerinde kullanılabilir. Bu, eklenti
örneğinin konumudur; erişebileceği her oturumun veya alacağı her olayın konumu değildir.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### Seçenekler

Eklenti seçeneklerini `opencode.json(c)` içinde nesne biçimiyle iletin.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

Bu değerleri `setup` sırasında `ctx.options` üzerinden okuyun.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## Dönüşümler

Dönüşümler OpenCode'un alan durumuna eşzamanlı düzenlemelerdir ve her biri kendi alanındaki önceki kayıtların üzerine
kurulur. `ctx.model.list()` gibi kayıt defteri okumaları, eklenti kurulumu sırasında da dahil, o ana kadarki her kaydı
yansıtır; başlangıç toplu işlemesi yalnızca güncelleme bildirimlerini birleştirir ve bir okumanın döndürdüğünü asla
geciktirmez. Kaynak durum API'leri yine çalışan kaynakların durumunu bildirir: kayıtlı bir tanım, bağlantısının veya
diğer kaynak işinin tamamlandığı anlamına gelmez.

Kaynaklar, `ctx.provider.transform` üzerinden sağlayıcıları ve değişmez model tanımlarını katkı olarak verir.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

Herhangi bir kayıt, kaldırma veya `reload()` kayıt defterini değişmiş olarak işaretler; sonraki okuma, etkin her
dönüşümü kayıt sırasına göre yeni bir değer üzerinde yeniden oynatarak onu yeniden oluşturur. Dönüşümleri ucuz ve
yinelenebilir tutun. Zaten okuduğunuz bir değer sonraki yeniden oluşturmalarla asla değiştirilmez.

Sağlayıcı dönüşümleri ve kullanılabilirlik çözümlendikten sonra OpenCode etkin sağlayıcıların modellerini somutlaştırır
ve her model dönüşümünü sırayla yeniden oynatır. Bir model politikası, yeni yenilenen kaynaklar dahil tüm aday
koleksiyonunu inceleyebilir.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

Yakalanan girdiler otomatik olarak izlenmez. Harici verileri eşzamanlı geri çağırmadan önce yükleyin, ardından bu girdiler
değiştikten sonra `reload()` çağırın. Burada `loadFromSource()` `{ info: Provider.Info, models: readonly Model.Info[] }`
girdileri döndürür.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

Sağlayıcı değişiklikleri tüm etkin model sonucunu geçersiz kılar; böylece çıktı fiyatı politikası yenilenmiş modelleri
yine filtreler. Yalnızca bir model dönüşümünün yakaladığı girdi değiştiğinde `ctx.model.reload()` kullanın.

## API

### Agent

Tüm agent'ları okuyun veya kimliğiyle bir tane getirin.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

Agent'ları incelemek, oluşturmak, güncellemek veya kaldırmak ya da varsayılan agent'ı seçmek için bir dönüşüm kaydedin.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

Yeni bir agent kaydetmek için `editor.update` kullanın. Kimlik zaten varsa bu yöntem o agent'ı düzenler. Yoksa geri
çağırma işlevini çalıştırmadan önce `Agent.Info.default(id)` ile bir agent oluşturur.

```ts
await ctx.agent.transform((editor) => {
  editor.update("reviewer", (agent) => {
    agent.description = "Reviews code for correctness and maintainability"
    agent.mode = "subagent"
    agent.system = "Review the proposed changes and report actionable findings."
  })
})
```

Bir dönüşümün kullandığı harici durum değiştikten sonra agent'ları yeniden yükleyin.

```ts
await ctx.agent.reload()
```

### Sağlayıcılar

Kullanılabilir sağlayıcıları okuyun veya bir sağlayıcının üst verisini kimliğiyle inceleyin.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

Sağlayıcı dönüşümleri sağlayıcı ayarlarını ve kaynak tanımlarını düzenler. Düzenleyici okumaları etkin olmayan
sağlayıcıları içerir ve değişmez tanımları sunar; `models.update` bir kaynak modelin sahiplenilmiş kopyasını düzenler.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

Bir sağlayıcının kaynak envanterini `models.set` ile değiştirin, ardından yakalanan tanımlar değiştikten sonra yeniden
yükleyin.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

Hesaba özgü keşif için envanteri yüklemek üzere kullanılan bağlantıyı `sourceConnection` olarak iletin. Eklentiniz
yenilenmiş envanterini yayımlayana kadar başka bir bağlantı seçiliyken OpenCode o sağlayıcıyı dışlar.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### Modeller

Kullanılabilir modelleri ve varsayılan seçimi okuyun.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

Model dönüşümleri etkin sağlayıcının eksiksiz aday koleksiyonunu düzenler. Devre dışı adaylar tüm dönüşümler bitene kadar
düzenlenebilir kalır; `update` bir modeli yalnızca kullanılabilir bir sağlayıcı altında ekleyebilir.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})
```

Geri çağırmalar ham model geçersiz kılmalarını düzenler. OpenCode sonucu işlerken sağlayıcı varsayılanları bir kez
birleştirilir; değişmemiş okumalar o sonucu yeniden kullanır. `editor.provider`, model dönüşümü çıktısı yerine etkin
olmayan şablonlar dahil değişmez kaynak tanımlarını sunar.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### Entegrasyonlar

Entegrasyonları okuyun ve etkin kimlik bilgilerini inceleyin.

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

Entegrasyonları bir API anahtarıyla bağlayın.

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

Bir OAuth bağlantı denemesini başlatın, inceleyin, tamamlayın veya iptal edin.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

Komut tabanlı bağlantılar aynı başlatma, durum ve iptal akışını sunar.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

Entegrasyonları incelemek ve kimlik doğrulama yöntemlerini yönetmek için bir dönüşüm kaydedin.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

Bir dönüşümün kullandığı harici durum değiştikten sonra entegrasyonları yeniden yükleyin.

```ts
await ctx.integration.reload()
```

### MCP

MCP sunucularını ve güncel bağlantı durumlarını listeleyin.

```ts
const servers = await ctx.mcp.list()
```

Eklentiler MCP sunucularını yalnızca dönüşümler üzerinden yönetir. Bir sunucu eklemek veya değiştirmek için `editor.set`,
yapılandırmasını değiştirmek için `editor.update`, kaldırmak için `editor.remove` kullanın. Yapılandırmayı `editor.list` ve
`editor.get` ile inceleyin.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

Bir sunucuyu devre dışı bırakmak ve bağlantısını kesmek için dönüşümde `disabled: true`, etkinleştirmek ve OpenCode'un
bağlanmasına izin vermek için `disabled: false` ayarlayın. OpenCode sunucu yaşam döngüsünü dönüştürülmüş
yapılandırmadan uzlaştırır.

Bir dönüşümün kullandığı harici durum değiştiğinde dönüşümleri yeniden uygulamak ve sunucuları uzlaştırmak için
`reload()` çağırın.

```ts
await ctx.mcp.reload()
```

### Generate (deneysel)

const review = await ctx.experimental.generate.text({

### İzinler

Bir eylem yapmadan önce izin isteyin. `assert`, oturumun [izin kurallarını](/permissions), kaydedilmiş onaylar dahil,
değerlendirir ve bir kural `ask` olarak sonuçlandığında kullanıcıya sorar. Eyleme izin verildiğinde sonuçlanır.

```ts
execute: async (input, context) => {
  await ctx.permission.assert({
    sessionID: context.sessionID,
    agent: context.agent,
    source: { type: "tool", messageID: context.messageID, id: context.id },
    action: "deploy",
    resources: [input.environment],
    save: [input.environment],
  })
  return { content: await deploy(input.environment) }
}
```

- `action` ve `resources` kurallarla eşleştirilir. Herhangi bir `deny` eylemi engeller; aksi halde herhangi bir `ask`
  onay ister.
- `save`, kullanıcı her zaman izin vermeyi seçtiğinde saklanan desenleri listeler.
- `agent` kimin kurallarının uygulanacağını seçer ve varsayılan olarak oturumun agent'ını kullanır. `source`, istemi bir
  araç çağrısına bağlar.
- `metadata`, izin istemlerine ve `evaluate` kancalarına ek ayrıntı iletir.

Bir ret kuralı veya geri bildirimli bir ret, nedeni taşıyan bir `Tool.Error` ile reddeder; böylece model bunu görür ve
devam eder. Düz bir ret mevcut adımı bitirir. Bu hataları araç çıktısı olarak döndürmek yerine yayılmalarına izin verin.

Bekleyen izin isteklerini inceleyin veya çözümleyin.

```ts
const pending = await ctx.permission.list({ sessionID })
const request = await ctx.permission.get({ sessionID, requestID })
await ctx.permission.reply({ sessionID, requestID, decision: "once" })
```

Oturum kapsamlı izin kurallarını değiştirin. Agent'ın kurallarından sonra değerlendirilirler ve son eşleşen kural kazanır.
Alt oturumlar oluşturulduklarında yürürlükte olan kuralları devralır.

```ts
await ctx.session.update({
  sessionID,
  permissions: [{ action: "edit", resource: "/path/to/original/checkout/**", effect: "deny" }],
})
```

### Oturumlar

Bir oturum oluşturun veya okuyun.

```ts
const created = await ctx.session.create({ title: "Review" })
const session = await ctx.session.get({ sessionID })
const messages = await ctx.session.context({ sessionID })
```

Oturumları sayfa sayfa listeleyin. Sonraki sayfayı almak için `cursor.next` değerini `cursor` olarak geri iletin. İmleç
filtrelerinizi hatırlar; bu nedenle onları yinelemeniz gerekmez.

```ts
const page = await ctx.session.list({ directory: ctx.location.directory, limit: 20 })
const next = page.cursor.next ? await ctx.session.list({ cursor: page.cursor.next, limit: 20 }) : undefined
```

Sonraki isteklerde kullanılan agent'ı veya modeli değiştirin.

```ts
await ctx.session.switchAgent({ sessionID, agent: "build" })
await ctx.session.switchModel({ sessionID, model: { providerID: "anthropic", id: "claude-sonnet-5-5" } })
```

Kullanıcı promptları, geçici oluşturma istekleri, komutlar veya sentetik mesajlar gönderin.

```ts
const prompt = await ctx.session.prompt({ sessionID, text: "Review the current changes" })
const generated = await ctx.session.generate({ sessionID, prompt: "Summarize this project" })
await ctx.session.command({ sessionID, name: "review", text: "--staged" })
const synthetic = await ctx.session.synthetic({ sessionID, text: "Deployment completed" })
```

`generate`, `text` değerini çağrının `tokens` ve `cost` değerleriyle, bir asistan mesajının bildirdiği biçimde döndürür.

Bir oturumu yeniden adlandırın, kesin veya bekleyin.

```ts
await ctx.session.update({ sessionID, title: "Review" })
await ctx.session.interrupt({ sessionID, resume: false })
await ctx.session.wait({ sessionID })
```

Geçici bir oturumu `remove` ile kaldırın. Kaldırma etkin yürütmeyi durdurur ve alt oturumları özyinelemeli olarak siler.

```ts
await ctx.session.remove({ sessionID })
```

Sıkıştırmayı `compact` ile isteyin. Tamamlanmış bir özet değil kabul edilen gelen kutusu öğesini döndürür; sıkıştırma
varsayılan olarak sonraki adım sınırında çalışır. Kuyruk sırasını korumak için bunun yerine `delivery: "queue"` iletin.

```ts
const compaction = await ctx.session.compact({ sessionID })
```

Anahtarlı oturum talimat girdilerini `instructions.entry` ile ekleyin, listeleyin veya kaldırın. Girdiler oturumun
talimatlarında `<context key="...">` blokları olarak render edilir ve güncellemeler veya kaldırmalar bir mesaj turu
kuyruğa almadan sonraki adım sınırında duyurulur.

```ts
await ctx.session.instructions.entry.put({ sessionID, key: "deploy-target", value: "production" })
const entries = await ctx.session.instructions.entry.list({ sessionID })
await ctx.session.instructions.entry.remove({ sessionID, key: "deploy-target" })
```

### Araçlar

Bir dönüşüm geri çağırmasının dışında, tüm dönüşümlerden sonra şu anda kayıtlı araçları okuyun. Her aracın etkin adını
içeren bir `id` değeri vardır.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

Promise eklentileri dahil olmak üzere araçları eşzamanlı bir dönüşümle kaydedin, güncelleyin ve kaldırın. Dönüşümü kaydetmeden veya yeniden yüklemeden önce harici verileri yükleyin. Aynı etkin araç adı için sonraki geçerli kayıt, önceki kaydın yerini alır.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Promise araç yürütücüleri `context.signal` alır. Oturumu durdurmanın alttaki işlemi de durdurması için onu `fetch` gibi
iptal edilebilir işlere iletin.

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

#### Serbest biçimli araç girdisi

Tam olarak bir gerekli dize alanı olan doğrudan bir araç, modelin o dizeyi JSON sarmalayıcısı olmadan yazmasına izin
verebilir. `freeform` değerini `{ type: "text" }`, `{ type: "regex", pattern }` veya `{ type: "lark", grammar }` yapın.

```ts
editor.add({
  name: "ticket",
  description: "Look up a ticket by ID",
  options: { codemode: false },
  input: Schema.Struct({ id: Schema.String }),
  freeform: { type: "regex", pattern: "OPS-[0-9]+" },
  execute: async ({ id }) => ({ content: await lookup(id) }),
})
```

Seçili modelin API'si models.dev'de `regex` listeliyorsa model `OPS-42` yazabilir. Aksi halde Core **yalnızca**
`freeform` alanını atlar: model yine `ticket` aracına sahiptir ve onu `{"id":"OPS-42"}` ile çağırır. Eksik veya boş
biçim listeleri serbest biçim desteği olmadığı anlamına gelir. Yürütücü her iki durumda da `{ id }` alır.

Code Mode içinde (`codemode: true`), serbest biçimli bir araç dizesini doğrudan alır, örneğin
`await tools.ticket("OPS-42")`. `await tools.ticket({ id: "OPS-42" })` de çalışır.

Geri çağırmanın yakaladığı kaynak verileri değiştirdikten sonra `reload()` çağırın. Yeniden yükleme etkin dönüşümleri
sıralarını değiştirmeden yeniden oynatır; eklenti kurulumunu yeniden çalıştırmaz.

```ts
await ctx.tool.reload()
```

Düzenleyicide şu anda bulunan araçları incelemek için `list()` ve `get()` kullanın. Araçların etkin adlarını içeren bir
`id` değeri vardır ve o kimlik yoksa `get()` `undefined` döndürür. `update` ve `remove` işlemlerini etkin araç adıyla,
ad alanı dahil (yukarıdaki `acme_greeting`) kullanın. Ad alanlarındaki noktalar `_` ile değiştirilir. Araç adlarında
harfler, rakamlar, `_` ve `-` dışındaki karakterler `_` ile değiştirilir. Var olmayan adlar yok sayılır; bir araç
oluşturmak için `add` yöntemini eksiksiz bir tanımla çağırın.
Güncellemeler adı ve ad alanını korur. Yeni şemaları veya seçenekleri atayarak onları değiştirin, iç içe değerleri
değiştirmeyin. Geçersiz güncellemeler günlüğe yazılır ve önceki tanım bozulmadan kalır.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Güncellemeler ve kaldırmalar, MCP katalog yenilemelerinden sonra da dahil, eklemelerle sırayla yeniden oynatılır.
Kayıtlarını elden çıkarmak bu değişiklikleri kaldırır ve kalan dönüşümlerden yeniden oluşturur.

Bir kaydı kaldırdığınızda ilgili dönüşüm de kaldırılır ve sonuç kalan dönüşümlerden yeniden oluşturulur. Böylece kaldırılan dönüşümün geçersiz kıldığı önceki tanım yeniden geçerli olur. Aynı kaydı tekrar kaldırmanın ek bir etkisi yoktur. Eklenti devreden çıkarıldığında kayıtları da kaldırılır.

```ts
await registration.dispose()
```

Her model isteği kararlı ve yürütülebilir bir araç anlık görüntüsü yakalar. Sonraki dönüşümler, yeniden yüklemeler ve
elden çıkarma, zaten yakalanmış tanımları, Code Mode ad alanı açıklamalarını veya yürütücüleri değil gelecekteki anlık
görüntüleri etkiler. Değiştirilebilir eklenti verilerini kapatarak kullanan yürütücüler o verileri yine görür; bir
tanıma bağlı kalması gerektiğinde dönüşüm içinde bir değer yakalayın.

### VCS

Depo bilgilerini, çalışma kopyası durumunu veya dosya diff'lerini okuyun.

```ts
const info = await ctx.vcs.get()
const branches = await ctx.vcs.branch.list({ search: "feature", limit: 10 })
const changes = await ctx.vcs.status()
const diff = await ctx.vcs.diff({ mode: "working", context: 3 })
```

Konum kapsamlı bir VCS sağlayıcısını bir dönüşümle kaydedin. Algılanan depo türüyle eşleşen sağlayıcı otomatik olarak
seçilir; farklı bir sağlayıcı seçmek için `editor.default.set` kullanın.

```ts
await ctx.vcs.transform((editor) => {
  editor.add({
    id: "custom",
    name: "Custom VCS",
    info: async () => ({ branch: { current: "feature", default: "main" } }),
    branches: async (input, { signal }) => readBranches(input, signal),
    status: async (scope, { signal }) => readStatus(scope.worktree, signal),
    diff: async (input, { signal }) => readDiff(input, signal),
  })
  editor.default.set("custom")
})
```

Sağlayıcı geri çağırmaları geçerli konumu, çalışma kopyası kökünü, asıl proje kökünü ve isteğe bağlı depo deposunu alır.
Diff geri çağırmaları ayrıca seçilen modu, istenen bağlamı ve çıktı bayt bütçesini alır. Depo keşfi OpenCode'un yerleşik
Git ve Mercurial algılayıcılarını kullanmaya devam eder.

Sağlayıcılar isteğe bağlı olarak `scope.worktree` içinde bir depo oluşturmak için `init(scope, { signal })` uygulayabilir.
Başlatma sağlayıcıyı algılanan depo türüne göre değil kimliğine göre (varsayılan Git) seçer. Konumda henüz depo olmasa
bile `init` içeren bir sağlayıcı kaydedin; OpenCode onu çağırmadan önce dizinin var olduğunu ve depo içermediğini
denetler, ardından projeyi yeniden keşfeder. Yeni depo biçimleri yine de bu geri çağırmanın ötesinde keşif desteği
gerektirir.

### Worktree'ler

Normal eklenti yaşam döngüsünü kullanarak yerel bir worktree stratejisi kaydedin. Bu örnekteki uygulama modülü seçenek
doğrulamasına ve arka ucun `create`, `remove` ve `list` işlemlerine sahiptir.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

Eklentiyi `plugins` üzerinden yükleyin ve ortak hedefi ayrıca yapılandırın:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- Bir strateji eklemek onu otomatik olarak seçer. Son etkin kayıt kazanır; strateji seçimi yapılandırması gerekmez.
- Stratejinin kaydını kaldırmak veya eklentiyi devreden çıkarmak önceki uygulamayı geri getirir. Başka strateji kalmadığında yerleşik Git stratejisi kullanılır.
- `reload()`, yakalanan girdiler değiştikten sonra dönüşümleri yeniden oynatır; eklenti kurulumunu yeniden çalıştırmaz.
- Oluşturma hataları Git üzerinden yeniden denenmez. Var olan worktree'ler, varsayılan değişse bile kaydedilmiş
  sahiplerini korur.
- Stratejiler yerel dizinleri yönetir. Uzak çalışma alanı sağlama bu arayüzün parçası değildir.

#### İşlemler

Eklenti bağlamı, istemciyle aynı proje tabanlı worktree işlemlerini sunar. Her işlem bir `projectID` gerektirir. `list`
yalnızca aynı projenin bilinen checkout'ları dahil kayıtlı envanteri okur; yapılandırma yüklemez, eklenti başlatmaz veya
dosya sistemi değişikliklerini keşfetmez.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

Oluşturma, yapılandırmayı ve eklentileri projenin kayıtlı `canonical` dizininden yükler ve seçili stratejilerini kullanır.
İsteğe bağlı bir üst `directory`, kaynak `from`, başlangıç `branch` ve `name` kabul eder. Kaynak varsayılan olarak asıl
checkout'tur ve `from` geçersiz kılması o projeye ait olmalıdır. Kaynak seçmek yapılandırma kökünü değiştirmez. Verilen
başlangıç referansı seçili strateji tarafından desteklenmelidir; örneğin Rift'in yerel anlık görüntü işleminin referans
seçme seçeneği yoktur.

Oluşturma ve yenileme, asıl checkout'un eklentilerinin etkinleşmesini bekler. O checkout'un eklenti kurulumu sırasında
yapılan çağrılar o ana kadarki kayıtları görür ve kendi etkinleşmelerini beklemez.

Kaldırma asıl yapılandırmayı yükler ve eklentilerini etkinleştirir, ardından şu anda seçili varsayılan yerine worktree'nin
kaydedilmiş stratejisini kullanır. Kullanılamayan kaydedilmiş sahip bir hata üretir. Worktree'nin hedefi başka bir yerde
olabilir:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

Kayıtlı strateji bulunamazsa Git'e dönülmez; kaldırma işlemi hata verir. Bir strateji, zorla kaldırma için onay istemek üzere `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })` hatasını fırlatabilir. Bunun için `Worktree` öğesini `@opencode/plugin` paketinden içe aktarın. Core veya Git hatalarına bağımlılık gerekmez.

Yenileme asıl yapılandırmayı yükler ve kullanılabilir tüm stratejilerden bilinen checkout köklerinde worktree'leri
bulmalarını ister. Sonuçları birleştirir, kaydedilmiş sahipliği korur ve eksik dizinleri budar. Başarısız bir keşif
kaynağı günlüğe yazılırken diğer kaynaklar devam eder. Var olan dizinler, kullanılabilir hiçbir strateji onları
bildirmese bile kayıtlı kalır. Değişen envanteri okumak için `worktree.updated` olayını izleyin ve `list` komutunu
yeniden çağırın.

```ts
await ctx.worktree.refresh({ projectID })
```

#### Referans

Uygulamalar, adlandırma ve çakışma işlemesinden sonra önerilen bir hedef alır. `create` işleminden gerçek dizini
döndürün; bir arka uç kendi düzenini gerektirdiğinde bu farklı olabilir. OpenCode döndürülen yolu çözer ve envanter,
başlatma komutları ve API sonucu için onu kullanır. Döndürülen dizin var olmalıdır.

Başka bir hedef seçen stratejiler adlandırma çakışmalarını orada yönetir. OpenCode yine de stratejiyi çağırmadan önce
önerilen üst dizini oluşturur. `list`, stratejinin sahip olduğu dizinleri ve varsa depo köklerini bildirmelidir.

## Kancalar

Kancalar, işlemler yürütülürken devreye girer. Kancayı ilgili alana kaydedin ve artık gerekmediğinde döndürülen kaydı kaldırın.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

Birden fazla eklenti aynı kancayı kaydedebilir. OpenCode onları eklenti sırasına göre çalıştırır; böylece sonraki kancalar
önceki kancaların yaptığı değişiklikleri görür.

### Oturumlar

Oturum kancaları prompt kabulünde, model çağrılarında, doğrudan HTTP trafiğinde ve yeniden denemelerde devreye girer.

#### Fork'lar

`fork` kancası, OpenCode geçmişi kopyaladıktan sonra ve fork çağrısı dönmeden önce çalışır. `sessionID` yeni oturumu
tanımlar.

```ts
await ctx.session.hook("fork", ({ sessionID }) => console.log(sessionID))
```

#### Prompt kabulü

Gelen kullanıcı prompt'larını, ekler ve skill'ler çözümlenmeden ve prompt kalıcı gelen kutusuna alınmadan önce işleyin:

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

Kanca sahiplenilmiş ve değiştirilebilir bir taslak alır:

- `prompt`, `text`, `files`, `agents` içindeki agent anmalarını ve seçili `skills` değerlerini içerir.
- `metadata`, uygulama tanımlı kabul üst verisini içerir.
- `delivery` varsayılan olarak `"steer"` olur ve `"queue"` olarak değiştirilebilir.
- Oturum ve mesaj kimlikleri salt okunurdur; bir kanca kabulü yönlendiremez.

Bir kancanın eklediği dosyalar ve skill'ler normal çözümleme ve doğrulama yolunu izler. Metni yeniden yazarken artık
eşleşmeyen ek `mention` uzaklıklarını güncelleyin veya kaldırın. Agent anmaları oturumun etkin agent'ını değiştirmez.

Prompt kancaları şu koşullarda çalışır:

- Kancalar, oturumun konum eklentileri hazır olduktan sonra kayıt sırasına göre çalışır.
- `session.prompt` üzerinden gönderen komutlar kancayı çalıştırır.
- Sentetik mesajlar, kabuk mesajları, sıkıştırma denetimleri ve taşıma denetimleri çalıştırmaz.
- Kanca her model çağrısından önce değil, kabul sırasında bir kez çalışır.
- Model çözümlemesi kabulden sonra yapıldığı için sağlayıcı kapsamı kullanılamaz.

Düzenlemeler kalıcı kullanıcı girdisinin kendisi olur. Hazırlık başarısız olur veya kesilirse OpenCode promptu kabul
etmez.

Prompt kancalarını yeniden denemeye dayanıklı tutun. Tam olarak bir kez çalışan yan etki sınırı değildirler:

- Zaten bekleyen veya teslim edilmiş bir kimlikle yeniden denemek, kancaları yeniden çalıştırmadan özgün kabulü döndürür.
- Eşzamanlı gönderimler kancaları birden fazla kez çalıştırabilir, ancak yalnızca ilk başarılı kabul kazanır.
- Prompt kancaları girdiyi dönüştürür ve tipli bir ret API'si sunmaz.

#### Model istekleri

Model gönderiminden hemen önce birleştirilmiş sistem talimatlarını, mesajları, araçları veya istek seçeneklerini
değiştirin. Bir oturumun yaptığı her istek türünün kendi kancası vardır; böylece bir eklenti agent döngüsünü ve yardımcı
istekleri farklı ele alabilir:

- `context`, araç kaynaklı devamlar dahil agent döngüsü için çalışır.
- `compaction`, kontrol noktası özetleri için çalışır. `messages`, özetlenen konuşma dökümüdür; OpenCode özet promptunu
  kancalar çalıştıktan sonra ekler. Sıkıştırmayı kendiniz kaydetmek ve model çağrısını atlamak için `result` ayarlayın;
  tamamlanmış bir sıkıştırma mesajıyla aynı alanları alır.
- `generate`, geçici `ctx.session.generate` çağrıları için çalışır.
- `title`, başlık oluşturma için çalışır. `agent` veya `tools` içermez. Başlığı kendiniz sağlamak için `result` ayarlayın.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

Değişiklikler yalnızca giden model çağrısını etkiler, kalıcı geçmişi veya yapılandırmayı etkilemez. Her isteğe
uygulanması gereken bir kanca her tür için kaydolmalıdır.

`context`, `compaction` ve `generate` kancalarındaki mesajlar, saklanan mesajlarının `metadata` değerini salt okunur
olarak taşır (örneğin bir `prompt` kancasının ayarladığı değer). Bu, modele gönderilmez.

OpenCode'un talimatlarını tutan `system` parçası ayrıca her kaynağı `metadata.experimental.instructions` içinde
`{ key, text }` olarak listeler, örneğin `core/date` veya `core/environment`; böylece bir kanca kaynakları ayırt
edebilir. Liste bir kopyadır: parçanın `text` değerini düzenlemek onu güncellemez. Bu deneyseldir ve değişebilir.

İstek geçersiz kılmaları şu kuralları izler:

- `options` her model çağrısı için boş başlar; çözümlenmiş model ayarlarını içermez.
- Tipli anahtarlar üretim ayarlarıdır; diğer her anahtar seçili protokole sağlayıcı seçeneği olarak iletilir.
- Kancalar kayıt sırasına göre çalışır ve önceki kancaların yaptığı geçersiz kılmaları görür.
- İstek geçersiz kılmaları model varsayılanlarının, model varsayılanları da rota varsayılanlarının önüne geçer.
- Sağlayıcı seçenek nesneleri özyinelemeli olarak birleşir; diziler ve skaler değerler önceki değerlerin yerini alır.
- Bir geçersiz kılmayı silmek veya `undefined` yapmak, onları kaldırmak yerine yapılandırılmış varsayılanlara geri döner.
- Ham HTTP gövde katmanları protokol indirgemesinden sonra uygulanır ve ortaya çıkan alanları geçersiz kılabilir.

#### Sağlayıcı seçenekleri

Sağlayıcı seçenekleri ham HTTP gövde alanlarını değil seçili protokolün anlamsal seçenek adlarını kullanır. Sağlayıcıya
özgü ayarları eşleşen sağlayıcıyla sınırlayın. Örneğin OpenAI Responses `reasoningEffort` kullanır:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

Üretim seçenekleri seçili protokole ve modele bağlıdır:

- `maxTokens` anlamsal çıktı token limitidir.
- Gemini `topK` destekler; OpenAI Responses bunu sunmaz.

#### Model çözümleme

Deneysel. Bir Oturum bir istek için modeli her çözümlediğinde, onun için herhangi bir şey oluşturulmadan önce çalışır.
`model` seçili model olarak başlar; bu isteği aynı sağlayıcıdan başka bir modelle, model seçicide gizli olanlar dahil,
sunmak için onu değiştirin. Oturum seçili modelini korur; istek ve asistan mesajı yeni modeli kullanır. `kind`, hangi
isteğin çözümlendiğini söyler; böylece bir yönlendirici başlıkları atlayabilir veya sıkıştırmadan sonra yeniden
yönlendirebilir. Başka bir sağlayıcıdan gelen model kullanılamaz olarak başarısız olur.

```ts
await ctx.session.hook(
  "experimental.model.resolve",
  (event) => {
    if (event.model.id === "auto" && event.kind !== "title")
      event.model = { providerID: event.model.providerID, id: pick(event.sessionID) }
  },
  { providerID: "acme" },
)
```

#### Model isteği

Model istek ayarlarını değiştirin ve isteğe bağlı olarak kancayı tek bir sağlayıcıyla sınırlayın. Olay, aşağıdaki HTTP
kancalarıyla aynı `kind` değerini taşır.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### Yerel HTTP

Yerel sağlayıcı isteklerini veya yanıtlarını değiştirin. Gövdeleri tek kullanımlık akışlardır; okumadan önce bir gövdeyi
klonlayın veya değiştirin.

İki kanca da bir oturumun yaptığı her istek için çalışır. `event.kind`, isteği hangi akışın yaptığını söyler: agent
döngüsü için `"primary"`, kontrol noktası özetleri için `"compaction"`, başlık oluşturma için `"title"` ve geçici
`ctx.session.generate` çağrıları için `"generate"`. Yardımcı istekleri ayırt etmek için agent kimliği yerine bunu
kullanın.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### Yerel WebSocket (deneysel)

WebSocket üzerinden akış yapan sağlayıcılar oturum başına bir bağlantı açar ve istekler arasında onu yeniden kullanır;
bu nedenle `http.request` ve `http.response` o trafiği hiç görmez. `experimental.ws.handshake` kancası model çağrısı
başına bir kez, bağlantı seçilmeden önce çalışır. HTTP kancalarıyla aynı `sessionID`, `agent`, `model` ve `kind`
değerlerini, ayrıca bağlantının `url` ve `headers` değerlerini taşır. `url` veya `headers` değiştirmek isteğin hangi
soketi kullanacağını değiştirir; böylece döndürülmüş bir bearer token bağlantıyı yeniden açar.

HTTP kancaları tüm HTTP isteklerinde çalışmaya devam eder. WebSocket yerine HTTP'ye geçildiğinde gönderilen istek de buna dahildir.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` ve `experimental.ws.receive`, bir HTTP istek veya yanıt gövdesini düzenlemenin WebSocket
karşılığı olarak çerçevelerin kendisini sunar. `send`, sağlayıcı sürücüsü giden bir çerçeve oluşturduktan sonra ve o
yazılmadan önce; `receive` ise her gelen çerçevede sürücü onu görmeden önce çalışır. İkisi de çerçeveyi dize olarak
taşır ve kanca döndüğünde `frame` ne tutuyorsa onu gönderir.

OpenCode yeniden yazılmış çerçeveleri doğrulamaz. Sürücü durumu sağlayıcının yanıtlarından izler; bu nedenle protokol
anlamını değiştiren bir yeniden yazma, tıpkı yeniden yazılmış bir HTTP gövdesi gibi, eklentinin sorumluluğundadır.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

Bu kancalar deneyseldir ve adları veya biçimleri değişebilir.

#### Yeniden deneme politikası

Bir sağlayıcı hatası için yeniden deneme kararını geçersiz kılın veya gecikmesini milisaniye olarak değiştirin. Kanca,
OpenCode hatayı sınıflandırıp politikasını önerdikten sonra ama herhangi bir yeniden deneme planlanmadan önce çalışır.
OpenCode'un sonraki denemeyi dahili olarak nasıl yaptığını sunmaz.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

Yeniden deneme kancaları, sonlandırıcı bir hatayı yeniden denenebilir yaparak veya önerilen bir yeniden denemeyi veto
ederek OpenCode'un başlangıçtaki `decision` değerini değiştirebilir.

Yeniden deneme kararları şu kuralları izler:

- Birden fazla kanca kayıt sırasına göre çalışır ve sonraki kancalar geçerli kararı görür.
- Yerleşik azami deneme sayısı kesin bir sınır olarak kalır.
- `attempt`, değerlendirilen fiziksel denemedir. İlk istek `1`dir, bu nedenle ilk yeniden deneme `2`dir.
- `NaN`, sonsuz veya negatif değerler gibi geçersiz gecikmeler hesaplanan gecikmeye geri döner.
- Bağlam taşması kurtarması ayrıdır; çünkü aynı isteği yeniden denemek yerine konuşmayı sıkıştırır.

### İzinler

Yapılandırılmış kurallar değerlendirildikten sonra ve bir eylem çalışmadan veya bir izin istemi yayımlanmadan önce izin
kararlarını gözden geçirin.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-5-5" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

İzin kancaları şu kuralları izler:

- Kancalar `allow` ve `ask` kararları için çalışır.
- Açıkça yapılandırılmış bir `deny` kesindir ve kancayı çağırmaz.
- Bir kanca `effect` değerini `allow`, `ask` veya `deny` olarak değiştirebilir.
- `message`, yükseltilmiş bir izin isteğinde görünür veya ret nedeni olur.

### Kabuk

Kabuk komutlarını, çalışma dizinlerini, zaman aşımlarını, çalıştırılabilir dosyaları veya ortam değişkenlerini yürütmeden
önce değiştirin.

```ts
await ctx.shell.hook("create.before", (event) => {
  event.timeout = Math.min(event.timeout, 60_000)
  event.env.COMPANY_ENV = "development"
})
```

### Araçlar

Yürütmeden önce araç girdisini inceleyin veya değiştirin.

```ts
await ctx.tool.hook("execute.before", (event) => {
  if (event.tool === "read") console.log(event.input)
})
```

Yürütmeden sonra başarılı sonuçları veya hataları inceleyin.

```ts
await ctx.tool.hook("execute.after", (event) => {
  if (event.status === "completed") event.result = { ...event.result, metadata: { observed: true } }
  if (event.status === "error") console.error(event.error.message)
})
```

## V1 desteği

Bir eklenti aynı paket giriş noktasından V1 ve V2 desteği sunabilir. V1 `server()` işlevi ve V2 `setup()` işlevi olan
tek bir nesneyi varsayılan olarak dışa aktarın:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 `server()` çağırır ve döndürülen kancaları kullanır.
- V2 varsayılan dışa aktarımın `id` ve `setup()` değerlerini (Effect eklentilerinde `effect()`) okur, `server()` yok
  sayar.
- Her uygulamayı kendi API'sinde tutun; bir dışa aktarımı paylaşmak V1 kancalarını V2 kancalarına çevirmez.
- V2 tanımını `server()` işlevinden ayrı olarak tür denetlemek için `Plugin.define(...)` sonucunu dışa aktarılan nesneye
  yayın.

V1 nesne biçimi OpenCode `1.18.29` sürümünde desteklenir. Daha eski V1 sürümleri bunun yerine işlev dışa aktarımları
bekleyebilir; kurulu paketi desteklemeyi amaçladığınız en eski V1 sürümüyle ve V2 ile test edin.
