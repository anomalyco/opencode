<Callout type="tip">
  OpenCode'dan kendisinde hata ayıklamasını isteyebilirsiniz. Sorunu açıklayın ve bu sorun giderme sayfasını kullanmasını
  isteyin; aşağıdaki adımları okuyabilir, hizmetini ve günlüklerini inceleyebilir ve sorunu belirlemeye yardımcı olabilir.
</Callout>

OpenCode istemci-sunucu mimarisi kullanır. Arka plandaki bir sunucu oturumları, eklentileri, izinleri ve diğer uygulama
durumunu yönetir. Bir sorunun istemcide, paylaşılan sunucuda mı yoksa belirli bir projede mi olduğunu belirleyerek başlayın.

## Arka plan hizmetini denetleme

Geçerli sunucu bilgilerini gösterin:

```bash
opencode service status
```

API'sinin düzgün çalıştığını doğrulayın:

```bash
opencode api get /api/info
```

Hizmet takılmışsa veya sağlıksızsa yeniden başlatın:

```bash
opencode service restart
```

Açıkça da durdurup başlatabilirsiniz:

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  OpenCode normalde paylaşılan arka plan hizmetini otomatik olarak bulur veya başlatır. Hizmet komutlarına yalnızca
  yaşam döngüsünü teşhis ederken ihtiyaç duyulur.
</Callout>

## Bir tarayıcı kaynağına izin verme

Başka bir kaynaktaki bir tarayıcı istemcisi CORS nedeniyle bağlanamıyorsa istemcinin kaynağını hizmet yapılandırmasına ekleyin:

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

Yol ve sondaki eğik çizgi olmadan, gerektiğinde bağlantı noktası dahil tam bir HTTP veya HTTPS kaynağı kullanın. Birden
fazla kaynağa izin vermek için virgülle ayrılmış listeyi tek argüman olarak iletin; her kaynağın çevresindeki boşluklar
kırpılır:

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` bir JSON dizisi yazdırır. Yapılandırılmış listeyi şu komutla kaldırın:

```bash
opencode service unset cors
```

Hizmet yapılandırmasını ayarlamak veya kaldırmak arka plan hizmetini durdurur. Sonraki başlatması yeni yapılandırmayı alır;
açıkça başlatmak için `opencode service start` kullanın.

Ön planda çalışan bir sunucu için izin verilen her ek kaynak için `--cors` bayrağını yineleyin:

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

`serve --service` ile verilen `--cors` bayrakları o süreç için kalıcı listeyi geçersiz kılar. Bu bayraklar yoksa hizmet modu
kalıcı listeyi kullanır. CORS dinleme adresini değiştirmez ve sunucu kimlik doğrulamasını atlamaz.

## API'yi inceleme

`api` komutu yerel hizmet keşfi ve kimlik doğrulama akışını kullanır. Bir HTTP yöntemi ve yol ya da bir OpenAPI işlem
kimliği kabul eder.

Tüm endpoint'ler ve işlem kimlikleri için [API referansına](/api) bakın.

JSON istek gövdesini `--data` veya `-d` ile, başlıkları `--header` veya `-H` ile iletin.

<Callout type="warning">
  `opencode api` çalıştırmak, uyumlu ve sağlıklı bir hizmet yoksa arka plan hizmetini başlatabilir.
</Callout>

## Günlükleri okuma

Kurulu derlemeler günlükleri şuraya yazar:

```text
~/.local/share/opencode/log/opencode.log
```

Sorunu yeniden üretirken günlüğü izleyin:

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

Her satır bir süreç `run` kimliği ve bir `role` alanı içerir. Oturum, sağlayıcı, eklenti, izin ve araç etkinliği için
`role=server` kullanın.

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## Telemetriyi dışa aktarma

OpenCode, günlüklerini ve izlerini bir OpenTelemetry toplayıcısına veya HTTP üzerinden OTLP kabul eden bir APM
arka ucuna gönderebilir. Toplayıcının base URL'sini yol eklemeden ayarlayın:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer example-token"
export OTEL_RESOURCE_ATTRIBUTES="team=platform,host.name=dev-laptop"
opencode
```

| Değişken | Davranış |
| --- | --- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Base URL. Günlükler `<endpoint>/v1/logs`, izler `<endpoint>/v1/traces` adresine gönderilir. Değişken ayarlı değilse dışa aktarma kapalıdır. |
| `OTEL_EXPORTER_OTLP_HEADERS` | Her dışa aktarmada gönderilen, virgülle ayrılmış `key=value` başlıkları. Örneğin bir API anahtarı gönderebilirsiniz. |
| `OTEL_RESOURCE_ATTRIBUTES` | Her kayda eklenen, virgülle ayrılmış ve URL kodlaması uygulanmış `key=value` öznitelikleri. Tek bir giriş bile hatalı biçimlendirilmişse özniteliklerin hiçbiri eklenmez. |

Her kayıtta ayrıca `service.name` (`opencode`), `service.version`, `deployment.environment.name` (sürüm kanalı),
`opencode.client` ve günlük dosyasındakiyle aynı çalıştırma kimliğini taşıyan `opencode.run` bulunur.

Arka plan hizmeti ayrı bir süreçtir ve kabuğunuzdaki ortam değişkenlerini devralmaz. Model çağrılarının ve araç
çalıştırmalarının izlenmesi için değişkenleri hizmette de ayarlayın:

```bash
opencode service set env OTEL_EXPORTER_OTLP_ENDPOINT http://localhost:4318
opencode service set env OTEL_EXPORTER_OTLP_HEADERS "authorization=Bearer example-token"
opencode service start
```

## Heap anlık görüntüsü alma

Çalışan arka plan sunucusunun bellek (heap) anlık görüntüsünü her platformda yazın:

```bash
opencode debug heap-dump
```

Komut anlık görüntü tamamlanana kadar bekler, ardından yolunu yazdırır:

```text
/home/me/.local/share/opencode/log/heap-48213-2026-10-23T013012345Z.heapsnapshot
```

`--directory` ile başka bir yere yazın. Sunucu dizin yoksa oluşturur:

```bash
opencode debug heap-dump --directory ./snapshots
```

- Yalnızca zaten çalışan bir sunucu kullanır. Asla bir sunucu başlatmaz, değiştirmez veya yeniden başlatmaz.
- `opencode serve` ile başlattığınız bir sunucuyu yakalamak için `--server <url>` kullanın. Parolası varsa
  `OPENCODE_PASSWORD` ayarlayın. `--directory` bu durumda sunucunun makinesindeki bir yoldur.
- Dosyayı Chrome DevTools'un Memory panelinde açın.

<Callout type="warning">
  Sunucu anlık görüntüyü yazarken duraklar ve bellek kullanımı kısa süreliğine artabilir. Anlık görüntü promptlar, dosya
  içerikleri ve kimlik bilgileri barındırabilir. Herkese açık paylaşmayın.
</Callout>

### Masaüstü uygulamasında

Komut paletinden **Capture heap snapshots** komutunu çalıştırın. İndirilenler klasörünüzde uygulamanın her bölümünün bir
anlık görüntüsünü ve anlık görüntünün gösteremediği belleğin dökümünü içeren bir klasör yazar:

```text
opencode-heap-2026-10-23T013012345Z/
  memory.json                  where the memory is, per process, in MiB: start here
  memory-infra.json            Chromium's memory dump trace; open it in https://ui.perfetto.dev
  heap-48213-….heapsnapshot    the desktop's own server
  window-1-48390.heapsnapshot  one per app window
  main-48102.heapsnapshot      the desktop main process
  gpu.json                     the GPU and driver
  manifest.json                processes, PIDs, and memory before and after; written last
```

- Bir heap anlık görüntüsü yalnızca JavaScript nesnelerini ve sayfayı tutar. Görseller, yerleşim, birleştirici katmanları
  ve GPU belleği bunun yerine `memory.json` ve `memory-infra.json` içindedir.
- Uzak sunucular yakalanmaz. Bunun yerine o makinede `opencode debug heap-dump` kullanın.
- Sunucu anlık görüntüsünü doğrudan klasöre yazar; bu nedenle büyük bir şey taşınmaz veya kopyalanmaz.
- Ziyaret ettiğiniz sayfaların içeriğini barındırdıkları için tarayıcı sekmeleri dahil edilmez.

## CPU ve bellek profilleri alma

macOS ve Linux'ta tanılama verisi toplamak için çalışan bir OpenCode sürecine sinyal gönderebilirsiniz. Arka plan
sunucusunun PID değerini durum kontrolü endpoint'inden alın:

```bash
opencode api get /api/info
```

Yanıttaki `pid` değerini şu sinyallerden biriyle kullanın:

- `SIGPROF` on saniyelik bir CPU profili yakalar:

  ```bash
  kill -SIGPROF <pid>
  ```

  Sonuç günlük dizinine `cpu-<pid>-<timestamp>.cpuprofile` olarak yazılır.

- `SIGUSR1` bir bellek (heap) anlık görüntüsü yakalar:

  ```bash
  kill -SIGUSR1 <pid>
  ```

  Sonuç günlük dizinine `heap-<pid>-<timestamp>.heapsnapshot` olarak yazılır.

Dosyayı açmadan önce `opencode.log` içinde `CPU profile written` veya `heap snapshot written` ifadesini bekleyin. İlgili
günlük girdisi tam yolunu içerir. Her iki dosya türünü de Chrome DevTools'ta inceleyebilirsiniz.

<Callout type="note">
  Sinyalle tetiklenen profiller Windows'ta kullanılamaz. Heap anlık görüntüleri için bunun yerine
  `opencode debug heap-dump` kullanın. Heap anlık görüntüsü yazmak süreci duraklatabilir ve bellek kullanımını geçici
  olarak artırabilir.
</Callout>

## Hizmet dosyaları

Paylaşılan sunucu kendisini şurada kaydeder:

```text
~/.local/state/opencode/service.json
```

Özel hizmet yapılandırması ayrı olarak şurada saklanır:

```text
~/.config/opencode/service.json
```

Veritabanı normalde şurada bulunur:

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` veritabanı konumunu geçersiz kılabilir.

<Callout type="warning">
  Sorun giderirken hizmet dosyalarını veya veritabanını silmeyin ya da düzenlemeyin. Daemon'ı yönetmek için hizmet
  komutlarını kullanın ve kalıcı verileri harici araçlarla incelemeden önce yedek alın.
</Callout>

## Sorun bildirme

Yeniden üretilebilir bir sorunu bildirirken şunları ekleyin:

- `opencode --version` çıktısı
- `opencode service status` çıktısı
- Sorunu yeniden üreten en küçük adım dizisi
- Sorunun paylaşılan hizmeti, belirli bir istemciyi mi yoksa tek bir projeyi mi etkilediği
- İlgili günlük satırları ve bunların `run` ve `role` alanları

Günlükleri paylaşmadan önce API anahtarlarını, yetkilendirme başlıklarını, promptları, dosya içeriklerini ve diğer hassas
verileri kaldırın.

Yeniden üretilebilir sorunları [GitHub Issues](https://github.com/anomalyco/opencode/issues) üzerinde bildirin.
