OpenCode [Model Context Protocol](https://modelcontextprotocol.io/) sunucularına bağlanır ve araçlar, promptlar, kaynaklar ve talimatlar gibi yetenekleri kullanıma açar. MCP araçları model bağlamı tükettiği için yalnızca ihtiyaç duyduğunuz sunucuları ekleyin.

## Kurulum

Uzak bir sunucuyu onu kullanacak projeden ekleyin, ardından bağlantısını denetleyin:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp list
```

Komut sunucuyu proje [yapılandırmasına](/config) yazar. Her projede kullanılabilir kılmak için `--global` ekleyin:

```sh
opencode mcp add context7 --global --url https://mcp.context7.com/mcp
```

Uzak sunucular varsayılan olarak OAuth kullanır. Listede `needs authentication` görünüyorsa OpenCode'u açın, `/mcps` çalıştırın, sunucuyu seçin ve oturum açın. Bağlı bir sunucu agent'ın kullanması için hazırdır:

```text
✓ context7  connected
```

## Yapılandırma

Bir sunucuyu elle yapılandırmak için ona `mcp.servers` altında benzersiz bir ad verin. V2 sunucu adlarını doğrudan `mcp` altına koymaz.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
      },
    },
  },
}
```

Sunucular otomatik olarak bağlanır. Bir sunucuyu bağlamadan yapılandırılmış tutmak için `enabled` alanı değil `disabled` kullanın:

```jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "disabled": true,
      },
    },
  },
}
```

Daha yüksek öncelikli bir proje yapılandırması aynı ada sahip sunucu nesnesinin tamamının yerini alır. Ayrı bağlantılar veya hesaplar için farklı adlar kullanın; aksi halde geçersiz kılmada gerekli her alanı yineleyin:

```jsonc title="opencode.jsonc"
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
      },
    },
  },
}
```

## Yerel

Yerel bir sunucu, OpenCode'un MCP stdio taşıması üzerinden başlattığı bir komuttur. `--` sonrasında bir komutla ekleyin:

```sh
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything
```

Ortam değişkenlerini yinelenen `--env` bayraklarıyla iletin:

```sh
opencode mcp add everything --env LOG_LEVEL=info -- npx -y @modelcontextprotocol/server-everything
```

Çalışma dizini gibi diğer süreç seçenekleri için yapılandırmayı kullanın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "everything": {
        "type": "local",
        "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
        "cwd": ".",
        "environment": {
          "LOG_LEVEL": "info",
          "MCP_API_KEY": "{env:MCP_API_KEY}",
        },
      },
    },
  },
}
```

| Alan | Gerekli | Açıklama |
| --- | --- | --- |
| `type` | Evet | `"local"` olmalıdır. |
| `command` | Evet | Çalıştırılabilir dosya ve ardından argümanları. |
| `cwd` | Hayır | Süreç dizini. Göreli yollar çalışma alanından çözümlenir; varsayılan da budur. |
| `environment` | Hayır | OpenCode'un devraldığı süreç ortamına eklenen dize değişkenleri. |
| `disabled` | Hayır | `true` olduğunda bağlantıyı engeller. Varsayılan `false`dur. |
| `codemode` | Hayır | Araçları Code Mode yerine doğrudan sunmak için `false` yapın. Varsayılan `true`dur. |
| `timeout` | Hayır | Sunucu başına zaman aşımı geçersiz kılmaları. |
| `protocol` | Hayır | `auto` (varsayılan), `legacy` veya `2026-07-28`. Bkz. [Protokol sürümü](#protocol-version). |
| `pool` | Hayır | Dizinler arasında tek bağlantı paylaş. Varsayılan `false`dur. Bkz. [Paylaşılan bağlantılar](#shared-connections). |

Ortam değişkeninin değerini yerleştirmek için `{env:NAME}` kullanın. `$NAME` gibi kabuk ifadeleri JSON dizelerinde genişletilmez:

```jsonc
{
  "environment": {
    "MCP_API_KEY": "{env:MCP_API_KEY}",
  },
}
```

## Uzak

Uzak bir sunucu MCP Streamable HTTP taşımasını kullanır ve mutlak bir URL gerektirir:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
```

İstek başlıklarını yinelenen `--header` bayraklarıyla iletin. `{env:NAME}` referanslarını tırnak içine alın; böylece kabuk bunları olduğu gibi yazar:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp --header 'CONTEXT7_API_KEY={env:CONTEXT7_API_KEY}'
```

Diğer seçenekler için yapılandırmayı kullanın. Gizli değerleri dosyada değil ortam değişkenlerinde saklayın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}",
        },
      },
    },
  },
}
```

| Alan | Gerekli | Açıklama |
| --- | --- | --- |
| `type` | Evet | `"remote"` olmalıdır. |
| `url` | Evet | Mutlak Streamable HTTP endpoint'i. |
| `headers` | Hayır | Endpoint'e gönderilen, değerleri dize olan HTTP başlıkları. |
| `oauth` | Hayır | OAuth ayarları veya OAuth'u kapatmak için `false`. |
| `disabled` | Hayır | `true` olduğunda bağlantıyı engeller. Varsayılan `false`dur. |
| `codemode` | Hayır | Araçları Code Mode yerine doğrudan sunmak için `false` yapın. Varsayılan `true`dur. |
| `timeout` | Hayır | Sunucu başına zaman aşımı geçersiz kılmaları. |
| `protocol` | Hayır | `auto` (varsayılan), `legacy` veya `2026-07-28`. Bkz. [Protokol sürümü](#protocol-version). |
| `pool` | Hayır | Dizinler arasında tek bağlantı paylaş. Varsayılan `false`dur. Bkz. [Paylaşılan bağlantılar](#shared-connections). |

`oauth: false` yalnızca sunucu sadece bir API anahtarı veya başka bir başlık kimlik bilgisi kullandığında kullanın:

```jsonc
{
  "type": "remote",
  "url": "https://mcp.example.com/mcp",
  "oauth": false,
  "headers": { "Authorization": "Bearer {env:MCP_API_KEY}" },
}
```

## OAuth

`oauth` değeri `false` olmadığı sürece uzak sunucularda OAuth etkindir. OpenCode yetkilendirme sunucusunu keşfeder, PKCE ile oturum açar ve token'ları yeniler. Kimlik bilgileri proje yapılandırmasının dışında saklanır.

Çoğu sunucu yalnızca URL'ye ihtiyaç duyar:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
      },
    },
  },
}
```

Sunucu kimlik doğrulama gerektiriyorsa `/mcps` çalıştırın, sunucuyu seçin ve tarayıcıda yetkilendirmeyi tamamlayın. CLI aynı akışı başlatabilir:

```sh
opencode mcp auth sentry
```

### Başka bir makinedeki tarayıcı

OpenCode SSH, bir kapsayıcı veya uzak bir sunucu üzerinden çalıştığında tarayıcı oturum açtıktan sonra OpenCode'a ulaşamaz ve yüklenmeyen bir sayfa gösterir. O sayfanın URL'sini adres çubuğundan kopyalayıp oturum açma istemine yapıştırın:

```text
http://127.0.0.1:52817/callback?code=...&state=...
```

İstem, OpenCode tarayıcıyı beklerken `/mcps` içinde, `opencode mcp auth` içinde ve masaüstü ve web uygulamasının oturum açma iletişim kutusunda görünür.

### İstemci kaydı

OpenCode kendisini yetkilendirme sunucusuna uygulanan ilk yöntemle tanıtır:

| Yöntem | Kullanıldığı durum |
| --- | --- |
| Önceden kayıtlı istemci | `oauth.client_id` yapılandırılmıştır. |
| [Client ID Metadata Document](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#client-id-metadata-documents) (CIMD) | Yetkilendirme sunucusu CIMD ve genel istemcileri destekler ve `oauth.redirect_uri` ayarlanmamıştır. |
| [Dinamik istemci kaydı](https://datatracker.ietf.org/doc/html/rfc7591) (DCR) | Yukarıdakilerin hiçbiri geçerli değildir. OpenCode bir istemci kaydeder ve sonraki oturum açmalarda onu yeniden kullanır. |

Bir yetkilendirme sunucusu CIMD'yi meta verileriyle etkinleştirir:

```json
{
  "issuer": "https://auth.example.com",
  "client_id_metadata_document_supported": true,
  "token_endpoint_auth_methods_supported": ["none"]
}
```

CIMD ile OpenCode meta veri belgesi URL'sini `client_id` olarak gönderir ve kaydı atlar:

```text
https://opencode.ai/oauth/opencode/client.json
```

Belge, bu loopback yönlendirmelerine port belirtilmeden izin verir:

- `http://127.0.0.1/callback`
- `http://localhost/callback`
- Eski istemciler için `http://127.0.0.1/mcp/oauth/callback`

Yetkilendirme sunucuları [RFC 8252](https://datatracker.ietf.org/doc/html/rfc8252#section-7.3) gereği bu yönlendirmelerde herhangi bir loopback portunu kabul eder. Bu nedenle `callback_port` CIMD ile çalışır. Özel bir `redirect_uri` ise çalışmaz; bu durumda OpenCode DCR'ye geçer.

Yetkilendirme sunucusu ne CIMD ne de DCR destekliyorsa önceden kayıtlı bir istemci yapılandırın.

### Önceden kayıtlı istemciler

Bir sağlayıcı size istemci kimlik bilgileri verdiğinde V2'nin snake_case OAuth alanlarını kullanın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "oauth": {
          "client_id": "{env:MCP_CLIENT_ID}",
          "client_secret": "{env:MCP_CLIENT_SECRET}",
          "scope": "tools:read tools:execute",
          "callback_port": 19876,
          "redirect_uri": "http://127.0.0.1:19876/callback",
        },
      },
    },
  },
}
```

| Alan | Açıklama |
| --- | --- |
| `client_id` | Önceden kayıtlı istemci kimliği. CIMD ve DCR'nin önüne geçer. |
| `client_secret` | Gizli istemci için sır; token isteği gövdesinde gönderilir. Genel istemcilerde bunu atlayın. |
| `scope` | İstenecek boşlukla ayrılmış kapsamlar. Sunucu kimlik doğrulanmamış bir isteği reddettiğinde belirttiği kapsam varsayılandır. |
| `callback_port` | `1` ile `65535` arasında yerel geri çağırma bağlantı noktası. Varsayılan olarak `redirect_uri` bağlantı noktası, sonra kullanılabilir bir geçici bağlantı noktası kullanılır. |
| `redirect_uri` | Yolu ve portu yerel geri çağırma dinleyicisine ulaşan, önceden kayıtlı loopback URI'si. Ayarlanması CIMD'yi kapatır. |
| `auth_server_metadata_url` | Yetkilendirme sunucusunun OAuth veya OpenID Connect meta veri belgesinin URL'si. MCP sunucusu, yetkilendirme sunucusunu belirten korumalı kaynak meta verilerini yayımlamadığında ayarlayın. |

Yeniden oturum açmanız veya hesap değiştirmeniz gerektiğinde saklanan OAuth kimlik bilgilerini kaldırın:

```sh
opencode mcp logout sentry
```

## Zaman aşımları

Zaman aşımları pozitif tam sayı milisaniyelerdir. Varsayılanları `mcp.timeout` altında ayarlayın; bir sunucunun `timeout` nesnesi eşleşen varsayılanları geçersiz kılar.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "timeout": {
      "startup": 45000,
      "catalog": 30000,
      "execution": 600000,
    },
    "servers": {
      "slow-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "timeout": {
          "catalog": 60000,
        },
      },
    },
  },
}
```

| Zaman aşımı | Varsayılan | Geçerli olduğu alan |
| --- | --- | --- |
| `startup` | 30 saniye | Taşıma bağlantısı ve sunucu başlatma. |
| `catalog` | 30 saniye | Araç, prompt, kaynak ve kaynak şablonlarını listeleme. |
| `execution` | 12 saat | Araç çağrıları, prompt alma ve kaynak okumaları. |

## Protokol sürümü

OpenCode varsayılan olarak her sunucuyu 2026-07-28 revizyonu için yoklar ve sunucu desteklemiyorsa klasik MCP `initialize` el sıkışmasına geri döner. Yoklamayı atlamak için bir sunucunun `protocol` değerini `legacy` yapın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "older": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "protocol": "legacy",
      },
    },
  },
}
```

| Değer | Davranış |
| --- | --- |
| `auto` | Varsayılan. 2026-07-28 revizyonu için `server/discover` ile yoklar ve sunucu desteklemiyorsa, uzak bir sunucu yoklamaya HTTP 5xx hatasıyla yanıt verdiğinde de `legacy`ye geri döner. |
| `legacy` | `initialize` gönderir ve 2025-11-25 dahil önceki protokol sürümlerini destekler. |
| `2026-07-28` | 2026-07-28 revizyonunu zorunlu kılar. Daha eski sunucularda bağlantı başarısız olur. |

Daha eski bir yerel sunucuyu yoklamak kısa ömürlü ek bir süreç ekler ve sunucu bilinmeyen istekleri yok saydığında başlangıç zaman aşımına kadar bekleyebilir; bu nedenle 2026-07-28 revizyonundan önce geldiğini bildiğiniz sunucularda `legacy` ayarlayın.

## Paylaşılan bağlantılar

Bir OpenCode sunucusunda birçok dizin açık olabilir ve her biri kendi başına her MCP sunucusuna bağlanır. Aynı sunucu ayarlarına sahip dizinlerin tek bir bağlantıyı ve tek bir araç listesini paylaşması için `pool` değerini `true` yapın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "cloudflare": {
        "type": "remote",
        "url": "https://mcp.cloudflare.com/mcp",
        "pool": true,
      },
    },
  },
}
```

- Yalnızca 2026-07-28 revizyonundaki bağlantılar paylaşılır. Daha eski bir revizyonla yanıt veren veya `legacy` olarak ayarlanmış bir sunucu dizin başına bir bağlantı tutar.
- Dizinler bir bağlantıyı yalnızca onu değiştiren her şey eşleştiğinde paylaşır: uzak sunucu için URL, başlıklar, OAuth ayarları ve oturum açılmış hesap; yerel sunucu için komut, çalışma dizini ve ortam. Zaman aşımları ve `protocol` de eşleşmelidir. Sunucunun adının eşleşmesi gerekmez, ancak oturum açmalar ad başına saklandığı için bir OAuth sunucusu yalnızca aynı ad altında paylaşılır.
- Yerel bir sunucu yalnızca bu makinedeki dizinler arasında paylaşılır, bir çalışma alanındakiler arasında değil. Projeler arasında paylaşmak `"~"` gibi sabit bir `cwd` gerektirir. Sabit bir çalışma dizini yoksa her projenin klasöründe çalışır; böylece her proje kendi sunucusunu alır ve OpenCode bir uyarı günlüğe yazar.
- Paylaşılan bir bağlantının kökleri yoktur. Bir araç girdi istediğinde istek onu çağıran dizinde görünür.
- Bağlantı, onu kullanan son dizin kapandığında veya sunucunun bağlantısını kestiğinde kapanır.

## Adlar

OpenCode bir aracı `<server>_<tool>` olarak adlandırır. Harf, sayı, `_` ve `-` dışındaki karakterleri `_` ile değiştirir:

```text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id
```

MCP promptları `<server>:<prompt>` adlı komutlara dönüşür ve aynı normalleştirmeyi kullanır. Örneğin:

```text
/context_7:find_docs
```

Komut metni promptun argümanlarını sırayla doldurur. Argümanları boşlukla ayırın ve boşluk içeren değerleri tırnak içine alın:

```text
/context_7:find_docs react "server components"
```

Normalleştirmeden sonra benzersiz kalan kısa sunucu adları seçin. Varsayılan Code Mode'da araçlar normalleştirilmiş sunucu adına göre gruplanır:

```text
tools.context_7.resolve_library_id(...)
```

## İzinler

Code Mode varsayılandır. Bir sunucunun araçları sağlayıcının yerel araç listesinde kalması gerektiğinde `codemode` değerini `false` yapın:

```jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "codemode": false,
      },
    },
  },
}
```

Sunucularının bağlantısını kesmeden araçları gizlemek veya reddetmek için izin eylemlerini kullanın. Normalleştirilmiş `<server>_<tool>` adıyla eşleştirin:

```jsonc
{
  "permissions": [
    {
      "action": "context7_*",
      "resource": "*",
      "effect": "deny",
    },
  ],
}
```

## Kaynaklar

Agent'lar MCP kaynaklarını `list_mcp_resources` ve `read_mcp_resource` olmak üzere iki yerleşik araçla okur. Bunları şu izin eylemleriyle denetleyin:

| Eylem | Kaynak |
| --- | --- |
| `opencode_list_mcp_resources` | Sunucu adı. |
| `opencode_read_mcp_resource` | `<server>:<uri>` |

Örneğin `docs` sunucusundan her okumaya izin verin:

```jsonc
{
  "permissions": [
    {
      "action": "opencode_read_mcp_resource",
      "resource": "docs:*",
      "effect": "allow",
    },
  ],
}
```

## Sunucu talimatları

Bir sunucu başlatma sırasında talimat döndürdüğünde OpenCode bunları sistem promptuna ekler:

```text
<mcp_instructions>
  <server name="sentry">
    Search for an existing issue before creating a new one.
  </server>
</mcp_instructions>
```

Code Mode kullanan sunucular için OpenCode agent'ın sunucunun araçlarını nerede bulabileceğini söyleyen bir satır ekler.

Agent'ın izinleri bir sunucunun tüm araçlarını reddettiğinde o sunucunun talimatları atlanır. `execute` reddedildiğinde sunucunun araçları doğrudan listelenir ve talimatları Code Mode satırı olmadan korunur.

## Girdi istekleri

Sunucular bir çağrı sırasında MCP elicitation ile girdi isteyebilir. OpenCode isteği bir form olarak veya URL istekleri için açılacak bir bağlantı olarak gösterir:

```text
sentry is requesting input
```

Formu kapatmak isteği iptal eder.

## Bağlam

Bir oturum adına yapılan çağrılar için OpenCode oturum kimliğini `CallToolRequest.params._meta["ai.opencode/sessionID"]` içinde gönderir. Bu, doğrudan araçlar ve stdio ile Streamable HTTP üzerinden Code Mode için geçerlidir:

```json
{
  "method": "tools/call",
  "params": {
    "name": "lookup",
    "arguments": { "query": "example" },
    "_meta": { "ai.opencode/sessionID": "ses_..." }
  }
}
```

Kimlik bir araç argümanı değil istek üst verisidir; bu nedenle modelin gördüğü şemada yer almaz. Ona opak bir ilişkilendirme değeri olarak davranın:

| Kural | Davranış |
| --- | --- |
| Kimlik | MCP taşıma oturumunu değil çağrıyı yapan OpenCode oturumunu tanımlar. |
| Varlık | Oturum bağlamı olmayan çağrılarda bulunmayabilir. |
| Güvenlik | Kimlik doğrulama veya yetkilendirme için tek başına kullanmayın. |
| Gizlilik | Uzak sunucular ham kimliği alır ve günlüğe yazabilir veya saklayabilir. |

## Yönetim

Sunucuları ve güncel bağlantı durumlarını herhangi bir projeden listeleyin:

```sh
opencode mcp list
```

Sunucuları görüntülemek, bağlanmak, bağlantısını kesmek veya kimlik doğrulamak için OpenCode'da `/mcps` kullanın. Sunucu eklemek ve OAuth kimlik bilgilerini yönetmek için CLI'yı kullanın:

```sh
opencode mcp add sentry --url https://mcp.sentry.dev/mcp
opencode mcp auth sentry
opencode mcp logout sentry
```

OAuth destekli sunuculardan seçim yapmak için `opencode mcp auth` komutunu ad vermeden çalıştırın:

```sh
opencode mcp auth
```

Bir sunucuyu kaldırmak için onu eklediğiniz proje veya genel yapılandırmadan girdisini silin:

```jsonc
{
  "mcp": {
    "servers": {},
  },
}
```

`/mcps` içinde bir sunucunun bağlantısını kesmek yapılandırmayı değiştirmez. OAuth istemci ayarları, zaman aşımları, çalışma dizinleri için veya bir sunucuyu bağlantısız tutmak için yapılandırmayı doğrudan düzenleyin:

```jsonc
{
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
        "disabled": true,
      },
    },
  },
}
```
