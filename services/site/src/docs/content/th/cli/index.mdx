รัน CLI ในโปรเจกต์เพื่อเปิดอินเทอร์เฟซเทอร์มินัลแบบเต็มหน้าจอ

```bash
opencode
```

ส่งไดเรกทอรีเพื่อทำงานในโปรเจกต์อื่น

```bash
opencode ~/code/my-project
```

เทอร์มินัลที่แนะนำ

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

การรองรับ Truecolor ทำให้ธีมแสดงสีได้แม่นยำที่สุด เทอร์มินัลที่ไม่รองรับจะใช้สีใกล้เคียงจากพาเลตต์ที่มี

## ระบบอัตโนมัติ

ใช้ `opencode run` เพื่อส่งพรอมต์โดยไม่เปิดอินเทอร์เฟซแบบอินเทอร์แอกทีฟ ออกแบบสำหรับสคริปต์ งาน CI และ
เวิร์กโฟลว์อื่นที่ต้องการผลลัพธ์ของโมเดลโดยตรงในเทอร์มินัล

```bash
opencode run "Explain this repository"
```

## Mini

ใช้ `opencode mini` เพื่อเปิดอินเทอร์เฟซโต้ตอบแบบเรียบง่ายของ OpenCode แทน TUI เต็มหน้าจอ

```bash
opencode mini
```

รัน `opencode mini --help` เพื่อดูตัวเลือกเซสชัน โมเดล เอเจนต์ พรอมต์ และการเล่นซ้ำ

## บริการเบื้องหลัง

โดยค่าเริ่มต้น OpenCode จะค้นหาหรือเริ่มเซิร์ฟเวอร์เบื้องหลังที่ใช้ร่วมกันหนึ่งตัวสำหรับบัญชีผู้ใช้ของคุณ ไคลเอนต์ OpenCode
ในเครื่องทุกตัวเชื่อมต่อกับเซิร์ฟเวอร์นั้น ซึ่งเป็นเจ้าของเซสชัน การกำหนดค่า การเชื่อมต่อ สิทธิ์ และการเรียกใช้เครื่องมือ

ใช้ `--standalone` เพื่อรันด้วยเซิร์ฟเวอร์ส่วนตัว หรือ `--server` เพื่อเชื่อมต่อกับ URL ของเซิร์ฟเวอร์ที่ระบุ

```bash
opencode --standalone
opencode --server http://localhost:4096
```

หากต้องการให้เซิร์ฟเวอร์ส่วนตัวเป็นค่าเริ่มต้นสำหรับคำสั่ง CLI แทนการเริ่มบริการที่ใช้ร่วมกัน ให้ปิดบริการนั้น

```bash
opencode service set disabled true
opencode
```

คำสั่งนี้จะหยุดบริการเบื้องหลังที่กำลังทำงาน `--server` ยังเชื่อมต่อกับเซิร์ฟเวอร์ที่เลือกอย่างชัดเจนได้ `opencode service start`
ยังเริ่มบริการที่ใช้ร่วมกันได้อย่างชัดเจน หากต้องการกลับไปใช้บริการอัตโนมัติ ให้รัน `opencode service unset disabled`
การจับคู่ (pairing) ต้องใช้บริการที่ใช้ร่วมกันและใช้ไม่ได้ขณะปิดอยู่

ดู[การแก้ปัญหา](/troubleshooting)สำหรับการวินิจฉัยบริการที่ใช้ร่วมกัน และ[เอกสารอ้างอิง API](/api)สำหรับเอนด์พอยต์ของเซิร์ฟเวอร์

## พาธ

พิมพ์พาธในเครื่องที่ระบุเพื่อใช้กับเครื่องมืออื่น

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

หากระบุ `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log` หรือ `repos` คำสั่งจะแสดงเฉพาะพาธนั้นแล้วขึ้นบรรทัดใหม่
พาธฐานข้อมูลขึ้นอยู่กับช่องทางการออกรุ่นและ `OPENCODE_DB` หากกำหนดพาธฐานข้อมูลเป็นพาธสัมพัทธ์ ระบบจะอ้างอิงจากไดเรกทอรีข้อมูล ส่วน `:memory:` จะแสดงตามที่ระบุ คำสั่งนี้ไม่เริ่มเซิร์ฟเวอร์หรือเปิดฐานข้อมูล

ไม่ระบุตัวเลือกเพื่อแสดงทุกพาธพร้อมป้ายชื่อ

```bash
opencode debug paths
```

## ถอนการติดตั้ง

ดูตัวอย่างไฟล์และการติดตั้งที่จะถูกลบ

```bash
opencode uninstall --dry-run
```

รัน `opencode uninstall` เพื่อยืนยันการลบ OpenCode จะหยุดบริการเบื้องหลังที่ลงทะเบียนและเทอร์มินัลแบบถาวรก่อน
ลบไดเรกทอรีแคชส่วนกลาง ซึ่งใช้ร่วมกันระหว่างเวอร์ชันและช่องทางของ OpenCode ข้อมูลเซสชัน การกำหนดค่า และ
สถานะจะไม่ถูกลบ

- `--force` (`-f`) ข้ามการยืนยัน ใช้สำหรับการลบแบบไม่โต้ตอบ
- การติดตั้งผ่านตัวจัดการแพ็กเกจจะใช้ตัวจัดการแพ็กเกจที่ตรวจพบ การติดตั้งผ่าน Curl จะพิมพ์คำสั่งสุดท้ายเพื่อลบ
  ไฟล์ปฏิบัติการด้วยตัวเอง
