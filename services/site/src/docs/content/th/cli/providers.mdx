เชื่อมต่อผู้ให้บริการใน TUI แล้วเลือกโมเดลหนึ่งตัว

```text
/connect
/models
```

`/connect` แสดงรายการการเชื่อมต่อที่ใช้ได้จากเซิร์ฟเวอร์และโปรเจกต์ปัจจุบัน เลือกผู้ให้บริการ เลือก
วิธีตรวจสอบสิทธิ์เมื่อมีมากกว่าหนึ่งวิธี แล้วทำตามพรอมต์

## TUI

TUI รองรับคีย์ API, OAuth และคำสั่งตรวจสอบสิทธิ์ของผู้ให้บริการ OAuth จะเปิด URL การอนุญาตหรือแสดง
รหัสให้ป้อน กด `o` เพื่อเปิด URL และ `c` เพื่อคัดลอกรายละเอียดการอนุญาต

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

รัน `/connect` อีกครั้งเพื่อเพิ่มบัญชีอื่น การเลือกผู้ให้บริการที่เชื่อมต่อแล้วจะเปิดรายการบัญชี ซึ่งคุณ
เปิดใช้งาน เปลี่ยนชื่อ หรือลบบัญชีที่บันทึกไว้ได้

## CLI

ใช้ `auth login` สำหรับวิธีของผู้ให้บริการเดียวกันโดยไม่ต้องเปิด TUI หากไม่ระบุผู้ให้บริการ คำสั่งจะเปิด
ตัวเลือกผู้ให้บริการแบบอินเทอร์แอกทีฟ

```bash
opencode auth login
```

ส่ง ID หรือชื่อการเชื่อมต่อเพื่อข้ามตัวเลือกแรก ใช้ `--method key` เพื่อเลือกการป้อนคีย์ API อย่างชัดเจน

```bash
opencode auth login anthropic --method key
```

ID วิธีขึ้นกับผู้ให้บริการ รันคำสั่งโดยไม่ใส่ `--method` เพื่อดูวิธีที่ใช้ได้เมื่อผู้ให้บริการมี
มากกว่าหนึ่งวิธี

```bash
opencode auth login openai
```

การป้อนคีย์ API และแบบฟอร์มของผู้ให้บริการต้องใช้เทอร์มินัลแบบอินเทอร์แอกทีฟ วิธี OAuth ที่ขอให้วางรหัสการอนุญาต
ก็ต้องใช้เช่นกัน

## วิธี

OpenCode รับข้อมูลรับรองของผู้ให้บริการผ่านวิธีเชื่อมต่อสี่แบบ

| วิธี | ลักษณะการทำงาน |
| --- | --- |
| คีย์ API | ขอความลับแล้วบันทึกเป็นบัญชีผู้ให้บริการ |
| OAuth | แสดง URL สำหรับเปิดในเบราว์เซอร์ รหัสอุปกรณ์ หรือช่องให้ป้อนรหัสอนุญาต จากนั้นบันทึกโทเคนและต่ออายุเมื่อทำได้ |
| คำสั่ง | รันคำสั่งตรวจสอบสิทธิ์ที่ผู้ให้บริการจัดหา แล้วบันทึกเอาต์พุตมาตรฐานเป็นคีย์ |
| สภาพแวดล้อม | อ่านตัวแปรที่รองรับจากโปรเซสเซิร์ฟเวอร์โดยไม่บันทึก |

ผู้ให้บริการเพิ่มแบบฟอร์มในวิธีคีย์ API และ OAuth สำหรับรายละเอียดที่จำเป็น เช่น ชื่อทรัพยากร Azure หรือโดเมน GitHub
Enterprise CLI และ TUI จะแสดงแบบฟอร์มเหล่านั้นก่อนเริ่มการตรวจสอบสิทธิ์

## สภาพแวดล้อม

ตั้งตัวแปรสภาพแวดล้อมที่ผู้ให้บริการรองรับในโปรเซสเซิร์ฟเวอร์ที่รันคำขอโมเดล สำหรับเซิร์ฟเวอร์ส่วนตัว
แบบครั้งเดียว ให้ส่งตอนเริ่มโหมด standalone

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

สำหรับเซิร์ฟเวอร์เบื้องหลังที่ใช้ร่วมกัน ให้เพิ่มตัวแปรในสภาพแวดล้อมแบบมีการจัดการ คำสั่งนี้จะหยุดบริการที่ทำงานอยู่
คำสั่ง OpenCode ถัดไปจะเริ่มใหม่ด้วยค่าใหม่

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

การเชื่อมต่อผ่านสภาพแวดล้อมจะปรากฏใน `auth list` ด้วยชนิด `environment` ไม่ใช่บัญชี: `auth logout` ลบไม่ได้
จึงต้อง unset ตัวแปรเพื่อยกเลิกการเชื่อมต่อ บัญชีที่บันทึกไว้มีลำดับเหนือกว่าการเชื่อมต่อผ่านสภาพแวดล้อมสำหรับ
การเชื่อมต่อเดียวกัน

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

ผู้ให้บริการบางรายยังใช้กลไกของตนเองเพื่อค้นหาข้อมูลรับรองตามลำดับจากแหล่งที่มีอยู่ในสภาพแวดล้อม แทนการใช้ตัวแปรคีย์ API

- Amazon Bedrock รองรับห่วงโซ่ข้อมูลรับรองเริ่มต้นของ AWS รวมถึงโปรไฟล์ สภาพแวดล้อมคีย์การเข้าถึง web identity
  และข้อมูลรับรองคอนเทนเนอร์ ยังรองรับ `AWS_BEARER_TOKEN_BEDROCK` ด้วย
- Google Vertex ใช้ Application Default Credentials และต้องระบุโปรเจกต์ได้จากการตั้งค่าที่มีอยู่ ตัวอย่างเช่น ยืนยันตัวตนด้วย
  `gcloud auth application-default login` และตั้ง `GOOGLE_CLOUD_PROJECT`
- Azure แสดง **Microsoft Entra ID (Azure CLI)** เป็นวิธีเชื่อมต่อเมื่อติดตั้ง `az` แล้ว ให้รัน `az login` ก่อน แล้ว
  เลือกวิธีนั้นใน `/connect` หรือ `auth login azure`

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

ดู[ผู้ให้บริการ](/providers)สำหรับการตั้งค่าเฉพาะผู้ให้บริการและฝั่งเซิร์ฟเวอร์

## บัญชี

การลงชื่อเข้าใช้ด้วยคีย์ API, OAuth หรือคำสั่งที่สำเร็จแต่ละครั้งจะสร้างบัญชีที่บันทึกไว้ บัญชีใหม่สุดจะใช้งานอยู่ สลับ
บัญชีที่ใช้งานตามป้ายชื่อหรือ ID ข้อมูลรับรอง

```bash
opencode auth list
opencode auth switch anthropic work
```

ลบบัญชีที่บันทึกไว้ด้วย `auth logout` ทั้งสองคำสั่งจะเปิดตัวเลือกเมื่อไม่ระบุอาร์กิวเมนต์

```bash
opencode auth logout anthropic work
```

ใน TUI `/connect` มีการเพิ่ม เปิดใช้งาน เปลี่ยนชื่อ และลบสำหรับบัญชีที่บันทึกไว้เหมือนกัน

## ที่เก็บข้อมูล

เซิร์ฟเวอร์เก็บคีย์ API และโทเคน OAuth ไว้ในฐานข้อมูล SQLite หากใช้เซิร์ฟเวอร์ในเครื่อง ให้แสดงพาธฐานข้อมูลด้วยคำสั่งนี้

```bash
opencode debug paths db
```

พาธปกติของรุ่นที่เผยแพร่คือ `~/.local/share/opencode/opencode.db`; `XDG_DATA_HOME`, ช่องทางการออกรุ่น และ `OPENCODE_DB`
เปลี่ยนได้ อย่าแก้ไขฐานข้อมูลเพื่อจัดการข้อมูลรับรอง ให้ใช้ `/connect` หรือคำสั่ง `auth`

V2 นำเข้าข้อมูลรับรองที่รองรับจาก `auth.json` แบบเดิมในไดเรกทอรีข้อมูลของ OpenCode ระหว่างการย้าย
ฐานข้อมูล ข้อมูลรับรองใหม่และที่อัปเดตจะถูกเก็บใน SQLite ไม่ได้เขียนกลับไปยังไฟล์นั้น
