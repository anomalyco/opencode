OpenCode มีธีมในตัวมากมายสำหรับโหมดสว่างและมืด เลือกได้ในการตั้งค่า หรือผสมสีของคุณเอง

## เลือกธีม

กด `Ctrl+P` เลือก **Open settings** แล้วเปิด **Theme** ธีมเริ่มต้นคือ `opencode` ธีมเริ่มต้นเดิมยังใช้ได้ในชื่อ `opencode-classic`

คุณยังตั้งธีมและโหมดใน[การตั้งค่า CLI](/cli/config)ส่วนกลางได้

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

รัน `/themes` เพื่อเปลี่ยนธีมโดยไม่ต้องเปิดการตั้งค่า

## สีของระบบ

เมื่อ OpenCode อ่านพาเลตต์ของเทอร์มินัลคุณได้ ตัวเลือกธีมจะมีธีม `system` ด้วย ธีมนี้สร้างสีจาก
สีพื้นหน้า พื้นหลัง และพาเลตต์ ANSI ของเทอร์มินัลคุณ

ชื่อธีม `system` เลือกสีที่มาจากเทอร์มินัล โหมด `system` ตามรูปลักษณ์สว่างหรือมืดของเทอร์มินัล

## โหมด

ใช้ `system` เพื่อตามรูปลักษณ์ของเทอร์มินัล หรือล็อกธีมเป็นโหมดสว่างหรือมืด

| โหมด | ลักษณะการทำงาน |
| --- | --- |
| `system` | ตามรูปลักษณ์สว่างหรือมืดที่ตรวจพบของเทอร์มินัล |
| `dark` | ใช้สีมืดของธีมเสมอ |
| `light` | ใช้สีสว่างของธีมเสมอ |

ค่านี้แมปกับฟิลด์ `mode` ภายใน `theme` ในการกำหนดค่า CLI ของคุณ หากธีมกำหนดเองมีเพียงโหมดเดียว
OpenCode จะใช้โหมดนั้นเมื่อขออีกโหมด

## การเพิ่มธีม

หากต้องการเพิ่มธีมที่ดาวน์โหลดมาหรือได้รับจากผู้อื่น ให้คัดลอกไฟล์ JSON ไปยังไดเรกทอรีธีมส่วนกลาง

```bash
cp theme.json ~/.config/opencode/themes/
```

คุณยังวางธีมในไดเรกทอรี `.opencode/themes` ของโปรเจกต์เพื่อให้ใช้ได้เฉพาะโปรเจกต์นั้นได้

ชื่อไฟล์จะเป็นชื่อธีม เช่น `my-theme.json` จะปรากฏเป็น `my-theme` รีสตาร์ต OpenCode หลังเพิ่มไฟล์
แล้วรัน `/themes` เพื่อเลือก

OpenCode อ่านเฉพาะไฟล์ `.json` ธีมที่อยู่ใกล้ไดเรกทอรีปัจจุบันกว่าจะแทนที่ธีมส่วนกลางหรือธีมแม่
ที่ชื่อเดียวกัน

## การใช้ธีมในปลั๊กอิน

[ปลั๊กอิน TUI](/build/plugins/cli) อ่านค่าสีที่ระบบคำนวณแล้วผ่าน `context.theme` และอ่านโหมดที่ใช้งานผ่าน `context.themeMode` ใช้โทเคนเชิงความหมายเพื่อให้ปลั๊กอินใช้สีตามธีมที่เลือก

```tsx title="Inside a TUI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

API ปลั๊กอิน TUI สาธารณะไม่ได้ลงทะเบียนธีม ให้เพิ่มคำจำกัดความธีมกำหนดเองด้วยไฟล์ JSON ในไดเรกทอรีด้านบน

## การสร้างธีม

ใช้[เครื่องมือธีม](https://opencode.ai/theme/)ของเราเพื่อสร้างหรือแก้ไขธีม เครื่องมือนี้ช่วยให้เข้าใจโครงสร้าง
เปลี่ยน และกำหนดสีกำหนดเองได้ง่าย คำอธิบายด้านล่างเป็นข้อมูลอ้างอิง

ธีมแยกโทเคนเชิงความหมายที่ใช้ร่วมกันออกจากพาเลตต์เฉพาะโหมด

| ส่วน | จุดประสงค์ |
| --- | --- |
| `base` | โครงสร้างโทเคนทั้งหมดที่ใช้ร่วมกันในทุกโหมด |
| `light`, `dark` | พาเลตต์เฉดสีทั้งหมดของโหมดนั้น และโทเคนที่ต้องการระบุเพื่อใช้แทนค่าเดิม |

ทุกธีมมี `base` ที่สมบูรณ์และกำหนดอย่างน้อยหนึ่งใน `light` หรือ `dark` โหมดสืบทอดจาก `base`
ของไฟล์ ไม่ได้สืบทอดจากธีมในตัวของ OpenCode หรือจากกันและกัน

ตัวอย่างด้านล่างแสดงเฉพาะส่วนที่เกี่ยวข้องกับแต่ละแนวคิด ใช้ตัวแก้ไขธีมสร้างไฟล์ที่สมบูรณ์ก่อน
ปรับแต่ง

### โครงสร้าง

ใส่สีที่ทั้งสองโหมดใช้ใน `base` แล้วแทนที่ใน `light` หรือ `dark` เมื่อจำเป็น

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

`base` ที่สมบูรณ์ต้องมีโทเคนเชิงความหมายครบทุกตัว แต่ละโหมดต้องกำหนดเฉดสีที่จำเป็นให้ครบ และแทนที่ส่วนใดของโครงสร้างโทเคนพื้นฐานก็ได้

### สีและการอ้างอิง

สีอาจเป็นค่า hex, `"transparent"` หรือการอ้างอิงสีอื่นในธีม

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### เฉดสี

เฉดสีเป็นการไล่สีเก้าขั้น แต่ละโหมดกำหนดเฉดสีฐานแปดเฉดและนามแฝงสามรายการ

| ชนิด | ค่า |
| --- | --- |
| ฐาน | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| นามแฝง | `accent`, `interactive`, `neutral` |
| ขั้น | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

กำหนดทั้งเก้าขั้นสำหรับเฉดสีฐาน หรือตั้งนามแฝงเฉดสีหนึ่งไปยังอีกเฉดสี

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

ขั้นของเฉดสีเป็นไปตามทิศทางคอนทราสต์ของโหมด ธีมสว่างไล่จากเข้มที่ `100` ไปอ่อนที่ `900`
ธีมมืดไล่จากอ่อนที่ `100` ไปเข้มที่ `900`

อาร์เรย์ `categorical` ใน `base` กำหนดลำดับเฉดสีเพื่อแยกเอเจนต์และรายการอื่น ๆ ที่ปรากฏซ้ำ

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### โทเคนเชิงความหมาย

โทเคนเชิงความหมายกำหนดสีตามหน้าที่ขององค์ประกอบใน UI คอมโพเนนต์อ้างอิงหน้าที่เหล่านี้แทนการเลือกสีโดยตรง

| กลุ่ม | จุดประสงค์ |
| --- | --- |
| `text` | ข้อความฐาน จาง หม่น เลือก การกระทำ ฟิลด์ฟอร์ม และข้อความตอบกลับ `faint` มีค่าเริ่มต้นเป็น `muted` |
| `background` | พื้นผิวฐาน การเลือก พื้นผิวยกขึ้น การกระทำ ฟิลด์ฟอร์ม และพื้นเติมข้อความตอบกลับ |
| `border`, `scrollbar` | สีขอบและแถบเลื่อน |
| `diff` | สีที่เพิ่ม ลบ บริบท ไฮไลต์ และเลขบรรทัด |
| `syntax` | การไฮไลต์ซอร์สโค้ด |
| `markdown` | องค์ประกอบ Markdown |

ตัวอย่างเช่น `text.muted` ควบคุมข้อความรอง ส่วน `background.raised` กำหนดพื้นผิวที่ยกขึ้นทีละระดับ

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

`text.selection` และ `background.selection` กำหนดสีข้อความที่คุณเลือกด้วยเมาส์หรือแป้นพิมพ์
ค่าเริ่มต้นคือการกระทำหลักที่โฟกัส `text.action.primary.$focused` บน `background.action.primary.$focused`

คีย์ของ syntax คือ `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` และ
`punctuation`

คีย์ของ Markdown คือ `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`,
`listItem`, `listEnumeration`, `image`, `imageText` และ `codeBlock`

### การกระทำและสถานะ

การดำเนินการมีรูปแบบ `primary`, `secondary` และ `destructive` การดำเนินการและฟิลด์ฟอร์มใช้ `base`
บวกสถานะการโต้ตอบที่ไม่บังคับ

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

คีย์สถานะคือ `$hovered`, `$focused`, `$pressed`, `$selected` และ `$disabled` สถานะที่ไม่ระบุจะใช้สี
`base` ของการกระทำหรือฟิลด์ฟอร์มนั้น

### พื้นผิวกล่องโต้ตอบ

แผง กล่องโต้ตอบ เมนู และทอสต์เลือกความลึกจาก `background.raised` กล่องโต้ตอบอาจแทนที่
โทเคนเชิงความหมายด้วย `@dialog` เพิ่มเติม

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI จะคำนวณค่าที่อ้างอิงใหม่หลังใช้ `@dialog` โทเคนที่อ้างถึง `$background.base` จึงใช้สีตามพื้นหลังของกล่องโต้ตอบ ระบบใช้ `base` ของการดำเนินการในบริบทนั้นกับสถานะที่ไม่ได้ระบุ แต่ถ้าระบุค่าสถานะไว้โดยตรง ระบบจะใช้ค่านั้นก่อน
