นโยบายตัดสินว่า OpenCode ทำการกระทำกับทรัพยากรที่มีชื่อได้หรือไม่ เขียนไว้
ภายใต้ `policies` และยังส่งได้จากเวิร์กสเปซของ
[OpenCode Console](/console) ที่เชื่อมต่ออยู่

นโยบายแยกจาก [สิทธิ์](/permissions) สิทธิ์เป็นกฎการใช้เครื่องมือของเอเจนต์แต่ละตัว โดยใช้ `allow`, `deny` หรือ `ask` ได้
ส่วนนโยบายมีเพียงสองผลลัพธ์คืออนุญาตหรือปฏิเสธ ไม่ขออนุมัติ และทำได้เพียงจำกัดสิ่งที่สิทธิ์และผู้ให้บริการอนุญาตอยู่แล้วให้แคบลง

## การกำหนดค่า

ปฏิเสธผู้ให้บริการหนึ่งทุกที่ด้วยการเพิ่มข้อกำหนดใน `opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

ผู้ให้บริการที่ถูกปฏิเสธจะหายจากแคตตาล็อกและการเลือกโมเดลแม้มี
ข้อมูลรับรองที่ถูกต้อง

รุ่นก่อนอ่านนโยบายจาก `experimental.policies` คีย์นั้นยังใช้ได้และ
รวมเข้า `policies`

```jsonc
{
  "experimental": {
    "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
  },
}
```

## ข้อกำหนด

แต่ละข้อกำหนดมีสามฟิลด์

| ฟิลด์      | ค่า                                                                                                                      | ความหมาย                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `action`   | `provider.use`, `tool.use`, `integration.connect`, `integration.use`, `mcp.use`, `skill.use`, `plugin.use`, `websearch.use` | การดำเนินการที่ถูกควบคุม                       |
| `resource` | สตริงหรือรูปแบบไวลด์การ์ด                                                                                                  | สิ่งที่ข้อกำหนดมีผลกับ ขึ้นกับการกระทำ |
| `effect`   | `allow`, `deny`                                                                                                             | การตัดสินเมื่อข้อกำหนดนี้ตรง             |

ข้อกำหนดที่ตรวจสอบไม่ผ่านจะถูกตัดทิ้งพร้อมคำเตือนในบันทึกเซิร์ฟเวอร์ และ
ส่วนที่เหลือยังมีผล ตรวจบันทึกหลังแก้ไข `deny`

## การจับคู่

ทรัพยากรใช้ไวลด์การ์ดแบบทั้งค่าเดียวกับสิทธิ์: `*` ตรงกับศูนย์ตัวอักษรขึ้นไป และ
`?` ตรงกับหนึ่งตัว

```jsonc
{
  "policies": [{ "action": "provider.use", "resource": "company-*", "effect": "deny" }],
}
```

สิ่งนี้ปฏิเสธ `company-us` และ `company-eu` รูปแบบที่ลงท้ายด้วย ` *` ยังจับ
ค่าที่ไม่มีอาร์กิวเมนต์ `shell:git push *` จึงครอบคลุม `git push` เดี่ยวๆ

## ลำดับ

เมื่อมีหลายข้อกำหนดตรงเงื่อนไข ระบบจะใช้ข้อสุดท้ายโดยไม่พิจารณาว่าข้อใดเฉพาะเจาะจงกว่า จึงควรวางข้อกำหนดทั่วไปไว้ก่อนข้อยกเว้น
หากไม่มีข้อใดตรงเงื่อนไข ระบบจะอนุญาตให้ดำเนินการ

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  ],
}
```

เหลือเฉพาะ Anthropic ที่ใช้ได้

## ผู้ให้บริการ

`provider.use` ควบคุมว่าผู้ให้บริการใช้ได้หรือไม่เลย ทรัพยากรคือ
ID ผู้ให้บริการ: `anthropic`, `openai`, `opencode` หรือ ID กำหนดเองจาก
[`providers`](/providers)

```jsonc
{
  "providers": {
    "company-ai": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://ai.company.example/v1" },
    },
  },
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "company-ai", "effect": "allow" },
  ],
}
```

รายการ `providers` กำหนดค่าเอนด์พอยต์ ส่วนข้อกำหนดทำให้เป็นผู้ให้บริการเดียว
ที่ OpenCode ใช้ นโยบายมีผลไม่ว่าผู้ให้บริการจะรู้จักมาทางใด: ข้อมูลแคตตาล็อก
ตัวแปรสภาพแวดล้อม บัญชีที่บันทึกไว้ ปลั๊กอินในตัว หรือการกำหนดค่า

ใช้ `provider.use` แทนรายการ `enabled_providers` และ `disabled_providers`
ของ V1 ไฟล์ V1 ยังโหลดได้ ดู
[ย้ายจาก V1](/migrate-v1#supported-fields-without-direct-native-equivalents)

## เครื่องมือ

ข้อกำหนด `tool.use` ปฏิเสธอย่างเด็ดขาดการตรวจ[สิทธิ์](/permissions) ทรัพยากรคือ
`<action>:<value>` จับคู่กับทุกทรัพยากรที่เครื่องมือตรวจ

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
    { "action": "tool.use", "resource": "edit:*.env", "effect": "deny" },
    { "action": "tool.use", "resource": "webfetch:*", "effect": "deny" },
  ],
}
```

การตรวจที่ถูกปฏิเสธจะล้มเหลวด้วย `Blocked by configuration policy` แทนการถาม
มีผลหลังกฎเอเจนต์และการอนุมัติที่บันทึกไว้ จึงแทนที่ทั้ง `ask` และการอนุมัติ
“Allow always”

| รูปแบบ                      | บล็อก                                      |
| ---------------------------- | ------------------------------------------- |
| `shell:*`                    | ทุกคำสั่ง shell                         |
| `read:*/.ssh/*`              | การอ่านข้อมูล SSH                        |
| `external_directory:*`       | การเข้าถึงใดๆ นอก Location หรือเวิร์กทรี |
| `subagent:general`           | การเปิดซับเอเจนต์หนึ่งตัว                      |
| `github_delete_repository:*` | เครื่องมือ MCP หนึ่งตัว                                |
| `*`                          | ทุกอย่างที่ยังไม่ถูกปฏิเสธ               |

ข้อกำหนด `tool.use` ที่เป็น `allow` ไม่เคยให้สิทธิ์ เพียงยกเลิก `deny`
กว้างก่อนหน้า หลังจากนั้นกฎของเอเจนต์เองจะเป็นตัวตัดสิน

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:*", "effect": "deny" },
    { "action": "tool.use", "resource": "shell:git status *", "effect": "allow" },
  ],
}
```

`git status` จะถอยไปใช้กฎ `shell` ของเอเจนต์ คำสั่งอื่นทั้งหมดถูกบล็อก

## การเชื่อมต่อ

การเชื่อมต่อคือสิ่งที่คุณเชื่อมต่อใน `/connect`: OpenCode Console
(`opencode`), ผู้ให้บริการเช่น `anthropic`, บริการค้นหาเว็บเช่น `exa`
หรือต้นทางการกำหนดค่าที่รู้จักเช่น `https://ai.acme.com` การลงชื่อเข้าใช้เซิร์ฟเวอร์ MCP
ไม่ได้รับผลจากนโยบายการเชื่อมต่อ ให้ใช้ `mcp.use` ควบคุมเซิร์ฟเวอร์ MCP

`integration.connect` ควบคุมว่าการเชื่อมต่อใดที่ `/connect` แสดงและเชื่อมต่อได้
ทรัพยากรคือ ID การเชื่อมต่อ

`integration.use` ควบคุมทุกอย่างที่การเชื่อมต่อจัดหา: ผู้ให้บริการและโมเดล
การค้นหาเว็บ และเซิร์ฟเวอร์ MCP กับการกำหนดค่าที่เวิร์กสเปซ Console หรือต้นทางที่รู้จักส่งมา
ทรัพยากรคือ `<integration>#<account>` โดย account คือ ID องค์กรหรือบัญชีที่เชื่อมต่อ เช่น
`opencode#org_01M3CAP8H43Z49CER6NT0Y3ZF1` หากไม่มีบัญชีที่เชื่อมต่อ จะเป็น
ID การเชื่อมต่อเปล่าๆ: ระดับฟรีที่ไม่ได้ลงชื่อเข้าใช้คือ `opencode`, ตัวแปรสภาพแวดล้อม `ANTHROPIC_API_KEY`
คือ `anthropic` และผู้ให้บริการจาก `opencode.json` คือ ID ผู้ให้บริการของมัน

นโยบาย MDM นี้กำหนดให้ใช้เวิร์กสเปซ Console หนึ่งแห่งและไม่มีอย่างอื่น ดู[องค์กร](/enterprise)สำหรับตัวอย่างเพิ่มเติม

```jsonc
{
  "policies": [
    { "action": "integration.connect", "resource": "*", "effect": "deny" },
    { "action": "integration.connect", "resource": "opencode", "effect": "allow" },
    { "action": "integration.use", "resource": "*", "effect": "deny" },
    { "action": "integration.use", "resource": "opencode#org_01M3CAP8H43Z49CER6NT0Y3ZF1", "effect": "allow" },
  ],
}
```

`/connect` เสนอเฉพาะ Console เพื่อให้สมาชิกลงชื่อเข้าใช้ ระดับฟรี บัญชี
Console ส่วนตัว องค์กรอื่น คีย์ API จากสภาพแวดล้อม และผู้ให้บริการจาก
`opencode.json` ใช้ไม่ได้ทั้งหมด ผู้ให้บริการ เซิร์ฟเวอร์ MCP และ
การค้นหาเว็บของเวิร์กสเปซทำงานได้ และการเปลี่ยนใน Console ไม่ต้องมีโปรไฟล์ MDM ใหม่

เฉพาะนโยบายแบบมีการจัดการเท่านั้นที่ยับยั้งเซิร์ฟเวอร์ MCP และการกำหนดค่าที่การเชื่อมต่อ
ส่งมาได้ นโยบายของตัวเองยังมีผลทั้งสองทาง

## เซิร์ฟเวอร์ MCP สกิล และปลั๊กอิน

| การกระทำ       | ทรัพยากร                                                          |
| ------------ | ----------------------------------------------------------------- |
| `mcp.use`    | [เซิร์ฟเวอร์ MCP](/mcp-servers) ตามชื่อที่กำหนด              |
| `skill.use`  | [สกิล](/skills) ตาม ID                                      |
| `plugin.use` | [ปลั๊กอิน](/plugins) ตามชื่อแพ็กเกจที่ไม่ระบุเวอร์ชันหรือพาธสัมบูรณ์ |

```jsonc
{
  "policies": [
    { "action": "mcp.use", "resource": "*", "effect": "deny" },
    { "action": "mcp.use", "resource": "github", "effect": "allow" },
    { "action": "plugin.use", "resource": "opencode-acme-cli", "effect": "deny" },
  ],
}
```

เซิร์ฟเวอร์ MCP หรือสกิลที่ถูกปฏิเสธจะถูกนำออก และปลั๊กอินที่ถูกปฏิเสธจะไม่ถูกโหลด ไม่ว่า
กำหนดค่าไว้อย่างไร

### การอัปเกรดจาก `integration.use`

ก่อน OpenCode 2.2.3 `integration.use` ครอบคลุมเซิร์ฟเวอร์ MCP สกิล และปลั๊กอิน
ผ่านคำนำหน้า `mcp:`, `skill:` หรือ `plugin:` ข้อกำหนดที่มีคำนำหน้ายังโหลดได้และ
ถูกแปลงเป็น `mcp.use`, `skill.use` หรือ `plugin.use`

ข้อกำหนดที่ไม่มีคำนำหน้าเหล่านี้ รวมถึง `*` เปล่าๆ ตอนนี้มีผลกับการเชื่อมต่อแทน
การปฏิเสธแบบกว้างเช่น

```jsonc
{ "action": "integration.use", "resource": "*", "effect": "deny" }
```

จะไม่บล็อกเซิร์ฟเวอร์ MCP สกิล หรือปลั๊กอินอีกต่อไป แต่จะบล็อกผู้ให้บริการทุก
ราย รวมถึงระดับฟรี เว้นแต่ข้อกำหนดภายหลังจะอนุญาตการเชื่อมต่อ หากต้องการคง
ความหมายเดิม ให้แทนที่ด้วย

```jsonc
{
  "policies": [
    { "action": "mcp.use", "resource": "*", "effect": "deny" },
    { "action": "skill.use", "resource": "*", "effect": "deny" },
    { "action": "plugin.use", "resource": "*", "effect": "deny" },
  ],
}
```

ข้อยกเว้นย้ายแบบเดียวกัน: `integration.use` `mcp:github` กลายเป็น `mcp.use`
`github` และ `skill:team:review` กลายเป็น `skill.use` `team:review`

ไคลเอนต์เก่ากว่า 2.2.3 เพิกเฉยต่อ `integration.connect`, `integration.use` (ในความหมายใหม่),
`mcp.use`, `skill.use` และ `plugin.use` จึงควรกำหนดให้ใช้ 2.2.3 ขึ้นไป
ทุกที่ที่พึ่งพาสิ่งเหล่านี้

## การค้นหาเว็บ

`websearch.use` ควบคุมผู้ให้บริการค้นหาเว็บที่เครื่องมือ `websearch` ใช้ได้
ทรัพยากรคือ ID ผู้ให้บริการ: `opencode` สำหรับ OpenCode Web Search จาก Console,
ผู้ให้บริการในตัวเช่น `exa`, `firecrawl`, `parallel`, `tavily` หรือ `tinyfish` หรือ
ID ของผู้ให้บริการที่ปลั๊กอินเพิ่ม

```jsonc
{
  "policies": [
    { "action": "websearch.use", "resource": "*", "effect": "deny" },
    { "action": "websearch.use", "resource": "opencode", "effect": "allow" },
  ],
}
```

ผู้ให้บริการที่ถูกปฏิเสธจะถูกนำออกแม้ทำงานได้โดยไม่ต้องใช้คีย์ API เช่น Exa และ
TinyFish เมื่อผู้ให้บริการทุกรายถูกปฏิเสธ เครื่องมือ `websearch` จะไม่ถูกเสนออีก
ไคลเอนต์เก่ากว่า 2.2.6 เพิกเฉยต่อ `websearch.use`

## ลำดับความสำคัญ

สำหรับการตั้งค่าทั่วไป ระบบให้ไฟล์กำหนดค่าที่อยู่ใกล้ที่สุดมีลำดับสูงกว่า ส่วนนโยบายใช้ลำดับกลับกัน โดยประเมินข้อกำหนดที่มีขอบเขตกว้างกว่าทีหลัง จึงแทนที่ข้อกำหนดที่มีขอบเขตแคบกว่าได้
การตั้งค่าที่ผู้ดูแลจัดการและ Console ที่เชื่อมต่ออยู่มีลำดับสูงกว่าไฟล์กำหนดค่าของผู้ใช้และโปรเจกต์เสมอ

| อำนาจ   | แหล่ง                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| 1 (สูงสุด) | การตั้งค่าแบบมีการจัดการของ macOS (`/Library/Managed Preferences/ai.opencode.managed.plist`)                           |
| 2           | ระบบ `opencode.json(c)` (`/Library/Application Support/opencode`, `/etc/opencode`, `%ProgramData%\opencode`) |
| 3           | เวิร์กสเปซ OpenCode Console ที่เชื่อมต่อ                                                                           |
| 4           | ส่วนกลาง `~/.config/opencode/opencode.json(c)`                                                                   |
| 5           | `opencode.json(c)` โดยตรง ไดเรกทอรีชั้นนอกชนะชั้นใน                                                   |
| 6 (ต่ำสุด)  | `.opencode/opencode.json(c)` ไดเรกทอรีชั้นนอกชนะชั้นใน                                                |

รีโพเปิดผู้ให้บริการที่คุณปฏิเสธทั่วโลกอีกครั้งไม่ได้

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

```jsonc title="project/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "allow" }],
}
```

`openai` ยังถูกปฏิเสธ ภายในไฟล์เดียว ข้อกำหนดคงลำดับที่เขียน

## Console

เวิร์กสเปซบน [OpenCode Console](/console) จะคอมไพล์นโยบาย Providers และ Tools
เป็นข้อกำหนด `policies` ปกติในการกำหนดค่าเวิร์กสเปซ OpenCode
รวมการกำหนดค่านั้นเหมือนไฟล์กำหนดค่าที่มีลำดับต่ำกว่าการตั้งค่าแบบมีการจัดการ
และไฟล์ระบบทันที `deny` ขององค์กรจึงถูกยกเลิกด้วย `allow` ของรีโพหรือผู้ใช้ไม่ได้
และ `allow` ขององค์กรยกเลิก `deny` ที่ลำดับต่ำกว่า
การตั้งค่าแบบมีการจัดการและไฟล์ระบบยังแทนที่เวิร์กสเปซ

การปฏิเสธจากข้อกำหนดเหล่านี้ระบุชื่อเวิร์กสเปซ

```text
Blocked by Acme's policy
```

ข้อกำหนดตามบัญชีที่เชื่อมต่อ

| เหตุการณ์                       | ผลลัพธ์                                              |
| --------------------------- | --------------------------------------------------- |
| นโยบาย Console เปลี่ยน      | ใช้เมื่อดึงครั้งถัดไป ประมาณทุกห้านาที |
| สลับไปเวิร์กสเปซอื่น | ข้อกำหนดถูกแทนที่ด้วยของเวิร์กสเปซนั้น           |
| ยกเลิกการเชื่อมต่อ                  | ข้อกำหนดถูกล้าง                                  |
| เข้าถึง Console ไม่ได้         | ข้อกำหนดล่าสุดของการเชื่อมต่อนั้นยังมีผล  |

ปลั๊กอิน Console และปลั๊กอินนโยบายปิดจาก `plugins` ไม่ได้ ดู
[การควบคุมปลั๊กอิน](/plugins#control)

<Callout type="note">
  นโยบายไม่ได้กำหนดค่าเอนด์พอยต์หรือข้อมูลรับรอง และทำให้ผู้ให้บริการที่ใช้ไม่ได้กลายเป็นใช้ได้ไม่ได้ ทั้งไม่ได้
  แซนด์บ็อกซ์โค้ดปลั๊กอิน: ผู้ให้บริการที่ถูกปฏิเสธจะถูกบล็อกในเส้นทางผู้ให้บริการและโมเดลปกติ
</Callout>
