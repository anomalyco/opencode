ส่วนเซิร์ฟเวอร์ของปลั๊กอินทำงานในเซิร์ฟเวอร์ OpenCode ปรับเปลี่ยนพฤติกรรมของ OpenCode และเพิ่มฟีเจอร์: เครื่องมือ
ฮุก การเชื่อมต่อ คำสั่ง และเอเจนต์ ดู[ภาพรวม](/build/plugins)สำหรับการจัดวาง โหลด
และเผยแพร่แพ็กเกจปลั๊กอิน

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

## วงจรชีวิต

`setup` ทำงานเมื่อโหลดปลั๊กอิน และอาจคืนฟังก์ชันสำหรับคืนทรัพยากรที่จะทำงานเมื่อเลิกโหลดปลั๊กอิน

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### บริบท

บริบทปลั๊กอินโดยพื้นฐานคือ[ไคลเอนต์เซิร์ฟเวอร์ OpenCode](/build/client)
เมธอดอ่านและดำเนินการใช้พารามิเตอร์และการตอบกลับเดียวกับไคลเอนต์ เพิ่มเมธอดเฉพาะปลั๊กอินสำหรับการแปลง ฮุกขณะรัน การโหลดใหม่ การลงทะเบียน
และตัวเลือกปลั๊กอิน

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location` อธิบาย location ที่อินสแตนซ์ปลั๊กอินนี้โหลด รวมถึง `directory`, `workspaceID` ที่ไม่บังคับ และข้อมูลเมตา `project` (`id`,
`directory` และ `canonical`) ใช้ได้ทั้งปลั๊กอิน Promise และ Effect
นี่คือ location ของอินสแตนซ์ปลั๊กอิน ไม่ใช่ location ของทุกเซสชันที่เข้าถึงหรืออีเวนต์ที่ได้รับ

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### ตัวเลือก

ส่งตัวเลือกปลั๊กอินด้วยรูปแบบออบเจกต์ใน `opencode.json(c)`

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

อ่านค่าเหล่านั้นจาก `ctx.options` ระหว่าง `setup`

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## การแปลง

การแปลงคือการแก้ไขสถานะโดเมนของ OpenCode แบบซิงโครนัส และแต่ละรายการต่อยอดจากการลงทะเบียนก่อนหน้าในโดเมน
การอ่าน registry เช่น `ctx.model.list()` จะแสดงผลของการลงทะเบียนทั้งหมดจนถึงขณะนั้น รวมถึงระหว่างตั้งค่าปลั๊กอิน
การรวมตอนเริ่มต้นเพียงรวมการแจ้งเตือนอัปเดตและไม่หน่วงสิ่งที่การอ่านคืน API สถานะทรัพยากรยัง
รายงานสถานะทรัพยากรที่ทำงานอยู่: คำจำกัดความที่ลงทะเบียนไม่ได้หมายความว่าการเชื่อมต่อหรือทรัพยากรอื่นเสร็จแล้ว

แหล่งให้ผู้ให้บริการและคำจำกัดความโมเดลที่ไม่เปลี่ยนรูปผ่าน `ctx.provider.transform`

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

การลงทะเบียน การยกเลิกการลงทะเบียน หรือการเรียก `reload()` จะทำเครื่องหมายว่า registry มีการเปลี่ยนแปลง เมื่ออ่านครั้งถัดไป ระบบจะสร้าง registry ใหม่โดยนำการแปลงที่เปิดใช้งานทั้งหมดมาใช้กับค่าใหม่ตามลำดับการลงทะเบียน
เขียนการแปลงให้ใช้ทรัพยากรน้อยและทำซ้ำได้ การสร้างใหม่ภายหลังจะไม่แก้ไขค่าที่คุณอ่านไปแล้ว

หลังจากใช้การแปลงและระบุว่าผู้ให้บริการรายใดพร้อมใช้งานแล้ว OpenCode จะสร้างรายการโมเดลของผู้ให้บริการที่ใช้งานและใช้
การแปลงโมเดลทุกตัวตามลำดับ นโยบายโมเดลตรวจคอลเลกชันตัวเลือกทั้งหมดได้ รวมถึงแหล่งที่รีเฟรชใหม่

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

อินพุตที่จับไว้ไม่ถูกเฝ้าดูอัตโนมัติ ให้โหลดข้อมูลภายนอกก่อนคอลแบ็กซิงโครนัส แล้วเรียก
`reload()` หลังอินพุตเหล่านั้นเปลี่ยน ในที่นี้ `loadFromSource()` คืน
รายการ `{ info: Provider.Info, models: readonly Model.Info[] }`

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

เมื่อผู้ให้บริการเปลี่ยน ระบบจะถือว่าผลลัพธ์ของโมเดลที่ใช้งานทั้งหมดไม่เป็นปัจจุบัน นโยบายราคาเอาต์พุตจึงกรองโมเดลชุดที่รีเฟรชแล้วด้วย
ใช้ `ctx.model.reload()` เมื่อเฉพาะอินพุตที่การแปลงโมเดลจับไว้เปลี่ยน

## API

### Agent

อ่านเอเจนต์ทั้งหมดหรือดึงตาม ID

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

ลงทะเบียนการแปลงเพื่อตรวจดู สร้าง อัปเดต หรือนำเอเจนต์ออก หรือเพื่อเลือกเอเจนต์เริ่มต้น

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

ลงทะเบียนเอเจนต์ใหม่ด้วย `editor.update` หากมี ID นี้แล้ว ระบบจะอัปเดตเอเจนต์เดิม หากยังไม่มี ระบบจะสร้างเอเจนต์ด้วย
`Agent.Info.default(id)` ก่อนเรียกคอลแบ็ก

```ts
await ctx.agent.transform((editor) => {
  editor.update("reviewer", (agent) => {
    agent.description = "Reviews code for correctness and maintainability"
    agent.mode = "subagent"
    agent.system = "Review the proposed changes and report actionable findings."
  })
})
```

โหลดเอเจนต์ใหม่หลังสถานะภายนอกที่การแปลงใช้เปลี่ยน

```ts
await ctx.agent.reload()
```

#### Reference

Schema: [`Agent.Info`](/api#schema-Agent.Info)

```ts
interface AgentContext {
  list(input?: AgentListInput, requestOptions?: RequestOptions): Promise<AgentListOutput>
  get(input: AgentGetInput, requestOptions?: RequestOptions): Promise<AgentGetOutput>
  transform(callback: (editor: AgentEditor) => void): Promise<Registration>
  reload(): Promise<void>
}

interface AgentEditor {
  list(): readonly AgentInfo[]
  get(id: string): AgentInfo | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: AgentInfo) => void): void
  remove(id: string): void
}

  dispose(): Promise<void>
}
```

### Providers

อ่านผู้ให้บริการที่ใช้ได้หรือดูข้อมูลเมตาของผู้ให้บริการหนึ่งตาม ID

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

การแปลงผู้ให้บริการแก้ไขการตั้งค่าผู้ให้บริการและคำจำกัดความแหล่ง การอ่านของตัวแก้ไขรวมผู้ให้บริการที่ไม่ใช้งานและเปิด
คำจำกัดความที่ไม่เปลี่ยนรูป `models.update` แก้ไขสำเนาของโมเดลแหล่งที่ตัวแก้ไขเป็นเจ้าของ

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

แทนที่รายการแหล่งของผู้ให้บริการด้วย `models.set` แล้วโหลดใหม่หลังคำจำกัดความที่จับไว้เปลี่ยน

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

สำหรับการค้นพบเฉพาะบัญชี ให้ส่งการเชื่อมต่อที่ใช้โหลดรายการเป็น `sourceConnection` OpenCode จะตัด
ผู้ให้บริการนั้นออกขณะเลือกการเชื่อมต่ออื่น จนกว่าปลั๊กอินของคุณจะเผยแพร่รายการที่รีเฟรชแล้ว

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

#### Reference

Schemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info)

```ts
  transform(callback: (editor: ProviderEditor) => void): Promise<Registration>

}

}

interface ProviderEditor {

  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void

  }
}
```

### Models

อ่านโมเดลที่ใช้ได้และการเลือกเริ่มต้น

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

การแปลงโมเดลแก้ไขคอลเลกชันตัวเลือกของผู้ให้บริการที่ใช้งานทั้งหมด ตัวเลือกที่ปิดใช้งานยังแก้ไขได้จนกว่า
การแปลงทั้งหมดจะเสร็จ `update` เพิ่มโมเดลได้เฉพาะภายใต้ผู้ให้บริการที่พร้อมใช้

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})
```

คอลแบ็กแก้ไขการแทนที่โมเดลดิบ ค่าเริ่มต้นของผู้ให้บริการถูกรวมครั้งเดียวเมื่อ OpenCode ยืนยันผล การอ่านที่ไม่เปลี่ยน
ใช้ผลนั้นซ้ำ `editor.provider` เปิดคำจำกัดความแหล่งที่ไม่เปลี่ยนรูป รวมถึงเทมเพลตที่ไม่ใช้งาน แทน
ผลของการแปลงโมเดล

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### Commands

อ่านคำสั่งที่ใช้ได้ที่ location

```ts
const commands = await ctx.command.list()
```

ลงทะเบียนคำสั่งด้วยการแปลง ตัวเรียกใช้ได้รับเซสชัน ไฟล์แนบพรอมต์ และโหมดการส่งที่ขอ

```ts
await ctx.command.transform((editor) => {
  editor.add({
    name: "security-review",
    description: "Review changes for security issues",
    execute: async ({ sessionID, prompt, delivery }) => {
      await ctx.session.prompt({
        ...prompt,
        sessionID,
        text: `Review these changes for security issues.\n\n${prompt.text}`,
        delivery,
      })
    },
  })
})
```

โหลดคำสั่งใหม่หลังสถานะภายนอกที่การแปลงใช้เปลี่ยน

```ts
await ctx.command.reload()
```

### Integrations

อ่านการเชื่อมต่อและตรวจข้อมูลรับรองที่ใช้งาน

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

เชื่อมต่อการเชื่อมต่อด้วยคีย์ API

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

เริ่ม ตรวจ ทำเสร็จ หรือยกเลิกความพยายามเชื่อมต่อ OAuth

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

การเชื่อมต่อแบบคำสั่งเปิดขั้นตอนเริ่ม สถานะ และยกเลิกเดียวกัน

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

ลงทะเบียนการแปลงเพื่อตรวจการเชื่อมต่อและจัดการวิธีตรวจสอบสิทธิ์

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

โหลดการเชื่อมต่อใหม่หลังสถานะภายนอกที่การแปลงใช้เปลี่ยน

```ts
await ctx.integration.reload()
```

#### Reference

Schemas: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer)

```ts
interface IntegrationContext {
  list(input?: IntegrationListInput, requestOptions?: RequestOptions): Promise<IntegrationListOutput>
```

### Permissions

ขออนุญาตก่อนทำการกระทำ `assert` ประเมิน[กฎสิทธิ์](/permissions)ของเซสชัน
รวมถึงการอนุมัติที่บันทึกไว้ และถามผู้ใช้เมื่อกฎตัดสินเป็น `ask` จะเสร็จเมื่อการกระทำได้รับอนุญาต

```ts
execute: async (input, context) => {
  await ctx.permission.assert({
    sessionID: context.sessionID,
    agent: context.agent,
    source: { type: "tool", messageID: context.messageID, id: context.id },
    action: "deploy",
    resources: [input.environment],
    save: [input.environment],
  })
  return { content: await deploy(input.environment) }
}
```

- `action` และ `resources` ถูกจับคู่กับกฎ `deny` ใดๆ บล็อกการกระทำ มิฉะนั้น `ask` ใดๆ จะถาม
- `save` ระบุรูปแบบที่จัดเก็บเมื่อผู้ใช้เลือกอนุญาตเสมอ
- `agent` เลือกว่ากฎของใครใช้ และมีค่าเริ่มต้นเป็นเอเจนต์ของเซสชัน `source` แนบพรอมต์กับการเรียกเครื่องมือ
- `metadata` ส่งรายละเอียดเพิ่มเติมให้พรอมต์สิทธิ์และฮุก `evaluate`

กฎ deny หรือการปฏิเสธพร้อมความคิดเห็นจะ reject ด้วย `Tool.Error` ที่มีเหตุผล โมเดลจึงเห็นและ
ดำเนินต่อ การปฏิเสธเฉยๆ จบขั้นปัจจุบัน ให้ข้อผิดพลาดเหล่านี้แพร่ออกไปแทนการคืนเป็นเอาต์พุตเครื่องมือ

ตรวจสอบหรือตอบกลับคำขอสิทธิ์ที่รอดำเนินการ

```ts
const pending = await ctx.permission.list({ sessionID })
const request = await ctx.permission.get({ sessionID, requestID })
await ctx.permission.reply({ sessionID, requestID, decision: "once" })
```

แทนที่กฎสิทธิ์ตามขอบเขตเซสชัน กฎเหล่านี้ประเมินหลังกฎของเอเจนต์ และ
กฎสุดท้ายที่ตรงชนะ เซสชันลูกสืบทอดกฎที่ใช้อยู่เมื่อสร้าง

```ts
await ctx.session.update({
  sessionID,
  permissions: [{ action: "edit", resource: "/path/to/original/checkout/**", effect: "deny" }],
})
```

#### อินพุตเครื่องมือ freeform

เครื่องมือโดยตรงที่มีฟิลด์สตริงที่จำเป็นหนึ่งฟิลด์พอดีสามารถให้โมเดลเขียนสตริงนั้นโดยไม่มีตัวห่อ JSON ตั้ง `freeform` เป็น `{ type: "text" }`, `{ type: "regex", pattern }` หรือ `{ type: "lark", grammar }`

```ts
editor.add({
  name: "ticket",
  description: "Look up a ticket by ID",
  options: { codemode: false },
  input: Schema.Struct({ id: Schema.String }),
  freeform: { type: "regex", pattern: "OPS-[0-9]+" },
  execute: async ({ id }) => ({ content: await lookup(id) }),
})
```

หาก API ของโมเดลที่เลือกระบุ `regex` ใน models.dev โมเดลเขียน `OPS-42` ได้โดยตรง มิฉะนั้น Core จะละ **เฉพาะ** `freeform`: โมเดลยังมีเครื่องมือ `ticket` และเรียกด้วย `{"id":"OPS-42"}` รายการรูปแบบที่ขาดหรือว่างหมายถึงไม่รองรับ freeform ตัวเรียกใช้ได้รับ `{ id }` ทั้งสองทาง

ใน Code Mode (`codemode: true`) เครื่องมือ freeform รับสตริงโดยตรง เช่น `await tools.ticket("OPS-42")` และ `await tools.ticket({ id: "OPS-42" })` ก็ใช้ได้

เรียก `reload()` หลังเปลี่ยนข้อมูลแหล่งที่คอลแบ็กจับไว้ การโหลดใหม่เล่นการแปลงที่ใช้งานโดยไม่
เปลี่ยนลำดับ ไม่ได้รัน setup ปลั๊กอินใหม่

```ts
await ctx.tool.reload()
```

ใช้ `list()` และ `get()` เพื่อตรวจดูเครื่องมือที่อยู่ในตัวแก้ไข ค่า `id` ของเครื่องมือคือชื่อที่ระบบใช้จริง
และ `get()` จะคืน `undefined` หากไม่พบ ID นั้น เมื่อเรียก `update` หรือ `remove` ให้ใช้ชื่อที่ระบบใช้จริงซึ่งรวมเนมสเปซด้วย
(เช่น `acme_greeting` ข้างต้น) ระบบจะแทนจุดในเนมสเปซด้วย `_` และแทนอักขระในชื่อเครื่องมือด้วย `_` หากไม่ใช่ตัวอักษร ตัวเลข `_` หรือ `-`
ระบบจะข้ามชื่อที่ไม่พบ หากต้องการสร้างเครื่องมือ ให้ใช้
`add` พร้อมคำจำกัดความที่สมบูรณ์ การอัปเดตจะคงชื่อและเนมสเปซไว้ ให้แทนที่ด้วย schema หรือตัวเลือกใหม่
แทนการแก้ไขค่าที่ซ้อน การอัปเดตที่ไม่ถูกต้องจะถูกบันทึกและคงคำจำกัดความก่อนหน้าไว้

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

การอัปเดตและการนำออกเล่นตามลำดับพร้อมการเพิ่ม รวมถึงหลังการรีเฟรชแคตตาล็อก MCP การ dispose
การลงทะเบียนของมันจะนำการเปลี่ยนแปลงเหล่านั้นออกและสร้างใหม่จากการแปลงที่เหลือ

ยกเลิกการลงทะเบียนเพื่อนำการแปลงนั้นออกและสร้างผลลัพธ์ใหม่จากการแปลงที่เหลือ ระบบจึงกลับมาใช้คำจำกัดความเดิมที่เคยถูกแทนที่ การยกเลิกซ้ำไม่เปลี่ยนผล และระบบจะยกเลิกการลงทะเบียนของปลั๊กอินโดยอัตโนมัติเมื่อเลิกโหลดปลั๊กอิน

```ts
await registration.dispose()
```

แต่ละคำขอโมเดลจับสแนปช็อตเครื่องมือที่ stable และเรียกใช้ได้ การแปลง การโหลดใหม่ และการ dispose ภายหลังมีผลกับสแนปช็อต
ในอนาคต ไม่ใช่คำจำกัดความ คำอธิบายเนมสเปซ Code Mode หรือตัวเรียกใช้ที่จับไว้แล้ว ตัวเรียกใช้ที่ปิดทับ
ข้อมูลปลั๊กอินที่แก้ไขได้ยังเห็นข้อมูลนั้น ให้จับค่าในการแปลงเมื่อค่านั้นต้องผูกกับ
คำจำกัดความนั้น

### VCS

อ่านข้อมูลรีโพ สถานะสำเนาทำงาน หรือ diff ของไฟล์

```ts
const info = await ctx.vcs.get()
const branches = await ctx.vcs.branch.list({ search: "feature", limit: 10 })
const changes = await ctx.vcs.status()
const diff = await ctx.vcs.diff({ mode: "working", context: 3 })
```

ลงทะเบียนผู้ให้บริการ VCS ตามขอบเขต location ด้วยการแปลง ผู้ให้บริการที่ตรงกับชนิดรีโพที่ตรวจพบจะถูกเลือก
อัตโนมัติ ใช้ `editor.default.set` เพื่อเลือกผู้ให้บริการอื่น

```ts
await ctx.vcs.transform((editor) => {
  editor.add({
    id: "custom",
    name: "Custom VCS",
    info: async () => ({ branch: { current: "feature", default: "main" } }),
    branches: async (input, { signal }) => readBranches(input, signal),
    status: async (scope, { signal }) => readStatus(scope.worktree, signal),
    diff: async (input, { signal }) => readDiff(input, signal),
  })
  editor.default.set("custom")
})
```

คอลแบ็กผู้ให้บริการได้รับ location ปัจจุบัน รากสำเนาทำงาน รากโปรเจกต์มาตรฐาน และที่เก็บรีโพ
ที่ไม่บังคับ คอลแบ็ก diff ยังได้รับโหมดที่เลือก บริบทที่ขอ และงบไบต์เอาต์พุต การค้นพบรีโพ
ยังใช้ตัวตรวจ Git และ Mercurial ในตัวของ OpenCode

ผู้ให้บริการเลือกใช้ `init(scope, { signal })` เพื่อสร้างรีโพใน `scope.worktree` ได้ การเริ่มต้น
เลือกผู้ให้บริการตาม ID (Git โดยค่าเริ่มต้น) ไม่ใช่ตามชนิดรีโพที่ตรวจพบ ลงทะเบียนผู้ให้บริการที่มี `init` แม้
location ยังไม่มีรีโพ OpenCode จะตรวจว่าไดเรกทอรีมีอยู่และไม่มีรีโพก่อนเรียก
แล้วจึงค้นพบโปรเจกต์ใหม่ รูปแบบรีโพใหม่ยังต้องมีการรองรับการค้นพบนอกเหนือจากคอลแบ็กนี้

### Worktrees

ลงทะเบียนกลยุทธ์เวิร์กทรีในเครื่องด้วยวงจรชีวิตปลั๊กอินปกติ โมดูลการใช้งานในตัวอย่างนี้เป็นเจ้าของ
การตรวจสอบตัวเลือกและการดำเนินการ `create`, `remove` และ `list` ของแบ็กเอนด์

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

โหลดปลั๊กอินผ่าน `plugins` และกำหนดปลายทางทั่วไปแยก

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- การเพิ่มกลยุทธ์จะเลือกมันอัตโนมัติ การลงทะเบียนที่ใช้งานล่าสุดชนะ ไม่ต้องมีการกำหนดค่าเลือกกลยุทธ์
- การ dispose การลงทะเบียนหรือการถอนปลั๊กอินจะคืนการใช้งานก่อนหน้า สุดท้ายคือกลยุทธ์ Git ที่รวมมา
- `reload()` เล่นการแปลงใหม่หลังอินพุตที่จับไว้เปลี่ยน ไม่ได้รัน setup ปลั๊กอินใหม่
- ความล้มเหลวในการสร้างจะไม่ลองใหม่ผ่าน Git เวิร์กทรีที่มีอยู่คงเจ้าของที่บันทึกไว้แม้ค่าเริ่มต้นเปลี่ยน
- กลยุทธ์จัดการไดเรกทอรีในเครื่อง การจัดเตรียมเวิร์กสเปซระยะไกลไม่ใช่ส่วนของอินเทอร์เฟซนี้

#### การดำเนินการ

บริบทปลั๊กอินเปิดการดำเนินการเวิร์กทรีตามโปรเจกต์เดียวกับไคลเอนต์ ทุกการดำเนินการต้องมี
`projectID` `list` อ่านเฉพาะรายการที่บันทึกไว้ รวมถึงเช็กเอาต์ที่รู้จักของโปรเจกต์เดียวกัน ไม่โหลด
การกำหนดค่า ไม่เริ่มปลั๊กอิน และไม่ค้นพบการเปลี่ยนแปลงระบบไฟล์

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

การสร้างโหลดการกำหนดค่าและปลั๊กอินจากไดเรกทอรี `canonical` ที่บันทึกไว้ของโปรเจกต์ และใช้กลยุทธ์ที่เลือก
รับ `directory` แม่ที่เลือกได้ `from` ต้นทาง `branch` เริ่มต้น และ `name`
ต้นทางมีค่าเริ่มต้นเป็นเช็กเอาต์หลัก และ `from` ที่แทนที่ต้องเป็นของโปรเจกต์นั้น การเลือกต้นทาง
ไม่เปลี่ยนรากการกำหนดค่า
ref เริ่มต้นที่ให้มาต้องรองรับโดยกลยุทธ์ที่เลือก
เช่น การดำเนินการสแนปช็อตเนทีฟของ Rift ไม่มีตัวเลือกเลือก ref

การสร้างและรีเฟรชรอให้ปลั๊กอินของเช็กเอาต์หลักทำงาน การเรียกที่ทำระหว่าง
setup ปลั๊กอินของเช็กเอาต์นั้นจะเห็นการลงทะเบียนจนถึงตอนนั้นและไม่รอการทำงานของตัวเอง

การลบโหลดการกำหนดค่าหลักและเปิดปลั๊กอิน แล้วใช้กลยุทธ์ที่บันทึกไว้ของเวิร์กทรี
แทนค่าเริ่มต้นที่เลือกปัจจุบัน เจ้าของที่บันทึกไว้ไม่พร้อมใช้จะทำให้เกิดข้อผิดพลาด ปลายทางของเวิร์กทรี
อยู่ที่อื่นได้

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

หากไม่พบเจ้าของเดิมของเวิร์กทรี การลบจะไม่สำเร็จและระบบจะไม่สลับไปใช้ Git กลยุทธ์สามารถโยน `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })` โดยนำเข้า `Worktree` จาก `@opencode/plugin` เพื่อขอให้ผู้ใช้ยืนยันการบังคับลบโดยไม่ต้องพึ่งข้อผิดพลาดจาก Core หรือ Git

การรีเฟรชโหลดการกำหนดค่าหลักและขอให้กลยุทธ์ทั้งหมดที่ใช้ได้ค้นหาเวิร์กทรีในรากเช็กเอาต์ที่รู้จัก
รวมผลลัพธ์ รักษาความเป็นเจ้าของที่บันทึกไว้ และตัดไดเรกทอรีที่ขาด แหล่งค้นพบที่ล้มเหลวจะถูกบันทึก
ขณะแหล่งอื่นดำเนินต่อ ไดเรกทอรีที่มีอยู่ยังถูกเก็บแม้ไม่มีกลยุทธ์ที่ใช้ได้รายงาน ตรวจ
`worktree.updated` แล้วเรียก `list` อีกครั้งเพื่ออ่านรายการที่เปลี่ยน

```ts
await ctx.worktree.refresh({ projectID })
```

#### Reference

การใช้งานได้รับปลายทางที่แนะนำหลังการตั้งชื่อและจัดการการชนกัน คืนไดเรกทอรีจริงจาก
`create` ซึ่งอาจต่างเมื่อแบ็กเอนด์ต้องใช้เลย์เอาต์ของตัวเอง OpenCode จะหาตำแหน่งจากพาธที่คืนมาแล้วใช้สำหรับ
รายการ คำสั่งเริ่มต้น และผล API ไดเรกทอรีที่คืนต้องมีอยู่

กลยุทธ์ที่เลือกปลายทางอื่นจัดการการชนของชื่อที่นั่น OpenCode ยังสร้างไดเรกทอรีแม่ที่แนะนำ
ก่อนเรียกกลยุทธ์ `list` ต้องรายงานเฉพาะไดเรกทอรีที่กลยุทธ์เป็นเจ้าของ บวกกับรากรีโพใดๆ

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },

  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>

}
```

คอลแบ็ก Promise ต้องร่วมมือกับการยกเลิกผ่าน `signal` คอลแบ็ก Effect คืน Effect และใช้การขัดจังหวะของ Effect
แทน การลงทะเบียนผูกกับรันไทม์ปลั๊กอิน การดำเนินการระดับโปรเจกต์ใช้ registry ของเช็กเอาต์หลัก
อะแดปเตอร์การกำหนดค่าของ Core ส่งการตั้งค่าไดเรกทอรีเข้า registry นั้น

### Websearch

แสดงรายการผู้ให้บริการค้นหาเว็บหรือรันคำค้นผ่านผู้ให้บริการที่เลือก

```ts
const providers = await ctx.websearch.providers()
const results = await ctx.websearch.query({ query: "OpenCode plugins", providerID: "internal" })
```

ลงทะเบียนผู้ให้บริการและเลือกผู้ให้บริการเริ่มต้นด้วยการแปลง

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = (await response.json()) as { url: string; title: string; content: string }
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

ปิดการค้นหาเว็บโดยเลือก `false` หรือโหลดผู้ให้บริการใหม่หลังสถานะภายนอกเปลี่ยน

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```


### Events

สมัครรับสตรีมอีเวนต์สาธารณะของเซิร์ฟเวอร์ที่เชื่อมต่อ ให้ยกเลิกสตรีมเมื่อคืนทรัพยากรของปลั๊กอิน ส่ง `types` เช่น `ctx.event.subscribe({ types: ["config.updated"] })` เพื่อรับเฉพาะอีเวนต์ที่ระบุ ระบบจะกำหนดชนิดข้อมูลให้ตรงกับอีเวนต์เหล่านั้น ปลั๊กอินทำงานภายในเซิร์ฟเวอร์ จึงไม่ได้รับ `server.connected` ต่างจากไคลเอนต์ SDK ระบบจะข้ามชื่อชนิดที่ไม่รู้จักและบันทึกคำเตือนในบันทึกของเซิร์ฟเวอร์

```ts
const controller = new AbortController()
void (async () => {
  for await (const event of ctx.event.subscribe({ signal: controller.signal })) {
    console.log(event.type)
  }
})()
return () => controller.abort()
```

#### Reference

Schema: [`V2EventEncoded`](/api#schema-V2EventEncoded)

```ts
type EventType = Exclude<OpenCodeEvent["type"], "server.connected">

interface EventContext {
  subscribe<Type extends EventType = EventType>(options?: {
    types?: Type[]
    signal?: AbortSignal
  }): AsyncIterable<Extract<OpenCodeEvent, { type: Type }>>
}
```

## ฮุก

ฮุกดักการดำเนินการสด ลงทะเบียนฮุกบนโดเมนของมันและ dispose
การลงทะเบียนที่คืนเมื่อไม่ต้องการ

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

ปลั๊กอินหลายตัวลงทะเบียนฮุกเดียวกันได้ OpenCode รันตามลำดับปลั๊กอิน
ฮุกภายหลังจึงเห็นการเปลี่ยนแปลงที่ฮุกก่อนหน้าทำ

### Sessions

ฮุกเซสชันดักการรับพรอมต์ การเรียกโมเดล HTTP เนทีฟ และการลองใหม่

#### Forks

ฮุก `fork` ทำงานหลัง OpenCode คัดลอกประวัติและก่อนการเรียก fork คืน `sessionID` ระบุเซสชันใหม่

```ts
await ctx.session.hook("fork", ({ sessionID }) => console.log(sessionID))
```

#### การรับพรอมต์

ดักจับพรอมต์ที่ผู้ใช้ส่งเข้ามาก่อนที่ระบบจะระบุไฟล์แนบและสกิล แล้วบันทึกรายการนั้นลงอินบ็อกซ์แบบถาวร

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

ฮุกได้รับฉบับร่างที่แก้ไขได้และเป็นเจ้าของ

- `prompt` มี `text`, `files`, การกล่าวถึงเอเจนต์ใน `agents` และ `skills` ที่เลือก
- `metadata` มีข้อมูลเมตาการรับเข้าที่แอปกำหนด
- `delivery` เป็น `"steer"` โดยค่าเริ่มต้นและเปลี่ยนเป็น `"queue"` ได้
- ID เซสชันและข้อความเป็นแบบอ่านอย่างเดียว ฮุกเปลี่ยนเส้นทางการรับเข้าไม่ได้

ระบบจะค้นหาและตรวจสอบไฟล์กับสกิลที่ฮุกเพิ่มตามขั้นตอนปกติ
เมื่อเขียนข้อความใหม่ ให้อัปเดตหรือนำ offset `mention` ของไฟล์แนบที่ไม่ตรงแล้วออก
การกล่าวถึงเอเจนต์ไม่สลับเอเจนต์ที่ใช้งานของเซสชัน

ฮุกพรอมต์ทำงานภายใต้เงื่อนไขเหล่านี้

- ฮุกทำงานตามลำดับการลงทะเบียนหลังปลั๊กอินของ location ของเซสชันพร้อม
- คำสั่งที่ส่งผ่าน `session.prompt` รันฮุก
- ข้อความสังเคราะห์ ข้อความ shell การควบคุมการบีบอัด และการควบคุมการย้ายไม่รัน
- ฮุกทำงานครั้งเดียวระหว่างการรับเข้า ไม่ใช่ก่อนทุกการเรียกโมเดล
- จำกัดฮุกตามผู้ให้บริการไม่ได้ เพราะระบบระบุโมเดลที่จะใช้หลังจากรับพรอมต์เข้าอินบ็อกซ์แล้ว

การแก้ไขกลายเป็นอินพุตผู้ใช้ที่บันทึกไว้ตามมาตรฐาน หากการเตรียมล้มเหลวหรือถูก
ขัดจังหวะ OpenCode จะไม่รับพรอมต์

ให้ฮุกพรอมต์ปลอดภัยต่อการลองใหม่ ไม่ใช่ขอบเขตผลข้างเคียงแบบครั้งเดียว

- การลอง ID ที่รอดำเนินการหรือส่งแล้วซ้ำจะคืนการรับเข้าเดิมโดยไม่รันฮุกอีก
- การส่งพร้อมกันอาจรันฮุกมากกว่าหนึ่งครั้ง แต่เฉพาะการรับเข้าที่สำเร็จครั้งแรกชนะ
- ฮุกพรอมต์แปลงอินพุตและไม่มี API การปฏิเสธที่มีชนิด

#### คำขอโมเดล

แก้ไขคำแนะนำระบบ ข้อความ เครื่องมือ หรือตัวเลือกคำขอที่ประกอบแล้วทันทีก่อนส่งถึงโมเดล แต่ละ
ชนิดคำขอที่เซสชันส่งมีฮุกของตัวเอง ปลั๊กอินจึงจัดการลูปเอเจนต์และคำขอเสริมต่างกันได้

- `context` ทำงานสำหรับลูปเอเจนต์ รวมถึงการทำงานต่อที่เกิดจากเครื่องมือ
- `compaction` ทำงานสำหรับสรุปเช็กพอยต์ `messages` คือบทสนทนาที่สรุป OpenCode ต่อท้ายพรอมต์
  สรุปหลังฮุกทำงาน ตั้ง `result` เพื่อบันทึกการบีบอัดเองและข้ามการเรียกโมเดล รับ
  ฟิลด์เดียวกับข้อความการบีบอัดที่เสร็จ
- `generate` ทำงานสำหรับการเรียก `ctx.session.generate` ชั่วคราว
- `title` ทำงานสำหรับการสร้างชื่อเรื่อง ไม่มี `agent` หรือ `tools` ตั้ง `result` เพื่อให้ชื่อเรื่องเอง

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

การเปลี่ยนแปลงมีผลเฉพาะการเรียกโมเดลขาออก ไม่ใช่ประวัติหรือการกำหนดค่าที่บันทึก ฮุกที่ควรมีผลกับ
ทุกคำขอต้องลงทะเบียนทุกชนิด

ข้อความในฮุก `context`, `compaction` และ `generate` มี `metadata` ของข้อความที่จัดเก็บไว้อ่านอย่างเดียว
(เช่นสิ่งที่ฮุก `prompt` ตั้งไว้) ไม่ได้ส่งถึงโมเดล

ส่วน `system` ที่เก็บคำแนะนำของ OpenCode ยังแสดงแต่ละแหล่งใน `metadata.experimental.instructions` เป็น
`{ key, text }` เช่น `core/date` หรือ `core/environment` ฮุกจึงแยกแหล่งได้ รายการเป็นสำเนา:
การแก้ `text` ของส่วนนั้นไม่อัปเดตรายการ นี่เป็นฟีเจอร์ทดลองและอาจเปลี่ยน

การแทนที่คำขอเป็นไปตามกฎเหล่านี้

- `options` เริ่มว่างทุกครั้งที่เรียกโมเดล โดยไม่รวมการตั้งค่าโมเดลที่ระบบคำนวณไว้แล้ว
- คีย์ที่มีชนิดเป็นการตั้งค่าการสร้าง คีย์อื่นส่งให้โปรโตคอลที่เลือกเป็นตัวเลือกผู้ให้บริการ
- ฮุกทำงานตามลำดับการลงทะเบียนและเห็นการแทนที่ที่ฮุกก่อนหน้าทำ
- การแทนที่คำขอมีลำดับเหนือกว่าค่าเริ่มต้นโมเดล ซึ่งเหนือกว่าค่าเริ่มต้นเส้นทาง
- ระบบผสานออบเจกต์ตัวเลือกผู้ให้บริการแบบเรียกซ้ำ ส่วนอาร์เรย์และค่าสเกลาร์จะแทนค่าเดิม
- การลบการแทนที่หรือตั้งเป็น `undefined` จะถอยไปใช้ค่าเริ่มต้นที่กำหนด ไม่ได้ลบ
- ส่วนซ้อนบอดี HTTP ดิบใช้หลังการลดรูปโปรโตคอลและแทนที่ฟิลด์ที่ได้

#### ตัวเลือกผู้ให้บริการ

ตัวเลือกผู้ให้บริการใช้ชื่อตัวเลือกเชิงความหมายของโปรโตคอลที่เลือก ไม่ใช่ฟิลด์บอดี HTTP ดิบ จำกัดการตั้งค่า
เฉพาะผู้ให้บริการให้ตรงราย ตัวอย่างเช่น OpenAI Responses ใช้ `reasoningEffort`

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

ตัวเลือกการสร้างขึ้นกับโปรโตคอลและโมเดลที่เลือก

- `maxTokens` คือตัวเลือกกลางสำหรับจำกัดจำนวนโทเคนเอาต์พุต
- Gemini รองรับ `topK` ส่วน OpenAI Responses ไม่เปิด

#### การระบุโมเดลที่จะใช้

ฟีเจอร์ทดลอง ฮุกทำงานทุกครั้งที่เซสชันหาโมเดลสำหรับคำขอ ก่อนเริ่มประกอบคำขอนั้น `model` มีค่าเริ่มต้นเป็นโมเดลที่เลือกอยู่ คุณสามารถเปลี่ยนเป็นโมเดลอื่นจากผู้ให้บริการรายเดียวกันสำหรับคำขอนี้ได้ รวมถึงโมเดลที่ซ่อนไว้จากหน้าต่างเลือกโมเดล เซสชันยังคงโมเดลเดิมไว้ แต่คำขอและข้อความตอบกลับของผู้ช่วยจะใช้โมเดลใหม่
`kind` ระบุประเภทคำขอที่กำลังหาโมเดล เราเตอร์จึงข้ามคำขอตั้งชื่อเซสชันหรือเลือกเส้นทางใหม่หลังการบีบอัดได้ หากระบุโมเดลจากผู้ให้บริการรายอื่น ระบบจะแจ้งว่าโมเดลไม่พร้อมใช้งาน

```ts
await ctx.session.hook(
  "experimental.model.resolve",
  (event) => {
    if (event.model.id === "auto" && event.kind !== "title")
      event.model = { providerID: event.model.providerID, id: pick(event.sessionID) }
  },
  { providerID: "acme" },
)
```

#### คำขอที่ส่งไปยังโมเดล

แก้ไขการตั้งค่าคำขอโมเดลและจำกัดฮุกให้ผู้ให้บริการเดียวได้ อีเวนต์มี `kind`
เดียวกับฮุก HTTP ด้านล่าง

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### Native HTTP

แก้ไขคำขอหรือการตอบกลับของผู้ให้บริการเนทีฟ บอดีเป็นสตรีมใช้ครั้งเดียว ให้โคลนหรือแทนที่บอดีก่อนอ่าน

ฮุกทั้งสองทำงานทุกคำขอที่เซสชันส่ง `event.kind` บอกโฟลว์ที่ส่ง: `"primary"` สำหรับลูป
เอเจนต์ `"compaction"` สำหรับสรุปเช็กพอยต์ `"title"` สำหรับการสร้างชื่อเรื่อง และ `"generate"` สำหรับการเรียก
`ctx.session.generate` ชั่วคราว ใช้มันแทน ID เอเจนต์เพื่อแยกคำขอเสริม

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### Native WebSocket (ทดลอง)

ผู้ให้บริการที่สตรีมผ่าน WebSocket เปิดการเชื่อมต่อหนึ่งรายการต่อเซสชันและใช้ซ้ำข้ามคำขอ
`http.request` และ `http.response` จึงไม่เห็นทราฟฟิกนั้น ฮุก `experimental.ws.handshake` ทำงานครั้งเดียวต่อการเรียก
โมเดลก่อนเลือกการเชื่อมต่อ มี `sessionID`, `agent`, `model` และ `kind` เดียวกับฮุก HTTP
บวก `url` และ `headers` ของการเชื่อมต่อ การเปลี่ยน `url` หรือ `headers` เปลี่ยนซ็อกเก็ตที่คำขอใช้
bearer token ที่หมุนเวียนจึงเปิดการเชื่อมต่อใหม่

ฮุก HTTP ยังทำงานทุกคำขอ HTTP รวมถึงคำขอที่เส้นทาง WebSocket ถอยกลับไปใช้

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` และ `experimental.ws.receive` เปิดเฟรมเอง เป็นคู่ของ WebSocket กับการแก้ไข
บอดีคำขอหรือการตอบกลับ HTTP `send` ทำงานหลังไดรเวอร์ผู้ให้บริการสร้างเฟรมขาออกและก่อน
เขียน `receive` ทำงานทุกเฟรมขาเข้าก่อนไดรเวอร์เห็น ทั้งสองมีเฟรมเป็นสตริงและ
ส่งสิ่งที่ `frame` เก็บเมื่อฮุกคืน

OpenCode ไม่ตรวจสอบเฟรมที่เขียนใหม่ ไดรเวอร์ติดตามสถานะจากการตอบกลับของผู้ให้บริการ การเขียนใหม่ที่
เปลี่ยนความหมายโปรโตคอลจึงเป็นความรับผิดชอบของปลั๊กอิน เช่นเดียวกับบอดี HTTP ที่เขียนใหม่

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

ฮุกเหล่านี้เป็นฟีเจอร์ทดลองและชื่อหรือรูปร่างอาจเปลี่ยน

#### นโยบายการลองใหม่

แทนที่การตัดสินใจลองใหม่สำหรับความล้มเหลวของผู้ให้บริการหรือแทนที่เวลาหน่วงเป็นมิลลิวินาที ฮุกทำงานหลัง OpenCode
จำแนกความล้มเหลวและเสนอ นโยบาย แต่ก่อนกำหนดเวลาลองใหม่ ไม่เปิดเผยว่า OpenCode
ดำเนินการพยายามครั้งถัดไปภายในอย่างไร

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

ฮุกการลองใหม่เปลี่ยน `decision` เริ่มต้นของ OpenCode ได้โดยทำให้ความล้มเหลวที่เป็น terminal
ลองใหม่ได้ หรือยับยั้งการลองใหม่ที่เสนอ

การตัดสินใจลองใหม่เป็นไปตามกฎเหล่านี้

- ฮุกหลายตัวรันตามลำดับการลงทะเบียน และฮุกภายหลังเห็นการตัดสินใจปัจจุบัน
- จำนวนครั้งสูงสุดที่ระบบกำหนดยังคงเป็นเพดานที่เกินไม่ได้
- `attempt` คือลำดับของการส่งคำขอจริงที่ระบบกำลังพิจารณา คำขอแรกคือ `1` การลองใหม่ครั้งแรกจึงเป็น `2`
- เวลาหน่วงที่ไม่ถูกต้องเช่น `NaN`, อนันต์ หรือค่าลบ จะถอยไปใช้ค่าที่คำนวณ
- การกู้คืนเมื่อบริบทล้นแยก เพราะบีบอัดบทสนทนาแทนการลองคำขอเดิมใหม่

### Permissions

ตรวจการตัดสินใจสิทธิ์หลังประเมินกฎที่กำหนดและก่อน
การกระทำทำงานหรือพรอมต์สิทธิ์ถูกเผยแพร่

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-5-5" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

ฮุกสิทธิ์เป็นไปตามกฎเหล่านี้

- ฮุกทำงานสำหรับการตัดสินใจ `allow` และ `ask`
- `deny` ที่กำหนดไว้อย่างชัดเจนเป็นที่สุดและไม่เรียกฮุก
- ฮุกเปลี่ยน `effect` เป็น `allow`, `ask` หรือ `deny` ได้
- `message` ปรากฏในคำขอสิทธิ์ที่ยกระดับหรือกลายเป็นเหตุผลการปฏิเสธ

### Shell

แก้ไขคำสั่ง shell ไดเรกทอรีทำงาน เวลาหมดอายุ ไฟล์ปฏิบัติการ หรือตัวแปรสภาพแวดล้อมก่อนเรียกใช้

```ts
await ctx.shell.hook("create.before", (event) => {

})
```

### Tools

ตรวจหรือแทนที่อินพุตเครื่องมือก่อนเรียกใช้

```ts
await ctx.tool.hook("execute.before", (event) => {
  if (event.tool === "read") console.log(event.input)
})
```

ตรวจผลลัพธ์ที่สำเร็จหรือความล้มเหลวหลังเรียกใช้

```ts
await ctx.tool.hook("execute.after", (event) => {
  if (event.status === "completed") event.result = { ...event.result, metadata: { observed: true } }
  if (event.status === "error") console.error(event.error.message)
})
```

## รองรับ V1

ปลั๊กอินรองรับ V1 และ V2 จากจุดเข้าแพ็กเกจเดียวกันได้ ให้ default export
ออบเจกต์เดียวที่มีฟังก์ชัน `server()` ของ V1 และฟังก์ชัน `setup()` ของ V2

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 เรียก `server()` และใช้ฮุกที่คืน
- V2 อ่าน `id` และ `setup()` ของ default export (หรือ `effect()` สำหรับปลั๊กอิน Effect) โดยเพิกเฉย `server()`
- เก็บแต่ละการใช้งานบน API ของตัวเอง การแชร์ export ไม่ได้แปลงฮุก V1 เป็นฮุก V2
- spread `Plugin.define(...)` เข้าไปในออบเจกต์ที่ส่งออก เพื่อให้ตรวจชนิดคำจำกัดความ V2 แยกจาก `server()`

รูปแบบออบเจกต์ V1 รองรับใน OpenCode `1.18.29` V1 รุ่นเก่ากว่าอาจ
คาดหวังการส่งออกฟังก์ชันแทน ให้ทดสอบแพ็กเกจที่ติดตั้งกับ V1 รุ่นเก่าสุดที่ตั้งใจรองรับและกับ V2
