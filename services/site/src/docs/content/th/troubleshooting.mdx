<Callout type="tip">
  คุณขอให้ OpenCode แก้ไขปัญหาตัวเองได้ อธิบายปัญหาและขอให้ใช้หน้าการแก้ปัญหานี้ OpenCode อ่าน
  ขั้นตอนด้านล่าง ตรวจสอบบริการและบันทึก และช่วยระบุปัญหาได้
</Callout>

OpenCode ใช้สถาปัตยกรรมไคลเอนต์-เซิร์ฟเวอร์ เซิร์ฟเวอร์เบื้องหลังเป็นเจ้าของเซสชัน ปลั๊กอิน สิทธิ์ และสถานะแอปอื่น
เริ่มด้วยการพิจารณาว่าปัญหาอยู่ที่ไคลเอนต์ เซิร์ฟเวอร์ที่ใช้ร่วมกัน หรือโปรเจกต์ที่ระบุ

## ตรวจสอบบริการเบื้องหลัง

แสดงข้อมูลเซิร์ฟเวอร์ปัจจุบัน

```bash
opencode service status
```

ยืนยันว่า API สุขภาพดี

```bash
opencode api get /api/info
```

หากบริการค้างหรือไม่ดี ให้รีสตาร์ต

```bash
opencode service restart
```

คุณยังหยุดและเริ่มอย่างชัดเจนได้

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  โดยปกติ OpenCode ค้นหาหรือเริ่มบริการเบื้องหลังที่ใช้ร่วมกันโดยอัตโนมัติ คำสั่งบริการจำเป็นเฉพาะเมื่อ
  วินิจฉัยวงจรชีวิตของมัน
</Callout>

## อนุญาตต้นทางเบราว์เซอร์

หากไคลเอนต์เบราว์เซอร์จากต้นทางอื่นเชื่อมต่อไม่ได้เพราะ CORS ให้เพิ่มต้นทางของไคลเอนต์ในการกำหนดค่าบริการ

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

ใช้ต้นทาง HTTP หรือ HTTPS ที่ตรงตัว รวมพอร์ตเมื่อจำเป็น โดยไม่มีพาธหรือเครื่องหมายทับปิดท้าย หากต้องการอนุญาตหลาย
ต้นทาง ให้ส่งรายการคั่นด้วยจุลภาคเป็นอาร์กิวเมนต์เดียว ช่องว่างรอบแต่ละต้นทางจะถูกตัดออก

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` แสดงรายการเป็นอาร์เรย์ JSON หากต้องการลบรายการที่ตั้งไว้ ให้รัน

```bash
opencode service unset cors
```

การตั้งหรือลบการตั้งค่าบริการจะหยุดบริการเบื้องหลัง การเริ่มครั้งถัดไปจะใช้การกำหนดค่าใหม่
ใช้ `opencode service start` เพื่อเริ่มอย่างชัดเจน

สำหรับเซิร์ฟเวอร์แบบโฟร์กราวด์ ให้ทำ `--cors` ซ้ำสำหรับแต่ละต้นทางที่อนุญาตเพิ่มเติม

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

เมื่อใช้ `serve --service` แฟล็ก `--cors` ที่ส่งมาจะแทนที่รายการที่บันทึกไว้สำหรับโปรเซสนั้น หากไม่มีแฟล็กเหล่านั้น โหมดบริการ
จะใช้รายการที่บันทึกไว้ CORS ไม่เปลี่ยนที่อยู่ที่ฟังและไม่ข้ามการตรวจสอบสิทธิ์ของเซิร์ฟเวอร์

## ตรวจสอบ API

คำสั่ง `api` ใช้การค้นพบบริการในเครื่องและขั้นตอนการตรวจสอบสิทธิ์ รับได้ทั้งเมธอด HTTP กับพาธ หรือ
ID การดำเนินการ OpenAPI

ดู[เอกสารอ้างอิง API](/api)สำหรับเอนด์พอยต์และ ID การดำเนินการทั้งหมด

ส่งบอดีคำขอ JSON ด้วย `--data` หรือ `-d` และเพิ่มเฮดเดอร์ด้วย `--header` หรือ `-H`

<Callout type="warning">
  การรัน `opencode api` อาจเริ่มบริการเบื้องหลังเมื่อไม่มีบริการที่เข้ากันได้และสุขภาพดี
</Callout>

## อ่านบันทึก

บิลด์ที่ติดตั้งจะเขียนบันทึกไปที่

```text
~/.local/share/opencode/log/opencode.log
```

ติดตามบันทึกขณะทำซ้ำปัญหา

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

แต่ละบรรทัดมี `run` ID ของโปรเซสและฟิลด์ `role` ใช้ `role=server` สำหรับกิจกรรมเซสชัน ผู้ให้บริการ ปลั๊กอิน สิทธิ์ และ
เครื่องมือ

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## เก็บสแนปช็อตฮีป

เขียนสแนปช็อตหน่วยความจำ (ฮีป) ของเซิร์ฟเวอร์เบื้องหลังที่กำลังทำงานบนแพลตฟอร์มใดก็ได้

```bash
opencode debug heap-dump
```

คำสั่งจะรอจนสแนปช็อตเสร็จ แล้วพิมพ์พาธ

```text
/home/me/.local/share/opencode/log/heap-48213-2026-10-23T013012345Z.heapsnapshot
```

เขียนไปที่อื่นด้วย `--directory` เซิร์ฟเวอร์จะสร้างไดเรกทอรีเมื่อไม่มี

```bash
opencode debug heap-dump --directory ./snapshots
```

- ใช้เฉพาะเซิร์ฟเวอร์ที่ทำงานอยู่แล้วเท่านั้น ไม่เคยเริ่ม แทนที่ หรือรีสตาร์ต
- ใช้ `--server <url>` เพื่อจับเซิร์ฟเวอร์ที่คุณเริ่มด้วย `opencode serve` ตั้ง `OPENCODE_PASSWORD` หากมี
  `--directory` จะเป็นพาธบนเครื่องของเซิร์ฟเวอร์
- เปิดไฟล์ในแผง Memory ของ Chrome DevTools

<Callout type="warning">
  เซิร์ฟเวอร์หยุดชั่วคราวขณะเขียนสแนปช็อต และการใช้หน่วยความจำอาจเพิ่มขึ้นช่วงสั้นๆ สแนปช็อตอาจ
  มีพรอมต์ เนื้อหาไฟล์ และข้อมูลรับรอง อย่าแชร์ต่อสาธารณะ
</Callout>

### ในแอปเดสก์ท็อป

รัน **Capture heap snapshots** จากพาเลตต์คำสั่ง แอปจะสร้างโฟลเดอร์ไว้ใน Downloads ภายในมีสแนปช็อตของแต่ละส่วนของแอปและรายละเอียดการใช้หน่วยความจำส่วนที่สแนปช็อตไม่แสดง

```text
opencode-heap-2026-10-23T013012345Z/
  memory.json                  where the memory is, per process, in MiB: start here
  memory-infra.json            Chromium's memory dump trace; open it in https://ui.perfetto.dev
  heap-48213-….heapsnapshot    the desktop's own server
  window-1-48390.heapsnapshot  one per app window
  main-48102.heapsnapshot      the desktop main process
  gpu.json                     the GPU and driver
  manifest.json                processes, PIDs, and memory before and after; written last
```

- สแนปช็อตฮีปเก็บเฉพาะออบเจกต์ JavaScript และหน้า ภาพ เลย์เอาต์ เลเยอร์คอมโพสิตเตอร์ และหน่วยความจำ GPU อยู่ใน
  `memory.json` และ `memory-infra.json` แทน
- ไม่ได้จับเซิร์ฟเวอร์ระยะไกล ให้ใช้ `opencode debug heap-dump` บนเครื่องนั้นแทน
- เซิร์ฟเวอร์เขียนสแนปช็อตลงโฟลเดอร์โดยตรง จึงไม่มีการย้ายหรือคัดลอกไฟล์ใหญ่
- ไม่รวมแท็บเบราว์เซอร์ เพราะสแนปช็อตมีเนื้อหาของหน้าที่คุณเยี่ยมชม

## เก็บโปรไฟล์ CPU และหน่วยความจำ

บน macOS และ Linux คุณส่งสัญญาณให้โปรเซส OpenCode ที่กำลังทำงานเพื่อบันทึกข้อมูลวินิจฉัยได้ ดู PID ของเซิร์ฟเวอร์เบื้องหลังจากเอนด์พอยต์ตรวจสถานะ

```bash
opencode api get /api/info
```

ใช้ `pid` จากการตอบกลับกับสัญญาณใดสัญญาณหนึ่งเหล่านี้

- `SIGPROF` จับโปรไฟล์ CPU สิบวินาที

  ```bash
  kill -SIGPROF <pid>
  ```

  ผลลัพธ์จะถูกเขียนไปยังไดเรกทอรีบันทึกเป็น `cpu-<pid>-<timestamp>.cpuprofile`

- `SIGUSR1` จับสแนปช็อตหน่วยความจำ (ฮีป)

  ```bash
  kill -SIGUSR1 <pid>
  ```

  ผลลัพธ์จะถูกเขียนไปยังไดเรกทอรีบันทึกเป็น `heap-<pid>-<timestamp>.heapsnapshot`

รอข้อความ `CPU profile written` หรือ `heap snapshot written` ใน `opencode.log` ก่อนเปิดไฟล์ รายการบันทึก
ที่เกี่ยวข้องมีพาธทั้งหมด ตรวจไฟล์ทั้งสองชนิดได้ใน Chrome DevTools

<Callout type="note">
  โปรไฟล์ที่กระตุ้นด้วยสัญญาณใช้ไม่ได้บน Windows ให้ใช้ `opencode debug heap-dump` สำหรับสแนปช็อตฮีปแทน
  การเขียนสแนปช็อตฮีปอาจหยุดโปรเซสชั่วคราวและเพิ่มการใช้หน่วยความจำชั่วคราว
</Callout>

## ไฟล์บริการ

เซิร์ฟเวอร์ที่ใช้ร่วมกันลงทะเบียนตัวเองที่

```text
~/.local/state/opencode/service.json
```

การกำหนดค่าบริการแบบส่วนตัวถูกเก็บแยกที่

```text
~/.config/opencode/service.json
```

โดยปกติฐานข้อมูลอยู่ที่

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` แทนที่ตำแหน่งฐานข้อมูลได้

<Callout type="warning">
  อย่าลบหรือแก้ไขไฟล์บริการหรือฐานข้อมูลขณะแก้ปัญหา ให้ใช้คำสั่งบริการจัดการเดมอน และสำรองก่อน
  ตรวจข้อมูลถาวรด้วยเครื่องมือภายนอก
</Callout>

## รายงานปัญหา

ใส่สิ่งต่อไปนี้เมื่อรายงานปัญหาที่ทำซ้ำได้

- เอาต์พุตจาก `opencode --version`
- เอาต์พุตจาก `opencode service status`
- ลำดับขั้นตอนที่สั้นที่สุดที่ทำซ้ำปัญหา
- ปัญหามีผลกับบริการที่ใช้ร่วมกัน ไคลเอนต์ที่ระบุ หรือโปรเจกต์เดียว
- บรรทัดบันทึกที่เกี่ยวข้อง รวมถึงฟิลด์ `run` และ `role`

ลบคีย์ API เฮดเดอร์การอนุญาต พรอมต์ เนื้อหาไฟล์ และข้อมูลละเอียดอ่อนอื่นก่อนแชร์บันทึก

แจ้งปัญหาที่ทำซ้ำได้ใน [GitHub Issues](https://github.com/anomalyco/opencode/issues)
