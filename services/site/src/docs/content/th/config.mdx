สร้าง `opencode.jsonc` ในโปรเจกต์เพื่อกำหนดค่า OpenCode เพิ่ม schema ให้อีดิเตอร์ตรวจสอบค่าได้ แล้วตั้งเฉพาะตัวเลือกที่ต้องการ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

คุณยังขอให้ OpenCode อัปเดตไฟล์นี้ให้ได้

## รูปแบบ

OpenCode รองรับ JSON และ JSONC ใช้ JSONC หากต้องการใส่คอมเมนต์หรือเครื่องหมายจุลภาคท้ายรายการ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-5-5",
}
```

## ตำแหน่ง

วางการตั้งค่าแบบมีการจัดการทั่วเครื่องในไดเรกทอรีการกำหนดค่าระบบ

| แพลตฟอร์ม | ไดเรกทอรี                               |
| -------- | --------------------------------------- |
| macOS    | `/Library/Application Support/opencode` |
| Linux    | `/etc/opencode`                         |
| Windows  | `%ProgramData%\opencode`                |

ไดเรกทอรีระบบทำงานเหมือนไดเรกทอรีส่วนกลาง นอกจาก
`opencode.json(c)` ยังโหลด `agents/`, `commands/`, `skills/` และ `plugins/`
สำหรับผู้ใช้ทุกคนบนเครื่อง

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

บน macOS OpenCode ยังอ่านค่ากำหนดแบบมีการจัดการที่เครื่องมือ MDM เผยแพร่สำหรับ
โดเมน `ai.opencode.managed` โปรไฟล์เฉพาะผู้ใช้จะแทนที่โปรไฟล์ทั่วเครื่อง

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

การตั้งค่าแบบมีการจัดการมีลำดับสูงสุด ผู้ใช้และโปรเจกต์จึงแทนที่ค่าที่ตั้งไว้ไม่ได้
และการตั้งค่าแบบมีการจัดการแทนที่ไดเรกทอรีระบบ การตั้งค่าเพียงอย่างเดียวหยุดผู้ใช้จากการเพิ่มผู้ให้บริการ เซิร์ฟเวอร์ MCP
เอเจนต์ หรือปลั๊กอินไม่ได้ ให้ใช้[นโยบาย](/policies#precedence)ในการกำหนดค่าแบบมีการจัดการ
เพื่อบังคับข้อจำกัด

วางการตั้งค่าผู้ใช้สำหรับทุกโปรเจกต์ในการกำหนดค่าส่วนกลาง

```text
~/.config/opencode/opencode.json(c)
```

วางการตั้งค่าโปรเจกต์ในไฟล์ใดไฟล์หนึ่งเหล่านี้

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode ค้นหาไฟล์กำหนดค่าจากไดเรกทอรีปัจจุบันขึ้นไปถึงรากของระบบไฟล์ โดยรวมไฟล์ `opencode.json(c)`
ที่วางไว้ในแต่ละไดเรกทอรีโดยตรงจากไกลสุดมาใกล้สุดก่อน แล้วจึงรวมไฟล์ในไดเรกทอรี `.opencode` ตามลำดับเดียวกัน
ค่าจากไฟล์ใน `.opencode` ทุกไฟล์ที่พบจึงมีลำดับสูงกว่าค่าจากไฟล์ที่วางไว้โดยตรงทุกไฟล์
ควรใช้รูปแบบเดียวกันตลอดทั้งโครงสร้างไดเรกทอรี เว้นแต่จะตั้งใจใช้ลำดับนี้

ตัวอย่างเช่น เริ่ม OpenCode จาก `/home/user/projects/acme/packages/web`

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode ใช้ไฟล์เหล่านี้จากลำดับต่ำไปสูง

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

การกำหนดค่าแพ็กเกจแทนที่การตั้งค่าที่ตรงกันจากรีโพ ซึ่งแทนที่การกำหนดค่าส่วนกลาง การกำหนดค่าระบบแทนที่ทั้งหมด
การตั้งค่าที่ไม่ขัดกันจะถูกเก็บไว้ [นโยบาย](/policies#precedence)
จากไฟล์ส่วนกลางและโปรเจกต์ประเมินในลำดับย้อนกลับ และนโยบายระบบมีลำดับเหนือกว่าทั้งหมด

## Schema

schema การกำหนดค่าฉบับเต็มของ OpenCode อยู่ที่
[opencode.ai/config.json](https://opencode.ai/config.json)

เพิ่มฟิลด์ `$schema` ในไฟล์กำหนดค่าเพื่อเปิดการตรวจสอบและ
เติมอัตโนมัติในอีดิเตอร์ที่รองรับ JSON Schema

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

ใช้ schema เป็นข้อมูลอ้างอิงว่ามีฟิลด์ใดบ้าง แต่ละฟิลด์รับค่าอะไร และการกำหนดค่าที่ซ้อนกันมีโครงสร้างอย่างไร

### Shell

ตั้งเชลล์ที่เทอร์มินัลและเครื่องมือ shell ใช้

```jsonc
{
  "shell": "/bin/zsh",
}
```

### โมเดล

ตั้งโมเดลเริ่มต้นในรูปแบบ `provider/model` ค่าเริ่มต้นระดับรากปัจจุบัน
ไม่ได้เก็บ `#variant` การอ้างอิงโมเดลของเอเจนต์และคำสั่งเลือกได้

```jsonc
{
  "model": "anthropic/claude-sonnet-5-5",
}
```

ดู[คู่มือโมเดล](/models)สำหรับการเลือกโมเดลและโมเดลในเครื่อง

### เอเจนต์

เลือกเอเจนต์หลักที่ใช้เมื่อเซสชันไม่ได้เลือกอย่างชัดเจน

```jsonc
{
  "default_agent": "build",
}
```

ดู[คู่มือเอเจนต์](/agents)สำหรับเอเจนต์ในตัวและ
กำหนดเอง

### การอัปเดต

ควบคุมการตรวจอัปเดตจากการกำหนดค่าส่วนกลาง ตั้ง `update` เป็น `"disable"` เพื่อ
ข้าม `"notify"` เพื่อแสดงอัปเดตที่มีก่อนติดตั้ง หรือ `"auto"` เพื่อติดตั้งอัตโนมัติ เมื่อไม่ระบุ `update` มีค่าเริ่มต้น `"notify"`

การติดตั้งอัตโนมัติไม่รีสตาร์ตเซิร์ฟเวอร์ที่ทำงานอยู่ ให้รีสตาร์ตเองเพื่อเปิดใช้การอัปเดตที่ติดตั้ง
ค่าที่ระดับโปรเจกต์จะถูกเพิกเฉย

```jsonc
{
  "update": "notify",
}
```

### ชื่อผู้ใช้

ตั้งชื่อผู้ใช้ OpenCode รับฟิลด์นี้แต่ไม่แสดงใน
บทสนทนา

```jsonc
{
  "username": "alice",
}
```

### สิทธิ์

กำหนดกฎตามลำดับที่อนุญาต ปฏิเสธ หรือถามก่อนเอเจนต์ใช้เครื่องมือกับ
ทรัพยากรที่ตรงกัน

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

ดู[คู่มือสิทธิ์](/permissions)สำหรับการจับคู่กฎและการกระทำที่ใช้ได้

### นโยบาย

อนุญาตหรือปฏิเสธการใช้ผู้ให้บริการ ปฏิเสธอย่างเด็ดขาดการตรวจสิทธิ์ หรือบล็อก
เซิร์ฟเวอร์ MCP สกิล หรือปลั๊กอิน ด้วยข้อกำหนดตามลำดับที่การกำหนดค่ากว้างกว่าสามารถ
แทนที่ได้

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

ดู[คู่มือนโยบาย](/policies)สำหรับการจับคู่ ลำดับความสำคัญข้ามไฟล์
การกำหนดค่า และนโยบายที่จัดการผ่าน Console

### เอเจนต์ที่กำหนดเอง

แทนที่เอเจนต์ในตัวหรือกำหนดเอเจนต์เฉพาะทางพร้อมโมเดล
คำแนะนำ โหมด และสิทธิ์ของตัวเอง

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

ดู[คู่มือเอเจนต์](/agents)สำหรับตัวเลือกเอเจนต์ทั้งหมดและเอเจนต์แบบไฟล์

### สแนปช็อต

เปิดหรือปิดสแนปช็อตระบบไฟล์ที่ใช้สำหรับการเลิกทำและการย้อนกลับ

```jsonc
{
  "snapshots": false,
}
```

ดู[คู่มือสแนปช็อต](/snapshots)สำหรับพฤติกรรมการเลิกทำและทำซ้ำ

### การติดตามการเปลี่ยนแปลงไฟล์

เพิกเฉยไฟล์และไดเรกทอรีที่ไม่ควรกระตุ้นการอัปเดตระบบไฟล์

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### ฟอร์แมตเตอร์

จัดรูปแบบไฟล์หลังเครื่องมือ `write`, `edit` หรือ `patch` เปลี่ยน ตั้ง
`formatter` เป็น `true` เพื่อเปิดฟอร์แมตเตอร์ในตัวที่ใช้ได้

```jsonc
{
  "formatter": true,
}
```

ดู[คู่มือฟอร์แมตเตอร์](/formatters)สำหรับฟอร์แมตเตอร์ในตัวและกำหนดเอง

### สื่อ

ควบคุมวิธีปรับขนาดหรือปฏิเสธภาพที่เครื่องมือ `read` โหลดแล้วพบว่าเกินขีดจำกัด
ก่อนส่งให้โมเดล

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

ดู[คู่มือไฟล์แนบ](/attachments)สำหรับการประมวลผลภาพและขีดจำกัด

### เอาต์พุต

ตั้งจำนวนบรรทัดและไบต์สูงสุดที่เก็บจากผลเครื่องมือ

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### การค้นหา

เลือกวิธีที่ OpenCode ค้นหาเว็บ ใช้ `"random"` เพื่อเลือกผู้ให้บริการที่พร้อมใช้
โดยอัตโนมัติ

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

ดู[คู่มือการค้นหาเว็บ](/websearch)สำหรับผู้ให้บริการ ข้อมูลรับรอง การเลือก
ขีดจำกัดอัตรา และการปิดการค้นหา

### MCP

กำหนดเซิร์ฟเวอร์ Model Context Protocol ในเครื่องและระยะไกล ค่า
`mcp.timeout` ส่วนกลางมีผลกับเซิร์ฟเวอร์ที่กำหนดในไฟล์กำหนดค่า `timeout`
ของแต่ละเซิร์ฟเวอร์จะแทนที่

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

ดู[คู่มือ MCP](/mcp-servers)สำหรับเซิร์ฟเวอร์ระยะไกล OAuth ตัวแปรสภาพแวดล้อม และเวลาหมดอายุ

### การบีบอัด

ควบคุมการบีบอัดบริบทอัตโนมัติและปริมาณบริบทล่าสุดที่เก็บไว้

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": "15%",
  },
}
```

`buffer` คือสัดส่วนของหน้าต่างบริบทของโมเดลที่เว้นว่างไว้ก่อนการบีบอัดอัตโนมัติเริ่ม

สรุปในเครื่องยังเป็นค่าเริ่มต้น เลือกใช้การบีบอัดแบบเนทีฟของผู้ให้บริการสำหรับทั้ง
คำขออัตโนมัติและด้วยตัวเองด้วยนโยบายผู้ให้บริการหรือโมเดล

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

ค่าที่ตั้งไว้ในโมเดลจะแทนที่ค่าของผู้ให้บริการ การบีบอัดอัตโนมัติอิงพื้นที่อินพุตที่โมเดลที่เลือกใช้งานได้
เช็กพอยต์ของผู้ให้บริการเก็บข้อความล่าสุดของผู้ใช้ตามขีดจำกัด `compaction.keep.tokens` เดียวกับที่ใช้เก็บบทสนทนาส่วนท้ายเมื่อสรุปในเครื่อง
การตั้ง `compaction.auto: false` ที่ระดับบนสุดจะปิดการบีบอัดอัตโนมัติครั้งใหม่โดยไม่ทิ้งเช็กพอยต์ที่ใช้อยู่ ดู [คู่มือการบีบอัด](/compaction) สำหรับการจัดสรรพื้นที่และการกู้คืนเมื่อเกินขีดจำกัด

### การอุ่นเซสชัน

รักษาเซสชันโมเดลที่ใช้งานล่าสุดให้อุ่นด้วยคำขอชั่วคราวเป็นระยะ
การอุ่นปิดโดยค่าเริ่มต้น ตั้งเป็น `true` เพื่ออุ่นก่อนแคชของแต่ละ
โมเดลหมดอายุ นานสูงสุด 30 นาที

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "auto",
    "duration": "30 minutes",
  },
}
```

`settings.cache.warming` ของผู้ให้บริการหรือโมเดลแทนที่ และ
`settings.cache.ttl` กำหนดระยะที่ผู้ให้บริการเก็บแคช ดู
[คู่มือการอุ่นเซสชัน](/warming)สำหรับพฤติกรรมคำขอ การปรับแต่ง และข้อควรพิจารณา
ด้านค่าใช้จ่าย และ[อายุแคช](/models#cache-lifetime)สำหรับ `cache.ttl`

### สกิล

เพิ่มไดเรกทอรีหรือ URL ที่ OpenCode ควรค้นหาสกิลของเอเจนต์

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

ดู[คู่มือสกิล](/skills)สำหรับโครงสร้างสกิลและการค้นพบอัตโนมัติใต้ `.opencode/skills/`

### คำสั่ง

กำหนดคำสั่ง slash ที่ใช้ซ้ำได้เป็นเทมเพลตพรอมต์ที่มีชื่อ

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

ดู[คู่มือคำสั่ง](/commands)สำหรับอาร์กิวเมนต์ โมเดล เอเจนต์ และคำสั่งแบบไฟล์

### คำแนะนำ

ประกาศไฟล์คำแนะนำ glob หรือ URL แบบ HTTP(S) เพิ่มเติม OpenCode โหลด
ควบคู่กับไฟล์ `AGENTS.md` ที่ค้นพบ

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

ดู[คู่มือคำแนะนำ](/instructions)สำหรับคำแนะนำโปรเจกต์และ `AGENTS.md`

### การอ้างอิง

ทำให้ไดเรกทอรีในเครื่องหรือรีโพ Git ใช้ได้เป็นบริบทประกอบที่มีชื่อ

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

ดู[คู่มือการอ้างอิง](/references)สำหรับรูปแบบย่อ การมองเห็น และการแก้ไขพาธ

### เวิร์กทรี

ตั้งไดเรกทอรีแม่สำหรับเวิร์กทรีในเครื่องใหม่ OpenCode ต่อท้ายชื่อเวิร์กทรีที่ขอหรือสร้างขึ้น

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

พาธสัมพัทธ์อ้างอิงจากเช็กเอาต์หลักที่บันทึกไว้ของโปรเจกต์ ไม่ว่าจะกำหนดค่าไว้ในระดับส่วนกลางหรือระดับโปรเจกต์ ระบบใช้พาธสัมบูรณ์ตามที่ระบุ และให้ `~/` อ้างอิงจากโฮมไดเรกทอรีของผู้ใช้

ตัวอย่างเช่น การกำหนดค่าส่วนกลางนี้วางเวิร์กทรีใหม่ไว้ใต้ไดเรกทอรี `.lane/trees/` ของแต่ละโปรเจกต์

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

หากไม่มีการตั้งค่านี้ การสร้างจะใช้ไดเรกทอรีข้อมูลของเซิร์ฟเวอร์ใต้ `worktree/<first-six-project-ID-characters>`
การสร้างและรีเฟรชเวิร์กทรีโหลดการกำหนดค่าจากเช็กเอาต์หลักที่บันทึกไว้ของโปรเจกต์ รวมถึงเมื่อคลอนอื่น
ใช้ ID โปรเจกต์เดียวกัน การเปลี่ยนไม่ย้ายเวิร์กทรีที่มีอยู่

Git เป็นค่าเริ่มต้นในตัว [ปลั๊กอิน](/build/plugins/server#worktrees)ที่ลงทะเบียนกลยุทธ์จะกลายเป็น
ค่าเริ่มต้นในรันไทม์ของปลั๊กอินนั้นโดยอัตโนมัติ การดำเนินการโปรเจกต์ใช้รันไทม์ของเช็กเอาต์หลัก
ตัวเลือกเฉพาะกลยุทธ์เป็นของปลั๊กอินนั้น ไม่ใช่ออบเจกต์การกำหนดค่า `worktree`

### ปลั๊กอิน

โหลดปลั๊กอินจากแพ็กเกจหรือไดเรกทอรีปลั๊กอินในเครื่อง ใช้รูปแบบออบเจกต์เมื่อปลั๊กอิน
รับตัวเลือก

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

ดู[คู่มือปลั๊กอิน](/plugins)สำหรับการโหลดและการกำหนดค่าปลั๊กอิน

### ผู้ให้บริการ

กำหนดผู้ให้บริการและเพิ่มหรือแทนที่โมเดล การตั้งค่าคำขอ
เฮดเดอร์ และตัวเลือกย่อยของโมเดล

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol-custom": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

`settings.transport: "websocket"` ของผู้ให้บริการเลือก WebSocket ของเซสชัน

ดู[คู่มือผู้ให้บริการ](/providers)สำหรับข้อมูลรับรอง เอนด์พอยต์กำหนดเอง แพ็กเกจผู้ให้บริการ การรับส่ง WebSocket และการกำหนดค่าโมเดล

## ตัวแปร

คุณใช้การแทนที่ตัวแปรในไฟล์กำหนดค่าเพื่ออ้างอิงตัวแปรสภาพแวดล้อมและเนื้อหาไฟล์ได้ วางการอ้างอิงในสตริง JSON

### ตัวแปรสภาพแวดล้อม

ใช้ `{env:VARIABLE_NAME}` เพื่อแทนที่ตัวแปรสภาพแวดล้อม

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "providers": {
    "anthropic": {
      "settings": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
      },
    },
  },
}
```

หากไม่ได้ตั้งตัวแปรสภาพแวดล้อม จะถูกแทนที่ด้วยสตริงว่าง

### ไฟล์

ใช้ `{file:path/to/file}` เพื่อแทนที่เนื้อหาไฟล์

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": {
        "apiKey": "{file:~/.secrets/openai-key}",
      },
    },
  },
}
```

พาธไฟล์อาจเป็น

- สัมพัทธ์กับไดเรกทอรีของไฟล์กำหนดค่า
- สัมบูรณ์ หรือเริ่มด้วย `~/` สำหรับไดเรกทอรีบ้านของคุณ

หากไฟล์ไม่มี จะถูกแทนที่ด้วยสตริงว่าง

สิ่งเหล่านี้มีประโยชน์สำหรับ

- เก็บข้อมูลละเอียดอ่อนเช่นคีย์ API ในไฟล์แยก
- แชร์ตัวอย่างการกำหนดค่าทั่วไปข้ามไฟล์กำหนดค่าหลายไฟล์

## การทดลอง

<Callout type="warning">
  การตั้งค่าทดลองอาจเปลี่ยน ใช้งานไม่ได้ หรือถูกนำออกในรุ่นใดก็ได้โดยไม่แจ้งล่วงหน้า อย่าพึ่งพาการตั้งค่าเหล่านี้ในเวิร์กโฟลว์ที่ต้องการความเสถียร
</Callout>

การตั้งค่าทดลองทั้งหมดอยู่ภายใต้คีย์ `experimental`

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "todo": true,
    "subagent_depth": 2,
    "image_generate": { "model": "openai/gpt-image-2" },
    "location_idle_timeout": "4 hours",
  },
}
```

### รายการงาน

ตั้ง `todo` เป็น `true` เพื่อให้เอเจนต์มีเครื่องมือ `todowrite` สำหรับติดตามงานหลายขั้น ค่าเริ่มต้น `false`

### ความลึกซับเอเจนต์

`subagent_depth` กำหนดว่าซับเอเจนต์เริ่มซับเอเจนต์ของตัวเองได้ลึกเท่าใด ค่าเริ่มต้น `1` ซับเอเจนต์จึงเริ่ม
ซับเอเจนต์อื่นไม่ได้

### การสร้างภาพ

`image_generate` ตั้งโมเดลเริ่มต้นสำหรับเครื่องมือ [`generate_image`](/tools#image-generate) เป็น
`providerID/modelID` พร้อม `#variant` ที่ไม่บังคับ เมื่อโมเดลนั้นไม่พร้อมใช้หรือจัดการคำขอไม่ได้ OpenCode
จะเลือกโมเดลสร้างภาพอื่นโดยอัตโนมัติ

```jsonc
{
  "experimental": {
    "image_generate": {
      "model": "openai/gpt-image-2",
    },
  },
}
```

### ระยะเวลาก่อนหยุดบริการของ location ที่ไม่ได้ใช้งาน

`location_idle_timeout` กำหนดว่า location ของโปรเจกต์ไม่มีเซสชันทำงานได้นานเท่าใดก่อนที่ OpenCode จะเลิกโหลดบริการของ location นั้น
ระบุเป็นช่วงเวลา เช่น `"2 hours"` ค่าเริ่มต้นคือ `"60 minutes"` หากยังมีเซสชันหรืองานเบื้องหลังทำงานอยู่ ระบบจะไม่เลิกโหลด location
ตั้งเป็น `false` หากไม่ต้องการให้ระบบเลิกโหลด location ที่ไม่ได้ใช้งานเลย ค่าของโปรเจกต์แทนที่ค่าส่วนกลางได้

```jsonc
{
  "experimental": {
    "location_idle_timeout": false,
  },
}
```

### นโยบายที่เลิกใช้

`experimental.policies` เลิกใช้แล้ว ให้ใช้ [`policies`](/policies)ระดับบนสุดแทน คีย์เดิมยังใช้ได้และ
รวมเข้า `policies`
