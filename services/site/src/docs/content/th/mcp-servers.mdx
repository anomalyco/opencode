OpenCode เชื่อมต่อกับเซิร์ฟเวอร์ [Model Context Protocol](https://modelcontextprotocol.io/) เพื่อเปิดให้ใช้เครื่องมือ พรอมต์ ทรัพยากร และคำแนะนำจากเซิร์ฟเวอร์ เครื่องมือ MCP ใช้พื้นที่ในบริบทของโมเดล จึงควรเพิ่มเฉพาะเซิร์ฟเวอร์ที่จำเป็น

## การตั้งค่า

เพิ่มเซิร์ฟเวอร์ระยะไกลจากโปรเจกต์ที่ควรใช้ แล้วตรวจการเชื่อมต่อ

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp list
```

คำสั่งเขียนเซิร์ฟเวอร์ลง[การกำหนดค่า](/config)ของโปรเจกต์ เพิ่ม `--global` เพื่อให้ใช้ได้ในทุกโปรเจกต์

```sh
opencode mcp add context7 --global --url https://mcp.context7.com/mcp
```

เซิร์ฟเวอร์ระยะไกลใช้ OAuth โดยค่าเริ่มต้น หากรายการแสดง `needs authentication` ให้เปิด OpenCode รัน `/mcps` เลือกเซิร์ฟเวอร์ แล้วลงชื่อเข้าใช้ เซิร์ฟเวอร์ที่เชื่อมต่อแล้วพร้อมให้เอเจนต์ใช้

```text
✓ context7  connected
```

## การกำหนดค่า

หากต้องการกำหนดเซิร์ฟเวอร์ด้วยตัวเอง ให้ตั้งชื่อที่ไม่ซ้ำภายใต้ `mcp.servers` V2 ไม่วางชื่อเซิร์ฟเวอร์โดยตรงใต้ `mcp`

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
      },
    },
  },
}
```

เซิร์ฟเวอร์เชื่อมต่ออัตโนมัติ ใช้ `disabled` ไม่ใช่ฟิลด์ `enabled` เพื่อให้กำหนดค่าไว้โดยไม่เชื่อมต่อ

```jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "disabled": true,
      },
    },
  },
}
```

การกำหนดค่าโปรเจกต์ที่ลำดับสูงกว่าจะแทนที่ออบเจกต์เซิร์ฟเวอร์ทั้งหมดที่ชื่อเดียวกัน ใช้ชื่อต่างกันสำหรับการเชื่อมต่อหรือบัญชีแยก มิฉะนั้นให้ระบุทุกฟิลด์ที่จำเป็นซ้ำในการแทนที่

```jsonc title="opencode.jsonc"
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
      },
    },
  },
}
```

## ในเครื่อง

เซิร์ฟเวอร์ในเครื่องคือคำสั่งที่ OpenCode เริ่มผ่านการรับส่ง MCP stdio เพิ่มด้วยคำสั่งหลัง `--`

```sh
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything
```

ส่งตัวแปรสภาพแวดล้อมด้วยแฟล็ก `--env` ซ้ำ

```sh
opencode mcp add everything --env LOG_LEVEL=info -- npx -y @modelcontextprotocol/server-everything
```

ใช้การกำหนดค่าสำหรับตัวเลือกโปรเซสอื่นเช่นไดเรกทอรีทำงาน

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "everything": {
        "type": "local",
        "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
        "cwd": ".",
        "environment": {
          "LOG_LEVEL": "info",
          "MCP_API_KEY": "{env:MCP_API_KEY}",
        },
      },
    },
  },
}
```

| ฟิลด์ | จำเป็น | คำอธิบาย |
| --- | --- | --- |
| `type` | ใช่ | ต้องเป็น `"local"` |
| `command` | ใช่ | ไฟล์ปฏิบัติการตามด้วยอาร์กิวเมนต์ |
| `cwd` | ไม่ | ไดเรกทอรีทำงานของโปรเซส พาธสัมพัทธ์อ้างอิงจากเวิร์กสเปซ ซึ่งเป็นไดเรกทอรีทำงานเริ่มต้นด้วย |
| `environment` | ไม่ | ตัวแปรสตริงที่เพิ่มในสภาพแวดล้อมโปรเซสที่สืบทอดมาของ OpenCode |
| `disabled` | ไม่ | ป้องกันการเชื่อมต่อเมื่อเป็น `true` ค่าเริ่มต้น `false` |
| `codemode` | ไม่ | ตั้งเป็น `false` เพื่อเปิดเครื่องมือโดยตรงแทนผ่าน Code Mode ค่าเริ่มต้น `true` |
| `timeout` | ไม่ | การแทนที่เวลาหมดอายุต่อเซิร์ฟเวอร์ |
| `protocol` | ไม่ | `auto` (ค่าเริ่มต้น), `legacy` หรือ `2026-07-28` ดู[เวอร์ชันโปรโตคอล](#protocol-version) |
| `pool` | ไม่ | แชร์การเชื่อมต่อเดียวข้ามไดเรกทอรี ค่าเริ่มต้น `false` ดู[การเชื่อมต่อที่แชร์](#shared-connections) |

ใช้ `{env:NAME}` สำหรับการแทนที่ตัวแปรสภาพแวดล้อม นิพจน์ shell เช่น `$NAME` ไม่ถูกขยายในสตริง JSON

```jsonc
{
  "environment": {
    "MCP_API_KEY": "{env:MCP_API_KEY}",
  },
}
```

## ระยะไกล

เซิร์ฟเวอร์ระยะไกลใช้การรับส่ง MCP Streamable HTTP และต้องใช้ URL สัมบูรณ์

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
```

ส่งเฮดเดอร์คำขอด้วยแฟล็ก `--header` ซ้ำ ใส่เครื่องหมายคำพูดครอบการอ้างอิง `{env:NAME}` เพื่อให้ shell เขียนตามจริง

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp --header 'CONTEXT7_API_KEY={env:CONTEXT7_API_KEY}'
```

ใช้การกำหนดค่าสำหรับตัวเลือกอื่น เก็บความลับในตัวแปรสภาพแวดล้อมแทนไฟล์

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}",
        },
      },
    },
  },
}
```

| ฟิลด์ | จำเป็น | คำอธิบาย |
| --- | --- | --- |
| `type` | ใช่ | ต้องเป็น `"remote"` |
| `url` | ใช่ | เอนด์พอยต์ Streamable HTTP แบบสัมบูรณ์ |
| `headers` | ไม่ | เฮดเดอร์ HTTP แบบสตริงที่ส่งไปยังเอนด์พอยต์ |
| `oauth` | ไม่ | การตั้งค่า OAuth หรือ `false` เพื่อปิด OAuth |
| `disabled` | ไม่ | ป้องกันการเชื่อมต่อเมื่อเป็น `true` ค่าเริ่มต้น `false` |
| `codemode` | ไม่ | ตั้งเป็น `false` เพื่อเปิดเครื่องมือโดยตรงแทนผ่าน Code Mode ค่าเริ่มต้น `true` |
| `timeout` | ไม่ | การแทนที่เวลาหมดอายุต่อเซิร์ฟเวอร์ |
| `protocol` | ไม่ | `auto` (ค่าเริ่มต้น), `legacy` หรือ `2026-07-28` ดู[เวอร์ชันโปรโตคอล](#protocol-version) |
| `pool` | ไม่ | แชร์การเชื่อมต่อเดียวข้ามไดเรกทอรี ค่าเริ่มต้น `false` ดู[การเชื่อมต่อที่แชร์](#shared-connections) |

ใช้ `oauth: false` เฉพาะเมื่อเซิร์ฟเวอร์ใช้คีย์ API หรือข้อมูลรับรองในเฮดเดอร์อย่างเดียว

```jsonc
{
  "type": "remote",
  "url": "https://mcp.example.com/mcp",
  "oauth": false,
  "headers": { "Authorization": "Bearer {env:MCP_API_KEY}" },
}
```

## OAuth

เซิร์ฟเวอร์ระยะไกลใช้ OAuth เว้นแต่ตั้ง `oauth` เป็น `false` OpenCode จะค้นหาเซิร์ฟเวอร์ที่ให้สิทธิ์ ลงชื่อเข้าใช้ด้วย PKCE และต่ออายุโทเคน ระบบเก็บข้อมูลรับรองไว้นอกไฟล์กำหนดค่าของโปรเจกต์

เซิร์ฟเวอร์ส่วนใหญ่ต้องการเพียง URL

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
      },
    },
  },
}
```

หากเซิร์ฟเวอร์ต้องตรวจสอบสิทธิ์ ให้รัน `/mcps` เลือกมัน แล้วทำการอนุญาตในเบราว์เซอร์ให้เสร็จ CLI เริ่มขั้นตอนเดียวกันได้

```sh
opencode mcp auth sentry
```

### เบราว์เซอร์บนเครื่องอื่น

เมื่อ OpenCode ทำงานผ่าน SSH ในคอนเทนเนอร์ หรือบนเซิร์ฟเวอร์ระยะไกล เบราว์เซอร์จะเข้าถึง OpenCode ไม่ได้หลังลงชื่อเข้าใช้และแสดงหน้าที่โหลดไม่ขึ้น ให้คัดลอก URL ของหน้านั้นจากแถบที่อยู่แล้ววางในพรอมต์ลงชื่อเข้าใช้

```text
http://127.0.0.1:52817/callback?code=...&state=...
```

พรอมต์จะปรากฏใน `/mcps` ใน `opencode mcp auth` และในกล่องโต้ตอบลงชื่อเข้าใช้ของแอปเดสก์ท็อปและเว็บแอปขณะที่ OpenCode รอเบราว์เซอร์

### การลงทะเบียนไคลเอนต์

OpenCode ระบุตัวเองต่อเซิร์ฟเวอร์การอนุญาตด้วยวิธีแรกที่ใช้ได้

| วิธี | ใช้เมื่อ |
| --- | --- |
| ไคลเอนต์ที่ลงทะเบียนล่วงหน้า | กำหนด `oauth.client_id` ไว้ |
| [Client ID Metadata Document](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#client-id-metadata-documents) (CIMD) | เซิร์ฟเวอร์การอนุญาตรองรับ CIMD และไคลเอนต์สาธารณะ และไม่ได้ตั้ง `oauth.redirect_uri` |
| [Dynamic client registration](https://datatracker.ietf.org/doc/html/rfc7591) (DCR) | เมื่อใช้ทั้งสองวิธีข้างต้นไม่ได้ OpenCode จะลงทะเบียนไคลเอนต์ เมื่อมีการลงชื่อเข้าใช้ครั้งต่อไป ระบบจะใช้ไคลเอนต์เดิมและรอรับการเชื่อมต่อที่พอร์ตที่ลงทะเบียนไว้ หากพอร์ตนั้นถูกใช้งานอยู่ ระบบจะลงทะเบียนใหม่ |

เซิร์ฟเวอร์การอนุญาตเลือกใช้ CIMD ผ่านข้อมูลเมตา

```json
{
  "issuer": "https://auth.example.com",
  "client_id_metadata_document_supported": true,
  "token_endpoint_auth_methods_supported": ["none"]
}
```

เมื่อใช้ CIMD OpenCode ส่ง URL เอกสารข้อมูลเมตาของตัวเองเป็น `client_id` และข้ามการลงทะเบียน

```text
https://opencode.ai/oauth/opencode/client.json
```

เอกสารอนุญาต redirect แบบลูปแบ็กเหล่านี้โดยไม่ต้องระบุพอร์ต

- `http://127.0.0.1/callback`
- `http://localhost/callback`
- `http://127.0.0.1/mcp/oauth/callback` สำหรับไคลเอนต์รุ่นเก่า

เซิร์ฟเวอร์การอนุญาตรับพอร์ตลูปแบ็กใดก็ได้สำหรับ redirect เหล่านี้ ตามที่ [RFC 8252](https://datatracker.ietf.org/doc/html/rfc8252#section-7.3) กำหนด `callback_port` จึงใช้ได้กับ CIMD ส่วน `redirect_uri` กำหนดเองใช้ไม่ได้ OpenCode จึงถอยไปใช้ DCR

หากเซิร์ฟเวอร์การอนุญาตไม่รองรับทั้ง CIMD และ DCR ให้กำหนดไคลเอนต์ที่ลงทะเบียนล่วงหน้า

### ไคลเอนต์ที่ลงทะเบียนล่วงหน้า

เมื่อผู้ให้บริการให้ข้อมูลรับรองไคลเอนต์ ให้ใช้ฟิลด์ OAuth แบบ snake_case ของ V2

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "oauth": {
          "client_id": "{env:MCP_CLIENT_ID}",
          "client_secret": "{env:MCP_CLIENT_SECRET}",
          "scope": "tools:read tools:execute",
          "callback_port": 19876,
          "redirect_uri": "http://127.0.0.1:19876/callback",
        },
      },
    },
  },
}
```

| ฟิลด์ | คำอธิบาย |
| --- | --- |
| `client_id` | ID ไคลเอนต์ที่ลงทะเบียนล่วงหน้า มีลำดับเหนือกว่า CIMD และ DCR |
| `client_secret` | ค่าลับสำหรับไคลเอนต์ที่เก็บข้อมูลลับได้ ระบบส่งค่านี้ในบอดีของคำขอโทเคน ไม่ต้องระบุสำหรับไคลเอนต์สาธารณะ |
| `scope` | รายการสโคปที่ขอ คั่นด้วยช่องว่าง ค่าเริ่มต้นคือสโคปที่เซิร์ฟเวอร์ระบุเมื่อปฏิเสธคำขอที่ยังไม่ได้ยืนยันตัวตน OpenCode จะส่งสโคปที่ได้รับอนุญาตอีกครั้งเมื่อต่ออายุโทเคน |
| `callback_port` | พอร์ต callback ในเครื่องตั้งแต่ `1` ถึง `65535` หากไม่ระบุ ระบบจะใช้พอร์ตของ `redirect_uri` ก่อน ถ้าไม่มีจึงใช้พอร์ตของไคลเอนต์ที่ลงทะเบียนไว้ในการลงชื่อเข้าใช้ครั้งก่อน หรือเลือกพอร์ตชั่วคราวที่ว่างหากยังไม่มีพอร์ตที่ลงทะเบียนไว้ |
| `redirect_uri` | URI ลูปแบ็กที่ลงทะเบียนล่วงหน้าซึ่งพาธและพอร์ตไปถึงตัวรับ callback ในเครื่อง การตั้งค่าจะปิด CIMD |
| `auth_server_metadata_url` | URL เอกสารข้อมูลเมตา OAuth หรือ OpenID Connect ของเซิร์ฟเวอร์การอนุญาต ตั้งเมื่อเซิร์ฟเวอร์ MCP ไม่เผยแพร่ข้อมูลเมตาทรัพยากรที่ได้รับการป้องกันซึ่งระบุเซิร์ฟเวอร์การอนุญาต |

ลบข้อมูลรับรอง OAuth ที่เก็บไว้เมื่อต้องการลงชื่อเข้าใช้อีกครั้งหรือสลับบัญชี

```sh
opencode mcp logout sentry
```

## เวลาหมดอายุ

เวลาหมดอายุเป็นจำนวนเต็มบวกหน่วยมิลลิวินาที ตั้งค่าเริ่มต้นภายใต้ `mcp.timeout` ออบเจกต์ `timeout` ของเซิร์ฟเวอร์แทนที่ค่าเริ่มต้นที่ตรงกัน

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "timeout": {
      "startup": 45000,
      "catalog": 30000,
      "execution": 600000,
    },
    "servers": {
      "slow-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "timeout": {
          "catalog": 60000,
        },
      },
    },
  },
}
```

| เวลาหมดอายุ | ค่าเริ่มต้น | ใช้กับ |
| --- | --- | --- |
| `startup` | 30 วินาที | การเชื่อมต่อการรับส่งและการเริ่มต้นเซิร์ฟเวอร์ |
| `catalog` | 30 วินาที | การแสดงรายการเครื่องมือ พรอมต์ ทรัพยากร และเทมเพลตทรัพยากร |
| `execution` | 12 ชั่วโมง | การเรียกเครื่องมือ การดึงพรอมต์ และการอ่านทรัพยากร |

## เวอร์ชันโปรโตคอล

OpenCode ตรวจสอบเซิร์ฟเวอร์ทุกตัวสำหรับรีวิชัน 2026-07-28 โดยค่าเริ่มต้น และถอยไปใช้การจับมือ `initialize` แบบ MCP คลาสสิกเมื่อเซิร์ฟเวอร์ไม่รองรับ ตั้ง `protocol` ของเซิร์ฟเวอร์เป็น `legacy` เพื่อข้ามการตรวจสอบ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "older": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "protocol": "legacy",
      },
    },
  },
}
```

| ค่า | ลักษณะการทำงาน |
| --- | --- |
| `auto` | ค่าเริ่มต้น ตรวจด้วย `server/discover` สำหรับรีวิชัน 2026-07-28 และถอยไป `legacy` เมื่อเซิร์ฟเวอร์ไม่รองรับ รวมถึงเมื่อเซิร์ฟเวอร์ระยะไกลตอบการตรวจด้วย HTTP 5xx |
| `legacy` | ส่ง `initialize` และใช้โปรโตคอลรีวิชันถึง 2025-11-25 |
| `2026-07-28` | ต้องใช้รีวิชัน 2026-07-28 การเชื่อมต่อล้มเหลวกับเซิร์ฟเวอร์เก่า |

การตรวจเซิร์ฟเวอร์ในเครื่องรุ่นเก่าจะเพิ่มโปรเซสชั่วคราวและอาจรอถึงเวลาหมดอายุเริ่มต้นเมื่อเซิร์ฟเวอร์เพิกเฉยต่อคำขอที่ไม่รู้จัก จึงควรตั้ง `legacy` ในเซิร์ฟเวอร์ที่รู้ว่ามาก่อนรีวิชัน 2026-07-28

## การเชื่อมต่อที่แชร์

เซิร์ฟเวอร์ OpenCode หนึ่งตัวเปิดหลายไดเรกทอรีได้ และแต่ละแห่งเชื่อมต่อเซิร์ฟเวอร์ MCP ทุกตัวแยกกัน ตั้ง `pool` เป็น `true` เพื่อให้ไดเรกทอรีที่ตั้งค่าเซิร์ฟเวอร์เหมือนกันแชร์การเชื่อมต่อเดียวและรายการเครื่องมือเดียว

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "cloudflare": {
        "type": "remote",
        "url": "https://mcp.cloudflare.com/mcp",
        "pool": true,
      },
    },
  },
}
```

- แชร์เฉพาะการเชื่อมต่อในรีวิชัน 2026-07-28 เซิร์ฟเวอร์ที่ตอบด้วยรีวิชันเก่าหรือตั้งเป็น `legacy` จะคงการเชื่อมต่อหนึ่งรายการต่อไดเรกทอรี
- ไดเรกทอรีใช้การเชื่อมต่อร่วมกันได้ก็ต่อเมื่อการตั้งค่าที่มีผลต่อการเชื่อมต่อตรงกันทั้งหมด สำหรับเซิร์ฟเวอร์ระยะไกลต้องตรงกันทั้ง URL เฮดเดอร์ การตั้งค่า OAuth และบัญชีที่ลงชื่อเข้าใช้ ส่วนเซิร์ฟเวอร์ในเครื่องต้องตรงกันทั้งคำสั่ง ไดเรกทอรีทำงาน และสภาพแวดล้อม ค่า timeout และ `protocol` ต้องตรงกันทั้งสองกรณี ชื่อเซิร์ฟเวอร์ไม่จำเป็นต้องตรงกัน แต่ระบบเก็บข้อมูลการลงชื่อเข้าใช้แยกตามชื่อ ดังนั้นเซิร์ฟเวอร์ที่ใช้ OAuth จึงใช้การเชื่อมต่อร่วมกันได้เฉพาะเมื่อชื่อเดียวกัน
- เซิร์ฟเวอร์ในเครื่องแชร์เฉพาะระหว่างไดเรกทอรีบนเครื่องนี้ ไม่ใช่ในเวิร์กสเปซ การแชร์ข้ามโปรเจกต์ต้องมี `cwd` คงที่ เช่น `"~"` หากไม่มี จะรันในโฟลเดอร์ของแต่ละโปรเจกต์ แต่ละโปรเจกต์จึงได้ของตัวเองและ OpenCode บันทึกคำเตือน
- การเชื่อมต่อที่แชร์ไม่มีราก เมื่อเครื่องมือขออินพุต คำขอจะปรากฏในไดเรกทอรีที่เรียก
- การเชื่อมต่อจะปิดทันทีที่ไดเรกทอรีสุดท้ายที่ใช้ปิดหรือยกเลิกการเชื่อมต่อเซิร์ฟเวอร์

## ชื่อ

OpenCode ตั้งชื่อเครื่องมือ `<server>_<tool>` และแทนอักขระอื่นที่ไม่ใช่ตัวอักษร ตัวเลข `_` และ `-` ด้วย `_`

```text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id
```

พรอมต์ MCP กลายเป็นคำสั่งชื่อ `<server>:<prompt>` ด้วยการปรับมาตรฐานเดียวกัน ตัวอย่างเช่น

```text
/context_7:find_docs
```

ข้อความคำสั่งเติมอาร์กิวเมนต์ของพรอมต์ตามลำดับ คั่นด้วยช่องว่างและใส่เครื่องหมายคำพูดครอบค่าที่มีช่องว่าง

```text
/context_7:find_docs react "server components"
```

เลือกชื่อเซิร์ฟเวอร์สั้นที่ยังไม่ซ้ำหลังการปรับมาตรฐาน ภายใต้ Code Mode ค่าเริ่มต้น เครื่องมือจะจัดกลุ่มตามชื่อเซิร์ฟเวอร์ที่ปรับมาตรฐาน

```text
tools.context_7.resolve_library_id(...)
```

## สิทธิ์

Code Mode เป็นค่าเริ่มต้น ตั้ง `codemode` เป็น `false` เมื่อเครื่องมือของเซิร์ฟเวอร์ต้องอยู่ในรายการเครื่องมือเนทีฟของผู้ให้บริการ

```jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "codemode": false,
      },
    },
  },
}
```

ใช้การกระทำสิทธิ์เพื่อซ่อนหรือปฏิเสธเครื่องมือโดยไม่ยกเลิกการเชื่อมต่อเซิร์ฟเวอร์ จับคู่ชื่อ `<server>_<tool>` ที่ปรับมาตรฐาน

```jsonc
{
  "permissions": [
    {
      "action": "context7_*",
      "resource": "*",
      "effect": "deny",
    },
  ],
}
```

## ทรัพยากร

เอเจนต์อ่านทรัพยากร MCP ผ่านเครื่องมือในตัวสองตัว `list_mcp_resources` และ `read_mcp_resource` ควบคุมด้วยการกระทำสิทธิ์เหล่านี้

| การกระทำ | ทรัพยากร |
| --- | --- |
| `opencode_list_mcp_resources` | ชื่อเซิร์ฟเวอร์ |
| `opencode_read_mcp_resource` | `<server>:<uri>` |

ตัวอย่างเช่น อนุญาตทุกการอ่านจากเซิร์ฟเวอร์ `docs`

```jsonc
{
  "permissions": [
    {
      "action": "opencode_read_mcp_resource",
      "resource": "docs:*",
      "effect": "allow",
    },
  ],
}
```

## คำแนะนำของเซิร์ฟเวอร์

เมื่อเซิร์ฟเวอร์คืนคำแนะนำระหว่างการเริ่มต้น OpenCode จะเพิ่มลงในพรอมต์ระบบ

```text
<mcp_instructions>
  <server name="sentry">
    Search for an existing issue before creating a new one.
  </server>
</mcp_instructions>
```

สำหรับเซิร์ฟเวอร์ที่ใช้ Code Mode OpenCode จะเพิ่มบรรทัดที่บอกว่าเอเจนต์หาเครื่องมือของเซิร์ฟเวอร์ได้ที่ใด

คำแนะนำของเซิร์ฟเวอร์จะถูกละเมื่อสิทธิ์ของเอเจนต์ปฏิเสธเครื่องมือทุกตัว เมื่อปฏิเสธ `execute` เครื่องมือของเซิร์ฟเวอร์จะแสดงโดยตรงและคำแนะนำยังคงอยู่โดยไม่มีบรรทัด Code Mode

## คำขออินพุต

เซิร์ฟเวอร์ขออินพุตระหว่างการเรียกผ่าน MCP elicitation ได้ OpenCode แสดงคำขอเป็นแบบฟอร์ม หรือเป็นลิงก์ให้เปิดสำหรับคำขอแบบ URL

```text
sentry is requesting input
```

การปิดแบบฟอร์มจะยกเลิกคำขอ

## บริบท

สำหรับการเรียกที่ทำในนามของเซสชัน OpenCode ส่ง ID เซสชันใน `CallToolRequest.params._meta["ai.opencode/sessionID"]` ใช้กับเครื่องมือโดยตรงและ Code Mode ผ่าน stdio และ Streamable HTTP

```json
{
  "method": "tools/call",
  "params": {
    "name": "lookup",
    "arguments": { "query": "example" },
    "_meta": { "ai.opencode/sessionID": "ses_..." }
  }
}
```

ID นี้เป็นข้อมูลเมตาของคำขอ ไม่ใช่อาร์กิวเมนต์ของเครื่องมือ จึงไม่อยู่ใน schema ที่โมเดลเห็น ใช้ ID นี้เพื่อเชื่อมโยงข้อมูลเท่านั้น โดยไม่ต้องตีความค่าภายใน

| กฎ | ลักษณะการทำงาน |
| --- | --- |
| ตัวตน | ระบุเซสชัน OpenCode ผู้เรียก ไม่ใช่เซสชันการรับส่ง MCP |
| การมีอยู่ | อาจไม่มีสำหรับการเรียกที่ไม่มีบริบทเซสชัน |
| ความปลอดภัย | อย่าใช้เพียงลำพังเพื่อการตรวจสอบสิทธิ์หรือการอนุญาต |
| ความเป็นส่วนตัว | เซิร์ฟเวอร์ระยะไกลได้รับ ID ดิบและอาจบันทึกหรือเก็บไว้ |

## การจัดการ

แสดงรายการเซิร์ฟเวอร์และสถานะการเชื่อมต่อปัจจุบันจากโปรเจกต์ใดก็ได้

```sh
opencode mcp list
```

ใช้ `/mcps` ใน OpenCode เพื่อดู เชื่อมต่อ ยกเลิกการเชื่อมต่อ หรือตรวจสอบสิทธิ์เซิร์ฟเวอร์ ใช้ CLI เพื่อเพิ่มเซิร์ฟเวอร์และจัดการข้อมูลรับรอง OAuth

```sh
opencode mcp add sentry --url https://mcp.sentry.dev/mcp
opencode mcp auth sentry
opencode mcp logout sentry
```

รัน `opencode mcp auth` โดยไม่ระบุชื่อเพื่อเลือกจากเซิร์ฟเวอร์ที่รองรับ OAuth

```sh
opencode mcp auth
```

หากต้องการนำเซิร์ฟเวอร์ออก ให้ลบรายการจากโปรเจกต์หรือการกำหนดค่าส่วนกลางที่เพิ่มไว้

```jsonc
{
  "mcp": {
    "servers": {},
  },
}
```

การยกเลิกการเชื่อมต่อเซิร์ฟเวอร์ใน `/mcps` ไม่เปลี่ยนการกำหนดค่า ให้แก้ไขการกำหนดค่าโดยตรงสำหรับการตั้งค่าไคลเอนต์ OAuth เวลาหมดอายุ ไดเรกทอรีทำงาน หรือเพื่อให้เซิร์ฟเวอร์ไม่เชื่อมต่อ

```jsonc
{
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
        "disabled": true,
      },
    },
  },
}
```
