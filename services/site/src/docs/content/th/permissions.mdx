สิทธิ์กำหนดว่าเอเจนต์ดำเนินการกับทรัพยากรหนึ่ง ๆ ได้หรือไม่

## การกำหนดค่า

ตัวอย่างการตั้งค่าที่ใช้บ่อยคือขออนุมัติก่อนรันคำสั่ง shell อนุญาตคำสั่ง Git สำหรับตรวจสถานะหรือการเปลี่ยนแปลง
และบล็อกการ push เสมอ เพิ่มกฎต่อไปนี้ใน `opencode.jsonc` ตามลำดับ

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

ระบบใช้กฎข้อสุดท้ายที่ตรงเงื่อนไข จึงควรวางข้อยกเว้นไว้หลังกฎทั่วไป

<Callout type="warning">
  V1 ใช้ชื่อฟิลด์และการกระทำต่างกัน ใน V2 ใช้ `permissions`, `shell` และ `subagent` แทน `permission`,
  `bash` และ `task`
</Callout>

## กฎ

แต่ละกฎต้องมีฟิลด์สตริงสามฟิลด์

| ฟิลด์      | ความหมาย                                                                    |
| ---------- | -------------------------------------------------------------------------- |
| `action`   | การกระทำของเครื่องมือที่กฎนี้ควบคุม                                                     |
| `resource` | ค่าที่ใช้ เช่น พาธ คำสั่ง URL คำค้น ID สกิล หรือ ID เอเจนต์ |
| `effect`   | `allow`, `deny` หรือ `ask`                                                   |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| ผล  | ผลลัพธ์                              |
| ------- | ----------------------------------- |
| `allow` | ดำเนินต่อโดยไม่ถาม          |
| `deny`  | บล็อกการดำเนินการ                 |
| `ask`   | รอการตัดสินใจจากไคลเอนต์ |

หากไม่มีกฎใดตรง OpenCode จะใช้ `ask`

## การจับคู่

รูปแบบสำหรับการกระทำและทรัพยากรใช้ไวลด์การ์ดได้ โดยเทียบกับค่าทั้งหมด

| รูปแบบ | ตรงกับ                                      |
| ------- | ------------------------------------------ |
| `*`     | อักขระตั้งแต่ศูนย์ตัวขึ้นไป รวม `/`    |
| `?`     | อักขระหนึ่งตัวพอดี                     |
| อื่น ๆ  | อักขระนั้นโดยตรง                     |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

รูปแบบนี้ต้องตรงกับพาธทั้งพาธหลังปรับให้เป็นรูปแบบมาตรฐาน ระบบจะแปลงแบ็กสแลชเป็นสแลช
และบน Windows จะเทียบโดยไม่แยกตัวพิมพ์เล็กกับตัวพิมพ์ใหญ่

รูปแบบ shell ที่ลงท้ายด้วย ` *` ยังจับคู่คำสั่งที่ไม่มีอาร์กิวเมนต์

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

รูปแบบนี้จับคู่ทั้ง `git status` และ `git status --short`

OpenCode รวมกฎตามลำดับและใช้กฎข้อสุดท้ายที่ตรง ระบบจะโหลดการกำหนดค่าที่มีลำดับความสำคัญต่ำกว่าก่อน
จากนั้นจึงต่อท้ายด้วยกฎส่วนกลางและกฎของเอเจนต์ตามลำดับ

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

การดำเนินการหนึ่งอาจต้องตรวจสิทธิ์ของหลายทรัพยากร เช่น แพตช์ที่แก้หลายไฟล์
หากมีผลเป็น `deny` แม้เพียงรายการเดียว ระบบจะปฏิเสธทั้งการดำเนินการ หากไม่มีแต่พบ `ask` ระบบจะขออนุมัติ
นอกนั้นระบบจะอนุญาต

## การกระทำ

ชื่อการกระทำใน V2 เป็นสตริง ปลั๊กอินจึงกำหนดการกระทำเพิ่มได้ เครื่องมือในตัว
ปัจจุบันใช้การกระทำและทรัพยากรเหล่านี้

| การกระทำ               | ทรัพยากร                                                                    |
| -------------------- | --------------------------------------------------------------------------- |
| `read`               | พาธภายในสัมพัทธ์กับ Location หรือพาธภายนอกสัมบูรณ์ตามรูปแบบมาตรฐาน         |
| `edit`               | พาธเป้าหมายสำหรับ `edit`, `write` และ `patch`                                |
| `glob`               | รูปแบบ glob ที่ขอ                                                      |
| `grep`               | regular expression ที่ใช้ค้นหา ไม่ใช่พาธที่ค้นหา                           |
| `shell`              | สตริงคำสั่งที่ตัวสแกนสร้าง คำสั่งผสมอาจสร้างหลายรายการ      |
| `subagent`           | ID เอเจนต์เป้าหมาย                                                             |
| `skill`              | ID สกิล                                                                    |
| `question`           | `*`                                                                         |
| `webfetch`           | URL ที่ขอ                                                               |
| `websearch`          | คำค้น                                                                |
| `generate_image` | โมเดลสร้างภาพที่เลือกเป็น `providerID/modelID` บวก `#variant` เมื่อตั้งไว้ |
| `external_directory` | ขอบเขตไดเรกทอรีภายนอกตามมาตรฐาน มักลงท้ายด้วย `/*`              |
| `<server>_<tool>`    | `*` สำหรับเครื่องมือ MCP ทั้งชื่อเซิร์ฟเวอร์และชื่อเครื่องมือจะคงตัวอักษร ตัวเลข `_` และ `-` ไว้ ส่วนอักขระอื่นจะแทนด้วย `_` |
| `opencode_list_mcp_resources` | ชื่อเซิร์ฟเวอร์ MCP                                                    |
| `opencode_read_mcp_resource`  | `<server>:<uri>`                                                   |
| `execute`            | `*` การปฏิเสธจะเอา Code Mode ออกและแสดงเครื่องมือโดยตรง ส่วนเครื่องมือที่ซ้อนกันบังคับใช้กฎของตัวเอง |

ชื่อการกระทำของ MCP จะคงขีดกลางไว้ ดังนั้นเครื่องมือจากเซิร์ฟเวอร์ชื่อ `mcp-atlassian` จึงตรงกับ `mcp-atlassian_*` ไม่ใช่
`mcp_atlassian_*`

ตัวอย่างเช่น อนุญาตสกิลหนึ่งและปฏิเสธสกิลอื่นทั้งหมด

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

ปัจจุบัน V2 Core ไม่ใช้ `doom_loop` และ `lsp` เป็นการกระทำในกฎสิทธิ์

## ไดเรกทอรี

หากพาธอยู่นอกทั้ง Location ที่ใช้งานและเวิร์กทรีของโปรเจกต์ที่ไม่ใช่ราก ระบบจะตรวจ `external_directory` ก่อนตรวจตามกฎ `read` หรือ `edit`
นโยบายเริ่มต้นอนุญาต `external_directory` ระบบจึงไม่ขออนุมัติสำหรับพาธภายนอก เว้นแต่คุณจะเพิ่มกฎ
หากต้องการให้ระบบขออนุมัติก่อนเข้าถึงพาธใด ๆ นอกโปรเจกต์ ให้ตั้งค่าดังนี้

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "*", "effect": "ask" },
  ],
}
```

กฎที่แคบกว่าหลังจากนั้นสามารถอนุญาตหรือปฏิเสธไดเรกทอรีที่ระบุได้

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

กฎนี้มีผลกับพาธภายนอกที่ `read`, `edit`, `write` และ `patch` ใช้
สำหรับคำสั่ง shell ระบบจะตรวจไดเรกทอรีทำงานที่อยู่ภายนอกและไดเรกทอรีที่ตัวสแกนหาได้
ก่อนตรวจทรัพยากร `shell`

สำหรับ `external_directory`, `read` และ `edit` ส่วนนำ `~`, `~/`, `$HOME` หรือ
`$HOME/` จะถูกขยายเมื่อโหลดการกำหนดค่า

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

ทรัพยากร shell ยังคงเป็นข้อความคำสั่งดิบ ระบบจะไม่แทนส่วนนำด้วยพาธของโฮมไดเรกทอรี

<Callout type="warning">
  `shell` ใช้สิทธิ์ของผู้ใช้บนโฮสต์ในการเข้าถึงระบบไฟล์ โปรเซส และเครือข่าย ระบบอาจระบุไดเรกทอรีจากข้อความคำสั่งได้ไม่ครบ
  จึงควรระบุรายการคำสั่ง shell ที่อนุญาตเท่าที่จำเป็น แทนการใช้รูปแบบที่พยายามดักจับคำสั่งอันตรายทุกแบบ
</Callout>

พาธสัมพัทธ์ที่ใช้แก้ไขไฟล์อาจชี้ออกไปนอก Location ที่ใช้งาน แต่ยังอยู่ภายในเวิร์กทรีของโปรเจกต์ได้ ระบบจะแปลงพาธภายนอกที่ระบุชัดเจนเป็นพาธมาตรฐานก่อนจับคู่
จึงควรอนุญาตเฉพาะภายในไดเรกทอรีที่เชื่อถือได้

## ตัวสแกน

OpenCode ใช้ตัวสแกนในตัวเพื่อตรวจสิทธิ์ของคำสั่ง Bash, Zsh, POSIX `sh` และ PowerShell บางคำสั่งวิเคราะห์อย่างปลอดภัยไม่ได้
เช่น คำสั่งที่มีไวยากรณ์ผิดหรือประเมินผลแบบไดนามิกด้วย `eval` หากมีกฎ deny สำหรับ `shell` ที่ใช้บังคับ ตัวสแกนจะแจ้งข้อผิดพลาด
เพราะตรวจคำสั่งย่อยตามกฎ deny ไม่ได้ หากไม่มีกฎดังกล่าว ต้องขออนุมัติสองรายการ ได้แก่ คำสั่งทั้งชุดในฐานะทรัพยากร
`shell` หนึ่งรายการ และ `external_directory` `*` รายการที่สองอนุมัติได้โดยผู้ใช้หรือกฎที่อนุญาตทุกไดเรกทอรีเท่านั้น
ระบบจะไม่บันทึกการอนุมัติทั้งสองรายการเป็นรูปแบบสำหรับใช้ซ้ำ

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [
    {
      "permissions": [
        { "action": "shell", "resource": "git status *", "effect": "allow" },
        { "action": "shell", "resource": "rm *", "effect": "deny" },
      ],
    },
  ],
}
```

ระบบใช้กฎสิทธิ์ รูปแบบการอนุมัติที่บันทึกไว้ และการระบุไดเรกทอรีเท่าที่ทำได้กับทุกคำสั่งย่อยที่แยกได้
และไดเรกทอรีปลายทางของ `cd` ไม่มีโหมดอนุมัติเพิ่มเติมหรือข้อจำกัดแบบเหมารวมสำหรับไดเรกทอรีที่ระบุไม่ได้

## ค่าเริ่มต้น

ทุกเอเจนต์ รวมถึงเอเจนต์กำหนดเอง เริ่มด้วยนโยบายฐานตามลำดับนี้

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

เอเจนต์ที่มาพร้อมระบบเพิ่มนโยบายต่อไปนี้ต่อท้าย

| เอเจนต์        | นโยบายเพิ่มเติม                                                              |
| ------------ | ------------------------------------------------------------------------------ |
| `build`      | อนุญาตคำถาม                                                               |
| `plan`       | อนุญาตคำถาม ปฏิเสธการแก้ไขยกเว้นไฟล์ใต้ `~/.opencode/plan`           |
| `general`    | ปฏิเสธคำถามและการเปิดซับเอเจนต์                                       |
| `explore`    | ปฏิเสธทุกอย่างยกเว้น shell, การอ่าน, glob, grep, การดึงข้อมูลจากเว็บ, การค้นเว็บ และการเข้าถึงไดเรกทอรีภายนอก โดยจะขออนุมัติก่อนอ่าน `.env` |
| `title`      | ปฏิเสธทุกการกระทำ                                                              |
| `summary`    | ปฏิเสธทุกการกระทำ                                                              |
| `compaction` | คงนโยบายฐาน                                                          |

เนื่องจากกฎเริ่มต้นไม่ขออนุมัติสำหรับ `external_directory` ระบบจึงอ่านและแก้ไขไฟล์นอก
Location และเวิร์กทรีได้โดยไม่ถาม เพิ่มกฎ `ask` หรือ `deny` สำหรับ
`external_directory` ตามตัวอย่างใน
[ไดเรกทอรี](#directories) เพื่อให้ระบบถามก่อนหรือบล็อกการเข้าถึงภายนอก
กฎส่วนกลางและกฎของเอเจนต์ที่ต่อท้ายจะแทนที่ค่าเริ่มต้นเหล่านี้

## เอเจนต์

วางกฎที่ใช้ร่วมกันที่ระดับบนสุดและกฎที่แคบกว่าใต้
`agents.<id>.permissions`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

ระบบเพิ่มกฎของเอเจนต์ต่อท้ายกฎส่วนกลาง ไม่ได้แทนที่อาร์เรย์ส่วนกลาง
ซับเอเจนต์ที่กำหนดเองใช้สิทธิ์ของตัวเอง ไม่ได้ใช้สิทธิ์บางส่วนจากเอเจนต์แม่

## การอนุมัติ

เมื่อผลการตรวจสิทธิ์เป็น `ask` ไคลเอนต์เลือกตอบได้ดังนี้

| ตัวเลือก       | การตอบกลับ      | ผลลัพธ์                                                               |
| ------------ | ---------- | -------------------------------------------------------------------- |
| อนุญาตครั้งเดียว   | `once`     | อนุมัติเฉพาะคำขอที่รอดำเนินการ                                     |
| อนุญาตเสมอ | `always`   | อนุมัติและบันทึกรูปแบบที่เครื่องมือเสนอสำหรับโปรเจกต์     |
| ปฏิเสธ      | `reject`   | ปฏิเสธคำขอนั้นและคำขอสิทธิ์ที่รอดำเนินการอื่นทั้งหมดในเซสชันนั้น |

ตัวอย่างเช่น การเลือก **Allow always** สำหรับ `git status --short` อาจบันทึก
คำนำหน้าคำสั่ง shell ที่ครอบคลุมคำสั่ง `git status` ภายหลัง

```text
shell: git status * → allow
```

การอนุมัติที่บันทึกไว้เป็นกฎ `allow` ถาวรระดับโปรเจกต์ และไม่เคยแทนที่
`deny` ที่กำหนดค่าไว้ เครื่องมือเลือกรูปแบบที่บันทึก: บางตัวเสนอ `*`
shell เสนอคำนำหน้าคำสั่ง การดึงเว็บเสนอไซต์ของ URL (เช่น
`https://opencode.ai/*`) และสกิลกับซับเอเจนต์เสนอ ID ของตัวเอง
ตรวจสอบการอนุมัติที่กว้างและนำออกเมื่อไม่จำเป็น

ไคลเอนต์อาจแนบความคิดเห็นเมื่อปฏิเสธ ไคลเอนต์ที่ไม่โต้ตอบต้องตัดสินใจ
วิธีจัดการคำขออนุมัติ กฎ `deny` ที่กำหนดค่าไว้ยังถูกบังคับใช้เสมอ

## นโยบาย

[นโยบาย](/policies) สามารถบังคับปฏิเสธการเข้าถึงได้หลังจากระบบตรวจตามกฎและการอนุมัติที่บันทึกไว้แล้ว
นโยบายเปลี่ยน `allow` หรือ `ask` เป็น `deny` ได้ แต่ไม่สามารถให้สิทธิ์เพิ่ม

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

นโยบายส่วนกลางและที่จัดการผ่าน Console แทนที่การกำหนดค่าโปรเจกต์ องค์กรจึง
บล็อกคำสั่งที่รีโพจะอนุญาตได้
