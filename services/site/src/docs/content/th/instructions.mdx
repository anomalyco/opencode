เพิ่มไฟล์ `AGENTS.md` เพื่อมอบคำแนะนำโปรเจกต์ถาวรให้ OpenCode ใช้สำหรับคำสั่งบิลด์ บันทึกสถาปัตยกรรม ข้อตกลงโค้ด และข้อกำหนดการตรวจสอบ

```md title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

คอมมิตไฟล์คำแนะนำของโปรเจกต์เพื่อให้ทุกคนที่ทำงานในรีโพได้รับคำแนะนำเดียวกัน

## ขอบเขต

วาง `AGENTS.md` ในไดเรกทอรีที่คำแนะนำควรมีผล OpenCode จะโหลดไฟล์ส่วนกลางตามด้วย `AGENTS.md` ทุกไฟล์จากไดเรกทอรีเวิร์กสเปซปัจจุบันขึ้นไปยังไดเรกทอรีบ้าน สำหรับเวิร์กสเปซนอกไดเรกทอรีบ้าน จะหยุดที่รากโปรเจกต์

```text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace
```

ในตัวอย่างนี้ ไฟล์ทั้งสี่ถูกโหลด รวมกันตามลำดับนี้

```text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md
```

เก็บคำแนะนำที่ใช้ทุกที่ไว้ในไฟล์ส่วนกลาง วางคำแนะนำระดับรีโพไว้ที่รากโปรเจกต์ และคำแนะนำที่เฉพาะเจาะจงกว่าไว้ใกล้โค้ดที่ครอบคลุม OpenCode รวมไฟล์เข้าด้วยกันและไม่แก้ไขความขัดแย้งระหว่างไฟล์

หากเวิร์กสเปซอยู่นอกรากโปรเจกต์ จะโหลดเฉพาะไฟล์ส่วนกลาง ตั้ง `OPENCODE_DISABLE_PROJECT_CONFIG=1` เพื่อข้ามการค้นหา `AGENTS.md` ของโปรเจกต์โดยไม่ปิดไฟล์ส่วนกลาง

### การใช้ CLAUDE.md แทน

ในไดเรกทอรีใดที่ไม่มี `AGENTS.md` OpenCode จะอ่าน `CLAUDE.md` แทน หากไม่มี
`~/.config/opencode/AGENTS.md` ส่วนกลาง จะอ่าน `~/.claude/CLAUDE.md` ถ้ามีทั้งสองไฟล์ในไดเรกทอรีเดียวกัน ระบบจะเลือก `AGENTS.md` ก่อน `CLAUDE.md` เสมอ
ถ้าใช้ symlink เชื่อมทั้งสองไฟล์ ระบบจึงโหลดเพียงครั้งเดียว

ตั้ง `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` เพื่อข้าม `CLAUDE.md` ทั้งหมด หรือ `OPENCODE_DISABLE_CLAUDE_CODE=1` เพื่อข้าม
สกิลใน `.claude` ด้วย เซิร์ฟเวอร์อ่านทั้งสองค่าเมื่อเริ่มทำงาน สำหรับบริการเบื้องหลัง ให้บันทึกค่าถาวรด้วย
`opencode service set env` แล้วรัน `opencode service restart`

## การค้นพบ

ไฟล์คำแนะนำใต้เวิร์กสเปซจะถูกค้นพบเมื่อเอเจนต์สำรวจโปรเจกต์ การอ่านไฟล์หรือการแสดงรายการไดเรกทอรีจะโหลดไฟล์ `AGENTS.md` ทั้งหมดระหว่างเป้าหมายนั้นกับเวิร์กสเปซ

```text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

ไฟล์ที่ซ้อนกันจะถูกโหลดจากใกล้สุดก่อนและตัดรายการซ้ำ ตราบใดที่รายการคำแนะนำยังอยู่ในประวัติที่โมเดลมองเห็น การอ่านพื้นที่เดิมอีกครั้งมักไม่เพิ่มไฟล์เหล่านั้นซ้ำ หากการบีบอัดหรือการย้อนกลับลบรายการนั้นออก การอ่านภายหลังอาจโหลดไฟล์อีกครั้ง

ระบบไม่ตรวจจับการแก้ไขไฟล์ที่ซ้อนกันโดยอัตโนมัติหลังโหลดแล้ว ให้เริ่มเซสชันใหม่เมื่อข้อความที่อัปเดตต้องมีผลทันที

## ลำดับ

พรอมต์ระบบของเอเจนต์หรือผู้ให้บริการที่เลือกจะถูกส่งก่อน จากนั้น OpenCode จะประกอบคำแนะนำเริ่มต้นตามลำดับนี้

```text
1. Agent or provider system prompt
2. Code Mode tool guidance, when enabled
3. MCP server, reference, and skill guidance
4. Global and project AGENTS.md files, then configured instructions
5. Built-in date and environment context
6. Session-specific instruction entries supplied through the API
```

แหล่งเหล่านี้ถูกนำมารวมกัน ไม่ใช่ใช้แทนกัน ไฟล์ `AGENTS.md` ที่ซ้อนกันซึ่งค้นพบภายหลังจะถูกเพิ่มในประวัติเซสชันตามลำดับการค้นพบ

## การอัปเดต

ระหว่างที่เซสชันทำงาน คุณอัปเดตคำแนะนำได้โดยแก้ไข `AGENTS.md` ส่วนกลางหรือไฟล์ที่พบจากการค้นหาไล่ขึ้นไปตามไดเรกทอรี

```bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md
```

ก่อนคำขอถึงโมเดลครั้งถัดไป OpenCode จะตรวจจับการเปลี่ยนแปลงและเพิ่มการอัปเดตคำแนะนำก่อนส่งอินพุตที่รอดำเนินการ

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- การลบ `AGENTS.md` โดยรอบทั้งหมดจะบอกเซสชันว่าคำแนะนำโดยรอบเดิมไม่มีผลอีกต่อไป
- หากอ่านไฟล์ไม่ได้ชั่วคราว ระบบจะเก็บคำแนะนำล่าสุดไว้ ไม่ถือว่าไฟล์ถูกลบ
- การย้ายเซสชันจะเก็บสถานะคำแนะนำไว้ คำแนะนำที่ปลายทางจึงถูกนำเสนอเป็นการอัปเดต
- การคอมมิตการย้อนกลับของเซสชันจะล้างสถานะคำแนะนำและโหลดคำแนะนำใหม่ก่อนพรอมต์ถัดไป

ค่าของคำแนะนำยังคงเป็นข้อมูลสงวนสิทธิ์ ไคลเอนต์เห็นได้ว่าแหล่งใดเปลี่ยน แต่ไม่เห็นเนื้อหา

## การกำหนดค่า

ใช้อาร์เรย์ `instructions` เพื่อเพิ่มไฟล์ รูปแบบ glob หรือ URL แบบ HTTP(S) ควบคู่กับไฟล์ `AGENTS.md` ที่พบ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines/*.md",
    "~/rules/opencode.md",
    "https://example.com/instructions.md",
  ],
}
```

คำแนะนำที่กำหนดค่าไว้จะโหลดหลังไฟล์ `AGENTS.md` ตามลำดับที่ระบุ รายการจากเอกสารการกำหนดค่าทุกฉบับจะถูกรวมกัน

| รายการ | วิธีค้นหา |
| ----------------------- | -------------------------------------------------------------------- |
| พาธสัมพัทธ์หรือ glob   | ค้นหาในแต่ละไดเรกทอรีจากเวิร์กสเปซขึ้นไปถึงรากโปรเจกต์ |
| พาธ `~/` | อ้างอิงจากโฮมไดเรกทอรีของคุณ |
| พาธแบบสัมบูรณ์           | ใช้ตามที่เขียน ชื่อไฟล์อาจเป็น glob                         |
| `http://` หรือ `https://` | ดึงเมื่อโหลดการกำหนดค่า โดยมีเวลาหมดอายุห้าวินาที                |

- ไฟล์ในเครื่องอัปเดตเหมือน `AGENTS.md` เมื่อเปลี่ยน ไฟล์ใหม่ที่ตรงกับ glob จะโหลดเมื่อการกำหนดค่าเปลี่ยนครั้งถัดไป
- ไฟล์ที่หายไปจะถูกข้าม URL ที่ดึงไม่ได้จะถูกข้าม หรือเก็บเนื้อหาที่ดึงล่าสุดไว้
- เมื่อใช้ `OPENCODE_DISABLE_PROJECT_CONFIG=1` หรือเมื่อเวิร์กสเปซอยู่นอกโปรเจกต์ ระบบจะใช้ไดเรกทอรีกำหนดค่าส่วนกลางเป็นฐานสำหรับรายการที่ระบุด้วยพาธสัมพัทธ์

เวิร์กสเปซของ [OpenCode Console](/console) ที่เชื่อมต่ออยู่ยังแชร์คำแนะนำได้

ดู[การกำหนดค่า](/config)สำหรับตำแหน่งการกำหนดค่าและลำดับความสำคัญ
