การลงชื่อเข้าใช้ครั้งเดียว (SSO) ให้สมาชิกเวิร์กสเปซลงชื่อเข้าใช้ผ่านผู้ให้บริการระบุตัวตนของบริษัทคุณ เจ้าของตั้งค่าได้ใน **Settings › Security** และทุกเวิร์กสเปซใช้ SSO ได้

| โปรโตคอล       | ผู้ให้บริการ                                                                              |
| -------------- | -------------------------------------------------------------------------------------- |
| OpenID Connect | Google Workspace, Microsoft Entra ID, Okta, Auth0, Ping Identity หรือผู้ให้บริการ OIDC รายใดก็ได้ |
| SAML 2.0       | Google Workspace, Microsoft Entra ID, Okta หรือผู้ให้บริการ SAML รายใดก็ได้                       |

แต่ละเวิร์กสเปซมีการเชื่อมต่อ SSO หนึ่งรายการ

## ตั้งค่า OIDC

1. เปิด **Settings › Security** คลิก **Configure SSO** แล้วเลือก **OpenID Connect** และผู้ให้บริการของคุณ
2. สร้างแอปในผู้ให้บริการของคุณตามขั้นตอนที่แสดง ด้วยสโคป `openid`, `email` และ `profile`
3. ป้อน **Issuer URL** หรือ tenant หรือโดเมนของคุณ พร้อม **Client ID**, **Client Secret** และ
   **Display Name** แล้วคลิก **Save**
4. คัดลอก **Callback URL** จากการเชื่อมต่อไปยัง redirect URI ที่อนุญาตในผู้ให้บริการของคุณ

```text
https://opencode.ai/console/auth/sso/ssoconn_.../callback
```

Console จะตรวจสอบว่าเข้าถึง issuer ได้เมื่อคุณบันทึก SSO จะทำงานทันทีที่บันทึกการเชื่อมต่อ

## ตั้งค่า SAML

1. เปิด **Settings › Security** คลิก **Configure SSO** แล้วเลือก **SAML 2.0** และผู้ให้บริการของคุณ
2. คัดลอก **ACS URL** และ **SP Entity ID** ไปยังผู้ให้บริการของคุณ ผู้ให้บริการแบบกำหนดเองสามารถใช้ **SP Metadata URL** หรือ
   ดาวน์โหลด XML แทนได้
3. เพิ่มข้อมูลเมตาของผู้ให้บริการโดยใช้ URL อัปโหลด XML หรือวาง คุณยังป้อน **IdP Entity ID**, **IdP SSO
   URL** และ **IdP Certificate** ด้วยตัวเองได้
4. ตรวจสอบรายละเอียดแล้วคลิก **Activate SSO**

```text
ACS URL:       https://opencode.ai/console/auth/sso/ssoconn_.../callback
SP Entity ID:  https://opencode.ai/console/auth/sso/ssoconn_.../metadata
```

ผู้ให้บริการของคุณต้องลงนามใน response หรือ assertion และส่งอีเมลของผู้ใช้เป็นแอตทริบิวต์ `email` หรือเป็น
NameID

## ยืนยันโดเมนอีเมล

ผู้ที่ลงชื่อเข้าใช้ [Console](https://opencode.ai/console) ด้วยอีเมลบนโดเมนที่ยืนยันแล้วจะถูกส่งไปยัง
ผู้ให้บริการระบุตัวตนของคุณ เมื่อ SSO ทำงานแล้ว ให้คลิก **Add domain** ภายใต้ **Email domains** ป้อนโดเมนของคุณ แล้วเผยแพร่
ระเบียน TXT ที่แสดง

```text
Name:   _opencode-console-challenge.example.com
Type:   TXT
Value:  oc-verify=...
```

คลิก **Verify Domain** เมื่อเผยแพร่ระเบียนแล้ว การเปลี่ยนแปลง DNS อาจใช้เวลาสักพักจึงจะแพร่กระจาย แต่ละโดเมน
เป็นของเวิร์กสเปซเดียวเท่านั้น

## การบังคับใช้ SSO

เมื่อเวิร์กสเปซมี SSO แล้ว ผู้ดูแลและสมาชิกต้องลงชื่อเข้าใช้ผ่าน SSO เพื่อเปิดเวิร์กสเปซ และ Console จะเปลี่ยนเส้นทาง
ให้อัตโนมัติ การเชื่อมต่อ OpenCode ด้วย `/connect` ก็เป็นไปตามกฎเดียวกัน

เจ้าของยังลงชื่อเข้าใช้โดยไม่ผ่าน SSO ได้ จึงยังเข้าถึงการตั้งค่าเวิร์กสเปซได้แม้กำหนดค่าผู้ให้บริการไม่ถูกต้อง

## การเป็นสมาชิกอัตโนมัติ

ผู้คนบนโดเมนที่ยืนยันแล้วจะเข้าร่วมเวิร์กสเปซในบทบาท **Member** เมื่อลงชื่อเข้าใช้ผ่าน SSO ครั้งแรก
พวกเขาจะไม่ถูกเพิ่มโดยอัตโนมัติเมื่อ

- มีคำเชิญที่รอดำเนินการ ระบบจะใช้คำเชิญนั้นแทน
- เวิร์กสเปซใช้[การซิงค์ไดเรกทอรี](/console/scim) ซึ่งเป็นตัวกำหนดสมาชิกภาพ
- เวิร์กสเปซมีการสมัครสมาชิก [Go](/console/go)

คำเชิญไปยังเวิร์กสเปซที่ใช้ SSO จะพาผู้ได้รับเชิญไปยังผู้ให้บริการระบุตัวตนของคุณเมื่อเปิดลิงก์

## บัญชีที่มีอยู่

หากมีบัญชี Console ด้วยอีเมลเดียวกันอยู่แล้ว พวกเขาจะลงชื่อเข้าใช้อีกครั้งระหว่างขั้นตอน SSO และยืนยัน
ด้วย **Link account** คำเชิญไม่สามารถข้ามการยืนยันนี้ได้ บัญชีที่จัดเตรียมผ่าน SCIM บนโดเมนเวิร์กสเปซที่
ยืนยันแล้วยังเชื่อมโยงอัตโนมัติได้

## แก้ไขหรือลบ

คลิก **Edit** ที่การเชื่อมต่อเพื่อเปลี่ยนรายละเอียด เว้นช่อง secret หรือ certificate ว่างไว้เพื่อใช้ค่าเดิม
หากต้องการสลับระหว่าง OIDC และ SAML ให้ลบการเชื่อมต่อแล้วสร้างใหม่

ลบการเชื่อมต่อจาก **⋯ › Delete...** สมาชิกจะกลับไปใช้วิธีลงชื่อเข้าใช้อื่น และการซิงค์ไดเรกทอรีจะหยุด
และระบบจะเพิกถอนโทเคนที่ใช้ซิงค์ แต่ยังคงโดเมนอีเมลไว้
