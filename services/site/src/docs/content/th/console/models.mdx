OpenCode Console มีรายการโมเดลที่ทดสอบและตรวจสอบโดยทีม OpenCode ลงชื่อเข้าใช้ เพิ่มเครดิต และรับ
คีย์ API เพื่อใช้กับ OpenCode หรือเอเจนต์เขียนโค้ดอื่น

Console ทำงานเหมือนผู้ให้บริการรายอื่นใน OpenCode เป็นบริการ**ทางเลือกโดยสมบูรณ์** และคุณใช้ผู้ให้บริการรายอื่น
แทนได้ หากต้องการการสมัครสมาชิกที่มีการใช้งานรวมอยู่ ดู [OpenCode Go](/console/go)

## วิธีการทำงาน

1. ลงชื่อเข้าใช้ [console](https://opencode.ai/console) เพิ่มรายละเอียดการเรียกเก็บเงินและเครดิต แล้วคัดลอกคีย์ API
2. รัน `/connect` ใน TUI เลือกผู้ให้บริการแบบจ่ายตามการใช้งานของ OpenCode แล้ววางคีย์ API

   ```text
   /connect
   ```

3. รัน `/models` เพื่อดูโมเดลที่ใช้ได้และเลือกหนึ่งตัว

   ```text
   /models
   ```

คุณถูกเรียกเก็บเงินต่อคำขอ และเพิ่มเครดิตให้บัญชีได้

## เอนด์พอยต์

คุณยังเข้าถึงโมเดลโดยตรงผ่านเอนด์พอยต์ API ต่อไปนี้ได้ โมเดลแชตระดับฟรีต้องใช้ OpenCode
ให้ใช้โมเดลแบบเสียค่าใช้จ่ายหรือ [Go](/console/go) จากไคลเอนต์อื่น

แต่ละโมเดลแสดงพร้อม API เนทีฟ แต่โมเดลข้อความทุกตัวยังใช้ผ่าน API อื่นได้ ซึ่ง Console

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "opencode/gpt-6.1-sol",
}
```

### รายการโมเดล

ดึงรายการโมเดลที่ใช้ได้ทั้งหมดและข้อมูลเมตาจากเอนด์พอยต์ models

```bash
curl https://opencode.ai/inference/v1/models
```

ดู[API รายการโมเดล](/console/api/models)สำหรับทุกฟิลด์ในการตอบกลับ และสำหรับรายการ Console ที่
รวมผู้ให้บริการที่เวิร์กสเปซของคุณเชื่อมต่อด้วย

### Jev

Jev เป็นโมเดล System One จาก TypeSafe AI สำหรับการตัดสินใจแบบมีโครงสร้างอย่างรวดเร็ว แทนที่จะสร้างข้อความ โมเดลจะประเมิน `state` ตามคำถามที่ระบุชนิดไว้ แล้วคืนค่าและความน่าจะเป็นที่โค้ดของคุณใช้ได้โดยตรง รองรับคำถามแบบใช่/ไม่ใช่ (`noul`) แบบมีตัวเลือก (`choice`) และแบบให้คะแนนตามเกณฑ์ (`score`)

ใช้คีย์ API ของ OpenCode Console กับเอนด์พอยต์ `https://opencode.ai/inference/systemone/v1/systemone` ตัวอย่างนี้ตรวจว่าคำขอรับการสนับสนุนเร่งด่วนหรือไม่

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

คุณถามหลายคำถามในคำขอเดียวได้ Jev จะประเมินพร้อมกันและคืนแต่ละคำตอบภายใต้ ID คำถามที่ตรงกัน

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
```

### โมเดลสร้างภาพ

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` และ `grok-imagine-image-2.0` สร้างและแก้ไขภาพ ไม่ใช่โมเดลแชต จึงไม่ปรากฏใน `/models` หรือเอนด์พอยต์ models
และ `opencode/<model-id>` ไม่เลือกโมเดลเหล่านี้ เรียกผ่าน API เนทีฟด้วยคีย์ของ Console หรือให้เครื่องมือ
[`generate_image`](/tools#image-generate) ของ OpenCode ใช้โมเดลสร้างภาพโดยตั้ง
`experimental.image_generate.model` เช่น `opencode/gpt-image-2.5-sunburst`

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google รับ `contents` และ `generationConfig` แบบเนทีฟ และ xAI รับตัวเลือกเนทีฟเช่น `resolution` และ
`quality` OpenAI Images และ xAI Images ยังรับการแก้ไขภาพที่ `/images/edits`

### โมเดล embedding

`text-embedding-3-small`, `qwen3-embedding-8b` และโมเดล embedding อื่นๆ ในตารางด้านบนเปลี่ยนข้อความ
เป็นเวกเตอร์ OpenCode ไม่ได้ใช้โมเดลเหล่านี้สำหรับแชต จึงไม่ปรากฏใน `/models` และระดับฟรีไม่รวมโมเดลเหล่านี้
[Go](/console/go#embedding-models) รวมบางตัวไว้ เรียกผ่าน Embeddings API ของ OpenAI ด้วยคีย์ของ Console

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` รับสตริงหรืออาร์เรย์ของสตริง `data` คืนหนึ่งเวกเตอร์ต่ออินพุตตามลำดับเดิม
- `dimensions` ย่อเวกเตอร์ในโมเดลที่รองรับ เช่น `text-embedding-3-small`
- `encoding_format: "base64"` คืนเวกเตอร์ที่เข้ารหัสเป็น base64 แทนการคืนเป็นตัวเลขทศนิยม
- แต่ละอินพุตต้องพอดีกับหน้าต่างบริบทของโมเดล
- การตอบกลับรายงาน `usage.cost` เหมือนคำขอ inference อื่นๆ ดู[ค่าใช้จ่าย](/console/api/inference#cost)

เวกเตอร์จากต่างโมเดลเปรียบเทียบกันไม่ได้ จึงควร embed เอกสารและคำค้นด้วยโมเดลเดียวกัน
[ผู้ให้บริการที่เชื่อมต่อ](/console/api/providers#endpoints)ให้บริการโมเดล embedding ของตัวเองที่ `/embeddings`

## ที่มา

มีโมเดลให้เลือกมากมาย แต่มีเพียงไม่กี่ตัวที่ทำงานได้ดีในฐานะเอเจนต์เขียนโค้ด ผู้ให้บริการยังแตกต่างกันในด้าน
การกำหนดค่า ประสิทธิภาพ และคุณภาพ โมเดลที่เข้าถึงผ่านเกตเวย์อย่าง OpenRouter จึงอาจทำงานต่างออกไป

<Callout type="tip">เราทดสอบโมเดลและผู้ให้บริการกลุ่มคัดสรรที่ทำงานร่วมกับ OpenCode ได้ดี</Callout>

เพื่อสร้างแคตตาล็อกนี้ เรา

1. ทดสอบโมเดลกลุ่มคัดสรรและพูดคุยกับทีมของโมเดลเหล่านั้นเกี่ยวกับวิธีรันที่ดีที่สุด
2. ทำงานร่วมกับผู้ให้บริการเพื่อให้แน่ใจว่าโมเดลถูกให้บริการอย่างถูกต้อง
3. ทำเบนช์มาร์กทุกการจับคู่โมเดล/ผู้ให้บริการ เพื่อสร้างรายการที่เราแนะนำได้อย่างมั่นใจ

Console คือเกตเวย์ AI ที่ให้คุณเข้าถึงโมเดลเหล่านี้

## เป้าหมาย

เราสร้าง Console เพื่อ

1. **ทำเบนช์มาร์ก**โมเดลและผู้ให้บริการที่ดีที่สุดสำหรับเอเจนต์เขียนโค้ด
2. มอบตัวเลือก**คุณภาพสูงสุด**โดยไม่ลดประสิทธิภาพหรือเปลี่ยนเส้นทางไปยังผู้ให้บริการที่ถูกกว่า
3. ส่งต่อ**ราคาที่ลดลง**ให้คุณโดยคิดตามต้นทุน และบวกเพิ่มเพียงค่าธรรมเนียมการชำระเงิน
4. **ไม่ผูกมัด**: ใช้ Console กับเอเจนต์เขียนโค้ดใดก็ได้ หรือใช้ผู้ให้บริการรายอื่นกับ OpenCode
