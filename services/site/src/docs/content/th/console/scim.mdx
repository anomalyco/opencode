การซิงค์ไดเรกทอรี (SCIM 2.0) จะเพิ่มผู้ใช้เข้าเวิร์กสเปซเมื่อคุณมอบหมายสิทธิ์ให้ผ่านผู้ให้บริการระบุตัวตน และจะถอนสิทธิ์เข้าถึงเมื่อคุณยกเลิกการมอบหมาย ส่วนบทบาทยังจัดการใน Console

```text
https://opencode.ai/console/scim/v2
```

## ก่อนเริ่ม

- ตั้งค่า [SSO](/console/sso) สำหรับเวิร์กสเปซ
- [ยืนยัน](/console/sso#verify-email-domains)โดเมนอีเมลทุกโดเมนที่ผู้คนของคุณใช้ลงชื่อเข้าใช้ การซิงค์ไดเรกทอรีจะเพิ่ม
  เฉพาะผู้คนบนโดเมนที่ยืนยันแล้วเท่านั้น ให้เชิญคนอื่นจาก[สมาชิก](/console/members)

## สร้างโทเคน

เฉพาะเจ้าของเวิร์กสเปซเท่านั้นที่ตั้งค่าการซิงค์ไดเรกทอรีหรือสร้างและเพิกถอนโทเคนได้

1. เปิด **Settings › Security** แล้วคลิก **Set up** ภายใต้ **Directory sync**
2. คัดลอก **SCIM base URL** และโทเคน ระบบจะแสดงโทเคนเพียงครั้งเดียว ให้เก็บไว้ในระบบจัดการข้อมูลลับ

ผู้ให้บริการระบุตัวตนของคุณจะส่งโทเคนไปกับทุกคำขอ

```text
Authorization: Bearer <token>
```

## เชื่อมต่อผู้ให้บริการระบุตัวตนของคุณ

### Okta

1. เพิ่มแอป **SCIM 2.0 Test App (Header Auth)**
2. ตั้งค่า base URL แล้วป้อน `Bearer ` ตามด้วยโทเคนใน **API Token**
3. เปิด **Create Users**, **Update User Attributes** และ **Deactivate Users** เว้น **Import Groups** และการซิงค์
   รหัสผ่านไว้ปิด

### Microsoft Entra ID

1. ในแอปองค์กรของคุณ เปิด **Provisioning** แล้วตั้งโหมดเป็น **Automatic**
2. ป้อน base URL ในช่อง **Tenant URL** และโทเคนในช่อง **Secret Token**
3. กำหนดผู้ใช้และกลุ่ม แล้วเริ่มการจัดเตรียม

### ผู้ให้บริการรายอื่น

ใช้แอป SCIM 2.0 ที่ยืนยันตัวตนด้วยโทเคนในเฮดเดอร์ แล้วตั้งค่าแอปให้ส่งคำขอไปยัง base URL โดย Console รองรับเอนด์พอยต์ `/Users` และ
`/Groups`

กำหนดคนทดสอบหนึ่งคนก่อน **Directory sync** จะแสดง **Connected to your identity provider** หลัง
คำขอแรก

## สิ่งที่ซิงค์

| ในผู้ให้บริการระบุตัวตนของคุณ | ใน Console                                                                    |
| ------------------------- | --------------------------------------------------------------------------------- |
| กำหนดบุคคล           | เพิ่มเป็น **Member** สมาชิกที่มีอยู่จะคงบทบาทเดิม                            |
| อัปเดตชื่อ             | อัปเดตโปรไฟล์                                                                  |
| ยกเลิกการกำหนดหรือปิดใช้งาน    | ระงับการเข้าถึงและแสดงเป็น **Deactivated** คีย์ API ที่พวกเขาสร้างจะถูกเพิกถอน |
| กำหนดใหม่                  | คืนการเข้าถึง คีย์ที่เพิกถอนแล้วจะยังคงถูกเพิกถอน                                       |
| ลบ                    | นำออกจากเวิร์กสเปซ บัญชีและเวิร์กสเปซอื่นไม่ได้รับผลกระทบ    |

- บทบาทและอีเมลไม่ถูกเปลี่ยนโดยการซิงค์ไดเรกทอรี
- เจ้าของคนสุดท้ายไม่สามารถถูกปิดใช้งานหรือลบได้
- เวิร์กสเปซที่มีการสมัครสมาชิก [Go](/console/go) ไม่สามารถเพิ่มสมาชิกผ่านการซิงค์ไดเรกทอรีได้

## กลุ่ม

พุชกลุ่มเพื่อติดแท็กให้สมาชิก เช่น ด้วย **Push Groups** ของ Okta หรือการกำหนดกลุ่มของ Entra กำหนดผู้คน
ก่อนพุชกลุ่มของพวกเขา

```text
Platform Admins  →  platform-admins
```

แต่ละกลุ่มจะติดแท็กให้สมาชิกด้วยแท็กที่ตั้งชื่อตามกลุ่ม ภายใต้ **Settings › Security › Group tags** คุณ
เปลี่ยนชื่อแท็ก ชี้หลายกลุ่มไปที่แท็กเดียว หรือหยุดติดแท็กให้กลุ่มได้ การออกจากกลุ่มจะนำแท็กนั้นออก

## เปลี่ยนโทเคน

1. คลิก **New token** แล้วติดตั้งในผู้ให้บริการระบุตัวตนของคุณ
2. รอจน Console แสดงเวลาที่ใช้โทเคนใหม่ล่าสุด
3. เพิกถอนโทเคนเดิม

การเพิกถอนโทเคนจะหยุดการอัปเดตครั้งต่อ ๆ ไปโดยไม่กระทบสมาชิกปัจจุบัน หากลบการเชื่อมต่อ SSO ระบบจะเพิกถอนโทเคนทั้งหมด

## SSO และการซิงค์ไดเรกทอรี

เมื่อเวิร์กสเปซออกโทเคนแล้ว SSO จะไม่[เพิ่มสมาชิกโดยอัตโนมัติ](/console/sso#automatic-membership)
ไดเรกทอรีจะเป็นตัวกำหนดว่าใครเป็นสมาชิก แม้จะเพิกถอนโทเคนในภายหลังก็ตาม
