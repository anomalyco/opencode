## การแนบ

แนบไฟล์จากเครื่อง แล้วเขียนพรอมต์ให้ OpenCode ใช้ไฟล์นั้น ในแอปเดสก์ท็อปหรือเว็บแอป ให้เลือก **Attach file** วางไฟล์ หรือลากไฟล์ลงในช่องพิมพ์

```text
Summarize the attached README.md and list the required setup steps.
```

เมื่อใช้หน้าต่างเลือกไฟล์ในแอปเดสก์ท็อป ไฟล์ที่เลือกรวมกันได้สูงสุด 20 MiB ไคลเอนต์อื่นอาจกำหนดขีดจำกัดไว้ต่ำกว่า

<Callout type="warning">
  เลือกโมเดลที่รองรับอินพุตภาพก่อนแนบภาพ OpenCode ส่งภาพที่รองรับให้ผู้ให้บริการได้ แต่
  ผู้ให้บริการและโมเดลยังคงบังคับใช้รูปแบบ ขนาด จำนวนไฟล์ และขนาดไฟล์ของตัวเอง โมเดลข้อความล้วนอาจปฏิเสธ
  คำขอ
</Callout>

## ไวยากรณ์

อินพุตพรอมต์และคำสั่งของ V2 อธิบายไฟล์แนบด้วย `uri` และ `name` กับ
`description` ที่ไม่บังคับ

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

ใช้ URL แบบ `file:` ที่เป็นพาธสัมบูรณ์สำหรับไฟล์หรือไดเรกทอรีที่
เซิร์ฟเวอร์เข้าถึงได้ สำหรับไฟล์ข้อความ พารามิเตอร์ `start` และ `end` ที่เป็นบวกจะเลือกบรรทัด
โดยเริ่มนับที่ 1

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

ใช้ URL แบบ `data:` เพื่อส่งเนื้อหาแบบอินไลน์

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

ไม่รองรับ URL ของไฟล์แนบแบบ HTTP และ HTTPS ดู[เอกสารอ้างอิง API](/api)ที่สร้างขึ้น
สำหรับการส่งพรอมต์โดยโปรแกรม

## รูปแบบ

ปัจจุบันเซสชัน V2 ส่งไฟล์แนบประเภทต่อไปนี้ให้โมเดลได้

| อินพุต                   | โมเดลได้รับ                                           | ตัวอย่าง            |
| ----------------------- | -------------------------------------------------------- | ------------------ |
| ไฟล์ข้อความ UTF-8         | ชื่อไฟล์และข้อความที่ถอดรหัส                                | `README.md`        |
| ไดเรกทอรี               | รายการไฟล์และไดเรกทอรีในระดับนั้น โดยไม่ไล่ลงไปในไดเรกทอรีย่อย | `file:///home/me/` |
| PNG, JPEG, GIF หรือ WebP | สื่อภาพ                                              | `diagram.png`      |
| PDF                     | สื่อเอกสาร                                           | `report.pdf`       |

PDF ต้องใช้โมเดลที่รองรับอินพุต PDF หากโมเดลไม่รองรับชนิดของไฟล์แนบ
OpenCode จะส่งข้อความสั้นแทน

SVG ถือเป็นข้อความ ส่วน AVIF, BMP, เสียง วิดีโอ และไฟล์แนบแบบไบนารีอื่นๆ
จะไม่ถูกรวมในคำขอถึงโมเดล ให้แปลงไบนารีที่ไม่รองรับเป็นข้อความหรือภาพที่รองรับก่อน
เช่น แปลงภาพ BMP เป็น PNG ก่อนแนบ

OpenCode อ่านไฟล์แนบแต่ละไฟล์ก่อนรับพรอมต์ จะปฏิเสธ URL
ที่ไม่ถูกต้อง พาธที่อ่านไม่ได้ พาธที่ไม่ใช่ไฟล์หรือไดเรกทอรี และไฟล์แนบที่ถอดรหัสแล้วเกิน 20 MiB
ชนิดสื่อตรวจจากไบต์ การเปลี่ยนชื่อไฟล์หรือชนิดสื่อใน URL `data:` จึงไม่ทำให้ไบนารีที่ไม่รองรับมองเห็นได้

## ภาพ

กำหนดค่าการปรับภาพให้เป็นมาตรฐานใน `opencode.json` หรือ `opencode.jsonc`

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

ทุกฟิลด์เป็นทางเลือก

| ฟิลด์              | ค่าเริ่มต้น   | ลักษณะการทำงาน                                                                  |
| ------------------ | --------- | ------------------------------------------------------------------------- |
| `auto_resize`      | `true`    | ปรับขนาดภาพที่เกินขีดจำกัดที่กำหนด เมื่อเป็น `false` จะปฏิเสธภาพ  |
| `max_width`        | `2000`    | ความกว้างสูงสุดเป็นพิกเซล ต้องเป็นจำนวนเต็มบวก                      |
| `max_height`       | `2000`    | ความสูงสูงสุดเป็นพิกเซล ต้องเป็นจำนวนเต็มบวก                     |
| `max_base64_bytes` | `5242880` | ไบต์สูงสุดของภาพที่เข้ารหัส Base64 ต้องเป็นจำนวนเต็มบวก    |

ตัวอย่างนี้จะปฏิเสธแทนการปรับขนาดภาพที่กว้างเกิน 1200 พิกเซล

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

การตั้งค่าเหล่านี้มีผลทั้งกับภาพที่รองรับซึ่งแนบมากับพรอมต์และภาพที่เครื่องมือ `read` ในตัวส่งกลับมา

## การประมวลผล

เครื่องมือ `read` รู้จัก PNG, JPEG, GIF และ WebP จากเนื้อหา และอ่าน
ข้อมูลภาพต้นฉบับได้สูงสุด 20 MiB ตรวจความกว้าง ความสูง และความยาว Base64
เทียบกับขีดจำกัดภาพที่กำหนด

เมื่อ `auto_resize: true` OpenCode จะรักษาอัตราส่วนภาพและย่อลง
ให้อยู่ในขีดจำกัดขนาด จากนั้นลองเข้ารหัส PNG และ JPEG ที่เล็กลงเรื่อยๆ
จนได้ตามขีดจำกัด Base64 ชนิดสื่อเอาต์พุตจึงอาจเปลี่ยน

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

หากไม่มีรูปแบบการเข้ารหัสที่อยู่ในขีดจำกัด ระบบจะประมวลผลภาพไม่สำเร็จ เมื่อใช้ `auto_resize: false` ระบบจะปฏิเสธภาพที่เกินขีดจำกัดข้อใดข้อหนึ่งโดยไม่แก้ไขภาพ และจะปฏิเสธภาพที่ถอดรหัสไม่ได้เช่นกัน

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

หากตัวปรับขนาดภาพไม่พร้อมใช้งาน OpenCode จะส่งภาพเดิมผ่านไป
โดยไม่เปลี่ยน การตั้งค่าภาพจึงเป็นขีดจำกัดการประมวลผล ไม่ใช่ขอบเขตการอัปโหลดหรือ
ความปลอดภัย

## ขีดจำกัด

| ขีดจำกัด                         | ค่าหรือลักษณะการทำงาน                                             | ตัวอย่าง                                      |
| ----------------------------- | ------------------------------------------------------------- | -------------------------------------------- |
| ไฟล์แนบโดยตรง             | 20 MiB ที่ถอดรหัสแล้วต่อรายการ ไคลเอนต์อาจกำหนดขีดจำกัดต่ำกว่า      | สองไฟล์ขนาด 12 MiB ผ่านขีดจำกัดต่อรายการ     |
| การเลือกผ่านตัวเลือกไฟล์บนเดสก์ท็อป      | รวม 20 MiB                                                  | สองไฟล์ขนาด 12 MiB เกินขีดจำกัดการเลือก  |
| `max_base64_bytes`            | เฉพาะ Base64 ที่เข้ารหัส ไม่รวม URL `data:` ทั้งหมด       | `SGVsbG8=` นับเป็น 8 ไบต์                 |
| ขีดจำกัดภาพของผู้ให้บริการ         | ใช้หลังการประมวลผลของ OpenCode                               | ผู้ให้บริการอาจปฏิเสธภาพที่ยอมรับแล้ว      |
| การรองรับโมเดลสำหรับไฟล์แนบข้อความ | ไม่ต้องใช้โมเดลแบบหลายรูปแบบ                           | `notes.txt` ถูกแทรกเป็นข้อความพรอมต์       |
| ขีดจำกัดข้อความของ `read`            | ใช้ขีดจำกัดการแบ่งหน้าและการตัดทอนแยกกัน                    | อ่านบันทึกขนาดใหญ่ทีละหน้า                    |

การที่ไคลเอนต์ยอมรับไฟล์ไม่ได้หมายความว่าเนื้อหาจะถึงโมเดล ไฟล์แนบต้องใช้รูปแบบที่โมเดลมองเห็นและเป็นไปตาม
ขีดจำกัดของทั้ง OpenCode และผู้ให้บริการ
