---

การอุ่นเซสชันจะส่งคำขอถึงโมเดลเป็นระยะเพื่อรักษาพรอมต์แคชหรือสถานะอายุสั้นอื่น
ฝั่งผู้ให้บริการขณะคุณหยุดพักระหว่างพรอมต์ ปิดโดยค่าเริ่มต้น

เปิดการอุ่นใน[ไฟล์กำหนดค่า OpenCode](/config)ใดก็ได้

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}
```

ด้วยการกำหนดค่านี้ OpenCode จะอุ่นเซสชันที่ใช้งานล่าสุดก่อนพรอมต์แคชของเซสชันหมดอายุ
ที่ 90% ของ [`cache.ttl`](/models#cache-lifetime) ของโมเดล หรือทุกสี่นาทีเมื่อโมเดล
ไม่มีค่านี้ จะทำต่อจนครบ 30 นาทีนับจากคำขอที่ไม่ใช่การอุ่นครั้งล่าสุด

## ตัวเลือก

ใช้รูปแบบออบเจกต์เพื่อเปลี่ยนพรอมต์สำหรับอุ่นแคช เวลาระหว่างคำขอ หรือระยะเวลารวมที่เปิดให้อุ่นแคช

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour",
  },
}
```

| ฟิลด์ | ค่าเริ่มต้น | จุดประสงค์ |
| --- | --- | --- |
| `prompt` | คำสั่งคงการเชื่อมต่อ | ต่อท้ายเป็นข้อความผู้ใช้ชั่วคราวสำหรับแต่ละคำขออุ่น ค่าเริ่มต้นขอให้โมเดลไม่ทำงานใดๆ ไม่ใช้เครื่องมือ และตอบ `OK` |
| `interval` | `"auto"` | เวลาพักก่อนคำขออุ่นครั้งถัดไป `"auto"` ใช้ 90% ของ `cache.ttl` ของโมเดล หรือสี่นาทีเมื่อไม่มี |
| `duration` | `"30 minutes"` | ระยะเวลาที่ระบบจะอุ่นแคช นับจากคำขอปกติล่าสุดที่ส่งให้โมเดล |

ฟิลด์ที่ละไว้ในออบเจกต์คงค่าเริ่มต้น ตัวอย่างนี้เปลี่ยนเฉพาะช่วงพัก

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "2 minutes",
  },
}
```

## ช่วงพักอัตโนมัติ

โดยค่าเริ่มต้น `interval` เป็น `"auto"` ซึ่งอุ่นก่อนพรอมต์แคชของแต่ละโมเดล
หมดอายุ OpenCode ใช้ 90% ของการตั้งค่า
[`cache.ttl`](/models#cache-lifetime) ของโมเดล แคช `"5m"` จึงถูกอุ่น
ทุก 4.5 นาที โมเดลที่ไม่มี `cache.ttl` จะถูกอุ่นทุกสี่นาที

```jsonc title="opencode.jsonc"
{
  "warming": { "duration": "2 hours" },
  "providers": {
    "anthropic": { "settings": { "cache": { "ttl": "1h" } } },
  },
}
```

แคชที่อยู่นานกว่า `duration` เช่น `"1h"` กับค่าเริ่มต้น 30 นาที
จะไม่ถูกอุ่น เพราะอยู่นานกว่าหน้าต่างการอุ่นอยู่แล้ว OpenCode
จะบันทึกเรื่องนี้ครั้งเดียวต่อเซสชัน เพิ่ม `duration` เพื่ออุ่นแคชนั้น

## แยกตามผู้ให้บริการและโมเดล

ตั้ง `settings.cache.warming` ในผู้ให้บริการหรือโมเดลเพื่ออุ่นเฉพาะเซสชันของรายการนั้น
หรือให้เวลาของตัวเอง รับค่าเดียวกับ `warming` ระดับบนสุด ยกเว้น `prompt` และแทนที่ค่านั้น
การตั้งค่าในโมเดลแทนที่การตั้งค่าในผู้ให้บริการ

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "5m", "warming": true } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "warming": false } } },
      },
    },
  },
}
```

ในตัวอย่างนี้ เซสชันของ Anthropic ถูกอุ่นทุก 4.5 นาที ยกเว้นบน Claude Haiku
5.5 และผู้ให้บริการอื่นไม่อุ่น ฟิลด์ที่ละไว้ในรูปแบบออบเจกต์จะมาจาก `warming` ระดับบนสุด แล้วจึงเป็นค่าเริ่มต้น
การตั้งค่าที่ไม่ถูกต้องจะบันทึกคำเตือนและถอยไปใช้ `warming` ระดับบนสุด

## ระยะเวลา

`interval` และ `duration` รับสตริงระยะเวลา ทั้งสองต้องเป็นค่าจำกัดที่มากกว่าศูนย์
และ `interval` ต้องสั้นกว่า `duration` มิฉะนั้น OpenCode จะข้ามการอุ่นและบันทึกคำเตือน

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "30 seconds",
    "duration": "1 hour",
  },
}
```

## การจับเวลา

การอุ่นเริ่มหลังคำขอถึงโมเดลที่ไม่ใช่การอุ่นในเซสชันระดับบนสุด
เซสชันของซับเอเจนต์จะไม่ถูกอุ่น แต่ละช่วงนับจากเวลาที่ส่งคำขอล่าสุดหรือคำขออุ่น
ไม่ใช่เวลาที่การตอบกลับเสร็จ เพราะอายุแคชของผู้ให้บริการเริ่มเมื่อคำขอไปถึง
คำขออุ่นไม่ขยายหน้าต่างที่ใช้งาน

```text
00:00  normal model request sent
00:01  response finishes
00:04  warming request
00:08  warming request
00:30  warming stops
```

กิจกรรมถึงโมเดลที่ไม่ใช่การอุ่นใดๆ รวมถึงการบีบอัด จะรีเซ็ตตัวจับเวลาทั้งสอง
หากกำหนดช่วงระหว่างคำขอไว้นานเท่ากับหรือนานกว่าระยะเวลาอุ่นแคช ระบบจะปฏิเสธและแจ้งเตือน
หากช่วงที่ได้จาก `"auto"` ยาวถึงเกณฑ์เดียวกัน ระบบจะข้ามการอุ่น เพราะแคชจะยังไม่หมดอายุในช่วงนั้นอยู่แล้ว

```text
00:00  normal model request
00:20  normal model request; window restarts
00:24  warming request
00:50  warming stops
```

OpenCode จะไม่ส่งคำขออุ่นขณะมีคำขอถึงโมเดล รวมถึงการบีบอัด กำลังทำงาน
หากยังทำงานอยู่เมื่อถึงช่วงพัก การอุ่นจะรอให้เสร็จแล้วส่งทันที ตราบใดที่แคช
จากคำขอนั้นยังไม่หมดอายุ หากหมดอายุแล้ว การอุ่นจะหยุดจนกว่าจะมีคำขอปกติครั้งถัดไป

```text
00:00  normal model request sent
00:04  interval due; request still running
00:04:30  response finishes; warming request
00:08:30  warming request
```

## คำขอ

คำขออุ่นใช้โมเดล เอเจนต์ คำแนะนำ และบริบทบทสนทนาปัจจุบันของเซสชัน
OpenCode ต่อท้ายพรอมต์ที่กำหนดแบบชั่วคราว เรียกโมเดลหนึ่งครั้ง และทิ้งการตอบกลับ

```text
[current session context]
[transient user message: keep-alive prompt]
→ one model response, discarded
```

คำขอจะไม่รับอินพุต ไม่เพิ่มข้อความลงประวัติ และไม่เปลี่ยนสถานะเซสชันถาวร
OpenCode ไม่ส่งการเรียกเครื่องมือในเครื่องหรือวนลูปเครื่องมือต่อ พรอมต์เริ่มต้น
ยังบอกโมเดลไม่ให้ใช้เครื่องมือ

## ความล้มเหลว

ความล้มเหลวในการอุ่นจะถูกบันทึกโดยไม่ทำให้เซสชันล้มเหลวหรือเปลี่ยน OpenCode
จะรอจนถึงช่วงถัดไปก่อนลองใหม่ ขณะที่หน้าต่างที่ใช้งานเดิมนับถอยหลังต่อ

```text
00:04  warming request fails; session is unchanged
00:08  next warming attempt
```

คำขออุ่นที่พลาดแคช โดยอ่านจากแคชได้น้อยกว่าที่เขียน จะหยุดการอุ่นสำหรับเซสชันนั้น
จนกว่าจะมีคำขอที่ไม่ใช่การอุ่นครั้งถัดไป ผู้ให้บริการที่ไม่รายงานการใช้แคชจะไม่ถือว่าพลาด

```text
00:04  warming request misses the cache; warming stops
00:10  normal model request; warming resumes
00:14  warming request
```

## ค่าใช้จ่าย

คำขออุ่นแคชเป็นคำขอที่ส่งให้ผู้ให้บริการจริง จึงอาจใช้โทเคน มีค่าใช้จ่าย
นับเข้าในขีดจำกัดอัตรา และล้มเหลวได้เหมือนคำขอถึงโมเดลอื่น

- ช่วงพักที่สั้นลงจะเพิ่มปริมาณคำขอ
- ระยะเวลาที่นานขึ้นจะทำให้มีคำขออุ่นได้มากขึ้น
- เปิดการอุ่นเฉพาะเมื่อประโยชน์ฝั่งผู้ให้บริการคุ้มกับการใช้งานที่เพิ่มขึ้น

ตัวอย่างเช่น บนโมเดลที่ไม่มี `cache.ttl` ค่าเริ่มต้นอนุญาตการอุ่นได้สูงสุดเจ็ด
ครั้งภายในหน้าต่าง 30 นาทีที่ไม่ขาดตอน: นาทีที่ 4, 8, 12, 16, 20, 24 และ 28

## การปิดใช้งาน

ตั้ง `warming` เป็น `false` เพื่อปิดอย่างชัดเจน การไม่ระบุฟิลด์ก็
ทำให้การอุ่นปิดอยู่

```jsonc title="opencode.jsonc"
{
  "warming": false,
}
```
