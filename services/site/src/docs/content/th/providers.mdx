OpenCode มีแคตตาล็อกผู้ให้บริการและโมเดลจาก [models.dev](https://models.dev) สำหรับผู้ให้บริการส่วนใหญ่ ให้เชื่อมต่อ
บัญชีก่อน แล้วเลือกโมเดล

## การตั้งค่า

รัน `/connect` เลือกผู้ให้บริการ แล้วป้อนข้อมูลรับรอง จากนั้นรัน `/models` เพื่อเลือกโมเดลของผู้ให้บริการนั้น

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) เป็นการสมัครสมาชิกเสริมสำหรับโมเดลเขียนโค้ดที่ทดสอบโดยทีม OpenCode สมัครใน
[console](https://opencode.ai/console) คัดลอกคีย์ API แล้วเชื่อมต่อเป็น **OpenCode Go**

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

ดู[คู่มือ Go](/console/go)สำหรับขีดจำกัดการใช้งาน เอนด์พอยต์ และรายละเอียดความเป็นส่วนตัว

## ChatGPT

ใช้แพ็กเกจ ChatGPT Plus or Pro แทนคีย์ API ของ OpenAI เชื่อมต่อ **OpenAI** แล้วเลือก **Sign in with ChatGPT**
หรือวิธีลงชื่อเข้าใช้ **Codex** แบบเดิมวิธีใดวิธีหนึ่ง การใช้งานนับในแพ็กเกจของคุณ โมเดลเหล่านี้จึงไม่แสดงค่าใช้จ่าย

```text
/connect
/models
```

### ขีดจำกัดบริบท

โดยค่าเริ่มต้น OpenCode จำกัดหน้าต่างบริบทสำหรับการลงชื่อเข้าใช้เหล่านี้ให้ต่ำกว่าขีดจำกัดจริงของแต่ละโมเดล
ขีดจำกัดตรงกับค่าเริ่มต้นใน Codex การใช้งานแพ็กเกจของคุณจึงถูกใช้ในอัตราใกล้เคียงกับในผลิตภัณฑ์ OpenAI อื่น

| โมเดล                 | ขีดจำกัดอินพุต |
| --------------------- | ----------- |
| GPT-6.1 Sol และใหม่กว่า | 500,000     |
| โมเดลเก่ากว่า        | 272,000     |

หากต้องการเลือกไม่ใช้ ให้ปิดปลั๊กอินจำกัดบริบทในการกำหนดค่า คำนำหน้า `-` ปิดปลั๊กอินในตัว ปลั๊กอินอื่นทั้งหมดยัง
เปิดใช้งาน

```jsonc title="opencode.jsonc"
{
  "plugins": ["-opencode.provider.openai-context-caps"],
}
```

## กำหนดเอง

เพิ่มผู้ให้บริการเมื่อ API ยังไม่อยู่ในแคตตาล็อก ตัวอย่างที่เข้ากันได้กับ OpenAI นี้กำหนดข้อมูลรับรอง
แพ็กเกจรันไทม์ เอนด์พอยต์ และโมเดลแรกไว้ด้วยกัน

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

ออบเจกต์ `providers` คีย์ด้วย ID ผู้ให้บริการที่ใช้ในการอ้างอิงโมเดล เช่น `acme/qwen3-coder`

| ฟิลด์ | จุดประสงค์ |
| --- | --- |
| `name` | ชื่อที่แสดง |
| `env` | ชื่อตัวแปรสภาพแวดล้อมตามลำดับที่ให้ข้อมูลรับรองได้ |
| `package` | แพ็กเกจผู้ให้บริการรันไทม์ |
| `canonical` | ID ผู้ให้บริการในตัวที่แคตตาล็อกค่าเริ่มต้นซึ่งผู้ให้บริการนี้สืบทอด |
| `compatibility` | ลักษณะเฉพาะของ API ที่ทุกโมเดลของผู้ให้บริการนี้ใช้ร่วมกัน ดู[ความเข้ากันได้](/models#compatibility) |
| `settings` | ตัวควบคุม OpenCode แบบมีชนิดและตัวเลือก JSON ที่ส่งให้แพ็กเกจรันไทม์ |
| `headers` | เฮดเดอร์ HTTP แบบสตริงที่เพิ่มในคำขอ |
| `body` | ฟิลด์ JSON ที่รวมในบอดีคำขอ |
| `models` | โมเดลที่จะเพิ่มหรือแทนที่ คีย์ด้วย ID โมเดลของ OpenCode |

## เอนด์พอยต์

แทนที่ `settings.baseURL` เพื่อส่งผู้ให้บริการในแคตตาล็อกผ่านพร็อกซีหรือเอนด์พอยต์ที่เข้ากันได้ แพ็กเกจ โมเดล
และการเชื่อมต่อเดิมยังมีผล

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` ขึ้นกับแพ็กเกจ ฟิลด์จะมีผลเมื่อแพ็กเกจที่เลือกรองรับเท่านั้น

## คำขอ

ใช้ `headers` สำหรับเฮดเดอร์ HTTP เพิ่มเติม และ `body` สำหรับฟิลด์ JSON ที่ควรถูกรวมในบอดีคำขอทุกครั้ง

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

หากต้องการให้ค่าใหม่มีผลกับคำขอเพียงบางส่วนของผู้ให้บริการ ให้ตั้งทั้งสองฟิลด์นี้ในโมเดลหรือตัวเลือกย่อยของโมเดลได้

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## เวลาหมดอายุ

คำขอ HTTP รอเฮดเดอร์การตอบกลับสูงสุดห้านาที และรอระหว่างชังก์การตอบกลับที่สตรีมสูงสุดสิบห้านาที
ตั้ง `settings.headerTimeout` หรือ `settings.chunkTimeout` ของผู้ให้บริการเป็นจำนวนมิลลิวินาทีเพื่อเปลี่ยนขีดจำกัด
หรือเป็น `false` เพื่อปิด `settings.timeout` ยังจำกัดคำขอทั้งหมดตั้งแต่ส่งจนการตอบกลับ
เสร็จ และไม่มีค่าเริ่มต้น การตั้งค่าเหล่านี้มีผลกับผู้ให้บริการทั้งราย ไม่สามารถแยกตามโมเดลหรือตัวเลือกย่อยได้
เมื่อใช้ WebSocket ค่า `chunkTimeout` จะจำกัดเวลารอระหว่างเฟรมแทน โดยมีค่าเริ่มต้นสามสิบนาที

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

คำขอที่เกินขีดจำกัดใดขีดจำกัดหนึ่งจะล้มเหลวด้วยข้อผิดพลาดการรับส่ง OpenCode ลองใหม่คำขอที่หมดอายุ
สูงสุดสามครั้งก่อนเลิก

## การเข้ารหัสคำขอ

`settings.encoding` บีบอัดบอดีคำขอ HTTP ด้วย `"zstd"` หรือ `"gzip"` หรือส่ง JSON ธรรมดาด้วย `"none"` ตั้งใน
ผู้ให้บริการ โมเดล หรือตัวเลือกย่อยของโมเดล ระบบจะใช้ค่าจากระดับที่เจาะจงที่สุด เปิดใช้เฉพาะรูปแบบการเข้ารหัสที่เอนด์พอยต์ถอดรหัสได้ ผู้ให้บริการ
และเกตเวย์ส่วนใหญ่ปฏิเสธบอดีที่บีบอัด OpenAI ใช้ `"zstd"` โดยค่าเริ่มต้นเมื่อลงชื่อเข้าใช้ด้วย ChatGPT และไม่ได้กำหนด
`baseURL` เอง ส่วนคีย์ API ส่ง JSON ธรรมดา ข้อความ WebSocket ไม่ได้รับผล

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## แพ็กเกจ

ฟิลด์ `package` เลือกรันไทม์ที่สื่อสารกับผู้ให้บริการ ใช้รันไทม์ที่เข้ากันได้สำหรับ API ที่ใช้รูปแบบคำขอ OpenAI

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

- `@opencode/ai/providers/anthropic`

- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`

```jsonc title="opencode.jsonc"
      "package": "@acme/opencode-provider",

    },
  },
}
```

## โมเดล

เพิ่มหรือแทนที่โมเดลในแมป `models` ของผู้ให้บริการ คีย์ของแมปคือ ID โมเดลที่ OpenCode ใช้ `modelID` เปลี่ยน
ID ที่ส่งไปยังผู้ให้บริการ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Coding",
        },
      },
    },
  },
}
```

| ฟิลด์ | จุดประสงค์ |
| --- | --- |
| `modelID` | ID โมเดลหรือดีพลอยเมนต์ที่ส่งไปยังผู้ให้บริการ |
| `name` | ชื่อที่แสดง |
| `family` | ตระกูลโมเดลที่ใช้จัดกลุ่มโมเดลที่เกี่ยวข้อง |
| `type` | สิ่งที่โมเดลสร้าง: `chat`, `decision`, `image`, `video`, `realtime`, `embedding` หรือ `transcription` ค่าเริ่มต้นคือ `chat` เฉพาะโมเดลแชตที่เสนอสำหรับเซสชัน โมเดลเรียลไทม์ที่ตอบด้วยเสียงจะเสนอสำหรับเสียง และเมื่อตั้ง `disabled: true` จะไม่เสนอ |
| `releaseDate` | วันที่ออกรุ่นเป็น `YYYY-MM-DD` หรือ `YYYY-MM` |
| `package` | รันไทม์แทนที่สำหรับโมเดลนี้ โมเดลถอดเสียงระบุโปรโตคอลถอดเสียง เช่น `@opencode/ai/protocols/openai-transcription` ส่วนโมเดลเรียลไทม์ไม่ต้องระบุ เพราะเซสชันเสียงเริ่มผ่าน API ของมัน |
| `settings` | ตัวควบคุม OpenCode ระดับโมเดลและการตั้งค่า JSON เฉพาะแพ็กเกจ |
| `headers` | เฮดเดอร์คำขอแบบสตริงเพิ่มเติม |
| `body` | ฟิลด์บอดีคำขอ JSON เพิ่มเติม |
| `capabilities` | การรองรับเครื่องมือ ชนิดสื่ออินพุตและเอาต์พุตที่รับ การรองรับ temperature และการควบคุมการให้เหตุผล |
| `compatibility` | ลักษณะเฉพาะของ API สำหรับโมเดลนี้ แทนที่ของผู้ให้บริการ ดู[ความเข้ากันได้](/models#compatibility) |
| `variants` | ตัวเลือกย่อยที่มีชื่อและมี `settings`, `headers` และ `body` ของตัวเอง |
| `cost` | ราคาอินพุต เอาต์พุต และแคชต่อหนึ่งล้านโทเคน ระบุหรือไม่ก็ได้ |
| `limit` | ขีดจำกัดจำนวนโทเคนของบริบท อินพุต และเอาต์พุต |
| `disabled` | นำโมเดลออกจากการเลือกเมื่อเป็น `true` |

ดู [โมเดล](/models) สำหรับการเลือกโมเดล ค่าเริ่มต้น ความสามารถ ขีดจำกัด ค่าใช้จ่าย และตัวเลือกย่อย

## Azure

เอนด์พอยต์แคตตาล็อกมาตรฐานของ Azure ต้องใช้ชื่อทรัพยากรนอกเหนือจากข้อมูลรับรอง ตั้ง `settings.resourceName`
ครั้งเดียว แล้วเชื่อมต่อคีย์ API หรือใช้เซสชัน Microsoft Entra ID จาก Azure CLI ตามที่อธิบายใน
[บัญชีผู้ให้บริการ](/cli/providers)

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

หา **Resource name** ได้ใน [Azure portal](https://portal.azure.com/) หรือ
[Microsoft Foundry](https://ai.azure.com/) และเป็นส่วนแรกของเอนด์พอยต์เช่น
`https://my-models.openai.azure.com/` และ `https://my-models.services.ai.azure.com/`

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

หากต้องการใช้ Entra ID ให้ติดตั้ง [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli) ลงชื่อเข้าใช้ แล้ว
เลือก **Microsoft Entra ID (Azure CLI)** เมื่อเชื่อมต่อ Azure

```bash
az login
```

ป้อนชื่อทรัพยากรเมื่อเชื่อมต่อหากยังไม่ได้มาจากการกำหนดค่าหรือสภาพแวดล้อม ชื่อทรัพยากร
ที่บันทึกพร้อมการเชื่อมต่อมีลำดับเหนือกว่าการกำหนดค่า ให้เชื่อมต่อใหม่เพื่อเปลี่ยน

การเชื่อมต่อ Azure CLI ใช้บัญชีที่เลือกใน Azure CLI สำหรับทรัพยากรใน tenant หรือ subscription อื่น
ให้เลือกทั้งสองอย่างชัดเจน

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

แทนการกำหนดค่า `AZURE_RESOURCE_NAME` ให้ชื่อทรัพยากรแก่เซิร์ฟเวอร์ OpenCode ตัวแปร
`AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` แบบเดิมก็ใช้ได้

### ดีพลอยเมนต์

Azure ให้บริการโมเดลผ่านดีพลอยเมนต์เท่านั้น OpenCode จึงแสดงรายการดีพลอยเมนต์ของทรัพยากรคุณและแสดง
แทนแคตตาล็อก Azure ทั้งหมด รายการโหลดในเบื้องหลังหลังเริ่มทำงาน หลังเชื่อมต่อ และหลัง
สลับบัญชี หากต้องการรับดีพลอยเมนต์ที่เพิ่มภายหลัง ให้รีสตาร์ต OpenCode หรือเชื่อมต่อใหม่

- จนกว่ารายการจะโหลดสำหรับการเชื่อมต่อ หรือหากรายการล้มเหลว แคตตาล็อกทั้งหมดยังใช้ได้
- การโหลดใหม่ที่ล้มเหลวสำหรับการเชื่อมต่อเดิมจะคงรายการสมบูรณ์ล่าสุด
- การสลับบัญชีไม่เคยแสดงรายการของบัญชีก่อนหน้า บัญชีใหม่เริ่มจากแคตตาล็อกทั้งหมด
- ดีพลอยเมนต์สืบทอดขีดจำกัด ค่าใช้จ่าย และความสามารถจากโมเดลในแคตตาล็อก

ชื่อดีพลอยเมนต์คือ ID โมเดล เป็นตัวพิมพ์เล็กเพราะ Azure ไม่สนใจตัวพิมพ์ในชื่อ เช่น
`azure/gpt-production` ดีพลอยเมนต์ที่ตั้งชื่อตามโมเดล เช่น `gpt-6-luna` จะคง ID แคตตาล็อก ID เหล่านี้
คงที่เมื่อมีการเพิ่มหรือลบดีพลอยเมนต์อื่น

OpenCode จับคู่ดีพลอยเมนต์กับแคตตาล็อกตามโมเดลที่ deploy หรือตามชื่อเมื่อ Azure สะกดชื่อโมเดล
ต่างออกไป เช่น `gpt-4` สำหรับ GPT-4 Turbo ดีพลอยเมนต์ที่ตั้งชื่อตามโมเดลอื่น เช่น `gpt-6.1-sol` ที่ deploy
`gpt-6-luna` จะแสดงชื่อ ขีดจำกัด และค่าใช้จ่ายของโมเดลนั้น

เมื่อใช้ Azure CLI OpenCode แสดงดีพลอยเมนต์ผ่าน API การจัดการของ Azure ซึ่งต้องมีสิทธิ์อ่าน
ทรัพยากร หากล้มเหลว และเสมอเมื่อใช้คีย์ API จะใช้รายการดีพลอยเมนต์แบบเดิมของทรัพยากร การค้นพบอ่าน
ทุกหน้าก่อนเผยแพร่รายการ `settings.baseURL` กำหนดเองจะคงแคตตาล็อก

กำหนดดีพลอยเมนต์อย่างชัดเจนเมื่อโมเดลไม่อยู่ในแคตตาล็อก เช่นโมเดลที่ปรับแต่งแล้ว หรือเพื่อแมป ID โมเดล
กับดีพลอยเมนต์เอง OpenCode บันทึกคำเตือนระบุชื่อดีพลอยเมนต์เหล่านั้น โมเดลที่กำหนดค่าอย่างชัดเจนจะ
คงไว้เสมอ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-6-luna": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

ตัวตนของคุณต้องมีบทบาทใดบทบาทหนึ่งเหล่านี้

- **Cognitive Services OpenAI User** สำหรับโมเดล Azure OpenAI
- **Cognitive Services User** สำหรับโมเดล Foundry อื่น

หากคำขอใช้โทเคนจาก tenant ผิด ให้ลงชื่อเข้าใช้อีกครั้งด้วย tenant ที่ต้องการ

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock ใช้ห่วงโซ่ข้อมูลรับรองเริ่มต้นของ AWS โปรไฟล์ AWS ที่มีชื่อเป็นการตั้งค่าถาวรที่ง่ายที่สุด OpenCode ยัง
รู้จักสภาพแวดล้อมคีย์การเข้าถึง web identity และข้อมูลรับรองคอนเทนเนอร์

```bash
aws configure sso --profile work
aws sso login --profile work
```

เลือกโปรไฟล์และรีเจียนในการตั้งค่าผู้ให้บริการ `profile`, `AWS_PROFILE`, `AWS_ACCESS_KEY_ID`, ไฟล์โทเคน
web identity หรือ URI ข้อมูลรับรองคอนเทนเนอร์ที่กำหนดไว้จะเปิดผู้ให้บริการ รีเจียนอย่างเดียวไม่พอ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

หากไม่มีรีเจียนชัดเจน OpenCode ใช้ `AWS_REGION` แล้ว `AWS_DEFAULT_REGION` แล้ว `us-east-1` สำหรับเอนด์พอยต์ส่วนตัวหรือ
VPC ให้ตั้ง `baseURL` โดยคงโปรไฟล์และรีเจียนเดิม

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

คีย์ API ของ Bedrock ใช้ `AWS_BEARER_TOKEN_BEDROCK` ตัวแปร AWS อื่นป้อน SigV4 และไม่ถูกเก็บเป็นบัญชีคีย์ API
ของ OpenCode

## Vertex

Google Vertex ใช้ Application Default Credentials (ADC) และต้องมีโปรเจกต์ก่อนโมเดลจะใช้ได้
สร้าง ADC ในเครื่อง แล้วตั้งโปรเจกต์และตำแหน่งในการตั้งค่าผู้ให้บริการ

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode ยังอ่านค่าโปรเจกต์จาก `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` หรือ
`GCLOUD_PROJECT` ตามลำดับ และอ่านค่าตำแหน่งจาก `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION` หรือ
`VERTEX_LOCATION` โดยมีค่าเริ่มต้น `us-central1`

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

บัญชีบริการทำงานผ่านเส้นทาง ADC เดียวกัน ชี้ `GOOGLE_APPLICATION_CREDENTIALS` ไปยังไฟล์ JSON ของบัญชีบริการ
และยังต้องให้โปรเจกต์ผ่านการตั้งค่าหรือตัวแปรโปรเจกต์ด้านบนตัวใดตัวหนึ่ง

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

ใช้ ID ผู้ให้บริการ `google-vertex` เดียวสำหรับโมเดล Gemini, Anthropic และ Vertex ที่เข้ากันได้กับ OpenAI ในแคตตาล็อก
ID ผู้ให้บริการเดิม `google-vertex-anthropic` ใช้ไม่ได้ใน V2

## Copilot

GitHub Copilot รองรับ OAuth แบบอุปกรณ์แทนการป้อนคีย์ API ด้วยตัวเอง เชื่อมต่อ **GitHub Copilot** เลือก GitHub.com หรือ
GitHub Enterprise ทำขั้นตอนอุปกรณ์ให้เสร็จ แล้วเปิด `/models`

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

สำหรับ GitHub Enterprise ให้ป้อน URL หรือโดเมนของดีพลอยเมนต์เมื่อถูกขอ OpenCode ใช้เอนด์พอยต์ Copilot API ที่ GitHub
คืนมาเมื่อมี มิฉะนั้นจะอนุมานเอนด์พอยต์จากโดเมนองค์กร

```text
company.ghe.com
```

บัญชีที่เชื่อมต่อต้องมีสิทธิ์ Copilot Chat หาก GitHub รายงานว่าไม่มีสิทธิ์ ให้สมัคร Copilot Free หรือขอให้
องค์กรกำหนดที่นั่ง Copilot แล้วเชื่อมต่อใหม่ OpenCode ดึงรายการโมเดลปัจจุบันของบัญชีหลังลงชื่อเข้าใช้
และทุกครั้งที่บัญชี Copilot ที่ใช้งานเปลี่ยน

## Ollama

เริ่ม Ollama และดึงโมเดล OpenCode ตรวจ `http://127.0.0.1:11434` ค้นพบโมเดล completion และเพิ่มใน
`/models` โดยไม่ต้องเชื่อมต่อบัญชี

```bash
ollama serve
ollama pull qwen3:8b
```

ชี้ OpenCode ไปยังเซิร์ฟเวอร์ Ollama ระยะไกลหรือผ่านพร็อกซีด้วย `settings.baseURL` ให้ใส่ `/v1` ด้วย OpenCode
อนุมานพาธค้นพบเนทีฟ `/api/tags` และ `/api/show` จาก URL นั้น `apiKey` เป็นทางเลือกและถูกส่งเป็น bearer token
ให้การค้นพบและคำขอโมเดล

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

ระบบค้นหาโมเดลเป็นระยะ หากเกิดปัญหาชั่วคราวจะใช้รายการล่าสุดที่ดึงมาได้สำเร็จ โมเดลที่ทำได้เฉพาะ embedding
จะไม่ปรากฏ เพราะ OpenCode เพิ่มเฉพาะโมเดลที่ Ollama ระบุความสามารถ `completion` ไว้ในข้อมูลเมตา

## รันไทม์

LM Studio และ vLLM มีการค้นพบในเครื่องในตัวด้วย เอนด์พอยต์เริ่มต้นคือ
`http://127.0.0.1:1234/v1` และ `http://127.0.0.1:8000/v1`

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio ค้นพบโมเดลภาษาจาก `/api/v1/models` ส่วน vLLM ตรวจ `/health` ก่อนอ่าน `/v1/models` การค้นพบของ vLLM
อนุมานการรองรับเครื่องมือไม่ได้ โมเดล vLLM ที่ค้นพบจึงเริ่มด้วยเครื่องมือปิด สำหรับรันไทม์อื่นที่เข้ากันได้กับ OpenAI
ให้ใช้สูตร[ผู้ให้บริการกำหนดเอง](#custom)และระบุโมเดลอย่างชัดเจน

## เกตเวย์

OpenRouter ใช้รันไทม์และแคตตาล็อกเนทีฟ ให้ `OPENROUTER_API_KEY` แก่เซิร์ฟเวอร์ OpenCode หรือเชื่อมต่อ
บัญชี OpenRouter แล้วอ้างถึงโมเดลด้วย ID โมเดล OpenRouter เต็มหลังคำนำหน้าผู้ให้บริการ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-5.5",
}
```

คงแพ็กเกจ OpenRouter เนทีฟไว้เมื่อแทนที่เอนด์พอยต์หรือกำหนดเส้นทางผ่านเกตเวย์ที่เข้ากันได้กับ OpenRouter
วิธีนี้รักษาพฤติกรรมคำขอและการให้เหตุผลของ OpenRouter

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

สำหรับเกตเวย์ที่เปิด API ที่เข้ากันได้กับ OpenAI แต่มีรายการโมเดลของตัวเอง ให้กำหนดผู้ให้บริการกำหนดเองแทน
คีย์การกำหนดค่าจะกลายเป็นคำนำหน้าผู้ให้บริการ และแต่ละคีย์ `models` จะกลายเป็น ID โมเดลที่เลือกได้

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## ข้อผิดพลาด

ข้อผิดพลาดของผู้ให้บริการและโมเดลมักระบุขั้นตอนที่ล้มเหลว ตรวจสภาพแวดล้อมของโปรเซสเซิร์ฟเวอร์และ ID โมเดล
ที่ถูกต้องก่อนเปลี่ยนแพ็กเกจ

| ข้อผิดพลาดหรืออาการ | สิ่งที่ตรวจสอบ |
| --- | --- |
| `No model is available for session ...` | ไม่มีโมเดลที่เปิดใช้งานและเลือกได้ในขณะนี้ ทำการตั้งค่าเฉพาะผู้ให้บริการให้เสร็จ แล้วเลือกโมเดลใน `/models` |
| `Model unavailable: provider/model` | ผู้ให้บริการไม่ทำงาน ID โมเดลไม่มีหรือถูกปิด หรือการค้นพบแบบไดนามิกไม่คืนอีกต่อไป สำหรับนามแฝงกำหนดเอง ให้ตรวจคีย์ในแมป `models` ไม่ใช่ `modelID` |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | ยังมีตัวแทน `${NAME}` ใน `baseURL` ตั้งตัวแปรนั้นในเซิร์ฟเวอร์ OpenCode หรือแทนเทมเพลตด้วยเอนด์พอยต์ที่สมบูรณ์ |
| `Azure resource name is missing` | ตั้ง `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` หรือ `settings.baseURL` ที่สมบูรณ์ |
| Vertex ไม่ปรากฏ | ระบุโปรเจกต์ที่ระบบหาได้ในการตั้งค่าผู้ให้บริการหรือตัวแปรโปรเจกต์ที่รองรับ การตั้ง ADC อย่างเดียวไม่เปิดใช้งานผู้ให้บริการ |
| Bedrock ไม่ปรากฏ | ให้โปรไฟล์หรืออินพุตอื่นของห่วงโซ่ข้อมูลรับรอง AWS ที่รองรับ `AWS_REGION` เพียงอย่างเดียวเลือกแค่รีเจียน |
| Ollama ไม่มีโมเดล | ยืนยันว่าเซิร์ฟเวอร์เปิด `/api/tags` และ `/api/show` ที่พาธที่อนุมานจาก `baseURL` และ `/api/show` รายงานความสามารถ `completion` |
| Copilot ไม่มีโมเดล | ยืนยันว่าบัญชี OAuth ที่ใช้งานมีสิทธิ์ Copilot Chat การซิงค์โมเดลที่ล้มเหลวจะถูกบันทึกเป็น `failed to sync GitHub Copilot models` |

V2 ปฏิเสธ ID ผู้ให้บริการที่เลิกใช้พร้อมการแทนที่โดยตรง ใช้ `azure/<model>` แทน
`azure-cognitive-services/<model>` และ `google-vertex/<model>` แทน `google-vertex-anthropic/<model>`

## WebSocket

โมเดล OpenAI, xAI และ Azure Responses ที่รองรับสามารถคงการเชื่อมต่อ WebSocket หนึ่งรายการต่อเซสชันได้ ขั้นตอน
ต่อเนื่องจะใช้คำนำหน้าคำขอที่ไม่เปลี่ยนและส่งเฉพาะเนื้อหาที่เพิ่มตั้งแต่การตอบกลับก่อนหน้า ลดการอัปโหลดใน
เซสชันยาว

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

พฤติกรรม WebSocket เป็นไปตามกฎเหล่านี้

- ผู้ให้บริการในตัวเลือกเส้นทางที่รองรับตามนโยบายของตัวเอง
- `settings.transport: "websocket"` ของผู้ให้บริการเปิดใช้งาน `"http"` ปิด
- `"websocket"` บนเส้นทางที่ไม่มีช่อง WebSocket จะบันทึกคำเตือนและถอยไปใช้ HTTP
- การบีบอัดของผู้ให้บริการ OpenAI ใช้การเชื่อมต่อเดียวกัน
- xAI ต่อจากการตอบกลับที่จัดเก็บไว้เท่านั้น เมื่อใช้ `store: false` ค่าเริ่มต้น แต่ละขั้นจะถูกส่งทั้งหมดผ่าน
  การเชื่อมต่อที่ใช้ซ้ำ
- ซ็อกเก็ตที่ปิดจะเชื่อมต่อใหม่ในขั้นถัดไป หากเปิดการเชื่อมต่อไม่ได้ เซสชันจะดำเนินต่อผ่าน HTTP
- ปลั๊กอินผู้ให้บริการที่มีฮุก `http.request` หรือ `http.response` จะอยู่บน HTTP เพื่อให้ทุกคำขอยังตรวจสอบได้
