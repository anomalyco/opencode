การบีบอัดสร้างพื้นที่ในเซสชันยาวด้วยการแทนที่บทสนทนาก่อนหน้าด้วย
สรุป เซสชันจึงดำเนินต่อได้แม้เกินขีดจำกัดบริบทของโมเดล

## วิธีการทำงาน

เมื่อเซสชันเข้าใกล้ขีดจำกัดบริบทของโมเดล OpenCode จะสรุปบทสนทนาปัจจุบัน
ทั้งหมด และเก็บบทสนทนาส่วนล่าสุดไว้คู่กับสรุป โดยค่าเริ่มต้นจะเก็บไว้ประมาณ 15,000 โทเคน
เพื่อให้รายละเอียดล่าสุดที่แม่นยำยังใช้ได้

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

การส่งบทสนทนาทั้งหมดทำให้คำขอสรุปใช้พรอมต์แคชของคำขอปกติซ้ำได้เมื่อผู้ให้บริการ
รองรับ การบีบอัดครั้งต่อๆ ไปจะอัปเดตสรุปที่มีอยู่โดยใช้บทสนทนาตั้งแต่เช็กพอยต์นั้น

## เริ่มต้น

การบีบอัดอัตโนมัติเปิดโดยค่าเริ่มต้น

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

การบีบอัดทำให้ข้อมูลสูญหาย เพิ่ม `keep.tokens` เมื่อรายละเอียดล่าสุดที่แม่นยำสำคัญ
หรือขอบีบอัดเองก่อนการบีบอัดอัตโนมัติ

## ด้วยตัวเอง

ขอบีบอัดได้ทุกเมื่อ แม้ประวัติจะสั้น

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

คำสั่ง `api` ค้นหาและตรวจสอบสิทธิ์กับบริการเบื้องหลัง การตอบกลับยืนยันว่าคำขอได้รับการยอมรับ
ไม่ได้รอสรุป ติดตามอีเวนต์ `session.compaction.*` เพื่อทราบว่าเสร็จเมื่อใด ดู
[เอกสารอ้างอิง API](/api)สำหรับการดำเนินการทั้งหมด

| กฎ | ลักษณะการทำงาน |
| --- | --- |
| จังหวะเวลา | ทำงานที่จุดปลอดภัยถัดไป ก่อนพรอมต์ที่ยังรออยู่ |
| การทำซ้ำ | คำขอที่ทำขณะมีคำขอหนึ่งรอดำเนินการจะรวมเข้ากับคำขอนั้น |
| ระบบอัตโนมัติ | ทำงานได้เมื่อ `compaction.auto` เป็น `false` |

ส่ง `id` เพื่อให้การลองซ้ำแบบเดียวกันเป็น idempotent การใช้ ID นั้นซ้ำกับคำขออื่น
จะคืนความขัดแย้ง

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## การตั้งค่า

เพิ่ม `compaction` ใน[ไฟล์กำหนดค่า OpenCode](/config)ใดก็ได้

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": "20%",
  },
}
```

| ฟิลด์ | ค่าเริ่มต้น | ลักษณะการทำงาน |
| --- | ---: | --- |
| `auto` | `true` | บีบอัดอัตโนมัติใกล้ขีดจำกัดบริบท และกู้คืนหนึ่งครั้งเมื่อผู้ให้บริการปฏิเสธคำขอว่ายาวเกินไป การบีบอัดด้วยตัวเองใช้ได้เสมอ |
| `background` | `true` | เขียนสรุปล่วงหน้าเพื่อให้การบีบอัดอัตโนมัติไม่ต้องรอ ดู[การบีบอัดเบื้องหลัง](#background-compaction) |
| `keep.tokens` | `15000` | บทสนทนาล่าสุดโดยประมาณที่เก็บไว้ข้างสรุป ค่ามากขึ้นรักษารายละเอียดได้มากแต่เหลือที่สำหรับงานใหม่น้อยลง |
| `buffer` | `"15%"` อย่างน้อย 16k | สัดส่วนของหน้าต่างบริบทของโมเดลที่เว้นว่างไว้ การบีบอัดอัตโนมัติเริ่มเมื่อบทสนทนาถึงส่วนที่เหลือ ค่ามากขึ้นบีบอัดเร็วขึ้น |

`keep.tokens` รับจำนวนเต็มที่ไม่เป็นลบ

### บัฟเฟอร์

`buffer` เป็นเปอร์เซ็นต์ของหน้าต่างแต่ละโมเดล การตั้งค่าหนึ่งจึงใช้ได้กับทุกโมเดล

| หน้าต่างโมเดล | `"buffer": "20%"` บีบอัดที่ |
| ---: | ---: |
| 128k | ~102k |
| 1M | 800k |

- เป็นพื้นที่ที่เว้นว่างไว้ ไม่ใช่จุดที่การบีบอัดเริ่ม: `"20%"` บีบอัดเมื่อเต็ม 80%
- รับ `"1%"` ถึง `"99%"` รวมทศนิยมเช่น `"12.5%"`
- ระบุเป็นจำนวนโทเคน เช่น `20000` ก็ได้ จำนวนเดียวกันจะกินสัดส่วนมากในหน้าต่างบริบทขนาดเล็ก และกินสัดส่วนน้อยในหน้าต่างขนาดใหญ่
- หากจำนวนโทเคนเท่ากับหรือเกินขนาดหน้าต่างบริบทของโมเดล ระบบจะใช้ค่าเริ่มต้นแทน

## โมเดล

โดยค่าเริ่มต้น OpenCode เขียนสรุปเองโดยใช้โมเดลของเซสชัน ตั้ง
`agents.compaction.model` เพื่อใช้โมเดลอื่นสำหรับสรุป

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" },
  },
}
```

หากหาโมเดลที่ระบุไม่พบ OpenCode จะใช้โมเดลของเซสชันแทน

## การบีบอัดเบื้องหลัง

OpenCode เขียนสรุปล่วงหน้าขณะเซสชันดำเนินต่อ และสลับเข้าใช้เมื่อถึงเวลาบีบอัด
การบีบอัดอัตโนมัติจึงไม่หยุดเซสชันเพื่อเขียนสรุป

```text
60k tokens before the threshold   summary of the conversation so far starts in the background
                                  the session keeps going; the summary is held, not applied
threshold                         the held summary is swapped in; everything since it is kept as is
```

บนหน้าต่างบริบทเล็ก สรุปจะเริ่มอย่างช้าที่สุดกึ่งกลางระหว่างการตอบกลับครั้งแรกหลังการบีบอัดครั้งล่าสุด
กับเกณฑ์

| กฎ | ลักษณะการทำงาน |
| --- | --- |
| ค่าใช้จ่าย | คำขอให้สรุปใช้พรอมต์แคชเดิม ถึงจะไม่ได้ใช้สรุปนั้น เช่น เซสชันจบก่อนถึงเกณฑ์ ก็ยังเสียโทเคน |
| การรอ | หากสรุปยังเขียนอยู่เมื่อถึงเวลาบีบอัด เซสชันจะรอให้เสร็จ |
| การสรุปใหม่ | ระบบจะสรุปตามปกติหากบทสนทนาที่เพิ่มขึ้นหลังทำสรุปล่วงหน้ามีขนาดเกินประมาณ 40% ของเกณฑ์ หรือหากส่วนต้นของบทสนทนาเปลี่ยนไป |
| การข้าม | ไม่ใช้กับการบีบอัดแบบเนทีฟ หลังสลับโมเดลหรือหลังหยุดนานกว่าอายุพรอมต์แคช จะเริ่มจากการตอบกลับครั้งถัดไปแทน |
| ที่เก็บข้อมูล | ระบบเก็บสรุปที่ทำไว้ล่วงหน้าในหน่วยความจำ และสรุปนั้นจะหายเมื่อรีสตาร์ต |

ปิดเพื่อเขียนสรุปเฉพาะเมื่อถึงเวลาบีบอัด

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "background": false,
  },
}
```

## ผู้ให้บริการ

ผู้ให้บริการบางรายบีบอัดบทสนทนาฝั่งตัวเองแทนได้ เปิดต่อผู้ให้บริการหรือโมเดลด้วย
`settings.compaction`

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

การตั้งค่าในโมเดลแทนที่การตั้งค่าในผู้ให้บริการ `native` ใช้การบีบอัดของผู้ให้บริการ
ส่วน `summary` ใช้ของ OpenCode เอง

เมื่อใช้การบีบอัดแบบเนทีฟ OpenCode จะส่งบทสนทนาไปยังเอนด์พอยต์การบีบอัดของผู้ให้บริการ
ผู้ให้บริการส่งข้อมูลที่เข้ารหัสและเปิดอ่านไม่ได้กลับมาแทนบทสนทนาก่อนหน้า ระบบเก็บข้อความและไฟล์แนบล่าสุดไว้ควบคู่กันไม่เกิน `keep.tokens`

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| หัวข้อ | ลักษณะการทำงาน |
| --- | --- |
| การรองรับ | โมเดล OpenAI Responses การรองรับแตกต่างตามการปรับใช้และโมเดล |
| เกณฑ์ | ใช้การตั้งค่า `auto` และ `buffer` เดียวกับการบีบอัดแบบสรุป คำขอด้วยตัวเองก็ใช้ได้ |
| การใช้ข้ามโมเดล | เช็กพอยต์ที่เข้ารหัสใช้ได้กับผู้ให้บริการและโมเดลเดิมเท่านั้น หากสลับโมเดล เซสชันจะใช้บทสนทนาต้นฉบับแทน |
| ยาวเกินไป | หากผู้ให้บริการปฏิเสธการบีบอัดว่ายาวเกินไป OpenCode จะลองใหม่ด้วยคำขอที่เล็กลง ไม่สลับไปใช้สรุป |

## สรุป

สรุปมีโครงสร้างเพื่อให้เอเจนต์อื่นรับงานต่อได้

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

สรุปครอบคลุมวัตถุประสงค์และข้อกำหนด การตัดสินใจ งานที่เสร็จและที่กำลังทำ อุปสรรคและก้าวถัดไป
และไฟล์ที่เกี่ยวข้อง ในบทสนทนาล่าสุดที่เก็บไว้ข้างสรุป เอาต์พุตเครื่องมือยาวจะถูกย่อ
และข้อมูลไฟล์แนบจะถูกแทนที่ด้วยคำอธิบายสั้น

หลังการบีบอัด เวอร์ชันปัจจุบันของไฟล์คำแนะนำของคุณจะเป็นฐานของเซสชัน
ดู[คำแนะนำ](/instructions)

## ขีดจำกัด

| ขีดจำกัด | ผลลัพธ์ |
| --- | --- |
| โมเดล | การบีบอัดแบบสรุปใช้ `agents.compaction.model` หากตั้งไว้ มิฉะนั้นใช้โมเดลของเซสชัน การบีบอัดแบบเนทีฟใช้โมเดลของเซสชันเสมอ |
| ประวัติ | การบีบอัดต้องมีบทสนทนาก่อนหน้าให้แทนที่ หากคำขอส่วนใหญ่เป็นคำแนะนำกับ schema ของเครื่องมือที่ไม่เปลี่ยน ระบบจะคืนพื้นที่ไม่ได้ |
| ขนาด | หากบทสนทนาที่จะบีบอัดยาวเกินไปเอง OpenCode จะส่งข้อความเวอร์ชันย่อและอาจละบทสนทนาที่เก่าที่สุด |
| การกู้คืน | คำขอที่ถูกปฏิเสธว่ายาวเกินไปจะถูกบีบอัดและลองใหม่หนึ่งครั้ง การปฏิเสธครั้งที่สองจะคืนเป็นข้อผิดพลาด |
| ที่เก็บข้อมูล | ข้อความก่อนหน้ายังถูกเก็บไว้แม้จะไม่ส่งถึงโมเดลแล้ว |

ตัวอย่างเช่น การบีบอัดช่วยไม่ได้ในกรณีนี้

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## การย้ายจาก V1

V1 ใช้พฤติกรรม tail-turn และการตัดทอน V2 ใช้สรุปและ
`compaction.keep.tokens`

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

การตั้งค่าและพฤติกรรมในหน้านี้ใช้กับ V2
