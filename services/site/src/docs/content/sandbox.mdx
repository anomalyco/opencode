---
title: "Shell sandbox"
---

The experimental shell sandbox runs agent shell commands under macOS Seatbelt. It is disabled by default and supports local macOS hosts only.

**This confines the shell tool only.** Built-in file and search tools, formatters, snapshots, plugins, MCP services, web tools, and human-operated terminals remain outside the sandbox and retain their existing permissions. It is not a security boundary around the whole agent or server.

## Enable the shell sandbox

Add the setting to your global `~/.config/opencode/opencode.jsonc`.

```jsonc
{
  "experimental": {
    "sandbox": { "enabled": true },
  },
}
```

Settings are read when the server starts. Restart the background service with `opencode service restart`, or start a separate server with `opencode --standalone /path/to/project`. Project configuration cannot enable or change the sandbox.

| Setting | Default | Description |
| --- | --- | --- |
| `enabled` | `false` | Enable the shell sandbox on a local macOS host. |
| `full_disk_read` | `false` | Allow broad reads, subject to protected-path exclusions. |
| `readable_roots` | `[]` | Additional existing absolute paths shell commands may read. |
| `writable_roots` | `[]` | Additional existing absolute paths shell commands may write. |

## Shell command access

Sandboxed shell commands and their descendants can write to the workspace, a dedicated scratch directory, and configured writable roots, except for protected metadata and credentials. Reads are restricted to those roots, configured readable roots, and selected system and Homebrew runtime paths. The sandbox blocks command network access.

Shell commands skip the default approval prompt when no rule matches. Explicit shell and external-directory rules still apply, including rules that ask for approval or deny a command. The sandbox does not currently support requesting an unsandboxed shell command. Commands that need access outside the sandbox must be run separately by the user, or the server must be restarted with the sandbox disabled.

Git configuration and runtime dependencies outside the default readable paths may need explicit readable roots.

```jsonc
{
  "experimental": {
    "sandbox": {
      "enabled": true,
      "readable_roots": ["/opt/my-toolchain", "/opt/homebrew/etc/gitconfig"],
    },
  },
}
```

Configured roots must exist and be absolute. Runtime paths such as `/private/etc` and `/Library/Preferences` may contain configuration readable by your account.

## Broad reads and exclusions

Set `full_disk_read` to `true` to allow broad filesystem reads while retaining the write and network restrictions.

```jsonc
{
  "experimental": { "sandbox": { "enabled": true, "full_disk_read": true } },
}
```

OpenCode configuration, data and state directories, its configured SQLite database and journals, and `.aws` and `.ssh` directly under the home directory or writable roots are excluded. This list describes the current implementation and may change; it does not cover every possible credential or sensitive file.

The server fails closed if sandbox setup fails, the host is unsupported, or the location is remote. Sandboxed background commands are tied to their location and do not survive location teardown or server restart. CPU, memory, and process-count quotas are not provided.
