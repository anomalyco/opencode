Wähle mit `/models` ein Modell für die aktuelle Session:

```text
/models
```

OpenCode listet Modelle aus [models.dev](https://models.dev), aus Anbieterintegrationen und aus deiner Konfiguration auf.
Zur Auswahl stehen nur aktivierte Modelle, deren Anbieter im aktuellen Projekt verfügbar ist. Verbinde Anbieter unter
[Anbieter](/providers).

## Auswählen

Wähle das Modell in `/models` aus, statt die Anbieter- oder Modell-ID zu erraten. Die Auswahl gilt für die aktuelle Session
und ändert deine Konfiguration nicht.

```text
anthropic/claude-sonnet-5-5
```

Die Verfügbarkeit ist projektspezifisch:

- Das Modell muss aktiviert sein.
- Sein Anbieter muss im aktuellen Projekt verfügbar sein.
- Zugangsdaten und Konfiguration aus einem anderen Projekt werden nicht automatisch übernommen.

## Läufe

Nutze `--model`, um für einen einzelnen CLI-Aufruf ein Modell zu wählen, ohne das Standardmodell zu ändern:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Agenten und Befehle können ebenfalls ihr eigenes Modell wählen. Siehe [Agenten](/agents) und [Befehle](/commands).

## Standards

Setze `model` in `opencode.json` oder `opencode.jsonc`, um das Standardmodell für neue Aufgaben festzulegen:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Das konfigurierte Modell wird zum Standard im Katalog, wenn es aktiviert und sein Anbieter verfügbar ist. Andernfalls
nutzt OpenCode das neueste unterstützte Modell, das verfügbar ist.

- Ein bereits für eine Session gewähltes Modell hat Vorrang vor dem konfigurierten Standard.
- Ein Modellwechsel in der Session ändert die Konfigurationsdatei nicht.
- `model` auf der obersten Ebene speichert derzeit nur den Standardanbieter und das Standardmodell, keine Variante.

Siehe [Konfiguration](/config) für Speicherorte und Rangfolge der Konfiguration.

## Kostenlose Modelle

Setze `OPENCODE_DISABLE_FREE_MODELS=1` (oder `true`) im Serverprozess, um [kostenlose OpenCode-Modelle](/console/models#free-models) auszublenden:

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

Für den gemeinsamen Hintergrundserver:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

Modelle von `opencode` oder `opencode-go` gelten als kostenlos, wenn für Eingabetokens kein Preis anfällt. Sie sind
dann weder im Katalog noch als Standard verfügbar. Wählst du ein solches Modell ausdrücklich aus, erscheint
`Model unavailable`. Wenn du abgemeldet bist, fehlt der Anbieter `opencode`. Verbinde ein Konto in OpenCode Console
oder setze `OPENCODE_API_KEY`, damit seine kostenpflichtigen Modelle wieder verfügbar sind.

Um kostenlose Modelle für alle in einer Organisation zu blockieren, nutze stattdessen eine Policy. Siehe
[Enterprise](/enterprise#block-free-models).

## Varianten

Mit Varianten legst du benannte Einstellungen für ein Modell fest, etwa für den Reasoning-Effort oder das Token-Budget.
Hänge `#variant` an, wenn du eine Variante für einen Aufruf, eine Session, einen Agenten oder einen Befehl auswählst:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

Die Variantennamen stammen aus den aktuellen Katalogdaten des gewählten Modells. Nicht jedes Modell bietet `low`, `high`
und `max` an. Ist die Variante unbekannt, schlägt die Modellauswahl fehl.

Definiere neue Varianten oder ersetze Katalogvarianten mit derselben ID im `variants`-Array des Modells:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Jede Variante kann `settings`, `headers` und `body` enthalten. Ihre Werte werden nach Anbieter- und Modellwerten angewendet.

Um die Reasoning-Varianten eines Modells zu ersetzen, gib unter `capabilities.reasoning` die Reasoning-Einstellungen
im V2-Format von [models.dev](https://models.dev) an. OpenCode erzeugt daraus die Varianten für das Paket des Modells:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| Feld        | Zweck                                                                     |
| ----------- | ------------------------------------------------------------------------- |
| `supported` | Gibt an, ob das Modell Reasoning unterstützt. Bei `false` oder bei `true` ohne weitere Reasoning-Einstellungen kommen keine Varianten hinzu. |
| `toggle`    | Fügt eine Variante `none` hinzu, die Reasoning abschaltet.               |
| `effort`    | Effort-Stufen, die zur Auswahl stehen. `default` übernimmt die Vorgabe des Anbieters und fügt keine Variante hinzu. |
| `budget`    | Optionale Unter- und Obergrenze für Thinking-Tokens: `min` und `max`. Das Feld wird ignoriert, wenn `effort` gesetzt ist. |

OpenCode wendet die Varianten in `variants` auf die Varianten an, die es aus `capabilities.reasoning` erzeugt hat.

## Optionen

Anbieter- und Modelleinträge können Anfragen mit `settings`, `headers` und `body` anpassen:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Feld       | Zweck                                                            |
| ---------- | ---------------------------------------------------------------- |
| `settings` | Optionen des Anbieterpakets wie `baseURL` oder `reasoningEffort`. |
| `headers`  | Zusätzliche HTTP-Anfrage-Header.                                  |
| `body`     | Anbieterspezifische Felder im Anfrage-Body.                        |

OpenCode wendet zuerst Anbieterwerte, dann Modellwerte und zuletzt die gewählte Variante an.

- Verschachtelte `settings`- und `body`-Objekte werden zusammengeführt.
- Spätere Arrays und skalare Werte ersetzen frühere Werte.
- Header-Namen werden ohne Beachtung der Groß- und Kleinschreibung abgeglichen.
- Optionen sind anbieterspezifisch und können von einem anderen Anbieterpaket ignoriert oder abgelehnt werden.

## Aliase

Nutze `modelID`, um für ein API-Modell eine besser lesbare Katalog-ID zu vergeben:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Hier ist `openai/coding-default` die wählbare Referenz und `gpt-6.1-sol` wird an den Anbieter gesendet. Für ein Modell, das noch
nicht im Katalog ist, nimmt OpenCode an:

- Unterstützung für Tools mit JSON-Eingabe, für Text- und Bildeingabe sowie für Textausgabe. Freie Tool-Eingaben sind nur möglich, wenn `capabilities.freeform` das Format aufführt.
- Ein Kontextlimit von 200.000 Tokens und ein Ausgabelimit von 32.000 Tokens.
- Kein festgelegtes Eingabelimit.

OpenCode erkennt `text`, `regex` und `lark`. Andere Formatnamen von models.dev ignoriert es, ohne das Modell oder seine Tools
zu entfernen. Wenn ein vorgeschalteter Proxy Tools mit freier Eingabe für ein Katalogmodell ablehnt, setze
`capabilities.freeform` für dieses Modell auf `[]`.

Das sind Ersatzwerte und keine automatisch ermittelten Fähigkeiten. Wenn du die tatsächlichen Werte kennst, setze
`capabilities` und `limit` ausdrücklich. Sie ersetzen die Vorgaben. Die automatische Compaction nutzt `limit.input`,
jedoch höchstens `limit.context`.
Siehe [Kontextfenster](/compaction#window). Füge `disabled: true` hinzu, um ein Modell aus dem verfügbaren Katalog auszublenden:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Reasoning

Wenn ein OpenAI-kompatibles Modell Reasoning gestreamt in einem eigenen Feld der Assistentennachricht überträgt, setze
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode erkennt `reasoning`, `reasoning_content` und `reasoning_text` und akzeptiert außerdem einen anderen anbieterspezifischen
String. OpenCode liest das gestreamte Reasoning aus diesem Feld und ergänzt es wieder, wenn es frühere
Assistentennachrichten an das Modell sendet. Siehe [Kompatibilität](#compatibility) für das verwandte Feld `requireReasoning`.

## Prompt-Caching

Für Routen, die bekanntermaßen Breakpoints für den Prompt-Cache brauchen, etwa bei Anthropic, setzt OpenCode sie
automatisch. Laufen Claude-Modelle über einen OpenAI-kompatiblen Proxy wie LiteLLM, erkennt OpenCode nicht, dass
sie `cache_control`-Breakpoints im Anthropic-Format brauchen. Setze für diese Claude-Modelle `compatibility.cacheFormat`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

OpenCode markiert dann die letzte Tool-Definition, den System-Prompt und die letzte Nachricht mit
`cache_control: { "type": "ephemeral" }`. Dadurch gilt die Cache-Lebensdauer des Endpunkts von standardmäßig fünf Minuten. Nutze `"alibaba"`
für Modelle von Alibaba Model Studio, die dieselben Marker akzeptieren, sie bei Tool-Definitionen aber ignorieren. Setze
`compatibility.cacheFormat` stattdessen am Anbieter, wenn jedes von ihm bereitgestellte Modell dasselbe Format akzeptiert. Siehe
[Kompatibilität](#compatibility) für die anderen Felder.

### Cache-Lebensdauer

OpenCode gibt standardmäßig keine Cache-Lebensdauer vor. Daher gilt die Vorgabe des Anbieters, etwa fünf Minuten
bei Anthropic. Wenn du eine andere Lebensdauer anfordern möchtest, setze `settings.cache.ttl` für den Anbieter oder
das Modell. Die Einstellung am Modell hat Vorrang.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

Gib für `ttl` eine Zahl mit Einheit an: `ms`, `s`, `m`, `h` oder `d`, etwa `"5m"`, `"1h"` oder `"24h"`.
OpenCode übergibt den Wert unverändert. Verwende daher einen Wert, den der Anbieter akzeptiert:

| API | Feld für die Cache-Lebensdauer |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` an jedem Cache-Marker. Anthropic akzeptiert `"5m"` und `"1h"`. |
| Bedrock Converse | `ttl` an jedem `cachePoint`. Ältere Claude-Modelle, die nur fünf Minuten cachen, ignorieren `"1h"`. |
| OpenAI Chat und Responses | `"24h"` geht an `prompt_cache_retention`; andere Werte gehen an `prompt_cache_options.ttl`. |

Anbieter wie Gemini, die automatisch ohne Marker cachen, ignorieren die eingestellte Cache-Lebensdauer. Eine längere
Lebensdauer macht das Schreiben in den Cache meist teurer: Anthropic berechnet für eine Stunde den doppelten
Preis für Eingabetokens und für fünf Minuten das 1,25-Fache.

[Warming](/warming) kann die Abstände zwischen den Anfragen mit `interval: "auto"` an die Cache-Lebensdauer anpassen.

## Kompatibilität

`compatibility` beschreibt Besonderheiten bei Anfragen und Antworten der API, die ein Modell bereitstellt: etwa
in welchem Feld das Reasoning steht oder ob der Endpunkt `prompt_cache_key` akzeptiert. Jedes Modell nutzt eine
API. Ein Feld hat nur dann eine Wirkung, wenn diese API es auswertet. Andere Felder werden ignoriert.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

Die `compatibility`-Einstellungen des Anbieters gelten für alle seine Modelle. Ein Modell kann sie über sein eigenes
`compatibility` Feld für Feld überschreiben: OpenCode übernimmt zunächst die Werte, die [models.dev](https://models.dev)
für die API des Modells veröffentlicht (`reasoningField`, `maxTokensField` und `mediaInput` sowie `supportsEffortUpdates`
und `supportsSystemUpdates`, wenn models.dev diese Funktionen für die API als unterstützt ausweist). Danach wendet
OpenCode die Modellkonfiguration an. Ist ein Feld nicht gesetzt, gelten die Vorgaben oder die automatische Erkennung
des Anbieterpakets. `supportsThinkingBlockBinding`, `supportsEffortUpdates` und `supportsSystemUpdates` lassen sich nur
pro Modell einstellen.

| Feld | Wirkung | Unterstützt von | Werte und Standard |
| --- | --- | --- | --- |
| `reasoningField` | Feld für das Reasoning in der Assistentennachricht. OpenCode prüft es zuerst, wenn es gestreamtes Reasoning liest, und verwendet es beim erneuten Senden früheren Reasonings. | OpenAI Chat | Jeder Feldname außer `role`, `content`, `refusal` und `tool_calls`. Ohne Angabe nutzt OpenCode das Feld aus dem Stream, falls vorhanden, andernfalls `reasoning_content`. |
| `requireReasoning` | Sendet das Reasoning-Feld bei jeder früheren Assistenten-Nachricht, als leeren String, wenn es kein Reasoning gab. | OpenAI Chat | `true` oder `false`. Standard ist `true`, wenn `reasoningField` gesetzt ist oder das Modell DeepSeek ist, sonst `false`. |
| `maxTokensField` | Feld für das Limit der Ausgabetokens im Anfrage-Body. | OpenAI Chat | `max_completion_tokens` oder `max_tokens`. Ohne Angabe nutzt OpenCode `max_tokens` bei Anbietern, die es benötigen, etwa DeepSeek, Moonshot, Together AI, Z.AI und Cerebras. Sonst nutzt es `max_completion_tokens`. |
| `requireFinishReason` | Endet ein Stream ohne `finish_reason`, meldet OpenCode eine unvollständige Antwort. Bei `false` gilt der Stream als abgeschlossen. | OpenAI Chat | `true` oder `false`. Standard ist `true`. |
| `requireAssistantAfterTool` | Fügt eine Assistenten-Nachricht zwischen ein Tool-Ergebnis und die nächste Nutzernachricht ein, für Endpunkte, die diese Reihenfolge ablehnen. | OpenAI Chat | `true` oder `false`. Standard ist `true` für Modell-IDs der Mistral-Familie, sonst `false`. |
| `supportsPromptCacheKey` | Ob der Endpunkt das Body-Feld `prompt_cache_key` akzeptiert. | OpenAI Chat, OpenAI Responses, Mistral | `true` oder `false`. OpenAI Chat sendet den Schlüssel nur bei `true`, was manche Anbieterpakete standardmäßig setzen. Andere APIs senden ihn, sofern nicht `false`. |
| `streamUsage` | Fordert mit `stream_options.include_usage` Angaben zum Tokenverbrauch im Stream an. | OpenAI Chat | `true` oder `false`. Standard ist `true`. |
| `cacheFormat` | Syntax der Prompt-Cache-Marker, die der Endpunkt akzeptiert. Überschreibt die automatische Breakpoint-Platzierung des Anbieters. `alibaba` überspringt Tool-Definitionen. | Jede API mit Prompt-Cache-Markern, einschließlich OpenAI Chat, Anthropic Messages und Bedrock Converse | `anthropic` oder `alibaba`. Ungesetzt nutzt es den Anbieterstandard. Siehe [Prompt-Caching](#prompt-caching). |
| `supportsThinkingBlockBinding` | Bittet die API, Thinking-Blöcke zu verwerfen, deren früherer Kontext sich geändert hat, statt die Anfrage abzulehnen. | Anthropic Messages, Bedrock Converse | `true` oder `false`. Ungesetzt erkennt es Claude 5.1 und neuer. |
| `supportsEffortUpdates` | Sendet Änderungen des Reasoning-Efforts für die jeweilige Nachricht. Der Prompt-Cache bleibt erhalten. Andernfalls ändert sich der Effort für die gesamte Anfrage. | Anthropic Messages, OpenAI Responses | `true` oder `false`. Ohne Angabe erkennt OpenCode Claude Opus 5, Claude 5.1 und neuer sowie GPT-6 und neuer. |
| `supportsSystemUpdates` | Sendet Systemnachrichten, die im laufenden Gespräch hinzukommen, als native Systemnachrichten. Andernfalls fügt OpenCode sie als Text in die nächste Nutzernachricht ein. | Anthropic Messages | `true` oder `false`. Ohne Angabe erkennt OpenCode Claude Opus 4.8 sowie Claude 5 und neuer. |
| `mediaInput` | Wohin Bilder und andere Medien in einer Entscheidungsanfrage gehen. | System One | `assets` (Bilder, auf die aus dem State verwiesen wird), `state` (inline im State) oder `root` (Listen `images`, `audio` und `videos` auf oberster Ebene). Ungesetzt nutzt es den Anbieterstandard. |

## Lokal

OpenCode erkennt Modelle von Ollama, LM Studio und vLLM automatisch unter ihren lokalen Standardadressen. Du kannst auch
jeden OpenAI-kompatiblen Server von Hand konfigurieren.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Wenn Ollama auf `http://127.0.0.1:11434` lauscht, wähle ein erkanntes Modell mit der Anbieter-ID `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode aktualisiert die Modellliste im Hintergrund und liest aus Ollama die Angaben zum Kontext sowie zur
Unterstützung von Bildern und Tools. Reine Embedding-Modelle erscheinen nicht in der Liste.

Gib die OpenAI-kompatible URL von Ollama an, wenn du einen anderen Host oder Port nutzt. Die automatische Erkennung
verwendet weiterhin die native Ollama-API mit demselben Pfadpräfix:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Lass `apiKey` weg, wenn der Endpunkt keine Bearer-Authentifizierung verlangt.
- Schalte die automatische Erkennung mit `"plugins": ["-opencode.provider.ollama"]` ab.

### LM Studio

Wenn ein LM Studio-Server ohne Authentifizierung auf `http://127.0.0.1:1234` läuft, wähle ein erkanntes Modell mit der Anbieter-ID
`lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode aktualisiert die Modellliste im Hintergrund und liest aus LM Studio die Angaben zum Kontext sowie zur
Unterstützung von Bildern und Tools. Embedding-Modelle erscheinen nicht in der Liste.

Gib die OpenAI-kompatible URL an, wenn du einen anderen Host oder Port nutzt. OpenCode erkennt die Modelle weiterhin
automatisch:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Lass `apiKey` weg, wenn die Authentifizierung von LM Studio deaktiviert ist.
- Schalte die automatische Erkennung mit `"plugins": ["-opencode.provider.lmstudio"]` ab.

### vLLM

Wenn vLLM auf `http://127.0.0.1:8000` lauscht, wähle ein erkanntes Modell mit der Anbieter-ID `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode prüft `/health`, ruft `/v1/models` im Hintergrund erneut ab und verwendet den gemeldeten Wert
`max_model_len` als Kontextlimit. Es berücksichtigt nur Modellkarten, für die `vllm` als Eigentümer angegeben ist.

Die automatisch erkannten Modelle melden Texteingabe und -ausgabe, aber keine Unterstützung für Bilder oder Tools.
vLLM aktiviert Tool-Aufrufe über Server-Flags wie `--enable-auto-tool-choice` und `--tool-call-parser`. Die automatische
Erkennung erfasst diese Flags nicht.

Für einen anderen Endpunkt oder einen authentifizierten Server setze seine OpenAI-kompatible URL:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Lass `apiKey` weg, wenn die Authentifizierung deaktiviert ist.
- Schalte die automatische Erkennung mit `"plugins": ["-opencode.provider.vllm"]` ab.
- Proxys mit Pfadpräfix werden unterstützt. Bei `https://example.com/vllm/v1` prüft OpenCode beispielsweise
  `/vllm/health` und ruft die Modellliste über `/vllm/v1/models` ab.

### Kompatibel

Definiere für einen anderen OpenAI-kompatiblen Server sein Anbieterpaket, seinen Endpunkt und mindestens ein Modell:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Gib den tatsächlichen Modellnamen des Servers, seine Limits, die Ein- und Ausgabetypen und die Tool-Unterstützung an.
OpenCode kann nicht erkennen, ob die Ersatzwerte für eigene Modelle stimmen. Wenn der Endpunkt einen Schlüssel
verlangt, füge `apiKey` unter `settings` hinzu und verweise auf eine Umgebungsvariable, etwa mit
`"apiKey": "{env:LOCAL_API_KEY}"`. Committe keine Geheimnisse.

## Referenzen

Modellreferenzen haben das Format `provider/model`, optional gefolgt von `#variant`:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| Teil       | Regel                                                      |
| ---------- | ---------------------------------------------------------- |
| Anbieter   | Endet am ersten `/`; darf kein `/` oder `#` enthalten.     |
| Modell     | Darf weitere `/`-Zeichen enthalten; darf kein `#` enthalten. |
| Variante   | Folgt auf `#`, wenn vorhanden.                             |
| Groß-/Kleinschreibung | Anbieter- und Modell-IDs unterscheiden zwischen Groß- und Kleinschreibung. |

Nutze Katalog-IDs statt der Anzeigenamen von Anbietern. `model` akzeptiert auf der obersten Ebene sowie in Agenten-
und Befehlskonfigurationen entweder den oben beschriebenen String oder die ausführliche Form als Objekt:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}
```

Die Objektform eignet sich für Konfigurationen, die du generierst oder per Code erstellst.

## Hinweise

Beachte beim Konfigurieren von Modellen diese Regeln:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- In der Modellreferenz als Objekt steht `model`. Ein Katalogeintrag des Anbieters nutzt dagegen `modelID` für die ID, die OpenCode an den Anbieter sendet.
- Eine Modellreferenz auf der obersten Ebene kann zwar eine Variante enthalten, V2 speichert sie aber nicht als
  Teil des Katalogstandards. Wähle Varianten stattdessen für eine Session, einen Aufruf, einen Agenten oder einen Befehl.
- Modelloptionen sind anbieterspezifisch. Ein anderes Anbieterpaket kann sie ignorieren oder ablehnen.
- Katalogdaten, Zugangsdaten und Konfiguration sind an die Location gebunden. Ein Modell, das in einem Projekt verfügbar ist, kann in
  einem anderen nicht verfügbar sein.
- OpenCode lädt Konfigurationsdateien in der Regel automatisch neu. Für eine bereits laufende Modellanfrage gelten
  weiterhin die Einstellungen, mit denen sie gestartet ist.
