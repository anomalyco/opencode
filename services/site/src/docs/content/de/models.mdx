Wähle ein Modell für die aktuelle Session mit `/models`:

```text
/models
```

OpenCode listet Modelle von [models.dev](https://models.dev), Anbieter-Integrationen und deiner Konfiguration auf. Der
Picker zeigt nur aktivierte Modelle, deren Anbieter im aktuellen Projekt verfügbar ist. Verbinde Anbieter unter
[Anbieter](/providers).

## Auswählen

Wähle einen Eintrag aus `/models`, statt Anbieter oder Modell-ID zu raten. Die Auswahl gilt für die aktuelle Session
und ändert deine Konfiguration nicht.

```text
anthropic/claude-sonnet-5-5
```

Die Verfügbarkeit ist projektspezifisch:

- Das Modell muss aktiviert sein.
- Sein Anbieter muss im aktuellen Projekt verfügbar sein.
- Zugangsdaten und Konfiguration aus einem anderen Projekt werden nicht automatisch übernommen.

## Läufe

Nutze `--model`, um ein Modell für einen Befehlszeilenlauf zu wählen, ohne den konfigurierten Standard zu ändern:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Agenten und Befehle können ebenfalls ihr eigenes Modell wählen. Siehe [Agenten](/agents) und [Befehle](/commands).

## Standards

Setze `model` in `opencode.json` oder `opencode.jsonc`, um den Standard für neue Arbeit zu wählen:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Das konfigurierte Modell wird zum Katalogstandard, wenn es aktiviert ist und sein Anbieter verfügbar ist. Andernfalls
fällt OpenCode auf das neueste verfügbare unterstützte Modell zurück.

- Ein bereits für eine Session gewähltes Modell hat Vorrang vor dem konfigurierten Standard.
- Das Wechseln des Modells einer Session schreibt die Konfigurationsdatei nicht um.
- Das oberste `model` behält derzeit nur Standard-Anbieter und -Modell, keine Variante.

Siehe [Konfiguration](/config) für Speicherorte und Rangfolge der Konfiguration.

## Kostenlose Modelle

Setze `OPENCODE_DISABLE_FREE_MODELS=1` (oder `true`) im Serverprozess, um [kostenlose OpenCode-Modelle](/console/models#free-models) auszublenden:

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

Für den gemeinsamen Hintergrundserver:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

Kostenlos bedeutet ein `opencode`- oder `opencode-go`-Modell ohne Input-Preis. Diese Modelle verschwinden aus Katalog und Standards;
die ausdrückliche Auswahl eines solchen schlägt mit `Model unavailable` fehl. Abgemeldet fehlt der Anbieter `opencode`, bis du
ein OpenCode Console-Konto verbindest oder `OPENCODE_API_KEY` setzt, was seine kostenpflichtigen Modelle wiederherstellt.

Um kostenlose Modelle für alle in einer Organisation zu blockieren, nutze stattdessen eine Policy. Siehe
[Enterprise](/enterprise#block-free-models).

## Varianten

Varianten sind benannte Optionen für ein Modell, oft für Reasoning-Effort oder Token-Budgets. Füge `#variant` hinzu, wenn du
eine für einen Lauf, eine Session, einen Agenten oder einen Befehl wählst:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

Variantennamen stammen aus den aktuellen Katalogmetadaten des gewählten Modells. Namen wie `low`, `high` und `max` sind nicht
für jedes Modell verfügbar, und eine unbekannte Variante erzeugt einen Modellauflösungsfehler.

Definiere neue Varianten oder ersetze Katalogvarianten mit derselben ID im `variants`-Array des Modells:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Jede Variante kann `settings`, `headers` und `body` enthalten. Ihre Werte werden nach Anbieter- und Modellwerten angewendet.

Um die Reasoning-Varianten eines Modells zu ersetzen, beschreibe seine Reasoning-Steuerung in `capabilities.reasoning` in der
v2-Form von [models.dev](https://models.dev). OpenCode baut daraus die Varianten für das Paket des Modells:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| Feld        | Zweck                                                                     |
| ----------- | ------------------------------------------------------------------------- |
| `supported` | Gibt an, ob das Modell Reasoning unterstützt. Bei `false` oder bei `true` ohne weitere Reasoning-Einstellungen kommen keine Varianten hinzu. |
| `toggle`    | Fügt eine Variante `none` hinzu, die Reasoning abschaltet.               |
| `effort`    | Anzubietende Effort-Stufen. `default` behält den Anbieterstandard und fügt keine Variante hinzu. |
| `budget`    | Optionale `min` und `max` Thinking-Tokens. Wird ignoriert, wenn `effort` gesetzt ist. |

In `variants` aufgeführte Varianten werden zusätzlich zu denen angewendet, die aus `capabilities.reasoning` gebaut wurden.

## Optionen

Anbieter- und Modelleinträge können Anfragen mit `settings`, `headers` und `body` anpassen:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Feld       | Zweck                                                            |
| ---------- | ---------------------------------------------------------------- |
| `settings` | Optionen des Anbieterpakets wie `baseURL` oder `reasoningEffort`. |
| `headers`  | Zusätzliche HTTP-Request-Header.                                 |
| `body`     | Anbieterspezifische Request-Body-Felder.                         |

OpenCode wendet zuerst Anbieterwerte, dann Modellwerte und zuletzt die gewählte Variante an.

- Verschachtelte `settings`- und `body`-Objekte werden zusammengeführt.
- Spätere Arrays und skalare Werte ersetzen frühere Werte.
- Header-Namen werden ohne Beachtung der Groß- und Kleinschreibung abgeglichen.
- Optionen sind anbieterspezifisch und können von einem anderen Anbieterpaket ignoriert oder abgelehnt werden.

## Aliase

Nutze `modelID`, um einem API-Modell eine freundlichere Katalog-ID zu geben:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Hier ist `openai/coding-default` die wählbare Referenz und `gpt-6.1-sol` wird an den Anbieter gesendet. Für ein Modell, das noch
nicht im Katalog ist, nimmt OpenCode an:

- JSON-Tool-Unterstützung, Text- und Bildeingabe sowie Textausgabe. Keine freie Tool-Eingabe, sofern `capabilities.freeform` das Format nicht aufführt.
- Ein Kontextlimit von 200.000 Tokens und ein Ausgabelimit von 32.000 Tokens.
- Kein festgelegtes Eingabelimit.

OpenCode erkennt `text`, `regex` und `lark`. Andere Formatnamen von models.dev werden ignoriert, ohne das Modell oder seine Tools zu verwerfen. Wenn ein Proxy vor einem Katalogmodell freie Tools ablehnt, setze `capabilities.freeform` für dieses Modell auf `[]`.

Das sind Fallback-Annahmen, keine erkannten Fähigkeiten. Setze genaue `capabilities`- und `limit`-Werte, wenn du sie kennst;
ausdrückliche Werte ersetzen die Fallbacks. Füge `disabled: true` hinzu, um ein Modell aus dem verfügbaren Katalog auszublenden:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Reasoning

Für ein OpenAI-kompatibles Modell, das Reasoning in einem eigenen Feld der Assistenten-Nachricht streamt, setze
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode erkennt `reasoning`, `reasoning_content` und `reasoning_text` und akzeptiert außerdem einen anderen anbieterspezifischen
String. Es liest gestreamtes Reasoning aus diesem Feld und stellt das Feld wieder her, wenn frühere Assistenten-Nachrichten an
das Modell zurückgesendet werden. Siehe [Kompatibilität](#compatibility) für das verwandte Feld `requireReasoning`.

## Prompt-Caching

OpenCode setzt Prompt-Cache-Breakpoints automatisch auf Routen, die bekanntermaßen welche brauchen, etwa Anthropic. Wenn
Claude-Modelle über einen OpenAI-kompatiblen Proxy wie LiteLLM bereitgestellt werden, kann OpenCode nicht erkennen, dass sie
Anthropic-artige `cache_control`-Breakpoints brauchen. Setze `compatibility.cacheFormat` für diese Claude-Modelle:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

OpenCode markiert dann die letzte Tool-Definition, den System-Prompt und die letzte Nachricht mit
`cache_control: { "type": "ephemeral" }`, was die Standard-Cache-Lebensdauer von fünf Minuten des Endpunkts nutzt. Nutze `"alibaba"`
für Modelle von Alibaba Model Studio, die dieselben Marker akzeptieren, sie bei Tool-Definitionen aber ignorieren. Setze
`compatibility.cacheFormat` stattdessen am Anbieter, wenn jedes von ihm bereitgestellte Modell dasselbe Format akzeptiert. Siehe
[Kompatibilität](#compatibility) für die anderen Felder.

### Cache-Lebensdauer

OpenCode sendet standardmäßig keine Cache-Lebensdauer, daher nutzt jeder Anbieter seinen eigenen Standard, etwa fünf Minuten bei
Anthropic. Setze `settings.cache.ttl` an einem Anbieter oder Modell, um eine andere anzufordern. Eine Modelleinstellung überschreibt die
Anbietereinstellung.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

`ttl` nimmt eine Zahl und eine Einheit: `ms`, `s`, `m`, `h` oder `d`, etwa `"5m"`, `"1h"` oder `"24h"`. OpenCode sendet sie wie
angegeben, nutze also einen Wert, den der Anbieter akzeptiert:

| API | Wohin die Lebensdauer geht |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` an jedem Cache-Marker. Anthropic akzeptiert `"5m"` und `"1h"`. |
| Bedrock Converse | `ttl` an jedem `cachePoint`. Ältere Claude-Modelle, die nur fünf Minuten cachen, ignorieren `"1h"`. |
| OpenAI Chat und Responses | `"24h"` geht an `prompt_cache_retention`; andere Werte gehen an `prompt_cache_options.ttl`. |

Anbieter, die automatisch ohne Marker cachen, etwa Gemini, ignorieren sie. Eine längere Lebensdauer kostet beim Schreiben meist mehr:
Anthropic berechnet beim Schreiben in den Cache das Zweifache des Eingabepreises für eine Stunde Cache-Lebensdauer und
das 1,25-Fache für fünf Minuten.

[Warming](/warming) kann die Lebensdauer nutzen, um seine Anfragen mit `interval: "auto"` zu timen.

## Kompatibilität

`compatibility` beschreibt Eigenheiten von Anfrage und Antwort der API, über die ein Modell bedient wird, etwa welches Feld
Reasoning trägt oder ob der Endpunkt `prompt_cache_key` akzeptiert. Jedes Modell wird über eine API bedient, und ein Feld
wirkt nur, wenn diese API es liest. Andere Felder werden ignoriert.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

`compatibility` des Anbieters gilt für jedes Modell dieses Anbieters. Das eigene `compatibility` eines Modells überschreibt es Feld
für Feld: OpenCode startet mit den Werten, die [models.dev](https://models.dev) für die API des Modells veröffentlicht (`reasoningField`,
`maxTokensField` und `mediaInput` sowie `supportsEffortUpdates` und `supportsSystemUpdates`, wenn models.dev die
API als unterstützend markiert), und wendet dann die Konfiguration des Modells an. Nicht gesetzte Felder behalten den eingebauten
Standard oder die Erkennung des Anbieterpakets. `supportsThinkingBlockBinding`, `supportsEffortUpdates` und `supportsSystemUpdates` sind
nur modellspezifisch.

| Feld | Was es tut | Gelesen von | Werte und Standard |
| --- | --- | --- | --- |
| `reasoningField` | Feld der Assistenten-Nachricht, das Reasoning trägt. Wird zuerst geprüft, wenn gestreamtes Reasoning gelesen wird, und beim Zurücksenden früheren Reasonings genutzt. | OpenAI Chat | Jeder Feldname außer `role`, `content`, `refusal` oder `tool_calls`. Ungesetzt nutzt es das im Stream gesehene Feld, sonst `reasoning_content`. |
| `requireReasoning` | Sendet das Reasoning-Feld bei jeder früheren Assistenten-Nachricht, als leeren String, wenn es kein Reasoning gab. | OpenAI Chat | `true` oder `false`. Standard ist `true`, wenn `reasoningField` gesetzt ist oder das Modell DeepSeek ist, sonst `false`. |
| `maxTokensField` | Body-Feld, das das Output-Token-Limit trägt. | OpenAI Chat | `max_completion_tokens` oder `max_tokens`. Ungesetzt erkennt es `max_tokens` für Anbieter, die es brauchen, etwa DeepSeek, Moonshot, Together AI, Z.AI und Cerebras, sonst `max_completion_tokens`. |
| `requireFinishReason` | Behandelt einen Stream, der ohne `finish_reason` endet, als Fehler einer unvollständigen Antwort. `false` akzeptiert ihn als beendet. | OpenAI Chat | `true` oder `false`. Standard ist `true`. |
| `requireAssistantAfterTool` | Fügt eine Assistenten-Nachricht zwischen ein Tool-Ergebnis und die nächste Nutzernachricht ein, für Endpunkte, die diese Reihenfolge ablehnen. | OpenAI Chat | `true` oder `false`. Standard ist `true` für Modell-IDs der Mistral-Familie, sonst `false`. |
| `supportsPromptCacheKey` | Ob der Endpunkt das Body-Feld `prompt_cache_key` akzeptiert. | OpenAI Chat, OpenAI Responses, Mistral | `true` oder `false`. OpenAI Chat sendet den Schlüssel nur bei `true`, was manche Anbieterpakete standardmäßig setzen. Andere APIs senden ihn, sofern nicht `false`. |
| `streamUsage` | Fordert Token-Nutzung im Stream mit `stream_options.include_usage` an. | OpenAI Chat | `true` oder `false`. Standard ist `true`. |
| `cacheFormat` | Syntax der Prompt-Cache-Marker, die der Endpunkt akzeptiert. Überschreibt die automatische Breakpoint-Platzierung des Anbieters. `alibaba` überspringt Tool-Definitionen. | Jede API mit Prompt-Cache-Markern, einschließlich OpenAI Chat, Anthropic Messages und Bedrock Converse | `anthropic` oder `alibaba`. Ungesetzt nutzt es den Anbieterstandard. Siehe [Prompt-Caching](#prompt-caching). |
| `supportsThinkingBlockBinding` | Bittet die API, Thinking-Blöcke zu verwerfen, deren früherer Kontext sich geändert hat, statt die Anfrage abzulehnen. | Anthropic Messages, Bedrock Converse | `true` oder `false`. Ungesetzt erkennt es Claude 5.1 und neuer. |
| `supportsEffortUpdates` | Sendet Änderungen des Reasoning-Efforts als Updates pro Nachricht, die den Prompt-Cache bewahren. Andernfalls ändert sich der Effort für die ganze Anfrage. | Anthropic Messages, OpenAI Responses | `true` oder `false`. Ungesetzt erkennt es Claude Opus 5, Claude 5.1 und neuer sowie GPT-6 und neuer. |
| `supportsSystemUpdates` | Sendet Systemnachrichten, die mitten in der Unterhaltung hinzugefügt werden, als native Systemnachrichten. Andernfalls werden sie als Text in den nächsten Nutzer-Turn eingebettet. | Anthropic Messages | `true` oder `false`. Ungesetzt erkennt es Claude Opus 4.8 und Claude 5 und neuer. |
| `mediaInput` | Wohin Bilder und andere Medien in einer Entscheidungsanfrage gehen. | System One | `assets` (Bilder, auf die aus dem State verwiesen wird), `state` (inline im State) oder `root` (Listen `images`, `audio` und `videos` auf oberster Ebene). Ungesetzt nutzt es den Anbieterstandard. |

## Lokal

OpenCode entdeckt Modelle von Ollama, LM Studio und vLLM automatisch an ihren lokalen Standardadressen. Du kannst auch
jeden OpenAI-kompatiblen Server von Hand konfigurieren.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Wenn Ollama auf `http://127.0.0.1:11434` lauscht, wähle ein entdecktes Modell mit der Anbieter-ID `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode aktualisiert das Inventar im Hintergrund und liest Kontext-, Vision- und Tool-Fähigkeiten aus Ollama.
Reine Embedding-Modelle werden ausgeschlossen.

Für einen anderen Host oder Port setze die OpenAI-kompatible URL von Ollama. Die Entdeckung nutzt weiterhin die native Ollama-API am selben
Pfadpräfix:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Lass `apiKey` weg, wenn der Endpunkt keine Bearer-Authentifizierung verlangt.
- Deaktiviere die Entdeckung mit `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Wenn ein nicht authentifizierter LM Studio-Server auf `http://127.0.0.1:1234` läuft, wähle ein entdecktes Modell mit der Anbieter-ID
`lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode aktualisiert das Inventar im Hintergrund und liest Kontext-, Vision- und Tool-Fähigkeiten aus LM Studio.
Embedding-Modelle werden ausgeschlossen.

Für einen anderen Host oder Port setze die OpenAI-kompatible URL. Modelle werden weiterhin automatisch entdeckt:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Lass `apiKey` weg, wenn die Authentifizierung von LM Studio deaktiviert ist.
- Deaktiviere die Entdeckung mit `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Wenn vLLM auf `http://127.0.0.1:8000` lauscht, wähle ein entdecktes Modell mit der Anbieter-ID `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode prüft `/health`, aktualisiert `/v1/models` im Hintergrund, nutzt das gemeldete `max_model_len` als Kontext-
limit und schließt nur Modellkarten ein, die `vllm` gehören.

Entdeckte Modelle werben mit Text-Eingabe und -Ausgabe, aber nicht mit Vision oder Tools. vLLM aktiviert Tool-Aufrufe mit Server-Flags
wie `--enable-auto-tool-choice` und `--tool-call-parser`, die die Entdeckung nicht meldet.

Für einen anderen Endpunkt oder einen authentifizierten Server setze seine OpenAI-kompatible URL:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Lass `apiKey` weg, wenn die Authentifizierung deaktiviert ist.
- Deaktiviere die Entdeckung mit `"plugins": ["-opencode.provider.vllm"]`.
- Proxys mit Pfadpräfix werden unterstützt. `https://example.com/vllm/v1` prüft zum Beispiel `/vllm/health` und entdeckt
  `/vllm/v1/models`.

### Kompatibel

Definiere für einen anderen OpenAI-kompatiblen Server sein Anbieterpaket, seinen Endpunkt und mindestens ein Modell:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Nutze den echten Modellnamen des Servers, seine Limits, Eingabe- und Ausgabetypen und Tool-Unterstützung. OpenCode kann nicht erkennen, ob die
Fallback-Werte für eigene Modelle korrekt sind. Wenn der Endpunkt einen Schlüssel verlangt, füge `apiKey` zu `settings` mit einer Umgebungs-
ersetzung wie `"apiKey": "{env:LOCAL_API_KEY}"` hinzu; committe keine Geheimnisse.

## Referenzen

Modellwähler nutzen `provider/model` mit optionaler `#variant`:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| Teil       | Regel                                                      |
| ---------- | ---------------------------------------------------------- |
| Anbieter   | Endet am ersten `/`; darf kein `/` oder `#` enthalten.     |
| Modell     | Darf weitere `/`-Zeichen enthalten; darf kein `#` enthalten. |
| Variante   | Folgt auf `#`, wenn vorhanden.                             |
| Groß-/Kleinschreibung | Anbieter- und Modell-IDs unterscheiden zwischen Groß- und Kleinschreibung. |

Nutze Katalog-IDs statt Anzeigenamen von Anbietern. Die `model`-Felder auf oberster Ebene, von Agenten und Befehlen akzeptieren die obige String-Form
oder ein ausgeschriebenes Objekt:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}
```

Die ausgeschriebene Form ist für generierte oder programmatische Konfiguration nützlich.

## Hinweise

Behalte diese Regeln beim Konfigurieren von Modellen im Kopf:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- Ein Wählerobjekt nutzt `model`; ein Anbieterkatalogeintrag nutzt `modelID` für die an den Anbieter gesendete ID.
- Obwohl die Auswahlform auf oberster Ebene eine Variante akzeptiert, behält der V2-Katalogstandard sie nicht. Wähle Varianten für eine
  Session, einen Lauf, einen Agenten oder einen Befehl.
- Modelloptionen sind anbieterspezifisch. Ein anderes Anbieterpaket kann sie ignorieren oder ablehnen.
- Katalogdaten, Zugangsdaten und Konfiguration sind an die Location gebunden. Ein Modell, das in einem Projekt verfügbar ist, kann in
  einem anderen nicht verfügbar sein.
- Konfigurationsdateien laden normalerweise automatisch neu. Eine bereits laufende Modellanfrage behält die Einstellungen, mit denen sie
  gestartet ist.
