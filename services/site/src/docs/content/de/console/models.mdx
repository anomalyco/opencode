OpenCode Console bietet Modelle, die das OpenCode-Team getestet und verifiziert hat. Melde dich an, lade
Guthaben auf und rufe deinen API-Schlüssel ab, um sie in OpenCode oder einem anderen Coding-Agenten zu nutzen.

Die Console funktioniert wie jeder andere Anbieter in OpenCode. Sie ist **völlig optional**, und du kannst stattdessen
jeden anderen Anbieter nutzen. Für ein Abo mit enthaltener Nutzung siehe [OpenCode Go](/console/go).

## So funktioniert es

1. Melde dich in der [Console](https://opencode.ai/console) an, füge deine Rechnungsdaten und Guthaben hinzu und kopiere
   deinen API-Schlüssel.
2. Führe `/connect` in der TUI aus, wähle den Pay-as-you-go-Anbieter von OpenCode und füge deinen API-Schlüssel ein.

   ```text
   /connect
   ```

3. Führe `/models` aus, um die verfügbaren Modelle zu sehen und eines zu wählen.

   ```text
   /models
   ```

Die Kosten fallen pro Anfrage an. Du kannst dein Kontoguthaben aufladen.

## Endpunkte

Du kannst die Modelle auch direkt über die folgenden API-Endpunkte aufrufen. Chatmodelle des Free-Tarifs sind
nur in OpenCode verfügbar. Nutze in anderen Clients kostenpflichtige Modelle oder [Go](/console/go).

Für jedes Modell ist die native API angegeben. Alle Textmodelle funktionieren auch über die anderen APIs, für
die die Console die Anfragen übersetzt. Unter [Basis-URLs](/console/harnesses#base-urls) findest du die
vollständige Liste.

### Modellliste

Rufe die vollständige Liste der verfügbaren Modelle und ihrer Metadaten vom Modellendpunkt ab:

```bash
curl https://opencode.ai/inference/v1/models
```

Siehe die [Modelllisten-API](/console/api/models) für jedes Feld der Antwort und für die Console-Liste, die auch die
Anbieter enthält, die dein Workspace verbunden hat.

### Jev

Jev ist ein System-One-Modell von TypeSafe AI für schnelle, strukturierte Entscheidungen. Statt Text zu
generieren, wertet es einen `state` anhand typisierter Fragen aus und liefert Werte und Wahrscheinlichkeiten,
die dein Code direkt nutzen kann. Es unterstützt Ja/Nein-Fragen (`noul`), Multiple-Choice-Fragen (`choice`)
und Fragen mit Bewertungsraster (`score`).

Nutze deinen OpenCode Console API-Schlüssel mit dem Endpunkt `https://opencode.ai/inference/systemone/v1/systemone`.
Dieses Beispiel prüft, ob eine Support-Anfrage dringend ist:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Du kannst mehrere Fragen in einer Anfrage stellen. Jev bewertet sie parallel und gibt jede Antwort unter der passenden
Frage-ID zurück:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Mit `jev-1.13-free` nutzt du die zeitlich begrenzt kostenlose Variante von Jev 1.13. Details zu Fragetypen und
Antwortfeldern findest du in der [Dokumentation von TypeSafe AI](https://docs.typesafe.ai/).

### GPT 6 Luna Decision und Gemini Decision 1

`gpt-6-luna-decision` und `gemini-decision-1` nehmen dieselbe System-One-Anfrage wie Jev am selben Endpunkt. Übergib
Bilder, Audio, Video und PDFs in `state` als Chat-ähnliche Teile (`image_url`, `input_audio`, `video_url`, `file`).
GPT 6 Luna Decision akzeptiert Text und Bilder; Gemini Decision 1 akzeptiert zusätzlich Audio, Video und PDFs.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### Bildmodelle

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` und `grok-imagine-image-2.0` generieren und bearbeiten Bilder. Sie
sind keine Chat-Modelle, erscheinen daher nie in `/models` oder am Modellendpunkt, und `opencode/<model-id>` wählt sie
nicht aus. Rufe sie über ihre native API mit einem Console-Schlüssel auf, oder lass das
[`generate_image`](/tools#image-generate)-Tool von OpenCode ein Bildmodell nutzen, indem du
`experimental.image_generate.model` setzt, zum Beispiel `opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google nimmt seine nativen `contents` und `generationConfig`, xAI seine nativen Optionen wie `resolution` und
`quality`. OpenAI Images und xAI Images akzeptieren Bearbeitungen außerdem unter `/images/edits`.

### Embedding-Modelle

`text-embedding-3-small`, `qwen3-embedding-8b` und die anderen Embedding-Modelle in der Tabelle oben wandeln Text in
Vektoren um. OpenCode nutzt sie nicht für Chat, daher erscheinen sie nie in `/models`, und der Free-Tarif enthält sie
nicht. [Go](/console/go#embedding-models) enthält einige davon. Rufe sie über die Embeddings API von OpenAI mit einem
Console-Schlüssel auf.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` nimmt einen String oder ein Array von Strings. `data` gibt einen Vektor pro Eingabe zurück, in derselben
  Reihenfolge.
- `dimensions` verkürzt die Vektoren bei Modellen, die das unterstützen, etwa `text-embedding-3-small`.
- `encoding_format: "base64"` gibt die Vektoren base64-kodiert statt als Fließkommazahlen zurück.
- Jede Eingabe muss in das Kontextfenster des Modells passen.
- Die Antwort meldet `usage.cost` wie jede Inference-Anfrage. Siehe [Kosten](/console/api/inference#cost).

Vektoren verschiedener Modelle sind nicht vergleichbar. Verwende daher für die Embeddings deiner Dokumente und
Abfragen dasselbe Modell. Ein [verbundener Anbieter](/console/api/providers#endpoints) stellt seine eigenen
Embedding-Modelle unter `/embeddings` bereit.

Um diesen Katalog aufzubauen, haben wir:

1. ausgewählte Modelle getestet und mit ihren Teams besprochen, wie sich die Modelle am besten betreiben
   lassen.
2. mit Anbietern zusammengearbeitet, um sicherzustellen, dass die Modelle korrekt bereitgestellt werden.
3. jede Kombination aus Modell und Anbieter gebenchmarkt, um eine Liste zu erstellen, die wir guten Gewissens empfehlen.

Die Console ist ein AI-Gateway, das dir Zugriff auf diese Modelle gibt.

## Ziele

Wir haben die Console gebaut, um:

1. die besten Modelle und Anbieter für Coding-Agenten zu **benchmarken**.
2. Optionen in **höchster Qualität** anzubieten, ohne die Leistung zu mindern oder Anfragen an günstigere
   Anbieter weiterzuleiten.
3. **Preissenkungen** weiterzugeben, indem wir zum Selbstkostenpreis abrechnen und nur die Bearbeitungsgebühr
   aufschlagen.
4. **Dich nicht an einen Anbieter zu binden**: Nutze die Console mit einem beliebigen Coding-Agenten oder
   einen anderen Anbieter mit OpenCode.
