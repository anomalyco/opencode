Setze die Standard-Proxy-Variablen und schließe Loopback-Adressen aus. OpenCode nutzt lokale HTTP-Verbindungen zwischen
der CLI und ihrem Hintergrunddienst, daher ist der Loopback-Ausschluss nötig, wenn im CLI-Umfeld ein Proxy konfiguriert
ist.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` behandelt HTTP-Ziele und `HTTPS_PROXY` HTTPS-Ziele. Die Proxy-URL selbst kann `http://`
für beide Variablen verwenden. `NO_PROXY` ist eine kommagetrennte Liste von Hosts und Adressen, die direkt verbinden.

## Dienst

Shell-Exporte wirken auf einen Hintergrunddienst nur, wenn dieser Dienst aus der Shell startet. Speichere die Variablen
in der verwalteten Dienstkonfiguration, damit spätere Dienststarts dieselben Netzwerkeinstellungen verwenden.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Das Ändern einer verwalteten Umgebungsvariable stoppt den laufenden Dienst. `service start` startet ihn erneut mit der
neuen Umgebung. Behalte `NO_PROXY` auch in der CLI-Shell, wenn diese Shell einen Proxy setzt, weil verwaltete
Dienstvariablen für den Serverprozess gelten, nicht für den CLI-Prozess.

Entferne eine gespeicherte Variable mit `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Authentifizierung

Für einen Proxy, der Zugangsdaten in der URL akzeptiert, schließe Benutzername und Passwort in jede Proxy-URL ein, die
eine Authentifizierung erfordert. Verwende für Zeichen wie `@`, `:` und `/` im Benutzernamen oder Passwort die
Prozentkodierung.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Speichere für den Hintergrunddienst die vollständige URL. Der Wert liegt in der privaten Dienstkonfiguration und wird von
`opencode service get env` angezeigt, teile diese Ausgabe also nicht.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Zertifikate

Setze `NODE_EXTRA_CA_CERTS` auf eine PEM-Datei, wenn der Proxy oder das Ziel ein Zertifikat verwendet, das von einer
privaten Zertifizierungsstelle signiert wurde. Die zusätzlichen Zertifizierungsstellen werden beim Prozessstart zum
Trust Store der Laufzeit hinzugefügt.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Speichere den Dateipfad für den Hintergrunddienst und starte ihn dann neu:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Antivirus und HTTPS-Inspektion

„HTTPS-Scanning“ oder „Scan verschlüsselter Verbindungen“ von Antivirensoftware (Kaspersky, Avast, ESET und andere) und
SSL-Inspektionsproxys von Unternehmen ersetzen das Zertifikat des Servers durch ihr eigenes. OpenCode lehnt es ab, und
Anfragen schlagen mit Fehlern fehl wie:

```text
self signed certificate in certificate chain
SELF_SIGNED_CERT_IN_CHAIN
CERT_NOT_YET_VALID
CERT_SIGNATURE_FAILURE
```

Behebe das auf eine von zwei Arten:

- Schließe `opencode.ai` und `*.opencode.ai` in den Antivirus-Einstellungen vom HTTPS-Scanning aus. Füge auch den
  API-Host deines Anbieters hinzu, etwa `api.anthropic.com`, wenn du dich direkt mit einem Anbieter verbindest.
- Exportiere die Zertifizierungsstelle der Inspektion als PEM-Datei und vertraue ihr mit `NODE_EXTRA_CA_CERTS`, wie unter
  [Zertifikate](#certificates) gezeigt.

## Client-Zertifikate

Setze `settings.tls` auf einem Anbieter, dessen Gateway gegenseitiges TLS verlangt. Seine Modellanfragen legen das
Zertifikat vor, und der TLS-Handshake sendet es nur an Server, die eines anfordern.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "company": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.company.example/v1",
        "tls": {
          "cert": "{file:/etc/company/client.pem}",
          "key": "{file:/etc/company/client.key}",
          "passphrase": "{env:CLIENT_KEY_PASSPHRASE}",
        },
      },
    },
  },
}
```

- `cert` und `key` sind PEM-Text. Nutze `{file:...}`, um sie aus Dateien zu lesen. Eine Datei, die nicht gelesen werden
  kann, lässt `tls` ungesetzt.
- `passphrase` ist nur für einen verschlüsselten Schlüssel nötig.
- Funktioniert in den Bun- und Node-Builds. Ein Server auf Cloudflare Workers kann über `fetch` kein Client-Zertifikat
  vorlegen.
- Anfragen mit einem Client-Zertifikat folgen keinen Weiterleitungen, daher wird das Zertifikat keinem anderen Host
  vorgelegt.

Jede Modellanfrage dieses Anbieters legt das Zertifikat vor: Chat, Compaction, Bild- und Entscheidungsmodelle. Ein Anbieter
mit `tls` nutzt HTTP statt WebSockets. Tools wie Webfetch, entfernte MCP-Server und Plugin-Installationen legen es nicht
vor.

## Vordergrund

`--standalone` und `serve` nutzen die Umgebung ihres eigenen Prozesses. `opencode service set env` konfiguriert diese
Prozesse nicht.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Wende dasselbe Muster auf einen Vordergrundserver an:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Prüfen

Prüfe, ob die CLI den Hintergrunddienst nach dem Anwenden der Einstellungen erreichen kann:

```bash
opencode api get /api/info
```

Eine erfolgreiche Health-Antwort bestätigt die lokale Verbindung vom Client zum Dienst. Führe eine normale
Anbieteranfrage aus, um den ausgehenden Proxy- und Zertifikatspfad des Dienstes zu prüfen.
