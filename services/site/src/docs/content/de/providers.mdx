OpenCode enthält einen Anbieter- und Modellkatalog von [models.dev](https://models.dev). Verbinde für die meisten Anbieter
zuerst ein Konto und wähle dann ein Modell.

## Einrichtung

Führe `/connect` aus, wähle einen Anbieter und gib seine Zugangsdaten ein. Führe dann `/models` aus, um eines seiner Modelle zu wählen.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) ist ein optionales Abo für Coding-Modelle, die das OpenCode-Team getestet hat. Abonniere es in der
[Console](https://opencode.ai/console), kopiere deinen API-Schlüssel und verbinde **OpenCode Go** mit diesem Schlüssel.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

Siehe die [Go-Anleitung](/console/go) für Nutzungslimits, Endpunkte und Datenschutzdetails.

## ChatGPT

Nutze ChatGPT Plus oder ChatGPT Pro statt eines API-Schlüssels von OpenAI. Verbinde **OpenAI** und wähle dann **Sign in with ChatGPT**
oder eine der älteren **Codex**-Anmeldemethoden. Die Nutzung wird auf deinen Tarif angerechnet, daher zeigt OpenCode
für diese Modelle keine Kosten an.

```text
/connect
/models
```

### Kontextlimits

Bei diesen Anmeldemethoden setzt OpenCode das Kontextlimit standardmäßig niedriger an als das tatsächliche Limit des jeweiligen Modells.
Die Limits entsprechen den Standardwerten in Codex, damit du dein Tarifkontingent ähnlich schnell ausschöpfst wie in
anderen OpenAI-Produkten.

| Modell                | Eingabelimit |
| --------------------- | ----------- |
| GPT-6.1 Sol und neuer | 500.000     |
| Ältere Modelle        | 272.000     |

Wenn du das volle Kontextfenster nutzen möchtest, deaktiviere das Plugin für die Kontextbegrenzung in deiner Konfiguration.
Das Präfix `-` schaltet ein integriertes Plugin aus. Alle anderen Plugins bleiben aktiviert.

```jsonc title="opencode.jsonc"
{
  "plugins": ["-opencode.provider.openai-context-caps"],
}
```

## Eigene Anbieter

Füge einen Anbieter hinzu, wenn seine API noch nicht im Katalog steht. Dieses Beispiel für einen OpenAI-kompatiblen
Anbieter legt die Zugangsdaten, das Laufzeitpaket, den Endpunkt und das erste Modell fest.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

Im Objekt `providers` dient die Anbieter-ID als Schlüssel. Dieselbe ID steht in Modellreferenzen wie `acme/qwen3-coder`.

| Feld | Zweck |
| --- | --- |
| `name` | Anzeigename. |
| `env` | Namen der Umgebungsvariablen, aus denen OpenCode in der angegebenen Reihenfolge Zugangsdaten lesen kann. |
| `package` | Laufzeitpaket des Anbieters. |
| `canonical` | ID des integrierten Anbieters, von dem dieser Anbieter die Katalogvorgaben übernimmt. |
| `compatibility` | API-Besonderheiten, die für alle Modelle dieses Anbieters gelten. Siehe [Kompatibilität](/models#compatibility). |
| `settings` | Typisierte OpenCode-Einstellungen und JSON-Optionen für das Laufzeitpaket. |
| `headers` | HTTP-Header mit String-Werten, die Anfragen hinzugefügt werden. |
| `body` | JSON-Felder, die OpenCode in den Anfrage-Body übernimmt. |
| `models` | Modelle, die du hinzufügst oder überschreibst. Als Schlüssel dient die OpenCode-Modell-ID. |

## Endpunkt

Überschreibe `settings.baseURL`, um Anfragen an einen Anbieter aus dem Katalog über einen Proxy oder einen kompatiblen
Endpunkt zu leiten. Paket, Modelle und Verbindung des Anbieters bleiben unverändert.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` ist paketspezifisch. Ein Feld wirkt nur, wenn das gewählte Paket es unterstützt.

## Anfragen

Nutze `headers` für zusätzliche HTTP-Header und `body` für JSON-Felder, die OpenCode in jeden Anfrage-Body übernehmen soll.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

Wenn die Änderung nur für einen Teil der Anfragen an den Anbieter gelten soll, setze die Felder für das jeweilige Modell
oder die Variante.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Timeouts

Bei HTTP-Anfragen wartet OpenCode bis zu fünf Minuten auf die Antwort-Header und bis zu fünfzehn Minuten zwischen
zwei Abschnitten einer gestreamten Antwort. Gib für `settings.headerTimeout` oder `settings.chunkTimeout` des Anbieters
einen Wert in Millisekunden an, um das jeweilige Limit zu ändern, oder `false`, um es abzuschalten. Mit `settings.timeout`
kannst du zusätzlich die Gesamtdauer vom Absenden der Anfrage bis zum Ende der Antwort begrenzen. Dafür gibt es keinen
Standardwert. Diese Einstellungen gelten für den gesamten Anbieter, nicht einzeln für Modelle oder Varianten. Bei
WebSocket-Verbindungen begrenzt `chunkTimeout` stattdessen die Zeit zwischen Frames auf standardmäßig dreißig Minuten.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

Wird eines der Zeitlimits überschritten, schlägt die Anfrage mit einem Transportfehler fehl. OpenCode wiederholt
die Anfrage daraufhin bis zu drei Mal.

## Request-Kodierung

Mit `settings.encoding` komprimierst du HTTP-Anfrage-Bodys mit `"zstd"` oder `"gzip"`. Bei `"none"` sendet OpenCode
unkomprimiertes JSON. Du kannst die Option für einen Anbieter, ein Modell oder eine Variante setzen. Die spezifischste
Einstellung hat Vorrang. Wähle nur eine Kodierung, die der Endpunkt versteht: Die meisten Anbieter und Gateways lehnen
komprimierte Anfrage-Bodys ab. Bei der Anmeldung mit ChatGPT nutzt OpenAI standardmäßig `"zstd"`, sofern du keine eigene
`baseURL` konfiguriert hast. Bei der Anmeldung per API-Schlüssel sendet OpenCode unkomprimiertes JSON. Die Einstellung gilt nicht für WebSocket-Nachrichten.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## Pakete

Das Feld `package` wählt die Laufzeit, die mit einem Anbieter kommuniziert. Nutze die kompatible Laufzeit für APIs, die
das OpenAI-Anfrageformat implementieren.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

Zu den nativen Paketen gehören:

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/messages`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

Du kannst auch ein npm-Paket wie `@acme/opencode-provider` oder eine absolute `file://`-URL für ein lokales Paket nutzen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## Modelle

Im Objekt `models` eines Anbieters kannst du Modelle hinzufügen oder überschreiben. Der Schlüssel ist die Modell-ID,
die OpenCode verwendet. Mit `modelID` änderst du die ID, die OpenCode an den Anbieter sendet.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Coding",
        },
      },
    },
  },
}
```

| Feld | Zweck |
| --- | --- |
| `modelID` | Modell- oder Deployment-ID, die an den Anbieter gesendet wird. |
| `name` | Anzeigename. |
| `family` | Modellfamilie zur Gruppierung verwandter Modelle. |
| `type` | Was das Modell erzeugt: `chat`, `decision`, `image`, `video`, `realtime`, `embedding` oder `transcription`. Standard ist `chat`. Für Sessions stehen nur Chat-Modelle zur Auswahl. Echtzeitmodelle mit Sprachausgabe stehen für Voice zur Auswahl, sofern sie nicht mit `disabled: true` deaktiviert sind. |
| `releaseDate` | Veröffentlichungsdatum als `YYYY-MM-DD` oder `YYYY-MM`. |
| `package` | Abweichendes Laufzeitpaket für dieses Modell. Gib bei Transkriptionsmodellen das Transkriptionsprotokoll an, etwa `@opencode/ai/protocols/openai-transcription`. Bei Echtzeitmodellen entfällt das Feld, da Voice-Sessions direkt über die jeweilige API starten. |
| `settings` | OpenCode-Einstellungen für dieses Modell und paketspezifische JSON-Einstellungen. |
| `headers` | Zusätzliche Anfrage-Header mit String-Werten. |
| `body` | Zusätzliche JSON-Felder für den Anfrage-Body. |
| `capabilities` | Tool-Unterstützung, unterstützte Medientypen für Ein- und Ausgabe, Unterstützung für die Temperatur und Reasoning-Einstellungen. |
| `compatibility` | API-Eigenheiten für dieses Modell, die die des Anbieters überschreiben. Siehe [Kompatibilität](/models#compatibility). |
| `variants` | Benannte Varianten mit eigenen `settings`, `headers` und `body`. |
| `cost` | Preise pro Million Eingabe- und Ausgabetokens, optional auch für Cache-Zugriffe. |
| `limit` | Token-Limits für Kontext, Eingabe und Ausgabe. |
| `disabled` | Entfernt das Modell aus der Auswahl, wenn `true`. |

Siehe [Modelle](/models) für Auswahl, Standards, Fähigkeiten, Limits, Kosten und Varianten.

## Azure

Der Standard-Katalogendpunkt von Azure braucht zusätzlich zu seinen Zugangsdaten einen Ressourcennamen. Setze `settings.resourceName`
einmal und verbinde dann einen API-Schlüssel oder nutze die Microsoft Entra ID-Session aus der Azure CLI, wie unter
[Anbieterkonten](/cli/providers) beschrieben.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

Den **Resource name** findest du im [Azure portal](https://portal.azure.com/) oder in
[Microsoft Foundry](https://ai.azure.com/). Er ist auch der erste Teil von Endpunkten wie
`https://my-models.openai.azure.com/` und `https://my-models.services.ai.azure.com/`.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Um Entra ID zu nutzen, installiere die [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli), melde dich an und
wähle beim Verbinden von Azure **Microsoft Entra ID (Azure CLI)**.

```bash
az login
```

Gib den Ressourcennamen beim Verbinden ein, wenn er nicht bereits in der Konfiguration oder der Umgebung hinterlegt ist.
Ein für die Verbindung gespeicherter Ressourcenname hat Vorrang vor der Konfiguration. Stelle die Verbindung erneut her,
wenn du ihn ändern willst.

Verbindungen über die Azure CLI nutzen das dort ausgewählte Konto. Liegt eine Ressource in einem anderen Mandanten
oder Abo, gib sowohl den Mandanten als auch das Abo ausdrücklich an.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

Du kannst den Ressourcennamen für den OpenCode-Server statt in der Konfiguration über `AZURE_RESOURCE_NAME` angeben. Die alte
Variable `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` funktioniert ebenfalls.

### Deployments

Azure stellt Modelle ausschließlich über Deployments bereit. Deshalb zeigt OpenCode statt des gesamten Azure-Katalogs
die Deployments deiner Ressource an. OpenCode lädt die Liste im Hintergrund, wenn du das Programm startest, die
Verbindung herstellst oder das Konto wechselst. Damit ein später hinzugefügtes Deployment erscheint, starte OpenCode
neu oder stelle die Verbindung erneut her.

- Bis die Liste für eine Verbindung geladen ist oder wenn das erste Laden fehlschlägt, bleibt der gesamte Katalog verfügbar.
- Schlägt das erneute Laden für dieselbe Verbindung fehl, behält OpenCode die letzte vollständige Liste bei.
- Beim Kontowechsel zeigt OpenCode nie die Liste des vorherigen Kontos an. Für das neue Konto ist zunächst der gesamte Katalog verfügbar.
- Deployments erben Limits, Kosten und Fähigkeiten von ihren Katalogmodellen.

Der Deployment-Name dient als Modell-ID, zum Beispiel `azure/gpt-production`. OpenCode verwendet Kleinbuchstaben,
weil Azure bei Namen nicht zwischen Groß- und Kleinschreibung unterscheidet. Ein nach seinem Modell benanntes
Deployment wie `gpt-6-luna` behält die Katalog-ID. Diese IDs bleiben
stabil, wenn andere Deployments hinzugefügt oder entfernt werden.

OpenCode gleicht ein Deployment anhand des von ihm bereitgestellten Modells mit dem Katalog ab oder anhand seines Namens, wenn Azure das Modell
anders schreibt, wie `gpt-4` für GPT-4 Turbo. Ein nach einem anderen Modell benanntes Deployment, etwa `gpt-6.1-sol`, das
`gpt-6-luna` bereitstellt, zeigt Name, Limits und Kosten dieses Modells.

Bei der Verbindung über die Azure CLI ruft OpenCode die Deployments über die Azure-Management-API ab. Dafür braucht
es Lesezugriff auf die Ressource. Schlägt der Abruf fehl oder nutzt du einen API-Schlüssel, fragt OpenCode die
ältere Deployment-Liste der Ressource ab. Es liest alle Seiten ein, bevor es die Liste bereitstellt. Mit einer
eigenen `settings.baseURL` bleibt der Katalog erhalten.

Konfiguriere ein Deployment ausdrücklich, wenn sein Modell nicht im Katalog steht, etwa nach einem Fine-Tuning,
oder wenn du selbst eine Modell-ID zuweisen willst. OpenCode nennt solche Deployments in einer Warnung im
Protokoll. Ausdrücklich konfigurierte Modelle bleiben immer erhalten.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-6-luna": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

Dein Konto braucht eine dieser Rollen:

- **Cognitive Services OpenAI User** für Azure OpenAI-Modelle.
- **Cognitive Services User** für andere Foundry-Modelle.

Wenn eine Anfrage ein Token aus dem falschen Mandanten nutzt, melde dich erneut im richtigen Mandanten an.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock sucht Zugangsdaten in der von AWS vorgegebenen Reihenfolge. Am einfachsten nutzt du dauerhaft
ein benanntes AWS-Profil. OpenCode unterstützt auch Zugriffsschlüssel aus Umgebungsvariablen, Web Identity und Container-Zugangsdaten.

```bash
aws configure sso --profile work
aws sso login --profile work
```

Wähle Profil und Region in den Anbietereinstellungen. Der Anbieter wird aktiviert, wenn `profile`, `AWS_PROFILE`,
`AWS_ACCESS_KEY_ID`, eine Datei mit einem Web-Identity-Token oder eine URI für Container-Zugangsdaten konfiguriert ist.
Eine Region allein reicht nicht.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

Ohne ausdrückliche Region nutzt OpenCode `AWS_REGION`, dann `AWS_DEFAULT_REGION`, dann `us-east-1`. Für einen privaten oder
VPC-Endpunkt setze `baseURL` und behalte dasselbe Profil und dieselbe Region.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Für Bedrock-API-Schlüssel gilt `AWS_BEARER_TOKEN_BEDROCK`. Andere AWS-Variablen dienen der Authentifizierung über
SigV4. OpenCode speichert sie nicht als API-Schlüssel-Konten.

## Vertex

Google Vertex nutzt Application Default Credentials (ADC). Seine Modelle stehen erst zur Verfügung, wenn du ein
Projekt angibst. Richte ADC lokal ein und gib dann in den Anbietereinstellungen das Projekt und den Standort an.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode kann das Projekt auch aus `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` oder
`GCLOUD_PROJECT` ermitteln, in dieser Reihenfolge. Für den Standort prüft es `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION`
und `VERTEX_LOCATION`. Ohne Angabe nutzt es `us-central1`.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

Service-Konten nutzen ebenfalls ADC. Setze `GOOGLE_APPLICATION_CREDENTIALS` auf den Pfad zur JSON-Datei des
Service-Kontos und gib zusätzlich ein Projekt in den Einstellungen oder über eine der Projektvariablen oben an.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Verwende für Gemini-, Anthropic- und OpenAI-kompatible Modelle aus dem Vertex-Katalog dieselbe Anbieter-ID `google-vertex`. Die alte
Anbieter-ID `google-vertex-anthropic` ist in V2 nicht verfügbar.

## Copilot

Bei GitHub Copilot meldest du dich per OAuth-Geräteanmeldung statt mit einem manuell eingegebenen API-Schlüssel an.
Verbinde **GitHub Copilot**, wähle GitHub.com oder GitHub Enterprise, schließe die Geräteanmeldung ab und öffne dann `/models`.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

Gib für GitHub Enterprise die Deployment-URL oder Domain ein, wenn danach gefragt wird. OpenCode nutzt einen von GitHub zurückgegebenen
Copilot-API-Endpunkt, wenn verfügbar; andernfalls leitet es den Endpunkt aus der Enterprise-Domain ab.

```text
company.ghe.com
```

Das verbundene Konto braucht Zugriff auf Copilot Chat. Meldet GitHub keine Berechtigung, melde dich für Copilot Free an oder bitte die
Organisation, dir eine Copilot-Lizenz zuzuweisen, und verbinde das Konto dann erneut. OpenCode ruft nach der Anmeldung die aktuelle Modellliste des Kontos ab
und immer, wenn sich das aktive Copilot-Konto ändert.

## Ollama

Starte Ollama und lade ein Modell. OpenCode prüft `http://127.0.0.1:11434`, entdeckt Completion-Modelle und fügt sie zu
`/models` hinzu, ohne Kontoverbindung.

```bash
ollama serve
ollama pull qwen3:8b
```

Gib unter `settings.baseURL` die Adresse des entfernten oder über einen Proxy erreichbaren Ollama-Servers an.
Die Adresse muss `/v1` enthalten. Daraus leitet OpenCode die nativen Pfade `/api/tags` und `/api/show` ab. Wenn
du `apiKey` angibst, sendet OpenCode den Schlüssel als Bearer-Token beim Abrufen der Modellliste und bei Modellanfragen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

OpenCode ruft die Modellliste regelmäßig ab. Bei einer vorübergehenden Störung bleibt die zuletzt erfolgreich
abgerufene Liste erhalten. Reine Embedding-Modelle erscheinen nicht, weil OpenCode nur Modelle hinzufügt, deren
Ollama-Metadaten die Fähigkeit `completion` enthalten.

## Laufzeiten

OpenCode erkennt auch lokale Modelle von LM Studio und vLLM automatisch. Ihre Standardendpunkte sind
`http://127.0.0.1:1234/v1` und `http://127.0.0.1:8000/v1`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

Die Sprachmodelle von LM Studio liest OpenCode aus `/api/v1/models`. Bei vLLM prüft OpenCode zuerst `/health`
und fragt dann `/v1/models` ab. Da OpenCode die Tool-Unterstützung dabei nicht ermitteln kann, sind Tools für
automatisch erkannte vLLM-Modelle zunächst deaktiviert. Richte andere OpenAI-kompatible Laufzeiten nach dem
Muster für [eigene Anbieter](#custom) ein und liste ihre Modelle ausdrücklich auf.

## Gateways

OpenRouter nutzt seine native Laufzeit und seinen Katalog. Stelle `OPENROUTER_API_KEY` für den OpenCode-Server bereit oder verbinde ein
OpenRouter-Konto und verweise dann mit der vollständigen OpenRouter-Modell-ID nach dem Anbieterpräfix auf Modelle.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-5.5",
}
```

Behalte das native OpenRouter-Paket, wenn du seinen Endpunkt überschreibst oder über ein OpenRouter-kompatibles Gateway routest.
Das bewahrt das Anfrage- und Reasoning-Verhalten von OpenRouter.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

Wenn ein Gateway eine OpenAI-kompatible API mit eigener Modellliste bereitstellt, richte stattdessen einen eigenen Anbieter ein.
Der Konfigurationsschlüssel wird zum Anbieterpräfix, und jeder `models`-Schlüssel wird zu einer wählbaren Modell-ID.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## Fehler

Fehlermeldungen zu Anbietern und Modellen zeigen meist, bei welchem Schritt das Problem aufgetreten ist.
Prüfe die Umgebung des Serverprozesses und die genaue Modell-ID, bevor du Pakete änderst.

| Fehler oder Symptom | Prüfen |
| --- | --- |
| `No model is available for session ...` | Kein aktiviertes Modell ist derzeit wählbar. Schließe die anbieterspezifische Einrichtung ab und wähle dann ein Modell in `/models`. |
| `Model unavailable: provider/model` | Der Anbieter ist inaktiv, die Modell-ID fehlt, das Modell ist deaktiviert oder die automatische Erkennung findet es nicht mehr. Prüfe bei eigenen Aliasen den Schlüssel im Objekt `models` statt `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | Ein `${NAME}`-Platzhalter bleibt in `baseURL`. Setze diese Variable auf dem OpenCode-Server oder ersetze die Vorlage durch einen vollständigen Endpunkt. |
| `Azure resource name is missing` | Setze `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` oder eine vollständige `settings.baseURL`. |
| Vertex erscheint nicht | Gib in den Anbietereinstellungen oder über eine unterstützte Projektvariable ein gültiges Projekt an. ADC allein aktiviert den Anbieter nicht. |
| Bedrock erscheint nicht | Gib ein Profil an oder stelle AWS-Zugangsdaten auf einem anderen unterstützten Weg bereit. `AWS_REGION` legt nur die Region fest. |
| Ollama hat keine Modelle | Bestätige, dass der Server `/api/tags` und `/api/show` am aus `baseURL` abgeleiteten Pfad bereitstellt und dass `/api/show` die Fähigkeit `completion` meldet. |
| Copilot hat keine Modelle | Bestätige, dass das aktive OAuth-Konto Copilot Chat-Zugriff hat. Eine fehlgeschlagene Modellsynchronisierung wird als `failed to sync GitHub Copilot models` protokolliert. |

V2 lehnt die alten Anbieter-IDs ab und nennt den jeweiligen Ersatz. Nutze `azure/<model>` statt
`azure-cognitive-services/<model>` und `google-vertex/<model>` statt `google-vertex-anthropic/<model>`.

## WebSockets

OpenAI, xAI und unterstützte Azure Responses-Modelle können eine WebSocket-Verbindung pro Session offen halten. Aufeinanderfolgende Schritte
nutzen das unveränderte Anfragepräfix wieder und senden nur Inhalte, die seit der vorherigen Antwort hinzugekommen sind, was Uploads in langen
Sessions reduziert.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

Das WebSocket-Verhalten folgt diesen Regeln:

- Jeder integrierte Anbieter entscheidet nach eigenen Regeln, für welche unterstützten Routen er WebSockets aktiviert.
- Mit `settings.transport: "websocket"` aktivierst du WebSockets für den Anbieter, mit `"http"` deaktivierst du sie.
- Steht bei `"websocket"` kein WebSocket-Kanal für die Route zur Verfügung, protokolliert OpenCode eine Warnung und nutzt HTTP.
- Die Compaction des OpenAI-Anbieters nutzt dieselbe Verbindung.
- xAI kann nur an gespeicherte Antworten anknüpfen. Bei der Standardeinstellung `store: false` sendet OpenCode jeden Schritt
  vollständig über dieselbe Verbindung.
- Wenn der Socket geschlossen ist, baut OpenCode beim nächsten Schritt eine neue Verbindung auf. Schlägt das fehl, läuft die Session über HTTP weiter.
- Anbieter-Plugins mit `http.request`- oder `http.response`-Hooks nutzen weiterhin HTTP, damit sich jede Anfrage nachvollziehen lässt.
