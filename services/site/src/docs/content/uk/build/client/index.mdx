`@opencode/client` — це TypeScript-клієнт для HTTP API OpenCode. Використовуйте
його, коли ваш застосунок підключається до сервера OpenCode через мережу. Його
нативні типи й методи згенеровано з того самого контракту, що й
[довідник API](/api). Типи RPC плагінів надходять з імпортованих визначень RPC.

## Встановлення

```sh
bun add @opencode/client
```

## Створення клієнта

Створіть клієнт з URL-адресою сервера, а потім викликайте методи, згруповані за ресурсами API:

```ts
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})
```

## Заголовки та запити

Передайте типові заголовки автентифікації або застосунку в `OpenCode.make` через
`headers`. Також можна передати власну реалізацію `fetch`. Кожна операція
приймає параметри запиту останнім аргументом — для `AbortSignal` або
заголовків окремого запиту. Виняток — підписки на події: вони приймають лише
скасування, локальне для підписника, і використовують заголовки базового клієнта.

```ts
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})
```

## Потокові події

Потокові ендпоінти повертають асинхронні ітерабельні об'єкти:

```ts
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}
```

У межах одного клієнта підписки на нативні події та події RPC використовують спільне з'єднання, яке відкривається
за потреби. Створення клієнта, дескриптора чи ітерабельного об'єкта не відкриває з'єднання: воно відкривається
на початку читання подій. Переривання ітерації або скасування підписки завершує лише відповідний ітератор.
Після від'єднання останнього підписника з'єднання закривається. Спільне джерело чекає, доки всі активні
підписники приймуть кожну подію, тому перед тривалими операціями слід буферизувати події.

Підписки працюють лише в реальному часі, без повторного відтворення чи
автоматичного перепідключення. Збій джерела завершує поточні підписки;
підпишіться знову після відновлення. Якщо підписка на нативні події починається пізніше, підписник отримує поточний
маркер `server.connected`, а не попередні бізнес-події.

Передайте `types`, щоб отримувати лише окремі типи подій. Типи подій відповідно
звужуються, а `server.connected` надходить завжди, тож відфільтрований підписник
усе одно знає, коли синхронізуватися заново. Фільтрування відбувається на
спільному з'єднанні, всередині клієнта.

```ts
for await (const event of client.event.subscribe({ types: ["config.updated"] })) {
  // event.type is "config.updated" | "server.connected"
}
```

## RPC плагінів

Імпортуйте спільний контракт плагіна й передайте його в `client.rpc`:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
```

Другий необов'язковий аргумент методу містить `location`, `signal` і `headers`
окремо від вхідних даних, визначених плагіном. Якщо location не вказано,
діють типові параметри нативних запитів: заголовки базової локації, потім
робочий каталог сервера. Під час створення субклієнта локація не вибирається.

Методи виводять аргументи й результати з визначення. Розбір схем належить межі
контракту; виклики надсилають прийняте подання вхідних даних, а обробники
отримують розібрані значення. Promise-клієнт приймає визначення Standard Schema
або звичайні JSON Schema і не запускає парсери схем локально: сервер повертає
вже розібраний і перетворений результат. Визначення Effect Schema потребують
Effect-клієнта.

Оголошені помилки методів відхиляють проміс так само, як помилки інших
ендпоінтів Promise-клієнта, а перехоплені помилки лишаються нетипізованими.
Типізований субклієнт прибирає загальні обгортки помилок HTTP RPC. Зарезервовані
збої фреймворку `rpc.*` лишаються звичайними збоями RPC, а не пов'язані з ними
помилки автентифікації, транспорту й протоколу зберігають своє типове подання в
клієнті.

Підписки RPC використовують локальні назви й отримують події цього RPC з усіх
локацій. Щоб відфільтрувати їх, перевіряйте обов'язкове поле `event.location`.
`events.subscribe` відповідає нативному API асинхронних ітерабельних об'єктів:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

`events.on` — зручна обгортка над тим самим джерелом. Вона повертає функцію
відписки; асинхронні колбеки очікуються послідовно. Збої колбека або джерела
записуються в журнал і завершують цей слухач. Нативні й типізовані підписки
отримують той самий звичайний конверт `rpc.<rpcID>.<event>` з даними події у
вигляді безпосереднього об'єкта. Живі підписки не відтворюють пропущені події.

Серверний плагін має бути налаштований і реалізовувати RPC; імпорт визначення
його не реєструє. Дивіться [RPC плагінів](/build/plugins/rpc), щоб дізнатися про
API визначення й реєстрації. Будь-який HTTP-клієнт також може викликати загальний
маршрут `POST /api/rpc/{rpcID}/{method}` з `{ "input": ... }` і отримати
`{ "output": ... }`. Пропущені поля input/output означають відсутність значення.

## Локальна фонова служба

Основні точки входу клієнта сумісні з браузером і не містять керування локальними
процесами. У застосунку Node імпортуйте нативний Promise API служби з
`@opencode/client/service`.

- `Service.discover()` повертає зареєстрований ендпоінт, який пройшов перевірку стану, не запускаючи
  процес.
- `Service.ensure()` повертає сумісну службу, запускаючи її за потреби.
- `Service.stop()` зупиняє саме той зареєстрований екземпляр служби.
- `Service.headers(endpoint)` створює заголовки автентифікації для клієнта.

```ts
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()
```

`Service.ensure()` приймає необов'язкові файл реєстрації, версію, команду служби
й колбек `onStart`. `version` приймає або точне значення, або предикат
сумісності:

```ts
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})
```

Пропустіть ці параметри, щоб використати стандартний шлях реєстрації та команду
`opencode serve --service`.
