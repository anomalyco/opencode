---

Ущільнення звільняє місце в довгій сесії: попередню частину розмови замінює підсумок,
тож сесія може тривати після досягнення межі контексту моделі.

## Як це працює

Коли сесія наближається до межі контексту моделі, OpenCode підсумовує
всю поточну розмову. Він також зберігає найновішу частину розмови, типово близько
15,000 токенів, поруч із підсумком, щоб точні нещодавні деталі лишалися
доступними.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

Надсилання всієї розмови дозволяє запиту на підсумок повторно використати кеш
промптів звичайного запиту, коли провайдер це підтримує. Під час наступних ущільнень OpenCode
оновлює наявний підсумок, використовуючи частину розмови після цієї контрольної точки.

## Запуск

Автоматичне ущільнення ввімкнено за замовчуванням:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

Під час ущільнення частина деталей втрачається. Якщо важливо зберегти точні деталі недавньої розмови,
збільште `keep.tokens` або запустіть ущільнення вручну, не чекаючи автоматичного.

## Вручну

Ущільнення можна запустити будь-коли, навіть якщо історія коротка:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

Команда `api` знаходить фонову службу й автентифікується в ній. Вона підтверджує прийняття запиту, не чекаючи на підсумок.
Стежте за подіями `session.compaction.*`, щоб дізнатися, коли ущільнення завершиться. Повний опис операції наведено
в [довіднику API](/api).

| Правило | Поведінка |
| --- | --- |
| Час виконання | Ущільнення починається в найближчий безпечний момент, перш ніж OpenCode обробить промпти, які ще чекають. |
| Повторні запити | Якщо запит ще очікує виконання, нові запити об'єднуються з ним. |
| Автоматизація | Працює, коли `compaction.auto` дорівнює `false`. |

Передайте `id`, щоб повторення того самого запиту було ідемпотентним. Якщо використати цей ID для іншого запиту,
OpenCode поверне помилку конфлікту.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## Налаштування

Додайте `compaction` до будь-якого [файлу конфігурації OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": "20%",
  },
}
```

| Поле | Типово | Поведінка |
| --- | ---: | --- |
| `auto` | `true` | Автоматично ущільнює контекст поблизу його межі. Якщо провайдер відхилив задовгий запит, OpenCode робить одну спробу відновлення. Ущільнення вручну доступне завжди. |
| `background` | `true` | Готує підсумок заздалегідь, щоб автоматичне ущільнення не чекало на нього. Дивіться розділ [Фонове ущільнення](#background-compaction). |
| `keep.tokens` | `15000` | Орієнтовний обсяг недавньої розмови, яку OpenCode зберігає разом із підсумком. Більше значення зберігає більше деталей, але лишає менше місця для нової роботи. |
| `buffer` | `"15%"`, щонайменше 16k | Частка вікна контексту моделі, яку OpenCode лишає вільною. Автоматичне ущільнення починається, коли розмова займає решту вікна. Що більше значення, то раніше це відбудеться. |

`keep.tokens` приймає невід'ємне ціле число.

### Буфер

`buffer` — це відсоток вікна кожної моделі, тож одне налаштування підходить для всіх моделей:

| Вікно моделі | Поріг ущільнення за `"buffer": "20%"` |
| ---: | ---: |
| 128k | ~102k |
| 1M | 800k |

- Це резерв вільного місця, а не поріг ущільнення: за значення `"20%"` ущільнення починається, коли контекст заповнено на 80%.
- Приймає від `"1%"` до `"99%"`, включно з десятковими, як-от `"12.5%"`.
- Кількість токенів, як-от `20000`, теж працює. Та сама кількість — велика частка малого вікна й мала частка великого.
- Кількість токенів, що дорівнює вікну моделі або більша за нього, ігнорується, і застосовується типове значення.

### Вікно контексту

Розмір вікна дорівнює ліміту вхідних токенів моделі (`limit.input`), але не перевищує ліміту контексту (`limit.context`).
Якщо в моделі задано лише один із цих лімітів, OpenCode використовує його. Якщо не задано жодного, автоматичне
ущільнення вимкнено. OpenCode ущільнює контекст один раз, коли провайдер відхиляє надто довгий запит.

У конфігурації кожен ліміт можна перевизначити окремо. Якщо в каталозі задано обидва ліміти, збільшення лише
`limit.context` не змінить розміру вікна: він залишиться на рівні ліміту вхідних токенів із каталогу. Тому задайте також `limit.input`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "limit": { "context": 1050000, "input": 1000000 },
        },
      },
    },
  },
}
```

## Модель

Типово OpenCode пише підсумок сам, використовуючи модель сесії. Встановіть
`agents.compaction.model`, щоб використовувати іншу модель для підсумків:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" },
  },
}
```

Якщо OpenCode не може знайти вказану модель, він використовує модель сесії.

## Фонове ущільнення

OpenCode готує підсумок заздалегідь, не зупиняючи сесію, і підставляє його, коли настає час ущільнення.
Тоді під час автоматичного ущільнення не потрібно призупиняти сесію, щоб скласти підсумок:

```text
60k tokens before the threshold   summary of the conversation so far starts in the background
                                  the session keeps going; the summary is held, not applied
threshold                         the held summary is swapped in; everything since it is kept as is
```

Якщо вікно контексту мале, OpenCode починає готувати підсумок не пізніше ніж на півдорозі від першої відповіді
після попереднього ущільнення до порога.

| Правило | Поведінка |
| --- | --- |
| Вартість | Запит на підсумок повторно використовує кеш промптів. Підсумок, який так і не використали, наприклад бо сесія завершилася до порогу, усе одно коштує токенів. |
| Очікування | Якщо на момент ущільнення підсумок ще не готовий, сесія чекає, доки його буде завершено. |
| Звичайний підсумок | OpenCode створює підсумок під час ущільнення, якщо після збереженого підсумку розмова зросла більш ніж приблизно на 40% від порога або якщо змінився початок розмови. |
| Пропуск | Фоновий підсумок не використовується, коли контекст ущільнює провайдер. Після зміни моделі або перерви, довшої за строк дії кешу промптів, підготовка підсумку починається з наступної відповіді. |
| Зберігання | Збережені підсумки живуть у пам'яті й втрачаються під час перезапуску. |

Вимкніть фонове ущільнення, щоб готувати підсумок лише тоді, коли настає час ущільнення:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "background": false,
  },
}
```

## Провайдери

Деякі провайдери можуть натомість ущільнювати контекст на своєму боці. Увімкніть це для
провайдера чи моделі через `settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Налаштування моделі має пріоритет над налаштуванням провайдера. Зі значенням `native` контекст ущільнює
провайдер, а зі значенням `summary` — сам OpenCode.

Якщо контекст ущільнює провайдер, OpenCode надсилає розмову на його ендпоінт ущільнення.
Провайдер повертає непрозорий зашифрований елемент, що заміняє старішу розмову.
Ваші нещодавні повідомлення й вкладення, до `keep.tokens`, зберігаються поруч із ним:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| Тема | Поведінка |
| --- | --- |
| Підтримка | Моделі OpenAI Responses. Підтримка залежить від розгортання й моделі. |
| Поріг | Ті самі налаштування `auto` і `buffer`, що й для ущільнення за допомогою підсумку. Запити на ущільнення вручну теж працюють. |
| Переносність | Зашифрована контрольна точка працює лише з тим самим провайдером і моделлю. Якщо ви зміните модель, сесія натомість продовжиться з початкової розмови. |
| Задовгий запит | Якщо провайдер відхиляє задовгий запит на ущільнення, OpenCode повторює спробу з коротшим запитом. На підсумок він не переходить. |

## Підсумки

Підсумок структурований так, щоб інший агент міг продовжити роботу з нього:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

Він охоплює мету й вимоги, рішення, завершену та активну роботу, блокери й наступні кроки
та доцільні файли. У нещодавній розмові, збереженій поруч, довгий вивід інструментів
скорочується, а дані вкладень замінюються коротким описом.

Після ущільнення сесія бере за основу поточні версії ваших файлів інструкцій. Дивіться розділ [Інструкції](/instructions).

## Межі

| Межа | Результат |
| --- | --- |
| Модель | Для ущільнення з підсумком OpenCode використовує `agents.compaction.model`, якщо його задано, а інакше — модель сесії. Ущільнення на боці провайдера завжди використовує модель сесії. |
| Історія | Потрібна попередня частина розмови, яку можна замінити. Ущільнення не звільнить місця, якщо запит здебільшого складається з незмінних інструкцій і схем інструментів. |
| Розмір | Якщо сама розмова задовга для ущільнення, OpenCode надсилає скорочену текстову версію й може пропустити найдавніші репліки. |
| Відновлення | Якщо задовгий запит відхилено, OpenCode ущільнює контекст і повторює запит один раз. Якщо запит відхилено знову, OpenCode повертає помилку. |
| Зберігання | Раніші повідомлення лишаються збереженими, навіть коли їх більше не надсилають моделі. |

Наприклад, тут ущільнення не допоможе:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## Міграція

V1 використовував поведінку tail-turn і обрізання. V2 використовує підсумки й
`compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

Налаштування й поведінка на цій сторінці стосуються V2.
