Додайте файл `AGENTS.md`, щоб дати OpenCode постійні настанови для проєкту. Використовуйте його для команд збірки, нотаток про архітектуру, домовленостей щодо коду й вимог до перевірки.

```md title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

Додавайте файли інструкцій проєкту до комітів, щоб усі, хто працює в репозиторії, отримували ті самі настанови.

## Область дії

Розмістіть `AGENTS.md` у каталозі, де мають діяти його настанови. OpenCode завантажує глобальний файл, а потім кожен `AGENTS.md` від поточного каталогу робочого простору в напрямку домашнього каталогу. Для робочих просторів поза домашнім каталогом він зупиняється на корені проєкту.

```text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace
```

У цьому прикладі завантажуються всі чотири файли. Вони об'єднуються в такому порядку:

```text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md
```

Тримайте настанови, що діють усюди, у глобальному файлі. Загальнорепозиторні настанови розміщуйте в корені проєкту, а конкретніші — ближче до коду, якого вони стосуються. OpenCode об'єднує файли й не вирішує конфлікти між ними.

Якщо робочий простір поза коренем проєкту, завантажується лише глобальний файл. Встановіть `OPENCODE_DISABLE_PROJECT_CONFIG=1`, щоб пропустити виявлення проєктних `AGENTS.md`, не вимикаючи глобальний файл.

### Запасний варіант із CLAUDE.md

У будь-якому каталозі без `AGENTS.md` OpenCode натомість читає `CLAUDE.md`. Без глобального
`~/.config/opencode/AGENTS.md` він читає `~/.claude/CLAUDE.md`. `AGENTS.md` каталогу завжди переважає його
`CLAUDE.md`, тож символьне посилання між ними завантажується один раз.

Встановіть `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1`, щоб пропустити кожен `CLAUDE.md`, або `OPENCODE_DISABLE_CLAUDE_CODE=1`, щоб також пропустити
навички `.claude`. Сервер читає обидві змінні під час запуску. Для фонової служби збережіть їх за допомогою
`opencode service set env` і виконайте `opencode service restart`.

## Виявлення

Файли інструкцій нижче робочого простору виявляються, коли агент досліджує проєкт. Читання файлу або перегляд каталогу завантажує всі файли `AGENTS.md` між цією ціллю та робочим простором.

```text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

OpenCode завантажує вкладені файли, починаючи з найближчих. Він не дублює інструкцій, доки їхній запис є в історії, видимій моделі. Повторне читання тієї самої частини проєкту зазвичай не додає їх знову. Якщо ущільнення або відкат вилучить цей запис, OpenCode може знову завантажити файл під час наступного читання.

Зміни у вкладеному файлі не виявляються автоматично після його завантаження. Почніть нову сесію, якщо оновлений текст має застосуватися негайно.

## Порядок

Спершу надсилається системний промпт вибраного агента або провайдера. Далі OpenCode збирає початкові інструкції в такому порядку:

```text
1. Agent or provider system prompt
2. Code Mode tool guidance, when enabled
3. MCP server, reference, and skill guidance
4. Global and project AGENTS.md files, then configured instructions
5. Built-in date and environment context
6. Session-specific instruction entries supplied through the API
```

Ці джерела об'єднуються, а не використовуються як перевизначення. Вкладені файли `AGENTS.md`, виявлені пізніше, додаються до історії сесії в порядку виявлення.

## Оновлення

Відредагуйте глобальний `AGENTS.md` або той, що виявлено вище, під час роботи сесії, щоб оновити його настанови.

```bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md
```

Перед наступним запитом до моделі OpenCode виявляє зміну й додає оновлення інструкцій перед доставкою очікуваних вхідних даних:

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- Якщо видалити глобальний файл `AGENTS.md` і всі такі файли на шляху вгору від поточного каталогу, сесія отримає повідомлення, що попередні інструкції з цих файлів більше не діють.
- У разі тимчасової помилки читання OpenCode зберігає останні відомі інструкції й не вважає їх видаленими.
- Переміщення сесії зберігає її стан інструкцій, тож настанови в місці призначення подаються як оновлення.
- Підтвердження відкату сесії очищає її стан інструкцій і перезавантажує інструкції перед наступним промптом.

Значення інструкцій залишаються привілейованими. Клієнти бачать, які джерела змінилися, але не їхній вміст.

## Конфігурація

Використовуйте масив `instructions`, щоб додати файли, glob-шаблони або HTTP(S)-адреси разом із виявленими файлами `AGENTS.md`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines/*.md",
    "~/rules/opencode.md",
    "https://example.com/instructions.md",
  ],
}
```

Налаштовані інструкції завантажуються після файлів `AGENTS.md`, у порядку їх переліку. Записи з кожного документа конфігурації об'єднуються.

| Запис                   | Як визначається розташування                                         |
| ----------------------- | -------------------------------------------------------------------- |
| Відносний шлях або glob | Шукається в кожному каталозі від робочого простору до кореня проєкту |
| Шлях `~/`               | Обчислюється від вашого домашнього каталогу                          |
| Абсолютний шлях         | Використовується як записано; ім'я файлу може бути glob-шаблоном     |
| `http://` або `https://` | Завантажується під час завантаження конфігурації, з тайм-аутом п'ять секунд |

- Локальні файли оновлюються так само, як `AGENTS.md`, коли змінюються. Нові файли, що відповідають glob-шаблону, завантажуються під час наступної зміни конфігурації.
- OpenCode пропускає відсутні файли. Якщо не вдається отримати вміст за URL-адресою, OpenCode пропускає її або використовує останній отриманий вміст.
- З `OPENCODE_DISABLE_PROJECT_CONFIG=1` або коли робочий простір поза проєктом, відносні записи обчислюються від каталогу глобальної конфігурації.

Підключений робочий простір [OpenCode Console](/console) також може ділитися інструкціями.

Дивіться [Конфігурацію](/config), щоб дізнатися про розташування конфігурації та пріоритет.
