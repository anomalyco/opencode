description: "Пишіть файли SKILL.md, які дають агентам OpenCode повторно використовувані інструкції для завдання, що завантажуються лише тоді, коли вони потрібні."

Створіть навичку, щоб дати агенту повторно використовувані інструкції для конкретного завдання. Покладіть файл `SKILL.md` у `.opencode/skills/<skill-id>` і опишіть, коли його використовувати, у `description`.

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow

1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

OpenCode показує цю навичку, коли вона доречна. Тоді агент може завантажити її інструкції інструментом `skill`, замість додавати кожну навичку до кожного промпту.

## Створення

Тримайте пов'язані скрипти, довідники й шаблони поруч із `SKILL.md`:

```text
.opencode/skills/
└── git-release/
    ├── SKILL.md
    ├── scripts/
    │   └── changelog.ts
    └── references/
        └── release-policy.md
```

Шляхи, записані всередині навички, відносні до каталогу, що містить `SKILL.md`. Рекомендується форма з каталогом, бо вона дає допоміжним файлам окремий базовий каталог.

## Виявлення

OpenCode автоматично шукає в таких місцях:

| Область              | Джерела                                |
| -------------------- | -------------------------------------- |
| Глобально            | `~/.config/opencode/skills`            |
| Глобальна сумісність | `~/.claude/skills`, `~/.agents/skills` |
| Проєкт               | `.opencode/skills`                     |
| Сумісність проєкту   | `.claude/skills`, `.agents/skills`     |

Джерела проєкту OpenCode шукає від поточного каталогу до кореня файлової системи й додає відповідні каталоги на кожному рівні.

Кожне джерело може містити будь-яку з двох форм:

```text
skills/
├── review.md
└── git-release/
    └── SKILL.md
```

- Файли Markdown мають бути в корені джерела, наприклад `skills/review.md`.
- Файли з точною назвою `SKILL.md` можуть лежати вкладено в каталогах групування, наприклад `skills/git-release/SKILL.md` або `skills/teams/release/SKILL.md`.
- Каталог із `SKILL.md` — це одна навичка. OpenCode не шукає всередині нього інші навички.
- Приховані файли й каталоги та `node_modules` пропускаються.
- Пошук не заглиблюється більш ніж на шість рівнів від кореня джерела.

## Джерела

Додайте більше локальних каталогів або HTTP-каталогів масивом `skills` у будь-якому `opencode.json` чи `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "skills": [
    "./team-skills",
    "~/shared/opencode-skills",
    "/opt/company-skills",
    "https://example.com/opencode/skills/",
  ],
}
```

| Значення | Як визначається розташування |
| -------- | ----------- |
| Відносний шлях | Від активного робочого каталогу OpenCode, а не від файлу конфігурації |
| Шлях `~/` | Від домашнього каталогу поточного користувача |
| Абсолютний шлях | Використовується як записано |
| URL `http://` або `https://` | Завантажується як HTTP-каталог |

Кожен знайдений файл конфігурації додає свої записи. Масиви `skills` об'єднуються, а не замінюються.

Підключений робочий простір [OpenCode Console](/console) також може ділитися навичками.

## Каталоги

HTTP-каталог — це базова URL-адреса з файлом `index.json`:

```json title="index.json"
{
  "skills": [
    {
      "name": "git-release",
      "version": "3",
      "files": ["git-release.md", "references/release-policy.md"]
    }
  ]
}
```

Для цього запису OpenCode завантажує кожен файл із `<base-url>/git-release/<file>`.

| Правило | Вимога |
| ------- | ------ |
| Шляхи | Мають бути безпечними, відносними й того самого походження |
| Вхідний файл | Містить `SKILL.md` або `<name>.md`, наприклад `git-release.md` |
| Оновлення | Збільшуйте `version`, коли файли змінюються, щоб OpenCode оновив свій кеш |

Кожен завантажений каталог навички стає коренем джерела з назвою запису, тож і `git-release.md`, і `SKILL.md` мають ID `git-release`.

## Frontmatter

Використовуйте frontmatter, щоб назвати навичку й керувати тим, де вона з'являється:

```markdown title="SKILL.md"
---
name: Git Release
description: Prepare a repository release
metadata:
  opencode/autoinvoke: false
---

Prepare the changelog, version bump, tag, and release notes.
```

| Поле                           | Поведінка                                                        |
| ------------------------------ | ---------------------------------------------------------------- |
| `name`                         | Відображувана назва; типово — ID, утворений зі шляху             |
| `description`                  | Опис, який використовується, щоб показати навичку моделі          |
| `metadata.opencode/autoinvoke` | Встановіть `false`, щоб пропустити навичку в списку доступних для моделі |
| `disable-model-invocation`     | Встановіть `true` для того самого ефекту, що й `opencode/autoinvoke: false` |

Увесь frontmatter необов'язковий під час виконання. Додайте чіткий `description`, коли модель має знаходити навичку; навички без нього не показуються.

`opencode/autoinvoke: false` лише ховає навичку зі списку доступних для моделі. Навичка лишається зареєстрованою, і її все ще можна завантажити явно за ID. Коли задано і `disable-model-invocation`, і `opencode/autoinvoke`, перемагає `opencode/autoinvoke`. V2 приймає поля переносності, як-от `license` і `compatibility`, але не інтерпретує їх.

## ID

Шлях до файлу визначає ID навички. `name` у frontmatter — лише відображувана назва.

| Файл                              | ID            |
| --------------------------------- | ------------- |
| `<source>/git-release.md`         | `git-release` |
| `<source>/git-release/SKILL.md`   | `git-release` |
| `<source>/teams/release/SKILL.md` | `release`     |

ID точні й чутливі до регістру. Для переносних навичок використовуйте унікальний ID у нижньому регістрі з kebab-case довжиною 1–64 символи й тримайте його узгодженим із назвою каталогу:

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

V2 наразі не перевіряє цей шаблон, рекомендацію про 1–64 символи, збіг між `name` і каталогом чи максимальну довжину опису.

## Пріоритет

Навички вибираються за ID. Якщо два джерела визначають `git-release`, навичку, яку завантажує OpenCode, дає джерело, зареєстроване пізніше:

```text
~/.config/opencode/skills/git-release/SKILL.md  ← lower precedence
.opencode/skills/git-release/SKILL.md           ← loaded
```

Джерела реєструються від нижчого до вищого пріоритету:

1. Вбудовані навички
2. `.claude/skills`: спершу глобальні, потім від найдальшого предка до поточного каталогу
3. `.agents/skills`: спершу глобальні, потім від найдальшого предка до поточного каталогу
4. `~/.config/opencode/skills`
5. Проєктні `.opencode/skills`: від найдальшого батьківського каталогу до поточного
6. Явні записи `skills` у конфігурації: за пріоритетом конфігурації й порядком у масиві

Уникайте дубльованих ID, якщо тільки ви не хочете перекрити попередню навичку.

## Завантаження

На кожному кроці моделі OpenCode показує дозволені навички, які мають опис і не встановлюють `opencode/autoinvoke` у `false`. Список містить лише ID, назву й опис, а не повне тіло Markdown.

Модель завантажує навичку, викликаючи інструмент `skill` з її точним ID:

```json title="skill tool input"
{
  "id": "git-release"
}
```

Потім OpenCode:

1. Вибирає поточне визначення для цього ID.
2. Перевіряє дозвіл `skill` вибраного агента.
3. Додає тіло Markdown без frontmatter до розмови.
4. Надає базовий каталог навички й вибірку до десяти шляхів допоміжних файлів.

Щоб завантажити навичку самостійно, згадайте її у промпті як `@skill-id`.

Вміст допоміжних файлів не завантажується автоматично. Агент читає їх, коли навичка вказує йому це зробити. Вибірка файлів доступна для навичок `SKILL.md` у каталозі; навички у вигляді окремого файлу Markdown не отримують списку сусідніх файлів.

## Дозволи

Використовуйте дію `skill` і ID навички як ресурс. Правила виконуються послідовно, і перемагає останнє правило, що збігається:

```jsonc title="opencode.jsonc"
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" },
  ],
}
```

| Ефект  | Поведінка |
| ------ | --------- |
| `allow` | Показує й завантажує відповідні навички без схвалення |
| `ask` | Показує відповідні навички й запитує перед їх завантаженням |
| `deny` | Ховає відповідні навички від моделі й відхиляє завантаження |

Розмістіть ті самі правила в `agents.<id>.permissions`, щоб застосувати їх лише до одного агента.

## Вирішення проблем

Наприклад, ID цієї навички — `release`, а не її назва у frontmatter `Git Release`:

```text
.opencode/skills/release/SKILL.md
                      └─ ID: release
```

Якщо навичка відсутня або завантажує не той вміст:

1. Переконайтеся, що файл — це або `*.md` у корені, або вкладений файл із точною назвою `SKILL.md`.
2. Перевірте ID, утворений зі шляху, з урахуванням регістру, а не `name` у frontmatter.
3. Додайте `description`, якщо модель має знаходити навичку.
4. Перевірте `opencode/autoinvoke` і дозволи `skill` вибраного агента.
5. Пошукайте пізніше джерело, яке визначає той самий ID.
6. Для HTTP-каталогів перевірте `index.json`, шляхи файлів того самого походження й змінений `version`.
