Посилання дають OpenCode іменований доступ до каталогів поза поточним
проєктом. Додайте одне в `opencode.json` або `opencode.jsonc`, а потім прикріпіть його псевдонім у
своєму клієнті, коли воно потрібне.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Після прикріплення `docs` попросіть агента оглянути відповідний шлях:

```text
Read the attached docs reference and summarize api/authentication.md.
```

Використовуйте посилання для документації, спільних бібліотек, прикладів або коду з
іншого репозиторію.

## Локальні

Використовуйте `path` для локального каталогу:

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

Шляхи поводяться так:

- Відносні шляхи обчислюються від каталогу, що містить файл конфігурації.
- Абсолютні шляхи підтримуються.
- Шляхи відносно домашнього каталогу, як-от `~/docs`, підтримуються.

Використовуйте рядкову скорочену форму, коли інші поля не потрібні:

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  Скорочений рядок є локальним шляхом, лише якщо він починається з `.`, `/` або `~`. Використовуйте `./docs`, а не `docs`; голе значення `docs`
  інтерпретується як Git-репозиторій.
</Callout>

## Git

Використовуйте `repository` для віддаленого Git-репозиторію:

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

Підтримувані форми віддалених репозиторіїв:

- Скорочена форма GitHub `owner/repo`
- Git-URL-адреси
- Форми «хост/шлях»
- Віддалені репозиторії у стилі SCP

Локальні репозиторії `file:` не підтримуються.

Використовуйте рядкову скорочену форму, щоб слідувати типовій гілці віддаленого репозиторію:

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

Без `branch` OpenCode виконує чекаут і оновлює типову гілку віддаленого репозиторію.
Назви гілок можуть містити літери, цифри, `/`, `_`, `.` і `-`, але не можуть
починатися з `-` або містити `..`.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## Зберігання

OpenCode нормалізує кожен віддалений репозиторій і зберігає один чекаут на репозиторій і гілку
у своєму глобальному каталозі даних. Без явної гілки шлях має такий
вигляд:

```text
opencode/repos/<host>/<repository-path>
```

У типовій інсталяції Linux `Effect-TS/effect` зберігається за шляхом:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

Явна гілка додає закодований суфікс `@<branch>`:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## Оновлення

Відсутні репозиторії клонуються асинхронно. Наявні чекаути перевіряються
у фоні, коли посилання завантажуються або перезавантажуються, і після того, як у їхній Location
прийнято новий промпт користувача.

```text
Prompt admitted → refresh check starts in background → agent continues
```

Чекаут має право на оновлення, якщо його остання спроба оновлення була щонайменше 24 години тому
або якщо спроби не зафіксовано. Оновлення виконує fetch і скидає до
налаштованої гілки або типової гілки віддаленого репозиторію.

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

Поведінка оновлення підкоряється таким правилам:

- Позначки часу зберігаються між перезапусками служби.
- Location, що використовують той самий чекаут, спільно використовують його позначку часу.
- Невдалі спроби записуються в журнал і далі підпадають під 24-годинне обмеження.
- Поки Location не використовується, періодичного опитування немає.
- Помилки клонування чи оновлення не заважають завантаженню інших посилань.

Промпти не чекають на клонування чи оновлення. Вкладення може містити старіший
вміст, навіть якщо пізніше читання інструментом побачить оновлений чекаут, а нове посилання
може з'явитися, перш ніж його чекаут буде готовий.

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  Кешовані чекаути спільні й можуть оновлюватися, поки агент їх використовує. Не редагуйте кешовані чекаути, бо
  оновлення скидає їх.
</Callout>

## Настанови

`description` підказує агентам, коли посилання доречне. Посилання з
описом з'являються в інструкціях агента зі своїм псевдонімом і обчисленим шляхом.

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Посилання без опису залишаються доступними клієнтам, але не
повідомляються автоматично.

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## Видимість

Встановіть `hidden` у `true`, щоб прибрати посилання з інтерактивних селекторів клієнта:

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden` впливає лише на інтерактивну видимість. Посилання залишається в
API посилань, а якщо має опис — і в інструкціях агента.

## Використання

Клієнти прикріплюють посилання за його кореневим псевдонімом. Вкладення містить
список файлів і підкаталогів кореня без рекурсивного обходу.

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

Попросіть агента оглянути конкретний шлях, якщо вам потрібен вміст нижче кореня.

## Дозволи

Посилання не дають додаткових дозволів інструментів. Доступ поза активним
Location усе одно підпадає під звичайні правила інструментів і дозвіл `external_directory`;
редагування також потребує відповідного дозволу на редагування.

```text
Read ../product-docs/api.md
```

Запит успішний, лише коли активні дозволи дозволяють це зовнішнє читання.

## Поля

| Поле          | Локальні     | Git          | Опис                                          |
| ------------- | ------------ | ------------ | --------------------------------------------- |
| `path`        | Обов'язково  | Ні           | Шлях до локального каталогу                   |
| `repository`  | Ні           | Обов'язково  | Віддалений Git-репозиторій                    |
| `branch`      | Ні           | Необов'язково | Гілка для fetch і чекауту                    |
| `description` | Необов'язково | Необов'язково | Настанова, що описує, коли агенти мають його використовувати |
| `hidden`      | Необов'язково | Необов'язково | Приховує його з інтерактивних селекторів клієнта |

Повний запис Git може використовувати кожне сумісне з Git поле:

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## Псевдоніми

Псевдонім не може бути порожнім або містити `/`, `\`, пробіли, зворотний апостроф чи
кому.

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
