API Console дозволяє вашим скриптам та інтеграціям викликати моделі й експортувати використання. Кожен запит
автентифікується API-ключем.

```bash
curl --fail-with-body "https://opencode.ai/inference/v1/models" \
  --header "Authorization: Bearer oc_sk_..."
```

| API                                       | Ендпоінти                                         |
| ----------------------------------------- | ------------------------------------------------- |
| [Моделі](/console/api/models)             | `https://opencode.ai/console/api/v1/models`       |
| [Інференс](/console/api/inference)        | `https://opencode.ai/inference/...`               |
| [Провайдери](/console/api/providers)      | `https://opencode.ai/inference/custom/...`        |
| [Експорт використання](/console/api/usage-export) | `https://opencode.ai/console/api/v2/usage/export` |

## API-ключі

API-ключі можуть мати і учасники робочого простору, і сервісні облікові записи. Надсилайте ключ як bearer-токен.

```text
Authorization: Bearer oc_sk_...
```

|                  | Особистий API-ключ                                     | Ключ сервісного облікового запису                                        |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Створює          | Будь-який учасник, для себе                             | Власники й адміністратори                                                |
| Створюється в    | **Account › Personal API keys**                        | **Settings › Service accounts**                                          |
| Діє як           | Учасник, який його створив                             | Сервісний обліковий запис                                                |
| Використання зараховується до | [Бюджету](/console/budgets#member-budgets) учасника | [Бюджету](/console/budgets#service-account-budgets) сервісного облікового запису |
| Найкраще для     | Власних скриптів і [harness](/console/harnesses)       | CI, спільних машин та інтеграцій                                         |

- Кожен ключ працює в одному робочому просторі, який вибирають під час створення. Заголовок робочого простору не потрібен.
- Повний ключ показується лише один раз, одразу після створення. Далі Console показує лише його префікс.
- **Expiration** необов'язковий: **Never**, **1 day**, **7 days**, **30 days** або **Custom** (від 1 до 365 днів). Прострочений
  ключ не можна поновити, тож створіть новий.

## Особисті API-ключі

Особистий ключ діє від вашого імені. На нього поширюються ваша роль, [бюджети](/console/budgets#member-budgets) і
правила для моделей.

1. Відкрийте **Account** у меню облікового запису й знайдіть **Personal API keys**.
2. Натисніть **Add API key**.
3. Виберіть **Workspace**, **Key name** і за бажанням **Expiration**. Власники й адміністратори також вибирають
   **Permissions**.
4. Натисніть **Create** і скопіюйте ключ.

```text
oc_sk_1a2b3c4d5e6f_...
```

Дозволи ключа залежать від вашого поточного доступу до робочого простору. Якщо ваша роль зміниться, зміняться
й дозволи ключа. Якщо робочий простір вимагає [SSO](/console/sso#sso-enforcement), ключ працює лише за наявності
активної сесії SSO. Це обмеження не поширюється на власників.

## Сервісні облікові записи

Сервісний обліковий запис — це учасник робочого простору, який не прив'язаний до людини. Він має власні API-ключі,
окремий облік використання й окремий [бюджет](/console/budgets#service-account-budgets). Використовуйте такий
запис для автоматизації, щоб використання не зараховувалося конкретній людині. Сервісними обліковими записами керують власники й адміністратори.

1. Відкрийте **Settings › Service accounts** і натисніть **Add Service Account**, потім дайте йому назву, наприклад `CI Pipeline`.
2. Відкрийте сервісний обліковий запис і натисніть **Add API Key**.
3. Виберіть **Key name**, за бажанням **Expiration** і **Permissions**, потім натисніть **Create**.
4. Скопіюйте ключ.

```bash
export SERVICE_API_KEY="oc_sk_..."
```

Власники й адміністратори можуть пізніше перейменувати ключ сервісного облікового запису або змінити його дозволи
через **Edit…** у меню дій ключа.

## Дозволи

Кожен ключ має рівень дозволів, який вибирають у **Permissions** під час створення.

| Дозволи        | Дозволяє                                                                             |
| -------------- | ------------------------------------------------------------------------------------ |
| **All**        | Усе, що може робити учасник або сервісний обліковий запис, крім **This account's API keys**. |
| **Restricted** | Лише вибрані вами ресурси.                                                           |
| **Read only**  | Доступ на читання до кожного ресурсу. Ключ може перелічувати моделі, але не викликати їх. |

Ключ ніколи не робить більше, ніж той, від чийого імені він діє. Особистий ключ обмежений поточною роллю учасника, а
ключ сервісного облікового запису — тим, що [можуть робити сервісні облікові записи](#limitations).

### Обмежені ключі

Задайте для кожного ресурсу **None**, **Read** або **Write**. **Write** включає **Read**.

| Ресурс                      | Рівні                 |
| --------------------------- | --------------------- |
| **Models**                  | **Read**, **Request** |
| **Usage**                   | **Read**              |
| **Budgets**                 | **Read**, **Write**   |
| **Members**                 | **Read**, **Write**   |
| **Providers**               | **Read**, **Write**   |
| **Billing**                 | **Read**, **Write**   |
| **Workspace settings**      | **Read**, **Write**   |
| **SSO**                     | **Read**              |
| **Service accounts**        | **Read**              |
| **This account's API keys** | **Write**             |

**Models › Read** дозволяє перелічувати моделі, а **Models › Request** — ще й викликати їх через API
[Inference](/console/api/inference) та [Providers](/console/api/providers). Наприклад, ключу, який лише викликає
моделі, потрібно:

```text
Permissions: Restricted
Models:      Request
```

Ключі, створені як **Inference only** до появи обмежених дозволів, показуються як **Restricted** з **Models**,
установленим на **Request**.

### Хто що може надавати

- **Members** можуть створювати лише особисті ключі, які перелічують і викликають моделі. Console показує «This key can
  list and call models as you.» замість вибору дозволів.
- **Owners and admins** можуть давати своїм особистим ключам **All**, **Restricted** або **Read only** у межах власної
  ролі. За замовчуванням діє **Restricted** зі значенням **Request** для **Models**. Якщо згодом їхню роль знизять,
  дозволи ключів буде відповідно обмежено.
- **Ключі сервісних облікових записів** типово мають **All**. Власники й адміністратори вибирають їхні дозволи.

### Обмеження

Деякі дії завжди потребують людини, яка ввійшла в Console, а створювати нові ключі за допомогою ключа можна лише дуже
обмежено.

- Жоден API-ключ не може змінювати налаштування SSO чи видаляти робочий простір.
- Ключі сервісних облікових записів не можуть запрошувати учасників, змінювати ролі, видаляти учасників, керувати
  оплатою, змінювати налаштування робочого простору, керувати моделями чи створювати або видаляти сервісні облікові
  записи, навіть із **All**.
- **This account's API keys** доступний лише для ключів сервісних облікових записів, і **All** його не включає. Ключ із
  ним може створювати й відкликати ключі лише для свого сервісного облікового запису. Нові ключі мають бути
  **Restricted**, не перевищувати дозволи ключа, що їх створив, і не включати **This account's API keys**.
- Особисті ключі ніколи не отримують **This account's API keys**, і жоден API-ключ не може створювати чи відкликати
  особисті API-ключі.

Запити поза дозволами ключа повертають HTTP `403`.

## Відкликання

| Ключ                        | Хто може відкликати    | Де                                                                                |
| --------------------------- | ---------------------- | --------------------------------------------------------------------------------- |
| Особистий API-ключ          | Учасник, який ним володіє | **Account › Personal API keys**, потім **Revoke**                               |
| Особистий API-ключ          | Власники й адміністратори | Сторінка учасника в **Settings › Members**, розділ **API Keys**                  |
| Ключ сервісного облікового запису | Власники й адміністратори | Сторінка сервісного облікового запису в **Settings › Service accounts**, розділ **API Keys** |

Ключі також відкликаються автоматично:

- Вихід із робочого простору, видалення з нього або скасування доступу через [SCIM](/console/scim) відкликає кожен
  ключ, який ця людина створила в ньому, зокрема ключі сервісних облікових записів. Інші ключі того самого
  сервісного облікового запису продовжують працювати.
- Видалення сервісного облікового запису відкликає всі його ключі.

Відкликані й прострочені ключі одразу перестають працювати й повертають HTTP `401`.
