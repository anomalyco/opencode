OpenCode Console надає список моделей, перевірених і схвалених командою OpenCode. Увійдіть, додайте кредити й
отримайте API-ключ, щоб користуватися ними в OpenCode або в іншому агенті для кодування.

Console працює як будь-який інший провайдер в OpenCode. Він **цілком необов'язковий**, і ви можете натомість
використовувати будь-який інший провайдер. Про підписку з включеним використанням дивіться [OpenCode Go](/console/go).

## Як це працює

1. Увійдіть у [Console](https://opencode.ai/console), додайте платіжні дані й кредити та скопіюйте свій API-ключ.
2. Виконайте `/connect` в TUI, виберіть провайдера OpenCode з оплатою за використання і вставте свій API-ключ.

   ```text
   /connect
   ```

3. Виконайте `/models`, щоб побачити доступні моделі, і виберіть одну з них.

   ```text
   /models
   ```

Ви платите за кожен запит і можете поповнювати кредити на своєму обліковому записі.

## Ендпоінти

Ви також можете звертатися до моделей напряму через наведені нижче ендпоінти API. Безкоштовні чат-моделі потребують
OpenCode. В інших клієнтах використовуйте платні моделі або [Go](/console/go).

Для кожної моделі вказано її нативний API, але текстові моделі працюють і через інші API: Console перетворює запити на потрібний формат.

### Список моделей

Отримайте повний список доступних моделей та їхні метадані з ендпоінта моделей:

```bash
curl https://opencode.ai/inference/v1/models
```

Дивіться [API списку моделей](/console/api/models), щоб дізнатися про кожне поле відповіді, а також про список
Console, який також охоплює провайдерів, підключених до вашого робочого простору.

### Jev

Jev — це модель System One від TypeSafe AI для швидких структурованих рішень. Замість генерації тексту вона оцінює
`state` щодо типізованих питань і повертає значення та ймовірності, які ваш код може використовувати напряму. Вона
підтримує питання так/ні (`noul`), з кількома варіантами (`choice`) і за рубрикою (`score`).

Використовуйте свій API-ключ OpenCode Console з ендпоінтом `https://opencode.ai/inference/systemone/v1/systemone`.
Цей приклад перевіряє, чи запит до підтримки терміновий:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Ви можете поставити кілька питань в одному запиті. Jev оцінює їх паралельно й повертає кожну відповідь під
відповідним ID питання:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Використовуйте `jev-1.13-free`, щоб скористатися тимчасово безкоштовною моделлю, яка запускає Jev 1.13. Докладніше
про типи питань і поля відповіді дивіться в [документації TypeSafe AI](https://docs.typesafe.ai/).

### GPT 6 Luna Decision і Gemini Decision 1

`gpt-6-luna-decision` і `gemini-decision-1` приймають такий самий запит System One, як Jev, на тому самому ендпоінті.
Передавайте зображення, аудіо, відео й PDF у `state` як частини в стилі чату (`image_url`, `input_audio`,
`video_url`, `file`). GPT 6 Luna Decision приймає текст і зображення. Gemini Decision 1 також приймає аудіо, відео й PDF.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
```

### Моделі зображень

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` і `grok-imagine-image-2.0` генерують і редагують зображення. Це не
чат-моделі, тому вони ніколи не з'являються в `/models` чи в ендпоінті моделей, і `opencode/<model-id>` їх не вибирає.
Звертайтеся до них через нативний API з ключем Console або дозвольте інструменту OpenCode
[`generate_image`](/tools#image-generate) використовувати модель зображень, задавши
`experimental.image_generate.model`, наприклад `opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google приймає свої нативні `contents` і `generationConfig`, а xAI — свої нативні параметри, як-от `resolution` і
`quality`. OpenAI Images і xAI Images також приймають редагування за `/images/edits`.

### Моделі ембедингів

`text-embedding-3-small`, `qwen3-embedding-8b` та інші моделі ембедингів із таблиці вище перетворюють текст у вектори.
OpenCode не використовує їх для чату, тому вони ніколи не з'являються в `/models`, і безкоштовний тариф їх не включає.
[Go](/console/go#embedding-models) включає деякі з них. Звертайтеся до них через Embeddings API від OpenAI з ключем
Console.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` приймає рядок або масив рядків. `data` повертає один вектор на кожен вхід, у тому самому порядку.
- `dimensions` скорочує вектори в моделях, які це підтримують, як-от `text-embedding-3-small`.
- `encoding_format: "base64"` повертає вектори в кодуванні base64 замість чисел із плаваючою комою.
- Кожен вхідний фрагмент має вміщатися у вікно контексту моделі.
- Відповідь містить `usage.cost`, як і будь-який запит інференсу. Дивіться [вартість](/console/api/inference#cost).

Вектори з різних моделей не можна порівнювати, тому перетворюйте свої документи й запити однією моделлю.
[Підключений провайдер](/console/api/providers#endpoints) обслуговує власні моделі ембедингів за `/embeddings`.

## Передісторія

Доступно багато моделей, але лише деякі добре працюють як агенти для кодування. Провайдери також різняться
конфігурацією, швидкодією та якістю, тому модель, доступна через шлюз на кшталт OpenRouter, може поводитися інакше.

<Callout type="tip">Ми перевірили добірку моделей і провайдерів, які добре працюють з OpenCode.</Callout>

Щоб створити цей каталог, ми:

1. Перевірили добірку моделей і поговорили з їхніми командами про те, як їх найкраще запускати.
2. Попрацювали з провайдерами, щоб моделі обслуговувалися правильно.
3. Протестували швидкодію кожної пари «модель — провайдер» і склали список, який можемо впевнено рекомендувати.

Console — це AI-шлюз, який дає доступ до цих моделей.

## Цілі

Ми створили Console, щоб:

1. **Порівнювати** найкращі моделі й провайдерів для агентів для кодування.
2. Пропонувати **найвищу якість** без погіршення швидкодії та без маршрутизації до дешевших провайдерів.
3. Передавати **зниження цін** далі, продаючи за собівартістю, з націнкою лише на покриття комісій за обробку платежів.
4. Не мати **прив'язки**: використовуйте Console з будь-яким агентом для кодування або іншого провайдера з OpenCode.
