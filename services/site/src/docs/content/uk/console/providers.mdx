Підключіть облікові записи провайдерів, за які ви вже платите, як-от Anthropic, OpenAI чи AWS Bedrock, і діліться
їхніми моделями з усіма в робочому просторі. Console зберігає облікові дані й обслуговує кожного провайдера через свій
шлюз, тож учасники користуються моделями, не бачачи ключа провайдера. Той самий шлюз доступний вашим інструментам через
[API провайдерів](/console/api/providers).

Власники й адміністратори керують провайдерами на вкладці **Providers**. Учасники отримують увімкнені моделі
в OpenCode після виконання `/connect`.

## Підключення провайдера

1. Відкрийте **Providers** і натисніть **Connect Provider**.
2. Виберіть провайдера з каталогу й введіть його API-ключ.
3. За бажанням натисніть **Test connection**, а потім **Save**.

Каталог охоплює Anthropic, OpenAI, Google, xAI, DeepSeek, Mistral, Groq, OpenRouter та багато інших. Провайдери
з каталогу вже мають налаштовані моделі.

### Хмарні провайдери

Хмарним провайдерам потрібні додаткові дані.

| Провайдер             | Дані                                  |
| --------------------- | ------------------------------------- |
| Azure                 | Назва ресурсу й API-ключ              |
| AWS Bedrock           | Регіон і API-ключ                     |
| Google Vertex AI      | Регіон і JSON сервісного облікового запису |
| Cloudflare AI Gateway | ID облікового запису, ID шлюзу й API-токен |
| Databricks            | URL-адреса робочого простору й токен  |

### Власні провайдери

Натисніть **Add Custom Provider**, щоб підключити будь-який інший ендпоінт, а потім додайте його моделі через
**Add Model**.

| Поле       | Опис                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| Base URL   | Куди Console пересилає запити, наприклад `https://api.deepseek.com/v1`.        |
| Format     | Chat Completions, Responses API, Anthropic Compatible або Google Generative AI. |
| Auth mode  | Bearer, заголовок API-ключа або власний заголовок.                              |
| Credential | Ключ, який Console надсилає провайдеру.                                         |

## Вибір моделей

Відкрийте провайдера, щоб побачити його моделі. Учасникам доступні лише ввімкнені моделі.

- Перемикач **Enabled** вмикає або вимикає модель.
- Увімкніть **New models**, щоб автоматично вмикати моделі, які провайдер додасть у майбутньому.

## Редагування моделей

Натисніть модель, щоб відредагувати її. Зміни зберігаються, коли ви закриваєте панель.

| Розділ        | Що можна змінити                                               |
| ------------- | --------------------------------------------------------------- |
| General       | Відображувана назва, API ID, підтримка інструментів, типи входу й виходу |
| Variants      | Варіанти з власними заголовками або тілом                      |
| Configuration | Типовий варіант, заголовки й тіло запиту, ліміти токенів        |
| Cost Tiers    | Ціни входу, виходу, читання з кешу й запису в кеш за 1M токенів |

### Власні ціни

Для моделей із каталогу за замовчуванням діють ціни за прейскурантом провайдера. Якщо ви домовилися про інші ціни,
наприклад про знижку за договором з OpenAI, змініть ціни в **Cost Tiers**, щоб звіти про використання
й [бюджети](/console/budgets) відповідали фактичним витратам.

| Поле              | Ціна за прейскурантом | Ваша ціна |
| ----------------- | ------------- | --------- |
| Ціна входу        | $2.50         | $2.00     |
| Ціна виходу       | $15.00        | $12.00    |
| Ціна читання з кешу | $0.25       | $0.20     |

Змінені ціни виділено на сторінці провайдера. Скористайтеся **Restore default value** біля поля або
**⋯ › Restore...** на моделі, щоб повернутися до ціни за прейскурантом.

Додайте ціновий рівень **Context**, якщо використання моделі дорожчає за певного розміру контексту, наприклад для промптів понад
200K токенів.

### Власні моделі

Натисніть **Add Model**, щоб додати модель, якої немає в каталозі, вказавши її **Display name** і **Model ID**.
Скористайтеся **⋯ › Duplicate...** на наявній моделі, щоб почати з її налаштувань.

## Моделі OpenCode

Вкладка **Models** керує [моделями](/console/models), які надає Console і які оплачуються з кредитів робочого простору.
Вона працює як сторінка провайдера:

- Вмикайте або вимикайте окремі моделі.
- Вимкніть **Free models**, щоб заблокувати безкоштовні моделі для робочого простору.
- Увімкніть **New models**, щоб автоматично вмикати нові моделі Console.

Вимкніть провайдера повністю через **⋯ › Disable**, щоб користуватися лише власними провайдерами.

## Використання в OpenCode

Учасники виконують `/connect` і вибирають робочий простір. Кожен увімкнений провайдер з'являється як назва робочого
простору, за якою йде назва провайдера, а `/models` показує його ввімкнені моделі.

```text
Acme Inc. / Anthropic
```

Увімкніть **Managed providers only** у **Settings › General**, щоб обмежити OpenCode провайдерами робочого простору
для всіх.

## Передавання даних про відправника

Якщо провайдер — це шлюз, який запускаєте ви, увімкніть **Send identity** на його сторінці. Тоді Console додає
заголовок `x-opencode-actor` до кожного запиту до моделі, який туди надсилає. Заголовок називає учасника або
сервісний обліковий запис, від імені якого виконано запит, тож ваш шлюз може журналювати запити або обмежувати їх
за відправником.

```text
x-opencode-actor: eyJhbGciOiJFUzI1NiIsInR5cCI6Im9wZW5jb2RlLWFjdG9yK2p3dCIsImtpZCI6Ii4uLiJ9...
```

- Типово він вимкнений, і зміна базової URL-адреси його вимикає.
- Якщо ви використовуєте API безпосередньо від постачальника, як-от `https://api.openai.com/v1`, цього налаштування
  немає, оскільки постачальник ігнорує заголовок.
- Console вилучає будь-який заголовок `x-opencode-*`, який надсилає клієнт, тож єдиний `x-opencode-actor`, який
  отримає ваш шлюз, — це той, що підписав Console.
- **Test connection** і список моделей викликають `GET <base URL>/models` лише з обліковими даними, тож не вимагайте
  заголовка на цьому маршруті.

### Токен

Заголовок — це JWT, який Console підписує для кожного запиту.

| Поле         | Значення                                          |
| ------------ | ------------------------------------------------- |
| `alg`        | `ES256`                                           |
| `typ`        | `opencode-actor+jwt`                              |
| `iss`        | `https://opencode.ai/inference`                   |
| `aud`        | Базова URL-адреса провайдера без завершальних слешів |
| `iat`, `exp` | `exp` настає через 120 секунд після `iat`         |

| Твердження           | Значення                                                               |
| -------------------- | ---------------------------------------------------------------------- |
| `sub`                | `user_id` для учасника, інакше `service_account_id`                     |
| `workspace_id`       | Робочий простір, у якому виконано запит                                 |
| `user_id`, `email`   | Учасник, якщо запит надіслав учасник                                    |
| `service_account_id` | Сервісний обліковий запис, якщо запит надіслав він (зокрема агенти)     |
| `session_id`         | ID сесії клієнта, якщо клієнт його надіслав                             |
| `request_id`         | ID, який клієнт отримує у заголовку відповіді `x-opencode-log-id`      |

Запит учасника містить такий payload:

```json
{
  "iss": "https://opencode.ai/inference",
  "aud": "https://llm.example.com/v1",
  "sub": "user_...",
  "workspace_id": "org_...",
  "user_id": "user_...",
  "email": "ada@example.com",
  "session_id": "ses_...",
  "request_id": "019a6e8f-24a0-7b12-9c3d-4e5f6a7b8c9d",
  "iat": 1794500000,
  "exp": 1794500120
}
```

### Перевірка токена

Console публікує свої відкриті ключі за адресою `https://opencode.ai/inference/.well-known/jwks.json` із заголовком
`Cache-Control: public, max-age=300`. Перевірте підпис, емітента, аудиторію, тип і час, що минув від видачі токена,
а потім — робочий простір.
Цей приклад використовує [jose](https://github.com/panva/jose).

```ts
import { createRemoteJWKSet, jwtVerify } from "jose"

const keys = createRemoteJWKSet(new URL("https://opencode.ai/inference/.well-known/jwks.json"))

export async function sender(request: Request) {
  const token = request.headers.get("x-opencode-actor")
  if (!token) throw new Error("Missing x-opencode-actor")
  const { payload } = await jwtVerify(token, keys, {
    issuer: "https://opencode.ai/inference",
    audience: "https://llm.example.com/v1",
    algorithms: ["ES256"],
    typ: "opencode-actor+jwt",
    maxTokenAge: "120s",
    clockTolerance: "5s",
  })
  if (payload.workspace_id !== "org_...") throw new Error("Another workspace")
  return payload
}
```

Задайте в `audience` базову URL-адресу провайдера, збережену в Console, без завершальних слешів, і замініть `org_...`
на ID робочого простору з вашої URL-адреси Console. Console публікує новий ключ підпису до того, як почне ним
підписувати, тож перевірка з пошуком ключів за `kid`, як у `createRemoteJWKSet`, продовжує працювати
під час ротації.

## Вимкнення або видалення

Відкрийте меню **⋯** провайдера:

- **Disable** приховує провайдера та його моделі від учасників, але зберігає його налаштування.
- **Remove...** видаляє провайдера та його моделі. У діалозі видно, хто користувався ним нещодавно, і є кнопка
  **Disable instead**.

Щоб замінити ключ, натисніть поле облікових даних на сторінці провайдера й уведіть новий ключ.

## Оплата

Провайдер виставляє вам рахунок за токени, а Console не списує за них кредити. Console все одно записує кожен запит
і його вартість за цінами моделі, тож звіти про використання й [бюджети](/console/budgets) їх враховують.

Щоб звертатися до провайдера зі своїх інструментів, а не з OpenCode, використовуйте
[API провайдерів](/console/api/providers).
