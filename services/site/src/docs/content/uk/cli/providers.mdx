title: "Провайдери CLI"
description: "Підключайте облікові записи провайдерів і керуйте обліковими даними з CLI та TUI."
---

Підключіть провайдера в TUI, а потім виберіть одну з його моделей:

```text
/connect
/models
```

`/connect` показує інтеграції, доступні на поточному сервері для цього проєкту. Виберіть провайдера й спосіб автентифікації,
якщо їх кілька, а тоді дотримуйтеся підказок.

## TUI

TUI підтримує API-ключі, OAuth і команди автентифікації провайдерів. OAuth відкриває URL-адресу авторизації або показує
код для введення; натисніть `o`, щоб відкрити URL-адресу, і `c`, щоб скопіювати дані авторизації.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

Запустіть `/connect` ще раз, щоб додати інший обліковий запис. Вибір уже підключеного провайдера відкриває список його облікових записів, де
можна активувати, перейменувати або видалити збережений обліковий запис.

## CLI

Використовуйте `auth login` для тих самих методів провайдера, не відкриваючи TUI. Без аргументу провайдера команда відкриває
інтерактивний вибір провайдера.

```bash
opencode auth login
```

Передайте ID інтеграції або назву, щоб пропустити перший вибір. Використовуйте `--method key`, щоб явно вибрати введення API-ключа.

```bash
opencode auth login anthropic --method key
```

ID методів залежать від провайдера. Запустіть команду без `--method`, щоб побачити доступні методи, коли провайдер має
більше одного.

```bash
opencode auth login openai
```

Введення API-ключа та форми провайдера потребують інтерактивного термінала. Методи OAuth, які просять вставити код
авторизації, також потребують інтерактивного термінала.

## Методи

OpenCode отримує облікові дані провайдерів через чотири методи інтеграції:

| Метод | Поведінка |
| --- | --- |
| API key | Запитує секрет і зберігає його як обліковий запис провайдера. |
| OAuth | Надає URL-адресу браузера, код пристрою або запит коду авторизації, потім зберігає токени й оновлює їх, коли це підтримується. |
| Command | Запускає надану провайдером команду автентифікації й зберігає її стандартний вивід як ключ. |
| Environment | Читає підтримувану змінну з процесу сервера, не зберігаючи її. |

Провайдери можуть додавати форми до методів API-ключа й OAuth для потрібних деталей, як-от назва ресурсу Azure або домен GitHub
Enterprise. CLI і TUI показують ці форми перед початком автентифікації.

## Середовище

Задайте підтримувану змінну середовища провайдера в процесі сервера, який виконує запити до моделей. Для разового приватного
сервера передайте її під час запуску автономного режиму.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

Для спільного фонового сервера додайте змінну до його керованого середовища. Це зупиняє запущений сервіс; наступна
команда OpenCode запустить його з новим значенням.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

Підключення через середовище з'являються в `auth list` з типом `environment`. Це не облікові записи: `auth logout` не може
їх видалити, тож скасуйте змінну, щоб відключитися. Збережений обліковий запис має перевагу над підключенням через середовище для
тієї самої інтеграції.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

Деякі провайдери також використовують власний нативний ланцюжок облікових даних середовища замість змінної API-ключа:

- Amazon Bedrock підтримує типовий ланцюжок облікових даних AWS, зокрема profile, змінні середовища ключів доступу, web identity
  і облікові дані контейнера. Він також підтримує `AWS_BEARER_TOKEN_BEDROCK`.
- Google Vertex використовує Application Default Credentials і проєкт, який можна визначити. Наприклад, автентифікуйтеся за допомогою
  `gcloud auth application-default login` і задайте `GOOGLE_CLOUD_PROJECT`.
- Azure показує **Microsoft Entra ID (Azure CLI)** як метод підключення, коли встановлено `az`. Спершу виконайте `az login`, а потім
  виберіть цей метод у `/connect` або `auth login azure`.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

Дивіться [Провайдери](/providers) щодо налаштування для конкретних провайдерів і на боці сервера.

## Облікові записи

Кожен успішний вхід через API-ключ, OAuth або команду створює збережений обліковий запис. Найновіший обліковий запис стає активним; перемикайте
активний обліковий запис за його міткою або ID облікових даних.

```bash
opencode auth list
opencode auth switch anthropic work
```

Щоб видалити збережений обліковий запис, виконайте `auth logout`. Якщо не вказати аргументів, обидві команди показують меню вибору.

```bash
opencode auth logout anthropic work
```

У TUI `/connect` надає ті самі операції додавання, активації, перейменування й видалення для збережених облікових записів.

## Сховище

Збережені API-ключі та токени OAuth зберігаються в базі даних SQLite сервера. Для локального сервера виведіть шлях до його бази даних:

```bash
opencode debug paths db
```

Звичайний шлях у релізі — `~/.local/share/opencode/opencode.db`; `XDG_DATA_HOME`, канал випуску та `OPENCODE_DB`
можуть його змінити. Не редагуйте базу даних, щоб керувати обліковими даними; використовуйте `/connect` або команди `auth`.

V2 імпортує підтримувані облікові дані зі спадкового `auth.json` у каталозі даних OpenCode під час міграції
бази даних. Нові та оновлені облікові дані зберігаються в SQLite, а не записуються назад у цей файл.
