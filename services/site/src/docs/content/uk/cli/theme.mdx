OpenCode має багато вбудованих тем для світлого й темного режимів. Виберіть одну в налаштуваннях або змішайте власні кольори.

## Вибір теми

Натисніть `Ctrl+P`, виберіть **Open settings**, потім відкрийте **Theme**. Типова тема — `opencode`. Попередня типова тема досі доступна як `opencode-classic`.

Також можна задати тему й режим у глобальних [налаштуваннях CLI](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Виконайте `/themes`, щоб змінити тему, не відкриваючи налаштування.

## Системні кольори

Коли OpenCode може прочитати палітру вашого термінала, у виборі тем з'являється тема `system`. Вона виводить кольори з переднього плану, фону та ANSI-палітри термінала.

Назва теми `system` вибирає кольори, похідні від термінала. Режим `system` слідує за світлим або темним виглядом термінала.

## Режим

Використовуйте `system`, щоб слідувати за виглядом термінала, або зафіксуйте тему в світлому чи темному режимі:

| Режим | Поведінка |
| --- | --- |
| `system` | Слідує за виявленим світлим або темним виглядом термінала. |
| `dark` | Завжди використовує темні кольори теми. |
| `light` | Завжди використовує світлі кольори теми. |

Це відповідає полю `mode` всередині `theme` у вашій конфігурації CLI. Якщо власна тема надає лише один режим, OpenCode використовує його, коли запитано інший.

## Додавання теми

Щоб додати тему, яку ви завантажили або отримали від когось, скопіюйте її JSON-файл у глобальний каталог тем:

```bash
cp theme.json ~/.config/opencode/themes/
```

Також можна покласти тему в каталог `.opencode/themes` проєкту, щоб вона була доступна лише в цьому проєкті.

Ім'я файлу стає назвою теми. Наприклад, `my-theme.json` з'являється як `my-theme`. Перезапустіть OpenCode після додавання файлу, потім виконайте `/themes`, щоб вибрати її.

OpenCode читає лише файли `.json`. Тема, ближча до поточного каталогу, замінює глобальну або батьківську тему з такою самою назвою.

## Використання тем у плагінах

[Плагіни TUI](/build/plugins/cli) отримують підсумкові значення кольорів через `context.theme`, а активний режим — через `context.themeMode`. Використовуйте семантичні токени, щоб кольори плагіна відповідали вибраній темі:

```tsx title="Inside a TUI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

Публічний API плагінів TUI не реєструє теми. Додавайте власні визначення тем через JSON-файли в каталогах вище.

## Створення теми

Використовуйте наш [інструмент тем](https://opencode.ai/theme/), щоб створювати або редагувати теми. Він допомагає зрозуміти структуру, змінити її та задати власні кольори. Пояснення нижче — для довідки.

Тема відокремлює спільні семантичні токени від палітр для кожного режиму:

| Розділ | Призначення |
| --- | --- |
| `base` | Повне дерево токенів, спільне для всіх режимів. |
| `light`, `dark` | Повна палітра відтінків і необов'язкові перевизначення токенів для цього режиму. |

Кожна тема надає повний `base` і визначає принаймні один із `light` або `dark`. Режими успадковують від `base` цього файлу; вони не успадковують від вбудованої теми OpenCode або один від одного.

Наведені нижче приклади показують лише розділи, дотичні до кожної концепції. Скористайтеся редактором тем, щоб згенерувати повний файл, перш ніж його налаштовувати.

### Структура

Розмістіть кольори, які використовують обидва режими, у `base`, а потім за потреби перевизначте їх у `light` або `dark`:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

Повний `base` надає кожен семантичний токен. Кожен режим надає кожен обов'язковий відтінок і може перевизначити будь-яку частину дерева базових токенів.

### Кольори та посилання

Колір може бути hex-значенням, `"transparent"` або посиланням на інший колір теми:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Відтінки

Відтінки — це кольорові шкали з дев'яти кроків. Кожен режим визначає вісім базових відтінків і три псевдоніми:

| Тип | Значення |
| --- | --- |
| Базовий | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Псевдонім | `accent`, `interactive`, `neutral` |
| Крок | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Визначте всі дев'ять кроків для базового відтінку або задайте псевдонім одного відтінку для іншого:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Кроки відтінків підкоряються напрямку контрасту режиму. Світлі теми йдуть від темного на `100` до світлого на `900`; темні теми — від світлого на `100` до темного на `900`.

Масив `categorical` у `base` задає впорядковані відтінки, які розрізняють агентів та інші повторювані елементи:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Семантичні токени

Семантичні токени призначають кольори ролям інтерфейсу. Компоненти використовують ці ролі замість прямого вибору кольорів.

| Група | Призначення |
| --- | --- |
| `text` | Основний, приглушений, ледь помітний текст, текст виділення, дій, полів форми та відгуків. `faint` типово дорівнює `muted`. |
| `background` | Основний фон, виділення, підняті поверхні, дії, поля форм і заливки відгуків. |
| `border`, `scrollbar` | Кольори рамок і смуги прокрутки. |
| `diff` | Кольори доданих, вилучених, контекстних рядків, підсвічування та номерів рядків. |
| `syntax` | Підсвічування вихідного коду. |
| `markdown` | Елементи Markdown. |

Наприклад, `text.muted` керує другорядним текстом, а `background.raised` визначає поступово підняті поверхні:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

`text.selection` і `background.selection` задають колір тексту, який ви виділяєте мишею або клавіатурою. Типово вони беруть сфокусовану основну дію — `text.action.primary.$focused` на `background.action.primary.$focused`.

Ключі синтаксису: `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` і `punctuation`.

Ключі Markdown: `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` і `codeBlock`.

### Дії та стани

Дії мають варіанти `primary`, `secondary` і `destructive`. Дії та поля форм використовують `base` плюс необов'язкові стани взаємодії:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Ключі станів: `$hovered`, `$focused`, `$pressed`, `$selected` і `$disabled`. Незаданий стан використовує колір `base` цієї дії або поля форми.

### Поверхня діалогу

Панелі, діалоги, меню й тости вибирають свою глибину з `background.raised`. Діалоги додатково можуть перевизначати семантичні токени через `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI повторно розв'язує посилання після застосування `@dialog`, тож токени, які посилаються на `$background.base`, слідують за фоном діалогу. `base` контекстної дії стає запасним значенням для її незаданих станів; явні перевизначення станів усе одно мають перевагу.
