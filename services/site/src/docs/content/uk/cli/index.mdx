Запустіть CLI у проєкті, щоб відкрити повноекранний термінальний інтерфейс:

```bash
opencode
```

Передайте каталог, щоб працювати в іншому проєкті:

```bash
opencode ~/code/my-project
```

Рекомендовані термінали:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

Термінали з підтримкою Truecolor найточніше відтворюють кольори тем. Решта використовують найближчі кольори зі своєї палітри.

## Автоматизація

Використовуйте `opencode run`, щоб надіслати промпт, не відкриваючи інтерактивний інтерфейс. Він призначений для скриптів, завдань CI та
інших робочих процесів, яким потрібен вивід моделі прямо в терміналі.

```bash
opencode run "Explain this repository"
```

## Mini

Використовуйте `opencode mini`, щоб запустити мінімальний інтерактивний інтерфейс OpenCode замість повноекранного TUI.

```bash
opencode mini
```

Запустіть `opencode mini --help`, щоб переглянути його параметри сесій, моделей, агентів, промптів і відтворення.

## Фоновий сервіс

За замовчуванням OpenCode знаходить або запускає один спільний фоновий сервер для вашого облікового запису. До нього підключаються
всі локальні клієнти OpenCode. Сервер керує сесіями, конфігурацією, інтеграціями, дозволами та виконанням інструментів.

Використовуйте `--standalone`, щоб працювати з приватним сервером, або `--server`, щоб підключитися до конкретної URL-адреси сервера:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

Щоб зробити приватні сервери типовими для команд CLI замість запуску спільного сервісу, вимкніть його:

```bash
opencode service set disabled true
opencode
```

Це зупиняє запущений фоновий сервіс. `--server` усе одно підключається до явно вибраного сервера; `opencode service start`
усе ще може явно запустити спільний сервіс. Щоб повернутися до автоматичного використання сервісу, виконайте `opencode service unset disabled`.
Сполучення пристроїв потребує спільного сервісу й недоступне, поки його вимкнено.

Дивіться [Усунення проблем](/troubleshooting) щодо діагностики спільного сервісу та [довідник API](/api) щодо серверних ендпоінтів.

## Шляхи

Виведіть конкретний локальний шлях для використання в інших інструментах:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

Необов'язковий селектор приймає `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log` або `repos` і виводить
лише шлях та символ нового рядка. Шлях до бази даних залежить від каналу випуску та `OPENCODE_DB`; відносні перевизначення бази даних
розв'язуються в каталозі даних, а `:memory:` виводиться як є. Ця команда не запускає сервер і не відкриває базу даних.

Пропустіть селектор, щоб показати всі шляхи з підписами:

```bash
opencode debug paths
```

## Видалення

Перегляньте файли й інсталяцію, які буде видалено:

```bash
opencode uninstall --dry-run
```

Виконайте `opencode uninstall`, щоб підтвердити видалення. OpenCode зупиняє зареєстровані фонові сервіси та постійні термінали, перш ніж
видалити глобальний каталог кешу, який спільний для версій і каналів OpenCode. Дані сесій, конфігурація та
стан ніколи не видаляються.

- `--force` (`-f`) пропускає підтвердження; використовуйте його для неінтерактивного видалення.
- Інсталяції через менеджер пакетів використовують виявлений менеджер пакетів. Інсталяції через curl виводять остаточну команду, щоб видалити
  бінарник вручну.
