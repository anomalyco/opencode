---

Політики визначають, чи може OpenCode виконати дію над іменованим ресурсом. Вони описуються
в `policies` і також можуть надходити з підключеного робочого простору
[OpenCode Console](/console).

Політики відокремлені від [дозволів](/permissions). Дозволи — це правила інструментів
для кожного агента, які можуть `allow`, `deny` або `ask`. Політики бінарні, ніколи не запитують
підтвердження й лише звужують те, що інакше дозволили б дозволи та провайдери.

## Налаштування

Забороніть одного провайдера всюди, додавши запис до `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

Заборонений провайдер зникає з каталогу й вибору моделей, навіть якщо має
чинні облікові дані.

Раніші випуски читали політики з `experimental.policies`. Цей ключ досі працює й
об'єднується з `policies`:

```jsonc
{
  "experimental": {
    "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
  },
}
```

## Записи

Кожен запис має три поля:

| Поле       | Значення                                                                                                                    | Що означає                                           |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `action`   | `provider.use`, `tool.use`, `integration.connect`, `integration.use`, `mcp.use`, `skill.use`, `plugin.use`, `websearch.use` | Операція, якою керують                               |
| `resource` | рядок або шаблон підстановки                                                                                                | До чого застосовується запис; залежить від дії        |
| `effect`   | `allow`, `deny`                                                                                                             | Рішення, коли цей запис збігається                   |

Записи, що не проходять перевірку, відкидаються з попередженням у журналі сервера, а
решта списку все одно діє. Перевірте журнал після зміни `deny`.

## Зіставлення

Ресурси використовують ті самі шаблони підстановки на все значення, що й дозволи: `*` збігається з нулем або
більше символами, а `?` — з одним.

```jsonc
{
  "policies": [{ "action": "provider.use", "resource": "company-*", "effect": "deny" }],
}
```

Це забороняє `company-us` і `company-eu`. Шаблон, що закінчується на ` *`, також збігається зі
значенням без аргументів, тож `shell:git push *` охоплює й сам `git push`.

## Порядок

Коли збігається кілька записів, перемагає останній. Правила специфічності немає, тому
ставте широкі записи першими, а винятки — після них. Якщо нічого не збігається,
дію дозволено.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  ],
}
```

Лишається доступним лише Anthropic.

## Провайдери

`provider.use` визначає, чи можна взагалі використовувати провайдера. Ресурс — це
ID провайдера: `anthropic`, `openai`, `opencode` або власний ID з
[`providers`](/providers).

```jsonc
{
  "providers": {
    "company-ai": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://ai.company.example/v1" },
    },
  },
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "company-ai", "effect": "allow" },
  ],
}
```

Запис `providers` налаштовує ендпоінт; записи роблять його єдиним
провайдером, який використовуватиме OpenCode. Політика застосовується незалежно від того, як провайдер став відомий: дані
каталогу, змінні середовища, збережені облікові записи, вбудовані плагіни чи конфігурація.

Використовуйте `provider.use` замість списків `enabled_providers` і `disabled_providers`
з V1. Файли V1 досі завантажуються; дивіться
[Міграція з V1](/migrate-v1#supported-fields-without-direct-native-equivalents).

## Інструменти

Записи `tool.use` можуть остаточно заборонити дію під час перевірки [дозволу](/permissions). Ресурс —
`<action>:<value>`, який зіставляється з кожним ресурсом, що його перевіряє інструмент.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
    { "action": "tool.use", "resource": "edit:*.env", "effect": "deny" },
    { "action": "tool.use", "resource": "webfetch:*", "effect": "deny" },
  ],
}
```

Заборонена перевірка завершується помилкою `Blocked by configuration policy` замість запиту підтвердження. Вона
застосовується після правил агента й збережених схвалень, тож перекриває і `ask`, і
схвалення «Allow always».

| Шаблон                       | Що блокує                                   |
| ---------------------------- | ------------------------------------------- |
| `shell:*`                    | Кожну команду оболонки                      |
| `read:*/.ssh/*`              | Читання матеріалів SSH                      |
| `external_directory:*`       | Будь-який доступ поза Location або робочим деревом |
| `subagent:general`           | Запуск одного субагента                     |
| `github_delete_repository:*` | Один інструмент MCP                         |
| `*`                          | Усе, що ще не заборонено                    |

Запис `tool.use` з `allow` ніколи не надає доступу. Він лише знімає попередню
ширшу заборону `deny`, після чого вирішують власні правила агента.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:*", "effect": "deny" },
    { "action": "tool.use", "resource": "shell:git status *", "effect": "allow" },
  ],
}
```

`git status` повертається до правила `shell` агента; кожна інша команда блокується.

## Інтеграції

Інтеграція — це все, що ви підключаєте в `/connect`: OpenCode Console
(`opencode`), провайдер, як-от `anthropic`, сервіс вебпошуку, як-от `exa`,
або відоме джерело конфігурації, як-от `https://ai.acme.com`. Вхід на сервер MCP
не зачіпають політики інтеграцій; для керування серверами MCP використовуйте
`mcp.use`.

`integration.connect` визначає, які інтеграції показує `/connect` і які можна
підключити. Ресурс — це ID інтеграції.

`integration.use` керує всім, що надає інтеграція: її провайдери й
моделі, її вебпошук, а також сервери MCP і конфігурація, які надає робочий простір Console або
відоме джерело. Ресурс — `<integration>#<account>`, де
account — ID підключеної організації або облікового запису, наприклад
`opencode#org_01M3CAP8H43Z49CER6NT0Y3ZF1`. Без підключеного облікового запису це
голий ID інтеграції: безкоштовний тариф без входу — `opencode`, змінна середовища
`ANTHROPIC_API_KEY` — `anthropic`, а провайдер з `opencode.json` — це його
ID провайдера.

Ця політика MDM вимагає один робочий простір Console і більше нічого. Дивіться [Enterprise](/enterprise) щодо інших прикладів:

```jsonc
{
  "policies": [
    { "action": "integration.connect", "resource": "*", "effect": "deny" },
    { "action": "integration.connect", "resource": "opencode", "effect": "allow" },
    { "action": "integration.use", "resource": "*", "effect": "deny" },
    { "action": "integration.use", "resource": "opencode#org_01M3CAP8H43Z49CER6NT0Y3ZF1", "effect": "allow" },
  ],
}
```

`/connect` пропонує лише Console, щоб учасники могли увійти. Безкоштовний тариф, особисті
облікові записи Console, інші організації, API-ключі зі змінних середовища й провайдери з
`opencode.json` — усе це недоступне. Провайдери, сервери MCP і
вебпошук робочого простору працюють, а їхня зміна в Console не потребує нового профілю MDM.

Прибрати сервери MCP і конфігурацію, які надає інтеграція, можуть лише керовані
політики; її власні політики в будь-якому разі продовжують діяти.

## Сервери MCP, навички й плагіни

| Дія          | Ресурс                                                            |
| ------------ | ----------------------------------------------------------------- |
| `mcp.use`    | [Сервер MCP](/mcp-servers) за його налаштованою назвою             |
| `skill.use`  | [Навичка](/skills) за її ID                                       |
| `plugin.use` | [Плагін](/plugins) за назвою пакета без версії або абсолютним шляхом |

```jsonc
{
  "policies": [
    { "action": "mcp.use", "resource": "*", "effect": "deny" },
    { "action": "mcp.use", "resource": "github", "effect": "allow" },
    { "action": "plugin.use", "resource": "opencode-acme-cli", "effect": "deny" },
  ],
}
```

Заборонений сервер MCP або навичку вилучено, а заборонений плагін не завантажується, хоч би як
його було налаштовано.

### Оновлення з `integration.use`

До OpenCode 2.2.3 `integration.use` охоплював сервери MCP, навички й плагіни
через префікс `mcp:`, `skill:` або `plugin:`. Записи з префіксом досі завантажуються й
перетворюються на `mcp.use`, `skill.use` або `plugin.use`.

Запис без жодного з цих префіксів, зокрема голий `*`, тепер стосується
інтеграцій. Широка заборона, як-от

```jsonc
{ "action": "integration.use", "resource": "*", "effect": "deny" }
```

більше не блокує сервери MCP, навички й плагіни. Натомість вона блокує кожного провайдера,
зокрема безкоштовний тариф, якщо пізніший запис не дозволяє інтеграцію. Щоб зберегти
старе значення, замініть її на:

```jsonc
{
  "policies": [
    { "action": "mcp.use", "resource": "*", "effect": "deny" },
    { "action": "skill.use", "resource": "*", "effect": "deny" },
    { "action": "plugin.use", "resource": "*", "effect": "deny" },
  ],
}
```

Винятки переміщуються так само: `integration.use` `mcp:github` стає `mcp.use`
`github`, а `skill:team:review` стає `skill.use` `team:review`.

Клієнти з версіями до 2.2.3 ігнорують `integration.connect`, `integration.use` (у його новому
значенні), `mcp.use`, `skill.use` і `plugin.use`, тож вимагайте 2.2.3 або новішу версію
всюди, де покладаєтеся на них.

## Вебпошук

`websearch.use` керує провайдерами вебпошуку, які може використовувати інструмент `websearch`. Ресурс —
ID провайдера: `opencode` для OpenCode Web Search з Console,
вбудований провайдер, як-от `exa`, `firecrawl`, `parallel`, `tavily` або `tinyfish`, або
ID провайдера, який додає плагін.

```jsonc
{
  "policies": [
    { "action": "websearch.use", "resource": "*", "effect": "deny" },
    { "action": "websearch.use", "resource": "opencode", "effect": "allow" },
  ],
}
```

Заборонені провайдери вилучаються, навіть коли працюють без API-ключа, як-от Exa і
TinyFish. Коли заборонено всіх провайдерів, інструмент `websearch` більше не пропонується.
Клієнти з версіями до 2.2.6 ігнорують `websearch.use`.

## Пріоритет

Звичайні налаштування дозволяють перемагати найближчій конфігурації. Політики роблять навпаки: записи
з ширшої конфігурації обчислюються пізніше, тож перекривають вужчі. Керована
конфігурація й підключений Console завжди переважають файли користувача та проєкту.

| Рівень      | Джерело                                                                                                        |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| 1 (найвищий) | Керовані налаштування macOS (`/Library/Managed Preferences/ai.opencode.managed.plist`)                        |
| 2           | Системний `opencode.json(c)` (`/Library/Application Support/opencode`, `/etc/opencode`, `%ProgramData%\opencode`) |
| 3           | Підключений робочий простір OpenCode Console                                                                   |
| 4           | Глобальний `~/.config/opencode/opencode.json(c)`                                                               |
| 5           | Прямий `opencode.json(c)`; зовнішні каталоги переважають внутрішні                                             |
| 6 (найнижчий) | `.opencode/opencode.json(c)`; зовнішні каталоги переважають внутрішні                                         |

Репозиторій не може повторно ввімкнути провайдера, якого ви забороняєте глобально:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

```jsonc title="project/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "allow" }],
}
```

`openai` лишається забороненим. У межах одного файлу записи зберігають записаний порядок.

## Console

Робочий простір у [OpenCode Console](/console) компілює свої політики Providers і Tools
у звичайні записи `policies` в конфігурації робочого простору. OpenCode
об'єднує цю конфігурацію як файл конфігурації, що стоїть одразу під керованими
налаштуваннями й системним файлом, тож заборону `deny` організації не може зняти
`allow` репозиторію чи користувача, а дозвіл `allow` організації знімає `deny` з нижчим пріоритетом.
Керовані налаштування й системний файл усе одно перекривають робочий простір.

Заборони з цих записів називають робочий простір:

```text
Blocked by Acme's policy
```

Записи слідують за підключеним обліковим записом.

| Подія                        | Результат                                            |
| ---------------------------- | --------------------------------------------------- |
| Зміни політик у Console      | Застосовуються під час наступного отримання, приблизно кожні п'ять хвилин |
| Перехід на інший робочий простір | Записи замінюються записами того робочого простору |
| Від'єднання                  | Записи очищаються                                   |
| Console недоступний          | Останні записи для цього підключення лишаються чинними |

Плагін Console і плагін політик не можна вимкнути з `plugins`; дивіться
[керування плагінами](/plugins#control).

<Callout type="note">
  Політики не налаштовують ендпоінти чи облікові дані й не можуть зробити непридатний провайдер придатним. Вони також не
  ізолюють код плагінів: заборонений провайдер блокується на звичайному шляху провайдера й моделей.
</Callout>
