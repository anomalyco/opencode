---
title: "Прогрівання"
description: "Надсилайте періодичні запити, які не дають кешу промптів провайдера в сесії спливати, поки ви робите паузу між промптами."
---

Прогрівання сесії надсилає періодичні запити до моделі, щоб зберегти кеші промптів
на боці провайдера чи інший короткоживучий стан, поки ви робите паузу між промптами.
Воно вимкнене типово.

Увімкніть прогрівання в будь-якому [файлі конфігурації OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}
```

З цією конфігурацією OpenCode прогріває нещодавно активну сесію безпосередньо перед
тим, як спливе її кеш промптів: на 90% [`cache.ttl`](/models#cache-lifetime) моделі,
або кожні чотири хвилини, якщо в моделі його немає. Воно триває, доки не мине 30 хвилин
від останнього запиту, що не був прогрівом.

## Параметри

Використайте об'єктну форму, щоб змінити промпт прогріву, інтервал простою чи активне
вікно:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour",
  },
}
```

| Поле | Типово | Призначення |
| --- | --- | --- |
| `prompt` | Інструкція keep-alive | Додається як тимчасове повідомлення користувача до кожного запиту прогріву. Типова інструкція просить модель не виконувати жодної роботи, не використовувати інструменти й відповісти `OK`. |
| `interval` | `"auto"` | Час простою до наступного запиту прогріву. `"auto"` використовує 90% `cache.ttl` моделі або чотири хвилини, якщо його немає. |
| `duration` | `"30 minutes"` | Вікно прогріву, що відраховується від останнього запиту до моделі, який не був прогрівом. |

Пропущені поля об'єкта зберігають типові значення. Наприклад, це змінює лише
інтервал:

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "2 minutes",
  },
}
```

## Автоматичний інтервал

Типово `interval` дорівнює `"auto"`, що прогріває безпосередньо перед тим, як
спливе кеш промптів кожної моделі. OpenCode використовує 90% налаштування
[`cache.ttl`](/models#cache-lifetime) моделі, тож кеш `"5m"` прогрівається
кожні 4.5 хвилини. Моделі без `cache.ttl` прогріваються кожні чотири хвилини.

```jsonc title="opencode.jsonc"
{
  "warming": { "duration": "2 hours" },
  "providers": {
    "anthropic": { "settings": { "cache": { "ttl": "1h" } } },
  },
}
```

Кеш, що триває довше за `duration`, наприклад `"1h"` із типовими 30 хвилинами,
не прогрівається, оскільки він усе одно переживає вікно прогріву. OpenCode
записує це в лог раз на сесію. Збільште `duration`, щоб його прогрівати.

## Для провайдера й моделі

Встановіть `settings.cache.warming` на провайдері чи моделі, щоб прогрівати лише їхні
сесії або дати їм власний розклад. Це налаштування приймає ті самі значення, що й `warming`
верхнього рівня, крім `prompt`, і перекриває його. Налаштування моделі перекриває
налаштування провайдера.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "5m", "warming": true } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "warming": false } } },
      },
    },
  },
}
```

Тут сесії Anthropic прогріваються кожні 4.5 хвилини, крім Claude Haiku
5.5, а інші провайдери не прогріваються. Поля, пропущені в об'єктній формі, беруться
з `warming` верхнього рівня, а далі з типових значень. Некоректне налаштування записує
попередження в лог і повертається до `warming` верхнього рівня.

## Тривалості

`interval` і `duration` приймають рядки тривалості. Обидва мають давати скінченні
значення більші за нуль, а `interval` має бути коротшим за `duration`;
інакше OpenCode пропускає прогрівання й записує попередження в лог.

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "30 seconds",
    "duration": "1 hour",
  },
}
```

## Час

Прогрівання починається після запиту до моделі, що не був прогрівом, у сесії верхнього
рівня. Сесії субагентів не прогріваються. Кожен інтервал відраховується від моменту
надсилання останнього запиту або запиту прогріву, а не від завершення його відповіді,
бо строк життя кешу провайдера починається, коли запит до нього доходить. Запит
прогріву не подовжує активне вікно.

```text
00:00  normal model request sent
00:01  response finishes
00:04  warming request
00:08  warming request
00:30  warming stops
```

Будь-який новий запит до моделі, крім запиту прогрівання, зокрема й під час ущільнення, скидає обидва
таймери. Явний інтервал, що дорівнює тривалості або довший за неї, відхиляється з
попередженням, а інтервал `"auto"` такої довжини пропускає прогрівання, бо кеш
переживає вікно.

```text
00:00  normal model request
00:20  normal model request; window restarts
00:24  warming request
00:50  warming stops
```

OpenCode ніколи не надсилає запит прогріву, поки виконується запит до моделі, зокрема
запит для ущільнення. Якщо такий запит ще виконується, коли спливає інтервал, прогрівання
чекає на його завершення й одразу надсилає свій, якщо кеш від того запиту ще не сплив.
Якщо сплив, прогрівання зупиняється до наступного звичайного запиту.

```text
00:00  normal model request sent
00:04  interval due; request still running
00:04:30  response finishes; warming request
00:08:30  warming request
```

## Запити

Запит прогріву використовує поточну модель, агента, інструкції та контекст розмови
сесії. OpenCode тимчасово додає налаштований промпт, робить один виклик моделі
й відкидає відповідь.

```text
[current session context]
[transient user message: keep-alive prompt]
→ one model response, discarded
```

Запит не приймає ввід, не додає повідомлень до історії й не змінює постійний стан
сесії. OpenCode не викликає локальні інструменти й не продовжує цикл інструментів;
типовий промпт також каже моделі не використовувати інструменти.

## Збої

Збої прогріву записуються в лог, не спричиняючи збою сесії й не змінюючи її. OpenCode
чекає до наступного інтервалу, перш ніж спробувати знову, а початкове активне
вікно продовжує відраховуватися.

```text
00:04  warming request fails; session is unchanged
00:08  next warming attempt
```

Якщо запит прогрівання читає з кешу менше, ніж записує, це промах кешу.
Прогрівання цієї сесії тоді зупиняється до наступного звичайного запиту. Якщо провайдер не повідомляє про використання кешу,
OpenCode не зараховує його запити як промахи.

```text
00:04  warming request misses the cache; warming stops
00:10  normal model request; warming resumes
00:14  warming request
```

## Витрати

Запити прогріву — це справжні запити до провайдера. Вони можуть споживати токени,
спричиняти витрати, зараховуватися до лімітів частоти й збоїти, як інші запити до моделі.

- Коротші інтервали збільшують обсяг запитів.
- Довші тривалості дозволяють більше запитів прогріву.
- Вмикайте прогрівання, лише коли його користь на боці провайдера варта додаткового використання.

Наприклад, на моделі без `cache.ttl` типові налаштування дозволяють до семи
спроб прогріву протягом одного безперервного 30-хвилинного вікна: на 4, 8,
12, 16, 20, 24 і 28 хвилинах.

## Вимкнення

Встановіть `warming` у `false`, щоб явно вимкнути його. Пропуск поля також
залишає прогрівання вимкненим.

```jsonc title="opencode.jsonc"
{
  "warming": false,
}
```
