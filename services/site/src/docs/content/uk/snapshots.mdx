Знімки дають змогу одночасно скасувати останні зміни в розмові й файлах. Використовуйте їх, щоб переробити
щойно виконане, але все важливе зберігайте в комітах Git або резервних копіях.

## Робочий процес

Запустіть `/undo` після відповіді, яку хочете переробити. OpenCode готує відкат, відновлює змінені файли й повертає
видалений промпт у поле введення, щоб ви могли його відредагувати.

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

Надсилання відредагованого промпту фіксує підготовлений відкат. Перш ніж надсилати, запустіть `/redo`, щоб скасувати
його й відновити розмову та файли, які були до `/undo`.

```text
/redo
```

Термінал також надає типові комбінації клавіш:

| Дія | Команда | Комбінація |
| --- | --- | --- |
| Підготувати відкат попереднього повідомлення | `/undo` | `<leader>u` |
| Скасувати підготовлений відкат | `/redo` | `<leader>r` |

Також можна вибрати попереднє повідомлення й натиснути **Revert**, щоб підготувати відкат до цієї точки.

## Створення знімків

На кожному кроці OpenCode намагається зробити знімок безпосередньо перед викликом моделі й ще один після того, як
зафіксує успішне завершення кроку або помилку. У повідомленні асистента фіксуються шляхи, за якими відбулися зміни між знімками.

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

Знімки створюються, якщо це можливо. Якщо один зі знімків недоступний, розмова продовжується, але для цього кроку
відновлення файлів може бути недоступним.

## Обсяг

Знімки охоплюють активний каталог сесії в робочому дереві Git. Наприклад, для сесії, відкритої в
`packages/app`, до знімка потрапляють файли, які відповідають умовам, із `packages/app` та його підкаталогів, а не зміни в інших частинах репозиторію.

| Вміст | Потрапляє до знімка | Приклад |
| --- | --- | --- |
| Відстежувані файли в активному каталозі | Так | `packages/app/src/app.tsx` |
| Невідстежувані файли, які Git не ігнорує, до 2 MiB кожен | Так | `packages/app/notes.txt` |
| Файли, ігноровані Git | Ні | `packages/app/dist/app.js` |
| Окремі невідстежувані файли, більші за 2 MiB | Ні | `packages/app/debug.log` |
| Файли поза активним каталогом | Ні | `packages/server/src/index.ts` |
| Метадані Git та інші побічні ефекти | Ні | коміти, гілки, бази даних або процеси |

Знімки файлової системи потребують репозиторію Git. Поза ним `/undo` усе ще може відкотити історію
розмови, але не може відновити файли.

## Відновлення

Відкат відновлює лише шляхи, приписані крокам асистента після вибраної межі розмови. Кожен шлях повертається до стану
перед першим скасованим кроком; файл, створений цими кроками, видаляється, якщо його тоді не існувало.

| Часова шкала | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| Вибрана межа | версія A | відсутній |
| Пізніші кроки асистента | версія B | створено |
| Після відкату | версія A | видалено |

Шляхи, не пов'язані з цими кроками, не змінюються. Поточні зміни за шляхами, які відновлюються, може бути перезаписано, тому
перегляньте підсумок відновлення й `git diff`, перш ніж продовжити.

```sh
git diff --stat
git diff
```

## Зберігання

OpenCode зберігає знімки локально, в окремій внутрішній базі об'єктів Git у своєму каталозі даних.
Під час створення знімка OpenCode не створює комітів, не переміщує гілки й не змінює індекс вашого репозиторію навмисно.

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

Об'єкти знімків можуть містити повний вміст відстежуваних і невідстежуваних файлів, що відповідають умовам. Ставтеся до
каталогу даних OpenCode як до чутливих локальних даних.

## Налаштування

Знімки ввімкнено за замовчуванням. Задайте `snapshots` зі значенням `false` у своїй [конфігурації](/config#snapshots), щоб
OpenCode більше не створював знімків файлової системи.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

Вимкнення знімків не видаляє вже збережені. Відкат розмови залишається доступним, але без збереженого стану
файлової системи він не може відновити пов'язані зміни файлів.

## Безпека

Знімки спрощують відновлення, але не замінюють транзакцій чи резервних копій:

- Команди оболонки можуть змінювати служби, процеси, мережеві ресурси, бази даних, стан Git, ігнорований вивід або
  файли поза активним каталогом. Відновлення зі знімка не скасовує цих наслідків.
- Після перерваної чи невдалої роботи зміни можуть залишитися, якщо не вдалося зробити знімок або немає придатної пари
  знімків.
- Відновлення змінених шляхів перезаписує їхній поточний вміст. Скасування підготовленого відкату також може
  перезаписати пізніші зміни.
- OpenCode відхиляє операції відкату, поки сесія виконується, але зовнішні редактори й команди все одно можуть
  змінити робоче дерево між створенням знімка й відновленням.
- Фіксація відкату видаляє повідомлення з активного подання розмови, а не з довготривалої історії сесії чи наявного
  сховища знімків. Це не безпечне стирання.

Закомітьте або зробіть резервну копію важливої роботи, перш ніж використовувати `/undo` у робочому дереві зі змінами.
