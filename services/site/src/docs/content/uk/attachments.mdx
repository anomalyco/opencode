## Прикріплення

Прикріпіть локальний файл, а потім попросіть OpenCode використати його у вашому промпті. У десктопному
або вебклієнті виберіть **Attach file**, вставте файл або перетягніть його в промпт.

```text
Summarize the attached README.md and list the required setup steps.
```

У діалоговому вікні десктопного застосунку можна вибрати файли загальним розміром до 20 MiB.
Інші інтерфейси можуть мати нижчі клієнтські ліміти.

<Callout type="warning">
  Перш ніж прикріпити зображення, виберіть модель, яка вміє їх приймати. OpenCode може передати підтримувані зображення провайдеру, але
  провайдер і модель мають власні вимоги до формату, ширини й висоти, кількості та розміру файлів.
  Модель, яка приймає лише текст, може відхилити запит.
</Callout>

## Синтаксис

Вхідні дані промптів і команд V2 описують вкладення через `uri` та необов'язкові
`name` і `description`:

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

Використовуйте абсолютну URL-адресу `file:` для файлу або каталогу, доступного
серверу. Для текстових файлів додатні параметри `start` і `end` вибирають рядки
з відліком від одиниці.

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

Використовуйте URL-адресу `data:`, щоб надіслати вміст безпосередньо:

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

URL-адреси вкладень HTTP і HTTPS не підтримуються. Дивіться згенерований
[довідник API](/api), щоб надсилати промпти програмно.

## Формати

Поточні сесії V2 роблять ці типи вкладень видимими для моделі:

| Вхідні дані             | Модель отримує                                           | Приклад            |
| ----------------------- | -------------------------------------------------------- | ------------------ |
| Текстовий файл UTF-8    | Ім'я файлу й декодований текст                           | `README.md`        |
| Каталог                 | Список файлів і підкаталогів верхнього рівня без рекурсивного обходу | `file:///home/me/` |
| PNG, JPEG, GIF або WebP | Медіа зображення                                         | `diagram.png`      |
| PDF                     | Медіа документа                                          | `report.pdf`       |

PDF потребують моделі з підтримкою вхідних PDF. Якщо модель не підтримує тип вкладення,
OpenCode надсилає замість нього коротку примітку.

SVG обробляється як текст. AVIF, BMP, аудіо, відео та інші бінарні вкладення промптів
не включаються в запит до моделі. Спершу конвертуйте непідтримуваний
бінарник у текст або підтримуване зображення; наприклад, конвертуйте зображення BMP у
PNG, перш ніж прикріпити його.

OpenCode читає кожне вкладення, перш ніж прийняти промпт. Він відхиляє недійсні
URL-адреси, недоступні шляхи, шляхи, що не є файлами чи каталогами, і декодовані
вкладення понад 20 MiB. Тип медіа визначається за байтами, тож зміна імені файлу
або типу медіа в URL-адресі `data:` не робить непідтримуваний бінарник видимим.

## Зображення

Налаштуйте нормалізацію зображень в `opencode.json` або `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Усі поля необов'язкові:

| Поле               | Типове значення | Поведінка                                                                  |
| ------------------ | --------------- | -------------------------------------------------------------------------- |
| `auto_resize`      | `true`          | Змінює розмір зображення, що перевищує налаштоване обмеження; якщо `false`, відхиляє зображення. |
| `max_width`        | `2000`          | Максимальна ширина в пікселях; має бути додатним цілим числом.             |
| `max_height`       | `2000`          | Максимальна висота в пікселях; має бути додатним цілим числом.             |
| `max_base64_bytes` | `5242880`       | Максимальна кількість байтів у зображенні, закодованому Base64; має бути додатним цілим числом. |

Наприклад, ця конфігурація відхиляє, а не змінює розмір зображення, ширшого за 1200 пікселів:

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

Ці налаштування застосовуються і до підтримуваних зображень, прикріплених до промптів, і до зображень,
які повертає вбудований інструмент `read`.

## Обробка

Інструмент `read` розпізнає PNG, JPEG, GIF і WebP за їхнім вмістом і читає
до 20 MiB вихідних даних зображення. Він перевіряє ширину, висоту й довжину Base64
щодо налаштованих обмежень зображень.

З `auto_resize: true` OpenCode зберігає пропорції та зменшує зображення
до обмежень розмірів. Далі він пробує дедалі менші кодування PNG і JPEG,
доки не вкладеться в ліміт Base64, тож тип медіа на виході може змінитися.

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

Якщо жодне кодування не підходить, обробка завершується помилкою. З `auto_resize: false` зображення, що
перевищує будь-яке обмеження, завершується помилкою без змін; зображення, яке не вдається декодувати,
також завершується помилкою.

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

Якщо засіб зміни розміру зображень недоступний, OpenCode передає оригінальне зображення
без змін. Тому налаштування зображень — це обмеження обробки, а не межа завантаження чи
безпеки.

## Обмеження

| Обмеження                      | Значення або поведінка                                        | Приклад                                      |
| ------------------------------ | ------------------------------------------------------------- | -------------------------------------------- |
| Пряме вкладення                | 20 MiB у декодованому вигляді на елемент; клієнти можуть встановлювати нижчі обмеження | Два файли по 12 MiB проходять обмеження на елемент |
| Вибір у діалозі десктопного застосунку | 20 MiB загалом                                        | Два файли по 12 MiB перевищують обмеження вибору  |
| `max_base64_bytes`             | Лише закодований Base64, без повної URL-адреси `data:`        | `SGVsbG8=` рахується як 8 байтів             |
| Обмеження зображень провайдера | Застосовуються після обробки в OpenCode                       | Провайдер може відхилити прийняте зображення |
| Підтримка текстових вкладень моделлю | Не потребує мультимодальної моделі                     | `notes.txt` вставляється як текст промпту    |
| Обмеження тексту в `read`      | Використовує окремі обмеження посторінкового читання й обрізання | Читайте великий журнал посторінково        |

Те, що клієнт прийняв файл, не гарантує, що його вміст дійде до
моделі. Вкладення має бути у форматі, видимому для моделі, і відповідати обмеженням і OpenCode,
і провайдера.
