OpenCode підключається до серверів [Model Context Protocol](https://modelcontextprotocol.io/) і надає доступ до їхніх інструментів, промптів, ресурсів та інструкцій. Інструменти MCP займають місце у вікні контексту моделі, тому додавайте лише потрібні сервери.

## Налаштування

Додайте віддалений сервер із проєкту, який має його використовувати, а потім перевірте підключення:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp list
```

Команда записує сервер у [конфігурацію](/config) проєкту. Додайте `--global`, щоб зробити його доступним у кожному проєкті:

```sh
opencode mcp add context7 --global --url https://mcp.context7.com/mcp
```

Віддалені сервери типово використовують OAuth. Якщо в списку видно `needs authentication`, відкрийте OpenCode, запустіть `/mcps`, виберіть сервер і увійдіть. Підключений сервер готовий до використання агентом:

```text
✓ context7  connected
```

## Конфігурація

Щоб налаштувати сервер вручну, дайте йому унікальну назву в `mcp.servers`. V2 не розміщує назви серверів безпосередньо в `mcp`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
      },
    },
  },
}
```

Сервери підключаються автоматично. Використовуйте `disabled`, а не поле `enabled`, щоб залишити сервер налаштованим, але не підключеним:

```jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "disabled": true,
      },
    },
  },
}
```

Конфігурація проєкту з вищим пріоритетом повністю замінює об'єкт сервера з такою самою назвою. Використовуйте різні назви для окремих підключень чи облікових записів, інакше повторіть у перевизначенні кожне обов'язкове поле:

```jsonc title="opencode.jsonc"
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
      },
    },
  },
}
```

## Локальні

Локальний сервер — це команда, яку OpenCode запускає через транспорт MCP stdio. Додайте його, вказавши команду після `--`:

```sh
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything
```

Передавайте змінні середовища повторюваними прапорцями `--env`:

```sh
opencode mcp add everything --env LOG_LEVEL=info -- npx -y @modelcontextprotocol/server-everything
```

Використовуйте конфігурацію для інших параметрів процесу, як-от робочий каталог:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "everything": {
        "type": "local",
        "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
        "cwd": ".",
        "environment": {
          "LOG_LEVEL": "info",
          "MCP_API_KEY": "{env:MCP_API_KEY}",
        },
      },
    },
  },
}
```

| Поле | Обов'язкове | Опис |
| --- | --- | --- |
| `type` | Так | Має бути `"local"`. |
| `command` | Так | Виконуваний файл, за яким ідуть його аргументи. |
| `cwd` | Ні | Каталог процесу. Відносні шляхи обчислюються від робочої області, яка теж типова. |
| `environment` | Ні | Рядкові змінні, додані до успадкованого середовища процесу OpenCode. |
| `disabled` | Ні | Запобігає підключенню, коли `true`. Типово `false`. |
| `codemode` | Ні | Задайте `false`, щоб надавати інструменти напряму, а не через Code Mode. Типово `true`. |
| `timeout` | Ні | Перевизначення тайм-аутів для сервера. |
| `protocol` | Ні | `auto` (типово), `legacy` або `2026-07-28`. Дивіться [Версія протоколу](#protocol-version). |
| `pool` | Ні | Спільне використання одного підключення між каталогами. Типово `false`. Дивіться [Спільні підключення](#shared-connections). |

Використовуйте `{env:NAME}` для підстановки змінних середовища. Вирази оболонки, як-от `$NAME`, у рядках JSON не розгортаються:

```jsonc
{
  "environment": {
    "MCP_API_KEY": "{env:MCP_API_KEY}",
  },
}
```

## Віддалені

Віддалений сервер використовує транспорт MCP Streamable HTTP і потребує абсолютної URL-адреси:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
```

Передавайте заголовки запиту повторюваними прапорцями `--header`. Беріть посилання `{env:NAME}` у лапки, щоб оболонка записала їх дослівно:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp --header 'CONTEXT7_API_KEY={env:CONTEXT7_API_KEY}'
```

Використовуйте конфігурацію для інших параметрів. Зберігайте секрети у змінних середовища, а не у файлі:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}",
        },
      },
    },
  },
}
```

| Поле | Обов'язкове | Опис |
| --- | --- | --- |
| `type` | Так | Має бути `"remote"`. |
| `url` | Так | Абсолютна URL-адреса ендпоінта Streamable HTTP. |
| `headers` | Ні | Заголовки HTTP із рядковими значеннями, що надсилаються на ендпоінт. |
| `oauth` | Ні | Налаштування OAuth або `false`, щоб вимкнути OAuth. |
| `disabled` | Ні | Запобігає підключенню, коли `true`. Типово `false`. |
| `codemode` | Ні | Задайте `false`, щоб надавати інструменти напряму, а не через Code Mode. Типово `true`. |
| `timeout` | Ні | Перевизначення тайм-аутів для сервера. |
| `protocol` | Ні | `auto` (типово), `legacy` або `2026-07-28`. Дивіться [Версія протоколу](#protocol-version). |
| `pool` | Ні | Спільне використання одного підключення між каталогами. Типово `false`. Дивіться [Спільні підключення](#shared-connections). |

Використовуйте `oauth: false`, лише коли сервер послуговується винятково API-ключем або іншими обліковими даними в заголовку:

```jsonc
{
  "type": "remote",
  "url": "https://mcp.example.com/mcp",
  "oauth": false,
  "headers": { "Authorization": "Bearer {env:MCP_API_KEY}" },
}
```

## OAuth

OAuth увімкнено для віддалених серверів, якщо `oauth` не `false`. OpenCode виявляє сервер авторизації, входить за допомогою PKCE і оновлює токени. Облікові дані зберігаються поза конфігурацією проєкту.

Більшості серверів потрібна лише URL-адреса:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
      },
    },
  },
}
```

Якщо серверу потрібна автентифікація, запустіть `/mcps`, виберіть його і завершіть авторизацію в браузері. CLI може запустити той самий процес:

```sh
opencode mcp auth sentry
```

### Браузер на іншій машині

Коли OpenCode працює через SSH, у контейнері або на віддаленому сервері, після входу браузер не може дістатися до OpenCode і показує сторінку, що не завантажується. Скопіюйте URL-адресу цієї сторінки з адресного рядка і вставте її в запит на вхід:

```text
http://127.0.0.1:52817/callback?code=...&state=...
```

Запит з'являється в `/mcps`, у `opencode mcp auth` і в діалозі входу десктопного та вебзастосунку, поки OpenCode чекає на браузер.

### Реєстрація клієнта

OpenCode ідентифікує себе серверу авторизації першим методом, що підходить:

| Метод | Коли використовується |
| --- | --- |
| Попередньо зареєстрований клієнт | Налаштовано `oauth.client_id`. |
| [Client ID Metadata Document](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#client-id-metadata-documents) (CIMD) | Сервер авторизації підтримує CIMD і публічні клієнти, а `oauth.redirect_uri` не задано. |
| [Динамічна реєстрація клієнта](https://datatracker.ietf.org/doc/html/rfc7591) (DCR) | Жоден із наведених вище варіантів не підходить. OpenCode реєструє клієнта й використовує його для наступних входів, слухаючи порт, указаний під час реєстрації. Якщо порт зайнято, OpenCode повторює реєстрацію. |

Сервер авторизації вмикає CIMD через свої метадані:

```json
{
  "issuer": "https://auth.example.com",
  "client_id_metadata_document_supported": true,
  "token_endpoint_auth_methods_supported": ["none"]
}
```

Із CIMD OpenCode надсилає URL-адресу свого документа метаданих як `client_id` і пропускає реєстрацію:

```text
https://opencode.ai/oauth/opencode/client.json
```

Документ дозволяє такі loopback-переадресації без порту:

- `http://127.0.0.1/callback`
- `http://localhost/callback`
- `http://127.0.0.1/mcp/oauth/callback` для старіших клієнтів

Сервери авторизації приймають будь-який loopback-порт для цих переадресацій, як вимагає [RFC 8252](https://datatracker.ietf.org/doc/html/rfc8252#section-7.3), тому `callback_port` працює з CIMD. Із власним `redirect_uri` це не працює, тож OpenCode повертається до DCR.

Якщо сервер авторизації не підтримує ні CIMD, ні DCR, налаштуйте попередньо зареєстрований клієнт.

### Попередньо зареєстровані клієнти

Коли провайдер надає вам облікові дані клієнта, використовуйте поля OAuth у snake_case з V2:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "oauth": {
          "client_id": "{env:MCP_CLIENT_ID}",
          "client_secret": "{env:MCP_CLIENT_SECRET}",
          "scope": "tools:read tools:execute",
          "callback_port": 19876,
          "redirect_uri": "http://127.0.0.1:19876/callback",
        },
      },
    },
  },
}
```

| Поле | Опис |
| --- | --- |
| `client_id` | ID попередньо зареєстрованого клієнта. Має пріоритет над CIMD і DCR. |
| `client_secret` | Секрет конфіденційного клієнта, надсилається в тілі запиту токена. Пропустіть його для публічних клієнтів. |
| `scope` | Області доступу, які слід запросити, через пробіл. Типово використовується область, яку сервер указує, коли відхиляє неавтентифікований запит. Під час оновлення токена OpenCode повторно надсилає надану область доступу. |
| `callback_port` | Локальний порт зворотного виклику від `1` до `65535`. OpenCode насамперед використовує порт із `redirect_uri`; якщо його немає — порт клієнта, зареєстрованого під час попереднього входу; якщо й такого немає — вільний тимчасовий порт. |
| `redirect_uri` | Попередньо зареєстрований loopback URI, чиї шлях і порт ведуть до локального обробника зворотного виклику. Якщо його задати, CIMD вимикається. |
| `auth_server_metadata_url` | URL-адреса документа метаданих OAuth або OpenID Connect сервера авторизації. Задайте її, коли сервер MCP не публікує метадані захищеного ресурсу із зазначенням свого сервера авторизації. |

Видаліть збережені облікові дані OAuth, коли потрібно знову увійти або змінити обліковий запис:

```sh
opencode mcp logout sentry
```

## Тайм-аути

Тайм-аути — додатні цілі числа в мілісекундах. Задайте типові значення в `mcp.timeout`; об'єкт `timeout` сервера перевизначає відповідні типові.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "timeout": {
      "startup": 45000,
      "catalog": 30000,
      "execution": 600000,
    },
    "servers": {
      "slow-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "timeout": {
          "catalog": 60000,
        },
      },
    },
  },
}
```

| Тайм-аут | За замовчуванням | До чого застосовується |
| --- | --- | --- |
| `startup` | 30 секунд | Підключення транспорту та ініціалізація сервера. |
| `catalog` | 30 секунд | Перелік інструментів, промптів, ресурсів і шаблонів ресурсів. |
| `execution` | 12 годин | Виклики інструментів, отримання промптів і читання ресурсів. |

## Версія протоколу

OpenCode типово перевіряє кожен сервер на наявність редакції 2026-07-28 і повертається до класичного рукостискання MCP `initialize`, якщо сервер її не підтримує. Задайте для сервера `protocol` зі значенням `legacy`, щоб пропустити перевірку:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "older": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "protocol": "legacy",
      },
    },
  },
}
```

| Значення | Поведінка |
| --- | --- |
| `auto` | Типово. Перевіряє через `server/discover` наявність редакції 2026-07-28 і повертається до `legacy`, якщо сервер її не підтримує, зокрема коли віддалений сервер відповідає на перевірку помилкою HTTP 5xx. |
| `legacy` | Надсилає `initialize` і працює з редакціями протоколу до 2025-11-25. |
| `2026-07-28` | Вимагає редакції 2026-07-28. Підключення до старіших серверів завершується помилкою. |

Перевірка старішого локального сервера додає короткоживучий зайвий процес і може чекати до тайм-ауту запуску, якщо сервер ігнорує невідомі запити, тому задавайте `legacy` для серверів, які, як ви знаєте, старші за редакцію 2026-07-28.

## Спільні підключення

Один сервер OpenCode може мати багато відкритих каталогів, і кожен із них підключається до кожного сервера MCP окремо. Задайте `pool` як `true`, щоб каталоги з однаковими налаштуваннями сервера спільно використовували одне підключення й один список інструментів:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "cloudflare": {
        "type": "remote",
        "url": "https://mcp.cloudflare.com/mcp",
        "pool": true,
      },
    },
  },
}
```

- Спільно використовуються лише підключення на редакції 2026-07-28. Сервер, який відповідає старішою редакцією, або сервер зі значенням `legacy` зберігає одне підключення на каталог.
- Каталоги спільно використовують підключення, лише коли збігається все, що його змінює: URL-адреса, заголовки, налаштування OAuth і обліковий запис, у який виконано вхід, для віддаленого сервера, а також команда, робочий каталог і середовище для локального. Тайм-аути й `protocol` теж мають збігатися. Назва сервера збігатися не мусить, але входи зберігаються за назвою, тому сервер з OAuth спільно використовується лише під тією самою назвою.
- Локальний сервер спільно використовується лише між каталогами на цій машині, а не між каталогами в робочому просторі. Щоб ділити його між проєктами, потрібен фіксований `cwd`, наприклад `"~"`. Без нього він запускається в теці кожного проєкту, тож кожен проєкт отримує власний, а OpenCode записує попередження в журнал.
- Спільне підключення не має коренів. Коли інструмент просить ввести дані, запит з'являється в каталозі, який його викликав.
- Підключення закривається, щойно останній каталог, що його використовує, закривається або відключає сервер.

## Назви

OpenCode називає інструмент `<server>_<tool>`. Символи, відмінні від літер, цифр, `_` і `-`, він замінює на `_`:

```text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id
```

Промпти MCP стають командами з назвою `<server>:<prompt>` із тією ж нормалізацією. Наприклад:

```text
/context_7:find_docs
```

Текст команди по черзі заповнює аргументи промпту. Розділяйте їх пробілами, а значення з пробілами беріть у лапки:

```text
/context_7:find_docs react "server components"
```

Вибирайте короткі назви серверів, які лишаються унікальними після нормалізації. У типовому Code Mode інструменти групуються за нормалізованою назвою сервера:

```text
tools.context_7.resolve_library_id(...)
```

## Дозволи

Типово використовується Code Mode. Задайте `codemode` як `false`, коли інструменти сервера мають лишатися в рідному списку інструментів провайдера:

```jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "codemode": false,
      },
    },
  },
}
```

Використовуйте дії дозволів, щоб приховати інструменти або заборонити їх, не відключаючи сервер. Зіставляйте нормалізовану назву `<server>_<tool>`:

```jsonc
{
  "permissions": [
    {
      "action": "context7_*",
      "resource": "*",
      "effect": "deny",
    },
  ],
}
```

## Ресурси

Агенти читають ресурси MCP через два вбудовані інструменти, `list_mcp_resources` і `read_mcp_resource`. Керуйте ними за допомогою таких дій дозволів:

| Дія | Ресурс |
| --- | --- |
| `opencode_list_mcp_resources` | Назва сервера. |
| `opencode_read_mcp_resource` | `<server>:<uri>` |

Наприклад, дозвольте будь-яке читання із сервера `docs`:

```jsonc
{
  "permissions": [
    {
      "action": "opencode_read_mcp_resource",
      "resource": "docs:*",
      "effect": "allow",
    },
  ],
}
```

## Інструкції сервера

Коли сервер повертає інструкції під час ініціалізації, OpenCode додає їх до системного промпту:

```text
<mcp_instructions>
  <server name="sentry">
    Search for an existing issue before creating a new one.
  </server>
</mcp_instructions>
```

Для серверів, що використовують Code Mode, OpenCode додає рядок із зазначенням, де агент може знайти інструменти сервера.

Інструкції сервера пропускаються, якщо дозволи агента забороняють усі його інструменти. Якщо заборонено `execute`, інструменти сервера перелічуються напряму, а його інструкції зберігаються без рядка Code Mode.

## Запити на введення

Сервери можуть під час виклику попросити ввести дані через MCP elicitation. OpenCode показує запит як форму або, для запитів із URL, як посилання для відкриття:

```text
sentry is requesting input
```

Закриття форми скасовує запит.

## Контекст

Для викликів від імені сесії OpenCode надсилає ID сесії в `CallToolRequest.params._meta["ai.opencode/sessionID"]`. Це стосується прямих інструментів і Code Mode через stdio та Streamable HTTP:

```json
{
  "method": "tools/call",
  "params": {
    "name": "lookup",
    "arguments": { "query": "example" },
    "_meta": { "ai.opencode/sessionID": "ses_..." }
  }
}
```

ID — це метадані запиту, а не аргумент інструмента, тому його немає у схемі, видимій моделі. Сприймайте його як непрозоре значення для зіставлення:

| Правило | Поведінка |
| --- | --- |
| Ідентичність | Він позначає сесію OpenCode, що виконує виклик, а не сесію транспорту MCP. |
| Наявність | Він може бути відсутній у викликах без контексту сесії. |
| Безпека | Не використовуйте його сам по собі для автентифікації чи авторизації. |
| Приватність | Віддалені сервери отримують необроблений ID і можуть його журналювати або зберігати. |

## Керування

Перегляньте список серверів та їхній поточний стан підключення з будь-якого проєкту:

```sh
opencode mcp list
```

Використовуйте `/mcps` в OpenCode, щоб переглядати, підключати, відключати сервери або проходити автентифікацію. Використовуйте CLI, щоб додавати сервери й керувати обліковими даними OAuth:

```sh
opencode mcp add sentry --url https://mcp.sentry.dev/mcp
opencode mcp auth sentry
opencode mcp logout sentry
```

Запустіть `opencode mcp auth` без назви, щоб вибрати з-поміж серверів із підтримкою OAuth:

```sh
opencode mcp auth
```

Щоб видалити сервер, видаліть його запис із конфігурації проєкту або глобальної конфігурації, куди його було додано:

```jsonc
{
  "mcp": {
    "servers": {},
  },
}
```

Відключення сервера в `/mcps` не змінює конфігурацію. Редагуйте конфігурацію напряму, щоб змінити налаштування клієнта OAuth, тайм-аути, робочі каталоги або залишити сервер відключеним:

```jsonc
{
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
        "disabled": true,
      },
    },
  },
}
```
