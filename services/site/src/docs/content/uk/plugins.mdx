Додавайте опубліковані пакети, пакети з версією, пакети зі скоупом або локальні каталоги плагінів до
`opencode.json(c)`.

## Налаштування

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

Відносні шляхи обчислюються від файлу конфігурації, що містить запис.

Налаштовані локальні шляхи мають бути каталогами. Шлях до окремого файлу пропускається. Дивіться
[Завантаження](/build/plugins#load), щоб дізнатися, як OpenCode знаходить кожну частину в каталозі.

Масиви плагінів із застосовних файлів конфігурації застосовуються від найнижчого до найвищого пріоритету, а не
замінюють один одного.

```text
~/.config/opencode/opencode.jsonc
./opencode.jsonc
./.opencode/opencode.jsonc
```

## Виявлення

OpenCode також завантажує безпосередні файли `.ts` і `.js` та каталоги пакетів плагінів першого рівня з кожного
виявленого каталогу `.opencode/plugins/`.

```text
.opencode/
└── plugins/
    ├── concise.ts
    ├── reviewer.js
    └── acme-package/
```

Глобальні плагіни використовують ту саму схему виявлення в каталозі конфігурації OpenCode.

```text
~/.config/opencode/plugins/
```

Каталог `plugins/` поруч із `opencode.json(c)` у корені проєкту не виявляється автоматично; налаштуйте його каталоги
плагінів явно або перемістіть його в `.opencode/`.

```jsonc title="opencode.jsonc"
{
  "plugins": ["./plugins/local"]
}
```

## Керування

OpenCode обробляє записи плагінів послідовно. Поставте `-` перед ID або шаблоном, щоб вимкнути відповідні плагіни. Використовуйте `*`
для всіх плагінів і `.*` для збігу з префіксом ID. Пізніший ID знову вмикає плагін.

```jsonc title="opencode.jsonc"
{
  "plugins": ["*", "-opencode.provider.*", "opencode.provider.openai", "-acme.reviewer"]
}
```

Щоб вимкнути повідомлення, яке додається до нових форків, додайте `"-opencode.fork-notice"` до `plugins`.

Два вбудовані плагіни ігнорують видалення, щоб репозиторій не міг вимкнути застосування [політик](/policies):
`opencode.config.policy` і `opencode.provider.opencode` — з'єднання Console, яке доставляє політику організації.

## Керування пакетами

Встановлюйте, перелічуйте, перевіряйте, оновлюйте й видаляйте глобальні пакетні плагіни за допомогою CLI.

```sh
opencode plugin add opencode-acme-plugin@1.2.0
opencode plugin list
opencode plugin list --builtin
opencode plugin check
opencode plugin update
opencode plugin update opencode-acme-plugin
opencode plugin remove opencode-acme-plugin@1.2.0
```

`plugin check` перевіряє оновлення для серверних, лише GUI та лише TUI пакетних плагінів. `plugin update` оновлює
кожен застарілий пакет; передайте налаштовану ціль пакета, щоб перевірити або оновити лише цей пакет. Локальні плагіни
й точні ревізії пакетів пропускаються.

Пакет оновлюється сам, коли вказує, за чим стежити: `name@latest`, діапазон версій на кшталт `name@^1.2.0`,
`name@~1.2.0`, `name@1.x` чи `name@>=1.2.0 <2`, гілка Git на кшталт `github:acme/plugin#main` або діапазон `semver:`
у Git. OpenCode перевіряє його під час запуску й кожні 24 години, встановлює новішу версію та перезавантажує її.
Діапазон переходить лише на версії в його межах. Якщо нова версія не завантажується, попередня продовжує працювати й
залишається встановленою.

Гола назва (`name`) або репозиторій (`github:acme/plugin`) залишається на встановленій версії. Так само інші
npm-теги, як-от `name@next`, і теги Git. `plugin check` усе одно повідомляє про їхні оновлення, а `plugin update` їх
встановлює. Точні версії й хеші комітів зафіксовані.

Встановлення пакетів приймає npm-назви з версіями, тегами чи діапазонами, а також сумісні з npm специфікації
Git-пакетів. Репозиторії Git можуть використовувати хостингові скорочення, HTTPS або SSH, зокрема приватні
репозиторії, доступні через ваші наявні облікові дані Git.

```sh
opencode plugin add @acme/opencode-plugin@latest
opencode plugin add github:acme/opencode-plugin
opencode plugin add git+ssh://git@github.com/acme/opencode-plugin.git#main
opencode plugin add 'github:acme/plugins#main::path:packages/opencode-plugin'
```

Підтримуються гілки, теги, повні хеші комітів і селектори підкаталогу репозиторію npm `::path:`. Локальні шляхи
налаштовуйте напряму; `plugin add` не приймає цілі tarball і npm-аліасів.

## Перезавантаження

Зміни в каталогах конфігурації, за якими стежать, перезавантажуються автоматично. Під час запуску сервер одразу
завантажує кешовані пакетні плагіни, встановлює відсутні пакети у фоні та перевіряє незафіксовані npm- і Git-плагіни
на оновлення. Точні npm-версії й повні хеші комітів Git залишаються зафіксованими. Зміни в локальних залежностях, за
якими не стежать, усе ще можуть вимагати перезапуску OpenCode.

```sh
touch .opencode/plugins/concise/index.ts
opencode service restart
```

## Desktop

Плагін, що експортує `./gui-experimental`, також додає панелі, команди або налаштування в OpenCode Desktop. Застосунок
завантажує плагіни із сервера, на якому працює, тому налаштуйте плагін у глобальному `opencode.json(c)`, щоб
використовувати його в кожному вікні.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "plugins": ["opencode-acme-plugin"],
}
```

**Settings > Extensions > Plugins** перелічує їх, коли вибрано власний сервер застосунку. Перемикач плагіна вимикає
лише його десктопний інтерфейс, а **Reload** завантажує його знову після збою. Щоб вимкнути весь плагін, додайте `-`
та його ID до `plugins`, наприклад `"-acme"`.

## Термінал

Плагіни лише для TUI налаштовуються окремо й залишаються активними, коли підключено віддалений сервер.

```json title="cli.json"
{
  "plugins": ["opencode-acme-cli"]
}
```
