Виберіть модель для поточної сесії за допомогою `/models`:

```text
/models
```

OpenCode перелічує моделі з [models.dev](https://models.dev), інтеграцій провайдерів і вашої конфігурації. Список
показує лише ввімкнені моделі, чий провайдер доступний у поточному проєкті. Підключайте провайдерів у розділі
[Провайдери](/providers).

## Вибір

Виберіть запис із `/models`, а не вгадуйте його провайдера чи ID моделі. Вибір діє для поточної сесії й не змінює вашу
конфігурацію.

```text
anthropic/claude-sonnet-5-5
```

Доступність залежить від проєкту:

- Модель має бути ввімкнена.
- Її провайдер має бути доступний у поточному проєкті.
- Облікові дані й конфігурація з іншого проєкту не переносяться автоматично.

## Запуски

Використовуйте `--model`, щоб вибрати модель для одного запуску з командного рядка, не змінюючи налаштовану типову модель:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Агенти й команди також можуть вибирати власну модель. Дивіться [Агенти](/agents) і [Команди](/commands).

## Типові значення

Задайте `model` у `opencode.json` або `opencode.jsonc`, щоб вибрати типову модель для нової роботи:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Налаштована модель стає типовою в каталозі, коли вона ввімкнена й її провайдер доступний. Інакше OpenCode
повертається до найновішої доступної підтримуваної моделі.

- Модель, уже вибрана для сесії, має перевагу над налаштованою типовою.
- Зміна моделі сесії не переписує файл конфігурації.
- Параметр `model` верхнього рівня наразі зберігає лише провайдера й модель за замовчуванням, а не варіант.

Дивіться [Конфігурацію](/config), щоб дізнатися про розташування конфігурації та пріоритет.

## Безкоштовні моделі

Задайте `OPENCODE_DISABLE_FREE_MODELS=1` (або `true`) у процесі сервера, щоб приховати
[безкоштовні моделі OpenCode](/console/models#free-models):

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

Для спільного фонового сервера:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

Безкоштовними вважаються моделі `opencode` або `opencode-go` без вхідної ціни. Ці моделі зникають із каталогу й типових
значень; явний вибір такої моделі завершується помилкою `Model unavailable`. Без входу провайдер `opencode` відсутній,
доки ви не підключите обліковий запис OpenCode Console або не задасте `OPENCODE_API_KEY`, і це відновить його платні
моделі.

Щоб заблокувати безкоштовні моделі для всіх в організації, натомість використайте політику. Дивіться
[Enterprise](/enterprise#block-free-models).

## Варіанти

Варіанти — це іменовані параметри для однієї моделі, які часто використовують для зусилля міркування або бюджетів
токенів. Додайте `#variant` під час вибору для запуску, сесії, агента або команди:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

Назви варіантів походять із поточних метаданих каталогу вибраної моделі. Назви, як-от `low`, `high` і `max`, доступні не
для кожної моделі, а невідомий варіант спричиняє помилку визначення моделі.

Визначте нові варіанти або замініть варіанти каталогу з тим самим ID у масиві `variants` моделі:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Кожен варіант може містити `settings`, `headers` і `body`. Його значення застосовуються після значень провайдера й
моделі.

Щоб замінити варіанти міркування моделі, опишіть її засоби керування міркуванням у `capabilities.reasoning`,
використовуючи форму v2 з [models.dev](https://models.dev). З них OpenCode будує варіанти для пакета моделі:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| Поле        | Призначення                                                                    |
| ----------- | ------------------------------------------------------------------------------ |
| `supported` | Чи міркує модель. `false` або `true` без засобів керування не додає варіантів. |
| `toggle`    | Додає варіант `none`, який вимикає міркування.                                 |
| `effort`    | Рівні зусилля для пропозиції. `default` зберігає типове значення провайдера й не додає варіанта. |
| `budget`    | Необов'язкові `min` і `max` токенів міркування. Ігнорується, коли задано `effort`. |

Варіанти, перелічені в `variants`, застосовуються поверх тих, що побудовані з `capabilities.reasoning`.

## Параметри

Записи провайдера й моделі можуть налаштовувати запити за допомогою `settings`, `headers` і `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Поле       | Призначення                                                        |
| ---------- | ------------------------------------------------------------------ |
| `settings` | Параметри пакета провайдера, як-от `baseURL` або `reasoningEffort`. |
| `headers`  | Додаткові HTTP-заголовки запитів.                                  |
| `body`     | Поля тіла запиту, специфічні для провайдера.                       |

OpenCode застосовує спершу значення провайдера, потім значення моделі, а останнім — вибраний варіант.

- Вкладені об'єкти `settings` і `body` об'єднуються.
- Пізніші масиви й скалярні значення замінюють попередні.
- Назви заголовків зіставляються без урахування регістру.
- Параметри залежать від провайдера, і інший пакет провайдера може їх ігнорувати або відхиляти.

## Псевдоніми

Використовуйте `modelID`, щоб дати моделі API зручніший ID у каталозі:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Тут `openai/coding-default` — це доступне для вибору посилання, а `gpt-6.1-sol` надсилається провайдеру. Для моделі,
якої ще немає в каталозі, OpenCode припускає:

- Підтримку інструментів JSON, вхід тексту й зображень і вихід тексту. Жодного вводу інструментів у вільному форматі,
  якщо `capabilities.freeform` не перелічує формат.
- Ліміт контексту 200,000 токенів і ліміт виходу 32,000 токенів.
- Невизначений ліміт вхідних даних.

OpenCode розпізнає `text`, `regex` і `lark`. Інші назви форматів із models.dev ігноруються без вилучення моделі чи її
інструментів. Якщо проксі перед моделлю каталогу відхиляє інструменти вільного формату, задайте `capabilities.freeform`
як `[]` для цієї моделі.

Це запасні припущення, а не виявлені можливості. Задавайте точні значення `capabilities` і `limit`, коли вони відомі;
явні значення замінюють запасні. Додайте `disabled: true`, щоб приховати модель із доступного каталогу:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Міркування

Для сумісної з OpenAI моделі, яка передає міркування потоком в окремому полі повідомлення асистента, задайте
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode розпізнає `reasoning`, `reasoning_content` і `reasoning_text`, а також приймає інший рядок, специфічний для
провайдера. Він читає потокове міркування з цього поля й відновлює поле, надсилаючи попередні повідомлення асистента
назад моделі. Дивіться [Сумісність](#compatibility), щоб дізнатися про пов'язане поле `requireReasoning`.

## Кешування промптів

OpenCode автоматично розставляє точки розриву кешу промптів на маршрутах, які, як відомо, їх потребують, як-от
Anthropic. Коли моделі Claude обслуговує сумісний з OpenAI проксі, як-от LiteLLM, OpenCode не може визначити, що їм
потрібні точки розриву `cache_control` у стилі Anthropic. Задайте `compatibility.cacheFormat` для цих моделей Claude:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

Тоді OpenCode позначає останнє визначення інструмента, системний промпт і останнє повідомлення як
`cache_control: { "type": "ephemeral" }`, що використовує типовий п'ятихвилинний строк життя кешу ендпоінта.
Використовуйте `"alibaba"` для моделей Alibaba Model Studio, які приймають ті самі маркери, але ігнорують їх для
визначень інструментів. Задайте `compatibility.cacheFormat` на провайдері, коли кожна модель, яку він обслуговує,
приймає той самий формат. Дивіться [Сумісність](#compatibility), щоб дізнатися про інші поля.

### Строк життя кешу

OpenCode не надсилає строк життя кешу типово, тому кожен провайдер використовує власне типове значення, як-от п'ять
хвилин в Anthropic. Задайте `settings.cache.ttl` на провайдері або моделі, щоб запросити інший. Налаштування моделі
перевизначає налаштування провайдера.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

`ttl` приймає число й одиницю: `ms`, `s`, `m`, `h` або `d`, як-от `"5m"`, `"1h"` чи `"24h"`. OpenCode надсилає його як
задано, тому використовуйте значення, яке приймає провайдер:

| API | Куди потрапляє строк життя |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` у кожному маркері кешу. Anthropic приймає `"5m"` і `"1h"`. |
| Bedrock Converse | `ttl` у кожному `cachePoint`. Старіші моделі Claude, які кешують лише на п'ять хвилин, ігнорують `"1h"`. |
| OpenAI Chat and Responses | `"24h"` потрапляє в `prompt_cache_retention`; інші значення — у `prompt_cache_options.ttl`. |

Провайдери, які кешують автоматично без маркерів, як-от Gemini, його ігнорують. Довший строк життя зазвичай дорожчий
для запису: Anthropic стягує 2× вхідної ціни за годинний запис у кеш і 1.25× за п'ятихвилинний.

[Прогрівання](/warming) може використовувати строк життя, щоб розрахувати час своїх запитів із `interval: "auto"`.

## Сумісність

`compatibility` описує особливості запитів і відповідей API моделі: наприклад, у якому полі передаються міркування
та чи приймає ендпоінт `prompt_cache_key`. Кожна модель працює через один API. Поле діє, лише якщо цей API його читає.
Інші поля ігноруються.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

`compatibility` провайдера застосовується до кожної моделі цього провайдера. Власний `compatibility` моделі перевизначає
його поле за полем: OpenCode починає зі значень, які [models.dev](https://models.dev) публікує для API моделі
(`reasoningField`, `maxTokensField` і `mediaInput`, а також `supportsEffortUpdates` і `supportsSystemUpdates`, коли
models.dev позначає API як такий, що їх підтримує), потім застосовує конфігурацію моделі. Незадані поля зберігають
вбудоване типове значення або виявлення пакета провайдера. `supportsThinkingBlockBinding`, `supportsEffortUpdates` і
`supportsSystemUpdates` існують лише для моделей.

| Поле | Що робить | Читає | Значення й типове |
| --- | --- | --- | --- |
| `reasoningField` | Поле повідомлення асистента з міркуванням. OpenCode перевіряє його першим, коли читає міркування з потоку, і використовує, коли надсилає моделі попередні міркування. | OpenAI Chat | Будь-яка назва поля, крім `role`, `content`, `refusal` або `tool_calls`. Якщо назву не задано, OpenCode бере поле, знайдене в потоці, а якщо такого немає — `reasoning_content`. |
| `requireReasoning` | Надсилає поле міркування в кожному попередньому повідомленні асистента, порожнім рядком, коли міркування не було. | OpenAI Chat | `true` або `false`. Типово `true`, коли задано `reasoningField` або модель — DeepSeek, інакше `false`. |
| `maxTokensField` | Поле тіла, яке несе ліміт вихідних токенів. | OpenAI Chat | `max_completion_tokens` або `max_tokens`. Якщо не задано, визначається `max_tokens` для провайдерів, яким він потрібен, як-от DeepSeek, Moonshot, Together AI, Z.AI і Cerebras, інакше `max_completion_tokens`. |
| `requireFinishReason` | Вважає потік, що завершився без `finish_reason`, помилкою неповної відповіді. `false` приймає його як завершений. | OpenAI Chat | `true` або `false`. Типово `true`. |
| `requireAssistantAfterTool` | Вставляє повідомлення асистента між результатом інструмента й наступним повідомленням користувача для ендпоінтів, які відхиляють такий порядок. | OpenAI Chat | `true` або `false`. Типово `true` для ID моделей родини Mistral, інакше `false`. |
| `supportsPromptCacheKey` | Чи приймає ендпоінт поле тіла `prompt_cache_key`. | OpenAI Chat, OpenAI Responses, Mistral | `true` або `false`. OpenAI Chat надсилає ключ, лише коли `true`, що деякі пакети провайдерів задають типово. Інші API надсилають його, якщо не `false`. |
| `streamUsage` | Запитує використання токенів у потоці за допомогою `stream_options.include_usage`. | OpenAI Chat | `true` або `false`. Типово `true`. |
| `cacheFormat` | Синтаксис маркерів кешу промптів, який приймає ендпоінт. Перевизначає автоматичне розміщення точок розриву провайдером. `alibaba` пропускає визначення інструментів. | Кожен API з маркерами кешу промптів, зокрема OpenAI Chat, Anthropic Messages і Bedrock Converse | `anthropic` або `alibaba`. Якщо не задано, використовується типове значення провайдера. Дивіться [Кешування промптів](#prompt-caching). |
| `supportsThinkingBlockBinding` | Просить API відкидати блоки міркування, чий попередній контекст змінився, замість відхилення запиту. | Anthropic Messages, Bedrock Converse | `true` або `false`. Якщо не задано, визначається для Claude 5.1 і новіших. |
| `supportsEffortUpdates` | Надсилає зміни зусилля міркування як оновлення в межах повідомлення, які зберігають кеш промптів. Інакше зусилля змінюється для всього запиту. | Anthropic Messages, OpenAI Responses | `true` або `false`. Якщо не задано, визначається для Claude Opus 5, Claude 5.1 і новіших, а також GPT-6 і новіших. |
| `supportsSystemUpdates` | Надсилає системні повідомлення, додані посеред розмови, як нативні системні повідомлення. Інакше вони обгортаються як текст у наступному ході користувача. | Anthropic Messages | `true` або `false`. Якщо не задано, визначається для Claude Opus 4.8 і Claude 5 і новіших. |
| `mediaInput` | Куди потрапляють зображення та інші медіа в запиті рішення. | System One | `assets` (зображення, на які посилається стан), `state` (усередині стану) або `root` (списки `images`, `audio` і `videos` верхнього рівня). Якщо не задано, використовується типове значення провайдера. |

## Локальні

OpenCode автоматично виявляє моделі від Ollama, LM Studio і vLLM за їхніми типовими локальними адресами. Також можна
вручну налаштувати будь-який сервер, сумісний з OpenAI.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Коли Ollama слухає на `http://127.0.0.1:11434`, виберіть виявлену модель з ID провайдера `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode оновлює перелік у фоні й читає можливості контексту, зору та використання інструментів з Ollama. Моделі лише
для ембедингів виключаються.

Для іншого хоста або порту задайте сумісну з OpenAI URL-адресу Ollama. Виявлення все одно використовує нативний API
Ollama за тим самим префіксом шляху:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Пропустіть `apiKey`, коли ендпоінт не потребує bearer-автентифікації.
- Вимкніть виявлення за допомогою `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Коли неавтентифікований сервер LM Studio працює на `http://127.0.0.1:1234`, виберіть виявлену модель з ID провайдера
`lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode оновлює перелік у фоні й читає можливості контексту, зору та використання інструментів з LM Studio. Моделі
ембедингів виключаються.

Для іншого хоста або порту задайте сумісну з OpenAI URL-адресу. Моделі все одно виявляються автоматично:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Пропустіть `apiKey`, коли автентифікацію LM Studio вимкнено.
- Вимкніть виявлення за допомогою `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Коли vLLM слухає на `http://127.0.0.1:8000`, виберіть виявлену модель з ID провайдера `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode перевіряє `/health`, оновлює `/v1/models` у фоні, використовує повідомлений `max_model_len` як ліміт контексту
й включає лише картки моделей, якими володіє `vllm`.

Виявлені моделі заявляють про текстовий вхід і вихід, але не про зір чи інструменти. vLLM вмикає виклик інструментів
серверними прапорцями, як-от `--enable-auto-tool-choice` і `--tool-call-parser`, про які виявлення не повідомляє.

Для іншого ендпоінта або сервера з автентифікацією задайте його сумісну з OpenAI URL-адресу:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Пропустіть `apiKey`, коли автентифікацію вимкнено.
- Вимкніть виявлення за допомогою `"plugins": ["-opencode.provider.vllm"]`.
- Проксі з префіксом шляху підтримуються. Наприклад, `https://example.com/vllm/v1` перевіряє `/vllm/health` і виявляє
  `/vllm/v1/models`.

### Сумісний сервер

Для іншого сервера, сумісного з OpenAI, визначте пакет провайдера, ендпоінт і принаймні одну модель:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Використовуйте справжню назву моделі сервера, ліміти, вхідні й вихідні типи та підтримку інструментів. OpenCode не може
визначити, чи точні запасні значення для власної моделі. Якщо ендпоінт потребує ключа, додайте `apiKey` до `settings` із
підстановкою середовища, як-от `"apiKey": "{env:LOCAL_API_KEY}"`; не додавайте секрети до репозиторію.

## Посилання

Селектори моделей використовують `provider/model` з необов'язковим `#variant`:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| Частина | Правило |
| --- | --- |
| Провайдер | Закінчується на першому `/`; не може містити `/` або `#`. |
| Модель | Може містити додаткові символи `/`; не може містити `#`. |
| Варіант | Іде після `#`, якщо він є. |
| Регістр | ID провайдера й моделі чутливі до регістру. |

Використовуйте ID з каталогу, а не відображувані назви провайдерів. Поля `model` кореня, агента й команди приймають
рядкову форму вище або розширений об'єкт:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}
```

Розширена форма корисна для згенерованої або програмної конфігурації.

## Застереження

Пам'ятайте ці правила, налаштовуючи моделі:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- Селектор-об'єкт використовує `model`; запис каталогу провайдера використовує `modelID` для ID, що надсилається
  провайдеру.
- Хоча форма кореневого вибору приймає варіант, типовий каталог V2 його не зберігає. Вибирайте варіанти для сесії,
  запуску, агента або команди натомість.
- Параметри моделі залежать від провайдера. Інший пакет провайдера може їх ігнорувати або відхиляти.
- Дані каталогу, облікові дані й конфігурація прив'язані до розташування. Модель, доступна в одному проєкті, може бути
  недоступною в іншому.
- Файли конфігурації зазвичай перезавантажуються автоматично. Запит до моделі, який уже виконується, зберігає
  налаштування, з якими почався.
