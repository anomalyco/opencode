description: "Визначайте агентів, яких можна використовувати повторно, у Markdown або конфігурації, кожен зі своїм системним промптом, моделлю, дозволами та режимом."
---

Створіть Markdown-файл, щоб додати агента, якого можна використовувати повторно. Цей приклад додає рецензента лише для читання, якого головний агент може запускати для перевірки коду:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-5-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Попросіть свого основного агента скористатися ним:

```text
Use the reviewer subagent to review my current changes.
```

Агент поєднує системний промпт, налаштування моделі, дозволи й деталі відображення в іменований профіль асистента.

## Розташування

Зберігайте Markdown-агентів глобально для всіх проєктів або всередині проєкту:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode знаходить проєктні каталоги `.opencode` від поточного каталогу аж до кореня проєкту. Вкладений шлях стає частиною ID агента:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Формати

### Markdown

Frontmatter приймає ті самі поля, що й запис `agents` у конфігурації. Тіло Markdown стає системним промптом агента (`system`):

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

Поля frontmatter з V1 застаріли. Дивіться [Файли агентів](/migrate-v1#agent-files), щоб дізнатися, як читаються файли, що досі їх використовують.

### JSONC

Визначайте агентів у розділі `agents` будь-якого [файлу конфігурації OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Вибір

Задайте основного агента, який використовується, коли сесія не вибрала жодного:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

Агент за замовчуванням має існувати, бути видимим і підтримувати роботу в ролі основного. Інакше OpenCode вибирає `build`, а якщо це неможливо — першого видимого агента, який може бути основним. Зміна цього налаштування не замінює агента, збереженого в наявній сесії.

## Режими

Задайте `mode` залежно від того, де агент має працювати:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Режим | Поведінка |
| --- | --- |
| `primary` | Працює як основний агент сесії. Це типовий режим для нового власного агента. |
| `subagent` | Працює лише в дочірній сесії через інструмент `subagent`. |
| `all` | Працює і як основний агент, і як субагент. |

Субагенти працюють із чистим контекстом у власних дочірніх сесіях. Вони завжди працюють
у фоновому режимі: батьківський агент отримує звіт, коли дочірній переходить у стан простою, і ще раз
після кожного наступного раунду роботи. Дозволи `subagent` батьківського агента визначають,
яких агентів він може запускати, а дочірній використовує власні налаштовані дозволи.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Вбудовані агенти

OpenCode містить таких видимих агентів:

| Агент | Режим | Призначення |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Типовий агент для кодування. Інструменти й доступ поза робочою областю дозволені типово; читання чутливих файлів середовища потребує підтвердження. |
| **Plan** (`plan`) | `primary` | Досліджує та планує, не редагуючи звичайні файли проєкту. За запитом може записувати файли планів OpenCode, а shell-команди й далі керуються дозволами. |
| **General** (`general`) | `subagent` | Виконує дослідження й багатокрокову роботу з широким доступом до інструментів, але не може запускати інших субагентів. |
| **Explore** (`explore`) | `subagent` | Шукає та читає код або вебджерела, не редагуючи файли. |

Перевизначте вбудованого агента, використавши той самий ID:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Приховані агенти `compaction`, `title` і `summary` виконують обслуговування й не можуть бути вибрані напряму. У V2 немає вбудованого агента `scout`.

## Об'єднання

Визначення агентів об'єднуються в порядку конфігурації. Пізніші скалярні значення замінюють попередні, мапи запитів об'єднуються за ключами, а правила дозволів дописуються в кінець:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

Глобальні `permissions` застосовуються перед правилами конкретного агента, тож пізніші правила агента можуть їх уточнювати.

## Параметри

### Опис

`description` пояснює призначення агента. Додавайте його субагентам, бо OpenCode показує його моделі, яка вибирає, якого агента запускати:

```yaml
description: Reviews database migrations for safety
```

### Режим

`mode` приймає значення `primary`, `subagent` або `all`. Якщо його не вказати для нового власного агента, типово буде `primary`:

```yaml
mode: all
```

### Модель

`model` використовує `provider/model` з необов'язковим `#variant`:

```yaml
model: anthropic/claude-sonnet-5-5#high
```

Конфігурація JSON також приймає розгорнуту форму:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-5-5",
        "variant": "high",
      },
    },
  },
}
```

- Субагент використовує налаштовану модель або успадковує модель батьківської сесії, якщо модель не налаштована.
- Сесія зберігає вибрану модель окремо. Вибір основного агента за ID не змінює цю модель.

### Системний промпт

`system` задає системний промпт агента. Непорожнє значення замінює базовий промпт провайдера для цього агента:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

Інструкції проєкту, навички, посилання та інші джерела інструкцій усе одно додаються. У Markdown-агенті розмістіть цей текст у тілі документа, а не в полі `system` у frontmatter.

### Дозволи

`permissions` — це впорядкований список правил зіставлення:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Поле | Значення |
| --- | --- |
| `action` | Назва інструмента або дії, для якої перевіряється дозвіл. Підтримуються символи підстановки. |
| `resource` | Шлях, команда, ID агента чи інше значення, до якого застосовується дія. Підтримуються символи підстановки. |
| `effect` | `allow`, `ask` або `deny`. |

Перемагає останнє відповідне правило, тож ставте широкі правила перед винятками. Поширені дії:

| Дія | Що охоплює |
| --- | --- |
| `shell` | Shell-команди |
| `edit` | Інструменти редагування, запису й патчів |
| `subagent` | Дочірні агенти |
| `read`, `glob`, `grep` | Локальні інструменти пошуку |
| `webfetch`, `websearch` | Вебінструменти |
| `skill` | Завантаження навичок |

Для ресурсів `read`, `edit` і `external_directory` OpenCode розгортає `~` і `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Ресурси shell залишаються необробленим текстом команди й не розгортають ці значення.

### Кроки

`steps` задає додатне максимальне число кроків моделі:

```yaml
steps: 8
```

На останньому кроці OpenCode прибирає інструменти й просить модель підсумувати текстом. Нове введення користувача скидає ліміт.

### Приховування

`hidden` прибирає агента зі звичайних списків, інтерактивного пошуку та каталогу субагентів:

```yaml
hidden: true
```

Це керує видимістю, а не безпекою. Обмежуйте поведінку через дозволи.

### Колір

`color` задає колір агента в інтерфейсі шестизначним hex-значенням:

```yaml
color: "#ff6b6b"
```

### Вимкнення

`disabled` прибирає вбудованого або власного агента на цьому етапі завантаження конфігурації:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Запит

`request` приймає для кожного агента перевизначення заголовків і JSON-тіла:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  Виконавець сесій V2 зберігає ці значення, але поки не надсилає їх із запитами до моделі. Натомість
  налаштуйте активні параметри запиту на провайдері, моделі або варіанті моделі.
</Callout>

Не використовуйте застарілі поля верхнього рівня, як-от `temperature`, `top_p`, `prompt`, `permission`, `tools`, `disable` чи `maxSteps`, у новій конфігурації агентів V2.
