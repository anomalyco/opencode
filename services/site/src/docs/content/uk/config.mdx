Створіть `opencode.jsonc` у своєму проєкті, щоб налаштувати OpenCode. Додайте схему для перевірки в редакторі, а потім задайте лише потрібні вам параметри.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Ви також можете попросити OpenCode оновити цей файл за вас.

## Формат

OpenCode підтримує JSON і JSONC. Використовуйте JSONC, якщо хочете коментарі або коми в кінці.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-5-5",
}
```

## Розташування

Розмістіть керовані налаштування для всієї машини в системному каталозі конфігурації:

| Платформа | Каталог                                 |
| --------- | --------------------------------------- |
| macOS     | `/Library/Application Support/opencode` |
| Linux     | `/etc/opencode`                         |
| Windows   | `%ProgramData%\opencode`                |

Системний каталог працює так само, як глобальний. Крім
`opencode.json(c)`, він завантажує `agents/`, `commands/`, `skills/` і `plugins/`
для кожного користувача на машині:

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

На macOS OpenCode також читає керовані налаштування (managed preferences), які MDM-інструменти
розгортають для домену `ai.opencode.managed`. Профіль конкретного користувача перекриває
загальномашинний:

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

Керовані налаштування мають найвищий пріоритет, тому користувачі та проєкти не можуть
перевизначити задані там значення, а керовані налаштування macOS переважають системний
каталог. Лише налаштування не можуть заборонити користувачам додавати провайдерів, MCP-сервери,
агентів чи плагіни. Щоб запровадити обмеження, використовуйте [політики](/policies#precedence) у керованій
конфігурації.

Розмістіть користувацькі налаштування для всіх проєктів у глобальній конфігурації:

```text
~/.config/opencode/opencode.json(c)
```

Розмістіть налаштування проєкту в одному з цих файлів:

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode шукає від поточного каталогу до кореня файлової системи. Спершу він
об'єднує прямі файли `opencode.json(c)` від найдальшого каталогу до
найближчого, потім у тому самому порядку об'єднує файли в каталогах `.opencode`.
Тобто кожна знайдена конфігурація `.opencode` перевизначає кожну пряму конфігурацію.
Використовуйте одну форму в усьому дереві каталогів, якщо вам не потрібна саме така поведінка.

Наприклад, запустіть OpenCode з `/home/user/projects/acme/packages/web`:

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode застосовує ці файли від найнижчого до найвищого пріоритету:

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

Конфігурація пакета перевизначає відповідні налаштування з конфігурації репозиторію,
а та — глобальну конфігурацію. Системна конфігурація перевизначає їх усі.
Налаштування, що не конфліктують, зберігаються. [Політики](/policies#precedence)
з глобальних і проєктних файлів обчислюються у зворотному порядку, а системні
політики переважають усі інші.

## Схема

Повна схема конфігурації OpenCode доступна на
[opencode.ai/config.json](https://opencode.ai/config.json).

Додайте поле `$schema` у файл конфігурації, щоб увімкнути перевірку та
автодоповнення в редакторах, які підтримують JSON Schema:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

Звіряйте зі схемою доступні поля, допустимі значення та структуру вкладеної конфігурації.

### Оболонка

Виберіть оболонку, яку використовуватимуть термінал та інструменти для запуску команд.

```jsonc
{
  "shell": "/bin/zsh",
}
```

### Модель

Задайте типову модель у форматі `provider/model`. Кореневе значення зараз
не зберігає `#variant`; посилання на модель в агенті чи команді можуть вибрати варіант.

```jsonc
{
  "model": "anthropic/claude-sonnet-5-5",
}
```

Дивіться [посібник з моделей](/models), щоб дізнатися про вибір моделей і локальні моделі.

### Агент

Виберіть основного агента, який використовується, коли сесія не вибирає його явно.

```jsonc
{
  "default_agent": "build",
}
```

Дивіться [посібник з агентів](/agents), щоб дізнатися про вбудованих і власних
агентів.

### Оновлення

Керуйте перевірками оновлень із глобальної конфігурації. Встановіть `update` у `"disable"`, щоб
пропускати їх, `"notify"`, щоб показувати доступні оновлення перед встановленням, або
`"auto"`, щоб встановлювати оновлення автоматично. Якщо поле не задане, `update` типово має значення `"notify"`.

Автоматичне встановлення не перезапускає запущений сервер. Перезапустіть його вручну, щоб активувати встановлене оновлення.
Значення на рівні проєкту ігноруються.

```jsonc
{
  "update": "notify",
}
```

### Ім'я користувача

Задайте ім'я користувача. OpenCode приймає це поле, але не показує його в
розмовах.

```jsonc
{
  "username": "alice",
}
```

### Дозволи

Визначте впорядковані правила, які дозволяють, забороняють або вимагають підтвердження, перш ніж агент використає інструмент для
відповідного ресурсу.

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

Дивіться [посібник з дозволів](/permissions), щоб дізнатися про зіставлення правил і доступні дії.

### Політики

За допомогою впорядкованих правил можна дозволити чи заборонити використання провайдера, заборонити дію незалежно
від результату перевірки дозволів або заблокувати MCP-сервер, навичку чи плагін. Ці правила можна перевизначити
в конфігурації з ширшою областю дії.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

Дивіться [посібник з політик](/policies), щоб дізнатися про зіставлення, пріоритет між файлами
конфігурації та політику, якою керує Console.

### Агенти

Перевизначте вбудованих агентів або створіть спеціалізованих агентів із власною моделлю,
інструкціями, режимом і дозволами.

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

Дивіться [посібник з агентів](/agents), щоб дізнатися про всі параметри агентів і агентів у файлах.

### Знімки

Увімкніть або вимкніть знімки файлової системи, які використовуються для скасування та відкату.

```jsonc
{
  "snapshots": false,
}
```

Дивіться [посібник зі знімків](/snapshots), щоб дізнатися про скасування та повторення.

### Спостерігач

Ігноруйте файли й каталоги, які не повинні запускати оновлення файлової системи.

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### Форматувальник

Форматуйте файли після того, як їх змінять інструменти `write`, `edit` або `patch`. Встановіть
`formatter` у `true`, щоб увімкнути доступні вбудовані форматувальники.

```jsonc
{
  "formatter": true,
}
```

Дивіться [посібник з форматувальників](/formatters), щоб дізнатися про вбудовані та власні форматувальники.

### Медіа

Керуйте тим, як завеликі зображення, завантажені інструментом `read`, змінюють розмір або відхиляють,
перш ніж їх надіслати моделі.

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Дивіться [посібник із вкладень](/attachments), щоб дізнатися про обробку зображень та обмеження.

### Вивід

Задайте максимальну кількість рядків і байтів, які зберігаються з результату інструмента.

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### Пошук

Виберіть, як OpenCode шукає в інтернеті. Використовуйте `"random"`, щоб автоматично вибрати доступного
провайдера.

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

Дивіться [посібник з вебпошуку](/websearch), щоб дізнатися про провайдерів, облікові дані, вибір,
обмеження швидкості та вимкнення пошуку.

### MCP

Налаштуйте локальні й віддалені сервери Model Context Protocol. Глобальні
значення `mcp.timeout` застосовуються до серверів, визначених у файлах конфігурації; `timeout` кожного
сервера перевизначає їх.

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

Дивіться [посібник з MCP](/mcp-servers), щоб дізнатися про віддалені сервери, OAuth, змінні середовища й тайм-аути.

### Ущільнення

Керуйте автоматичним ущільненням контексту та тим, скільки недавнього контексту воно зберігає.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": "15%",
  },
}
```

`buffer` — це частка вікна контексту моделі, яку тримають вільною, перш ніж почнеться автоматичне ущільнення.

Локальні підсумки залишаються типовими. Увімкніть нативне ущільнення провайдера для автоматичних
і ручних запитів за допомогою політики провайдера або моделі:

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Налаштування моделі перевизначає налаштування провайдера. Автоматичне ущільнення використовує
доступний бюджет вхідних даних вибраної моделі. Контрольні точки провайдера зберігають недавні повідомлення користувача в межах того самого
бюджету `compaction.keep.tokens`, який локальні підсумки використовують для збереженого хвоста.
`compaction.auto: false` на верхньому рівні вимикає нове автоматичне ущільнення, не
відкидаючи встановлені контрольні точки. Дивіться [посібник з ущільнення](/compaction), щоб дізнатися про
бюджетування й відновлення після переповнення.

### Прогрівання

Підтримуйте недавно активні сесії моделей теплими за допомогою періодичних короткочасних запитів.
Прогрівання вимкнене типово; встановіть `true`, щоб прогрівати безпосередньо перед тим,
як спливе кеш кожної моделі, до 30 хвилин.

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "auto",
    "duration": "30 minutes",
  },
}
```

`settings.cache.warming` провайдера або моделі перевизначає це, а
`settings.cache.ttl` задає, як довго провайдер зберігає кеш. Дивіться
[посібник з прогрівання](/warming), щоб дізнатися про поведінку запитів, налаштування та
витрати, а також [час життя кешу](/models#cache-lifetime) про `cache.ttl`.

### Навички

Додайте каталоги або URL-адреси, у яких OpenCode має шукати навички агентів.

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

Дивіться [посібник з навичок](/skills), щоб дізнатися про структуру навичок і автоматичне виявлення в `.opencode/skills/`.

### Команди

Визначте повторно використовувані слеш-команди як іменовані шаблони промптів.

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

Дивіться [посібник з команд](/commands), щоб дізнатися про аргументи, моделі, агентів і команди у файлах.

### Інструкції

Оголосіть додаткові файли інструкцій, glob-шаблони або HTTP(S)-адреси. OpenCode завантажує
їх разом із знайденими файлами `AGENTS.md`.

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

Дивіться [посібник з інструкцій](/instructions), щоб дізнатися про інструкції проєкту та `AGENTS.md`.

### Посилання

Зробіть локальні каталоги або Git-репозиторії доступними як іменований допоміжний
контекст.

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

Дивіться [посібник з посилань](/references), щоб дізнатися про скорочену форму, видимість і обчислення шляхів.

### Робочі дерева

Задайте батьківський каталог для нових локальних робочих дерев. OpenCode додає запитану або згенеровану назву робочого дерева.

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

Відносні шляхи обчислюються від збереженого канонічного чекауту проєкту. Це стосується і глобальної, і проєктної
конфігурації; абсолютні шляхи використовуються як є, а `~/` обчислюється
від домашнього каталогу користувача.

Наприклад, ця глобальна конфігурація розміщує нові робочі дерева в каталозі `.lane/trees/` кожного проєкту:

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

Без цього налаштування створення використовує каталог даних сервера в `worktree/<first-six-project-ID-characters>`.
Створення й оновлення робочих дерев завантажують конфігурацію зі збереженого канонічного чекауту проєкту, зокрема коли інші
клони мають той самий ID проєкту. Зміна цього налаштування не переміщує наявні робочі дерева.

Git — вбудоване типове значення. [Плагін](/build/plugins/server#worktrees), який реєструє стратегію, автоматично стає
типовим у середовищі виконання цього плагіна. Операції проєкту використовують середовище виконання канонічного чекауту. Параметри конкретної
стратегії належать тому плагіну, а не об'єкту конфігурації `worktree`.

### Плагіни

Завантажуйте плагіни з пакетів або локальних каталогів плагінів. Використовуйте об'єктну форму, коли плагін
приймає параметри.

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

Дивіться [посібник з плагінів](/plugins), щоб дізнатися про завантаження й налаштування плагінів.

### Провайдери

Налаштуйте провайдерів і додайте або перевизначте їхні моделі, налаштування запитів,
заголовки й варіанти моделей.

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol-custom": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

`settings.transport: "websocket"` у провайдера вибирає його сесійний WebSocket.

Дивіться [посібник з провайдерів](/providers), щоб дізнатися про облікові дані, власні ендпоінти, пакети провайдерів, транспорт WebSocket і конфігурацію моделей.

## Змінні

У файлах конфігурації можна підставляти змінні, щоб посилатися на змінні середовища та вміст файлів. Розміщуйте посилання всередині JSON-рядків.

### Змінні середовища

Використовуйте `{env:VARIABLE_NAME}`, щоб підставити змінні середовища:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "providers": {
    "anthropic": {
      "settings": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
      },
    },
  },
}
```

Якщо змінна середовища не задана, вона замінюється порожнім рядком.

### Файли

Використовуйте `{file:path/to/file}`, щоб підставити вміст файлу:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": {
        "apiKey": "{file:~/.secrets/openai-key}",
      },
    },
  },
}
```

Шляхи до файлів можуть бути:

- Відносними до каталогу файлу конфігурації
- Абсолютними або починатися з `~/` для вашого домашнього каталогу

Якщо файлу не існує, він замінюється порожнім рядком.

Це корисно для:

- Зберігання чутливих даних, як-от API-ключі, в окремих файлах.
- Спільного використання типових фрагментів конфігурації в кількох файлах конфігурації.

## Експериментальні налаштування

<Callout type="warning">
  Експериментальні налаштування можуть змінюватися, ламатися або зникати в будь-якому випуску без попередження. Не покладайтеся на них у стабільних
  робочих процесах.
</Callout>

Усі експериментальні налаштування містяться під ключем `experimental`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "todo": true,
    "subagent_depth": 2,
    "image_generate": { "model": "openai/gpt-image-2" },
    "location_idle_timeout": "4 hours",
  },
}
```

### Завдання

Встановіть `todo` у `true`, щоб дати агентам інструмент `todowrite` для відстеження багатокрокової роботи. Типово — `false`.

### Глибина вкладеності субагентів

`subagent_depth` задає, наскільки глибоко субагенти можуть запускати власних субагентів. Типово — `1`, тобто субагент не може
запустити іншого субагента.

### Генерування зображень

`image_generate` задає типову модель для інструмента [`generate_image`](/tools#image-generate) у форматі
`providerID/modelID`, за потреби з `#variant`. Якщо ця модель недоступна або не може обробити запит, OpenCode
автоматично вибирає іншу модель зображень.

```jsonc
{
  "experimental": {
    "image_generate": {
      "model": "openai/gpt-image-2",
    },
  },
}
```

### Тайм-аут простою Location

`location_idle_timeout` визначає, як довго Location проєкту може бути без активності сесій, перш ніж OpenCode вивантажить
її сервіси. Він приймає тривалість, наприклад `"2 hours"`, і типово дорівнює `"60 minutes"`. Активні сесії та фонові
завдання утримують Location завантаженою. Встановіть `false`, щоб ніколи не вивантажувати неактивні Location. Конфігурація проєкту може перевизначити глобальне
значення.

```jsonc
{
  "experimental": {
    "location_idle_timeout": false,
  },
}
```

### Застарілі політики

`experimental.policies` застаріло. Використовуйте [`policies`](/policies) на верхньому рівні. Старий ключ досі працює й
об'єднується з `policies`.
