title: Plugins Effect
description: Écrivez des plugins serveur avec l’API de plugin native Effect.

`@opencode/plugin/effect` est la version native Effect de l’API de plugin OpenCode. Ses opérations de contexte renvoient des Effects ou Streams, les callbacks renvoient des Effects, et la durée de vie du plugin est représentée par `Scope`.

OpenCode fournit `effect` (y compris les sous-chemins `effect/*` exportés) et `@opencode/plugin` à l’exécution lors du chargement des plugins et de leurs dépendances `node_modules`. Déclarez-les comme dépendances homologues et de développement pour la vérification des types et les tests locaux plutôt que de les empaqueter dans votre plugin.

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

Exportez un plugin Effect depuis `.opencode/plugins/` pour le charger automatiquement.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Les paquets publiés et les répertoires de plugins hors de `.opencode/plugins/` utilisent la même configuration `plugins` que les autres plugins serveur.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Consultez [Configurer les plugins](/plugins) pour l’activation, la résolution des paquets et l’ordre de priorité des réglages.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Cycle de vie

L’`effect` s’exécute au chargement du plugin. Son scope se ferme au rechargement ou au déchargement du plugin, si bien que les enregistrements, fibres à portée et finaliseurs sont libérés ensemble.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Utilisez des fibres à portée pour le travail d’arrière-plan. Le scope du plugin interrompt la fibre lors du nettoyage.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Contexte

Le contexte expose le client Effect du serveur OpenCode connecté, plus les transforms, hooks, le stockage, les rechargements et les options réservés aux plugins. Il n’expose pas les services Core privés d’OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

La définition du plugin et le contexte complet sont déclarés comme suit.

### Options

Passez des options avec la forme objet dans `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Lisez les options depuis `ctx.options`. Affinez les valeurs inconnues avant utilisation.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transforms

Les transforms modifient l’état de façon synchrone via un éditeur. OpenCode applique les transforms dans l’ordre d’enregistrement au sein de chaque domaine. Les sources fournissent d’abord les fournisseurs et les définitions de modèles immuables ; les transforms de modèle modifient ensuite les candidats des fournisseurs actifs. Le yield de l’enregistrement le rattache au scope du plugin.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Un transform de modèle peut appliquer une politique sur toute la collection de candidats des fournisseurs actifs.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Appelez `reload` lorsque l’état externe utilisé par un transform change. Ici, `loadFromSource()` renvoie des entrées `{ info: Provider.Info, models: readonly Model.Info[] }` ; le rechargement d’un fournisseur invalide aussi tout le résultat de modèles.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agent

Lisez tous les agents ou récupérez-en un par ID. Les réponses du client incluent la Location résolue et les données de schéma.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transformez ou rechargez les agents.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

### Fournisseurs

Lisez les fournisseurs disponibles ou inspectez les métadonnées d’un fournisseur par ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Les transforms de fournisseur modifient les réglages de fournisseur et les définitions de source. L’éditeur permet aussi de lire les fournisseurs inactifs et exposent des définitions immuables ; `models.update` modifie une copie du modèle source propre à l’éditeur.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Remplacez un inventaire de source avec `models.set`, puis rechargez après le changement de ses définitions capturées.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Pour une découverte propre à un compte, passez la connexion utilisée pour charger l’inventaire comme `sourceConnection`. OpenCode exclut ce fournisseur tant qu’une autre connexion est sélectionnée, jusqu’à ce que votre plugin publie son inventaire rafraîchi.

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### Modèles

Lisez les modèles disponibles et la sélection par défaut.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Les transforms de modèle modifient toute la collection de candidats des fournisseurs actifs. Les candidats désactivés restent modifiables jusqu’à la fin de tous les transforms ; `update` ne peut ajouter un modèle que sous un fournisseur disponible.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Les callbacks modifient les surcharges brutes des réglages du modèle. Les valeurs par défaut du fournisseur sont fusionnées une fois lorsque OpenCode valide le résultat ; tant que rien ne change, les lectures réutilisent ce résultat. `editor.provider` lit les définitions de source immuables, y compris les gabarits inactifs, plutôt que la sortie des transforms de modèle.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schéma : [`Model.Info`](/api#schema-Model.Info).

### Commandes

Lisez les commandes disponibles pour la Location actuelle.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Pour le moment, le transform de commande permet uniquement d’ajouter des commandes. Un exécuteur reçoit la session, les pièces jointes du prompt et le mode de livraison.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

### Intégrations

Lisez les intégrations et résolvez l’identifiant actif lorsqu’il existe.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Connectez-vous avec une clé ou pilotez une tentative OAuth via l’API connectée.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transformez les intégrations et les méthodes d’authentification. Les callbacks de méthode OAuth sont des Effects et peuvent acquérir des ressources à portée.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

### MCP

Listez les serveurs MCP et leur état de connexion actuel.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Les plugins ne gèrent les serveurs MCP que via des transforms. Utilisez `editor.set` pour ajouter ou remplacer un serveur, `editor.update` pour changer sa configuration et `editor.remove` pour le retirer. Inspectez la configuration avec `editor.list` et `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Définissez `disabled: true` dans un transform pour désactiver un serveur et le déconnecter, ou `disabled: false` pour l’activer et permettre à OpenCode de se connecter. OpenCode aligne l’état de chaque serveur sur la configuration obtenue après application des transforms.

Appelez `reload()` après un changement de l’état externe utilisé par un transform pour réappliquer les transforms et mettre à jour l’état des serveurs.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schémas : [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded), [`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

### Plugins

Listez les plugins actifs, en échec et résolus pour la Location actuelle.

```ts
effect: (ctx) =>
```

Filtrez les valeurs de schéma dans un pipeline Effect lorsque seuls les plugins actifs comptent.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.state.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

### Références

Lisez les références disponibles pour la Location actuelle.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Ajoutez ou retirez des références locales et Git, puis rechargez après un changement d’état externe. `get(name)` renvoie la source configurée actuelle, ou `undefined` lorsque le nom est absent.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
```

### Outils

Enregistrez des outils typés avec `Schema` d’Effect. L’exécuteur reçoit l’entrée décodée et renvoie un Effect contenant une sortie typée, un contenu d’affichage ou des métadonnées.

L’éditeur prend en charge `add`, `update` et `remove`. Le callback de transform est synchrone : il ne doit renvoyer ni Effect ni Promise. Chargez les données externes avant l’enregistrement ou le rechargement. OpenCode rejoue les transforms actifs dans l’ordre d’enregistrement sur un éditeur neuf ; pour le même nom d’outil effectif, un enregistrement valide ultérieur remplace le précédent.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Appelez `yield* ctx.tool.reload()` après avoir changé les données de source capturées par le callback. Le rechargement rejoue les transforms actifs sans changer leur ordre ; il ne relance pas l’effect du plugin.

Les outils Effect acceptent la même [déclaration d’entrée libre](/build/plugins/server#freeform-tool-input) que les outils Promise. Si le modèle n’annonce pas ce format, l’outil conserve son entrée objet normale.

Les outils ont un `id` contenant leur nom effectif, et `get()` renvoie `undefined` lorsque cet ID n’est pas présent. Utilisez `update` et `remove` avec le nom d’outil effectif, espace de noms compris (`acme_greeting` ci-dessus). Les points des espaces de noms deviennent `_`. Dans les noms d’outils, seuls les lettres, les chiffres, `_` et `-` sont conservés ; tout autre caractère devient `_`. Les noms absents sont ignorés. Pour créer un outil, appelez `add` avec une définition complète. Les mises à jour conservent le nom et l’espace de noms. Pour remplacer les schémas ou les options, affectez-leur de nouvelles valeurs plutôt que de modifier les valeurs imbriquées sur place. Les mises à jour non valides sont consignées dans les journaux et laissent la définition précédente intacte.

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Les mises à jour et retraits sont rejoués dans l’ordre avec les ajouts, y compris après les rafraîchissements du catalogue MCP.

`transform` renvoie un enregistrement à portée. Exécutez `yield* registration.dispose` pour retirer son transform et reconstruire à partir des transforms restants, en révélant toute définition antérieure qu’il remplaçait. La libération est idempotente, et la fermeture du scope du plugin libère aussi ses enregistrements.

Chaque requête de modèle capture un snapshot des outils. Le rechargement et la libération affectent les prochains snapshots, pas les définitions ni exécuteurs déjà capturés par une requête existante. Les exécuteurs qui capturent des données mutables du plugin les observent toujours ; capturez une valeur dans le transform lorsqu’elle doit rester liée à cette définition.

Schémas : [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent), [`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Les hooks interceptent les opérations en direct. Plusieurs plugins peuvent enregistrer le même hook ; OpenCode les exécute dans l’ordre des plugins afin que les hooks ultérieurs voient les changements précédents. Les enregistrements restent actifs pour le scope du plugin.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sessions

Modifiez les instructions système assemblées, les messages ou les outils juste avant l’envoi au modèle. `context` s’exécute pour la boucle de l’agent ; `compaction`, `generate` et `title` s’exécutent pour ces requêtes auxiliaires. `compaction` et `title` acceptent un `result` qui permet de ne pas appeler le modèle.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Les messages des hooks `context`, `compaction` et `generate` portent les `metadata` de leur message stocké, en lecture seule (par exemple ce qu’un hook `prompt` a défini). Elles ne sont pas envoyées au modèle.

La partie `system` qui contient les instructions d’OpenCode liste aussi chaque source dans `metadata.experimental.instructions` sous la forme `{ key, text }`, comme `core/date` ou `core/environment`, afin qu’un hook puisse distinguer les sources. La liste est une copie : modifier le `text` de la partie ne la met pas à jour. C’est expérimental et susceptible de changer.

Modifiez les réglages de requête de modèle et limitez éventuellement le hook à un fournisseur. L’événement porte le même `kind` que les hooks HTTP ci-dessous.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Modifiez les requêtes ou réponses natives du fournisseur. Leurs corps sont des flux à usage unique ; clonez ou remplacez un corps avant de le lire. Les deux hooks s’exécutent pour chaque requête émise par une session ; `event.kind` vaut `"primary"`, `"compaction"`, `"title"` ou `"generate"` selon le flux émetteur.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Les fournisseurs qui diffusent sur un WebSocket réutilisent une connexion par session : les hooks HTTP ne voient donc jamais ce trafic. Le hook expérimental de négociation WebSocket `experimental.ws.handshake` s’exécute une fois par appel de modèle avant la sélection de la connexion et expose l’`url` et les `headers` de la connexion ; changer l’un ou l’autre rouvre le socket. Les hooks HTTP s’exécutent toujours pour toute requête HTTP utilisée en repli d’une route WebSocket.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` et `experimental.ws.receive` exposent les trames elles-mêmes : `send` s’exécute après que le pilote du fournisseur a construit une trame sortante, `receive` s’exécute sur chaque trame entrante avant que le pilote ne l’observe. Ce que `frame` contient au retour du hook est ce qui traverse le réseau ou atteint le pilote ; OpenCode ne le valide pas.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

En cas d’erreur du fournisseur, décidez s’il faut réessayer ou modifiez le délai avant la prochaine tentative, en millisecondes. Le hook s’exécute après qu’OpenCode a classé l’échec et proposé sa politique, mais avant toute planification de nouvelle tentative. Il n’expose pas comment OpenCode effectue la tentative suivante en interne.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

La `decision` initiale est la politique d’OpenCode : les hooks peuvent donc rendre réessayable un échec de fournisseur normalement définitif, ou annuler une nouvelle tentative proposée. Plusieurs hooks s’exécutent dans l’ordre d’enregistrement et les hooks ultérieurs voient la décision courante. Le nombre maximal de tentatives intégré reste une limite stricte. `attempt` est la tentative effective proposée ; la requête initiale est la tentative `1`, la première nouvelle tentative est donc la tentative `2`. Les délais invalides (`NaN`, infini ou négatifs) sont remplacés par le délai calculé. La récupération après dépassement de contexte reste séparée, car elle compacte la conversation au lieu de réessayer la même requête.

```ts
type RetryDecision = { retry: false } | { retry: true; delay: number }

interface SessionRetry {
  readonly sessionID: string
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly error: { type: string; message: string; status?: number }
  readonly attempt: number
  decision: RetryDecision
}

interface SessionHookDomain {
  readonly hook: ModelHooks<SessionHooks>
}
```

### Shell

Modifiez les commandes shell, répertoires de travail, délais, exécutables ou variables d’environnement avant l’exécution.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const shell = ctx.shell
    yield* shell.hook("create.before", (event) =>
      Effect.sync(() => {
        if (event.command === "npm") event.command = "bun"
        event.timeout = Math.min(event.timeout, 60_000)
        event.env.COMPANY_ENV = "development"
      }),
    )
  }),
```

#### Référence

```ts
interface ShellCreateBefore {
  command: string
  cwd: string
  timeout: number
  shell: string
  env: Record<string, string | undefined>
}

interface ShellHooks {
  readonly "create.before": ShellCreateBefore
}

interface ShellHookDomain {
  readonly hook: Hooks<ShellHooks>
}
```

### Outils

Les hooks exécutés avant l’appel peuvent remplacer l’entrée ou échouer avec `Tool.Error`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

Les hooks exécutés après l’appel peuvent inspecter ou remplacer les résultats réussis et les échecs.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

#### Référence

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

Les types d’enregistrement partagés montrent quelles opérations nécessitent le scope du plugin.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publication

Un plugin de paquet utilise le même export par défaut qu’un plugin Effect local. Exportez l’implémentation Effect depuis le point d’entrée principal et déclarez `effect` comme `peerDependency`. Sous `devDependencies`, fixez la version à celle qu’utilise `@opencode/plugin` pour que les installations de développement n’en aient qu’une copie.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

OpenCode redirige les imports de `effect`, des sous-chemins `effect/*` exportés et de `@opencode/plugin` (y compris les imports des dépendances dans les `node_modules` du plugin) vers les instances d’exécution de l’hôte, afin que les fibres, journaliseurs et analyseurs `Schema` partagent une seule copie du runtime.

- N’empaquetez pas `effect` dans l’artefact publié du plugin. Si vous utilisez un bundler, marquez `effect` et `effect/*` comme externes.
- Les plugins et leurs dépendances `node_modules` s’exécutent toujours avec l’instance `effect` de la version d’OpenCode hôte. Utilisez des API et chemins de module `effect` compatibles avec la version d’OpenCode que vous ciblez ; les dépendances construites sur une autre version majeure d’`effect` (comme Effect 3) reçoivent aussi l’`effect` de l’hôte et ne sont pas prises en charge.
- Seuls les sous-chemins publics d’`effect` sont fournis. Un plugin qui importe l’un des modules `internal` privés d’Effect échoue au chargement avec une erreur nommant le chemin.
- Le binaire OpenCode compilé n’inclut pas les ressources Scalar et Swagger UI utilisées par les pages de doc de l’API HTTP d’Effect ; servir ces pages depuis un plugin affiche une notice à la place.

Le point d’entrée du paquet exporte `Plugin.define` avec une fonction `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Utilisez des versions compatibles avec la version d’OpenCode que vous ciblez et testez le paquet installé plutôt qu’une simple copie liée au workspace.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
