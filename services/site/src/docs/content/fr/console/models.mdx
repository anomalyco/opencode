OpenCode Console propose une liste de modèles testés et vérifiés par l’équipe OpenCode. Connectez-vous, ajoutez des crédits et récupérez une clé d’API pour les utiliser avec OpenCode ou un autre agent de code.

Console fonctionne comme n’importe quel autre fournisseur dans OpenCode. C’est **entièrement facultatif**, et vous pouvez utiliser un autre fournisseur à la place. Pour un abonnement avec utilisation incluse, consultez [OpenCode Go](/console/go).

## Fonctionnement

1. Connectez-vous à la [console](https://opencode.ai/console), ajoutez vos informations de facturation et des crédits, puis copiez votre clé d’API.
2. Lancez `/connect` dans le TUI, choisissez le fournisseur OpenCode en paiement à l’usage et collez votre clé d’API.

   ```text
   /connect
   ```

3. Lancez `/models` pour voir les modèles disponibles et en sélectionner un.

   ```text
   /models
   ```

Vous êtes facturé à la requête et pouvez ajouter des crédits à votre compte.

## Endpoints

Vous pouvez aussi accéder aux modèles directement via les endpoints d’API suivants. Les modèles de chat de l’offre gratuite nécessitent OpenCode ; utilisez des modèles payants ou [Go](/console/go) depuis les autres clients.

Chaque modèle est listé avec son API native, mais chaque modèle texte fonctionne aussi via les autres API, que Console traduit. Consultez les [URL de base](/console/harnesses#base-urls) pour connaître toutes les API compatibles.

### Jev

Jev est un modèle System One de TypeSafe AI pour des décisions rapides et structurées. Au lieu de générer du texte, il évalue un `state` par rapport à des questions typées et renvoie des valeurs et des probabilités que votre code peut utiliser directement. Il prend en charge les questions oui/non (`noul`), à choix multiples (`choice`) et fondées sur une grille (`score`).

Utilisez votre clé d’API OpenCode Console avec l’endpoint `https://opencode.ai/inference/systemone/v1/systemone`. Cet exemple vérifie si une demande de support est urgente :

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Vous pouvez poser plusieurs questions dans une seule requête. Jev les évalue en parallèle et renvoie chaque réponse sous l’ID de question correspondant :

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Utilisez `jev-1.13-free` pour le modèle gratuit à durée limitée, qui exécute Jev 1.13. Consultez la [documentation TypeSafe AI](https://docs.typesafe.ai/) pour les détails sur les types de questions et les champs de réponse.

### GPT 6 Luna Decision et Gemini Decision 1

`gpt-6-luna-decision` et `gemini-decision-1` acceptent la même requête System One que Jev, sur le même endpoint. Passez les images, l’audio, la vidéo et les PDF dans `state` sous forme de parties de type chat (`image_url`, `input_audio`, `video_url`, `file`). GPT 6 Luna Decision accepte le texte et les images ; Gemini Decision 1 accepte aussi l’audio, la vidéo et les PDF.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### Modèles d’image

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` et `grok-imagine-image-2.0` génèrent et modifient des images. Ce ne sont pas des modèles de chat : ils n’apparaissent donc jamais dans `/models` ni dans l’endpoint des modèles, et `opencode/<model-id>` ne les sélectionne pas. Appelez-les sur leur API native avec une clé Console, ou laissez l’outil [`generate_image`](/tools#image-generate) d’OpenCode utiliser un modèle d’image en définissant `experimental.image_generate.model`, par exemple `opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google accepte ses `contents` et `generationConfig` natifs, et xAI ses options natives comme `resolution` et `quality`. OpenAI Images et xAI Images acceptent aussi les modifications à `/images/edits`.

### Modèles d’embedding

`text-embedding-3-small`, `qwen3-embedding-8b` et les autres modèles d’embedding du tableau ci-dessus transforment du texte en vecteurs. OpenCode ne les utilise pas pour le chat : ils n’apparaissent donc jamais dans `/models`, et l’offre gratuite ne les inclut pas. [Go](/console/go#embedding-models) en inclut certains. Appelez-les sur l’API Embeddings d’OpenAI avec une clé Console.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` accepte une chaîne ou un tableau de chaînes. `data` renvoie un vecteur par entrée, dans le même ordre.
- `dimensions` raccourcit les vecteurs sur les modèles qui le prennent en charge, comme `text-embedding-3-small`.
- `encoding_format: "base64"` renvoie les vecteurs en base64 plutôt que sous forme de nombres à virgule flottante.
- Chaque entrée doit tenir dans la fenêtre de contexte du modèle.
- La réponse indique `usage.cost` comme toute requête d’inférence. Consultez [Coût](/console/api/inference#cost).

Les vecteurs de modèles différents ne sont pas comparables : utilisez donc le même modèle pour vectoriser vos documents et vos requêtes. Un [fournisseur connecté](/console/api/providers#endpoints) propose ses propres modèles d’embedding sur `/embeddings`.

## Contexte

De nombreux modèles sont disponibles, mais peu fonctionnent bien comme agents de code. Les fournisseurs varient aussi en configuration, performance et qualité : un modèle utilisé via une passerelle comme OpenRouter peut donc se comporter différemment.

<Callout type="tip">Nous avons testé un groupe restreint de modèles et de fournisseurs qui fonctionnent bien avec OpenCode.</Callout>

Pour construire ce catalogue, nous avons :

1. Testé un groupe restreint de modèles et parlé à leurs équipes de la meilleure façon de les exploiter.
2. Travaillé avec les fournisseurs pour nous assurer que les modèles étaient correctement mis à disposition.

## Objectifs

Nous avons construit Console pour :

1. **Évaluer** les meilleurs modèles et fournisseurs pour les agents de code.
2. Fournir les options de **plus haute qualité** sans dégrader les performances ni router vers des fournisseurs moins chers.
3. Répercuter les **baisses de prix** en vendant au prix coûtant, avec un supplément qui couvre uniquement les frais de traitement.
4. Préserver votre **liberté de choix** : utilisez Console avec n’importe quel agent de code, ou un autre fournisseur avec OpenCode.
