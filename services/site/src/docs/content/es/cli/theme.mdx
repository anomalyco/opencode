title: "Tema de la CLI"
description: "Elige un tema integrado para la interfaz de terminal de OpenCode, usa los propios colores de tu terminal o agrega un tema propio."
---

OpenCode incluye muchos temas integrados para modos claro y oscuro. Elige uno en los ajustes o combina tus propios colores.

## Elegir un tema

Pulsa `Ctrl+P`, selecciona **Open settings** y abre **Theme**. El tema predeterminado es `opencode`. El valor predeterminado anterior sigue disponible como `opencode-classic`.

También puedes definir el tema y el modo en tu [configuración global de la CLI](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Ejecuta `/themes` para cambiar de tema sin abrir los ajustes.

## Colores del sistema

Cuando OpenCode puede leer la paleta de tu terminal, el selector de temas incluye el tema `system`. Deriva los colores del primer plano, el fondo y la paleta ANSI de tu terminal.

El nombre de tema `system` selecciona colores derivados del terminal. El modo `system` sigue la apariencia clara u oscura del terminal.

## Modo

Usa `system` para seguir la apariencia de tu terminal, o fija el tema en modo claro u oscuro:

| Modo | Comportamiento |
| --- | --- |
| `system` | Sigue la apariencia clara u oscura detectada del terminal. |
| `dark` | Usa siempre los colores oscuros del tema. |
| `light` | Usa siempre los colores claros del tema. |

Esto se corresponde con el campo `mode` dentro de `theme` en tu configuración de la CLI. Si un tema personalizado solo proporciona un modo, OpenCode usa ese modo cuando se solicita el otro.

## Agregar un tema

Para agregar un tema que descargaste o recibiste de otra persona, copia su archivo JSON en el directorio global de temas:

```bash
cp theme.json ~/.config/opencode/themes/
```

También puedes poner el tema en el directorio `.opencode/themes` de un proyecto para que solo esté disponible en ese proyecto.

El nombre del archivo se convierte en el nombre del tema. Por ejemplo, `my-theme.json` aparece como `my-theme`. Reinicia OpenCode después de agregar el archivo y ejecuta `/themes` para seleccionarlo.

OpenCode solo lee archivos `.json`. Un tema más cercano al directorio actual sustituye a un tema global o de un directorio superior con el mismo nombre.

## Usar temas en plugins

Los [plugins de TUI](/build/plugins/cli) leen los colores resueltos a través de `context.theme` y el modo activo a través de `context.themeMode`. Usa tokens semánticos para que tu plugin siga el tema seleccionado:

```tsx title="Inside a TUI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

La API pública de plugins de TUI no registra temas. Agrega definiciones de temas personalizados con archivos JSON en los directorios anteriores.

## Crear un tema

Usa nuestra [herramienta de temas](https://opencode.ai/theme/) para crear o editar temas. Esta herramienta facilita entender la estructura, cambiarla y definir colores personalizados. La explicación siguiente es de referencia.

Un tema separa los tokens semánticos compartidos de las paletas específicas de cada modo:

| Sección | Propósito |
| --- | --- |
| `base` | El árbol de tokens completo que comparten todos los modos. |
| `light`, `dark` | Una paleta de matices completa y sobrescrituras de tokens opcionales para ese modo. |

Todos los temas proporcionan un `base` completo y definen al menos uno de `light` o `dark`. Los modos heredan del `base` del archivo; no heredan del tema integrado de OpenCode ni entre sí.

Los ejemplos siguientes muestran solo las secciones relevantes para cada concepto. Usa el editor de temas para generar un archivo completo antes de personalizarlo.

### Estructura

Pon en `base` los colores que usan ambos modos y sobrescríbelos en `light` o `dark` cuando sea necesario:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

El `base` completo proporciona todos los tokens semánticos. Cada modo proporciona todos los matices requeridos y puede sobrescribir cualquier parte del árbol de tokens base.

### Colores y referencias

Un color puede ser un valor hexadecimal, `"transparent"` o una referencia a otro color del tema:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Matices

Los matices son escalas de color de nueve pasos. Cada modo define los ocho matices base y tres alias:

| Tipo | Valores |
| --- | --- |
| Base | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Alias | `accent`, `interactive`, `neutral` |
| Paso | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Define los nueve pasos de un matiz base, o asigna un alias de un matiz a otro:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Los pasos de matiz siguen la dirección de contraste del modo. Los temas claros van de oscuro en `100` a claro en `900`; los temas oscuros van de claro en `100` a oscuro en `900`.

El array `categorical` de `base` define los matices ordenados que se usan para distinguir agentes y otros elementos repetidos:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Tokens semánticos

Los tokens semánticos asignan colores a roles de la interfaz. Los componentes usan estos roles en lugar de elegir colores directamente.

| Grupo | Propósito |
| --- | --- |
| `text` | Texto base, atenuado, tenue, de selección, de acción, de campos de formulario y de mensajes de estado. `faint` usa `muted` de forma predeterminada. |
| `background` | Rellenos base, de selección, de superficies elevadas, de acciones, de campos de formulario y de mensajes de estado. |
| `border`, `scrollbar` | Colores de borde y de barra de desplazamiento. |
| `diff` | Colores de líneas añadidas, eliminadas, de contexto, de resaltado y de número de línea. |
| `syntax` | Resaltado de código fuente. |
| `markdown` | Elementos de Markdown. |

Por ejemplo, `text.muted` controla el texto secundario, mientras que `background.raised` define superficies progresivamente elevadas:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

`text.selection` y `background.selection` dan color al texto que seleccionas con el ratón o el teclado. De forma predeterminada usan la acción principal enfocada, `text.action.primary.$focused` sobre `background.action.primary.$focused`.

Las claves de sintaxis son `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` y `punctuation`.

Las claves de Markdown son `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` y `codeBlock`.

### Acciones y estados

Las acciones tienen variantes `primary`, `secondary` y `destructive`. Las acciones y los campos de formulario usan `base` más estados de interacción opcionales:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Las claves de estado son `$hovered`, `$focused`, `$pressed`, `$selected` y `$disabled`. Un estado no especificado usa el color `base` de esa acción o campo de formulario.

### Superficie de diálogo

Los paneles, diálogos, menús y avisos eligen su profundidad de `background.raised`. Los diálogos pueden además sobrescribir tokens semánticos con `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

La TUI vuelve a resolver las referencias después de aplicar `@dialog`, así que los tokens que hacen referencia a `$background.base` siguen el fondo del diálogo. El `base` de una acción contextual se convierte en el valor de reserva para sus estados no especificados; las sobrescrituras de estado explícitas siguen prevaleciendo.
