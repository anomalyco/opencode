---
title: "Plugins de Effect"
description: "Escribe plugins de servidor con la API de plugins nativa de Effect."
---

`@opencode/plugin/effect` es la versión nativa de Effect de la API de plugins de OpenCode. Sus operaciones de contexto devuelven
Effects o Streams, los callbacks devuelven Effects y `Scope` representa el ciclo de vida del plugin.

OpenCode proporciona `effect` (incluidas las subrutas exportadas `effect/*`) y `@opencode/plugin` en tiempo de ejecución al cargar
plugins y sus dependencias de `node_modules`. Instálalos como dependencias peer/dev para la comprobación de tipos y las pruebas locales,
en lugar de incluirlos en el bundle de tu plugin.

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

Exporta un plugin de Effect desde `.opencode/plugins/` para cargarlo automáticamente.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Los paquetes publicados y los directorios de plugins fuera de `.opencode/plugins/` usan la misma configuración `plugins` que otros plugins de servidor.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Consulta [Configurar plugins](/plugins) para la habilitación, la resolución de paquetes y la precedencia de configuración.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Ciclo de vida

El `effect` se ejecuta al cargar el plugin. Su ámbito se cierra al recargar o descargar el plugin, de modo que los registros, las fibras
asociadas a ese ámbito y los finalizadores se liberan juntos.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Usa fibras con ámbito para el trabajo en segundo plano. El ámbito del plugin interrumpe la fibra durante la limpieza.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Contexto

El contexto expone el cliente de Effect para el servidor de OpenCode conectado, además de transformaciones, hooks, almacenamiento,
recargas y opciones exclusivos del plugin. No expone los servicios privados de Core de OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

La definición del plugin y el contexto completo se declaran así.

```ts
interface Context {
  readonly app: App
  readonly location: Location.Info
  readonly options: PluginOptions

  readonly aisdk: AISDKDomain

    readonly terminal: Pick<ExperimentalApi<unknown>["persistentPty"], "read">
    readonly generate: GenerateApi<unknown>
  }
  readonly integration: IntegrationDomain
  readonly mcp: MCPDomain
  readonly model: ModelDomain
  /** @deprecated Use `experimental.generate.text`. */
  readonly generate: Pick<ExperimentalGenerateApi<unknown>, "text">
  readonly permission: PermissionDomain
  readonly plugin: Pick<PluginApi<unknown>, "list">
  readonly provider: ProviderDomain
  readonly reference: ReferenceDomain
  readonly rpc: RpcDomain
  readonly session: SessionDomain
  readonly shell: ShellDomain
  readonly skill: SkillDomain
  readonly storage: StorageDomain
  readonly tool: ToolDomain
  readonly vcs: VcsDomain
  readonly websearch: WebSearchDomain
  readonly worktree: WorktreeDomain
}

interface Plugin<R = Scope.Scope> {
  readonly id: string
  readonly effect: (context: Context) => Effect.Effect<void, never, R>
}
```

### Opciones

Usa el formato de objeto en `opencode.json(c)` para pasar opciones.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Lee las opciones de `ctx.options`. Antes de usar los valores de tipo desconocido, comprueba su tipo para acotarlo.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transformaciones

Las transformaciones editan el estado de forma síncrona mediante un editor. OpenCode aplica las transformaciones en orden de registro dentro de cada
dominio. Las fuentes aportan primero proveedores y definiciones de modelo inmutables; luego las transformaciones de modelo editan los candidatos
de los proveedores activos. Al obtener el registro mediante yield, este queda asociado al ámbito del plugin.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Una transformación de modelo puede aplicar políticas a toda la colección de candidatos de proveedores activos.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Llama a `reload` cuando cambie el estado externo que usa una transformación. Aquí, `loadFromSource()` devuelve
entradas `{ info: Provider.Info, models: readonly Model.Info[] }`; la recarga de proveedores también invalida todo el resultado de modelos.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agentes

Lee todos los agentes u obtén uno por ID. Las respuestas del cliente incluyen la ubicación resuelta y los datos del esquema.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transforma o recarga agentes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Esquema: [`Agent.Info`](/api#schema-Agent.Info).

```ts

  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Proveedores

Lee los proveedores disponibles o inspecciona los metadatos de un proveedor por ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Las transformaciones de proveedor editan los ajustes del proveedor y las definiciones de origen. Las lecturas del editor incluyen proveedores inactivos y exponen
definiciones inmutables; `models.update` edita una copia propia de un modelo de origen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Sustituye un inventario de origen con `models.set` y luego recarga cuando cambien las definiciones capturadas.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Para descubrir los modelos de una cuenta concreta, pasa en `sourceConnection` la conexión que usaste para cargar el inventario. OpenCode excluye
ese proveedor mientras haya otra conexión seleccionada, hasta que tu plugin publique su inventario actualizado.

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

Esquemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

```ts

```

### Modelos

Lee los modelos disponibles y la selección predeterminada.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Las transformaciones de modelo editan toda la colección de candidatos de proveedores activos. Los candidatos deshabilitados siguen siendo editables hasta que terminan
todas las transformaciones; `update` puede agregar un modelo solo bajo un proveedor disponible.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Los callbacks editan los valores sin procesar que sustituyen a los del modelo. Los valores predeterminados del proveedor se fusionan una sola vez, cuando OpenCode consolida el resultado;
las lecturas sin cambios reutilizan ese resultado. `editor.provider` lee definiciones de origen inmutables, incluidas plantillas inactivas, en lugar de
la salida de la transformación de modelos.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Esquema: [`Model.Info`](/api#schema-Model.Info).

```ts

  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined

  readonly default: {

```

### Comandos

Lee los comandos disponibles en la ubicación actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Actualmente, la transformación de comandos solo permite agregarlos. El ejecutor recibe la sesión, los adjuntos del prompt y el modo de entrega.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Esquemas: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Integraciones

Lee las integraciones y resuelve la credencial activa cuando exista.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Conecta con una clave o gestiona un intento de OAuth mediante la API conectada.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transforma integraciones y métodos de autenticación. Las devoluciones de llamada de los métodos OAuth son Effects y pueden adquirir
recursos con ámbito.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Esquemas: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

### MCP

Lista los servidores MCP y su estado de conexión actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Los plugins gestionan los servidores MCP solo mediante transformaciones. Usa `editor.set` para agregar o sustituir un servidor, `editor.update` para
cambiar su configuración y `editor.remove` para eliminarlo. Inspecciona la configuración con `editor.list` y `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Define `disabled: true` en una transformación para deshabilitar un servidor y desconectarlo, o `disabled: false` para habilitarlo y permitir
que OpenCode se conecte. OpenCode ajusta el ciclo de vida del servidor a la configuración resultante.

Llama a `reload()` cuando cambie el estado externo que usa una transformación para volver a aplicar las transformaciones y ajustar el estado de los servidores.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Esquemas: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts

  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void

```

### Plugins

Lista los plugins activos, fallidos y resueltos en la ubicación actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtra los valores del esquema en un pipeline de Effect si solo te interesan los plugins activos.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.state.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Esquemas: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

### Referencias

Lee las referencias disponibles en la ubicación actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Agrega o elimina referencias locales y de Git, y luego recarga cuando cambie el estado externo. `get(name)` devuelve el origen configurado actual,
o `undefined` cuando el nombre no existe.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

### Herramientas

Registra herramientas tipadas con `Schema` de Effect. El ejecutor recibe la entrada descodificada y devuelve un Effect que contiene la salida
tipada, el contenido de visualización o los metadatos.

El editor admite `add`, `update` y `remove`. La devolución de llamada de transformación es síncrona: no debe devolver un Effect ni una Promise. Carga
los datos externos antes de registrar o recargar. OpenCode repite las transformaciones activas en orden de registro sobre un editor
nuevo; para el mismo nombre efectivo de herramienta, un registro válido posterior sobrescribe uno anterior.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Llama a `yield* ctx.tool.reload()` después de cambiar los datos de origen que captura la devolución de llamada. La recarga repite las transformaciones activas
sin cambiar su orden; no vuelve a ejecutar el efecto del plugin.

Las herramientas de Effect aceptan la misma [declaración de entrada en formato libre](/build/plugins/server#freeform-tool-input) que las herramientas Promise. Si el modelo no declara que admite ese formato, la herramienta sigue recibiendo un objeto como entrada.

Las herramientas tienen un `id` que contiene su nombre efectivo, y `get()` devuelve `undefined` cuando ese ID no está presente. Usa
`update` y `remove` con el nombre efectivo de la herramienta, incluido su espacio de nombres (`acme_greeting` arriba). Los puntos en los
espacios de nombres y los caracteres no admitidos en los nombres de herramientas se convierten en `_`. Los nombres ausentes se ignoran; crear una herramienta requiere
`add` con una definición completa. Las actualizaciones conservan el nombre y el espacio de nombres. Asigna esquemas u opciones nuevas para sustituirlos
en lugar de mutar valores anidados. Las actualizaciones no válidas se registran y dejan intacta la definición anterior.

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Las actualizaciones y eliminaciones se repiten en orden con las adiciones, incluso después de las actualizaciones del catálogo MCP.

`transform` devuelve un registro asociado al ámbito. Ejecuta `yield* registration.dispose` para eliminar su transformación
y reconstruir el resultado a partir de las restantes. Así vuelven a quedar disponibles las definiciones anteriores que hubiera sustituido.
Retirar un registro es una operación idempotente; al cerrar el ámbito del plugin también se retiran sus registros.

Cada solicitud al modelo captura una instantánea de herramientas. La recarga y el desecho afectan a las instantáneas futuras, no a las definiciones ni a los
ejecutores que ya capturó una solicitud existente. Los ejecutores que capturan datos mutables del plugin siguen observando
esos datos; captura un valor dentro de la transformación cuando deba permanecer ligado a esa definición.

Esquemas: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

seleccionan automáticamente; usa `editor.default.set` para seleccionar otro proveedor.

```ts
effect: (ctx) =>

    const vcs = ctx.vcs
    yield* vcs.transform((editor) => {
      editor.add({
        id: "custom",
        name: "Custom VCS",

        status: (scope) => readStatus(scope.worktree),
```

Las devoluciones de llamada del proveedor reciben la ubicación actual, la raíz de la copia de trabajo, la raíz canónica del proyecto y el almacén de repositorios

sigue usando los detectores integrados de Git y Mercurial de OpenCode.

Los proveedores pueden implementar opcionalmente `init(scope)` para crear un repositorio en `scope.worktree`. La inicialización selecciona
el proveedor por ID (Git de forma predeterminada), no por el tipo de repositorio detectado. Registra un proveedor con `init` incluso cuando
la ubicación aún no tenga repositorio; OpenCode comprueba que el directorio existe y no tiene repositorio antes de llamarlo,
y luego vuelve a descubrir el proyecto. Los formatos de repositorio nuevos aún necesitan compatibilidad de descubrimiento más allá de esta devolución de llamada.

## Hooks

Los hooks interceptan operaciones en vivo. Varios plugins pueden registrar el mismo hook; OpenCode los ejecuta en orden de plugin, así que
los hooks posteriores ven los cambios anteriores. Los registros siguen activos durante el ámbito del plugin.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sesiones

Modifica las instrucciones del sistema, los mensajes o las herramientas ya preparados justo antes de enviar la solicitud al modelo. `context` se ejecuta para el
bucle del agente; `compaction`, `generate` y `title` se ejecutan para esas solicitudes auxiliares. `compaction` y `title` aceptan un
`result` que omite la llamada al modelo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Los mensajes de los hooks `context`, `compaction` y `generate` llevan los `metadata` de su mensaje almacenado, de solo lectura
(por ejemplo, lo que definió un hook `prompt`). No se envía al modelo.

La parte `system` que contiene las instrucciones de OpenCode también enumera cada fuente en `metadata.experimental.instructions` como
`{ key, text }`, como `core/date` o `core/environment`, para que un hook pueda distinguir las fuentes. La lista es una copia:
editar el `text` de la parte no la actualiza. Esto es experimental y puede cambiar.

Modifica los ajustes de solicitud al modelo y, opcionalmente, limita el hook a un proveedor. El evento lleva el mismo `kind` que
los hooks HTTP de abajo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Modifica las solicitudes o respuestas nativas del proveedor. Sus cuerpos son streams de un solo uso; clona o sustituye un cuerpo antes de leerlo.
Ambos hooks se ejecutan para cada solicitud que emite una sesión; `event.kind` es `"primary"`, `"compaction"`, `"title"` o
`"generate"` según el flujo que la emitió.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Los proveedores que transmiten por WebSocket reutilizan una conexión por sesión, así que los hooks HTTP nunca ven ese tráfico. El
hook experimental `experimental.ws.handshake` se ejecuta una vez por llamada al modelo antes de seleccionar la conexión y expone la
`url` y los `headers` de la conexión; cambiar cualquiera de los dos vuelve a abrir el socket. Los hooks HTTP siguen ejecutándose para cualquier solicitud a la que recurra una ruta WebSocket.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` y `experimental.ws.receive` exponen los propios frames: `send` se ejecuta después de que el controlador del proveedor
construye un frame saliente; `receive` se ejecuta en cada frame entrante antes de que lo lea el controlador. El contenido de `frame` al
terminar el hook es lo que se transmite por la conexión o se entrega al controlador. OpenCode no lo valida.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Sobrescribe la decisión de reintento de un fallo del proveedor o sustituye su retardo en milisegundos. El hook se ejecuta después de que OpenCode
clasifique el fallo y proponga su política, pero antes de programar ningún reintento. No expone cómo realiza OpenCode
internamente el siguiente intento.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

La `decision` inicial refleja la política de OpenCode. Los hooks pueden permitir que se reintente tras un fallo del proveedor que normalmente sería definitivo o impedir un
reintento propuesto. Varios hooks se ejecutan en orden de registro y los posteriores ven la decisión actual. El número máximo de intentos
integrado sigue siendo un límite estricto. `attempt` identifica el intento real que se propone; la solicitud inicial es el intento `1`,
así que el primer reintento es el intento `2`. Los retardos no válidos (`NaN`, infinito o valores negativos) recurren al retardo calculado.
La recuperación de desbordamiento de contexto sigue siendo independiente porque compacta la conversación en lugar de reintentar la misma solicitud.

```ts
type RetryDecision = { retry: false } | { retry: true; delay: number }

interface SessionRetry {
  readonly sessionID: string
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly error: { type: string; message: string; status?: number }
  readonly attempt: number
  decision: RetryDecision
}

interface SessionHookDomain {
  readonly hook: ModelHooks<SessionHooks>
}
```

### Shell

Modifica comandos de shell, directorios de trabajo, tiempos de espera, ejecutables o variables de entorno antes de la ejecución.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const shell = ctx.shell
    yield* shell.hook("create.before", (event) =>
      Effect.sync(() => {
        if (event.command === "npm") event.command = "bun"
        event.timeout = Math.min(event.timeout, 60_000)
        event.env.COMPANY_ENV = "development"
      }),
    )
  }),
```

#### Referencia

```ts
interface ShellCreateBefore {
  command: string
  cwd: string
  timeout: number
  shell: string
  env: Record<string, string | undefined>
}

interface ShellHooks {
  readonly "create.before": ShellCreateBefore
}

interface ShellHookDomain {
  readonly hook: Hooks<ShellHooks>
}
```

### Herramientas

Los hooks previos a la ejecución pueden sustituir la entrada o fallar con `Tool.Error`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

Los hooks posteriores a la ejecución pueden inspeccionar o sustituir los resultados correctos y los fallos.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

#### Referencia

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

Los tipos de registro compartidos muestran qué operaciones requieren el ámbito del plugin.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publicar

Un plugin de paquete usa la misma exportación predeterminada que un plugin de Effect local. Exporta la implementación de Effect desde el punto de entrada
principal y declara `effect` como `peerDependency`. En `devDependencies`, fija la versión que usa `@opencode/plugin`
para que las instalaciones de desarrollo solo tengan una copia.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

OpenCode redirige las importaciones de `effect`, las subrutas exportadas `effect/*` y `@opencode/plugin` (incluidas las importaciones de
dependencias en el `node_modules` del plugin) a las instancias del entorno de ejecución del host, para que las fibras, los loggers y los analizadores `Schema`
compartan una copia del entorno de ejecución.

- No incluyas `effect` en el artefacto publicado del plugin. Si compilas con un bundler, marca `effect` y `effect/*`
  como externos.
- Los plugins y sus dependencias de `node_modules` siempre se ejecutan con la instancia de `effect` que incluye la versión de OpenCode del host.
  Usa API y rutas de módulo de `effect` compatibles con la versión de OpenCode a la que apuntas; las dependencias basadas en otra
  versión mayor de `effect` (como Effect 3) también reciben el `effect` del host y no son compatibles.
- Solo se proporcionan las subrutas públicas de `effect`. Un plugin que importa uno de los módulos `internal` privados de Effect no se
  carga, con un error que nombra la ruta.
- El binario compilado de OpenCode no incluye los recursos de Scalar y Swagger UI que usan las páginas de documentación de la API HTTP de Effect;
  servir esas páginas desde un plugin muestra un aviso en su lugar.

El punto de entrada del paquete exporta `Plugin.define` con una función `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Usa versiones compatibles con la versión de OpenCode a la que apuntas y prueba el paquete instalado, no solo una
copia enlazada al espacio de trabajo.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
