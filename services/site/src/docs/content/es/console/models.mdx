OpenCode Console ofrece una lista de modelos probados y verificados por el equipo de OpenCode. Inicia sesión, agrega créditos y obtén una
clave de API para usarlos con OpenCode u otro agente de programación.

Console funciona como cualquier otro proveedor en OpenCode. Es **completamente opcional**, y puedes usar cualquier otro proveedor
en su lugar. Para una suscripción con uso incluido, consulta [OpenCode Go](/console/go).

## Cómo funciona

1. Inicia sesión en [Console](https://opencode.ai/console), agrega tus datos de facturación, carga créditos y copia tu clave de API.
2. Ejecuta `/connect` en la TUI, elige el proveedor de pago por uso de OpenCode y pega tu clave de API.

   ```text
   /connect
   ```

3. Ejecuta `/models` para ver los modelos disponibles y selecciona uno.

   ```text
   /models
   ```

Se te cobra por solicitud y puedes agregar créditos a tu cuenta.

## Endpoints

También puedes acceder a los modelos directamente a través de los siguientes endpoints de API. Los modelos de chat del nivel gratis requieren OpenCode;
usa modelos de pago o [Go](/console/go) desde otros clientes.

Cada modelo aparece con su API nativa, pero todos los modelos de texto también funcionan a través de las otras API, que Console
traduce. Consulta las [URL base](/console/harnesses#base-urls) para el conjunto completo.

### Jev

Jev es un modelo System One de TypeSafe AI para decisiones rápidas y estructuradas. En lugar de generar texto, evalúa un `state` frente a preguntas tipadas y devuelve valores y probabilidades que tu código puede usar directamente. Admite preguntas de sí/no (`noul`), de opción múltiple (`choice`) y basadas en rúbrica (`score`).

Usa tu clave de API de OpenCode Console con el endpoint `https://opencode.ai/inference/systemone/v1/systemone`. Este ejemplo comprueba si una solicitud de soporte es urgente:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Puedes hacer varias preguntas en una sola solicitud. Jev las evalúa en paralelo y devuelve cada respuesta bajo el ID de pregunta correspondiente:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Selecciona `jev-1.13-free` para acceder al modelo gratuito por tiempo limitado, que ejecuta Jev 1.13. Consulta la [documentación de TypeSafe AI](https://docs.typesafe.ai/) para conocer los tipos de pregunta y los campos de respuesta.

### GPT 6 Luna Decision y Gemini Decision 1

`gpt-6-luna-decision` y `gemini-decision-1` aceptan la misma solicitud System One que Jev, en el mismo endpoint. Pasa imágenes, audio, video y PDF en `state` como partes al estilo del chat (`image_url`, `input_audio`, `video_url`, `file`). GPT 6 Luna Decision acepta texto e imágenes; Gemini Decision 1 también acepta audio, video y PDF.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### Modelos de imagen

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` y `grok-imagine-image-2.0` generan y editan imágenes. No son modelos de chat, así que nunca aparecen en `/models` ni en el endpoint de modelos,
y `opencode/<model-id>` no los selecciona. Llámalos en su API nativa con una clave de Console, o deja que la herramienta
[`generate_image`](/tools#image-generate) de OpenCode use un modelo de imagen definiendo
`experimental.image_generate.model`, por ejemplo `opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google acepta sus `contents` y `generationConfig` nativos, y xAI sus opciones nativas como `resolution` y
`quality`. OpenAI Images y xAI Images también aceptan ediciones en `/images/edits`.

### Modelos de embedding

`text-embedding-3-small`, `qwen3-embedding-8b` y los demás modelos de embedding de la tabla anterior convierten texto en
vectores. OpenCode no los usa para chat, así que nunca aparecen en `/models`, y el nivel gratis no los incluye.
[Go](/console/go#embedding-models) incluye algunos. Llámalos en la API Embeddings de OpenAI con una clave de Console.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` acepta una cadena o un array de cadenas. `data` devuelve un vector por entrada, en el mismo orden.
- `dimensions` acorta los vectores en los modelos que lo admiten, como `text-embedding-3-small`.
- `encoding_format: "base64"` devuelve los vectores codificados en base64 en lugar de números de punto flotante.
- Cada entrada debe caber en la ventana de contexto del modelo.
- La respuesta indica `usage.cost` como cualquier solicitud de inferencia. Consulta el [costo](/console/api/inference#cost).

Los vectores de modelos distintos no son comparables, así que genera los embeddings de tus documentos y de tus consultas con el mismo modelo. Un
[proveedor conectado](/console/api/providers#endpoints) sirve sus propios modelos de embedding en `/embeddings`.

## Contexto

Hay muchos modelos disponibles, pero solo unos pocos funcionan bien como agentes de programación. Los proveedores también varían en configuración,
rendimiento y calidad, así que un modelo al que se accede a través de un gateway como OpenRouter puede comportarse de forma distinta.

<Callout type="tip">Probamos una selección de modelos y proveedores que funcionan bien con OpenCode.</Callout>

Para crear este catálogo:

1. Probamos un grupo selecto de modelos y hablamos con sus equipos sobre cómo ejecutarlos de la mejor forma.
2. Trabajamos con los proveedores para asegurarnos de que los modelos se sirvieran correctamente.
3. Medimos el rendimiento de cada combinación de modelo y proveedor para preparar una lista que podemos recomendar con confianza.

Console es un gateway de IA que te da acceso a estos modelos.

## Objetivos

Creamos Console para:

1. **Evaluar** los mejores modelos y proveedores para agentes de programación.
2. Ofrecer las opciones de **mayor calidad** sin degradar el rendimiento ni enrutar a proveedores más baratos.
3. Trasladarte las **reducciones de precio** al ofrecerte los modelos al costo, con un recargo solo para cubrir las comisiones de procesamiento.
4. Evitar la **dependencia de un proveedor**: usa Console con cualquier agente de programación o usa otro proveedor con OpenCode.
