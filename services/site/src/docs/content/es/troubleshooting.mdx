<Callout type="tip">
  Puedes pedir a OpenCode que se depure a sí mismo. Describe el problema y pídele que use esta página de solución de problemas; puede leer
  los pasos siguientes, inspeccionar su servicio y sus registros, y ayudar a identificar el problema.
</Callout>

OpenCode usa una arquitectura cliente-servidor. Un servidor en segundo plano gestiona las sesiones, los plugins, los permisos y otro estado
de la aplicación. Empieza por determinar si el problema está en un cliente, en el servidor compartido o en un proyecto concreto.

## Comprobar el servicio en segundo plano

Muestra la información actual del servidor:

```bash
opencode service status
```

Comprueba que la API responde correctamente:

```bash
opencode api get /api/info
```

Si el servicio se bloquea o no funciona correctamente, reinícialo:

```bash
opencode service restart
```

También puedes detenerlo e iniciarlo explícitamente:

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  OpenCode normalmente descubre o inicia el servicio en segundo plano compartido automáticamente. Los comandos de servicio solo son
  necesarios al diagnosticar su ciclo de vida.
</Callout>

## Permitir un origen de navegador

Si un cliente de navegador en otro origen no puede conectarse por CORS, agrega el origen del cliente a la configuración del servicio:

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

Usa un origen HTTP o HTTPS exacto, incluido el puerto cuando sea necesario, sin ruta ni barra final. Para permitir varios
orígenes, pasa una lista separada por comas como un solo argumento; se recortan los espacios alrededor de cada origen:

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` imprime un array JSON. Elimina la lista configurada con:

```bash
opencode service unset cors
```

Definir o quitar la configuración del servicio detiene el servicio en segundo plano. Su siguiente inicio toma la nueva configuración;
usa `opencode service start` para iniciarlo explícitamente.

Para un servidor en primer plano, repite `--cors` por cada origen adicional permitido:

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

Con `serve --service`, los flags `--cors` proporcionados sobrescriben la lista guardada para ese proceso. Sin esos flags, el modo
servicio usa la lista guardada. CORS no cambia la dirección de escucha ni omite la autenticación del servidor.

## Inspeccionar la API

El comando `api` usa el flujo local de descubrimiento y autenticación del servicio. Acepta un método y una ruta HTTP o un
ID de operación de OpenAPI.

Consulta la [referencia de la API](/api) para todos los endpoints y ID de operación.

Pasa un cuerpo de solicitud JSON con `--data` o `-d`, y agrega encabezados con `--header` o `-H`.

<Callout type="warning">
  Ejecutar `opencode api` puede iniciar el servicio en segundo plano cuando no hay ningún servicio compatible y sano disponible.
</Callout>

## Leer los registros

Las compilaciones instaladas escriben los registros en:

```text
~/.local/share/opencode/log/opencode.log
```

Sigue el registro mientras reproduces el problema:

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

Cada línea incluye un ID de `run` del proceso y un campo `role`. Usa `role=server` para la actividad de sesiones, proveedores, plugins, permisos y
herramientas.

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## Exportar telemetría

OpenCode puede enviar sus registros y trazas a un colector de OpenTelemetry o a un backend de APM que acepte OTLP a través de HTTP. Define
la URL base del colector, sin ruta:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer example-token"
export OTEL_RESOURCE_ATTRIBUTES="team=platform,host.name=dev-laptop"
opencode
```

| Variable                      | Comportamiento                                                                                                 |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | URL base. Los registros se envían a `<endpoint>/v1/logs` y las trazas a `<endpoint>/v1/traces`. Si no se define, se desactiva la exportación. |
| `OTEL_EXPORTER_OTLP_HEADERS`  | Encabezados `key=value` separados por comas que se envían en cada exportación, como una clave de API. |
| `OTEL_RESOURCE_ATTRIBUTES`    | Atributos `key=value` codificados para URL y separados por comas que se agregan a cada registro. Si una entrada tiene un formato incorrecto, se ignoran todas. |

Cada registro incluye también `service.name` (`opencode`), `service.version`, `deployment.environment.name` (el canal de
lanzamiento), `opencode.client` y `opencode.run`, que coincide con el ID de ejecución que aparece en el archivo de registro.

El servicio en segundo plano se ejecuta en un proceso separado y no hereda el entorno de tu shell. Configura las variables también en ese servicio
para obtener trazas de las llamadas a modelos y las ejecuciones de herramientas:

```bash
opencode service set env OTEL_EXPORTER_OTLP_ENDPOINT http://localhost:4318
opencode service set env OTEL_EXPORTER_OTLP_HEADERS "authorization=Bearer example-token"
opencode service start
```

## Capturar una instantánea del heap

Escribe una instantánea de memoria (heap) del servidor en segundo plano en ejecución en cualquier plataforma:

```bash
opencode debug heap-dump
```

El comando espera hasta que la instantánea está completa y luego imprime su ruta:

```text
/home/me/.local/share/opencode/log/heap-48213-2026-10-23T013012345Z.heapsnapshot
```

Escríbela en otro lugar con `--directory`. El servidor crea el directorio cuando falta:

```bash
opencode debug heap-dump --directory ./snapshots
```

- Solo usa un servidor que ya está en ejecución. Nunca inicia, sustituye ni reinicia uno.
- Usa `--server <url>` para capturar un servidor que iniciaste con `opencode serve`. Define `OPENCODE_PASSWORD` si tiene una.
  `--directory` es entonces una ruta en la máquina del servidor.
- Abre el archivo en el panel Memory de Chrome DevTools.

<Callout type="warning">
  El servidor se pausa mientras escribe la instantánea, y su uso de memoria puede aumentar durante un breve periodo. La instantánea puede
  contener prompts, contenido de archivos y credenciales. No la compartas públicamente.
</Callout>

### En la aplicación de escritorio

Ejecuta **Capture heap snapshots** desde la paleta de comandos. Escribe una carpeta en tu carpeta Descargas con una instantánea de
cada parte de la aplicación, además de un desglose de la memoria que una instantánea no puede mostrar:

```text
opencode-heap-2026-10-23T013012345Z/
  memory.json                  where the memory is, per process, in MiB: start here
  memory-infra.json            Chromium's memory dump trace; open it in https://ui.perfetto.dev
  heap-48213-….heapsnapshot    the desktop's own server
  window-1-48390.heapsnapshot  one per app window
  main-48102.heapsnapshot      the desktop main process
  gpu.json                     the GPU and driver
  manifest.json                processes, PIDs, and memory before and after; written last
```

- Una instantánea del heap solo contiene objetos JavaScript y la página. Las imágenes, el diseño, las capas del compositor y la memoria de la GPU están en
  `memory.json` y `memory-infra.json`.
- Los servidores remotos no se capturan. Usa `opencode debug heap-dump` en esa máquina.
- El servidor escribe su instantánea directamente en la carpeta, así que no se mueve ni se copia nada grande.
- Las pestañas del navegador no se incluyen, porque sus instantáneas contienen el contenido de las páginas que visitaste.

## Capturar perfiles de CPU y memoria

En macOS y Linux, puedes enviar una señal a un proceso de OpenCode en ejecución para capturar datos de diagnóstico. Obtén el PID del servidor en segundo plano
desde el endpoint de estado:

```bash
opencode api get /api/info
```

Usa el `pid` de la respuesta con una de estas señales:

- `SIGPROF` captura un perfil de CPU de diez segundos:

  ```bash
  kill -SIGPROF <pid>
  ```

  El resultado se escribe en el directorio de registros como `cpu-<pid>-<timestamp>.cpuprofile`.

- `SIGUSR1` captura una instantánea de memoria (heap):

  ```bash
  kill -SIGUSR1 <pid>
  ```

  El resultado se escribe en el directorio de registros como `heap-<pid>-<timestamp>.heapsnapshot`.

Espera a `CPU profile written` o `heap snapshot written` en `opencode.log` antes de abrir el archivo. La entrada de registro correspondiente
incluye su ruta completa. Puedes inspeccionar ambos tipos de archivo en Chrome DevTools.

<Callout type="note">
  Los perfiles activados por señal no están disponibles en Windows. Usa `opencode debug heap-dump` para las instantáneas del heap.
  Escribir una instantánea del heap puede pausar el proceso y aumentar temporalmente su uso de memoria.
</Callout>

## Archivos del servicio

El servidor compartido se registra en:

```text
~/.local/state/opencode/service.json
```

Su configuración privada del servicio se guarda por separado en:

```text
~/.config/opencode/service.json
```

La base de datos normalmente está en:

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` puede sobrescribir la ubicación de la base de datos.

<Callout type="warning">
  No elimines ni edites los archivos del servicio ni la base de datos mientras solucionas problemas. Usa los comandos de servicio para gestionar el
  demonio, y haz una copia de seguridad antes de inspeccionar datos persistentes con herramientas externas.
</Callout>

## Informar de un problema

Incluye lo siguiente al informar de un problema reproducible:

- La salida de `opencode --version`
- La salida de `opencode service status`
- La secuencia de pasos más pequeña que reproduce el problema
- Si el problema afecta al servicio compartido, a un cliente concreto o a un proyecto
- Las líneas de registro relevantes, incluidos sus campos `run` y `role`

Elimina las claves de API, los encabezados de autorización, los prompts, el contenido de archivos y otros datos sensibles antes de compartir registros.

Informa de los problemas reproducibles en [GitHub Issues](https://github.com/anomalyco/opencode/issues).
