Angi de vanlige proxyvariablene og unnta loopback-adresser fra proxyen. OpenCode bruker lokale HTTP-tilkoblinger mellom CLI-en og
bakgrunnstjenesten, så du må unnta disse adressene hvis du har satt opp en proxy i CLI-miljøet.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` håndterer HTTP-destinasjoner og `HTTPS_PROXY` håndterer HTTPS-destinasjoner. Selve proxy-URLen kan bruke `http://`
for begge variablene. `NO_PROXY` er en kommaseparert liste over verter og adresser som kobles direkte til.

## Tjeneste

Miljøvariabler du eksporterer i et shell, påvirker bakgrunnstjenesten bare når tjenesten startes derfra.
Lagre variablene i den administrerte tjenestekonfigurasjonen, så brukes de samme nettverksinnstillingene neste gang tjenesten starter.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Endring av en administrert miljøvariabel stopper den kjørende tjenesten. `service start` starter den igjen med det nye miljøet.
Behold også `NO_PROXY` i shell-miljøet til CLI-en hvis proxyen er satt der, fordi administrerte tjenestevariabler gjelder serverprosessen,
ikke CLI-prosessen.

Fjern en varig variabel med `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Autentisering

Hvis proxyen godtar tilgangsopplysninger i URL-en, oppgir du brukernavn og passord i hver proxy-URL som krever autentisering.
Prosentkod tegn som `@`, `:` og `/` i både brukernavnet og passordet.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

For bakgrunnstjenesten, gjør hele URLen varig. Verdien lagres i den private tjenestekonfigurasjonen og
vises av `opencode service get env`, så ikke del denne utdataen.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Sertifikater

Angi `NODE_EXTRA_CA_CERTS` til en PEM-fil når proxyen eller destinasjonen bruker et sertifikat signert av en privat sertifikatmyndighet.
De ekstra myndighetene legges til i kjøretidens tillitslager når prosessen starter.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Gjør filbanen varig for bakgrunnstjenesten, og start den deretter på nytt:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Antivirus og HTTPS-inspeksjon

Antivirusets «HTTPS-skanning» eller «skanning av krypterte tilkoblinger» (Kaspersky, Avast, ESET og andre) og bedriftsproxyer
for SSL-inspeksjon erstatter serverens sertifikat med sitt eget. OpenCode avviser det, og forespørsler mislykkes med
feil som:

```text
self signed certificate in certificate chain
SELF_SIGNED_CERT_IN_CHAIN
CERT_NOT_YET_VALID
CERT_SIGNATURE_FAILURE
```

Løs det på én av to måter:

- Utelat `opencode.ai` og `*.opencode.ai` fra HTTPS-skanning i antivirusinnstillingene. Legg også til leverandørens API-vert,
  for eksempel `api.anthropic.com`, hvis du kobler direkte til en leverandør.
- Eksporter sertifikatet til sertifikatmyndigheten som brukes til inspeksjon, som en PEM-fil. Bruk `NODE_EXTRA_CA_CERTS` for å klarere sertifikatet, som vist i
  [Sertifikater](#certificates).

## Klientsertifikater

Angi `settings.tls` på en leverandør hvis gateway krever gjensidig TLS. Modellforespørslene presenterer sertifikatet, og
TLS-håndtrykket sender det bare til servere som ber om det.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "company": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.company.example/v1",
        "tls": {
          "cert": "{file:/etc/company/client.pem}",
          "key": "{file:/etc/company/client.key}",
          "passphrase": "{env:CLIENT_KEY_PASSPHRASE}",
        },
      },
    },
  },
}
```

- `cert` og `key` er PEM-tekst. Bruk `{file:...}` for å lese dem fra filer. En fil som ikke kan leses, lar `tls` stå uangitt.
- `passphrase` trengs bare for en kryptert nøkkel.
- Virker på Bun- og Node-byggene. En server på Cloudflare Workers kan ikke presentere et klientsertifikat gjennom `fetch`.
- Forespørsler med et klientsertifikat følger ikke omdirigeringer, slik at sertifikatet ikke presenteres for en annen vert.

Hver modellforespørsel til den leverandøren presenterer sertifikatet: chat-, komprimerings-, bilde- og decision-modeller. En leverandør
med `tls` bruker HTTP i stedet for WebSockets. Verktøy som webfetch, eksterne MCP-servere og plugin-installasjoner presenterer
det ikke.

## Forgrunn

`--standalone` og `serve` bruker miljøet i sin egen prosess. `opencode service set env` konfigurerer ikke disse
prosessene.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Bruk samme mønster for en forgrunnsserver:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Verifiser

Sjekk at CLI-en kan nå bakgrunnstjenesten etter at innstillingene er brukt:

```bash
opencode api get /api/info
```

Hvis helsesjekken lykkes, virker den lokale tilkoblingen mellom klienten og tjenesten. Send en vanlig forespørsel til leverandøren
for å sjekke at tjenestens utgående proxy og sertifikatsti fungerer.
