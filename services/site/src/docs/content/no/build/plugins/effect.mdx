`@opencode/plugin/effect` er den Effect-native versjonen av OpenCode-plugin-API-et. Kontekstoperasjonene returnerer
Effects eller Streams, tilbakeringinger returnerer Effects, og pluginens levetid representeres av `Scope`.

OpenCode tilbyr `effect` (inkludert eksporterte `effect/*`-understier) og `@opencode/plugin` ved kjøring når den laster
plugins og deres `node_modules`-avhengigheter. Installer dem som peer-/dev-avhengigheter for lokal typekontroll og testing
i stedet for å pakke dem sammen med pluginen.

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

Eksporter en Effect-plugin fra `.opencode/plugins/` for å laste den automatisk.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Publiserte pakker og pluginkataloger utenfor `.opencode/plugins/` bruker samme `plugins`-konfigurasjon som andre serverplugins.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Se [Konfigurer plugins](/plugins) for aktivering, pakkeoppløsning og konfigurasjonsprioritet.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Livssyklus

`effect` kjører når plugin'en lastes. Scopen lukkes når plugin'en lastes på nytt eller lastes av, så registreringer, avgrensede
fibere og finalizers frigjøres sammen.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Bruk avgrensede fibere for bakgrunnsarbeid. Plugin-scopen avbryter fiberen under oppryddingen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Kontekst

Konteksten eksponerer Effect-klienten for den tilkoblede OpenCode-serveren pluss plugin-only-transforms, hooks, lagring,
omlastinger og alternativer. Den eksponerer ikke OpenCodes private Core-tjenester.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

Plugindefinisjonen og hele konteksten er deklarert som følger.

```ts title="plugins/company-effect/index.ts"
export default Plugin.define({

```

## Transforms

Transforms endrer tilstanden synkront via et redigeringsobjekt. Innenfor hvert domene bruker OpenCode transformene i den rekkefølgen
de ble registrert. Først leverer kildene leverandører og uforanderlige modelldefinisjoner. Deretter redigerer modelltransformene kandidatene fra de aktive
leverandørene. Når du bruker yield på registreringen, knyttes den til pluginens scope.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

En modelltransform kan håndheve policy på tvers av hele kandidatsamlingen for aktive leverandører.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Kall `reload` når ekstern tilstand som en transform bruker, endres. Her returnerer `loadFromSource()`
oppføringene `{ info: Provider.Info, models: readonly Model.Info[] }`; leverandøromlastinger invaliderer også hele modellresultatet.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agent

Les alle agenter eller hent én etter ID. Klientsvar inkluderer den oppløste plasseringen og skjemadata.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transform eller last agenter på nytt.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

### Leverandører

Les tilgjengelige leverandører eller inspiser én leverandørs metadata etter ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Leverandørtransforms redigerer leverandørinnstillinger og kildedefinisjoner. Redigererlesinger inkluderer inaktive leverandører og eksponerer
uforanderlige definisjoner; `models.update` redigerer en eid kopi av en kildemodell.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Erstatt en kildebeholdning med `models.set`, og last deretter på nytt etter at de fangede definisjonene endres.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

For kontospesifikk oppdagelse, send tilkoblingen som ble brukt til å laste beholdningen, som `sourceConnection`. OpenCode utelater
den leverandøren mens en annen tilkobling er valgt, til plugin'en din publiserer sin oppdaterte beholdning.

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

Skjemaer: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

### Modeller

Les tilgjengelige modeller og standardvalget.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Modelltransforms redigerer hele kandidatsamlingen for aktive leverandører. Deaktiverte kandidater forblir redigerbare til alle
transforms er ferdige; `update` kan legge til en modell bare under en tilgjengelig leverandør.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Tilbakeringinger redigerer rå modelloverstyringer. Leverandørstandarder flettes én gang når OpenCode fullfører resultatet; uendrede lesinger
gjenbruker det resultatet. `editor.provider` leser uforanderlige kildedefinisjoner, inkludert inaktive maler, i stedet for
modelltransformutdata.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Skjema: [`Model.Info`](/api#schema-Model.Info).


### Kommandoer

Les kommandoer som er tilgjengelige på gjeldende plassering.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Kommandotransformen kan foreløpig bare legge til kommandoer. Funksjonen som utfører kommandoen, får økten, promptvedleggene og leveringsmodusen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Integrasjoner

Les integrasjonene og finn de aktive tilgangsopplysningene hvis det finnes noen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Koble til med en nøkkel eller driv et OAuth-forsøk gjennom det tilkoblede API-et.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transform integrasjoner og autentiseringsmetoder. OAuth-metodetilbakeringinger er Effects og kan anskaffe avgrensede
ressurser.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

### MCP

List MCP-servere og deres gjeldende tilkoblingstilstand.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Plugins administrerer MCP-servere bare gjennom transforms. Bruk `editor.set` for å legge til eller erstatte en server, `editor.update` for å
endre konfigurasjonen og `editor.remove` for å fjerne den. Inspiser konfigurasjonen med `editor.list` og `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Angi `disabled: true` i en transform for å deaktivere og koble fra en server, eller `disabled: false` for å aktivere den og la
OpenCode koble til. OpenCode tilpasser servernes livssyklus til den transformerte konfigurasjonen.

Kall `reload()` når ekstern tilstand som en transform bruker, endres. Da brukes transformene på nytt, og serverne tilpasses resultatet.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Skjemaer: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts

  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void

```

### Plugins

List aktive, feilede og oppløste plugins på gjeldende plassering.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtrer skjemaverdiene i en Effect-pipeline når bare aktive plugins er relevante.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.state.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

### Referanser

Les referanser som er tilgjengelige på gjeldende plassering.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Legg til eller fjern lokale referanser og Git-referanser, og last deretter på nytt når ekstern tilstand endres. `get(name)` returnerer gjeldende konfigurerte
kilde, eller `undefined` når navnet mangler.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
```

### Verktøy

Registrer typede verktøy med Effect `Schema`. Utføreren mottar dekodet inndata og returnerer en Effect som inneholder typet
utdata, visningsinnhold eller metadata.

Redigereren støtter `add`, `update` og `remove`. Transformtilbakeringingen er synkron: den må ikke returnere en Effect eller Promise. Last
eksterne data før du registrerer eller laster på nytt. OpenCode spiller av aktive transforms i registreringsrekkefølge på en fersk
redigerer; for samme effektive verktøynavn overstyrer en senere gyldig registrering en tidligere.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Kall `yield* ctx.tool.reload()` etter at kildedata fanget av tilbakeringingen er endret. Omlasting spiller av aktive transforms
uten å endre rekkefølgen; den kjører ikke plugin-Effecten på nytt.

Effect-verktøy godtar samme [deklarasjon av fri form-inndata](/build/plugins/server#freeform-tool-input) som Promise-verktøy. Hvis modellen ikke annonserer det formatet, beholder verktøyet sin normale objektinndata.

Verktøy har en `id` som inneholder deres effektive navn, og `get()` returnerer `undefined` når den ID-en ikke finnes. Bruk
`update` og `remove` med navnet verktøyet er registrert under, inkludert navnerommet (`acme_greeting` ovenfor).
Punktum i navnerom blir `_`. I verktøynavn beholdes bokstaver, sifre, `_` og `-`. Alle andre tegn blir `_`.
Navn som ikke finnes, ignoreres. Bruk `add` med en fullstendig definisjon for å opprette et verktøy.
Oppdateringer bevarer navn og navnerom. Tilordne nye skjemaer eller alternativer for å erstatte
dem i stedet for å mutere nestede verdier. Ugyldige oppdateringer logges og lar den forrige definisjonen være intakt.

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Oppdateringer og fjerninger spilles av i rekkefølge med tillegg, også etter oppdateringer av MCP-katalogen.

`transform` returnerer en avgrenset registrering. Kjør `yield* registration.dispose` for å fjerne transformen og bygge på nytt
fra de gjenværende transformene, slik at en tidligere definisjon den overstyrte, avdekkes. Avhending er idempotent, og lukking
av plugin-scopen avhender også registreringene.

Hver modellforespørsel fanger et verktøysnapshot. Omlasting og avhending påvirker fremtidige snapshots, ikke definisjonene eller
utførerne som en eksisterende forespørsel allerede har fanget. Utførere som lukker over muterbare plugin-data, observerer fortsatt
disse dataene; fang en verdi inne i transformen når den må forbli knyttet til den definisjonen.

Skjemaer: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Hooks griper inn i operasjoner mens de pågår. Flere plugins kan registrere samme hook; OpenCode kjører dem i pluginrekkefølge, så
senere hooks ser tidligere endringer. Registreringene forblir aktive i plugin-scopen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Økter

Endre sammensatte systeminstruksjoner, meldinger eller verktøy rett før modelutsending. `context` kjører for
agentløkken; `compaction`, `generate` og `title` kjører for disse hjelpeforespørslene. `compaction` og `title` godtar et
`result` som hopper over modellkallet.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Meldinger i `context`-, `compaction`- og `generate`-hookene bærer `metadata` fra sin lagrede melding, skrivebeskyttet
(for eksempel det en `prompt`-hook satte). Det sendes ikke til modellen.

`system`-delen som inneholder OpenCodes instruksjoner, lister også hver kilde i `metadata.experimental.instructions` som
`{ key, text }`, for eksempel `core/date` eller `core/environment`, slik at en hook kan skille kildene. Listen er en kopi:
redigering av delens `text` oppdaterer den ikke. Dette er eksperimentelt og kan endres.

Endre modellforespørselsinnstillinger og eventuelt avgrens hooken til én leverandør. Hendelsen bærer samme `kind` som
HTTP-hookene nedenfor.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Endre native leverandørforespørsler eller -svar. Bodyene deres er engangsstrømmer; klon eller erstatt en body før du leser
den. Begge hookene kjører for hver forespørsel en økt sender; `event.kind` er `"primary"`, `"compaction"`, `"title"` eller
`"generate"` avhengig av hvilken flyt som sendte den.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Leverandører som strømmer over en WebSocket, gjenbruker én tilkobling per økt, så HTTP-hookene ser aldri den trafikken. Den
eksperimentelle `experimental.ws.handshake`-hooken kjører én gang per modellkall før tilkoblingen velges og eksponerer tilkoblingens
`url` og `headers`; endring av en av dem åpner socketen på nytt. HTTP-hooks kjører fortsatt for enhver forespørsel en WebSocket-
rute faller tilbake til.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` og `experimental.ws.receive` eksponerer rammene selv: `send` kjører etter at leverandør-
driveren har bygget en utgående ramme, `receive` kjører på hver innkommende ramme før driveren observerer den. Det `frame` inneholder når hooken returnerer, er det som går over ledningen eller når driveren;
OpenCode validerer det ikke.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Overstyr beslutningen om nytt forsøk for en leverandørfeil eller erstatt forsinkelsen i millisekunder. Hooken kjører etter at OpenCode
klassifiserer feilen og foreslår policyen sin, men før noe nytt forsøk planlegges. Den eksponerer ikke hvordan OpenCode
internt utfører neste forsøk.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

Den innledende `decision` er OpenCodes policy, så hooks kan gjøre en normalt terminal leverandørfeil retrybar eller nedlegge veto mot et
foreslått nytt forsøk. Flere hooks kjører i registreringsrekkefølge, og senere hooks ser gjeldende beslutning. Det innebygde maksimale
antallet forsøk er fortsatt en hard grense. `attempt` er det fysiske forsøket som foreslås; den innledende forespørselen er forsøk `1`,
så det første nye forsøket er forsøk `2`. Ugyldige forsinkelser (`NaN`, uendelighet eller negative verdier) faller tilbake til den beregnede forsinkelsen.
Gjenoppretting ved kontekstoverflyt forblir separat, fordi den komprimerer samtalen i stedet for å prøve samme forespørsel på nytt.

```ts
  readonly "experimental.ws.receive": SessionWebSocketReceive
  readonly retry: SessionRetry
}

type RetryDecision = { retry: false } | { retry: true; delay: number }

interface SessionRetry {
  readonly sessionID: string
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly error: { type: string; message: string; status?: number }
  readonly attempt: number
  decision: RetryDecision
}

interface SessionHookDomain {
  readonly hook: ModelHooks<SessionHooks>
}
```

### Shell

Endre terminalkommandoer, arbeidskataloger, tidsavbrudd, kjørbare filer eller miljøvariabler før kjøring.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const shell = ctx.shell
    yield* shell.hook("create.before", (event) =>
      Effect.sync(() => {
        if (event.command === "npm") event.command = "bun"
        event.timeout = Math.min(event.timeout, 60_000)
        event.env.COMPANY_ENV = "development"
      }),
    )
  }),
```

### Verktøy

Før-hooks kan erstatte inndata eller feile med `Tool.Error`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

Etter-hooks kan inspisere eller erstatte vellykkede resultater og feil.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

#### Referanse

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

De delte registreringstypene viser hvilke operasjoner som krever plugin-scopen.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publiser

En pakkeplugin bruker samme standardeksport som en lokal Effect-plugin. Eksporter Effect-implementasjonen fra hoved-
inngangspunktet og erklær `effect` som en `peerDependency`. Under `devDependencies`, lås versjonen `@opencode/plugin` bruker,
slik at utviklingsinstallasjoner bare har én kopi.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

OpenCode omdirigerer importer av `effect`, eksporterte `effect/*`-understier og `@opencode/plugin` (inkludert importer fra
avhengigheter i pluginens `node_modules`) til vertens kjøretidsforekomster, slik at fibere, loggere og `Schema`-parsere
deler én kjøretidskopi.

- Ikke bundle `effect` inn i den publiserte plugin-artefakten. Hvis du bygger med en bundler, merk `effect` og `effect/*`
  som eksterne.
- Plugins og deres `node_modules`-avhengigheter kjører alltid mot vertens OpenCode-utgivelses `effect`-forekomst.
  Bruk `effect`-API-er og modulstier som er kompatible med OpenCode-utgivelsen du sikter mot; avhengigheter bygget på en annen
  `effect`-hovedversjon (som Effect 3) mottar også vertens `effect` og støttes ikke.
- Bare offentlige `effect`-understier tilbys. En plugin som importerer en av Effects private `internal`-moduler, kan ikke
  lastes. Feilmeldingen oppgir stien.
- Den kompilerte OpenCode-binæren inkluderer ikke Scalar- og Swagger UI-assetene som Effects HTTP-API-dokumentasjonssider bruker;
  servering av disse sidene fra en plugin viser et varsel i stedet.

Pakkeinngangspunktet eksporterer `Plugin.define` med en `effect`-funksjon.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Bruk versjoner som er kompatible med OpenCode-utgivelsen du sikter mot, og test den installerte pakken i stedet for bare en
workspace-koblet kopi.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
