يفسح ضغط السياق مجالًا في جلسة طويلة باستبدال المحادثة الأقدم
بملخص، لتواصل الجلسة بعد حد سياق النموذج.

## كيف يعمل

عندما تقترب جلسة من حد سياق النموذج، يلخّص OpenCode
المحادثة الحالية كاملة. ويحتفظ أيضًا بأحدث محادثة، نحو
15,000 رمز افتراضيًا، بجانب الملخص لتبقى التفاصيل الحديثة الدقيقة
متاحة.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

وإرسال المحادثة كاملة يتيح لطلب الملخص إعادة استخدام ذاكرة مطالبات الطلب
العادي المؤقتة عندما يدعمها المزوّد. وتحدّث عمليات الضغط اللاحقة الملخص
القائم بما دار في المحادثة منذ نقطة التحقق تلك.

## البدء

ضغط السياق التلقائي مفعّل افتراضيًا:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

ضغط السياق يفقد بعض التفاصيل. فارفع `keep.tokens` عندما تهمّك التفاصيل الحديثة الدقيقة،
أو اطلب الضغط بنفسك قبل الضغط التلقائي.

## يدويًا

اطلب الضغط في أي وقت، حتى لسجل قصير:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

يعثر أمر `api` على الخدمة الخلفية ويجري المصادقة للاتصال بها. تؤكد استجابته قبول الطلب؛
ولا ينتظر إعداد الملخّص. تابع أحداث `session.compaction.*` لمعرفة موعد اكتمال الضغط. راجع
[مرجع API](/api) للاطّلاع على تفاصيل العملية.

| القاعدة | السلوك |
| --- | --- |
| التوقيت | يعمل عند أول نقطة آمنة، قبل المطالبات التي ما زالت تنتظر. |
| التكرار | تندمج الطلبات المقدَّمة أثناء وجود طلب معلّق في ذلك الطلب. |
| الأتمتة | يعمل عندما تكون `compaction.auto` على `false`. |

مرّر `id` حتى لا يتكرر أثر الطلب إذا أعدت إرساله كما هو. أما استخدام المعرّف نفسه في طلب
مختلف فيؤدي إلى خطأ تعارض.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## الإعدادات

أضف `compaction` إلى أي [ملف إعدادات لـ OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": "20%",
  },
}
```

| الحقل | الافتراضي | السلوك |
| --- | ---: | --- |
| `auto` | `true` | يضغط تلقائيًا قرب حد السياق، ويتعافى مرة واحدة عندما يرفض مزوّد طلبًا لأنه طويل جدًا. والضغط اليدوي يعمل دائمًا. |
| `background` | `true` | يكتب الملخص مسبقًا حتى لا ينتظره الضغط التلقائي. راجع [الضغط في الخلفية](#background-compaction). |
| `keep.tokens` | `15000` | المحادثة الحديثة التقريبية المحفوظة بجانب الملخص. والقيم الأكبر تحفظ تفاصيل أكثر لكنها تترك مجالًا أقل للعمل الجديد. |
| `buffer` | `"15%"`، 16k على الأقل | حصة نافذة سياق النموذج التي تبقى فارغة. ويبدأ الضغط التلقائي بمجرد أن تبلغ المحادثة الباقي. والقيم الأكبر تضغط أبكر. |

ويقبل `keep.tokens` عددًا صحيحًا غير سالب.

### المخزن الاحتياطي

`buffer` نسبة من نافذة كل نموذج، فيناسب إعداد واحد كل النماذج:

| نافذة النموذج | يضغط `"buffer": "20%"` عند |
| ---: | ---: |
| 128k | ~102k |
| 1M | 800k |

- وهي المساحة التي تبقى فارغة، لا النقطة التي يبدأ عندها الضغط: فضبط `"20%"` يضغط عند امتلاء 80%.
- يقبل من `"1%"` إلى `"99%"`، بما في ذلك الكسور العشرية مثل `"12.5%"`.
- ويعمل أيضًا عدد الرموز مثل `20000`. والعدد نفسه حصة كبيرة من نافذة صغيرة وحصة صغيرة من نافذة كبيرة.
- ويُتجاهل عدد الرموز الذي يساوي نافذة النموذج أو يتجاوزها، ويُطبَّق الافتراضي.

## النموذج

افتراضيًا يكتب OpenCode الملخص بنفسه بنموذج الجلسة. واضبط
`agents.compaction.model` لاستخدام نموذج آخر للملخصات:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" },
  },
}
```

إذا تعذّر العثور على ذلك النموذج، يستخدم OpenCode نموذج الجلسة بدلًا منه.

## الضغط في الخلفية

يكتب OpenCode الملخّص مسبقًا دون إيقاف الجلسة، ويضعه مكان المحادثة الأقدم عند حلول وقت الضغط.
فلا يوقف الضغط التلقائي الجلسة لكتابة ملخص:

```text
60k tokens before the threshold   summary of the conversation so far starts in the background
                                  the session keeps going; the summary is held, not applied
threshold                         the held summary is swapped in; everything since it is kept as is
```

وفي نوافذ السياق الصغيرة، يبدأ الملخص عند منتصف المسافة بين أول استجابة بعد آخر ضغط
وبين الحد على الأكثر.

| القاعدة | السلوك |
| --- | --- |
| التكلفة | يعيد طلب الملخص استخدام ذاكرة المطالبات المؤقتة. والملخص الذي لا يُستخدم أبدًا، مثلًا لأن الجلسة تنتهي قبل الحد، يكلّف رموزًا مع ذلك. |
| الانتظار | إذا كان الملخص ما زال يُكتب عند حلول موعد الضغط، تنتظر الجلسة انتهاءه. |
| الرجوع | يضغط السياق كالمعتاد إذا نمت المحادثة منذ الملخص المحفوظ بما يزيد على نحو 40% من الحد، أو إذا تغيّرت بداية المحادثة. |
| التخطي | لا يُستخدم للضغط الأصلي. وبعد تبديل النموذج مباشرةً، أو بعد انقطاع أطول من عمر ذاكرة المطالبات المؤقتة، يبدأ من الاستجابة التالية بدلًا من ذلك. |
| التخزين | تعيش الملخصات المحفوظة في الذاكرة وتُفقد عند إعادة التشغيل. |

أوقفه لكتابة الملخص فقط عند حلول موعد الضغط:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "background": false,
  },
}
```

## المزوّدون

يمكن لبعض المزوّدين ضغط المحادثة من جهتهم بدلًا من ذلك. فعّله لكل
مزوّد أو نموذج بـ`settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

ويتجاوز إعداد النموذج إعداد المزوّد. ويستخدم `native` ضغط
المزوّد؛ ويستخدم `summary` ضغط OpenCode نفسه.

وفي الضغط الأصلي، يرسل OpenCode المحادثة إلى نقطة نهاية الضغط
لدى المزوّد. ويعيد المزوّد عنصرًا معتمًا مشفّرًا ينوب
عن المحادثة الأقدم. وتبقى رسائلك ومرفقاتك الحديثة، حتى
`keep.tokens`، بجانبه:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| الموضوع | السلوك |
| --- | --- |
| الدعم | نماذج OpenAI Responses. ويتفاوت الدعم حسب النشر والنموذج. |
| الحد | الإعدادان `auto` و`buffer` نفسهما المستخدمان في ضغط الملخص. والطلبات اليدوية تعمل أيضًا. |
| قابلية النقل | لا تعمل نقطة التحقق المشفّرة إلا مع المزوّد والنموذج نفسيهما. وإذا بدّلت النموذج، تواصل الجلسة من المحادثة الأصلية بدلًا من ذلك. |
| الطول المفرط | إذا رفض المزوّد الضغط لأنه طويل جدًا، يعيد OpenCode المحاولة بطلب أصغر. ولا ينتقل إلى ملخص. |

## الملخصات

الملخص منظّم بحيث يستطيع وكيل آخر متابعة العمل منه:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

ويغطي الهدف والمتطلبات والقرارات والعمل المكتمل والنشط
والعوائق والخطوات التالية والملفات ذات الصلة. وفي المحادثة الحديثة المحفوظة
بجانبه، تُقصَّر مخرجات الأدوات الطويلة وتُستبدل بيانات المرفقات
بوصف قصير.

وبعد الضغط، تصبح النسخ الحالية من ملفات تعليماتك
أساس الجلسة؛ راجع [التعليمات](/instructions).

## الحدود

| الحد | النتيجة |
| --- | --- |
| النموذج | يحترم ضغط الملخص `agents.compaction.model`؛ وإلا استخدم نموذج الجلسة. والضغط الأصلي يستخدم نموذج الجلسة دائمًا. |
| السجل | يحتاج الضغط إلى محادثة أقدم ليستبدلها. ولا يستطيع إفساح مجال عندما يكون الطلب في معظمه تعليمات ثابتة ومخططات أدوات. |
| الحجم | إذا كانت المحادثة المطلوب ضغطها طويلة جدًا هي نفسها، يرسل OpenCode نسخة نصية مقصّرة وقد يغفل أقدم التبادلات. |
| التعافي | يُضغط الطلب المرفوض لطول مفرط وتُعاد محاولته مرة واحدة. ويُعاد الرفض الثاني كخطأ. |
| التخزين | تبقى الرسائل الأقدم مخزّنة حتى عندما لا تُرسل إلى النموذج. |

مثلًا، لا يفيد الضغط هنا:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## الترحيل

استخدم V1 سلوك الجولة الأخيرة والتشذيب. ويستخدم V2 الملخصات و
`compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

تنطبق الإعدادات والسلوك في هذه الصفحة على V2.
