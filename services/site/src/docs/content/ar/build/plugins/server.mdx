يعمل جزء الخادم من الملحق في خادم OpenCode. وهو يعدّل سلوك OpenCode ويضيف ميزات: الأدوات
والخطافات والتكاملات والأوامر والوكلاء. راجع [النظرة العامة](/build/plugins) لبنية حزمة الملحق
وتحميلها ونشرها.

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

## دورة الحياة

يعمل `setup` عند تحميل الملحق. وقد يعيد دالة لتحرير الموارد تُستدعى عند إلغاء تحميله.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### السياق

سياق الملحق هو أساسًا [عميل خادم OpenCode](/build/client).
وتستخدم طرق القراءة والإجراء فيه المدخلات والاستجابات نفسها التي يستخدمها العميل. ويضيف
طرقًا خاصة بالملحقات للتحويلات وخطافات وقت التشغيل وإعادات التحميل والتسجيلات
وخيارات الملحق.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

ويصف `ctx.location` الموقع الذي حُمِّلت فيه نسخة الملحق هذه. ويضم
`directory` و`workspaceID` اختياريًا وبيانات `project` الوصفية (`id`
و`directory` و`canonical`). وهو متاح في ملحقات Promise وEffect معًا.
وهو موقع نسخة الملحق، لا موقع كل جلسة تستطيع
الوصول إليها أو كل حدث تتلقاه.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### الخيارات

مرّر خيارات الملحق بصيغة الكائن في `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

واقرأ تلك القيم من `ctx.options` أثناء `setup`.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## التحويلات

التحويلات تعديلات متزامنة لحالة نطاقات OpenCode، وكل منها يبني على التسجيلات السابقة في نطاقه.
وتعكس قراءات السجل مثل `ctx.model.list()` كل تسجيل حتى الآن، بما في ذلك أثناء إعداد الملحق؛
فعند بدء التشغيل لا يُجمَّع سوى إشعارات التحديث، ولا يتأخّر ظهور التسجيلات عند قراءة السجل. وتظلّ واجهات API لحالة الموارد
تعرض حالة تشغيلها الفعلية. فتسجيل التعريف لا يعني اكتمال الاتصال بالمورد أو انتهاء العمليات
الأخرى المتعلقة به.

وتسهم المصادر بمزوّدين وتعريفات نماذج غير قابلة للتغيير عبر `ctx.provider.transform`.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

يُوسَم السجل بأنه تغيّر عند أيّ تسجيل أو إزالة أو استدعاء لـ `reload()`. ويُعاد بناؤه عند القراءة التالية بتطبيق كل
تحويل نشط على قيمة جديدة، حسب ترتيب التسجيل. احرص على أن تكون التحويلات قليلة الكلفة وقابلة لإعادة التطبيق. ولا تؤثّر أيّ إعادة بناء لاحقة
في القيم التي سبق أن قرأتها.

بعد تطبيق تحويلات المزوّدين وتحديد المتاح منهم، ينشئ OpenCode مجموعة نماذج المزوّدين النشطين ويعيد تطبيق
جميع تحويلات النماذج بالترتيب. ويمكن لسياسة النماذج فحص المجموعة الكاملة للنماذج المرشّحة، بما فيها نماذج المصادر
التي حُدّثت مؤخرًا.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

ولا تُراقب المدخلات الملتقطة تلقائيًا. فحمّل البيانات الخارجية قبل رد النداء المتزامن، ثم استدعِ
`reload()` بعد تغيّر تلك المدخلات. وهنا، تعيد `loadFromSource()`
إدخالات `{ info: Provider.Info, models: readonly Model.Info[] }`.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

وتُبطل تغييرات المزوّد نتيجة النماذج النشطة كلها، فتواصل سياسة سعر الإخراج تصفية النماذج المحدّثة.
واستخدم `ctx.model.reload()` عندما يتغيّر مدخل التقطه تحويل نموذج وحده.

## API

### الوكيل

اقرأ كل الوكلاء أو اجلب وكيلًا بمعرّفه.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

سجّل تحويلًا لفحص الوكلاء أو إنشائهم أو تحديثهم أو إزالتهم أو اختيار الوكيل الافتراضي.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

سجّل وكيلًا جديدًا باستخدام `editor.update`. إذا كان المعرّف موجودًا بالفعل، تُعدِّل هذه الطريقة الوكيل المقابل. وإلا فإنها تُنشئ وكيلًا باستخدام `Agent.Info.default(id)` قبل استدعاء دالة رد النداء.

```ts
await ctx.agent.transform((editor) => {
  editor.update("reviewer", (agent) => {
    agent.description = "Reviews code for correctness and maintainability"
    agent.mode = "subagent"
    agent.system = "Review the proposed changes and report actionable findings."
  })
})
```

وأعد تحميل الوكلاء بعد تغيّر حالة خارجية يستخدمها تحويل.

```ts
await ctx.agent.reload()
```

### المزوّدون

اقرأ المزوّدين المتاحين أو افحص بيانات مزوّد واحد الوصفية بمعرّفه.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

وتعدّل تحويلات المزوّد إعدادات المزوّد وتعريفات المصادر. وتضم قراءات المحرّر المزوّدين غير النشطين وتعرض
تعريفات غير قابلة للتغيير؛ ويعدّل `models.update` نسخة مملوكة من نموذج مصدر.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

واستبدل جرد مصادر المزوّد بـ`models.set`، ثم أعد التحميل بعد تغيّر التعريفات الملتقطة.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

وللاكتشاف الخاص بحساب، مرّر الاتصال المستخدم لتحميل الجرد كـ`sourceConnection`. ويستبعد OpenCode
ذلك المزوّد ما دام اتصال آخر مختارًا، حتى ينشر ملحقك جرده المحدّث.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### النماذج

اقرأ النماذج المتاحة والاختيار الافتراضي.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

تعدّل تحويلات النماذج المجموعة الكاملة للنماذج المرشّحة لدى المزوّدين النشطين. ويمكن تعديل النماذج المعطّلة إلى أن تنتهي كل
التحويلات، ولا يستطيع `update` إضافة نموذج إلا إلى مزوّد متاح.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})
```

وتعدّل ردود النداء تجاوزات النموذج الخام. وتُدمج افتراضيات المزوّد مرة واحدة عندما يثبّت OpenCode النتيجة؛ وتعيد القراءات غير المتغيّرة
استخدام تلك النتيجة. ويعرض `editor.provider` تعريفات المصادر غير القابلة للتغيير، بما في ذلك القوالب غير النشطة، لا
مخرجات تحويل النموذج.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### التكاملات

اقرأ التكاملات وافحص بيانات الاعتماد النشطة.

```ts
const integrations = await ctx.integration.list()
```

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,

```

وابدأ محاولة اتصال OAuth أو افحصها أو أكملها أو ألغها.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

وتعرض الاتصالات القائمة على الأوامر تدفق البدء والحالة والإلغاء نفسه.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

سجّل تحويلًا لفحص التكاملات وإدارة طرق مصادقتها.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

وأعد تحميل التكاملات بعد تغيّر حالة خارجية يستخدمها تحويل.

```ts
await ctx.integration.reload()
```

### MCP

اسرد خوادم MCP وحالة اتصالها الحالية.

```ts
const servers = await ctx.mcp.list()
```

ولا تدير الملحقات خوادم MCP إلا عبر التحويلات. واستخدم `editor.set` لإضافة خادم أو استبداله، و`editor.update`
لتغيير إعداده، و`editor.remove` لإزالته. وافحص الإعداد بـ`editor.list` و`editor.get`.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

واضبط `disabled: true` في تحويل لتعطيل خادم وقطع اتصاله، أو `disabled: false` لتفعيله والسماح
لـOpenCode بالاتصال. ويوائم OpenCode دورة حياة الخادم من الإعداد المحوّل.

واستدعِ `reload()` بعد تغيّر حالة خارجية يستخدمها تحويل لإعادة تطبيق التحويلات ومواءمة الخوادم.

```ts
await ctx.mcp.reload()
```

### الأذونات

اطلب الإذن قبل تنفيذ إجراء. ويقيّم `assert` [قواعد الأذونات](/permissions) في الجلسة،
بما في ذلك الموافقات المحفوظة، ويطلب من المستخدم الموافقة إذا أسفر تقييم القواعد عن `ask`. وينجح الاستدعاء بمجرد السماح بالإجراء.

```ts
execute: async (input, context) => {
  await ctx.permission.assert({
    sessionID: context.sessionID,
    agent: context.agent,
    source: { type: "tool", messageID: context.messageID, id: context.id },
    action: "deploy",
    resources: [input.environment],
    save: [input.environment],
  })
  return { content: await deploy(input.environment) }
}
```

- يُطابَق `action` و`resources` مع القواعد. تمنع أيّ نتيجة `deny` تنفيذ الإجراء؛ وفي غيابها، تؤدي أيّ نتيجة `ask` إلى طلب موافقة المستخدم.
- ويسرد `save` الأنماط المحفوظة عندما يختار المستخدم السماح دائمًا.
- ويختار `agent` قواعد من تنطبق، ويؤول إلى وكيل الجلسة. ويربط `source` المطالبة باستدعاء أداة.
- ويمرّر `metadata` تفاصيل إضافية إلى مطالبات الأذونات وخطافات `evaluate`.

إذا منعت قاعدةٌ الإجراء أو رفضه المستخدم مع إبداء ملاحظات، يفشل الاستدعاء بخطأ `Tool.Error` يتضمّن السبب، فيتلقّاه النموذج
ويواصل عمله. أما الرفض من دون ملاحظات فينهي الخطوة الحالية. دع الأخطاء تنتقل إلى المستدعي بدلًا من إرجاعها على أنها مخرجات
الأداة.

افحص طلبات الأذونات المعلّقة أو حلها.

```ts
const pending = await ctx.permission.list({ sessionID })
const request = await ctx.permission.get({ sessionID, requestID })
await ctx.permission.reply({ sessionID, requestID, decision: "once" })
```

استبدل قواعد الأذونات المحدودة بالجلسة. وتُقيَّم بعد قواعد الوكيل، وتفوز القاعدة
المطابقة الأخيرة. وترث الجلسات الفرعية القواعد السارية عند إنشائها.

```ts
await ctx.session.update({
  sessionID,
  permissions: [{ action: "edit", resource: "/path/to/original/checkout/**", effect: "deny" }],
})
```

### الأدوات

اقرأ الأدوات المسجّلة حاليًا، بعد كل تحويل، خارج رد نداء تحويل. ولكل أداة `id`
يحتوي اسمها الفعّال.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

وسجّل الأدوات وحدّثها وأزلها بتحويل متزامن، بما في ذلك في ملحقات Promise. وحمّل البيانات الخارجية
قبل التسجيل أو إعادة التحميل. ويسود تسجيل صالح لاحق على اسم الأداة الفعّال نفسه.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {

      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,

```

العملية الأساسية أيضًا.

```ts
execute: async ({ url }, context) => {

  return { content: await response.text() }
}
```

#### إدخال الأدوات الحر

الأداة المباشرة التي لها حقل نصي مطلوب واحد بالضبط يمكن أن تدع النموذج يكتب ذلك النص دون غلاف JSON. فاضبط `freeform` على `{ type: "text" }` أو `{ type: "regex", pattern }` أو `{ type: "lark", grammar }`.

```ts
editor.add({
  name: "ticket",
  description: "Look up a ticket by ID",
  options: { codemode: false },
  input: Schema.Struct({ id: Schema.String }),
  freeform: { type: "regex", pattern: "OPS-[0-9]+" },
  execute: async ({ id }) => ({ content: await lookup(id) }),
})
```

إذا كانت `regex` ضمن الصيغ المدعومة في API النموذج المختار على models.dev، أمكن للنموذج كتابة `OPS-42` مباشرةً. وإلا حذف Core `freeform` **وحده**؛ فتظلّ الأداة `ticket` متاحة للنموذج ويستدعيها باستخدام `{"id":"OPS-42"}`. وغياب قائمة الصيغ أو خلوّها يعني أن الإدخال الحر غير مدعوم. ويتلقّى المنفّذ `{ id }` في الحالتين.

وداخل Code Mode (`codemode: true`)، تأخذ الأداة الحرة نصها مباشرةً، كما في `await tools.ticket("OPS-42")`. ويعمل أيضًا `await tools.ticket({ id: "OPS-42" })`.

واستدعِ `reload()` بعد تغيير بيانات المصدر التي التقطها رد النداء. فإعادة التحميل تعيد تشغيل التحويلات النشطة دون
تغيير ترتيبها؛ وهي لا تعيد تشغيل إعداد الملحق.

```ts
await ctx.tool.reload()
```

واستخدم `list()` و`get()` لفحص الأدوات الموجودة في المحرّر حاليًا. وللأدوات `id` يحتوي اسمها الفعّال،
ويعيد `get()` القيمة `undefined` عندما يغيب ذلك المعرّف. واستخدم `update` و`remove` باسم الأداة الفعّال،
بما في ذلك نطاقها (`acme_greeting` أعلاه). تُستبدل النقاط في النطاقات بـ`_`. وفي أسماء الأدوات، تبقى الحروف والأرقام و`_` و`-` كما هي، ويُستبدل أي محرف آخر بـ`_`. وتُتجاهل الأسماء الغائبة؛ وإنشاء أداة يحتاج
`add` بتعريف كامل. وتحفظ التحديثات الاسم والنطاق. وعيّن مخططات أو خيارات جديدة لتستبدلها
بدل تعديل القيم المتداخلة. وتُسجّل التحديثات غير الصالحة وتُبقي التعريف السابق سليمًا.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

وتُعاد التحديثات والإزالات بالترتيب مع الإضافات، بما في ذلك بعد تحديثات كتالوج MCP. والتخلص من
تسجيلها يزيل تلك التغييرات ويعيد البناء من التحويلات المتبقية.

ألغِ التسجيل لإزالة تحويله وإعادة البناء من التحويلات المتبقية، فيعود أيّ تعريف سابق
حلّ التحويل محلّه. ولا يترتّب على تكرار الإلغاء أيّ أثر إضافي. ويؤدّي إلغاء تحميل الملحق أيضًا إلى إلغاء تسجيلاته.

```ts
await registration.dispose()
```

وكل طلب نموذج يلتقط لقطة أدوات مستقرة قابلة للتنفيذ. وتؤثر التحويلات وإعادات التحميل والتخلص اللاحقة في اللقطات
المستقبلية، لا في التعريفات أو أوصاف نطاقات Code Mode أو المنفّذين الملتقطين أصلًا. والمنفّذون الذين يغلقون
على بيانات ملحق متغيّرة يلاحظون تلك البيانات مع ذلك؛ فالتقط قيمة داخل التحويل عندما يجب أن تبقى مرتبطة
بذلك التعريف.

### VCS

اقرأ معلومات المستودع أو حالة نسخة العمل أو فروق الملفات.

```ts
const info = await ctx.vcs.get()

const changes = await ctx.vcs.status()
const diff = await ctx.vcs.diff({ mode: "working", context: 3 })
```

وسجّل مزوّد VCS محدود النطاق بالموقع بتحويل. ويُختار المزوّد المطابق لنوع المستودع المكتشف
تلقائيًا؛ واستخدم `editor.default.set` لاختيار مزوّد آخر.

```ts
await ctx.vcs.transform((editor) => {
  editor.add({
    id: "custom",
    name: "Custom VCS",
    info: async () => ({ branch: { current: "feature", default: "main" } }),
    branches: async (input, { signal }) => readBranches(input, signal),
    status: async (scope, { signal }) => readStatus(scope.worktree, signal),
    diff: async (input, { signal }) => readDiff(input, signal),
  })
  editor.default.set("custom")
})
```

وتتلقى ردود نداء المزوّد الموقع الحالي وجذر نسخة العمل وجذر المشروع الأساسي ومخزن المستودع
الاختياري. وتتلقى ردود نداء الفروق أيضًا الوضع المختار والسياق المطلوب وميزانية بايتات الإخراج. ويواصل اكتشاف المستودع
استخدام أدوات كشف Git وMercurial المدمجة في OpenCode.

ويمكن للمزوّدين اختياريًا تطبيق `init(scope, { signal })` لإنشاء مستودع في `scope.worktree`. ويختار التهيئة
المزوّد بمعرّفه (Git افتراضيًا)، لا بنوع المستودع المكتشف. وسجّل مزوّدًا فيه `init` حتى
عندما لا يكون للموقع مستودع بعد؛ فيتحقق OpenCode من وجود المجلد وخلوّه من مستودع قبل استدعائه،
ثم يعيد اكتشاف المشروع. ولا تزال صيغ المستودعات الجديدة تحتاج دعم اكتشاف يتجاوز رد النداء هذا.

```ts
  add(definition: VcsDefinition): void
  default: {
    get(): string | undefined
    set(providerID: string): void
  }
}

interface VcsDefinition {
  init?(scope: VcsScope, context: { signal: AbortSignal }): Promise<void>
  // Existing info, branches, status, and diff callbacks are required.

```

### Worktrees

سجّل استراتيجية worktree محلية باستخدام دورة حياة الملحق العادية. وتملك وحدة التطبيق في هذا المثال
التحقق من الخيارات وعمليات `create` و`remove` و`list` في الواجهة الخلفية.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

وحمّل الملحق عبر `plugins` وأعدّ الوجهة المشتركة على حدة:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- وإضافة استراتيجية تختارها تلقائيًا. ويفوز آخر تسجيل نشط؛ ولا حاجة إلى إعداد لاختيار الاستراتيجية.
- والتخلص من تسجيلها أو تفريغ الملحق يعيد التطبيق السابق، وفي النهاية استراتيجية Git المضمّنة.
- و`reload()` يعيد تشغيل التحويلات بعد تغيّر المدخلات الملتقطة؛ ولا يعيد تشغيل إعداد الملحق.
- وإخفاقات الإنشاء لا تعيد المحاولة عبر Git. وتحتفظ worktrees القائمة بمالكها المسجّل حتى عندما يتغيّر الافتراضي.
- تدير الاستراتيجيات مجلدات محلية. ولا تشمل هذه الواجهة إعداد مساحات عمل بعيدة.

#### العمليات

ويعرض سياق الملحق عمليات worktree القائمة على المشروع نفسها التي يعرضها العميل. وتشترط كل عملية
`projectID`. ويقرأ `list` الجرد المحفوظ وحده، بما في ذلك نسخ السحب المعروفة للمشروع نفسه؛ ولا يحمّل
الإعداد ولا يبدأ الملحقات ولا يكتشف تغييرات نظام الملفات.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

ويحمّل الإنشاء الإعداد والملحقات من مجلد المشروع المحفوظ `canonical` ويستخدم استراتيجيتها المختارة.
وتقبل العملية خيارات `directory` للمجلد الأب، و`from` للمصدر، و`branch` للفرع المبدئي، و`name` للاسم.
ويؤول المصدر إلى النسخة الأساسية، ويجب أن ينتمي تجاوز `from` إلى ذلك المشروع. واختيار مصدر
لا يغيّر جذر الإعداد.
ويجب أن تدعم الاستراتيجية المختارة مرجع البداية المقدّم؛
فعملية اللقطة الأصلية في Rift، مثلًا، ليس لها خيار اختيار مرجع.

وينتظر الإنشاء والتحديث تفعيل ملحقات النسخة الأساسية. والاستدعاءات التي تُجرى أثناء إعداد ملحقات تلك النسخة
ترى التسجيلات حتى الآن ولا تنتظر تفعيلها.

وتحمّل الإزالة الإعداد الأساسي وتفعّل ملحقاته، ثم تستخدم استراتيجية worktree المسجّلة لا
الافتراضي المختار حاليًا. والمالك المسجّل غير المتاح ينتج خطأ. وقد تكون وجهة worktree
في مكان آخر:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

والملكية الغائبة تفشل الإزالة بدل العودة إلى Git. ويمكن للاستراتيجية رفع `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })`، مع استيراد `Worktree` من `@opencode/plugin`، لطلب
تأكيد الإجبار دون الاعتماد على أخطاء Core أو Git.

والتحديث يحمّل الإعداد الأساسي ويطلب من كل الاستراتيجيات المتاحة إيجاد worktrees عبر جذور نسخ السحب المعروفة.
ويجمع النتائج ويحفظ الملكية المسجّلة ويشذّب المجلدات المفقودة. ويُسجّل مصدر اكتشاف فاشل
بينما تواصل المصادر الأخرى. وتبقى المجلدات القائمة محفوظة حتى لو لم تفد بها أي استراتيجية متاحة. وراقب
`worktree.updated` واستدعِ `list` مجددًا لقراءة الجرد المتغيّر.

```ts
await ctx.worktree.refresh({ projectID })
```

#### Reference

وتتلقى التطبيقات وجهة مقترحة بعد التسمية ومعالجة التعارض. فأعد المجلد الفعلي من
`create`؛ فقد يختلف عندما تتطلب واجهة خلفية تخطيطها. ويحل OpenCode المسار المعاد ويستخدمه
للجرد وأوامر بدء التشغيل ونتيجة API. ويجب أن يكون المجلد المعاد موجودًا.

والاستراتيجيات التي تختار وجهة أخرى تعالج تعارضات الأسماء هناك. ولا يزال OpenCode ينشئ المجلد الأب
المقترح قبل استدعاء الاستراتيجية. ويجب أن يفيد `list` بالمجلدات التي تملكها الاستراتيجية وحدها، مع أي جذور مستودعات.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

ويجب أن تتعاون ردود نداء Promise مع إلغاء `signal`. أما ردود نداء Effect فتعيد Effects وتستخدم مقاطعة
Effect بدلًا من ذلك. وتبقى التسجيلات محدودة النطاق بوقت تشغيل الملحق؛ وتستخدم عمليات المشروع سجل النسخة الأساسية.
ومحوّلات إعداد Core تغذّي إعدادات المجلدات إلى ذلك السجل.

### البحث على الويب

اسرد مزوّدي البحث على الويب أو نفّذ استعلامًا عبر المزوّد المختار.

```ts
const providers = await ctx.websearch.providers()
const results = await ctx.websearch.query({ query: "OpenCode plugins", providerID: "internal" })
```

وسجّل مزوّدًا واختر المزوّد الافتراضي بتحويل.

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = (await response.json()) as { url: string; title: string; content: string }
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

وعطّل البحث على الويب باختيار `false`، أو أعد تحميل المزوّدين بعد تغيّر الحالة الخارجية.

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```

### الأحداث

اشترك في تدفق الأحداث العام للخادم المرتبط. وألغِ التدفق أثناء تنظيف الملحق. ومرّر `types`، مثلًا `ctx.event.subscribe({ types: ["config.updated"] })`، لتلقي تلك الأنواع وحدها؛ وتُحدَّد أنواع الأحداث وفقًا لذلك. فالملحقات تعمل داخل الخادم، فلا تتلقى `server.connected` أبدًا خلافًا لعملاء SDK. وتُتجاهل أسماء الأنواع غير المعروفة مع تحذير في سجل الخادم.

```ts
const controller = new AbortController()
void (async () => {
  for await (const event of ctx.event.subscribe({ signal: controller.signal })) {
    console.log(event.type)
  }
})()
return () => controller.abort()
```

## الخطافات

تعترض الخطافات العمليات الجارية. فسجّل خطافًا في نطاقه وتخلص من
التسجيل المعاد عندما لا تعود تحتاجه.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

ويمكن لعدة ملحقات تسجيل الخطاف نفسه. ويشغّلها OpenCode بترتيب الملحقات،
فترى الخطافات اللاحقة التغييرات التي أجرتها الخطافات السابقة.

### الجلسات

تعترض خطافات الجلسة قبول المطالبات واستدعاءات النموذج وHTTP الأصلية وإعادات المحاولة.

#### التفرعات

ويعمل خطاف `fork` بعد نسخ OpenCode للسجل وقبل إرجاع استدعاء التفرّع. ويحدّد `sessionID` الجلسة الجديدة.

```ts
await ctx.session.hook("fork", ({ sessionID }) => console.log(sessionID))
```

#### قبول المطالبات

اعترض مطالبات المستخدم الواردة قبل تحديد المرفقات والمهارات وإدراج المطالبة في صندوق الوارد الدائم:

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

ويتلقى الخطاف مسودة مملوكة قابلة للتغيير:

- و`prompt` يضم `text` و`files` وإشارات الوكلاء في `agents` والمهارات المختارة `skills`.
- و`metadata` يضم بيانات قبول يعرّفها التطبيق.
- و`delivery` هو `"steer"` افتراضيًا ويمكن تغييره إلى `"queue"`.
- ومعرّفات الجلسة والرسالة للقراءة فقط؛ ولا يستطيع خطاف إعادة توجيه القبول.

وتتبع الملفات والمهارات التي يضيفها خطاف مسار التحليل والتحقق
العادي. وعند إعادة كتابة النص، حدّث إزاحات `mention` في المرفقات التي لم تعد
مطابقة أو أزلها. وإشارات الوكلاء لا تبدّل الوكيل النشط للجلسة.

وتعمل خطافات المطالبات وفق هذه الشروط:

- تعمل الخطافات بترتيب التسجيل بعد جاهزية ملحقات موقع الجلسة.
- والأوامر التي ترسل عبر `session.prompt` تشغّل الخطاف.
- أما الرسائل التركيبية ورسائل shell وضوابط الضغط والنقل فلا.
- ويعمل الخطاف مرة واحدة أثناء القبول، لا قبل كل استدعاء نموذج.
- ولا يتاح التحديد حسب المزوّد لأن تحليل النموذج يحدث بعد القبول.

وتصبح التعديلات إدخال المستخدم المحفوظ الأساسي. وإذا فشل التحضير أو
قُوطع، لا يقبل OpenCode المطالبة.

صمّم خطافات المطالبات بحيث يمكن إعادة المحاولة بأمان. فلا تضمن هذه الخطافات تنفيذ آثارها الجانبية مرة واحدة بالضبط:

- وإعادة محاولة معرّف معلّق أو مسلّم أصلًا تعيد القبول الأصلي دون إعادة تشغيل الخطافات.
- والتقديمات المتزامنة قد تشغّل الخطافات أكثر من مرة، لكن يفوز أول قبول ناجح وحده.
- وخطافات المطالبات تحوّل الإدخال ولا تعرض واجهة رفض محدّدة النوع.

#### طلبات النموذج

عدّل تعليمات النظام المجمّعة أو الرسائل أو الأدوات أو خيارات الطلب قبل إرسال الطلب إلى النموذج مباشرةً. ولكل
نوع طلب تصدره الجلسة خطافه الخاص، فيستطيع الملحق معاملة حلقة الوكيل والطلبات المساعدة
بشكل مختلف:

- يعمل `context` لحلقة الوكيل، بما في ذلك المتابعات المدفوعة بالأدوات.
- ويعمل `compaction` لملخصات نقاط التحقق. و`messages` هو سجل المحادثة الجاري تلخيصه؛ ويضيف OpenCode
  مطالبة تلخيصه بعد عمل الخطافات. واضبط `result` لتسجيل الضغط بنفسك وتخطي استدعاء النموذج؛ ويأخذ
  الحقول نفسها التي تأخذها رسالة ضغط مكتملة.
- ويعمل `generate` لاستدعاءات `ctx.session.generate` العابرة.
- ويعمل `title` لتوليد العناوين. وليس له `agent` ولا `tools`. واضبط `result` لتوفير العنوان بنفسك.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

وتؤثر التغييرات في استدعاء النموذج الصادر وحده، لا في السجل المحفوظ ولا الإعداد. والخطاف الذي ينبغي أن ينطبق على
كل طلب يجب أن يسجّل لكل نوع.

وتحمل الرسائل في خطافات `context` و`compaction` و`generate` بيانات `metadata` لرسالتها المخزّنة، للقراءة فقط
(مثلًا ما ضبطه خطاف `prompt`). ولا تُرسل إلى النموذج.

ويسرد جزء `system` الذي يحمل تعليمات OpenCode كل مصدر أيضًا في `metadata.experimental.instructions` كـ
`{ key, text }`، مثل `core/date` أو `core/environment`، ليستطيع الخطاف تمييز المصادر. والقائمة نسخة:
فتعديل `text` في الجزء لا يحدّثها. وهذه ميزة تجريبية قد تتغيّر.

وتتبع تجاوزات الطلب هذه القواعد:

- يبدأ `options` فارغًا لكل استدعاء نموذج؛ ولا يحتوي إعدادات النموذج المحلولة.
- والمفاتيح المحدّدة النوع إعدادات توليد؛ وأي مفتاح آخر يُمرَّر إلى البروتوكول المختار كخيار مزوّد.
- وتعمل الخطافات بترتيب التسجيل وترى التجاوزات التي أجرتها الخطافات السابقة.
- لإعدادات الطلب أسبقية على الإعدادات الافتراضية للنموذج، وللأخيرة أسبقية على الإعدادات الافتراضية للمسار.
- تُدمج كائنات خيارات المزوّد على جميع مستويات التداخل، بينما تحلّ المصفوفات والقيم المفردة محلّ القيم السابقة.
- وحذف تجاوز أو ضبطه على `undefined` يعود إلى الافتراضيات المضبوطة بدل إزالتها.
- تُطبَّق تعديلات جسم طلب HTTP الخام بعد تحويل الطلب إلى صيغة البروتوكول، ويمكنها استبدال الحقول الناتجة.

#### خيارات المزوّد

وتستخدم خيارات المزوّد أسماء الخيارات الدلالية للبروتوكول المختار، لا حقول جسم HTTP الخام. وحدّد الإعدادات الخاصة
بالمزوّد للمزوّد المطابق. مثلًا، يستخدم OpenAI Responses الخيار `reasoningEffort`:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

وتعتمد خيارات التوليد على البروتوكول والنموذج المختارين:

- `maxTokens` هو حد رموز الإخراج الدلالي.
- ويدعم Gemini الخيار `topK`؛ ولا يعرضه OpenAI Responses.

#### تحديد النموذج

هذا خطاف تجريبي يعمل كلّما حدّدت الجلسة النموذج الذي سيعالج الطلب، وقبل تجهيز أيّ جزء من الطلب. يبدأ `model`
بالنموذج المختار؛ فغيّره لخدمة هذا الطلب بنموذج آخر من المزوّد نفسه، بما في ذلك نموذج مخفي
من منتقي النماذج. وتحتفظ الجلسة بنموذجها المختار؛ ويستخدم الطلب ورسالة المساعد النموذج الجديد.
ويفيد `kind` بالطلب الجاري حله، فيستطيع موجّه تخطي العناوين أو إعادة التوجيه بعد الضغط. ونموذج من
مزوّد آخر يفشل باعتباره غير متاح.

```ts
await ctx.session.hook(
  "experimental.model.resolve",
  (event) => {
    if (event.model.id === "auto" && event.kind !== "title")
      event.model = { providerID: event.model.providerID, id: pick(event.sessionID) }
  },
  { providerID: "acme" },
)
```

#### طلب النموذج

عدّل إعدادات طلب النموذج وحدّد نطاق الخطاف لمزوّد واحد اختياريًا. ويحمل الحدث `kind` نفسه
الذي تحمله خطافات HTTP أدناه.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### HTTP الأصلية

عدّل طلبات المزوّد الأصلية أو استجاباته. فأجسامها تدفقات تُقرأ مرة واحدة؛ فانسخ الجسم أو استبدله قبل
قراءته.

ويعمل الخطافان لكل طلب تصدره الجلسة. ويفيد `event.kind` بالتدفق الذي أصدره: `"primary"` لحلقة
الوكيل، و`"compaction"` لملخصات نقاط التحقق، و`"title"` لتوليد العناوين، و`"generate"` لاستدعاءات
`ctx.session.generate` العابرة. واستخدمه بدل معرّف الوكيل لتمييز الطلبات المساعدة.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### WebSocket الأصلية (تجريبي)

والمزوّدون الذين يبثّون عبر WebSocket يفتحون اتصالًا واحدًا لكل جلسة ويعيدون استخدامه بين الطلبات، فلا
ترى `http.request` و`http.response` تلك الحركة أبدًا. ويعمل خطاف `experimental.ws.handshake` مرة لكل استدعاء نموذج
قبل اختيار الاتصال. ويحمل `sessionID` و`agent` و`model` و`kind` نفسها التي تحملها خطافات
HTTP، إضافة إلى `url` و`headers` للاتصال. وتغيير `url` أو `headers` يغيّر المقبس الذي يستخدمه الطلب، فيعيد
رمز bearer المدوّر فتح الاتصال.

ولا تزال خطافات HTTP تعمل لكل طلب HTTP، بما في ذلك الطلب الذي يعود إليه مسار WebSocket.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

ويعرض `experimental.ws.send` و`experimental.ws.receive` الإطارات نفسها، وهما نظير WebSocket
لتحرير جسم طلب HTTP أو استجابته. ويعمل `send` بعد بناء سائق المزوّد إطارًا صادرًا وقبل
كتابته؛ ويعمل `receive` على كل إطار وارد قبل أن يلاحظه السائق. وكلاهما يحمل الإطار كسلسلة ويرسل
ما يحمله `frame` عند إرجاع الخطاف.

ولا يتحقق OpenCode من الإطارات المعاد كتابتها. ويتتبع السائق الحالة من ردود المزوّد، فإعادة الكتابة التي
تغيّر معنى البروتوكول مسؤولية الملحق، كما هو جسم HTTP المعاد كتابته.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

وهذه الخطافات تجريبية وقد تتغير أسماؤها أو أشكالها.

#### سياسة إعادة المحاولة

تجاوز قرار إعادة المحاولة لفشل مزوّد أو استبدل مهلة التأخير بالمللي ثانية. ويعمل الخطاف بعد أن يصنّف OpenCode
الفشل ويقترح سياسته، لكن قبل جدولة أي إعادة محاولة. ولا يعرض كيفية إجراء OpenCode
للمحاولة التالية داخليًا.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

ويمكن لخطافات إعادة المحاولة تغيير `decision` الأولي في OpenCode بجعل فشل نهائي
قابلًا لإعادة المحاولة أو بنقض إعادة محاولة مقترحة.

وتتبع قرارات إعادة المحاولة هذه القواعد:

- وتعمل عدة خطافات بترتيب التسجيل، وترى الخطافات اللاحقة القرار الحالي.
- ويبقى الحد الأقصى المدمج لعدد المحاولات حدًّا صارمًا.
- و`attempt` المحاولة الفعلية قيد النظر. فالطلب الأولي `1`، وأول إعادة محاولة `2`.
- والتأخيرات غير الصالحة مثل `NaN` أو اللانهاية أو القيم السالبة تعود إلى التأخير المحسوب.
- والتعافي من فائض السياق منفصل لأنه يضغط المحادثة بدل إعادة محاولة الطلب نفسه.

### الأذونات

راجع قرارات الأذونات بعد تقييم القواعد المضبوطة وقبل
تنفيذ إجراء أو نشر مطالبة إذن.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-5-5" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

- تعمل الخطافات لقرارات `allow` و`ask`.

- ويمكن للخطاف تغيير `effect` إلى `allow` أو `ask` أو `deny`.
- ويظهر `message` في طلب إذن مصعّد أو يصبح سبب الرفض.

## دعم V1

ويمكن لملحق دعم V1 وV2 من نقطة دخول الحزمة نفسها. فصدّر افتراضيًا
كائنًا واحدًا فيه دالة `server()` لـV1 ودالة `setup()` لـV2:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- يستدعي V1 الدالة `server()` ويستخدم الخطافات المعادة.
- ويقرأ V2 `id` و`setup()` من التصدير الافتراضي (أو `effect()` لملحقات Effect)، ويتجاهل `server()`.
- وأبقِ كل تطبيق على واجهته؛ فمشاركة تصدير لا تترجم خطافات V1 إلى خطافات V2.
- وافرد `Plugin.define(...)` في الكائن المصدّر ليتحقق من نوع تعريف V2 على حدة من `server()`.

وتُدعم صيغة كائن V1 في OpenCode `1.18.29`. وقد تتوقع إصدارات V1 الأقدم
تصديرات دوال بدلًا من ذلك؛ فاختبر الحزمة المثبّتة بأقدم إصدار V1
تنوي دعمه وبـV2.
