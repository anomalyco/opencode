شغّل CLI في مشروع لفتح واجهة الطرفية بملء الشاشة:

```bash
opencode
```

ومرّر مجلدًا للعمل في مشروع آخر:

```bash
opencode ~/code/my-project
```

ومن الطرفيات المُستحسنة:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

تعرض الطرفيات التي تدعم Truecolor ألوان السمات بأعلى دقة؛ أما الطرفيات التي لا تدعمه فتختار أقرب الألوان من لوحتها المتاحة.

## الأتمتة

استخدم `opencode run` لإرسال مطالبة دون فتح الواجهة التفاعلية. وهو مصمّم للسكربتات ومهام CI
وغيرها من سير العمل التي تحتاج مخرجات النموذج مباشرةً في الطرفية.

```bash
opencode run "Explain this repository"
```

## Mini

استخدم `opencode mini` لبدء الواجهة التفاعلية المصغّرة لـ OpenCode بدل TUI بملء الشاشة.

```bash
opencode mini
```

شغّل `opencode mini --help` للاطلاع على خيارات الجلسة والنموذج والوكيل والمطالبة وإعادة العرض.

## الخدمة الخلفية

افتراضيًا، يكتشف OpenCode خادمًا خلفيًا مشتركًا واحدًا لحساب مستخدمك أو يبدأه. ويتصل كل عميل OpenCode محلي
بذلك الخادم، الذي يملك الجلسات والإعدادات والتكاملات والأذونات وتنفيذ الأدوات.

واستخدم `--standalone` للعمل بخادم خاص، أو `--server` للاتصال بعنوان URL لخادم محدّد:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

عطّل الخدمة المشتركة لتستخدم أوامر CLI خوادم خاصة افتراضيًا بدل تشغيلها:

```bash
opencode service set disabled true
opencode
```

وهذا يوقف الخدمة الخلفية العاملة. ولا يزال `--server` يتصل بخادم مختار صراحةً؛ ولا يزال
`opencode service start` قادرًا على بدء الخدمة المشتركة صراحةً. وللعودة إلى الاستخدام التلقائي للخدمة، شغّل `opencode service unset disabled`.
ويحتاج الاقتران إلى الخدمة المشتركة ولا يتاح أثناء تعطيلها.

راجع [استكشاف الأخطاء وإصلاحها](/troubleshooting) لتشخيص الخدمة المشتركة، و[مرجع API](/api) لنقاط نهاية الخادم.

## المسارات

اطبع مسارًا محليًا محدّدًا لاستخدامه مع أدوات أخرى:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

ويقبل المحدّد الاختياري `db` أو `home` أو `data` أو `config` أو `cache` أو `state` أو `tmp` أو `bin` أو `log` أو `repos` ويطبع
المسار متبوعًا بمحرف سطر جديد فحسب. يُحدَّد مسار قاعدة البيانات وفق قناة الإصدار و`OPENCODE_DB`؛ وإذا حدّدت مسارًا نسبيًا لقاعدة البيانات، فإنه يُفسَّر
انطلاقًا من مجلد البيانات. وتُطبع القيمة `:memory:` كما هي. لا يبدأ هذا الأمر خادمًا ولا يفتح قاعدة البيانات.

وأغفل المحدّد لعرض كل المسارات مع تسمياتها:

```bash
opencode debug paths
```

## إزالة التثبيت

عاين الملفات والتثبيت المطلوب إزالتهما:

```bash
opencode uninstall --dry-run
```

وشغّل `opencode uninstall` لتأكيد الإزالة. ويوقف OpenCode الخدمات الخلفية المسجّلة والطرفيات الدائمة قبل
إزالة مجلد الذاكرة المؤقتة العام، المشترك بين إصدارات OpenCode وقنواته. ولا تُزال بيانات
الجلسات ولا الإعدادات ولا الحالة أبدًا.

- يتخطى `--force` (`-f`) التأكيد؛ فاستخدمه للإزالة غير التفاعلية.
- وتستخدم تثبيتات مديري الحزم مدير الحزمة المكتشف. وتطبع تثبيتات Curl الأمر الأخير لإزالة
  الملف التنفيذي يدويًا.
