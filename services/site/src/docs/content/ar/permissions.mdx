تحدّد الأذونات ما إذا كان بإمكان الوكيل تنفيذ إجراء على مورد معيّن.

## الإعداد

من الإعدادات الشائعة أن يطلب OpenCode موافقتك قبل تشغيل أوامر shell، ويسمح بأوامر فحص Git المعتادة،
ويمنع دائمًا إرسال التغييرات إلى المستودع البعيد. أضف هذه القواعد بالترتيب إلى `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

تُطبَّق القاعدة المطابقة الأخيرة، لذا ضع الاستثناءات المحدّدة بعد القاعدة العامة.

<Callout type="warning">
  يستخدم V1 أسماء حقول وإجراءات مختلفة. وفي V2، استخدم `permissions` و`shell` و`subagent` بدل `permission`
  و`bash` و`task`.
</Callout>

## القواعد

تشترط كل قاعدة ثلاثة حقول نصية:

| الحقل      | المعنى                                                                    |
| ---------- | -------------------------------------------------------------------------- |
| `action`   | الإجراء الذي تطلب الأداة إذنًا لتنفيذه |
| `resource` | القيمة المستخدمة، مثل مسار أو أمر أو URL أو استعلام أو معرّف مهارة أو معرّف وكيل |
| `effect`   | `allow` أو `deny` أو `ask`                                                   |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| الأثر  | النتيجة                              |
| ------- | ----------------------------------- |
| `allow` | المتابعة دون سؤال          |
| `deny`  | حجب العملية                 |
| `ask`   | انتظار قرار من العميل |

إذا لم تنطبق أي قاعدة، يستخدم OpenCode `ask`.

## المطابقة

تستخدم الإجراءات والموارد أحرف بدل بسيطة للقيمة كاملة:

| النمط | المطابقة                                      |
| ------- | ------------------------------------------ |
| `*`     | صفر أو أكثر من الأحرف، بما في ذلك `/`    |
| `?`     | حرف واحد بالضبط                     |
| غير ذلك   | الحرف نفسه، دون معنى خاص |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

يطابق هذا النمط المسار كله بعد توحيد صيغته. تُستبدل الشرطات المائلة العكسية
بشرطات مائلة عادية، ولا تميّز المطابقة بين الأحرف الكبيرة والصغيرة على Windows.

ونمط shell المنتهي بـ ` *` يطابق الأمر بلا وسائط أيضًا:

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

فهو يطابق `git status` و`git status --short` معًا.

ويجمع OpenCode القواعد بالترتيب ويستخدم آخر مطابقة. ويُحمَّل الإعداد الأقل أولوية
أولًا، ثم تُضاف القواعد العامة، ثم تُضاف قواعد الوكيل
أخيرًا.

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

قد يشمل التحقّق من الأذونات عدة موارد في عملية واحدة، مثل تعديل يمسّ عدة
ملفات. تمنع أي نتيجة `deny` العملية؛ وفي غيابها، تؤدي أي نتيجة `ask` إلى طلب الموافقة.
وفي غياب النتيجتين، يُسمح بالعملية.

## الإجراءات

أسماء إجراءات V2 سلاسل نصية، فيمكن للملحقات تعريف مزيد منها. وتستخدم الأدوات المدمجة
حاليًا هذه الإجراءات والموارد:

| الإجراء               | المورد                                                                    |
| -------------------- | --------------------------------------------------------------------------- |
| `read`               | مسار داخلي نسبي إلى الموقع أو مسار خارجي مطلق بصيغته المعيارية |
| `edit`               | المسار الهدف لـ`edit` و`write` و`patch`                                |
| `glob`               | نمط glob المطلوب                                                      |
| `grep`               | التعبير النمطي المطلوب، لا مسار البحث                           |
| `shell`              | نصّ الأمر الذي يستخرجه المحلّل، وقد يستخرج عدة نصوص من أمر مركّب |
| `subagent`           | معرّف الوكيل الهدف                                                             |
| `skill`              | معرّف المهارة                                                                    |
| `question`           | `*`                                                                         |
| `webfetch`           | عنوان URL المطلوب                                                               |
| `websearch`          | استعلام البحث                                                                |
| `generate_image` | نموذج الصور المختار بصيغة `providerID/modelID`، مع `#variant` عند ضبطه |
| `external_directory` | النطاق الذي يحدّده مسار المجلد الخارجي بصيغته المعيارية، وينتهي عادةً بـ `/*` |
| `<server>_<tool>`    | `*` لأداة MCP؛ تبقى الحروف والأرقام و`_` و`-` كما هي في كلا الاسمين، ويُستبدل أي محرف آخر بـ`_` |
| `opencode_list_mcp_resources` | اسم خادم MCP                                                    |
| `opencode_read_mcp_resource`  | `<server>:<uri>`                                                   |
| `execute`            | `*`؛ والرفض يزيل Code Mode ويسرد أدواته مباشرة، بينما تفرض الأدوات المتداخلة قواعدها |

تحتفظ إجراءات MCP بالشرطات، لذا تطابق أدوات خادم اسمه `mcp-atlassian` النمط `mcp-atlassian_*`، لا `mcp_atlassian_*`.

مثلًا، اسمح بمهارة واحدة وارفض كل المهارات الأخرى:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

و`doom_loop` و`lsp` ليستا إجراءَي إذن حاليين في Core V2.

## المجلدات

يُفحص المسار خارج الموقع النشط وخارج worktree مشروعه غير الجذري
وفق قواعد `external_directory` قبل تقييم قواعد `read` أو `edit` الخاصة به. تسمح السياسة
الافتراضية بـ`external_directory`، فلا يطلب OpenCode الموافقة على المسارات الخارجية
إلا إذا أضفت قاعدة. ولطلب الموافقة قبل أي وصول خارج المشروع:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "*", "effect": "ask" },
  ],
}
```

ويمكن لقواعد أضيق بعده أن تسمح بمجلدات محدّدة أو ترفضها:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

وينطبق ذلك على المسارات الخارجية التي تستخدمها `read` و`edit` و`write` و`patch`.
يفحص shell مجلد العمل الخارجي والمجلدات التي يستنتجها
محلّل الأوامر قبل فحص موارد `shell`.

ولـ`external_directory` و`read` و`edit`، تُوسَّع البادئة `~` أو `~/` أو `$HOME` أو
`$HOME/` عند تحميل الإعداد:

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

أما موارد shell فتبقى كما وردت في نص الأمر، من دون توسيع الاختصارات التي تشير إلى المجلد الرئيسي.

<Callout type="warning">
  يعمل `shell` بصلاحيات مستخدم النظام المضيف في الوصول إلى نظام الملفات والعمليات والشبكة. ولا يمكن ضمان استنتاج جميع المجلدات من نص الأمر،
  لذا استخدم قائمة سماح محدودة لأوامر shell بدل الاعتماد على أنماط تحاول التعرّف على كل أمر خطير.
</Callout>

قد تخرج مسارات التغيير النسبية من الموقع النشط مع بقائها داخل
worktree مشروعه. وتُطبَّع المسارات الخارجية الصريحة قبل المطابقة،
فأذن لحدود مجلدات موثوقة فقط.

## محلّل أوامر shell

يفحص OpenCode أذونات shell بمحلّله المدمج لأوامر Bash وZsh وPOSIX `sh` وPowerShell. ويتعذّر تحليل بعض الأوامر بأمان، مثل الأوامر ذات الصياغة غير الصالحة أو التي تستخدم التقييم الديناميكي مثل `eval`. إذا انطبقت أي قاعدة رفض من قواعد `shell`، يفشل الأمر بخطأ من المحلّل، إذ يتعذّر التحقّق من أوامره الفرعية في ضوء قاعدة الرفض. وإلا لزم الحصول على موافقتين: واحدة على الأمر كاملًا بوصفه مورد `shell` واحدًا، وأخرى على `external_directory` بالقيمة `*`. ولا يمنح الموافقة الثانية إلا المستخدم نفسه أو قاعدة تسمح بالوصول إلى جميع المجلدات. ولا تُحفَظ أيّ من الموافقتين في صورة نمط.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [
    {
      "permissions": [
        { "action": "shell", "resource": "git status *", "effect": "allow" },
        { "action": "shell", "resource": "rm *", "effect": "deny" },
      ],
    },
  ],
}
```

تُطبَّق قواعد الأذونات وأنماط الموافقة المحفوظة على كل أمر فرعي يستخرجه المحلّل وعلى كل وجهة لأمر `cd`، وتُستنتج المجلدات المعنية حيثما أمكن. لا يوجد وضع موافقة إضافي ولا تقييد شامل للمجلدات غير المعروفة.

## الإعدادات الافتراضية

يبدأ كل وكيل، بما في ذلك الوكلاء المخصّصون، بهذه السياسة الأساسية المرتّبة:

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

يضيف الوكلاء المدمجون هذه السياسات:

| الوكيل        | السياسة الإضافية                                                              |
| ------------ | ------------------------------------------------------------------------------ |
| `build`      | يسمح بالأسئلة                                                               |
| `plan`       | يسمح بالأسئلة، ولا يسمح بالتعديل إلا على الملفات الموجودة ضمن `~/.opencode/plan` |
| `general`    | يرفض الأسئلة وتشغيل الوكلاء الفرعيين                                       |
| `explore`    | يرفض كل شيء إلا shell والقراءات وglobs وgrep وجلب الويب والبحث على الويب والمجلدات الخارجية؛ ويسأل عن قراءات `.env` |
| `title`      | يرفض كل الإجراءات                                                              |
| `summary`    | يرفض كل الإجراءات                                                              |
| `compaction` | يحتفظ بالسياسة الأساسية                                                          |

لا توجد قاعدة افتراضية تطلب الموافقة على `external_directory`، لذا تتم القراءة والتعديل خارج
الموقع وworktree دون طلب الموافقة. أضف قاعدة `external_directory` بقيمة `ask` أو `deny`، كما هو موضّح في
[المجلدات](#directories)، لإعادة طلب الموافقة أو منع الوصول إلى المسارات الخارجية.
وتعلو القواعد العامة وقواعد الوكلاء اللاحقة على هذه القواعد الافتراضية.

## الوكلاء

ضع القواعد المشتركة في الأعلى والقواعد الأضيق تحت
`agents.<id>.permissions`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

تُضاف قواعد الوكيل بعد القواعد العامة؛ فهي لا تحل محل المصفوفة
العامة. ويستخدم الوكيل الفرعي المخصّص أذوناته الخاصة، لا مجموعة فرعية من أذونات
الوكيل الذي أطلقه.

## الموافقات

عندما يسفر تقييم القواعد عن `ask`، يمكن لتطبيقات العميل الرد بأحد الخيارات التالية:

| الخيار       | الرد      | النتيجة                                                               |
| ------------ | ---------- | -------------------------------------------------------------------- |
| Allow once   | `once`     | الموافقة على الطلب المعلّق وحده                                     |
| Allow always | `always`   | الموافقة عليه وحفظ الأنماط التي تقترحها الأداة للمشروع     |
| Reject       | `reject`   | رفضه ورفض كل طلب إذن معلّق آخر في تلك الجلسة |

مثلًا، اختيار **Allow always** لـ`git status --short` قد يحفظ
بادئة shell تشمل أوامر `git status` اللاحقة:

```text
shell: git status * → allow
```

الموافقات المحفوظة قواعد `allow` دائمة خاصة بالمشروع. ولا تتجاوز أبدًا
أيّ قاعدة `deny` واردة في الإعدادات. وتقترح الأدوات الأنماط التي يمكن حفظها: فبعضها يقترح `*`،
ويقترح shell بادئات الأوامر، ويقترح جلب الويب موقع عنوان URL (مثل
`https://opencode.ai/*`)، وتقترح المهارات والوكلاء الفرعيون معرّفاتها.
راجع الموافقات الواسعة وأزل ما لم تعد تحتاجه.

ويمكن للعملاء إرفاق ملاحظات عند الرفض. وعلى العملاء غير التفاعليين أن يقرروا
كيفية معالجة طلبات الموافقة؛ وتبقى قواعد `deny` المضبوطة مفروضة دائمًا.

## السياسات

يمكن لأيّ [سياسة](/policies) أن تمنع إجراءً نهائيًا بعد تقييم قواعد الأذونات والموافقات
المحفوظة. فهي تحوّل `allow` أو `ask` إلى `deny`، ولا تمنح حق الوصول أبدًا.

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

وتتجاوز السياسات العامة والسياسات المُدارة من Console إعداد المشروع، وهكذا تحجب
مؤسسة ما أمرًا كان المستودع سيسمح به.
