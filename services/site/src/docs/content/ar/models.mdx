اختر نموذجًا للجلسة الحالية بـ`/models`:

```text
/models
```

يسرد OpenCode النماذج من [models.dev](https://models.dev) وتكاملات المزوّدين وإعدادك. ولا يعرض المنتقي
إلا النماذج المفعّلة التي يكون مزوّدها متاحًا في المشروع الحالي. واربط المزوّدين في
[المزوّدون](/providers).

## الاختيار

اختر إدخالًا من `/models` بدل تخمين مزوّده أو معرّف نموذجه. وينطبق الاختيار على الجلسة الحالية
ولا يغيّر إعدادك.

```text
anthropic/claude-sonnet-5-5
```

والتوفر خاص بكل مشروع:

- يجب أن يكون النموذج مفعّلًا.
- ويجب أن يكون مزوّده متاحًا في المشروع الحالي.
- ولا تنتقل بيانات الاعتماد والإعداد من مشروع آخر تلقائيًا.

## التشغيلات

استخدم `--model` لاختيار نموذج لتشغيل واحد من سطر الأوامر دون تغيير الافتراضي المضبوط:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

ويمكن للوكلاء والأوامر اختيار نموذجها أيضًا. راجع [الوكلاء](/agents) و[الأوامر](/commands).

## الافتراضيات

اضبط `model` في `opencode.json` أو `opencode.jsonc` لاختيار الافتراضي للعمل الجديد:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

يصبح النموذج المضبوط افتراضي الكتالوج عندما يكون مفعّلًا ومزوّده متاحًا. وإلا عاد OpenCode
إلى أحدث نموذج مدعوم متاح.

- النموذج المختار أصلًا لجلسة له أولوية على الافتراضي المضبوط.
- وتبديل نموذج الجلسة لا يعيد كتابة ملف الإعداد.
- ويحتفظ `model` في الجذر حاليًا بالمزوّد والنموذج الافتراضيين فقط، لا بالمتغيّر.

راجع [الإعدادات](/config) لمواقع الإعدادات وأسبقيتها.

## النماذج المجانية

اضبط `OPENCODE_DISABLE_FREE_MODELS=1` (أو `true`) على عملية الخادم لإخفاء [نماذج OpenCode المجانية](/console/models#free-models):

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

وللخادم الخلفي المشترك:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

المجاني يعني نموذج `opencode` أو `opencode-go` بلا سعر إدخال. وتختفي هذه النماذج من الكتالوج والافتراضيات؛
واختيار أحدها صراحةً يفشل بـ`Model unavailable`. وبدون تسجيل دخول، يغيب مزوّد `opencode` حتى تربط
حساب OpenCode Console أو تضبط `OPENCODE_API_KEY`، الذي يعيد نماذجه المدفوعة.

ولحجب النماذج المجانية عن الجميع في مؤسسة، استخدم سياسة بدلًا من ذلك. راجع [المؤسسات](/enterprise#block-free-models).

## المتغيّرات

المتغيّرات خيارات مسمّاة لنموذج واحد، تُستخدم غالبًا لجهد التفكير أو ميزانيات الرموز. أضف `#variant` عند اختيار
واحد لتشغيل أو جلسة أو وكيل أو أمر:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

تأتي أسماء المتغيّرات من البيانات الوصفية الحالية للنموذج المختار. وأسماء مثل `low` و`high` و`max` ليست
متاحة لكل نموذج، والمتغيّر غير المعروف ينتج خطأ في تحليل النموذج.

عرّف متغيّرات جديدة، أو استبدل متغيّرات الكتالوج بالمعرّف نفسه، في مصفوفة `variants` الخاصة بالنموذج:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

ويمكن أن يحتوي كل متغيّر `settings` و`headers` و`body`. وتُطبَّق قيمه بعد قيم المزوّد والنموذج.

لاستبدال متغيّرات استدلال نموذج، صف أدوات ضبط استدلاله في `capabilities.reasoning`، بصيغة
[models.dev](https://models.dev) v2. ويبني OpenCode متغيّرات حزمة النموذج منها:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| الحقل       | الغرض                                                                    |
| ----------- | -------------------------------------------------------------------------- |
| `supported` | هل يستخدم النموذج الاستدلال. والقيمة `false`، أو `true` دون أدوات ضبط، لا تضيف أي صيغة. |
| `toggle`    | يضيف صيغة `none` تعطّل الاستدلال.                                           |
| `effort`    | مستويات الجهد المعروضة. وتحتفظ `default` بالافتراضي لدى المزوّد ولا تضيف أي صيغة. |
| `budget`    | رموز التفكير الاختيارية `min` و`max`. وتُتجاهل عند ضبط `effort`.             |

وتُطبَّق المتغيّرات المدرجة في `variants` فوق تلك المبنية من `capabilities.reasoning`.

## الخيارات

ويمكن لإدخالات المزوّد والنموذج تخصيص الطلبات بـ`settings` و`headers` و`body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| الحقل      | الغرض                                                            |
| ---------- | ------------------------------------------------------------------ |
| `settings` | خيارات حزمة المزوّد مثل `baseURL` أو `reasoningEffort`.           |
| `headers`  | ترويسات HTTP إضافية للطلبات.                                       |
| `body`     | حقول جسم الطلب الخاصة بالمزوّد.                                    |

ويطبّق OpenCode قيم المزوّد أولًا، ثم قيم النموذج، ثم المتغيّر المختار أخيرًا.

- تُدمج كائنات `settings` و`body` المتداخلة.
- وتحلّ المصفوفات والقيم المفردة اللاحقة محل القيم السابقة.
- وتُطابق أسماء الترويسات دون حساسية لحالة الأحرف.
- والخيارات خاصة بكل مزوّد وقد تتجاهلها حزمة مزوّد آخر أو ترفضها.

## الأسماء المستعارة

استخدم `modelID` لمنح نموذج API معرّفًا أسهل في الكتالوج:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

هنا، `openai/coding-default` هو المرجع القابل للاختيار ويُرسل `gpt-6.1-sol` إلى المزوّد. وللنموذج غير
الموجود في الكتالوج أصلًا، يفترض OpenCode:

- دعم أدوات JSON، وإدخال نص وصورة، وإخراج نص. ولا إدخال أدوات حر إلا إذا سرد `capabilities.freeform` الصيغة.
- حد سياق 200,000 رمز وحد إخراج 32,000 رمز.
- وحد إدخال غير محدّد.

ويتعرّف OpenCode على `text` و`regex` و`lark`. وتُتجاهل أسماء الصيغ الأخرى من models.dev دون إسقاط النموذج أو أدواته. وإذا رفض وسيط أمام نموذج كتالوج أدوات النص الحر، فاضبط `capabilities.freeform` على `[]` في ذلك النموذج.

هذه افتراضات احتياطية، لا قدرات مكتشفة. فاضبط قيم `capabilities` و`limit` الدقيقة عند معرفتها؛
والقيم الصريحة تحل محل الاحتياطية. وأضف `disabled: true` لإخفاء نموذج من الكتالوج المتاح:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## الاستدلال

لنموذج متوافق مع OpenAI يبثّ الاستدلال في حقل مخصّص لرسالة المساعد، اضبط
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

ويتعرّف OpenCode على `reasoning` و`reasoning_content` و`reasoning_text`، ويقبل أيضًا سلسلة أخرى خاصة
بالمزوّد. ويقرأ الاستدلال المبثوث من ذلك الحقل ويعيد الحقل عند إرسال رسائل مساعد سابقة إلى
النموذج. راجع [التوافق](#compatibility) لحقل `requireReasoning` ذي الصلة.

## التخزين المؤقت للمطالبات

يضع OpenCode تلقائيًا علامات تحدّد حدود التخزين المؤقت للمطالبات على المسارات المعروفة بحاجتها إليها، مثل مسارات Anthropic. وعندما
تُقدَّم نماذج Claude عبر وسيط متوافق مع OpenAI مثل LiteLLM، لا يستطيع OpenCode تمييز حاجتها إلى
علامات `cache_control` على نمط Anthropic. اضبط `compatibility.cacheFormat` على نماذج Claude تلك:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

حينها يعلّم OpenCode آخر تعريف أداة ومطالبة النظام وأحدث رسالة بـ
`cache_control: { "type": "ephemeral" }`، الذي يستخدم عمر الذاكرة المؤقتة الافتراضي لنقطة النهاية، خمس دقائق. واستخدم `"alibaba"`
لنماذج Alibaba Model Studio، التي تقبل العلامات نفسها لكنها تتجاهلها في تعريفات الأدوات. واضبط
`compatibility.cacheFormat` على المزوّد بدلًا من ذلك عندما تقبل كل نماذجه الصيغة نفسها. راجع
[التوافق](#compatibility) للحقول الأخرى.

### عمر الذاكرة المؤقتة

لا يرسل OpenCode مدة صلاحية الذاكرة المؤقتة افتراضيًا، فيستخدم كل مزوّد مدته الافتراضية. وهي خمس دقائق مثلًا لدى
Anthropic. اضبط `settings.cache.ttl` للمزوّد أو النموذج لطلب مدة أخرى. وتكون الأولوية لإعداد النموذج على
إعداد المزوّد.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

يأخذ `ttl` عددًا ووحدة: `ms` أو `s` أو `m` أو `h` أو `d`، مثل `"5m"` أو `"1h"` أو `"24h"`. ويرسله OpenCode كما
أُعطي، فاستخدم قيمة يقبلها المزوّد:

| API | أين يذهب العمر |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` على كل علامة ذاكرة مؤقتة. وتقبل Anthropic القيمتين `"5m"` و`"1h"`. |
| Bedrock Converse | `ttl` على كل `cachePoint`. وتتجاهل نماذج Claude الأقدم التي تخزّن خمس دقائق فقط القيمة `"1h"`. |
| OpenAI Chat and Responses | تُوضع `"24h"` في `prompt_cache_retention`، وتُوضع القيم الأخرى في `prompt_cache_options.ttl`. |

ويتجاهله المزوّدون الذين يخزّنون تلقائيًا دون علامات، مثل Gemini. وعمر أطول يكلّف عادةً أكثر عند
الكتابة: تتقاضى Anthropic ما يعادل 2× سعر الإدخال عند الكتابة إلى ذاكرة مؤقتة تدوم ساعة، و 1.25× سعر الإدخال لذاكرة تدوم خمس دقائق.

ويمكن لـ[التسخين](/warming) استخدام العمر لتوقيت طلباته بـ`interval: "auto"`.

## التوافق

يصف `compatibility` خصوصيات طلبات واستجابات API التي يُقدَّم عبرها النموذج، مثل الحقل الذي يحمل
الاستدلال أو ما إذا كانت نقطة النهاية تقبل `prompt_cache_key`. ويُقدَّم كل نموذج عبر API واحدة، ولا
يسري أي حقل إلا عندما تقرأه تلك الواجهة. وتُتجاهل الحقول الأخرى.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

وينطبق `compatibility` الخاص بالمزوّد على كل نماذج ذلك المزوّد. ويتجاوزه `compatibility` الخاص بالنموذج حقلًا
بحقل: فيبدأ OpenCode من القيم التي ينشرها [models.dev](https://models.dev) لواجهة النموذج (`reasoningField`
و`maxTokensField` و`mediaInput` و`supportsEffortUpdates` و`supportsSystemUpdates` عندما يعلّم models.dev
أن الواجهة تدعمها)، ثم يطبّق إعداد النموذج. وتحتفظ الحقول غير المضبوطة بالافتراضي المدمج في حزمة
المزوّد أو بكشفها. و`supportsThinkingBlockBinding` و`supportsEffortUpdates` و`supportsSystemUpdates`
للنموذج وحده.

| الحقل | ما يفعله | من يقرأه | القيم والافتراضي |
| --- | --- | --- | --- |
| `reasoningField` | حقل رسالة المساعد الذي يحمل الاستدلال. ويُفحص أولًا عند قراءة الاستدلال المبثوث، ويُستخدم عند إرسال الاستدلال السابق مجددًا. | OpenAI Chat | أي اسم حقل عدا `role` أو `content` أو `refusal` أو `tool_calls`. وعند عدم ضبطه يُستخدم الحقل الظاهر في البثّ، وإلا فـ`reasoning_content`. |
| `requireReasoning` | يرسل حقل الاستدلال في كل رسالة مساعد سابقة، كسلسلة فارغة عند عدم وجود استدلال. | OpenAI Chat | `true` أو `false`. والافتراضي `true` عند ضبط `reasoningField` أو عندما يكون النموذج DeepSeek، وإلا فـ`false`. |
| `maxTokensField` | حقل الجسم الذي يحمل حد رموز الإخراج. | OpenAI Chat | `max_completion_tokens` أو `max_tokens`. وعند عدم ضبطه يُكتشف `max_tokens` للمزوّدين الذين يحتاجونه، مثل DeepSeek وMoonshot وTogether AI وZ.AI وCerebras، وإلا فـ`max_completion_tokens`. |
| `requireFinishReason` | يعامل البثّ الذي ينتهي دون `finish_reason` كخطأ استجابة غير مكتملة. والقيمة `false` تقبله كمنتهٍ. | OpenAI Chat | `true` أو `false`. والافتراضي `true`. |
| `requireAssistantAfterTool` | يُدرج رسالة مساعد بين نتيجة أداة ورسالة المستخدم التالية، لنقاط النهاية التي ترفض هذا الترتيب. | OpenAI Chat | `true` أو `false`. والافتراضي `true` لمعرّفات نماذج عائلة Mistral، وإلا فـ`false`. |
| `supportsPromptCacheKey` | هل تقبل نقطة النهاية حقل الجسم `prompt_cache_key`. | OpenAI Chat، OpenAI Responses، Mistral | `true` أو `false`. لا يرسل OpenAI Chat المفتاح إلا عندما تكون القيمة `true`، وهي القيمة التي تضبطها بعض حزم المزوّدين افتراضيًا. وترسله واجهات API الأخرى ما لم تكن القيمة `false`. |
| `streamUsage` | يطلب استخدام الرموز في البثّ عبر `stream_options.include_usage`. | OpenAI Chat | `true` أو `false`. والافتراضي `true`. |
| `cacheFormat` | صيغة علامات التخزين المؤقت للمطالبات التي تقبلها نقطة النهاية. وتتجاوز وضع نقاط التوقف التلقائي لدى المزوّد. والقيمة `alibaba` تتخطى تعريفات الأدوات. | كل واجهة API تستخدم علامات التخزين المؤقت للمطالبات، بما فيها OpenAI Chat وAnthropic Messages وBedrock Converse | `anthropic` أو `alibaba`. وعند عدم ضبطه يُستخدم افتراضي المزوّد. راجع [التخزين المؤقت للمطالبات](#prompt-caching). |
| `supportsThinkingBlockBinding` | يطلب من API إسقاط كتل التفكير التي تغيّر سياقها السابق بدلًا من رفض الطلب. | Anthropic Messages، Bedrock Converse | `true` أو `false`. وعند عدم ضبطه يُكتشف Claude 5.1 وما بعده. |
| `supportsEffortUpdates` | يرسل تغييرات جهد الاستدلال كتحديثات لكل رسالة، مما يحافظ على التخزين المؤقت للمطالبات. وإلا يتغيّر الجهد للطلب كله. | Anthropic Messages، OpenAI Responses | `true` أو `false`. وعند عدم ضبطه يُكتشف Claude Opus 5 وClaude 5.1 وما بعدهما وGPT-6 وما بعده. |
| `supportsSystemUpdates` | يرسل رسائل النظام المضافة في منتصف المحادثة كرسائل نظام أصلية. وإلا تُلفّ كنص في دور المستخدم التالي. | Anthropic Messages | `true` أو `false`. وعند عدم ضبطه يُكتشف Claude Opus 4.8 وClaude 5 وما بعدهما. |
| `mediaInput` | أين تذهب الصور والوسائط الأخرى في طلب قرار. | System One | `assets` (صور يُشار إليها من الحالة)، أو `state` (مضمّنة في الحالة)، أو `root` (قوائم `images` و`audio` و`videos` في المستوى الأعلى). وعند عدم ضبطه يُستخدم افتراضي المزوّد. |

## المحلية

يكتشف OpenCode تلقائيًا نماذج Ollama وLM Studio وvLLM على عناوينها المحلية الافتراضية. ويمكنك أيضًا
ضبط أي خادم متوافق مع OpenAI يدويًا.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

مع استماع Ollama على `http://127.0.0.1:11434`، اختر نموذجًا مكتشفًا بمعرّف المزوّد `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

ويحدّث OpenCode الجرد في الخلفية ويقرأ قدرات السياق والرؤية واستخدام الأدوات من Ollama.
وتُستبعد النماذج المخصّصة للتضمين وحدها.

ولمضيف أو منفذ آخر، اضبط عنوان URL المتوافق مع OpenAI في Ollama. ولا يزال الاكتشاف يستخدم Ollama API الأصلية على بادئة
المسار نفسها:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- أغفل `apiKey` عندما لا تتطلب نقطة النهاية مصادقة bearer.
- وعطّل الاكتشاف بـ`"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

مع خادم LM Studio غير الموثّق على `http://127.0.0.1:1234`، اختر نموذجًا مكتشفًا بمعرّف المزوّد
`lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

ويحدّث OpenCode الجرد في الخلفية ويقرأ قدرات السياق والرؤية واستخدام الأدوات من LM Studio.
وتُستبعد نماذج التضمين.

ولمضيف أو منفذ آخر، اضبط عنوان URL المتوافق مع OpenAI. ولا تزال النماذج تُكتشف تلقائيًا:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- أغفل `apiKey` عندما تكون مصادقة LM Studio معطّلة.
- وعطّل الاكتشاف بـ`"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

مع استماع vLLM على `http://127.0.0.1:8000`، اختر نموذجًا مكتشفًا بمعرّف المزوّد `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

ويفحص OpenCode `/health`، ويحدّث `/v1/models` في الخلفية، ويستخدم `max_model_len` المفاد كحد
للسياق، ويضم بطاقات النماذج المملوكة لـ`vllm` وحدها.

تُعرَض النماذج التي يعثر عليها OpenCode على أنها تدعم إدخال النص وإخراجه، دون الرؤية أو الأدوات. ويمكن تفعيل استدعاء الأدوات في vLLM بخيارات الخادم
مثل `--enable-auto-tool-choice` و`--tool-call-parser`، لكن عملية الاكتشاف لا ترصد هذه الخيارات.

ولنقطة نهاية أخرى أو خادم موثّق، اضبط عنوان URL المتوافق مع OpenAI:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- أغفل `apiKey` عندما تكون المصادقة معطّلة.
- وعطّل الاكتشاف بـ`"plugins": ["-opencode.provider.vllm"]`.
- الوسائط ذات بادئة المسار مدعومة. مثلًا، يفحص `https://example.com/vllm/v1` المسار `/vllm/health` ويكتشف
  `/vllm/v1/models`.

### المتوافق

ولخادم آخر متوافق مع OpenAI، عرّف حزمة مزوّده ونقطة نهايته ونموذجًا واحدًا على الأقل:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

استخدم اسم النموذج الحقيقي في الخادم وحدوده وأنواع إدخاله وإخراجه ودعمه للأدوات. ولا يستطيع OpenCode كشف ما إذا كانت
قيم النموذج المخصّص الاحتياطية دقيقة. وإذا كانت نقطة النهاية تشترط مفتاحًا، فأضف `apiKey` إلى `settings` باستبدال
متغيّر بيئة مثل `"apiKey": "{env:LOCAL_API_KEY}"`؛ ولا تثبّت الأسرار.

## المراجع

تستخدم منتقيات النماذج `provider/model` مع `#variant` اختياريًا:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| الجزء       | القاعدة                                                       |
| ---------- | ---------------------------------------------------------- |
| المزوّد   | ينتهي عند أول `/`؛ ولا يمكن أن يحتوي `/` أو `#`.          |
| النموذج   | قد يحتوي على `/` إضافية؛ ولا يمكن أن يحتوي `#`.            |
| الصيغة    | يأتي بعد `#` عند وجوده.                                    |
| حالة الأحرف | معرّفات المزوّد والنموذج حساسة لحالة الأحرف.               |

استخدم معرّفات الكتالوج لا أسماء عرض المزوّدين. وتقبل حقول `model` في الجذر والوكيل والأمر الصيغة النصية أعلاه
أو كائنًا موسّعًا:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}
```

والصيغة الموسّعة مفيدة للإعداد المولّد أو البرمجي.

## تنبيهات

ضع هذه القواعد في الحسبان عند إعداد النماذج:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- كائن المنتقي يستخدم `model`؛ وإدخال كتالوج المزوّد يستخدم `modelID` للمعرّف المُرسل إلى المزوّد.
- رغم أن شكل الاختيار في الجذر يقبل متغيّرًا، فإن افتراضي الكتالوج في V2 لا يحتفظ به. فاختر المتغيّرات
  لجلسة أو تشغيل أو وكيل أو أمر بدلًا من ذلك.
- خيارات النموذج خاصة بكل مزوّد. وقد تتجاهلها حزمة مزوّد آخر أو ترفضها.
- بيانات الكتالوج وبيانات الاعتماد والإعداد محصورة بالموقع. فقد يكون نموذج متاح في مشروع غير
  متاح في آخر.
- يُعاد تحميل ملفات الإعدادات تلقائيًا في العادة. أما طلب النموذج الجاري فيحتفظ بالإعدادات التي بدأ
  بها.
