スナップショットを使うと、直近の会話とファイルの変更をまとめて元に戻せます。最近の作業を修正するのに使い、重要なものは Git のコミットやバックアップで保持してください。

## ワークフロー

修正したい応答の後で `/undo` を実行します。OpenCode はロールバックを仮適用して対象のファイルを復元し、取り消したプロンプトを入力欄に戻します。入力欄に戻ったプロンプトは編集できます。

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

編集したプロンプトを送信すると、仮適用したロールバックが確定します。送信前に `/redo` を実行すると、ロールバックをキャンセルし、会話とファイルを `/undo` の前の状態に戻せます。

```text
/redo
```

ターミナルにはデフォルトのショートカットもあります。

| 操作                                   | コマンド | ショートカット |
| -------------------------------------- | -------- | -------------- |
| 前のメッセージへのロールバックを仮適用     | `/undo`  | `<leader>u`    |
| 仮適用したロールバックをキャンセル        | `/redo`  | `<leader>r`    |

以前のメッセージを選んで **Revert** を選択すると、その時点までのロールバックを仮適用できます。

## 取得

モデルの各ステップで、OpenCode はモデル呼び出しの直前にスナップショットを、ステップが成功または失敗として記録されたときに別のスナップショットを取得しようとします。アシスタントメッセージには、それらのスナップショット間で変更されたパスが記録されます。

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

スナップショットを必ず取得できるとは限りません。どちらか一方でも利用できなければ、会話は続きますが、そのステップで変更されたファイルは復元できないことがあります。

## 対象範囲

スナップショットの対象は、Git のワークツリー内でセッションが使用しているディレクトリです。たとえば `packages/app` で開いたセッションでは、`packages/app` 以下の対象ファイルを記録し、リポジトリ内の他の場所への変更は記録しません。

| 内容                                             | 取得   | 例                                 |
| ------------------------------------------------ | ------ | ---------------------------------- |
| アクティブディレクトリ内の追跡ファイル           | はい   | `packages/app/src/app.tsx`         |
| 無視されていない未追跡ファイル（各 2 MiB まで）  | はい   | `packages/app/notes.txt`           |
| Git で無視されているファイル                     | いいえ | `packages/app/dist/app.js`         |
| 2 MiB を超える個々の未追跡ファイル               | いいえ | `packages/app/debug.log`           |
| アクティブディレクトリ外のファイル               | いいえ | `packages/server/src/index.ts`     |
| Git のメタデータやその他の副作用                 | いいえ | コミット、ブランチ、データベース、プロセス |

ファイルシステムのスナップショットには Git リポジトリが必要です。リポジトリの外では、`/undo` は会話履歴を元に戻せますが、ファイルは復元できません。

## 復元

ロールバックでは、会話中の選択した時点より後にアシスタントのステップで変更されたパスだけを復元します。各パスは、取り消す最初のステップの直前の状態に戻ります。対象のステップで作成されたファイルがその時点に存在しなければ、削除されます。

| タイムライン                 | `src/api.ts` | `src/new.ts` |
| ---------------------------- | ------------ | ------------ |
| 選択した境界                 | バージョン A | なし         |
| それ以降のアシスタントのステップ | バージョン B | 作成         |
| ロールバック後               | バージョン A | 削除         |

それらのステップに帰属しないパスはそのまま残されます。影響を受けたパスへの現在の編集は上書きされる可能性があるため、続行する前に復元された概要と `git diff` を確認してください。

```sh
git diff --stat
git diff
```

## 保存

OpenCode はスナップショットを、データディレクトリの下にある別の内部 Git オブジェクトデータベースにローカル保存します。スナップショットの取得は、コミットの作成、ブランチの移動、リポジトリのインデックスの意図的な変更を行いません。

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

スナップショットのオブジェクトには、追跡ファイルと対象の未追跡ファイルの完全な内容が含まれることがあります。OpenCode のデータディレクトリは機密性の高いローカルデータとして扱ってください。

## 設定

スナップショットはデフォルトで有効です。[設定](/config#snapshots)で `snapshots` を `false` にすると、以降のファイルシステムの取得を停止します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

スナップショットを無効にしても、すでに保存されたスナップショットは削除されません。会話のロールバックは引き続き利用できますが、取得されたファイルシステムの状態がないため、関連するファイルの変更は復元できません。

## 安全性

スナップショットは便利な機能であり、トランザクションやバックアップではありません。

- シェルコマンドは、サービス、プロセス、ネットワークリソース、データベース、Git の状態、無視された出力、アクティブディレクトリ外のファイルを変更することがあります。スナップショットの復元はそれらの影響を取り消しません。
- 取得に失敗した場合や、使用可能なスナップショットのペアが存在しない場合、中断または失敗した作業が変更を残すことがあります。
- 対象のパスを復元すると、現在の内容が上書きされます。仮適用したロールバックをキャンセルする場合も、仮適用後の編集内容が上書きされることがあります。
- OpenCode はセッションの実行中にロールバック操作を拒否しますが、外部のエディタやコマンドは取得と復元の間にも worktree を変更できます。
- ロールバックを確定すると、メッセージは現在の会話ビューから消えますが、永続的なセッション履歴や既存のスナップショットストレージからは削除されません。安全に消去するための機能ではありません。

変更のある worktree で `/undo` を使う前に、重要な作業をコミットするかバックアップしてください。
