---
title: "ウォーミング"
description: "プロンプトの合間に休止している間、セッションのプロバイダー側プロンプトキャッシュが失効しないよう、定期的にリクエストを送信します。"
---

セッションのウォーミングは、次のプロンプトまで間が空いてもプロバイダー側のプロンプトキャッシュなど、短時間で失効する状態を維持する機能です。定期的にモデルにリクエストを送信します。デフォルトでは無効です。

任意の [OpenCode 設定ファイル](/config)でウォーミングを有効にします。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}
```

この設定では、OpenCode は最近アクティブだったセッションのプロンプトキャッシュが失効する直前にウォーミングします。モデルの [`cache.ttl`](/models#cache-lifetime) の 90%、またはモデルに設定がない場合は 4 分ごとです。ウォーミングでない最新のリクエストから 30 分経過するまで続きます。

## オプション

オブジェクト形式を使うと、ウォーミングのプロンプト、アイドル間隔、アクティブウィンドウを変更できます。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour",
  },
}
```

| フィールド | デフォルト             | 目的                                                                                                                         |
| ---------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `prompt`   | キープアライブの指示   | 各ウォーミングリクエストに一時的なユーザーメッセージとして追加されます。デフォルトでは、作業を行わず、ツールを使わず、`OK` とだけ返信するようモデルに求めます。 |
| `interval` | `"auto"`               | 次のウォーミングリクエストまでのアイドル時間。`"auto"` はモデルの `cache.ttl` の 90%、設定がない場合は 4 分を使用します。      |
| `duration` | `"30 minutes"`         | ウォーミングでない最新のモデルリクエストから測ったウォーミングウィンドウ。                                                   |

省略したオブジェクトのフィールドはデフォルトのままです。たとえば、次の設定は間隔だけを変更します。

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "2 minutes",
  },
}
```

## 自動の間隔

デフォルトでは `interval` は `"auto"` で、各モデルのプロンプトキャッシュが失効する直前にウォーミングします。OpenCode はモデルの [`cache.ttl`](/models#cache-lifetime) 設定の 90% を使用するため、`"5m"` のキャッシュは 4.5 分ごとにウォーミングされます。`cache.ttl` のないモデルは 4 分ごとにウォーミングされます。

```jsonc title="opencode.jsonc"
{
  "warming": { "duration": "2 hours" },
  "providers": {
    "anthropic": { "settings": { "cache": { "ttl": "1h" } } },
  },
}
```

`duration` より長く続くキャッシュ（30 分のデフォルトに対する `"1h"` など）は、ウォーミングウィンドウより長く残るためウォーミングされません。OpenCode はこれをセッションごとに 1 回ログに記録します。ウォーミングするには `duration` を増やしてください。

## プロバイダーとモデルごと

プロバイダーまたはモデルで `settings.cache.warming` を設定すると、そのセッションだけをウォーミングしたり、独自のタイミングを与えたりできます。`prompt` を除き、トップレベルの `warming` と同じ値を受け付け、それを上書きします。モデルの設定はプロバイダーの設定を上書きします。

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "5m", "warming": true } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "warming": false } } },
      },
    },
  },
}
```

この例では、Anthropic のセッションは Claude Haiku 5.5 を除いて 4.5 分ごとにウォーミングされ、他のプロバイダーはウォーミングされません。オブジェクト形式で省略したフィールドはトップレベルの `warming`、次にデフォルトから取得されます。無効な設定は警告をログに記録し、トップレベルの `warming` にフォールバックします。

## 期間

`interval` と `duration` には時間の長さを表す文字列を指定します。文字列を変換した結果はどちらも 0 より大きい有限の値であり、かつ `interval` は `duration` より短い必要があります。条件を満たさない場合、OpenCode はウォーミングをスキップして警告をログに記録します。

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "30 seconds",
    "duration": "1 hour",
  },
}
```

## タイミング

ウォーミングは、トップレベルのセッションでウォーミングでないモデルリクエストの後に始まります。サブエージェントのセッションはウォーミングされません。各間隔は、最新のリクエストまたはウォーミングリクエストが送信された時点から数え、レスポンスが完了した時点からは数えません。プロバイダーのキャッシュの有効期間は、リクエストが到達した時点で始まるためです。ウォーミングリクエストはアクティブウィンドウを延長しません。

```text
00:00  normal model request sent
00:01  response finishes
00:04  warming request
00:08  warming request
00:30  warming stops
```

コンパクションを含む、ウォーミングでない新しいモデルのアクティビティは、両方のタイマーをリセットします。期間以上の明示的な間隔は警告とともに拒否され、それほど長い `"auto"` の間隔は、キャッシュがウィンドウより長く残るためウォーミングをスキップします。

```text
00:00  normal model request
00:20  normal model request; window restarts
00:24  warming request
00:50  warming stops
```

OpenCode は、コンパクションを含むモデルリクエストの実行中にウォーミングリクエストを送信しません。間隔が来たときにまだ実行中の場合、ウォーミングは完了を待ち、そのリクエストのキャッシュが失効していなければすぐに送信します。失効している場合は、次の通常のリクエストまでウォーミングを停止します。

```text
00:00  normal model request sent
00:04  interval due; request still running
00:04:30  response finishes; warming request
00:08:30  warming request
```

## リクエスト

ウォーミングリクエストは、セッションの現在のモデル、エージェント、指示、会話のコンテキストを使用します。OpenCode は設定されたプロンプトを一時的に追加し、1 回モデルを呼び出して、レスポンスを破棄します。

```text
[current session context]
[transient user message: keep-alive prompt]
→ one model response, discarded
```

このリクエストは入力を受け付けず、履歴にメッセージを追加せず、永続的なセッション状態も変更しません。OpenCode はローカルツールの呼び出しを実行せず、ツールループも続行しません。デフォルトのプロンプトでも、ツールを使わないようモデルに指示します。

## 失敗

ウォーミングの失敗は、セッションを失敗させたり変更したりせずにログに記録されます。OpenCode は次の間隔まで待ってから再試行し、元のアクティブウィンドウのカウントダウンは続きます。

```text
00:04  warming request fails; session is unchanged
00:08  next warming attempt
```

ウォーミングリクエストでキャッシュミスが起きた場合（キャッシュへの書き込み量より読み取り量が少ない場合）、そのセッションで次の通常のリクエストがあるまでウォーミングを停止します。キャッシュ使用量を報告しないプロバイダーでは、キャッシュミスとは判定しません。

```text
00:04  warming request misses the cache; warming stops
00:10  normal model request; warming resumes
00:14  warming request
```

## コスト

ウォーミングリクエストは実際のプロバイダーリクエストです。トークンを消費し、コストがかかり、レート制限に計上され、他のモデルリクエストと同様に失敗することがあります。

- 間隔を短くするとリクエスト量が増えます。
- 期間を長くするとウォーミングリクエストが増えます。
- プロバイダー側の利点が増加する使用量に見合う場合にのみ、ウォーミングを有効にしてください。

たとえば、`cache.ttl` のないモデルでは、デフォルトで 1 回の途切れない 30 分のウィンドウ中に最大 7 回のウォーミングを試行できます。4、8、12、16、20、24、28 分の時点です。

## 無効化

明示的に無効にするには `warming` を `false` に設定します。フィールドを省略した場合もウォーミングは無効のままです。

```jsonc title="opencode.jsonc"
{
  "warming": false,
}
```
