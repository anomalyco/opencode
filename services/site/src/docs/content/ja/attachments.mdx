## 添付

ローカルファイルを添付し、プロンプトでそれを使うよう OpenCode に依頼します。デスクトップまたは Web クライアントでは、**Attach file** を選ぶか、ファイルを貼り付けるか、プロンプトにドラッグします。

```text
Summarize the attached README.md and list the required setup steps.
```

デスクトップのファイル選択では、合計で最大 20 MiB まで選択できます。他のインターフェースでは、より低いクライアント側の制限が適用される場合があります。

<Callout type="warning">
  画像を添付する前に、画像入力に対応したモデルを選んでください。OpenCode は対応する画像をプロバイダーに渡せますが、形式、寸法、ファイル数、ファイルサイズには、プロバイダーとモデルそれぞれの制限が適用されます。テキスト専用のモデルはリクエストを拒否することがあります。
</Callout>

## 構文

V2 のプロンプトとコマンドの入力では、添付を `uri` と、任意の `name` および `description` で記述します。

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

サーバーから利用できるファイルまたはディレクトリには、絶対 `file:` URL を使用します。テキストファイルでは、正の `start` と `end` パラメーターで 1 始まりの行を選択します。

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

コンテンツをインラインで送信するには `data:` URL を使用します。

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

HTTP と HTTPS の添付 URL には対応していません。プログラムによるプロンプトの送信については、生成された [API リファレンス](/api)を参照してください。

## 形式

現在の V2 のセッションでは、次の種類の添付データがモデルに渡されます。

| 入力                    | モデルが受け取るもの                                     | 例                 |
| ----------------------- | -------------------------------------------------------- | ------------------ |
| UTF-8 のテキストファイル | ファイル名とデコードされたテキスト                       | `README.md`        |
| ディレクトリ            | 直下のファイルとディレクトリの非再帰的な一覧             | `file:///home/me/` |
| PNG、JPEG、GIF、WebP    | 画像メディア                                             | `diagram.png`      |
| PDF                     | ドキュメントメディア                                     | `report.pdf`       |

PDF には PDF 入力に対応したモデルが必要です。モデルが添付の種類に対応していない場合、OpenCode は代わりに短い注記を送信します。

SVG はテキストとして扱われます。AVIF、BMP、音声、動画、その他のバイナリのプロンプト添付は、モデルへのリクエストに含まれません。サポートされていないバイナリは、先にテキストか対応する画像に変換してください。たとえば、BMP 画像は添付する前に PNG に変換します。

OpenCode はプロンプトを受け付ける前に添付を 1 件ずつ読み取ります。無効な URL、読み取れないパス、ファイルでもディレクトリでもないパス、デコード後に 20 MiB を超える添付は拒否します。メディアタイプはバイト列から判定するため、ファイル名や `data:` URL のメディアタイプを変えても、未対応のバイナリはモデルに渡されません。

## 画像

画像の正規化は `opencode.json` または `opencode.jsonc` で設定します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

すべてのフィールドは任意です。

| フィールド         | デフォルト | 動作                                                                     |
| ------------------ | ---------- | ------------------------------------------------------------------------ |
| `auto_resize`      | `true`     | 設定された上限を超える画像をリサイズします。`false` の場合は画像を拒否します。 |
| `max_width`        | `2000`     | ピクセル単位の最大幅。正の整数である必要があります。                     |
| `max_height`       | `2000`     | ピクセル単位の最大高さ。正の整数である必要があります。                   |
| `max_base64_bytes` | `5242880`  | Base64 でエンコードされた画像の最大バイト数。正の整数である必要があります。 |

たとえば、次の設定は幅 1200 ピクセルを超える画像をリサイズせずに拒否します。

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

これらの設定は、プロンプトに添付された対応画像と、組み込みの `read` ツールが返す画像の両方に適用されます。

## 処理

`read` ツールは PNG、JPEG、GIF、WebP を内容から認識し、最大 20 MiB のソース画像データを読み取ります。幅、高さ、Base64 の長さを設定された画像の上限と照合します。

`auto_resize: true` の場合、OpenCode はアスペクト比を保って寸法の上限まで縮小します。その後、Base64 の上限を満たすまで、より小さな PNG と JPEG のエンコーディングを順に試すため、出力のメディアタイプが変わることがあります。

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

どのエンコード方法でも上限に収まらなければ、処理は失敗します。`auto_resize: false` の場合、いずれかの上限を超えた画像は変更せず、エラーにします。デコードできない場合もエラーになります。

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

画像をリサイズできる環境でない場合、OpenCode は元の画像をそのまま渡します。したがって、画像の設定は処理上の制限にすぎず、アップロード制限やセキュリティ境界としては機能しません。

## 制限

| 制限                             | 値または動作                                                   | 例                                                  |
| -------------------------------- | -------------------------------------------------------------- | --------------------------------------------------- |
| 直接の添付                       | 項目ごとにデコード後 20 MiB。クライアントがより低い制限を課す場合があります | 12 MiB のファイル 2 つは項目ごとの制限を満たします |
| デスクトップの選択               | 合計 20 MiB                                                    | 12 MiB のファイル 2 つは選択の制限を超えます        |
| `max_base64_bytes`               | エンコードされた Base64 のみで、`data:` URL 全体は含みません  | `SGVsbG8=` は 8 バイトとして数えます                |
| プロバイダーの画像の制限         | OpenCode の処理後に適用されます                                | 受け入れられた画像をプロバイダーが拒否することがあります |
| テキスト添付のモデル対応         | マルチモーダルモデルは不要です                                 | `notes.txt` はプロンプトのテキストとして挿入されます |
| `read` のテキストの制限          | 別のページ送りと切り捨ての制限を使用します                     | 大きなログをページ単位で読み取ります                |

クライアントがファイルを受け付けても、その内容がモデルに届くとは限りません。添付はモデルから見える形式である必要があり、OpenCode とプロバイダーの両方の制限を満たす必要があります。
