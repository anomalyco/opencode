OpenCode Console は、OpenCode チームがテストと検証を行ったモデルの一覧を提供します。サインインしてクレジットを追加し、API キーを取得すると、OpenCode や他のコーディングエージェントで使用できます。

Console は OpenCode の他のプロバイダーと同じように動作します。**完全に任意**であり、他のプロバイダーに替えることもできます。使用量が含まれるサブスクリプションについては、[OpenCode Go](/console/go) を参照してください。

## 仕組み

1. [Console](https://opencode.ai/console) にサインインし、請求先情報を登録してクレジットを追加したら、API キーをコピーします。
2. TUI で `/connect` を実行し、OpenCode の従量課金プロバイダーを選択して、API キーを貼り付けます。

   ```text
   /connect
   ```

3. `/models` を実行して利用可能なモデルを表示し、1 つ選択します。

   ```text
   /models
   ```

料金はリクエストごとに請求され、アカウントにクレジットを追加できます。

## エンドポイント

次の API エンドポイントからモデルに直接アクセスすることもできます。無料枠のチャットモデルは OpenCode が必要です。他のクライアントからは、有料モデルまたは [Go](/console/go) を使用してください。

各モデルはネイティブ API とともに掲載されていますが、すべてのテキストモデルは Console が変換する他の API からも利用できます。一覧は[ベース URL](/console/harnesses#base-urls)を参照してください。

### モデル一覧

利用可能なモデルの完全な一覧とメタデータは、models エンドポイントから取得できます。

```bash
curl https://opencode.ai/inference/v1/models
```

レスポンスのすべてのフィールドと、ワークスペースが接続したプロバイダーも含む Console の一覧については、[モデル一覧 API](/console/api/models)を参照してください。

### Jev

Jev は、高速で構造化された意思決定のための TypeSafe AI の System One モデルです。テキストを生成する代わりに、`state` を型付きの質問に対して評価し、コードでそのまま使える値と確率を返します。はい / いいえ（`noul`）、多肢選択（`choice`）、ルーブリック（`score`）の質問に対応しています。

OpenCode Console の API キーを使って、`https://opencode.ai/inference/systemone/v1/systemone` エンドポイントを使用します。次の例は、サポートリクエストが緊急かどうかを判定します。

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

1 つのリクエストで複数の質問ができます。Jev はそれらを並行して評価し、一致する質問 ID の下に各回答を返します。

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

期間限定の無料モデルを使うには `jev-1.13-free` を使用します。これは Jev 1.13 で動作します。質問の種類とレスポンスのフィールドの詳細については、[TypeSafe AI のドキュメント](https://docs.typesafe.ai/)を参照してください。

### GPT 6 Luna Decision と Gemini Decision 1

`gpt-6-luna-decision` と `gemini-decision-1` は、Jev と同じエンドポイントで同じ System One リクエストを受け付けます。画像、音声、動画、PDF は、チャット形式のパーツ（`image_url`、`input_audio`、`video_url`、`file`）として `state` に渡します。GPT 6 Luna Decision はテキストと画像を受け付け、Gemini Decision 1 は音声、動画、PDF も受け付けます。

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### 画像モデル

`gpt-image-2.5-sunburst`、`gemini-nano-banana-2.1`、`grok-imagine-image-2.0` は画像を生成および編集します。チャットモデルではないため、`/models` や models エンドポイントには表示されず、`opencode/<model-id>` でも選択できません。Console のキーを使ってネイティブ API で呼び出すか、`experimental.image_generate.model` を設定して（例：`opencode/gpt-image-2.5-sunburst`）、OpenCode の [`generate_image`](/tools#image-generate) ツールに画像モデルを使わせます。

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google はネイティブの `contents` と `generationConfig` を、xAI は `resolution` や `quality` などのネイティブオプションを使用します。OpenAI Images と xAI Images は `/images/edits` での編集も受け付けます。

### 埋め込みモデル

`text-embedding-3-small`、`qwen3-embedding-8b`、および上の表にあるその他の埋め込みモデルは、テキストをベクトルに変換します。OpenCode はチャットには使用しないため、`/models` には表示されず、無料枠にも含まれません。[Go](/console/go#embedding-models) には一部が含まれています。Console のキーを使って OpenAI の Embeddings API で呼び出します。

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` は文字列または文字列の配列を受け付けます。`data` は入力ごとに 1 つのベクトルを、同じ順序で返します。
- `dimensions` は、対応しているモデル（`text-embedding-3-small` など）でベクトルを短縮します。
- `encoding_format: "base64"` を指定すると、ベクトルが浮動小数点数ではなく base64 でエンコードされて返ります。
- 各入力は、モデルのコンテキストウィンドウに収まる必要があります。
- レスポンスは、他の推論リクエストと同様に `usage.cost` を報告します。[コスト](/console/api/inference#cost)を参照してください。

異なるモデルで生成したベクトル同士は比較できないため、ドキュメントとクエリは同じモデルでベクトル化してください。[接続したプロバイダー](/console/api/providers#endpoints)は、独自の埋め込みモデルを `/embeddings` で提供します。

[ワークスペース](/console/workspaces)から、Console のモデルをチームと共有できます。オーナーと管理者は、[メンバーを招待](/console/members)し、**Models** タブで有効にするモデルを選択し、[予算](/console/budgets)を設定し、[自分のプロバイダー](/console/providers)を接続できます。

## 背景

利用できるモデルは多数ありますが、コーディングエージェントとしてうまく機能するのはごく一部です。プロバイダーによって構成、性能、品質も異なるため、OpenRouter などのゲートウェイ経由でアクセスしたモデルは動作が異なる場合があります。

<Callout type="tip">OpenCode でうまく機能するモデルとプロバイダーを厳選してテストしました。</Callout>

このカタログを作るために、私たちは次のことを行いました。

1. 厳選したモデルをテストし、最適な運用方法について各チームと話し合いました。
2. プロバイダーと協力して、モデルが正しく提供されていることを確認しました。
3. モデルとプロバイダーの各組み合わせをベンチマークし、自信を持っておすすめできる一覧を作成しました。

Console は、これらのモデルにアクセスできる AI ゲートウェイです。

## 目標

Console は次の目的で作りました。

1. コーディングエージェント向けの最良のモデルとプロバイダーを**ベンチマーク**する。
2. 性能を落とすことなく、安価なプロバイダーにルーティングすることもなく、**最高品質**の選択肢を提供する。
3. 原価で販売して**値下げ**を還元し、上乗せは手数料の補填のみにとどめる。
4. **ロックインをなくす**。Console は任意のコーディングエージェントで使え、OpenCode では他のプロバイダーも使えます。
