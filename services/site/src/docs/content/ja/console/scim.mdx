---
title: "ディレクトリ同期"
description: "Okta、Microsoft Entra ID、その他の SCIM 2.0 ID プロバイダーから、ワークスペースのメンバーを自動的に追加・削除します。"
---

ディレクトリ同期（SCIM 2.0）は、ID プロバイダーでユーザーを割り当てるとワークスペースに追加し、割り当てを解除するとアクセスを削除します。ロールは引き続き Console で管理します。

```text
https://opencode.ai/console/scim/v2
```

## 始める前に

- ワークスペースの [SSO](/console/sso) を設定します。
- ユーザーがサインインに使うすべてのメールドメインを[確認](/console/sso#verify-email-domains)します。ディレクトリ同期は確認済みドメインのユーザーだけを追加します。それ以外のユーザーは[メンバー](/console/members)から招待してください。

## トークンを作成する

ディレクトリ同期の設定と、そのトークンの作成・失効は、ワークスペースのオーナーだけが行えます。

1. **Settings › Security** を開き、**Directory sync** の下の **Set up** をクリックします。
2. **SCIM base URL** とトークンをコピーします。トークンは一度しか表示されないため、シークレットマネージャーに保存してください。

ID プロバイダーは、すべてのリクエストでトークンを送信します。

```text
Authorization: Bearer <token>
```

## ID プロバイダーを接続する

### Okta

1. **SCIM 2.0 Test App (Header Auth)** アプリを追加します。
2. ベース URL を設定し、**API Token** に `Bearer ` とトークンを続けて入力します。
3. **Create Users**、**Update User Attributes**、**Deactivate Users** を有効にします。**Import Groups** とパスワード同期はオフのままにします。

### Microsoft Entra ID

1. エンタープライズアプリで **Provisioning** を開き、モードを **Automatic** に設定します。
2. ベース URL を **Tenant URL** に、トークンを **Secret Token** に入力します。
3. ユーザーとグループを割り当て、プロビジョニングを開始します。

### その他のプロバイダー

ヘッダートークン認証を使用する SCIM 2.0 アプリを、ベース URL に向けて使用します。Console は `/Users` と `/Groups` エンドポイントに対応しています。

まずテスト用のユーザーを 1 人割り当てます。最初のリクエストの後、**Directory sync** に **Connected to your identity provider** と表示されます。

## 同期される内容

| ID プロバイダーでの操作      | Console での動作                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------- |
| ユーザーを割り当てる         | **Member** として追加されます。既存のメンバーはロールを保持します。               |
| 名前を更新する               | プロフィールが更新されます。                                                      |
| 割り当ての解除または無効化   | アクセスが停止され、**Deactivated** と表示されます。そのユーザーが作成した API キーは失効します。 |
| 再割り当て                   | アクセスが復元されます。失効したキーは失効したままです。                          |
| 削除                         | ワークスペースから削除されます。アカウントと他のワークスペースには影響しません。  |

- ディレクトリ同期によってロールとメールアドレスは変更されません。
- 最後のオーナーは無効化も削除もできません。
- [Go](/console/go) のサブスクリプションがあるワークスペースでは、ディレクトリ同期でメンバーを追加できません。

## グループ

ID プロバイダーからグループを同期すると、所属メンバーにタグを付けられます。たとえば Okta の **Push Groups** や Entra のグループ割り当てを使います。グループを同期する前に、ユーザーを割り当ててください。

```text
Platform Admins  →  platform-admins
```

メンバーには、所属するグループの名前に基づくタグが付きます。**Settings › Security › Group tags** では、タグの名前を変更したり、複数のグループに同じタグを割り当てたり、特定のグループのメンバーへのタグ付けを止めたりできます。メンバーがグループから外れると、そのタグも外れます。

## トークンをローテーションする

1. **New token** をクリックし、ID プロバイダーに設定します。
2. 新しいトークンに最終使用日時が表示されるまで待ちます。
3. 古いトークンを失効させます。

トークンを失効させると以降の更新は停止しますが、既存のメンバーは変更されません。SSO 接続を削除すると、すべてのトークンが失効します。

## SSO とディレクトリ同期

ワークスペースがトークンを発行すると、SSO は[メンバーを自動追加](/console/sso#automatic-membership)しなくなります。トークンが後で失効しても、誰が所属するかはディレクトリが決定します。
