Console API を使うと、スクリプトや連携機能からモデルを呼び出したり、使用量をエクスポートしたりできます。すべてのリクエストは API キーで認証します。

```bash
curl --fail-with-body "https://opencode.ai/inference/v1/models" \
  --header "Authorization: Bearer oc_sk_..."
```

| API                                       | エンドポイント                                    |
| ----------------------------------------- | ------------------------------------------------- |
| [モデル](/console/api/models)             | `https://opencode.ai/console/api/v1/models`       |
| [推論](/console/api/inference)            | `https://opencode.ai/inference/...`               |
| [プロバイダー](/console/api/providers)    | `https://opencode.ai/inference/custom/...`        |
| [使用量のエクスポート](/console/api/usage-export) | `https://opencode.ai/console/api/v2/usage/export` |

## API キー

ワークスペースのメンバーとサービスアカウントの両方が API キーを持てます。キーはベアラートークンとして送信します。

```text
Authorization: Bearer oc_sk_...
```

|                  | パーソナル API キー                                    | サービスアカウントキー                                                   |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| 作成者           | 各メンバー（自分の分）                                 | オーナーと管理者                                                        |
| 作成場所         | **Account › Personal API keys**                        | **Settings › Service accounts**                                          |
| 動作する主体     | 作成したメンバー                                       | サービスアカウント                                                      |
| 使用量の計上先   | メンバーの[予算](/console/budgets#member-budgets)      | サービスアカウントの[予算](/console/budgets#service-account-budgets)     |
| 用途             | 自分のスクリプトと [harness](/console/harnesses)       | CI、共有マシン、連携機能                                                |

- 各キーは、作成時に選択した 1 つのワークスペースで機能します。ワークスペースのヘッダーは不要です。
- 完全なキーは作成直後に一度だけ表示されます。その後は、Console にはプレフィックスだけが表示されます。
- **Expiration** は任意で、**Never**、**1 day**、**7 days**、**30 days**、**Custom**（1〜365 日）から選べます。期限切れのキーは更新できないため、新しいキーを作成してください。

## パーソナル API キー

パーソナル API キーを使った操作は、キーを作成した本人の操作として扱われます。本人のロール、[予算](/console/budgets#member-budgets)、モデルのルールが適用されます。

1. アカウントメニューから **Account** を開き、**Personal API keys** を探します。
2. **Add API key** をクリックします。
3. **Workspace**、**Key name**、任意の **Expiration** を選択します。オーナーと管理者は **Permissions** も選択します。
4. **Create** をクリックし、キーをコピーします。

```text
oc_sk_1a2b3c4d5e6f_...
```

キーは、あなたの現在のワークスペースへのアクセス権に従います。ロールが変わると、キーでできることも変わります。ワークスペースで [SSO](/console/sso#sso-enforcement) を強制している場合、キーはオーナーでない限り、有効な SSO セッションがある間だけ機能します。

## サービスアカウント

サービスアカウントは、独自の API キー、使用量、[予算](/console/budgets#service-account-budgets)を持つ、人間ではないワークスペースのメンバーです。自動化に使用すると、使用量が特定の個人に紐付きません。オーナーと管理者が管理します。

1. **Settings › Service accounts** を開き、**Add Service Account** をクリックして、名前を付けます（例：`CI Pipeline`）。
2. サービスアカウントを開き、**Add API Key** をクリックします。
3. **Key name**、任意の **Expiration**、**Permissions** を選択し、**Create** をクリックします。
4. キーをコピーします。

```bash
export SERVICE_API_KEY="oc_sk_..."
```

オーナーと管理者は、後からキーの操作メニューの **Edit…** で、サービスアカウントキーの名前を変更したり権限を変更したりできます。

## 権限

各キーには権限レベルがあり、作成時に **Permissions** で選択します。

| 権限           | 許可されること                                                                       |
| -------------- | ------------------------------------------------------------------------------------ |
| **All**        | メンバーまたはサービスアカウントができるすべてのこと（**This account's API keys** を除く）。 |
| **Restricted** | 選択したリソースのみ。                                                               |
| **Read only**  | すべてのリソースへの読み取りアクセス。モデルの一覧表示はできますが、呼び出しはできません。 |

キーは、その主体ができる以上のことは行えません。パーソナルキーはメンバーの現在のロールによって、サービスアカウントキーは[サービスアカウントができること](#limitations)によって上限が決まります。

### 制限付きキー

各リソースを **None**、**Read**、**Write** に設定します。**Write** には **Read** が含まれます。

| リソース                    | レベル                |
| --------------------------- | --------------------- |
| **Models**                  | **Read**、**Request** |
| **Usage**                   | **Read**              |
| **Budgets**                 | **Read**、**Write**   |
| **Members**                 | **Read**、**Write**   |
| **Providers**               | **Read**、**Write**   |
| **Billing**                 | **Read**、**Write**   |
| **Workspace settings**      | **Read**、**Write**   |
| **SSO**                     | **Read**              |
| **Service accounts**        | **Read**              |
| **This account's API keys** | **Write**             |

**Models › Read** はモデルを一覧表示し、**Models › Request** はさらに[推論](/console/api/inference) API と[プロバイダー](/console/api/providers) API を通じてモデルを呼び出します。たとえば、モデルを呼び出すだけのキーには次の設定が必要です。

```text
Permissions: Restricted
Models:      Request
```

スコープ付き権限より前に **Inference only** として作成されたキーは、**Models** が **Request** に設定された **Restricted** として表示されます。

### 誰が何を付与できるか

- **メンバー**は、モデルの一覧表示と呼び出しができるパーソナルキーだけを作成できます。Console は権限の選択肢の代わりに「This key can list and call models as you.」と表示します。
- **オーナーと管理者**は、自分のロールの範囲で、パーソナルキーに **All**、**Restricted**、**Read only** を付与できます。デフォルトは **Models** が **Request** の **Restricted** です。後でロールが下がると、キーの権限もそれに合わせて縮小されます。
- **サービスアカウントキー**のデフォルトは **All** です。権限はオーナーと管理者が選択します。

### 制限事項

一部の操作は、ユーザーが Console にサインインして行う必要があり、API キーによる操作はできません。API キーを使って別のキーを作成できる場合も、厳しく制限されています。

- API キーで SSO の設定を変更したり、ワークスペースを削除したりすることはできません。
- サービスアカウントキーは、**All** であっても、メンバーの招待、ロールの変更、メンバーの削除、請求の管理、ワークスペース設定の変更、モデルの管理、サービスアカウントの作成・削除はできません。
- **This account's API keys** はサービスアカウントキーでのみ利用でき、**All** には含まれません。この権限を持つキーは、自分のサービスアカウントのキーだけを作成・失効できます。新しいキーは **Restricted** である必要があり、作成元のキーの権限の範囲内で、**This account's API keys** を含めることはできません。
- パーソナルキーに **This account's API keys** を付与することはできず、API キーでパーソナル API キーを作成・失効することもできません。

キーの権限外のリクエストは HTTP `403` を返します。

## 失効

| キー                 | 失効できる人   | 場所                                                                              |
| -------------------- | -------------- | --------------------------------------------------------------------------------- |
| パーソナル API キー  | 所有するメンバー | **Account › Personal API keys** で **Revoke**                                    |
| パーソナル API キー  | オーナーと管理者 | **Settings › Members** のメンバーページの **API Keys**                           |
| サービスアカウントキー | オーナーと管理者 | **Settings › Service accounts** のサービスアカウントページの **API Keys**        |

キーは次の場合にも自動的に失効します。

- ワークスペースを退出する、削除される、または [SCIM](/console/scim) でプロビジョニングを解除されると、その人がワークスペースで作成したすべてのキー（サービスアカウントキーを含む）が失効します。同じサービスアカウントの他のキーは引き続き機能します。
- サービスアカウントを削除すると、そのすべてのキーが失効します。

失効したキーと期限切れのキーはすぐに機能しなくなり、HTTP `401` を返します。
