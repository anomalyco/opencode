---
title: "権限"
description: "アクションと、パスやコマンドなどのリソースを照合し、記述順に評価する allow、deny、ask のルールで、OpenCode のエージェントができることを制御します。"
---

権限は、エージェントがリソースに対して操作を実行できるかどうかを制御します。

## 設定

よくある設定は、シェルコマンドの実行前に確認し、日常的な Git の確認は許可し、プッシュは常にブロックするものです。次の順序付きルールを `opencode.jsonc` に追加します。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

最後に一致したルールが優先されるため、具体的な例外は広いルールの後に置きます。

<Callout type="warning">
  V1 ではフィールド名とアクション名が異なります。V2 では `permission`、`bash`、`task` の代わりに `permissions`、`shell`、`subagent` を使用します。
</Callout>

## ルール

各ルールには 3 つの文字列フィールドが必要です。

| フィールド | 意味                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| `action`   | ツールの権限アクション                                                   |
| `resource` | 使用される値（パス、コマンド、URL、クエリ、スキル ID、エージェント ID など） |
| `effect`   | `allow`、`deny`、`ask`                                                   |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| 効果    | 結果                     |
| ------- | ------------------------ |
| `allow` | 確認せずに続行           |
| `deny`  | 操作をブロック           |
| `ask`   | クライアントの判断を待つ |

一致するルールがない場合、OpenCode は `ask` を使用します。

## マッチング

アクションとリソースの照合には、値全体に対して働く単純なワイルドカードを使います。

| パターン | 一致                       |
| -------- | -------------------------- |
| `*`      | 0 文字以上（`/` を含む）   |
| `?`      | 正確に 1 文字              |
| その他   | その文字そのもの           |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

このパターンは正規化されたパス全体に一致します。バックスラッシュはスラッシュに正規化され、Windows では大文字と小文字を区別しません。

` *` で終わるシェルパターンは、引数なしのコマンドにも一致します。

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

これは `git status` と `git status --short` の両方に一致します。

OpenCode はルールを順番に結合し、最後に一致したものを使用します。優先度の低い設定が最初に読み込まれ、次にグローバルルール、最後にエージェントルールが追加されます。

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

操作は複数のリソースをチェックすることがあります（複数のファイルに触れるパッチなど）。いずれかが `deny` なら操作は拒否され、そうでなければいずれかが `ask` なら確認し、それもなければ操作は許可されます。

## アクション

V2 のアクション名は文字列であるため、プラグインがアクションを追加できます。組み込みツールが現在使用しているアクションとリソースは次のとおりです。

| アクション                    | リソース                                                                 |
| ----------------------------- | ------------------------------------------------------------------------ |
| `read`                        | Location 相対の内部パス、または正規化された絶対外部パス                  |
| `edit`                        | `edit`、`write`、`patch` の対象パス                                      |
| `glob`                        | 要求された glob パターン                                                 |
| `grep`                        | 要求された正規表現（検索パスではない）                                   |
| `shell`                       | スキャナーが生成したコマンド文字列。複合コマンドでは複数になることがあります |
| `subagent`                    | 対象のエージェント ID                                                    |
| `skill`                       | スキル ID                                                                |
| `question`                    | `*`                                                                      |
| `webfetch`                    | 要求された URL                                                           |
| `websearch`                   | 検索クエリ                                                               |
| `generate_image`              | 選択した画像モデル（`providerID/modelID`）。設定されている場合は `#variant` も付きます |
| `external_directory`          | 正規化された外部ディレクトリの境界。通常は `/*` で終わります             |
| `<server>_<tool>`             | MCP ツールの場合は `*`。サーバー名とツール名では、英字、数字、`_`、`-` をそのまま使い、それ以外の文字は `_` に置き換えます |
| `opencode_list_mcp_resources` | MCP サーバー名                                                           |
| `opencode_read_mcp_resource`  | `<server>:<uri>`                                                         |
| `execute`                     | `*`。deny の場合は Code Mode が削除されてツールが直接一覧表示され、ネストされたツールはそれぞれのルールを適用します |

MCP のアクション名ではハイフンがそのまま残ります。たとえば、`mcp-atlassian` というサーバーのツールに一致するのは `mcp-atlassian_*` であり、`mcp_atlassian_*` ではありません。

たとえば、1 つのスキルだけを許可し、他のすべてのスキルを拒否するには次のようにします。

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

`doom_loop` と `lsp` は、現在の V2 Core の権限アクションではありません。

## ディレクトリ

アクティブな Location とその非ルートのプロジェクト worktree の両方の外にあるパスは、`read` や `edit` のルールより前に `external_directory` に対してチェックされます。デフォルトのポリシーは `external_directory` を許可するため、ルールを追加しない限り外部パスで確認は求められません。プロジェクト外へのアクセスの前に確認を求めるには、次のようにします。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "*", "effect": "ask" },
  ],
}
```

その後に狭いルールを置くと、特定のディレクトリを許可または拒否できます。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

これは `read`、`edit`、`write`、`patch` が使用する外部パスに適用されます。シェルは、`shell` リソースをチェックする前に、外部の作業ディレクトリとスキャナーが推測したディレクトリをチェックします。

`external_directory`、`read`、`edit` では、先頭の `~`、`~/`、`$HOME`、`$HOME/` が設定の読み込み時に展開されます。

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

シェルのリソースは生のコマンドテキストのままで、ホームディレクトリは展開されません。

<Callout type="warning">
  `shell` は、ホストユーザーが持つファイルシステム、プロセス、ネットワークの権限で実行されます。コマンド文字列からディレクトリを推定しますが、すべて検出できるとは限りません。危険なコマンドをすべて検出しようとするパターンではなく、必要なコマンドだけを許可するリストを使ってください。
</Callout>

相対的な変更パスは、プロジェクト worktree 内にとどまりながらアクティブな Location の外に出ることがあります。明示的な外部パスはマッチングの前に正規化されるため、信頼できるディレクトリ境界だけを許可してください。

## スキャナー

シェルの権限チェックは、Bash、Zsh、POSIX `sh`、PowerShell に対応した OpenCode 組み込みのシェルスキャナーを使用します。構文が不正な場合や `eval` のような動的評価など、安全に解析できないコマンドもあります。`shell` の deny ルールが 1 つでも適用される場合、そのようなコマンドはスキャナーエラーで失敗します。サブコマンドを deny ルールに対してチェックできないためです。それ以外の場合は、コマンド全体を 1 つの `shell` リソースとして、また `external_directory` の `*` として承認する必要があります。2 つ目の承認は、すべてのディレクトリを許可するルールか、ユーザーだけが行えます。どちらの承認もパターンとして保存されません。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [
    {
      "permissions": [
        { "action": "shell", "resource": "git status *", "effect": "allow" },
        { "action": "shell", "resource": "rm *", "effect": "deny" },
      ],
    },
  ],
}
```

抽出されたすべてのサブコマンドと `cd` の対象について、権限ルールと保存済みの承認パターンを適用し、可能な範囲でディレクトリを推定します。不明なディレクトリに対する追加の承認モードや一律の制限はありません。

## デフォルト

カスタムエージェントを含むすべてのエージェントは、次の順序付きの基本ポリシーから始まります。

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

同梱のエージェントは次のポリシーを追加します。

| エージェント | 追加されるポリシー                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `build`      | 質問を許可                                                                                                               |
| `plan`       | 質問を許可。`~/.opencode/plan` 以下のファイルを除き編集を拒否                                                            |
| `general`    | 質問とサブエージェントの起動を拒否                                                                                       |
| `explore`    | シェル、読み取り、glob、grep、Web フェッチ、Web 検索、外部ディレクトリ以外のすべてを拒否。`.env` の読み取りは確認         |
| `title`      | すべてのアクションを拒否                                                                                                 |
| `summary`    | すべてのアクションを拒否                                                                                                 |
| `compaction` | 基本ポリシーを維持                                                                                                       |

デフォルトのルールは `external_directory` を確認しないため、Location と worktree の外の読み取りと編集は確認なしで進みます。[ディレクトリ](#directories)に示すように `external_directory` の `ask` または `deny` ルールを追加すると、確認を復元するか外部アクセスをブロックできます。後から追加されるグローバルルールとエージェントルールは、これらのデフォルトを上書きします。

## エージェント

共有ルールはトップレベルに、狭いルールは `agents.<id>.permissions` の下に置きます。

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

エージェントのルールはグローバルルールの後に追加され、グローバルの配列を置き換えることはありません。カスタムサブエージェントは、親の権限のサブセットではなく、自身の権限を使用します。

## 承認

ルールが `ask` になった場合、クライアントは次のように応答できます。

| 選択肢       | 応答     | 結果                                                               |
| ------------ | -------- | ------------------------------------------------------------------ |
| 1 回だけ許可 | `once`   | 保留中のリクエストだけを承認                                       |
| 常に許可     | `always` | 承認し、ツールが提案したパターンをプロジェクトに保存               |
| 拒否         | `reject` | そのリクエストと、そのセッションで保留中の他のすべての権限リクエストを拒否 |

たとえば、`git status --short` に対して **Allow always** を選ぶと、以降の `git status` コマンドをカバーするシェルのプレフィックスが保存されることがあります。

```text
shell: git status * → allow
```

保存された承認は、プロジェクト単位の永続的な `allow` ルールです。設定済みの `deny` を上書きすることはありません。保存するパターンはツールが決めます。`*` を提案するものもあれば、シェルはコマンドのプレフィックス、Web フェッチは URL のサイト（`https://opencode.ai/*` など）、スキルとサブエージェントは自身の ID を提案します。広い承認は見直し、不要になったものを削除してください。

クライアントは拒否時にフィードバックを添えられます。非対話型のクライアントは承認リクエストの扱いを決める必要があります。設定済みの `deny` ルールは常に適用されます。

## ポリシー

[ポリシー](/policies)は、これらのルールと保存済みの承認が実行された後に、権限チェックを強制的に拒否できます。`allow` や `ask` を `deny` に変え、アクセスを付与することはありません。

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

グローバルポリシーと Console のマネージドポリシーはプロジェクト設定を上書きします。これにより、組織はリポジトリが許可するコマンドをブロックできます。
