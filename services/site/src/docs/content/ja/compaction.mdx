description: "コンパクションは、自動または要求に応じて古い会話を要約し、OpenCode のセッションがモデルのコンテキスト上限を超えて続けられるようにします。"
---

コンパクションは、古い会話を要約に置き換えて長いセッションの空きを作り、セッションがモデルのコンテキスト上限を超えて続けられるようにします。

## 仕組み

セッションがモデルのコンテキスト上限に近づくと、OpenCode はそこまでの会話全体を要約します。直近のやり取り（デフォルトで約 15,000 トークン）は要約とは別に保持するので、直近の詳細は正確に参照できます。

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

会話全体を送信することで、プロバイダーが対応していれば、要約リクエストが通常のリクエストのプロンプトキャッシュを再利用できます。以降のコンパクションは、そのチェックポイント以降の会話を使って既存の要約を更新します。

## 開始

自動コンパクションはデフォルトで有効です。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

コンパクションでは情報が失われます。最近の正確な詳細が重要な場合は `keep.tokens` を増やすか、自動コンパクションの前に自分でコンパクションを要求してください。

## 手動

短い履歴でも、いつでもコンパクションを要求できます。

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

`api` コマンドはバックグラウンドサービスを検出して認証します。レスポンスはリクエストが受け付けられたことを示すだけで、要約は待ちません。いつ完了するかは `session.compaction.*` イベントで確認できます。操作の全体については [API リファレンス](/api)を参照してください。

| ルール     | 動作                                                               |
| ---------- | ------------------------------------------------------------------ |
| タイミング | 次に安全な時点で、まだ待機中のプロンプトより前に実行されます。     |
| 繰り返し   | 実行待ちの間にされたリクエストは、それにマージされます。           |
| 自動化     | `compaction.auto` が `false` でも機能します。                      |

`id` を渡すと、同じ再試行を冪等にできます。その ID を別のリクエストで再利用すると競合が返ります。

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## 設定

任意の [OpenCode 設定ファイル](/config)に `compaction` を追加します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": "20%",
  },
}
```

| フィールド    | デフォルト        | 動作                                                                                                                         |
| ------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `auto`        | `true`            | コンテキスト上限に近づくと自動的にコンパクションし、プロバイダーがリクエストを長すぎると拒否した場合に 1 回復旧します。手動のコンパクションは常に機能します。 |
| `background`  | `true`            | 自動コンパクションが待たないよう、要約を事前に作成します。[バックグラウンドのコンパクション](#background-compaction)を参照してください。 |
| `keep.tokens` | `15000`           | 要約の隣に保持する直近の会話の目安。値を大きくすると詳細が多く残りますが、新しい作業の余地が減ります。                       |
| `buffer`      | `"15%"`、最低 16k | 空けておくモデルのコンテキストウィンドウの割合。会話が残りの部分に達すると自動コンパクションが始まります。値を大きくすると早くコンパクションされます。 |

`keep.tokens` は負でない整数を受け付けます。

### バッファ

`buffer` は各モデルのウィンドウに対する割合であるため、1 つの設定ですべてのモデルに対応できます。

| モデルのウィンドウ | `"buffer": "20%"` でコンパクションする時点 |
| -----------------: | -----------------------------------------: |
| 128k               |                                      ~102k |
| 1M                 |                                       800k |

- これは空けておく余地であり、コンパクションが始まる時点ではありません。`"20%"` は 80% 埋まった時点でコンパクションします。
- `"1%"` から `"99%"` まで、`"12.5%"` のような小数も受け付けます。
- `20000` のようなトークン数も使用できます。同じ数でも、小さいウィンドウでは大きな割合、大きいウィンドウでは小さな割合になります。
- モデルのウィンドウ以上のトークン数は無視され、デフォルトが適用されます。

### ウィンドウ

ウィンドウはモデルの入力上限（`limit.input`）で決まり、コンテキスト上限（`limit.context`）を超えません。どちらか一方しか設定されていないモデルでは、その値を使います。両方とも設定されていないモデルでは自動コンパクションは行われません。プロバイダーがリクエストの長さを理由に拒否した場合、OpenCode はコンパクションを 1 回実行します。

設定で上限を上書きすると、指定したフィールドだけが置き換わります。カタログに両方の上限が設定されている場合、`limit.context` だけを引き上げてもウィンドウはカタログの入力上限のままです。`limit.input` も設定してください。

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "limit": { "context": 1050000, "input": 1000000 },
        },
      },
    },
  },
}
```

## モデル

デフォルトでは、OpenCode はセッションのモデルを使って自身で要約を作成します。要約に別のモデルを使うには `agents.compaction.model` を設定します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" },
  },
}
```

指定したモデルが見つからなければ、OpenCode はセッションのモデルにフォールバックします。

## バックグラウンドのコンパクション

OpenCode はセッションが続く間に要約を事前に作成し、コンパクションの時期に差し替えます。これにより、自動コンパクションのためにセッションを止める必要がありません。

```text
60k tokens before the threshold   summary of the conversation so far starts in the background
                                  the session keeps going; the summary is held, not applied
threshold                         the held summary is swapped in; everything since it is kept as is
```

小さなコンテキストウィンドウでは、要約は前回のコンパクション後の最初のレスポンスとしきい値の中間までに開始されます。

| ルール         | 動作                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| コスト         | 要約リクエストはプロンプトキャッシュを再利用します。しきい値の前にセッションが終了するなど、使われなかった要約にもトークンのコストがかかります。 |
| 待機           | コンパクションの時期に要約がまだ作成中の場合、セッションは完了を待ちます。                                                    |
| フォールバック | 保持された要約以降の会話がしきい値の約 40% を超えて増えた場合、または会話の開始部分が変わった場合、コンパクションは通常どおり要約します。 |
| スキップ       | ネイティブのコンパクションには使用されません。モデルを切り替えた直後や、プロンプトキャッシュの有効期間より長い休止の後は、代わりに次のレスポンスから開始されます。 |
| 保存           | 保持された要約はメモリ上にあり、再起動すると失われます。                                                                      |

コンパクションの時期にのみ要約を作成するには、オフにします。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "background": false,
  },
}
```

## プロバイダー

一部のプロバイダーは、代わりに自社側で会話をコンパクションできます。プロバイダーまたはモデルごとに `settings.compaction` で有効にします。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

モデルの設定はプロバイダーの設定を上書きします。`native` はプロバイダーのコンパクションを、`summary` は OpenCode 自身のものを使用します。

ネイティブのコンパクションでは、OpenCode は会話をプロバイダーのコンパクションエンドポイントに送信します。プロバイダーは古い会話に代わる、中身を参照できない暗号化データを返します。それに加えて、直近のメッセージと添付ファイルを `keep.tokens` まで保持します。

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| 項目           | 動作                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 対応           | OpenAI の Responses モデル。対応状況はデプロイメントとモデルによって異なります。                                               |
| しきい値       | 要約によるコンパクションと同じ `auto` と `buffer` の設定を使用します。手動のリクエストも機能します。                           |
| 移植性         | 暗号化されたチェックポイントは、同じプロバイダーとモデルでのみ機能します。モデルを切り替えると、セッションは元の会話から続行されます。 |
| 長すぎる場合   | プロバイダーがコンパクションを長すぎると拒否した場合、OpenCode はより小さなリクエストで再試行します。要約には切り替えません。   |

## 要約

要約は、別のエージェントがそこから作業を引き継げるように構成されています。

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

目的と要件、決定事項、完了した作業と進行中の作業、ブロッカーと次の行動、関連するファイルを扱います。隣に保持される直近の会話では、長いツールの出力は短縮され、添付のデータは短い説明に置き換えられます。

コンパクション後は、指示ファイルの現在のバージョンがセッションの基準になります。[指示](/instructions)を参照してください。

## 制限

| 制限     | 結果                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| モデル   | 要約によるコンパクションは `agents.compaction.model` に従い、なければセッションのモデルを使用します。ネイティブのコンパクションは常にセッションのモデルを使用します。 |
| 履歴     | コンパクションには置き換える古い会話が必要です。リクエストのほとんどが固定の指示とツールのスキーマである場合、空きを作れません。 |
| サイズ   | コンパクションする会話自体が長すぎる場合、OpenCode は短縮したテキスト版を送信し、最も古いやり取りを省略することがあります。   |
| 復旧     | 長すぎるとして拒否されたリクエストは、コンパクションされて 1 回再試行されます。2 回目の拒否はエラーとして返されます。           |
| 保存     | 以前のメッセージは、モデルに送信されなくなっても保存されたままです。                                                           |

たとえば、次の場合はコンパクションでは解決できません。

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## 移行

V1 は末尾のターンとプルーニングの動作を使用していました。V2 は要約と `compaction.keep.tokens` を使用します。

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

このページの設定と動作は V2 に適用されます。
