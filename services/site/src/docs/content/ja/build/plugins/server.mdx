プラグインのサーバー部分は OpenCode サーバーで実行されます。OpenCode の動作を変更し、ツール、フック、連携、コマンド、エージェントといった機能を追加します。プラグインパッケージの構成、読み込み、公開については[概要](/build/plugins)を参照してください。

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

## ライフサイクル

`setup` はプラグインの読み込み時に実行されます。プラグインのアンロード時に実行されるクリーンアップ関数を返すこともできます。

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### コンテキスト

プラグインのコンテキストは、実質的に [OpenCode サーバークライアント](/build/client)です。読み取りとアクションのメソッドは、クライアントと同じ入力とレスポンスを使用します。transform、ランタイムフック、再読み込み、登録、プラグインのオプションのための、プラグイン専用のメソッドが追加されます。

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location` は、このプラグインインスタンスが読み込まれた location を表します。`directory`、任意の `workspaceID`、`project` のメタデータ（`id`、`directory`、`canonical`）が含まれます。Promise プラグインと Effect プラグインの両方で利用できます。これはプラグインインスタンスの location であり、アクセスできるすべてのセッションや受信するイベントの location ではありません。

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### オプション

プラグインのオプションは、`opencode.json(c)` のオブジェクト形式で渡します。

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

`setup` の中で `ctx.options` からそれらの値を読み取ります。

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## Transform

Transform は OpenCode のドメイン状態への同期的な編集で、それぞれが同じドメイン内の以前の登録の上に構築されます。`ctx.model.list()` などのレジストリの読み取りは、プラグインの setup 中も含め、それまでのすべての登録を反映します。起動時のバッチ処理は更新の通知をまとめるだけで、読み取りが返す内容を遅らせることはありません。リソースの状態の API は、実行中のリソースの状態を引き続き報告します。定義が登録されたからといって、その接続やその他のリソースの処理が完了したわけではありません。

ソースは `ctx.provider.transform` を通じてプロバイダーと不変のモデル定義を提供します。

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

登録、削除、`reload()` のいずれかがレジストリを変更済みにします。次の読み取りでは、アクティブなすべての transform を登録順に新しい値へ再生してレジストリを再構築します。transform は軽量で再現可能に保ってください。すでに読み取った値が、後の再構築で変更されることはありません。

プロバイダーの transform と可用性が解決された後、OpenCode はアクティブなプロバイダーのモデルを具体化し、すべてのモデルの transform を順に再生します。モデルのポリシーは、新しく更新されたソースを含む候補全体を検査できます。

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

取り込んだ入力は自動的には監視されません。外部データは同期のコールバックの前に読み込み、それらの入力が変わったら `reload()` を呼び出してください。ここで `loadFromSource()` は `{ info: Provider.Info, models: readonly Model.Info[] }` のエントリを返します。

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

プロバイダーの変更はアクティブなモデルの結果全体を無効にするため、出力価格のポリシーは更新されたモデルにも引き続き適用されます。モデルの transform が取り込んだ入力だけが変わった場合は `ctx.model.reload()` を使用します。

## API

### Agent

すべてのエージェントを読むか、ID で 1 つ取得します。

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

transform を登録すると、エージェントの確認、作成、更新、削除や、デフォルトエージェントの選択ができます。

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

新しいエージェントは `editor.update` で登録します。指定した ID のエージェントがすでにあれば、そのエージェントを編集します。なければ `Agent.Info.default(id)` で作成してからコールバックを実行します。

```ts
await ctx.agent.transform((editor) => {
  editor.update("reviewer", (agent) => {
    agent.description = "Reviews code for correctness and maintainability"
    agent.mode = "subagent"
    agent.system = "Review the proposed changes and report actionable findings."
  })
})
```

transform が使用する外部の状態が変わったら、エージェントを再読み込みします。

```ts
await ctx.agent.reload()
```

### プロバイダー

利用可能なプロバイダーを読むか、ID で 1 つのプロバイダーのメタデータを確認します。

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

プロバイダーの transform はプロバイダーの設定とソースの定義を編集します。エディタの読み取りは非アクティブなプロバイダーも含み、不変の定義を公開します。`models.update` はソースモデルの所有コピーを編集します。

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

プロバイダーのソースの一覧は `models.set` で置き換え、取り込んだ定義が変わったら再読み込みします。

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

アカウント固有の検出では、一覧の読み込みに使用した接続を `sourceConnection` として渡します。別の接続が選択されている間、プラグインが更新された一覧を公開するまで、OpenCode はそのプロバイダーを除外します。

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### モデル

利用可能なモデルとデフォルトの選択を読み取ります。

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

モデルの transform は、アクティブなプロバイダーの候補全体を編集します。無効な候補もすべての transform が終わるまで編集でき、`update` は利用可能なプロバイダーの下にのみモデルを追加できます。

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})
```

コールバックは生のモデルの上書きを編集します。プロバイダーのデフォルトは、OpenCode が結果を確定するときに一度だけマージされ、変更のない読み取りはその結果を再利用します。`editor.provider` は、モデルの transform の出力ではなく、非アクティブなテンプレートを含む不変のソース定義を公開します。

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### 連携

連携を読み取り、アクティブな認証情報を確認します。

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

連携は API キーで接続します。

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

OAuth 接続の試行を開始、確認、完了、キャンセルします。

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

コマンドベースの接続も、同じ開始、ステータス、キャンセルのフローを提供します。

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

transform を登録して、連携の確認と認証方法の管理を行います。

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

transform が使用する外部の状態が変わったら、連携を再読み込みします。

```ts
await ctx.integration.reload()
```

### MCP

MCP サーバーとその現在の接続状態を一覧表示します。

```ts
const servers = await ctx.mcp.list()
```

プラグインは transform を通じてのみ MCP サーバーを管理します。サーバーの追加または置き換えには `editor.set`、設定の変更には `editor.update`、削除には `editor.remove` を使用します。設定の確認には `editor.list` と `editor.get` を使用します。

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

transform で `disabled: true` を設定するとサーバーを無効にして切断し、`disabled: false` を設定すると有効にして OpenCode の接続を許可します。OpenCode は transform 後の設定からサーバーのライフサイクルを調整します。

transform が使用する外部の状態が変わったら `reload()` を呼び出して、transform を再適用しサーバーを調整します。

```ts
await ctx.mcp.reload()
```

### 生成（実験的）

### 権限

操作を実行する前に権限を求めます。`assert` は、保存済みの承認を含むセッションの[権限ルール](/permissions)を評価し、結果が `ask` ならユーザーに確認します。操作が許可されると Promise は正常に完了します。

```ts
execute: async (input, context) => {
  await ctx.permission.assert({
    sessionID: context.sessionID,
    agent: context.agent,
    source: { type: "tool", messageID: context.messageID, id: context.id },
    action: "deploy",
    resources: [input.environment],
    save: [input.environment],
  })
  return { content: await deploy(input.environment) }
}
```

- `action` と `resources` がルールと照合されます。いずれかが `deny` なら操作はブロックされ、そうでなければいずれかが `ask` なら確認します。
- `save` は、ユーザーが常に許可を選んだときに保存するパターンを列挙します。
- `agent` は適用するルールの主体を選び、デフォルトはセッションのエージェントです。`source` はプロンプトをツール呼び出しに紐付けます。
- `metadata` は、権限のプロンプトと `evaluate` フックに追加の詳細を渡します。

拒否ルール、またはフィードバック付きの拒否は、理由を伴う `Tool.Error` で拒否されるため、モデルはそれを認識して続行します。単なる拒否は現在のステップを終了します。これらのエラーはツールの出力として返すのではなく、そのまま伝播させてください。

保留中の権限リクエストを確認したり、許可・拒否を回答したりできます。

```ts
const pending = await ctx.permission.list({ sessionID })
const request = await ctx.permission.get({ sessionID, requestID })
await ctx.permission.reply({ sessionID, requestID, decision: "once" })
```

セッション単位の権限ルールを置き換えます。ルールはエージェントのルールの後に評価され、最後に一致したルールが優先されます。子セッションは、作成時に有効だったルールを継承します。

```ts
await ctx.session.update({
  sessionID,
  permissions: [{ action: "edit", resource: "/path/to/original/checkout/**", effect: "deny" }],
})
```

セッションを作成または読み取ります。

### ツール

すべての transform の後、transform のコールバックの外で、現在登録されているツールを読み取ります。各ツールは実効的な名前を含む `id` を持ちます。

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

ツールの登録、更新、削除は同期の transform で行います（Promise プラグインでも同様です）。外部データは登録または再読み込みの前に読み込んでください。後の有効な登録が、同じ実効的なツール名を上書きします。

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Promise のツールのエグゼキューターは `context.signal` を受け取ります。`fetch` などキャンセル可能な処理に渡すと、セッションを停止したときに基になる処理も停止します。

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

#### 自由形式のツール入力

必須の文字列フィールドをちょうど 1 つ持つ直接ツールは、モデルにその文字列を JSON のラッパーなしで書かせることができます。`freeform` を `{ type: "text" }`、`{ type: "regex", pattern }`、`{ type: "lark", grammar }` のいずれかに設定します。

```ts
editor.add({
  name: "ticket",
  description: "Look up a ticket by ID",
  options: { codemode: false },
  input: Schema.Struct({ id: Schema.String }),
  freeform: { type: "regex", pattern: "OPS-[0-9]+" },
  execute: async ({ id }) => ({ content: await lookup(id) }),
})
```

選択したモデルの API が models.dev で `regex` を列挙している場合、モデルは `OPS-42` を直接書けます。そうでない場合、Core は**`freeform` だけ**を省略します。モデルは `ticket` ツールを引き続き持ち、`{"id":"OPS-42"}` で呼び出します。形式の一覧がない、または空の場合は自由形式に未対応です。どちらの場合もエグゼキューターは `{ id }` を受け取ります。

Code Mode（`codemode: true`）の内部では、自由形式のツールは `await tools.ticket("OPS-42")` のように文字列を直接受け取ります。`await tools.ticket({ id: "OPS-42" })` も機能します。

コールバックが取り込んだソースデータを変更したら `reload()` を呼び出します。再読み込みはアクティブな transform を順序を変えずに再生し、プラグインの setup は再実行しません。

```ts
await ctx.tool.reload()
```

エディタにあるツールを確認するには `list()` と `get()` を使います。ツールの `id` には実際に使われる名前が入ります。その ID のツールが存在しない場合、`get()` は `undefined` を返します。`update` と `remove` には、名前空間を含めた実際のツール名（上の例では `acme_greeting`）を渡します。名前空間のドットは `_` に変換されます。ツール名では英字、数字、`_`、`-` 以外の文字が `_` に置き換わります。存在しない名前は無視されます。新しいツールを作成するには、`add` に完全な定義を渡してください。更新しても名前と名前空間は変わりません。ネストした値を直接変更するのではなく、新しいスキーマやオプションを代入して置き換えてください。無効な更新はログに記録され、以前の定義がそのまま残ります。

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

更新と削除は、MCP カタログの更新後も含め、追加とともに順番に再生されます。登録を破棄するとそれらの変更が削除され、残りの transform から再構築されます。

登録を破棄するとその transform が削除され、残りの transform から再構築されて、上書きしていた以前の定義が現れます。破棄は冪等で、プラグインのアンロード時にもその登録が破棄されます。

```ts
await registration.dispose()
```

各モデルリクエストは、安定した実行可能なツールのスナップショットを取得します。後の transform、再読み込み、破棄は将来のスナップショットに影響し、すでに取得された定義、Code Mode の名前空間の説明、エグゼキューターには影響しません。可変のプラグインデータをクローズオーバーするエグゼキューターはそのデータを引き続き参照するため、その定義に紐付けたい値は transform の内部で取り込んでください。

スキーマ：[`Tool.Content`](/api#schema-Tool.Content)、[`Tool.TextContent`](/api#schema-Tool.TextContent)、[`Tool.FileContent`](/api#schema-Tool.FileContent)

### VCS

リポジトリの情報、作業コピーの状態、ファイルの Diff を読み取ります。

```ts
const info = await ctx.vcs.get()
const branches = await ctx.vcs.branch.list({ search: "feature", limit: 10 })
const changes = await ctx.vcs.status()
const diff = await ctx.vcs.diff({ mode: "working", context: 3 })
```

transform で location 単位の VCS プロバイダーを登録します。検出されたリポジトリの種類に一致するプロバイダーが自動的に選択され、別のプロバイダーを選ぶには `editor.default.set` を使用します。

```ts
await ctx.vcs.transform((editor) => {
  editor.add({
    id: "custom",
    name: "Custom VCS",
    info: async () => ({ branch: { current: "feature", default: "main" } }),
    branches: async (input, { signal }) => readBranches(input, signal),
    status: async (scope, { signal }) => readStatus(scope.worktree, signal),
    diff: async (input, { signal }) => readDiff(input, signal),
  })
  editor.default.set("custom")
})
```

プロバイダーのコールバックは、現在の location、作業コピーのルート、カノニカルなプロジェクトルート、任意のリポジトリのストアを受け取ります。Diff のコールバックはさらに、選択されたモード、要求されたコンテキスト、出力のバイトバジェットを受け取ります。リポジトリの検出は、引き続き OpenCode 組み込みの Git と Mercurial の検出器を使用します。

プロバイダーは任意で `init(scope, { signal })` を実装し、`scope.worktree` にリポジトリを作成できます。初期化は検出されたリポジトリの種類ではなく、ID（デフォルトは Git）でプロバイダーを選択します。location にまだリポジトリがない場合でも、`init` を持つプロバイダーを登録してください。OpenCode は呼び出す前にディレクトリが存在しリポジトリがないことを確認し、その後プロジェクトを再検出します。新しいリポジトリ形式には、このコールバックとは別に検出のサポートが必要です。

### Worktree

通常のプラグインのライフサイクルで、ローカルの worktree ストラテジーを登録します。ここでの実装モジュールは、オプションの検証と、バックエンドの `create`、`remove`、`list` の操作を担当します。

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

プラグインは `plugins` で読み込み、共通の移動先は別に設定します。

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- ストラテジーを追加すると自動的に選択されます。最後に有効な登録が優先され、ストラテジー選択の設定は不要です。
- 登録を破棄するかプラグインをアンロードすると、以前の実装、最終的には同梱の Git ストラテジーに戻ります。
- `reload()` は取り込んだ入力が変わった後に transform を再生します。プラグインの setup は再実行しません。
- 作成の失敗は Git で再試行されません。既存の worktree は、デフォルトが変わっても記録された所有者を保ちます。
- ストラテジーはローカルのディレクトリを管理します。リモートのワークスペースのプロビジョニングはこのインターフェースの対象外です。

#### 操作

プラグインのコンテキストは、クライアントと同じプロジェクトベースの worktree 操作を提供します。すべての操作には `projectID` が必要です。`list` は、同じプロジェクトの既知のチェックアウトを含む保存済みの一覧だけを読み取り、設定の読み込み、プラグインの起動、ファイルシステムの変更の検出は行いません。

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

作成時は、プロジェクトに保存された `canonical` ディレクトリから設定とプラグインを読み込み、そこで選択されたストラテジーを使います。親ディレクトリの `directory`、作成元の `from`、起点となるブランチの `branch`、名前の `name` を任意で指定できます。デフォルトの作成元は正規のチェックアウトです。`from` で別の作成元を指定する場合も、同じプロジェクトに属している必要があります。作成元を選んでも設定のルートは変わりません。起点の参照を指定するには、選択されたストラテジーがその指定に対応している必要があります。たとえば Rift のネイティブなスナップショット操作では参照を選べません。

作成と更新は、カノニカルなチェックアウトのプラグインが有効になるまで待ちます。そのチェックアウトのプラグインの setup 中に行われた呼び出しは、それまでの登録を認識し、自身の有効化は待ちません。

削除は、カノニカルな設定を読み込んでそのプラグインを有効にし、現在選択されているデフォルトではなく、worktree に記録されたストラテジーを使用します。記録された所有者が利用できない場合はエラーになります。worktree の移動先は別の場所でもかまいません。

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

管理元のストラテジーが見つからない場合は、Git にフォールバックせずに削除が失敗します。ストラテジーでは `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })` をスローして、強制削除の確認を要求できます。`Worktree` は `@opencode/plugin` からインポートでき、Core や Git のエラーに依存する必要はありません。

更新時は正規の設定を読み込み、利用可能なすべてのストラテジーで既知のチェックアウトルートから worktree を探します。結果を統合し、記録済みの管理元を維持しながら、存在しないディレクトリを一覧から取り除きます。検出に失敗した場合はその検出元がログに記録され、他の検出元の処理は続きます。どのストラテジーからも報告されなかったディレクトリでも、実際に存在する限り一覧に残ります。`worktree.updated` を監視し、変更後の一覧は `list` を再度呼び出して取得してください。

```ts
await ctx.worktree.refresh({ projectID })
```

#### リファレンス

実装は、名前付けと衝突処理の後に推奨される移動先を受け取ります。`create` からは実際のディレクトリを返してください。バックエンドが独自のレイアウトを必要とする場合は異なることがあります。OpenCode は返されたパスを解決し、一覧、起動コマンド、API の結果に使用します。返されたディレクトリは存在している必要があります。

別の移動先を選ぶストラテジーは、そこで名前の衝突を処理します。OpenCode はストラテジーを呼び出す前に、推奨される親ディレクトリを引き続き作成します。`list` は、そのストラテジーが所有するディレクトリと、リポジトリのルートだけを報告する必要があります。

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Promise のコールバックは `signal` によるキャンセルに協力する必要があります。Effect のコールバックは Effect を返し、代わりに Effect の中断を使用します。登録はプラグインのランタイムにスコープされ、プロジェクトの操作はカノニカルなチェックアウトのレジストリを使用します。Core の設定アダプターが、ディレクトリの設定をそのレジストリに渡します。

### Web 検索

Web 検索のプロバイダーを一覧表示するか、選択されたプロバイダーでクエリを実行します。

```ts
const providers = await ctx.websearch.providers()
const results = await ctx.websearch.query({ query: "OpenCode plugins", providerID: "internal" })
```

transform でプロバイダーを登録し、デフォルトのプロバイダーを選択します。

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = (await response.json()) as { url: string; title: string; content: string }
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

Web 検索を無効にするには `false` を選択します。外部の状態が変わった場合は、プロバイダーを再読み込みします。

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```

## フック

フックは実行中の操作を横取りします。フックはそのドメインに登録し、不要になったら返された登録を破棄します。

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

複数のプラグインが同じフックを登録できます。OpenCode はプラグインの順に実行するため、後のフックは以前のフックによる変更を認識します。

### セッション

セッションのフックは、プロンプトの受け付け、モデル呼び出し、ネイティブ HTTP、再試行を横取りします。

#### フォーク

`fork` フックは、OpenCode が履歴をコピーした後、フォークの呼び出しが戻る前に実行されます。`sessionID` は新しいセッションを識別します。

```ts
await ctx.session.hook("fork", ({ sessionID }) => console.log(sessionID))
```

#### プロンプトの受け付け

受信したユーザープロンプトを、添付とスキルの解決、および永続的な受信トレイへの受け付けの前に横取りします。

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

フックは所有権を持つ可変のドラフトを受け取ります。

- `prompt` には `text`、`files`、`agents` 内のエージェントのメンション、選択された `skills` が含まれます。
- `metadata` にはアプリケーションが定義した受け付けのメタデータが含まれます。
- `delivery` はデフォルトで `"steer"` で、`"queue"` に変更できます。
- セッションとメッセージの ID は読み取り専用で、フックが受け付け先を変更することはできません。

フックが追加したファイルとスキルは、通常の解決と検証の経路に従います。テキストを書き換えるときは、一致しなくなった添付の `mention` オフセットを更新または削除してください。エージェントのメンションはセッションのアクティブなエージェントを切り替えません。

プロンプトのフックは次の条件で実行されます。

- フックは、セッションの location のプラグインが準備できた後、登録順に実行されます。
- `session.prompt` を通じて送信するコマンドはフックを実行します。
- 合成メッセージ、シェルメッセージ、コンパクションの制御、移動の制御は実行しません。
- フックは受け付け時に 1 回だけ実行され、モデル呼び出しのたびに実行されるわけではありません。
- モデルの解決は受け付けの後に行われるため、プロバイダーによるスコープは利用できません。

編集内容は、正規の永続化されたユーザー入力になります。準備に失敗した、または中断された場合、OpenCode はプロンプトを受け付けません。

プロンプトのフックは再試行に対して安全に保ってください。これらは副作用の exactly-once の境界ではありません。

- すでに保留中または配信済みの ID を再試行すると、フックを再実行せずに元の受け付け結果を返します。
- 同時に送信された場合はフックが複数回実行されることがありますが、最初に成功した受け付けだけが有効になります。
- プロンプトのフックは入力を変換するもので、型付きの拒否 API は提供しません。

#### モデルリクエスト

モデルのディスパッチ直前に、組み立てられたシステム指示、メッセージ、ツール、リクエストオプションを変更します。セッションが発行するリクエストの種類ごとにフックがあるため、プラグインはエージェントのループと補助的なリクエストを別々に扱えます。

- `context` は、ツールによる継続を含むエージェントのループで実行されます。
- `compaction` はチェックポイントの要約で実行されます。`messages` は要約対象のトランスクリプトで、OpenCode はフックの実行後に要約のプロンプトを追加します。`result` を設定すると自分でコンパクションを記録してモデル呼び出しをスキップできます。完了したコンパクションメッセージと同じフィールドを取ります。
- `generate` は一時的な `ctx.session.generate` の呼び出しで実行されます。
- `title` はタイトルの生成で実行されます。`agent` や `tools` はありません。`result` を設定すると自分でタイトルを指定できます。

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

変更は送信されるモデル呼び出しにのみ影響し、永続化された履歴や設定には影響しません。すべてのリクエストに適用したいフックは、種類ごとに登録する必要があります。

`context`、`compaction`、`generate` フックのメッセージは、保存されたメッセージの `metadata` を読み取り専用で持ちます（たとえば `prompt` フックが設定した内容）。これはモデルには送信されません。

OpenCode の指示を保持する `system` パーツは、各ソースを `metadata.experimental.instructions` に `{ key, text }` として列挙します（`core/date` や `core/environment` など）。フックはこれでソースを区別できます。リストはコピーであるため、パーツの `text` を編集しても更新されません。これは実験的な機能で変更される可能性があります。

リクエストの上書きは次のルールに従います。

- `options` はモデル呼び出しごとに空で始まり、解決済みのモデル設定は含みません。
- 型付きのキーは生成の設定で、それ以外のキーはプロバイダーのオプションとして選択されたプロトコルに渡されます。
- フックは登録順に実行され、以前のフックによる上書きを認識します。
- リクエストの上書きはモデルのデフォルトより優先され、モデルのデフォルトは経路のデフォルトより優先されます。
- プロバイダーのオプションのオブジェクトは再帰的にマージされ、配列とスカラー値は以前の値を置き換えます。
- 上書きを削除するか `undefined` を設定すると、設定済みのデフォルトを削除するのではなく、デフォルトにフォールバックします。
- 生の HTTP ボディのオーバーレイはプロトコルへの変換後に適用され、結果のフィールドを上書きできます。

#### プロバイダーのオプション

プロバイダーのオプションは、生の HTTP ボディのフィールドではなく、選択されたプロトコルのセマンティックなオプション名を使用します。プロバイダー固有の設定は、該当するプロバイダーにスコープしてください。たとえば OpenAI Responses は `reasoningEffort` を使用します。

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

生成のオプションは、選択されたプロトコルとモデルによって異なります。

- `maxTokens` は、出力トークン数の上限を指定するセマンティックオプションです。
- Gemini は `topK` に対応していますが、OpenAI Responses は公開していません。

#### モデルの解決

実験的。セッションがリクエストのモデルを解決するたびに、そのリクエストのために何かが構築される前に実行されます。`model` は選択されたモデルから始まり、同じプロバイダーの別のモデル（モデルピッカーから隠れているものを含む）でこのリクエストを処理するように変更できます。セッションは選択したモデルを保ち、リクエストとアシスタントメッセージは新しいモデルを使用します。`kind` はどのリクエストを解決しているかを示すため、ルーターはタイトルをスキップしたり、コンパクション後に再度ルーティングしたりできます。別のプロバイダーのモデルは利用不可として失敗します。

```ts
await ctx.session.hook(
  "experimental.model.resolve",
  (event) => {
    if (event.model.id === "auto" && event.kind !== "title")
      event.model = { providerID: event.model.providerID, id: pick(event.sessionID) }
  },
  { providerID: "acme" },
)
```

#### モデルリクエスト

モデルリクエストの設定を変更し、必要に応じてフックを 1 つのプロバイダーに限定します。イベントは、以下の HTTP フックと同じ `kind` を持ちます。

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### ネイティブ HTTP

ネイティブのプロバイダーのリクエストまたはレスポンスを変更します。ボディは 1 回限りのストリームであるため、読み取る前に複製するか置き換えてください。

どちらのフックも、セッションが発行するすべてのリクエストで実行されます。`event.kind` はどのフローが発行したかを示します。エージェントのループは `"primary"`、チェックポイントの要約は `"compaction"`、タイトルの生成は `"title"`、一時的な `ctx.session.generate` の呼び出しは `"generate"` です。補助的なリクエストを区別するには、エージェント ID ではなくこれを使用してください。

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### ネイティブ WebSocket（実験的）

WebSocket でストリーミングするプロバイダーは、セッションごとに 1 つの接続を開いてリクエスト間で再利用するため、`http.request` と `http.response` がそのトラフィックを見ることはありません。`experimental.ws.handshake` フックは、接続が選択される前にモデル呼び出しごとに 1 回実行されます。HTTP フックと同じ `sessionID`、`agent`、`model`、`kind` に加えて、接続の `url` と `headers` を持ちます。`url` または `headers` を変更すると、リクエストが使用するソケットが変わるため、ローテーションしたベアラートークンで接続が開き直されます。

HTTP フックは、WebSocket の経路がフォールバックするリクエストを含め、すべての HTTP リクエストで引き続き実行されます。

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` と `experimental.ws.receive` は、HTTP のリクエストやレスポンスのボディを編集するのに対応する WebSocket の機能として、フレーム自体を公開します。`send` はプロバイダードライバーが送信フレームを構築した後、書き込まれる前に実行され、`receive` はドライバーが観測する前に各受信フレームで実行されます。どちらもフレームを文字列として受け取り、フックが戻ったときに `frame` が保持している内容を送信します。

OpenCode は書き換えられたフレームを検証しません。ドライバーはプロバイダーの応答から状態を追跡するため、プロトコルの意味を変える書き換えは、書き換えた HTTP ボディと同様にプラグインの責任です。

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

これらのフックは実験的で、名前や形が変わる可能性があります。

#### 再試行ポリシー

プロバイダーの失敗に対する再試行の判断を上書きするか、その遅延をミリ秒で置き換えます。フックは、OpenCode が失敗を分類してポリシーを提案した後、再試行がスケジュールされる前に実行されます。OpenCode が次の試行を内部でどのように行うかは公開しません。

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

再試行のフックは、通常は打ち切られる失敗を再試行可能にしたり、提案された再試行を拒否したりして、OpenCode の最初の `decision` を変更できます。

再試行の判断は次のルールに従います。

- 複数のフックは登録順に実行され、後のフックは現在の判断を認識します。
- 組み込みの最大試行回数はハードリミットとして残ります。
- `attempt` は検討中の実際の試行です。最初のリクエストが `1` のため、最初の再試行は `2` です。
- `NaN`、無限大、負の値などの無効な遅延は、計算された遅延にフォールバックします。
- コンテキストのオーバーフローからの復旧は、同じリクエストを再試行するのではなく会話をコンパクションするため、別に扱われます。

### 権限

設定済みのルールが評価された後、操作が実行されるか権限のプロンプトが公開される前に、権限の判断を確認します。

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-5-5" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

権限のフックは次のルールに従います。

- フックは `allow` と `ask` の判断で実行されます。
- 明示的に設定された `deny` は最終的なもので、フックを呼び出しません。
- フックは `effect` を `allow`、`ask`、`deny` に変更できます。
- `message` は、エスカレーションされた権限リクエストに表示されるか、拒否の理由になります。

#### リファレンス

```ts
interface PermissionEvaluation {
  readonly sessionID: string
  readonly agent?: string
  readonly action: string
  readonly resources: readonly string[]
  readonly metadata?: Record<string, unknown>
  readonly source?: { type: "tool"; messageID: string; id: string }
  effect: "allow" | "ask" | "deny"
  message?: string
}
```

## V1 のサポート

プラグインは、同じパッケージのエントリポイントから V1 と V2 の両方をサポートできます。V1 の `server()` 関数と V2 の `setup()` 関数を持つ 1 つのオブジェクトをデフォルトエクスポートします。

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 は `server()` を呼び出し、返されたフックを使用します。
- V2 はデフォルトエクスポートの `id` と `setup()`（Effect プラグインでは `effect()`）を読み取り、`server()` を無視します。
- 各実装はそれぞれの API の上に保ってください。エクスポートを共有しても、V1 のフックが V2 のフックに変換されるわけではありません。
- `Plugin.define(...)` をエクスポートするオブジェクトに展開すると、`server()` とは別に V2 の定義が型チェックされます。

V1 のオブジェクト形式は OpenCode `1.18.29` でサポートされています。より古い V1 のリリースは代わりに関数のエクスポートを期待する場合があります。サポートする予定の最も古い V1 のリリースと V2 の両方で、インストールしたパッケージをテストしてください。
