---

`@opencode/plugin/effect` は OpenCode プラグイン API の Effect ネイティブ版です。コンテキストの操作は Effect または Stream を返し、コールバックは Effect を返し、プラグインのライフタイムは `Scope` で表現されます。

OpenCode は、プラグインとその `node_modules` の依存関係を読み込むときに、`effect`（エクスポートされた `effect/*` サブパスを含む）と `@opencode/plugin` を実行時に提供します。プラグインにバンドルするのではなく、ローカルの型チェックとテストのために peer/dev 依存関係としてインストールしてください。

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

`.opencode/plugins/` から Effect プラグインをエクスポートすると、自動的に読み込まれます。

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

公開パッケージと `.opencode/plugins/` の外にあるプラグインディレクトリは、他のサーバープラグインと同じ `plugins` 設定を使用します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

有効化、パッケージの解決、設定の優先順位については[プラグインの設定](/plugins)を参照してください。

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## ライフサイクル

`effect` はプラグインの読み込み時に実行されます。スコープはプラグインの再読み込みまたはアンロード時に閉じられるため、登録、スコープ付きファイバー、ファイナライザーがまとめて解放されます。

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

バックグラウンドの作業にはスコープ付きファイバーを使用します。クリーンアップ時にプラグインのスコープがファイバーを中断します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### コンテキスト

コンテキストは、接続している OpenCode サーバー用の Effect クライアントに加えて、プラグイン専用の transform、フック、ストレージ、再読み込み、オプションを公開します。OpenCode のプライベートな Core サービスは公開しません。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

プラグインの定義と完全なコンテキストは次のように宣言されています。

```ts
  readonly id: string

```

### オプション

`opencode.json(c)` のオブジェクト形式でオプションを渡します。

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

オプションは `ctx.options` から読み取ります。不明な値は使用前に型を絞ってください。

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transform

Transform はエディタを通じて同期的に状態を編集します。OpenCode は各ドメイン内で登録順に transform を適用します。最初にソースがプロバイダーと不変のモデル定義を提供し、次にモデルの transform がアクティブなプロバイダーの候補を編集します。登録を yield するとプラグインのスコープに保持されます。

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

モデルの transform は、アクティブなプロバイダーの候補全体にポリシーを適用できます。

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

transform が使用する外部の状態が変わったら `reload` を呼び出します。ここで `loadFromSource()` は `{ info: Provider.Info, models: readonly Model.Info[] }` のエントリを返し、プロバイダーの再読み込みはモデルの結果全体も無効にします。

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agent

すべてのエージェントを読むか、ID で 1 つ取得します。クライアントのレスポンスには、解決された location とスキーマのデータが含まれます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

エージェントを transform または再読み込みします。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

スキーマ：[`Agent.Info`](/api#schema-Agent.Info)。

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### プロバイダー

利用可能なプロバイダーを読むか、ID で 1 つのプロバイダーのメタデータを確認します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

プロバイダーの transform はプロバイダーの設定とソースの定義を編集します。エディタの読み取りは非アクティブなプロバイダーも含み、不変の定義を公開します。`models.update` はソースモデルの所有コピーを編集します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

ソースの一覧は `models.set` で置き換え、取り込んだ定義が変わったら再読み込みします。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

アカウント固有の検出では、一覧の読み込みに使用した接続を `sourceConnection` として渡します。別の接続が選択されている間、プラグインが更新された一覧を公開するまで、OpenCode はそのプロバイダーを除外します。

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

スキーマ：[`Provider.Info`](/api#schema-Provider.Info)、[`Model.Info`](/api#schema-Model.Info)。

```ts

  readonly provider: Provider.Info

}

```

### モデル

利用可能なモデルとデフォルトの選択を読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

モデルの transform は、アクティブなプロバイダーの候補全体を編集します。無効な候補もすべての transform が終わるまで編集でき、`update` は利用可能なプロバイダーの下にのみモデルを追加できます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

コールバックは生のモデルの上書きを編集します。プロバイダーのデフォルトは、OpenCode が結果を確定するときに一度だけマージされ、変更のない読み取りはその結果を再利用します。`editor.provider` は、モデルの transform の出力ではなく、非アクティブなテンプレートを含む不変のソース定義を読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

スキーマ：[`Model.Info`](/api#schema-Model.Info)。

```ts

  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined

  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined

```

### コマンド

現在の location で利用可能なコマンドを読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

現在のコマンドの transform は追加のみです。エグゼキューターはセッション、プロンプトの添付、配信モードを受け取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

スキーマ：[`Command.Info`](/api#schema-Command.Info)、[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery)。


### 連携

連携を読み取り、有効な認証情報が設定されていれば取得します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

キーで接続するか、接続済みの API を通じて OAuth の試行を進めます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

連携と認証方法を transform します。OAuth の方法のコールバックは Effect で、スコープ付きのリソースを取得できます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

スキーマ：[`Integration.Info`](/api#schema-Integration.Info)、[`Integration.Method`](/api#schema-Integration.Method)、[`Connection.Info`](/api#schema-Connection.Info)、[`Form.Answer`](/api#schema-Form.Answer)。

### MCP

MCP サーバーとその現在の接続状態を一覧表示します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

プラグインは transform を通じてのみ MCP サーバーを管理します。サーバーの追加または置き換えには `editor.set`、設定の変更には `editor.update`、削除には `editor.remove` を使用します。設定の確認には `editor.list` と `editor.get` を使用します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

transform で `disabled: true` を設定するとサーバーを無効にして切断し、`disabled: false` を設定すると有効にして OpenCode の接続を許可します。OpenCode は transform 後の設定からサーバーのライフサイクルを調整します。

transform が使用する外部の状態が変わったら `reload()` を呼び出して、transform を再適用しサーバーを調整します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

スキーマ：[`Mcp.Server`](/api#schema-Mcp.Server)、[`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded)、[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded)。

```ts

  set(name: string, config: Mcp.ServerConfig): void
  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void
}

interface MCPDomain extends Pick<McpApi<unknown>, "list"> {
  readonly transform: Transform<MCPEditor>

}
```

### プラグイン

現在の location のアクティブ、失敗、解決済みのプラグインを一覧表示します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
```

### ツール

型付きのツールは Effect の `Schema` で登録します。エグゼキューターはデコードされた入力を受け取り、型付きの出力、表示コンテンツ、メタデータを含む Effect を返します。

エディタは `add`、`update`、`remove` に対応しています。transform のコールバックは同期で、Effect や Promise を返してはいけません。外部データは登録または再読み込みの前に読み込んでください。OpenCode は新しいエディタ上で、アクティブな transform を登録順に再生します。同じ実効的なツール名では、後の有効な登録が以前の登録を上書きします。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

コールバックが取り込んだソースデータを変更したら、`yield* ctx.tool.reload()` を呼び出します。再読み込みはアクティブな transform を順序を変えずに再生し、プラグインの effect は再実行しません。

Effect のツールは、Promise のツールと同じ[自由形式の入力の宣言](/build/plugins/server#freeform-tool-input)を受け付けます。モデルがその形式を提示しない場合、ツールは通常のオブジェクト入力のままです。

ツールは実効的な名前を含む `id` を持ち、その ID がない場合 `get()` は `undefined` を返します。`update` と `remove` には、名前空間を含む実効的なツール名（上記の `acme_greeting` など）を使用します。名前空間のドットと、ツール名のサポートされない文字は `_` になります。存在しない名前は無視され、ツールの作成には完全な定義を伴う `add` が必要です。更新は名前と名前空間を保ちます。ネストした値を変更するのではなく、新しいスキーマやオプションを代入して置き換えてください。無効な更新はログに記録され、以前の定義がそのまま残ります。

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

更新と削除は、MCP カタログの更新後も含め、追加とともに順番に再生されます。

`transform` はスコープ付きの登録を返します。`yield* registration.dispose` を実行すると、その transform を削除して残りの transform から再構築し、上書きしていた以前の定義が現れます。破棄は冪等で、プラグインのスコープを閉じてもその登録が破棄されます。

各モデルリクエストはツールのスナップショットを取得します。再読み込みと破棄は将来のスナップショットに影響し、既存のリクエストがすでに取得した定義やエグゼキューターには影響しません。可変のプラグインデータをクローズオーバーするエグゼキューターはそのデータを引き続き参照するため、その定義に紐付けたい値は transform の内部で取り込んでください。

スキーマ：[`Tool.Content`](/api#schema-Tool.Content)、[`Tool.TextContent`](/api#schema-Tool.TextContent)、[`Tool.FileContent`](/api#schema-Tool.FileContent)。

```ts

  list(): readonly (Tool.Info & { readonly id: string })[]
  get(id: string): (Tool.Info & { readonly id: string }) | undefined
  namespace(namespace: { name: string; description: string }): void
  add<Input extends Tool.ValueSchema<any>, Output extends Tool.ValueSchema<any> | undefined>(
    tool: Tool.Info<Input, Output>,
  ): void
  update(id: string, update: (tool: Types.Mutable<Tool.Info>) => void): void
```

### VCS

リポジトリの情報、作業コピーの状態、ファイルの Diff を読み取ります。

```ts
effect: (ctx) =>

    const vcs = ctx.vcs
    const info = yield* vcs.get().pipe(Effect.orDie)
    const branches = yield* vcs.branch.list({ search: "feature", limit: 10 }).pipe(Effect.orDie)
    const changes = yield* vcs.status().pipe(Effect.orDie)
    const diff = yield* vcs.diff({ mode: "working", context: 3 }).pipe(Effect.orDie)
    yield* Effect.logInfo("vcs", { branch: info.data.branch.current, files: changes.data.length })
  }),
```

スコープ付きの transform で location 単位のプロバイダーを登録します。検出されたリポジトリの種類に一致するプロバイダーが自動的に選択され、別のプロバイダーを選ぶには `editor.default.set` を使用します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const vcs = ctx.vcs
    yield* vcs.transform((editor) => {
      editor.add({
        id: "custom",
        name: "Custom VCS",
        info: () => Effect.succeed({ branch: { current: "feature", default: "main" } }),
        branches: (input) => readBranches(input),
        status: (scope) => readStatus(scope.worktree),
        diff: (input) => readDiff(input),
      })
      editor.default.set("custom")
    })
  }),
```

プロバイダーのコールバックは、現在の location、作業コピーのルート、カノニカルなプロジェクトルート、任意のリポジトリのストアを受け取ります。Diff のコールバックはさらに、選択されたモード、要求されたコンテキスト、出力のバイトバジェットを受け取ります。リポジトリの検出は、引き続き OpenCode 組み込みの Git と Mercurial の検出器を使用します。

プロバイダーは任意で `init(scope)` を実装し、`scope.worktree` にリポジトリを作成できます。初期化は検出されたリポジトリの種類ではなく、ID（デフォルトは Git）でプロバイダーを選択します。location にまだリポジトリがない場合でも、`init` を持つプロバイダーを登録してください。OpenCode は呼び出す前にディレクトリが存在しリポジトリがないことを確認し、その後プロジェクトを再検出します。新しいリポジトリ形式には、このコールバックとは別に検出のサポートが必要です。

## フック

フックは実行中の操作を横取りします。複数のプラグインが同じフックを登録でき、OpenCode はプラグインの順に実行するため、後のフックは以前の変更を認識します。登録はプラグインのスコープ中有効です。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### セッション

モデルのディスパッチ直前に、組み立てられたシステム指示、メッセージ、ツールを変更します。`context` はエージェントのループで、`compaction`、`generate`、`title` はそれらの補助的なリクエストで実行されます。`compaction` と `title` はモデル呼び出しをスキップする `result` を受け付けます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

`context`、`compaction`、`generate` フックのメッセージは、保存されたメッセージの `metadata` を読み取り専用で持ちます（たとえば `prompt` フックが設定した内容）。これはモデルには送信されません。

OpenCode の指示を保持する `system` パーツは、各ソースを `metadata.experimental.instructions` に `{ key, text }` として列挙します（`core/date` や `core/environment` など）。フックはこれでソースを区別できます。リストはコピーであるため、パーツの `text` を編集しても更新されません。これは実験的な機能で変更される可能性があります。

モデルリクエストの設定を変更し、必要に応じてフックを 1 つのプロバイダーに限定します。イベントは、以下の HTTP フックと同じ `kind` を持ちます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

ネイティブのプロバイダーのリクエストまたはレスポンスを変更します。ボディは 1 回限りのストリームであるため、読み取る前に複製するか置き換えてください。どちらのフックもセッションが発行するすべてのリクエストで実行され、`event.kind` はどのフローが発行したかに応じて `"primary"`、`"compaction"`、`"title"`、`"generate"` になります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

WebSocket でストリーミングするプロバイダーはセッションごとに 1 つの接続を再利用するため、HTTP フックがそのトラフィックを見ることはありません。実験的な `experimental.ws.handshake` フックは、接続が選択される前にモデル呼び出しごとに 1 回実行され、接続の `url` と `headers` を公開します。どちらかを変更するとソケットが開き直されます。WebSocket の経路がフォールバックするリクエストでは、HTTP フックは引き続き実行されます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` と `experimental.ws.receive` はフレーム自体を公開します。`send` はプロバイダードライバーが送信フレームを構築した後に実行され、`receive` はドライバーが観測する前に各受信フレームで実行されます。フックが戻ったときに `frame` が保持している内容がそのまま回線を渡るかドライバーに届きます。OpenCode は検証しません。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

プロバイダーの失敗に対する再試行の判断を上書きするか、その遅延をミリ秒で置き換えます。フックは、OpenCode が失敗を分類してポリシーを提案した後、再試行がスケジュールされる前に実行されます。OpenCode が次の試行を内部でどのように行うかは公開しません。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

最初の `decision` は OpenCode のポリシーであるため、フックは通常は打ち切られるプロバイダーの失敗を再試行可能にしたり、提案された再試行を拒否したりできます。複数のフックは登録順に実行され、後のフックは現在の判断を認識します。組み込みの最大試行回数はハードリミットとして残ります。`attempt` は提案されている実際の試行で、最初のリクエストが試行 `1` のため、最初の再試行は試行 `2` です。無効な遅延（`NaN`、無限大、負の値）は計算された遅延にフォールバックします。コンテキストのオーバーフローからの復旧は、同じリクエストを再試行するのではなく会話をコンパクションするため、別に扱われます。

### ツール

Before フックは入力を置き換えるか、`Tool.Error` で失敗できます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

After フックは成功した結果と失敗を確認または置き換えられます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

共有の登録の型は、どの操作がプラグインのスコープを必要とするかを示します。

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## 公開

パッケージのプラグインは、ローカルの Effect プラグインと同じデフォルトエクスポートを使用します。Effect の実装をメインのエントリポイントからエクスポートし、`effect` を `peerDependency` として宣言します。`devDependencies` では `@opencode/plugin` が使用するバージョンに固定し、開発時に 1 つのコピーだけがインストールされるようにします。

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

OpenCode は、`effect`、エクスポートされた `effect/*` サブパス、`@opencode/plugin` のインポート（プラグインの `node_modules` 内の依存関係からのインポートを含む）をホストのランタイムインスタンスにリダイレクトし、ファイバー、ロガー、`Schema` パーサーが 1 つのランタイムコピーを共有するようにします。

- `effect` を公開するプラグインの成果物にバンドルしないでください。バンドラーでビルドする場合は、`effect` と `effect/*` を external に指定します。
- プラグインとその `node_modules` の依存関係は、常にホストの OpenCode リリースの `effect` インスタンスに対して実行されます。対象とする OpenCode のリリースと互換性のある `effect` の API とモジュールパスを使用してください。別の `effect` メジャー（Effect 3 など）で構築された依存関係もホストの `effect` を受け取り、サポートされません。
- 提供されるのは公開されている `effect` のサブパスのみです。Effect のプライベートな `internal` モジュールをインポートするプラグインは、そのパスを示すエラーで読み込みに失敗します。
- コンパイルされた OpenCode のバイナリには、Effect の HTTP API ドキュメントページが使用する Scalar と Swagger UI のアセットが含まれていません。プラグインからそれらのページを提供すると、代わりに通知が表示されます。

パッケージのエントリポイントは、`effect` 関数を持つ `Plugin.define` をエクスポートします。

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

対象とする OpenCode のリリースと互換性のあるバージョンを使用し、ワークスペースにリンクしたコピーだけでなく、インストールしたパッケージをテストしてください。

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
