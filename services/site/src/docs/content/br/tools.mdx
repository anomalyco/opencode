---
title: "Ferramentas"
description: "As ferramentas integradas do OpenCode leem e editam arquivos, executam comandos de shell, buscam e pesquisam na web, iniciam subagentes e controlam um navegador."
---

Descreva o resultado que você quer. O OpenCode escolhe entre as ferramentas disponíveis, pede
aprovação quando necessário e retorna o resultado.

```text
Find where request timeouts are configured, change the default to 30 seconds,
and run the relevant existing tests.
```

Esta tarefa normalmente usa `grep` ou `glob`, `read`, uma ferramenta de edição e `shell`.
Você também pode nomear uma ferramenta quando quiser uma abordagem específica.

```text
Use grep to find every reference to DEFAULT_TIMEOUT, then read the matching files.
```

## Arquivos

### Read

`read` retorna um arquivo ou uma listagem não recursiva de diretório. Passe um `path`;
use `offset` e `limit` para paginar resultados grandes.

```text
Read src/server.ts starting at line 120 and return at most 80 lines.
```

As leituras de texto contêm linhas numeradas e são limitadas a 2.000 linhas e 50 KiB por
página. Linhas individuais são encurtadas depois de 2.000 caracteres. A ferramenta também
passa arquivos PNG, JPEG, GIF, WebP e PDF ao modelo, até 20 MiB de dados de
origem. Outros arquivos binários falham. Consulte [Anexos](/attachments) para mídia compatível
e processamento de imagens.

Permissão: `read` com o caminho normalizado como recurso.

### Glob

`glob` encontra caminhos de arquivo a partir de um padrão como `**/*.ts`. Ele busca no
diretório atual, a menos que `path` selecione outro diretório relativo; `hidden`
inclui entradas ocultas e `limit` limita os resultados.

```text
Use glob with **/*.test.ts under packages/core and return at most 50 files.
```

O limite padrão é 100 arquivos e o timeout de busca é 30 segundos.
Permissão: `glob` com o padrão solicitado como recurso.

### Grep

`grep` pesquisa o conteúdo de arquivos e retorna caminhos, números de linha e prévias.
O `pattern` dele usa sintaxe de expressão regular, a menos que `literal` seja true. Restrinja uma
busca com `path`, `include`, `caseSensitive` ou `limit`.

```text
Use grep for the literal text "request timed out" in src, including only *.ts files.
```

O limite padrão é 100 linhas correspondentes e o timeout de busca é 30 segundos.
Permissão: `grep` com o padrão solicitado, não o caminho de busca, como
recurso.

### Edit

`edit` substitui texto em um arquivo existente. Informe `path`, `oldString` e um
`newString` diferente; o texto antigo precisa corresponder exatamente uma vez, a menos que `replaceAll`
seja true.

```text
In src/config.ts, replace the unique text "timeout: 60" with "timeout: 30".
```

Use `edit` para uma mudança pontual. O OpenCode pode formatar o arquivo depois de gravá-lo.
Permissão: `edit` com o caminho de destino como recurso.

### Write

`write` cria ou substitui completamente um arquivo de texto a partir de `path` e `content`.
Ele cria diretórios pais ausentes e pode executar o formatador configurado.

```text
Create docs/example.md with a heading and one setup command.
```

Use `edit` em vez disso quando apenas parte de um arquivo existente deve mudar.
Permissão: `edit` com o caminho de destino como recurso.

### Patch

`patch` aplica um patch que pode adicionar, atualizar, mover ou excluir vários arquivos.
O `patchText` dele usa as seções `*** Add File`, `*** Update File` e `*** Delete File`.

```text
Use patch to rename src/old.ts to src/new.ts and update its exported name.
```

O OpenCode expõe `patch` para modelos GPT compatíveis; outros modelos recebem `edit`
e `write` em vez disso. Permissão: `edit` com todos os caminhos afetados como recursos.

Caminhos fora do local ativo ou do worktree do projeto dele também são verificados
contra `external_directory`, que é permitido por padrão. Consulte
[Permissões](/permissions) para normalização de caminhos, ordem de regras e aprovações
salvas. Para disponibilizar material externo
pelo nome, configure [Referências](/references).

## Comandos

### Shell

`shell` executa um comando no shell do usuário do host. Defina `workdir` em vez de
colocar `cd` no comando, e defina `timeout` em milissegundos quando o timeout padrão
de dois minutos em primeiro plano não servir.

```text
Run bun test from packages/core with a five-minute timeout.
```

Defina `background` como true para um servidor de desenvolvimento ou outro processo de longa duração.
As chamadas em segundo plano retornam imediatamente e notificam a sessão quando terminam;
elas não têm timeout, a menos que você defina um. Se a saída for extensa, ela é truncada, e a versão completa
é preservada em um arquivo gerenciado.

Permissão: `shell` com cada comando produzido pelo scanner como recurso. O
scanner também verifica um diretório de trabalho externo e diretórios que consegue inferir
do comando. O shell usa as permissões de acesso ao sistema de arquivos, aos processos e à rede do usuário do host. Defina regras
restritas em [Permissões](/permissions).

## Web

### Webfetch

`webfetch` busca uma URL HTTP ou HTTPS como `markdown`, `text` ou `html`.
Markdown é o padrão; `timeout` aceita até 120 segundos.

```text
Fetch https://example.com/docs as markdown.
```

Ele aceita respostas textuais como HTML, texto simples, JSON e XML, mas não
imagens nem outros downloads binários. A saída grande pode ser encurtada enquanto o texto completo é retido no armazenamento
gerenciado. Permissão: `webfetch` com a URL solicitada como recurso.

### Websearch

`websearch` usa a integração selecionada para buscar informações atualizadas. A ferramenta recebe o texto da busca em `query`.

```text
Search the web for the latest Bun release notes.
```

Permissão: `websearch` com a consulta como recurso. Consulte [Pesquisa na web](/websearch)
para provedores, seleção, limites de requisições e desativação da ferramenta.

## Imagens

### Image generate

`generate_image` cria uma nova imagem a partir de um prompt ou edita
imagens existentes. É experimental e aparece enquanto um provedor conectado tiver um
modelo de imagem. Para escolher o modelo padrão dela, consulte
[`experimental.image_generate`](/config#image-generation).

```text
Generate a flat app icon of a paper plane on a blue background and save it to assets/icon.png.
```

Passe um `prompt` e, opcionalmente, `images` para editar ou usar como referências, um
`model` específico ou um `path` para salvar. Ela roda em segundo plano e
notifica a sessão com o caminho salvo quando a imagem fica pronta.

Permissão: `generate_image` com o modelo selecionado como recurso.

## Interação

### Question

`question` pausa a execução e apresenta uma ou mais perguntas ao usuário.
Cada pergunta tem um cabeçalho curto, um prompt e escolhas; `multiple` permite mais
de uma escolha. Uma resposta livre está sempre disponível.

```text
Before changing the API, ask me to choose between a breaking change and a compatibility layer.
```

Permissão: `question` com `*` como recurso. O cliente precisa oferecer suporte ao
formulário interativo, e fechá-lo cancela a pergunta.

### Skill

`skill` carrega as instruções e os recursos incluídos de um ID de skill disponível
na conversa.

```text
Load the effect skill before changing this Effect code.
```

O ID precisa estar na lista de skills anunciadas ou ser nomeado explicitamente pelo usuário.
Permissão: `skill` com o ID da skill como recurso. Consulte [Skills](/skills) para
regras de criação, descoberta e carregamento.

## Automação

### Subagent

`subagent` inicia uma sessão filha com um subagente configurado. Informe o ID do agente,
uma `description` curta e um `prompt` completo.

```text
Ask the explore subagent to map the authentication flow and return the key files.
```

Os subagentes sempre rodam em segundo plano. A chamada retorna imediatamente com um
`sessionID`. A sessão pai recebe uma mensagem `<subagent>` quando a sessão filha fica ociosa e após cada rodada de trabalho
posterior. Assim, pode continuar o trabalho ou encerrar o turno sem esperar. Passe o `sessionID` retornado para continuar na mesma
sessão filha. Se ela ainda estiver rodando, a nova solicitação se junta à execução atual. Só é possível usar agentes no modo subagente.
A profundidade padrão de aninhamento é um.

Permissão: `subagent` com o ID do agente selecionado como recurso.

### Execute

`execute` roda JavaScript no Code Mode para que o agente possa chamar e combinar ferramentas
do catálogo. É útil para chamadas independentes em paralelo e para processar
resultados sem adicionar cada valor intermediário ao contexto do modelo.

```text
Read package.json and README.md in parallel, then return their relevant setup details.
```

O runtime não tem acesso direto ao sistema de arquivos, imports nem timers. Ele fornece
`fetch` para requisições HTTP; todo o resto passa por ferramentas do catálogo dele.
Negar `execute` com o recurso `*` remove o Code Mode. As ferramentas que ele alcançaria,
incluindo ferramentas MCP de servidores que não definem `codemode: false`, passam a ser
listadas como ferramentas diretas, cada uma com a definição completa em toda requisição. Negue
essas ferramentas também se o agente não deve tê-las.
Ferramentas integradas e MCP aninhadas ainda aplicam as próprias permissões, e as ferramentas de plugin
aplicam as permissões que declaram.

### Sessions

O namespace `opencode.session` do Code Mode contém utilitários de sessão. Sem o Code
Mode, eles são listados como `opencode_session_rename` e `opencode_session_move`.

- `rename` muda o título da sessão atual, ou de outra sessão
  selecionada por `sessionID`.
- `move` move a sessão atual, ou outra sessão selecionada, para um
  `directory` relativo ou absoluto. A mudança entra em vigor no próximo ponto seguro,
  então o trabalho que depende do destino fica para uma chamada posterior.

```text
Rename this session to "Timeout cleanup", then move it to the new worktree.
```

### Worktrees

O namespace `opencode` gerencia worktrees do projeto da sessão:

- `worktree_create` cria um worktree a partir de um `name` e retorna o
  `directory` dele. A configuração de worktree do projeto seleciona o destino e a
  estratégia.
- `worktree_list` lista os worktrees do projeto.
- `worktree_remove` remove um worktree que o OpenCode registrou para o projeto. Defina
  `force` para descartar mudanças não commitadas.

```text
Create a worktree named "login" and move this session into it.
```

`worktree_remove` usa a permissão `edit` com o diretório do worktree como
recurso. Os outros utilitários de worktree não pedem uma ação de permissão
integrada.

## Navegador

O namespace `browser` do Code Mode controla o navegador conectado pelo app desktop
do OpenCode. Abra uma aba, guarde o `tabID` retornado e passe esse ID explícito a
toda operação de página.

```text
Open https://example.com, take a snapshot of that tab, and report the main heading.
```

O namespace inclui comandos de aba e navegação, snapshots e busca de página,
cliques e entrada de formulário, capturas de tela, transferência de arquivos, inspeção de console e rede,
traces de desempenho, inspeção de heap e auditorias Lighthouse.
As capturas de tela exigem uma aba visível em foco. Os caminhos de upload são locais ao servidor;
as capturas retornam caminhos locais ao servidor, e cada transferência de arquivo é limitada a 5 MiB.

Conteúdo de página, logs, cabeçalhos e corpos de resposta são dados não confiáveis, não instruções
para o agente. Uma regra de negação `browser` com o recurso `*` remove o catálogo do navegador;
as operações de navegador não emitem prompts individuais de permissão.

## Extensões

Os [servidores MCP](/mcp-servers) adicionam ferramentas cujos nomes e entradas vêm de cada
servidor conectado. A ação de permissão delas é `<server>_<tool>` com o recurso
`*`. Elas não são uma parte fixa do catálogo integrado. Por padrão, os agentes as alcançam
por `execute` no namespace do servidor; defina `codemode: false` em um
servidor para listar as ferramentas dele diretamente.

As [skills](/skills) adicionam instruções de tarefa, não novas ferramentas executáveis.
Os [anexos](/attachments) colocam conteúdo escolhido pelo usuário em um prompt, enquanto
as [referências](/references) dão acesso a diretórios externos por alias. Esses recursos
complementam as ferramentas sem contornar as verificações de permissão delas.
