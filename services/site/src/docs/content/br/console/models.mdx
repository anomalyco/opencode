O OpenCode Console oferece uma lista de modelos testados e verificados pela equipe do OpenCode. Entre, adicione créditos e obtenha uma
chave de API para usá-los com o OpenCode ou outro agente de codificação.

O Console funciona como qualquer outro provedor no OpenCode. Ele é **totalmente opcional**, e você pode usar qualquer outro provedor
em vez dele. Para uma assinatura com uso incluído, consulte o [OpenCode Go](/console/go).

## Como funciona

1. Entre no [Console](https://opencode.ai/console), informe seus dados de cobrança, adicione créditos e copie sua chave de API.
2. Execute `/connect` na TUI, escolha o provedor de pagamento por uso do OpenCode e cole a sua chave de API.

   ```text
   /connect
   ```

3. Execute `/models` para ver os modelos disponíveis e selecionar um.

   ```text
   /models
   ```

Você é cobrado por requisição e pode adicionar créditos à sua conta.

### Jev

O Jev é um modelo System One da TypeSafe AI para decisões rápidas e estruturadas. Em vez de gerar texto, ele avalia um `state` com perguntas tipadas e retorna valores e probabilidades que o seu código pode usar diretamente. Ele oferece suporte a perguntas de sim/não (`noul`), de múltipla escolha (`choice`) e baseadas em rubrica (`score`).

Use a sua chave de API do OpenCode Console com o endpoint `https://opencode.ai/inference/systemone/v1/systemone`. Este exemplo verifica se uma solicitação de suporte é urgente:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Você pode fazer várias perguntas em uma requisição. O Jev as avalia em paralelo e retorna cada resposta sob o ID da pergunta correspondente:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Use `jev-1.13-free` para usar o modelo grátis por tempo limitado, que executa o Jev 1.13. Consulte a [documentação da TypeSafe AI](https://docs.typesafe.ai/) para detalhes sobre os tipos de pergunta e os campos de resposta.

### GPT 6 Luna Decision e Gemini Decision 1

`gpt-6-luna-decision` e `gemini-decision-1` aceitam a mesma requisição System One do Jev, no mesmo endpoint. Passe imagens, áudio, vídeo e PDFs em `state` como partes no estilo de chat (`image_url`, `input_audio`, `video_url`, `file`). O GPT 6 Luna Decision aceita texto e imagens; o Gemini Decision 1 também aceita áudio, vídeo e PDFs.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### Modelos de imagem

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` e `grok-imagine-image-2.0` geram e editam imagens. Eles não são modelos de chat, então nunca aparecem em `/models` nem no endpoint de modelos,
e `opencode/<model-id>` não os seleciona. Chame-os na API nativa deles com uma chave do Console, ou deixe a ferramenta
[`generate_image`](/tools#image-generate) do OpenCode usar um modelo de imagem definindo
`experimental.image_generate.model`, por exemplo `opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

O Google usa os próprios `contents` e `generationConfig`, e o xAI as próprias opções, como `resolution` e
`quality`. OpenAI Images e xAI Images também aceitam edições em `/images/edits`.

### Modelos de embedding

`text-embedding-3-small`, `qwen3-embedding-8b` e os demais modelos de embedding da tabela acima transformam texto em
vetores. O OpenCode não os usa para chat, então eles nunca aparecem em `/models`, e o nível gratuito não os inclui.
O [Go](/console/go#embedding-models) inclui alguns deles. Chame-os na API Embeddings da OpenAI com uma chave do Console.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` aceita uma string ou um array de strings. `data` retorna um vetor por entrada, na mesma ordem.
- `dimensions` encurta os vetores nos modelos que oferecem suporte, como `text-embedding-3-small`.
- `encoding_format: "base64"` retorna os vetores codificados em base64 em vez de floats.
- Cada entrada precisa caber na janela de contexto do modelo.
- A resposta informa `usage.cost` como qualquer requisição de inferência. Consulte [Custo](/console/api/inference#cost).

Vetores de modelos diferentes não são comparáveis, então gere os embeddings dos seus documentos e das suas consultas com o mesmo modelo. Um
[provedor conectado](/console/api/providers#endpoints) serve os próprios modelos de embedding em `/embeddings`.

## Contexto

Há muitos modelos disponíveis, mas só alguns funcionam bem como agentes de codificação. Os provedores também variam em configuração,
desempenho e qualidade, então um modelo acessado por um gateway como o OpenRouter pode ter desempenho diferente.

<Callout type="tip">Testamos um grupo seleto de modelos e provedores que funcionam bem com o OpenCode.</Callout>

Para montar este catálogo, nós:

1. Testamos um grupo seleto de modelos e conversamos com as equipes deles sobre a melhor forma de executá-los.
2. Trabalhamos com provedores para garantir que os modelos fossem servidos corretamente.
3. Medimos o desempenho de cada combinação de modelo e provedor para criar uma lista que podemos recomendar com confiança.

O Console é um gateway de AI que dá acesso a esses modelos.

## Objetivos

Criamos o Console para:
