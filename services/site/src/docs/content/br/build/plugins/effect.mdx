title: "Plugins Effect"
description: "Escreva plugins de servidor com a API de plugins nativa de Effect."
---

O `@opencode/plugin/effect` é a versão nativa de Effect da API de plugins do OpenCode. As operações de contexto dele retornam
Effects ou Streams, os callbacks retornam Effects, e o tempo de vida do plugin é representado por `Scope`.

O OpenCode fornece `effect` (incluindo os subcaminhos `effect/*` exportados) e `@opencode/plugin` em tempo de execução ao carregar
plugins e as dependências `node_modules` deles. Instale-os como dependências peer/dev para checagem de tipos e testes locais,
em vez de empacotá-los no seu plugin.

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

Exporte um plugin Effect de `.opencode/plugins/` para carregá-lo automaticamente.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Pacotes publicados e diretórios de plugin fora de `.opencode/plugins/` usam a mesma configuração `plugins` dos outros plugins
de servidor.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Consulte [Configurar plugins](/plugins) para ativação, resolução de pacotes e precedência de configuração.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Ciclo de vida

O `effect` roda quando o plugin é carregado. Ao recarregar ou descarregar o plugin, o escopo é fechado e o Effect libera os registros e as fibras
do escopo e executa os finalizadores.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Use fibras com escopo para trabalho em segundo plano. O escopo do plugin interrompe a fibra durante a limpeza.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Contexto

O contexto expõe o cliente Effect do servidor OpenCode conectado, além de transformações, hooks, armazenamento,
recargas e opções exclusivos de plugin. Ele não expõe os serviços privados do Core do OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

A definição do plugin e o contexto completo são declarados assim.

```ts
interface Context {

  readonly options: PluginOptions

  readonly aisdk: AISDKDomain

    readonly generate: GenerateApi<unknown>
  }
  readonly integration: IntegrationDomain
  readonly mcp: MCPDomain
  readonly model: ModelDomain
  /** @deprecated Use `experimental.generate.text`. */
  readonly generate: Pick<ExperimentalGenerateApi<unknown>, "text">
  readonly permission: PermissionDomain
  readonly plugin: Pick<PluginApi<unknown>, "list">
  readonly provider: ProviderDomain
  readonly reference: ReferenceDomain
  readonly rpc: RpcDomain
  readonly session: SessionDomain
  readonly shell: ShellDomain
  readonly skill: SkillDomain
  readonly storage: StorageDomain
  readonly tool: ToolDomain

  readonly worktree: WorktreeDomain
}

interface Plugin<R = Scope.Scope> {
  readonly id: string
  readonly effect: (context: Context) => Effect.Effect<void, never, R>
}
```

### Opções

Passe opções com a forma de objeto em `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Leia as opções de `ctx.options`. Restrinja valores desconhecidos antes de usar.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transformações

As transformações editam o estado de forma síncrona por um editor. O OpenCode aplica transformações na ordem de registro dentro de cada
domínio. As fontes contribuem com provedores e definições de modelo imutáveis primeiro; as transformações de modelo depois editam os
candidatos dos provedores ativos. Use yield para manter o registro no escopo do plugin.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Uma transformação de modelo pode impor política na coleção completa de candidatos de provedores ativos.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Chame `reload` quando o estado externo usado por uma transformação mudar. Aqui, `loadFromSource()` retorna
entradas `{ info: Provider.Info, models: readonly Model.Info[] }`; recargas de provedor também invalidam todo o resultado de modelo.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agentes

Leia todos os agentes ou busque um por ID. As respostas do cliente incluem a location resolvida e os dados de schema.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transforme ou recarregue agentes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {

  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Provedores

Leia os provedores disponíveis ou inspecione os metadados de um provedor por ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

As transformações de provedor editam configurações de provedor e definições de fonte. As leituras do editor incluem provedores inativos e expõem
definições imutáveis; `models.update` edita uma cópia própria de um modelo de fonte.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Substitua um inventário de fonte com `models.set` e recarregue depois que as definições capturadas mudarem.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Para descoberta específica de conta, passe a conexão usada para carregar o inventário como `sourceConnection`. O OpenCode exclui
esse provedor enquanto outra conexão estiver selecionada, até o seu plugin publicar o inventário atualizado dele.

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

Schemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

### Modelos

Leia os modelos disponíveis e a seleção padrão.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

As transformações de modelo editam a coleção completa de candidatos de provedores ativos. Candidatos desativados continuam editáveis até todas
as transformações terminarem; `update` só pode adicionar um modelo em um provedor disponível.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Os callbacks editam substituições brutas de modelo. Os padrões do provedor são mesclados uma vez quando o OpenCode confirma o resultado; leituras inalteradas
reutilizam esse resultado. `editor.provider` lê definições de origem imutáveis, incluindo templates inativos, em vez do
resultado da transformação de modelo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).

```ts
interface ModelEditor {
  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined

  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined
    set(providerID: string, modelID: string): void
  }
  readonly provider: {
    list(): readonly ProviderRecord[]

  }

}
```

### Comandos

Leia os comandos disponíveis na location atual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

A transformação de comando atual é somente adição. Um executor recebe a sessão, os anexos do prompt e o modo de entrega.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schemas: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Integrações

Leia integrações e resolva a credencial ativa quando existir uma.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Conecte com uma chave ou conduza uma tentativa OAuth pela API conectada.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transforme integrações e métodos de autenticação. Os callbacks de método OAuth são Effects e podem adquirir
recursos com escopo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

### MCP

Liste servidores MCP e o estado atual de conexão deles.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Os plugins gerenciam servidores MCP apenas por transformações. Use `editor.set` para adicionar ou substituir um servidor, `editor.update` para
mudar a configuração dele e `editor.remove` para removê-lo. Inspecione a configuração com `editor.list` e `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Defina `disabled: true` em uma transformação para desativar um servidor e desconectá-lo, ou `disabled: false` para ativá-lo e permitir
que o OpenCode se conecte. O OpenCode reconcilia o ciclo de vida do servidor a partir da configuração transformada.

Chame `reload()` depois que o estado externo usado por uma transformação mudar, para reaplicar as transformações e reconciliar os servidores.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schemas: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

### Plugins

Liste plugins ativos, com falha e resolvidos na location atual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)

```

Filtre os valores de schema em um pipeline Effect quando apenas plugins ativos importarem.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.state.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

### Referências

Leia as referências disponíveis na location atual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Adicione ou remova referências locais e Git e recarregue depois que o estado externo mudar. `get(name)` retorna a fonte configurada
atual, ou `undefined` quando o nome está ausente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

Schemas: [`Reference.Info`](/api#schema-Reference.Info), [`Reference.LocalSource`](/api#schema-Reference.LocalSource),
[`Reference.GitSource`](/api#schema-Reference.GitSource).

```ts
interface ReferenceEditor {
  add(name: string, source: ReferenceLocalSource | ReferenceGitSource): void
```

### Ferramentas

Registre ferramentas tipadas com `Schema` do Effect. O executor recebe a entrada decodificada e retorna um Effect contendo saída tipada,
conteúdo de exibição ou metadados.

O editor aceita `add`, `update` e `remove`. O callback de transformação é síncrono: ele não pode retornar um Effect nem uma Promise. Carregue
dados externos antes de registrar ou recarregar. O OpenCode reaplica as transformações ativas na ordem de registro em um editor
novo; para o mesmo nome efetivo de ferramenta, um registro válido posterior substitui um anterior.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Chame `yield* ctx.tool.reload()` depois de mudar dados de origem capturados pelo callback. A recarga reaplica as transformações ativas
sem mudar a ordem delas; ela não roda de novo o effect do plugin.

As ferramentas Effect aceitam a mesma [declaração de entrada em formato livre](/build/plugins/server#freeform-tool-input) das ferramentas Promise. Se o modelo não anuncia esse formato, a ferramenta mantém a entrada de objeto normal.

As ferramentas têm um `id` que contém o nome efetivo delas, e `get()` retorna `undefined` quando esse ID não está presente. Use
`update` e `remove` com o nome efetivo da ferramenta, incluindo o namespace dela (`acme_greeting` acima). Pontos em
namespaces viram `_`. Nos nomes das ferramentas, qualquer caractere que não seja letra, dígito, `_` ou `-` vira `_`.
Nomes ausentes são ignorados. Para criar uma ferramenta, use `add` com uma definição completa.
As atualizações preservam o nome e o namespace. Atribua novos schemas ou opções para substituí-los
em vez de mutar valores aninhados. Atualizações inválidas são registradas e deixam a definição anterior intacta.

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Atualizações e remoções são reaplicadas em ordem com as adições, inclusive depois de atualizações do catálogo MCP.

`transform` retorna um registro com escopo. Execute `yield* registration.dispose` para remover a transformação dele e reconstruir
a partir das transformações restantes, revelando qualquer definição anterior que ele substituía. O descarte é idempotente, e fechar
o escopo do plugin também descarta os registros dele.

Cada requisição de modelo captura um snapshot de ferramentas. Recarga e descarte afetam snapshots futuros, não as definições nem os
executores já capturados por uma requisição existente. Executores que acessam dados mutáveis do plugin por closure continuam vendo as alterações nesses dados.
Para vincular um valor à definição, capture esse valor dentro da transformação.

Schemas: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Os hooks interceptam operações ao vivo. Vários plugins podem registrar o mesmo hook; o OpenCode os executa na ordem dos plugins, então
hooks posteriores veem mudanças anteriores. Os registros ficam ativos durante o escopo do plugin.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sessões

Modifique instruções de sistema, mensagens ou ferramentas montadas imediatamente antes do despacho ao modelo. `context` roda para o
loop do agente; `compaction`, `generate` e `title` rodam para essas requisições auxiliares. `compaction` e `title` aceitam um
`result` que pula a chamada ao modelo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

As mensagens nos hooks `context`, `compaction` e `generate` trazem o campo `metadata` da mensagem armazenada, em modo somente leitura
(por exemplo, o que um hook `prompt` definiu). Esses metadados não são enviados ao modelo.

A parte `system` que contém as instruções do OpenCode também lista cada fonte em `metadata.experimental.instructions` como
`{ key, text }`, como `core/date` ou `core/environment`, para que um hook consiga distinguir as fontes. A lista é uma cópia:
editar o `text` da parte não a atualiza. Isso é experimental e pode mudar.

Modifique configurações de requisição de modelo e, opcionalmente, limite o hook a um provedor. O evento carrega o mesmo `kind`
dos hooks HTTP abaixo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Modifique requisições ou respostas nativas do provedor. Os corpos delas são streams de uso único; clone ou substitua um corpo antes de lê-lo.
Os dois hooks rodam para toda requisição que uma sessão emite; `event.kind` é `"primary"`, `"compaction"`, `"title"` ou
`"generate"`, conforme o fluxo que a emitiu.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Provedores que transmitem por WebSocket reutilizam uma conexão por sessão, então os hooks HTTP nunca veem esse tráfego. O
hook experimental `experimental.ws.handshake` roda uma vez por chamada de modelo antes de a conexão ser selecionada e expõe a
`url` e os `headers` da conexão; mudar qualquer um reabre o socket. Os hooks HTTP ainda rodam para qualquer requisição em que uma rota WebSocket
recorra a HTTP.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` e `experimental.ws.receive` expõem os próprios frames: `send` roda depois que o driver do provedor
monta um frame de saída, `receive` roda em cada frame de entrada antes de o driver observá-lo. O que `frame` contiver quando o hook retornar é o que cruza a rede ou chega ao driver;
o OpenCode não o valida.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Substitua a decisão de nova tentativa de uma falha de provedor ou o atraso dela em milissegundos. O hook roda depois que o OpenCode
classifica a falha e propõe a política dele, mas antes de qualquer nova tentativa ser agendada. Ele não expõe como o OpenCode
executa internamente a próxima tentativa.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

A `decision` inicial é a política do OpenCode, então os hooks podem tornar uma falha de provedor normalmente terminal passível de nova tentativa ou vetar uma
nova tentativa proposta. Vários hooks rodam na ordem de registro, e hooks posteriores veem a decisão atual. O número máximo de tentativas
integrado continua sendo um limite rígido. `attempt` é a tentativa física sendo proposta; a requisição inicial é a tentativa `1`,
então a primeira nova tentativa é a tentativa `2`. Atrasos inválidos (`NaN`, infinito ou valores negativos) recaem no atraso calculado.
A recuperação de estouro de contexto continua separada, porque compacta a conversa em vez de repetir a mesma requisição.

#### Referência

```ts
interface ShellCreateBefore {
  command: string
  cwd: string
  timeout: number
  shell: string
  env: Record<string, string | undefined>
}

interface ShellHooks {
  readonly "create.before": ShellCreateBefore
}

interface ShellHookDomain {
  readonly hook: Hooks<ShellHooks>
}
```

### Ferramentas

Os hooks que rodam antes da execução podem substituir a entrada ou falhar com `Tool.Error`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

Os hooks que rodam após a execução podem inspecionar ou substituir os resultados de sucesso e de falha.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

#### Referência

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

Os tipos de registro compartilhados mostram quais operações exigem o escopo do plugin.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publicar

Um plugin de pacote usa o mesmo export padrão de um plugin Effect local. Exporte a implementação Effect pelo entrypoint principal
e declare `effect` como `peerDependency`. Em `devDependencies`, fixe a versão que `@opencode/plugin` usa
para que as instalações de desenvolvimento tenham apenas uma cópia.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

O OpenCode redireciona imports de `effect`, dos subcaminhos `effect/*` exportados e de `@opencode/plugin` (incluindo imports de
dependências no `node_modules` do plugin) para as instâncias de runtime do host, para que fibras, loggers e analisadores `Schema`
compartilhem uma cópia de runtime.

- Não empacote `effect` no artefato publicado do plugin. Se você usa um bundler, marque `effect` e `effect/*`
  como externos.
- Os plugins e suas dependências em `node_modules` sempre usam a instância de `effect` da versão do OpenCode no host.
  Use APIs e caminhos de módulo de `effect` compatíveis com a versão do OpenCode a que o plugin se destina. Dependências feitas para outra
  versão principal de `effect` (como Effect 3) também recebem o `effect` do host e não são compatíveis.
- Apenas subcaminhos públicos de `effect` são fornecidos. Um plugin que importa um dos módulos `internal` privados do Effect falha ao
  carregar com um erro que nomeia o caminho.
- O binário compilado do OpenCode não inclui os ativos de Scalar e Swagger UI usados pelas páginas de documentação da API HTTP do Effect;
  servir essas páginas a partir de um plugin mostra um aviso.

O entrypoint do pacote exporta `Plugin.define` com uma função `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Use versões compatíveis com a versão do OpenCode que você tem como alvo e teste o pacote instalado, não apenas uma
cópia vinculada ao workspace.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
