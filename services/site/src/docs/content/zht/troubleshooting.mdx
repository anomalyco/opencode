<Callout type="tip">
  你可以請 OpenCode 自我偵錯。描述問題並請它使用這個疑難排解頁面；它可以閱讀
  下列步驟、檢查其服務與日誌，並協助找出問題。
</Callout>

OpenCode 使用用戶端-伺服器架構。背景伺服器擁有工作階段、外掛、權限與其他應用程式
狀態。請先判斷問題出在用戶端、共用的伺服器，還是特定專案。

## 檢查背景服務

顯示目前的伺服器資訊：

```bash
opencode service status
```

確認服務的 API 是否正常：

```bash
opencode api get /api/info
```

若服務卡住或運作異常，請重新啟動：

```bash
opencode service restart
```

你也可以明確停止並啟動它：

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  OpenCode 通常會自動探索或啟動共用的背景服務。只有在診斷其生命週期時才需要
  服務指令。
</Callout>

## 允許瀏覽器來源

若另一個來源的瀏覽器用戶端因 CORS 無法連線，請將該用戶端的來源加入服務設定：

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

請使用確切的 HTTP 或 HTTPS 來源，需要時包含連接埠，不要有路徑或結尾斜線。若要允許多個
來源，請以逗號分隔清單作為單一引數傳入；每個來源前後的空白會移除：

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` 會輸出 JSON 陣列。移除設定的清單：

```bash
opencode service unset cors
```

設定或取消設定服務設定會停止背景服務。它下次啟動時會採用新設定；
請使用 `opencode service start` 明確啟動它。

對於前景伺服器，請為每個額外允許的來源重複 `--cors`：

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

使用 `serve --service` 時，提供的 `--cors` 旗標會覆寫該處理程序已保存的清單。沒有這些旗標時，服務
模式會使用已保存的清單。CORS 不會變更監聽位址，也不會繞過伺服器驗證。

## 檢視 API

`api` 指令會使用本機服務探索與驗證流程。它接受 HTTP 方法與路徑，或
OpenAPI 操作 ID。

所有端點與操作 ID 請參閱 [API 參考](/api)。

使用 `--data` 或 `-d` 傳入 JSON 請求主體，並使用 `--header` 或 `-H` 新增標頭。

<Callout type="warning">
  若沒有相容且正常運作的服務，執行 `opencode api` 可能會啟動背景服務。
</Callout>

## 讀取日誌

已安裝的版本會將日誌寫入：

```text
~/.local/share/opencode/log/opencode.log
```

重現問題時，請持續追蹤日誌：

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

每一行都包含處理程序 `run` ID 與 `role` 欄位。工作階段、供應商、外掛、權限與
工具活動請使用 `role=server`。

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## 擷取堆積快照

在任一平台上寫入執行中背景伺服器的記憶體（堆積）快照：

```bash
opencode debug heap-dump
```

此指令會等到快照完成，然後印出其路徑：

```text
/home/me/.local/share/opencode/log/heap-48213-2026-10-23T013012345Z.heapsnapshot
```

使用 `--directory` 將它寫到其他地方。伺服器會在目錄缺少時建立它：

```bash
opencode debug heap-dump --directory ./snapshots
```

- 它只會使用已在執行的伺服器。它絕不會啟動、取代或重新啟動伺服器。
- 使用 `--server <url>` 擷取你以 `opencode serve` 啟動的伺服器。若有密碼，請設定 `OPENCODE_PASSWORD`。
  此時 `--directory` 是伺服器機器上的路徑。
- 在 Chrome DevTools 的 Memory 面板中開啟該檔案。

<Callout type="warning">
  伺服器在寫入快照時會暫停，且其記憶體用量可能短暫增加。快照可能
  包含提示詞、檔案內容與憑證。請勿公開分享。
</Callout>

### 在桌面應用程式中

從指令面板執行 **Capture heap snapshots**。這個指令會在「下載」資料夾中建立子資料夾，內含應用程式各部分的快照，
以及快照無法顯示的記憶體明細：

```text
opencode-heap-2026-10-23T013012345Z/
  memory.json                  where the memory is, per process, in MiB: start here
  memory-infra.json            Chromium's memory dump trace; open it in https://ui.perfetto.dev
  heap-48213-….heapsnapshot    the desktop's own server
  window-1-48390.heapsnapshot  one per app window
  main-48102.heapsnapshot      the desktop main process
  gpu.json                     the GPU and driver
  manifest.json                processes, PIDs, and memory before and after; written last
```

- 堆積快照只包含 JavaScript 物件與頁面。圖片、版面、合成器圖層與 GPU 記憶體會改放在
  `memory.json` 與 `memory-infra.json` 中。
- 不會擷取遠端伺服器。請改在該機器上使用 `opencode debug heap-dump`。
- 伺服器會直接將快照寫入資料夾，因此不會移動或複製大型檔案。
- 不包含瀏覽器分頁，因為其快照會包含你造訪過的頁面內容。

## 擷取 CPU 與記憶體效能分析

在 macOS 與 Linux 上，你可以向執行中的 OpenCode 處理程序傳送訊號，以擷取診斷資料。請從健康狀態端點取得背景伺服器 PID：

```bash
opencode api get /api/info
```

使用回應中的 `pid` 搭配下列其中一種訊號：

- `SIGPROF` 會擷取十秒的 CPU 效能分析：

  ```bash
  kill -SIGPROF <pid>
  ```

  結果會以 `cpu-<pid>-<timestamp>.cpuprofile` 寫入日誌目錄。

- `SIGUSR1` 會擷取記憶體（堆積）快照：

  ```bash
  kill -SIGUSR1 <pid>
  ```

  結果會以 `heap-<pid>-<timestamp>.heapsnapshot` 寫入日誌目錄。

開啟檔案前，請先在 `opencode.log` 中等待 `CPU profile written` 或 `heap snapshot written`。對應的
日誌項目會包含其完整路徑。你可以在 Chrome DevTools 中檢視這兩種檔案。

<Callout type="note">
  Windows 不支援訊號觸發的效能分析。堆積快照請改用 `opencode debug heap-dump`。
  寫入堆積快照可能會暫停處理程序，並暫時增加其記憶體用量。
</Callout>

## 服務檔案

共用的伺服器會將自身註冊於：

```text
~/.local/state/opencode/service.json
```

其私有的服務設定會另外儲存在：

```text
~/.config/opencode/service.json
```

資料庫通常位於：

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` 可以覆寫資料庫位置。

<Callout type="warning">
  疑難排解期間，請勿刪除或編輯服務檔案或資料庫。請使用服務指令管理
  常駐程式，並在使用外部工具檢視持久資料前先備份。
</Callout>

## 回報問題

回報可重現的問題時，請包含下列內容：

- `opencode --version` 的輸出
- `opencode service status` 的輸出
- 能重現問題的最短步驟序列
- 問題影響的是共用服務、特定用戶端，還是單一專案
- 相關日誌行，包括其 `run` 與 `role` 欄位

分享日誌前，請移除 API 金鑰、授權標頭、提示詞、檔案內容與其他敏感資料。

請在 [GitHub Issues](https://github.com/anomalyco/opencode/issues) 回報可重現的問題。
