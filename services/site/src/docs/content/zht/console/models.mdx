OpenCode 控制台提供一份經 OpenCode 團隊測試與驗證的模型清單。登入、新增額度並取得
API 金鑰，即可在 OpenCode 或其他編碼 agent 中使用它們。

控制台的運作方式與 OpenCode 中的其他供應商相同。它**完全為選用**，你也可以改用任何其他供應商。
若需要包含用量的訂閱，請參閱 [OpenCode Go](/console/go)。

## 運作方式

1. 登入[控制台](https://opencode.ai/console)、新增帳單詳細資料與額度，並複製 API 金鑰。
2. 在 TUI 中執行 `/connect`、選擇 OpenCode 的按用量計費供應商，並貼上 API 金鑰。

   ```text
   /connect
   ```

3. 執行 `/models` 查看可用模型並選擇一個。

   ```text
   /models
   ```

你會依請求付費，並可為帳號新增額度。

## 端點

你也可以直接透過下列 API 端點存取模型。免費方案聊天模型只能在 OpenCode 中使用；
其他用戶端請使用付費模型或 [Go](/console/go)。

每個模型都會列出其原生 API，但所有文字模型也可透過其他 API 使用，由控制台
轉譯。完整清單請參閱[基礎 URL](/console/harnesses#base-urls)。

### 模型清單

從模型端點擷取可用模型的完整清單及其中繼資料：

```bash
curl https://opencode.ai/inference/v1/models
```

回應中的每個欄位，以及同時包含工作區已連接供應商的控制台清單，請參閱[模型清單 API](/console/api/models)。

### Jev

Jev 是 TypeSafe AI 的 System One 模型，用於快速、結構化的決策。它不產生文字，而是依具型別的問題評估 `state`，
並回傳你的程式碼可直接使用的值與機率。它支援是非題（`noul`）、選擇題（`choice`），以及
依評分標準作答的題型（`score`）。

使用你的 OpenCode 控制台 API 金鑰搭配 `https://opencode.ai/inference/systemone/v1/systemone` 端點。此範例會檢查支援請求是否緊急：

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

你可以在一個請求中提出多個問題。Jev 會平行評估它們，並在對應的問題 ID 下回傳每個答案：

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

使用 `jev-1.13-free` 可使用限時免費模型，它會執行 Jev 1.13。問題類型與回應欄位的詳細資訊請參閱
[TypeSafe AI 文件](https://docs.typesafe.ai/)。

### GPT 6 Luna Decision 與 Gemini Decision 1

`gpt-6-luna-decision` 與 `gemini-decision-1` 會在相同端點接受與 Jev 相同的 System One 請求。請以聊天式組件
（`image_url`、`input_audio`、`video_url`、`file`）在 `state` 中傳入圖片、音訊、影片與 PDF。GPT 6 Luna Decision
接受文字與圖片；Gemini Decision 1 也接受音訊、影片與 PDF。

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### 圖片模型

`gpt-image-2.5-sunburst`、`gemini-nano-banana-2.1` 與 `grok-imagine-image-2.0` 會產生與編輯圖片。它們不是聊天模型，因此永遠不會出現在 `/models` 或模型端點中，
且 `opencode/<model-id>` 不會選取它們。請以控制台金鑰在其原生 API 上呼叫它們，或讓 OpenCode 的
[`generate_image`](/tools#image-generate) 工具使用圖片模型，方法是設定
`experimental.image_generate.model`，例如 `opencode/gpt-image-2.5-sunburst`。

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google 接受其原生 `contents` 與 `generationConfig`，xAI 則接受其原生選項，例如 `resolution` 與
`quality`。OpenAI Images 與 xAI Images 也會在 `/images/edits` 接受編輯。

### 嵌入模型

`text-embedding-3-small`、`qwen3-embedding-8b` 與上表中的其他嵌入模型會將文字轉為
向量。OpenCode 不會將它們用於聊天，因此它們永遠不會出現在 `/models`，免費方案也不包含它們。
[Go](/console/go#embedding-models) 包含其中一些。請以控制台金鑰在 OpenAI 的 Embeddings API 上呼叫它們。

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` 接受字串或字串陣列。`data` 會依相同順序為每個輸入回傳一個向量。
- `dimensions` 會在支援的模型上縮短向量，例如 `text-embedding-3-small`。
- `encoding_format: "base64"` 會回傳 base64 編碼的向量，而不是浮點數。
- 每個輸入都必須符合模型的上下文視窗。
- 回應會像任何推論請求一樣回報 `usage.cost`。請參閱[成本](/console/api/inference#cost)。

不同模型的向量無法互相比較，因此請以相同模型為文件與查詢建立嵌入。
[已連接的供應商](/console/api/providers#endpoints)會在 `/embeddings` 提供其自己的嵌入模型。

## 背景

有許多模型可用，但只有少數能勝任編碼 agent。供應商在設定、
效能與品質上也各不相同，因此透過 OpenRouter 等閘道存取的模型可能表現不同。

<Callout type="tip">我們測試了一組精選的模型與供應商，確認它們能與 OpenCode 良好搭配。</Callout>

為了建立這份目錄，我們：

1. 測試一組精選模型，並與其團隊討論最佳的執行方式。
2. 與供應商合作，確保模型正確提供。
3. 對每個模型／供應商組合進行基準測試，整理出我們能安心推薦的清單。

控制台是一個 AI 閘道，讓你存取這些模型。

## 目標

我們建立控制台是為了：
