Политики определяют, может ли OpenCode выполнить действие с указанным ресурсом. Политики задаются в разделе `policies` или поступают из подключённого рабочего пространства [OpenCode Console](/console).

Политики отделены от [разрешений](/permissions). Разрешения — это правила инструментов для каждого агента, которые могут `allow`, `deny` или `ask`. Политики бинарны, никогда не запрашивают подтверждение и только ужесточают то, что иначе разрешили бы разрешения и провайдеры.

## Настройка

Запретите одного провайдера везде, добавив правило в `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

Запрещённый провайдер исчезает из каталога и выбора моделей, даже если у него есть действующие учётные данные.

В более ранних версиях политики читались из `experimental.policies`. Этот ключ по-прежнему работает и сливается в `policies`:

```jsonc
{
  "experimental": {
    "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
  },
}
```

## Правила политики

У каждого правила три поля:

| Поле       | Значения                                                                                                                       | Значение                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `action`   | `provider.use`, `tool.use`, `integration.connect`, `integration.use`, `mcp.use`, `skill.use`, `plugin.use`, `websearch.use`     | Управляемая операция                                  |
| `resource` | строка или шаблон с подстановочными знаками                                                                                     | К чему применяется правило; зависит от действия       |
| `effect`   | `allow`, `deny`                                                                                                                 | Решение при совпадении этого правила                  |

Правила, не прошедшие проверку, отбрасываются с предупреждением в журнале сервера, а остальная часть списка продолжает действовать. Проверьте журнал после изменения `deny`.

## Сопоставление

Ресурсы используют те же подстановочные знаки для всего значения, что и разрешения: `*` совпадает с нулём или более символов, а `?` — с одним.

```jsonc
{
  "policies": [{ "action": "provider.use", "resource": "company-*", "effect": "deny" }],
}
```

Это запрещает `company-us` и `company-eu`. Шаблон, оканчивающийся на ` *`, также совпадает со значением без аргументов, поэтому `shell:git push *` охватывает и `git push` без аргументов.

## Порядок

Если совпадает несколько правил, побеждает последнее. Правила специфичности нет, поэтому ставьте широкие правила первыми, а исключения — после них. Если ничего не совпало, действие разрешено.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  ],
}
```

Доступным остаётся только Anthropic.

## Провайдеры

`provider.use` определяет, можно ли вообще использовать провайдера. Ресурс — ID провайдера: `anthropic`, `openai`, `opencode` или пользовательский ID из [`providers`](/providers).

```jsonc
{
  "providers": {
    "company-ai": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://ai.company.example/v1" },
    },
  },
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "company-ai", "effect": "allow" },
  ],
}
```

Запись `providers` настраивает эндпоинт, а правила делают его единственным провайдером, который будет использовать OpenCode. Политика применяется независимо от того, как провайдер стал известен: из данных каталога, переменных окружения, сохранённых аккаунтов, встроенных плагинов или конфигурации.

Используйте `provider.use` вместо списков `enabled_providers` и `disabled_providers` из V1. Файлы V1 по-прежнему загружаются; см. [Переход с V1](/migrate-v1#supported-fields-without-direct-native-equivalents).

## Инструменты

Правила `tool.use` могут запретить действие независимо от результата проверки [разрешений](/permissions). Ресурс — `<action>:<value>`. Правило сопоставляется с каждым ресурсом, который проверяет инструмент.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
    { "action": "tool.use", "resource": "edit:*.env", "effect": "deny" },
    { "action": "tool.use", "resource": "webfetch:*", "effect": "deny" },
  ],
}
```

При запрете проверка выдаёт ошибку `Blocked by configuration policy`, а не запрос подтверждения. Запрет применяется после правил агента и сохранённых подтверждений, поэтому имеет приоритет как над `ask`, так и над подтверждением «Allow always».

| Шаблон                       | Что блокирует                                      |
| ---------------------------- | --------------------------------------------------- |
| `shell:*`                    | Каждую shell-команду                                |
| `read:*/.ssh/*`              | Чтение материалов SSH                               |
| `external_directory:*`       | Любой доступ за пределы локации или worktree        |
| `subagent:general`           | Запуск одного субагента                             |
| `github_delete_repository:*` | Один инструмент MCP                                 |
| `*`                          | Всё, что ещё не запрещено                           |

Правило `tool.use` с `allow` никогда не даёт доступ. Оно лишь снимает более ранний широкий `deny`, после чего решают собственные правила агента.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:*", "effect": "deny" },
    { "action": "tool.use", "resource": "shell:git status *", "effect": "allow" },
  ],
}
```

`git status` возвращается к правилу `shell` агента; все остальные команды блокируются.

## Интеграции

Интеграция — это всё, что вы подключаете через `/connect`: OpenCode Console (`opencode`), провайдер вроде `anthropic`, сервис веб-поиска вроде `exa` или источник конфигурации well-known вроде `https://ai.acme.com`. Вход в MCP-сервер не зависит от политик интеграций; для управления MCP-серверами используйте `mcp.use`.

`integration.connect` определяет, какие интеграции показывает `/connect` и какие можно подключить. Ресурс — ID интеграции.

`integration.use` управляет доступом ко всему, что предоставляет интеграция: провайдерам, моделям, веб-поиску, а также MCP-серверам и конфигурации из рабочего пространства Console или источника well-known. Ресурс — `<integration>#<account>`, где account — ID подключённой организации или аккаунта, например `opencode#org_01M3CAP8H43Z49CER6NT0Y3ZF1`. Если аккаунт не подключён, указывается только ID интеграции: для бесплатного уровня без входа — `opencode`, для переменной окружения `ANTHROPIC_API_KEY` — `anthropic`, для провайдера из `opencode.json` — его ID.

Эта политика MDM разрешает доступ только к одному рабочему пространству Console. Другие примеры см. в разделе [Для компаний](/enterprise):

```jsonc
{
  "policies": [
    { "action": "integration.connect", "resource": "*", "effect": "deny" },
    { "action": "integration.connect", "resource": "opencode", "effect": "allow" },
    { "action": "integration.use", "resource": "*", "effect": "deny" },
    { "action": "integration.use", "resource": "opencode#org_01M3CAP8H43Z49CER6NT0Y3ZF1", "effect": "allow" },
  ],
}
```

В `/connect` доступен только вход через Console. Бесплатный уровень, личные аккаунты Console, другие организации, API-ключи из окружения и провайдеры из `opencode.json` недоступны. Провайдеры, MCP-серверы и веб-поиск рабочего пространства доступны. Если изменить их в Console, новый профиль MDM не потребуется.

Отказаться от MCP-серверов и конфигурации, предоставляемых интеграцией, можно только через управляемые политики. Собственные политики интеграции продолжают действовать в любом случае.

## MCP-серверы, навыки и плагины

| Действие     | Ресурс                                                           |
| ------------ | ---------------------------------------------------------------- |
| `mcp.use`    | [MCP-сервер](/mcp-servers) по его настроенному имени             |
| `skill.use`  | [Навык](/skills) по его ID                                       |
| `plugin.use` | [Плагин](/plugins) по имени пакета без версии или абсолютному пути |

```jsonc
{
  "policies": [
    { "action": "mcp.use", "resource": "*", "effect": "deny" },
    { "action": "mcp.use", "resource": "github", "effect": "allow" },
    { "action": "plugin.use", "resource": "opencode-acme-cli", "effect": "deny" },
  ],
}
```

Запрещённый MCP-сервер или навык удаляется, а запрещённый плагин не загружается, независимо от способа настройки.

### Переход с `integration.use`

До OpenCode 2.2.3 `integration.use` охватывал MCP-серверы, навыки и плагины через префикс `mcp:`, `skill:` или `plugin:`. Правила с префиксом по-прежнему загружаются и преобразуются в `mcp.use`, `skill.use` или `plugin.use`.

Правило без такого префикса, включая голый `*`, теперь относится к интеграциям. Широкий запрет вроде

```jsonc
{ "action": "integration.use", "resource": "*", "effect": "deny" }
```

больше не блокирует MCP-серверы, навыки и плагины. Вместо этого он блокирует всех провайдеров, включая бесплатный уровень, если более позднее правило не разрешает интеграцию. Чтобы сохранить прежний смысл, замените его на:

```jsonc
{
  "policies": [
    { "action": "mcp.use", "resource": "*", "effect": "deny" },
    { "action": "skill.use", "resource": "*", "effect": "deny" },
    { "action": "plugin.use", "resource": "*", "effect": "deny" },
  ],
}
```

Исключения переносятся так же: `integration.use` `mcp:github` становится `mcp.use` `github`, а `skill:team:review` — `skill.use` `team:review`.

Клиенты версий до 2.2.3 игнорируют `integration.connect`, `integration.use` (в новом значении), `mcp.use`, `skill.use` и `plugin.use`. Если вы используете эти правила, требуйте версию 2.2.3 или новее.

## Веб-поиск

`websearch.use` управляет провайдерами веб-поиска, которые может использовать инструмент `websearch`. Ресурс — ID провайдера: `opencode` для OpenCode Web Search из Console, встроенный провайдер вроде `exa`, `firecrawl`, `parallel`, `tavily` или `tinyfish`, либо ID провайдера, добавленного плагином.

```jsonc
{
  "policies": [
    { "action": "websearch.use", "resource": "*", "effect": "deny" },
    { "action": "websearch.use", "resource": "opencode", "effect": "allow" },
  ],
}
```

Запрещённые провайдеры удаляются, даже если работают без API-ключа, как Exa и TinyFish. Если запрещены все провайдеры, инструмент `websearch` больше не предлагается. Клиенты версий до 2.2.6 игнорируют `websearch.use`.

## Приоритет

Обычные настройки отдают приоритет ближайшей конфигурации. Политики делают наоборот: правила из более широкой конфигурации вычисляются позже, поэтому переопределяют более узкие. Управляемая конфигурация и подключённый Console всегда превосходят пользовательские и проектные файлы.

| Приоритет     | Источник                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| 1 (высший)    | Управляемые настройки macOS (`/Library/Managed Preferences/ai.opencode.managed.plist`)                          |
| 2             | Системный `opencode.json(c)` (`/Library/Application Support/opencode`, `/etc/opencode`, `%ProgramData%\opencode`) |
| 3             | Подключённое рабочее пространство OpenCode Console |
| 4             | Глобальный `~/.config/opencode/opencode.json(c)`                                                                |
| 5             | Прямой `opencode.json(c)`; внешние каталоги важнее внутренних                                                    |
| 6 (низший)    | `.opencode/opencode.json(c)`; внешние каталоги важнее внутренних                                                |

Репозиторий не может снова включить провайдера, запрещённого глобально:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

```jsonc title="project/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "allow" }],
}
```

`openai` остаётся запрещённым. В пределах одного файла правила сохраняют порядок записи.

## Console

Политики Providers и Tools рабочего пространства [OpenCode Console](/console) преобразуются в обычные правила `policies` в его конфигурации. При объединении настроек OpenCode ставит конфигурацию рабочего пространства сразу после управляемых настроек и системного файла по приоритету. Поэтому правило `allow` из конфигурации репозитория или пользователя не может отменить `deny` организации, а `allow` организации отменяет `deny` с меньшим приоритетом. Управляемые настройки и системный файл по-прежнему имеют приоритет над рабочим пространством.

В сообщении об отказе по этим правилам указано рабочее пространство:

```text
Blocked by Acme's policy
```

Правила следуют за подключённым аккаунтом.

| Событие                          | Результат                                                   |
| -------------------------------- | ----------------------------------------------------------- |
| Изменение политик в Console      | Применяются при следующей загрузке, примерно каждые пять минут |
| Переключение на другое рабочее пространство | Начинают действовать правила нового рабочего пространства |
| Отключение                       | Правила очищаются                                           |
| Console недоступен               | Последние правила для этого подключения продолжают действовать |

Плагин Console и плагин политик нельзя отключить через `plugins`; см. [управление плагинами](/plugins#control).

<Callout type="note">
  Политики не настраивают эндпоинты и учётные данные и не могут сделать непригодного провайдера пригодным. Они также не
  изолируют код плагинов: запрещённый провайдер блокируется на обычном пути провайдеров и моделей.
</Callout>
