---

Прогрев сессии периодически отправляет запросы к модели, чтобы сохранить кэши промптов на стороне провайдера или другое недолговечное состояние, пока вы делаете паузу между промптами. По умолчанию отключён.

Включите прогрев в любом [файле конфигурации OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}
```

С этой конфигурацией OpenCode прогревает недавно активную сессию незадолго до истечения срока жизни её кэша промптов: через 90% от [`cache.ttl`](/models#cache-lifetime) модели или каждые четыре минуты, если этот параметр не задан. Прогрев продолжается 30 минут с момента последнего запроса к модели, не считая запросов прогрева.

## Параметры

Используйте объектную форму, чтобы изменить промпт прогрева, интервал простоя или активное окно:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour",
  },
}
```

| Поле       | По умолчанию     | Назначение                                                                                                                     |
| ---------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`   | Инструкция keep-alive | Добавляется как временное сообщение пользователя к каждому запросу прогрева. По умолчанию модель просят ничего не делать, не использовать инструменты и ответить `OK`. |
| `interval` | `"auto"`         | Время простоя перед следующим запросом прогрева. `"auto"` использует 90% от `cache.ttl` модели или четыре минуты, если его нет. |
| `duration` | `"30 minutes"`   | Длительность прогрева с момента последнего запроса к модели, не считая запросов прогрева. |

Пропущенные поля объекта сохраняют значения по умолчанию. Например, здесь меняется только интервал:

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "2 minutes",
  },
}
```

## Автоматический интервал

По умолчанию `interval` равен `"auto"`: прогрев выполняется незадолго до истечения кэша промптов каждой модели. OpenCode использует 90% от настройки [`cache.ttl`](/models#cache-lifetime) модели, поэтому кэш `"5m"` прогревается каждые 4.5 минуты. Модели без `cache.ttl` прогреваются каждые четыре минуты.

```jsonc title="opencode.jsonc"
{
  "warming": { "duration": "2 hours" },
  "providers": {
    "anthropic": { "settings": { "cache": { "ttl": "1h" } } },
  },
}
```

Кэш, который живёт дольше `duration`, например `"1h"` при стандартных 30 минутах, не прогревается, так как он всё равно переживает окно прогрева. OpenCode записывает это в журнал один раз за сессию. Увеличьте `duration`, чтобы прогревать его.

## Для провайдера и модели

Задайте `settings.cache.warming` у провайдера или модели, чтобы прогревать только его сессии или задать им собственный тайминг. Он принимает те же значения, что и `warming` верхнего уровня, кроме `prompt`, и переопределяет его. Настройка модели переопределяет настройку провайдера.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "5m", "warming": true } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "warming": false } } },
      },
    },
  },
}
```

Здесь сессии Anthropic прогреваются каждые 4.5 минуты, кроме Claude Haiku 5.5, а другие провайдеры не прогреваются. Поля, пропущенные в объектной форме, берутся из `warming` верхнего уровня, затем из значений по умолчанию. Недопустимая настройка записывает предупреждение и возвращается к `warming` верхнего уровня.

## Длительности

`interval` и `duration` принимают строки длительности. Оба должны давать конечные значения больше нуля, а `interval` должен быть короче `duration`; иначе OpenCode пропускает прогрев и записывает предупреждение.

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "30 seconds",
    "duration": "1 hour",
  },
}
```

## Тайминг

Прогрев начинается после обычного запроса к модели в сессии верхнего уровня. Сессии субагентов не прогреваются. Интервал отсчитывается с момента отправки последнего запроса, в том числе запроса прогрева, а не с момента получения полного ответа: срок жизни кэша начинается, когда провайдер получает запрос. Запросы прогрева не продлевают время, в течение которого выполняется прогрев.

```text
00:00  normal model request sent
00:01  response finishes
00:04  warming request
00:08  warming request
00:30  warming stops
```

Любой новый запрос к модели, кроме запросов прогрева, сбрасывает оба таймера. Это касается и сжатия контекста. Если заданный интервал не меньше длительности прогрева, OpenCode отклоняет его с предупреждением. Если такой интервал получился при `"auto"`, прогрев не нужен: срок действия кэша превышает длительность прогрева.

```text
00:00  normal model request
00:20  normal model request; window restarts
00:24  warming request
00:50  warming stops
```

OpenCode не отправляет запрос прогрева, пока выполняется другой запрос к модели, в том числе запрос на сжатие контекста. Если интервал истёк раньше, OpenCode дожидается завершения запроса к модели и сразу отправляет запрос прогрева, если срок действия кэша ещё не истёк. Иначе прогрев приостанавливается до следующего обычного запроса.

```text
00:00  normal model request sent
00:04  interval due; request still running
00:04:30  response finishes; warming request
00:08:30  warming request
```

## Запросы

Запрос прогрева использует текущую модель, агента, инструкции и контекст разговора сессии. OpenCode временно добавляет настроенный промпт, делает один вызов модели и отбрасывает ответ.

```text
[current session context]
[transient user message: keep-alive prompt]
→ one model response, discarded
```

Запрос не принимает ввод, не добавляет сообщения в историю и не изменяет постоянное состояние сессии. OpenCode не отправляет локальные вызовы инструментов и не продолжает цикл инструментов; промпт по умолчанию также просит модель не использовать инструменты.

## Ошибки

Ошибки прогрева записываются в журнал, не ломая и не меняя сессию. OpenCode ждёт следующего интервала, прежде чем повторить, а исходное активное окно продолжает отсчитываться.

```text
00:04  warming request fails; session is unchanged
00:08  next warming attempt
```

Если запрос прогрева читает из кэша меньше, чем записывает, это считается промахом: прогрев сессии останавливается до следующего обычного запроса. Если провайдер не сообщает об использовании кэша, промах не засчитывается.

```text
00:04  warming request misses the cache; warming stops
00:10  normal model request; warming resumes
00:14  warming request
```

## Затраты

Запросы прогрева действительно отправляются провайдеру. Как и другие запросы к модели, они могут расходовать токены, оплачиваться, учитываться в лимитах частоты запросов и завершаться ошибкой.

- Более короткие интервалы увеличивают объём запросов.
- Более длинные окна допускают больше запросов прогрева.
- Включайте прогрев, только когда выгода на стороне провайдера стоит дополнительного расхода.

Например, для модели без `cache.ttl` значения по умолчанию допускают до семи попыток прогрева в течение одного непрерывного 30-минутного окна: на 4, 8, 12, 16, 20, 24 и 28-й минуте.

## Отключение

Установите `warming` в `false`, чтобы явно отключить прогрев. Если поле не указано, прогрев также остаётся отключённым.

```jsonc title="opencode.jsonc"
{
  "warming": false,
}
```
