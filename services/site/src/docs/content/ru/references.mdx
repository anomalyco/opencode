---

Референс позволяет OpenCode обращаться к каталогу за пределами текущего проекта по заданному имени. Добавьте его в `opencode.json` или `opencode.jsonc`, а затем при необходимости прикрепите его по псевдониму в клиенте.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Прикрепив `docs`, попросите агента просмотреть нужный путь:

```text
Read the attached docs reference and summarize api/authentication.md.
```

Используйте референсы для документации, общих библиотек, примеров или исходного кода из другого репозитория.

## Локальные

Используйте `path` для локального каталога:

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

Пути ведут себя так:

- Относительные пути разрешаются от каталога, содержащего файл конфигурации.
- Абсолютные пути поддерживаются.
- Пути относительно домашнего каталога, например `~/docs`, поддерживаются.

Используйте строковую сокращённую форму, когда другие поля не нужны:

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  Строка сокращённой формы считается локальным путём, только если начинается с `.`, `/` или `~`. Используйте `./docs`,
  а не `docs`; значение `docs` без префикса интерпретируется как Git-репозиторий.
</Callout>

## Git

Используйте `repository` для удалённого Git-репозитория:

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

Поддерживаемые формы удалённых репозиториев:

- сокращение GitHub `owner/repo`;
- URL Git;
- формы host/path;
- удалённые адреса в стиле SCP.

Локальные репозитории `file:` не поддерживаются.

Используйте строковую сокращённую форму, чтобы следовать ветке по умолчанию удалённого репозитория:

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

Без `branch` OpenCode переключается на ветку по умолчанию удалённого репозитория и обновляет её. Имена веток могут содержать буквы, цифры, `/`, `_`, `.` и `-`, но не могут начинаться с `-` или содержать `..`.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## Хранение

OpenCode нормализует каждый удалённый репозиторий и хранит одну рабочую копию на репозиторий и ветку в своём глобальном каталоге данных. Без явной ветки путь имеет такую форму:

```text
opencode/repos/<host>/<repository-path>
```

В типичной установке Linux `Effect-TS/effect` хранится в:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

Явная ветка добавляет закодированный суффикс `@<branch>`:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## Обновление

Отсутствующие репозитории клонируются асинхронно. Существующие рабочие копии проверяются в фоне при загрузке или перезагрузке референсов и после приёма нового промпта пользователя в их локации.

```text
Prompt admitted → refresh check starts in background → agent continues
```

Рабочую копию можно обновить, если с последней попытки прошло не менее 24 часов или если попыток ещё не было. При обновлении OpenCode загружает изменения и приводит копию к состоянию указанной ветки или ветки по умолчанию удалённого репозитория.

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

Обновление подчиняется следующим правилам:

- Отметки времени сохраняются между перезапусками сервиса.
- Локации, использующие одну рабочую копию, делят её отметку времени.
- Неудачные попытки записываются в журнал и подчиняются тому же ограничению в 24 часа.
- Периодического опроса, пока локация не используется, нет.
- Ошибки клонирования или обновления не мешают загрузке других референсов.

Обработка промпта не ждёт клонирования или обновления. Во вложение могут попасть данные до обновления, хотя при последующем чтении инструмент уже увидит новую рабочую копию. Новый референс может появиться до того, как будет готова его рабочая копия.

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  Кэшированные рабочие копии общие и могут обновляться, пока агент их использует. Не редактируйте кэшированные рабочие
  копии: обновление сбрасывает их.
</Callout>

## Указания

`description` сообщает агентам, когда референс уместен. Референсы с описанием появляются в инструкциях агента с псевдонимом и разрешённым путём.

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Референсы без описания остаются доступны клиентам, но не объявляются автоматически.

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## Видимость

Установите `hidden` в `true`, чтобы убрать референс из интерактивных селекторов клиента:

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden` влияет только на интерактивную видимость. Референс остаётся в API референсов и, если у него есть описание, в инструкциях агента.

## Использование

Клиенты прикрепляют референс по его корневому псевдониму. Вложение содержит нерекурсивный список непосредственных файлов и каталогов корня.

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

Просите агента просмотреть конкретный путь, когда нужен контент ниже корня.

## Разрешения

Референсы не дают дополнительных разрешений инструментов. Доступ за пределами активной локации по-прежнему подчиняется обычным правилам инструментов и разрешению `external_directory`; редактирование также требует соответствующего разрешения на изменение.

```text
Read ../product-docs/api.md
```

Запрос успешен, только когда активные разрешения допускают это внешнее чтение.

## Поля

| Поле          | Локальный  | Git        | Описание                                      |
| ------------- | ---------- | ---------- | --------------------------------------------- |
| `path`        | Обязательно | Нет       | Путь локального каталога                      |
| `repository`  | Нет        | Обязательно | Удалённый Git-репозиторий                    |
| `branch`      | Нет        | Необязательно | Ветка для загрузки и переключения          |
| `description` | Необязательно | Необязательно | Указание, когда агентам использовать референс |
| `hidden`      | Необязательно | Необязательно | Скрыть из интерактивных селекторов клиента |

Полная запись Git может использовать каждое совместимое с Git поле:

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## Псевдонимы

Псевдоним не может быть пустым или содержать `/`, `\`, пробельные символы, обратную кавычку или запятую.

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
