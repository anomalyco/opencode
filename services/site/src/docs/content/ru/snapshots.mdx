Снимки позволяют отменить недавние изменения разговора и файлов вместе. Используйте их для правки недавней работы, но для важных вещей сохраняйте коммиты Git или резервные копии.

## Рабочий процесс

Запустите `/undo` после ответа, который хотите переделать. OpenCode подготавливает откат, восстанавливает затронутые файлы и возвращает удалённый промпт в поле ввода, чтобы его можно было отредактировать.

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

Отправка отредактированного промпта фиксирует подготовленный откат. До отправки запустите `/redo`, чтобы отменить его и вернуть разговор и файлы в состояние до `/undo`.

```text
/redo
```

Терминал также предоставляет стандартные сочетания клавиш:

| Действие                              | Команда  | Сочетание    |
| ------------------------------------- | -------- | ------------ |
| Подготовить откат предыдущего сообщения | `/undo`  | `<leader>u`  |
| Отменить подготовленный откат         | `/redo`  | `<leader>r`  |

Можно также выбрать более раннее сообщение и нажать **Revert**, чтобы подготовить откат до этой точки.

## Снимки

На каждом шаге OpenCode пытается сделать снимок непосредственно перед вызовом модели и ещё один после того, как зафиксирован результат шага: успех или ошибка. В сообщении ассистента отмечено, какие пути изменились между снимками.

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

Снимки делаются по возможности. Если один из них недоступен, разговор продолжается, но для этого шага может не быть изменений файлов, доступных для восстановления.

## Область охвата

Снимки охватывают активный каталог сессии внутри worktree Git. Например, сессия, открытая в `packages/app`, захватывает подходящие файлы ниже `packages/app`, а не изменения в других частях репозитория.

| Содержимое                                                | Захватывается | Пример                        |
| --------------------------------------------------------- | ------------- | ----------------------------- |
| Отслеживаемые файлы в активном каталоге                   | Да            | `packages/app/src/app.tsx`    |
| Неигнорируемые неотслеживаемые файлы до 2 MiB каждый      | Да            | `packages/app/notes.txt`      |
| Файлы, игнорируемые Git                                   | Нет           | `packages/app/dist/app.js`    |
| Отдельные неотслеживаемые файлы больше 2 MiB              | Нет           | `packages/app/debug.log`      |
| Файлы за пределами активного каталога                     | Нет           | `packages/server/src/index.ts` |
| Метаданные Git и другие побочные эффекты                  | Нет           | коммиты, ветки, базы данных или процессы |

Снимки файловой системы требуют репозитория Git. Вне его `/undo` всё ещё может откатить историю разговора, но не может восстановить файлы.

## Восстановление

При откате восстанавливаются только пути, изменённые на шагах ассистента после выбранного места в диалоге. Файлы возвращаются к состоянию до первого отменённого шага. Если файла на тот момент не было и он появился на одном из отменённых шагов, OpenCode его удаляет.

| Время                        | `src/api.ts` | `src/new.ts` |
| ---------------------------- | ------------ | ------------ |
| Выбранная граница            | версия A     | отсутствует  |
| Последующие шаги ассистента  | версия B     | создан       |
| После отката                 | версия A     | удалён       |

Пути, не приписанные этим шагам, не трогаются. Текущие изменения затронутого пути могут быть перезаписаны, поэтому перед продолжением просмотрите восстановленную сводку и `git diff`.

```sh
git diff --stat
git diff
```

## Хранение

OpenCode хранит снимки локально в отдельной внутренней базе объектов Git в своём каталоге данных. Создание снимка не создаёт коммитов, не перемещает ветки и намеренно не меняет индекс вашего репозитория.

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

Объекты снимков могут содержать полное содержимое отслеживаемых и подходящих неотслеживаемых файлов. Относитесь к каталогу данных OpenCode как к конфиденциальным локальным данным.

## Настройки

Снимки включены по умолчанию. Установите `snapshots` в `false` в [конфигурации](/config#snapshots), чтобы прекратить создание снимков файловой системы.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

Отключение снимков не удаляет уже сохранённые снимки. Откат разговора остаётся доступным, но без захваченного состояния файловой системы он не может восстановить связанные изменения файлов.

## Безопасность

Снимки — удобство, а не транзакция и не резервная копия:

- Shell-команды могут менять сервисы, процессы, сетевые ресурсы, базы данных, состояние Git, игнорируемый вывод или файлы за пределами активного каталога. Восстановление снимка не отменяет эти эффекты.
- Прерванная или неудачная работа может оставить изменения, если создать снимок не удалось или нет пригодной пары снимков.
- Восстановление затронутых путей перезаписывает их текущее содержимое. Отмена подготовленного отката также может перезаписать более поздние изменения.
- OpenCode отклоняет операции отката, пока сессия работает, но внешние редакторы и команды всё равно могут изменить worktree между созданием снимка и восстановлением.
- После фиксации отката сообщения исчезают из текущего диалога, но не из сохранённой истории сессии и не из хранилища снимков. Откат не обеспечивает безвозвратного удаления.

Закоммитьте или сохраните важную работу, прежде чем использовать `/undo` в worktree с незакоммиченными изменениями.
