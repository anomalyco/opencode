## Прикрепление файлов

Прикрепите локальный файл, затем попросите OpenCode использовать его в промпте. В десктопном или веб-клиенте выберите **Attach file**, вставьте файл или перетащите его в поле промпта.

```text
Summarize the attached README.md and list the required setup steps.
```

В диалоге выбора файлов приложения для компьютера можно выбрать файлы общим объёмом до 20 MiB. В других интерфейсах клиент может устанавливать меньший лимит.

<Callout type="warning">
  Перед прикреплением изображения выберите модель с поддержкой изображений на входе. OpenCode может передать
  поддерживаемые изображения провайдеру, но провайдер и модель по-прежнему применяют свои форматы, размеры, количество
  файлов и ограничения по размеру. Модель только для текста может отклонить запрос.
</Callout>

## Синтаксис

Входные данные промптов и команд V2 описывают вложение через `uri` и необязательные `name` и `description`:

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

Используйте абсолютный URL `file:` для файла или каталога, доступного серверу. Для текстовых файлов положительные параметры `start` и `end` выбирают строки с нумерацией от единицы.

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

Чтобы передать содержимое прямо в запросе, используйте URL `data:`:

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

URL вложений HTTP и HTTPS не поддерживаются. О программной отправке промптов см. сгенерированный [справочник API](/api).

## Форматы

В текущей версии V2 модель получает следующие типы вложений:

| Входные данные          | Модель получает                                           | Пример             |
| ----------------------- | --------------------------------------------------------- | ------------------ |
| Текстовый файл UTF-8    | Имя файла и декодированный текст                          | `README.md`        |
| Каталог                 | Нерекурсивный список непосредственных файлов и каталогов  | `file:///home/me/` |
| PNG, JPEG, GIF или WebP | Медиа изображения                                         | `diagram.png`      |
| PDF                     | Медиа документа                                           | `report.pdf`       |

Для PDF нужна модель с поддержкой PDF на входе. Если модель не поддерживает тип вложения, OpenCode отправляет вместо него короткое примечание.

SVG считается текстом. AVIF, BMP, аудио, видео и другие бинарные вложения промпта не включаются в запрос к модели. Сначала преобразуйте неподдерживаемый бинарный файл в текст или поддерживаемое изображение; например, преобразуйте BMP в PNG перед прикреплением.

OpenCode читает каждое вложение до приёма промпта. Он отклоняет недопустимые URL, нечитаемые пути, пути, не являющиеся файлами или каталогами, и декодированные вложения больше 20 MiB. Тип медиа определяется по байтам, поэтому изменение имени файла или типа медиа в URL `data:` не делает неподдерживаемый бинарный файл видимым.

## Изображения

Настройте нормализацию изображений в `opencode.json` или `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Все поля необязательны:

| Поле               | По умолчанию | Поведение                                                                 |
| ------------------ | ------------ | ------------------------------------------------------------------------- |
| `auto_resize`      | `true`       | Изменять размер изображения сверх заданного ограничения; при `false` отклонять изображение. |
| `max_width`        | `2000`       | Максимальная ширина в пикселях; должна быть положительным целым числом.   |
| `max_height`       | `2000`       | Максимальная высота в пикселях; должна быть положительным целым числом.   |
| `max_base64_bytes` | `5242880`    | Максимальное число байтов в изображении, закодированном Base64; должно быть положительным целым числом. |

Например, эта настройка отклоняет, а не изменяет изображение шире 1200 пикселей:

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

Эти настройки применяются и к поддерживаемым изображениям в промптах, и к изображениям, возвращаемым встроенным инструментом `read`.

## Обработка

Инструмент `read` распознаёт PNG, JPEG, GIF и WebP по содержимому и читает до 20 MiB исходных данных изображения. Он проверяет ширину, высоту и длину Base64 по настроенным ограничениям изображений.

При `auto_resize: true` OpenCode сохраняет пропорции и уменьшает изображение до пределов размеров. Затем он пробует всё меньшие кодировки PNG и JPEG, пока не уложится в лимит Base64, поэтому тип медиа на выходе может измениться.

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

Если ни одна кодировка не подходит, обработка завершается ошибкой. При `auto_resize: false` изображение, превышающее любое ограничение, отклоняется без изменений; изображение, которое не удаётся декодировать, также отклоняется.

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

Если средство изменения размера недоступно, OpenCode передаёт исходное изображение без изменений. Поэтому настройки изображений ограничивают только обработку: они не действуют как лимит загрузки или средство защиты.

## Ограничения

| Ограничение                       | Значение или поведение                                            | Пример                                       |
| --------------------------------- | ----------------------------------------------------------------- | -------------------------------------------- |
| Прямое вложение                   | 20 MiB в декодированном виде на элемент; клиенты могут устанавливать меньшие ограничения | Два файла по 12 MiB проходят ограничение на элемент |
| Выбор в десктопном приложении     | 20 MiB всего                                                      | Два файла по 12 MiB превышают лимит выбора  |
| `max_base64_bytes`                | Только закодированный Base64, без полного URL `data:`             | `SGVsbG8=` считается как 8 байтов            |
| Ограничения изображений провайдера | Применяются после обработки OpenCode                              | Провайдер может отклонить принятое изображение |
| Поддержка текстовых вложений моделью | Не требует мультимодальной модели                              | `notes.txt` вставляется как текст промпта    |
| Лимиты текста в `read`            | Использует отдельные лимиты разбиения на страницы и усечения      | Читайте большой журнал постранично           |

Принятие файла клиентом не гарантирует, что его содержимое дойдёт до модели. Вложение должно иметь видимый модели формат и удовлетворять ограничениям и OpenCode, и провайдера.
