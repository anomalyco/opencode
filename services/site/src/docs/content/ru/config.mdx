Создайте `opencode.jsonc` в проекте, чтобы настроить OpenCode. Добавьте схему для проверки в редакторе и задайте только нужные параметры.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Можно также попросить OpenCode обновить этот файл за вас.

## Формат

OpenCode поддерживает JSON и JSONC. Используйте JSONC, если нужны комментарии или запятые в конце.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-5-5",
}
```

## Расположение файлов

Управляемые настройки для всей машины размещайте в системном каталоге конфигурации:

| Платформа | Каталог                                 |
| --------- | --------------------------------------- |
| macOS     | `/Library/Application Support/opencode` |
| Linux     | `/etc/opencode`                         |
| Windows   | `%ProgramData%\opencode`                |

Системный каталог работает как глобальный. Помимо `opencode.json(c)`, он загружает `agents/`, `commands/`, `skills/` и `plugins/` для всех пользователей машины:

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

В macOS OpenCode также читает управляемые настройки, которые MDM-инструменты разворачивают для домена `ai.opencode.managed`. Профиль конкретного пользователя заменяет профиль для всей машины:

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

Управляемые настройки имеют наивысший приоритет, поэтому пользователи и проекты не могут переопределить заданные в них значения, а управляемые настройки переопределяют системный каталог. Одни лишь настройки не мешают пользователям добавлять провайдеров, MCP-серверы, агентов или плагины; чтобы ввести ограничения, используйте [политики](/policies#precedence) в управляемой конфигурации.

Пользовательские настройки для всех проектов размещайте в глобальной конфигурации:

```text
~/.config/opencode/opencode.json(c)
```

Настройки проекта можно разместить в одном из этих файлов:

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode ищет файлы от текущего каталога до корня файловой системы. Сначала он объединяет файлы `opencode.json(c)` из самих каталогов, от самого дальнего к ближайшему, затем в том же порядке — файлы внутри каталогов `.opencode`. Поэтому любой найденный файл настроек внутри `.opencode` имеет приоритет над любым файлом, лежащим непосредственно в одном из каталогов поиска. Если такой порядок не нужен, придерживайтесь одного способа размещения файлов во всём дереве каталогов.

Например, запустите OpenCode из `/home/user/projects/acme/packages/web`:

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode применяет эти файлы от низшего приоритета к высшему:

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

Конфигурация пакета переопределяет соответствующие настройки конфигурации репозитория, а та — глобальную конфигурацию. Системная конфигурация переопределяет их все. Не конфликтующие настройки сохраняются. [Политики](/policies#precedence) из глобальных и проектных файлов вычисляются в обратном порядке, а системные политики превосходят их все.

## Схема

Полная схема конфигурации OpenCode доступна по адресу [opencode.ai/config.json](https://opencode.ai/config.json).

Добавьте поле `$schema` в файл конфигурации, чтобы включить проверку и автодополнение в редакторах, поддерживающих JSON Schema:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

Считайте схему источником истины для доступных полей, допустимых значений и структуры вложенной конфигурации.

### Shell

Задаёт shell, используемый терминалом и инструментами shell.

```jsonc
{
  "shell": "/bin/zsh",
}
```

### Модель

Задаёт модель по умолчанию в формате `provider/model`. Модель по умолчанию верхнего уровня сейчас не сохраняет `#variant`; ссылки на модель в агентах и командах могут его выбирать.

```jsonc
{
  "model": "anthropic/claude-sonnet-5-5",
}
```

О выборе моделей и локальных моделях см. в [руководстве по моделям](/models).

### Агент

Выбирает основного агента, когда сессия не указала его явно.

```jsonc
{
  "default_agent": "build",
}
```

О встроенных и пользовательских агентах см. в [руководстве по агентам](/agents).

### Обновления

Параметр `update` управляет проверкой обновлений из глобальной конфигурации. Значение `"disable"` пропускает проверки, `"notify"` показывает доступные обновления перед установкой, `"auto"` устанавливает их автоматически. Если параметр не указан, `update` по умолчанию равен `"notify"`.

Автоматическая установка не перезапускает работающий сервер. Перезапустите его вручную, чтобы активировать установленное обновление. Значения на уровне проекта игнорируются.

```jsonc
{
  "update": "notify",
}
```

### Имя пользователя

Задаёт имя пользователя. OpenCode принимает это поле, но не показывает его в разговорах.

```jsonc
{
  "username": "alice",
}
```

### Разрешения

Определяет упорядоченные правила, которые разрешают, запрещают или запрашивают подтверждение, прежде чем агент использует инструмент с подходящим ресурсом.

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

О сопоставлении правил и доступных действиях см. в [руководстве по разрешениям](/permissions).

### Политики

Позволяет разрешить или запретить использование провайдера, запретить действие независимо от результата проверки разрешений или заблокировать MCP-сервер, навык или плагин. Правила задаются по порядку, и конфигурация с более широкой областью действия может их переопределять.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

О сопоставлении, приоритете между файлами конфигурации и политиках, управляемых из Console, см. в [руководстве по политикам](/policies).

### Агенты

Переопределяйте встроенных агентов или определяйте специализированных агентов со своей моделью, инструкциями, режимом и разрешениями.

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

О всех параметрах агентов и агентах в файлах см. в [руководстве по агентам](/agents).

### Снимки

Включает или отключает снимки файловой системы, используемые для отмены и возврата.

```jsonc
{
  "snapshots": false,
}
```

О поведении отмены и повтора см. в [руководстве по снимкам](/snapshots).

### Наблюдение за файлами

Игнорирует файлы и каталоги, которые не должны запускать обновления файловой системы.

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### Форматтер

Форматирует файлы после изменения инструментами `write`, `edit` или `patch`. Установите `formatter` в `true`, чтобы включить доступные встроенные форматтеры.

```jsonc
{
  "formatter": true,
}
```

О встроенных и пользовательских форматтерах см. в [руководстве по форматтерам](/formatters).

### Медиа

Управляет тем, как слишком большие изображения, загруженные инструментом `read`, изменяются в размере или отклоняются до отправки модели.

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Об обработке изображений и ограничениях см. в [руководстве по вложениям](/attachments).

### Вывод

Задаёт максимальное число строк и байтов, сохраняемых из результата инструмента.

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### Поиск

Выбирает способ веб-поиска OpenCode. Значение `"random"` автоматически выбирает доступного провайдера.

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

О провайдерах, учётных данных, выборе, ограничениях частоты и отключении поиска см. в [руководстве по веб-поиску](/websearch).

### MCP

Настраивает локальные и удалённые серверы Model Context Protocol. Глобальные значения `mcp.timeout` применяются к серверам, определённым в файлах конфигурации; `timeout` каждого сервера их переопределяет.

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

Об удалённых серверах, OAuth, переменных окружения и тайм-аутах см. в [руководстве по MCP](/mcp-servers).

### Сжатие контекста

Здесь настраиваются автоматическое сжатие контекста и объём последних сообщений, сохраняемых при сжатии.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": "15%",
  },
}
```

`buffer` — доля контекстного окна модели, которую OpenCode оставляет свободной перед автоматическим сжатием.

По умолчанию используются локальные сводки. Чтобы автоматическое и ручное сжатие выполнялись на стороне провайдера, задайте политику провайдера или модели:

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Настройка модели переопределяет настройку провайдера. Автоматическое сжатие учитывает доступный объём входных данных выбранной модели. При использовании чекпоинтов провайдера недавние сообщения пользователя сохраняются в пределах того же лимита `compaction.keep.tokens`, что и последние сообщения при использовании локальных сводок. Настройка `compaction.auto: false` верхнего уровня отключает дальнейшее автоматическое сжатие, но не удаляет уже созданные чекпоинты. Подробнее о лимитах и восстановлении после переполнения см. в [руководстве по сжатию контекста](/compaction).

### Прогрев

Периодически отправляет временные запросы для прогрева кэша недавно активных сессий. Прогрев отключён по умолчанию. Укажите `true`, чтобы в течение не более 30 минут обновлять кэш незадолго до истечения срока его действия.

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "auto",
    "duration": "30 minutes",
  },
}
```

`settings.cache.warming` провайдера или модели переопределяет эту настройку, а `settings.cache.ttl` задаёт, как долго провайдер хранит кэш. О поведении запросов, настройке и расходах см. в [руководстве по прогреву](/warming), а о `cache.ttl` — в разделе [Время жизни кэша](/models#cache-lifetime).

### Навыки

Добавьте каталоги или URL, в которых OpenCode должен искать навыки агентов.

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

О структуре навыков и автоматическом обнаружении в `.opencode/skills/` см. в [руководстве по навыкам](/skills).

### Команды

Определяйте переиспользуемые слеш-команды как именованные шаблоны промптов.

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

Об аргументах, моделях, агентах и командах в файлах см. в [руководстве по командам](/commands).

### Инструкции

Объявляйте дополнительные файлы инструкций, glob-шаблоны или URL HTTP(S). OpenCode загружает их вместе с найденными файлами `AGENTS.md`.

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

Об инструкциях проекта и `AGENTS.md` см. в [руководстве по инструкциям](/instructions).

### Референсы

Делает локальные каталоги или Git-репозитории доступными как именованный вспомогательный контекст.

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

О сокращённой форме, видимости и разрешении путей см. в [руководстве по референсам](/references).

### Worktree

Задаёт родительский каталог для новых локальных worktree. OpenCode добавляет к нему запрошенное или сгенерированное имя worktree.

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

Относительные пути разрешаются относительно сохранённой канонической рабочей копии проекта. Это касается и глобальной, и проектной конфигурации; абсолютные пути используются как есть, а `~/` разрешается относительно домашнего каталога пользователя.

Например, эта глобальная конфигурация размещает новые worktree в каталоге `.lane/trees/` каждого проекта:

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

Без этой настройки worktree создаются в каталоге данных сервера, в `worktree/<first-six-project-ID-characters>`. Создание и обновление worktree загружают конфигурацию из сохранённой канонической рабочей копии проекта, в том числе когда другие клоны используют тот же ID проекта. Изменение настройки не перемещает существующие worktree.

Git — встроенный вариант по умолчанию. [Плагин](/build/plugins/server#worktrees), регистрирующий стратегию, автоматически становится вариантом по умолчанию в своей среде выполнения. Операции проекта используют среду выполнения канонической рабочей копии. Параметры конкретной стратегии относятся к этому плагину, а не к объекту конфигурации `worktree`.

### Плагины

Загружает плагины из пакетов или локальных каталогов плагинов. Используйте объектную форму, если плагин принимает параметры.

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

О загрузке и настройке плагинов см. в [руководстве по плагинам](/plugins).

### Провайдеры

Настраивает провайдеров и добавляет или переопределяет их модели, параметры запросов, заголовки и варианты моделей.

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol-custom": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

`settings.transport: "websocket"` у провайдера выбирает его WebSocket для сессий.

Об учётных данных, пользовательских эндпоинтах, пакетах провайдеров, транспорте WebSocket и конфигурации моделей см. в [руководстве по провайдерам](/providers).

## Переменные

В файлах конфигурации можно подставлять переменные окружения и содержимое файлов. Ссылки размещайте внутри строк JSON.

### Переменные окружения

Используйте `{env:VARIABLE_NAME}` для подстановки переменных окружения:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "providers": {
    "anthropic": {
      "settings": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
      },
    },
  },
}
```

Если переменная окружения не задана, вместо неё подставляется пустая строка.

### Файлы

Используйте `{file:path/to/file}` для подстановки содержимого файла:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": {
        "apiKey": "{file:~/.secrets/openai-key}",
      },
    },
  },
}
```

Пути к файлам могут быть:

- относительными — от каталога файла конфигурации;
- абсолютными или начинаться с `~/` для домашнего каталога.

Если файл не существует, вместо него подставляется пустая строка.

Это удобно для:

- хранения конфиденциальных данных, например API-ключей, в отдельных файлах;
- совместного использования общих фрагментов конфигурации в нескольких файлах.

## Экспериментальные настройки

<Callout type="warning">
  Экспериментальные настройки могут меняться, ломаться или исчезать в любом релизе без предупреждения. Не полагайтесь
  на них в стабильных рабочих процессах.
</Callout>

Все экспериментальные настройки находятся под ключом `experimental`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "todo": true,
    "subagent_depth": 2,
    "image_generate": { "model": "openai/gpt-image-2" },
    "location_idle_timeout": "4 hours",
  },
}
```

### Задачи

Установите `todo` в `true`, чтобы дать агентам инструмент `todowrite` для отслеживания многошаговой работы. По умолчанию `false`.

### Глубина субагентов

`subagent_depth` задаёт, насколько глубоко субагенты могут запускать своих субагентов. По умолчанию `1`, поэтому субагент не может запустить другого субагента.

### Генерация изображений

`image_generate` задаёт модель по умолчанию для инструмента [`generate_image`](/tools#image-generate) в виде `providerID/modelID`, необязательно с `#variant`. Если эта модель недоступна или не может обработать запрос, OpenCode автоматически выбирает другую модель изображений.

```jsonc
{
  "experimental": {
    "image_generate": {
      "model": "openai/gpt-image-2",
    },
  },
}
```

### Тайм-аут простоя локации

`location_idle_timeout` определяет, сколько времени локация проекта может простаивать без активности сессий, прежде чем OpenCode выгрузит её сервисы. Принимает длительность, например `"2 hours"`, по умолчанию `"60 minutes"`. Работающие сессии и фоновые задачи удерживают локацию загруженной. Значение `false` запрещает выгружать простаивающие локации. Конфигурация проекта может переопределить глобальное значение.

```jsonc
{
  "experimental": {
    "location_idle_timeout": false,
  },
}
```

### Устаревшие политики

`experimental.policies` устарел. Используйте [`policies`](/policies) верхнего уровня. Старый ключ по-прежнему работает и сливается в `policies`.
