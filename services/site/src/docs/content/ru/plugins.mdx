В `opencode.json(c)` можно указать опубликованный пакет, пакет с версией или с префиксом области видимости npm, либо локальный каталог плагина.

## Настройка

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

Относительные пути разрешаются от файла конфигурации, содержащего запись.

Настроенные локальные пути должны быть каталогами. Путь к отдельному файлу пропускается. О том, как OpenCode находит каждую часть в каталоге, см. [Загрузка](/build/plugins#load).

Массивы плагинов из применимых файлов конфигурации применяются от низшего приоритета к высшему, а не заменяют друг друга.

```text
~/.config/opencode/opencode.jsonc
./opencode.jsonc
./.opencode/opencode.jsonc
```

## Обнаружение

OpenCode также загружает непосредственные файлы `.ts` и `.js` и каталоги пакетов плагинов первого уровня из каждого обнаруженного каталога `.opencode/plugins/`.

```text
.opencode/
└── plugins/
    ├── concise.ts
    ├── reviewer.js
    └── acme-package/
```

Глобальные плагины используют ту же схему обнаружения в каталоге конфигурации OpenCode.

```text
~/.config/opencode/plugins/
```

Каталог `plugins/` рядом с `opencode.json(c)` в корне проекта не обнаруживается автоматически; настройте его каталоги плагинов явно или перенесите его в `.opencode/`.

```jsonc title="opencode.jsonc"
{
  "plugins": ["./plugins/local"]
}
```

## Управление

Записи плагинов обрабатываются по порядку. Поставьте `-` перед ID или шаблоном, чтобы отключить его, используйте `*` для всех плагинов и `.*` для совпадения с префиксом ID. Более поздний ID снова включает плагин.

```jsonc title="opencode.jsonc"
{
  "plugins": ["*", "-opencode.provider.*", "opencode.provider.openai", "-acme.reviewer"]
}
```

Чтобы отключить уведомление, добавляемое в новые форки, добавьте `"-opencode.fork-notice"` в `plugins`.

Два встроенных плагина игнорируют удаление, чтобы репозиторий не мог отключить применение [политик](/policies): `opencode.config.policy` и `opencode.provider.opencode` — подключение Console, доставляющее политики организации.

## Команды CLI

Устанавливайте, перечисляйте, проверяйте, обновляйте и удаляйте глобальные пакетные плагины через CLI.

```sh
opencode plugin add opencode-acme-plugin@1.2.0
opencode plugin list
opencode plugin list --builtin
opencode plugin check
opencode plugin update
opencode plugin update opencode-acme-plugin
opencode plugin remove opencode-acme-plugin@1.2.0
```

`plugin check` проверяет обновления пакетных плагинов для сервера, только GUI и только TUI. `plugin update` обновляет все устаревшие пакеты; передайте настроенную цель пакета, чтобы проверить или обновить только его. Локальные плагины и точные ревизии пакетов пропускаются.

Пакет обновляет себя, если указывает, за чем следовать: `name@latest`, диапазон версий вроде `name@^1.2.0`, `name@~1.2.0`, `name@1.x` или `name@>=1.2.0 <2`, ветку Git вроде `github:acme/plugin#main` или диапазон Git `semver:`. OpenCode проверяет его при запуске и каждые 24 часа, устанавливает более новую версию и перезагружает её. Диапазон переходит только на версии внутри него. Если новая версия не загружается, предыдущая продолжает работать и остаётся установленной.

Если указать только имя (`name`) или репозиторий (`github:acme/plugin`), пакет останется на установленной версии. То же касается других тегов npm вроде `name@next` и тегов Git. `plugin check` всё равно сообщает о доступных обновлениях, а `plugin update` устанавливает их. Если указать точную версию или хеш коммита, пакет закрепляется на этой версии.

Установка пакетов принимает имена npm с версиями, тегами или диапазонами, а также совместимые с npm спецификации Git-пакетов. Git-репозитории могут использовать хостинговые сокращения, HTTPS или SSH, включая приватные репозитории, доступные через ваши существующие учётные данные Git.

```sh
opencode plugin add @acme/opencode-plugin@latest
opencode plugin add github:acme/opencode-plugin
opencode plugin add git+ssh://git@github.com/acme/opencode-plugin.git#main
opencode plugin add 'github:acme/plugins#main::path:packages/opencode-plugin'
```

Поддерживаются ветки, теги, полные хеши коммитов и селекторы подкаталога репозитория npm `::path:`. Локальные пути настраивайте напрямую; tarball и цели-псевдонимы npm не принимаются `plugin add`.

## Перезагрузка

Изменения в отслеживаемых каталогах конфигурации перезагружаются автоматически. При запуске сервер сразу загружает кэшированные пакетные плагины, устанавливает отсутствующие пакеты в фоне и проверяет обновления незакреплённых плагинов npm и Git. Точные версии npm и полные хеши коммитов Git остаются закреплёнными. Изменения в неотслеживаемых локальных зависимостях всё ещё могут требовать перезапуска OpenCode.

```sh
touch .opencode/plugins/concise/index.ts
opencode service restart
```

## Desktop

Плагин, экспортирующий `./gui-experimental`, также добавляет панели, команды или настройки в OpenCode Desktop. Приложение загружает плагины с сервера, который запускает, поэтому настройте плагин в глобальном `opencode.json(c)`, чтобы использовать его в каждом окне.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "plugins": ["opencode-acme-plugin"],
}
```

**Settings > Extensions > Plugins** перечисляет их, когда выбран собственный сервер приложения. Переключатель плагина отключает только его десктопный интерфейс, а **Reload** загружает его снова после ошибки. Чтобы отключить плагин целиком, добавьте `-` и его ID в `plugins`, например `"-acme"`.

## Терминал

Плагины только для TUI настраиваются отдельно и остаются активными при подключении к удалённому серверу.

```json title="cli.json"
{
  "plugins": ["opencode-acme-cli"]
}
```
