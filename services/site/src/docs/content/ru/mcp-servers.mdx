OpenCode подключается к серверам [Model Context Protocol](https://modelcontextprotocol.io/) и предоставляет такие возможности, как инструменты, промпты, ресурсы и инструкции. Инструменты MCP расходуют контекст модели, поэтому добавляйте только нужные серверы.

## Настройка

Добавьте удалённый сервер из проекта, который должен его использовать, затем проверьте подключение:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp list
```

Команда записывает сервер в [конфигурацию](/config) проекта. Добавьте `--global`, чтобы он был доступен во всех проектах:

```sh
opencode mcp add context7 --global --url https://mcp.context7.com/mcp
```

Удалённые серверы по умолчанию используют OAuth. Если в списке указано `needs authentication`, откройте OpenCode, запустите `/mcps`, выберите сервер и войдите. Подключённый сервер готов к использованию агентом:

```text
✓ context7  connected
```

## Конфигурация

Чтобы настроить сервер вручную, задайте ему уникальное имя в `mcp.servers`. V2 не размещает имена серверов напрямую в `mcp`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
      },
    },
  },
}
```

Серверы подключаются автоматически. Используйте `disabled`, а не поле `enabled`, чтобы сервер оставался настроенным, но не подключался:

```jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "disabled": true,
      },
    },
  },
}
```

Проектная конфигурация с более высоким приоритетом заменяет весь объект сервера с тем же именем. Используйте разные имена для отдельных подключений или аккаунтов; иначе повторите каждое обязательное поле в переопределении:

```jsonc title="opencode.jsonc"
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
      },
    },
  },
}
```

## Локальные серверы

Для работы с локальным сервером OpenCode запускает команду и связывается с ней через транспорт stdio протокола MCP. Чтобы добавить сервер, укажите команду запуска после `--`:

```sh
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything
```

Передайте переменные окружения повторяющимися флагами `--env`:

```sh
opencode mcp add everything --env LOG_LEVEL=info -- npx -y @modelcontextprotocol/server-everything
```

Используйте конфигурацию для других параметров процесса, например рабочего каталога:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "everything": {
        "type": "local",
        "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
        "cwd": ".",
        "environment": {
          "LOG_LEVEL": "info",
          "MCP_API_KEY": "{env:MCP_API_KEY}",
        },
      },
    },
  },
}
```

| Поле          | Обязательно | Описание                                                                                                              |
| ------------- | ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `type`        | Да          | Должен быть `"local"`.                                                                                                |
| `command`     | Да          | Исполняемый файл и его аргументы.                                                                                     |
| `cwd`         | Нет         | Рабочий каталог процесса. Относительные пути отсчитываются от рабочего каталога проекта; он же используется по умолчанию. |
| `environment` | Нет         | Строковые переменные, добавляемые к унаследованному окружению процесса OpenCode.                                      |
| `disabled`    | Нет         | Запрещает подключение при `true`. По умолчанию `false`.                                                               |
| `codemode`    | Нет         | Установите `false`, чтобы предоставлять инструменты напрямую, а не через Code Mode. По умолчанию `true`.              |
| `timeout`     | Нет         | Переопределения тайм-аутов для сервера.                                                                               |
| `protocol`    | Нет         | `auto` (по умолчанию), `legacy` или `2026-07-28`. См. [Версия протокола](#protocol-version).                          |
| `pool`        | Нет         | Совместно использовать одно подключение между каталогами. По умолчанию `false`. См. [Общие подключения](#shared-connections). |

Используйте `{env:NAME}` для подстановки окружения. Shell-выражения вроде `$NAME` в строках JSON не раскрываются:

```jsonc
{
  "environment": {
    "MCP_API_KEY": "{env:MCP_API_KEY}",
  },
}
```

## Удалённые серверы

Удалённый сервер использует транспорт MCP Streamable HTTP и требует абсолютный URL:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
```

Передайте заголовки запроса повторяющимися флагами `--header`. Заключайте ссылки `{env:NAME}` в кавычки, чтобы shell записал их буквально:

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp --header 'CONTEXT7_API_KEY={env:CONTEXT7_API_KEY}'
```

Используйте конфигурацию для других параметров. Храните секреты в переменных окружения, а не в файле:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}",
        },
      },
    },
  },
}
```

| Поле       | Обязательно | Описание                                                                                         |
| ---------- | ----------- | ------------------------------------------------------------------------------------------------ |
| `type`     | Да          | Должен быть `"remote"`.                                                                         |
| `url`      | Да          | Абсолютный эндпоинт Streamable HTTP.                                                             |
| `headers`  | Нет         | Строковые заголовки HTTP, отправляемые эндпоинту.                                                |
| `oauth`    | Нет         | Настройки OAuth или `false`, чтобы отключить OAuth.                                              |
| `disabled` | Нет         | Запрещает подключение при `true`. По умолчанию `false`.                                          |
| `codemode` | Нет         | Установите `false`, чтобы предоставлять инструменты напрямую, а не через Code Mode. По умолчанию `true`. |
| `timeout`  | Нет         | Переопределения тайм-аутов для сервера.                                                          |
| `protocol` | Нет         | `auto` (по умолчанию), `legacy` или `2026-07-28`. См. [Версия протокола](#protocol-version).     |
| `pool`     | Нет         | Совместно использовать одно подключение между каталогами. По умолчанию `false`. См. [Общие подключения](#shared-connections). |

Используйте `oauth: false`, только когда сервер использует исключительно API-ключ или другие учётные данные в заголовке:

```jsonc
{
  "type": "remote",
  "url": "https://mcp.example.com/mcp",
  "oauth": false,
  "headers": { "Authorization": "Bearer {env:MCP_API_KEY}" },
}
```

## OAuth

OAuth включён для удалённых серверов, если `oauth` не `false`. OpenCode обнаруживает сервер авторизации, входит с PKCE и обновляет токены. Учётные данные хранятся вне конфигурации проекта.

Большинству серверов нужен только URL:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
      },
    },
  },
}
```

Если сервер требует аутентификации, запустите `/mcps`, выберите сервер и завершите авторизацию в браузере. Этот же процесс можно начать из CLI:

```sh
opencode mcp auth sentry
```

### Браузер на другой машине

Когда OpenCode работает по SSH, в контейнере или на удалённом сервере, после входа браузер не может достучаться до OpenCode и показывает незагружающуюся страницу. Скопируйте URL этой страницы из адресной строки и вставьте его в запрос входа:

```text
http://127.0.0.1:52817/callback?code=...&state=...
```

Запрос появляется в `/mcps`, в `opencode mcp auth` и в диалоге входа десктопного и веб-приложения, пока OpenCode ждёт браузер.

### Регистрация клиента

OpenCode представляется серверу авторизации первым подходящим способом:

| Способ | Используется когда |
| --- | --- |
| Предварительно зарегистрированный клиент | Настроен `oauth.client_id`. |
| [Client ID Metadata Document](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#client-id-metadata-documents) (CIMD) | Сервер авторизации поддерживает CIMD и публичные клиенты, а `oauth.redirect_uri` не задан. |
| [Динамическая регистрация клиента](https://datatracker.ietf.org/doc/html/rfc7591) (DCR) | Ни один из предыдущих способов не подходит. OpenCode регистрирует клиента, использует его при следующих входах и слушает указанный при регистрации порт. Если порт занят, OpenCode регистрирует клиента заново. |

Сервер авторизации включает CIMD через свои метаданные:

```json
{
  "issuer": "https://auth.example.com",
  "client_id_metadata_document_supported": true,
  "token_endpoint_auth_methods_supported": ["none"]
}
```

При CIMD OpenCode отправляет URL своего документа метаданных как `client_id` и пропускает регистрацию:

```text
https://opencode.ai/oauth/opencode/client.json
```

Документ разрешает эти loopback-перенаправления без порта:

- `http://127.0.0.1/callback`
- `http://localhost/callback`
- `http://127.0.0.1/mcp/oauth/callback` для старых клиентов

Серверы авторизации принимают любой loopback-порт для этих перенаправлений, как требует [RFC 8252](https://datatracker.ietf.org/doc/html/rfc8252#section-7.3), поэтому `callback_port` работает с CIMD. Пользовательский `redirect_uri` — нет, поэтому OpenCode возвращается к DCR.

Если сервер авторизации не поддерживает ни CIMD, ни DCR, настройте предварительно зарегистрированного клиента.

### Предварительно зарегистрированные клиенты

Когда провайдер выдаёт учётные данные клиента, используйте OAuth-поля V2 в snake_case:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "oauth": {
          "client_id": "{env:MCP_CLIENT_ID}",
          "client_secret": "{env:MCP_CLIENT_SECRET}",
          "scope": "tools:read tools:execute",
          "callback_port": 19876,
          "redirect_uri": "http://127.0.0.1:19876/callback",
        },
      },
    },
  },
}
```

| Поле | Описание |
| --- | --- |
| `client_id` | Предварительно зарегистрированный ID клиента. Имеет приоритет над CIMD и DCR. |
| `client_secret` | Секрет конфиденциального клиента, отправляемый в теле запроса токена. Для публичных клиентов не указывайте. |
| `scope` | Запрашиваемые области доступа через пробел. По умолчанию используется область, которую указывает сервер, отклоняя запрос без аутентификации. При обновлении токена OpenCode снова отправляет предоставленную область доступа. |
| `callback_port` | Локальный порт обратного вызова от `1` до `65535`. По умолчанию OpenCode выбирает сначала порт из `redirect_uri`, затем порт клиента, зарегистрированного при предыдущем входе, а если ни один из них не задан — свободный эфемерный порт. |
| `redirect_uri` | Предварительно зарегистрированный loopback-URI, чей путь и порт достигают локального слушателя обратного вызова. Его установка отключает CIMD. |
| `auth_server_metadata_url` | URL документа метаданных OAuth или OpenID Connect сервера авторизации. Задайте его, когда MCP-сервер не публикует метаданные защищённого ресурса с именем своего сервера авторизации. |

Удалите сохранённые учётные данные OAuth, если нужно войти снова или сменить аккаунт:

```sh
opencode mcp logout sentry
```

## Тайм-ауты

Тайм-ауты — положительные целые числа миллисекунд. Задайте значения по умолчанию в `mcp.timeout`; объект `timeout` сервера переопределяет совпадающие значения.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "timeout": {
      "startup": 45000,
      "catalog": 30000,
      "execution": 600000,
    },
    "servers": {
      "slow-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "timeout": {
          "catalog": 60000,
        },
      },
    },
  },
}
```

| Тайм-аут    | По умолчанию | К чему применяется                                                    |
| ----------- | ------------ | --------------------------------------------------------------------- |
| `startup`   | 30 секунд    | Подключение транспорта и инициализация сервера.                       |
| `catalog`   | 30 секунд    | Перечисление инструментов, промптов, ресурсов и шаблонов ресурсов.    |
| `execution` | 12 часов     | Вызовы инструментов, получение промптов и чтение ресурсов.            |

## Версия протокола

По умолчанию OpenCode проверяет каждый сервер на ревизию 2026-07-28 и возвращается к классическому рукопожатию `initialize` MCP, если сервер её не поддерживает. Установите `protocol` сервера в `legacy`, чтобы пропустить проверку:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "older": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "protocol": "legacy",
      },
    },
  },
}
```

| Значение    | Поведение                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`      | По умолчанию. Проверяет через `server/discover` ревизию 2026-07-28 и возвращается к `legacy`, если сервер её не поддерживает, в том числе когда удалённый сервер отвечает на проверку ошибкой HTTP 5xx. |
| `legacy`    | Отправляет `initialize` и говорит на ревизиях протокола до 2025-11-25.                                                                        |
| `2026-07-28` | Требует ревизию 2026-07-28. Подключение к старым серверам завершается ошибкой.                                                               |

Для проверки старого локального сервера OpenCode запускает кратковременный дополнительный процесс. Если сервер игнорирует незнакомые запросы, ожидание может продлиться до тайм-аута запуска. Задайте `legacy` для серверов, которые заведомо появились до редакции от 2026-07-28.

## Общие подключения

У одного сервера OpenCode может быть открыто много каталогов, и каждый подключается к каждому MCP-серверу самостоятельно. Установите `pool` в `true`, чтобы каталоги с одинаковыми настройками сервера делили одно подключение и один список инструментов:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "cloudflare": {
        "type": "remote",
        "url": "https://mcp.cloudflare.com/mcp",
        "pool": true,
      },
    },
  },
}
```

- Совместно используются только подключения на ревизии 2026-07-28. Сервер, отвечающий более старой ревизией, или сервер с `legacy` сохраняет одно подключение на каталог.
- Каталоги делят подключение, только когда совпадает всё, что его меняет: URL, заголовки, настройки OAuth и аккаунт входа для удалённого сервера, а также команда, рабочий каталог и окружение для локального. Тайм-ауты и `protocol` тоже должны совпадать. Имя сервера может отличаться, но входы хранятся по имени, поэтому OAuth-сервер делится только под одним именем.
- Один локальный сервер можно использовать для нескольких каталогов на этой машине, но не для каталогов в рабочем пространстве. Для совместного использования несколькими проектами задайте фиксированный `cwd`, например `"~"`. Иначе в каталоге каждого проекта запустится отдельный сервер, а OpenCode запишет предупреждение.
- В общем подключении не передаются корневые каталоги. Если инструмент запрашивает данные у пользователя, запрос появляется там, где был вызван инструмент.
- Подключение закрывается, как только закрывается последний каталог, который его использует, или в этом каталоге отключают сервер.

## Имена

OpenCode называет инструмент `<server>_<tool>`. Он заменяет символы, кроме букв, цифр, `_` и `-`, на `_`:

```text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id
```

Промпты MCP становятся командами с именем `<server>:<prompt>` с той же нормализацией. Например:

```text
/context_7:find_docs
```

Текст команды заполняет аргументы промпта по порядку. Разделяйте их пробелами и заключайте в кавычки значения с пробелами:

```text
/context_7:find_docs react "server components"
```

Выбирайте короткие имена серверов, остающиеся уникальными после нормализации. В стандартном Code Mode инструменты группируются по нормализованному имени сервера:

```text
tools.context_7.resolve_library_id(...)
```

## Разрешения

Code Mode используется по умолчанию. Установите `codemode` в `false`, если инструменты сервера должны оставаться в нативном списке инструментов провайдера:

```jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "codemode": false,
      },
    },
  },
}
```

Используйте действия разрешений, чтобы скрыть или запретить инструменты, не отключая их сервер. Сопоставляйте нормализованное имя `<server>_<tool>`:

```jsonc
{
  "permissions": [
    {
      "action": "context7_*",
      "resource": "*",
      "effect": "deny",
    },
  ],
}
```

## Ресурсы

Агенты читают ресурсы MCP через два встроенных инструмента, `list_mcp_resources` и `read_mcp_resource`. Управляйте ими через эти действия разрешений:

| Действие                      | Ресурс            |
| ----------------------------- | ----------------- |
| `opencode_list_mcp_resources` | Имя сервера.      |
| `opencode_read_mcp_resource`  | `<server>:<uri>`  |

Например, разрешите всё чтение с сервера `docs`:

```jsonc
{
  "permissions": [
    {
      "action": "opencode_read_mcp_resource",
      "resource": "docs:*",
      "effect": "allow",
    },
  ],
}
```

## Инструкции сервера

Когда сервер возвращает инструкции при инициализации, OpenCode добавляет их в системный промпт:

```text
<mcp_instructions>
  <server name="sentry">
    Search for an existing issue before creating a new one.
  </server>
</mcp_instructions>
```

Для серверов, использующих Code Mode, OpenCode добавляет строку о том, где агент может найти инструменты сервера.

Инструкции сервера опускаются, если разрешения агента запрещают все его инструменты. Если они запрещают `execute`, инструменты сервера перечисляются напрямую, а его инструкции сохраняются без строки Code Mode.

## Запросы ввода

Серверы могут запрашивать ввод во время вызова через MCP elicitation. OpenCode показывает запрос в виде формы или ссылки для URL-запросов:

```text
sentry is requesting input
```

Закрытие формы отменяет запрос.

## Контекст

Для вызовов от имени сессии OpenCode отправляет ID сессии в `CallToolRequest.params._meta["ai.opencode/sessionID"]`. Это касается прямых инструментов и Code Mode через stdio и Streamable HTTP:

```json
{
  "method": "tools/call",
  "params": {
    "name": "lookup",
    "arguments": { "query": "example" },
    "_meta": { "ai.opencode/sessionID": "ses_..." }
  }
}
```

ID передаётся в метаданных запроса, а не в аргументах инструмента, поэтому модель не видит его в схеме. Используйте его как непрозрачный идентификатор для сопоставления запросов:

| Правило    | Поведение                                                                  |
| ---------- | -------------------------------------------------------------------------- |
| Идентичность | Он идентифицирует вызывающую сессию OpenCode, а не сессию транспорта MCP. |
| Наличие    | Может отсутствовать для вызовов без контекста сессии.                      |
| Безопасность | Не используйте его сам по себе для аутентификации или авторизации.       |
| Приватность | Удалённые серверы получают сырой ID и могут записывать или хранить его.   |

## Управление

Перечислите серверы и их текущее состояние подключения из любого проекта:

```sh
opencode mcp list
```

Используйте `/mcps` в OpenCode, чтобы просматривать, подключать, отключать и аутентифицировать серверы. CLI добавляет серверы и управляет учётными данными OAuth:

```sh
opencode mcp add sentry --url https://mcp.sentry.dev/mcp
opencode mcp auth sentry
opencode mcp logout sentry
```

Запустите `opencode mcp auth` без имени, чтобы выбрать из серверов с поддержкой OAuth:

```sh
opencode mcp auth
```

Чтобы удалить сервер, удалите его запись из проектной или глобальной конфигурации, куда он был добавлен:

```jsonc
{
  "mcp": {
    "servers": {},
  },
}
```

Отключение сервера в `/mcps` не меняет конфигурацию. Редактируйте конфигурацию напрямую для настроек клиента OAuth, тайм-аутов, рабочих каталогов или чтобы оставить сервер отключённым:

```jsonc
{
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
        "disabled": true,
      },
    },
  },
}
```
