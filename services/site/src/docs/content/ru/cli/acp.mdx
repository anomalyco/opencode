`opencode acp` запускает OpenCode как агента [Agent Client Protocol](https://agentclientprotocol.com), поэтому его можно использовать из ACP-клиента вроде Zed. Этот пример добавляет OpenCode в Zed:

```json title="~/.config/zed/settings.json"
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

Другие ACP-клиенты используют ту же команду и аргумент `acp`, но их файл конфигурации и имена полей могут отличаться. Если графический клиент не находит `opencode`, укажите в `command` абсолютный путь, который выводит `which opencode`.

## Аутентификация

OpenCode использует уже имеющиеся учётные данные провайдеров. Войдите из терминала перед запуском ACP-клиента:

```bash
opencode auth login
```

OpenCode предлагает один способ аутентификации, `opencode-login`. По умолчанию это способ аутентификации агента. Запрос `authenticate` принимает только этот способ и не собирает учётные данные. Если промпт завершается ошибкой из-за того, что провайдеру нужна аутентификация, OpenCode возвращает ошибку ACP `auth_required`.

Если клиент устанавливает `clientCapabilities.auth.terminal` в `true`, способ аутентификации становится терминальным:

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "type": "terminal",
  "args": ["--login"]
}
```

Клиент не должен отправлять этот способ в `authenticate`. Вместо этого он добавляет `--login` к команде запуска OpenCode, например `opencode acp --login`, и выполняет её в терминале. OpenCode запускает поток `opencode auth login` и завершается. Код выхода 0 означает успешный вход. Затем клиент переподключается и снова отправляет `initialize`.

Если клиент устанавливает `clientCapabilities._meta["terminal-auth"]` в `true`, способ аутентификации включает команду входа:

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "_meta": { "terminal-auth": { "command": "opencode", "args": ["auth", "login"], "label": "OpenCode Login" } }
}
```

## Устранение неполадок

`opencode acp` ждёт сообщения ACP в stdin, поэтому при прямом запуске в терминале выглядит зависшим. Запускайте его из ACP-клиента.

Если клиент сообщает, что процесс завершился или вывел недопустимый вывод протокола, добавьте `--print-logs` перед `acp` в аргументах клиента. Тогда OpenCode пишет свои журналы ACP и приватного сервера в stderr. Stdout содержит только сообщения ACP.

```bash
opencode --print-logs acp
```

## Справочник по протоколу

Этот раздел для авторов ACP-клиентов. В нём перечислены части ACP, которые поддерживает OpenCode, и ключи `_meta`, которые OpenCode добавляет. Клиенты, не знающие этих ключей, могут их игнорировать. Сообщения определяет [документация ACP](https://agentclientprotocol.com).

### Транспорт

Клиент запускает `opencode acp` как дочерний процесс. Они обмениваются сообщениями JSON-RPC, разделёнными переводами строк, через stdin и stdout, используя версию протокола ACP 1.

`opencode acp` запускает приватный сервер OpenCode для собственного использования. Он не подключается к общему фоновому сервису и не открывает сетевой порт для ACP. Один процесс может обслуживать много сессий ACP. Он завершается, когда клиент закрывает stdin.

### Возможности

Ответ OpenCode на `initialize` включает следующие возможности агента:

```json
{
  "loadSession": true,
  "mcpCapabilities": { "http": true, "sse": false },
  "promptCapabilities": { "embeddedContext": true, "image": true },
  "sessionCapabilities": {
    "additionalDirectories": {},
    "close": {},
    "delete": {},
    "fork": {},
    "list": {},
    "resume": {}
  }
}
```

OpenCode читает следующие возможности клиента:

| Возможность                            | Действие                                                             |
| -------------------------------------- | -------------------------------------------------------------------- |
| `auth.terminal` в `true`               | Способ аутентификации становится [терминальным](#authentication).    |
| `elicitation.form`                     | OpenCode задаёт [вопросы](#questions) в виде форм.                   |
| `session.compaction`                   | OpenCode сообщает о [сжатии контекста](#compaction) через обновления ACP. |
| `_meta["terminal-auth"]` в `true`      | Способ аутентификации включает [команду входа](#authentication).     |

### Сессии

Клиент задаёт рабочий каталог при создании сессии. OpenCode использует конфигурацию этого каталога, включая его модели, агентов, команды, навыки, инструкции, плагины и MCP-серверы.

- `cwd` должен быть абсолютным путём. OpenCode отклоняет относительный `cwd` ошибкой недопустимых параметров.
- `session/load` воспроизводит сохранённые сообщения. `session/resume` и `session/fork` их не воспроизводят.
- Чтобы загрузить, возобновить или ответвить сессию, клиент должен передать каталог этой сессии как `cwd` или другой каталог того же проекта, например основную рабочую копию сессии, перемещённой в worktree. OpenCode отклоняет любой другой `cwd` ошибкой недопустимых параметров, где `data.directory` — каталог сессии.
- `session/list` возвращает до 100 сессий на страницу. Он принимает фильтр `cwd` и `cursor`. Каждая сессия субагента несёт `_meta["opencode/child-session"]` со своими `id`, `parentID` и `title`.
- Когда OpenCode переименовывает сессию, например после генерации заголовка, он отправляет `session_info_update` с новым `title`.
- `session/close` прерывает активную работу и отсоединяет сессию от процесса ACP. OpenCode сохраняет сессию.
- `session/delete` завершает активный промпт как `session/cancel`, затем удаляет сессию. Удаление несуществующей сессии завершается успешно.
- Сессия выполняет один промпт за раз. OpenCode возвращает ошибку на второй `session/prompt`, пока активен первый.
- Если промпт завершается ошибкой, `data` ошибки содержит `errorName` сбоя. Там же `status` и `retryAfterMs`, если провайдер их отправил.

### Отмена

`session/cancel` завершает активный промпт со `stopReason: "cancelled"`. `$/cancel_request` для запроса промпта делает то же. OpenCode отклоняет ожидающие запросы разрешений. Вызовы инструментов, не завершившиеся после отмены, он сообщает как `failed`.

### Дополнительные каталоги

Клиент может передать `additionalDirectories` в `session/new`, `session/load`, `session/resume` и `session/fork`:

```json
{ "cwd": "/work/app", "additionalDirectories": ["/work/shared"], "mcpServers": [] }
```

- Каждая запись должна быть абсолютным путём без `*` и `?`.
- OpenCode разрешает доступ к внешним каталогам внутри каждого корня. Правила разрешений на чтение, изменение и shell по-прежнему действуют.
- Список каждого запроса заменяет предыдущий список сессии, как указывает
  [RFD о дополнительных каталогах](https://agentclientprotocol.com/rfds/additional-directories).
- OpenCode сохраняет разрешения в сессии, поэтому они действуют и когда сессию использует другой клиент OpenCode. Дочерние сессии копируют разрешения при создании.

`session/list` возвращает сохранённый список каждой сессии в `additionalDirectories`.

### Параметры конфигурации

Новые сессии используют модель и основного агента каталога по умолчанию. Ответы на `session/new`, `session/load`, `session/resume` и `session/fork` включают следующие параметры конфигурации:

| ID       | Категория       | Значения                                                                        |
| -------- | --------------- | ------------------------------------------------------------------------------- |
| `model`  | `model`         | Включённые модели в виде `provider/model`. Суффикс `/variant` также задаёт интенсивность. |
| `effort` | `thought_level` | Варианты модели и `default`. Присутствует только у моделей с вариантами.         |
| `mode`   | `mode`          | Видимые основные агенты.                                                         |

Каждый параметр `model` называется по отображаемому имени провайдера и имени модели, например `Anthropic / Claude Sonnet 5.5`. `session/set_config_option` принимает строковые значения:

```json
{ "sessionId": "ses_123", "configId": "model", "value": "anthropic/claude-sonnet-5-5" }
```

`session/set_mode` также задаёт агента. OpenCode отправляет `config_option_update`, когда меняются доступные модели или агенты. Он также отправляет его, когда другой клиент меняет модель или агента сессии.

### Содержимое промпта

Промпты могут содержать текст, изображения, встроенные ресурсы и ссылки на ресурсы. OpenCode игнорирует аудиоблоки. С другими блоками он обращается так:

| Блок                                                  | Что делает OpenCode                                                                     |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `text`                                                | Отправляет модели.                                                                      |
| `text` только с аудиторией `assistant`                | Отправляет модели как отдельный контекст вне сообщения пользователя.                    |
| `text` только с аудиторией `user`                     | Не включает во вход модели.                                                             |
| `image` с `data`                                      | Прикрепляет к промпту.                                                                  |
| `image` только с `uri`                                | Обрабатывает как ссылку на ресурс.                                                      |
| `resource` с `text`                                   | Встраивает текст после пути или URI ресурса.                                            |
| `resource` с `blob`                                   | Прикрепляет. Без `mimeType` определяет его по имени файла URI.                          |
| `resource_link` на URI `file:`                        | Прикрепляет файл. Отправляет ссылку Markdown, если файл отсутствует или нечитаем.       |
| `resource_link` на URI `zed://` с запросом `path`     | Прикрепляет файл по `path`.                                                             |
| `resource_link` на другой URI                         | Отправляет ссылку Markdown вроде `[spec](https://example.com/spec.md)`.                 |

Аудитория берётся из `annotations` блока. OpenCode отклоняет блок `image` без `data` и без `uri`. Этот блок — контекст только для модели:

```json
{ "type": "text", "text": "Open file: src/app.ts", "annotations": { "audience": ["assistant"] } }
```

### Команды

После `session/new`, `session/load`, `session/resume` или `session/fork` OpenCode отправляет `available_commands_update` с командами каталога, встроенной командой `compact` и навыками каталога. Он отправляет ещё одно обновление при изменении команд или навыков.

```json
{
  "sessionUpdate": "available_commands_update",
  "availableCommands": [{ "name": "compact", "description": "Compact the session" }]
}
```

Если промпт начинается с `/` и имени доступной команды, OpenCode запускает эту команду и передаёт остальной текст как аргументы. Если после `/` указан ID навыка, OpenCode отправляет промпт с этим навыком во вложении. В остальных случаях текст, начинающийся с `/`, отправляется как обычный промпт. `/compact` запускает [сжатие контекста](/compaction). Навыки, ID которых совпадают с именами команд, не показываются в списке.

Если команда завершается ошибкой, промпт завершается её собственным сообщением, например справкой по использованию, а `data.service` устанавливается в `command`.

### MCP-серверы

Клиент может передать stdio- и HTTP-серверы MCP в `session/new`, `session/load`, `session/resume` и `session/fork`. OpenCode добавляет их в каталог сессии на время жизни процесса `opencode acp`, поэтому другие сессии в этом каталоге могут их использовать. Если OpenCode выгружает простаивающий каталог, он добавляет их снова перед следующим промптом сессии. OpenCode передаёт заголовки HTTP и не использует OAuth для этих серверов. Он не объявляет MCP через SSE и не поддерживает MCP через ACP.

| Случай                                | Поведение                                                          |
| ------------------------------------- | ------------------------------------------------------------------ |
| Имя совпадает с настроенным сервером  | Сервер клиента заменяет настроенный в этом каталоге.               |
| [Политики](/policies)                 | Правила `integration.use` по-прежнему действуют.                   |

```json
{ "type": "http", "name": "docs", "url": "https://mcp.example.com", "headers": [] }
```

### Разрешения

Запросы разрешений предлагают три варианта:

```json
[
  { "optionId": "once", "kind": "allow_once", "name": "Allow once" },
  { "optionId": "always", "kind": "allow_always", "name": "Always allow" },
  { "optionId": "reject", "kind": "reject_once", "name": "Reject" }
]
```

Когда запрос меняет файлы, OpenCode включает содержимое `diff`, если может построить предпросмотр изменения.

### Вопросы

Если клиент объявляет `elicitation.form`, OpenCode задаёт вопросы через `elicitation/create` в режиме формы. Запрос включает `toolCallId`, когда OpenCode отправил этот вызов инструмента как `session/update` для этой сессии.

```json
{
  "mode": "form",
  "sessionId": "ses_123",
  "toolCallId": "call_1",
  "message": "Which package manager?",
  "requestedSchema": {
    "type": "object",
    "properties": { "pm": { "type": "string", "oneOf": [{ "const": "bun", "title": "Bun" }] } },
    "required": ["pm"]
  }
}
```

- OpenCode никогда не отправляет формы, через которые можно получить секреты. Вопрос с готовыми вариантами, похожий на запрос секрета, например «Which API token should I use?», всё равно отправляется, но без возможности ввести свой ответ.
- Если кроме готовых вариантов можно ввести свой ответ, схема добавляет необязательное строковое свойство `<key>_custom`. Если можно выбрать только один вариант, непустой ответ пользователя заменяет его. Если можно выбрать несколько, OpenCode добавляет ответ к выбранным вариантам.
- Если пользователь отклоняет или отменяет форму, OpenCode отменяет вопрос.

Если OpenCode не может показать вопрос, он отменяет его и просит модель продолжить без ответа.

### Сжатие контекста

Если клиент объявляет `session.compaction`, OpenCode сообщает о сжатии контекста через обновления `compaction_update` и `compaction_summary_chunk` из RFD ACP [session compaction](https://agentclientprotocol.com/rfds/session-compaction) со статусом Preview. Когда клиент загружает сессию, OpenCode отправляет по одному обновлению для каждого завершённого или неудачного сжатия.

```json
{
  "sessionUpdate": "compaction_update",
  "compactionId": "msg_123",
  "status": "completed",
  "summary": [{ "type": "text", "text": "..." }]
}
```

Другие клиенты вместо этого получают [маркер сжатия](#compaction-marker). Такой же маркер используется при сжатии в дочерних сессиях.

### Использование

Ответ на промпт включает `usage` из RFD [end-turn usage](https://agentclientprotocol.com/rfds/end-turn-token-usage), который является черновиком. `usage` суммирует вызовы модели этого промпта в этой сессии. Он не включает дочерние сессии.

```json
{ "stopReason": "end_turn", "usage": { "inputTokens": 1200, "outputTokens": 340, "totalTokens": 1540 }, "_meta": {} }
```

Перед ответом OpenCode отправляет `usage_update` из RFD [session usage](https://agentclientprotocol.com/rfds/session-usage). Он отправляет его, только если промпт использовал токены и OpenCode знает размер контекста модели. `cost` — общая стоимость сессии и её дочерних сессий в USD.

```json
{ "sessionUpdate": "usage_update", "used": 1540, "size": 200000, "cost": { "amount": 0.012, "currency": "USD" } }
```

### Дочерние сессии

Пока выполняется промпт, OpenCode отправляет обновления своих дочерних сессий как уведомления `session/update` в сессии промпта. Каждое обновление несёт `_meta["opencode/child-session"]`. OpenCode предваряет ID вызовов инструментов `<childSessionId>:`. Он предваряет заголовки вызовов инструментов заголовком дочерней сессии, если он у неё есть.

```json
{
  "sessionUpdate": "tool_call",
  "toolCallId": "ses_child:call_1",
  "title": "Explore the codebase: src/app.ts",
  "_meta": {
    "opencode/child-session": { "id": "ses_child", "parentID": "ses_123", "depth": 1, "title": "Explore the codebase" }
  }
}
```

| Поле       | Тип      | Описание                                                                                    |
| ---------- | -------- | ------------------------------------------------------------------------------------------- |
| `id`       | `string` | ID дочерней сессии.                                                                         |
| `parentID` | `string` | ID родительской сессии дочерней сессии.                                                     |
| `depth`    | `number` | 1 для дочерней сессии промпта, 2 для дочерней сессии той дочерней сессии и так далее.       |
| `title`    | `string` | Заголовок дочерней сессии. OpenCode опускает его, если у дочерней сессии нет заголовка.      |

Запросы разрешений из дочерней сессии несут тот же ключ в `toolCall._meta`. После завершения промпта OpenCode перестаёт отправлять обновления дочерних сессий. Запросы разрешений и вопросы из дочерних сессий всё равно доходят до клиента.

### Статус повтора

Когда вызов модели завершается ошибкой и OpenCode планирует повтор, он отправляет `session_info_update` с `_meta["opencode/retry"]`. Когда повтор начинается, OpenCode отправляет `"opencode/retry": null`. Очищайте статус повтора при получении ответа на промпт.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": {
    "opencode/retry": {
      "attempt": 1,
      "nextRetryAt": "2026-10-02T12:00:05.000Z",
      "error": { "type": "provider.rate-limit", "message": "Rate limit exceeded", "status": 429 }
    }
  }
}
```

| Поле          | Тип      | Описание                                                                                          |
| ------------- | -------- | ------------------------------------------------------------------------------------------------- |
| `attempt`     | `number` | Номер попытки повтора.                                                                            |
| `nextRetryAt` | `string` | Время следующей попытки в формате ISO 8601.                                                       |
| `error`       | `object` | Содержит `type` и `message`. Также `status` и `response.body`, если провайдер их отправил.        |

### Маркер сжатия

Если клиент не объявляет `session.compaction`, OpenCode сообщает о ходе сжатия через `session_info_update` с `_meta["opencode/compaction"]`. Для сжатия в дочерних сессиях OpenCode всегда использует маркер.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": { "opencode/compaction": { "status": "started", "messageId": "msg_123", "reason": "auto" } }
}
```

| Поле        | Тип      | Описание                                                                          |
| ----------- | -------- | ---------------------------------------------------------------------------------- |
| `status`    | `string` | `started`, `completed` или `failed`. При отмене сжатия — `failed`. |
| `messageId` | `string` | Связывает начало сжатия с его завершением. Не интерпретируйте содержимое этого ключа. |
| `reason`    | `string` | `auto` или `manual`.                                                              |
| `error`     | `object` | Присутствует при `status` равном `failed`. Та же форма, что у `error` в [повторе](#retry-status). |

Маркер не содержит сводку. Автоматическое сжатие может завершиться ошибкой без маркера `started`. Когда клиент загружает сессию, OpenCode отправляет по одному маркеру для каждого завершённого или неудачного сжатия.
