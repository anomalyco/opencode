В OpenCode есть множество встроенных тем для светлого и тёмного режимов. Выберите тему в настройках или составьте собственную палитру.

## Выбор темы

Нажмите `Ctrl+P`, выберите **Open settings**, затем откройте **Theme**. Тема по умолчанию — `opencode`. Прежняя тема по умолчанию по-прежнему доступна как `opencode-classic`.

Также тему и режим можно задать в глобальных [настройках CLI](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Запустите `/themes`, чтобы менять темы, не открывая настройки.

## Системные цвета

Если OpenCode может прочитать палитру терминала, в списке тем появляется `system`. Тема использует цвет текста, фон и палитру ANSI терминала.

Имя темы `system` выбирает цвета, производные от терминала. Режим `system` следует светлому или тёмному оформлению терминала.

## Режим

Используйте `system`, чтобы следовать оформлению терминала, или зафиксируйте тему в светлом либо тёмном режиме:

| Режим    | Поведение                                                     |
| -------- | ------------------------------------------------------------- |
| `system` | Следует определённому светлому или тёмному оформлению терминала. |
| `dark`   | Всегда использует тёмные цвета темы.                          |
| `light`  | Всегда использует светлые цвета темы.                         |

Это соответствует полю `mode` внутри `theme` в конфигурации CLI. Если пользовательская тема предоставляет только один режим, OpenCode использует его, когда запрошен другой.

## Добавление темы

Чтобы добавить скачанную или полученную от кого-то тему, скопируйте её JSON-файл в глобальный каталог тем:

```bash
cp theme.json ~/.config/opencode/themes/
```

Также можно поместить тему в каталог `.opencode/themes` проекта, чтобы она была доступна только в нём.

Имя файла становится именем темы. Например, `my-theme.json` появляется как `my-theme`. После добавления файла перезапустите OpenCode, затем запустите `/themes`, чтобы выбрать её.

OpenCode читает только файлы `.json`. Тема ближе к текущему каталогу заменяет глобальную или родительскую тему с тем же именем.

## Темы в плагинах

[Плагины TUI](/build/plugins/cli) получают значения цветов через `context.theme`, а текущий режим — через `context.themeMode`. Используйте семантические токены, чтобы плагин подстраивался под выбранную тему:

```tsx title="Inside a TUI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

Публичный API плагинов TUI не регистрирует темы. Добавляйте определения пользовательских тем JSON-файлами в каталоги выше.

## Создание темы

Используйте наш [инструмент тем](https://opencode.ai/theme/), чтобы создавать или редактировать темы. Он помогает понять структуру, изменить её и задать собственные цвета. Объяснение ниже приведено для справки.

Тема отделяет общие семантические токены от палитр конкретных режимов:

| Раздел        | Назначение                                                                 |
| ------------- | -------------------------------------------------------------------------- |
| `base`        | Полное дерево токенов, общее для всех режимов.                             |
| `light`, `dark` | Полная палитра оттенков и необязательные переопределения токенов для этого режима. |

Каждая тема предоставляет полную `base` и определяет хотя бы один режим `light` или `dark`. Режимы наследуют из `base` файла; они не наследуют от встроенной темы OpenCode или друг от друга.

Примеры ниже показывают только разделы, относящиеся к каждому понятию. Прежде чем настраивать, создайте полный файл в редакторе тем.

### Структура

Поместите цвета, используемые обоими режимами, в `base`, затем при необходимости переопределите их в `light` или `dark`:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

Полная `base` предоставляет каждый семантический токен. Каждый режим предоставляет каждый обязательный оттенок и может переопределять любую часть дерева базовых токенов.

### Цвета и ссылки

Цвет может быть hex-значением, `"transparent"` или ссылкой на другой цвет темы:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Оттенки

Оттенки — девятиступенчатые цветовые шкалы. Каждый режим определяет восемь базовых оттенков и три псевдонима:

| Вид        | Значения                                                             |
| ---------- | -------------------------------------------------------------------- |
| Базовые    | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Псевдонимы | `accent`, `interactive`, `neutral`                                   |
| Шаги       | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900`        |

Определите все девять шагов базового оттенка или сделайте псевдоним одного оттенка на другой:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Порядок оттенков зависит от режима: в светлой теме шкала идёт от тёмного `100` к светлому `900`, в тёмной — от светлого `100` к тёмному `900`.

Массив `categorical` в `base` задаёт упорядоченные оттенки для различения агентов и других повторяющихся элементов:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Семантические токены

Семантические токены назначают цвета ролям интерфейса. Компоненты используют эти роли, а не выбирают цвета напрямую.

| Группа                | Назначение                                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `text`                | Базовый, приглушённый, слабый текст, выделение, действия, поля форм и обратная связь. `faint` по умолчанию равен `muted`. |
| `background`          | База, выделение, приподнятые поверхности, действия, поля форм и заливки обратной связи.             |
| `border`, `scrollbar` | Цвета границ и полос прокрутки.                                                                     |
| `diff`                | Цвета добавленных, удалённых, контекстных, подсвеченных строк и номеров строк.                      |
| `syntax`              | Подсветка исходного кода.                                                                           |
| `markdown`            | Элементы Markdown.                                                                                  |

Например, `text.muted` управляет вторичным текстом, а `background.raised` задаёт последовательно приподнятые поверхности:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

`text.selection` и `background.selection` окрашивают текст, выделенный мышью или клавиатурой. По умолчанию они используют сфокусированное основное действие: `text.action.primary.$focused` на `background.action.primary.$focused`.

Ключи подсветки: `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` и `punctuation`.

Ключи Markdown: `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` и `codeBlock`.

### Действия и состояния

У действий есть варианты `primary`, `secondary` и `destructive`. Действия и поля форм используют `base` и необязательные состояния взаимодействия:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Ключи состояний: `$hovered`, `$focused`, `$pressed`, `$selected` и `$disabled`. Неуказанное состояние использует цвет `base` этого действия или поля формы.

### Поверхность диалога

Панели, диалоги, меню и уведомления выбирают глубину из `background.raised`. Диалоги дополнительно могут переопределять семантические токены через `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI заново разрешает ссылки после применения `@dialog`, поэтому токены, ссылающиеся на `$background.base`, следуют фону диалога. Контекстная `base` действия становится запасным значением для его неуказанных состояний; явные переопределения состояний по-прежнему побеждают.
