title: "Провайдеры в CLI"

---

Подключите провайдера в TUI, затем выберите одну из его моделей:

```text
/connect
/models
```

`/connect` перечисляет интеграции, доступные с текущего сервера и проекта. Выберите провайдера, выберите способ аутентификации, если их несколько, и следуйте подсказкам.

## TUI

TUI поддерживает API-ключи, OAuth и команды аутентификации провайдеров. OAuth открывает URL авторизации или показывает код для ввода; нажмите `o`, чтобы открыть URL, и `c`, чтобы скопировать данные авторизации.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

Запустите `/connect` снова, чтобы добавить другой аккаунт. Выбор уже подключённого провайдера открывает список его аккаунтов, где можно активировать, переименовать или удалить сохранённый аккаунт.

## CLI

Команда `auth login` поддерживает те же способы аутентификации, что и TUI, но не открывает его. Если не указать провайдера, команда предложит выбрать его в интерактивном списке.

```bash
opencode auth login
```

Передайте ID или имя интеграции, чтобы пропустить первый выбор. Используйте `--method key`, чтобы явно выбрать ввод API-ключа.

```bash
opencode auth login anthropic --method key
```

ID способов зависят от провайдера. Запустите команду без `--method`, чтобы увидеть доступные способы, если у провайдера их несколько.

```bash
opencode auth login openai
```

Ввод API-ключа и формы провайдера требуют интерактивного терминала. Способы OAuth, просящие вставить код авторизации, тоже требуют его.

## Способы

OpenCode получает учётные данные провайдера четырьмя способами интеграции:

| Способ      | Поведение                                                                                                             |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| API key     | Запрашивает секрет и сохраняет его как аккаунт провайдера.                                                            |
| OAuth       | Предоставляет URL браузера, код устройства или запрос кода авторизации, затем сохраняет токены и обновляет их, если поддерживается. |
| Command     | Запускает команду аутентификации, предоставленную провайдером, и сохраняет её стандартный вывод как ключ.             |
| Environment | Читает поддерживаемую переменную из процесса сервера, не сохраняя её.                                                 |

Провайдеры могут добавлять формы к способам API-ключа и OAuth для обязательных данных, например имени ресурса Azure или домена GitHub Enterprise. CLI и TUI показывают эти формы перед началом аутентификации.

## Окружение

Задайте поддерживаемую переменную окружения провайдера в процессе сервера, который выполняет запросы к моделям. Для разового частного сервера передайте её при запуске standalone-режима.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

Для общего фонового сервера добавьте переменную в его управляемое окружение. Это останавливает работающий сервис; следующая команда OpenCode запускает его с новым значением.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

Подключения через окружение появляются в `auth list` с типом `environment`. Это не аккаунты: `auth logout` не может их удалить, поэтому снимите переменную, чтобы отключиться. Сохранённый аккаунт имеет приоритет над подключением через окружение для той же интеграции.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

Некоторые провайдеры могут искать учётные данные в стандартных для них источниках вместо использования переменной окружения с API-ключом:

- Amazon Bedrock поддерживает стандартную цепочку учётных данных AWS, включая профили, окружения с ключами доступа, веб-идентичность и учётные данные контейнера. Он также поддерживает `AWS_BEARER_TOKEN_BEDROCK`.
- Google Vertex использует Application Default Credentials и должен иметь возможность определить проект. Например, выполните `gcloud auth application-default login` и задайте `GOOGLE_CLOUD_PROJECT`.
- Azure предлагает **Microsoft Entra ID (Azure CLI)** как способ подключения, когда установлен `az`. Сначала выполните `az login`, затем выберите этот способ в `/connect` или `auth login azure`.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

О настройке конкретных провайдеров и серверной стороне см. [Провайдеры](/providers).

## Аккаунты

Каждый успешный вход по API-ключу, OAuth или команде создаёт сохранённый аккаунт. Самый новый аккаунт становится активным; переключайте активный аккаунт по его метке или ID учётных данных.

```bash
opencode auth list
opencode auth switch anthropic work
```

Удалите сохранённый аккаунт через `auth logout`. Обе команды открывают выбор, если аргументы опущены.

```bash
opencode auth logout anthropic work
```

В TUI `/connect` предоставляет те же операции добавления, активации, переименования и удаления для сохранённых аккаунтов.

## Хранение

Сохранённые API-ключи и токены OAuth хранятся в базе данных SQLite сервера. Для локального сервера выведите путь к базе данных командой:

```bash
opencode debug paths db
```

Обычный путь релиза — `~/.local/share/opencode/opencode.db`; его могут изменить `XDG_DATA_HOME`, канал релиза и `OPENCODE_DB`. Не редактируйте базу данных для управления учётными данными; используйте `/connect` или команды `auth`.

При миграции базы данных V2 импортирует поддерживаемые учётные данные из устаревшего `auth.json` в каталоге данных OpenCode. Новые и обновлённые учётные данные хранятся в SQLite и не записываются обратно в этот файл.
