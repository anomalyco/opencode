Разрешения определяют, может ли агент выполнить действие с ресурсом.

## Настройка

Частая настройка: спрашивать перед выполнением shell-команд, разрешать обычную проверку Git и всегда блокировать push. Добавьте эти упорядоченные правила в `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

Побеждает последнее подходящее правило, поэтому конкретные исключения идут после широкого правила.

<Callout type="warning">
  В V1 используются другие имена полей и действий. В V2 используйте `permissions`, `shell` и `subagent` вместо
  `permission`, `bash` и `task`.
</Callout>

## Правила

Каждое правило требует три строковых поля:

| Поле       | Значение                                                                        |
| ---------- | ------------------------------------------------------------------------------- |
| `action`   | Действие разрешения инструмента                                                 |
| `resource` | Используемое значение: путь, команда, URL, запрос, ID навыка или ID агента      |
| `effect`   | `allow`, `deny` или `ask`                                                       |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| Эффект  | Результат                             |
| ------- | ------------------------------------- |
| `allow` | Продолжить без запроса                |
| `deny`  | Заблокировать операцию                |
| `ask`   | Дождаться решения от клиента          |

Если ни одно правило не подошло, OpenCode использует `ask`.

## Сопоставление

Действия и ресурсы используют простые подстановочные знаки для всего значения:

| Шаблон | Совпадение                                |
| ------ | ----------------------------------------- |
| `*`    | Ноль или более символов, включая `/`      |
| `?`    | Ровно один символ                         |
| Другое | Сам символ                                |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

Этот шаблон сопоставляется со всем нормализованным путём. Обратные слеши нормализуются в прямые, а в Windows регистр не учитывается.

Shell-шаблон, оканчивающийся на ` *`, также совпадает с командой без аргументов:

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

Он совпадает и с `git status`, и с `git status --short`.

OpenCode объединяет правила по порядку и использует последнее совпадение. Сначала загружается конфигурация с более низким приоритетом, затем добавляются глобальные правила, а последними — правила агента.

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

Операция может проверять несколько ресурсов, например патч, затрагивающий несколько файлов. Любой `deny` запрещает операцию; иначе любой `ask` запрашивает подтверждение; иначе операция разрешается.

## Действия

В V2 имена действий — строки, поэтому плагины могут определять дополнительные действия. Встроенные инструменты сейчас используют следующие действия и ресурсы:

| Действие                      | Ресурс                                                                                                                     |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `read`                        | Внутренний путь относительно локации или канонический абсолютный внешний путь                                              |
| `edit`                        | Целевой путь для `edit`, `write` и `patch`                                                                                 |
| `glob`                        | Запрошенный glob-шаблон                                                                                                    |
| `grep`                        | Запрошенное регулярное выражение, а не путь поиска                                                                         |
| `shell`                       | Строка команды, сформированная сканером; составные команды могут давать несколько строк                                     |
| `subagent`                    | ID целевого агента                                                                                                         |
| `skill`                       | ID навыка                                                                                                                  |
| `question`                    | `*`                                                                                                                        |
| `webfetch`                    | Запрошенный URL                                                                                                            |
| `websearch`                   | Поисковый запрос                                                                                                           |
| `generate_image`              | Выбранная модель изображений в виде `providerID/modelID` плюс `#variant`, если задан                                       |
| `external_directory`          | Граница канонического внешнего каталога, обычно заканчивающаяся на `/*`                                                    |
| `<server>_<tool>`             | `*` для инструмента MCP; неподдерживаемые символы в обоих именах заменяются на `_`                                         |
| `opencode_list_mcp_resources` | Имя MCP-сервера                                                                                                            |
| `opencode_read_mcp_resource`  | `<server>:<uri>`                                                                                                           |
| `execute`                     | `*`; запрет убирает Code Mode и перечисляет его инструменты напрямую, а вложенные инструменты применяют свои правила        |

Например, разрешите один навык и запретите все остальные:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

`doom_loop` и `lsp` не входят в текущие действия разрешений V2 Core.

## Каталоги

Если путь находится и за пределами активной локации, и за пределами её worktree проекта, не совпадающей с корнем файловой системы, OpenCode проверяет `external_directory` до проверки правил `read` или `edit`. Политика по умолчанию разрешает `external_directory`, поэтому без дополнительного правила подтверждение при доступе к внешним путям не требуется. Чтобы OpenCode запрашивал подтверждение при любом доступе за пределами проекта:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "*", "effect": "ask" },
  ],
}
```

Более узкие правила после него могут разрешать или запрещать конкретные каталоги:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

Это касается внешних путей, используемых `read`, `edit`, `write` и `patch`. Shell проверяет свой внешний рабочий каталог и каталоги, выведенные сканером, перед проверкой ресурсов `shell`.

Для `external_directory`, `read` и `edit` ведущие `~`, `~/`, `$HOME` или `$HOME/` раскрываются при загрузке конфигурации:

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

Ресурсы shell остаются необработанным текстом команды и не раскрываются относительно домашнего каталога.

<Callout type="warning">
  `shell` работает с правами пользователя хоста на файловую систему, процессы и сеть. Вывод каталогов из текста команды
  выполняется по возможности, поэтому предпочитайте узкий белый список shell, а не шаблоны, которые должны распознавать
  все опасные команды.
</Callout>

Относительный путь при записи может выйти за пределы активной локации, но остаться внутри worktree проекта. Явно заданные внешние пути приводятся к каноническому виду перед сопоставлением, поэтому разрешайте доступ только к доверенным каталогам.

## Сканер

Проверки разрешений shell используют встроенный сканер shell в OpenCode для Bash, Zsh, POSIX `sh` и PowerShell. Некоторые команды нельзя безопасно проанализировать, например команды с некорректным синтаксисом или динамическим вычислением вроде `eval`. Если применимо какое-либо правило deny для `shell`, такая команда завершается ошибкой сканера, потому что её подкоманды нельзя проверить по правилу запрета. В остальных случаях требуется подтверждение для всей команды как одного ресурса `shell` и для `external_directory` `*`. Второе подтверждение может дать только правило, разрешающее все каталоги, или пользователь, и ни одно из подтверждений не сохраняется как шаблон.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [
    {
      "permissions": [
        { "action": "shell", "resource": "git status *", "effect": "allow" },
        { "action": "shell", "resource": "rm *", "effect": "deny" },
      ],
    },
  ],
}
```

Правила разрешений, сохранённые шаблоны подтверждений и вывод каталогов по возможности применяются к каждой извлечённой подкоманде и цели `cd`. Для неизвестных каталогов нет отдельного режима подтверждения или общего ограничения.

## Значения по умолчанию

Каждый агент, включая пользовательских, начинает с этой упорядоченной базовой политики:

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

Поставляемые агенты добавляют следующие политики:

| Агент        | Дополнительная политика                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `build`      | Разрешает вопросы                                                                                                               |
| `plan`       | Разрешает вопросы; запрещает изменения, кроме файлов в `~/.opencode/plan`                                                        |
| `general`    | Запрещает вопросы и запуск субагентов                                                                                           |
| `explore`    | Запрещает всё, кроме shell, чтения, glob, grep, веб-загрузок, веб-поиска и внешних каталогов; запрашивает подтверждение для `.env` |
| `title`      | Запрещает все действия                                                                                                          |
| `summary`    | Запрещает все действия                                                                                                          |
| `compaction` | Сохраняет базовую политику                                                                                                      |

Поскольку ни одно правило по умолчанию не запрашивает `external_directory`, чтение и изменения за пределами локации и worktree выполняются без запроса. Добавьте правило `ask` или `deny` для `external_directory`, как показано в разделе [Каталоги](#directories), чтобы вернуть запрос или заблокировать внешний доступ. Последующие глобальные правила и правила агента переопределяют эти значения по умолчанию.

## Агенты

Размещайте общие правила на верхнем уровне, а более узкие — в `agents.<id>.permissions`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

Правила агента добавляются после глобальных правил и не заменяют глобальный массив. Пользовательский субагент использует свои разрешения, а не подмножество разрешений родителя.

## Подтверждения

Когда правило даёт `ask`, клиенты могут ответить:

| Вариант      | Ответ    | Результат                                                                   |
| ------------ | -------- | --------------------------------------------------------------------------- |
| Allow once   | `once`   | Одобрить только ожидающий запрос                                            |
| Allow always | `always` | Одобрить его и сохранить предложенные инструментом шаблоны для проекта      |
| Reject       | `reject` | Отклонить его и все остальные ожидающие запросы разрешений в этой сессии    |

Например, выбор **Allow always** для `git status --short` может сохранить префикс shell, который охватит последующие команды `git status`:

```text
shell: git status * → allow
```

Сохранённые подтверждения — это постоянные правила `allow` в рамках проекта. Они никогда не переопределяют настроенный `deny`. Инструменты сами выбирают предлагаемый шаблон: некоторые предлагают `*`, shell предлагает префиксы команд, веб-загрузки — сайт URL (например, `https://opencode.ai/*`), а навыки и субагенты — свои ID. Просматривайте широкие подтверждения и удаляйте ненужные.

При отклонении клиенты могут приложить комментарий. Неинтерактивные клиенты должны сами решать, как обрабатывать запросы подтверждения; настроенные правила `deny` всегда действуют.

## Политики

После применения этих правил и сохранённых подтверждений [политика](/policies) может окончательно запретить действие. Она меняет результат `allow` или `ask` на `deny` и никогда не даёт доступ.

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

Глобальные политики и политики, управляемые из Console, переопределяют конфигурацию проекта — так организация блокирует команду, которую репозиторий разрешил бы.
