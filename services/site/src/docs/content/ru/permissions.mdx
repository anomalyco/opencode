Разрешения определяют, может ли агент выполнить действие с ресурсом.

## Настройка

Типичная настройка: запрашивать подтверждение перед выполнением команд оболочки, разрешать обычный просмотр состояния репозитория Git и всегда блокировать push. Добавьте приведённые правила в `opencode.jsonc`, сохранив их порядок:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

Действует последнее подходящее правило, поэтому конкретные исключения указывают после общего правила.

<Callout type="warning">
  В V1 используются другие имена полей и действий. В V2 используйте `permissions`, `shell` и `subagent` вместо
  `permission`, `bash` и `task`.
</Callout>

## Правила

Каждое правило требует три строковых поля:

| Поле       | Значение                                                                        |
| ---------- | ------------------------------------------------------------------------------- |
| `action`   | Действие инструмента, для которого проверяется разрешение                       |
| `resource` | Используемое значение: путь, команда, URL, запрос, ID навыка или ID агента      |
| `effect`   | `allow`, `deny` или `ask`                                                       |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| Эффект  | Результат                             |
| ------- | ------------------------------------- |
| `allow` | Продолжить без запроса                |
| `deny`  | Заблокировать операцию                |
| `ask`   | Дождаться решения от клиента          |

Если ни одно правило не подошло, OpenCode использует `ask`.

## Сопоставление

Шаблоны действий и ресурсов поддерживают простые подстановочные знаки и сопоставляются со значением целиком:

| Шаблон | Совпадение                                |
| ------ | ----------------------------------------- |
| `*`    | Ноль или более символов, включая `/`      |
| `?`    | Ровно один символ                         |
| Другое | Сам символ                                |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

Этот шаблон сопоставляется с нормализованным путём целиком. Обратные слеши заменяются прямыми, а в Windows регистр не учитывается.

Шаблон команды оболочки, оканчивающийся на ` *`, подходит и для команды без аргументов:

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

Под этот шаблон подпадают и `git status`, и `git status --short`.

OpenCode объединяет списки правил и применяет последнее подходящее правило. Сначала загружается конфигурация с более низким приоритетом, затем добавляются глобальные правила, а последними — правила агента.

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

Для одной операции могут проверяться несколько ресурсов. Например, патч может затрагивать несколько файлов. Если хотя бы для одного ресурса действует `deny`, операция запрещена. Если запретов нет, но есть хотя бы один `ask`, потребуется подтверждение. В остальных случаях операция разрешена.

## Действия

В V2 имена действий — строки, поэтому плагины могут определять дополнительные действия. Встроенные инструменты сейчас используют следующие действия и ресурсы:

| Действие                      | Ресурс                                                                                                                     |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `read`                        | Внутренний путь относительно локации или канонический абсолютный внешний путь                                              |
| `edit`                        | Целевой путь для `edit`, `write` и `patch`                                                                                 |
| `glob`                        | Запрошенный glob-шаблон                                                                                                    |
| `grep`                        | Запрошенное регулярное выражение, а не путь поиска                                                                         |
| `shell`                       | Строка команды, сформированная сканером; составные команды могут давать несколько строк                                     |
| `subagent`                    | ID целевого агента                                                                                                         |
| `skill`                       | ID навыка                                                                                                                  |
| `question`                    | `*`                                                                                                                        |
| `webfetch`                    | Запрошенный URL                                                                                                            |
| `websearch`                   | Поисковый запрос                                                                                                           |
| `generate_image`              | Выбранная модель изображений в виде `providerID/modelID` плюс `#variant`, если задан                                       |
| `external_directory`          | Граница внешнего каталога в канонической форме, обычно с окончанием `/*`                                                   |
| `<server>_<tool>`             | `*` для инструмента MCP; в обоих именах сохраняются буквы, цифры, `_` и `-`, остальные символы заменяются на `_`          |
| `opencode_list_mcp_resources` | Имя MCP-сервера                                                                                                            |
| `opencode_read_mcp_resource`  | `<server>:<uri>`                                                                                                           |
| `execute`                     | `*`; при запрете Code Mode не предоставляется, а вместо него перечисляются его инструменты. К вложенным инструментам применяются их собственные правила |

В именах действий MCP дефисы сохраняются. Поэтому инструментам сервера `mcp-atlassian` соответствует шаблон `mcp-atlassian_*`, а не `mcp_atlassian_*`.

Например, разрешите один навык и запретите все остальные:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

В текущей версии V2 Core `doom_loop` и `lsp` не используются для проверки разрешений.

## Каталоги

Если путь находится вне активной локации и вне worktree проекта, OpenCode проверяет `external_directory` перед правилами `read` или `edit`. Worktree учитывается, только если не совпадает с корнем файловой системы. По умолчанию политика разрешает `external_directory`, поэтому без дополнительного правила доступ к внешним путям не требует подтверждения. Чтобы OpenCode запрашивал подтверждение при любом доступе за пределами проекта:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "*", "effect": "ask" },
  ],
}
```

Более узкие правила после него могут разрешать или запрещать конкретные каталоги:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

Это касается внешних путей, используемых `read`, `edit`, `write` и `patch`. Для команд оболочки OpenCode сначала проверяет внешний рабочий каталог и каталоги, которые определил сканер, а затем — ресурсы `shell`.

Для `external_directory`, `read` и `edit` сокращения `~`, `~/`, `$HOME` и `$HOME/` в начале пути заменяются путём к домашнему каталогу при загрузке конфигурации:

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

Для команд оболочки ресурсом служит исходный текст команды. Подстановки пути к домашнему каталогу не выполняются.

<Callout type="warning">
  `shell` работает с правами пользователя хоста на доступ к файловой системе, процессам и сети. По тексту команды
  не всегда можно определить все затронутые каталоги. Лучше явно разрешить только нужные команды, чем пытаться
  охватить шаблонами все опасные команды.
</Callout>

Относительный путь при записи может выйти за пределы активной локации, но остаться внутри worktree проекта. Явно заданные внешние пути приводятся к каноническому виду перед сопоставлением, поэтому разрешайте доступ только к доверенным каталогам.

## Сканер

Для проверки разрешений OpenCode анализирует команды Bash, Zsh, POSIX `sh` и PowerShell встроенным сканером. Некоторые команды нельзя безопасно разобрать — например, если в них есть синтаксические ошибки или они выполняют код динамически, как `eval`. Если применимо хотя бы одно правило deny для `shell`, сканер возвращает ошибку: он не может проверить подкоманды по этому правилу. В противном случае нужно подтвердить всю команду как один ресурс `shell` и отдельно разрешить `external_directory` для `*`. Доступ ко всем каталогам может разрешить только пользователь или правило, охватывающее все каталоги. Ни одно из этих подтверждений не сохраняется в виде шаблона.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [
    {
      "permissions": [
        { "action": "shell", "resource": "git status *", "effect": "allow" },
        { "action": "shell", "resource": "rm *", "effect": "deny" },
      ],
    },
  ],
}
```

К каждой выделенной подкоманде и каждому каталогу назначения `cd` применяются правила разрешений и сохранённые шаблоны подтверждений. Сканер определяет затронутые каталоги там, где это возможно. Для неизвестных каталогов нет отдельного режима подтверждения или общего ограничения.

## Значения по умолчанию

Для всех агентов, в том числе пользовательских, действует следующий базовый набор правил в указанном порядке:

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

Встроенные агенты добавляют следующие правила:

| Агент        | Дополнительная политика                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `build`      | Разрешает вопросы                                                                                                               |
| `plan`       | Разрешает вопросы; запрещает изменения, кроме файлов в `~/.opencode/plan`                                                        |
| `general`    | Запрещает вопросы и запуск субагентов                                                                                           |
| `explore`    | Запрещает всё, кроме команд оболочки, чтения, поиска glob и grep, загрузки веб-страниц, веб-поиска и доступа к внешним каталогам. Запрашивает подтверждение при чтении `.env` |
| `title`      | Запрещает все действия                                                                                                          |
| `summary`    | Запрещает все действия                                                                                                          |
| `compaction` | Сохраняет базовую политику                                                                                                      |

Правила по умолчанию не требуют подтверждения для `external_directory`, поэтому читать и изменять файлы за пределами локации и worktree можно без подтверждения. Чтобы запрашивать подтверждение или запретить доступ, добавьте правило `ask` или `deny` для `external_directory`, как описано в разделе [Каталоги](#directories). Глобальные правила и правила агента, применяемые позже, имеют приоритет над этими настройками.

## Агенты

Размещайте общие правила на верхнем уровне, а более узкие — в `agents.<id>.permissions`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

Правила агента добавляются после глобальных, а не заменяют их. Пользовательский субагент использует собственные разрешения: они не ограничены разрешениями родительского агента.

## Подтверждения

Если правило требует подтверждения (`ask`), клиент может ответить одним из следующих способов:

| Вариант      | Ответ    | Результат                                                                   |
| ------------ | -------- | --------------------------------------------------------------------------- |
| Allow once   | `once`   | Одобрить только ожидающий запрос                                            |
| Allow always | `always` | Одобрить его и сохранить предложенные инструментом шаблоны для проекта      |
| Reject       | `reject` | Отклонить его и все остальные ожидающие запросы разрешений в этой сессии    |

Например, если выбрать **Allow always** для `git status --short`, OpenCode может сохранить префикс команды, который подойдёт и для последующих вызовов `git status`:

```text
shell: git status * → allow
```

Сохранённые подтверждения — это постоянные правила `allow` для проекта. Они не могут отменить явно заданный `deny`. Каждый инструмент сам предлагает шаблон для сохранения: некоторые предлагают `*`, команды оболочки — префикс команды, загрузка веб-страниц — шаблон для сайта по URL (например, `https://opencode.ai/*`), а навыки и субагенты — свои ID. Проверяйте разрешения с широким охватом и удаляйте те, которые больше не нужны.

При отклонении клиенты могут приложить комментарий. Неинтерактивные клиенты должны сами решать, как обрабатывать запросы подтверждения; настроенные правила `deny` всегда действуют.

## Политики

После применения этих правил и сохранённых подтверждений [политика](/policies) может окончательно запретить действие. Она меняет результат `allow` или `ask` на `deny` и никогда не даёт доступ.

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

Глобальные политики и политики, управляемые из Console, переопределяют конфигурацию проекта — так организация блокирует команду, которую репозиторий разрешил бы.
