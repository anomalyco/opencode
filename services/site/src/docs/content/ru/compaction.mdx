Сжатие контекста освобождает место в длинной сессии: OpenCode заменяет ранние сообщения сводкой, чтобы работа могла продолжаться, даже если вся история не помещается в контекстное окно модели.

## Как это работает

Когда контекстное окно модели почти заполнено, OpenCode составляет сводку всего диалога. Вместе со сводкой он сохраняет последние сообщения — по умолчанию около 15 000 токенов, — чтобы не потерять точные детали недавнего обсуждения.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

Если провайдер это поддерживает, отправка полного диалога позволяет при запросе сводки использовать кэш промптов обычного запроса. При следующем сжатии OpenCode обновляет сводку по сообщениям после этого чекпоинта.

## Запуск

Автоматическое сжатие включено по умолчанию:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

При сжатии часть контекста теряется. Если важно сохранить точные детали последних сообщений, увеличьте `keep.tokens` или запустите сжатие вручную, не дожидаясь автоматического.

## Ручной запуск

Сжатие можно запустить в любой момент, даже если история пока короткая:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

Команда `api` находит фоновый сервис и аутентифицируется в нём. Её ответ подтверждает, что запрос принят; она не ждёт сводку. Следите за событиями `session.compaction.*`, чтобы узнать о завершении. О полной операции см. [справочник API](/api).

| Правило    | Поведение                                                              |
| ---------- | ---------------------------------------------------------------------- |
| Момент     | Выполняется в следующей безопасной точке, перед промптами, которые ещё ждут. |
| Повторы    | Запросы, сделанные пока один ожидает, объединяются с ним.              |
| Автоматика | Работает, когда `compaction.auto` равен `false`.                       |

Передайте `id`, чтобы точный повтор был идемпотентным. Повторное использование этого ID для другого запроса возвращает конфликт.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## Настройки

Добавьте `compaction` в любой [файл конфигурации OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": "20%",
  },
}
```

| Поле          | По умолчанию        | Поведение                                                                                                                  |
| ------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `auto`        | `true`              | Сжимать контекст, когда окно почти заполнено, и один раз повторять запрос после сжатия, если провайдер отклонил его из-за длины. Ручное сжатие работает всегда. |
| `background`  | `true`              | Готовить сводку заранее, чтобы не ждать её при автоматическом сжатии. См. [Фоновое сжатие контекста](#background-compaction). |
| `keep.tokens` | `15000`             | Приблизительный объём недавнего разговора, сохраняемого рядом со сводкой. Большие значения сохраняют больше деталей, но оставляют меньше места для новой работы. |
| `buffer`      | `"15%"`, не менее 16k | Доля контекстного окна модели, которую OpenCode оставляет свободной. Автоматическое сжатие начинается, когда диалог заполняет остальную часть окна. Чем больше буфер, тем раньше начнётся сжатие. |

`keep.tokens` принимает неотрицательное целое число.

### Буфер

`buffer` — процент от окна каждой модели, поэтому одна настройка подходит всем моделям:

| Окно модели | `"buffer": "20%"` сжимает при |
| -----------: | ----------------------------: |
| 128k | ~102k |
| 1M | 800k |

- Это запас свободного места, а не порог сжатия: при `"20%"` сжатие начнётся, когда окно заполнится на 80%.
- Принимает от `"1%"` до `"99%"`, включая десятичные значения вроде `"12.5%"`.
- Число токенов вроде `20000` тоже работает. Одно и то же число — большая доля малого окна и малая доля большого.
- Число токенов, не меньшее окна модели, игнорируется, и применяется значение по умолчанию.

## Модель

По умолчанию OpenCode пишет сводку сам, используя модель сессии. Задайте `agents.compaction.model`, чтобы использовать для сводок другую модель:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" },
  },
}
```

Если указанную модель не удаётся найти, OpenCode использует модель сессии.

## Фоновое сжатие контекста

OpenCode заранее готовит сводку, не прерывая сессию, и подставляет её, когда пора сжимать контекст. Это позволяет при автоматическом сжатии не приостанавливать сессию ради составления сводки:

```text
60k tokens before the threshold   summary of the conversation so far starts in the background
                                  the session keeps going; the summary is held, not applied
threshold                         the held summary is swapped in; everything since it is kept as is
```

При небольшом контекстном окне подготовка сводки начинается не позднее середины пути от первого ответа после предыдущего сжатия до порога сжатия.

| Правило      | Поведение                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Стоимость    | Запрос сводки переиспользует кэш промптов. Сводка, которая так и не была использована, например потому что сессия завершилась до порога, всё равно расходует токены. |
| Ожидание     | Если к моменту сжатия сводка ещё не готова, сессия ждёт её завершения. |
| Обычное сжатие | OpenCode составляет сводку как обычно, если после подготовки фоновой сводки диалог вырос более чем примерно на 40% от порога сжатия либо если его начало изменилось. |
| Пропуск      | Фоновая сводка не используется при сжатии на стороне провайдера. Сразу после смены модели или после паузы дольше срока жизни кэша промптов подготовка сводки начинается со следующего ответа. |
| Хранение     | Подготовленные сводки хранятся в памяти и теряются при перезапуске. |

Отключите фоновое сжатие, чтобы OpenCode составлял сводку только тогда, когда пора сжимать контекст:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "background": false,
  },
}
```

## Провайдеры

Некоторые провайдеры могут сжимать разговор на своей стороне. Включите это для провайдера или модели через `settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Настройка модели переопределяет настройку провайдера. При `native` контекст сжимает провайдер, при `summary` — OpenCode.

При сжатии на стороне провайдера OpenCode отправляет диалог в эндпоинт сжатия. Провайдер возвращает непрозрачный зашифрованный элемент взамен ранней части диалога. Вместе с ним сохраняются ваши недавние сообщения и вложения в пределах `keep.tokens`:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| Тема          | Поведение                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Поддержка     | Модели OpenAI Responses. Поддержка зависит от развёртывания и модели.                                                                     |
| Порог         | Те же настройки `auto` и `buffer`, что при сжатии с помощью сводки. Ручные запросы тоже работают. |
| Переносимость | Зашифрованный чекпоинт работает только с тем же провайдером и моделью. При смене модели сессия продолжается с исходного разговора.        |
| Слишком длинный запрос | Если провайдер отклоняет запрос на сжатие из-за длины, OpenCode отправляет более короткий запрос. На сводку он не переключается. |

## Сводки

Сводка структурирована так, чтобы другой агент мог продолжить работу по ней:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

Она охватывает цель и требования, решения, выполненную и текущую работу, блокеры и следующие шаги, а также соответствующие файлы. В недавнем разговоре рядом с ней длинный вывод инструментов сокращается, а данные вложений заменяются кратким описанием.

После сжатия за основу берутся текущие версии файлов с инструкциями. См. раздел [Инструкции](/instructions).

## Ограничения

| Ограничение | Результат                                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Модель      | OpenCode составляет сводку с помощью модели из `agents.compaction.model`, а если она не задана, использует модель сессии. При сжатии на стороне провайдера всегда используется модель сессии. |
| История     | Сжатие заменяет раннюю часть диалога. Если запрос в основном состоит из неизменных инструкций и схем инструментов, освободить место не получится. |
| Размер      | Если сам диалог слишком длинный для сжатия, OpenCode отправляет сокращённую текстовую версию и может опустить самые ранние реплики. |
| Восстановление | Запрос, отклонённый как слишком длинный, сжимается и повторяется один раз. Второй отказ возвращается как ошибка.                                     |
| Хранение    | Более ранние сообщения остаются сохранёнными, даже когда больше не отправляются модели.                                                                |

Например, здесь сжатие не поможет:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## Миграция

В V1 сохранялись последние реплики, а старый вывод инструментов обрезался. В V2 используются сводки и `compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

Настройки и поведение на этой странице относятся к V2.
