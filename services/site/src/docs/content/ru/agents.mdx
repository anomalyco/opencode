---
title: "Агенты"
description: "Определяйте переиспользуемых агентов в Markdown или конфигурации, у каждого свой системный промпт, модель, разрешения и режим."
---

Создайте Markdown-файл, чтобы добавить агента для повторного использования. В этом примере основной агент сможет запускать проверку кода через агента с доступом только на чтение:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-5-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Попросите основного агента использовать его:

```text
Use the reviewer subagent to review my current changes.
```

Агент объединяет системный промпт, предпочитаемую модель, разрешения и параметры отображения в именованный профиль ассистента.

## Расположение

Markdown-агенты можно хранить глобально для всех проектов или внутри проекта:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode ищет проектные каталоги `.opencode` от текущего каталога до корня файловой системы. Вложенный путь становится частью ID агента:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Форматы

### Markdown

Frontmatter принимает те же поля, что и запись `agents` в конфигурации. Тело Markdown становится системным промптом агента (`system`):

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

Поля frontmatter из V1 устарели. О том, как читаются файлы, которые всё ещё их используют, см. в разделе [Файлы агентов](/migrate-v1#agent-files).

### JSONC

Определите агентов в разделе `agents` любого [файла конфигурации OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Выбор по умолчанию

Задайте основного агента, который используется, если в сессии не выбран другой:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

Выбранный агент должен существовать, быть видимым и поддерживать работу в роли основного. Иначе OpenCode попробует использовать `build`, а если он не подходит — первого видимого агента, способного быть основным. Изменение параметра не заменяет агента, сохранённого в существующей сессии.

## Режимы

Задайте `mode` в зависимости от того, где должен работать агент:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Режим | Поведение |
| --- | --- |
| `primary` | Работает как основной агент сессии. Это режим по умолчанию для нового пользовательского агента. |
| `subagent` | Работает только в дочерней сессии через инструмент `subagent`. |
| `all` | Работает и как основной агент, и как субагент. |

Субагенты начинают работу с чистым контекстом в собственных дочерних сессиях и всегда работают в фоне. Родительский агент получает отчёт, когда субагент переходит в режим ожидания, и снова после каждого следующего этапа работы. Разрешения `subagent` определяют, каких субагентов родительский агент может запускать. Сам субагент использует собственные разрешения.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Встроенные агенты

OpenCode включает следующие видимые агенты:

| Агент | Режим | Назначение |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Агент для программирования по умолчанию. Инструменты и доступ за пределами рабочей директории разрешены по умолчанию; чтение конфиденциальных файлов окружения требует подтверждения. |
| **Plan** (`plan`) | `primary` | Исследует проект и планирует, не изменяя обычные файлы проекта. По запросу может записывать файлы планов OpenCode; shell-команды по-прежнему контролируются разрешениями. |
| **General** (`general`) | `subagent` | Выполняет исследования и многошаговую работу с широким доступом к инструментам, но не может запускать других субагентов. |
| **Explore** (`explore`) | `subagent` | Ищет и читает код или веб-источники, не изменяя файлы. |

Переопределите встроенного агента, используя тот же ID:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Скрытые агенты `compaction`, `title` и `summary` выполняют служебные задачи, и их нельзя выбрать напрямую. В V2 нет встроенного агента `scout`.

## Слияние

Определения агентов объединяются в порядке загрузки конфигурации. Более поздние скалярные значения заменяют более ранние, настройки запросов объединяются по ключам, а правила разрешений добавляются в конец списка:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

Глобальные `permissions` применяются раньше правил конкретного агента, поэтому последующие правила агента могут их уточнять.

## Параметры

### Описание

`description` объясняет назначение агента. Добавьте её субагентам, потому что OpenCode показывает её модели, которая выбирает, какого агента запустить:

```yaml
description: Reviews database migrations for safety
```

### Режим

`mode` принимает `primary`, `subagent` или `all`. Если у нового пользовательского агента режим не указан, используется `primary`:

```yaml
mode: all
```

### Модель

`model` использует `provider/model` с необязательным `#variant`:

```yaml
model: anthropic/claude-sonnet-5-5#high
```

В JSON-конфигурации также доступна развёрнутая форма:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-5-5",
        "variant": "high",
      },
    },
  },
}
```

- Субагент использует настроенную модель или наследует модель родительской сессии, если модель не задана.
- Сессия хранит выбранную модель отдельно. Выбор основного агента по ID не меняет эту модель.

### System

`system` задаёт системный промпт агента. Непустое значение заменяет базовый промпт провайдера для этого агента:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

Инструкции проекта, навыки, референсы и другие источники инструкций при этом добавляются. В Markdown-агенте разместите этот текст в теле документа, а не в поле frontmatter `system`.

### Разрешения

`permissions` — упорядоченный список правил сопоставления:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Поле | Значение |
| --- | --- |
| `action` | Инструмент или действие разрешения. Поддерживаются подстановочные знаки. |
| `resource` | Путь, команда, ID агента или другое значение, с которым сопоставляется действие. Поддерживаются подстановочные знаки. |
| `effect` | `allow`, `ask` или `deny`. |

Побеждает последнее подходящее правило, поэтому ставьте широкие правила перед исключениями. Распространённые действия:

| Действие | Что охватывает |
| --- | --- |
| `shell` | Shell-команды |
| `edit` | Инструменты edit, write и patch |
| `subagent` | Дочерние агенты |
| `read`, `glob`, `grep` | Инструменты локального поиска |
| `webfetch`, `websearch` | Веб-инструменты |
| `skill` | Загрузка навыков |

Для ресурсов `read`, `edit` и `external_directory` OpenCode раскрывает `~` и `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Ресурсы shell остаются необработанным текстом команды и такие значения не раскрывают.

### Шаги

`steps` задаёт положительное максимальное число шагов модели:

```yaml
steps: 8
```

На последнем шаге OpenCode убирает инструменты и просит модель подвести итог текстом. Новый ввод пользователя сбрасывает лимит.

### Скрытие

`hidden` убирает агента из обычных списков, интерактивного выбора и каталога субагентов:

```yaml
hidden: true
```

Это управляет видимостью, а не безопасностью. Чтобы ограничить поведение, используйте разрешения.

### Цвет

`color` задаёт цвет агента в интерфейсе шестизначным hex-значением:

```yaml
color: "#ff6b6b"
```

### Отключение

`disabled` убирает встроенного или пользовательского агента на этом этапе загрузки конфигурации:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Запрос

`request` принимает для каждого агента переопределения заголовков и JSON-тела запроса:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  Раннер сессий V2 сохраняет эти значения, но пока не отправляет их с запросами к модели. Настройте активные параметры
  запроса на провайдере, модели или варианте модели.
</Callout>

Не используйте устаревшие поля верхнего уровня, такие как `temperature`, `top_p`, `prompt`, `permission`, `tools`, `disable` или `maxSteps`, в новой конфигурации агентов V2.
