`@opencode/client` — TypeScript-клиент для HTTP API OpenCode. Используйте его, когда приложение подключается к серверу OpenCode по сети. Его нативные типы и методы генерируются из того же контракта, что и [справочник API](/api). Типы RPC плагинов берутся из импортированных определений RPC.

## Установка

```sh
bun add @opencode/client
```

## Создание клиента

Создайте клиент с URL сервера, затем вызывайте методы, сгруппированные по ресурсам API:

```ts
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})
```

## Заголовки и запросы

Передайте стандартные заголовки аутентификации или приложения в `OpenCode.make` через `headers`. Также можно предоставить собственную реализацию `fetch`. Каждая операция принимает параметры запроса последним аргументом для `AbortSignal` или заголовков конкретного запроса. Исключение — подписки на события: они принимают только локальную для подписчика отмену и используют заголовки базового клиента.

```ts
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})
```

## Потоковая передача событий

Потоковые эндпоинты возвращают асинхронные итерируемые объекты:

```ts
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}
```

Подписчики на встроенные события и события RPC используют одно соединение на клиент. Соединение открывается не при создании клиента, дескриптора или итерируемого объекта, а при начале чтения. Прерывание итерации или отмена подписки завершает только соответствующий итератор. Когда отписывается последний подписчик, соединение закрывается. Источник ждёт, пока все активные подписчики примут событие, поэтому перед длительной обработкой помещайте события в буфер.

Подписки доставляют только новые события, без повторной доставки и автоматического переподключения. При сбое источника текущие подписки завершаются. После восстановления подпишитесь заново. Подключившийся позже подписчик на встроенные события получает текущий маркер `server.connected`, а не прошлые события приложения.

Передайте `types`, чтобы получать только некоторые типы событий. События типизируются соответствующим образом, а `server.connected` всегда проходит, чтобы отфильтрованный подписчик знал, когда синхронизироваться заново. Фильтрация происходит в общем соединении, внутри клиента.

```ts
for await (const event of client.event.subscribe({ types: ["config.updated"] })) {
  // event.type is "config.updated" | "server.connected"
}
```

## RPC плагинов

Импортируйте общий контракт плагина и передайте его в `client.rpc`:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
```

Второй необязательный аргумент метода содержит `location`, `signal` и `headers` отдельно от входных данных, определённых плагином. Пропущенная локация следует нативным значениям запроса по умолчанию: заголовки базовой локации, затем рабочий каталог сервера. При создании подклиента локация не выбирается.

Методы выводят аргументы и результаты из определения. Разбор схем относится к границе контракта; вызывающие отправляют принятое представление входа, а обработчики получают разобранные значения. Promise-клиент принимает определения Standard Schema или обычной JSON Schema и не запускает парсеры схем локально: сервер возвращает уже разобранный и преобразованный вывод. Определения Effect Schema требуют Effect-клиента.

Объявленные ошибки методов отклоняются как ошибки других эндпоинтов Promise-клиента, а перехваченные ошибки остаются без типа. Общие обёртки ошибок HTTP RPC удаляются типизированным подклиентом. Зарезервированные сбои фреймворка `rpc.*` остаются обычными сбоями RPC, а несвязанные ошибки аутентификации, транспорта и протокола сохраняют обычные представления клиента.

Подписки RPC используют локальные имена и получают события этого RPC по всем локациям. Проверяйте обязательный `event.location`, чтобы фильтровать их. `events.subscribe` соответствует нативному API асинхронных итераторов:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

`events.on` — удобная обёртка над тем же источником. Она возвращает функцию отписки; асинхронные обратные вызовы ожидаются последовательно. Сбои обратного вызова или источника записываются в журнал и завершают этот слушатель. Нативные и типизированные подписки получают один и тот же обычный конверт `rpc.<rpcID>.<event>` с данными события в виде объекта. Живые подписки не повторяют пропущенные события.

Серверный плагин должен быть настроен и реализовывать RPC; импорт определения его не регистрирует. Об API определения и регистрации см. [RPC плагинов](/build/plugins/rpc). Любой HTTP-клиент также может вызвать общий маршрут `POST /api/rpc/{rpcID}/{method}` с `{ "input": ... }` и получить `{ "output": ... }`. Пропущенные поля input/output означают отсутствие значения.

## Локальный фоновый сервис

Основные точки входа клиента совместимы с браузером и не включают управление локальными процессами. В приложении Node импортируйте нативный API сервиса Promise из `@opencode/client/service`.

- `Service.discover()` возвращает рабочую зарегистрированную конечную точку, не запуская процесс.
- `Service.ensure()` возвращает совместимый сервис, запуская его при необходимости.
- `Service.stop()` останавливает именно зарегистрированный экземпляр сервиса.
- `Service.headers(endpoint)` создаёт заголовки аутентификации для клиента.

```ts
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()
```

`Service.ensure()` принимает необязательные файл регистрации, версию, команду сервиса и обратный вызов `onStart`. `version` принимает точное значение или предикат совместимости:

```ts
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})
```

Опустите эти параметры, чтобы использовать стандартный путь регистрации и команду `opencode serve --service`.
