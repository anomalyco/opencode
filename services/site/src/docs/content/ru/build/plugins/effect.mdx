`@opencode/plugin/effect` — версия API плагинов OpenCode, нативная для Effect. Его операции контекста возвращают
Effect или Stream, обратные вызовы возвращают Effect, а время жизни плагина представлено `Scope`.

OpenCode предоставляет `effect` (включая экспортируемые подпути `effect/*`) и `@opencode/plugin` во время работы при загрузке
плагинов и их зависимостей из `node_modules`. Устанавливайте их как peer/dev-зависимости для локальной проверки типов и тестирования,
а не включайте в бандл плагина.

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

Экспортируйте Effect-плагин из `.opencode/plugins/`, чтобы он загружался автоматически.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Опубликованные пакеты и каталоги плагинов вне `.opencode/plugins/` используют ту же конфигурацию `plugins`, что и другие серверные
плагины.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

О включении, разрешении пакетов и приоритете конфигурации см. [Настройка плагинов](/plugins).

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Жизненный цикл

`effect` выполняется при загрузке плагина. При перезагрузке или выгрузке область видимости Effect закрывается: регистрации отменяются, файберы завершаются, а финализаторы выполняются.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Для фоновой работы запускайте файберы в области видимости плагина. При очистке файбер прерывается.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Контекст

Контекст предоставляет Effect-клиент подключённого сервера OpenCode, а также преобразования, хуки, хранилище,
перезагрузки и параметры только для плагинов. Он не предоставляет приватные сервисы Core OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

Определение плагина и полный контекст объявлены так.

```ts

  readonly generate: Pick<ExperimentalGenerateApi<unknown>, "text">

}
```

### Параметры

Передавайте параметры объектной формой в `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Читайте параметры из `ctx.options`. Сужайте неизвестные значения перед использованием.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Преобразования

Преобразования синхронно редактируют состояние через редактор. OpenCode применяет преобразования в порядке регистрации внутри каждого
домена. Сначала источники добавляют провайдеров и неизменяемые определения моделей; затем преобразования моделей редактируют кандидатов
активных провайдеров. Возврат регистрации через yield оставляет её в scope плагина.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Преобразование модели может применять политику ко всей коллекции кандидатов активных провайдеров.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Вызывайте `reload`, когда меняется внешнее состояние, используемое преобразованием. Здесь `loadFromSource()` возвращает
записи `{ info: Provider.Info, models: readonly Model.Info[] }`; перезагрузки провайдеров также инвалидируют весь результат моделей.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Агент

Прочитайте всех агентов или получите одного по ID. Ответы клиента включают разрешённую локацию и данные схемы.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Преобразуйте или перезагружайте агентов.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Провайдеры

Прочитайте доступных провайдеров или метаданные одного провайдера по ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Преобразования провайдеров редактируют настройки провайдера и определения источников. Чтения редактора включают неактивных провайдеров и предоставляют
неизменяемые определения; `models.update` редактирует принадлежащую ему копию исходной модели.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Замените инвентарь источников через `models.set`, затем перезагрузите после изменения захваченных определений.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Для обнаружения, зависящего от аккаунта, передайте подключение, использованное для загрузки инвентаря, как `sourceConnection`. OpenCode исключает
этого провайдера, пока выбрано другое подключение, до тех пор пока ваш плагин не опубликует обновлённый инвентарь.

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

Schemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

### Модели

Прочитайте доступные модели и выбор по умолчанию.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Преобразования моделей редактируют всю коллекцию кандидатов активных провайдеров. Отключённые кандидаты остаются редактируемыми, пока все
преобразования не завершатся; `update` может добавить модель только под доступным провайдером.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Обратные вызовы редактируют сырые переопределения модели. Значения провайдера по умолчанию сливаются один раз, когда OpenCode фиксирует результат; неизменённые чтения
переиспользуют этот результат. `editor.provider` читает неизменяемые определения источников, включая неактивные шаблоны, а не
вывод преобразования моделей.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).

```ts

  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined

  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined

```

### Команды

Прочитайте команды, доступные в текущей локации.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Текущее преобразование команд только добавляет. Исполнитель получает сессию, вложения промпта и режим доставки.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schemas: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Интеграции

Прочитайте интеграции и разрешите активные учётные данные, если они есть.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Подключайтесь ключом или управляйте попыткой OAuth через подключённый API.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Преобразуйте интеграции и способы аутентификации. Обратные вызовы методов OAuth — это Effect, и они могут захватывать ресурсы
области видимости.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Schemas: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

### MCP

Перечислите MCP-серверы и их текущее состояние подключения.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Плагины управляют MCP-серверами только через преобразования. Используйте `editor.set`, чтобы добавить или заменить сервер, `editor.update`, чтобы
изменить его конфигурацию, и `editor.remove`, чтобы удалить его. Просматривайте конфигурацию через `editor.list` и `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Установите `disabled: true` в преобразовании, чтобы отключить сервер и разорвать подключение, или `disabled: false`, чтобы включить его и разрешить
OpenCode подключиться. OpenCode согласует жизненный цикл сервера по преобразованной конфигурации.

Вызывайте `reload()` после изменения внешнего состояния, используемого преобразованием, чтобы повторно применить преобразования и согласовать серверы.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schemas: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts
interface MCPEditor {
  list(): readonly [string, Types.DeepMutable<Mcp.ServerConfig>][]
```

### Инструменты

Регистрируйте типизированные инструменты через Effect `Schema`. Исполнитель получает декодированный вход и возвращает Effect с типизированным
выводом, отображаемым содержимым или метаданными.

Редактор поддерживает `add`, `update` и `remove`. Обратный вызов преобразования синхронный: он не должен возвращать Effect или Promise. Загружайте
внешние данные до регистрации или перезагрузки. OpenCode воспроизводит активные преобразования в порядке регистрации на новом
редакторе; для одного действующего имени инструмента более поздняя допустимая регистрация переопределяет более раннюю.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Вызывайте `yield* ctx.tool.reload()` после изменения исходных данных, захваченных обратным вызовом. Перезагрузка воспроизводит активные преобразования,
не меняя их порядок; она не перезапускает effect плагина.

Effect-инструменты принимают то же [объявление ввода свободной формы](/build/plugins/server#freeform-tool-input), что и Promise-инструменты. Если модель не объявляет этот формат, инструмент сохраняет обычный объектный ввод.

У инструментов есть `id`, содержащий действующее имя, а `get()` возвращает `undefined`, когда такого ID нет. Используйте
`update` и `remove` с действующим именем инструмента, включая его пространство имён (`acme_greeting` выше). В пространствах имён точки заменяются на `_`. В именах инструментов
сохраняются буквы, цифры, `_` и `-`, а остальные символы заменяются на `_`. Если указанного имени нет, операция игнорируется. Для создания инструмента нужен вызов
`add` с полным определением. Обновления сохраняют имя и пространство имён. Присваивайте новые схемы или параметры, чтобы заменить
их, а не изменяйте вложенные значения. Недопустимые обновления записываются в журнал, а предыдущее определение остаётся нетронутым.

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Обновления и удаления воспроизводятся по порядку вместе с добавлениями, в том числе после обновлений каталога MCP.

`transform` возвращает регистрацию области видимости. Выполните `yield* registration.dispose`, чтобы удалить его преобразование и перестроить
из оставшихся, обнаружив любое более раннее определение, которое оно переопределяло. Освобождение идемпотентно, а закрытие
scope плагина также освобождает его регистрации.

Каждый запрос к модели захватывает снимок инструментов. Перезагрузка и освобождение влияют на будущие снимки, а не на определения или
исполнители, уже захваченные существующим запросом. Исполнители, замыкающиеся на изменяемые данные плагина, всё равно наблюдают
эти данные; захватите значение внутри преобразования, когда оно должно оставаться привязанным к этому определению.

Schemas: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Хуки

Хуки перехватывают операции во время выполнения. Несколько плагинов могут зарегистрировать один и тот же хук. OpenCode запускает хуки в порядке подключения плагинов, поэтому каждый следующий хук видит изменения предыдущих. Регистрации действуют в пределах области видимости плагина.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Сессии

Изменяйте собранные системные инструкции, сообщения или инструменты непосредственно перед отправкой модели. `context` выполняется для

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

В хуках `context`, `compaction` и `generate` поле `metadata` соответствующего сохранённого сообщения доступно только для чтения. Например, эти метаданные мог задать хук `prompt`. Модели они не передаются.

Часть `system`, содержащая инструкции OpenCode, также перечисляет каждый источник в `metadata.experimental.instructions` как
`{ key, text }`, например `core/date` или `core/environment`, чтобы хук мог различать источники. Список — копия:
правка `text` части не обновляет его. Это экспериментально и может измениться.

Изменяйте настройки запроса к модели и при необходимости ограничьте хук одним провайдером. Событие несёт тот же `kind`,
что и HTTP-хуки ниже.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Изменяйте нативные запросы или ответы провайдера. Их тела — одноразовые потоки; клонируйте или заменяйте тело перед чтением.
Оба хука выполняются для каждого запроса сессии; `event.kind` равен `"primary"`, `"compaction"`, `"title"` или
`"generate"` в зависимости от выдавшего потока.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Провайдеры, передающие поток по WebSocket, переиспользуют одно соединение на сессию, поэтому HTTP-хуки никогда не видят этот трафик.
Экспериментальный хук `experimental.ws.handshake` выполняется один раз на вызов модели до выбора соединения и предоставляет
`url` и `headers` соединения; изменение любого из них переоткрывает сокет. HTTP-хуки по-прежнему выполняются для любого запроса, на который
откатывается маршрут WebSocket.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` и `experimental.ws.receive` предоставляют сами кадры: `send` выполняется после того, как драйвер провайдера
построил исходящий кадр, `receive` — для каждого входящего кадра до того, как драйвер его увидит. То, что содержит `frame` к моменту возврата хука, и уходит по сети или доходит до драйвера;
OpenCode это не проверяет.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Переопределите решение о повторе для сбоя провайдера или замените его задержку в миллисекундах. Хук выполняется после того, как OpenCode
классифицирует сбой и предлагает политику, но до планирования любого повтора. Он не раскрывает, как OpenCode
внутренне выполняет следующую попытку.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

Начальное значение `decision` определяется политикой OpenCode. Хук может разрешить повтор после сбоя провайдера, который обычно завершает запрос, или отменить предложенную повторную попытку. Хуки выполняются в порядке регистрации; каждый следующий видит текущее решение. Встроенный предел числа попыток нельзя превысить. `attempt` — номер предлагаемой фактической попытки: исходный запрос — это попытка `1`, первый повтор — попытка `2`. Если указана недопустимая задержка (`NaN`, бесконечность или отрицательное значение), используется рассчитанная задержка.
Восстановление после переполнения контекста работает отдельно: оно сжимает историю диалога, а не отправляет тот же запрос повторно.

#### Справочник

```ts
interface SessionHooks {
  readonly context: SessionContext
  readonly compaction: SessionCompaction
  readonly generate: SessionGenerate
  readonly title: SessionTitle
  readonly "model.request": SessionModelRequest
  readonly "http.request": SessionHttpRequest
  readonly "http.response": SessionHttpResponse
  readonly "experimental.ws.handshake": SessionWebSocketHandshake
  readonly "experimental.ws.send": SessionWebSocketSend
  readonly "experimental.ws.receive": SessionWebSocketReceive
  readonly retry: SessionRetry
}

type RetryDecision = { retry: false } | { retry: true; delay: number }

interface SessionRetry {
  readonly sessionID: string
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly error: { type: string; message: string; status?: number }

}

interface SessionHookDomain {
  readonly hook: ModelHooks<SessionHooks>
}
```

### Инструменты

Хуки before могут заменить вход или завершиться ошибкой `Tool.Error`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

Хуки after могут просматривать или заменять успешные результаты и сбои.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

#### Справочник

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

Общие типы регистрации показывают, какие операции требуют scope плагина.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Публикация

Пакетный плагин использует тот же экспорт по умолчанию, что и локальный Effect-плагин. Экспортируйте реализацию Effect из главной
точки входа и объявите `effect` как `peerDependency`. В `devDependencies` закрепите версию, которую использует `@opencode/plugin`,
чтобы при разработке устанавливалась только одна копия.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

OpenCode перенаправляет импорты `effect`, экспортируемых подпутей `effect/*` и `@opencode/plugin` (включая импорты из
зависимостей в `node_modules` плагина) на экземпляры времени выполнения хоста, чтобы файберы, журналы и парсеры `Schema`
использовали одну копию среды выполнения.

- Не включайте `effect` в опубликованный артефакт плагина. Если собираете бандлером, пометьте `effect` и `effect/*`
  external.
- Плагины и их зависимости из `node_modules` всегда выполняются на экземпляре `effect` релиза OpenCode-хоста.
  Используйте API и пути модулей `effect`, совместимые с релизом OpenCode, на который ориентируетесь; зависимости, собранные на другой
  мажорной версии `effect` (например, Effect 3), тоже получают `effect` хоста и не поддерживаются.
- Предоставляются только публичные подпути `effect`. Плагин, импортирующий один из приватных модулей `internal` Effect, не
  загружается с ошибкой, называющей путь.
- Скомпилированный бинарник OpenCode не включает ресурсы Scalar и Swagger UI, используемые страницами документации HTTP API Effect;
  при обслуживании этих страниц из плагина вместо них показывается уведомление.

Точка входа пакета экспортирует `Plugin.define` с функцией `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Используйте версии, совместимые с релизом OpenCode, на который ориентируетесь, и тестируйте установленный пакет, а не только
копию, подключённую через рабочее пространство менеджера пакетов.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
