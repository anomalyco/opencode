Серверная часть плагина работает в сервере OpenCode. Она изменяет поведение OpenCode и добавляет функции: инструменты,
хуки, интеграции, команды и агентов. О том, как устроен, загружается и публикуется пакет плагина, см. [Обзор](/build/plugins).

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

## Жизненный цикл

`setup` выполняется при загрузке плагина. Он может вернуть функцию очистки, которая выполняется при выгрузке плагина.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### Контекст

Контекст плагина — по сути [клиент сервера OpenCode](/build/client).
Его методы чтения и действий используют те же входы и ответы, что и клиент. Он
добавляет методы только для плагинов: преобразования, хуки времени выполнения, перезагрузки, регистрации
и параметры плагина.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location` описывает локацию, в которой загружен этот экземпляр плагина. Она
включает `directory`, необязательный `workspaceID` и метаданные `project` (`id`,
`directory` и `canonical`). Доступна и в Promise-, и в Effect-плагинах.
Это локация экземпляра плагина, а не каждой сессии, к которой он может
обращаться, и не каждого получаемого события.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### Параметры

Передавайте параметры плагина объектной формой в `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [

      "package": "./plugins/company",
```

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## Преобразования

Преобразования — синхронные правки состояния доменов OpenCode, и каждое опирается на предыдущие регистрации в своём домене.
Чтения реестра, такие как `ctx.model.list()`, отражают каждую регистрацию на данный момент, в том числе во время setup плагина;
пакетная обработка запуска только объединяет уведомления об обновлениях и никогда не задерживает результат чтения. API состояния ресурсов по-прежнему
сообщают состояние работающих ресурсов: зарегистрированное определение не означает, что его подключение или другая работа с ресурсом
завершены.

Источники добавляют провайдеров и неизменяемые определения моделей через `ctx.provider.transform`.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

Любая регистрация, удаление или `reload()` помечают реестр изменённым; следующее чтение перестраивает его, воспроизводя каждое
активное преобразование в порядке регистрации на новом значении. Держите преобразования дешёвыми и повторяемыми. Значение, которое вы уже
прочитали, никогда не изменяется последующими перестройками.

После разрешения преобразований провайдеров и доступности OpenCode материализует модели активных провайдеров и воспроизводит
каждое преобразование моделей по порядку. Политика моделей может просмотреть всю коллекцию кандидатов, включая только что обновлённые
источники.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

Захваченные входные данные не отслеживаются автоматически. Загрузите внешние данные до синхронного обратного вызова, затем вызовите
`reload()` после их изменения. Здесь `loadFromSource()` возвращает
записи `{ info: Provider.Info, models: readonly Model.Info[] }`.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

Изменения провайдера инвалидируют весь результат активных моделей, поэтому политика цены выхода по-прежнему фильтрует обновлённые модели.
Используйте `ctx.model.reload()`, когда меняется только вход, захваченный преобразованием модели.

## API

### Агент

Прочитайте всех агентов или получите одного по ID.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

Зарегистрируйте преобразование, чтобы просматривать, создавать, обновлять и удалять агентов, а также выбирать агента по умолчанию.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

Чтобы зарегистрировать нового агента, используйте `editor.update`. Если агент с таким ID уже существует, метод изменит его. Если нет, метод сначала создаст агента через `Agent.Info.default(id)`, а затем вызовет переданную функцию.

```ts
await ctx.agent.transform((editor) => {
  editor.update("reviewer", (agent) => {
    agent.description = "Reviews code for correctness and maintainability"
    agent.mode = "subagent"
    agent.system = "Review the proposed changes and report actionable findings."
  })
})
```

Перезагрузите агентов после изменения внешнего состояния, используемого преобразованием.

```ts
await ctx.agent.reload()
```

### Провайдеры

Прочитайте доступных провайдеров или метаданные одного провайдера по ID.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

Преобразования провайдеров редактируют настройки провайдера и определения источников. Чтения редактора включают неактивных провайдеров и предоставляют
неизменяемые определения; `models.update` редактирует принадлежащую ему копию исходной модели.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

Замените инвентарь источников провайдера через `models.set`, затем перезагрузите после изменения захваченных определений.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

Для обнаружения, зависящего от аккаунта, передайте подключение, использованное для загрузки инвентаря, как `sourceConnection`. OpenCode исключает
этого провайдера, пока выбрано другое подключение, до тех пор пока ваш плагин не опубликует обновлённый инвентарь.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### Модели

Прочитайте доступные модели и выбор по умолчанию.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

Преобразования моделей редактируют всю коллекцию кандидатов активных провайдеров. Отключённые кандидаты остаются редактируемыми, пока все
преобразования не завершатся; `update` может добавить модель только под доступным провайдером.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})
```

Обратные вызовы редактируют сырые переопределения модели. Значения провайдера по умолчанию сливаются один раз, когда OpenCode фиксирует результат; неизменённые чтения
переиспользуют этот результат. `editor.provider` предоставляет неизменяемые определения источников, включая неактивные шаблоны, а не
вывод преобразования моделей.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### Интеграции

Прочитайте интеграции и проверьте активные учётные данные.

```ts
const integrations = await ctx.integration.list()
```

Подключайте интеграции с помощью API-ключа.

```ts
await ctx.integration.connect.key({

  key: process.env.GITHUB_TOKEN!,
```

Запускайте, проверяйте, завершайте или отменяйте попытку подключения OAuth.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
```

Подключения на основе команд предоставляют тот же поток запуска, состояния и отмены.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
```

Зарегистрируйте преобразование, чтобы просматривать интеграции и управлять их способами аутентификации.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

Перезагрузите интеграции после изменения внешнего состояния, используемого преобразованием.

```ts
await ctx.integration.reload()
```

### MCP

Перечислите MCP-серверы и их текущее состояние подключения.

```ts
const servers = await ctx.mcp.list()
```

Плагины управляют MCP-серверами только через преобразования. Используйте `editor.set`, чтобы добавить или заменить сервер, `editor.update`, чтобы
изменить его конфигурацию, и `editor.remove`, чтобы удалить его. Просматривайте конфигурацию через `editor.list` и `editor.get`.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

Установите `disabled: true` в преобразовании, чтобы отключить сервер и разорвать подключение, или `disabled: false`, чтобы включить его и разрешить
OpenCode подключиться. OpenCode согласует жизненный цикл сервера по преобразованной конфигурации.

Вызывайте `reload()` после изменения внешнего состояния, используемого преобразованием, чтобы повторно применить преобразования и согласовать серверы.

```ts
await ctx.mcp.reload()
```

### Референсы

Прочитайте референсы, доступные в локации.

```ts
const references = await ctx.reference.list()
```

Зарегистрируйте преобразование, чтобы просматривать, добавлять или удалять локальные референсы и референсы Git. `get(name)` возвращает текущий настроенный источник
или `undefined`, если имя отсутствует.

```ts
await ctx.reference.transform((editor) => {
  const references = editor.list()
  editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
  editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
```

### Разрешения

Запросите разрешение перед выполнением действия. `assert` оценивает [правила разрешений](/permissions) сессии,
включая сохранённые подтверждения, и спрашивает пользователя, когда правило даёт `ask`. Он разрешается, как только действие разрешено.

```ts
execute: async (input, context) => {
  await ctx.permission.assert({
    sessionID: context.sessionID,
    agent: context.agent,
    source: { type: "tool", messageID: context.messageID, id: context.id },
    action: "deploy",
    resources: [input.environment],
    save: [input.environment],
  })
  return { content: await deploy(input.environment) }
}
```

- `action` и `resources` сопоставляются с правилами. Любой `deny` блокирует действие; иначе любой `ask` запрашивает подтверждение.
- `save` перечисляет шаблоны, сохраняемые когда пользователь выбирает «разрешать всегда».
- `agent` выбирает, чьи правила применяются, по умолчанию агент сессии. `source` привязывает запрос к вызову инструмента.
- `metadata` передаёт дополнительные сведения в запросы разрешений и хуки `evaluate`.

Правило запрета или отклонение с комментарием отклоняет с `Tool.Error`, несущей причину, поэтому модель видит её и
продолжает. Обычное отклонение завершает текущий шаг. Позволяйте этим ошибкам распространяться, а не возвращайте их как вывод
инструмента.

Просматривайте или разрешайте ожидающие запросы разрешений.

```ts
const pending = await ctx.permission.list({ sessionID })
const request = await ctx.permission.get({ sessionID, requestID })
await ctx.permission.reply({ sessionID, requestID, decision: "once" })
```

Замените правила разрешений в области сессии. Они вычисляются после правил агента, и
побеждает последнее подходящее правило. Дочерние сессии наследуют правила, действовавшие при их создании.

```ts
await ctx.session.update({
  sessionID,
  permissions: [{ action: "edit", resource: "/path/to/original/checkout/**", effect: "deny" }],
})
```

#### Ввод инструмента свободной формы

Прямой инструмент ровно с одним обязательным строковым полем может позволить модели записать эту строку без обёртки JSON. Установите `freeform` в `{ type: "text" }`, `{ type: "regex", pattern }` или `{ type: "lark", grammar }`.

```ts
editor.add({
  name: "ticket",
  description: "Look up a ticket by ID",
  options: { codemode: false },
  input: Schema.Struct({ id: Schema.String }),
  freeform: { type: "regex", pattern: "OPS-[0-9]+" },
  execute: async ({ id }) => ({ content: await lookup(id) }),
})
```

Если API выбранной модели перечисляет `regex` в models.dev, модель может написать `OPS-42` напрямую. Иначе Core опускает **только** `freeform`: у модели всё равно есть инструмент `ticket`, и она вызывает его с `{"id":"OPS-42"}`. Отсутствующий или пустой список форматов означает отсутствие поддержки свободной формы. Исполнитель в любом случае получает `{ id }`.

Внутри Code Mode (`codemode: true`) инструмент свободной формы принимает строку напрямую, как в `await tools.ticket("OPS-42")`. `await tools.ticket({ id: "OPS-42" })` тоже работает.

Вызывайте `reload()` после изменения исходных данных, захваченных обратным вызовом. Перезагрузка воспроизводит активные преобразования, не
меняя их порядок; она не перезапускает setup плагина.

```ts
await ctx.tool.reload()
```

Используйте `list()` и `get()` для просмотра инструментов, находящихся в редакторе. У инструментов есть `id`, содержащий действующее имя,
а `get()` возвращает `undefined`, когда такого ID нет. Используйте `update` и `remove` с действующим именем инструмента,
включая его пространство имён (`acme_greeting` выше). В пространствах имён точки заменяются на `_`. В именах инструментов
сохраняются буквы, цифры, `_` и `-`, а остальные символы заменяются на `_`. Если указанного имени нет, операция игнорируется. Для создания инструмента нужен вызов
`add` с полным определением. Обновления сохраняют имя и пространство имён. Присваивайте новые схемы или параметры, чтобы заменить
их, а не изменяйте вложенные значения. Недопустимые обновления записываются в журнал, а предыдущее определение остаётся нетронутым.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Обновления и удаления воспроизводятся по порядку вместе с добавлениями, в том числе после обновлений каталога MCP. Освобождение их
регистрации удаляет эти изменения и перестраивает из оставшихся преобразований.

Освободите регистрацию, чтобы удалить её преобразование и перестроить из оставшихся, обнаружив любое более раннее
определение, которое оно переопределяло. Освобождение идемпотентно, а выгрузка плагина также освобождает его регистрации.

```ts
await registration.dispose()
```

Каждый запрос к модели захватывает стабильный исполняемый снимок инструментов. Последующие преобразования, перезагрузки и освобождение влияют на будущие
снимки, а не на уже захваченные определения, описания пространств имён Code Mode или исполнители. Исполнители, замыкающиеся
на изменяемые данные плагина, всё равно наблюдают эти данные; захватите значение внутри преобразования, когда оно должно оставаться привязанным к
этому определению.

### Worktree

Зарегистрируйте локальную стратегию worktree обычным жизненным циклом плагина. Модуль реализации в этом примере отвечает за
проверку параметров и операции `create`, `remove` и `list` бэкенда.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

Загрузите плагин через `plugins` и настройте общий каталог назначения отдельно:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- Добавление стратегии выбирает её автоматически. Побеждает последняя активная регистрация; конфигурация выбора стратегии не нужна.
- Освобождение её регистрации или выгрузка плагина восстанавливает предыдущую реализацию, в конечном итоге встроенную стратегию Git.
- `reload()` воспроизводит преобразования после изменения захваченных входных данных; он не перезапускает setup плагина.
- Ошибки создания не повторяются через Git. Существующие worktree сохраняют записанного владельца, даже когда значение по умолчанию меняется.
- Стратегии управляют локальными каталогами. Подготовка удалённых рабочих каталогов не входит в этот интерфейс.

#### Операции

Контекст плагина предоставляет те же операции worktree на основе проекта, что и клиент. Каждая операция требует
`projectID`. `list` читает только сохранённый инвентарь, включая известные рабочие копии того же проекта; он не загружает
конфигурацию, не запускает плагины и не обнаруживает изменения файловой системы.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

Создание загружает конфигурацию и плагины из сохранённого каталога `canonical` проекта и использует их выбранную стратегию.
Оно принимает необязательные родительский `directory`, источник `from`, начальную `branch` и `name`.
Источник по умолчанию — каноническая рабочая копия, а переопределение `from` должно принадлежать этому проекту. Выбор источника
не меняет корень конфигурации.
Переданная начальная ссылка должна поддерживаться выбранной стратегией;
у нативной операции снимков Rift, например, нет параметра выбора ссылки.

Создание и обновление ждут активации плагинов канонической рабочей копии. Вызовы, сделанные во время setup плагинов этой рабочей
копии, видят уже сделанные регистрации и не ждут собственной активации.

Удаление загружает каноническую конфигурацию и активирует её плагины, затем использует записанную стратегию worktree, а не
текущее выбранное значение по умолчанию. Недоступный записанный владелец вызывает ошибку. Каталог worktree может
находиться в другом месте:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

Отсутствующие владельцы приводят к ошибке удаления, а не к откату на Git. Стратегия может бросить `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })`, импортировав `Worktree` из `@opencode/plugin`, чтобы запросить
подтверждение force, не завися от ошибок Core или Git.

Обновление загружает каноническую конфигурацию и просит все доступные стратегии найти worktree по известным корням рабочих копий.
Операция объединяет результаты, сохраняет привязку к исходной стратегии и исключает отсутствующие каталоги из списка. Если один источник поиска завершается ошибкой, она попадает в журнал, а остальные источники продолжают работу. Существующие каталоги остаются в списке, даже если ни одна доступная стратегия их не вернула. Подпишитесь на событие
`worktree.updated` и снова вызовите `list`, чтобы получить обновлённый список.

```ts
await ctx.worktree.refresh({ projectID })
```

#### Справочник

Реализации получают предложенный каталог после обработки имени и коллизий. Возвращайте фактический каталог из
`create`; он может отличаться, когда бэкенду нужна собственная структура. OpenCode разрешает возвращённый путь и использует его для
инвентаря, команд запуска и результата API. Возвращённый каталог должен существовать.

Стратегии, выбирающие другой каталог, обрабатывают коллизии имён там. OpenCode всё равно создаёт предложенный родительский
каталог перед вызовом стратегии. `list` должен сообщать только каталоги, принадлежащие стратегии, плюс любые корни репозиториев.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Обратные вызовы Promise должны учитывать отмену через `signal`. Обратные вызовы Effect возвращают Effect и используют прерывание Effect.
Регистрации остаются в области среды выполнения плагина; операции проекта используют реестр канонической рабочей копии.
Адаптеры конфигурации Core передают настройки каталогов в этот реестр.

### Веб-поиск

Перечислите провайдеров веб-поиска или выполните запрос через выбранного провайдера.

```ts
const providers = await ctx.websearch.providers()
const results = await ctx.websearch.query({ query: "OpenCode plugins", providerID: "internal" })
```

Зарегистрируйте провайдера и выберите провайдера по умолчанию преобразованием.

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = (await response.json()) as { url: string; title: string; content: string }
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

Отключите веб-поиск, выбрав `false`, или перезагрузите провайдеров после изменения внешнего состояния.

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```

### События

Подпишитесь на публичный поток событий подключённого сервера. Прерывайте поток при очистке плагина. Передайте `types`, например `ctx.event.subscribe({ types: ["config.updated"] })`, чтобы получать только эти типы событий; события типизируются соответствующим образом. Плагины работают внутри сервера, поэтому, в отличие от клиентов SDK, они никогда не получают `server.connected`. Неизвестные имена типов игнорируются с предупреждением в журнале сервера.

```ts
const controller = new AbortController()
void (async () => {

    console.log(event.type)
  }
})()
return () => controller.abort()
```

## Хуки

Хуки перехватывают операции во время выполнения. Зарегистрируйте хук в соответствующем домене и отмените регистрацию, когда хук больше не нужен.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

Несколько плагинов могут зарегистрировать один хук. OpenCode запускает их в порядке плагинов,
поэтому более поздние хуки видят изменения, сделанные более ранними.

### Сессии

Хуки сессий перехватывают приём промпта, вызовы модели, нативный HTTP и повторы.

#### Ответвления

Хук `fork` выполняется после того, как OpenCode копирует историю, и до возврата вызова ответвления. `sessionID` идентифицирует новую сессию.

```ts
await ctx.session.hook("fork", ({ sessionID }) => console.log(sessionID))
```

#### Приём промпта

Перехватывайте входящие пользовательские промпты до разрешения вложений и навыков и устойчивого приёма во входящие:

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

Хук получает принадлежащий ему изменяемый черновик:

- `prompt` содержит `text`, `files`, упоминания агентов в `agents` и выбранные `skills`.
- `metadata` содержит определённые приложением метаданные приёма.
- `delivery` по умолчанию `"steer"` и может быть изменён на `"queue"`.
- ID сессии и сообщения только для чтения; хук не может перенаправить приём.

Файлы и навыки, добавленные хуком, проходят обычный путь разрешения и проверки.
При переписывании текста обновляйте или удаляйте смещения `mention` вложений, которые больше
не совпадают. Упоминания агентов не переключают активного агента сессии.

Хуки промптов выполняются при следующих условиях:

- Хуки выполняются в порядке регистрации после готовности плагинов локации сессии.
- Команды, отправляющие через `session.prompt`, запускают хук.
- Синтетические сообщения, сообщения shell и команды управления сжатием контекста или перемещением хук не вызывают.
- Хук выполняется один раз при приёме, а не перед каждым вызовом модели.
- Область провайдера недоступна, потому что разрешение модели происходит после приёма.

Правки становятся каноническим сохраняемым пользовательским вводом. Если подготовка не удалась или
прервана, OpenCode не принимает промпт.

Держите хуки промптов безопасными при повторах. Они не являются границей побочных эффектов ровно один раз:

- Повтор ID, уже ожидающего или доставленного, возвращает исходный приём без повторного запуска хуков.
- Параллельные отправки могут запускать хуки более одного раза, но побеждает только первый успешный приём.
- Хуки промптов преобразуют ввод и не предоставляют типизированный API отклонения.

#### Запросы к модели

Изменяйте собранные системные инструкции, сообщения, инструменты или параметры запроса непосредственно перед отправкой модели. У каждого
вида запросов сессии есть свой хук, поэтому плагин может обрабатывать цикл агента и вспомогательные запросы
по-разному:

- `context` выполняется для цикла агента, включая продолжения, управляемые инструментами.
- `compaction` выполняется при подготовке сводки для чекпоинта. `messages` содержит историю диалога для обобщения. OpenCode добавляет
  промпт для составления сводки после выполнения хуков. Задайте `result`, чтобы самостоятельно записать результат сжатия контекста и пропустить вызов модели. Поля те же, что у готового сообщения с результатом сжатия.
- `generate` выполняется для временных вызовов `ctx.session.generate`.
- `title` выполняется для генерации заголовка. У него нет `agent` и `tools`. Установите `result`, чтобы задать заголовок самим.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

Изменения влияют только на исходящий вызов модели, а не на сохранённую историю или конфигурацию. Хук, который должен применяться к
каждому запросу, должен регистрироваться для каждого вида.

В хуках `context`, `compaction` и `generate` поле `metadata` соответствующего сохранённого сообщения доступно только для чтения. Например, эти метаданные мог задать хук `prompt`. Модели они не передаются.

Часть `system`, содержащая инструкции OpenCode, также перечисляет каждый источник в `metadata.experimental.instructions` как
`{ key, text }`, например `core/date` или `core/environment`, чтобы хук мог различать источники. Список — копия:
правка `text` части не обновляет его. Это экспериментально и может измениться.

Переопределения запроса подчиняются следующим правилам:

- `options` начинается пустым для каждого вызова модели; он не содержит разрешённых настроек модели.
- Типизированные ключи — настройки генерации; любой другой ключ передаётся выбранному протоколу как параметр провайдера.
- Хуки выполняются в порядке регистрации и видят переопределения предыдущих хуков.
- Переопределения запроса имеют приоритет над значениями модели по умолчанию, а те — над значениями маршрута по умолчанию.
- Объекты параметров провайдера сливаются рекурсивно; массивы и скалярные значения заменяют предыдущие.
- Удаление переопределения или установка `undefined` возвращает настроенные значения по умолчанию, а не удаляет их.
- Сырые наложения тела HTTP применяются после понижения протокола и могут переопределить получившиеся поля.

#### Параметры провайдера

Параметры провайдера используют семантические имена параметров выбранного протокола, а не сырые поля тела HTTP. Ограничивайте настройки,
специфичные для провайдера, соответствующим провайдером. Например, OpenAI Responses использует `reasoningEffort`:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

Параметры генерации зависят от выбранного протокола и модели:

- `maxTokens` — семантический лимит выходных токенов.
- Gemini поддерживает `topK`; OpenAI Responses его не предоставляет.

#### Разрешение модели

Экспериментально. Выполняется всякий раз, когда сессия разрешает модель для запроса, до построения чего-либо для него. `model` начинается
как выбранная модель; измените её, чтобы обслужить этот запрос другой моделью того же провайдера, включая скрытую
от выбора моделей. Сессия сохраняет выбранную модель; запрос и сообщение ассистента используют новую.
`kind` указывает вид запроса: маршрутизатор может, например, пропускать запросы на создание заголовка или заново выбирать маршрут после сжатия контекста. Модель от
другого провайдера завершается ошибкой как недоступная.

```ts
await ctx.session.hook(
  "experimental.model.resolve",
  (event) => {
    if (event.model.id === "auto" && event.kind !== "title")
      event.model = { providerID: event.model.providerID, id: pick(event.sessionID) }
  },
  { providerID: "acme" },
)
```

#### Запрос к модели

Изменяйте настройки запроса к модели и при необходимости ограничьте хук одним провайдером. Событие несёт тот же `kind`,
что и HTTP-хуки ниже.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### Нативный HTTP

Изменяйте нативные запросы или ответы провайдера. Их тела — одноразовые потоки; клонируйте или заменяйте тело перед чтением.

Оба хука выполняются для каждого запроса сессии. `event.kind` сообщает, какой поток его выдал: `"primary"` для цикла
агента, `"compaction"` для сводок чекпоинтов, `"title"` для генерации заголовка и `"generate"` для временных
вызовов `ctx.session.generate`. Используйте его вместо ID агента, чтобы различать вспомогательные запросы.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### Нативный WebSocket (экспериментально)

Провайдеры, передающие поток по WebSocket, открывают одно соединение на сессию и переиспользуют его между запросами, поэтому
`http.request` и `http.response` никогда не видят этот трафик. Хук `experimental.ws.handshake` выполняется один раз на вызов
модели до выбора соединения. Он несёт те же `sessionID`, `agent`, `model` и `kind`, что и HTTP-
хуки, плюс `url` и `headers` соединения. Изменение `url` или `headers` меняет сокет, который использует запрос, поэтому
сменённый токен bearer переоткрывает соединение.

HTTP-хуки по-прежнему выполняются для каждого HTTP-запроса, включая запрос, на который откатывается маршрут WebSocket.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` и `experimental.ws.receive` предоставляют сами кадры — аналог WebSocket для
правки тела HTTP-запроса или ответа. `send` выполняется после того, как драйвер провайдера построил исходящий кадр, и до его
записи; `receive` выполняется для каждого входящего кадра до того, как драйвер его увидит. Оба несут кадр строкой и
отправляют то, что содержит `frame` к моменту возврата хука.

OpenCode не проверяет переписанные кадры. Драйвер отслеживает состояние по ответам провайдера, поэтому переписывание,
меняющее смысл протокола, — ответственность плагина, как и переписанное тело HTTP.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

Эти хуки экспериментальны, и их имена или формы могут меняться.

#### Политика повторов

Переопределите решение о повторе для сбоя провайдера или замените его задержку в миллисекундах. Хук выполняется после того, как OpenCode
классифицирует сбой и предлагает политику, но до планирования любого повтора. Он не раскрывает, как OpenCode
внутренне выполняет следующую попытку.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

Хуки повторных попыток могут изменить исходное решение OpenCode (`decision`): разрешить повтор после сбоя, который обычно завершает запрос, или отменить предложенную повторную попытку.

Решения о повторе подчиняются следующим правилам:

- Несколько хуков выполняются в порядке регистрации, и более поздние видят текущее решение.
- Встроенное максимальное число попыток остаётся жёстким лимитом.
- `attempt` — рассматриваемая физическая попытка. Начальный запрос — `1`, поэтому первый повтор — `2`.
- Недопустимые задержки, такие как `NaN`, бесконечность или отрицательные значения, возвращаются к вычисленной задержке.
- Восстановление после переполнения контекста работает отдельно: оно сжимает историю диалога, а не отправляет тот же запрос повторно.

### Разрешения

Проверяйте решения о разрешениях после вычисления настроенных правил и до
выполнения действия или публикации запроса разрешения.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-5-5" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

Хуки разрешений подчиняются следующим правилам:

- Хуки выполняются для решений `allow` и `ask`.
- Явно настроенный `deny` окончателен и не вызывает хук.
- Хук может изменить `effect` на `allow`, `ask` или `deny`.
- `message` появляется в эскалированном запросе разрешения или становится причиной отказа.

## Поддержка V1

Плагин может поддерживать V1 и V2 из одной точки входа пакета. Экспортируйте по умолчанию
один объект с функцией `server()` для V1 и функцией `setup()` для V2:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 вызывает `server()` и использует возвращённые хуки.
- V2 читает `id` и `setup()` экспорта по умолчанию (или `effect()` для Effect-плагинов), игнорируя `server()`.
- Держите каждую реализацию на своём API; общий экспорт не переводит хуки V1 в хуки V2.
- Раскройте `Plugin.define(...)` в экспортируемом объекте, чтобы он проверял определение V2 отдельно от `server()`.

Объектная форма V1 поддерживается в OpenCode `1.18.29`. Более старые релизы V1 могут
ожидать экспорт функций; тестируйте установленный пакет со старейшим релизом V1,
который собираетесь поддерживать, и с V2.
