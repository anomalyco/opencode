---
title: "Навыки"
description: "Пишите файлы SKILL.md, которые дают агентам OpenCode переиспользуемые инструкции для задачи и загружаются только тогда, когда задача в них нуждается."
---

Создайте навык, чтобы дать агенту переиспользуемые инструкции для конкретной задачи. Поместите файл `SKILL.md` в `.opencode/skills/<skill-id>` и опишите в `description`, когда его использовать.

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow

1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

OpenCode сообщает модели об этом навыке, когда он уместен. Затем агент может загрузить его инструкции инструментом `skill`, не добавляя каждый навык в каждый промпт.

## Создание

Храните связанные скрипты, референсы и шаблоны рядом с `SKILL.md`:

```text
.opencode/skills/
└── git-release/
    ├── SKILL.md
    ├── scripts/
    │   └── changelog.ts
    └── references/
        └── release-policy.md
```

Пути внутри навыка отсчитываются от каталога с `SKILL.md`. Рекомендуется форма с каталогом: она даёт вспомогательным файлам собственный базовый каталог.

## Обнаружение

OpenCode автоматически ищет в следующих местах:

| Область               | Источники                              |
| --------------------- | -------------------------------------- |
| Глобально             | `~/.config/opencode/skills`            |
| Глобальная совместимость | `~/.claude/skills`, `~/.agents/skills` |
| Проект                | `.opencode/skills`                     |
| Совместимость проекта | `.claude/skills`, `.agents/skills`     |

При поиске источников проекта OpenCode поднимается от текущего каталога до корня файловой системы и учитывает подходящие каталоги на каждом уровне.

Каждый источник может содержать любую из форм:

```text
skills/
├── review.md
└── git-release/
    └── SKILL.md
```

- Markdown-файлы должны лежать в корне источника, например `skills/review.md`.
- Файлы с именем ровно `SKILL.md` могут лежать во вложенных каталогах группировки, например `skills/git-release/SKILL.md` или `skills/teams/release/SKILL.md`.
- Каталог с `SKILL.md` — это один навык. OpenCode не ищет внутри него другие навыки.
- Скрытые файлы и каталоги, а также `node_modules` пропускаются.
- Поиск останавливается на шести каталогах ниже корня источника.

## Источники

Добавьте локальные каталоги или HTTP-каталоги массивом `skills` в любом `opencode.json` или `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "skills": [
    "./team-skills",
    "~/shared/opencode-skills",
    "/opt/company-skills",
    "https://example.com/opencode/skills/",
  ],
}
```

| Значение                   | Как разрешается                                              |
| -------------------------- | ------------------------------------------------------------ |
| Относительный путь         | От активного рабочего каталога OpenCode, а не от файла конфигурации |
| Путь с `~/`                | От домашнего каталога текущего пользователя                  |
| Абсолютный путь            | Используется как записан                                     |
| URL `http://` или `https://` | Загружается как HTTP-каталог                               |

Каждый найденный файл конфигурации добавляет свои записи. Массивы `skills` объединяются, а не заменяются.

Навыки также могут поступать из подключённого рабочего пространства [OpenCode Console](/console).

## Каталоги

HTTP-каталог — это базовый URL с файлом `index.json`:

```json title="index.json"
{
  "skills": [
    {
      "name": "git-release",
      "version": "3",
      "files": ["git-release.md", "references/release-policy.md"]
    }
  ]
}
```

Для этой записи OpenCode скачивает каждый файл из `<base-url>/git-release/<file>`.

| Правило      | Требование                                                                        |
| ------------ | --------------------------------------------------------------------------------- |
| Пути         | Безопасные, относительные и с того же origin                                      |
| Входной файл | Включайте `SKILL.md` или `<name>.md`, например `git-release.md`                   |
| Обновления   | Увеличивайте `version` при изменении файлов, чтобы OpenCode обновил кэш            |

Каждый скачанный каталог навыка становится корнем источника с именем записи, поэтому и `git-release.md`, и `SKILL.md` получают ID `git-release`.

## Frontmatter

Frontmatter задаёт имя навыка и управляет тем, где он появляется:

```markdown title="SKILL.md"
---
name: Git Release
description: Prepare a repository release
metadata:
  opencode/autoinvoke: false
---

Prepare the changelog, version bump, tag, and release notes.
```

| Поле                           | Поведение                                                          |
| ------------------------------ | ------------------------------------------------------------------ |
| `name`                         | Отображаемое имя; по умолчанию — ID из пути                        |
| `description`                  | Краткое описание, показываемое модели                              |
| `metadata.opencode/autoinvoke` | Установите `false`, чтобы убрать навык из списка доступных модели  |
| `disable-model-invocation`     | Установите `true` для того же эффекта, что у `opencode/autoinvoke: false` |

Для работы OpenCode поля frontmatter не обязательны. Добавьте понятное `description`, чтобы модель могла найти навык: без этого поля он не попадёт в список доступных навыков.

`opencode/autoinvoke: false` лишь скрывает навык из списка доступных модели. Навык остаётся зарегистрированным, и его по-прежнему можно загрузить явно по ID. Если заданы и `disable-model-invocation`, и `opencode/autoinvoke`, побеждает `opencode/autoinvoke`. V2 принимает поля переносимости, такие как `license` и `compatibility`, но не интерпретирует их.

## ID

ID навыка определяется путём к файлу. `name` во frontmatter — только отображаемая метка.

| Файл                              | ID            |
| --------------------------------- | ------------- |
| `<source>/git-release.md`         | `git-release` |
| `<source>/git-release/SKILL.md`   | `git-release` |
| `<source>/teams/release/SKILL.md` | `release`     |

ID должны совпадать посимвольно, с учётом регистра. Для переносимых навыков используйте уникальный ID в формате kebab-case: от 1 до 64 символов в нижнем регистре с дефисами между словами. Имя каталога должно совпадать с ID:

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

Сейчас V2 не проверяет этот шаблон, рекомендацию в 1–64 символа, совпадение `name` и каталога или максимальную длину описания.

## Приоритет

Навыки выбираются по ID. Если два источника определяют `git-release`, навык, который загружает OpenCode, берётся из источника, зарегистрированного позже:

```text
~/.config/opencode/skills/git-release/SKILL.md  ← lower precedence
.opencode/skills/git-release/SKILL.md           ← loaded
```

Источники регистрируются от низшего приоритета к высшему:

1. Встроенные навыки
2. `.claude/skills`: сначала глобальные, затем от самого дальнего предка к текущему каталогу
3. `.agents/skills`: сначала глобальные, затем от самого дальнего предка к текущему каталогу
4. `~/.config/opencode/skills`
5. Проектные `.opencode/skills`: от самого дальнего родительского каталога к текущему
6. Явные записи `skills` из конфигурации, в порядке приоритета конфигурации и порядке массива

Избегайте дублирующихся ID, если не хотите переопределить более ранний навык.

## Загрузка

На каждом шаге модели OpenCode перечисляет разрешённые навыки, у которых есть описание и `opencode/autoinvoke` не равен `false`. В списке только ID, имя и описание, без полного тела Markdown.

Модель загружает навык, вызывая инструмент `skill` с его точным ID:

```json title="skill tool input"
{
  "id": "git-release"
}
```

Затем OpenCode:

1. Выбирает текущее определение для этого ID.
2. Проверяет разрешение `skill` выбранного агента.
3. Добавляет в разговор тело Markdown без frontmatter.
4. Предоставляет базовый каталог навыка и выборку до десяти путей вспомогательных файлов.

Чтобы загрузить навык самостоятельно, упомяните его в промпте как `@skill-id`.

Содержимое вспомогательных файлов не загружается автоматически: агент читает их по инструкциям навыка. Список таких файлов доступен для навыков с `SKILL.md` в отдельном каталоге, но не для навыков в виде отдельного Markdown-файла.

## Разрешения

Используйте действие `skill` и ID навыка в качестве ресурса. Правила выполняются по порядку, и побеждает последнее подходящее:

```jsonc title="opencode.jsonc"
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" },
  ],
}
```

| Эффект  | Поведение                                                        |
| ------- | ---------------------------------------------------------------- |
| `allow` | Объявляет и загружает подходящие навыки без подтверждения        |
| `ask`   | Объявляет подходящие навыки и спрашивает перед загрузкой         |
| `deny`  | Скрывает подходящие навыки от модели и отклоняет загрузку        |

Разместите те же правила в `agents.<id>.permissions`, чтобы применить их только к одному агенту.

## Устранение неполадок

Например, ID этого навыка — `release`, а не имя `Git Release` из frontmatter:

```text
.opencode/skills/release/SKILL.md
                      └─ ID: release
```

Если навык не найден или загружает не то содержимое:

1. Убедитесь, что файл — либо `*.md` в корне, либо вложенный файл с именем ровно `SKILL.md`.
2. Проверьте ID из пути с учётом регистра, а не `name` из frontmatter.
3. Добавьте `description`, если навык должна находить модель.
4. Проверьте `opencode/autoinvoke` и разрешения `skill` выбранного агента.
5. Поищите более поздний источник с тем же ID.
6. Для HTTP-каталогов проверьте `index.json`, пути файлов с того же origin и изменённый `version`.
