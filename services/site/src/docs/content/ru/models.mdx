Выберите модель для текущей сессии командой `/models`:

```text
/models
```

OpenCode показывает модели из каталога [models.dev](https://models.dev), интеграций провайдеров и вашей конфигурации. В списке выбора видны только включённые модели провайдеров, доступных в текущем проекте. Как их подключить, см. в разделе [Провайдеры](/providers).

## Выбор

Выберите модель в меню `/models`: так не придётся угадывать ID провайдера или модели. Выбор действует только в текущей сессии и не меняет конфигурацию.

```text
anthropic/claude-sonnet-5-5
```

Доступность зависит от проекта:

- Модель должна быть включена.
- Её провайдер должен быть доступен в текущем проекте.
- Учётные данные и конфигурация другого проекта не переносятся автоматически.

## Запуски

Используйте `--model`, чтобы выбрать модель для одного запуска из командной строки, не меняя настроенное значение по умолчанию:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Агенты и команды также могут выбирать свою модель. См. [Агенты](/agents) и [Команды](/commands).

## Значения по умолчанию

Задайте `model` в `opencode.json` или `opencode.jsonc`, чтобы выбрать модель по умолчанию для новой работы:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Заданная модель становится моделью по умолчанию в каталоге, если она включена и её провайдер доступен. Иначе OpenCode выбирает новейшую из доступных и поддерживаемых моделей.

- Модель, уже выбранная для сессии, имеет приоритет над настроенной по умолчанию.
- Переключение модели сессии не переписывает файл конфигурации.
- Корневой `model` сейчас хранит только провайдера и модель по умолчанию, но не вариант.

О расположении и приоритете конфигурации см. [Конфигурация](/config).

## Бесплатные модели

Установите `OPENCODE_DISABLE_FREE_MODELS=1` (или `true`) для процесса сервера, чтобы скрыть [бесплатные модели OpenCode](/console/models#free-models):

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

Для общего фонового сервера:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

Бесплатными считаются модели `opencode` и `opencode-go`, у которых нет платы за входные токены. При отключении таких моделей они исчезают из каталога и не могут быть выбраны по умолчанию. Попытка явно выбрать такую модель приводит к ошибке `Model unavailable`. Без входа провайдер `opencode` скрыт. Чтобы снова получить доступ к его платным моделям, подключите аккаунт OpenCode Console или задайте `OPENCODE_API_KEY`.

Чтобы заблокировать бесплатные модели для всех в организации, используйте политику. См. [Для компаний](/enterprise#block-free-models).

## Варианты

Варианты — это именованные наборы настроек одной модели, например с разной интенсивностью рассуждений или разным бюджетом токенов. Чтобы выбрать вариант для запуска, сессии, агента или команды, добавьте `#variant`:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

Имена вариантов берутся из актуальных метаданных выбранной модели в каталоге. Варианты `low`, `high` и `max` есть не у всех моделей. Если указать неизвестный вариант, OpenCode не сможет выбрать модель и вернёт ошибку.

Определите новые варианты или замените варианты каталога с тем же ID в массиве `variants` модели:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Каждый вариант может содержать `settings`, `headers` и `body`. Его значения применяются после значений провайдера и модели.

Чтобы переопределить варианты рассуждений модели, задайте настройки рассуждений в `capabilities.reasoning` в формате [models.dev](https://models.dev) v2. На основе этих настроек OpenCode создаёт варианты для пакета модели:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| Поле        | Назначение                                                                        |
| ----------- | --------------------------------------------------------------------------------- |
| `supported` | Рассуждает ли модель. `false` или `true` без элементов управления не добавляет вариантов. |
| `toggle`    | Добавляет вариант `none`, отключающий рассуждения.                                |
| `effort`    | Уровни интенсивности рассуждений, доступные для выбора. `default` сохраняет значение провайдера по умолчанию и не добавляет вариант. |
| `budget`    | Необязательные пределы числа токенов рассуждений: `min` и `max`. Игнорируются, если задан `effort`. |

Варианты из `variants` применяются поверх вариантов, созданных из `capabilities.reasoning`.

## Параметры

Записи провайдера и модели могут настраивать запросы через `settings`, `headers` и `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Поле       | Назначение                                                          |
| ---------- | ------------------------------------------------------------------- |
| `settings` | Параметры пакета провайдера, такие как `baseURL` или `reasoningEffort`. |
| `headers`  | Дополнительные заголовки HTTP-запроса.                              |
| `body`     | Поля тела запроса, специфичные для провайдера.                      |

OpenCode применяет сначала значения провайдера, затем модели, а последним — выбранный вариант.

- Вложенные объекты `settings` и `body` объединяются.
- Более поздние массивы и скалярные значения заменяют предыдущие.
- Имена заголовков не учитывают регистр.
- Параметры специфичны для провайдера и могут игнорироваться или отклоняться другим пакетом провайдера.

## Псевдонимы

Используйте `modelID`, чтобы дать модели API более удобный ID в каталоге:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Здесь в OpenCode можно выбрать `openai/coding-default`, а провайдеру отправляется `gpt-6.1-sol`. Если модели ещё нет в каталоге, OpenCode предполагает:

- поддержку инструментов с вводом в JSON, текста и изображений на входе и текста на выходе; ввод в свободной форме для инструментов поддерживается только для форматов, указанных в `capabilities.freeform`;
- лимит контекста в 200 000 токенов и лимит вывода в 32 000 токенов;
- лимит ввода не задан.

OpenCode распознаёт `text`, `regex` и `lark`. Другие имена форматов из models.dev игнорируются без удаления модели или её инструментов. Если прокси перед моделью каталога отклоняет инструменты свободной формы, установите `capabilities.freeform` в `[]` для этой модели.

Это запасные значения, а не результаты автоматического определения возможностей. Если точные значения `capabilities` и `limit` известны, задайте их явно: они заменят запасные. При автоматическом сжатии контекста используется `limit.input`, но не больше `limit.context`; см. раздел [Размер окна](/compaction#window). Добавьте `disabled: true`, чтобы скрыть модель из каталога доступных моделей:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Рассуждения

Если модель, совместимая с OpenAI, передаёт рассуждения потоком в нестандартном поле сообщения ассистента, задайте `compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode распознаёт `reasoning`, `reasoning_content` и `reasoning_text`. Можно указать и другое имя поля, которое использует провайдер. OpenCode читает рассуждения из этого поля в потоке и восстанавливает его, когда отправляет модели предыдущие сообщения ассистента. О связанном поле `requireReasoning` см. [Совместимость](#compatibility).

## Кэширование промптов

OpenCode автоматически ставит метки кэширования промптов там, где они нужны, например для маршрутов Anthropic. Если модель Claude доступна через совместимый с OpenAI прокси, например LiteLLM, OpenCode не может определить, что модели нужны метки `cache_control` в формате Anthropic. Задайте `compatibility.cacheFormat` для таких моделей Claude:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

Затем OpenCode помечает последнее определение инструмента, системный промпт и последнее сообщение как `cache_control: { "type": "ephemeral" }`, что использует стандартное пятиминутное время жизни кэша эндпоинта. Используйте `"alibaba"` для моделей Alibaba Model Studio, которые принимают те же маркеры, но игнорируют их на определениях инструментов. Установите `compatibility.cacheFormat` у провайдера, если все его модели принимают один формат. О других полях см. [Совместимость](#compatibility).

### Время жизни кэша

По умолчанию OpenCode не указывает срок жизни кэша, поэтому действует значение провайдера: например, у Anthropic это пять минут. Чтобы запросить другой срок, задайте `settings.cache.ttl` у провайдера или модели. Настройка модели имеет приоритет над настройкой провайдера.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

`ttl` принимает число и единицу: `ms`, `s`, `m`, `h` или `d`, например `"5m"`, `"1h"` или `"24h"`. OpenCode отправляет его как есть, поэтому используйте значение, которое принимает провайдер:

| API | Куда попадает время жизни |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` в каждом маркере кэша. Anthropic принимает `"5m"` и `"1h"`. |
| Bedrock Converse | `ttl` в каждом `cachePoint`. Старые модели Claude, кэширующие только на пять минут, игнорируют `"1h"`. |
| OpenAI Chat и Responses | `"24h"` попадает в `prompt_cache_retention`, остальные значения — в `prompt_cache_options.ttl`. |

Провайдеры с автоматическим кэшированием без маркеров, например Gemini, игнорируют этот параметр. Чем дольше хранится кэш, тем дороже обычно обходится запись. У Anthropic запись в кэш на час стоит в 2 раза дороже обычных входных токенов, а на пять минут — в 1,25 раза дороже.

[Прогрев](/warming) может использовать время жизни кэша, чтобы выбрать момент отправки запросов при `interval: "auto"`.

## Совместимость

`compatibility` описывает особенности запросов и ответов API модели: например, в каком поле передаются рассуждения и принимает ли эндпоинт `prompt_cache_key`. Для каждой модели используется один API. Действуют только те параметры, которые этот API читает; остальные игнорируются.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

`compatibility` провайдера применяется ко всем моделям этого провайдера. Собственный `compatibility` модели переопределяет его поле за полем: OpenCode начинает со значений, которые [models.dev](https://models.dev) публикует для API модели (`reasoningField`, `maxTokensField` и `mediaInput`, а также `supportsEffortUpdates` и `supportsSystemUpdates`, когда models.dev отмечает, что API их поддерживает), затем применяет конфигурацию модели. Незаданные поля сохраняют встроенное значение или обнаружение пакета провайдера. `supportsThinkingBlockBinding`, `supportsEffortUpdates` и `supportsSystemUpdates` относятся только к модели.

| Поле | Что делает | Кем читается | Значения и значение по умолчанию |
| --- | --- | --- | --- |
| `reasoningField` | Поле сообщения ассистента, несущее рассуждения. Проверяется первым при чтении потоковых рассуждений и используется при отправке предыдущих рассуждений обратно. | OpenAI Chat | Любое имя поля, кроме `role`, `content`, `refusal` или `tool_calls`. Если не задано, используется поле, увиденное в потоке, иначе `reasoning_content`. |
| `requireReasoning` | Отправляет поле рассуждений в каждом предыдущем сообщении ассистента, пустой строкой, если рассуждений не было. | OpenAI Chat | `true` или `false`. По умолчанию `true`, если задан `reasoningField` или модель — DeepSeek, иначе `false`. |
| `maxTokensField` | Поле тела, несущее лимит выходных токенов. | OpenAI Chat | `max_completion_tokens` или `max_tokens`. Если не задано, определяет `max_tokens` для провайдеров, которым он нужен, например DeepSeek, Moonshot, Together AI, Z.AI и Cerebras, иначе `max_completion_tokens`. |
| `requireFinishReason` | Считает поток, завершившийся без `finish_reason`, ошибкой неполного ответа. `false` принимает его как завершённый. | OpenAI Chat | `true` или `false`. По умолчанию `true`. |
| `requireAssistantAfterTool` | Вставляет сообщение ассистента между результатом инструмента и следующим сообщением пользователя для эндпоинтов, отклоняющих такой порядок. | OpenAI Chat | `true` или `false`. По умолчанию `true` для ID моделей семейства Mistral, иначе `false`. |
| `supportsPromptCacheKey` | Принимает ли эндпоинт поле тела `prompt_cache_key`. | OpenAI Chat, OpenAI Responses, Mistral | `true` или `false`. OpenAI Chat отправляет ключ, только когда `true`, что некоторые пакеты провайдеров задают по умолчанию. Другие API отправляют его, если не `false`. |
| `streamUsage` | Запрашивает использование токенов в потоке через `stream_options.include_usage`. | OpenAI Chat | `true` или `false`. По умолчанию `true`. |
| `cacheFormat` | Синтаксис маркера кэша промптов, который принимает эндпоинт. Переопределяет автоматическую расстановку точек разрыва провайдера. `alibaba` пропускает определения инструментов. | Каждый API с маркерами кэша промптов, включая OpenAI Chat, Anthropic Messages и Bedrock Converse | `anthropic` или `alibaba`. Если не задано, используется значение провайдера по умолчанию. См. [Кэширование промптов](#prompt-caching). |
| `supportsThinkingBlockBinding` | Позволяет API отбросить блоки рассуждений, если предшествующий контекст изменился, вместо того чтобы отклонять запрос. | Anthropic Messages, Bedrock Converse | `true` или `false`. Если не задано, OpenCode автоматически включает параметр для Claude 5.1 и новее. |
| `supportsEffortUpdates` | Применяет изменения интенсивности рассуждений к отдельным сообщениям, не сбрасывая кэш промптов. В противном случае интенсивность меняется для всего запроса. | Anthropic Messages, OpenAI Responses | `true` или `false`. Если не задано, OpenCode автоматически включает параметр для Claude Opus 5, Claude 5.1 и новее, а также GPT-6 и новее. |
| `supportsSystemUpdates` | Передаёт системные сообщения, добавленные в ходе диалога, как системные сообщения API. В противном случае они передаются в виде текста в следующем сообщении пользователя. | Anthropic Messages | `true` или `false`. Если не задано, OpenCode автоматически включает параметр для Claude Opus 4.8, Claude 5 и новее. |
| `mediaInput` | Куда попадают изображения и другие медиа в запросе принятия решения. | System One | `assets` (изображения, на которые ссылается состояние), `state` (встроенно в состояние) или `root` (списки `images`, `audio` и `videos` верхнего уровня). Если не задано, используется значение провайдера по умолчанию. |

## Локальные модели

OpenCode автоматически обнаруживает модели Ollama, LM Studio и vLLM по их стандартным локальным адресам. Любой сервер, совместимый с OpenAI, можно настроить вручную.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Если Ollama слушает `http://127.0.0.1:11434`, выберите обнаруженную модель с ID провайдера `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode обновляет список в фоне и получает из Ollama сведения о размере контекста и поддержке изображений и инструментов. Модели только для эмбеддингов в список не попадают.

Для другого хоста или порта задайте совместимый с OpenAI URL Ollama. Обнаружение по-прежнему использует нативный API Ollama с тем же префиксом пути:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Не указывайте `apiKey`, если эндпоинт не требует аутентификации bearer.
- Отключите обнаружение с помощью `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Если сервер LM Studio без аутентификации работает на `http://127.0.0.1:1234`, выберите обнаруженную модель с ID провайдера `lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode обновляет список в фоне и получает из LM Studio сведения о размере контекста и поддержке изображений и инструментов. Модели эмбеддингов в список не попадают.

Для другого хоста или порта задайте совместимый с OpenAI URL. Модели по-прежнему обнаруживаются автоматически:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Не указывайте `apiKey`, если аутентификация LM Studio отключена.
- Отключите обнаружение с помощью `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Если vLLM слушает `http://127.0.0.1:8000`, выберите обнаруженную модель с ID провайдера `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode проверяет `/health`, обновляет `/v1/models` в фоне, использует сообщённый `max_model_len` как контекстный лимит и включает только карточки моделей, принадлежащие `vllm`.

У автоматически обнаруженных моделей указана поддержка текста на входе и выходе, но не изображений или инструментов. В vLLM вызов инструментов включается серверными флагами, например `--enable-auto-tool-choice` и `--tool-call-parser`. При автоматическом обнаружении сведения об этих флагах недоступны.

Для другого эндпоинта или сервера с аутентификацией задайте его совместимый с OpenAI URL:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Не указывайте `apiKey`, если аутентификация отключена.
- Отключите обнаружение с помощью `"plugins": ["-opencode.provider.vllm"]`.
- Прокси с префиксом пути поддерживаются. Например, `https://example.com/vllm/v1` проверяет `/vllm/health` и обнаруживает `/vllm/v1/models`.

### Совместимый сервер

Для другого сервера, совместимого с OpenAI, определите пакет провайдера, эндпоинт и хотя бы одну модель:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Используйте настоящее имя модели на сервере, лимиты, типы ввода и вывода и поддержку инструментов. OpenCode не может определить, точны ли запасные значения для пользовательской модели. Если эндпоинту нужен ключ, добавьте `apiKey` в `settings` с подстановкой окружения вроде `"apiKey": "{env:LOCAL_API_KEY}"`; не коммитьте секреты.

## Ссылки на модели

Ссылка на модель имеет формат `provider/model` с необязательным суффиксом `#variant`:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| Часть      | Правило                                                       |
| ---------- | ------------------------------------------------------------- |
| Провайдер  | Заканчивается на первом `/`; не может содержать `/` или `#`.  |
| Модель     | Может содержать дополнительные `/`; не может содержать `#`.    |
| Вариант    | Следует после `#`, если присутствует.                         |
| Регистр    | ID провайдера и модели чувствительны к регистру.              |

Используйте ID каталога, а не отображаемые имена провайдеров. Поля `model` верхнего уровня, агента и команды принимают строковую форму выше или развёрнутый объект:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}
```

Развёрнутая форма удобна для сгенерированной или программной конфигурации.

## Ограничения

Учитывайте эти правила при настройке моделей:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- В объекте выбора модели используется поле `model`, а в записи каталога провайдера поле `modelID` задаёт ID, который отправляется провайдеру.
- Настройка верхнего уровня позволяет указать вариант, но каталог V2 не сохраняет его для модели по умолчанию. Выбирайте вариант для сессии, запуска, агента или команды.
- Параметры моделей специфичны для провайдера. Другой пакет провайдера может их игнорировать или отклонять.
- Данные каталога, учётные данные и конфигурация привязаны к локации. Модель, доступная в одном проекте, может быть недоступна в другом.
- Файлы конфигурации обычно перезагружаются автоматически. Уже выполняющийся запрос к модели сохраняет настройки, с которыми начался.
