Подключайте аккаунты провайдеров, за которые уже платите, например Anthropic, OpenAI или AWS Bedrock, и предоставляйте доступ к их моделям всем участникам рабочего пространства. Console хранит учётные данные и отправляет запросы к провайдерам через свой шлюз. Участники пользуются моделями, не получая ключи провайдеров. Тот же шлюз доступен вашим инструментам через [API провайдеров](/console/api/providers).

Владельцы и администраторы управляют провайдерами на вкладке **Providers**. Участники получают включённые модели в OpenCode после `/connect`.

## Подключение провайдера

1. Откройте **Providers** и нажмите **Connect Provider**.
2. Выберите провайдера из каталога и введите его API-ключ.
3. При необходимости нажмите **Test connection**, затем **Save**.

Каталог включает Anthropic, OpenAI, Google, xAI, DeepSeek, Mistral, Groq, OpenRouter и многие другие. У провайдеров каталога модели настроены заранее.

### Облачные провайдеры

Облачным провайдерам нужны дополнительные данные.

| Провайдер             | Данные                               |
| --------------------- | ------------------------------------ |
| Azure                 | Имя ресурса и API-ключ               |
| AWS Bedrock           | Регион и API-ключ                    |
| Google Vertex AI      | Регион и JSON сервисного аккаунта    |
| Cloudflare AI Gateway | Account ID, Gateway ID и API-токен   |
| Databricks            | URL рабочего пространства и токен   |

### Свои провайдеры

Нажмите **Add Custom Provider**, чтобы подключить другой эндпоинт, затем добавьте его модели кнопкой **Add Model**.

| Поле       | Описание                                                                        |
| ---------- | ------------------------------------------------------------------------------- |
| Base URL   | Куда Console перенаправляет запросы, например `https://api.deepseek.com/v1`.     |
| Format     | Chat Completions, Responses API, Anthropic Compatible или Google Generative AI. |
| Auth mode  | Bearer, заголовок API-ключа или пользовательский заголовок.                      |
| Credential | Ключ, который Console отправляет провайдеру.                                     |

## Выбор моделей

Откройте провайдера, чтобы увидеть его модели. Участникам доступны только включённые модели.

- Переключателем **Enabled** включайте и отключайте модель.
- Включите **New models**, чтобы включать модели, которые провайдер добавит в будущем.

## Изменение моделей

Щёлкните модель, чтобы изменить её. Изменения сохраняются при закрытии панели.

| Раздел        | Что можно изменить                                              |
| ------------- | --------------------------------------------------------------- |
| General       | Отображаемое имя, ID API, поддержка инструментов, типы ввода и вывода |
| Variants      | Варианты со своими заголовками или телом                        |
| Configuration | Вариант по умолчанию, заголовки и тело запроса, лимиты токенов  |
| Cost Tiers    | Цены за вход, выход, чтение и запись кэша за 1M токенов         |

### Свои цены

По умолчанию для моделей из каталога действуют цены по прайс-листу провайдера. Если у вас договорные цены, например скидка по контракту с OpenAI, укажите свои цены в **Cost Tiers**, чтобы в статистике использования и [бюджетах](/console/budgets) учитывались фактические расходы.

| Поле             | Прайс-лист | Ваша цена |
| ---------------- | ---------- | --------- |
| Цена входа       | $2.50      | $2.00     |
| Цена выхода      | $15.00     | $12.00    |
| Цена чтения кэша | $0.25      | $0.20     |

Изменённые цены подсвечиваются на странице провайдера. Используйте **Restore default value** у поля или **⋯ › Restore...** у модели, чтобы вернуться к прайс-листу.

Добавьте уровень **Context**, если для модели действуют более высокие цены при превышении определённого размера контекста, например для промптов длиннее 200 тысяч токенов.

### Свои модели

Нажмите **Add Model**, чтобы добавить модель, которой нет в каталоге, с её **Display name** и **Model ID**. Используйте **⋯ › Duplicate...** у существующей модели, чтобы начать с её настроек.

## Модели OpenCode

На вкладке **Models** можно управлять [моделями](/console/models) Console, запросы к которым оплачиваются с баланса рабочего пространства. Вкладка работает как страница провайдера:

- Включайте и отключайте отдельные модели.
- Отключите **Free models**, чтобы заблокировать бесплатные модели для рабочего пространства.
- Включите **New models**, чтобы новые модели Console включались автоматически.

Отключите провайдера целиком через **⋯ › Disable**, чтобы использовать только своих провайдеров.

## Использование в OpenCode

Участники выполняют `/connect` и выбирают рабочее пространство. Для каждого включённого провайдера OpenCode показывает название рабочего пространства, затем название провайдера. Команда `/models` выводит список его включённых моделей.

```text
Acme Inc. / Anthropic
```

Включите **Managed providers only** в **Settings › General**, чтобы все участники OpenCode могли пользоваться только провайдерами рабочего пространства.

## Передача данных об отправителе

Если в качестве провайдера вы используете свой шлюз, включите **Send identity** на его странице. Console будет добавлять заголовок `x-opencode-actor` в каждый запрос к модели через этот шлюз. Заголовок указывает, кто отправил запрос — участник или сервисный аккаунт, — чтобы шлюз мог вести журнал или ограничивать запросы по отправителю.

```text
x-opencode-actor: eyJhbGciOiJFUzI1NiIsInR5cCI6Im9wZW5jb2RlLWFjdG9yK2p3dCIsImtpZCI6Ii4uLiJ9...
```

- По умолчанию выключено; изменение базового URL выключает его.
- У провайдера, который всё ещё использует собственный API поставщика, например `https://api.openai.com/v1`, настройка не показывается, так как поставщик игнорирует заголовок.
- Console удаляет любой заголовок `x-opencode-*`, отправленный клиентом, поэтому единственный `x-opencode-actor`, который получает ваш шлюз, — подписанный Console.
- **Test connection** и перечисление моделей вызывают `GET <base URL>/models` только с учётными данными, поэтому не требуйте заголовок на этом маршруте.

### Токен

Заголовок — это JWT, который Console подписывает для каждого запроса.

| Поле         | Значение                                         |
| ------------ | ------------------------------------------------ |
| `alg`        | `ES256`                                          |
| `typ`        | `opencode-actor+jwt`                             |
| `iss`        | `https://opencode.ai/inference`                  |
| `aud`        | Базовый URL провайдера без завершающих слешей    |
| `iat`, `exp` | `exp` на 120 секунд позже `iat`                  |

| Утверждение          | Значение                                                               |
| -------------------- | ---------------------------------------------------------------------- |
| `sub`                | `user_id` для участника, иначе `service_account_id`                    |
| `workspace_id`       | Рабочее пространство, в котором выполнялся запрос                     |
| `user_id`, `email`   | Участник, когда запрос отправил участник                               |
| `service_account_id` | Сервисный аккаунт, когда запрос отправил он (включая агентов)          |
| `session_id`         | ID сессии клиента, если он его отправил                                |
| `request_id`         | ID, который клиент получает обратно в заголовке ответа `x-opencode-log-id` |

Пример содержимого токена в запросе участника:

```json
{
  "iss": "https://opencode.ai/inference",
  "aud": "https://llm.example.com/v1",
  "sub": "user_...",
  "workspace_id": "org_...",
  "user_id": "user_...",
  "email": "ada@example.com",
  "session_id": "ses_...",
  "request_id": "019a6e8f-24a0-7b12-9c3d-4e5f6a7b8c9d",
  "iat": 1794500000,
  "exp": 1794500120
}
```

### Проверка токена

Console публикует открытые ключи по адресу `https://opencode.ai/inference/.well-known/jwks.json` с заголовком `Cache-Control: public, max-age=300`. Проверьте подпись, эмитента, получателя, тип и давность выдачи токена, затем рабочее пространство. В примере используется [jose](https://github.com/panva/jose).

```ts
import { createRemoteJWKSet, jwtVerify } from "jose"

const keys = createRemoteJWKSet(new URL("https://opencode.ai/inference/.well-known/jwks.json"))

export async function sender(request: Request) {
  const token = request.headers.get("x-opencode-actor")
  if (!token) throw new Error("Missing x-opencode-actor")
  const { payload } = await jwtVerify(token, keys, {
    issuer: "https://opencode.ai/inference",
    audience: "https://llm.example.com/v1",
    algorithms: ["ES256"],
    typ: "opencode-actor+jwt",
    maxTokenAge: "120s",
    clockTolerance: "5s",
  })
  if (payload.workspace_id !== "org_...") throw new Error("Another workspace")
  return payload
}
```

Укажите в `audience` базовый URL провайдера из Console без завершающих слешей и замените `org_...` на ID рабочего пространства из URL в Console. Console публикует новый ключ подписи до того, как начнёт им пользоваться. Поэтому проверка не прерывается при ротации, если ключ выбирается по `kid`, как в `createRemoteJWKSet`.

## Отключение и удаление

Откройте меню **⋯** провайдера:

- **Disable** скрывает провайдера и его модели от участников, но сохраняет настройки.
- **Remove...** удаляет провайдера и его модели. В диалоге показано, кто недавно им пользовался, и предложено **Disable instead**.

Чтобы сменить ключ, щёлкните учётные данные на странице провайдера и введите новые.

## Оплата

Провайдер выставляет вам счёт за токены; Console не списывает за них кредиты. Console всё равно записывает каждый запрос и его стоимость по цене модели, поэтому отчёты об использовании и [бюджеты](/console/budgets) их учитывают.

Чтобы вызывать провайдера из своих инструментов, а не из OpenCode, используйте [API провайдеров](/console/api/providers).
