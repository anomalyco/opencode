Через API Console скрипты и интеграции могут обращаться к моделям и экспортировать статистику использования. В каждом запросе передавайте API-ключ для аутентификации.

```bash
curl --fail-with-body "https://opencode.ai/inference/v1/models" \
  --header "Authorization: Bearer oc_sk_..."
```

| API                                       | Эндпоинты                                         |
| ----------------------------------------- | ------------------------------------------------- |
| [Модели](/console/api/models)             | `https://opencode.ai/console/api/v1/models`       |
| [Инференс](/console/api/inference)        | `https://opencode.ai/inference/...`               |
| [Провайдеры](/console/api/providers)      | `https://opencode.ai/inference/custom/...`        |
| [Экспорт использования](/console/api/usage-export) | `https://opencode.ai/console/api/v2/usage/export` |

## API-ключи

API-ключи могут быть и у участников рабочего пространства, и у сервисных аккаунтов. Передавайте ключ как токен Bearer.

```text
Authorization: Bearer oc_sk_...
```

|                  | Личный API-ключ                                        | Ключ сервисного аккаунта                                                 |
| ---------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Создаёт          | Любой участник для себя                                 | Владельцы и администраторы                                                |
| Где создаётся    | **Account › Personal API keys**                        | **Settings › Service accounts**                                          |
| Действует как    | Участник, создавший его                                | Сервисный аккаунт                                                        |
| Использование учитывается | В [бюджете](/console/budgets#member-budgets) участника | В [бюджете](/console/budgets#service-account-budgets) сервисного аккаунта |
| Лучше всего для  | Своих скриптов и [harness](/console/harnesses)         | CI, общих машин и интеграций                                             |

- Каждый ключ работает только в рабочем пространстве, выбранном при его создании. Передавать рабочее пространство в заголовке не нужно.
- Полный ключ показывается только один раз, сразу после создания. После этого Console показывает только его префикс.
- **Expiration** необязательна: **Never**, **1 day**, **7 days**, **30 days** или **Custom** (от 1 до 365 дней). Просроченный ключ нельзя продлить, поэтому создайте новый.

## Личные API-ключи

Личный ключ действует от вашего имени. На него распространяются ваша роль, [бюджеты](/console/budgets#member-budgets) и правила моделей.

1. Откройте **Account** из меню аккаунта и найдите **Personal API keys**.
2. Нажмите **Add API key**.
3. Выберите **Workspace**, **Key name** и при необходимости **Expiration**. Владельцы и администраторы также выбирают
   **Permissions**.
4. Нажмите **Create** и скопируйте ключ.

```text
oc_sk_1a2b3c4d5e6f_...
```

Права ключа зависят от вашего текущего доступа к рабочему пространству и меняются вместе с вашей ролью. Если в рабочем
пространстве обязателен [SSO](/console/sso#sso-enforcement), ключ работает только при активной сессии SSO. На владельцев
это ограничение не распространяется.

## Сервисные аккаунты

Сервисный аккаунт — отдельный участник рабочего пространства для автоматизации со своими API-ключами, статистикой
использования и [бюджетом](/console/budgets#service-account-budgets). Используйте его, чтобы запросы автоматизации
не учитывались за конкретным человеком. Сервисными аккаунтами управляют владельцы и администраторы.

1. Откройте **Settings › Service accounts** и нажмите **Add Service Account**, затем задайте имя, например `CI Pipeline`.
2. Откройте сервисный аккаунт и нажмите **Add API Key**.
3. Задайте **Key name** и **Permissions**, при необходимости укажите **Expiration**, затем нажмите **Create**.
4. Скопируйте ключ.

```bash
export SERVICE_API_KEY="oc_sk_..."
```

Владельцы и администраторы могут позже переименовать ключ сервисного аккаунта или изменить его разрешения через
**Edit…** в меню действий ключа.

## Разрешения

У каждого ключа есть уровень разрешений, выбираемый в разделе **Permissions** при создании.

| Разрешения     | Что позволяет                                                                              |
| -------------- | ------------------------------------------------------------------------------------------ |
| **All**        | Всё, что может участник или сервисный аккаунт, кроме **This account's API keys**.          |
| **Restricted** | Только выбранные вами ресурсы.                                                             |
| **Read only**  | Доступ на чтение ко всем ресурсам. Ключ может перечислять модели, но не вызывать их.       |

Ключ никогда не делает больше того, от чьего имени действует. Личный ключ ограничен текущей ролью участника, а ключ
сервисного аккаунта — тем, что [могут делать сервисные аккаунты](#limitations).

### Ограниченные ключи

Установите для каждого ресурса **None**, **Read** или **Write**. **Write** включает **Read**.

| Ресурс                     | Уровни                |
| -------------------------- | --------------------- |
| **Models**                 | **Read**, **Request** |
| **Usage**                  | **Read**              |
| **Budgets**                | **Read**, **Write**   |
| **Members**                | **Read**, **Write**   |
| **Providers**              | **Read**, **Write**   |
| **Billing**                | **Read**, **Write**   |
| **Workspace settings**     | **Read**, **Write**   |
| **SSO**                    | **Read**              |
| **Service accounts**       | **Read**              |
| **This account's API keys** | **Write**            |

**Models › Read** перечисляет модели, а **Models › Request** также вызывает их через API [инференса](/console/api/inference)
и [провайдеров](/console/api/providers). Например, ключу, который только вызывает модели, нужно:

```text
Permissions: Restricted
Models:      Request
```

Ключи, созданные как **Inference only** до появления ограниченных разрешений, отображаются как **Restricted** с
**Models**, установленным в **Request**.

### Кто что может выдать

- **Участники** могут создавать только личные ключи, которые перечисляют и вызывают модели. Console показывает
  "This key can list and call models as you." вместо выбора разрешений.
- **Владельцы и администраторы** могут давать своим личным ключам **All**, **Restricted** или **Read only** в
  пределах своей роли. По умолчанию — **Restricted** с **Models**, установленным в **Request**. Если роль участника
  понизят, права его ключей будут ограничены соответственно.
- **Ключи сервисных аккаунтов** по умолчанию получают **All**. Владельцы и администраторы выбирают их разрешения.

### Ограничения

Некоторые действия всегда требуют человека, вошедшего в Console, а создание ключей ключом строго ограничено.

- Ни один API-ключ не позволяет менять настройки SSO или удалять рабочее пространство.
- Ключи сервисных аккаунтов не могут приглашать участников, менять роли, удалять участников, управлять оплатой,
  менять настройки рабочего пространства, управлять моделями, создавать или удалять сервисные аккаунты, даже с **All**.
- **This account's API keys** доступно только в ключах сервисных аккаунтов, и **All** его не включает. Ключ с ним
  может создавать и отзывать ключи только для своего сервисного аккаунта. Новые ключи должны быть **Restricted**,
  оставаться в пределах разрешений создающего ключа и не могут включать **This account's API keys**.
- Личные ключи никогда не получают **This account's API keys**, и ни один API-ключ не может создавать или отзывать
  личные API-ключи.

Запросы вне разрешений ключа возвращают HTTP `403`.

## Отзыв

| Ключ                | Кто может отозвать     | Где                                                                              |
| ------------------- | ---------------------- | -------------------------------------------------------------------------------- |
| Личный API-ключ     | Владелец ключа         | **Account › Personal API keys**, затем **Revoke**                                |
| Личный API-ключ     | Владельцы и администраторы | Страница участника в **Settings › Members**, раздел **API Keys**              |
| Ключ сервисного аккаунта | Владельцы и администраторы | Страница сервисного аккаунта в **Settings › Service accounts**, раздел **API Keys** |

Ключи также отзываются автоматически:

- Если участник покинул рабочее пространство, был удалён или потерял доступ через [SCIM](/console/scim),
  отзываются все ключи, которые он там создал, в том числе ключи сервисных аккаунтов. Другие ключи того же сервисного аккаунта продолжают работать.
- Удаление сервисного аккаунта отзывает все его ключи.

Отозванные и просроченные ключи сразу перестают работать и возвращают HTTP `401`.
