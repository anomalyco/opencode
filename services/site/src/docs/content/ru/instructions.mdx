Добавьте файл `AGENTS.md`, чтобы дать OpenCode постоянные указания по проекту. Используйте его для команд сборки, заметок об архитектуре, соглашений о коде и требований к проверке.

```md title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

Коммитьте файлы инструкций проекта, чтобы все, кто работает с репозиторием, получали одинаковые указания.

## Область действия

Разместите `AGENTS.md` в каталоге, к которому должны применяться его указания. OpenCode загружает глобальный файл, а затем каждый `AGENTS.md` от текущей рабочей директории в сторону домашнего каталога. Для рабочих директорий за пределами домашнего каталога поиск останавливается на корне проекта.

```text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace
```

В этом примере загружаются все четыре файла. Они объединяются в таком порядке:

```text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md
```

Общие для всех указания держите в глобальном файле. Указания для всего репозитория размещайте в корне проекта, а более конкретные — ближе к коду, к которому они относятся. OpenCode объединяет файлы и не разрешает конфликты между ними.

Если рабочая директория находится за пределами корня проекта, загружается только глобальный файл. Установите `OPENCODE_DISABLE_PROJECT_CONFIG=1`, чтобы пропустить обнаружение проектных `AGENTS.md`, не отключая глобальный файл.

### Запасной вариант CLAUDE.md

В любом каталоге без `AGENTS.md` OpenCode вместо него читает `CLAUDE.md`. Без глобального
`~/.config/opencode/AGENTS.md` он читает `~/.claude/CLAUDE.md`. `AGENTS.md` каталога всегда важнее его
`CLAUDE.md`, поэтому символическая ссылка между ними загружается один раз.

Установите `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1`, чтобы пропускать все `CLAUDE.md`, или `OPENCODE_DISABLE_CLAUDE_CODE=1`, чтобы также пропускать навыки из `.claude`. Сервер читает обе переменные при запуске. Для фонового сервиса сохраните их через `opencode service set env` и выполните `opencode service restart`.

## Обнаружение

Файлы инструкций ниже рабочей директории обнаруживаются по мере того, как агент исследует проект. Чтение файла или просмотр каталога загружает все `AGENTS.md` между этой целью и рабочей директорией.

```text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

Вложенные файлы загружаются начиная с ближайшего. Пока инструкции из файла есть в доступной модели истории, OpenCode не добавляет их повторно. Поэтому при повторном чтении той же части проекта они обычно не дублируются. Если сжатие контекста или откат уберёт запись с инструкциями из истории, при следующем чтении OpenCode может загрузить файл заново.

Изменения вложенного файла не обнаруживаются автоматически после его загрузки. Начните новую сессию, если обновлённый текст должен примениться сразу.

## Порядок

Сначала отправляется системный промпт выбранного агента или провайдера. Затем OpenCode собирает начальные инструкции в таком порядке:

```text
1. Agent or provider system prompt
2. Code Mode tool guidance, when enabled
3. MCP server, reference, and skill guidance
4. Global and project AGENTS.md files, then configured instructions
5. Built-in date and environment context
6. Session-specific instruction entries supplied through the API
```

Эти источники объединяются, а не переопределяют друг друга. Вложенные `AGENTS.md`, обнаруженные позже, добавляются в историю сессии в порядке обнаружения.

## Обновления

Чтобы обновить инструкции в ходе сессии, отредактируйте глобальный файл `AGENTS.md` или файл с таким именем, найденный в текущем либо вышестоящем каталоге.

```bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md
```

Перед следующим запросом к модели OpenCode обнаруживает изменение и добавляет обновление инструкций до доставки ожидающего ввода:

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- Если удалить все `AGENTS.md`, обнаруженные при поиске вверх от рабочего каталога или в глобальной конфигурации, прежние инструкции из этих файлов перестанут действовать.
- Временная ошибка чтения сохраняет последние известные инструкции, а не считает их удалёнными.
- Перемещение сессии сохраняет её состояние инструкций, поэтому указания в новом месте вводятся как обновление.
- Фиксация отката сессии очищает её состояние инструкций и перезагружает инструкции перед следующим промптом.

Содержимое инструкций остаётся закрытым. Клиенты видят, какие источники изменились, но не видят их содержимого.

## Конфигурация

Используйте массив `instructions`, чтобы добавить файлы, glob-шаблоны или URL HTTP(S) вместе с обнаруженными `AGENTS.md`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines/*.md",
    "~/rules/opencode.md",
    "https://example.com/instructions.md",
  ],
}
```

Настроенные инструкции загружаются после `AGENTS.md` в порядке перечисления. Записи из всех документов конфигурации объединяются.

| Запись                    | Как разрешается                                                        |
| ------------------------- | ---------------------------------------------------------------------- |
| Относительный путь или glob | Ищется в каждом каталоге от рабочей директории до корня проекта      |
| Путь с `~/`               | Разрешается от вашего домашнего каталога                                |
| Абсолютный путь           | Используется как записан; имя файла может быть glob-шаблоном           |
| `http://` или `https://`  | Загружается при загрузке конфигурации с тайм-аутом пять секунд         |

- Локальные файлы обновляются как `AGENTS.md` при изменении. Новые файлы, подходящие под glob, загружаются при следующем изменении конфигурации.
- Отсутствующие файлы пропускаются. URL, который не удалось загрузить, пропускается или сохраняет последнее загруженное содержимое.
- При `OPENCODE_DISABLE_PROJECT_CONFIG=1` или когда рабочая директория находится за пределами проекта, относительные записи разрешаются относительно глобального каталога конфигурации.

Инструкции также могут поступать из подключённого рабочего пространства [OpenCode Console](/console).

О расположении и приоритете конфигурации см. в разделе [Конфигурация](/config).
