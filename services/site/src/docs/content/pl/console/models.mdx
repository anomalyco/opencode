OpenCode Console udostępnia listę modeli przetestowanych i zweryfikowanych przez zespół OpenCode. Zaloguj się, doładuj
środki i pobierz klucz API, aby używać ich w OpenCode lub innym agencie kodującym.

Console działa jak każdy inny dostawca w OpenCode. Jest **całkowicie opcjonalna** i możesz zamiast niej używać
dowolnego innego dostawcy. Subskrypcję z zawartym użyciem opisuje [OpenCode Go](/console/go).

## Jak to działa

1. Zaloguj się do [Console](https://opencode.ai/console), dodaj dane rozliczeniowe i środki, a następnie skopiuj klucz API.
2. Uruchom `/connect` w TUI, wybierz dostawcę OpenCode rozliczanego za użycie i wklej klucz API.

   ```text
   /connect
   ```

3. Uruchom `/models`, aby zobaczyć dostępne modele i wybrać jeden.

   ```text
   /models
   ```

Opłata jest pobierana za żądanie, a środki możesz doładować na koncie.

## Endpointy

Modele są też dostępne bezpośrednio przez następujące endpointy API. Modele czatu z darmowego planu wymagają OpenCode;
w innych klientach używaj modeli płatnych lub [Go](/console/go).

Każdy model jest wymieniony z natywnym API, ale każdy model tekstowy działa też przez pozostałe API, które Console
tłumaczy. Pełny zestaw opisują [bazowe URL-e](/console/harnesses#base-urls).

### Jev

Jev to model System One od TypeSafe AI do szybkich, ustrukturyzowanych decyzji. Zamiast generować tekst, ocenia `state`
względem typowanych pytań i zwraca wartości oraz prawdopodobieństwa, których Twój kod może użyć bezpośrednio. Obsługuje
pytania tak/nie (`noul`), wielokrotnego wyboru (`choice`) i oparte na kryteriach (`score`).

Użyj klucza API OpenCode Console z endpointem `https://opencode.ai/inference/systemone/v1/systemone`. Ten przykład
sprawdza, czy zgłoszenie do pomocy jest pilne:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

Możesz zadać wiele pytań w jednym żądaniu. Jev ocenia je równolegle i zwraca każdą odpowiedź pod pasującym ID pytania:

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.14",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

Użyj `jev-1.13-free`, aby skorzystać z darmowego modelu dostępnego przez ograniczony czas, który uruchamia Jev 1.13.
Szczegóły typów pytań i pól odpowiedzi opisuje [dokumentacja TypeSafe AI](https://docs.typesafe.ai/).

### GPT 6 Luna Decision i Gemini Decision 1

`gpt-6-luna-decision` i `gemini-decision-1` przyjmują to samo żądanie System One co Jev, na tym samym endpointcie.
Przekazuj obrazy, audio, wideo i pliki PDF w `state` jako części w stylu czatu (`image_url`, `input_audio`, `video_url`,
`file`). GPT 6 Luna Decision akceptuje tekst i obrazy; Gemini Decision 1 akceptuje też audio, wideo i pliki PDF.

```bash
curl https://opencode.ai/inference/systemone/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-decision-1",
    "state": "I was charged twice for my order.",
    "questions": {
      "refund": {
        "type": "noul",
        "instructions": "Is this a refund request?"
      }
    }
  }'
```

### Modele obrazów

`gpt-image-2.5-sunburst`, `gemini-nano-banana-2.1` i `grok-imagine-image-2.0` generują i edytują obrazy. Nie są modelami
czatu, więc nigdy nie pojawiają się w `/models` ani w endpointcie modeli, a `opencode/<model-id>` ich nie wybiera.
Wywołuj je w ich natywnym API kluczem Console albo pozwól narzędziu OpenCode
[`generate_image`](/tools#image-generate) użyć modelu obrazu, ustawiając `experimental.image_generate.model`, na przykład
`opencode/gpt-image-2.5-sunburst`.

```bash
curl https://opencode.ai/inference/openai/v1/images/generations \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "A mountain at sunrise",
    "size": "1024x1024"
  }'
```

Google przyjmuje natywne `contents` i `generationConfig`, a xAI swoje natywne opcje, takie jak `resolution` i `quality`.
OpenAI Images i xAI Images przyjmują też edycje pod `/images/edits`.

### Modele osadzeń

`text-embedding-3-small`, `qwen3-embedding-8b` i pozostałe modele osadzeń z powyższej tabeli zamieniają tekst na
wektory. OpenCode nie używa ich do czatu, więc nigdy nie pojawiają się w `/models`, a darmowy plan ich nie obejmuje.
[Go](/console/go#embedding-models) obejmuje niektóre z nich. Wywołuj je w API OpenAI Embeddings kluczem Console.

```bash
curl https://opencode.ai/inference/openai/v1/embeddings \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "text-embedding-3-small",
    "input": ["hello world", "goodbye"]
  }'
```

- `input` przyjmuje ciąg znaków lub tablicę ciągów. `data` zwraca jeden wektor na każde wejście, w tej samej kolejności.
- `dimensions` skraca wektory w modelach, które to obsługują, takich jak `text-embedding-3-small`.
- `encoding_format: "base64"` zwraca wektory zakodowane w base64 zamiast liczb zmiennoprzecinkowych.
- Każde wejście musi mieścić się w oknie kontekstu modelu.
- Odpowiedź podaje `usage.cost` jak każde żądanie inferencji. Zobacz [Koszt](/console/api/inference#cost).

Wektory z różnych modeli nie są porównywalne, więc osadzaj dokumenty i zapytania tym samym modelem.
[Podłączony dostawca](/console/api/providers#endpoints) udostępnia własne modele osadzeń pod `/embeddings`.

## Dla zespołów

Udostępniaj modele Console zespołowi z poziomu [obszaru roboczego](/console/workspaces). Właściciele i administratorzy
mogą [zapraszać członków](/console/members), wybierać włączone modele na karcie **Models**, ustawiać
[budżety](/console/budgets) i podłączać [własnych dostawców](/console/providers).

## Tło

Dostępnych jest wiele modeli, ale tylko nieliczne dobrze sprawdzają się jako agenci kodujący. Dostawcy różnią się też
konfiguracją, wydajnością i jakością, więc model używany przez bramkę typu OpenRouter może działać inaczej.

<Callout type="tip">Przetestowaliśmy wybraną grupę modeli i dostawców, którzy dobrze współpracują z OpenCode.</Callout>

Tworząc ten katalog:

1. Przetestowaliśmy wybraną grupę modeli i rozmawialiśmy z ich zespołami o najlepszym sposobie ich uruchamiania.
2. Współpracowaliśmy z dostawcami, aby zapewnić prawidłowe udostępnianie modeli.
3. Zrobiliśmy benchmarki każdej kombinacji model/dostawca, tworząc listę, którą z czystym sumieniem polecamy.

Console to bramka AI, która zapewnia dostęp do tych modeli.

## Cele

Zbudowaliśmy Console, aby:

1. **Porównywać w benchmarkach** najlepsze modele i najlepszych dostawców pod kątem pracy z agentami kodującymi.
2. Zapewniać **najwyższą jakość** bez obniżania wydajności ani przekierowywania żądań do tańszych dostawców.
3. Przekładać **obniżki cen** na Twoje rachunki: sprzedajemy po kosztach, a marża pokrywa tylko obsługę płatności.
4. **Nie wiązać Cię z jednym dostawcą**: używaj Console z dowolnym agentem kodującym lub korzystaj w OpenCode z innego dostawcy.
