Et GUI-plugin tilføjer paneler, kommandoer, indstillingssider og native integrationer til OpenCode Desktop med GUI-plugin-SDK'et,
`@opencode/plugin/gui`. Det er `./gui-experimental`-delen af en [pluginpakke](/build/plugins), alene eller ved siden af en
[serverdel](/build/plugins/server) og en [TUI-del](/build/plugins/cli).

<Callout type="note">
  GUI-plugin-API'et er eksperimentelt og kan ændre sig fra version til version. I pakken markerer eksportnavnet `-experimental`, at API'et er eksperimentelt.
</Callout>

Filen `./gui-experimental` har `Plugin.define` som standardeksport, ligesom server- og TUI-delene:

```tsx title="src/gui.tsx"
import { Command, Plugin } from "@opencode/plugin/gui"
import { Acme } from "./rpc"

export default Plugin.define({
  i18n: { en: { "command.open": "Open Acme" } },
  setup(ctx) {
    ctx.add(Command, () => ({
      id: "open",
      title: ctx.t("command.open"),
      run: () => void ctx.client.rpc(Acme).open({}),
    }))
  },
  main(ctx) {
    ctx.log.write("info", "acme started")
  },
})
```

Et GUI-plugin kan køre i to processer:

- **`setup`** kører i hvert vindue i desktopappen. Funktionen bidrager med paneler, kommandoer, indstillingssider, slots, serverkilder,
  linkhandlere og stilarter. Se [Vinduet](#the-window).
- **`main`** kører én gang i Electrons hovedproces. Den leverer typede `Ipc`-kontrakter, native menupunkter,
  indlejrede `WebContentsView`-visninger samt Node- og Electron-integrationer. Se [Hovedprocessen](#the-main-process).

## Pakke

En pluginpakke kan levere server-, TUI- og GUI-kode fra én npm-pakke. Tilføj ét `./gui-experimental`-export ved siden af
`./tui`, og OpenCode Desktop indlæser det for hvert plugin på sin egen baggrundsserver.

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./tui": "./src/tui.tsx",
    "./gui-experimental": "./dist/gui-experimental.cjs"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "devDependencies": {
    "solid-js": "^1.9.0",
    "vite": "^7.0.0",
    "vite-plugin-solid": "^2.11.0"
  }
}
```

Brugere installerer det som ethvert andet plugin; der er ikke et separat GUI-installationstrin.

```jsonc title="opencode.jsonc"
{
  "plugins": ["opencode-acme-plugin"],
}
```

GUI'en angiver ikke sit eget id, men bruger pluginets id: serverdelens `id` eller pakkenavnet, hvis pakken ikke har en serverdel (for en lokal mappe uden `name` bruges mappenavnet). Læs id'et som `ctx.id`.

### Én fil, to processer

Hver proces evaluerer hele `./gui-experimental`-filen og læser dens standardeksport. Vinduerne kører `setup`, og desktopappens hovedproces kører `main`.

```tsx title="src/gui.tsx"
import { shell } from "electron"
import { Plugin } from "@opencode/plugin/gui"

export default Plugin.define({
  setup(ctx) {
    // Window code: Solid components, ctx.layout, ctx.add(Command, …).
  },
  main(ctx) {
    // Main code: electron, Node built-ins, ctx.windows.
    ctx.windows.on("open", () => shell.beep())
  },
})
```

Da begge processer evaluerer samme fil, erstatter hver proces den anden proces' moduler med inaktive pladsholdere:

- **I et vindue** er `electron` og Nodes indbyggede moduler inaktive pladsholdere.
- **I hovedprocessen** er Solid og de moduler, der kun bruges i vinduerne, inaktive pladsholdere.

På modulniveau accepterer en pladsholder alle læsninger af egenskaber, funktionskald og konstruktioner, f.eks. skabeloner, som Solid løfter op på modulniveau, eller `require`-kald, som en bundler løfter op. Hold koden for hver proces i dens egen opsætningsfunktion: Kode, der kører i den forkerte proces, får pladsholdere i stedet for fungerende værdier.

`Plugin.define` og kontrakthjælperne kommer fra samme SDK i begge processer. I hovedprocessen henviser `@opencode/plugin/gui` til hovedprocessens SDK, som eksporterer de samme `Plugin`, `Store`, `Ipc`, `Contract` og `Registry`. Én definition dækker begge processer. De eksporter, der kun gælder i vinduer, f.eks. `Command`, `bindPlugin` og `createKeyed`, er `undefined` i hovedprocessen, så brug dem kun i `setup`.

## Byg bundlet

`./gui-experimental` skal være én forudbygget CommonJS-fil. Byg den med Vite-presettet fra `@opencode/plugin/gui/vite`:

```ts title="vite.config.ts"
import { defineConfig } from "vite"
import { gui } from "@opencode/plugin/gui/vite"

export default defineConfig({ plugins: [gui()] })
```

```bash
vite build
```

Presettet gør følgende:

- Kompilerer Solid JSX med `vite-plugin-solid`.
- Genererer én CommonJS-fil og indlejrer alle dynamiske `import()`-kald, fordi appen ikke kan indlæse flere chunks.
- Holder appens [delte moduler](#shared-modules), Electron og Nodes indbyggede moduler eksterne og bundler hver anden
afhængighed.
- Får buildet til at fejle ved ethvert andet `effect/*`-, `solid-js/*`- eller `@opencode/*`-modul. Appen leverer det ikke, og en
bundlet kopi ville ikke dele appens instans.

```text
effect/Schema is not a module the OpenCode app provides to plugin GUIs: effect, @opencode/plugin/gui, …
```

Importér i stedet fra det delte entry, f.eks. `import { Schema } from "effect"`.

### Presetindstillinger

Send indstillinger til `gui()` for at ændre entry eller outputfilen.

```ts title="vite.config.ts"
export default defineConfig({ plugins: [gui({ entry: "src/desktop.tsx", outFile: "dist/desktop.cjs" })] })
```

- `entry` er filen, der har `Plugin.define` som standardeksport. Standard er `src/gui.tsx`.
- `outFile` er bundlet, som `./gui-experimental`-eksportet peger på. Standard er `dist/gui-experimental.cjs`.

#### Reference

```ts
function gui(options?: GuiOptions): Plugin[]

interface GuiOptions {
  entry?: string
  outFile?: string
}
```

### Afhængigheder

Tilføj byggeværktøjerne som devDependencies. Appen leverer `@opencode/plugin/gui` ved kørsel, så bundlet behøver kun dets
typer fra `@opencode/plugin`-afhængigheden.

```bash
bun add -d vite vite-plugin-solid solid-js
```

Til Electron- og Node-typerne i `main` skal du også tilføje `electron` og `@types/node`:

```bash
bun add -d electron @types/node
```

### Delte moduler

Hver proces stiller disse moduler til rådighed for bundlet. Hvis pluginets GUI forsøger at indlæse et modul, som ingen af processerne leverer, fejler GUI'en.

```ts
import { Schema } from "effect" // Both processes
import { createSignal } from "solid-js" // Windows; an inert placeholder in the main process
import { readFile } from "node:fs/promises" // The main process; an inert placeholder in windows
```

- **Begge processer:** `effect`, `@opencode/plugin/gui`, `@opencode/plugin/gui/main`, `@opencode/plugin/rpc`,
  `@opencode/schema/rpc`, `@opencode/client` og `@opencode/client/effect`.
- **Kun vinduer:** `solid-js`, `solid-js/web`, `solid-js/store`, `@opencode/client/solid` og
  `@opencode/plugin/gui/{file,review,browser}`. Hovedprocessen får inaktive pladsholdere.
- **Kun hovedprocessen:** `electron` og Nodes indbyggede moduler som `node:fs`. Vinduer får inaktive pladsholdere.

## Hvor GUI-entries indlæses

OpenCode Desktop indlæser GUI-entries fra sin egen baggrundsserver, som allerede indlæser plugins fra din konfiguration, så
de tilføjer aldrig en ny kilde til kode. Konfigurer pluginet i den globale `opencode.json(c)` for at gøre dets GUI tilgængeligt i
hvert vindue.

<Callout type="note">
  TUI'en læser sine plugins fra `cli.json`, men desktopappen læser kun `opencode.json(c)`. En pakke, der kun leverede
  en TUI-del, og som brugerne angiver i `cli.json`, skal også angives i `opencode.json(c)`, når den tilføjer
  `./gui-experimental`.
</Callout>

Desktopappens hovedproces henter listen over plugins og læser deres bundles fra sin egen server med legitimationsoplysninger, som kun hovedprocessen har, og sender det samme sæt til vinduerne. Et vindue kan ikke levere kode til hovedprocessen.

Et plugin, hvis serverdel ikke kan indlæses, har ingen GUI.

## Genindlæsning og opdateringer

Indlæs pluginet fra dets lokale mappe, og genbyg ved hver ændring:

```bash
vite build --watch
```

- Hvis en lokal mappes `package.json` har `name` og `exports`, bruger OpenCode dem til at finde `./gui-experimental`. Ellers indlæses
  `gui-experimental.cjs` (eller `.js`) i roden. Indgangsfilen skal være `.cjs` eller `.js`; alle andre filer ignoreres.
ignoreres.
- Hver genbygning genindlæser pluginets GUI i hvert vindue og i hovedprocessen. Server-entryet genstartes ikke.
- En installeret pakkes GUI ændres kun med dens version.
- Ændring af pluginets `options` i `opencode.json(c)` genindlæser pluginet.
- `opencode plugin update` erstatter en pakkes GUI, når opdateringen er færdig.
- [**Settings > Extensions > Plugins**](/plugins#desktop) viser pluginet med en kontakt, der slår dets GUI fra. Hvis du vil
fjerne det, skal du fjerne det fra `opencode.json(c)` eller køre `opencode plugin remove <package>`.

<Callout type="note">
  Appens egne plugins reserverer deres id'er. Hvis dit plugins id er et af dem, ligger under et med et `.`, har et
  under sig eller er i `opencode`-navnerummet, indlæses dets GUI ikke, og **Settings > Extensions > Plugins**
  viser det som ikke indlæst.
</Callout>

## Definér GUI-pluginet

`Plugin.define` angiver, hvilke systemer pluginet kører på, samt dets gemte vinduestilstand, ikoner og tekster. Værten læser oplysningerne, før opsætningsfunktionerne kører.

```ts title="src/gui/definition.ts"
import { Schema } from "effect"
import { Plugin, Store } from "@opencode/plugin/gui"

export const definition = Plugin.define({
  os: ["macos", "linux"],
  stores: {
    prefs: Store.global(Schema.Struct({ enabled: Schema.Boolean }), { enabled: true }),
  },
  i18n: {
    en: { title: "Acme", "command.open": "Open Acme" },
    de: { title: "Acme", "command.open": "Acme öffnen" },
  },
})
```

- Værten tildeler pluginet dets id, `ctx.id`: serverdelens `id` eller pakkenavnet for en pakke uden serverdel
  (mappenavnet for en lokal mappe uden `name`). Værten sætter id'et foran alle id'er, pluginet opretter: kommandoer
  (`<id>.<command>`), panelnøgler (`<id>:<tab>`), gemte nøgler (`plugin.<id>.<key>`) og id'erne for de
  [kontrakter og Ipc'er](#contracts-and-tokens), pluginet stiller til rådighed.
- `os` begrænser pluginet til visse operativsystemer. Udelad det for at køre på alle OS'er. Et plugin, hvis `os` udelader dette
system, kører ikke, og **Settings > Extensions > Plugins** beholder rækken med “Not available on this system.”
- `stores` erklærer [gemt tilstand](#stored-state) for vinduer. Læs den som `ctx.stores.<key>`.
- `icons` erklærer pluginets [egne ikoner](#icons), hver en SVG-fils tekst. Læs et ikons navn som
`ctx.icons.<name>`.
- `i18n` indeholder tekster for hver sprogvariant. Skriv hver variant direkte i definitionen; mangler en nøgle i en variant, bruges den engelske tekst. Læs teksterne med
  `ctx.t(key, params)` og `ctx.plural(key, count)`. I et vindue læser `ctx.t` også appens fælles nøgler som `common.*`. I `main` returneres selve nøglen, hvis der ikke findes en tekst for den.
- Definer `setup`, `main` eller begge. En GUI uden nogen af dem kan ikke indlæses.
- Uden opsætningsfunktioner returnerer `Plugin.define` deklarationerne som en `Plugin.Declarations`, så typerne for
  opsætningsfunktioner i andre filer kan udledes af dem. `Plugin.Definition` er typen for hele definitionen.
- Et plugin erklærer ikke de kontrakter, det leverer eller bruger. Det leverer og læser dem ved kørsel; se
[Kontrakter og tokens](#contracts-and-tokens).

#### Reference

```ts
interface Declarations {
  os?: ("macos" | "windows" | "linux")[]
  stores?: Record<string, StoreDeclaration>
  icons?: Record<string, string>
  i18n?: { en: Messages; [locale: string]: Messages }
}

interface Definition extends Declarations {
  setup?(ctx: SetupContext<this>): Cleanup | void
  main?(ctx: MainContext): Cleanup | void | Promise<Cleanup | void>
}

type Messages = Record<string, string>

type Cleanup = () => void | Promise<void>
```

### Opdelt på flere filer

Et lille GUI-plugin kan ligge i `src/gui.tsx`. I et større plugin skal du erklære pluginet i `definition.ts`, lægge fælles tokens i `contract.ts`, skrive hver opsætningsfunktion i sin egen fil og samle dem i `src/gui.tsx`.

```text
src/
├── index.ts            Server part: Plugin.define from @opencode/plugin
├── rpc.ts              RPC contract between the server part and its clients
├── gui.tsx             ./gui-experimental entry: export default Plugin.define({ ...definition, setup, main })
└── gui/
    ├── definition.ts   Plugin.define: os, stores, icons, i18n
    ├── contract.ts     Tokens other code may import: Ipc, Contract, Registry
    ├── window.tsx      Window setup: Plugin.Setup<typeof definition>
    ├── main.ts         Main setup: Plugin.MainSetup (desktop only)
    ├── page.tsx        Components that panels and pages render
    ├── icons/logo.svg  The plugin's own icons
    └── i18n/en.ts      English copy
```

Hele `./gui-experimental`-filen evalueres, når et vindue starter, så hold modulniveau og `setup` lette. Registrér
bidrag der, og udfør dyrt arbejde inde i komponenter, `createKeyed` eller `createLatest`.

For et større plugin skal du først deklarere pluginet, udlede typerne for opsætningsfunktionerne af deklarationerne og
derefter definere pluginet med funktionerne.

```ts title="src/gui/definition.ts"
import { Schema } from "effect"
import { Plugin, Store } from "@opencode/plugin/gui"

export const definition = Plugin.define({
  stores: { notes: Store.global(Schema.Struct({ count: Schema.Number }), { count: 0 }) },
})
```

```tsx title="src/gui/window.tsx"
import type { Plugin } from "@opencode/plugin/gui"
import { Notes } from "./contract"
import type { definition } from "./definition"

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  ctx.provide(Notes, { count: () => ctx.stores.notes.value.count })
}
```

```ts title="src/gui/main.ts"
import type { Plugin } from "@opencode/plugin/gui"

export const main: Plugin.MainSetup = (ctx) => {
  ctx.log.write("info", "acme started")
}
```

```tsx title="src/gui.tsx"
import { Plugin } from "@opencode/plugin/gui"
import { definition } from "./gui/definition"
import { main } from "./gui/main"
import { setup } from "./gui/window"

export default Plugin.define({ ...definition, setup, main })
```

- `Plugin.Setup<typeof definition>` er typen for vinduets opsætningsfunktion. Typen udleder typen af `ctx.stores` fra
  de deklarerede stores og typen af `ctx.icons` fra de deklarerede ikoner.
- `Plugin.MainSetup` er typen for hovedprocessens opsætningsfunktion, og `Plugin.Cleanup` er typen for den
  oprydningsfunktion, som begge opsætningsfunktioner kan returnere.
- Importér registre, tokens og hjælpere som `Command`, `SettingsPage`, `Panel`, `Slot`, `Contract`, `Ipc`,
`Registry`, `Store`, `createKeyed`, `usePlugin` og `bindPlugin` fra `@opencode/plugin/gui`.
- Importér registre, der kun bruges i hovedprocessen som `MenubarItem` fra `@opencode/plugin/gui/main`.

## Delt kontekst

Begge opsætningsfunktioner modtager pluginets indstillinger, en klient til OpenCode-serveren og metadata om appen, ligesom server- og TUI-delene.

### Indstillinger

`ctx.options` indeholder `options` fra pluginets `opencode.json(c)`-post: de samme værdier, som serverdelen får.

```jsonc title="opencode.jsonc"
{
  "plugins": [{ "package": "opencode-acme-plugin", "options": { "team": "core" } }],
}
```

```ts
setup(ctx) {
  const team = ctx.options.team
}
```

- Ændring af indstillingerne genindlæser pluginet.

### Serverklient

`ctx.client` er OpenCode-klienten for serveren, der kører pluginet: desktopappens egen server. Brug den til at kalde
din serverdel gennem dens [RPC](/build/plugins/rpc).

```ts
import { Command } from "@opencode/plugin/gui"
import { Acme } from "./rpc"

ctx.add(Command, () => ({
  id: "search",
  title: ctx.t("command.search"),
  run: async () => {
    const result = await ctx.client.rpc(Acme).search({ query: "todo" })
    console.log(result)
  },
}))
```

- Læs `ctx.client` der, hvor du kalder den. Den ændres, efter serveren genstarter.
- Mens serveren er utilgængelig, afvises hvert kald.

### Appmetadata

`ctx.app` beskriver den kørende app.

```ts
if (!ctx.app.packaged) console.log(`Acme on ${ctx.app.name} ${ctx.app.version} (${ctx.app.channel})`)
```

- `name` er `"opencode"` som i et serverplugins `ctx.app.name`.
- `platform` er `"desktop"` i Electron-appen og i `main` og `"web"` i en browserfane.
- `packaged` er `true`, når desktopappen kører pakket. Den er altid `false` på web.
- Serverplugins får `name`, `version` og `channel`; TUI-plugins får `version` og `channel`.

#### Reference

```ts
interface App {
  name: string
  version: string
  channel: "local" | "dev" | "beta" | "prod"
  platform: "web" | "desktop"
  packaged: boolean
}
```

## Kontrakter og tokens

Tokens lader GUI-plugins tale på tværs af processer og med hinanden uden at importere hinandens runtimekode. Læg hvert
token i `contract.ts`. Et token indeholder kun sin art og sit id samt skemaerne for en `Ipc`, så andre plugins kan importere det
uden din runtimekode.

- `ctx.provide(token, impl)` leverer et af dine egne tokens: en `Contract` fra vinduets opsætningsfunktion eller en `Ipc` fra
`main`.
- `ctx.use(token)` følger en kontrakt eller en `Ipc`, som et andet plugin leverer. Den returnerer en
[`Live`](#live-dependencies-and-failure-handling)-accessor.
- `ctx.main(ipc)` returnerer en klient til en `Ipc`, som din egen `main` leverer.

Et plugin kan kun levere tokens med samme id som pluginet eller med dets id som præfiks, som i `<id>.<name>`. `ctx.provide` kaster en fejl ved alle andre id'er, og `ctx.main` kaster en fejl ved en `Ipc` uden for dit plugins id. Eksemplerne på denne side bruger plugin-id'et `acme`, så deres token-id'er begynder med `acme.`.

```ts
Contract.define<AcmeBadge, "acme.badge">("acme.badge") // Plugin acme can provide it.
Contract.define<AcmeBadge, "badge">("badge") // ctx.provide throws in plugin acme.
```

### Kontrakter

Brug `Contract.define`, når et plugins opsætningsfunktion i vinduet stiller et API eller en Solid-komponent til rådighed for andre plugins' opsætningsfunktioner i vinduet.

```ts title="src/gui/contract.ts"
import type { JSX } from "solid-js"
import { Contract } from "@opencode/plugin/gui"

export interface AcmeBadge {
  Badge(props: { readonly label: string }): JSX.Element
  count(): number
}

export const AcmeBadge = Contract.define<AcmeBadge, "acme.badge">("acme.badge")
```

Stil kontrakten til rådighed fra vinduets opsætningsfunktion med `ctx.provide`. Indeholder kontrakten en komponent,
skal du omslutte komponenten med `bindPlugin` under opsætningen. Så læser `usePlugin()` inde i komponenten
konteksten for det plugin, der leverer den, og ikke for det plugin, der bruger den.

```tsx title="src/gui.tsx"
import { bindPlugin, Plugin } from "@opencode/plugin/gui"
import { AcmeBadge } from "./gui/contract"

export default Plugin.define({
  i18n: { en: { title: "Acme" } },
  setup(ctx) {
    ctx.provide(AcmeBadge, {
      Badge: bindPlugin((props: { readonly label: string }) => (
        <span>
          {ctx.t("title")}: {props.label}
        </span>
      )),
      count: () => 42,
    })
  },
})
```

- Annotér props for en komponent, du pakker med `bindPlugin`, som i `bindPlugin((props: FileTreeProps) => ...)`.
TypeScript kan ikke udlede dem inde i `ctx.provide`.
- Lad datametoder som `count` være upakkede.
- `ctx.provide` returnerer en funktion, der kan trække kontrakten tilbage før tid. Værten trækker den også tilbage, når den aktuelle ejers levetid ophører,
  eller når pluginet stopper, hvis der ikke er en ejer.

### Brug et andet plugins kontrakt

Eksportér `contract.ts` fra din pakke, f.eks. som `./contract`, så andre plugins kan importere dens tokens. Et andet
plugin følger kontrakten med `ctx.use(token)`. Accessorens værdi ændres, når udbyderen starter, stopper og
genstarter, så læs den der, hvor du bruger den.

```tsx title="src/gui.tsx"
import { Plugin, Slot } from "@opencode/plugin/gui"
import { AcmeBadge } from "opencode-acme-plugin/contract"

export default Plugin.define({
  setup(ctx) {
    const badge = ctx.use(AcmeBadge)

    const count = () => {
      const live = badge()

      return live.status === "active" ? live.value.count() : 0
    }

    ctx.add(Slot, { at: "window.bottom", render: () => <span>{count()}</span> })
  },
})
```

- `ctx.use` returnerer samme accessor for hvert kald med tokenet.
- Forbrugeren bliver ved med at virke, mens udbyderen er slukket. Se
[Live-afhængigheder og fejlhåndtering](#live-dependencies-and-failure-handling).

### IPC mellem main og vinduer

Brug `Ipc.define` med Effect-`Schema`-codecs til at definere en typet bro mellem `main` og `setup`. `main` implementerer den
med `ctx.provide`, og vinduet kalder den gennem `ctx.main`.

```ts title="src/gui/contract.ts"
import { Schema } from "effect"
import { Ipc } from "@opencode/plugin/gui"

export const KeepAwake = Ipc.define({
  id: "acme.awake",
  methods: {
    screenActive: { output: Schema.Boolean },
    setScreenActive: { input: Schema.Boolean },
  },
})
```

```ts
const awake = ctx.main(KeepAwake)

await awake.setScreenActive(true)
```

- Andre plugins følger din `Ipc` med `ctx.use(KeepAwake)` som en kontrakt.
- Se [Definér og lever en Ipc](#define-and-provide-an-ipc) for tilstand, hændelser og udbyderen.

### Registre, dit plugin ejer

Brug `Registry.define` til en liste, dit plugin ejer. Andre plugins bidrager med elementer via `ctx.add`, og dit plugin læser
dem med `ctx.list`.

```ts title="src/gui/contract.ts"
import { Registry } from "@opencode/plugin/gui"

export interface Exporter {
  readonly id: string
  readonly title: string
  run(text: string): void
}

export const Exporter = Registry.define<Exporter>("acme.exporter")
```

```tsx
// Another plugin contributes an item.
ctx.add(Exporter, () => ({ id: "gist", title: ctx.t("exporter.gist"), run: (text) => upload(text) }))

// The owner lists every contribution. Reactive: read it in render or in a memo.
const exporters = () => ctx.list(Exporter)
```

## Vinduet

Et plugins `setup` kører i hvert desktopappvindue. Send den til `Plugin.define` fra `@opencode/plugin/gui` i
pluginets [`./gui-experimental`-fil](#define-the-gui-plugin). `setup` er synkron og kan returnere en
oprydningsfunktion; se [Levetider og oprydning](#lifetimes-and-cleanup).

```tsx title="src/gui.tsx"
import { Command, Plugin } from "@opencode/plugin/gui"

export default Plugin.define({
  i18n: { en: { open: "Open Acme" } },
  setup(ctx) {
    ctx.add(Command, () => ({
      id: "open",
      title: ctx.t("open"),
      run: () => ctx.system.openExternal("https://acme.example"),
    }))
  },

```

## Komponenter

Kald `usePlugin<typeof definition>()` i en Solid-komponent for at få det samme kontekstobjekt, som `setup` modtager.
Brug deklarationerne i deres egen fil til at angive typen ([opdelt på flere filer](#split-across-files)), så komponenten
og definitionen ikke importerer hinanden.

```tsx title="src/gui/window.tsx"
import { Slot, usePlugin, type Plugin } from "@opencode/plugin/gui"
import type { definition } from "./definition"

function StatusLabel() {
  const ctx = usePlugin<typeof definition>()

  return <span>{ctx.t("title")}</span>
}

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  ctx.add(Slot, { at: "window.bottom", render: () => <StatusLabel /> })
}
```

`usePlugin` kaster en fejl uden for et pluginbidrag. I en komponent, som et andet plugin gengiver, returnerer funktionen det andet plugins kontekst, så brug `bindPlugin` omkring en komponent, du leverer via en kontrakt; se [Kontrakter](#contracts).

## Ikoner

Hvert `icon`-felt i SDK'et og `ctx.ui.Icon` tager et `IconName`: navnet på et af appens egne ikoner eller på
et ikon, dit plugin erklærer. Enhver anden streng kompilerer ikke.

```ts
ctx.add(TitlebarItem, () => ({ id: "sync", label: ctx.t("sync"), icon: "server", run: () => sync() }))
```

### Erklær dine egne ikoner

Til grafik, appen ikke har, som dit produkts mærke, skal du beholde SVG-filen i din pakke og erklære den i
`icons`. Importér filen med `?raw`, som `gui()`-presettet bundler som tekst.

```ts title="src/gui/definition.ts"
import { Plugin } from "@opencode/plugin/gui"
import logo from "./icons/logo.svg?raw"

export const definition = Plugin.define({
  icons: { logo },
})
```

Send derefter ikonets navn fra `ctx.icons` overalt, hvor et `IconName` bruges.

```tsx title="src/gui/window.tsx"
import { ComposerPill, Slot, type Plugin } from "@opencode/plugin/gui"
import type { definition } from "./definition"

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  ctx.add(ComposerPill, {
    id: "sync",
    show: () => ({ label: ctx.t("synced"), icon: ctx.icons.logo, tone: "success" }),
  })

  ctx.add(Slot, { at: "window.bottom", render: () => <ctx.ui.Icon name={ctx.icons.logo} size="small" /> })
}
```

- `ctx.icons` har ét navn for hvert ikon, du erklærer. Et navn, du ikke erklærede, kompilerer ikke.
- Værten registrerer dine ikoner, før `setup` kører, og trækker dem tilbage, når pluginet forsvinder.
- En værdi, der ikke er et SVG-dokument, får pluginet til at fejle ved start.
- For at `?raw`-importet kan typechecke skal du tilføje `"vite/client"` til `types` i din `tsconfig.json`.

### Tegn et ikon

Værten tegner dit ikon, som den tegner sine egne: i den størrelse og farve, som stedet viser det i.

```xml title="src/gui/icons/logo.svg"
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 16 16" fill="none">
  <circle cx="8" cy="8" r="6.5" stroke="currentColor" />
  <path d="M5 8.5 7 10.5 11 6" stroke="currentColor" stroke-linecap="round" stroke-linejoin="round" />
</svg>
```

- `viewBox` afgrænser tegningen; uden den bruges `width` og `height`. Værten skalerer tegningen til 14, 16 eller
  20 pixels, så tegn på et gitter på 16 pixels.
- Tegn med `currentColor`. Ikonet tager derefter farven fra sit sted, f.eks. et mærkes `tone` eller en menurækkes dæmpede
ikonfarve.
- Et `id` i tegningen tilhører hele vinduet. Hold id'er unikke, eller udelad dem.

### Animér et ikon

Et ikon kan bevæge sig, f.eks. for at vise, at arbejde er i gang. Brug SVG-animationselementer som `animate` og
`animateTransform` inde i filen.

```xml title="src/gui/icons/working.svg"
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 16 16" fill="none">
  <circle cx="8" cy="8" r="6.5" stroke="currentColor" />
  <circle cx="8" cy="8" r="2" fill="currentColor">
    <animate attributeName="r" values="2;4.5;2" dur="2.4s" repeatCount="indefinite" />
  </circle>
</svg>
```

- Ikonets animation kører synkront alle de steder, hvor det vises.
- Animationen fortsætter, mens værten renderer stedet igen, f.eks. når et mærkes `show` kører igen.
- Under brugerens indstilling for reduceret bevægelse holder værten hvert ikon på dets første frame. Gør første frame til
den hvilende tegning.
- Et ikon, som intet sted viser, koster intet.

### Gemte ikonnavne

Et ikons navn er en streng, `<plugin id>:<name>`, så værten gemmer det på samme måde som navnene på sine egne ikoner. En [note eller et citat i inputfeltet](#attach-to-the-composer) gemmer navnet sammen med udkastet og den sendte besked, og en [lukket fane](#reopen-closed-tabs) gemmer det sammen med sessionens layout.

```ts
ctx.screen.current()?.composer.attach({
  type: "note",
  origin: ctx.id,
  commentID: crypto.randomUUID(),
  label: "button#submit",
  icon: ctx.icons.logo,
  subject: 'element <button id="submit">Save</button>',
  comment: "",
})
```

- Mens dit plugin ikke er aktivt, tegner ikonet intet og beholder sin størrelse.
- Læs navnet fra `ctx.icons` der, hvor du bruger det. Et håndskrevet navn kompilerer ikke.

## Registre

Send et registertoken og et element til `ctx.add` for at bidrage til vinduesskallen. Send elementet som en funktion,
`() => item | undefined`, når det følger reaktiv tilstand som sproget. Værten kører funktionen igen, når
det, den læser, ændres. Returnér `undefined` for at trække elementet tilbage, indtil funktionen returnerer et igen.

```ts
ctx.add(Command, () => ({ id: "open", title: ctx.t("command.open"), run: () => open() }))
```

- Læs labels med `ctx.t` inde i funktionen. En label, der læses én gang i et fast element, beholder det sprog, den blev læst på.
- Når elementet har et felt af en literal type, som `hidden: true`, en `section`, et `icon` eller et menunavn, skal du annotere
funktionens returtype: `(): Command => ({ ... })`. Uden det udvider TypeScript feltet til `string` eller
`boolean`, og ingen overload matcher.
- Send et fast element, når det aldrig ændres, som en [stil](#styles).
- Værten holder nogle objekter stabile: de faner, et panel returnerer fra `list`, og elementer med en `render`, som paneler
og indstillingssider. Læs deres labels fra gettere som `get title() { return ctx.t("title") }`.
- `ctx.add` returnerer en funktion, der kan trække elementet tilbage før tid.

### Kommandoer

`Command` tilføjer en handling til kommandopaletten, **Settings > Shortcuts** og eventuelt inputfeltets `/`-menu. Værten
publicerer kommandoen som `<plugin id>.<command id>`.

```ts
import { Command } from "@opencode/plugin/gui"

ctx.add(
  Command,
  (): Command => ({
    id: "toggle",
    title: ctx.t("command.toggle"),
    keywords: "notes scratch",
    group: ctx.t("command.category.view"),
    section: "terminal",
    bind: "ctrl+`",
    slash: { name: "notes", after: "open" },
    featured: true,
    enabled: !!ctx.sessions.current(),
    run: () => {
      const session = ctx.sessions.current()

      if (session) ctx.layout.toggle(`${ctx.id}:main`, session)
    },
  }),
)
```

- `title` er palettens label, `description` dens anden linje og `group` dens kategori som oversat tekst.
- `keywords` indeholder ekstra ord, som paletten matcher, adskilt af mellemrum.
- `section` er sektionen i **Settings > Shortcuts**. Standard er `general`.
- `bind` er standardtastebindingen, f.eks. `mod+shift+t`. Brugere kan ændre den.
- `slash` tilbyder også kommandoen i `/`-menuen. Med `arguments: true` går teksten efter navnet til
`run(input)`.
- `hidden` holder kommandoen ude af paletten, men dens tastebinding virker stadig.
- `suggested` viser også kommandoen under **Suggested**, mens den er aktiveret. `featured` viser den, når paletten åbnes
uden en forespørgsel.
- `enabled: false` tager kommandoen ud af paletten og slår dens tastebinding fra. Det er reaktivt.
- `scope` er en CSS-selector, som tastaturfokus skal være inden for, for at bindingen gælder. Med `editable` udløses bindingen
også, mens et tekstfelt har fokus.
- Hvis du vil køre en kommando fra din egen kode, skal du bruge `ctx.commands.run`; se [Kør kommandoer](#run-commands).

Fra en tastebinding kan `run` returnere `false` for at afvise tasten. Hændelsen går derefter videre til sit mål, som om kommandoen
ikke havde en tastebinding. Denne kommando fortsætter sessionen, når brugeren trykker Enter i en tom prompt, og overlader enhver
anden Enter til prompten:

```ts
ctx.add(Command, () => ({
  id: "continue",
  title: ctx.t("command.continue"),
  bind: "enter",
  editable: true,
  hidden: true,
  run: () => {
    const composer = ctx.screen.current()?.composer
    const session = ctx.sessions.current()

    if (!composer?.focused() || composer.text().trim() || !session) return false
    void session.server.client.session.prompt({ sessionID: session.id, text: ctx.t("continue") })
  },
}))
```

- Returnér `false` synkront; et promise håndterer tasten.
- `false` fra paletten eller en slash-kommando gør intet mere.

#### Reference

```ts
interface Command {
  id: string
  title: string
  description?: string
  keywords?: string
  group?: string
  section?: "general" | "session" | "navigation" | "model" | "terminal" | "prompt"
  bind?: string
  slash?: { name: string; arguments?: true; after?: string }
  hidden?: true
  suggested?: boolean
  featured?: true
  enabled?: boolean
  scope?: string
  editable?: true
  run(input?: string): void | false | Promise<void>
}
```

### Paneler

`Panel` tilføjer faner til en sessions sideområde (`region: "side"`). Brugeren kan trække en fane til panelet under tidslinjen.

```tsx
import { Panel, type PanelTab } from "@opencode/plugin/gui"

const mainTab: PanelTab = {
  id: "main",
  get title() {
    return ctx.t("panel.title")
  },
  closable: "compact",
  fallback: true,
}

ctx.add(Panel, {
  id: "main",
  region: "side",
  mobile: {
    get title() {
      return ctx.t("panel.title")
    },
    order: 45,
    kind: "menu",
    icon: "file-tree",
  },
  list: (input) => (input.open.includes("main") ? [mainTab] : []),
  render: (props) => <NotesView session={props.session} screen={props.screen} tab={props.tab} />,
})
```

Alle panel-callbacks (`list`, `render`, `focus`, `enter`, `close`, `closed`, `restore`, `normalize`) modtager ét
inputobjekt:

- Læs `props.session` og `props.tab` som reaktive gettere der, hvor du bruger dem. Destrukturér dem aldrig i toppen af
`render`: når brugeren skifter fra session A til session B, forbliver panelet monteret, og `props.session` opdateres på
stedet.
- `props.screen` er det samme `SessionScreen`-objekt (`file`, `comment`, `composer`), som panelet hører til. Dets handlinger anvendes altid på den
  session, som den aktuelle rute peger på.
- Returnér samme `PanelTab`-objekt fra `list`, mens en fane er uændret, så værten ikke genmonterer dens trigger.
Læs dens labels fra gettere, så de følger sproget uden et nyt objekt.

Et panels callbacks:

- `list` returnerer de faner, der skal vises. `input.open` indeholder dette plugins fane-id'er, gemt i sessionen. Det er reaktivt.
- `render` renderer en fanes indhold én gang.
- `focus` kører, når en fane vælges. `restored` er `true` for den markering, regionen monteres med.
- `enter` kører, når brugeren åbner sideområdet på fanen med dens kontakt, når fanen er på skærmen. Flyt tastatur-
fokus til fanens eget mål, som et tekstfelt. Når fokus stadig er uden for regionen, fokuserer værten
regionen.
- `close` kører, efter at værten har fjernet en fane.
- `closed` og `restore` lader brugeren genåbne en lukket fane; se [Genåbn lukkede faner](#reopen-closed-tabs).
- `normalize` returnerer den kanoniske form af et gemt fane-id, som kan gemmes på mere end én måde.

Et panels indstillinger:

- `mobile` tilføjer en smalskærmsvisning af panelet. Med `cached: true` forbliver visningen monteret, mens brugeren viser
en anden visning. Som standard monteres visningen, hver gang den vises.
- `wide` anmoder om en større minimumsbredde for sessionen, mens sideområdet er åbent.
- `width` giver panelet sin egen bredde i sideområdet; se [Panelbredde](#panel-width).
- `transient`-panalers faner gendannes ikke.

#### Panelbredde

Som standard har alle faner i sideområdet samme bredde som samtalen. Angiv `width`, hvis panelet skal være smallere eller bredere end gennemgangs- eller browserpanelet. Angiv bredden i CSS-pixels, eller brug `"narrow"` for den mindst mulige bredde.

```ts
ctx.add(Panel, {
  id: "quota",
  region: "side",
  width: "narrow",
  list: (input) => (input.open.includes("quota") ? [tab] : []),
  render: () => <Quota />,
})
```

- Bredden gælder, mens sidepanelet viser en af panelets faner. Andre faner beholder samtalens bredde.
- Når brugeren trækker skillelinjen på en af panelets faner, beholder værten den bredde for panelet i hele appen i stedet
for `width`.
- Værten holder samtalen på sin minimumsbredde og regionen på mindst `"narrow"`.
- `ctx.layout.side.width(panel)` læser den gemte bredde, og `ctx.layout.side.resize(panel, width)` gemmer en, som et træk
gør. En gemt bredde gælder også for et panel uden `width`.

En fanes indstillinger:

- `id` er fane-id'et; dets værtsnøgle er `<plugin id>:<id>`. `title` er dets tilgængelige navn, og `label` renderer brugerdefineret
triggerindhold.
- `pinned`-faner vises uden at blive åbnet, kommer først og lukkes eller trækkes aldrig.
- `draggable` lader brugeren omarrangere fanen. Standard er `true`.
- `closable` angiver lukkeknappens udseende: `"compact"`, `"hover"` eller `false` for intet.
- `transient` markerer en launcherfane, som **Open file**, som den næste forhåndsvisning erstatter.
- Med `fallback` kan fanen vælges som reserve, hvis den fane, der var valgt og gemt, mangler.
- Faner i samme `group` deler én render, der forbliver monteret.
- `missing` streger fanen over, f.eks. for en fil, der ikke længere findes.
- `hidden` holder en gendannet fane på listen og valgbar, men ikke tegnet, mens dens indhold endnu ikke kendes.
- `file` er den sti i arbejdsområdet, fanen viser, listet som en af sessionens åbne filer.
- `tabbable` sætter fanepanelet i tabulatorrækkefølgen til indhold uden fokuserbare elementer.

#### Reference

```ts

  width?: number | "narrow"
```

### Genåbn lukkede faner

Værten gemmer en post for hver sidefane, brugeren lukker. Mens fokus er i sideområdet, genåbner ⌘⇧T den nyeste.
Sideområdets **New tab**-visning viser lukkede faner med en `file` under **Recently closed**. Tilføj `closed` og
`restore` for at styre, hvordan en fane vises der, og hvordan den kommer tilbage.

```tsx
ctx.add(Panel, {
  id: "page",
  region: "side",
  list: (input) => input.open.map(pageTab),
  render: (props) => <PageView tab={props.tab} />,
  closed: (input) => {
    const url = pages.get(input.tab.id)

    return url ? { icon: "globe", detail: new URL(url).host, data: url } : false
  },
  restore: (input) => {
    if (input.data) openPage(input.session, input.data)
  },
})
```

- `closed` kører, når brugeren lukker en fane. Gem det, der skal bruges til at genåbne den: Returnér rækkens visning og de `data`,
  som `restore` skal bruge, eller `false`, hvis fanen ikke kan genåbnes.
- `title` er som standard fanens titel, og `icon` panelets mobile ikon. En fane med en `file` viser sit filikon
og sin mappe som `detail`.
- Værten gemmer posten, så hold `data` små, f.eks. en URL.
- `restore` modtager den lukkede fanes `id` og de `data`, som `closed` returnerede. Uden `restore` åbner værten
samme nøgle igen.
- Uden `closed` vises en fane, der ikke er `transient`, under sin titel og genåbnes under samme nøgle.

### Indstillingssider

`SettingsPage` bidrager med en side til **Settings**, en sektion på en værtens side (`page: "general"` eller `page: "servers"`) eller
rækker i værtens General-sektion (`page: "general", section: "general"`).

```tsx
import { SettingsPage } from "@opencode/plugin/gui"
import { AcmeSettings } from "./settings"

ctx.add(SettingsPage, {
  id: "acme",
  icon: "server",
  get title() {
    return ctx.t("title")
  },
  get entries() {
    return [{ id: "sync", title: ctx.t("settings.sync"), keywords: "sync remote" }]
  },
  render: (input) => <AcmeSettings highlight={input.target} />,
})
```

- `id` er værdien for sidens fane i indstillingerne (`/settings?tab=<id>`) og argumentet til `ctx.layout.settings`.
- `page` tilføjer en sektion til en værtens side i stedet for en side. Med `section: "general"` tilføjer den rækker til den sides General-
sektion.
- `title` og `icon` er en sides navigationslabel og ikon.
- `entries` er søgemetadata, indekseret uden at montere siden. Når søgning afslører en post, modtager `render` dens
id som `target`.
- En indstillingsside har en `render`, så værten holder den stabil. Læs dens labels og poster fra gettere.

Render siden med appens indstillingskomponenter, så den ligner appens egne sider, og søgning kan afsløre dens
rækker:

```tsx
const ui = ctx.ui

const AcmeSettings = () => (
  <ui.SettingsLayout title={ctx.t("title")} description={ctx.t("description")}>
    <ui.SettingsSection title={ctx.t("settings.section")}>
      <ui.SettingsRow id="sync" title={ctx.t("settings.sync")} description={ctx.t("settings.sync.description")}>
        <ui.Switch label={ctx.t("settings.sync")} hideLabel checked={sync()} onChange={setSync} />
      </ui.SettingsRow>
    </ui.SettingsSection>
  </ui.SettingsLayout>
)
```

- Til din egen side bruges `SettingsLayout`, til en sektion på en af værtens sider (`page`) bruges `SettingsSection`, og til rækker
  i en af værtens sektioner (`section`) bruges `SettingsRow`.
- En rækkes `id` er den `SettingEntry.id`, der afslører den: søgning ruller til rækken og fremhæver den.
- Se [Indstillingskomponenter](#settings-components) for deres props.

### Slots

`Slot` renderer UI i en af fire vindues-slots.

```tsx
import { Slot } from "@opencode/plugin/gui"

ctx.add(Slot, {
  at: "session.header",
  order: 10,
  render: (input) => <UsageRing session={input.session} active={input.active} />,
})
```

- `window.bottom` er en fuldbreddestribe i bunden af vinduet over toasts.
- `session.header` er sessionstidslinjens titelrække. En cachelagret tidslinje forbliver monteret, mens den er skjult, med `active`
`false`.
- `session.location.menu` tilføjer elementer til projektmenuen efter dens locationoplysninger.
- `session.panel.end` indeholder handlinger i den bagerste ende af sideområdets fanestribe.
- `order` sorterer elementerne i én slot.

`session.location.menu` modtager `shown`, som er `true`, mens projektmenuen er åben. Abonnér kun på locationdata,
mens den er `true`:

```tsx
ctx.add(Slot, {
  at: "session.location.menu",
  render: (input) => <BranchStatus session={input.session} screen={input.screen} shown={input.shown} />,
})
```

Projektmenuen er en værtsmenu: render dens rækker med `ctx.ui.MenuItem`, `MenuSub`, `MenuGroup` og `MenuSeparator`,
så de navigerer med tastaturet og lukker menuen som værtens rækker. Se [Menurækker](#menu-rows).

```tsx
ctx.add(Slot, {
  at: "session.location.menu",
  render: (input) => <ctx.ui.MenuItem label={ctx.t("usage")} icon="status" onSelect={() => openUsage(input.session)} />,
})
```

### Menupunkter

`MenuItem` tilføjer en post til sidepanelets **+**-menu (`"session.panel"`), **Add server**-menuen (`"server.add"`)
eller hver servers rækkemenu i Settings (`"server.row"`).

```ts
import { MenuItem } from "@opencode/plugin/gui"

ctx.add(MenuItem, (): MenuItem => {
  const session = ctx.sessions.current()

  return {
    menu: "session.panel",
    id: "open",
    title: ctx.t("menu.open"),
    icon: "folder",
    keybind: `${ctx.id}.open`,
    opened: !!session && ctx.layout.state(`${ctx.id}:main`, session) !== "closed",
    run: () => {
      if (session) ctx.layout.open(`${ctx.id}:main`, session)
    },
  }
})
```

- `order` sorterer elementerne i stigende rækkefølge. Standard er `0`.
- Et `server.row`-elements `run` modtager rækkens servernøgle. `when` viser elementet på kun nogle rækker, og `enabled`
viser det deaktiveret på andre.

Et `session.panel`-element er også en launcher. Når brugeren åbner sideområdet uden faner eller klikker på **+**, mens intet
element er `primary`, viser værten en **New tab**-visning med launchere.

- `icon` er elementets ikon, og `keybind` et publiceret kommando-id, hvis genvej elementet viser.
- `description` er en kort dæmpet detalje efter titlen i en launcherrække, f.eks. et antal.
- `opened: true` betyder, at fanen, elementet åbner, allerede er åben. Launcherlister udelader elementet, og **+**-menuen
viser det stadig.
- `primary: true` får **+** til at køre elementet direkte i stedet for at vise launchere. Det første primary-element i `order`
vinder. Åbning af sideområdet uden faner viser stadig **New tab**-visningen, som viser de elementer, der ikke er
primary og ikke åbne.
- `ctx.layout.side.menu()` viser hvert plugins `session.panel`-elementer til din egen launcher; se
[Layout](#layout).

### Statusmærker ved inputfeltet

`ComposerPill` tilføjer et statusmærke til rækken over sessionens inputfelt ved siden af appens mærker for baggrundsarbejde og opgaver. Brug det til status for den session, brugeren arbejder i, f.eks. branchens pull requests. Mærkerne ligger oven på tidslinjen, så inputfeltets størrelse ikke ændrer sig, når et mærke vises eller forsvinder. Rækken følger brugerens indstilling for placering af baggrundsaktivitet og vises ikke i subagenters sessioner.

`show` returnerer mærket for én session eller `undefined`, hvis det ikke skal vises der. Værten kører funktionen for hvert monteret inputfelt og igen, når det, funktionen læser, ændrer sig. I eksemplet henter pluginet de åbne pull requests i hver sessions mappe via serverdelens [RPC](/build/plugins/rpc) og viser dem som ét mærke:

```tsx
import { createStore } from "solid-js/store"
import { ComposerPill, createKeyed } from "@opencode/plugin/gui"
import { GitHub, type Pull } from "./rpc"

const [pulls, setPulls] = createStore<Record<string, readonly Pull[]>>({})

createKeyed(
  () => ctx.sessions.current()?.directory,
  (directory) =>
    void ctx.client
      .rpc(GitHub)
      .pulls({ directory })
      .then((list) => setPulls(directory, list)),
)

ctx.add(ComposerPill, {
  id: "pulls",
  show: (input) => {
    const list = pulls[input.session.directory] ?? []

    if (list.length === 0) return undefined

    return {
      icon: "github",
      label: ctx.plural("pulls", list.length),
      tone: list.some((pull) => pull.checks === "failure") ? "danger" : undefined,
      title: ctx.t("pulls.title"),
      rows: list.map((pull) => ({
        id: String(pull.number),
        label: `#${pull.number} ${pull.title}`,
        icon: pull.checks === "failure" ? "circle-x" : "circle-check",
        tone: pull.checks === "failure" ? "danger" : "success",
        detail: pull.branch,
        run: () => ctx.system.openExternal(pull.url),
      })),
    }
  },
})
```

- `label` er mærkets tekst og afkortes, hvis den er for lang. `icon` er valgfrit.
- `tone` farver ikonet: `"success"`, `"warning"` eller `"danger"`.
- Til et symbol, appen ikke har, som et statusmærke, der bevæger sig, skal du [erklære dit eget ikon](#icons) og sende
`ctx.icons.<name>`. Det tager `tone` som ethvert ikon, og dets animation fortsætter, mens `show` kører igen.
- Med `rows` åbner mærket en menu med `title` som overskrift, eller `label` hvis der ikke er angivet en titel. Hver række har sit eget `icon`,
`tone` og dæmpede `detail` og kører `run`, når den vælges; en række uden `run` vises kun.
- Uden `rows` kører mærket `run` ved klik.
- `title` er også mærkets tilgængelige navn, når det afviger fra `label`.
- `order` sorterer dine mærker blandt andre plugins' mærker, laveste værdi først. Appens egne mærker kommer først.
- En `show`, der kaster, fejler kun dit plugins bidrag.

### Kodeblokke

`CodeBlock` renderer de indrammede kodeblokke for de sprog, du angiver, som dit eget UI i stedet for den fremhævede kode.
Brug den til indhold, der læses bedre tegnet end som kilde, f.eks. en ` ```csv `-tabel eller en ` ```latex `-
formel:

```tsx
import { For } from "solid-js"
import { CodeBlock } from "@opencode/plugin/gui"

ctx.add(CodeBlock, {
  languages: ["csv"],
  render: (props) => {
    const rows = props.code.split("\n").map((line) => line.split(","))

    if (rows.length < 2) return undefined

    return (
      <table>
        <tbody>
          <For each={rows}>
            {(row) => (
              <tr>
                <For each={row}>{(cell) => <td>{cell}</td>}</For>
              </tr>
            )}
          </For>
        </tbody>
      </table>
    )
  },
})
```

- `languages` sammenlignes med det første ord i indramningens infostreng, med små bogstaver: ` ```CSV title="Q3" `
matcher `csv`. Værten slår ikke aliaser op, så angiv hvert navn, du accepterer.
- `render` modtager blokkens `code`, dens `language` og den `session`, der viser den. Returnér `undefined` eller `null` for
at beholde den fremhævede kode, f.eks. når kilden ikke kan parses.
- En render, der kaster, registrerer fejlen under dit plugin, og blokken viser sin kode. Dine andre bidrag
fortsætter.
- Når flere plugins angiver et sprog, renderer det første bidrag det. Din renderer erstatter også appens eget
Mermaid-diagram, når du angiver `mermaid`.

#### Streaming

Værten renderer først en blok, når dens afsluttende indramning ankommer. Mens blokken streamer, og i en besked, der stoppede
midt i blokken, ser brugeren den fremhævede kode; derefter erstatter dit UI den på stedet. Din render ser aldrig en halv blok.

#### Hvor det gælder

| Flade                                                          | Kodebloksindhold |
| -------------------------------------------------------------- | ---------------- |
| Tidslinje: assistant-tekst og værktøjsoutput                    | Ja               |
| Sidepaneler på sessionsskærmen, f.eks. Markdown-forhåndsvisningen | Ja             |
| `ctx.ui.Markdown` renderet på sessionsskærmen                  | Ja               |
| `ctx.ui.Code` og Markdown inde i din egen `CodeBlock`-render    | Nej              |
| Indstillingssider, dialoger og andre flader uden for skærmen   | Nej              |

#### Layout og ydeevne

- Blokke med sprog, som intet plugin angiver, koster intet; kun en blok med et angivet sprog renderer dit UI, og kun mens
dens tidslinjerække er på skærmen.
- Blokken vokser og skrumper med dit UI. Giv asynkront indhold en minimumshøjde, så tidslinjen skifter mindre,
når det ankommer.
- Blokken beholder knappen Copy, der kopierer kildeteksten, og dine `CodeBlockAction`-knapper over det øverste hjørne ved linjens slutning.

### Linkhandlere

`LinkHandler` åbner links til lokale filer eller brugerdefinerede links, som brugeren klikker på i beskeder eller på chips i inputfeltet. Linket åbnes af den handler med højest `priority`, hvis `match` returnerer true.

```ts
import { LinkHandler } from "@opencode/plugin/gui"

ctx.add(LinkHandler, {
```

### Servere

`Server` bidrager med en liste over serverforbindelser, f.eks. servere, dit plugin starter på andre maskiner.

```ts
import { Server } from "@opencode/plugin/gui"

ctx.add(
  Server,
  (): Server => ({
    ready: loaded(),
    entries: machines().map((machine) => ({
      id: machine.id,
      name: machine.name,
      label: "Acme",
      state: machine.url ? "ready" : "starting",
      http: machine.url ? { url: machine.url } : undefined,

)
```

- Opstart venter på, at hver kilde er `ready`. En klar kildes poster er dens komplette fortegnelse.
- `order` sorterer kilderne i stigende rækkefølge.
- Hver posts nøgle er `<plugin id>:<id>`. `label` er et kort badge ved dens `name`.
- `auth` betyder, at serveren venter på, at brugeren logger ind, og `incompatible` at den kører en version, denne app ikke
understøtter.
- `listed: false` holder posten ude af appens serverliste. Settings viser den stadig.
- `http` er endpointet, når serveren er `ready`.
- `reconnect` finder et endpoint igen, når forbindelsen er afbrudt, `connect` gør en server klar, og `remove` kører, før
posten fjernes.

- En `row` modtager værtens status-`Indicator`, den seneste `health()`-kontrol og rækkens `server.row`-menu-`Items`.
Dens `remove()` kører postens `remove` og lukker derefter serverens faner.

### Layout

`ctx.layout.open(key, session, options?)` åbner en panelfane efter dens nøgle, `<plugin id>:<tab id>`. Den virker for sessioner,
der ikke er monterede.

```ts
const session = ctx.sessions.current()

if (session) ctx.layout.open(`${ctx.id}:main`, session, { tab: "select", background: true })
```

- `tab: "open"`, standard, vælger fanen i forhåndsvisningsslotten. `"preview"` gør den til den nye forhåndsvisning, `"append"` tilføjer
den uden at vælge den, og `"select"` tilføjer og vælger den og beholder forhåndsvisningen.
- `background: true` beholder den aktuelle visning på smalle skærme og åbner sideområdet for en handling, brugeren
ikke startede fra panelet.
- `close(key, session)` fjerner fanen og kalder dens panels `close`. `toggle(key, session)` lukker en synlig fane, ellers
åbner den den.
- `hide(key, session)` skjuler det panel, der viser en synlig fane, uden at lukke fanen: sideområdet eller bund-
panelet for en fane, brugeren flyttede dertil. Åbning af fanen igen viser dens panel.
- `state(key, session)` er `"closed"`, når fanen ikke er i striben, `"open"` når den er, men dens panel viser en anden
fane, `"active"` når dens panel viser den, men panelet er skjult (sideområdet er lukket, eller bundpanelet er
skjult), og `"visible"`, når den er på skærmen.
- `stored(session)` er dette plugins fane-id'er gemt i sessionens sidestribe.
- `ready()` er `true`, når det gemte layout er indlæst, og `narrow()`, mens viewporten er under 768px.
- `side.opened(session)` er `true`, mens sideområdet er åbent, og `side.toggle(session)` åbner eller lukker den.
- `side.menu()` viser hvert plugins `session.panel`-[menupunkter](#menu-items) i `order` til din egen launcher.
- `side.width(panel)` og `side.resize(panel, width)` læser og gemmer sideområdets bredde for et af dine paneler; se
[Panelbredde](#panel-width).
- `sidebar.opened()` angiver, om den indre sidebar er åben, en indstilling, som alle sidepaneler deler.
- `scroll` gemmer rulleforskydninger pr. session og nøgle.
- `settings(page?)` åbner Settings. `project(server, title)` åbner projektets mappevælger og et nyt udkast.
- `draft({ server, directory, prompt })` åbner en ny udkastsession i sin egen fane med prompten udfyldt, så
brugeren kan gennemgå og sende den.

```ts
const session = ctx.sessions.current()
const launchers = () => ctx.layout.side.menu().filter((item) => !item.primary && !item.opened)

if (session) {
  ctx.layout.draft({ server: session.server.id, directory: session.directory, prompt: ctx.t("setup.prompt") })
}
```

### Sessioner og sessionsskærmen

`ctx.sessions.current()` er den session, som den aktuelle rute peger på, og `ctx.screen.current()` er dens skærm. Begge er `undefined` på Home
og i et udkast. Læs dem der, hvor du handler, aldrig én gang i `setup`.

```ts
const session = ctx.sessions.current()
const file = ctx.screen.current()?.file

if (session && file) void file.sync("README.md")
```

- `key` er `<server id>\n<session id>` og er unik på tværs af servere. Brug den som nøgle til tilstand, der gemmes pr. session.
- `tab` er nøglen for den shellfane, der ejer sessionen. `pending` er `true`, mens serveren stadig opretter den.
- `directory` er sessionens arbejdsområdemappe, og `local` er `true`, når den er projektroden.
- `listedProject` er det projekt i sidebar, som sessionen tilhører.
- `visit` er et nyt objekt, hver gang sessionen routes.

### Vedhæft til inputfeltet

Brug `ctx.screen.current()?.composer` i en hændelseshandler eller kommando til at vedhæfte en fil, en note eller et citat til brugerens
næste prompt.

```ts
const composer = ctx.screen.current()?.composer

composer?.attach({
  type: "note",
  origin: ctx.id,
  commentID: crypto.randomUUID(),
  label: "button#submit",
  icon: "globe",
  subject: 'element <button id="submit">Save</button>',
  comment: "Make this button primary and disable it while saving.",
  href: "http://localhost:3000/settings",
})
```

- `attach` lader tastaturfokus være, hvor det er. Kald `focus()` for at flytte det til prompten.
- `update(commentID, { comment?, preview? })` ændrer en vedhæftet del; en note eller et citat tager kun en ny `comment`.
- `detach(commentID)` fjerner en vedhæftet del.
- En notes `live` erstatter dens `subject` og `href`, så længe noten er i den aktuelle appproces, til referencer som kun denne
  proces kan slå op, f.eks. et sideelement. Den værdi udelades, når udkastet gemmes, og når en sendt besked gendannes ved en tilbagerulning eller forgrening.
forgrening gendanner, også.

Et citat er tekst, brugeren har citeret fra noget, dit plugin viser, f.eks. logoutput, med en valgfri kommentar. Det
renders som et citat fra sessionstidslinjen under kildens ikon og label. Tjek `quotable()` først: den er
`false` i en subagents session, som ikke har et inputfelt, og mens inputfeltet kører shell-kommandoer.

```ts
const composer = ctx.screen.current()?.composer

if (composer?.quotable()) {
  const commentID = crypto.randomUUID()

  composer.attach({
    type: "quote",
    commentID,
    text: selection,
    source: { label: ctx.t("source.label"), icon: "console", subject: "the Acme log" },
  })
  composer.focus(commentID)
}
```

- `source.subject` navngiver kilden for modellen, f.eks. `the terminal`. Det lokaliseres ikke.
- Udelad `comment` for at lade brugeren tilføje en fra chippen.
- `focus(commentID)` åbner kommentareditoren for et vedhæftet citat. Mens inputfeltet ikke vises, f.eks. på en smal
skærm, der viser et panel, åbnes editoren, når inputfeltet vises.
- Modellen læser `The user quoted the following from <subject>:`, derefter teksten med hver linje præfikset med `> `,
 og derefter kommentaren, hvis der er nogen.

### Læs og skriv prompten

Læs, hvad brugeren har skrevet, med `text()`, og om de skriver, med `focused()`:

```ts
const composer = ctx.screen.current()?.composer
const empty = !composer?.text().trim()
```

- `text()` er prompten som ren tekst: en omtale læses som sin `@`-tekst, og vedhæftninger og vedhæftede dele udelades.
I shell-tilstand er det shell-kommandoen. Den er `""`, indtil sessionens udkast indlæses, og i en subagents session,
som ikke har et inputfelt. Den er reaktiv.
- `focused()` er `true`, mens tastaturfokus er i prompten. Den er ikke reaktiv, så læs den der, hvor du handler, f.eks. i
en kommandos `run`.

`insert(text)` skriver tekst ind i prompten, så brugeren kan gennemgå og sende den. Ingen af metoderne på composer-objektet sender prompten.

```ts
const composer = ctx.screen.current()?.composer

composer?.insert(`Explain ${path}`)
composer?.focus()
```

- `insert` tilføjer teksten ved den markør, brugeren sidst efterlod i prompten, ellers i slutningen, og flytter markøren efter
den. Den erstatter ikke markeret tekst.
- Teksten parses ikke: `@path` forbliver tekst, ikke en omtale.
- `setText(text)` erstatter promptens tekst, inklusive omtaler. Vedhæftninger og vedhæftede dele bliver. `setText("")`
rydder teksten.
- Begge lader tastaturfokus være, hvor det er. Kald `focus()` for at flytte det til prompten.
- En skrivning, der foretages før sessionens gemte udkast indlæses (`insert`, `setText`, `attach`, `update` eller `detach`), venter på
det. Den anvendes derefter på den session, der var routet, da du kaldte den, i kaldets rækkefølge. Den erstatter aldrig det gemte
udkast.
- I en subagents session, som ikke har et inputfelt, gør skrivningerne intet.

### Vælg modellen

`model()` er modellen, som den næste prompt sendes med, og `setModel` vælger en, som modelvælgeren gør:

```ts
const composer = ctx.screen.current()?.composer

if (composer && !composer.setModel({ providerID: "anthropic", modelID: "claude-sonnet-4-5", variant: "high" })) {
  ctx.toast.show({ variant: "error", title: ctx.t("model.unavailable") })
}
```

- `model()` er brugerens valg for den session, som den aktuelle rute peger på, ellers agentens standard, ellers appens standard. Den er
`undefined`, mens modelkataloget indlæses, når ingen forbundet udbyder tilbyder modellen, og i en subagents session.
Den er reaktiv.
- `setModel` vælger modellen for sessionen og flytter den øverst på listen over senest brugte modeller. Uden `variant` beholder modellen
  den variant, modelvælgeren ville vise for den.
- `setVariant(variant)` vælger en variant af den aktuelle model. `undefined` vælger modellens standardvariant.
- `setModel` returnerer `false` og ændrer intet, mens kataloget indlæses, når ingen forbundet udbyder tilbyder
modellen, eller når modellen ikke har den variant.
- `setVariant` returnerer `false` og ændrer intet, når der ikke er en aktuel model, eller modellen ikke har den variant.
- Begge returnerer `false` i en subagents session.

```ts
import { onCleanup } from "solid-js"
```

oppe.

### Dialoger

`ctx.dialogs.open(render, { replace? })` åbner en dialog oven over de åbne og returnerer et handle, hvis `close()` lukker
den. Dialogen lukkes også, når dens ejende scope slutter.

```tsx
const handle = ctx.dialogs.open((dialog) => <ConfirmDialog onDone={dialog.close} />)
```

- `replace: true` lukker først hver åben dialog, inklusive værtens og andre plugins' dialoger.
- `ctx.dialogs.active()` er `true`, mens en dialog er åben.
- Render indholdet i `ctx.ui.Dialog` for appens dialogramme; se [Appkomponenter](#app-components).

### Spørg brugeren

`confirm`, `alert`, `prompt` og `select` spørger i appens egne dialoger, så dit plugin ikke behøver sit eget dialog-UI.
Hver returnerer et promise med svaret.

```ts
const ok = await ctx.dialogs.confirm({ title: ctx.t("end.title"), confirm: ctx.t("end"), danger: true })
```

- `confirm` giver kun resultatet `true`, hvis brugeren bekræfter. `danger` markerer bekræftelsesknappen som destruktiv og sætter
  fokus på Cancel i første omgang.
- Hver dialog åbnes som `open`, og lukkes med ejeren, der spurgte, ellers med dit plugin.
- Annullering, Escape, klik uden for dialogen, en ny dialog, der erstatter den, eller udløb af ejerens levetid giver resultatet `false` fra `confirm`
  og `undefined` fra `prompt` og `select`.

`alert` viser en besked med én knap, som brugeren skal kvittere med. Det returnerede promise fuldføres, når dialogen lukkes, uanset hvordan det sker:

```ts
await ctx.dialogs.alert({ title: ctx.t("export.done"), description: path })
```

`prompt` beder om én linje tekst. Startværdien `value` er markeret, så indtastning erstatter den. Resultatet er aldrig en tom streng: Det har ingen effekt at indsende feltet, når det er tomt. Brug `secret: true` til at skjule det indtastede, f.eks. en adgangskode eller et token:

```ts
const token = await ctx.dialogs.prompt({ title: ctx.t("token.title"), placeholder: "ghp_…", secret: true })
```

`select` viser valgmuligheder i en søgbar liste som kommandopaletten og giver det valgte elements `value` som resultat:

```ts
const url = await ctx.dialogs.select({
  title: ctx.t("links.title"),
  options: links.map((link) => ({ title: link.title, description: link.url, value: link.url, group: link.host })),
})

if (url) ctx.system.openExternal(url)
```

- Søgning matcher hver muligheds `title` og `description`.
- Muligheder med samme `group` vises sammen under den overskrift.
- `current` er værdien af den mulighed, der fremhæves først.

### Appkomponenter

Et pluginbundle kan ikke importere `@opencode/ui`, så `ctx.ui` giver det appens egne komponenter. De renderes i
brugerens tema, skrifttyper og sprog, så dit plugins UI ser ud og opfører sig som appens.

```tsx
import { Show } from "solid-js"
import { createLatest, Panel } from "@opencode/plugin/gui"

const ui = ctx.ui
const summary = createLatest(
  () => ctx.sessions.current()?.directory,
  (directory, signal) => fetchSummary(directory, signal),
)

ctx.add(Panel, {
  id: "summary",
  region: "side",
  list: () => [summaryTab],
  render: () => (
    <div>
      <ui.Tooltip value={ctx.t("copy")}>
        <ui.IconButton icon="copy" label={ctx.t("copy")} onClick={() => void ctx.system.copy(summary.latest ?? "")} />
      </ui.Tooltip>
      <Show when={summary.latest} fallback={<ui.Loader size="large" />}>
        {(text) => <ui.Markdown text={text()} />}
      </Show>
    </div>
  ),
})
```

- `Icon`, `Button` og `IconButton` tager ethvert `IconName`, som hvert `icon`-felt i SDK'et gør: et af appens
ikoner eller et af [dine egne](#icons) fra `ctx.icons`. En `IconButton`s `label` er dens tilgængelige navn; pak den i
`Tooltip` for at vise det ved hover.
- `busy` på en knap erstatter dens ikon med indlæsningsindikatoren og deaktiverer den, indtil den er `false` igen.
- Brug `Loader` til alle indlæsningstilstande undtagen dem, hvor AI'en arbejder, f.eks. når et panel eller søgeresultater indlæses,
  eller en forbindelse oprettes.
- `Menu` åbner en liste af `items`: handlinger, `{ type: "separator" }` og `{ type: "group", label, items }`.
- `Switch` og `TextInput` holder ingen tilstand: send værdien fra `onChange` eller `onInput` tilbage til `checked` eller `value`.
- `Keybind` viser taster som chips, f.eks. `ctx.keybinds.keybind(command)`.
- `Markdown` renderes, som tidslinjen renderer en besked, og `Code` viser en fremhævet, skrivebeskyttet kodeblok. Begge udfyldes
kort efter de monteres.

`Dialog` er appens dialogramme: en titel, indhold og knapper. Render den fra `ctx.dialogs.open`; andre steder
renderer den intet brugbart.

```tsx
const ui = ctx.ui

ctx.dialogs.open((dialog) => (
  <ui.Dialog
    title={ctx.t("rename.title")}
    footer={
      <ui.Button variant="contrast" onClick={dialog.close}>
        {ctx.t("done")}
      </ui.Button>
    }
  >
    <ui.TextInput label={ctx.t("rename.label")} value={name()} onInput={setName} onSubmit={dialog.close} autofocus />
  </ui.Dialog>
))
```

- `size` er `"fit"` som standard: 480px bred og så høj som indholdet. `"normal"`, `"large"` og `"x-large"` er faste
størrelser.
- Escape og et klik udenfor lukker dialogen. `closable: false` skjuler headerens lukkeknap.

#### Menurækker

`MenuItem`, `MenuSub`, `MenuGroup` og `MenuSeparator` er rækker til en menu, værten renderer, som
`session.location.menu`-slotten. De navigerer med tastaturet, viser værtens dæmpede ikoner og genvejschips og lukker
menuen ved et valg.

```tsx
import { For } from "solid-js"

const ui = ctx.ui

ctx.add(Slot, {
  at: "session.location.menu",
  render: (input) => (
    <>
      <ui.MenuItem
        label={ctx.t("usage")}
        icon="status"
        keys={["Ctrl", "U"]}
        onSelect={() => openUsage(input.session)}
      />
      <ui.MenuSub label={ctx.t("openIn")} icon="outline-share">
        <For each={apps()}>{(app) => <ui.MenuItem label={app.name} onSelect={() => launch(app, input.session)} />}</For>
      </ui.MenuSub>
    </>
  ),
})
```

- `MenuItem` tager samme felter som en post i `Menu`s `items`.
- `MenuSub` åbner sine børn i en undermenu ved siden af rækken. `onOpenChange` fortæller hvornår, så du kan indlæse dens rækker
kun, mens den er åben.
- `MenuGroup` sætter rækker under en overskrift, og `MenuSeparator` tegner en linje mellem rækker.
- `MenuItem`, `MenuSub` og `MenuGroup` kaster en fejl uden for en menu: værten registrerer fejlen og renderer intet af det
bidrag.

#### Selects

`Select` vælger en af en liste af valgmuligheder, som appens indstillingsrækker vælger et sprog. Dens værdi er en streng; typen af
`options` indsnævrer den.

```tsx
const [period, setPeriod] = createSignal<"day" | "month">("day")

<ui.Select
  label={ctx.t("period")}
  options={[
    { value: "day", label: ctx.t("period.day") },
    { value: "month", label: ctx.t("period.month") },
  ]}
  value={period()}
  onChange={setPeriod}
/>
```

- `label` er selectets tilgængelige navn; den valgte muligheds `label` er det, den viser.
- En `value`, som ingen mulighed har, viser `placeholder`. Valg af den allerede valgte mulighed kalder ikke `onChange`.

#### Indstillingskomponenter

`SettingsLayout`, `SettingsSection` og `SettingsRow` renderer en [indstillingsside](#settings-pages), som appen renderer
sine egne: sideheaderen, sektioner med overskrifter over indrammede lister og rækker med en titel, en beskrivelse og en
kontrol i slutningen.

```tsx
<ui.SettingsLayout title={ctx.t("title")} description={ctx.t("description")} actions={<HelpButton />}>
  <ui.SettingsSection title={ctx.t("section.display")} footer={<Show when={error()}>{ctx.t("error")}</Show>}>

    </ui.SettingsRow>
  </ui.SettingsSection>
</ui.SettingsLayout>
```

- Brug `SettingsLayout` til en side af din egen, `SettingsSection` til en sektion på en værtens side og `SettingsRow` alene
til rækker i en værtens sektion. Rækker flugter med værtens rækker i alle tilfælde.
- `id` på en række er den `SettingEntry.id`, der afslører den. Søgning, der afslører sidens eget id, fremhæver headeren.
- `actions` sidder i slutningen af titelrækken. En sektions `footer` sidder under dens liste uden for rammen.
- De tager deres udseende fra Settings-skærmens stilarter, så render dem fra en `SettingsPage`.

### Toasts

`ctx.toast.show` viser en kort besked i hjørnet af vinduet og returnerer et handle, hvis `dismiss()` lukker den.

```ts
ctx.toast.show({ variant: "success", title: ctx.t("invite.copied") })
```

- `variant` er `"default"`, `"success"`, `"error"` eller `"loading"`. En `success`-toast viser et checkikon, medmindre du sætter
`icon`.
- `duration` er, hvor længe toasten vises, i millisekunder. Standard er 5 sekunder.
- `persistent: true` beholder toasten, indtil brugeren eller `dismiss()` lukker den, og ignorerer `duration`.
- En toast, der er lig med en, der stadig vises, erstatter den i stedet for at stable en kopi.
- Dit plugins toasts lukkes, når det stopper, så ingen knap overlever den kode, den kører. En toast lukkes ikke med den
komponent eller `createKeyed`-kørsel, der viste den.

Vis en `loading`-toast, mens arbejde kører, og afvis den, når arbejdet slutter:

```ts
const saving = ctx.toast.show({ variant: "loading", title: ctx.t("saving"), persistent: true })
await save()
saving.dismiss()
```

`actions` tilføjer knapper. Et klik kører handlingen og lukker toasten:

```ts
ctx.toast.show({
  variant: "error",
  title: ctx.t("sync.failed"),
  actions: [{ label: ctx.t("retry"), run: () => void sync() }],
})
```

### Notifikationer

`ctx.attention.notify` får brugerens opmærksomhed, mens de kigger et andet sted: en systemnotifikation og en lyd med
samme regler som appens egne notifikationer.

```ts
const session = ctx.sessions.current()

if (session) {
  void ctx.attention.notify({
    title: ctx.t("tests.done"),
    message: ctx.t("tests.summary", { failed: 0 }),
    session: { server: session.server.id, id: session.id },
    id: run.id,
  })
}
```

- Systemnotifikationen vises kun, mens intet appvindue har fokus. Lyden afspilles uanset hvad.
- Begge følger **Settings > Notifications**. `variant: "default"` følger **Agent**-rækkerne, og `variant: "error"`
**Errors**-rækkerne. Desktopnotifikationer for begge er slået fra som standard; deres lyde er slået til.
- `sound: false` afspiller aldrig en lyd.
- Klik på notifikationen bringer appen frem og åbner `session`, når du angiver en.
- Hvert appvindue kører sin egen kopi af dit plugin. Angiv et `id` for hændelsen, f.eks. id'et for en kørsel. Så er det
  kun det første vindue, der sender id'et, som viser en notifikation og afspiller lyden. Uden `id` viser hvert kald
  en notifikation.
- Før appgrænsefladen monteres, venter `notify` på den.

`notify` afviser aldrig sit promise. Resultatet viser, hvad der skete: `notification` er `true`, hvis appen bad systemet om at vise notifikationen, og `sound` er `true`, hvis lyden begyndte at spille.

```ts
const result = await ctx.attention.notify({ title: ctx.t("deploy.failed"), variant: "error" })

if (!result.notification) ctx.toast.show({ variant: "error", title: ctx.t("deploy.failed") })
```

- `notification` er `false`, når brugeren har slået den fra, et appvindue har fokus, eller et andet vindue allerede har sendt
`id`. Systemet kan stadig skjule en notifikation, appen bad det vise, f.eks. når brugeren har afvist en
browsers tilladelse.

### Forbrugsdata

En sessions token-, omkostnings- og plantal ligger i dens servers data, samme reaktive store som appen læser for
headerens “28k · $0.28”. Læs dem der i stedet for fra opencodes database.

```ts
import { lastAssistantWithUsage } from "@opencode/client/solid"

const data = session.server.data
const info = () => data.session.get(session.id)

const tokens = () => info()?.tokens // this session's tokens by kind
const cost = () => data.session.cost(session.id) // USD, with subagent sessions
const step = () => lastAssistantWithUsage(data.session.message.list(session.id), info()?.revert?.messageID)
const limits = () => (session.location ? data.location.usage.limits(session.location) : undefined)
```

- `step()` er det assistant-trin, hvis tokens fylder kontekstvinduet nu, som appens kontekstring bruger. Sammenlign dets
`tokens` med modellens `limit.context` fra `data.location.model.list`.
- `limits()` indeholder OpenCode Console-budgetterne og Go-planens kvote, når `data.location.usage.sync(location)` har
indlæst dem. Den er `null`, når serveren ikke rapporterer nogen.

### Faner

`ctx.tabs` læser og ændrer shellens fanestribe: de sessioner og udkast, der er åbne som faner. Dette flytter en sessions fane
frem, når dens kørsel slutter:

```ts
import { onCleanup } from "solid-js"
import { createKeyed } from "@opencode/plugin/gui"

createKeyed(
  () => ctx.servers.get("sidecar")?.data,
  (data) =>
    onCleanup(
      data.on("session.execution.succeeded", (event) => {
        const tab = ctx.tabs.list().find((item) => item.session?.id === event.data.sessionID)

        if (tab) ctx.tabs.move(tab.key, 0)
      }),
    ),
)
```

- `list()` returnerer de åbne faner i stribens rækkefølge. Det er reaktivt. En fanes `session` er `undefined` for et udkast, og
`active` er `true` for fanen på skærmen.
- `open({ server, id }, { focus? })` åbner en session som en fane i slutningen af striben, i baggrunden, medmindre `focus`
er `true`. En session, der allerede er åben, beholder sin fane. Det samme gælder en subagent, der vises i den overordnede sessions fane.
- `focus(key)` viser en fane, `move(key, index)` flytter den, og `close(key)` lukker den, som brugeren gør.
- En nøgle, som ingen åben fane har, gør intet. Skrivninger foretaget før appgrænsefladen monteres, venter på den.

### Kør kommandoer

### System og miljø

`ctx.system` virker på alle platforme. `ctx.desktop` tilføjer funktioner, der kun findes i desktopappen, og er `undefined` på web.

```ts
const show = async (path: string) => {
  if (ctx.desktop && (await ctx.desktop.reveal(path))) return
  await ctx.system.copy(path)
}
```

- `system.save` viser en gem-dialog på desktop og downloader på web. Den returnerer `false`, når brugeren annullerer
dialogen.
- `system.openExternal` åbner en URL i systembrowseren. Til links inde i appen skal du bruge `ctx.links.open`, som router
et `Link` til dens [linkhandler](#link-handlers).
- `desktop.launch(path, app?)` åbner en sti med en app eller med standardappen. `desktop.reveal(path)` viser den i
filhåndteringen.
- `ctx.embeds` renderer en hovedproces-webvisning i et vindue; se
[Indlejrede webvisninger](#embedded-web-views).
- `ctx.locale` læser grænsefladesproget og dets skriveretning. `ctx.appearance.font("mono")` er CSS-skriftfamilien
for brugerens terminalskrift.
- `ctx.router` læser den aktuelle rutesti og om en ruteovergang er i gang.
- `ctx.workspaces.on("remove", handler)` kører, når brugeren fjerner en arbejdsområdemappe fra en server, så du kan
rydde stores op, der er afgrænset til den.

`desktop.pick(options)` lader brugeren vælge filer eller mapper i systemets åbningsdialog og giver deres absolutte stier som resultat:

```ts
const [folder] = (await ctx.desktop?.pick({ directory: true, title: ctx.t("pick.folder") })) ?? []

if (folder) await ctx.client.rpc(Acme).index({ directory: folder })
```

- `directory: true` vælger mapper i stedet for filer, og `multiple: true` lader brugeren vælge mere end én.
- `extensions` begrænser de tilbudte filer, uden punktum, f.eks. `["json"]`. Mapper ignorerer det.
- `title` er dialogens titel. Ikke alle systemer viser den.
- Stierne er tomme, når brugeren annullerer. `pick` afvises, når dialogen ikke kan åbnes.
- `pick` er kun til desktop: en browser fortæller aldrig siden, hvor en valgt fil ligger.

`ctx.appearance.mode()` er det farveskema, grænsefladen viser, `"light"` eller `"dark"`. Det er reaktivt:

```ts
const background = () => (ctx.appearance.mode() === "dark" ? "#000" : "#fff")
```

- Det følger brugerens valg i **Settings > Appearance**, hvor **System** bruger systemets aktuelle farveskema.
- Før appgrænsefladen monteres, er det systemets skema.

## Gemt tilstand

Desktopvinduer indlæser gemt tilstand over IPC, mens web læser `localStorage` med det samme. Erklær stores i
`Plugin.define({ stores })`, så værten indlæser dem for dig.

- **`Store.global`** gemmer én værdi for appen. Den indlæses, før `setup` kører, så `ctx.stores.name.value` aldrig er
`undefined`.
- **`Store.session`** gemmer én værdi pr. session. Den indlæses, når sessionen monteres; `ctx.stores.name(session).value`
er `undefined` indtil da.

Erklærede stores er til vinduer. `main` åbner sin tilstand med `ctx.storage.store`, som læser synkront; se
[Hovedkontekst](#main-context).

Mutér en værdi på stedet med `update(draft => …)`, som ikke må returnere noget, eller erstat den med `set(next)`:

```ts
const enabled = ctx.stores.prefs.value.enabled

ctx.stores.prefs.update((draft) => {
  draft.enabled = !draft.enabled
})
```

- `ready()` er `true`, når værdien er indlæst. Skrivninger foretaget før det venter og anvendes i kaldets rækkefølge.
- `from` angiver andre gemte nøgler at importere værdien fra én gang, mens storen ikke indeholder nogen, f.eks. nøglen for en
store, du omdøbte: `"plugin.acme.settings"`. Send en liste for at prøve flere nøgler, nyeste først. Den anden nøgle beholder sin
kopi, indtil storen fjernes.

```ts
stores: {
  prefs: Store.global(Prefs, { enabled: true }, ["plugin.acme.settings.v2", "plugin.acme.settings"]),
}
```

#### Reference

```ts
const Store: {
  global(schema: Schema, initial: T, from?: string | string[]): StoreDeclaration
  session(schema: Schema, initial: T, from?: string | string[]): StoreDeclaration
}

interface Persisted<T, V = T | undefined> {
  value: V
  ready(): boolean
  update(mutate: (draft: T) => undefined): void
  set(next: T): void
}
```

### Runtime-stores

`ctx.storage.store(key, options)` åbner en store for en nøgle, der først kendes ved kørsel. `scope` gemmer én værdi pr. server,
mappe eller session.

```tsx
import { Schema } from "effect"
import { usePlugin, type MountedSession } from "@opencode/plugin/gui"
import type { definition } from "./definition"

function DraftView(props: { readonly session: MountedSession }) {
  const ctx = usePlugin<typeof definition>()

  const draft = ctx.storage.store("draft", {
    schema: Schema.Struct({ text: Schema.String }),
    initial: { text: "" },
    scope: { server: props.session.server.id, directory: props.session.directory },
  })

  return <p>{draft.value?.text}</p>
}
```

- `scope: "global"`, standard, gemmer én værdi for appen.
- `scope: { server, directory? }` gemmer én værdi pr. server eller pr. arbejdsområdemappe på den.
- `scope: { session }` gemmer én værdi pr. session, åbnet igen når sessionen flytter til en ny mappe.
- En runtime-stores `value` er `undefined`, indtil den indlæses.
- `ctx.storage.memory(key, { initial })` gemmer vindueslokal tilstand, der overlever plugin-genindlæsninger, men ikke vinduesgenindlæsninger.
- `ctx.storage.remove(key, { scope, from })` sletter værdien, så nøglen igen læses som `initial`.

#### Reference

```ts

  remove(key: string, options?: { scope?: StorageScope; from?: string | string[] }): void
}

interface StoreOptions {
  schema: Schema
  initial: T
  scope?: StorageScope
  from?: string | string[]
}
```

## Reaktive primitiver

Brug helst disse hjælpefunktioner frem for direkte kald til `createEffect`, `createRenderEffect` og `createComputed`. De følger pluginets levetid og tager højde for, at afhængigheder genstarter, hvilket er let at overse i håndskrevne effekter.

### createKeyed

`createKeyed(source, fn, { otherwise?, equals? })` kører `fn` i en frisk ejer for hver nøgle: hver aktiv generation af en
`ctx.use`-accessor eller hver værdi af en almindelig accessor. Alt, der registreres inde i `fn`, slutter med den kørsel.

```tsx
import { onCleanup } from "solid-js"
import { createKeyed, usePlugin, type SessionScreen } from "@opencode/plugin/gui"
import { Changes } from "@opencode/plugin/gui/review"

function ChangedFiles(props: { readonly screen: SessionScreen }) {
  const ctx = usePlugin()

  // Each active generation of Changes keeps this view's changes loaded; the watch ends with it.
  createKeyed(ctx.use(Changes), (changes) => onCleanup(changes.watch(props.screen, "files")))

  return <FileMarkers screen={props.screen} />
}
```

- `otherwise` kører, mens kilden ikke har en nøgle: en `Live`-accessor, der ikke er aktiv, eller en almindelig accessor, hvis værdi
er `undefined`, `null` eller `false`.
- `equals` afgør, om en almindelig accessors nye værdi er samme nøgle, så `fn` ikke kører igen. Brug den, når
kilden bygger et nyt objekt hver gang. En `Live`-accessor nøgler altid efter generation.

#### Reference

```ts
function createKeyed<T>(
  source: () => Live<T> | T,
  fn: (value: T) => void,
  options?: { otherwise?(): void; equals?(previous: T, next: T): boolean },
): void
```

- `error` er den aktuelle anmodnings afvisning, hvis nogen.

### Gennemgå ændringer

`@opencode/plugin/gui/review` eksporterer `Changes`, appens visning af en sessions ændringer, og `ChangeKind`
(`"add"`, `"del"` eller `"mix"`).

```ts
import { Changes } from "@opencode/plugin/gui/review"

const changes = ctx.use(Changes)

const count = () => {
  const live = changes()
  const session = ctx.sessions.current()

  return live.status === "active" && session ? live.value.diffs(session).length : 0
}
```

- `diffs(session)` er den aktuelle gennemgangstilstands diffs, og `ready(session)` er `true`, når de er indlæst. Begge er
reaktive. Kun den session, som den aktuelle rute peger på har ændringer; andre sessioner læses som tomme.
- `kinds(session)` knytter hver ændret fil og mappe til dens `ChangeKind`.
- `active(session)` er den fil, gennemgangspanelet viser.
- `details(session)` er sessionens mappes ikke-committede ændringer, uanset gennemgangstilstanden.
- `focus(session, path)` viser en fil i gennemgangspanelet, og `open(session)` viser alle ændringer.
- `watch(screen, source)` holder en visnings ændringer indlæst, mens den viser dem, på tværs af visningens sessionsskift.
Send den ejende skærm fra panelet eller slotinputtet. Den returnerer en funktion, der stopper overvågningen; se
[createKeyed](#createkeyed).
- En `tree`-overvågning er en vedvarende ændringsliste: åbning af sideområdet opdaterer den. En `details`-overvågning indlæser
`details(session)`.

## Hovedprocessen

I OpenCode Desktop kører et plugins `main`-opsætning én gang i Electrons hovedproces som en singleton for hele appen. Den har fuld adgang til Node.js' indbyggede moduler, `electron` og hovedprocessens værts-API'er. Send den til `Plugin.define` i pluginets [`./gui-experimental`-fil](#define-the-gui-plugin), sammen med vinduets `setup` eller alene.

```tsx title="src/gui.tsx"
import { Schema } from "effect"
import { powerSaveBlocker } from "electron"
import { Plugin } from "@opencode/plugin/gui"
import { KeepAwake } from "./gui/contract"

export default Plugin.define({
  main(ctx) {
    const stored = ctx.storage.store("keepScreenActive", { schema: Schema.Boolean, initial: false })
    let blockerId: number | undefined

    const release = () => {
      if (blockerId === undefined) return
      powerSaveBlocker.stop(blockerId)
      blockerId = undefined
    }

    const setActive = (enabled: boolean) => {
      if (enabled && blockerId === undefined) blockerId = powerSaveBlocker.start("prevent-display-sleep")
      if (!enabled) release()
      stored.set(enabled)
    }

    if (stored.value) setActive(true)

    ctx.provide(KeepAwake, {
      screenActive: () => blockerId !== undefined && powerSaveBlocker.isStarted(blockerId),
      setScreenActive: (enabled) => setActive(enabled),
    })

    return release
  },
})
```

I et vindue er `electron` en inaktiv pladsholder, så importet er sikkert i den delte `./gui-experimental`-fil. Se
[Én fil, to processer](#one-file-two-processes).

## Hovedkontekst

`main` modtager en `MainContext`. I modsætning til vinduets `setup` må `main` være `async`, og den kan returnere en oprydningsfunktion direkte eller via et promise.

```ts
main(ctx) {
  ctx.log.write("info", "acme started", { version: ctx.app.version })
}
```

- `ctx.options`, `ctx.client` og `ctx.app` er den [delte kontekst](#shared-context). I `main` er
`ctx.app.platform` altid `"desktop"`.
- `ctx.storage.store(key, { schema, initial })` åbner en store synkront i pluginets navnerum. Dens `value` er
altid defineret, og hvert `set` eller `update` når databasen, før det returnerer. `ctx.storage.remove(key)` sletter
værdien.
- `ctx.signal` afbrydes, når pluginet deaktiveres, genindlæses eller fjernes, eller appen afsluttes. `ctx.onCleanup(fn)` kører `fn`
derefter; se [Levetider og oprydning](#lifetimes-and-cleanup).
- `ctx.provide` implementerer en `Ipc` under pluginets id; se [Definér og lever en Ipc](#define-and-provide-an-ipc).
- `ctx.add` bidrager til hovedprocesregistre som [`MenubarItem`](#native-app-menu).
- `ctx.windows` viser appens vinduer og rapporterer, når et åbnes eller lukkes.
- `ctx.embeds` placerer en `WebContentsView` i et vindues layout; se [Indlejrede webvisninger](#embedded-web-views).
- `ctx.serverEndpoints.get(id)` returnerer en servers URL og legitimationsoplysninger. Desktopappens egen server er `"sidecar"`.
- `ctx.cli` beskriver den OpenCode CLI, desktopappen kører.
- `ctx.log.write` skriver til desktop-logfilen.

## Definér og lever en Ipc

En `Ipc`-specifikation kan angive `state` for hvert vindue, `methods`, der kan kaldes, og `events`, der sendes til vinduerne. Effect-`Schema` validerer og koder hver værdi, der krydser broen.

```ts title="src/gui/contract.ts"
import { Schema } from "effect"
import { Ipc } from "@opencode/plugin/gui"

export const Counter = Ipc.define({
  id: "acme.counter",
  state: Schema.Struct({ count: Schema.Number }),
  methods: {
    increment: {
      input: Schema.Number,
      output: Schema.Number,
    },
    reset: {},
  },
  events: {
    overflow: Schema.Struct({ limit: Schema.Number }),
  },
})
```

- Id'et er dit plugins id eller begynder med det, som `acme.counter`. `ctx.provide` i `main` og `ctx.main` i et vindue
kaster en fejl for alle andre id’er.
- Udelad `input` for en metode, der ikke tager argumenter, og `output` for en metode, der intet returnerer.

#### Reference

```ts
interface IpcSpec {
  id: string
  state?: Schema
  methods: Record<string, { input?: Schema; output?: Schema }>
  events?: Record<string, Schema>
}
```

### Implementér provideren i hovedprocessen

Hver metode modtager det afkodede input og en `Caller` (`{ window, signal }`). Kald `provider.changed(window?)`, når
`state` ændres, for at pushe det nye snapshot til abonnerende vinduer, eller `provider.emit(name, payload, window?)` for at sende en
hændelse.

```ts title="src/gui/main.ts"
import type { Plugin } from "@opencode/plugin/gui"
import { Counter } from "./contract"

export const main: Plugin.MainSetup = (ctx) => {
  const counts = new Map<number, number>()

  const provider = ctx.provide(Counter, {
    state: (window: number) => ({ count: counts.get(window) ?? 0 }),
    increment: (step, caller) => {
      const next = (counts.get(caller.window) ?? 0) + step
      counts.set(caller.window, next)
      provider.changed(caller.window)

      if (next > 100) provider.emit("overflow", { limit: 100 }, caller.window)

      return next
    },
    reset: (_input, caller) => {
      counts.set(caller.window, 0)
      provider.changed(caller.window)
    },
  })
}
```

- En spec med `state` kræver også `state(window)` i implementeringen. Main læser den, når et vindue abonnerer, og ved
hver `changed`.
- En metode, der kaster, afviser vinduets kald.
- `changed` og `emit` når hvert vindue, når du udelader `window`.
- `dispose()` trækker `Ipc`'en tilbage tidligt. Vinduer ser den som `pending`, og `ctx.main`-kald venter, indtil pluginet leverer
den igen eller stopper. Værten trækker den også tilbage, når pluginet stopper.

#### Reference

```ts
type IpcImpl<S extends IpcSpec> = {
  [Name in keyof S["methods"]]: (input: Input<Name>, caller: Caller) => Output<Name> | Promise<Output<Name>>
} & { state(window: number): State }

interface Caller {
  window: number
  signal: AbortSignal
}

interface IpcProvider<S extends IpcSpec> {
  changed(window?: number): void
  emit(name: keyof S["events"], data: EventData, window?: number): void
  dispose(): void
}
```

### Brug Ipc'en i et vindue

I et vindue returnerer `ctx.main(Counter)` klienten for den `Ipc`, din `main` leverer. En metode uden et `input`-
schema tager kun valgfrie `{ signal }`-kaldindstillinger. Send ikke `undefined` som dens første argument.

```tsx title="src/gui/window.tsx"
import { Command, type Plugin } from "@opencode/plugin/gui"
import { Counter } from "./contract"
import type { definition } from "./definition"

export const setup: Plugin.Setup<typeof definition> = (ctx) => {
  const counter = ctx.main(Counter)

  // Follows main across restarts; removed when the plugin stops.
  counter.on("overflow", (data) => console.log(`Counter exceeded ${data.limit}`))

  ctx.add(Command, () => ({
    id: "increment",
    title: ctx.t("command.increment"),
    enabled: ctx.app.platform === "desktop",
    run: async () => {
      await counter.increment(1, { signal: ctx.signal })
      await counter.reset({ signal: ctx.signal })
    },
  }))
}
```

- Et kald venter, mens `main` starter. Det afvises, når `main` ikke kan svare: på web, mens pluginets `main` er slukket
eller fejlet, eller når metoden kaster. Fang afvisningen der, hvor brugeren har brug for feedback.
- `state()` og `on()` følger `main` på tværs af genstarter. En lytter slutter med den aktuelle ejer, ellers med pluginet.
- `ctx.main` returnerer samme klient for hvert kald med tokenet.

Læs dette vindues `state` med `client.state()`. Den er `undefined`, indtil det første snapshot ankommer, og opdateres hver
gang, `main` kalder `changed`.

```tsx
const count = () => ctx.main(Counter).state()?.count ?? 0
```

#### Reference

```ts
type IpcClient<S extends IpcSpec> = {
  [Name in keyof S["methods"]]: S["methods"][Name] extends { input: Schema }
    ? (input: Input<Name>, options?: { signal?: AbortSignal }) => Promise<Output<Name>>
    : (options?: { signal?: AbortSignal }) => Promise<Output<Name>>
} & {
  state(): State | undefined
  on(name: keyof S["events"], listener: (data: EventData) => void): Cleanup
}
```

Definér pluginet med begge opsætningsfunktioner i `src/gui.tsx`: `Plugin.define({ ...definition, setup, main })`.

### Andre plugins

Et andet plugin følger din `Ipc` med `ctx.use(Counter)` som en kontrakt. Mens den er `active`, er dens værdi
den samme `IpcClient`.

```ts
const counter = ctx.use(Counter)
```

## Indlejrede webvisninger

For at indlejre en isoleret `WebContentsView` i et panel skal du oprette den i `main` og render dens boks fra vinduet.

```ts title="src/gui/main.ts"
import { type BrowserWindow, WebContentsView } from "electron"
import type { Plugin } from "@opencode/plugin/gui"

export const main: Plugin.MainSetup = (ctx) => {
  const attach = (window: BrowserWindow) => {
    const view = new WebContentsView()
    const embed = ctx.embeds.create(view, window)
    void view.webContents.loadURL("https://acme.example")
    embed.show(true)
    // Send embed.id to the window over your Ipc.
  }
  ctx.windows.list().forEach(attach)
  ctx.windows.on("open", attach)
}
```

```tsx title="src/gui/pane.tsx"
<ctx.embeds.View id={embedId} visible radius={8} />
```

- `"open"` udløses kun for vinduer, der åbnes senere, så knyt først til `ctx.windows.list()`.
- Et vindue sender embed'ens `id` til `ctx.embeds.View` og `ctx.embeds.capture`.
- `show(visible)` styrer synligheden fra siden: Webvisningen er kun synlig, når vinduet har gjort plads til den i sit layout, og
  `show(true)` er slået til.
- `on("visible", handler)` kører, når visningen går på eller af skærmen, også når vinduet maler et stillbillede i dens
sted.
- `capture()` returnerer et stillbillede af siden eller `undefined`, mens den er skjult.
- `dispose()` fjerner visningen fra vinduet, men lukker ikke dens side; kald `view.webContents.close()`, når
du er færdig med den. Værten afvikler også embed'en, når pluginet forsvinder.
- I vinduet fylder `View` sin boks med den indlejrede webvisning. Værten holder visningens placering og størrelse, zoom, afrundede hjørner og
  tildækning ved dialoger synkroniseret og skjuler visningen, når vinduet er skjult, eller en dialog er åben.
- `frozen` maler et stillbillede i stedet for den live visning, så DOM-indhold kan flyde over den. `radius` runder bund-
hjørnerne, og `background` er den farve, hjørnerne viser.
- `page` er det, embed'en viser, f.eks. dens URL. Mens et panel flyttes, maler værten et stillbillede af embed'en i dens
sted og dropper et stillbillede taget, mens `page` havde en anden værdi.
- Vinduets `capture(id)` returnerer et JPEG-stillbillede eller `undefined`, mens embed'en er skjult, og altid på web.

## Live-afhængigheder og fejlhåndtering

`ctx.use(token)` returnerer en accessor til en reaktiv `Live<T>`-værdi, som afspejler tilstanden for det plugin, der
leverer tokenet. Dit plugin kører videre, selv når provideren er slået fra, så håndtér også de andre tilstande end
`active`. Undgå betjeningselementer, der ikke reagerer, og indlæsningsindikatorer, der aldrig stopper.

```ts
import { Browser } from "@opencode/plugin/gui/browser"

const browser = ctx.use(Browser)

ctx.add(Command, () => {
  const live = browser()
  const session = ctx.sessions.current()

  return {
    id: "preview",
    title: ctx.t("command.preview"),
    enabled: live.status === "active" && !!session,
    run: () => {
      if (live.status === "active" && session) live.value.open(session, "http://localhost:3000")
    },
  }
})
```

- **`pending`:** provideren er ikke startet endnu, f.eks. mens dens plugin indlæses eller genstarter. Vis en indlæsningstilstand,
  eller skjul de valgfrie betjeningselementer.
- **`active`:** provideren kører, og `value` er dens kontrakt eller `Ipc`-klient. `generation` tæller aktiveringer og
  får en ny værdi, hver gang provideren genstarter.
- **`inactive`, `disabled`:** provideren er slået fra, mangler eller er ikke tilgængelig på denne platform; det sidste
  gælder alle `Ipc`-objekter på web. Vis, at betjeningselementet er utilgængeligt, eller udelad det.
- **`inactive`, `failed`:** providerens opsætningsfunktion kastede en fejl. Vis, at betjeningselementet er utilgængeligt.
- Din egen `main` har ingen `Live`-tilstand. Kald gennem [`ctx.main`](#use-the-ipc-in-a-window) venter, mens den starter, og
afvises, når den ikke kan svare.

#### Reference

```ts
type Live<T> =
  | { status: "pending" }
  | { status: "active"; value: T; generation: number }
  | { status: "inactive"; reason: "disabled" | "failed" }
```

## Levetider og oprydning

Alle registreringer via `ctx` (`ctx.add`, `ctx.provide`, `ctx.dialogs.open`, `ctx.embeds.create` og `Ipc`-hændelseslyttere) fjernes, når det scope, de tilhører, ophører:

- Inde i en komponent eller et `createKeyed`-callback slutter registreringer, når den komponent eller `createKeyed`-kørsel afvikles.
- På topniveau i `setup` slutter registreringer, når pluginet deaktiveres, genindlæses eller fjernes, eller dets vindue
lukkes.
- I `main` slutter registreringer, når pluginet deaktiveres, genindlæses eller fjernes, eller appen afsluttes. En embed slutter også,
når dens vindue lukkes.

For andre ressourcer som timere eller sockets skal du returnere en oprydningsfunktion fra setuppen. Den kører samtidig.

- **Vindues-`setup`** kan ikke være `async`, fordi den kører under en Solid-ejer. Returnér en oprydningsfunktion, eller brug
`onCleanup` eller `ctx.signal`.
- **`main`** må være `async`. Returnér en oprydningsfunktion direkte eller via et promise, eller brug `ctx.onCleanup(fn)`.

### Opsætning i vinduet

Vindues-`setup` skal være synkron. Start asynkront arbejde inde i `createKeyed` eller `createLatest`.

```tsx title="src/gui.tsx"
import { Command, createKeyed, Plugin } from "@opencode/plugin/gui"
import { Changes } from "@opencode/plugin/gui/review"

export default Plugin.define({
  i18n: { en: { changes: "Show changes" } },
  setup(ctx) {
    // Runs once per active generation of Changes; the command is withdrawn with it.
    createKeyed(ctx.use(Changes), (changes) => {
      ctx.add(Command, () => ({
        id: "changes",
        title: ctx.t("changes"),
        run: () => {
          const session = ctx.sessions.current()

          if (session) changes.open(session)
        },
      }))
    })

    const timer = setInterval(() => console.log("still here"), 60_000)

    return () => clearInterval(timer)
  },
})
```

### Opsætning i hovedprocessen

`main` må være `async`. For de ressourcer, den åbner, kan du returnere en oprydningsfunktion direkte eller via et promise eller registrere funktionen med `ctx.onCleanup(fn)`.

```ts
async main(ctx) {
  const socket = await connect(ctx.options)

  ctx.onCleanup(() => socket.close())
}
```

- `ctx.onCleanup` kører sine funktioner, når pluginet deaktiveres, genindlæses eller fjernes, eller appen afsluttes, sidst
registrerede først. Den kører en funktion med det samme, når pluginet allerede er væk.
- Efter en `await` skal du returnere, hvis `ctx.signal` er afbrudt, før du registrerer eller ændrer noget.
- En `async`-cleanup forsinker afslutningen, indtil den er færdig, i højst 3 sekunder.
