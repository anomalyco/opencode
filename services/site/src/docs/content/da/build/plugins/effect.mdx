`@opencode/plugin/effect` er versionen af OpenCodes plugin-API, der er skrevet til Effect. Metoderne på konteksten returnerer Effects eller Streams, callbacks returnerer Effects, og `Scope` repræsenterer pluginets levetid.

OpenCode leverer `effect` (inklusive eksporterede `effect/*`-understier) og `@opencode/plugin` ved kørsel, når plugins
og deres `node_modules`-afhængigheder indlæses. Installér dem som peer-/dev-afhængigheder til lokal typecheck og test
i stedet for at bundle dem ind i dit plugin.

```sh
bun add --peer @opencode/plugin effect@4.0.1
```

Eksportér et Effect-plugin fra `.opencode/plugins/` for at indlæse det automatisk.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Publicerede pakker og pluginmapper uden for `.opencode/plugins/` bruger samme `plugins`-konfiguration som andre server-
plugins.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Se [Konfigurer plugins](/plugins) for aktivering, opslag af pakker og konfigurationsprioritet.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Livscyklus

`effect` kører, når pluginet indlæses. Dets scope lukkes, når pluginet genindlæses eller afindlæses, så registreringer, fibers knyttet til scopet og finalizers frigives sammen.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Brug scoped fibers til baggrundsarbejde. Plugin-scopet afbryder fiberen under oprydningen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Kontekst

Konteksten giver adgang til Effect-klienten for den tilsluttede OpenCode-server og til transforms, hooks, lagring, genindlæsning og indstillinger, der kun er tilgængelige for plugins. Konteksten giver ikke adgang til OpenCodes private Core-tjenester.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

Plugindefinitionen og den komplette kontekst er erklæret sådan:

## Transforms

Transforms redigerer tilstand synkront via en editor. OpenCode anvender transforms i registreringsrækkefølge inden for hvert domæne. Kilderne tilføjer først udbydere og uforanderlige modeldefinitioner; derefter redigerer modeltransforms de modeller, der kan vælges hos de aktive udbydere. Når du bruger registreringen med yield, bliver den i pluginets scope.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

En modeltransform kan håndhæve en politik for alle de modeller, der kan vælges hos aktive udbydere.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Kald `reload`, når ekstern tilstand, som en transform bruger, ændres. Her returnerer `loadFromSource()`
`{ info: Provider.Info, models: readonly Model.Info[] }`-poster; udbyder-genindlæsninger invaliderer også hele modelresultatet.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agent

Læs alle agenter, eller hent én efter ID. Klientsvar indeholder den fundne location og skemadata.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transformér eller genindlæs agenter.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts

  remove(id: string): void

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>

```

### Udbydere

Læs tilgængelige udbydere, eller inspicér én udbyders metadata efter ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Udbyder-transforms redigerer udbyderindstillinger og kildedefinitioner. Editorlæsninger omfatter inaktive udbydere og eksponerer
uforanderlige definitioner; `models.update` redigerer en ejet kopi af en kildemodel.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-5-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Erstat en kildefortegnelse med `models.set`, og genindlæs derefter, når dens fangede definitioner ændres.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

For kontospecifik søgning skal du sende den forbindelse, der bruges til at indlæse fortegnelsen, som `sourceConnection`. OpenCode udelukker
den udbyder, mens en anden forbindelse er valgt, indtil dit plugin publicerer sin opdaterede fortegnelse.

{/* prettier-ignore */}
```ts
const connection = yield* ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield* loadInventory(connection)
yield* ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

Schemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

### Modeller

Læs tilgængelige modeller og standardvalget.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Model-transforms redigerer hele kandidatsamlingen for aktive udbydere. Deaktiverede kandidater forbliver redigerbare, indtil alle
transforms er færdige; `update` kan kun tilføje en model under en tilgængelig udbyder.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-5-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Callbacks redigerer de rå modelindstillinger, der afviger fra standarden. Udbyderens standardværdier flettes ind én gang, når OpenCode gemmer resultatet, som genbruges ved læsninger uden ændringer. `editor.provider` læser uforanderlige kildedefinitioner, også inaktive skabeloner, i stedet for resultatet af modeltransforms.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-5-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).


### Kommandoer

Læs kommandoer, der er tilgængelige på den aktuelle location.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Kommandoens transform kan i øjeblikket kun tilføje kommandoer. Funktionen, der udfører kommandoen, modtager sessionen, de vedhæftede dele af prompten og leveringsmåden.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schemas: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Integrationer

Hent integrationerne, og slå de aktive legitimationsoplysninger op, hvis de findes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Forbind med en nøgle, eller styr et OAuth-forsøg gennem det tilsluttede API.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transformér integrationer og autentificeringsmetoder. OAuth-metodecallbacks er Effects og kan erhverve scoped-
ressourcer.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Schemas: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

### MCP

Vis MCP-servere og deres aktuelle forbindelsestilstand.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Plugins administrerer kun MCP-servere gennem transforms. Brug `editor.set` til at tilføje eller erstatte en server, `editor.update` til
at ændre dens konfiguration og `editor.remove` til at fjerne den. Inspicér konfigurationen med `editor.list` og `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Sæt `disabled: true` i en transform for at deaktivere en server og afbryde den, eller `disabled: false` for at aktivere den og lade
OpenCode forbinde. OpenCode afstemmer serverlivscyklussen ud fra den transformerede konfiguration.

Kald `reload()`, når ekstern tilstand, som en transform bruger, ændres, for at genanvende transforms og afstemme serverne.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schemas: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts
  remove(name: string): void
```

### Plugins

Vis aktive plugins, plugins med fejl og plugins, OpenCode har fundet på den aktuelle location.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtrér skemaværdierne i en Effect-pipeline, når kun aktive plugins er relevante.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.state.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Schemas: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

```ts
interface PluginApi<E = never> {
  readonly list: PluginListOperation<E>

  readonly plugin: PluginApi<unknown>
```

### Referencer

Læs referencer, der er tilgængelige på den aktuelle location.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Tilføj eller fjern lokale referencer og Git-referencer, og genindlæs derefter, når ekstern tilstand ændres. `get(name)` returnerer den aktuelt konfigurerede
kilde eller `undefined`, når navnet mangler.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
```

### Værktøjer

Registrér typede værktøjer med Effect `Schema`. Executoren modtager afkodet input og returnerer et Effect med typet
output, visningsindhold eller metadata.

Editoren understøtter `add`, `update` og `remove`. Transformens callback er synkron: Den må ikke returnere et Effect eller Promise. Indlæs eksterne data før registrering eller genindlæsning. OpenCode anvender de aktive transforms igen i registreringsrækkefølge på en ny editor; en senere gyldig registrering med samme endelige værktøjsnavn tilsidesætter en tidligere.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Kald `yield* ctx.tool.reload()` efter ændring af kildedata, som callbacket har fanget. Genindlæsning genafspiller aktive transforms
uden at ændre deres rækkefølge; den kører ikke plugin-Effectet igen.

Effect-værktøjer accepterer samme [freeform-inputdeklaration](/build/plugins/server#freeform-tool-input) som Promise-værktøjer. Hvis modellen ikke annoncerer det format, beholder værktøjet sit normale objektinput.

Værktøjer har et `id`, der indeholder deres effektive navn, og `get()` returnerer `undefined`, når ID'et ikke findes. Brug
`update` og `remove` med det effektive værktøjsnavn, inklusive dets navnerum (`acme_greeting` ovenfor). Punktummer i
navnerum erstattes med `_`. I værktøjsnavne erstattes alle tegn undtagen bogstaver, cifre, `_` og `-` med `_`.
Manglende navne ignoreres; oprettelse af et værktøj kræver
`add` med en komplet definition. Opdateringer bevarer navn og navnerum. Tildel nye skemaer eller indstillinger for at erstatte
dem i stedet for at mutere indlejrede værdier. Ugyldige opdateringer logges og lader den tidligere definition være intakt.

{/* prettier-ignore */}
```ts
yield* ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Opdateringer og fjernelser genafspilles i rækkefølge sammen med tilføjelser, også efter MCP-katalogopdateringer.

`transform` returnerer en scoped registrering. Kør `yield* registration.dispose` for at fjerne dens transform og genopbygge
ud fra de resterende transforms, så en tidligere definition, den tilsidesatte, igen vises. Afvikling er idempotent, og lukning
af plugin-scopet afvikler også dets registreringer.

Hver modelanmodning fastholder et snapshot af værktøjerne. Genindlæsning og afvikling påvirker fremtidige snapshots, ikke definitioner og kørselsfunktioner, der er fastholdt af en eksisterende anmodning. Kørselsfunktioner med en reference til plugindata, der kan ændres, ser stadig ændringer i dataene; bind værdien i transformen, hvis den skal forblive knyttet til definitionen.

Schemas: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Hooks opsnapper live-operationer. Flere plugins kan registrere samme hook; OpenCode kører dem i pluginrækkefølge, så
senere hooks ser tidligere ændringer. Registreringer forbliver aktive i plugin-scopet.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sessions

Redigér de samlede systeminstruktioner, beskeder eller værktøjer, lige før anmodningen sendes til modellen. `context` kører i agentløkken; `compaction`, `generate` og `title` kører for de pågældende hjælpeanmodninger. Med `compaction` og `title` kan du angive et `result` og springe modelkaldet over.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Beskeder i `context`-, `compaction`- og `generate`-hooks bærer deres gemte beskeds `metadata`, skrivebeskyttet
(f.eks. hvad en `prompt`-hook satte). Det sendes ikke til modellen.

Den `system`-del, der indeholder OpenCodes instruktioner, viser også hver kilde i `metadata.experimental.instructions` som
`{ key, text }`, f.eks. `core/date` eller `core/environment`, så en hook kan skelne kilderne. Listen er en kopi:
redigering af delens `text` opdaterer den ikke. Dette er eksperimentelt og kan ændre sig.

Rediger model-indstillinger for anmodningen, og afgræns eventuelt hooken til én udbyder. Hændelsen bærer samme `kind` som
HTTP-hookene nedenfor.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Rediger native udbyderanmodninger eller -svar. Deres bodies er one-shot-streams; klon eller erstat en body, før du læser
den. Begge hooks kører for hver anmodning, en session udsteder; `event.kind` er `"primary"`, `"compaction"`, `"title"` eller
`"generate"` afhængigt af, hvilket flow der udstedte den.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Udbydere, der streamer over en WebSocket, genbruger én forbindelse pr. session, så HTTP-hookene ser aldrig den trafik. Den
eksperimentelle `experimental.ws.handshake`-hook kører én gang pr. modelkald, før forbindelsen vælges, og eksponerer
forbindelsens `url` og `headers`; ændring af en af dem genåbner socketten. HTTP-hooks kører stadig for enhver anmodning, som en WebSocket-
rute falder tilbage til.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` og `experimental.ws.receive` giver adgang til selve WebSocket-frames: `send` kører, efter at udbyderens driver har oprettet en udgående frame, og `receive` kører for hver indgående frame, før driveren læser den. Indholdet af `frame`, når hooket returnerer, er det, der sendes over forbindelsen eller når frem til driveren. OpenCode validerer det ikke.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Tilsidesæt genforsøgsbeslutningen for en udbyderfejl, eller erstat dens forsinkelse i millisekunder. Hooken kører, efter at OpenCode
klassificerer fejlen og foreslår sin politik, men før et genforsøg planlægges. Den eksponerer ikke, hvordan OpenCode
internt udfører det næste forsøg.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

Den indledende `decision` er OpenCodes politik, så hooks kan gøre en normalt terminal udbyderfejl genforsøgsbar eller nedlægge veto mod et
foreslået genforsøg. Flere hooks kører i registreringsrækkefølge, og senere hooks ser den aktuelle beslutning. Det indbyggede maksimale
forsøgsantal er stadig en hård grænse. `attempt` er det fysiske forsøg, der foreslås; den indledende anmodning er forsøg `1`,
så det første genforsøg er forsøg `2`. Ugyldige forsinkelser (`NaN`, uendelighed eller negative værdier) falder tilbage til den beregnede forsinkelse.
Gendannelse ved kontekstoverløb er fortsat separat, fordi den komprimerer samtalen i stedet for at prøve samme anmodning igen.

```ts
  readonly "experimental.ws.receive": SessionWebSocketReceive
  readonly retry: SessionRetry
}

type RetryDecision = { retry: false } | { retry: true; delay: number }

interface SessionRetry {
  readonly sessionID: string
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly error: { type: string; message: string; status?: number }
  readonly attempt: number
  decision: RetryDecision
}

interface SessionHookDomain {
  readonly hook: ModelHooks<SessionHooks>
}
```

### Shell

Rediger shell-kommandoer, arbejdsmapper, timeouts, eksekverbare filer eller miljøvariabler før kørsel.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const shell = ctx.shell
    yield* shell.hook("create.before", (event) =>
      Effect.sync(() => {
        if (event.command === "npm") event.command = "bun"
        event.timeout = Math.min(event.timeout, 60_000)
        event.env.COMPANY_ENV = "development"
      }),
    )
  }),
```

### Tools

Before-hooks kan erstatte input eller fejle med `Tool.Error`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

After-hooks kan inspicere eller erstatte vellykkede resultater og fejl.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

#### Reference

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

De fælles registreringstyper viser, hvilke operationer der kræver plugin-scopet.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publicering

Et plugin i en pakke bruger samme standardeksport som et lokalt Effect-plugin. Eksportér Effect-implementeringen fra pakkens hovedindgangspunkt, og angiv `effect` som `peerDependency`. Under `devDependencies` skal du fastlåse den version, `@opencode/plugin` bruger, så der kun installeres én kopi under udvikling.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.1"
  },
  "devDependencies": {
    "effect": "4.0.1"
  }
}
```

OpenCode omdirigerer imports af `effect`, eksporterede `effect/*`-understier og `@opencode/plugin` (inklusive imports fra
afhængigheder i pluginets `node_modules`) til værtens runtimeinstanser, så fibers, loggere og `Schema`-parsere
deler én runtimekopi.

- Bundle ikke `effect` ind i det publicerede pluginartefakt. Hvis du bygger med en bundler, skal du markere `effect` og `effect/*`
  som external.
- Plugins og deres `node_modules`-afhængigheder kører altid mod værtens OpenCode-releases `effect`-instans.
  Brug `effect`-API'er og modulstier, der er kompatible med den OpenCode-release, du målretter; afhængigheder bygget på en anden
  `effect`-major (som Effect 3) modtager også værtens `effect` og understøttes ikke.
- Kun offentlige `effect`-understier leveres. Et plugin, der importerer et af Effects private `internal`-moduler, kan ikke
  indlæses og får en fejl, der navngiver stien.
- Den kompilerede OpenCode-binær omfatter ikke Scalar- og Swagger UI-assets, som Effects HTTP API-dokumentationssider bruger;
  hvis et plugin viser de sider, vises i stedet en meddelelse.

Pakkens entrypoint eksporterer `Plugin.define` med en `effect`-funktion.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Brug versioner, der er kompatible med den OpenCode-release, du målretter, og test den installerede pakke i stedet for kun en
workspace-linket kopi.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
