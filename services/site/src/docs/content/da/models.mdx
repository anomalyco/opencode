Vælg en model til den aktuelle session med `/models`:

```text
/models
```

OpenCode viser modeller fra [models.dev](https://models.dev), udbyderintegrationer og din konfiguration. Modelvælgeren
viser kun aktiverede modeller fra udbydere, der er tilgængelige i det aktuelle projekt. Se, hvordan du tilslutter udbydere, under
[Udbydere](/providers).

## Vælg

Vælg en model i `/models` i stedet for at gætte udbyderens ID eller modellens ID. Valget gælder den aktuelle session
og ændrer ikke din konfiguration.

```text
anthropic/claude-sonnet-5-5
```

Tilgængeligheden er projektspecifik:

- Modellen skal være aktiveret.
- Dens udbyder skal være tilgængelig i det aktuelle projekt.
- Legitimationsoplysninger og konfiguration fra et andet projekt overføres ikke automatisk.

## Kørsler

Brug `--model` til at vælge en model for én kommandolinjekørsel uden at ændre den konfigurerede standard:

```bash
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Agenter og kommandoer kan også vælge deres egen model. Se [Agenter](/agents) og [Kommandoer](/commands).

## Standardmodel

Angiv `model` i `opencode.json` eller `opencode.jsonc` for at vælge standardmodellen til nye opgaver:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

Den konfigurerede model bliver standard i kataloget, hvis den er aktiveret, og udbyderen er tilgængelig. Ellers vælger OpenCode
den nyeste af de modeller, der både er understøttet og tilgængelige.

- Har du allerede valgt en model til en session, har den forrang for standardmodellen.
- Du kan skifte model i en session uden at ændre konfigurationsfilen.
- `model` på topniveau gemmer i øjeblikket kun standardudbyderen og standardmodellen, ikke en variant.

Se [Konfiguration](/config) for placeringer og prioritet.

## Gratis modeller

Sæt `OPENCODE_DISABLE_FREE_MODELS=1` (eller `true`) på serverprocessen for at skjule [gratis OpenCode-modeller](/console/models#free-models):

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
```

For den delte baggrundsserver:

```bash
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

En gratis model er en `opencode`- eller `opencode-go`-model uden inputpris. De modeller fjernes fra kataloget og kan ikke længere bruges som standard.
Hvis du vælger en af dem eksplicit, får du fejlen `Model unavailable`. Hvis du ikke er logget ind, vises `opencode`-udbyderen ikke. For at få adgang til de betalte modeller igen skal du tilknytte
en OpenCode Console-konto eller angive `OPENCODE_API_KEY`.

Hvis du vil blokere gratis modeller for alle i en organisation, skal du i stedet bruge en politik. Se [Enterprise](/enterprise#block-free-models).

## Varianter

Varianter er navngivne indstillinger for én model, ofte brugt til ræsonneringsniveau eller tokenbudgetter. Tilføj `#variant`, når du vælger
en til en kørsel, session, agent eller kommando:

```bash
opencode run --model openai/gpt-6.1-sol#high "Review this migration plan"
```

Variantnavne kommer fra den valgte models aktuelle katalogmetadata. Navne som `low`, `high` og `max` er ikke
tilgængelige for alle modeller, og du får en fejl, hvis OpenCode ikke kan finde modellen med den angivne variant.

Definér nye varianter, eller erstat katalogvarianter med samme ID, i modellens `variants`-array:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Hver variant kan indeholde `settings`, `headers` og `body`. Variantens værdier anvendes efter udbyderens og modellens.

Hvis du vil erstatte en models ræsonneringsvarianter, skal du angive modellens ræsonneringsindstillinger i `capabilities.reasoning` i v2-formatet fra
[models.dev](https://models.dev). OpenCode bruger dem til at bygge varianterne til modellens pakke:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "capabilities": {
            "reasoning": {
              "supported": true,
              "effort": ["low", "medium", "high"],
            },
          },
        },
      },
    },
  },
}
```

| Felt        | Formål                                                                    |
| ----------- | -------------------------------------------------------------------------- |
| `supported` | Om modellen kan ræsonnere. `false` eller `true` uden ræsonneringsindstillinger tilføjer ingen varianter. |
| `toggle`    | Tilføjer en `none`-variant, der slår ræsonnering fra.                     |
| `effort`    | Ræsonneringsniveauer, der tilbydes. `default` beholder udbyderens standard og tilføjer ingen variant. |
| `budget`    | Valgfri nedre og øvre grænse for ræsonneringstokens, `min` og `max`. Ignoreres, når `effort` er angivet. |

OpenCode anvender varianterne fra `variants` efter dem, der er bygget ud fra `capabilities.reasoning`.

## Indstillinger

Udbyder- og modelposter kan tilpasse anmodninger med `settings`, `headers` og `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-6.1-sol": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Felt       | Formål                                                             |
| ---------- | ------------------------------------------------------------------ |
| `settings` | Indstillinger for udbyderpakken som `baseURL` eller `reasoningEffort`. |
| `headers`  | Ekstra HTTP-headere til anmodningen.                               |
| `body`     | Udbyderspecifikke felter i anmodningens indhold.                    |

OpenCode anvender udbyderens værdier først, modellens værdier derefter og den valgte variant sidst.

- Indlejrede `settings`- og `body`-objekter flettes.
- Senere arrays og skalarværdier erstatter tidligere værdier.
- Headernavne matches uden forskel på store og små bogstaver.
- Indstillinger er udbyderspecifikke og kan ignoreres eller afvises af en anden udbyderpakke.

## Aliaser

Brug `modelID` til at give en API-model et katalog-ID, der er nemmere at bruge:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Her kan du vælge `openai/coding-default`, mens `gpt-6.1-sol` sendes til udbyderen. Hvis modellen ikke allerede
findes i kataloget, gør OpenCode sig følgende antagelser:

- JSON-værktøjsunderstøttelse, tekst- og billedinput og tekstoutput. Intet freeform-værktøjsinput, medmindre `capabilities.freeform` angiver formatet.
- En kontekstgrænse på 200.000 tokens og en outputgrænse på 32.000 tokens.
- En uspecificeret inputgrænse.

OpenCode genkender `text`, `regex` og `lark`. Andre formatnavne fra models.dev ignoreres uden at droppe modellen eller dens værktøjer. Hvis en proxy foran en katalogmodel afviser freeform-værktøjer, skal du sætte `capabilities.freeform` til `[]` på den model.

Disse værdier er antagelser, ikke egenskaber, OpenCode selv har registreret. Angiv de korrekte værdier for `capabilities` og
`limit`, hvis du kender dem. De erstatter de værdier, OpenCode ellers antager. Automatisk komprimering bruger `limit.input`,
dog højst `limit.context`. Se [Kontekstvindue](/compaction#window). Tilføj `disabled: true` for at skjule en model fra det tilgængelige katalog:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Ræsonnering

For en OpenAI-kompatibel model, der streamer ræsonnering i et brugerdefineret felt i assistentbeskeden, skal du angive
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode genkender `reasoning`, `reasoning_content` og `reasoning_text` og accepterer også en anden udbyderspecifik
streng. OpenCode læser den streamede ræsonnering fra feltet og gendanner feltet, når tidligere assistentbeskeder sendes tilbage til
modellen. Se [Kompatibilitet](#compatibility) for det relaterede `requireReasoning`-felt.

## Prompt-caching

OpenCode indsætter automatisk markører til promptcaching på ruter, der kræver dem, f.eks. hos Anthropic. Når
Claude-modeller leveres gennem en OpenAI-kompatibel proxy som LiteLLM, kan OpenCode ikke se, at de har brug for
Anthropics `cache_control`-markører. Angiv `compatibility.cacheFormat` for disse Claude-modeller:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1-sol": {},
      },
    },
  },
}
```

OpenCode markerer derefter den seneste værktøjsdefinition, systemprompten og den nyeste besked med
`cache_control: { "type": "ephemeral" }`, så endpointets standardlevetid på fem minutter bruges. Brug `"alibaba"`
til Alibaba Model Studio-modeller, som accepterer samme markører, men ignorerer dem på værktøjsdefinitioner. Angiv
`compatibility.cacheFormat` på udbyderen i stedet, når alle modeller, den leverer, accepterer samme format. Se
[Kompatibilitet](#compatibility) for de øvrige felter.

### Cachelevetid

OpenCode sender ikke en cachelevetid som standard, så hver udbyder bruger sin egen standard, f.eks. fem minutter på
Anthropic. Angiv `settings.cache.ttl` på en udbyder eller model for at anmode om en anden. En modelindstilling tilsidesætter
udbyderindstillingen.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } },
      },
    },
  },
}
```

`ttl` tager et tal og en enhed: `ms`, `s`, `m`, `h` eller `d`, f.eks. `"5m"`, `"1h"` eller `"24h"`. OpenCode sender den som
angivet, så brug en værdi, som udbyderen accepterer:

| API | Hvor levetiden angives |
| --- | --- |
| Anthropic Messages | `cache_control.ttl` på hver cache-markør. Anthropic accepterer `"5m"` og `"1h"`. |
| Bedrock Converse | `ttl` på hver `cachePoint`. Ældre Claude-modeller, der kun cacher i fem minutter, ignorerer `"1h"`. |
| OpenAI Chat and Responses | `"24h"` går til `prompt_cache_retention`; andre værdier går til `prompt_cache_options.ttl`. |

Udbydere, der cacher automatisk uden markører, f.eks. Gemini, ignorerer værdien. Det koster normalt mere at skrive til cachen med en længere
levetid: Hos Anthropic koster en cacheskrivning 2× inputprisen ved en levetid på en time og 1.25× ved fem minutter.

[Opvarmning](/warming) kan bruge levetiden til at time sine anmodninger med `interval: "auto"`.

## Kompatibilitet

`compatibility` beskriver særlige forhold ved anmodninger og svar i modellens API, f.eks. hvilket felt der indeholder
ræsonnering, eller om endpointet accepterer `prompt_cache_key`. Hver model bruger ét API, og et felt har kun
virkning, hvis det læses af det pågældende API. Andre felter ignoreres.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "compatibility": { "streamUsage": false },
      "models": {
        "reasoner": {
          "compatibility": { "reasoningField": "reasoning_content", "maxTokensField": "max_tokens" },
        },
      },
    },
  },
}
```

Udbyderens `compatibility` gælder for hver model hos den udbyder. En models egen `compatibility` tilsidesætter den felt for
felt: OpenCode starter med de værdier, [models.dev](https://models.dev) publicerer for modellens API (`reasoningField`,
`maxTokensField` og `mediaInput` samt `supportsEffortUpdates` og `supportsSystemUpdates`, når models.dev markerer
API'et som kompatibelt med disse felter), og anvender derefter modellens konfiguration. For felter uden en angivet værdi bruger OpenCode udbyderpakkens indbyggede
standard eller automatiske registrering. `supportsThinkingBlockBinding`, `supportsEffortUpdates` og `supportsSystemUpdates` er
kun for modeller.

| Felt | Hvad det gør | Læses af | Værdier og standard |
| --- | --- | --- | --- |
| `reasoningField` | Det felt i assistentbeskeden, der indeholder ræsonnering. OpenCode tjekker først dette felt, når det læser streamet ræsonnering, og bruger det, når tidligere ræsonnering sendes tilbage. | OpenAI Chat | Ethvert feltnavn undtagen `role`, `content`, `refusal` eller `tool_calls`. Hvis feltet ikke er angivet, bruges feltet fra streamen, hvis der er et, ellers `reasoning_content`. |
| `requireReasoning` | Sender ræsonneringsfeltet for hver tidligere assistentbesked, også som tom streng, hvis der ikke var nogen ræsonnering. | OpenAI Chat | `true` eller `false`. Standard er `true`, når `reasoningField` er angivet, eller modellen er DeepSeek, ellers `false`. |
| `maxTokensField` | Det felt i anmodningen, der angiver grænsen for outputtokens. | OpenAI Chat | `max_completion_tokens` eller `max_tokens`. Uden en angivet værdi bruger OpenCode `max_tokens` til udbydere, der kræver det, f.eks. DeepSeek, Moonshot, Together AI, Z.AI og Cerebras, ellers `max_completion_tokens`. |
| `requireFinishReason` | Behandler en stream, der slutter uden `finish_reason`, som en fejl om ufuldstændigt svar. `false` accepterer den som afsluttet. | OpenAI Chat | `true` eller `false`. Standard er `true`. |
| `requireAssistantAfterTool` | Indsætter en assistentbesked mellem et værktøjsresultat og næste brugerbesked, hvis endpointet ellers afviser rækkefølgen. | OpenAI Chat | `true` eller `false`. Standard er `true` for model-ID'er i Mistral-familien, ellers `false`. |
| `supportsPromptCacheKey` | Om endpointet accepterer body-feltet `prompt_cache_key`. | OpenAI Chat, OpenAI Responses, Mistral | `true` eller `false`. OpenAI Chat sender kun nøglen, når den er `true`, hvilket nogle udbyderpakker sætter som standard. Andre API'er sender den, medmindre den er `false`. |
| `streamUsage` | Anmoder om tokenforbrug i streamen med `stream_options.include_usage`. | OpenAI Chat | `true` eller `false`. Standard er `true`. |
| `cacheFormat` | Syntaks for prompt-cache-markører, som endpointet accepterer. Tilsidesætter udbyderens automatiske breakpointplacering. `alibaba` springer værktøjsdefinitioner over. | Hvert API med prompt-cache-markører, inklusive OpenAI Chat, Anthropic Messages og Bedrock Converse | `anthropic` eller `alibaba`. Uindstillet bruges udbyderens standard. Se [Prompt-caching](#prompt-caching). |
| `supportsThinkingBlockBinding` | Beder API'et om at droppe thinking-blokke, hvis tidligere kontekst er ændret, i stedet for at afvise anmodningen. | Anthropic Messages, Bedrock Converse | `true` eller `false`. Uindstillet registreres Claude 5.1 og nyere. |
| `supportsEffortUpdates` | Sender ændringer i ræsonneringsniveauet som opdateringer pr. besked, så prompt-cachen bevares. Ellers ændres niveauet for hele anmodningen. | Anthropic Messages, OpenAI Responses | `true` eller `false`. Uden en værdi genkender OpenCode Claude Opus 5, Claude 5.1 og nyere samt GPT-6 og nyere. |
| `supportsSystemUpdates` | Sender systembeskeder, der tilføjes midt i samtalen, som egentlige systembeskeder. Ellers føjes de som tekst til brugerens næste besked. | Anthropic Messages | `true` eller `false`. Uden en angivet værdi genkender OpenCode Claude Opus 4.8 samt Claude 5 og nyere. |
| `mediaInput` | Hvor billeder og andre medier placeres i en beslutningsanmodning. | System One | `assets` (billeder refereret fra state), `state` (inline i state) eller `root` (`images`-, `audio`- og `videos`-lister på topniveau). Uindstillet bruges udbyderens standard. |

## Lokalt

OpenCode finder automatisk modeller fra Ollama, LM Studio og vLLM på deres lokale standardadresser. Du kan også
konfigurere enhver OpenAI-kompatibel server manuelt.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Når Ollama lytter på `http://127.0.0.1:11434`, skal du vælge en fundet model med udbyder-ID'et `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode opdaterer listen i baggrunden og læser oplysninger om kontekst, billedinput og brug af værktøjer fra Ollama.
Modeller, der kun genererer embeddings, udelades.

Hvis du bruger en anden vært eller port, skal du angive Ollamas OpenAI-kompatible URL. OpenCode finder stadig modellerne via Ollamas eget API med samme
stipræfiks:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Udelad `apiKey`, når endpointet ikke kræver bearer-autentificering.
- Deaktivér søgning med `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Når en uautentificeret LM Studio-server kører på `http://127.0.0.1:1234`, skal du vælge en fundet model med `lmstudio`-
udbyder-ID'et:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode opdaterer listen i baggrunden og læser oplysninger om kontekst, billedinput og brug af værktøjer fra LM Studio.
Embedding-modeller udelades.

For en anden host eller port skal du angive den OpenAI-kompatible URL. Modeller findes stadig automatisk:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Udelad `apiKey`, når LM Studio-autentificering er deaktiveret.
- Deaktivér søgning med `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Når vLLM lytter på `http://127.0.0.1:8000`, skal du vælge en fundet model med udbyder-ID'et `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode kontrollerer `/health`, opdaterer `/v1/models` i baggrunden, bruger den rapporterede `max_model_len` som kontekst-
grænse og medtager kun modelkort ejet af `vllm`.

De modeller, OpenCode finder, angiver understøttelse af tekstinput og -output, men ikke af billedinput eller værktøjer. vLLM kan aktivere værktøjskald via serverflag
som `--enable-auto-tool-choice` og `--tool-call-parser`, men de fremgår ikke af modeloplysningerne.

For et andet endpoint eller en autentificeret server skal du angive dens OpenAI-kompatible URL:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Udelad `apiKey`, når autentificering er deaktiveret.
- Deaktivér søgning med `"plugins": ["-opencode.provider.vllm"]`.
- Proxies med stipræfiks understøttes. F.eks. kontrollerer `https://example.com/vllm/v1` `/vllm/health` og finder
  `/vllm/v1/models`.

### OpenAI-kompatible servere

For en anden OpenAI-kompatibel server skal du definere dens udbyderpakke, endpoint og mindst én model:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Angiv serverens faktiske modelnavn, grænser, input- og outputtyper og understøttelse af værktøjer. OpenCode kan ikke kontrollere, om
reserveværdierne for den brugerdefinerede model er korrekte. Hvis endpointet kræver en nøgle, skal du tilføje `apiKey` til `settings` og læse værdien fra en miljøvariabel,
f.eks. med `"apiKey": "{env:LOCAL_API_KEY}"`. Gem ikke hemmeligheder i commits.

## Referencer

Modelvælgere bruger `provider/model` med en valgfri `#variant`:

```text
openai/gpt-6.1-sol
openai/gpt-6.1-sol#high
openrouter/anthropic/claude-sonnet-5.5#high
```

| Del      | Regel                                                      |
| -------- | ---------------------------------------------------------- |
| Udbyder  | Slutter ved det første `/`; må ikke indeholde `/` eller `#`. |
| Model    | Må indeholde yderligere `/`-tegn; må ikke indeholde `#`.   |
| Variant  | Følger efter `#`, når den er til stede.                    |
| Store og små bogstaver | Der skelnes mellem store og små bogstaver i udbyder- og model-ID'er. |

Brug katalog-ID'er i stedet for udbyderens viste navne. `model`-felter på rodniveau, i agenter og i kommandoer accepterer strengformen ovenfor
eller et udvidet objekt:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-5.5",
  },
}
```

Den udvidede form er nyttig til genereret eller programmatisk konfiguration.

## Forbehold

Husk disse regler, når du konfigurerer modeller:

```jsonc
{
  "model": "openai/gpt-6.1-sol"
}
```

- Et objekt til modelvalg bruger `model`. En post i udbyderens katalog bruger `modelID` til det ID, der sendes til udbyderen.
- Selvom modelvalget på topniveau kan indeholde en variant, gemmer V2 den ikke som en del af katalogets standardmodel. Vælg i stedet en variant til en
  session, kørsel, agent eller kommando.
- Modelindstillinger er udbyderspecifikke. En anden udbyderpakke kan ignorere eller afvise dem.
- Katalogdata, legitimationsoplysninger og konfiguration er afgrænset til placeringen. En model, der er tilgængelig i ét projekt, kan være utilgængelig
  i et andet.
- Konfigurationsfiler genindlæses normalt automatisk. En modelanmodning, der allerede er i gang, beholder de indstillinger, den startede
  med.
