OpenCode indeholder et udbyder- og modelkatalog fra [models.dev](https://models.dev). For de fleste udbydere skal du først
forbinde en konto og derefter vælge en model.

## Opsætning

Kør `/connect`, vælg en udbyder, og angiv dens legitimationsoplysninger. Kør derefter `/models` for at vælge en af dens modeller.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) er et valgfrit abonnement på kodningsmodeller, som OpenCode-teamet har testet. Tegn abonnement i
[Console](https://opencode.ai/console), kopiér din API-nøgle, og brug den til at tilslutte **OpenCode Go**.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

Se [Go-guiden](/console/go) for forbrugsgrænser, endpoints og oplysninger om privatliv.

## ChatGPT

Brug et ChatGPT Plus- eller Pro-abonnement i stedet for en OpenAI-API-nøgle. Forbind **OpenAI**, og vælg derefter **Sign in with ChatGPT**
eller en af de ældre **Codex**-loginmetoder. Forbruget tæller mod dit abonnement, så disse modeller viser ingen omkostning.

```text
/connect
/models
```

### Kontekstgrænser

Som standard begrænser OpenCode kontekstvinduet for disse logins til under hver models reelle grænse. Grænserne matcher
standarderne i Codex, så dit forbrug stiger omtrent lige så hurtigt som i andre OpenAI-produkter.

| Model                 | Inputgrænse |
| --------------------- | ----------- |
| GPT-6.1 Sol og nyere  | 500.000     |
| Ældre modeller        | 272.000     |

Hvis du vil slå grænsen fra, skal du deaktivere det plugin, der sætter grænsen, i din konfiguration. Præfikset `-` slår et indbygget plugin fra;
alle andre plugins forbliver aktiveret.

```jsonc title="opencode.jsonc"
{
  "plugins": ["-opencode.provider.openai-context-caps"],
}
```

## Brugerdefineret

Tilføj en udbyder, når dens API ikke allerede findes i kataloget. Dette OpenAI-kompatible eksempel definerer legitimationsoplysningerne,
runtime-pakken, endpointet og den første model samlet.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

`providers`-objektet har udbyder-ID'et som nøgle, og det bruges i modelreferencer som `acme/qwen3-coder`.

| Felt | Formål |
| --- | --- |
| `name` | Vist navn. |
| `env` | Ordnede miljøvariabelnavne, der kan levere legitimationsoplysningerne. |
| `package` | Runtime-udbyderpakke. |
| `canonical` | Indbygget udbyder-ID, hvis katalogstandarder denne udbyder arver. |
| `compatibility` | API-særheder, som deles af hver model hos denne udbyder. Se [Kompatibilitet](/models#compatibility). |
| `settings` | Typede OpenCode-kontroller og JSON-indstillinger, der sendes til runtime-pakken. |
| `headers` | HTTP-headere med strengværdier, der føjes til anmodninger. |
| `body` | JSON-felter, der flettes ind i request-bodies. |
| `models` | Modeller, der skal tilføjes eller tilsidesættes, med OpenCode-model-ID som nøgle. |

## Endpoint

Tilsidesæt `settings.baseURL` for at sende en katalogudbyder gennem en proxy eller et kompatibelt endpoint. Dens eksisterende pakke,
modeller og forbindelse gælder stadig.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` er pakkespecifik. Et felt har kun effekt, når den valgte pakke understøtter det.

## Anmodninger

Brug `headers` til ekstra HTTP-headere og `body` til JSON-felter, der skal flettes ind i hver request-body.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

Begge felter kan også angives på en model eller variant, når kun en del af en udbyders trafik har brug for tilsidesættelsen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Timeouts

HTTP-anmodninger venter op til fem minutter på response-headere og op til femten minutter mellem streamede response-chunks.
Sæt udbyderens `settings.headerTimeout` eller `settings.chunkTimeout` til et antal millisekunder for at ændre en grænse
eller til `false` for at deaktivere den. `settings.timeout` begrænser desuden hele anmodningen fra afsendelse til svaret
er færdigt; den har ingen standard. Disse konfigurationsindstillinger gælder for hele udbyderen, ikke pr. model eller variant. På en
WebSocket-transport begrænser `chunkTimeout` i stedet afstanden mellem frames og er som standard tredive minutter.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

En anmodning, der overskrider en af grænserne, mislykkes med en transportfejl. Ved en timeout prøver OpenCode igen op til
tre gange, før det giver op.

## Kodning af anmodninger

`settings.encoding` komprimerer HTTP-request-bodies med `"zstd"` eller `"gzip"` eller sender almindelig JSON med `"none"`. Angiv den
på en udbyder, model eller variant; den mest specifikke værdi vinder. Aktivér kun en encoding, som endpointet afkoder: de fleste
udbydere og gateways afviser komprimerede bodies. OpenAI bruger som standard `"zstd"`, når du er logget ind med ChatGPT, og der ikke er konfigureret en brugerdefineret
`baseURL`; API-nøgler sender almindelig JSON. WebSocket-beskeder påvirkes ikke.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## Pakker

Feltet `package` vælger det runtime, der kommunikerer med en udbyder. Brug det kompatible runtime til API'er, der
implementerer OpenAIs requestformat.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

Native pakkemuligheder omfatter:

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/messages`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

Du kan også bruge en npm-pakke som `@acme/opencode-provider` eller en absolut `file://`-URL til en lokal pakke.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## Modeller

Tilføj eller tilsidesæt modeller i en udbyders `models`-map. Nøglen i mappet er det model-ID, som OpenCode bruger; `modelID` ændrer
det ID, der sendes til udbyderen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Coding",
        },
      },
    },
  },
}
```

| Felt | Formål |
| --- | --- |
| `modelID` | Model- eller deployment-ID, der sendes til udbyderen. |
| `name` | Vist navn. |
| `family` | Modelfamilie, der bruges til at gruppere relaterede modeller. |
| `type` | Hvad modellen producerer: `chat`, `decision`, `image`, `video`, `realtime`, `embedding` eller `transcription`. Standard er `chat`; kun chatmodeller tilbydes til sessioner. Realtidsmodeller, der svarer med tale, tilbydes til stemme, og med `disabled: true` gør de ikke. |
| `releaseDate` | Udgivelsesdato som `YYYY-MM-DD` eller `YYYY-MM`. |
| `package` | Runtime-tilsidesættelse for denne model. En transskriptionsmodel angiver sin transskriptionsprotokol, f.eks. `@opencode/ai/protocols/openai-transcription`; en realtidsmodel tager ingen, da stemmesessioner starter gennem dens API. |
| `settings` | OpenCode-kontroller på modelniveau og pakkespecifikke JSON-indstillinger. |
| `headers` | Ekstra request-headere med strengværdier. |
| `body` | Ekstra JSON-request-body-felter. |
| `capabilities` | Værktøjsunderstøttelse, accepterede input- og outputmedietyper, temperaturunderstøttelse og ræsonneringskontroller. |
| `compatibility` | API-særheder for denne model, som tilsidesætter udbyderens. Se [Kompatibilitet](/models#compatibility). |
| `variants` | Navngivne varianter med deres egne `settings`, `headers` og `body`. |
| `cost` | Priser for input, output og eventuelt cache pr. million tokens. |
| `limit` | Grænser for kontekst-, input- og output-tokens. |
| `disabled` | Fjerner modellen fra valget, når den er `true`. |

Se [Modeller](/models) for valg, standarder, kapaciteter, grænser, omkostninger og varianter.

## Azure

Azures standardkatalog-endpoint kræver et ressourcenavn ud over sine legitimationsoplysninger. Angiv `settings.resourceName`
én gang, og forbind derefter en API-nøgle, eller brug Microsoft Entra ID-sessionen fra Azure CLI som beskrevet i
[Udbyderkonti](/cli/providers).

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

Find **Resource name** i [Azure portal](https://portal.azure.com/) eller
[Microsoft Foundry](https://ai.azure.com/). Det er også den første del af endpoints som
`https://my-models.openai.azure.com/` og `https://my-models.services.ai.azure.com/`.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Hvis du vil bruge Entra ID, skal du installere [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli), logge ind og derefter
vælge **Microsoft Entra ID (Azure CLI)**, når du forbinder Azure.

```bash
az login
```

Angiv ressourcenavnet ved forbindelse, hvis det ikke allerede leveres af konfigurationen eller miljøet. Et ressourcenavn,
der er gemt med en forbindelse, har forrang over konfigurationen; forbind igen for at ændre det.

Azure CLI-forbindelser bruger den konto, der er valgt i Azure CLI. For en ressource i en anden tenant eller subscription
skal du vælge begge eksplicit.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

I stedet for konfiguration leverer `AZURE_RESOURCE_NAME` ressourcenavnet til OpenCode-serveren. Den ældre
`AZURE_COGNITIVE_SERVICES_RESOURCE_NAME`-variabel virker også.

### Deployments

Azure leverer kun en model gennem en deployment, så OpenCode viser dine ressourcers deployments og viser dem
i stedet for hele Azure-kataloget. Listen indlæses i baggrunden efter start, efter forbindelse og efter
kontoskift. Hvis du vil hente en deployment, der er tilføjet senere, skal du genstarte OpenCode eller forbinde igen.

- Indtil listen er indlæst for en forbindelse, eller hvis den mislykkes, forbliver hele kataloget tilgængeligt.
- En mislykket genindlæsning for samme forbindelse beholder sin seneste komplette fortegnelse.
- Kontoskift viser aldrig den forrige kontos fortegnelse; den nye konto starter fra hele kataloget.
- Deployments arver grænser, omkostninger og kapaciteter fra deres katalogmodeller.

Deploymentnavne er deres model-ID'er med små bogstaver, fordi Azure ignorerer casing i navne, f.eks.
`azure/gpt-production`. En deployment opkaldt efter sin model, som `gpt-6-luna`, beholder katalog-ID'et. Disse ID'er forbliver
stabile, når andre deployments tilføjes eller fjernes.

OpenCode matcher en deployment til kataloget efter den model, den deployer, eller efter dens navn, når Azure staver modellen
anderledes, som med `gpt-4` for GPT-4 Turbo. En deployment opkaldt efter en anden model, f.eks. `gpt-6.1-sol`, der deployer
`gpt-6-luna`, viser den models navn, grænser og omkostninger.

Med Azure CLI viser OpenCode deployments gennem Azure-administrations-API'et, som kræver læseadgang til
ressourcen. Hvis det mislykkes, og altid med en API-nøgle, bruger den ressourcens ældre deploymentfortegnelse. Søgningen læser
hver side, før listen publiceres. En brugerdefineret `settings.baseURL` beholder kataloget.

Konfigurer en deployment eksplicit, når dens model ikke findes i kataloget, f.eks. en finjusteret model, eller for selv at knytte et model-ID
til en deployment. OpenCode logger en advarsel, der navngiver sådanne deployments. Eksplicit konfigurerede modeller bevares
altid.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-6-luna": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

Din identitet skal have en af disse roller:

- **Cognitive Services OpenAI User** til Azure OpenAI-modeller.
- **Cognitive Services User** til andre Foundry-modeller.

Hvis en anmodning bruger et token fra den forkerte tenant, skal du logge ind igen med den krævede tenant.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock bruger AWS' standardlegitimationskæde. En navngivet AWS-profil er den enkleste varige opsætning; OpenCode genkender også
adgangsnøglemiljøer, webidentitet og containerlegitimationsoplysninger.

```bash
aws configure sso --profile work
aws sso login --profile work
```

Vælg profilen og regionen i udbyderindstillingerne. En konfigureret `profile`, `AWS_PROFILE`, `AWS_ACCESS_KEY_ID`, webidentitets-
tokenfil eller containerlegitimations-URI aktiverer udbyderen; en region alene gør ikke.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

Uden en eksplicit region bruger OpenCode `AWS_REGION`, derefter `AWS_DEFAULT_REGION` og derefter `us-east-1`. For et privat eller
VPC-endpoint skal du angive `baseURL` og beholde samme profil og region.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Bedrock-API-nøgler bruger `AWS_BEARER_TOKEN_BEDROCK`. Andre AWS-variabler fodrer SigV4 og gemmes ikke som OpenCode-API-nøgle-
konti.

## Vertex

Google Vertex bruger Application Default Credentials (ADC) og kræver et projekt, før dets modeller bliver tilgængelige.
Opret lokal ADC, og angiv derefter projekt og placering i udbyderindstillingerne.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode kan også finde projektet via `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` eller
`GCLOUD_PROJECT` i den rækkefølge. OpenCode finder placeringen via `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION` eller
`VERTEX_LOCATION` og bruger som standard `us-central1`.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

Tjenestekonti virker gennem samme ADC-sti. Peg `GOOGLE_APPLICATION_CREDENTIALS` på tjenestekontoens JSON-
fil, og angiv stadig et projekt gennem indstillingerne eller en af projektvariablerne ovenfor.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Brug det ene udbyder-ID `google-vertex` til Gemini-, Anthropic- og OpenAI-kompatible Vertex-katalogmodeller. Det gamle
udbyder-ID `google-vertex-anthropic` er utilgængeligt i V2.

## Copilot

GitHub Copilot understøtter device OAuth i stedet for manuel API-nøgleindtastning. Forbind **GitHub Copilot**, vælg GitHub.com eller
GitHub Enterprise, gennemfør device-flowet, og åbn derefter `/models`.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

For GitHub Enterprise skal du angive deployment-URL'en eller domænet, når du bliver bedt om det. OpenCode bruger et Copilot-API-endpoint returneret
af GitHub, når det er tilgængeligt; ellers udleder den endpointet fra enterprise-domænet.

```text
company.ghe.com
```

Den forbundne konto skal have adgang til Copilot Chat. Hvis GitHub rapporterer ingen rettighed, skal du tilmelde dig Copilot Free eller bede
organisationen om at tildele en Copilot-plads og derefter forbinde igen. OpenCode henter kontos aktuelle modelliste efter login
og hver gang den aktive Copilot-konto ændres.

## Ollama

Start Ollama, og hent en model. OpenCode undersøger `http://127.0.0.1:11434`, finder completion-modeller og føjer dem til
`/models` uden en kontoforbindelse.

```bash
ollama serve
ollama pull qwen3:8b
```

Peg OpenCode på en ekstern eller proxet Ollama-server med `settings.baseURL`. Medtag `/v1`; OpenCode udleder de native
søgestier `/api/tags` og `/api/show` fra den. `apiKey` er valgfri og sendes som bearer-token til søgning og
modelanmodninger.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

Søgningen opdateres periodisk og beholder den seneste vellykkede fortegnelse under et midlertidigt udfald. Modeller, der kun er
embeddings, vises ikke, fordi OpenCode kun tilføjer modeller, hvis Ollama-metadata omfatter `completion`-kapaciteten.

## Runtimes

LM Studio og vLLM har også indbygget lokal søgning. Deres standardendpoints er
`http://127.0.0.1:1234/v1` og `http://127.0.0.1:8000/v1`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio finder sprogmodeller fra `/api/v1/models`. vLLM kontrollerer `/health`, før den læser `/v1/models`; dens
søgning kan ikke udlede værktøjsunderstøttelse, så fundne vLLM-modeller starter med værktøjer deaktiveret. For et andet OpenAI-kompatibelt
runtime skal du bruge opskriften for [brugerdefinerede udbydere](#custom) og angive dens modeller eksplicit.

## Gateways

OpenRouter bruger sit native runtime og katalog. Giv `OPENROUTER_API_KEY` til OpenCode-serveren, eller forbind en
OpenRouter-konto, og referer derefter til modeller med det fulde OpenRouter-model-ID efter udbyderpræfikset.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-5.5",
}
```

Behold den native OpenRouter-pakke, når du tilsidesætter dens endpoint eller router gennem en OpenRouter-kompatibel gateway.
Det bevarer OpenRouters request- og ræsonneringsadfærd.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

For en gateway, der eksponerer et OpenAI-kompatibelt API, men har sin egen modelfortegnelse, skal du i stedet definere en brugerdefineret udbyder.
Konfigurationsnøglen bliver udbyderpræfikset, og hver `models`-nøgle bliver et valgbart model-ID.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## Fejl

Udbyder- og modelfejl angiver normalt det trin, der mislykkedes. Kontrollér serverprocessens miljø og det præcise model-
ID, før du ændrer pakker.

| Fejl eller symptom | Kontrollér |
| --- | --- |
| `No model is available for session ...` | Ingen aktiveret model kan vælges i øjeblikket. Gennemfør den udbyderspecifikke opsætning, og vælg derefter en model i `/models`. |
| `Model unavailable: provider/model` | Udbyderen er inaktiv, model-ID'et mangler eller er deaktiveret, eller dynamisk søgning returnerer det ikke længere. For brugerdefinerede aliaser skal du kontrollere `models`-mappets nøgle i stedet for `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | En `${NAME}`-pladsholder er tilbage i `baseURL`. Angiv variablen på OpenCode-serveren, eller erstat skabelonen med et komplet endpoint. |
| `Azure resource name is missing` | Angiv `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` eller en komplet `settings.baseURL`. |
| Vertex vises ikke | Angiv et projekt, som OpenCode kan finde, i udbyderindstillingerne eller i en understøttet projektvariabel. ADC alene aktiverer ikke udbyderen. |
| Bedrock vises ikke | Angiv en profil eller et andet understøttet input til AWS-legitimationskæden. `AWS_REGION` alene vælger kun en region. |
| Ollama har ingen modeller | Bekræft, at serveren eksponerer `/api/tags` og `/api/show` på stien udledt fra `baseURL`, og at `/api/show` rapporterer `completion`-kapaciteten. |
| Copilot har ingen modeller | Bekræft, at den aktive OAuth-konto har adgang til Copilot Chat. En mislykket modelsynkronisering logges som `failed to sync GitHub Copilot models`. |

V2 afviser de udgåede udbyder-ID'er med en direkte erstatning. Brug `azure/<model>` i stedet for
`azure-cognitive-services/<model>`, og `google-vertex/<model>` i stedet for `google-vertex-anthropic/<model>`.

## WebSockets

OpenAI-, xAI- og understøttede Azure Responses-modeller kan holde én WebSocket-forbindelse åben pr. session. Efterfølgende trin
genbruger det uændrede requestpræfiks og sender kun indhold tilføjet siden det forrige svar, hvilket reducerer uploads i lange
sessioner.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

WebSocket-adfærden følger disse regler:

- Indbyggede udbydere tilmelder understøttede ruter efter deres egen politik.
- Udbyders `settings.transport: "websocket"` aktiverer den; `"http"` deaktiverer den.
- `"websocket"` på en rute uden en WebSocket-kanal logger en advarsel og falder tilbage til HTTP.
- OpenAI-udbyderkomprimering bruger samme forbindelse.
- xAI fortsætter kun fra gemte svar. Med dens standard `store: false` sendes hvert trin fuldt over den genbrugte
  forbindelse.
- En lukket socket genopretter forbindelsen ved næste trin. Hvis forbindelsen ikke kan åbnes, fortsætter sessionen over HTTP.
- Udbyderplugins med `http.request`- eller `http.response`-hooks forbliver på HTTP, så hver anmodning forbliver observerbar.
