<Callout type="tip">
  Du kan bede OpenCode om at fejlfinde sig selv. Beskriv problemet, og bed den bruge denne fejlfindingsside; den kan læse
  trinnene nedenfor, inspicere sin tjeneste og sine logs og hjælpe med at identificere problemet.
</Callout>

OpenCode bruger en klient-server-arkitektur. En baggrundsserver ejer sessioner, plugins, tilladelser og anden applikationstilstand.
Start med at afgøre, om et problem ligger i en klient, den delte server eller et bestemt projekt.

## Kontrollér baggrundstjenesten

Vis den aktuelle serverinformation:

```bash
opencode service status
```

Kontrollér, at API'et svarer som forventet:

```bash
opencode api get /api/info
```

Hvis tjenesten hænger eller ikke virker som forventet, skal du genstarte den:

```bash
opencode service restart
```

Du kan også stoppe og starte den eksplicit:

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  OpenCode finder eller starter normalt den delte baggrundstjeneste automatisk. Service-kommandoerne er kun
  nødvendige, når du diagnosticerer dens livscyklus.
</Callout>

## Tillad en browserorigin

Hvis en browserklient på en anden origin ikke kan forbinde på grund af CORS, skal du tilføje klientens origin til tjenestekonfigurationen:

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

Brug en præcis HTTP- eller HTTPS-origin, inklusive porten når det er nødvendigt, uden sti eller afsluttende skråstreg. Hvis du vil tillade flere
origins, skal du sende en kommasepareret liste som ét argument; mellemrum omkring hver origin trimmes:

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` udskriver et JSON-array. Fjern den konfigurerede liste med:

```bash
opencode service unset cors
```

Angivelse eller fjernelse af tjenestekonfiguration stopper baggrundstjenesten. Dens næste start bruger den nye konfiguration;
brug `opencode service start` til at starte den eksplicit.

For en forgrundsserver skal du gentage `--cors` for hver ekstra tilladt origin:

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

Med `serve --service` tilsidesætter angivne `--cors`-flag den gemte liste for den proces. Uden disse flag bruger service-
tilstand den gemte liste. CORS ændrer ikke lytteadressen eller omgår serverautentificering.

## Inspicér API'et

Kommandoen `api` bruger den lokale tjenestesøgning og autentificeringsflow. Den accepterer enten en HTTP-metode og sti eller et
OpenAPI-handlings-ID.

Se [API-referencen](/api) for alle endpoints og handlings-ID'er.

Send anmodningens body som JSON med `--data` eller `-d`, og tilføj headere med `--header` eller `-H`.

<Callout type="warning">
  Når du kører `opencode api`, kan den starte baggrundstjenesten, hvis der ikke allerede kører en kompatibel tjeneste, der virker.
</Callout>

## Læs logs

Installerede builds skriver logs til:

```text
~/.local/share/opencode/log/opencode.log
```

Følg loggen, mens du gengiver problemet:

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

Hver linje indeholder et proces-`run`-ID og et `role`-felt. Brug `role=server` til aktivitet i sessioner, udbydere, plugins, tilladelser og
værktøjer.

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## Tag et heap-snapshot

Gem et heap-snapshot af den kørende baggrundsservers hukommelse, uanset platform:

```bash
opencode debug heap-dump
```

Kommandoen venter, indtil snapshottet er færdigt, og udskriver derefter dets sti:

```text
/home/me/.local/share/opencode/log/heap-48213-2026-10-23T013012345Z.heapsnapshot
```

Skriv det et andet sted med `--directory`. Serveren opretter mappen, når den mangler:

```bash
opencode debug heap-dump --directory ./snapshots
```

- Den bruger kun en server, der allerede kører. Den starter, erstatter eller genstarter aldrig en.
- Brug `--server <url>` til at optage en server, du startede med `opencode serve`. Angiv `OPENCODE_PASSWORD`, hvis den har en.
  `--directory` er derefter en sti på serverens maskine.
- Åbn filen i Memory-panelet i Chrome DevTools.

<Callout type="warning">
  Serveren sætter pause, mens den skriver snapshottet, og dens hukommelsesforbrug kan stige kortvarigt. Snapshottet kan
  indeholde prompts, filindhold og legitimationsoplysninger. Del det ikke offentligt.
</Callout>

### I desktop-appen

Kør **Capture heap snapshots** fra kommandopaletten. Den skriver én mappe i din Downloads-mappe med et snapshot af
hver del af appen samt en opgørelse over den hukommelse, et snapshot ikke kan vise:

```text
opencode-heap-2026-10-23T013012345Z/
  memory.json                  where the memory is, per process, in MiB: start here
  memory-infra.json            Chromium's memory dump trace; open it in https://ui.perfetto.dev
  heap-48213-….heapsnapshot    the desktop's own server
  window-1-48390.heapsnapshot  one per app window
  main-48102.heapsnapshot      the desktop main process
  gpu.json                     the GPU and driver
  manifest.json                processes, PIDs, and memory before and after; written last
```

- Et heap-snapshot indeholder kun JavaScript-objekter og siden. Billeder, layout, compositorlag og GPU-hukommelse findes i
  `memory.json` og `memory-infra.json` i stedet.
- Eksterne servere optages ikke. Brug `opencode debug heap-dump` på den maskine i stedet.
- Serveren skriver sit snapshot direkte i mappen, så intet stort flyttes eller kopieres.
- Browserfaner medtages ikke, fordi deres snapshots indeholder indholdet af de sider, du har besøgt.

## Optag CPU- og hukommelsesprofiler

På macOS og Linux kan du sende et signal til en kørende OpenCode-proces for at optage diagnostiske data. Hent baggrundsserverens PID
fra health-endpointet:

```bash
opencode api get /api/info
```

Brug `pid` fra svaret med et af disse signaler:

- `SIGPROF` optager en CPU-profil på ti sekunder:

  ```bash
  kill -SIGPROF <pid>
  ```

  Resultatet skrives til logmappen som `cpu-<pid>-<timestamp>.cpuprofile`.

- `SIGUSR1` tager et heap-snapshot af hukommelsen:

  ```bash
  kill -SIGUSR1 <pid>
  ```

  Resultatet skrives til logmappen som `heap-<pid>-<timestamp>.heapsnapshot`.

Vent på `CPU profile written` eller `heap snapshot written` i `opencode.log`, før du åbner filen. Den tilsvarende
logpost indeholder dens komplette sti. Du kan inspicere begge filtyper i Chrome DevTools.

<Callout type="note">
  Signalfremkaldte profiler er ikke tilgængelige på Windows. Brug i stedet `opencode debug heap-dump` til heap-snapshots.
  Skrivning af et heap-snapshot kan sætte processen på pause og øge dens hukommelsesforbrug midlertidigt.
</Callout>

## Servicefiler

Den delte server registrerer sig på:

```text
~/.local/state/opencode/service.json
```

Dens private tjenestekonfiguration gemmes separat på:

```text
~/.config/opencode/service.json
```

Databasen ligger normalt på:

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` kan tilsidesætte databaseplaceringen.

<Callout type="warning">
  Slet eller rediger ikke servicefiler eller databasen under fejlfinding. Brug service-kommandoerne til at administrere
  daemonen, og lav en backup, før du inspicerer vedvarende data med eksterne værktøjer.
</Callout>

## Rapportér et problem

Medtag følgende, når du rapporterer et reproducerbart problem:

- Output fra `opencode --version`
- Output fra `opencode service status`
- Den korteste trinsekvens, der gengiver problemet
- Om problemet påvirker den delte tjeneste, en bestemt klient eller ét projekt
- Relevante loglinjer, inklusive deres `run`- og `role`-felter

Fjern API-nøgler, autorisationsheadere, prompts, filindhold og andre følsomme data, før du deler logs.

Indsend reproducerbare problemer i [GitHub Issues](https://github.com/anomalyco/opencode/issues).
