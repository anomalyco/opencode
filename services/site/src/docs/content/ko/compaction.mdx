압축은 이전 대화를 요약으로 바꿔 긴 세션에 공간을 만들므로, 세션이 모델의 컨텍스트 한도를 넘어 계속 진행할 수
있습니다.

## 작동 방식

세션이 모델의 컨텍스트 한도에 가까워지면 OpenCode가 현재 대화 전체를 요약합니다. 또한 기본 약 15,000토큰의 최근
대화를 요약 옆에 유지해 최근 세부 사항을 그대로 사용할 수 있게 합니다.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

전체 대화를 보내면 제공자가 지원할 때 요약 요청이 일반 요청의 프롬프트 캐시를 재사용할 수 있습니다. 이후 압축은
그 체크포인트 이후의 대화로 기존 요약을 업데이트합니다.

## 시작

자동 압축은 기본으로 켜져 있습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

압축 과정에서 일부 정보가 손실됩니다. 최근 세부 사항이 정확해야 하면 `keep.tokens`를 늘리거나, 자동 압축 전에 직접 압축을
요청하세요.

## 수동

대화 기록이 짧아도 언제든 압축을 요청할 수 있습니다.

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

`api` 명령은 백그라운드 서비스를 찾아 인증합니다. 응답은 요청이 접수되었음을 확인할 뿐 요약을 기다리지 않습니다.
완료 시점은 `session.compaction.*` 이벤트로 확인하세요. 전체 작업은 [API 참조](/api)를 참고하세요.

| 규칙 | 동작 |
| --- | --- |
| 시점 | 다음 안전한 지점에서 실행되며, 아직 대기 중인 프롬프트보다 먼저 처리됩니다. |
| 반복 | 하나가 대기 중일 때 들어온 요청은 그 요청에 합쳐집니다. |
| 자동화 | `compaction.auto`가 `false`여도 동작합니다. |

`id`를 전달하면 동일한 재시도를 멱등하게 만들 수 있습니다. 같은 ID를 다른 요청에 재사용하면 충돌이 반환됩니다.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## 설정

[OpenCode 구성 파일](/config) 중 원하는 곳에 `compaction`을 추가하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": "20%",
  },
}
```

| 필드 | 기본값 | 동작 |
| --- | ---: | --- |
| `auto` | `true` | 컨텍스트 한도에 가까워지면 자동으로 압축하고, 제공자가 요청을 너무 길다고 거부하면 한 번 복구합니다. 수동 압축은 항상 동작합니다. |
| `background` | `true` | 요약을 미리 작성해 자동 압축이 기다리지 않게 합니다. [백그라운드 압축](#background-compaction)을 참고하세요. |
| `keep.tokens` | `15000` | 요약 옆에 유지하는 대략적인 최근 대화량. 값이 클수록 세부 사항을 더 보존하지만 새 작업을 위한 공간은 줄어듭니다. |
| `buffer` | `"15%"`, 최소 16k | 모델 컨텍스트 윈도에서 비워 두는 비율. 대화가 비워 둔 공간을 제외한 나머지 용량을 채우면 자동 압축이 시작됩니다. 값이 클수록 더 일찍 압축합니다. |

`keep.tokens`는 0 이상의 정수를 받습니다.

### 버퍼

`buffer`는 각 모델 윈도의 백분율이므로 하나의 설정으로 모든 모델에 맞출 수 있습니다.

| 모델 윈도 | `"buffer": "20%"`일 때 압축 시점 |
| ---: | ---: |
| 128k | 약 102k |
| 1M | 800k |

- 압축이 시작되는 지점이 아니라 비워 두는 공간입니다. `"20%"`는 80%가 찼을 때 압축합니다.
- `"1%"`부터 `"99%"`까지 받으며 `"12.5%"` 같은 소수도 가능합니다.
- `20000` 같은 토큰 수도 동작합니다. 같은 수치라도 작은 윈도에서는 큰 비율, 큰 윈도에서는 작은 비율입니다.
- 모델 윈도 이상인 토큰 수는 무시되고 기본값이 적용됩니다.

### 컨텍스트 윈도

컨텍스트 윈도는 모델의 입력 한도(`limit.input`)를 따르되 컨텍스트 한도(`limit.context`)를 넘지 않습니다.
둘 중 하나만 있으면 그 값을 사용합니다. 둘 다 없으면 자동 압축을 하지 않습니다. 다만 제공자가 요청이 너무 길다는
이유로 거부하면 OpenCode가 한 번 압축합니다.

설정에서 한도를 재정의하면 지정한 필드의 값만 바뀝니다. 카탈로그에 두 한도가 모두 지정되어 있으면
`limit.context`만 높여도 컨텍스트 윈도는 카탈로그의 입력 한도에 머무릅니다. `limit.input`도 함께 설정하세요.

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "limit": { "context": 1050000, "input": 1000000 },
        },
      },
    },
  },
}
```

## 모델

기본적으로 OpenCode는 세션의 모델로 요약을 직접 작성합니다. 요약에 다른 모델을 쓰려면
`agents.compaction.model`을 설정하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" },
  },
}
```

그 모델을 확인할 수 없으면 OpenCode는 세션의 모델로 대체합니다.

## 백그라운드 압축

OpenCode는 세션이 계속 진행되는 동안 요약을 미리 작성하고, 압축할 때 이를 바꿔 넣습니다. 그러면 자동 압축이 요약을
작성하느라 세션을 멈추지 않습니다.

```text
60k tokens before the threshold   summary of the conversation so far starts in the background
                                  the session keeps going; the summary is held, not applied
threshold                         the held summary is swapped in; everything since it is kept as is
```

컨텍스트 윈도가 작으면 요약은 마지막 압축 이후 첫 응답과 임계값 사이의 절반 지점에서 늦어도 시작됩니다.

| 규칙 | 동작 |
| --- | --- |
| 비용 | 요약 요청은 프롬프트 캐시를 재사용합니다. 임계값 전에 세션이 끝나는 등 사용되지 않은 요약도 토큰을 소비합니다. |
| 대기 | 압축 시점에 아직 요약을 작성 중이면 세션은 요약이 완료될 때까지 기다립니다. |
| 대체 | 보관된 요약 이후의 대화가 임계값의 약 40%를 넘게 늘었거나 대화 시작 부분이 바뀌면 평소처럼 요약하며 압축합니다. |
| 건너뜀 | 네이티브 압축에는 사용하지 않습니다. 모델을 바꾼 직후나 프롬프트 캐시 수명보다 긴 휴식 후에는 다음 응답부터 시작합니다. |
| 저장 | 보관된 요약은 메모리에 있으며 재시작하면 사라집니다. |

압축 시점에만 요약을 작성하려면 끄세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "background": false,
  },
}
```

## 제공자

일부 제공자는 대화를 자체적으로 압축할 수 있습니다. `settings.compaction`으로 제공자나 모델별로 활성화하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

모델 설정은 제공자 설정을 재정의합니다. `native`는 제공자의 압축을, `summary`는 OpenCode 자체 압축을 사용합니다.

네이티브 압축에서는 OpenCode가 대화를 제공자의 압축 엔드포인트로 보냅니다. 제공자는 이전 대화를 대신하는 불투명한
암호화 항목을 반환합니다. 최근 메시지와 첨부 파일은 `keep.tokens`까지 함께 유지됩니다.

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| 항목 | 동작 |
| --- | --- |
| 지원 | OpenAI Responses 모델. 지원 여부는 배포와 모델에 따라 다릅니다. |
| 임계값 | 요약 압축과 같은 `auto`, `buffer` 설정을 사용합니다. 수동 요청도 동작합니다. |
| 이식성 | 암호화된 체크포인트는 같은 제공자와 모델에서만 동작합니다. 모델을 바꾸면 세션은 원래 대화에서 이어집니다. |
| 너무 긺 | 제공자가 압축을 너무 길다고 거부하면 OpenCode는 더 작은 요청으로 재시도합니다. 요약으로 전환하지는 않습니다. |

## 요약

요약은 다른 에이전트가 이어받을 수 있도록 구조화됩니다.

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

목표와 요구 사항, 결정, 완료된 작업과 진행 중인 작업, 차단 요소와 다음 단계, 관련 파일을 다룹니다. 옆에 유지되는
최근 대화에서는 긴 도구 출력이 줄어들고 첨부 데이터가 짧은 설명으로 대체됩니다.

압축 후에는 지침 파일의 현재 버전이 세션의 기준이 됩니다. [지침](/instructions)을 참고하세요.

## 한도

| 한도 | 결과 |
| --- | --- |
| 모델 | 요약 압축은 `agents.compaction.model`을 따르고, 없으면 세션의 모델을 사용합니다. 네이티브 압축은 항상 세션의 모델을 사용합니다. |
| 기록 | 압축은 대체할 이전 대화가 필요합니다. 요청이 대부분 고정된 지침과 도구 스키마라면 공간을 만들 수 없습니다. |
| 크기 | 압축할 대화 자체가 너무 길면 OpenCode가 축약된 텍스트 버전을 보내고 가장 오래된 주고받음을 생략할 수 있습니다. |
| 복구 | 너무 길다고 거부된 요청은 압축한 뒤 한 번 재시도합니다. 두 번째로 거부되면 오류로 반환됩니다. |
| 저장 | 이전 메시지는 모델에 더 이상 전송되지 않아도 계속 저장됩니다. |

예를 들어 다음 경우에는 압축이 도움이 되지 않습니다.

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## 마이그레이션

V1은 최근 대화 턴을 남기고 이전 내용을 정리하는 방식을 사용했습니다. V2는 요약과 `compaction.keep.tokens`를 사용합니다.

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

이 페이지의 설정과 동작은 V2에 적용됩니다.
