---
title: "스킬"
description: "작업에 필요할 때만 로드되는 재사용 가능한 지침을 OpenCode 에이전트에 제공하는 SKILL.md 파일을 작성하세요."
---

특정 작업을 위한 재사용 가능한 지침을 에이전트에 제공하려면 스킬을 만드세요. `SKILL.md` 파일을 `.opencode/skills/<skill-id>`에 두고 `description`에 언제 사용할지 설명합니다.

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow

1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

OpenCode는 스킬이 작업에 적합하면 에이전트에 알려 줍니다. 그러면 에이전트가 모든 스킬을 모든 프롬프트에 넣지 않고 `skill` 도구로 지침을 로드할 수 있습니다.

## 만들기

관련 스크립트, 참고 자료, 템플릿은 `SKILL.md` 옆에 두세요.

```text
.opencode/skills/
└── git-release/
    ├── SKILL.md
    ├── scripts/
    │   └── changelog.ts
    └── references/
        └── release-policy.md
```

스킬 안에 작성한 경로는 `SKILL.md`가 있는 디렉터리 기준입니다. 디렉터리 형식은 보조 파일을 둘 전용 디렉터리가 생기므로 권장합니다.

## 탐색

OpenCode는 다음 위치를 자동으로 검색합니다.

| 범위          | 소스                                   |
| ------------- | -------------------------------------- |
| 전역          | `~/.config/opencode/skills`            |
| 전역 호환     | `~/.claude/skills`, `~/.agents/skills` |
| 프로젝트      | `.opencode/skills`                     |
| 프로젝트 호환 | `.claude/skills`, `.agents/skills`     |

프로젝트 소스의 경우 OpenCode는 현재 디렉터리에서 프로젝트 루트까지 검색하며 모든 수준의 일치하는 디렉터리를 포함합니다.

각 소스는 두 형식 중 하나를 포함할 수 있습니다.

```text
skills/
├── review.md
└── git-release/
    └── SKILL.md
```

- Markdown 파일은 `skills/review.md`처럼 소스 루트에 있어야 합니다.
- 이름이 정확히 `SKILL.md`인 파일은 `skills/git-release/SKILL.md`나 `skills/teams/release/SKILL.md`처럼 그룹 디렉터리에 중첩될 수 있습니다.
- `SKILL.md`가 있는 디렉터리는 하나의 스킬입니다. OpenCode는 그 안에서 더 많은 스킬을 찾지 않습니다.
- 숨김 파일과 디렉터리, `node_modules`는 건너뜁니다.
- 소스 루트 아래 최대 6단계 깊이까지 검색합니다.

## 소스

`skills` 배열로 로컬 디렉터리나 HTTP 카탈로그를 더 추가하세요. 모든 `opencode.json` 또는 `opencode.jsonc`에서 사용할 수 있습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "skills": [
    "./team-skills",
    "~/shared/opencode-skills",
    "/opt/company-skills",
    "https://example.com/opencode/skills/",
  ],
}
```

| 값 | 확인 방식 |
| ----- | ---------- |
| 상대 경로 | 구성 파일이 아니라 활성 OpenCode 작업 디렉터리 기준 |
| `~/` 경로 | 현재 사용자의 홈 디렉터리 기준 |
| 절대 경로 | 그대로 사용 |
| `http://` 또는 `https://` URL | HTTP 카탈로그로 로드 |

발견된 모든 구성 파일이 항목을 제공합니다. `skills` 배열은 교체되지 않고 결합됩니다.

연결된 [OpenCode Console](/console) 워크스페이스도 스킬을 공유할 수 있습니다.

## 카탈로그

HTTP 카탈로그는 `index.json` 파일이 있는 기본 URL입니다.

```json title="index.json"
{
  "skills": [
    {
      "name": "git-release",
      "version": "3",
      "files": ["git-release.md", "references/release-policy.md"]
    }
  ]
}
```

해당 항목에서 OpenCode는 각 파일을 `<base-url>/git-release/<file>`에서 내려받습니다.

| 규칙 | 요구 사항 |
| ---- | ----------- |
| 경로 | 안전한 상대 경로여야 하며 출처가 같아야 함 |
| 항목 파일 | `SKILL.md` 또는 `<name>.md`(예: `git-release.md`) 포함 |
| 업데이트 | 파일이 바뀌면 `version`을 올려 OpenCode가 캐시를 갱신하게 함 |

내려받은 각 스킬 디렉터리는 항목 이름을 딴 소스 루트가 되므로 `git-release.md`와 `SKILL.md` 모두 ID가 `git-release`입니다.

## 프런트매터

프런트매터로 스킬 이름을 지정하고 표시 위치를 제어하세요.

```markdown title="SKILL.md"
---
name: Git Release
description: Prepare a repository release
metadata:
  opencode/autoinvoke: false
---

Prepare the changelog, version bump, tag, and release notes.
```

| 필드                          | 동작                                                          |
| ------------------------------ | ----------------------------------------------------------------- |
| `name`                         | 표시 이름. 기본값은 경로에서 파생된 ID                     |
| `description`                  | 모델에 스킬을 보여 줄 때 쓰는 요약                       |
| `metadata.opencode/autoinvoke` | `false`로 설정하면 모델의 사용 가능 목록에서 스킬 제외  |
| `disable-model-invocation`     | `true`로 설정하면 `opencode/autoinvoke: false`와 같은 효과 |

런타임에서 모든 프런트매터는 선택 사항입니다. 모델이 스킬을 발견해야 한다면 명확한 `description`을 추가하세요. 설명이 없는 스킬은 모델에 안내하지 않습니다.

`opencode/autoinvoke: false`는 모델의 사용 가능 목록에서 스킬을 숨길 뿐입니다. 스킬은 계속 등록되어 있으며 ID로 명시적으로 로드할 수 있습니다. `disable-model-invocation`과 `opencode/autoinvoke`가 모두 설정되면 `opencode/autoinvoke`가 우선합니다. V2는 `license`, `compatibility` 같은 이식성 필드를 받아들이지만 해석하지는 않습니다.

## ID

파일 경로가 스킬 ID를 결정합니다. 프런트매터의 `name`은 표시 레이블일 뿐입니다.

| 파일                              | ID            |
| --------------------------------- | ------------- |
| `<source>/git-release.md`         | `git-release` |
| `<source>/git-release/SKILL.md`   | `git-release` |
| `<source>/teams/release/SKILL.md` | `release`     |

ID는 정확히 일치해야 하며 대소문자를 구분합니다. 이식 가능한 스킬에는 1~64자의 고유한 소문자 케밥 케이스 ID를 사용하고 디렉터리 이름과 맞추세요.

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

현재 V2는 이 패턴, 1~64자 권장 사항, `name`과 디렉터리의 일치, 설명 최대 길이를 강제하지 않습니다.

## 우선순위

스킬은 ID로 선택됩니다. 두 소스가 `git-release`를 정의하면 나중에 등록된 소스가 OpenCode가 로드하는 스킬을 제공합니다.

```text
~/.config/opencode/skills/git-release/SKILL.md  ← lower precedence
.opencode/skills/git-release/SKILL.md           ← loaded
```

소스는 우선순위가 낮은 것부터 높은 것 순서로 등록됩니다.

1. 내장 스킬
2. `.claude/skills`, 전역을 먼저, 그다음 가장 먼 상위에서 현재 디렉터리 방향으로
3. `.agents/skills`, 전역을 먼저, 그다음 가장 먼 상위에서 현재 디렉터리 방향으로
4. `~/.config/opencode/skills`
5. 프로젝트 `.opencode/skills`, 프로젝트 루트에서 현재 디렉터리 방향으로
6. 명시적 `skills` 구성 항목, 구성 우선순위와 배열 순서대로

이전 스킬을 재정의하려는 것이 아니라면 중복 ID를 피하세요.

## 로드

각 모델 단계에서 OpenCode는 설명이 있고 `opencode/autoinvoke`가 `false`가 아닌 허용된 스킬을 나열합니다. 목록에는 ID, 이름, 설명만 포함되고 Markdown 본문 전체는 포함되지 않습니다.

모델은 정확한 ID로 `skill` 도구를 호출해 스킬을 로드합니다.

```json title="skill tool input"
{
  "id": "git-release"
}
```

그러면 OpenCode는 다음과 같이 합니다.

1. 해당 ID의 현재 정의를 선택합니다.
2. 선택한 에이전트의 `skill` 권한을 확인합니다.
3. 프런트매터를 제외한 Markdown 본문을 대화에 추가합니다.
4. 스킬의 기본 디렉터리와 최대 10개의 보조 파일 경로 샘플을 제공합니다.

직접 스킬을 로드하려면 프롬프트에서 `@skill-id`로 언급하세요.

보조 파일 내용은 자동으로 로드되지 않습니다. 스킬이 지시할 때 에이전트가 읽습니다. 파일 샘플은 디렉터리 기반 `SKILL.md` 스킬에 제공되며, 단일 Markdown 스킬에는 주변 파일 목록이 제공되지 않습니다.

## 권한

`skill` 액션을 사용하고 스킬 ID를 리소스로 사용합니다. 규칙은 순서대로 실행되며 마지막으로 일치한 규칙이 우선합니다.

```jsonc title="opencode.jsonc"
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" },
  ],
}
```

| 효과 | 동작 |
| ------ | -------- |
| `allow` | 일치하는 스킬을 알리고 승인 없이 로드 |
| `ask` | 일치하는 스킬을 알리고 로드 전에 확인 |
| `deny` | 모델에서 일치하는 스킬을 숨기고 로드를 거부 |

같은 규칙을 `agents.<id>.permissions` 아래에 두면 하나의 에이전트에만 적용됩니다.

## 문제 해결

예를 들어 이 스킬의 ID는 `release`이며 프런트매터 이름 `Git Release`가 아닙니다.

```text
.opencode/skills/release/SKILL.md
                      └─ ID: release
```

스킬이 없거나 잘못된 내용을 로드하면 다음과 같이 확인하세요.

1. 파일이 루트 수준의 `*.md`이거나 이름이 정확히 `SKILL.md`인 중첩 파일인지 확인합니다.
2. 프런트매터 `name`이 아니라 경로에서 파생된 대소문자 구분 ID를 확인합니다.
3. 모델이 스킬을 발견해야 한다면 `description`을 추가합니다.
4. `opencode/autoinvoke`와 선택한 에이전트의 `skill` 권한을 확인합니다.
5. 같은 ID를 정의하는 나중 소스가 있는지 확인합니다.
6. HTTP 카탈로그라면 `index.json`, 동일 출처 파일 경로, 변경된 `version`을 확인합니다.
