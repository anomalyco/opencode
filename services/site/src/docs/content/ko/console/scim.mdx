디렉터리 동기화(SCIM 2.0)를 사용하면 ID 공급자에서 사용자를 할당할 때 워크스페이스에 멤버로 추가됩니다. 할당을
해제하면 접근 권한을 잃습니다. 역할은 계속 Console에서 관리합니다.

```text
https://opencode.ai/console/scim/v2
```

## 시작하기 전에

- 워크스페이스에 [SSO](/console/sso)를 설정합니다.
- 사용자가 로그인하는 모든 이메일 도메인을 [확인](/console/sso#verify-email-domains)합니다. 디렉터리 동기화는
  확인된 도메인의 사람만 추가하므로, 다른 사람은 [멤버](/console/members)에서 초대하세요.

## 토큰 만들기

워크스페이스 소유자만 디렉터리 동기화를 설정하거나 토큰을 만들고 폐기할 수 있습니다.

1. **Settings › Security**를 열고 **Directory sync**에서 **Set up**을 클릭하세요.
2. **SCIM base URL**과 토큰을 복사하세요. 토큰은 한 번만 표시되므로 보안 비밀 관리 도구에 저장하세요.

ID 공급자는 모든 요청에 이 토큰을 보냅니다.

```text
Authorization: Bearer <token>
```

## ID 공급자 연결

### Okta

1. **SCIM 2.0 Test App (Header Auth)** 앱을 추가하세요.
2. 기본 URL을 설정하고 **API Token**에 `Bearer `와 토큰을 이어서 입력하세요.
3. **Create Users**, **Update User Attributes**, **Deactivate Users**를 켜세요. **Import Groups**와 비밀번호
   동기화는 끈 상태로 두세요.

### Microsoft Entra ID

1. 엔터프라이즈 앱에서 **Provisioning**을 열고 모드를 **Automatic**으로 설정하세요.
2. 기본 URL을 **Tenant URL**에, 토큰을 **Secret Token**에 입력하세요.
3. 사용자와 그룹을 할당한 뒤 프로비저닝을 시작하세요.

### 기타 ID 공급자

SCIM 2.0 앱에서 헤더로 토큰을 보내 인증하도록 설정하고, 요청을 기본 URL로 보내세요. Console은 `/Users`와 `/Groups`
엔드포인트를 지원합니다.

먼저 테스트할 사람 한 명을 할당하세요. 첫 요청이 오면 **Directory sync**에 **Connected to your identity
provider**가 표시됩니다.

## 동기화되는 항목

| ID 공급자에서             | Console에서                                                                       |
| ------------------------- | --------------------------------------------------------------------------------- |
| 사람 할당                 | **Member**로 추가됩니다. 기존 멤버는 역할을 유지합니다.                            |
| 이름 업데이트             | 프로필이 업데이트됩니다.                                                          |
| 할당 해제 또는 비활성화   | 접근이 중지되고 **Deactivated**로 표시됩니다. 그 사람이 만든 API 키는 폐기됩니다. |
| 재할당                    | 접근이 복구됩니다. 폐기된 키는 계속 폐기된 상태입니다.                            |
| 삭제                      | 워크스페이스에서 제거됩니다. 계정과 다른 워크스페이스는 영향을 받지 않습니다.     |

- 디렉터리 동기화는 역할과 이메일 주소를 변경하지 않습니다.
- 마지막 소유자는 비활성화하거나 삭제할 수 없습니다.
- [Go](/console/go) 구독이 있는 워크스페이스는 디렉터리 동기화로 멤버를 추가할 수 없습니다.

## 그룹

그룹을 푸시해 멤버에 태그를 붙이세요. 예를 들어 Okta **Push Groups**나 Entra 그룹 할당을 사용합니다. 그룹을
푸시하기 전에 사람을 먼저 할당하세요.

```text
Platform Admins  →  platform-admins
```

각 그룹은 그룹 이름을 딴 태그를 멤버에 붙입니다. **Settings › Security › Group tags**에서 태그 이름을 바꾸거나,
여러 그룹을 하나의 태그로 연결하거나, 그룹 태그를 중단할 수 있습니다. 그룹을 떠나면 해당 태그가 제거됩니다.

## 토큰 교체

1. **New token**을 클릭하고 새 토큰을 ID 공급자에 등록하세요.
2. 새 토큰의 마지막 사용 시각이 표시될 때까지 기다리세요.
3. 기존 토큰을 폐기하세요.

토큰을 폐기하면 이후 업데이트가 중단되지만 기존 멤버는 바뀌지 않습니다. SSO 연결을 삭제하면 모든 토큰이
폐기됩니다.

## SSO와 디렉터리 동기화

워크스페이스가 토큰을 발급한 뒤에는 SSO가 더 이상 [멤버를 자동으로
추가](/console/sso#automatic-membership)하지 않습니다. 이후 토큰을 폐기하더라도 워크스페이스의 멤버 자격은
디렉터리에서 결정합니다.
