TUI에서 제공자를 연결한 다음 그 모델 중 하나를 선택하세요.

```text
/connect
/models
```

`/connect`는 현재 서버와 프로젝트에서 사용할 수 있는 통합을 나열합니다. 제공자를 선택하고, 인증 방법이 여러 개면
하나를 고른 뒤 안내를 따르세요.

## TUI

TUI는 API 키, OAuth, 제공자 인증 명령을 지원합니다. OAuth는 인증 URL을 열거나 입력할 코드를 보여 주며, `o`를 눌러
URL을 열고 `c`를 눌러 인증 정보를 복사합니다.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

`/connect`를 다시 실행하면 다른 계정을 추가합니다. 이미 연결된 제공자를 선택하면 계정 목록이 열리고 저장된 계정을
활성화, 이름 변경, 삭제할 수 있습니다.

## CLI

TUI를 열지 않고 동일한 방식으로 제공자를 인증하려면 `auth login`을 사용하세요. 제공자 인수를 생략하면 대화형 제공자 선택기가
열립니다.

```bash
opencode auth login
```

통합 ID나 이름을 전달하면 첫 선택기를 건너뜁니다. API 키 입력을 명시적으로 선택하려면 `--method key`를 사용하세요.

```bash
opencode auth login anthropic --method key
```

인증 방식마다 ID가 있으며, 제공자에 따라 다릅니다. 인증 방식이 여러 가지라면 `--method` 없이 명령어를 실행해 사용할 수 있는 방식을 확인하세요.

```bash
opencode auth login openai
```

API 키 입력과 제공자 양식에는 대화형 터미널이 필요합니다. 인증 코드를 붙여 넣으라고 요청하는 OAuth 방식도
마찬가지입니다.

## 인증 방식

OpenCode는 네 가지 통합 방식으로 제공자 자격 증명을 받습니다.

| 방식 | 동작 |
| --- | --- |
| API 키 | 시크릿을 입력받아 제공자 계정으로 저장합니다. |
| OAuth | 브라우저 URL, 기기 코드, 인증 코드 프롬프트를 제공한 뒤 토큰을 저장하고 지원되면 갱신합니다. |
| 명령 | 제공자가 제공한 인증 명령을 실행하고 표준 출력을 키로 저장합니다. |
| 환경 | 서버 프로세스에서 지원되는 변수를 읽고 저장하지 않습니다. |

제공자는 Azure 리소스 이름이나 GitHub Enterprise 도메인처럼 추가 정보가 필요한 경우 API 키나 OAuth 인증 과정에 입력 양식을 표시할 수 있습니다. CLI와 TUI는 인증을 시작하기 전에 그 양식을 렌더링합니다.

## 환경

모델 요청을 실행하는 서버 프로세스에 제공자의 지원 환경 변수를 설정하세요. 일회성 개인 서버라면 독립 실행 모드를
시작할 때 전달하세요.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

공유 백그라운드 서버에는 변수를 관리형 환경에 추가하세요. 그러면 실행 중인 서비스가 중지되고 다음 OpenCode 명령어를 실행할 때 새 값으로 서비스가 시작됩니다.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

환경 연결은 `auth list`에 `environment` 유형으로 나타납니다. 계정이 아니므로 `auth logout`으로 제거할 수 없으며,
연결을 끊으려면 변수를 해제하세요. 같은 통합에서는 저장된 계정이 환경 연결보다 우선합니다.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

일부 제공자는 API 키 변수 대신 실행 환경에서 자격 증명을 찾는 자체 체인을 사용합니다.

- Amazon Bedrock은 프로필, 액세스 키 환경, 웹 자격 증명, 컨테이너 자격 증명을 포함한 AWS 기본 자격 증명 체인을
  지원합니다. `AWS_BEARER_TOKEN_BEDROCK`도 지원합니다.
- Google Vertex는 Application Default Credentials와 확인 가능한 프로젝트를 사용합니다. 예를 들어
  `gcloud auth application-default login`으로 인증하고 `GOOGLE_CLOUD_PROJECT`를 설정하세요.
- Azure는 `az`가 설치되어 있으면 **Microsoft Entra ID (Azure CLI)**를 연결 방식으로 제공합니다. 먼저 `az login`을
  실행한 다음 `/connect`나 `auth login azure`에서 해당 방식을 선택하세요.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

제공자별 및 서버 측 설정은 [제공자](/providers)를 참고하세요.

## 계정

API 키, OAuth, 명령 로그인이 성공할 때마다 저장된 계정이 만들어집니다. 가장 최근 계정이 활성화되며, 레이블이나 자격
증명 ID로 활성 계정을 전환합니다.

```bash
opencode auth list
opencode auth switch anthropic work
```

저장된 계정은 `auth logout`으로 제거합니다. 두 명령 모두 인수를 생략하면 선택기를 엽니다.

```bash
opencode auth logout anthropic work
```

TUI에서 `/connect`는 저장된 계정의 추가, 활성화, 이름 변경, 삭제 작업을 제공합니다.

## 저장소

저장된 API 키와 OAuth 토큰은 서버의 SQLite 데이터베이스에 있습니다. 로컬 서버의 데이터베이스 경로는 다음과 같이
출력합니다.

```bash
opencode debug paths db
```

일반적인 릴리스 경로는 `~/.local/share/opencode/opencode.db`이며 `XDG_DATA_HOME`, 릴리스 채널, `OPENCODE_DB`가
이를 바꿀 수 있습니다. 자격 증명 관리를 위해 데이터베이스를 편집하지 말고 `/connect`나 `auth` 명령을 사용하세요.

V2는 데이터베이스 마이그레이션 중에 OpenCode 데이터 디렉터리의 이전 `auth.json`에서 지원되는 자격 증명을
가져옵니다. 새 자격 증명과 업데이트된 자격 증명은 그 파일에 다시 쓰지 않고 SQLite에 저장됩니다.
