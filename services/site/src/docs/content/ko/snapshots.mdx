스냅샷을 사용하면 최근 대화와 파일 변경을 함께 실행 취소할 수 있습니다. 최근 작업을 수정할 때 사용하되, 중요한
작업은 Git 커밋이나 백업으로 보관하세요.

## 워크플로

수정하고 싶은 응답이 나온 뒤 `/undo`를 실행하세요. OpenCode는 되돌리기를 준비하고 영향을 받은 파일을 복원하며,
제거된 프롬프트를 입력창으로 돌려놓아 수정할 수 있게 합니다.

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

수정한 프롬프트를 제출하면 준비된 되돌리기가 확정됩니다. 제출 전에 `/redo`를 실행하면 이를 취소하고 `/undo`
이전의 대화와 파일을 복원합니다.

```text
/redo
```

터미널은 기본 단축키도 제공합니다.

| 작업 | 명령 | 단축키 |
| --- | --- | --- |
| 이전 메시지 되돌리기 준비 | `/undo` | `<leader>u` |
| 준비된 되돌리기 취소 | `/redo` | `<leader>r` |

이전 메시지를 선택하고 **Revert**를 골라 그 지점으로 되돌리기를 준비할 수도 있습니다.

## 캡처

OpenCode는 각 모델 단계에서 모델 호출 직전과 단계의 성공 또는 실패를 기록할 때 각각 스냅샷을 캡처하려고 시도합니다.
어시스턴트 메시지에는 두 스냅샷 사이에 변경된 경로가 기록됩니다.

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

스냅샷 캡처가 항상 성공하는 것은 아닙니다. 두 스냅샷 중 하나를 사용할 수 없으면 대화는 계속되지만, 그 단계의 파일 변경은 복원하지
못할 수 있습니다.

## 범위

스냅샷은 Git 워크트리 안에서 세션의 활성 디렉터리를 대상으로 합니다. 예를 들어 `packages/app`에서 연 세션은
`packages/app` 아래의 대상 파일만 캡처하고 저장소의 다른 곳 변경은 캡처하지 않습니다.

| 콘텐츠 | 캡처 | 예 |
| --- | --- | --- |
| 활성 디렉터리의 추적 중인 파일 | 예 | `packages/app/src/app.tsx` |
| Git이 추적하지 않고 무시 대상도 아닌 파일(각 2MiB까지) | 예 | `packages/app/notes.txt` |
| Git에서 무시된 파일 | 아니요 | `packages/app/dist/app.js` |
| Git이 추적하지 않는 파일 중 하나의 크기가 2MiB를 넘는 경우 | 아니요 | `packages/app/debug.log` |
| 활성 디렉터리 밖의 파일 | 아니요 | `packages/server/src/index.ts` |
| Git 메타데이터 및 기타 부수 효과 | 아니요 | 커밋, 브랜치, 데이터베이스, 프로세스 |

파일 시스템 스냅샷에는 Git 저장소가 필요합니다. 저장소가 없으면 `/undo`가 대화 기록은 되돌릴 수 있지만 파일은
복원할 수 없습니다.

## 복원

되돌리기는 선택한 대화 경계 이후의 어시스턴트 단계에 속한 경로만 복원합니다. 각 경로는 되돌린 첫 단계 이전 상태로
돌아가고, 그 단계에서 만들어진 파일은 당시 존재하지 않았다면 제거됩니다.

| 시점 | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| 선택한 경계 | 버전 A | 없음 |
| 이후 어시스턴트 단계 | 버전 B | 생성됨 |
| 되돌린 후 | 버전 A | 제거됨 |

그 단계에 속하지 않은 경로는 그대로 둡니다. 영향을 받은 경로의 현재 편집 내용이 덮어써질 수 있으므로 계속하기 전에
복원 요약과 `git diff`를 확인하세요.

```sh
git diff --stat
git diff
```

## 저장

OpenCode는 스냅샷을 데이터 디렉터리 아래의 별도 내부 Git 객체 데이터베이스에 로컬로 저장합니다. 스냅샷 캡처는
커밋을 만들거나 브랜치를 이동하거나 저장소의 인덱스를 의도적으로 변경하지 않습니다.

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

스냅샷 객체에는 Git이 추적하는 파일과 추적하지 않는 파일 중 캡처 대상에 해당하는 파일의 전체 내용이 들어갈 수 있습니다. OpenCode 데이터
디렉터리를 민감한 로컬 데이터로 취급하세요.

## 설정

스냅샷은 기본으로 활성화되어 있습니다. [구성](/config#snapshots)에서 `snapshots`를 `false`로 설정하면 이후 파일
시스템 캡처를 중단합니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

스냅샷을 비활성화해도 이미 저장된 스냅샷은 삭제되지 않습니다. 대화 되돌리기는 계속 사용할 수 있지만, 캡처된 파일
시스템 상태가 없으면 관련 파일 변경을 복원할 수 없습니다.

## 안전

스냅샷은 편의 기능이며 트랜잭션이나 백업이 아닙니다.

- 셸 명령은 서비스, 프로세스, 네트워크 리소스, 데이터베이스, Git 상태, 무시된 출력, 활성 디렉터리 밖의 파일을
  변경할 수 있습니다. 스냅샷을 복원해도 이런 효과는 되돌려지지 않습니다.
- 캡처가 실패하거나 사용할 수 있는 스냅샷 쌍이 없으면 중단되거나 실패한 작업이 변경을 남길 수 있습니다.
- 영향을 받은 경로를 복원하면 현재 내용을 덮어씁니다. 준비된 되돌리기를 취소해도 이후 편집을 덮어쓸 수 있습니다.
- OpenCode는 세션이 실행 중일 때 되돌리기 작업을 거부하지만, 외부 편집기와 명령은 캡처와 복원 사이에 워크트리를
  변경할 수 있습니다.
- 되돌리기를 확정하면 활성 대화 보기에서 메시지가 제거될 뿐, 영구 세션 기록이나 기존 스냅샷 저장소에서는 제거되지
  않습니다. 안전한 삭제가 아닙니다.

변경 사항이 있는 워크트리에서 `/undo`를 사용하기 전에 중요한 작업을 커밋하거나 백업하세요.
