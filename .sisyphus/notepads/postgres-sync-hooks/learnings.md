- Task 1 event-contract result: all seven SSE event types used by `opencode-postgres-sync` have unversioned bus equivalents (`session.created/updated/deleted`, `message.updated/removed`, `message.part.updated/removed`).
- `session.updated` is special on the bus: sync storage keeps a patch schema, but `server/projectors.ts` converts it to a full `Session.Info` snapshot before publish.
- `message.part.delta` is bus-only and incremental. Current producers only emit `field: "text"` from `text-delta` and `reasoning-delta`; authoritative state still comes from `message.part.updated` snapshots.
- Hooks cannot reproduce the current SSE metadata contract: plugin-visible bus events omit `id`, `seq`, `origin`, and explicit `aggregateID`. `aggregateID` is derivable from `properties.sessionID` for the needed events, but `id`/`seq`/`origin` are unavailable.
- Because of that omission, a hooks rewrite can project session/message/part rows, but cannot preserve the current `event` table, `replication_state.last_event_id/last_seq`, or `session.origin_machine` behavior without a core contract change or a plugin redesign.
- Task 2 projector rewrite worked cleanly by splitting transport decoding from row upserts: keep `replay()` for SSE backfill, add `replayBus()`/`routeBus()` for `{ type, properties }`, and reuse the same session/message/part row mappers across both paths.
- Exporting the real row-mapping helpers into `projectors.test.ts` removed duplicated test logic and made the RED phase meaningful; the test failure came from missing bus exports instead of a copied implementation passing by accident.
- `session.updated` on the bus can reuse full-session upsert logic instead of the old patch updater because the bus already publishes a complete `Session.Info` snapshot.
- The rewritten `projectors.ts` no longer contains versioned event strings at all, so the bus path is fully unversioned and backfill compatibility is preserved by keeping the old `Sync`-shape `replay()` entrypoint.
