OpenCode supports standard proxy environment variables and custom certificates for enterprise network environments.

---

## Proxy

OpenCode respects standard proxy environment variables.

```bash
# HTTPS proxy (recommended)
export HTTPS_PROXY=https://proxy.example.com:8080

# HTTP proxy (if HTTPS not available)
export HTTP_PROXY=http://proxy.example.com:8080

# Bypass proxy for local server (required)
export NO_PROXY=localhost,127.0.0.1
```

:::caution
The TUI communicates with a local HTTP server. You must bypass the proxy for this connection to prevent routing loops.
:::

You can configure the server's port and hostname using [CLI flags](/docs/cli#run).

---

### Authenticate

If your proxy requires basic authentication, include credentials in the URL.

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

:::caution
Avoid hardcoding passwords. Use environment variables or secure credential storage.
:::

For **Negotiate (Kerberos/SPNEGO)** and **NTLM**, OpenCode authenticates
automatically using your OS credentials (Windows SSPI, or the Kerberos ticket
cache on macOS/Linux) when the optional native addon is installed. On a machine
already configured for browser or command-line proxy authentication, no extra
configuration is required.

:::note
The optional native addon's OS bindings are still being implemented. Until they
ship, use Basic credentials (below) or an authenticating proxy that accepts
them. The configuration and selection logic below are in place.
:::

You can be explicit about the mechanism and credentials in `opencode.json`:

```jsonc
{
  "proxy": {
    "url": "http://proxy.example.com:8080",
    "auth": "auto",                       // auto | negotiate | ntlm | basic | none
    "username": "DOMAIN\\user",           // optional
    "password": "{env:PROXY_PASSWORD}",   // optional; prefer env or the OS cache
    "no_proxy": "localhost,127.0.0.1,.internal.example.com"
  }
}
```

`auth: "auto"` tries Negotiate, then NTLM, then Basic, based on the proxy's
`Proxy-Authenticate` challenges. If the native addon is not installed, OpenCode
falls back to Basic credentials and warns once. Credentials are never logged.

## Custom certificates

If your enterprise uses custom CAs for HTTPS connections, configure OpenCode to trust them.

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

This works for both proxy connections and direct API access.
