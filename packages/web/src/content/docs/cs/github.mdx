OpenCode se integruje s vaším pracovním postupem GitHub. Ve svém komentáři uveďte `/opencode` nebo `/oc` a OpenCode bude provádět úkoly ve vašem běžci GitHub Actions.

---

## Funkce

- **Problémy s tříděním**: Požádejte OpenCode, aby se na problém podíval a vysvětlil vám ho.
- **Opravit a implementovat**: Požádejte OpenCode o vyřešení problému nebo implementaci funkce. A bude fungovat v nové pobočce a odevzdá PR se všemi změnami.
- **Secure**: OpenCode běží uvnitř běžců vašeho GitHub.

---

## Instalace

Spusťte následující příkaz v projektu, který je v úložišti GitHub:

```bash
opencode github install
```

To vás provede instalací aplikace GitHub, vytvořením pracovního postupu a nastavením tajemství.

---

### Ruční nastavení

Nebo jej můžete nastavit ručně.

1. **Nainstalujte si aplikaci GitHub**

Přejděte na [**github.com/apps/opencode-agent**](https://github.com/apps/opencode-agent). Ujistěte se, že je nainstalován v cílovém úložišti.

2. **Přidejte pracovní postup**

Přidejte následující soubor pracovního postupu do `.github/workflows/opencode.yml` ve vašem úložišti. Ujistěte se, že jste v `env` nastavili příslušné `model` a požadované klíče API.

   ```yml title=".github/workflows/opencode.yml" {24,26}
   name: opencode

   on:
     issue_comment:
       types: [created]
     pull_request_review_comment:
       types: [created]

   jobs:
     opencode:
       if: |
         contains(github.event.comment.body, '/oc') ||
         contains(github.event.comment.body, '/opencode')
       runs-on: ubuntu-latest
       permissions:
         id-token: write
       steps:
          - name: Checkout repository
            uses: actions/checkout@v6
            with:
              fetch-depth: 1
              persist-credentials: false

          - name: Run OpenCode
           uses: anomalyco/opencode/github@latest
           env:
             ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
           with:
             model: anthropic/claude-sonnet-4-20250514
             # share: true
             # github_token: xxxx
   ```

3. **Uložte klíče API v tajnosti**

V **nastavení** vaší organizace nebo projektu rozbalte vlevo **Tajemství a proměnné** a vyberte **Akce**. A přidejte požadované klíče API.

---

## Konfigurace

- `model`: Model pro použití s ​​OpenCode. Přebírá formát `provider/model`. Toto je **povinné**.
- `agent`: Agent k použití. Musí to být primární agent. Pokud není nalezen, vrátí se zpět na `default_agent` z konfigurace nebo `"build"`.
- `share`: Zda sdílet relaci OpenCode. Výchozí hodnota je **pravda** pro veřejná úložiště.
- `prompt`: Volitelná vlastní výzva k přepsání výchozího chování. Použijte toto k přizpůsobení způsobu, jakým OpenCode zpracovává požadavky.
- `token`: Volitelný přístupový token GitHub pro provádění operací, jako je vytváření komentářů, potvrzování změn a otevírání požadavků na stažení. Ve výchozím nastavení používá OpenCode instalační přístupový token z aplikace OpenCode GitHub, takže potvrzení, komentáře a žádosti o stažení se jeví jako přicházející z aplikace.

Případně můžete použít GitHub Action runner's [vestavěný `GITHUB_TOKEN`](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token) bez instalace aplikace OpenCode GitHub. Jen se ujistěte, že jste ve svém pracovním postupu udělili požadovaná oprávnění:

  ```yaml
  permissions:
    id-token: write
    contents: write
    pull-requests: write
    issues: write
  ```

Pokud dáváte přednost, můžete také použít [tokeny osobního přístupu](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)(PAT).

## Podporované události

OpenCode lze spustit následujícími událostmi GitHub:

| Typ události | Spuštěno | Podrobnosti |
| ------------------------------ | --------------------------------------- | --------------------------------------------------------------------------------------------------------
| `issue_comment` | Komentář k problému nebo PR | Ve svém komentáři uveďte `/opencode` nebo `/oc`. OpenCode čte kontext a může vytvářet větve, otevírat PR nebo odpovídat. |
| `pull_request_review_comment` | Komentář ke konkrétním řádkům kódu v PR | Při kontrole kódu zmiňte `/opencode` nebo `/oc`. OpenCode přijímá cestu k souboru, čísla řádků a kontext rozdílu.   |
| `issues` | Vydání otevřeno nebo upraveno | Automaticky spustit OpenCode, když jsou problémy vytvořeny nebo změněny. Vyžaduje vstup `prompt`.                      |
| `pull_request` | PR otevřeno nebo aktualizováno | Automaticky spustit OpenCode, když jsou PR otevřeny, synchronizovány nebo znovu otevřeny. Užitečné pro automatické kontroly.      |
| `schedule` | Harmonogram založený na cron | Spusťte OpenCode podle plánu. Vyžaduje vstup `prompt`. Výstup jde do protokolů a PR (není problém komentovat).        |
| `workflow_dispatch` | Ruční spoušť od GitHub UI | Spusťte OpenCode na vyžádání prostřednictvím karty Akce. Vyžaduje vstup `prompt`. Výstup jde do protokolů a PR.                 |

### Příklad plánu

Spusťte OpenCode podle plánu, abyste mohli provádět automatizované úlohy:

```yaml title=".github/workflows/opencode-scheduled.yml"
name: Scheduled OpenCode Task

on:
  schedule:
    - cron: "0 9 * * 1" # Every Monday at 9am UTC

jobs:
  opencode:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          persist-credentials: false

      - name: Run OpenCode
        uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review the codebase for any TODO comments and create a summary.
            If you find issues worth addressing, open an issue to track them.
```

Pro plánované události je vstup `prompt` **vyžadován**, protože zde není žádný komentář, ze kterého by bylo možné extrahovat pokyny. Naplánované pracovní postupy běží bez uživatelského kontextu pro kontrolu oprávnění, takže pracovní postup musí udělit `contents: write` a `pull-requests: write`, pokud očekáváte, že OpenCode vytvoří pobočky nebo PR.

### Příklad žádosti o stažení

Automaticky kontrolovat PR, když jsou otevřeny nebo aktualizovány:

```yaml title=".github/workflows/opencode-review.yml"
name: opencode-review

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
      pull-requests: read
      issues: read
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false
      - uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          use_github_token: true
          prompt: |
            Review this pull request:
            - Check for code quality issues
            - Look for potential bugs
            - Suggest improvements
```

Pokud pro události `pull_request` není zadáno žádné `prompt`, OpenCode standardně přezkoumá požadavek na stažení.

### Příklad třídění problémů

Automaticky třídit nové problémy. Tento příklad filtruje účty starší než 30 dní, aby se snížil výskyt spamu:

```yaml title=".github/workflows/opencode-triage.yml"
name: Issue Triage

on:
  issues:
    types: [opened]

jobs:
  triage:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Check account age
        id: check
        uses: actions/github-script@v7
        with:
          script: |
            const user = await github.rest.users.getByUsername({
              username: context.payload.issue.user.login
            });
            const created = new Date(user.data.created_at);
            const days = (Date.now() - created) / (1000 * 60 * 60 * 24);
            return days >= 30;
          result-encoding: string

      - uses: actions/checkout@v6
        if: steps.check.outputs.result == 'true'
        with:
          persist-credentials: false

      - uses: anomalyco/opencode/github@latest
        if: steps.check.outputs.result == 'true'
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review this issue. If there's a clear fix or relevant docs:
            - Provide documentation links
            - Add error handling guidance for code examples
            Otherwise, do not comment.
```

Pro události `issues` je vstup `prompt` **vyžadován**, protože zde není žádný komentář, ze kterého by bylo možné extrahovat instrukce.

## Vlastní výzvy

Přepište výchozí výzvu a přizpůsobte chování OpenCode vašemu pracovnímu postupu.

```yaml title=".github/workflows/opencode.yml"
- uses: anomalyco/opencode/github@latest
  with:
    model: anthropic/claude-sonnet-4-5
    prompt: |
      Review this pull request:
      - Check for code quality issues
      - Look for potential bugs
      - Suggest improvements
```

To je užitečné pro vynucení konkrétních kritérií kontroly, standardů kódování nebo oblastí zaměření relevantních pro váš projekt.

## Příklady

Zde je několik příkladů, jak můžete použít OpenCode na GitHubu.

- **Vysvětlete problém**

Přidejte tento komentář do vydání GitHub.

  ```
  /opencode explain this issue
  ```

OpenCode si přečte celé vlákno včetně všech komentářů a odpoví jasným vysvětlením.

- **Opravit problém**

V čísle GitHub řekněte:

  ```
  /opencode fix this
  ```

A OpenCode vytvoří novou pobočku, implementuje změny a otevře PR se změnami.

- **Zkontrolujte PR a proveďte změny**

Zanechte následující komentář k GitHub PR.

  ```
  Delete the attachment from S3 when the note is removed /oc
  ```

OpenCode implementuje požadovanou změnu a zaváže ji ke stejnému PR.

- **Zkontrolujte konkrétní řádky kódu**

Zanechte komentář přímo na řádcích kódu v záložce "Soubory" PR. OpenCode automaticky detekuje soubor, čísla řádků a kontext rozdílů, aby poskytl přesné odpovědi.

  ```
  [Comment on specific lines in Files tab]
  /oc add error handling here
  ```

Při komentování konkrétních řádků obdrží OpenCode:
  - Přesný soubor, který se kontroluje
  - Konkrétní řádky kódu
  - Okolní rozdílový kontext
  - Informace o čísle linky

To umožňuje cílenější požadavky, aniž byste museli ručně zadávat cesty k souborům nebo čísla řádků.
