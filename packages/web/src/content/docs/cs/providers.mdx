OpenCode používá [AI SDK](https://ai-sdk.dev/) a [Models.dev](https://models.dev) k podpoře **75+ poskytovatelů LLM** a podporuje spouštění místních modelů.

Chcete-li přidat poskytovatele, musíte:

1. Přidejte klíče API pro poskytovatele pomocí příkazu `/connect`.
2. Nakonfigurujte poskytovatele v konfiguraci OpenCode.

---

### Přihlašovací údaje

Když přidáte klíče API poskytovatele pomocí příkazu `/connect`, uloží se
v `~/.local/share/opencode/auth.json`.

---

### Konfigurace

Poskytovatele si můžete přizpůsobit prostřednictvím sekce `provider` ve vašem OpenCode
configu.

---

#### Základní URL

Základní URL můžete přizpůsobit libovolnému poskytovateli nastavením možnosti `baseURL`. To je užitečné při používání služeb proxy nebo vlastních koncových bodů.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

## OpenCode Zen

OpenCode Zen je seznam modelů poskytnutých týmem OpenCode, které byly
testováno a ověřeno, aby dobře fungovalo s OpenCode. [Další informace](/docs/cs/zen).

:::tip
Pokud jste noví, doporučujeme začít s OpenCode Zen.
:::

1. Spusťte příkaz `/connect` v TUI, vyberte `OpenCode Zen` a přejděte na [opencode.ai/auth](https://opencode.ai/zen).

   ```txt
   /connect
   ```

2. Přihlaste se, přidejte své fakturační údaje a zkopírujte klíč API.

3. Vložte klíč API.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Spusťte `/models` v TUI, abyste viděli seznam modelů, které doporučujeme.

   ```txt
   /models
   ```

Funguje jako každý jiný poskytovatel v OpenCode a je zcela volitelné.

### Amazon Bedrock

Chcete-li použít Amazon Bedrock s OpenCode:

1. Přejděte do **Katalogu modelů** v konzole Amazon Bedrock a požádejte
   přístup k požadovaným modelům.

   :::tip
   Musíte mít přístup k modelu, který chcete v Amazon Bedrock.
   :::

2. **Nakonfigurujte ověřování** pomocí jedné z následujících metod:

   ***

   #### Proměnné prostředí (rychlý start)

   Při spuštění OpenCode nastavte jednu z těchto proměnných prostředí:

   ```bash
   # Option 1: Using AWS access keys
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # Option 2: Using named AWS profile
   AWS_PROFILE=my-profile opencode

   # Option 3: Using Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   Nebo si je přidejte do svého bash profilu:

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### Konfigurační soubor (doporučeno)

   Pro projektovou nebo trvalou konfiguraci použijte `opencode.json`:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **Dostupné možnosti:**
   - `region` - Oblast AWS (např. `us-east-1`, `eu-west-1`)
   - `profile` - AWS pojmenovaný profil z `~/.aws/credentials`
   - `endpoint` - Vlastní koncový bod URL pro koncové body VPC (alias pro obecnou možnost `baseURL`)

   :::tip
   Možnosti konfiguračního souboru mají přednost před proměnnými prostředí.
   :::

   ***

   #### Pokročilé: koncové body VPC

   Pokud pro Bedrock používáte koncové body VPC:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   Volba `endpoint` je alias pro generickou volbu `baseURL` s použitím terminologie specifické pro AWS. Pokud jsou zadány oba `endpoint` i `baseURL`, `endpoint` má přednost.
   :::

   ***

   #### Metody autentizace
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: Vytvořte uživatele IAM a vygenerujte přístupové klíče v konzole AWS
   - **`AWS_PROFILE`**: Použijte pojmenované profily ze `~/.aws/credentials`. Nejprve nakonfigurujte pomocí `aws configure --profile my-profile` nebo `aws sso login`
   - **`AWS_BEARER_TOKEN_BEDROCK`**: Generujte dlouhodobé klíče API z konzole Amazon Bedrock
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: Pro EKS IRSA (IAM role pro servisní účty) nebo jiná prostředí Kubernetes s federací OIDC. Tyto proměnné prostředí automaticky vkládá Kubernetes při používání anotací servisních účtů.

   ***

   #### Priorita ověřování

   Amazon Bedrock používá následující prioritu ověřování:
   1. **Bearer token** – proměnná prostředí `AWS_BEARER_TOKEN_BEDROCK` nebo token z příkazu `/connect`
   2. **AWS Credential Chain** – profil, přístupové klíče, sdílené přihlašovací údaje, role IAM, tokeny webové identity (EKS IRSA), metadata instance

   :::note
   Když je nastaven bearer token (prostřednictvím `/connect` nebo `AWS_BEARER_TOKEN_BEDROCK`), má přednost před všemi metodami přihlašovacích údajů AWS včetně nakonfigurovaných profilů.
   :::

3. Spuštěním příkazu `/models` vyberte požadovaný model.

   ```txt
   /models
   ```

:::note
Pro vlastní inferenční profily použijte název modelu a poskytovatele v klíči a nastavte vlastnost `id` na arn. Tím je zajištěno správné ukládání do mezipaměti.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Cloudflare AI Gateway

Cloudflare AI Gateway vám umožňuje přistupovat k modelům od OpenAI, Anthropic, Workers AI a dalších prostřednictvím jednotného koncového bodu. S [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) nepotřebujete samostatné klíče API pro každého poskytovatele.

1. Přejděte do [Cloudflare dashboard](https://dash.cloudflare.com/), přejděte na **AI** > **AI Gateway** a vytvořte novou bránu. Poznamenejte si své **ID účtu** a **ID brány**.

2. Spusťte příkaz `/connect` a vyhledejte **Cloudflare AI Gateway**.

   ```txt
   /connect
   ```

3. Po zobrazení výzvy zadejte své **ID účtu**.

   ```txt
   ┌ Enter your Cloudflare Account ID
   │
   │
   └ enter
   ```

4. Po zobrazení výzvy zadejte své **ID brány**.

   ```txt
   ┌ Enter your Cloudflare AI Gateway ID
   │
   │
   └ enter
   ```

5. Zadejte svůj token **Cloudflare API**.

   ```txt
   ┌ Gateway API token
   │
   │
   └ enter
   ```

6. Spuštěním příkazu `/models` vyberte model.

   ```txt
   /models
   ```

Modely můžete také přidat prostřednictvím konfigurace opencode.

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "cloudflare-ai-gateway": {
         "models": {
           "openai/gpt-4o": {},
           "anthropic/claude-sonnet-4": {}
         }
       }
     }
   }
   ```

Alternativně můžete místo použití `/connect` nastavit proměnné prostředí.

   ```bash title="~/.bash_profile"
   export CLOUDFLARE_ACCOUNT_ID=your-32-character-account-id
   export CLOUDFLARE_GATEWAY_ID=your-gateway-id
   export CLOUDFLARE_API_TOKEN=your-api-token
   ```

### GitLab Duo

:::caution[experimentální]
Podpora GitLab Duo v OpenCode je experimentální. Vlastnosti, konfigurace a
chování se může v budoucích verzích změnit.
:::

OpenCode se integruje s [platformou GitLab Duo Agent](https://docs.gitlab.com/user/duo_agent_platform/),
poskytuje AI agentní chat s nativním voláním nástrojů.

:::note[Požadavky licence]
Platforma GitLab Duo Agent vyžaduje předplatné GitLab **Premium** nebo **Ultimate**.
Je dostupná na GitLab.com i v GitLab Self-Managed.
Viz [Předpoklady platformy GitLab Duo Agent](https://docs.gitlab.com/user/duo_agent_platform/#prerequisites)
pro úplné požadavky.
:::

1. Spusťte příkaz `/connect` a vyberte GitLab.

   ```txt
   /connect
   ```

2. Vyberte způsob ověření:

   ```txt
   ┌ Select auth method
   │
   │ OAuth (Recommended)
   │ Personal Access Token
   └
   ```

   #### Použití OAuth (doporučeno)

   Vyberte **OAuth** a prohlížeč se otevře pro autorizaci.

   #### Použití osobního přístupového tokenu
   1. Přejděte do [Nastavení uživatele GitLab > Přístupové tokeny](https://gitlab.com/-/user_settings/personal_access_tokens)
   2. Klikněte na **Přidat nový token**
   3. Název: `OpenCode`, Rozsah: `api`
   4. Zkopírujte token (začíná `glpat-`)
   5. Zadejte jej do terminálu

3. Spuštěním příkazu `/models` zobrazíte dostupné modely.

   ```txt
   /models
   ```

K dispozici jsou tři modely založené na Claude:
   - **duo-chat-haiku-4-5** (výchozí) - Rychlé reakce na rychlé úkoly
   - **duo-chat-sonnet-4-5** - Vyvážený výkon pro většinu pracovních postupů
   - **duo-chat-opus-4-5** - Nejschopnější pro komplexní analýzu

:::note
Pokud nechcete, můžete také zadat proměnnou prostředí 'GITLAB_TOKEN'
k uložení tokenu v úložišti ověření opencode.
:::

##### Self-Hosted GitLab

:::note[poznámka o shodě]
OpenCode používá malý model pro některé úlohy AI, jako je generování názvu relace.
Ve výchozím nastavení používá `gpt-5-nano` hostovaný službou Zen. Pokud chcete OpenCode
omezit pouze na svou vlastní instanci hostovanou v GitLabu, přidejte do souboru
`opencode.json` následující nastavení. Doporučuje se také zakázat sdílení relací.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "small_model": "gitlab/duo-chat-haiku-4-5",
  "share": "disabled"
}
```

:::

Pro samostatně hostované instance GitLab:

```bash
export GITLAB_INSTANCE_URL=https://gitlab.company.com
export GITLAB_TOKEN=glpat-...
```

Pokud vaše instance provozuje vlastní bránu AI:

```bash
GITLAB_AI_GATEWAY_URL=https://ai-gateway.company.com
```

##### OAuth pro instance s vlastním hostitelem

##### Modely pracovního postupu platformy GitLab Duo Agent (DAP)

#### Volitelné konfigurace

V případě, že uvidíte funkci nebo model ze Helicone, který není automaticky nakonfigurován prostřednictvím opencode, můžete jej vždy nakonfigurovat sami.

Zde je [adresář modelů Helicone](https://helicone.ai/models), budete jej potřebovat k získání ID modelů, které chcete přidat.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Model ID (from Helicone's model directory page)
          "name": "GPT-4o", // Your own custom name for the model
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### Vlastní záhlaví

Helicone podporuje vlastní záhlaví pro funkce, jako je ukládání do mezipaměti, sledování uživatelů a správa relací. Přidejte je do konfigurace poskytovatele pomocí `options.headers`:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### Sledování relací

Funkce [Sessions](https://docs.helicone.ai/features/sessions) Helicone vám umožňuje seskupit související požadavky LLM dohromady. Použijte plugin [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session) k automatickému přihlášení každé konverzace OpenCode jako relace v Helicone.

```bash
npm install -g opencode-helicone-session
```

Přidejte to do své konfigurace.

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

Plugin vloží do vašich požadavků hlavičky `Helicone-Session-Id` a `Helicone-Session-Name`. Na stránce Sessions Helicone uvidíte každou OpenCode konverzaci uvedenou jako samostatnou relaci.

##### Běžné záhlaví Helicone

| Záhlaví | Popis |
| --------------------------- | -------------------------------------------------------------- |
| `Helicone-Cache-Enabled` | Povolit ukládání odpovědí do mezipaměti (`true`/`false`) |
| `Helicone-User-Id` | Sledování metrik podle uživatele |
| `Helicone-Property-[Name]` | Přidat uživatelské vlastnosti (např. `Helicone-Property-Environment`) |
| `Helicone-Prompt-Id` | Přidružit požadavky k verzím prompt |

Všechna dostupná záhlaví naleznete v [Helicone Header Directory](https://docs.helicone.ai/helicone-headers/header-directory).

OpenCode můžete nakonfigurovat tak, aby používal lokální modely pomocí nástroje `llama-server` z [llama.cpp](https://github.com/ggml-org/llama.cpp).

```json title="opencode.json" "llama.cpp" {5, 6, 8, 10-15}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "llama.cpp": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "llama-server (local)",
      "options": {
        "baseURL": "http://127.0.0.1:8080/v1"
      },

          "name": "Qwen3-Coder: a3b-30b (local)",
          "limit": {
            "context": 128000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

V tomto příkladu:

- `llama.cpp` je vlastní ID poskytovatele. Může to být libovolný řetězec.
- `npm` určuje balíček, který se má použít pro tohoto poskytovatele. Zde se `@ai-sdk/openai-compatible` používá pro jakékoli API kompatibilní s OpenAI.
- `name` je zobrazovaný název poskytovatele v uživatelském rozhraní.
- `options.baseURL` je koncový bod pro místní server.
- `models` je mapa ID modelů k jejich konfiguracím. Název modelu se zobrazí v seznamu pro výběr modelu.

## Vlastní poskytovatel

Chcete-li přidat jakéhokoli poskytovatele **kompatibilního s OpenAI**, který není uveden v příkazu `/connect`:

:::tip
S opencode můžete použít jakéhokoli poskytovatele kompatibilního s OpenAI. Většina moderních poskytovatelů AI nabízí API kompatibilní s OpenAI.
:::

1. Spusťte příkaz `/connect` a přejděte dolů na **Ostatní**.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. Zadejte jedinečné ID poskytovatele.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   Vyberte si zapamatovatelné ID, použijete ho ve svém konfiguračním souboru.
   :::

3. Zadejte váš klíč API pro poskytovatele.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in opencode.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. Vytvořte nebo aktualizujte soubor `opencode.json` v adresáři projektu:

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI ProviderDisplay Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

Zde jsou možnosti konfigurace:
   - **npm**: Balíček AI SDK k použití, `@ai-sdk/openai-compatible` pro poskytovatele kompatibilní s OpenAI (pro `/v1/chat/completions`). Pokud váš poskytovatel/model používá `/v1/responses`, použijte `@ai-sdk/openai`.
   - **name**: Zobrazovaný název v uživatelském rozhraní.
   - **modely**: Dostupné modely.
   - **options.baseURL**: URL koncového bodu API.
   - **options.apiKey**: Volitelně nastavte klíč API, pokud nepoužíváte auth.
   - **options.headers**: Volitelně nastavte vlastní záhlaví.

Více o pokročilých možnostech v příkladu níže.

5. Spusťte příkaz `/models` a váš vlastní poskytovatel a modely se objeví ve výběrovém seznamu.

---

##### Příklad

Zde je příklad nastavení možností `apiKey`, `headers` a modelu `limit`.

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI ProviderDisplay Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

Podrobnosti konfigurace:

- **apiKey**: Nastavte pomocí syntaxe proměnné `env`, [další informace](/docs/cs/config/#proměnné-prostředí).
- **záhlaví**: Vlastní záhlaví odeslaná s každým požadavkem.
- **limit.context**: Maximální vstupní tokeny, které model přijímá.
- **limit.output**: Maximální počet tokenů, které může model vygenerovat.

Pole `limit` umožňují OpenCode pochopit, kolik kontextu vám zbývá. Standardní poskytovatelé je automaticky stahují z models.dev.

## Odstraňování problémů

Pokud máte potíže s konfigurací poskytovatele, zkontrolujte následující:

1. **Zkontrolujte nastavení ověřování**: Spusťte `opencode auth list` a zjistěte, zda přihlašovací údaje
   pro poskytovatele jsou přidány do vaší konfigurace.

To se netýká poskytovatelů jako Amazon Bedrock, kteří se při ověřování spoléhají na proměnné prostředí.

2. U vlastních poskytovatelů zkontrolujte konfiguraci opencode a:
   - Ujistěte se, že ID poskytovatele použité v příkazu `/connect` odpovídá ID ve vaší konfiguraci opencode.
   - Pro poskytovatele je použit správný balíček npm. Například použijte `@ai-sdk/cerebras` pro Cerebras. A pro všechny ostatní poskytovatele kompatibilní s OpenAI použijte `@ai-sdk/openai-compatible` (pro `/v1/chat/completions`); pokud model používá `/v1/responses`, použijte `@ai-sdk/openai`. U smíšených nastavení pod jedním poskytovatelem můžete přepsat na model pomocí `provider.npm`.
   - Zkontrolujte, zda je v poli `options.baseURL` použit správný koncový bod API.
