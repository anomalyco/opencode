Příkaz `opencode serve` spouští headless HTTP server, který zpřístupňuje koncový bod OpenAPI pro klienty OpenCode.

---

### Použití

```bash
opencode serve [--port <number>] [--hostname <string>] [--cors <origin>]
```

#### Možnosti

| Vlajka | Popis | Výchozí |
| ---------------- | ------------------------------------ | ----------------- |
| `--port` | Port k poslechu na | `4096` |
| `--hostname` | Název hostitele k poslechu | `127.0.0.1` |
| `--mdns` | Povolit zjišťování mDNS | `false` |
| `--mdns-domain` | Vlastní název domény pro službu mDNS | `opencode.local` |
| `--cors` | Další původ prohlížeče pro povolení | `[]` |

`--cors` lze absolvovat vícekrát:

```bash
opencode serve --cors http://localhost:5173 --cors https://app.example.com
```

---

### Autentizace

Nastavte `OPENCODE_SERVER_PASSWORD` na ochranu serveru pomocí základního ověření HTTP. Výchozí uživatelské jméno je `opencode` nebo jej přepíšete nastavením `OPENCODE_SERVER_USERNAME`. To platí pro `opencode serve` i `opencode web`.

```bash
OPENCODE_SERVER_PASSWORD=your-password opencode serve
```

---

### Jak to funguje

Když spustíte `opencode`, spustí se TUI a server. Kde je TUI
klient, který komunikuje se serverem. Server odhaluje specifikaci OpenAPI 3.1
koncový bod. Tento koncový bod se také používá ke generování [SDK](/docs/cs/sdk).

:::tip
Použijte server OpenCode k programové interakci s OpenCode.
:::

Tato architektura umožňuje OpenCode podporovat více klientů a vám programově komunikovat s OpenCode.

Spuštěním `opencode serve` můžete spustit samostatný server. Pokud máte
opencode TUI běží, `opencode serve` spustí nový server.

---

#### Připojte se k existujícímu serveru

Když spustíte TUI, náhodně přiřadí port a název hostitele. Místo toho můžete předat `--hostname` a `--port` [vlajky](/docs/cs/cli). Poté použijte toto pro připojení k jeho serveru.

Koncový bod [`/tui`](#tui) lze použít k řízení TUI přes server. Můžete například předvyplnit nebo spustit výzvu. Toto nastavení používají pluginy OpenCode [IDE](/docs/cs/ide).

---

## Spec

Server publikuje specifikaci OpenAPI 3.1, kterou lze zobrazit na:

```
http://<hostname>:<port>/doc
```

Například `http://localhost:4096/doc`. Specifikace použijte ke generování klientů nebo ke kontrole typů požadavků a odpovědí. Nebo si to prohlédněte v průzkumníku Swagger.

### Soubory

| Metoda | Cesta | Popis | Odpověď |
| ------ | ------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| `GET` | `/find?pattern=<pat>` | Hledat text v souborech | Pole shodných objektů se `path`, `lines`, `line_number`, `absolute_offset`, `submatches` |
| `GET` | `/find/file?query=<q>` | Najít soubory a adresáře podle názvu | `string[]` (cesty) |
| `GET` | `/find/symbol?query=<q>` | Najít symboly pracovního prostoru | <a href={typesUrl}><code>Symbol[]</code></a> |
| `GET` | `/file?path=<path>` | Seznam souborů a adresářů | <a href={typesUrl}><code>FileNode[]</code></a> |
| `GET` | `/file/content?path=<p>` | Číst soubor | <a href={typesUrl}><code>FileContent</code></a> |
| `GET` | `/file/status` | Získat stav pro sledované soubory | <a href={typesUrl}><code>File[]</code></a> |

#### Parametry dotazu `/find/file`

- `query` (povinné) — hledaný řetězec (fuzzy shoda)
- `type` (volitelné) — omezení výsledků na `"file"` nebo `"directory"`
- `directory` (volitelné) – přepíše kořen projektu pro vyhledávání
– `limit` (volitelné) – maximální počet výsledků (1–200)
- `dirs` (volitelné) — starší příznak (`"false"` vrací pouze soubory)
