## 背景

開源模型已經變得非常強大。它們在寫程式任務上的表現已接近專有模型。由於許多供應商都能以具競爭力的價格提供服務，它們通常便宜得多。

然而，要獲得穩定、低延遲的存取可能很困難。各家供應商的品質和可用性不一。

:::tip
我們測試了一組精選的模型和供應商，它們與 OpenCode 搭配運作良好。
:::

為了解決這個問題，我們做了幾件事：

1. 我們測試了一組精選的開源模型，並與其團隊討論如何以最佳方式運行。
2. 接著，我們與幾家供應商合作，確保這些模型獲得正確的服務。
3. 最後，我們對模型與供應商的組合進行基準測試，整理出一份值得推薦的清單。

Go 和 Go Plus 均可存取這些模型；請依您的使用量選擇合適的方案。

## 運作方式

OpenCode Go 的運作方式與 OpenCode 中的其他供應商相同。

1. 登入 **<a href={console}>OpenCode Console</a>**，訂閱 Go 或 Go Plus，然後複製您的 API key。
2. 在 TUI 中執行 `/connect` 命令，選擇 `OpenCode Go`，然後貼上您的 API key。
3. 在 TUI 中執行 `/models`，查看可透過 Go 使用的模型清單。

## 可以在哪裡使用？

OpenCode Go 適用於 [OpenCode](https://opencode.ai) 以及其他會產生類似請求的寫程式 Agent。我們會監控流量，以識別影響其他使用者體驗的濫用行為。

您的用戶端應：

1. 傳送典型的寫程式 Agent 流量
2. 使用自身專屬的 user agent 識別資訊（例如 `my-coding-agent/1.0`），而非通用的 SDK 或 HTTP 函式庫名稱。
3. 為每段對話在 `x-opencode-session` 中傳送穩定的工作階段 ID，以便我們最佳化路由和提示詞快取。

| **ZCode**         | Go 可辨識其原生工作階段標頭。我們[請求支援 `x-opencode-session`](https://github.com/zai-org/feedback/issues/492) 仍未關閉，但已不再需要傳送這個特定標頭。                                                                           |

| **Kilo Code CLI** | 包含 [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) 的建置版本恢復了 OpenCode 工作階段標頭。此修正僅適用於 CLI，不適用於 VS Code 擴充套件。請參閱 [issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723)。 |

### 超出限制的使用量

如果您的 Zen 餘額中還有額度，可以在控制台中啟用 **使用餘額（Use balance）** 選項。啟用後，當您達到使用限制時，Go 會改用 Zen 餘額，而不是阻擋請求。

---

### 為什麼部分模型的使用額度較低

使用 Go 時，包含的每月使用額度因模型而異。

對大多數模型而言，我們透過大量採購折扣和預留 GPU 容量來達成此目標，再以更高的每月使用額度將節省的成本回饋給您。

對於部分模型，我們尚未有機會議定折扣或以較低成本託管，原因可能是模型剛推出，或其公開價格已經過折扣。

對於這些模型，您獲得的用量仍會比直接向模型供應商付費多一些；這就是它們包含的每月使用額度較低的原因。

## 目標

我們建立 OpenCode Go 的目的是：

1. 透過低成本訂閱，讓更多人能**輕鬆使用** AI 寫程式。
2. 提供**穩定可靠**的方式來存取最佳開源寫程式模型。
3. 精選經過**測試與效能評估**、適合寫程式 Agent 使用的模型。
4. 允許您在 OpenCode 中同時使用任何其他供應商，確保**不被單一供應商綁定**。
