Создай интерактивный Halloween-веб-сайт для digital-агентства под названием:

«ЛАБОРАТОРИЯ КОРПОРАТИВНЫХ МОНСТРОВ»

Главный персонаж первой версии:

👹 МОНСТР №001 — МОНСТР ДЕДЛАЙНОВ

ВАЖНО:
Сначала полностью реализуй рабочий MVP и механику. Не трать время на сложные визуальные эффекты, пока основная механика не работает.

## 1. КОНЦЕПЦИЯ

Сайт — это корпоративная Halloween-лаборатория, в которой сотрудники компании пытаются победить общего рабочего монстра.

Монстр появился из реальных рабочих страхов сотрудников: дедлайнов, срочных задач, внезапных правок, сообщений «нужно было вчера» и постоянного изменения требований.

Каждый сотрудник может за 10–20 секунд написать своё «заклинание» против монстра.

AI оценивает заклинание, определяет нанесённый урон и генерирует реакцию монстра.

HP монстра ОБЩИЙ ДЛЯ ВСЕЙ КОМПАНИИ.

Если один сотрудник нанёс 18 HP урона, следующий сотрудник должен увидеть уже уменьшенный общий HP.

Участие добровольное. Пользователь может просто открыть страницу и посмотреть состояние монстра.

# 4. МЕХАНИКА ЗАКЛИНАНИЯ

Пользователь вводит обычную рабочую фразу.

Например:

«Сначала получить нормальное ТЗ»

AI должен превратить её в магическое заклинание:

SCOPEUS DEFINITUS

И определить силу атаки.

Другой пример:

«Не писать “срочно”, если задача на самом деле не срочная»

→

URGENTIUM BANISH

AI должен учитывать содержание заклинания и его соответствие слабости монстра.

---

# 5. УРОН

Используй диапазоны:

0–4 = MISS

5–9 = WEAK

10–14 = NORMAL

15–24 = STRONG

25–30 = CRITICAL

Максимальный урон одной атаки — 30 HP.

Результат должен содержать:

damage

attack_name

description

reaction

effect

Внутренний формат можно сделать таким:

{
"damage": 18,
"attack_name": "SCOPEUS DEFINITUS",
"description": "Фиксация границ задачи до начала работы лишает монстра возможности создавать внезапные правки.",
"reaction": "НЕТ! Только не согласованный scope!",
"effect": "strong"
}

Но JSON НЕ должен отображаться пользователю.

Пользователь должен видеть красивый результат атаки.

# 6. РЕАКЦИИ МОНСТРА

Для MISS:

«Это не заклинание. Это просьба.»

«Слабая попытка. Я уже поставил тебе дедлайн.»

Для CRITICAL:

«КТО НАУЧИЛ ВАС ПЛАНИРОВАТЬ?!»

Можно выбирать реакцию случайным образом из соответствующего списка.

# 7. СОСТОЯНИЕ МОНСТРА

В зависимости от HP меняй его состояние.

HP > 70:

Монстр уверенный.

HP 40–70:

Монстр начинает нервничать.

HP 1–39:

Монстр в панике.

HP = 0:

Монстр побеждён.

Состояние должно влиять на визуал и реакцию монстра.

---

# 8. ОБЩИЙ HP

Это очень важно.

HP должен быть общим для всех пользователей.

Не делай основное состояние только через localStorage.

Создай отдельный слой хранения состояния:

monsterState

Например:

{
"hp": 100,
"totalDamage": 0,
"spellsCount": 0,
"lastAttack": null
}

Для MVP можно сделать mock/backend abstraction, чтобы позже подключить настоящий backend.

Архитектуру сделай так, чтобы глобальное состояние можно было легко заменить на настоящий API/database.

# 13. АНИМАЦИЯ АТАКИ

После нажатия:

🪄 ЗАПУСТИТЬ ЗАКЛИНАНИЕ

покажи короткую анимацию.

Пример:

1. кнопка активируется
2. вокруг поля появляется магический/glitch-эффект
3. появляется название заклинания

6. появляется −18 HP
7. монстр реагирует
8. показывается результат

Вся анимация должна занимать примерно 1–2 секунды.

Не заставляй пользователя ждать.

В дальнейшем AI service должен легко заменяться на реальный API.
