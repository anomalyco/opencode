---
title: 智能体技能（Agent Skills）
description: 通过 SKILL.md 定义来实现可复用行为
---

智能体技能（Agent Skills）可让 OpenCode 从你的代码仓库或主目录中发现可复用指令。
工具型智能体（tool-agents）的原生技能会按需加载可识别的可用技能，并在需要时加载完整内容。

---

## 部署文件

为每个技能名称创建一个独立文件夹，并在其中放入一个 `SKILL.md` 文件。
OpenCode 会检索以下路径：

- 项目级配置: `.opencode/skills/<name>/SKILL.md`
- 全局配置: `~/.config/opencode/skills/<name>/SKILL.md`
- 兼容Claude项目级配置：`.claude/skills/<name>/SKILL.md`
- 兼容Claude全局配置： `~/.claude/skills/<name>/SKILL.md`
- 兼容agent项目级配置：`.agents/skills/<name>/SKILL.md`
- 兼容agent全局配置：`~/.agents/skills/<name>/SKILL.md`

---

## 发现机制

对于本地项目路径，OpenCode 会从当前工作目录向上递归查找，直到抵达 Git 工作区根目录。
沿途会任意匹配`.opencode/skills/*/SKILL.md`以及`.claude/skills/*/SKILL.md`或者`.agents/skills/*/SKILL.md`

也会从以下全局路径下加载： 
- `~/.config/opencode/skills/*/SKILL.md`
- `~/.claude/skills/*/SKILL.md`
- `~/.agents/skills/*/SKILL.md`.

---

## 编写前置元数据（Frontmatter）

每个 SKILL.md 文件必须以 YAML 前置元数据（frontmatter）开头。
仅以下字段会被识别：

- `name`（必填）
- `description`（必填）
- `license`（可选）
- `compatibility`（可选）
- `metadata`（可选）元数据（字符串键值对映射(string-to-string map))

未知的 frontmatter 栏位将被忽略。

---

## 名称校验规则

`name` 必须符合：

- 长度为 1–64 个字符
- 仅包含小写字母、数字，且仅允许使用单个连字符（-）作为分隔符
- 不能以连字符（-）开头或结尾
- 不能包含连续的两个连字符（--）
- 需与包含`SKILL.md`文件的文件夹名称完全一致

等效正则表达式：

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

---

## 遵循长度规则

`description` 必须是 1-1024 个字符。
请保持足够具体，以便智能体正确选择。

---

## 举个例子

像这样创建 `.opencode/skills/git-release/SKILL.md` :

```markdown
---
name: git-release
description: Create consistent releases and changelogs
license: MIT
compatibility: opencode
metadata:
  audience: maintainers
  workflow: github
---

## What I do

- Draft release notes from merged PRs
- Propose a version bump
- Provide a copy-pasteable `gh release create` command

## When to use me

Use this when you are preparing a tagged release.
Ask clarifying questions if the target versioning scheme is unclear.
```

## 识别工具描述

OpenCode 列出了 `skill` 工具描述中的可用技能。
每个条目都包含技能名称和描述：

```xml
<available_skills>
  <skill>
    <name>git-release</name>
    <description>Create consistent releases and changelogs</description>
  </skill>
</available_skills>
```

智能体通过调用工具来加载技能：

```
skill({ name: "git-release" })
```

## 配置权限

在 `opencode.json` 中使用基于模式的权限，控制智能体可以访问哪些技能：

```json
{
  "permission": {
    "skill": {
      "*": "allow",
      "pr-review": "allow",
      "internal-*": "deny",
      "experimental-*": "ask"
    }
  }
}
```

| 权限    | 行为                       |
| ------- | -------------------------- |
| `allow` | 技能立即加载               |
| `deny`  | 对智能体隐藏技能，访问被拒绝 |
| `ask`   | 加载前提示用户确认         |

模式支持通配符：`internal-*` 匹配 `internal-docs`、`internal-tools` 等。

---

## 覆盖每个智能体

为特定智能体赋予与全局默认值不同的权限。

**对于自定义智能体（在智能体前置元数据(frontmatter)中）：**

```yaml
---
permission:
  skill:
    "documents-*": "allow"
---
```

对于内置智能体（在 opencode.json 中）：

```json
{
  "agent": {
    "plan": {
      "permission": {
        "skill": {
          "internal-*": "allow"
        }
      }
    }
  }
}
```

---

## 禁用技能工具

对不应使用技能的智能体完全禁用技能：

**对于自定义智能体**：

```yaml
---
tools:
  skill: false
---
```

**对于内置智能体**：

```json
{
  "agent": {
    "plan": {
      "tools": {
        "skill": false
      }
    }
  }
}
```

禁用后，`<available_skills>` 部分将被完全省略。

---

## 加载问题排查

如果某项技能沒有显示：

1. 验证 `SKILL.md` 拼写为全部大写
2. 检查 frontmatter 是否包括 `name` 和 `description`
3. 确保技能名称在所有路径下都是唯一的
4. 检查查询 —— 被设为 `deny` 的技能对智能体隐藏
