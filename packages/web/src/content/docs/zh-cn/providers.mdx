OpenCode 使用 [AI SDK](https://ai-sdk.dev/) 与 [Models.dev](https://models.dev) 来支持 **75+ LLM providers**，并支持运行本地 models。

要添加 provider，需要：

1. 使用 `/connect` 命令添加该 provider 的 API keys。
2. 在 OpenCode 配置中配置该 provider。

---

### Credentials

当你通过 `/connect` 添加 provider 的 API keys 后，它们会存储在 `~/.local/share/opencode/auth.json`。

---

### Config

你可以通过 OpenCode 配置中的 `provider` 部分自定义 providers。

---

#### Base URL

你可以通过设置 `baseURL` 来自定义任意 provider 的基础 URL。这在使用代理服务或自定义端点时很有用。

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

### Amazon Bedrock

在 OpenCode 中使用 Amazon Bedrock：

1. 前往 Amazon Bedrock 控制台的 **Model catalog**，申请你要使用的 models 访问权限。

   :::tip
   你必须拥有想使用的 Amazon Bedrock model 的访问权限。
   :::

2. **配置认证**，选择以下方法之一：

   #### 环境变量（快速开始）

   在运行 opencode 时设置以下环境变量之一：

   ```bash
   # 选项 1：使用 AWS access keys
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # 选项 2：使用命名 AWS profile
   AWS_PROFILE=my-profile opencode

   # 选项 3：使用 Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   或添加到 bash profile：

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   #### 配置文件（推荐）

   如需项目级或持久配置，使用 `opencode.json`：

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **可用选项：**
   - `region` - AWS region（例如 `us-east-1`、`eu-west-1`）
   - `profile` - `~/.aws/credentials` 中的 AWS profile
   - `endpoint` - VPC endpoints 的自定义 URL（通用 `baseURL` 选项的别名）

   :::tip
   配置文件选项优先于环境变量。
   :::

   #### 高级：VPC Endpoints

   使用 VPC endpoints 时：

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   `endpoint` 是通用 `baseURL` 的别名，使用 AWS 术语。如果同时指定 `endpoint` 与 `baseURL`，`endpoint` 优先。
   :::

   #### 认证方式
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**：在 AWS 控制台创建 IAM 用户并生成 access keys
   - **`AWS_PROFILE`**：使用 `~/.aws/credentials` 中的命名 profile。先用 `aws configure --profile my-profile` 或 `aws sso login` 配置
   - **`AWS_BEARER_TOKEN_BEDROCK`**：在 Amazon Bedrock 控制台生成长期 API key
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**：用于 EKS IRSA（Service Account 的 IAM Role）或其他使用 OIDC federation 的 Kubernetes 环境。Kubernetes 在使用 service account annotations 时会自动注入这些环境变量

   #### 认证优先级

   Amazon Bedrock 的认证优先级如下：
   1. **Bearer Token** - `AWS_BEARER_TOKEN_BEDROCK` 环境变量或 `/connect` 提供的 token
   2. **AWS Credential Chain** - profile、access keys、共享凭证、IAM roles、Web Identity Tokens（EKS IRSA）、实例元数据

   :::note
   当设置了 bearer token（通过 `/connect` 或 `AWS_BEARER_TOKEN_BEDROCK`），它会优先于所有 AWS 凭证方式（包括已配置 profile）。
   :::

3. 运行 `/models` 选择要使用的 model。

   ```txt
   /models
   ```

### Azure OpenAI

:::note
如果出现 “I'm sorry, but I cannot assist with that request” 错误，尝试将 Azure 资源的内容过滤从 **DefaultV2** 改为 **Default**。
:::

1. 前往 [Azure portal](https://portal.azure.com/) 创建 **Azure OpenAI** 资源。你需要：
   - **Resource name**：作为 API 端点的一部分（`https://RESOURCE_NAME.openai.azure.com/`）
   - **API key**：资源中的 `KEY 1` 或 `KEY 2`

2. 前往 [Azure AI Foundry](https://ai.azure.com/) 部署 model。

   :::note
   部署名称必须与 model 名称一致，否则 opencode 无法正常工作。
   :::

3. 运行 `/connect` 并搜索 **Azure**。

   ```txt
   /connect
   ```

4. 输入 API key。

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

5. 将 resource name 设置为环境变量：

   ```bash
   AZURE_RESOURCE_NAME=XXX opencode
   ```

   或添加到 bash profile：

   ```bash title="~/.bash_profile"
   export AZURE_RESOURCE_NAME=XXX
   ```

6. 运行 `/models` 选择已部署的 model。

   ```txt
   /models
   ```

### Cloudflare AI Gateway

Cloudflare AI Gateway 允许你通过统一端点访问 OpenAI、Anthropic、Workers AI 等 models。借助 [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/)，无需为每个 provider 单独配置 API keys。

1. 前往 [Cloudflare dashboard](https://dash.cloudflare.com/)，进入 **AI** > **AI Gateway** 并创建新的 gateway。

2. 将 Account ID 与 Gateway ID 设置为环境变量：

   ```bash title="~/.bash_profile"
   export CLOUDFLARE_ACCOUNT_ID=your-32-character-account-id
   export CLOUDFLARE_GATEWAY_ID=your-gateway-id
   ```

3. 运行 `/connect` 并搜索 **Cloudflare AI Gateway**。

   ```txt
   /connect
   ```

4. 输入 Cloudflare API token。

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

   或设置环境变量：

   ```bash title="~/.bash_profile"
   export CLOUDFLARE_API_TOKEN=your-api-token
   ```

5. 运行 `/models` 选择 model。

   ```txt
   /models
   ```

   你也可以通过 opencode 配置添加 models。

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "cloudflare-ai-gateway": {
         "models": {
           "openai/gpt-4o": {},
           "anthropic/claude-sonnet-4": {}
         }
       }
     }
   }
   ```

### GitLab Duo

GitLab Duo 通过 GitLab 的 Anthropic proxy 提供原生 tool calling 的 AI agentic chat。

1. 运行 `/connect` 并选择 GitLab。

   ```txt
   /connect
   ```

2. 选择认证方式：

   ```txt
   ┌ Select auth method
   │
   │ OAuth (Recommended)
   │ Personal Access Token
   └
   ```

   #### 使用 OAuth（推荐）

   选择 **OAuth**，浏览器会打开并进行授权。

   #### 使用 Personal Access Token
   1. 前往 [GitLab User Settings > Access Tokens](https://gitlab.com/-/user_settings/personal_access_tokens)
   2. 点击 **Add new token**
   3. Name：`OpenCode`，Scopes：`api`
   4. 复制 token（以 `glpat-` 开头）
   5. 在终端中输入

3. 运行 `/models` 查看可用 models。

   ```txt
   /models
   ```

   可用的 Claude models：
   - **duo-chat-haiku-4-5**（默认）- 快速响应
   - **duo-chat-sonnet-4-5** - 适合大多数工作流的平衡性能
   - **duo-chat-opus-4-5** - 复杂分析最强

##### 自托管 GitLab

用于自托管 GitLab：

```bash
GITLAB_INSTANCE_URL=https://gitlab.company.com GITLAB_TOKEN=glpat-xxxxxxxxxxxxxxxxxxxx opencode
```

或添加到 bash profile：

```bash title="~/.bash_profile"
export GITLAB_INSTANCE_URL=https://gitlab.company.com
export GITLAB_TOKEN=glpat-xxxxxxxxxxxxxxxxxxxx
```

##### 配置

在 `opencode.json` 中配置：

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "gitlab": {
      "options": {
        "instanceUrl": "https://gitlab.com",
        "featureFlags": {
          "duo_agent_platform_agentic_chat": true,
          "duo_agent_platform": true
        }
      }
    }
  }
}
```

##### GitLab API Tools（可选）

如需访问 GitLab tools（merge requests、issues、pipelines、CI/CD 等）：

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@gitlab/opencode-gitlab-plugin"]
}
```

该 plugin 提供完整的 GitLab 仓库管理能力，包括 MR 审查、issue 跟踪、pipeline 监控等。

`global` region 可提升可用性并减少错误且无额外成本。如有数据驻留要求，请使用区域端点（如 `us-central1`）。[了解更多](https://cloud.google.com/vertex-ai/generative-ai/docs/partner-models/use-partner-models#regional_and_global_endpoints)

#### 可选配置

当 Helicone 中的某些功能或 model 无法通过 opencode 自动配置时，你可以手动配置。

这里有 [Helicone's Model Directory](https://helicone.ai/models)，用于获取 model IDs。

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Model ID (from Helicone's model directory page)
          "name": "GPT-4o", // Your own custom name for the model
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### 自定义 Headers

Helicone 支持自定义 headers，用于缓存、用户跟踪、会话管理等功能。通过 `options.headers` 添加：

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### Session tracking

Helicone 的 [Sessions](https://docs.helicone.ai/features/sessions) 功能可将相关 LLM 请求分组。使用 [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session) plugin 可将每次 OpenCode 会话自动记录为 Helicone session。

```bash
npm install -g opencode-helicone-session
```

添加到配置：

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

##### 常见 Helicone headers

| -------------------------- | ---------------------------------------------------- |

要添加 `/connect` 中未列出的 **OpenAI-compatible** provider：

:::tip
你可以在 opencode 中使用任意 OpenAI-compatible provider。多数现代 AI providers 都提供 OpenAI-compatible API。
:::

1. 运行 `/connect` 并向下滚动到 **Other**。

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. 输入 provider 的唯一 ID。

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   请选择容易记忆的 ID，你将在配置文件中使用它。
   :::

3. 输入 provider 的 API key。

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in opencode.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. 在项目目录创建或更新 `opencode.json`：

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI ProviderDisplay Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   配置选项说明：
   - **npm**：使用的 AI SDK 包，OpenAI-compatible providers 使用 `@ai-sdk/openai-compatible`
   - **name**：UI 中的展示名称
   - **models**：可用 models
   - **options.baseURL**：API 端点 URL
   - **options.apiKey**：可选设置 API key（如果未使用 auth）
   - **options.headers**：可选自定义 headers

   更多高级选项见下方示例。

5. 运行 `/models`，你的自定义 provider 与 models 会出现在选择列表中。

##### 示例

以下示例设置了 `apiKey`、`headers` 与 model `limit`：

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI ProviderDisplay Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

配置细节：

- **apiKey**：使用 `env` 变量语法设置，[了解更多](/docs/config#env-vars)。
- **headers**：每次请求发送的自定义 headers。
- **limit.context**：model 接收的最大输入 tokens。
- **limit.output**：model 可生成的最大 tokens。

`limit` 字段让 OpenCode 了解剩余上下文空间。标准 providers 会从 models.dev 自动获取这些信息。

## Troubleshooting

如果 provider 配置遇到问题，请检查：

1. **检查 auth 配置**：运行 `opencode auth list` 查看该 provider 的凭证是否已添加。

   这不适用于像 Amazon Bedrock 这样的 providers，它们通过环境变量认证。

2. 对于自定义 providers，检查 opencode 配置：
   - 确保 `/connect` 中使用的 provider ID 与 opencode 配置中的 ID 一致。
   - 确保使用正确的 npm 包。例如 Cerebras 用 `@ai-sdk/cerebras`，其他 OpenAI-compatible providers 用 `@ai-sdk/openai-compatible`。
   - 确保 `options.baseURL` 中的 API 端点正确。
