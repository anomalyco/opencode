Agents 是针对特定任务与工作流的专用 AI 助手。它们允许你创建带有自定义 prompt、模型与工具访问权限的专注工具。

:::tip
使用 plan agent 来分析代码并审查建议，但不进行任何代码修改。
:::

你可以在会话中切换不同的 agent，或通过 `@` mention 调用它们。

---

## 类型

OpenCode 中有两种类型的 agent：primary agent 与 subagent。

---

### Primary agents

Primary agents 是你直接交互的主要助手。你可以使用 **Tab** 键轮换它们，或使用你配置的 `switch_agent` 快捷键。这些 agents 负责主要对话，并可访问所有已配置的工具。

:::tip
你可以在会话中使用 **Tab** 键切换 primary agents。
:::

OpenCode 内置两个 primary agent：**Build** 与 **Plan**。我们将在下文介绍。

---

### Subagents

Subagents 是可由 primary agents 调用的专用助手，用于特定任务。你也可以在消息中通过 **@ mention** 手动调用它们。

OpenCode 内置两个 subagent：**General** 与 **Explore**。我们将在下文介绍。

---

## Built-in

OpenCode 内置两个 primary agents 和两个 subagents。

---

### Build

_Mode_: `primary`

Build 是 **默认** 的 primary agent，启用所有工具。这是进行开发工作时的标准 agent，拥有对文件操作与系统命令的完整访问权限。

---

### Plan

_Mode_: `primary`

一个用于规划与分析的受限 agent。我们使用权限系统来提供更强控制并防止非预期改动。
默认情况下，以下内容均为 `ask`：

- `file edits`：所有写入、补丁与编辑
- `bash`：所有 bash 命令

当你希望 LLM 分析代码、提出修改建议或生成计划但不实际修改代码库时，这个 agent 很有用。

---

### General

_Mode_: `subagent`

一个用于研究复杂问题、搜索代码、执行多步骤任务的通用 agent。当你需要查找关键词或文件，且不确定第一次就能找到正确匹配时使用。

---

### Explore

_Mode_: `subagent`

专注于快速探索代码库的 agent。当你需要按模式快速查找文件、搜索关键字或回答代码库相关问题时使用。

---

## 使用

1. 对 primary agents，使用 **Tab** 键在会话中轮换。你也可以使用已配置的 `switch_agent` 快捷键。

2. Subagents 的调用方式：
   - **自动**：primary agents 会根据描述自动调用 subagent 执行专门任务。
   - 手动：在消息中通过 **@ mention** 调用 subagent，例如：

     ```txt frame="none"
     @general help me search for this function
     ```

3. **会话间导航**：当 subagent 创建自己的子会话时，你可以在父会话与所有子会话之间导航：
   - **\<Leader>+Right**（或你配置的 `session_child_cycle` 快捷键）向前轮换 parent → child1 → child2 → ... → parent
   - **\<Leader>+Left**（或你配置的 `session_child_cycle_reverse` 快捷键）向后轮换 parent ← child1 ← child2 ← ... ← parent

   这使你能够在主对话与专用 subagent 工作之间无缝切换。

## 配置

你可以自定义内置 agents，或通过配置创建自己的 agents。agents 有两种配置方式：

---

### JSON

在 `opencode.json` 配置文件中定义 agents：

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "{file:./prompts/build.txt}",
      "tools": {
        "write": true,
        "edit": true,
        "bash": true
      }
    },
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-haiku-4-20250514",
      "tools": {
        "write": false,
        "edit": false,
        "bash": false
      }
    },
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "You are a code reviewer. Focus on security, performance, and maintainability.",
      "tools": {
        "write": false,
        "edit": false
      }
    }
  }
}
```

---

### Markdown

你也可以用 markdown 文件定义 agents。将它们放在：

- 全局：`~/.config/opencode/agents/`
- 项目级：`.opencode/agents/`

```markdown title="~/.config/opencode/agents/review.md"
---
description: Reviews code for quality and best practices
mode: subagent
model: anthropic/claude-sonnet-4-20250514
temperature: 0.1
tools:
  write: false
  edit: false
  bash: false
---

You are in code review mode. Focus on:

- Code quality and best practices
- Potential bugs and edge cases
- Performance implications
- Security considerations

Provide constructive feedback without making direct changes.
```

markdown 文件名即为 agent 名称。例如 `review.md` 会创建一个 `review` agent。

---

## 选项

我们来详细看看这些配置选项。

---

### Description

使用 `description` 选项来简要说明 agent 的作用及使用场景。

```json title="opencode.json"
{
  "agent": {
    "review": {
      "description": "Reviews code for best practices and potential issues"
    }
  }
}
```

这是一个 **必需** 的配置项。

---

### Temperature

使用 `temperature` 配置控制 LLM 回复的随机性与创造力。

较低的值使回复更聚焦、更确定；较高的值会增加创造力与变化度。

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "temperature": 0.1
    },
    "creative": {
      "temperature": 0.8
    }
  }
}
```

Temperature 常见范围为 0.0 到 1.0：

- **0.0-0.2**：非常聚焦且确定，适合代码分析与规划
- **0.3-0.5**：平衡且有一定创造力，适合一般开发任务
- **0.6-1.0**：更有创造力与变化性，适合头脑风暴与探索

```json title="opencode.json"
{
  "agent": {
    "analyze": {
      "temperature": 0.1,
      "prompt": "{file:./prompts/analysis.txt}"
    },
    "build": {
      "temperature": 0.3
    },
    "brainstorm": {
      "temperature": 0.7,
      "prompt": "{file:./prompts/creative.txt}"
    }
  }
}
```

如果未指定 temperature，OpenCode 会使用模型的默认值；通常多数模型为 0，Qwen 模型为 0.55。

---

### Max steps

使用 `maxSteps` 控制 agent 在被强制仅输出文本之前可执行的最大 agentic 迭代次数。这样可以让希望控制成本的用户限制 agent 的行动次数。

若未设置，agent 会继续迭代，直到模型选择停止或用户中断会话。

```json title="opencode.json"
{
  "agent": {
    "quick-thinker": {
      "description": "Fast reasoning with limited iterations",
      "prompt": "You are a quick thinker. Solve problems with minimal steps.",
      "maxSteps": 5
    }
  }
}
```

当达到上限时，agent 会收到一个特殊系统提示，要求其仅返回工作总结与推荐的剩余任务。

---

### Disable

设为 `true` 来禁用该 agent。

```json title="opencode.json"
{
  "agent": {
    "review": {
      "disable": true
    }
  }
}
```

---

### Prompt

使用 `prompt` 配置为该 agent 指定自定义系统 prompt 文件。该 prompt 文件应包含与 agent 用途相关的说明。

```json title="opencode.json"
{
  "agent": {
    "review": {
      "prompt": "{file:./prompts/code-review.txt}"
    }
  }
}
```

该路径相对于配置文件所在位置，因此既适用于全局 OpenCode 配置，也适用于项目级配置。

---

### Model

使用 `model` 配置来覆盖该 agent 的模型。适合根据任务选择不同的模型，例如用于规划的更快模型或用于实现的更强模型。

:::tip
如果你未指定模型，primary agents 会使用 [全局配置的模型](/docs/config#models)，而 subagents 会使用调用它们的 primary agent 的模型。
:::

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "model": "anthropic/claude-haiku-4-20250514"
    }
  }
}
```

OpenCode 配置中的 model ID 使用 `provider/model-id` 格式。例如，如果你在使用 [OpenCode Zen](/docs/zen)，你需要使用 `opencode/gpt-5.1-codex` 代表 GPT 5.1 Codex。

---

### Tools

使用 `tools` 配置控制该 agent 可用的工具。可以通过设置 `true` 或 `false` 来启用或禁用特定工具。

```json title="opencode.json" {3-6,9-12}
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

:::note
agent 专用配置会覆盖全局配置。
:::

你也可以使用通配符一次性控制多个工具。例如，禁用来自某个 MCP server 的所有工具：

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "readonly": {
      "tools": {
        "mymcp_*": false,
        "write": false,
        "edit": false
      }
    }
  }
}
```

[了解更多 tools](/docs/tools)。

---

### Permissions

你可以配置权限来管理 agent 能执行的操作。目前 `edit`、`bash` 与 `webfetch` 工具的权限可以设置为：

- `"ask"` — 运行工具前提示批准
- `"allow"` — 无需批准允许所有操作
- `"deny"` — 禁用工具

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  }
}
```

你可以为每个 agent 覆盖这些权限。

```json title="opencode.json" {3-5,8-10}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  },
  "agent": {
    "build": {
      "permission": {
        "edit": "ask"
      }
    }
  }
}
```

你也可以在 Markdown agents 中设置权限。

```markdown title="~/.config/opencode/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
    "grep *": allow
  webfetch: deny
---

Only analyze code and suggest changes.
```

你可以针对特定 bash 命令设置权限。

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git push": "ask",
          "grep *": "allow"
        }
      }
    }
  }
}
```

这里支持 glob 模式。

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git *": "ask"
        }
      }
    }
  }
}
```

你也可以使用 `*` 通配符管理所有命令的权限。
由于最后匹配的规则优先生效，请将 `*` 通配符放在前面，将更具体的规则放在后面。

```json title="opencode.json" {8}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status *": "allow"
        }
      }
    }
  }
}
```

[了解更多 permissions](/docs/permissions)。

---

### Mode

使用 `mode` 配置控制 agent 的模式。`mode` 选项用于决定该 agent 的使用方式。

```json title="opencode.json"
{
  "agent": {
    "review": {
      "mode": "subagent"
    }
  }
}
```

`mode` 可设置为 `primary`、`subagent` 或 `all`。若未指定，默认值为 `all`。

---

### Hidden

使用 `hidden: true` 从 `@` 自动补全菜单中隐藏 subagent。适合仅供内部使用、由其他 agents 通过 Task 工具以编程方式调用的 subagent。

```json title="opencode.json"
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

这只会影响自动补全菜单中的可见性。如果权限允许，隐藏的 agent 仍可由模型通过 Task 工具调用。

:::note
仅适用于 `mode: subagent` agents。
:::

---

### Task permissions

使用 `permission.task` 控制 agent 通过 Task 工具可调用的 subagents。支持 glob 模式进行灵活匹配。

```json title="opencode.json"
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

当设为 `deny` 时，该 subagent 会从 Task 工具描述中被完全移除，因此模型不会尝试调用它。

:::tip
规则按顺序评估，且 **最后匹配的规则生效**。在上例中，`orchestrator-planner` 同时匹配 `*`（deny）与 `orchestrator-*`（allow），但由于 `orchestrator-*` 在 `*` 之后，因此结果为 `allow`。
:::

:::tip
即使 agent 的 task 权限设置为 deny，用户仍可通过 `@` 自动补全菜单直接调用任意 subagent。
:::

---

### Additional

你在 agent 配置中指定的任何其他选项，都会 **直接传递** 给 provider 作为模型参数。这让你能够使用 provider 特定的特性与参数。

例如，在 OpenAI 的 reasoning 模型中，你可以控制 reasoning effort：

```json title="opencode.json" {6,7}
{
  "agent": {
    "deep-thinker": {
      "description": "Agent that uses high reasoning effort for complex problems",
      "model": "openai/gpt-5",
      "reasoningEffort": "high",
      "textVerbosity": "low"
    }
  }
}
```

这些额外选项与模型和 provider 相关。请查看你的 provider 文档了解可用参数。

:::tip
运行 `opencode models` 查看可用模型列表。
:::

## 创建 agents

你可以使用以下命令创建新的 agents：

```bash
opencode agent create
```

该交互式命令会：

1. 询问保存 agent 的位置：全局或项目级。
2. 询问该 agent 的功能描述。
3. 生成合适的系统 prompt 与标识符。
4. 让你选择该 agent 可访问的工具。
5. 最终创建包含 agent 配置的 markdown 文件。

---

## 使用场景

以下是不同 agents 的常见使用场景。

- **Build agent**：启用所有工具的完整开发
- **Plan agent**：仅分析与规划，不做改动
- **Review agent**：只读代码审查 + 文档工具
- **Debug agent**：专注排查，启用 bash 与 read 工具
- **Docs agent**：编写文档，允许文件操作但不允许系统命令

### Documentation agent

```markdown title="~/.config/opencode/agents/docs-writer.md"
---
description: Writes and maintains project documentation
mode: subagent

  bash: false
---

You are a technical writer. Create clear, comprehensive documentation.

Focus on:

- Clear explanations
- Proper structure
- Code examples
- User-friendly language
```

### Security auditor

```markdown title="~/.config/opencode/agents/security-auditor.md"
---
description: Performs security audits and identifies vulnerabilities
mode: subagent
tools:
  write: false
  edit: false
---

You are a security expert. Focus on identifying potential security issues.

Look for:

- Input validation vulnerabilities
- Authentication and authorization flaws
- Data exposure risks
- Dependency vulnerabilities
- Configuration security issues
```
