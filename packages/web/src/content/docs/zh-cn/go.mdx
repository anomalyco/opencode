OpenCode Go 让你能够稳定访问流行的开源编程模型，并提供两种月度方案：

| 方案        | 价格       | 包含的用量                   |
| ----------- | ---------- | ---------------------------- |
| **Go**      | **$10/月** | 以较低成本访问下列模型       |
| **Go Plus** | **$40/月** | 下列模型均享有更高的用量限制 |

Go 的工作方式与 OpenCode 中的其他提供商一样。订阅 OpenCode Go 后，你将获得 API 密钥。它是**完全可选**的，并非使用 OpenCode 所必需。

该服务主要面向国际用户，并提供稳定的全球访问。

## 背景

开源模型已经变得非常强大。在编程任务中，它们的性能已接近专有模型。由于许多提供商都能以有竞争力的价格提供服务，它们通常便宜得多。

然而，要获得可靠、低延迟的访问可能很困难。各提供商在质量和可用性方面参差不齐。

:::tip
我们测试了一组经过精选且与 OpenCode 配合良好的模型和提供商。
:::

为了解决这个问题，我们做了以下几件事：

1. 我们测试了一组精选的开源模型，并与其团队探讨了如何以最佳方式运行它们。
2. 随后，我们与一些提供商合作，确保这些模型得到正确的服务。
3. 最后，我们对模型与提供商的组合进行了基准测试，整理出一份值得推荐的列表。

Go 和 Go Plus 均可访问这些模型；请根据你的使用量选择合适的方案。

## 工作原理

OpenCode Go 的工作方式与 OpenCode 中的其他提供商一样。

1. 登录 **<a href={console}>OpenCode Console</a>**，订阅 Go 或 Go Plus，然后复制你的 API 密钥。
2. 在 TUI 中运行 `/connect` 命令，选择 `OpenCode Go`，然后粘贴你的 API 密钥。
3. 在 TUI 中运行 `/models`，查看可通过 Go 使用的模型列表。

每个工作空间只能有一名成员订阅 OpenCode Go 或 Go Plus。

## 可以在哪里使用？

OpenCode Go 适用于 [OpenCode](https://opencode.ai) 以及其他会产生类似请求的编程 Agent。我们会监控流量，识别影响其他用户体验的滥用行为。

你的客户端应当：

1. 发送典型的编程 Agent 流量
2. 使用自身专属的 user agent 标识（例如 `my-coding-agent/1.0`），而不是通用的 SDK 或 HTTP 库名称。
3. 为每段对话在 `x-opencode-session` 中发送稳定的会话 ID，以便我们优化路由和提示词缓存。

### 已验证的客户端

除 OpenCode 外，以下客户端已通过验证，能够正常使用 OpenCode Go。但我们无法保证它们未来仍能正常使用。

| 客户端            | 会话支持                                                                                                                                                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hermes**        | 包含 [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864) 的构建版本会在主要和辅助 OpenCode 请求中发送该请求头。此修复在 v0.21.0 发布后才合并，因此该版本本身并不包含此修复。                             |
| **Claude Code**   | Go 能识别其原生会话请求头，无需自定义请求头封装。                                                                                                                                                                           |
| **Codex**         | Go 能识别其原生会话请求头。某些版本和代理配置仍会遗漏该请求头；转发请求时请保留会话请求头。                                                                                                                                 |
| **ZCode**         | Go 能识别其原生会话请求头。我们[请求支持 `x-opencode-session`](https://github.com/zai-org/feedback/issues/492) 仍处于开放状态，但已不再需要发送这一特定请求头。                                                             |
| **Pi**            | 当前构建版本会为 OpenCode 发送会话信息。请更新旧版安装。                                                                                                                                                                    |
| **jcode**         | 请更新至 **v0.81.6 或更高版本**，其中包含[会话请求头修复](https://github.com/1jehuang/jcode/issues/1167)。                                                                                                                  |
| **Kilo Code CLI** | 包含 [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) 的构建版本恢复了 OpenCode 会话请求头。此修复仅适用于 CLI，不适用于 VS Code 扩展。参见 [issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723)。 |

### 超出限制的使用

如果你的 Zen 余额中还有积分，可以在控制台中启用 **使用余额（Use balance）** 选项。启用后，当你达到使用限制时，Go 会改用 Zen 余额，而不是拦截请求。

---

### 为什么某些模型的使用额度较低

使用 Go 时，包含的每月使用额度因模型而异。

对于大多数模型，我们通过批量折扣和预留 GPU 容量来实现这一点，再以更高的每月使用额度将节省的成本回馈给你。

对于某些模型，我们还没有机会协商折扣或以更低的成本托管，原因可能是模型较新，或其公开价格已经是折扣价。

对于这些模型，你获得的用量仍会略高于直接向模型提供商付费；这就是它们包含的每月使用额度较低的原因。

## 目标

我们创建 OpenCode Go 的目的是：

1. 通过低成本订阅，让更多人能够**轻松使用** AI 编程。
2. 为最佳开源编程模型提供**可靠**的访问。
3. 精选经过**测试和基准评估**、适合编程 Agent 使用的模型。
4. 允许你在 OpenCode 中同时使用任何其他提供商，确保**不被单一提供商锁定**。
