title: GitHub
description: 在 GitHub issues 与 pull requests 中使用 OpenCode。
---

OpenCode 可与 GitHub 工作流集成。在评论中提到 `/opencode` 或 `/oc`，OpenCode 将在你的 GitHub Actions runner 中执行任务。

---

## Features

- **问题分拣**：让 OpenCode 调查 issue 并向你解释。
- **修复与实现**：让 OpenCode 修复 issue 或实现功能。它会在新分支中工作并提交包含所有变更的 PR。
- **安全**：OpenCode 运行在你的 GitHub runner 内。

---

## Installation

在 GitHub 仓库项目中运行以下命令：

```bash
opencode github install
```

这会引导你安装 GitHub app、创建工作流并设置 secrets。

---

### 手动设置

你也可以手动设置。

1. **安装 GitHub app**

   访问 [**github.com/apps/opencode-agent**](https://github.com/apps/opencode-agent)。确保它已安装在目标仓库。

2. **添加工作流**

   将以下工作流文件添加到仓库的 `.github/workflows/opencode.yml`。确保在 `env` 中设置合适的 `model` 与所需 API keys。

   ```yml title=".github/workflows/opencode.yml" {24,26}
   name: opencode

   on:
     issue_comment:
       types: [created]
     pull_request_review_comment:
       types: [created]

   jobs:
     opencode:
       if: |
         contains(github.event.comment.body, '/oc') ||
         contains(github.event.comment.body, '/opencode')
       runs-on: ubuntu-latest
       permissions:
         id-token: write
       steps:
          - name: Checkout repository
            uses: actions/checkout@v6
            with:
              fetch-depth: 1
              persist-credentials: false

          - name: Run OpenCode
           uses: anomalyco/opencode/github@latest
           env:
             ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
           with:
             model: anthropic/claude-sonnet-4-20250514
             # share: true
             # github_token: xxxx
   ```

3. **在 secrets 中保存 API keys**

   在组织或项目的 **settings** 中，展开左侧 **Secrets and variables**，选择 **Actions**，并添加所需 API keys。

## Configuration

- `model`：OpenCode 使用的模型。格式为 `provider/model`。这是 **必填**。
- `agent`：要使用的 agent。必须为 primary agent。如果未找到，则回退到配置中的 `default_agent` 或 `"build"`。
- `share`：是否分享 OpenCode 会话。公开仓库默认 **true**。
- `prompt`：可选的自定义 prompt，用于覆盖默认行为，以定制 OpenCode 的请求处理方式。
- `token`：可选 GitHub access token，用于创建评论、提交变更与打开 PR 等操作。默认情况下，OpenCode 使用 OpenCode GitHub App 的安装 access token，因此提交、评论与 PR 都会显示为来自该 app。

  或者，你可以使用 GitHub Action runner 的内置 [`GITHUB_TOKEN`](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token)，无需安装 OpenCode GitHub App。只需在工作流中授予所需权限：

  ```yaml
  permissions:
    id-token: write
    contents: write
    pull-requests: write
    issues: write
  ```

  如有需要，你也可以使用 [personal access tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)(PAT)。

## Supported Events

OpenCode 可由以下 GitHub events 触发：

| Event Type                    | Triggered By          | Details                                                                              |
| ----------------------------- | --------------------- | ------------------------------------------------------------------------------------ |
| `issue_comment`               | 对 issue 或 PR 的评论 | 在评论中提到 `/opencode` 或 `/oc`。OpenCode 读取上下文，可创建分支、打开 PR 或回复。 |
| `pull_request_review_comment` | PR 中特定代码行的评论 | 在代码审查时提到 `/opencode` 或 `/oc`。OpenCode 会收到文件路径、行号与 diff 上下文。 |
| `issues`                      | issue 被打开或编辑    | 在 issues 被创建或修改时自动触发 OpenCode。需要 `prompt` 输入。                      |
| `pull_request`                | PR 被打开或更新       | 在 PR 打开、同步或重新打开时自动触发 OpenCode。适用于自动化审查。                    |
| `schedule`                    | Cron 定时任务         | 按计划运行 OpenCode。需要 `prompt` 输入。输出写入日志与 PR（无 issue 评论）。        |
| `workflow_dispatch`           | GitHub UI 手动触发    | 在 Actions 标签页按需触发 OpenCode。需要 `prompt` 输入。输出写入日志与 PR。          |

### Schedule 示例

按计划运行 OpenCode 以执行自动化任务：

```yaml title=".github/workflows/opencode-scheduled.yml"
name: Scheduled OpenCode Task

on:
  schedule:
    - cron: "0 9 * * 1" # Every Monday at 9am UTC

jobs:
  opencode:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          persist-credentials: false

      - name: Run OpenCode
        uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review the codebase for any TODO comments and create a summary.
            If you find issues worth addressing, open an issue to track them.
```

对于定时事件，`prompt` 输入是 **必填**，因为没有评论可用于提取指令。定时工作流在没有用户上下文的情况下运行，如果你希望 OpenCode 创建分支或 PR，工作流必须授予 `contents: write` 与 `pull-requests: write` 权限。

### Pull Request 示例

在 PR 打开或更新时自动审查：

```yaml title=".github/workflows/opencode-review.yml"
name: opencode-review

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
      pull-requests: read
      issues: read
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false
      - uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          use_github_token: true
          prompt: |
            Review this pull request:
            - Check for code quality issues
            - Look for potential bugs
            - Suggest improvements
```

对于 `pull_request` events，如果没有提供 `prompt`，OpenCode 默认审查该 PR。

### Issues 分拣示例

自动分拣新 issues。此示例过滤账号注册时间超过 30 天的用户，以减少垃圾信息：

```yaml title=".github/workflows/opencode-triage.yml"
name: Issue Triage

on:
  issues:
    types: [opened]

jobs:
  triage:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Check account age
        id: check
        uses: actions/github-script@v7
        with:
          script: |
            const user = await github.rest.users.getByUsername({
              username: context.payload.issue.user.login
            });
            const created = new Date(user.data.created_at);
            const days = (Date.now() - created) / (1000 * 60 * 60 * 24);
            return days >= 30;
          result-encoding: string

      - uses: actions/checkout@v6
        if: steps.check.outputs.result == 'true'
        with:
          persist-credentials: false

      - uses: anomalyco/opencode/github@latest
        if: steps.check.outputs.result == 'true'
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review this issue. If there's a clear fix or relevant docs:
            - Provide documentation links
            - Add error handling guidance for code examples
            Otherwise, do not comment.
```

对于 `issues` events，`prompt` 输入是 **必填**，因为没有评论可用于提取指令。

## Custom prompts

覆盖默认 prompt，以便为你的工作流自定义 OpenCode 行为。

```yaml title=".github/workflows/opencode.yml"
- uses: anomalyco/opencode/github@latest
  with:
    model: anthropic/claude-sonnet-4-5
    prompt: |
      Review this pull request:
      - Check for code quality issues
      - Look for potential bugs
      - Suggest improvements
```

这适合用于强制特定审查标准、编码规范或项目关注点。

## 示例

以下是你在 GitHub 中使用 OpenCode 的一些例子。

- **解释一个 issue**

  在 GitHub issue 中添加评论：

  ```
  /opencode explain this issue
  ```

  OpenCode 会读取完整线程（含所有评论），并给出清晰解释。

- **修复一个 issue**

  在 GitHub issue 中说明：

  ```
  /opencode fix this
  ```

  OpenCode 会创建新分支、实现变更，并创建 PR。

- **审查 PR 并进行修改**

  在 GitHub PR 中留下以下评论：

  ```
  Delete the attachment from S3 when the note is removed /oc
  ```

  OpenCode 会实现请求的更改并提交到同一个 PR。

- **审查特定代码行**

  在 PR 的 "Files" 标签页中直接对代码行评论。OpenCode 会自动检测文件、行号与 diff 上下文，以提供更精准的响应。

  ```
  [Comment on specific lines in Files tab]
  /oc add error handling here
  ```

  在对特定代码行评论时，OpenCode 会获得：
  - 正在审查的具体文件
  - 具体代码行
  - 周围 diff 上下文
  - 行号信息

  这使你无需手动指定文件路径或行号即可提出更有针对性的请求。
