---
title: عیب‌یابی
description: مشکلات رایج و نحوه رفع آن‌ها.
---

برای اشکال‌زدایی مشکلات OpenCode، با بررسی لاگ‌ها و داده‌های محلی که روی دیسک ذخیره می‌کند شروع کنید.

---

## لاگ‌ها

فایل‌های لاگ در این مسیرها نوشته می‌شوند:

- **macOS/Linux**: `~/.local/share/opencode/log/`
- **Windows**: `WIN+R` را فشار دهید و `%USERPROFILE%\.local\share\opencode\log` را بچسبانید

فایل‌های لاگ با برچسب زمانی نام‌گذاری می‌شوند (مثلاً `2025-01-09T123456.log`) و ۱۰ فایل لاگ اخیر نگه‌داری می‌شوند.

می‌توانید سطح لاگ را با گزینه خط‌فرمان `--log-level` تنظیم کنید تا اطلاعات اشکال‌زدایی دقیق‌تری دریافت کنید. برای مثال، `opencode --log-level DEBUG`.

---

## ذخیره‌سازی

opencode داده‌های نشست و سایر داده‌های اپلیکیشن را روی دیسک در این مسیر ذخیره می‌کند:

- **macOS/Linux**: `~/.local/share/opencode/`
- **Windows**: `WIN+R` را فشار دهید و `%USERPROFILE%\.local\share\opencode` را بچسبانید

این دایرکتوری شامل موارد زیر است:

- `auth.json` - داده‌های احراز هویت مانند کلیدهای API و توکن‌های OAuth
- `log/` - لاگ‌های اپلیکیشن
- `project/` - داده‌های مخصوص پروژه مانند داده‌های نشست و پیام
  - اگر پروژه درون یک مخزن Git باشد، در `./<project-slug>/storage/` ذخیره می‌شود
  - اگر مخزن Git نباشد، در `./global/storage/` ذخیره می‌شود

---

## حذف نصب

برای حذف نصب OpenCode CLI و پاک‌کردن فایل‌های مرتبط با آن، این دستور را اجرا کنید:

```bash
opencode uninstall
```

این دستور نشان می‌دهد چه چیزی حذف خواهد شد و درخواست تأیید می‌کند. برای گزینه‌های نگه‌داشتن پیکربندی یا داده‌های اپلیکیشن، به [مرجع CLI](/docs/cli#uninstall) مراجعه کنید.

برای حذف OpenCode Desktop، اپلیکیشن را از طریق ابزارهای مدیریت اپلیکیشن سیستم‌عامل خود حذف نصب کنید.

---

## اپلیکیشن دسکتاپ

OpenCode Desktop یک سرور محلی OpenCode (سایدکار `opencode-cli`) را در پس‌زمینه اجرا می‌کند. بیشتر مشکلات ناشی از یک افزونه با رفتار نادرست، یک کش خراب، یا یک تنظیم نامناسب سرور هستند.

### بررسی‌های سریع

- اپلیکیشن را کاملاً ببندید و دوباره راه‌اندازی کنید.
- اگر اپلیکیشن یک صفحه خطا نشان داد، روی **Restart** کلیک کنید و جزئیات خطا را کپی کنید.
- فقط macOS: منوی `OpenCode` -> **Reload Webview** (اگر رابط کاربری خالی/فریز شده باشد کمک می‌کند).

---

### غیرفعال‌کردن افزونه‌ها

اگر اپلیکیشن دسکتاپ هنگام راه‌اندازی کرش می‌کند، معلق می‌شود یا رفتار عجیبی دارد، با غیرفعال‌کردن افزونه‌ها شروع کنید.

#### پیکربندی سراسری را بررسی کنید

فایل پیکربندی سراسری خود را باز کنید و به دنبال کلید `plugin` بگردید.

- **macOS/Linux**: `~/.config/opencode/opencode.jsonc` (یا `~/.config/opencode/opencode.json`)
- **macOS/Linux** (نصب‌های قدیمی‌تر): `~/.local/share/opencode/opencode.jsonc`
- **Windows**: `WIN+R` را فشار دهید و `%USERPROFILE%\.config\opencode\opencode.jsonc` را بچسبانید

اگر افزونه‌هایی پیکربندی کرده‌اید، با حذف کلید یا تنظیم آن روی یک آرایه خالی، آن‌ها را موقتاً غیرفعال کنید:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [],
}
```

#### دایرکتوری‌های افزونه را بررسی کنید

OpenCode همچنین می‌تواند افزونه‌های محلی را از دیسک بارگذاری کند. این‌ها را موقتاً جابه‌جا کنید (یا نام پوشه را تغییر دهید) و اپلیکیشن دسکتاپ را دوباره راه‌اندازی کنید:

- **افزونه‌های سراسری**
  - **macOS/Linux**: `~/.config/opencode/plugins/`
  - **Windows**: `WIN+R` را فشار دهید و `%USERPROFILE%\.config\opencode\plugins` را بچسبانید
- **افزونه‌های پروژه** (فقط اگر از پیکربندی مخصوص هر پروژه استفاده می‌کنید)
  - `<your-project>/.opencode/plugins/`

اگر اپلیکیشن دوباره شروع به کار کرد، افزونه‌ها را یکی‌یکی دوباره فعال کنید تا بفهمید کدام‌یک باعث مشکل می‌شود.

---

### پاک‌کردن کش

اگر غیرفعال‌کردن افزونه‌ها کمک نکرد (یا نصب یک افزونه گیر کرده است)، کش را پاک کنید تا OpenCode بتواند آن را بازسازی کند.

1. OpenCode Desktop را کاملاً ببندید.
2. دایرکتوری کش را حذف کنید:

- **macOS**: Finder -> `Cmd+Shift+G` -> `~/.cache/opencode` را بچسبانید
- **Linux**: `~/.cache/opencode` را حذف کنید (یا `rm -rf ~/.cache/opencode` را اجرا کنید)
- **Windows**: `WIN+R` را فشار دهید و `%USERPROFILE%\.cache\opencode` را بچسبانید

3. OpenCode Desktop را دوباره راه‌اندازی کنید.

---

### رفع مشکلات اتصال سرور

OpenCode Desktop می‌تواند یا سرور محلی خود را شروع کند (پیش‌فرض) یا به یک URL سرور که پیکربندی کرده‌اید متصل شود.

اگر یک دیالوگ **"Connection Failed"** می‌بینید (یا اپلیکیشن هرگز از صفحه splash عبور نمی‌کند)، وجود یک URL سفارشی سرور را بررسی کنید.

#### URL پیش‌فرض سرور دسکتاپ را پاک کنید

از صفحه Home، روی نام سرور (همراه با نقطه وضعیت) کلیک کنید تا انتخاب‌گر سرور باز شود. در بخش **Default server**، روی **Clear** کلیک کنید.

#### `server.port` / `server.hostname` را از پیکربندی خود حذف کنید

اگر `opencode.json(c)` شما شامل یک بخش `server` است، آن را موقتاً حذف کنید و اپلیکیشن دسکتاپ را دوباره راه‌اندازی کنید.

#### متغیرهای محیطی را بررسی کنید

اگر `OPENCODE_PORT` را در محیط خود تنظیم کرده‌اید، اپلیکیشن دسکتاپ سعی می‌کند از آن پورت برای سرور محلی استفاده کند.

- تنظیم `OPENCODE_PORT` را بردارید (یا یک پورت آزاد انتخاب کنید) و دوباره راه‌اندازی کنید.

---

### Linux: مشکلات Wayland / X11

روی Linux، برخی تنظیمات Wayland می‌توانند باعث پنجره‌های خالی یا خطاهای compositor شوند.

- اگر روی Wayland هستید و اپلیکیشن خالی است/کرش می‌کند، راه‌اندازی با `OC_ALLOW_WAYLAND=1` را امتحان کنید.
- اگر این اوضاع را بدتر کرد، آن را بردارید و به جای آن راه‌اندازی در یک نشست X11 را امتحان کنید.

---

### Windows: محیط اجرای WebView2

روی Windows، OpenCode Desktop نیازمند **WebView2 Runtime** مربوط به Microsoft Edge است. اگر اپلیکیشن با یک پنجره خالی باز می‌شود یا شروع نمی‌شود، WebView2 را نصب/به‌روزرسانی کنید و دوباره امتحان کنید.

---

### Windows: مشکلات کلی عملکرد

اگر روی Windows با عملکرد کند، مشکلات دسترسی به فایل یا مشکلات ترمینال مواجه هستید، استفاده از [WSL (زیرسیستم Windows برای Linux)](/docs/windows-wsl) را امتحان کنید. WSL یک محیط Linux فراهم می‌کند که با ویژگی‌های OpenCode یکپارچه‌تر کار می‌کند.

---

### اعلان‌ها نمایش داده نمی‌شوند

OpenCode Desktop فقط زمانی اعلان‌های سیستم را نشان می‌دهد که:

- اعلان‌ها برای OpenCode در تنظیمات سیستم‌عامل شما فعال باشند، و
- پنجره اپلیکیشن در فوکوس نباشد.

---

### بازنشانی ذخیره‌سازی اپلیکیشن دسکتاپ (آخرین راه‌حل)

اگر اپلیکیشن شروع نمی‌شود و نمی‌توانید تنظیمات را از داخل رابط کاربری پاک کنید، حالت ذخیره‌شده اپلیکیشن دسکتاپ را بازنشانی کنید.

1. OpenCode Desktop را ببندید.
2. این فایل‌ها را پیدا و حذف کنید (آن‌ها در دایرکتوری داده اپلیکیشن OpenCode Desktop قرار دارند):

- `opencode.settings.dat` (URL پیش‌فرض سرور دسکتاپ)
- `opencode.global.dat` و `opencode.workspace.*.dat` (حالت رابط کاربری مانند سرورها/پروژه‌های اخیر)

برای یافتن سریع دایرکتوری:

- **macOS**: Finder -> `Cmd+Shift+G` -> `~/Library/Application Support` (سپس نام فایل‌های بالا را جست‌وجو کنید)
- **Linux**: زیر `~/.local/share` نام فایل‌های بالا را جست‌وجو کنید
- **Windows**: `WIN+R` را فشار دهید -> `%APPDATA%` (سپس نام فایل‌های بالا را جست‌وجو کنید)

1. **گزارش مشکلات در GitHub**

   بهترین راه برای گزارش باگ‌ها یا درخواست ویژگی‌ها از طریق مخزن GitHub ما است:

2. **به Discord ما بپیوندید**

   برای کمک بی‌درنگ و گفت‌وگوی جامعه، به سرور Discord ما بپیوندید:

   [**opencode.ai/discord**](https://opencode.ai/discord)

## مشکلات رایج

در ادامه برخی مشکلات رایج و نحوه رفع آن‌ها آمده است.

---

### OpenCode شروع نمی‌شود

1. لاگ‌ها را برای پیام‌های خطا بررسی کنید
2. اجرا با `--print-logs` را امتحان کنید تا خروجی را در ترمینال ببینید
3. مطمئن شوید که آخرین نسخه را با `opencode upgrade` دارید

---

### مشکلات احراز هویت

1. احراز هویت مجدد با دستور `/connect` در TUI را امتحان کنید
2. بررسی کنید که کلیدهای API شما معتبر باشند
3. مطمئن شوید که شبکه شما اجازه اتصال به API ارائه‌دهنده را می‌دهد

---

### مدل در دسترس نیست

1. بررسی کنید که با ارائه‌دهنده احراز هویت کرده‌اید
2. درست بودن نام مدل در پیکربندی خود را تأیید کنید
3. برخی مدل‌ها ممکن است نیازمند دسترسی یا اشتراک خاصی باشند

اگر با `ProviderModelNotFoundError` مواجه شدید، به احتمال زیاد در جایی به‌طور نادرست به یک مدل ارجاع می‌دهید.
مدل‌ها باید به این صورت ارجاع داده شوند: `<providerId>/<modelId>`

مثال‌ها:

- `openai/gpt-4.1`
- `openrouter/google/gemini-2.5-flash`
- `opencode/kimi-k2`

برای اینکه بفهمید به چه مدل‌هایی دسترسی دارید، `opencode models` را اجرا کنید

---

### ProviderInitError

اگر با ProviderInitError مواجه شدید، به احتمال زیاد یک پیکربندی نامعتبر یا خراب دارید.

برای رفع این مشکل:

1. ابتدا با دنبال‌کردن [راهنمای ارائه‌دهندگان](/docs/providers) تأیید کنید که ارائه‌دهنده شما به‌درستی تنظیم شده است
2. اگر مشکل ادامه داشت، پاک‌کردن پیکربندی ذخیره‌شده خود را امتحان کنید:

   ```bash
   rm -rf ~/.local/share/opencode
   ```

   روی Windows، `WIN+R` را فشار دهید و این مسیر را حذف کنید: `%USERPROFILE%\.local\share\opencode`

3. با دستور `/connect` در TUI با ارائه‌دهنده خود دوباره احراز هویت کنید.

---

### AI_APICallError و مشکلات بسته‌های ارائه‌دهنده

اگر با خطاهای فراخوانی API مواجه شدید، ممکن است به دلیل بسته‌های قدیمی ارائه‌دهنده باشد. opencode بسته‌های ارائه‌دهنده (OpenAI، Anthropic، Google و غیره) را به‌صورت پویا در صورت نیاز نصب می‌کند و آن‌ها را به‌صورت محلی کش می‌کند.

برای رفع مشکلات بسته‌های ارائه‌دهنده:

1. کش بسته‌های ارائه‌دهنده را پاک کنید:

   ```bash
   rm -rf ~/.cache/opencode
   ```

   روی Windows، `WIN+R` را فشار دهید و این مسیر را حذف کنید: `%USERPROFILE%\.cache\opencode`

2. opencode را دوباره راه‌اندازی کنید تا آخرین بسته‌های ارائه‌دهنده دوباره نصب شوند

این کار opencode را وادار می‌کند تا جدیدترین نسخه‌های بسته‌های ارائه‌دهنده را دانلود کند، که اغلب مشکلات سازگاری با پارامترهای مدل و تغییرات API را رفع می‌کند.

---

### کپی/چسباندن روی Linux کار نمی‌کند

کاربران Linux باید یکی از ابزارهای کلیپ‌بورد زیر را نصب کرده باشند تا قابلیت کپی/چسباندن کار کند:

**برای سیستم‌های X11:**

```bash
apt install -y xclip
# or
apt install -y xsel
```

**برای سیستم‌های Wayland:**

```bash
apt install -y wl-clipboard
```

**برای محیط‌های بدون واسط گرافیکی (headless):**

```bash
apt install -y xvfb
# and run:
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```

opencode تشخیص می‌دهد که آیا از Wayland استفاده می‌کنید و `wl-clipboard` را ترجیح می‌دهد، در غیر این صورت سعی می‌کند ابزارهای کلیپ‌بورد را به این ترتیب پیدا کند: `xclip` و `xsel`.
