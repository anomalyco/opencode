برای رفع اشکال در مسائل مربوط به OpenCode، با بررسی گزارش‌ها (logs) و داده‌های محلی که روی دیسک ذخیره می‌کند شروع کنید.

---

## گزارش‌ها (Logs)

پرونده‌های گزارش در این مسیرها نوشته می‌شوند:

- **macOS/Linux**: `~/.local/share/opencode/log/`
- **Windows**: کلید `WIN+R` را فشار دهید و `%USERPROFILE%\.local\share\opencode\log` را الصاق کنید

پرونده‌های گزارش با مهرهای زمانی نام‌گذاری می‌شوند (مثلاً `2025-01-09T123456.log`) و ۱۰ پرونده گزارش جدیدتر نگه داشته می‌شوند.

می‌توانید سطح گزارش را با گزینه خط‌فرمان `--log-level` برای دریافت اطلاعات اشکال‌زدایی دقیق‌تر تنظیم کنید. به عنوان مثال، `opencode --log-level DEBUG`.

---

## ذخیره‌سازی

opencode داده‌های نشست و سایر داده‌های برنامه را روی دیسک در این مسیر ذخیره می‌کند:

- **macOS/Linux**: `~/.local/share/opencode/`
- **Windows**: کلید `WIN+R` را فشار دهید و `%USERPROFILE%\.local\share\opencode` را الصاق کنید

این فهرست شامل موارد زیر است:

- `auth.json` - داده‌های احراز هویت مانند کلیدهای API، توکن‌های OAuth
- `log/` - گزارش‌های برنامه
- `project/` - داده‌های مختص پروژه مانند داده‌های نشست و پیام
  - اگر پروژه در یک مخزن Git باشد، در `./<project-slug>/storage/` ذخیره می‌شود
  - اگر مخزن Git نباشد، در `./global/storage/` ذخیره می‌شود

---

## حذف نصب (Uninstall)

برای حذف نصب OpenCode CLI و حذف پرونده‌های مرتبط آن، اجرا کنید:

```bash
opencode uninstall
```

این دستور نشان می‌دهد که چه چیزی حذف خواهد شد و برای تأیید سؤال می‌کند. به [مرجع CLI](/docs/cli#uninstall) برای گزینه‌های حفظ پیکربندی یا داده‌های برنامه مراجعه کنید.

برای حذف OpenCode Desktop، برنامه را از طریق ابزارهای مدیریت برنامه سیستم‌عامل خود حذف نصب کنید.

---

## برنامه رومیزی

OpenCode Desktop یک سرور محلی OpenCode (سایدکار `opencode-cli`) را در پس‌زمینه اجرا می‌کند. بیشتر مشکلات ناشی از یک افزونه با رفتار نامناسب، یک حافظه نهان خراب، یا یک تنظیم سرور نامناسب هستند.

### بررسی‌های سریع

- برنامه را کاملاً ببندید و دوباره راه‌اندازی کنید.
- اگر برنامه یک صفحه خطا نشان می‌دهد، روی **Restart** کلیک کنید و جزئیات خطا را کپی کنید.
- فقط macOS: منوی `OpenCode` -> **Reload Webview** (اگر رابط کاربری خالی/منجمد است کمک می‌کند).

---

### غیرفعال کردن افزونه‌ها

اگر برنامه رومیزی هنگام راه‌اندازی crash می‌کند، آویزان می‌ماند، یا رفتار عجیبی دارد، با غیرفعال کردن افزونه‌ها شروع کنید.

#### بررسی پیکربندی سراسری

پرونده پیکربندی سراسری خود را باز کنید و به دنبال یک کلید `plugin` بگردید.

- **macOS/Linux**: `~/.config/opencode/opencode.jsonc` (یا `~/.config/opencode/opencode.json`)
- **macOS/Linux** (نصب‌های قدیمی‌تر): `~/.local/share/opencode/opencode.jsonc`
- **Windows**: کلید `WIN+R` را فشار دهید و `%USERPROFILE%\.config\opencode\opencode.jsonc` را الصاق کنید

اگر افزونه‌هایی را پیکربندی کرده‌اید، آن‌ها را به‌طور موقت با حذف کلید یا تنظیم آن روی یک آرایه خالی غیرفعال کنید:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [],
}
```

#### بررسی فهرست‌های افزونه

OpenCode همچنین می‌تواند افزونه‌های محلی را از روی دیسک بارگذاری کند. این‌ها را به‌طور موقت از سر راه خارج کنید (یا پوشه را تغییر نام دهید) و برنامه رومیزی را دوباره راه‌اندازی کنید:

- **افزونه‌های سراسری**
  - **macOS/Linux**: `~/.config/opencode/plugins/`
  - **Windows**: کلید `WIN+R` را فشار دهید و `%USERPROFILE%\.config\opencode\plugins` را الصاق کنید
- **افزونه‌های پروژه** (فقط اگر از پیکربندی مختص پروژه استفاده می‌کنید)
  - `<your-project>/.opencode/plugins/`

اگر برنامه دوباره شروع به کار کرد، افزونه‌ها را یکی‌یکی دوباره فعال کنید تا بفهمید کدام یک باعث مشکل شده است.

---

### پاک کردن حافظه نهان

اگر غیرفعال کردن افزونه‌ها کمک نکرد (یا نصب یک افزونه گیر کرده است)، حافظه نهان را پاک کنید تا OpenCode بتواند آن را بازسازی کند.

1. OpenCode Desktop را کاملاً ببندید.
2. فهرست حافظه نهان را حذف کنید:

- **macOS**: Finder -> `Cmd+Shift+G` -> الصاق `~/.cache/opencode`
- **Linux**: حذف `~/.cache/opencode` (یا اجرای `rm -rf ~/.cache/opencode`)
- **Windows**: کلید `WIN+R` را فشار دهید و `%USERPROFILE%\.cache\opencode` را الصاق کنید

3. OpenCode Desktop را دوباره راه‌اندازی کنید.

---

### رفع مشکلات اتصال به سرور

OpenCode Desktop می‌تواند یا سرور محلی خودش را راه‌اندازی کند (پیش‌فرض) یا به یک URL سرور که پیکربندی کرده‌اید متصل شود.

اگر یک کادر گفتگو با **"Connection Failed"** را می‌بینید (یا برنامه هرگز از صفحه splash عبور نمی‌کند)، به دنبال یک URL سرور سفارشی بگردید.

#### پاک کردن URL سرور پیش‌فرض رومیزی

از صفحه Home، روی نام سرور (با نقطه وضعیت) کلیک کنید تا انتخاب‌گر سرور باز شود. در بخش **Default server**، روی **Clear** کلیک کنید.

#### حذف `server.port` / `server.hostname` از پیکربندی خود

اگر `opencode.json(c)` شما شامل یک بخش `server` است، آن را به‌طور موقت حذف کنید و برنامه رومیزی را دوباره راه‌اندازی کنید.

#### بررسی متغیرهای محیطی

اگر `OPENCODE_PORT` را در محیط خود تنظیم کرده‌اید، برنامه رومیزی سعی می‌کند از آن پورت برای سرور محلی استفاده کند.

- `OPENCODE_PORT` را لغو تنظیم کنید (یا یک پورت آزاد انتخاب کنید) و دوباره راه‌اندازی کنید.

---

### Linux: مشکلات Wayland / X11

در Linux، برخی تنظیمات Wayland می‌توانند باعث پنجره‌های خالی یا خطاهای compositor شوند.

- اگر در Wayland هستید و برنامه خالی/crash می‌شود، با `OC_ALLOW_WAYLAND=1` سعی کنید راه‌اندازی کنید.
- اگر اوضاع را بدتر کرد، آن را حذف کنید و به جای آن با یک نشست X11 سعی کنید راه‌اندازی کنید.

---

### Windows: زمان اجرای WebView2

در Windows، OpenCode Desktop به **WebView2 Runtime** مایکروسافت نیاز دارد. اگر برنامه به یک پنجره خالی باز می‌شود یا راه‌اندازی نمی‌شود، WebView2 را نصب/به‌روزرسانی کنید و دوباره امتحان کنید.

---

### Windows: مشکلات عملکرد عمومی

اگر عملکرد کند، مشکلات دسترسی به پرونده، یا مشکلات ترمینال را در Windows تجربه می‌کنید، سعی کنید از [WSL (Windows Subsystem for Linux)](/docs/windows-wsl) استفاده کنید. WSL یک محیط Linux ارائه می‌دهد که با ویژگی‌های OpenCode یکپارچگی بیشتری دارد.

---

### عدم نمایش اعلان‌ها

OpenCode Desktop فقط زمانی اعلان‌های سیستم را نشان می‌دهد که:

- اعلان‌ها برای OpenCode در تنظیمات سیستم‌عامل شما فعال باشند، و
- پنجره برنامه در تمرکز (focus) نباشد.

---

### بازنشانی ذخیره‌سازی برنامه رومیزی (آخرین چاره)

اگر برنامه راه‌اندازی نمی‌شود و نمی‌توانید تنظیمات را از داخل رابط کاربری پاک کنید، وضعیت ذخیره‌شده برنامه رومیزی را بازنشانی کنید.

1. OpenCode Desktop را ببندید.
2. این پرونده‌ها را پیدا کنید و حذف کنید (آن‌ها در فهرست داده برنامه OpenCode Desktop قرار دارند):

- `opencode.settings.dat` (URL سرور پیش‌فرض رومیزی)
- `opencode.global.dat` و `opencode.workspace.*.dat` (وضعیت رابط کاربری مانند سرورها/پروژه‌های اخیر)

برای پیدا کردن سریع فهرست:

- **macOS**: Finder -> `Cmd+Shift+G` -> `~/Library/Application Support` (سپس جستجو برای نام پرونده‌های بالا)
- **Linux**: جستجو زیر `~/.local/share` برای نام پرونده‌های بالا
- **Windows**: کلید `WIN+R` -> `%APPDATA%` (سپس جستجو برای نام پرونده‌های بالا)

اگر با OpenCode مشکلی دارید:

1. **گزارش مشکلات در GitHub**

   بهترین راه برای گزارش باگ یا درخواست ویژگی‌ها از طریق مخزن GitHub ما است:

   [**github.com/anomalyco/opencode/issues**](https://github.com/anomalyco/opencode/issues)

   قبل از ایجاد یک issue جدید، issue‌های موجود را جستجو کنید تا ببینید آیا مشکل شما قبلاً گزارش شده است یا خیر.

2. **عضویت در Discord ما**

   برای کمک بلادرنگ و بحث انجمن، به سرور Discord ما بپیوندید:

   [**opencode.ai/discord**](https://opencode.ai/discord)

## مشکلات رایج

در اینجا برخی مشکلات رایج و نحوه حل آن‌ها آورده شده است.

---

### OpenCode راه‌اندازی نمی‌شود

1. گزارش‌ها را برای پیام‌های خطا بررسی کنید
2. سعی کنید با `--print-logs` اجرا کنید تا خروجی را در ترمینال ببینید
3. اطمینان حاصل کنید که آخرین نسخه را با `opencode upgrade` دارید

---

### مشکلات احراز هویت

1. سعی کنید با دستور `/connect` در TUI دوباره احراز هویت کنید
2. بررسی کنید که کلیدهای API شما معتبر هستند
3. اطمینان حاصل کنید که شبکه شما اجازه اتصال به API ارائه‌دهنده را می‌دهد

---

### مدل در دسترس نیست

1. بررسی کنید که با ارائه‌دهنده احراز هویت کرده‌اید
2. نام مدل در پیکربندی خود را تأیید کنید که صحیح است
3. برخی مدل‌ها ممکن است به دسترسی یا اشتراک خاصی نیاز داشته باشند

اگر `ProviderModelNotFoundError` را با برخوردید، به احتمال زیاد در جایی در حال ارجاع نادرست به یک مدل هستید.
مدل‌ها باید به این شکل ارجاع داده شوند: `<providerId>/<modelId>`

مثال‌ها:

- `openai/gpt-4.1`
- `openrouter/google/gemini-2.5-flash`
- `opencode/kimi-k2`

برای فهمیدن اینکه به چه مدل‌هایی دسترسی دارید، اجرا کنید `opencode models`

---

### ProviderInitError

اگر با یک ProviderInitError مواجه شدید، احتمالاً یک پیکربندی نامعتبر یا خراب دارید.

برای حل این موضوع:

1. ابتدا، با دنبال کردن [راهنمای ارائه‌دهنده‌ها](/docs/providers) تأیید کنید که ارائه‌دهنده شما به‌درستی تنظیم شده است
2. اگر مشکل همچنان ادامه داشت، سعی کنید پیکربندی ذخیره‌شده خود را پاک کنید:

   ```bash
   rm -rf ~/.local/share/opencode
   ```

   در Windows، کلید `WIN+R` را فشار دهید و حذف کنید: `%USERPROFILE%\.local\share\opencode`

3. با استفاده از دستور `/connect` در TUI دوباره با ارائه‌دهنده خود احراز هویت کنید.

---

### خطای AI_APICallError و مشکلات بسته ارائه‌دهنده

اگر با خطاهای فراخوانی API مواجه شدید، این ممکن است به دلیل بسته‌های ارائه‌دهنده قدیمی باشد. opencode به‌طور پویا بسته‌های ارائه‌دهنده (OpenAI، Anthropic، Google و غیره) را در صورت نیاز نصب و به‌طور محلی کش (cache) می‌کند.

برای حل مشکلات بسته ارائه‌دهنده:

1. کش بسته ارائه‌دهنده را پاک کنید:

   ```bash
   rm -rf ~/.cache/opencode
   ```

   در Windows، کلید `WIN+R` را فشار دهید و حذف کنید: `%USERPROFILE%\.cache\opencode`

2. opencode را برای نصب مجدد جدیدترین بسته‌های ارائه‌دهنده دوباره راه‌اندازی کنید

این باعث می‌شود opencode جدیدترین نسخه‌های بسته‌های ارائه‌دهنده را دانلود کند، که اغلب مشکلات سازگاری با پارامترهای مدل و تغییرات API را حل می‌کند.

---

### کپی/چسباندن در Linux کار نمی‌کند

کاربران Linux باید یکی از ابزارهای تخته‌بریدن (clipboard) زیر را برای عملکرد کپی/چسباندن نصب کرده باشند:

**برای سیستم‌های X11:**

```bash
apt install -y xclip
# یا
apt install -y xsel
```

**برای سیستم‌های Wayland:**

```bash
apt install -y wl-clipboard
```

**برای محیط‌های بدون نمایشگر (headless):**

```bash
apt install -y xvfb
# و اجرا:
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```

opencode تشخیص می‌دهد که آیا از Wayland استفاده می‌کنید و `wl-clipboard` را ترجیح می‌دهد، در غیر این صورت سعی می‌کند ابزارهای تخته‌بریدن را به ترتیب `xclip` و `xsel` پیدا کند.
