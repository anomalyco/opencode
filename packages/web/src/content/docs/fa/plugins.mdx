---
title: افزونه‌ها
description: نوشتن افزونه‌های خودتان برای گسترش OpenCode.
---

افزونه‌ها به شما امکان می‌دهند OpenCode را با اتصال به رویدادهای مختلف و سفارشی‌سازی رفتار، گسترش دهید. می‌توانید افزونه‌هایی برای افزودن ویژگی‌های جدید، یکپارچه‌سازی با خدمات خارجی یا تغییر رفتار پیش‌فرض OpenCode ایجاد کنید.

برای نمونه‌ها، [افزونه‌هایی](/docs/ecosystem#plugins) را که توسط جامعه کاربری ایجاد شده‌اند بررسی کنید.

---

## استفاده از یک افزونه

دو روش برای بارگذاری افزونه‌ها وجود دارد.

---

### از پرونده‌های محلی

پرونده‌های جاوااسکریپت یا تایپ‌اسکریپت را در فهرست افزونه‌ها قرار دهید.

- `.opencode/plugins/` - افزونه‌های سطح پروژه
- `~/.config/opencode/plugins/` - افزونه‌های سراسری

پرونده‌های موجود در این فهرست‌ها به‌طور خودکار هنگام راه‌اندازی بارگذاری می‌شوند.

---

### از npm

بسته‌های npm را در پرونده پیکربندی خود مشخص کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-helicone-session", "opencode-wakatime", "@my-org/custom-plugin"]
}
```

هر دو بسته‌های npm معمولی و محدوده‌دار پشتیبانی می‌شوند.

افزونه‌های موجود را در [اکوسیستم](/docs/ecosystem#plugins) مرور کنید.

---

### نحوه نصب افزونه‌ها

**افزونه‌های npm** به‌طور خودکار با استفاده از Bun هنگام راه‌اندازی نصب می‌شوند. بسته‌ها و وابستگی‌های آن‌ها در `~/.cache/opencode/node_modules/` کش می‌شوند.

**افزونه‌های محلی** مستقیماً از فهرست افزونه‌ها بارگذاری می‌شوند. برای استفاده از بسته‌های خارجی، باید یک `package.json` درون فهرست پیکربندی خود ایجاد کنید (به [وابستگی‌ها](#dependencies) مراجعه کنید)، یا افزونه را روی npm منتشر کرده و [آن را به پیکربندی خود اضافه کنید](/docs/config#plugins).

---

### ترتیب بارگذاری

افزونه‌ها از تمام منابع بارگذاری می‌شوند و تمام هوک‌ها به ترتیب اجرا می‌شوند. ترتیب بارگذاری به این صورت است:

1. پیکربندی سراسری (`~/.config/opencode/opencode.json`)
2. پیکربندی پروژه (`opencode.json`)
3. فهرست افزونه سراسری (`~/.config/opencode/plugins/`)
4. فهرست افزونه پروژه (`.opencode/plugins/`)

بسته‌های npm تکراری با نام و نسخه یکسان تنها یک بار بارگذاری می‌شوند. با این حال، یک افزونه محلی و یک افزونه npm با نام‌های مشابه هر دو جداگانه بارگذاری می‌شوند.

---

## ایجاد یک افزونه

افزونه یک **ماژول جاوااسکریپت/تایپ‌اسکریپت** است که یک یا چند تابع افزونه را صادر
(export) می‌کند. هر تابع یک شیء بافتار (context) دریافت می‌کند و یک شیء هوک‌ها
بازمی‌گرداند.

---

### وابستگی‌ها

افزونه‌های محلی و ابزارهای سفارشی می‌توانند از بسته‌های npm خارجی استفاده کنند. یک `package.json` به فهرست پیکربندی خود با وابستگی‌های مورد نیاز اضافه کنید.

```json title=".opencode/package.json"
{
  "dependencies": {
    "shescape": "^2.1.0"
  }
}
```

OpenCode هنگام راه‌اندازی `bun install` را اجرا می‌کند تا این‌ها را نصب کند. سپس افزونه‌ها و ابزارهای شما می‌توانند آن‌ها را وارد (import) کنند.

```ts title=".opencode/plugins/my-plugin.ts"
import { escape } from "shescape"

export const MyPlugin = async (ctx) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash") {
        output.args.command = escape(output.args.command)
      }
    },
  }
}
```

---

### ساختار پایه

```js title=".opencode/plugins/example.js"
export const MyPlugin = async ({ project, client, $, directory, worktree }) => {
  console.log("Plugin initialized!")

  return {
    // Hook implementations go here
  }
}
```

تابع افزونه موارد زیر را دریافت می‌کند:

- `project`: اطلاعات پروژه فعلی.
- `directory`: فهرست کاری فعلی.
- `worktree`: مسیر git worktree.
- `client`: یک کلاینت SDK متعلق به opencode برای تعامل با هوش مصنوعی.
- `$`: [API پوسته](https://bun.com/docs/runtime/shell) مربوط به Bun برای اجرای دستورات.

### پشتیبانی از تایپ‌اسکریپت

برای افزونه‌های تایپ‌اسکریپت، می‌توانید انواع را از بسته افزونه وارد کنید:

```ts title="my-plugin.ts" {1}
import type { Plugin } from "@opencode-ai/plugin"

export const MyPlugin: Plugin = async ({ project, client, $, directory, worktree }) => {
  return {
    // Type-safe hook implementations
  }
}
```

### رویدادها

افزونه‌ها می‌توانند طبق آنچه در بخش نمونه‌ها آمده به رویدادها مشترک شوند. در اینجا فهرستی از رویدادهای مختلف موجود آورده شده است.

#### رویدادهای دستور

- `command.executed`

#### رویدادهای پرونده

- `file.edited`
- `file.watcher.updated`

#### رویدادهای نصب

- `installation.updated`

#### رویدادهای LSP

- `lsp.client.diagnostics`
- `lsp.updated`

#### رویدادهای پیام

- `message.part.removed`
- `message.part.updated`
- `message.removed`
- `message.updated`

#### رویدادهای مجوز

- `permission.asked`
- `permission.replied`

#### رویدادهای سرور

- `server.connected`

#### رویدادهای نشست

- `session.created`
- `session.compacted`
- `session.deleted`
- `session.diff`
- `session.error`
- `session.idle`
- `session.status`
- `session.updated`

#### رویدادهای وظیفه (Todo)

- `todo.updated`

#### رویدادهای پوسته

- `shell.env`

#### رویدادهای ابزار

- `tool.execute.after`
- `tool.execute.before`

#### رویدادهای TUI

- `tui.prompt.append`
- `tui.command.execute`
- `tui.toast.show`

## نمونه‌ها

در اینجا چند نمونه از افزونه‌هایی آورده شده است که می‌توانید برای گسترش opencode استفاده کنید.

---

### ارسال اعلان‌ها

ارسال اعلان هنگام وقوع رویدادهای خاص:

```js title=".opencode/plugins/notification.js"
export const NotificationPlugin = async ({ project, client, $, directory, worktree }) => {
  return {
    event: async ({ event }) => {
      // Send notification on session completion
      if (event.type === "session.idle") {
        await $`osascript -e 'display notification "Session completed!" with title "opencode"'`
      }
    },
  }
}
```

ما از `osascript` برای اجرای AppleScript روی macOS استفاده می‌کنیم. در اینجا از آن برای ارسال اعلان استفاده می‌کنیم.

:::note
اگر از برنامه دسکتاپ OpenCode استفاده می‌کنید، می‌تواند هنگام آماده شدن پاسخ یا بروز خطا در یک نشست، به‌طور خودکار اعلان‌های سیستمی ارسال کند.
:::

### محافظت از .env

جلوگیری از خواندن پرونده‌های `.env` توسط opencode:

```javascript title=".opencode/plugins/env-protection.js"
export const EnvProtection = async ({ project, client, $, directory, worktree }) => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "read" && output.args.filePath.includes(".env")) {
        throw new Error("Do not read .env files")
      }
    },
  }
}
```

### تزریق متغیرهای محیطی

تزریق متغیرهای محیطی به تمام اجراهای پوسته (ابزارهای هوش مصنوعی و ترمینال‌های کاربر):

```javascript title=".opencode/plugins/inject-env.js"
export const InjectEnvPlugin = async () => {
  return {
    "shell.env": async (input, output) => {
      output.env.MY_API_KEY = "secret"
      output.env.PROJECT_ROOT = input.cwd
    },
  }
}
```

### ابزارهای سفارشی

افزونه‌ها همچنین می‌توانند ابزارهای سفارشی به opencode اضافه کنند:

```ts title=".opencode/plugins/custom-tools.ts"
import { type Plugin, tool } from "@opencode-ai/plugin"

export const CustomToolsPlugin: Plugin = async (ctx) => {
  return {
    tool: {
      mytool: tool({
        description: "This is a custom tool",
        args: {
          foo: tool.schema.string(),
        },
        async execute(args, context) {
          const { directory, worktree } = context
          return `Hello ${args.foo} from ${directory} (worktree: ${worktree})`
        },
      }),
    },
  }
}
```

کمک‌کننده `tool` یک ابزار سفارشی ایجاد می‌کند که opencode می‌تواند فراخوانی کند. این یک تابع اسکیمای Zod دریافت می‌کند و یک تعریف ابزار با موارد زیر بازمی‌گرداند:

- `description`: کاری که ابزار انجام می‌دهد
- `args`: اسکیمای Zod برای آرگومان‌های ابزار
- `execute`: تابعی که هنگام فراخوانی ابزار اجرا می‌شود

ابزارهای سفارشی شما در کنار ابزارهای داخلی در دسترس opencode خواهند بود.

:::note
اگر یک ابزار افزونه از همان نام یک ابزار داخلی استفاده کند، ابزار افزونه اولویت دارد.
:::

### ثبت (Logging)

به جای `console.log` از `client.app.log()` برای ثبت ساختاریافته استفاده کنید:

```ts title=".opencode/plugins/my-plugin.ts"
export const MyPlugin = async ({ client }) => {
  await client.app.log({
    body: {
      service: "my-plugin",
      level: "info",
      message: "Plugin initialized",
      extra: { foo: "bar" },
    },
  })
}
```

سطوح: `debug`, `info`, `warn`, `error`. برای جزئیات به [مستندات SDK](https://opencode.ai/docs/sdk) مراجعه کنید.

### هوک‌های فشرده‌سازی

سفارشی‌سازی بافتار گنجانده‌شده هنگام فشرده‌سازی (compaction) یک نشست:

```ts title=".opencode/plugins/compaction.ts"
import type { Plugin } from "@opencode-ai/plugin"

export const CompactionPlugin: Plugin = async (ctx) => {
  return {
    "experimental.session.compacting": async (input, output) => {
      // Inject additional context into the compaction prompt
      output.context.push(`
## Custom Context

Include any state that should persist across compaction:
- Current task status
- Important decisions made
- Files being actively worked on
`)
    },
  }
}
```

هوک `experimental.session.compacting` پیش از آنکه LLM یک خلاصه ادامه تولید کند اجرا می‌شود. از آن برای تزریق بافتار تخصصی حوزه استفاده کنید که درخواست فشرده‌سازی پیش‌فرض آن را از دست می‌داد.

همچنین می‌توانید درخواست فشرده‌سازی را کاملاً با تنظیم `output.prompt` جایگزین کنید:

```ts title=".opencode/plugins/custom-compaction.ts"
import type { Plugin } from "@opencode-ai/plugin"

export const CustomCompactionPlugin: Plugin = async (ctx) => {
  return {
    "experimental.session.compacting": async (input, output) => {
      // Replace the entire compaction prompt
      output.prompt = `
You are generating a continuation prompt for a multi-agent swarm session.

Summarize:
1. The current task and its status
2. Which files are being modified and by whom
3. Any blockers or dependencies between agents
4. The next steps to complete the work

Format as a structured prompt that a new agent can use to resume work.
`
    },
  }
}
```

هنگامی که `output.prompt` تنظیم شود، درخواست فشرده‌سازی پیش‌فرض را کاملاً جایگزین می‌کند. در این حالت آرایه `output.context` نادیده گرفته می‌شود.
