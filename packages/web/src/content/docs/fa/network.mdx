OpenCode از متغیرهای محیطی استاندارد پروکسی و گواهینامه‌های سفارشی برای محیط‌های شبکه سازمانی پشتیبانی می‌کند.

---

## پروکسی

OpenCode به متغیرهای محیطی استاندارد پروکسی احترام می‌گذارد.

```bash
# HTTPS proxy (recommended)
export HTTPS_PROXY=https://proxy.example.com:8080

# HTTP proxy (if HTTPS not available)
export HTTP_PROXY=http://proxy.example.com:8080

# Bypass proxy for local server (required)
export NO_PROXY=localhost,127.0.0.1
```

:::caution
TUI با یک سرور HTTP محلی ارتباط برقرار می‌کند. برای جلوگیری از ایجاد حلقه در مسیریابی، باید این ارتباط را از پروکسی دور بزنید.
:::

می‌توانید درگاه و نام میزبان سرور را با استفاده از [پرچم‌های CLI](/docs/cli#run) پیکربندی کنید.

---

### احراز هویت

اگر پروکسی شما نیازمند احراز هویت پایه باشد، اعتبارنامه‌ها را در نشانی درج کنید.

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

:::caution
از قرار دادن رمزهای عبور به‌صورت کدثابت (hardcode) خودداری کنید. از متغیرهای محیطی یا ذخیره‌سازی ایمن اعتبارنامه‌ها استفاده کنید.
:::

برای پروکسی‌هایی که احراز هویت پیشرفته مانند NTLM یا Kerberos نیاز دارند، استفاده از یک درگاه LLM (LLM Gateway) که روش احراز هویت شما را پشتیبانی کند را در نظر بگیرید.

---

## گواهینامه‌های سفارشی

اگر سازمان شما از CAهای سفارشی برای ارتباطات HTTPS استفاده می‌کند، OpenCode را طوری پیکربندی کنید که به آن‌ها اعتماد کند.

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

این برای هر دو ارتباط پروکسی و دسترسی مستقیم به API کار می‌کند.
