OpenCode از متغیرهای محیطی استاندارد پراکسی و گواهی‌های سفارشی برای محیط‌های شبکه سازمانی پشتیبانی می‌کند.

---

## پراکسی

OpenCode متغیرهای محیطی استاندارد پراکسی را رعایت می‌کند.

```bash
# پراکسی HTTPS (توصیه‌شده)
export HTTPS_PROXY=https://proxy.example.com:8080

# پراکسی HTTP (در صورت در دسترس نبودن HTTPS)
export HTTP_PROXY=http://proxy.example.com:8080

# دور زدن پراکسی برای سرور محلی (لازم)
export NO_PROXY=localhost,127.0.0.1
```

:::caution
TUI با یک سرور HTTP محلی ارتباط برقرار می‌کند. برای جلوگیری از حلقه‌های مسیریابی، باید پراکسی را برای این اتصال دور بزنید.
:::

می‌توانید پورت و نام میزبان سرور را با استفاده از [پرچم‌های CLI](/docs/cli#run) پیکربندی کنید.

---

### احراز هویت

اگر پراکسی شما به احراز هویت پایه نیاز دارد، اطلاعات اعتبار را در URL بگنجانید.

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

:::caution
از قرار دادن ثابت رمزهای عبور در کد خودداری کنید. از متغیرهای محیطی یا ذخیره‌سازی امن اطلاعات اعتبار استفاده کنید.
:::

برای پراکسی‌هایی که به احراز هویت پیشرفته مانند NTLM یا Kerberos نیاز دارند، استفاده از یک LLM Gateway که از روش احراز هویت شما پشتیبانی کند را در نظر بگیرید.

---

## گواهی‌های سفارشی

اگر سازمان شما از CAهای سفارشی برای اتصالات HTTPS استفاده می‌کند، OpenCode را طوری پیکربندی کنید که به آن‌ها اعتماد کند.

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

این هم برای اتصالات پراکسی و هم برای دسترسی مستقیم به API کار می‌کند.
