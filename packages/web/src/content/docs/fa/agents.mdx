---
title: عامل‌ها
description: عامل‌های تخصصی را پیکربندی و استفاده کنید.
---

عامل‌ها دستیارهای هوش مصنوعی تخصصی هستند که می‌توان آن‌ها را برای کارها و گردش‌کارهای مشخص پیکربندی کرد. آن‌ها به شما اجازه می‌دهند ابزارهای متمرکزی با پرامپت‌ها، مدل‌ها و دسترسی به ابزارهای سفارشی بسازید.

:::tip
از عامل plan برای تحلیل کد و بررسی پیشنهادها بدون ایجاد هیچ تغییری در کد استفاده کنید.
:::

می‌توانید در طول یک نشست بین عامل‌ها جابه‌جا شوید یا آن‌ها را با اشاره‌ی `@` فراخوانی کنید.

---

## انواع

دو نوع عامل در OpenCode وجود دارد؛ عامل‌های اصلی و زیرعامل‌ها.

---

### عامل‌های اصلی

عامل‌های اصلی دستیارهای اصلی‌ای هستند که مستقیماً با آن‌ها تعامل می‌کنید. می‌توانید با استفاده از کلید **Tab** یا کلید میان‌بُر `switch_agent` که پیکربندی کرده‌اید بین آن‌ها بچرخید. این عامل‌ها مکالمه‌ی اصلی شما را مدیریت می‌کنند. دسترسی به ابزارها از طریق مجوزها پیکربندی می‌شود — برای مثال، Build همه‌ی ابزارها را فعال دارد در حالی که Plan محدود است.

:::tip
می‌توانید از کلید **Tab** برای جابه‌جایی بین عامل‌های اصلی در طول یک نشست استفاده کنید.
:::

OpenCode با دو عامل اصلی داخلی، **Build** و **Plan**، عرضه می‌شود. در ادامه به آن‌ها نگاهی می‌اندازیم.

---

### زیرعامل‌ها

زیرعامل‌ها دستیارهای تخصصی‌ای هستند که عامل‌های اصلی می‌توانند برای کارهای مشخص آن‌ها را فراخوانی کنند. همچنین می‌توانید با **اشاره‌ی @** به آن‌ها در پیام‌های خود، آن‌ها را به‌صورت دستی فراخوانی کنید.

OpenCode با سه زیرعامل داخلی، **General**، **Explore** و **Scout**، عرضه می‌شود. در ادامه به این موضوع نگاهی می‌اندازیم.

---

## داخلی

OpenCode با دو عامل اصلی داخلی و سه زیرعامل داخلی عرضه می‌شود.

---

### استفاده از build

_حالت_: `primary`

Build عامل اصلی **پیش‌فرض** با همه‌ی ابزارهای فعال است. این عامل استاندارد برای کارهای توسعه است، جایی که به دسترسی کامل به عملیات فایل و دستورات سیستم نیاز دارید.

---

### استفاده از plan

_حالت_: `primary`

عاملی محدود که برای برنامه‌ریزی و تحلیل طراحی شده است. ما از یک سیستم مجوز استفاده می‌کنیم تا کنترل بیشتری به شما بدهیم و از تغییرات ناخواسته جلوگیری کنیم.
به‌صورت پیش‌فرض، همه‌ی موارد زیر روی `ask` تنظیم شده‌اند:

- `file edits`: همه‌ی نوشتن‌ها، پچ‌ها و ویرایش‌ها
- `bash`: همه‌ی دستورات bash

این عامل زمانی مفید است که می‌خواهید LLM کد را تحلیل کند، تغییراتی را پیشنهاد دهد یا برنامه‌هایی بسازد بدون اینکه هیچ تغییر واقعی‌ای در کد شما ایجاد کند.

---

### استفاده از general

_حالت_: `subagent`

عاملی همه‌منظوره برای پژوهش درباره‌ی پرسش‌های پیچیده و اجرای کارهای چندمرحله‌ای. دسترسی کامل به ابزارها دارد (به‌جز todo)، بنابراین در صورت نیاز می‌تواند تغییراتی در فایل‌ها ایجاد کند. از این عامل برای اجرای چند واحد کار به‌صورت موازی استفاده کنید.

---

### استفاده از explore

_حالت_: `subagent`

عاملی سریع و فقط‌خواندنی برای کاوش در کدبیس‌ها. نمی‌تواند فایل‌ها را تغییر دهد. زمانی از این عامل استفاده کنید که نیاز دارید به‌سرعت فایل‌ها را بر اساس الگوها پیدا کنید، کد را برای کلیدواژه‌ها جست‌وجو کنید، یا به پرسش‌هایی درباره‌ی کدبیس پاسخ دهید.

---

### استفاده از scout

_حالت_: `subagent`

عاملی فقط‌خواندنی برای مستندات خارجی و پژوهش درباره‌ی وابستگی‌ها. زمانی از این عامل استفاده کنید که نیاز دارید مخزن یک وابستگی را در حافظه‌ی نهان مدیریت‌شده‌ی OpenCode کلون کنید، سورس یک کتابخانه را بررسی کنید، یا کد محلی را بدون تغییر فضای کاری خود با پیاده‌سازی‌های upstream مقایسه کنید.

---

### استفاده از compaction

_حالت_: `primary`

عامل سیستمی پنهانی که زمینه‌ی طولانی را به خلاصه‌ای کوچک‌تر فشرده می‌کند. در صورت نیاز به‌صورت خودکار اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

### استفاده از title

_حالت_: `primary`

عامل سیستمی پنهانی که عنوان‌های کوتاه برای نشست‌ها تولید می‌کند. به‌صورت خودکار اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

### استفاده از summary

_حالت_: `primary`

عامل سیستمی پنهانی که خلاصه‌های نشست را می‌سازد. به‌صورت خودکار اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

## استفاده

1. برای عامل‌های اصلی، از کلید **Tab** برای چرخیدن میان آن‌ها در طول یک نشست استفاده کنید. همچنین می‌توانید از کلید میان‌بُر `switch_agent` که پیکربندی کرده‌اید استفاده کنید.

2. زیرعامل‌ها را می‌توان فراخوانی کرد:
   - **به‌صورت خودکار** توسط عامل‌های اصلی برای کارهای تخصصی بر اساس توصیف‌هایشان.
   - به‌صورت دستی با **اشاره‌ی @** به یک زیرعامل در پیام شما. برای مثال.

     ```txt frame="none"
     @general help me search for this function
     ```

3. **پیمایش میان نشست‌ها**: وقتی زیرعامل‌ها نشست‌های فرزند ایجاد می‌کنند، از `session_child_first` (پیش‌فرض: **\<Leader>+Down**) برای ورود به اولین نشست فرزند از نشست والد استفاده کنید.

4. هنگامی که در یک نشست فرزند هستید، از موارد زیر استفاده کنید:
   - `session_child_cycle` (پیش‌فرض: **Right**) برای چرخیدن به نشست فرزند بعدی
   - `session_child_cycle_reverse` (پیش‌فرض: **Left**) برای چرخیدن به نشست فرزند قبلی
   - `session_parent` (پیش‌فرض: **Up**) برای بازگشت به نشست والد

   این کار به شما اجازه می‌دهد بین مکالمه‌ی اصلی و کار تخصصی زیرعامل‌ها جابه‌جا شوید.

---

## پیکربندی

می‌توانید عامل‌های داخلی را سفارشی کنید یا عامل‌های خود را از طریق پیکربندی بسازید. عامل‌ها را می‌توان به دو روش پیکربندی کرد:

---

### JSON

عامل‌ها را در فایل پیکربندی `opencode.json` خود پیکربندی کنید:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "{file:./prompts/build.txt}",
      "permission": {
        "edit": "allow",
        "bash": "allow"
      }
    },
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-haiku-4-20250514",
      "permission": {
        "edit": "deny",
        "bash": "deny"
      }
    },
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "You are a code reviewer. Focus on security, performance, and maintainability.",
      "permission": {
        "edit": "deny"
      }
    }
  }
}
```

---

### Markdown

همچنین می‌توانید عامل‌ها را با استفاده از فایل‌های markdown تعریف کنید. آن‌ها را در این مسیرها قرار دهید:

- سراسری: `~/.config/opencode/agents/`
- مخصوص هر پروژه: `.opencode/agents/`

```markdown title="~/.config/opencode/agents/review.md"
---
description: Reviews code for quality and best practices
mode: subagent
model: anthropic/claude-sonnet-4-20250514
temperature: 0.1
permission:
  edit: deny
  bash: deny
---

You are in code review mode. Focus on:

- Code quality and best practices
- Potential bugs and edge cases
- Performance implications
- Security considerations

Provide constructive feedback without making direct changes.
```

نام فایل markdown به نام عامل تبدیل می‌شود. برای مثال، `review.md` یک عامل `review` می‌سازد.

---

## گزینه‌ها

بیایید این گزینه‌های پیکربندی را با جزئیات بررسی کنیم.

---

### Description

از گزینه‌ی `description` برای ارائه‌ی توصیفی کوتاه از کاری که عامل انجام می‌دهد و زمان استفاده از آن بهره ببرید.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "description": "Reviews code for best practices and potential issues"
    }
  }
}
```

این یک گزینه‌ی پیکربندی **الزامی** است.

---

### Temperature

تصادفی‌بودن و خلاقیت پاسخ‌های LLM را با پیکربندی `temperature` کنترل کنید.

مقادیر پایین‌تر پاسخ‌ها را متمرکزتر و قطعی‌تر می‌کنند، در حالی که مقادیر بالاتر خلاقیت و تنوع را افزایش می‌دهند.

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "temperature": 0.1
    },
    "creative": {
      "temperature": 0.8
    }
  }
}
```

مقادیر temperature معمولاً بین 0.0 تا 1.0 قرار دارند:

- **0.0-0.2**: پاسخ‌های بسیار متمرکز و قطعی، ایده‌آل برای تحلیل کد و برنامه‌ریزی
- **0.3-0.5**: پاسخ‌های متعادل با کمی خلاقیت، مناسب برای کارهای توسعه‌ی عمومی
- **0.6-1.0**: پاسخ‌های خلاقانه‌تر و متنوع‌تر، مفید برای طوفان فکری و کاوش

```json title="opencode.json"
{
  "agent": {
    "analyze": {
      "temperature": 0.1,
      "prompt": "{file:./prompts/analysis.txt}"
    },
    "build": {
      "temperature": 0.3
    },
    "brainstorm": {
      "temperature": 0.7,
      "prompt": "{file:./prompts/creative.txt}"
    }
  }
}
```

اگر هیچ temperature تعیین نشود، OpenCode از مقادیر پیش‌فرض مخصوص مدل استفاده می‌کند؛ معمولاً 0 برای بیشتر مدل‌ها و 0.55 برای مدل‌های Qwen.

---

### Max steps

حداکثر تعداد تکرارهای عاملانه‌ای را که یک عامل می‌تواند پیش از اینکه مجبور به پاسخ‌دادن فقط با متن شود انجام دهد کنترل کنید. این کار به کاربرانی که می‌خواهند هزینه‌ها را کنترل کنند اجازه می‌دهد محدودیتی برای اقدامات عاملانه تعیین کنند.

اگر این گزینه تنظیم نشود، عامل تا زمانی که مدل تصمیم به توقف بگیرد یا کاربر نشست را قطع کند به تکرار ادامه می‌دهد.

```json title="opencode.json"
{
  "agent": {
    "quick-thinker": {
      "description": "Fast reasoning with limited iterations",
      "prompt": "You are a quick thinker. Solve problems with minimal steps.",
      "steps": 5
    }
  }
}
```

وقتی به این حد می‌رسد، عامل یک پرامپت سیستمی ویژه دریافت می‌کند که به آن دستور می‌دهد با خلاصه‌ای از کارش و کارهای باقی‌مانده‌ی توصیه‌شده پاسخ دهد.

:::caution
فیلد قدیمی `maxSteps` منسوخ شده است. به‌جای آن از `steps` استفاده کنید.
:::

---

### Disable

برای غیرفعال‌کردن عامل، آن را روی `true` تنظیم کنید.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "disable": true
    }
  }
}
```

---

### Prompt

یک فایل پرامپت سیستمی سفارشی برای این عامل با پیکربندی `prompt` تعیین کنید. فایل پرامپت باید دستورهای مخصوص هدف عامل را در بر داشته باشد.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "prompt": "{file:./prompts/code-review.txt}"
    }
  }
}
```

این مسیر نسبت به جایی که فایل پیکربندی در آن قرار دارد، نسبی است. بنابراین این برای هر دو پیکربندی سراسری OpenCode و پیکربندی مخصوص پروژه کار می‌کند.

---

### Model

از پیکربندی `model` برای جایگزین‌کردن مدل این عامل استفاده کنید. این برای استفاده از مدل‌های مختلف بهینه‌شده برای کارهای مختلف مفید است. برای مثال، مدلی سریع‌تر برای برنامه‌ریزی و مدلی توانمندتر برای پیاده‌سازی.

:::tip
اگر مدلی تعیین نکنید، عامل‌های اصلی از [مدل پیکربندی‌شده‌ی سراسری](/docs/config#models) استفاده می‌کنند، در حالی که زیرعامل‌ها از مدل عامل اصلی‌ای که زیرعامل را فراخوانی کرده استفاده خواهند کرد.
:::

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "model": "anthropic/claude-haiku-4-20250514"
    }
  }
}
```

شناسه‌ی مدل در پیکربندی OpenCode شما از قالب `provider/model-id` استفاده می‌کند. برای مثال، اگر از [OpenCode Zen](/docs/zen) استفاده می‌کنید، برای GPT 5.1 Codex از `opencode/gpt-5.1-codex` استفاده خواهید کرد.

---

### Tools (منسوخ‌شده)

`tools` **منسوخ** شده است. برای پیکربندی‌های جدید، به‌روزرسانی‌ها و کنترل دقیق‌تر، فیلد [`permission`](#permissions) عامل را ترجیح دهید.

به شما اجازه می‌دهد کنترل کنید کدام ابزارها در این عامل در دسترس باشند. می‌توانید ابزارهای مشخصی را با تنظیم آن‌ها روی `true` یا `false` فعال یا غیرفعال کنید. در پیکربندی `tools` یک عامل، `true` معادل مجوز `{"*": "allow"}` و `false` معادل مجوز `{"*": "deny"}` است.

```json title="opencode.json" {3-6,9-12}
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

:::note
پیکربندی مخصوص عامل، پیکربندی سراسری را جایگزین می‌کند.
:::

همچنین می‌توانید در ورودی‌های قدیمی `tools` از وایلدکارت‌ها برای کنترل چند ابزار به‌صورت همزمان استفاده کنید. برای مثال، برای غیرفعال‌کردن همه‌ی ابزارهای یک سرور MCP:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "readonly": {
      "tools": {
        "mymcp_*": false,
        "write": false,
        "edit": false
      }
    }
  }
}
```

[درباره‌ی ابزارها بیشتر بدانید](/docs/tools).

---

### Permissions

می‌توانید مجوزها را پیکربندی کنید تا مدیریت کنید یک عامل چه اقداماتی می‌تواند انجام دهد. هر کلید مجوز را می‌توان روی این مقادیر تنظیم کرد:

- `"ask"` — پیش از اجرای ابزار، درخواست تأیید کن
- `"allow"` — اجازه‌ی همه‌ی عملیات بدون تأیید
- `"deny"` — غیرفعال‌کردن ابزار

کلیدهای مجوز موجود عبارت‌اند از:

| کلید                 | ابزارهایی که محدود می‌کند                                          |
| -------------------- | ---------------------------------------------------------------- |
| `read`               | `read`                                                           |
| `edit`               | `write`، `edit`، `apply_patch`                                   |
| `glob`               | `glob`                                                           |
| `grep`               | `grep`                                                           |
| `list`               | `list`                                                           |
| `bash`               | `bash`                                                           |
| `task`               | `task`                                                           |
| `external_directory` | هر ابزاری که فایل‌های خارج از worktree پروژه را می‌خواند یا می‌نویسد |
| `todowrite`          | `todowrite`، `todoread`                                          |
| `webfetch`           | `webfetch`                                                       |
| `websearch`          | `websearch`                                                      |
| `lsp`                | `lsp`                                                            |
| `skill`              | `skill`                                                          |
| `question`           | `question`                                                       |
| `doom_loop`          | پرامپت‌های بازیابی زمانی که به نظر می‌رسد عامل گیر کرده است          |

`read`، `edit`، `glob`، `grep`، `list`، `bash`، `task`، `external_directory`، `lsp` و `skill` یا یک اقدام مختصر (`"allow" | "ask" | "deny"`) یا یک شیء از glob/الگو ← اقدام را برای کنترل دقیق می‌پذیرند. کلیدهای باقی‌مانده فقط اقدام مختصر را می‌پذیرند.

:::note
کلیدهای مجوز به‌عنوان الگوهای وایلدکارت در برابر نام ابزار زیربنایی مطابقت داده می‌شوند، بنابراین همان نحو برای ابزارهای داخلی، ابزارهای سفارشی و ابزارهای MCP کار می‌کند — برای مثال `"mymcp_*": "deny"` همه‌ی ابزارهای یک سرور MCP را رد می‌کند و `"mymcp_search": "ask"` تنها یکی از آن‌ها را هدف می‌گیرد.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  }
}
```

می‌توانید این مجوزها را برای هر عامل جایگزین کنید.

```json title="opencode.json" {3-5,8-10}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  },
  "agent": {
    "build": {
      "permission": {
        "edit": "ask"
      }
    }
  }
}
```

همچنین می‌توانید مجوزها را در عامل‌های Markdown تنظیم کنید.

```markdown title="~/.config/opencode/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
    "grep *": allow
  webfetch: deny
---

Only analyze code and suggest changes.
```

می‌توانید مجوزها را برای دستورات bash مشخص تنظیم کنید.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git push": "ask",
          "grep *": "allow"
        }
      }
    }
  }
}
```

این می‌تواند یک الگوی glob بگیرد.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git *": "ask"
        }
      }
    }
  }
}
```

و همچنین می‌توانید از وایلدکارت `*` برای مدیریت مجوزهای همه‌ی دستورات استفاده کنید.
از آنجا که آخرین قاعده‌ی مطابق اولویت دارد، وایلدکارت `*` را اول و قواعد مشخص را بعد از آن قرار دهید.

```json title="opencode.json" {8}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status *": "allow"
        }
      }
    }
  }
}
```

[درباره‌ی مجوزها بیشتر بدانید](/docs/permissions).

### Mode

حالت عامل را با پیکربندی `mode` کنترل کنید. گزینه‌ی `mode` برای تعیین نحوه‌ی استفاده از عامل به کار می‌رود.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "mode": "subagent"
    }
  }
}
```

گزینه‌ی `mode` را می‌توان روی `primary`، `subagent` یا `all` تنظیم کرد. اگر هیچ `mode`‌ای تعیین نشود، مقدار پیش‌فرض `all` است.

---

### Hidden

یک زیرعامل را با `hidden: true` از منوی تکمیل خودکار `@` پنهان کنید. این برای زیرعامل‌های داخلی‌ای که فقط باید به‌صورت برنامه‌ای توسط عامل‌های دیگر از طریق ابزار Task فراخوانی شوند مفید است.

```json title="opencode.json"
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

این فقط بر دیده‌شدن عامل توسط کاربر در منوی تکمیل خودکار اثر می‌گذارد. عامل‌های پنهان همچنان می‌توانند توسط مدل از طریق ابزار Task فراخوانی شوند، اگر مجوزها اجازه دهند.

:::note
فقط برای عامل‌های `mode: subagent` اعمال می‌شود.
:::

---

### Task permissions

با `permission.task` کنترل کنید که یک عامل کدام زیرعامل‌ها را می‌تواند از طریق ابزار Task فراخوانی کند. از الگوهای glob برای مطابقت انعطاف‌پذیر استفاده می‌کند.

```json title="opencode.json"
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

وقتی روی `deny` تنظیم شود، زیرعامل به‌طور کامل از توصیف ابزار Task حذف می‌شود، بنابراین مدل تلاشی برای فراخوانی آن نخواهد کرد.

:::tip
قواعد به‌ترتیب ارزیابی می‌شوند و **آخرین قاعده‌ی مطابق برنده می‌شود**. در مثال بالا، `orchestrator-planner` با هر دو `*` (deny) و `orchestrator-*` (allow) مطابقت دارد، اما از آنجا که `orchestrator-*` بعد از `*` می‌آید، نتیجه `allow` است.
:::

:::tip
کاربران همیشه می‌توانند هر زیرعاملی را مستقیماً از طریق منوی تکمیل خودکار `@` فراخوانی کنند، حتی اگر مجوزهای task عامل آن را رد کنند.
:::

### Color

ظاهر بصری عامل را در رابط کاربری با گزینه‌ی `color` سفارشی کنید. این بر نحوه‌ی نمایش عامل در رابط اثر می‌گذارد.

از یک رنگ هگز معتبر (مثلاً `#FF5733`) یا رنگ تم استفاده کنید: `primary`، `secondary`، `accent`، `success`، `warning`، `error`، `info`.

```json title="opencode.json"
{
  "agent": {
    "creative": {
      "color": "#ff6b6b"
    },
    "code-reviewer": {
      "color": "accent"
    }
  }
}
```

### Top P

تنوع پاسخ را با گزینه‌ی `top_p` کنترل کنید. جایگزینی برای temperature برای کنترل تصادفی‌بودن.

```json title="opencode.json"
{
  "agent": {
    "brainstorm": {
      "top_p": 0.9
    }
  }
}
```

مقادیر بین 0.0 تا 1.0 قرار دارند. مقادیر پایین‌تر متمرکزتر و مقادیر بالاتر متنوع‌ترند.

---

### Additional

هر گزینه‌ی دیگری که در پیکربندی عامل خود تعیین کنید **مستقیماً** به‌عنوان گزینه‌های مدل به ارائه‌دهنده **منتقل خواهد شد**. این به شما اجازه می‌دهد از ویژگی‌ها و پارامترهای مخصوص ارائه‌دهنده استفاده کنید.

برای مثال، با مدل‌های استدلالی OpenAI می‌توانید میزان تلاش استدلالی را کنترل کنید:

```json title="opencode.json" {6,7}
{
  "agent": {
    "deep-thinker": {
      "description": "Agent that uses high reasoning effort for complex problems",
      "model": "openai/gpt-5",
      "reasoningEffort": "high",
      "textVerbosity": "low"
    }
  }
}
```

این گزینه‌های اضافی مخصوص مدل و ارائه‌دهنده هستند. برای پارامترهای موجود به مستندات ارائه‌دهنده‌ی خود مراجعه کنید.

:::tip
`opencode models` را اجرا کنید تا فهرستی از مدل‌های موجود را ببینید.
:::

## ساختن عامل‌ها

می‌توانید عامل‌های جدید را با استفاده از دستور زیر بسازید:

```bash
opencode agent create
```

این دستور تعاملی موارد زیر را انجام می‌دهد:

1. می‌پرسد عامل را کجا ذخیره کند؛ سراسری یا مخصوص پروژه.
2. توصیف کاری که عامل باید انجام دهد.
3. یک پرامپت سیستمی و شناسه‌ی مناسب تولید می‌کند.
4. به شما اجازه می‌دهد انتخاب کنید عامل کدام مجوزها را داشته باشد (هر چیزی که انتخاب نکنید رد می‌شود).
5. در نهایت، یک فایل markdown با پیکربندی عامل می‌سازد.

## موارد استفاده

در اینجا برخی موارد استفاده‌ی رایج برای عامل‌های مختلف آورده شده است.

- **عامل Build**: کار توسعه‌ی کامل با همه‌ی ابزارهای فعال
- **عامل Plan**: تحلیل و برنامه‌ریزی بدون ایجاد تغییرات
- **عامل Review**: بررسی کد با دسترسی فقط‌خواندنی به‌علاوه‌ی ابزارهای مستندسازی
- **عامل Debug**: متمرکز بر بررسی با ابزارهای bash و read فعال
- **عامل Docs**: نوشتن مستندات با عملیات فایل اما بدون دستورات سیستم
