---

عامل‌ها دستیارهای هوش مصنوعی تخصصی هستند که می‌توان آن‌ها را برای وظایف و جریان‌کاری خاص پیکربندی کرد. آن‌ها به شما امکان می‌دهند ابزارهای متمرکزی با درخواست‌های (prompt) سفارشی، مدل‌ها، و دسترسی به ابزار ایجاد کنید.

:::tip
از عاملِ plan برای تحلیل کد و بررسی پیشنهادها بدون ایجاد هیچ تغییری در کد استفاده کنید.
:::

می‌توانید در طول یک نشست بین عامل‌ها جابجا شوید یا با ذکر `@` آن‌ها را فرابخوانید.

---

## انواع

دو نوع عامل در OpenCode وجود دارد؛ عامل‌های اصلی و زیرعامل‌ها.

---

### عامل‌های اصلی

عامل‌های اصلی دستیارهای اصلی هستند که مستقیماً با آن‌ها تعامل دارید. می‌توانید با استفاده از کلید **Tab** یا کلید میانبر `switch_agent` که پیکربندی کرده‌اید، میان آن‌ها بچرخید. این عامل‌ها گفتگوی اصلی شما را مدیریت می‌کنند. دسترسی به ابزارها از طریق مجوزها پیکربندی می‌شود — برای مثال، Build تمام ابزارها را فعال دارد در حالی که Plan محدود شده است.

:::tip
می‌توانید از کلید **Tab** برای جابجایی بین عامل‌های اصلی در طول یک نشست استفاده کنید.
:::

OpenCode با دو عامل اصلی داخلی، یعنی **Build** و **Plan**، ارائه می‌شود. این‌ها را در ادامه بررسی می‌کنیم.

---

### زیرعامل‌ها

زیرعامل‌ها دستیارهای تخصصی هستند که عامل‌های اصلی می‌توانند برای وظایف خاص آن‌ها را فرابخوانند. همچنین می‌توانید به‌صورت دستی با **@ ذکر کردن** آن‌ها در پیام‌هایتان، آن‌ها را فرابخوانید.

OpenCode با سه زیرعامل داخلی، یعنی **General**، **Explore**، و **Scout**، ارائه می‌شود. این را در ادامه بررسی می‌کنیم.

---

## داخلی

OpenCode با دو عامل اصلی داخلی و سه زیرعامل داخلی ارائه می‌شود.

---

### استفاده از build

_حالت_: `primary`

Build عامل اصلی **پیش‌فرض** با تمام ابزارهای فعال است. این عامل استاندارد برای کارهای توسعه‌ای است که در آن به دسترسی کامل به عملیات پرونده‌ها و دستورات سیستم نیاز دارید.

---

### استفاده از plan

_حالت_: `primary`

عاملی محدودشده که برای برنامه‌ریزی و تحلیل طراحی شده است. ما از یک سیستم مجوز استفاده می‌کنیم تا کنترل بیشتری به شما بدهیم و از تغییرات ناخواسته جلوگیری کنیم.
به‌طور پیش‌فرض، تمام موارد زیر روی `ask` تنظیم شده‌اند:

- `file edits`: تمام نوشته‌ها، وصله‌ها، و ویرایش‌ها
- `bash`: تمام دستورات bash

این عامل زمانی مفید است که می‌خواهید LLM کد را تحلیل کند، تغییرات پیشنهاد دهد، یا برنامه‌هایی بدون ایجاد هیچ تغییر واقعی در پایگاه کدتان ایجاد کند.

---

### استفاده از general

_حالت_: `subagent`

عاملی چندمنظوره برای پژوهش درباره پرسش‌های پیچیده و اجرای وظایف چندمرحله‌ای. دسترسی کامل به ابزارها (به‌جز todo) دارد، بنابراین می‌تواند در صورت نیاز تغییرات پرونده ایجاد کند. از این برای اجرای چندین واحد کاری به‌صورت موازی استفاده کنید.

---

### استفاده از explore

_حالت_: `subagent`

عاملی سریع و فقط-خواندنی برای کاوش در پایگاه‌های کد. نمی‌تواند پرونده‌ها را تغییر دهد. از این زمانی استفاده کنید که نیاز دارید به‌سرعت پرونده‌ها را بر اساس الگوها پیدا کنید، کد را برای کلیدواژه‌ها جستجو کنید، یا به پرسش‌هایی درباره پایگاه کد پاسخ دهید.

---

### استفاده از scout

_حالت_: `subagent`

عاملی فقط-خواندنی برای مستندات خارجی و پژوهش درباره وابستگی‌ها. از این زمانی استفاده کنید که نیاز دارید مخزن یک وابستگی را در حافظهٔ نهان مدیریت‌شدهٔ OpenCode کلون کنید، منبع کتابخانه را بازرسی کنید، یا کد محلی را در برابر پیاده‌سازی‌های بالادستی بدون تغییر فضای کاری‌تان تطبیق دهید.

---

### استفاده از compaction

_حالت_: `primary`

عامل سیستمی پنهان که زمینهٔ طولانی را به یک خلاصهٔ کوچکتر فشرده می‌کند. به‌طور خودکار وقتی نیاز باشد اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

### استفاده از title

_حالت_: `primary`

عامل سیستمی پنهان که عنوان‌های کوتاه نشست ایجاد می‌کند. به‌طور خودکار اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

### استفاده از summary

_حالت_: `primary`

عامل سیستمی پنهان که خلاصه‌های نشست ایجاد می‌کند. به‌طور خودکار اجرا می‌شود و در رابط کاربری قابل انتخاب نیست.

---

## استفاده

1. برای عامل‌های اصلی، از کلید **Tab** برای چرخش میان آن‌ها در طول یک نشست استفاده کنید. همچنین می‌توانید از کلید میانبر `switch_agent` که پیکربندی کرده‌اید استفاده کنید.

2. زیرعامل‌ها را می‌توان به این شکل‌ها فراخواند:
   - **به‌طور خودکار** توسط عامل‌های اصلی برای وظایف تخصصی بر اساس توصیف‌هایشان.
   - به‌صورت دستی با **@ ذکر کردن** یک زیرعامل در پیامتان. برای مثال.

     ```txt frame="none"
     @general help me search for this function
     ```

3. **ناوبری بین نشست‌ها**: وقتی زیرعامل‌ها نشست‌های فرزند ایجاد می‌کنند، از `session_child_first` (پیش‌فرض: **\<Leader>+Down**) برای ورود به اولین نشست فرزند از والد استفاده کنید.

4. وقتی در یک نشست فرزند هستید، از این‌ها استفاده کنید:
   - `session_child_cycle` (پیش‌فرض: **Right**) برای چرخش به نشست فرزند بعدی
   - `session_child_cycle_reverse` (پیش‌فرض: **Left**) برای چرخش به نشست فرزند قبلی
   - `session_parent` (پیش‌فرض: **Up**) برای بازگشت به نشست والد

   این به شما امکان می‌دهد بین گفتگوی اصلی و کار تخصصی زیرعامل جابجا شوید.

## پیکربندی

می‌توانید عامل‌های داخلی را سفارشی کنید یا عامل‌های خودتان را از طریق پیکربندی ایجاد کنید. عامل‌ها را می‌توان به دو روش پیکربندی کرد:

---

### JSON

عامل‌ها را در پروندهٔ پیکربندی `opencode.json` خود پیکربندی کنید:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "{file:./prompts/build.txt}",
      "permission": {
        "edit": "allow",
        "bash": "allow"
      }
    },
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-haiku-4-20250514",
      "permission": {
        "edit": "deny",
        "bash": "deny"
      }
    },
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "You are a code reviewer. Focus on security, performance, and maintainability.",
      "permission": {
        "edit": "deny"
      }
    }
  }
}
```

---

### Markdown

همچنین می‌توانید عامل‌ها را با استفاده از پرونده‌های markdown تعریف کنید. آن‌ها را در این مکان‌ها قرار دهید:

- سراسری: `~/.config/opencode/agents/`
- به‌ازایِ هر پروژه: `.opencode/agents/`

```markdown title="~/.config/opencode/agents/review.md"
---
description: Reviews code for quality and best practices
mode: subagent
model: anthropic/claude-sonnet-4-20250514
temperature: 0.1
permission:
  edit: deny
  bash: deny
---

You are in code review mode. Focus on:

- Code quality and best practices
- Potential bugs and edge cases
- Performance implications
- Security considerations

Provide constructive feedback without making direct changes.
```

نام پروندهٔ markdown به نام عامل تبدیل می‌شود. برای مثال، `review.md` یک عامل `review` ایجاد می‌کند.

---

## گزینه‌ها

بیایید این گزینه‌های پیکربندی را با جزئیات بررسی کنیم.

---

### Description

از گزینهٔ `description` برای ارائهٔ توصیفی کوتاه از اینکه عامل چه می‌کند و چه زمانی باید استفاده شود، استفاده کنید.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "description": "Reviews code for best practices and potential issues"
    }
  }
}
```

این یک گزینهٔ پیکربندی **ضروری** است.

---

### Temperature

میزان تصادفی‌بودن و خلاقیت پاسخ‌های LLM را با پیکربندی `temperature` کنترل کنید.

مقادیر پایین‌تر پاسخ‌ها را متمرکزتر و قطعی‌تر می‌کنند، در حالی که مقادیر بالاتر خلاقیت و تغییرپذیری را افزایش می‌دهند.

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "temperature": 0.1
    },
    "creative": {
      "temperature": 0.8
    }
  }
}
```

مقادیر temperature معمولاً از ۰٫۰ تا ۱٫۰ متغیرند:

- **۰٫۰-۰٫۲**: پاسخ‌های بسیار متمرکز و قطعی، ایده‌آل برای تحلیل کد و برنامه‌ریزی
- **۰٫۳-۰٫۵**: پاسخ‌های متوازن با کمی خلاقیت، مناسب برای وظایف توسعهٔ عمومی
- **۰٫۶-۱٫۰**: پاسخ‌های خلاق‌تر و متغیرتر، مفید برای طوفان فکری و کاوش

```json title="opencode.json"
{
  "agent": {
    "analyze": {
      "temperature": 0.1,
      "prompt": "{file:./prompts/analysis.txt}"
    },
    "build": {
      "temperature": 0.3
    },
    "brainstorm": {
      "temperature": 0.7,
      "prompt": "{file:./prompts/creative.txt}"
    }
  }
}
```

اگر هیچ temperature مشخص نشود، OpenCode از پیش‌فرض‌های ویژهٔ مدل استفاده می‌کند؛ معمولاً ۰ برای بیشتر مدل‌ها، و ۰٫۵۵ برای مدل‌های Qwen.

---

### Max steps

حداکثر تعداد تکرارهای agentic که یک عامل می‌تواند پیش از آنکه مجبور شود فقط با متن پاسخ دهد را کنترل کنید. این به کاربرانی که می‌خواهند هزینه را کنترل کنند اجازه می‌دهد سقفی برای اقدامات agentic تعیین کنند.

اگر این تنظیم نشود، عامل به تکرار ادامه می‌دهد تا زمانی که مدل تصمیم به توقف بگیرد یا کاربر نشست را قطع کند.

```json title="opencode.json"
{
  "agent": {
    "quick-thinker": {
      "description": "Fast reasoning with limited iterations",
      "prompt": "You are a quick thinker. Solve problems with minimal steps.",
      "steps": 5
    }
  }
}
```

وقتی سقف می‌رسد، عامل یک درخواست سیستمی ویژه دریافت می‌کند که به آن دستور می‌دهد با خلاصه‌ای از کارش و وظایف باقی‌ماندهٔ پیشنهادی پاسخ دهد.

:::caution
فیلد قدیمی `maxSteps` منسوخ شده است. به‌جای آن از `steps` استفاده کنید.
:::

---

### Disable

روی `true` تنظیم کنید تا عامل غیرفعال شود.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "disable": true
    }
  }
}
```

---

### Prompt

یک پروندهٔ درخواست سیستمی سفارشی برای این عامل با پیکربندی `prompt` مشخص کنید. پروندهٔ درخواست باید شامل دستورالعمل‌هایی مختص به هدف عامل باشد.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "prompt": "{file:./prompts/code-review.txt}"
    }
  }
}
```

این مسیر نسبت به محلی است که پروندهٔ پیکربندی در آن قرار دارد. بنابراین این هم برای پیکربندی سراسری OpenCode و هم برای پیکربندی ویژهٔ پروژه کار می‌کند.

---

### Model

از پیکربندی `model` برای لغو مدلِ پیش‌فرض این عامل استفاده کنید. مفید برای استفاده از مدل‌های مختلفی که برای وظایف متفاوت بهینه شده‌اند. برای مثال، مدلی سریع‌تر برای برنامه‌ریزی، و مدلی توانمندتر برای پیاده‌سازی.

:::tip
اگر مدلی را مشخص نکنید، عامل‌های اصلی از [مدلی که به‌صورت سراسری پیکربندی شده](/docs/config#models) استفاده می‌کنند، در حالی که زیرعامل‌ها از مدلِ عامل اصلی که زیرعامل را فراخوانده استفاده می‌کنند.
:::

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "model": "anthropic/claude-haiku-4-20250514"
    }
  }
}
```

شناسهٔ مدل در پیکربندی OpenCode شما از فرمت `provider/model-id` استفاده می‌کند. برای مثال، اگر از [OpenCode Zen](/docs/zen) استفاده می‌کنید، برای GPT 5.1 Codex باید از `opencode/gpt-5.1-codex` استفاده کنید.

---

### Tools (deprecated)

`tools` **منسوخ** شده است. برای پیکربندی‌های جدید، به‌روزرسانی‌ها و کنترل دقیق‌تر، فیلد [`permission`](#permissions) عامل را ترجیح دهید.

به شما اجازه می‌دهد کنترل کنید کدام ابزارها در این عامل در دسترس هستند. می‌توانید ابزارهای مشخصی را با تنظیم آن‌ها روی `true` یا `false` فعال یا غیرفعال کنید. در پیکربندی `tools` یک عامل، `true` معادل مجوز `{"*": "allow"}` و `false` معادل مجوز `{"*": "deny"}` است.

```json title="opencode.json" {3-6,9-12}
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

:::note
پیکربندی ویژهٔ عامل، پیکربندی سراسری را لغو می‌کند.
:::

همچنین می‌توانید در ورودی‌های قدیمی `tools` از کاراکترهای عام استفاده کنید تا چندین ابزار را یکجا کنترل کنید. برای مثال، برای غیرفعال کردن تمام ابزارهای یک سرور MCP:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "readonly": {
      "tools": {
        "mymcp_*": false,
        "write": false,
        "edit": false
      }
    }
  }
}
```

[دربارهٔ ابزارها بیشتر بیاموزید](/docs/tools).

### Permissions

می‌توانید مجوزها را برای مدیریت اینکه یک عامل چه اقداماتی می‌تواند انجام دهد پیکربندی کنید. هر کلید مجوز می‌تواند روی یکی از موارد زیر تنظیم شود:

- `"ask"` — پیش از اجرای ابزار، درخواست تأیید کند
- `"allow"` — اجازه دهد تمام عملیات بدون تأیید انجام شود
- `"deny"` — ابزار را غیرفعال کند

کلیدهای مجوز موجود عبارتند از:

| Key                  | Tools it gates                                                   |
| -------------------- | ---------------------------------------------------------------- |
| `read`               | `read`                                                           |
| `edit`               | `write`, `edit`, `apply_patch`                                   |
| `glob`               | `glob`                                                           |
| `grep`               | `grep`                                                           |
| `list`               | `list`                                                           |
| `bash`               | `bash`                                                           |
| `task`               | `task`                                                           |
| `external_directory` | Any tool that reads or writes files outside the project worktree |
| `todowrite`          | `todowrite`, `todoread`                                          |
| `webfetch`           | `webfetch`                                                       |
| `websearch`          | `websearch`                                                      |
| `lsp`                | `lsp`                                                            |
| `skill`              | `skill`                                                          |
| `question`           | `question`                                                       |
| `doom_loop`          | Recovery prompts when an agent appears stuck                     |

کلیدهای `read`, `edit`, `glob`, `grep`, `list`, `bash`, `task`, `external_directory`, `lsp`, و `skill` یا یک اقدام کوتاه‌نوشت (`"allow" | "ask" | "deny"`) یا یک شیء از الگو/glob → اقدام برای کنترل دقیق می‌پذیرند. بقیهٔ کلیدها فقط اقدام کوتاه‌نوشت را می‌پذیرند.

:::note
کلیدهای مجوز به‌عنوان الگوهای عام در برابر نام ابزارِ زیربنایی تطبیق داده می‌شوند، بنابراین همان نحو برای ابزارهای داخلی، ابزارهای سفارشی، و ابزارهای MCP کار می‌کند — برای مثال `"mymcp_*": "deny"` هر ابزاری از یک سرور MCP را رد می‌کند، و `"mymcp_search": "ask"` یکی را هدف قرار می‌دهد.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  }
}
```

می‌توانید این مجوزها را به‌ازایِ هر عامل لغو کنید.

```json title="opencode.json" {3-5,8-10}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  },
  "agent": {
    "build": {
      "permission": {
        "edit": "ask"
      }
    }
  }
}
```

همچنین می‌توانید مجوزها را در عامل‌های Markdown تنظیم کنید.

```markdown title="~/.config/opencode/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
    "grep *": allow
  webfetch: deny
---

Only analyze code and suggest changes.
```

می‌توانید مجوزها را برای دستورات bash مشخص تنظیم کنید.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git push": "ask",
          "grep *": "allow"
        }
      }
    }
  }
}
```

این می‌تواند یک الگوی glob بگیرد.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git *": "ask"
        }
      }
    }
  }
}
```

و همچنین می‌توانید از کاراکتر عام `*` برای مدیریت مجوزهای تمام دستورات استفاده کنید.
از آنجا که آخرین قانون مطابق‌شده اولویت دارد، کاراکتر عام `*` را ابتدا و قوانین مشخص را بعد قرار دهید.

```json title="opencode.json" {8}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status *": "allow"
        }
      }
    }
  }
}
```

[دربارهٔ مجوزها بیشتر بیاموزید](/docs/permissions).

### Mode

حالت عامل را با پیکربندی `mode` کنترل کنید. گزینهٔ `mode` برای تعیین اینکه عامل چگونه می‌تواند استفاده شود به کار می‌رود.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "mode": "subagent"
    }
  }
}
```

گزینهٔ `mode` می‌تواند روی `primary`، `subagent`، یا `all` تنظیم شود. اگر هیچ `mode` مشخص نشود، پیش‌فرض آن `all` است.

---

### Hidden

یک زیرعامل را با `hidden: true` از منوی تکمیل‌خودکار `@` پنهان کنید. مفید برای زیرعامل‌های داخلی که فقط باید به‌صورت برنامه‌نویسی‌شده توسط عامل‌های دیگر از طریق ابزار Task فراخوانده شوند.

```json title="opencode.json"
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

این فقط بر دیدِ کاربر در منوی تکمیل‌خودکار تأثیر می‌گذارد. عامل‌های پنهان همچنان می‌توانند در صورت اجازهٔ مجوزها توسط مدل از طریق ابزار Task فراخوانده شوند.

:::note
فقط برای عامل‌هایی با `mode: subagent` اعمال می‌شود.
:::

### Task permissions

کنترل کنید کدام زیرعامل‌ها را یک عامل می‌تواند از طریق ابزار Task با `permission.task` فرابخواند. از الگوهای glob برای تطبیق انعطاف‌پذیر استفاده می‌کند.

```json title="opencode.json"
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

وقتی روی `deny` تنظیم شود، زیرعامل کلاً از توصیف ابزار Task حذف می‌شود، بنابراین مدل تلاشی برای فراخوانی آن نخواهد کرد.

:::tip
قوانین به ترتیب ارزیابی می‌شوند، و **آخرین قانون مطابق‌شده برنده است**. در مثال بالا، `orchestrator-planner` با هر دو `*` (deny) و `orchestrator-*` (allow) تطبیق می‌یابد، اما از آنجا که `orchestrator-*` بعد از `*` می‌آید، نتیجه `allow` است.
:::

:::tip
کاربران همیشه می‌توانند هر زیرعاملی را مستقیماً از طریق منوی تکمیل‌خودکار `@` فرابخوانند، حتی اگر مجوزهای task عامل آن را رد کند.
:::

### Color

ظاهر بصری عامل در رابط کاربری را با گزینهٔ `color` سفارشی کنید. این بر نحوهٔ نمایش عامل در رابط تأثیر می‌گذارد.

از یک رنگ hex معتبر (مثل `#FF5733`) یا رنگ تم استفاده کنید: `primary`, `secondary`, `accent`, `success`, `warning`, `error`, `info`.

```json title="opencode.json"
{
  "agent": {
    "creative": {
      "color": "#ff6b6b"
    },
    "code-reviewer": {
      "color": "accent"
    }
  }
}
```

### Top P

تنوع پاسخ را با گزینهٔ `top_p` کنترل کنید. جایگزینی برای temperature جهت کنترل تصادفی‌بودن.

```json title="opencode.json"
{
  "agent": {
    "brainstorm": {
      "top_p": 0.9
    }
  }
}
```

مقادیر از ۰٫۰ تا ۱٫۰ متغیرند. مقادیر پایین‌تر متمرکزتر، و مقادیر بالاتر متنوع‌تر هستند.

### Additional

هر گزینهٔ دیگری که در پیکربندی عامل خود مشخص کنید، به‌طور **مستقیم به ارائه‌دهنده به‌عنوان گزینه‌های مدل منتقل می‌شود**. این به شما اجازه می‌دهد از ویژگی‌ها و پارامترهای ویژهٔ ارائه‌دهنده استفاده کنید.

برای مثال، با مدل‌های استنتاجی OpenAI، می‌توانید تلاش استنتاجی را کنترل کنید:

```json title="opencode.json" {6,7}
{
  "agent": {
    "deep-thinker": {
      "description": "Agent that uses high reasoning effort for complex problems",
      "model": "openai/gpt-5",
      "reasoningEffort": "high",
      "textVerbosity": "low"
    }
  }
}
```

این گزینه‌های اضافی ویژهٔ مدل و ارائه‌دهنده هستند. مستندات ارائه‌دهندهٔ خود را برای پارامترهای موجود بررسی کنید.

:::tip
دستور `opencode models` را اجرا کنید تا فهرستی از مدل‌های موجود را ببینید.
:::

## ایجاد عامل‌ها

می‌توانید عامل‌های جدید را با استفاده از دستور زیر ایجاد کنید:

```bash
opencode agent create
```

این دستور تعاملی:

1. می‌پرسد عامل کجا ذخیره شود؛ سراسری یا ویژهٔ پروژه.
2. توصیفی از اینکه عامل باید چه کند.
3. یک درخواست سیستمی و شناسهٔ مناسب تولید می‌کند.
4. به شما اجازه می‌دهد انتخاب کنید کدام مجوزها باید به عامل داده شود (هر چیزی که انتخاب نکنید رد می‌شود).
5. در نهایت، یک پروندهٔ markdown با پیکربندی عامل ایجاد می‌کند.

## موارد کاربرد

در اینجا برخی موارد کاربرد رایج برای عامل‌های مختلف آمده است.

- **عامل Build**: کارهای توسعهٔ کامل با تمام ابزارهای فعال
- **عامل Plan**: تحلیل و برنامه‌ریزی بدون ایجاد تغییر
- **عامل Review**: بازبینی کد با دسترسی فقط-خواندنی به‌علاوهٔ ابزارهای مستندسازی
- **عامل Debug**: متمرکز بر بررسی با ابزارهای bash و read فعال
- **عامل Docs**: نوشتن مستندات با عملیات پرونده اما بدون دستورات سیستم
