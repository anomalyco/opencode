---
title: ابزارها
description: ابزارهایی که یک LLM می‌تواند استفاده کند را مدیریت کنید.
---

ابزارها به LLM اجازه می‌دهند تا اقداماتی را در کدبیس شما انجام دهد. OpenCode با مجموعه‌ای از ابزارهای داخلی عرضه می‌شود، اما می‌توانید آن را با [ابزارهای سفارشی](/docs/custom-tools) یا [سرورهای MCP](/docs/mcp-servers) گسترش دهید.

به‌طور پیش‌فرض، همه ابزارها **فعال** هستند و برای اجرا به مجوز نیاز ندارند. می‌توانید رفتار ابزارها را از طریق [مجوزها](/docs/permissions) کنترل کنید.

---

## پیکربندی

از فیلد `permission` برای کنترل رفتار ابزارها استفاده کنید. می‌توانید برای هر ابزار اجازه دهید، رد کنید یا درخواست تأیید کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny",
    "bash": "ask",
    "webfetch": "allow"
  }
}
```

همچنین می‌توانید از وایلدکارد برای کنترل چند ابزار به‌صورت همزمان استفاده کنید. برای مثال، برای درخواست تأیید برای همه ابزارهای یک سرور MCP:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "mymcp_*": "ask"
  }
}
```

درباره پیکربندی مجوزها [بیشتر بدانید](/docs/permissions).

---

## داخلی

در اینجا همه ابزارهای داخلی موجود در OpenCode آمده است.

---

### bash

دستورات shell را در محیط پروژه خود اجرا کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": "allow"
  }
}
```

این ابزار به LLM اجازه می‌دهد دستورات ترمینال مانند `npm install`، `git status` یا هر دستور shell دیگری را اجرا کند.

---

### edit

فایل‌های موجود را با استفاده از جایگزینی دقیق رشته‌ای ویرایش کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

این ابزار با جایگزینی تطابق‌های دقیق متنی، ویرایش‌های دقیقی روی فایل‌ها انجام می‌دهد. این روش اصلی است که LLM با آن کد را ویرایش می‌کند.

---

### write

فایل‌های جدید ایجاد کنید یا فایل‌های موجود را بازنویسی کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

از این برای اجازه دادن به LLM جهت ایجاد فایل‌های جدید استفاده کنید. اگر فایل‌ها از قبل موجود باشند، روی آن‌ها بازنویسی می‌کند.

:::note
ابزار `write` توسط مجوز `edit` کنترل می‌شود که همه ویرایش‌های فایل (`edit`، `write`، `apply_patch`) را پوشش می‌دهد.
:::

---

### read

محتوای فایل‌ها را از کدبیس خود بخوانید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "read": "allow"
  }
}
```

این ابزار فایل‌ها را می‌خواند و محتوای آن‌ها را برمی‌گرداند. از خواندن بازه‌های مشخصی از خطوط برای فایل‌های بزرگ پشتیبانی می‌کند.

---

### grep

محتوای فایل‌ها را با استفاده از عبارات منظم جستجو کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "grep": "allow"
  }
}
```

جستجوی سریع محتوا در سراسر کدبیس شما. از نحو کامل regex و فیلتر کردن بر اساس الگوی فایل پشتیبانی می‌کند.

---

### glob

فایل‌ها را با تطبیق الگو پیدا کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "glob": "allow"
  }
}
```

فایل‌ها را با استفاده از الگوهای glob مانند `**/*.js` یا `src/**/*.ts` جستجو کنید. مسیرهای فایل‌های منطبق را مرتب‌شده بر اساس زمان ویرایش برمی‌گرداند.

---

### lsp (آزمایشی)

با سرورهای LSP پیکربندی‌شده خود تعامل کنید تا ویژگی‌های هوش کد مانند تعریف‌ها، ارجاع‌ها، اطلاعات hover و سلسله‌مراتب فراخوانی را به دست آورید.

:::note
این ابزار فقط زمانی در دسترس است که `OPENCODE_EXPERIMENTAL_LSP_TOOL=true` (یا `OPENCODE_EXPERIMENTAL=true`) باشد.
:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "lsp": "allow"
  }
}
```

عملیات پشتیبانی‌شده شامل `goToDefinition`، `findReferences`، `hover`، `documentSymbol`، `workspaceSymbol`، `goToImplementation`، `prepareCallHierarchy`، `incomingCalls` و `outgoingCalls` است.

برای پیکربندی اینکه کدام سرورهای LSP برای پروژه شما در دسترس باشند، [سرورهای LSP](/docs/lsp) را ببینید.

---

### apply_patch

پچ‌ها را روی فایل‌ها اعمال کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

این ابزار فایل‌های پچ را روی کدبیس شما اعمال می‌کند. برای اعمال diffها و پچ‌ها از منابع مختلف مفید است.

هنگام مدیریت هوک‌های `tool.execute.before` یا `tool.execute.after`، مقدار `input.tool === "apply_patch"` را بررسی کنید (نه `"patch"`).

`apply_patch` به‌جای `output.args.filePath` از `output.args.patchText` استفاده می‌کند. مسیرها در خطوط نشانگر درون `patchText` تعبیه شده‌اند و نسبت به ریشه پروژه هستند (برای مثال: `*** Add File: src/new-file.ts`، `*** Update File: src/existing.ts`، `*** Move to: src/renamed.ts`، `*** Delete File: src/obsolete.ts`).

:::note
ابزار `apply_patch` توسط مجوز `edit` کنترل می‌شود که همه ویرایش‌های فایل (`edit`، `write`، `apply_patch`) را پوشش می‌دهد.
:::

---

### skill

یک [مهارت](/docs/skills) (یک فایل `SKILL.md`) را بارگذاری کنید و محتوای آن را در مکالمه برگردانید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "skill": "allow"
  }
}
```

---

### todowrite

فهرست کارها را در طول جلسات کدنویسی مدیریت کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "todowrite": "allow"
  }
}
```

فهرست‌های وظایف را برای پیگیری پیشرفت در طول عملیات پیچیده ایجاد و به‌روزرسانی می‌کند. LLM از این برای سازماندهی وظایف چندمرحله‌ای استفاده می‌کند.

:::note
این ابزار به‌طور پیش‌فرض برای زیرعامل‌ها غیرفعال است، اما می‌توانید آن را به‌صورت دستی فعال کنید. [بیشتر بدانید](/docs/agents/#permissions)
:::

---

### webfetch

محتوای وب را دریافت کنید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "webfetch": "allow"
  }
}
```

به LLM اجازه می‌دهد صفحات وب را دریافت و بخواند. برای جستجوی مستندات یا تحقیق درباره منابع آنلاین مفید است.

---

### websearch

برای یافتن اطلاعات در وب جستجو کنید.

:::note
این ابزار فقط زمانی در دسترس است که از ارائه‌دهنده OpenCode استفاده می‌کنید یا زمانی که متغیر محیطی `OPENCODE_ENABLE_EXA` روی هر مقدار درست (truthy) تنظیم شده باشد (مثلاً `true` یا `1`).

برای فعال‌سازی هنگام راه‌اندازی OpenCode:

```bash
OPENCODE_ENABLE_EXA=1 opencode
```

:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "websearch": "allow"
  }
}
```

با استفاده از Exa AI جستجوهای وب را برای یافتن اطلاعات مرتبط آنلاین انجام می‌دهد. برای تحقیق درباره موضوعات، یافتن رویدادهای جاری یا گردآوری اطلاعات فراتر از زمان قطع داده‌های آموزشی مفید است.

به هیچ کلید API نیازی نیست — این ابزار بدون احراز هویت مستقیماً به سرویس MCP میزبانی‌شده Exa AI متصل می‌شود.

:::tip
وقتی نیاز به یافتن اطلاعات دارید (کشف) از `websearch` و وقتی نیاز به بازیابی محتوا از یک URL مشخص دارید (بازیابی) از `webfetch` استفاده کنید.
:::

---

### question

در حین اجرا از کاربر سؤال بپرسید.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "question": "allow"
  }
}
```

این ابزار به LLM اجازه می‌دهد تا در حین یک وظیفه از کاربر سؤال بپرسد. این برای موارد زیر مفید است:

- گردآوری ترجیحات یا نیازمندی‌های کاربر
- شفاف‌سازی دستورالعمل‌های مبهم
- گرفتن تصمیم درباره انتخاب‌های پیاده‌سازی
- ارائه گزینه‌هایی درباره مسیری که باید پیش گرفته شود

هر سؤال شامل یک سرعنوان، متن سؤال و فهرستی از گزینه‌هاست. کاربران می‌توانند از گزینه‌های ارائه‌شده انتخاب کنند یا پاسخی سفارشی تایپ کنند. وقتی چند سؤال وجود دارد، کاربران می‌توانند پیش از ارسال همه پاسخ‌ها بین آن‌ها جابه‌جا شوند.

## ابزارهای سفارشی

ابزارهای سفارشی به شما اجازه می‌دهند توابع خودتان را که LLM می‌تواند فراخوانی کند تعریف کنید. این‌ها در فایل پیکربندی شما تعریف می‌شوند و می‌توانند کد دلخواه را اجرا کنند.

درباره ساخت ابزارهای سفارشی [بیشتر بدانید](/docs/custom-tools).

---

## سرورهای MCP

سرورهای MCP (Model Context Protocol) به شما اجازه می‌دهند ابزارها و سرویس‌های خارجی را یکپارچه کنید. این شامل دسترسی به پایگاه داده، یکپارچه‌سازی API و سرویس‌های شخص ثالث می‌شود.

درباره پیکربندی سرورهای MCP [بیشتر بدانید](/docs/mcp-servers).

## جزئیات داخلی

از نظر داخلی، ابزارهایی مانند `grep` و `glob` در پشت صحنه از [ripgrep](https://github.com/BurntSushi/ripgrep) استفاده می‌کنند. به‌طور پیش‌فرض، ripgrep الگوهای `.gitignore` را رعایت می‌کند، به این معنی که فایل‌ها و دایرکتوری‌های فهرست‌شده در `.gitignore` شما از جستجوها و فهرست‌سازی‌ها کنار گذاشته می‌شوند.

---

### الگوهای نادیده‌گرفتن

برای گنجاندن فایل‌هایی که معمولاً نادیده گرفته می‌شوند، یک فایل `.ignore` در ریشه پروژه خود ایجاد کنید. این فایل می‌تواند مسیرهای خاصی را به‌صراحت اجازه دهد.

```text title=".ignore"
!node_modules/
!dist/
!build/
```

برای مثال، این فایل `.ignore` به ripgrep اجازه می‌دهد در دایرکتوری‌های `node_modules/`، `dist/` و `build/` جستجو کند، حتی اگر در `.gitignore` فهرست شده باشند.
