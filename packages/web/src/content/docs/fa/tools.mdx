---
title: ابزارها
description: مدیریت ابزارهایی که یک LLM می‌تواند استفاده کند.
---

ابزارها به LLM اجازه می‌دهند اقداماتی را در کد‌بنه شما انجام دهد. OpenCode با مجموعه‌ای از ابزارهای داخلی ارائه می‌شود، اما می‌توانید آن را با [ابزارهای سفارشی](/docs/custom-tools) یا [سرورهای MCP](/docs/mcp-servers) گسترش دهید.

به طور پیش‌فرض، تمام ابزارها **فعال** هستند و برای اجرا نیازی به مجوز ندارند. می‌توانید رفتار ابزارها را از طریق [مجوزها](/docs/permissions) کنترل کنید.

---

## پیکربندی

برای کنترل رفتار ابزارها از فیلد `permission` استفاده کنید. می‌توانید برای هر ابزار اجازه دهید، رد کنید یا نیاز به تأیید تعیین کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny",
    "bash": "ask",
    "webfetch": "allow"
  }
}
```

همچنین می‌توانید از کاراکترهای عام (wildcard) برای کنترل چندین ابزار به‌طور همزمان استفاده کنید. برای مثال، برای نیاز به تأیید تمام ابزارهای یک سرور MCP:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "mymcp_*": "ask"
  }
}
```

[اطلاعات بیشتر](/docs/permissions) درباره پیکربندی مجوزها.

---

## داخلی

در اینجا تمام ابزارهای داخلی موجود در OpenCode آورده شده است.

---

### bash

اجرای دستورات پوسته در محیط پروژه شما.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": "allow"
  }
}
```

این ابزار به LLM اجازه می‌دهد دستورات ترمینالی مانند `npm install`، `git status` یا هر دستور پوسته دیگری را اجرا کند.

---

### edit

اصلاح پرونده‌های موجود با استفاده از جایگزینی دقیق رشته‌ها.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

این ابزار ویرایش‌های دقیقی روی پرونده‌ها با جایگزینی تطابق‌های دقیق متن انجام می‌دهد. روش اصلی‌ای است که LLM کد را تغییر می‌دهد.

---

### write

ایجاد پرونده‌های جدید یا بازنویسی پرونده‌های موجود.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

از این برای اجازه دادن به LLM جهت ایجاد پرونده‌های جدید استفاده کنید. اگر پرونده‌ها از قبل وجود داشته باشند، آن‌ها را بازنویسی می‌کند.

:::note
ابزار `write` توسط مجوز `edit` کنترل می‌شود که تمام تغییرات پرونده (`edit`، `write`، `apply_patch`) را پوشش می‌دهد.
:::

---

### read

خواندن محتوای پرونده‌ها از کد‌بنه شما.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "read": "allow"
  }
}
```

این ابزار پرونده‌ها را می‌خواند و محتوای آن‌ها را بازمی‌گرداند. از خواندن محدوده‌های خط خاص برای پرونده‌های بزرگ پشتیبانی می‌کند.

---

### grep

جستجوی محتوای پرونده‌ها با استفاده از عبارات باقاعده.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "grep": "allow"
  }
}
```

جستجوی سریع محتوا در سراسر کد‌بنه. از نحو کامل regex و فیلتر الگوی پرونده پشتیبانی می‌کند.

---

### glob

یافتن پرونده‌ها با تطبیق الگو.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "glob": "allow"
  }
}
```

جستجو برای پرونده‌ها با استفاده از الگوهای glob مانند `**/*.js` یا `src/**/*.ts`. مسیرهای پرونده مطابق را مرتب‌شده بر پایه زمان تغییر بازمی‌گرداند.

---

### lsp (آزمایشی)

تعامل با سرورهای LSP پیکربندی‌شده شما برای دریافت ویژگی‌های هوش کد مانند تعاریف، ارجاع‌ها، اطلاعات هاور و سلسله‌مراتب فراخوانی.

:::note
این ابزار تنها زمانی در دسترس است که `OPENCODE_EXPERIMENTAL_LSP_TOOL=true` (یا `OPENCODE_EXPERIMENTAL=true`) باشد.
:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "lsp": "allow"
  }
}
```

عملیات‌های پشتیبانی‌شده شامل `goToDefinition`، `findReferences`، `hover`، `documentSymbol`، `workspaceSymbol`، `goToImplementation`، `prepareCallHierarchy`، `incomingCalls` و `outgoingCalls` هستند.

برای پیکربندی اینکه کدام سرورهای LSP برای پروژه شما در دسترس هستند، به [سرورهای LSP](/docs/lsp) مراجعه کنید.

---

### apply_patch

اعمال وصله (patch) روی پرونده‌ها.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

این ابزار پرونده‌های وصله را روی کد‌بنه شما اعمال می‌کند. برای اعمال تفاوت‌ها (diff) و وصله‌ها از منابع مختلف مفید است.

هنگام مدیریت هوک‌های `tool.execute.before` یا `tool.execute.after`، بررسی کنید `input.tool === "apply_patch"` (نه `"patch"`).

`apply_patch` از `output.args.patchText` به جای `output.args.filePath` استفاده می‌کند. مسیرها در خطوط نشانه‌گذار درون `patchText` جاسازی شده‌اند و نسبت به ریشه پروژه هستند (برای مثال: `*** Add File: src/new-file.ts`، `*** Update File: src/existing.ts`، `*** Move to: src/renamed.ts`، `*** Delete File: src/obsolete.ts`).

:::note
ابزار `apply_patch` توسط مجوز `edit` کنترل می‌شود که تمام تغییرات پرونده (`edit`، `write`، `apply_patch`) را پوشش می‌دهد.
:::

---

### skill

بارگذاری یک [مهارت](/docs/skills) (یک پرونده `SKILL.md`) و بازگرداندن محتوای آن در گفتگو.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "skill": "allow"
  }
}
```

---

### todowrite

مدیریت فهرست کارها در طول نشست‌های کدنویسی.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "todowrite": "allow"
  }
}
```

فهرست‌های وظیفه را ایجاد و به‌روزرسانی می‌کند تا پیشرفت را در طول عملیات پیچیده پیگیری کند. LLM از این برای سازماندهی وظایف چندمرحله‌ای استفاده می‌کند.

:::note
این ابزار به طور پیش‌فرض برای زیرعامل‌ها (subagents) غیرفعال است، اما می‌توانید آن را به‌صورت دستی فعال کنید. [اطلاعات بیشتر](/docs/agents/#permissions).
:::

---

### webfetch

واکشی محتوای وب.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "webfetch": "allow"
  }
}
```

به LLM اجازه می‌دهد صفحات وب را واکشی و بخواند. برای جستجوی مستندات یا پژوهش در منابع آنلاین مفید است.

---

### websearch

جستجوی وب برای اطلاعات.

:::note
این ابزار تنها زمانی در دسترس است که از ارائه‌دهنده OpenCode استفاده کنید یا متغیر محیطی `OPENCODE_ENABLE_EXA` روی هر مقدار درستی (مثلاً `true` یا `1`) تنظیم شده باشد.

برای فعال‌سازی هنگام راه‌اندازی OpenCode:

```bash
OPENCODE_ENABLE_EXA=1 opencode
```

:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "websearch": "allow"
  }
}
```

جستجوهای وب را با استفاده از Exa AI برای یافتن اطلاعات مرتبط آنلاین انجام می‌دهد. برای پژوهش درباره موضوعات، یافتن رویدادهای جاری یا جمع‌آوری اطلاعات فراتر از زمان قطع داده‌های آموزشی مفید است.

نیازی به کلید API نیست — ابزار مستقیماً به سرویس MCP میزبانی‌شده Exa AI بدون احراز هویت متصل می‌شود.

:::tip
از `websearch` هنگامی استفاده کنید که نیاز به یافتن اطلاعات (کشف) دارید، و از `webfetch` هنگامی که نیاز به بازیابی محتوا از یک نشانی URL خاص (واکشی) دارید.
:::

---

### question

پرسیدن سؤال از کاربر در طول اجرا.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "question": "allow"
  }
}
```

این ابزار به LLM اجازه می‌دهد در طول یک وظیفه از کاربر سؤال بپرسد. برای موارد زیر مفید است:

- جمع‌آوری ترجیحات یا نیازمندی‌های کاربر
- روشن‌سازی دستورالعمل‌های مبهم
- گرفتن تصمیم‌هایی درباره انتخاب‌های پیاده‌سازی
- ارائه گزینه‌ها درباره اینکه کدام مسیر را طی کند

هر سؤال شامل یک سرآیند، متن سؤال و یک فهرست گزینه است. کاربران می‌توانند از گزینه‌های ارائه‌شده انتخاب کنند یا پاسخ سفارشی تایپ کنند. وقتی چندین سؤال وجود دارد، کاربران می‌توانند پیش از ارسال تمام پاسخ‌ها میان آن‌ها جابجا شوند.

## ابزارهای سفارشی

ابزارهای سفارشی به شما اجازه می‌دهند توابع دلخواه خودتان را که LLM می‌تواند فراخوانی کند تعریف کنید. این‌ها در پرونده پیکربندی شما تعریف می‌شوند و می‌توانند کد دلخواه را اجرا کنند.

[اطلاعات بیشتر](/docs/custom-tools) درباره ایجاد ابزارهای سفارشی.

---

## سرورهای MCP

سرورهای MCP (Model Context Protocol) به شما امکان می‌دهند ابزارها و خدمات خارجی را یکپارچه کنید. این شامل دسترسی به پایگاه داده، یکپارچه‌سازی API و خدمات شخص ثالث است.

[اطلاعات بیشتر](/docs/mcp-servers) درباره پیکربندی سرورهای MCP.

## جزئیات داخلی

در داخل، ابزارهایی مانند `grep` و `glob` از [ripgrep](https://github.com/BurntSushi/ripgrep) استفاده می‌کنند. به طور پیش‌فرض، ripgrep به الگوهای `.gitignore` احترام می‌گذارد، که به این معناست پرونده‌ها و فهرست‌های فهرست‌شده در `.gitignore` شما از جستجوها و فهرست‌بندی‌ها حذف می‌شوند.

---

### الگوهای نادیده‌گرفته‌شده

برای گنجاندن پرونده‌هایی که معمولاً نادیده گرفته می‌شوند، یک پرونده `.ignore` در ریشه پروژه خود ایجاد کنید. این پرونده می‌تواند مسیرهای خاصی را صریحاً مجاز کند.

```text title=".ignore"
!node_modules/
!dist/
!build/
```

برای مثال، این پرونده `.ignore` به ripgrep اجازه می‌دهد درون فهرست‌های `node_modules/`، `dist/` و `build/` حتی اگر در `.gitignore` فهرست شده باشند جستجو کند.
