OpenCode از طریق pipeline مربوط به GitLab CI/CD شما یا با GitLab Duo، با سیر کاری GitLab شما یکپارچه می‌شود.

در هر دو حالت، OpenCode روی runnerهای GitLab شما اجرا می‌شود.

---

## GitLab CI

OpenCode در یک pipeline معمول GitLab کار می‌کند. می‌توانید آن را به‌عنوان یک [مؤلفه CI](https://docs.gitlab.com/ee/ci/components/) در یک pipeline بسازید.

در اینجا از یک مؤلفه CI/CD ساخته‌شده توسط جامعه برای OpenCode استفاده می‌کنیم — [nagyv/gitlab-opencode](https://gitlab.com/nagyv/gitlab-opencode).

---

### ویژگی‌ها

- **استفاده از پیکربندی سفارشی برای هر job**: OpenCode را با یک دایرکتوری پیکربندی سفارشی، برای مثال `./config/#custom-directory`، پیکربندی کنید تا قابلیت‌ها را در هر فراخوانی OpenCode فعال یا غیرفعال کنید.
- **راه‌اندازی حداقلی**: مؤلفه CI، OpenCode را در پس‌زمینه راه‌اندازی می‌کند؛ شما فقط باید پیکربندی OpenCode و پرامپت اولیه را ایجاد کنید.
- **انعطاف‌پذیر**: مؤلفه CI از چندین ورودی برای سفارشی‌سازی رفتار خود پشتیبانی می‌کند.

---

### راه‌اندازی

1. JSON احراز هویت OpenCode خود را به‌عنوان متغیرهای محیطی CI از نوع File در **Settings** > **CI/CD** > **Variables** ذخیره کنید. مطمئن شوید که آن‌ها را به‌صورت "Masked and hidden" علامت‌گذاری کرده‌اید.
2. موارد زیر را به فایل `.gitlab-ci.yml` خود اضافه کنید.

   ```yaml title=".gitlab-ci.yml"
   include:
     - component: $CI_SERVER_FQDN/nagyv/gitlab-opencode/opencode@2
       inputs:
         config_dir: ${CI_PROJECT_DIR}/opencode-config
         auth_json: $OPENCODE_AUTH_JSON # The variable name for your OpenCode authentication JSON
         command: optional-custom-command
         message: "Your prompt here"
   ```

برای ورودی‌ها و موارد استفاده بیشتر، [مستندات](https://gitlab.com/explore/catalog/nagyv/gitlab-opencode) مربوط به این مؤلفه را بررسی کنید.

## GitLab Duo

OpenCode با سیر کاری GitLab شما یکپارچه می‌شود.
در یک کامنت `@opencode` را ذکر کنید، و OpenCode وظایف را درون pipeline مربوط به GitLab CI شما اجرا خواهد کرد.

---

### ویژگی‌ها

- **فرز issueها**: از OpenCode بخواهید یک issue را بررسی و برای شما توضیح دهد.
- **رفع و پیاده‌سازی**: از OpenCode بخواهید یک issue را رفع کند یا یک قابلیت را پیاده‌سازی کند.
  یک شاخه جدید ایجاد می‌کند و یک merge request با تغییرات ثبت می‌کند.
- **امن**: OpenCode روی runnerهای GitLab شما اجرا می‌شود.

---

### راه‌اندازی

OpenCode درون pipeline مربوط به GitLab CI/CD شما اجرا می‌شود، و در اینجا آنچه برای راه‌اندازی آن نیاز دارید آورده شده است:

:::tip
برای دستورالعمل‌های به‌روز، [**مستندات GitLab**](https://docs.gitlab.com/user/duo_agent_platform/agent_assistant/) را بررسی کنید.
:::

1.  محیط GitLab خود را پیکربندی کنید
2.  CI/CD را راه‌اندازی کنید
3.  یک کلید API از ارائه‌دهنده مدل هوش مصنوعی دریافت کنید
4.  یک حساب سرویس (service account) ایجاد کنید
5.  متغیرهای CI/CD را پیکربندی کنید
6.  یک فایل پیکربندی flow ایجاد کنید، در اینجا یک مثال آورده شده است:

        <details>

    <summary>پیکربندی flow</summary>

    ```yaml
    image: node:22-slim
    commands:
      - echo "Installing opencode"
      - npm install --global opencode-ai
      - echo "Installing glab"
      - export GITLAB_TOKEN=$GITLAB_TOKEN_OPENCODE
      - apt-get update --quiet && apt-get install --yes curl wget gpg git && rm --recursive --force /var/lib/apt/lists/*
      - curl --silent --show-error --location "https://raw.githubusercontent.com/upciti/wakemeops/main/assets/install_repository" | bash
      - apt-get install --yes glab
      - echo "Configuring glab"
      - echo $GITLAB_HOST
      - echo "Creating OpenCode auth configuration"
      - mkdir --parents ~/.local/share/opencode
      - |
        cat > ~/.local/share/opencode/auth.json << EOF
        {
          "anthropic": {
            "type": "api",
            "key": "$ANTHROPIC_API_KEY"
          }
        }
        EOF
      - echo "Configuring git"
      - git config --global user.email "opencode@gitlab.com"
      - git config --global user.name "OpenCode"
      - echo "Testing glab"
      - glab issue list
      - echo "Running OpenCode"
      - |
        opencode run "
        You are an AI assistant helping with GitLab operations.

        Context: $AI_FLOW_CONTEXT
        Task: $AI_FLOW_INPUT
        Event: $AI_FLOW_EVENT

        Please execute the requested task using the available GitLab tools.
        Be thorough in your analysis and provide clear explanations.

        <important>
        Please use the glab CLI to access data from GitLab. The glab CLI has already been authenticated. You can run the corresponding commands.

        If you are asked to summarize an MR or issue or asked to provide more information then please post back a note to the MR/Issue so that the user can see it.
        You don't need to commit or push up changes, those will be done automatically based on the file changes you make.
        </important>
        "
      - git checkout --branch $CI_WORKLOAD_REF origin/$CI_WORKLOAD_REF
      - echo "Checking for git changes and pushing if any exist"
      - |
        if ! git diff --quiet || ! git diff --cached --quiet || [ --not --zero "$(git ls-files --others --exclude-standard)" ]; then
          echo "Git changes detected, adding and pushing..."
          git add .
          if git diff --cached --quiet; then
            echo "No staged changes to commit"
          else
            echo "Committing changes to branch: $CI_WORKLOAD_REF"
            git commit --message "Codex changes"
            echo "Pushing changes up to $CI_WORKLOAD_REF"
            git push https://gitlab-ci-token:$GITLAB_TOKEN@$GITLAB_HOST/gl-demo-ultimate-dev-ai-epic-17570/test-java-project.git $CI_WORKLOAD_REF
            echo "Changes successfully pushed"
          fi
        else
          echo "No git changes detected, skipping push"
        fi
    variables:
      - ANTHROPIC_API_KEY
      - GITLAB_TOKEN_OPENCODE
      - GITLAB_HOST
    ```

        </details>

می‌توانید برای دستورالعمل‌های مفصل به [مستندات GitLab CLI agents](https://docs.gitlab.com/user/duo_agent_platform/agent_assistant/) مراجعه کنید.

### مثال‌ها

در اینجا چند مثال از نحوه استفاده از OpenCode در GitLab آورده شده است.

:::tip
می‌توانید آن را طوری پیکربندی کنید که از یک عبارت فعال‌ساز متفاوت از `@opencode` استفاده کند.
:::

- **توضیح یک issue**

  این کامنت را در یک issue مربوط به GitLab اضافه کنید.

  ```
  @opencode explain this issue
  ```

  OpenCode آن issue را می‌خواند و با یک توضیح روشن پاسخ می‌دهد.

- **رفع یک issue**

  در یک issue مربوط به GitLab بنویسید:

  ```
  @opencode fix this
  ```

  OpenCode یک شاخه جدید ایجاد می‌کند، تغییرات را پیاده‌سازی می‌کند و یک merge request با تغییرات باز می‌کند.

- **بازبینی merge requestها**

  کامنت زیر را روی یک merge request مربوط به GitLab بگذارید.

  ```
  @opencode review this merge request
  ```

  OpenCode آن merge request را بازبینی می‌کند و بازخورد ارائه می‌دهد.
