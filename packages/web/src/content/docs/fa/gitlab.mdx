OpenCode با جریان‌کاری GitLab شما از طریق خط لوله GitLab CI/CD یا با GitLab Duo یکپارچه می‌شود.

در هر دو حالت، OpenCode روی runnerهای GitLab شما اجرا می‌شود.

---

## GitLab CI

OpenCode در یک خط لوله معمولی GitLab کار می‌کند. می‌توانید آن را به‌عنوان یک [مؤلفه CI](https://docs.gitlab.com/ee/ci/components/) در یک خط لوله بگنجانید.

در اینجا از یک مؤلفه CI/CD ایجاد شده توسط جامعه برای OpenCode استفاده می‌کنیم — [nagyv/gitlab-opencode](https://gitlab.com/nagyv/gitlab-opencode).

---

### ویژگی‌ها

- **استفاده از پیکربندی سفارشی به ازای هر job**: OpenCode را با یک فهرست پیکربندی سفارشی، برای مثال `./config/#custom-directory` پیکربندی کنید تا عملکرد را به ازای هر فراخوانی OpenCode فعال یا غیرفعال کنید.
- **راه‌اندازی حداقلی**: مؤلفه CI، OpenCode را در پس‌زمینه راه‌اندازی می‌کند و تنها کافی است پیکربندی OpenCode و درخواست اولیه را ایجاد کنید.
- **انعطاف‌پذیر**: مؤلفه CI از چندین ورودی برای سفارشی‌سازی رفتار خود پشتیبانی می‌کند.

---

### راه‌اندازی

1. JSON احراز هویت OpenCode خود را به‌عنوان متغیرهای محیطی از نوع File در **Settings** > **CI/CD** > **Variables** ذخیره کنید. مطمئن شوید آن‌ها را به‌عنوان «مخفی‌شده و پوشیده» علامت بزنید.
2. موارد زیر را به پرونده `.gitlab-ci.yml` خود اضافه کنید.

   ```yaml title=".gitlab-ci.yml"
   include:
     - component: $CI_SERVER_FQDN/nagyv/gitlab-opencode/opencode@2
       inputs:
         config_dir: ${CI_PROJECT_DIR}/opencode-config
         auth_json: $OPENCODE_AUTH_JSON # The variable name for your OpenCode authentication JSON
         command: optional-custom-command
         message: "Your prompt here"
   ```

برای ورودی‌ها و موارد استفاده بیشتر، [مستندات این مؤلفه را بررسی کنید](https://gitlab.com/explore/catalog/nagyv/gitlab-opencode).

## GitLab Duo

OpenCode با جریان‌کاری GitLab شما یکپارچه می‌شود.
با نوشتن `@opencode` در یک نظر، OpenCode وظایف را در خط لوله GitLab CI شما اجرا می‌کند.

---

### ویژگی‌ها

- **غربالگری issue‌ها**: از OpenCode بخواهید به یک issue نگاه کند و آن را برایتان توضیح دهد.
- **رفع و پیاده‌سازی**: از OpenCode بخواهید یک issue را رفع کند یا یک ویژگی را پیاده‌سازی کند.
  این یک شاخه جدید ایجاد کرده و یک merge request با تغییرات ایجاد می‌کند.
- **امن**: OpenCode روی runnerهای GitLab شما اجرا می‌شود.

---

### راه‌اندازی

OpenCode در خط لوله GitLab CI/CD شما اجرا می‌شود، آنچه برای راه‌اندازی آن نیاز دارید این موارد هستند:

:::tip
[مستندات **GitLab**](https://docs.gitlab.com/user/duo_agent_platform/agent_assistant/) را برای دستورالعمل‌های به‌روز بررسی کنید.
:::

1. پیکربندی محیط GitLab خود
2. راه‌اندازی CI/CD
3. دریافت کلید API یک ارائه‌دهنده مدل هوش مصنوعی
4. ایجاد یک حساب کاربری خدماتی
5. پیکربندی متغیرهای CI/CD
6. ایجاد یک پرونده پیکربندی جریان، در اینجا یک مثال آورده شده است:

        <details>

    <summary>Flow configuration</summary>

    ```yaml
    image: node:22-slim
    commands:
      - echo "Installing opencode"
      - npm install --global opencode-ai
      - echo "Installing glab"
      - export GITLAB_TOKEN=$GITLAB_TOKEN_OPENCODE
      - apt-get update --quiet && apt-get install --yes curl wget gpg git && rm --recursive --force /var/lib/apt/lists/*
      - curl --silent --show-error --location "https://raw.githubusercontent.com/upciti/wakemeops/main/assets/install_repository" | bash
      - apt-get install --yes glab
      - echo "Configuring glab"
      - echo $GITLAB_HOST
      - echo "Creating OpenCode auth configuration"
      - mkdir --parents ~/.local/share/opencode
      - |
        cat > ~/.local/share/opencode/auth.json << EOF
        {
          "anthropic": {
            "type": "api",
            "key": "$ANTHROPIC_API_KEY"
          }
        }
        EOF
      - echo "Configuring git"
      - git config --global user.email "opencode@gitlab.com"
      - git config --global user.name "OpenCode"
      - echo "Testing glab"
      - glab issue list
      - echo "Running OpenCode"
      - |
        opencode run "
        You are an AI assistant helping with GitLab operations.

        Context: $AI_FLOW_CONTEXT
        Task: $AI_FLOW_INPUT
        Event: $AI_FLOW_EVENT

        Please execute the requested task using the available GitLab tools.
        Be thorough in your analysis and provide clear explanations.

        <important>
        Please use the glab CLI to access data from GitLab. The glab CLI has already been authenticated. You can run the corresponding commands.

        If you are asked to summarize an MR or issue or asked to provide more information then please post back a note to the MR/Issue so that the user can see it.
        You don't need to commit or push up changes, those will be done automatically based on the file changes you make.
        </important>
        "
      - git checkout --branch $CI_WORKLOAD_REF origin/$CI_WORKLOAD_REF
      - echo "Checking for git changes and pushing if any exist"
      - |
        if ! git diff --quiet || ! git diff --cached --quiet || [ --not --zero "$(git ls-files --others --exclude-standard)" ]; then
          echo "Git changes detected, adding and pushing..."
          git add .
          if git diff --cached --quiet; then
            echo "No staged changes to commit"
          else
            echo "Committing changes to branch: $CI_WORKLOAD_REF"
            git commit --message "Codex changes"
            echo "Pushing changes up to $CI_WORKLOAD_REF"
            git push https://gitlab-ci-token:$GITLAB_TOKEN@$GITLAB_HOST/gl-demo-ultimate-dev-ai-epic-17570/test-java-project.git $CI_WORKLOAD_REF
            echo "Changes successfully pushed"
          fi
        else
          echo "No git changes detected, skipping push"
        fi
    variables:
      - ANTHROPIC_API_KEY
      - GITLAB_TOKEN_OPENCODE
      - GITLAB_HOST
    ```

### مثال‌ها

در اینجا چند مثال از نحوه استفاده از OpenCode در GitLab آورده شده است.

:::tip
می‌توانید پیکربندی کنید که به جای `@opencode` از یک عبارت محرک متفاوت استفاده شود.
:::

- **توضیح یک issue**

  این نظر را در یک issue در GitLab اضافه کنید.

  ```
  @opencode explain this issue
  ```

  OpenCode issue را می‌خواند و با یک توضیح واضح پاسخ می‌دهد.

- **رفع یک issue**

  در یک issue در GitLab، بگویید:

  ```
  @opencode fix this
  ```

  OpenCode یک شاخه جدید ایجاد کرده، تغییرات را پیاده‌سازی می‌کند و یک merge request با تغییرات باز می‌کند.

- **بررسی merge request‌ها**

  این نظر را روی یک merge request در GitLab بگذارید.

  ```
  @opencode review this merge request
  ```

  OpenCode merge request را بررسی کرده و بازخورد ارائه می‌دهد.
