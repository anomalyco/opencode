OpenCode یک رابط ترمینال تعاملی یا TUI برای کار روی پروژه‌هایتان با یک LLM فراهم می‌کند.

اجرای OpenCode، رابط TUI را برای دایرکتوری کنونی راه‌اندازی می‌کند.

```bash
opencode
```

یا می‌توانید آن را برای یک دایرکتوری کاری مشخص راه‌اندازی کنید.

```bash
opencode /path/to/project
```

پس از ورود به TUI، می‌توانید با یک پیام به آن دستور دهید.

```text
Give me a quick summary of the codebase.
```

## ارجاع به فایل‌ها

می‌توانید با استفاده از `@` در پیام‌هایتان به فایل‌ها ارجاع دهید. این کار یک جست‌وجوی تقریبی فایل در دایرکتوری کاری کنونی انجام می‌دهد.

:::tip
همچنین می‌توانید از `@` برای ارجاع به فایل‌ها در پیام‌هایتان استفاده کنید.
:::

```text "@packages/functions/src/api/index.ts"
How is auth handled in @packages/functions/src/api/index.ts?
```

محتوای فایل به‌صورت خودکار به گفتگو افزوده می‌شود.

[ارجاع‌های](/docs/references) پیکربندی‌شده نیز در تکمیل خودکار `@` ظاهر می‌شوند. ‏`@alias` را تایپ کنید تا ریشه ارجاع به‌عنوان بافت افزوده شود، یا `@alias/` را تایپ کنید تا فایل‌های درون آن ارجاع تکمیل خودکار شوند.

```text "@docs/README.md"
Compare our setup with @docs/README.md
```

## دستورهای Bash

پیامی را با `!` آغاز کنید تا یک دستور shell اجرا شود.

```bash frame="none"
!ls -la
```

خروجی دستور به‌عنوان نتیجه یک ابزار به گفتگو افزوده می‌شود.

## دستورها

هنگام استفاده از TUI ‏OpenCode، می‌توانید `/` و سپس نام یک دستور را تایپ کنید تا اقدام‌ها را به‌سرعت اجرا کنید. برای مثال:

```bash frame="none"
/help
```

بیشتر دستورها میان‌برهای صفحه‌کلیدی هم دارند که از `ctrl+x` به‌عنوان کلید رهبر پیش‌فرض استفاده می‌کنند. [اطلاعات بیشتر](/docs/keybinds).

در اینجا همه دستورهای اسلش در دسترس آمده‌اند:

---

### connect

افزودن یک ارائه‌دهنده به OpenCode. به شما امکان می‌دهد از میان ارائه‌دهندگان در دسترس انتخاب کنید و کلیدهای API آن‌ها را اضافه کنید.

```bash frame="none"
/connect
```

---

### compact

فشرده‌سازی نشست کنونی. _نام مستعار_: `/summarize`

```bash frame="none"
/compact
```

**میان‌بر:** `ctrl+x c`

---

### details

تغییر وضعیت نمایش جزئیات اجرای ابزار.

```bash frame="none"
/details
```

---

### editor

باز کردن ویرایشگر خارجی برای نوشتن پیام‌ها. از ویرایشگر تنظیم‌شده در متغیر محیطی `EDITOR` شما استفاده می‌کند. [اطلاعات بیشتر](#editor-setup).

```bash frame="none"
/editor
```

**میان‌بر:** `ctrl+x e`

---

### exit

خروج از OpenCode. _نام‌های مستعار_: `/quit`, `/q`

```bash frame="none"
/exit
```

**میان‌بر:** `ctrl+x q`

---

### export

صدور گفتگوی کنونی به Markdown و باز کردن آن در ویرایشگر پیش‌فرض شما. از ویرایشگر تنظیم‌شده در متغیر محیطی `EDITOR` شما استفاده می‌کند. [اطلاعات بیشتر](#editor-setup).

```bash frame="none"
/export
```

**میان‌بر:** `ctrl+x x`

---

### help

نمایش کادر گفتگوی راهنما.

```bash frame="none"
/help
```

---

### init

راه‌اندازی هدایت‌شده برای ساخت یا به‌روزرسانی `AGENTS.md`. [اطلاعات بیشتر](/docs/rules).

```bash frame="none"
/init
```

---

### models

فهرست مدل‌های در دسترس.

```bash frame="none"
/models
```

**میان‌بر:** `ctrl+x m`

---

### new

آغاز یک نشست جدید. _نام مستعار_: `/clear`

```bash frame="none"
/new
```

**میان‌بر:** `ctrl+x n`

---

### redo

انجام مجدد پیامی که پیش‌تر لغو شده است. تنها پس از استفاده از `/undo` در دسترس است.

:::tip
هرگونه تغییر فایل نیز بازگردانده خواهد شد.
:::

به‌صورت داخلی، این از Git برای مدیریت تغییرات فایل استفاده می‌کند. بنابراین پروژه شما **باید یک مخزن Git باشد**.

```bash frame="none"
/redo
```

**میان‌بر:** `ctrl+x r`

---

### sessions

فهرست و جابه‌جایی میان نشست‌ها. _نام‌های مستعار_: `/resume`, `/continue`

```bash frame="none"
/sessions
```

**میان‌بر:** `ctrl+x l`

---

### share

اشتراک‌گذاری نشست کنونی. [اطلاعات بیشتر](/docs/share).

```bash frame="none"
/share
```

---

### themes

فهرست تم‌های در دسترس.

```bash frame="none"
/themes
```

**میان‌بر:** `ctrl+x t`

---

### thinking

تغییر وضعیت نمایش بلوک‌های تفکر/استدلال در گفتگو. وقتی فعال باشد، می‌توانید فرایند استدلال مدل را برای مدل‌هایی که از تفکر گسترده پشتیبانی می‌کنند، ببینید.

:::note
این دستور تنها کنترل می‌کند که آیا بلوک‌های تفکر **نمایش داده شوند** یا نه — قابلیت‌های استدلال مدل را فعال یا غیرفعال نمی‌کند. برای تغییر قابلیت‌های واقعی استدلال، از `ctrl+t` برای چرخش میان گونه‌های مدل استفاده کنید.
:::

```bash frame="none"
/thinking
```

---

### undo

لغو آخرین پیام در گفتگو. جدیدترین پیام کاربر، تمام پاسخ‌های بعدی و هرگونه تغییر فایل را حذف می‌کند.

:::tip
هرگونه تغییر فایل انجام‌شده نیز بازگردانده خواهد شد.
:::

به‌صورت داخلی، این از Git برای مدیریت تغییرات فایل استفاده می‌کند. بنابراین پروژه شما **باید یک مخزن Git باشد**.

```bash frame="none"
/undo
```

**میان‌بر:** `ctrl+x u`

---

### unshare

لغو اشتراک‌گذاری نشست کنونی. [اطلاعات بیشتر](/docs/share#un-sharing).

```bash frame="none"
/unshare
```

## راه‌اندازی ویرایشگر

هر دو دستور `/editor` و `/export` از ویرایشگر مشخص‌شده در متغیر محیطی `EDITOR` شما استفاده می‌کنند.

<Tabs>
  <TabItem label="Linux/macOS">
    ```bash
    # مثال برای nano یا vim
    export EDITOR=nano
    export EDITOR=vim

    # برای ویرایشگرهای گرافیکی، VS Code، Cursor، VSCodium، Windsurf، Zed و غیره
    # ‏--wait را بگنجانید
    export EDITOR="code --wait"
    ```

    برای دائمی کردن آن، این را به نمایه shell خود اضافه کنید؛
    `~/.bashrc`، `~/.zshrc` و غیره.

  </TabItem>

  <TabItem label="Windows (CMD)">
    ```bash
    set EDITOR=notepad

    # برای ویرایشگرهای گرافیکی، VS Code، Cursor، VSCodium، Windsurf، Zed و غیره
    # ‏--wait را بگنجانید
    set EDITOR=code --wait
    ```

    برای دائمی کردن آن، از **System Properties** > **Environment
    Variables** استفاده کنید.

  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    $env:EDITOR = "notepad"

    # برای ویرایشگرهای گرافیکی، VS Code، Cursor، VSCodium، Windsurf، Zed و غیره
    # ‏--wait را بگنجانید
    $env:EDITOR = "code --wait"
    ```

    برای دائمی کردن آن، این را به نمایه PowerShell خود اضافه کنید.

  </TabItem>
</Tabs>

گزینه‌های محبوب ویرایشگر عبارت‌اند از:

- `code` - Visual Studio Code
- `cursor` - Cursor
- `windsurf` - Windsurf
- `nvim` - ویرایشگر Neovim
- `vim` - ویرایشگر Vim
- `nano` - ویرایشگر Nano
- `notepad` - Windows Notepad
- `subl` - Sublime Text

:::note
برخی ویرایشگرها مانند VS Code باید با پرچم `--wait` راه‌اندازی شوند.
:::

برخی ویرایشگرها برای اجرا در حالت مسدودکننده به آرگومان‌های خط فرمان نیاز دارند. پرچم `--wait` باعث می‌شود فرایند ویرایشگر تا زمان بسته شدن مسدود بماند.

## پیکربندی

می‌توانید رفتار TUI را از طریق `tui.json` (یا `tui.jsonc`) سفارشی کنید.

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "opencode",
  "leader_timeout": 2000,
  "keybinds": {
    "leader": "ctrl+x",
    "command_list": "ctrl+p"
  },
  "scroll_speed": 3,
  "scroll_acceleration": {
    "enabled": false
  },
  "diff_style": "auto",
  "mouse": true,
  "attention": {
    "enabled": true,
    "notifications": true,
    "sound": true,
    "volume": 0.4,
    "sound_pack": "opencode.default",
    "sounds": {
      "error": "./sounds/error.mp3"
    }
  }
}
```

این از `opencode.json` که رفتار سرور/زمان اجرا را پیکربندی می‌کند، جداست.

‏`keybinds` با مقادیر پیش‌فرض داخلی ادغام می‌شود، بنابراین تنها لازم است میان‌برهایی را که می‌خواهید تغییر دهید پیکربندی کنید.

### گزینه‌ها

- `theme` - تم UI شما را تنظیم می‌کند. [اطلاعات بیشتر](/docs/themes).
- `keybinds` - میان‌برهای صفحه‌کلید را سفارشی می‌کند. [اطلاعات بیشتر](/docs/keybinds).
- `leader_timeout` - کنترل می‌کند که OpenCode پس از کلید رهبر چه مدت منتظر بماند. مقدار پیش‌فرض `2000` است.
- `scroll_acceleration.enabled` - شتاب اسکرول به سبک macOS را برای اسکرول روان و طبیعی فعال می‌کند. وقتی فعال باشد، سرعت اسکرول با ژست‌های اسکرول سریع افزایش می‌یابد و برای حرکات کندتر دقیق می‌ماند. **این تنظیم بر `scroll_speed` اولویت دارد و هنگام فعال بودن آن را لغو می‌کند.**
- `scroll_speed` - کنترل می‌کند که TUI هنگام استفاده از دستورهای اسکرول با چه سرعتی اسکرول کند (حداقل: `0.001`، از مقادیر اعشاری پشتیبانی می‌کند). مقدار پیش‌فرض `3` است. **توجه: اگر `scroll_acceleration.enabled` روی `true` تنظیم شده باشد، این نادیده گرفته می‌شود.**
- `diff_style` - رندر تفاوت‌ها (diff) را کنترل می‌کند. مقدار `"auto"` با عرض ترمینال سازگار می‌شود و `"stacked"` همیشه چیدمان تک‌ستونی را نمایش می‌دهد.
- `mouse` - گرفتن ماوس در TUI را فعال یا غیرفعال می‌کند (پیش‌فرض: `true`). وقتی غیرفعال باشد، رفتار بومی ترمینال برای انتخاب/اسکرول با ماوس حفظ می‌شود.
- `attention` - اعلان‌ها و صداهای دسکتاپ TUI را پیکربندی می‌کند. به‌طور پیش‌فرض غیرفعال است.

از `OPENCODE_TUI_CONFIG` برای بارگذاری یک مسیر پیکربندی TUI سفارشی استفاده کنید.

### Attention

TUI می‌تواند برای پرسش‌ها، دسترسی‌ها، خطاهای نشست و نشست‌های تکمیل‌شده، توجه شما را درخواست کند. آن را با `attention.enabled` فعال کنید؛ رویدادهای داخلی هنگام رخ دادن صدا پخش می‌کنند، و رویدادهای غیر-subagent تنها زمانی که ترمینال در پس‌زمینه (blurred) باشد، اعلان دسکتاپ درخواست می‌کنند.

- `enabled` - فعال کردن همه اعلان‌ها و صداهای Attention. مقدار پیش‌فرض `false` است.
- `notifications` - اجازه دادن به اعلان‌های دسکتاپ با واسطه ترمینال هنگام فعال بودن Attention. مقدار پیش‌فرض `true` است.
- `sound` - اجازه دادن به صداهای Attention هنگام فعال بودن Attention. مقدار پیش‌فرض `true` است.
- `volume` - بلندی پیش‌فرض صدا از `0` تا `1`. مقدار پیش‌فرض `0.4` است.
- `sound_pack` - شناسه بسته صوتی (sound pack ID) موردنظر برای استفاده. مقدار پیش‌فرض `opencode.default` است.
- `sounds` - بازنویسی فایل‌های صوتی برای `default`، `question`، `permission`، `error`، `done` یا `subagent_done`. مسیرها می‌توانند مطلق، آدرس‌های `file://`، یا نسبی به `tui.json` باشند.

## سفارشی‌سازی

می‌توانید جنبه‌های گوناگون نمای TUI را با استفاده از پالت دستورها (`ctrl+p`) سفارشی کنید. این تنظیمات در طول راه‌اندازی‌های مجدد پایدار می‌مانند.

---

#### نمایش نام کاربری

تغییر وضعیت نمایش نام کاربری شما در پیام‌های چت. از این طریق به آن دسترسی پیدا کنید:

- پالت دستورها: عبارت "username" یا "hide username" را جست‌وجو کنید
- این تنظیم به‌صورت خودکار پایدار می‌ماند و در طول نشست‌های TUI به‌خاطر سپرده خواهد شد
