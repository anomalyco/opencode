OpenCode یک رابط ترمینال تعاملی یا TUI برای کار روی پروژه‌هایتان با یک LLM ارائه می‌دهد.

اجرای OpenCode، TUI را برای فهرست فعلی شروع می‌کند.

```bash
opencode
```

یا می‌توانید آن را برای یک فهرست کاری خاص شروع کنید.

```bash
opencode /path/to/project
```

پس از ورود به TUI، می‌توانید با یک پیام از آن درخواست کنید.

```text
Give me a quick summary of the codebase.
```

## ارجاعات پرونده

می‌توانید به پرونده‌ها در پیام‌های خود با استفاده از `@` ارجاع دهید. این یک جستجوی فازی پرونده در فهرست کاری فعلی انجام می‌دهد.

:::tip
همچنین می‌توانید از `@` برای ارجاع به پرونده‌ها در پیام‌های خود استفاده کنید.
:::

```text "@packages/functions/src/api/index.ts"
How is auth handled in @packages/functions/src/api/index.ts?
```

محتوای پرونده به‌طور خودکار به گفتگو اضافه می‌شود.

[ارجاعات](/docs/references) پیکربندی‌شده نیز در تکمیل خودکار `@` نمایش داده می‌شوند. `@alias` را تایپ کنید تا ریشه ارجاع به عنوان متن اضافه شود، یا `@alias/` را تایپ کنید تا پرونده‌های داخل آن ارجاع تکمیل خودکار شوند.

```text "@docs/README.md"
Compare our setup with @docs/README.md
```

## دستورات Bash

پیام را با `!` شروع کنید تا یک دستور شل اجرا شود.

```bash frame="none"
!ls -la
```

خروجی دستور به عنوان نتیجه یک ابزار به گفتگو اضافه می‌شود.

## دستورها

هنگام استفاده از TUI اوپن‌کد، می‌توانید `/` و سپس نام یک دستور را تایپ کنید تا سریعاً عملیات را اجرا کنید. به عنوان مثال:

```bash frame="none"
/help
```

اکثر دستورها همچنین میانبرهای صفحه‌کلید دارند که از `ctrl+x` به عنوان کلید راهبر پیش‌فرض استفاده می‌کنند. [بیشتر بدانید](/docs/keybinds).

در اینجا تمام دستورات اسلش موجود آمده است:

---

### connect

یک ارائه‌دهنده به OpenCode اضافه کنید. به شما اجازه می‌دهد از بین ارائه‌دهندگان موجود انتخاب کنید و کلیدهای API آن‌ها را اضافه کنید.

```bash frame="none"
/connect
```

---

### compact

نشست فعلی را فشرده کنید. _نام مستعار_: `/summarize`

```bash frame="none"
/compact
```

**کلید میانبر:** `ctrl+x c`

---

### details

نمایش/عدم نمایش جزئیات اجرای ابزار.

```bash frame="none"
/details
```

---

### editor

ویرایشگر خارجی را برای نوشتن پیام‌ها باز کنید. از ویرایشگری استفاده می‌کند که در متغیر محیطی `EDITOR` شما تنظیم شده است. [بیشتر بدانید](#editor-setup).

```bash frame="none"
/editor
```

**کلید میانبر:** `ctrl+x e`

---

### exit

خروج از OpenCode. _نام‌های مستعار_: `/quit`، `/q`

```bash frame="none"
/exit
```

**کلید میانبر:** `ctrl+x q`

---

### export

گفتگوی فعلی را به Markdown صادر کرده و در ویرایشگر پیش‌فرض خود باز کنید. از ویرایشگری استفاده می‌کند که در متغیر محیطی `EDITOR` شما تنظیم شده است. [بیشتر بدانید](#editor-setup).

```bash frame="none"
/export
```

**کلید میانبر:** `ctrl+x x`

---

### help

نمایش کادر راهنما.

```bash frame="none"
/help
```

---

### init

راه‌اندازی هدایت‌شده برای ایجاد یا به‌روزرسانی `AGENTS.md`. [بیشتر بدانید](/docs/rules).

```bash frame="none"
/init
```

---

### models

فهرست مدل‌های موجود.

```bash frame="none"
/models
```

**کلید میانبر:** `ctrl+x m`

---

### new

شروع یک نشست جدید. _نام مستعار_: `/clear`

```bash frame="none"
/new
```

**کلید میانبر:** `ctrl+x n`

---

### redo

انجام دوباره یک پیام پیش‌تر لغوشده. فقط پس از استفاده از `/undo` در دسترس است.

:::tip
هرگونه تغییر پرونده نیز بازیابی می‌شود.
:::

در داخل، از Git برای مدیریت تغییرات پرونده استفاده می‌کند. بنابراین پروژه شما **باید یک مخزن Git باشد**.

```bash frame="none"
/redo
```

**کلید میانبر:** `ctrl+x r`

---

### sessions

فهرست کردن و جابجایی بین نشست‌ها. _نام‌های مستعار_: `/resume`، `/continue`

```bash frame="none"
/sessions
```

**کلید میانبر:** `ctrl+x l`

---

### share

اشتراک‌گذاری نشست فعلی. [بیشتر بدانید](/docs/share).

```bash frame="none"
/share
```

---

### themes

فهرست تم‌های موجود.

```bash frame="none"
/themes
```

**کلید میانبر:** `ctrl+x t`

---

### thinking

نمایش/عدم نمایش بلوک‌های تفکر/استنتاج در گفتگو. هنگام فعال بودن، می‌توانید فرآیند استنتاج مدل را برای مدل‌هایی که تفکر گسترده را پشتیبانی می‌کنند، ببینید.

:::note
این دستور فقط کنترل می‌کند که آیا بلوک‌های تفکر **نمایش داده می‌شوند** - قابلیت‌های استنتاج مدل را فعال یا غیرفعال نمی‌کند. برای تغییر واقعی قابلیت‌های استنتاج، از `ctrl+t` برای چرخش بین گونه‌های مدل استفاده کنید.
:::

```bash frame="none"
/thinking
```

---

### undo

لغو آخرین پیام در گفتگو. جدیدترین پیام کاربر، تمام پاسخ‌های بعدی و هرگونه تغییر پرونده را حذف می‌کند.

:::tip
هرگونه تغییر پرونده ایجاد شده نیز بازگردانده می‌شود.
:::

در داخل، از Git برای مدیریت تغییرات پرونده استفاده می‌کند. بنابراین پروژه شما **باید یک مخزن Git باشد**.

```bash frame="none"
/undo
```

**کلید میانبر:** `ctrl+x u`

---

### unshare

لغو اشتراک‌گذاری نشست فعلی. [بیشتر بدانید](/docs/share#un-sharing).

```bash frame="none"
/unshare
```

## تنظیم ویرایشگر

هر دو دستور `/editor` و `/export` از ویرایشگری استفاده می‌کنند که در متغیر محیطی `EDITOR` شما مشخص شده است.

<Tabs>
  <TabItem label="Linux/macOS">
    ```bash
    # Example for nano or vim
    export EDITOR=nano
    export EDITOR=vim

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    export EDITOR="code --wait"
    ```

    برای دائمی کردن، این را به پروفایل شل خود اضافه کنید؛
    `~/.bashrc`، `~/.zshrc` و غیره.

  </TabItem>

  <TabItem label="Windows (CMD)">
    ```bash
    set EDITOR=notepad

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    set EDITOR=code --wait
    ```

    برای دائمی کردن، از **System Properties** > **Environment Variables** استفاده کنید.

  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    $env:EDITOR = "notepad"

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    $env:EDITOR = "code --wait"
    ```

    برای دائمی کردن، این را به پروفایل PowerShell خود اضافه کنید.

  </TabItem>
</Tabs>

گزینه‌های ویرایشگر محبوب شامل موارد زیر است:

- `code` - ویژوال استودیو کد
- `cursor` - کورسر
- `windsurf` - ویندسرف
- `nvim` - ویرایشگر Neovim
- `vim` - ویرایشگر Vim
- `nano` - ویرایشگر Nano
- `notepad` - Notepad ویندوز
- `subl` - سابلایم تکست

:::note
برخی ویرایشگرها مانند VS Code باید با پرچم `--wait` شروع شوند.
:::

برخی ویرایشگرها به آرگومان‌های خط فرمان نیاز دارند تا در حالت انسدادی اجرا شوند. پرچم `--wait` باعث می‌شود فرآیند ویرایشگر تا بسته شدن مسدود بماند.

## پیکربندی

می‌توانید رفتار TUI را از طریق `tui.json` (یا `tui.jsonc`) سفارشی کنید.

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "opencode",
  "leader_timeout": 2000,
  "keybinds": {
    "leader": "ctrl+x",
    "command_list": "ctrl+p"
  },
  "scroll_speed": 3,
  "scroll_acceleration": {
    "enabled": false
  },
  "diff_style": "auto",
  "mouse": true,
  "attention": {
    "enabled": true,
    "notifications": true,
    "sound": true,
    "volume": 0.4,
    "sound_pack": "opencode.default",
    "sounds": {
      "error": "./sounds/error.mp3"
    }
  }
}
```

این مجزا از `opencode.json` است که رفتار سرور/زمان اجرا را پیکربندی می‌کند.

`keybinds` با پیش‌فرض‌های داخلی ادغام می‌شود، بنابراین فقط کافی است میانبرهایی که می‌خواهید تغییر دهید را پیکربندی کنید.

### گزینه‌ها

- `theme` - تم رابط کاربری شما را تنظیم می‌کند. [بیشتر بدانید](/docs/themes).
- `keybinds` - میانبرهای صفحه‌کلید را سفارشی می‌کند. [بیشتر بدانید](/docs/keybinds).
- `leader_timeout` - کنترل می‌کند OpenCode چقدر پس از کلید راهبر منتظر می‌ماند. پیش‌فرض `2000`.
- `scroll_acceleration.enabled` - فعال کردن شتاب اسکرول به سبک macOS برای اسکرول صاف و طبیعی. هنگام فعال بودن، سرعت اسکرول با حرکات سریع اسکرول افزایش می‌یابد و برای حرکات آهسته دقیق باقی می‌ماند. **این تنظیم بر `scroll_speed` اولویت دارد و هنگام فعال بودن آن را لغو می‌کند.**
- `scroll_speed` - کنترل می‌کند TUI هنگام استفاده از دستورات اسکرول چقدر سریع حرکت می‌کند (حداقل: `0.001`، مقادیر اعشاری پشتیبانی می‌شود). پیش‌فرض `3`. **توجه: این مقدار نادیده گرفته می‌شود اگر `scroll_acceleration.enabled` روی `true` تنظیم شده باشد.**
- `diff_style` - رندر diff را کنترل می‌کند. `"auto"` با عرض ترمینال تطبیق می‌یابد، `"stacked"` همیشه چیدمان تک‌ستونی نشان می‌دهد.
- `mouse` - ضبط ماوس را در TUI فعال یا غیرفعال می‌کند (پیش‌فرض: `true`). هنگام غیرفعال بودن، رفتار انتخاب/اسکرول ماوس بومی ترمینال حفظ می‌شود.
- `attention` - اعلان‌های دسکتاپ و صداهای TUI را پیکربندی می‌کند. به‌طور پیش‌فرض غیرفعال است.

از `OPENCODE_TUI_CONFIG` برای بارگذاری یک مسیر پیکربندی TUI سفارشی استفاده کنید.

### توجه

TUI می‌تواند برای سوالات، مجوزها، خطاهای نشست و نشست‌های تکمیل‌شده توجه درخواست کند. آن را با `attention.enabled` فعال کنید؛ رویدادهای داخلی هنگام فعال شدن صدا پخش می‌کنند و رویدادهای غیرزیرعامل فقط زمانی اعلان دسکتاپ درخواست می‌کنند که ترمینال تاریک باشد.

- `enabled` - فعال کردن تمام اعلان‌ها و صداهای توجه. پیش‌فرض `false`.
- `notifications` - اجازه اعلان‌های دسکتاپ میانجی‌گری‌شده توسط ترمینال هنگام فعال بودن توجه. پیش‌فرض `true`.
- `sound` - اجازه صداهای توجه هنگام فعال بودن توجه. پیش‌فرض `true`.
- `volume` - حجم صدای پیش‌فرض از `0` تا `1`. پیش‌فرض `0.4`.
- `sound_pack` - شناسه بسته صدا برای استفاده. پیش‌فرض `opencode.default`.
- `sounds` - بازنویسی پرونده‌های صدا برای `default`، `question`، `permission`، `error`، `done` یا `subagent_done`. مسیرها می‌توانند مطلق، URLهای `file://` یا نسبت به `tui.json` باشند.

## سفارشی‌سازی

می‌توانید جنبه‌های مختلف نمای TUI را با استفاده از پالت دستور (`ctrl+p`) سفارشی کنید. این تنظیمات در میان راه‌اندازی‌های مجدد باقی می‌مانند.

#### نمایش نام کاربری

تغییر وضعیت نمایش نام کاربری شما در پیام‌های چت. از طریق موارد زیر به آن دسترسی پیدا کنید:

- پالت دستور: جستجو برای «username» یا «hide username»
- این تنظیم به‌طور خودکار باقی می‌ماند و در نشست‌های TUI به خاطر سپرده می‌شود
