SDK مربوط به opencode برای JS/TS یک کلاینت امن از نظر نوع برای تعامل با سرور فراهم می‌کند.
از آن برای ساخت یکپارچه‌سازی‌ها و کنترل برنامه‌نویسی‌شده‌ی opencode استفاده کنید.

[بیشتر بدانید](/docs/server) درباره‌ی نحوه‌ی کار سرور. برای مشاهده‌ی نمونه‌ها، [پروژه‌هایی](/docs/ecosystem#projects) را که جامعه ساخته است بررسی کنید.

---

## نصب

SDK را از npm نصب کنید:

```bash
npm install @opencode-ai/sdk
```

---

## ساخت کلاینت

یک نمونه از opencode بسازید:

```javascript
import { createOpencode } from "@opencode-ai/sdk"

const { client } = await createOpencode()
```

این کار هم یک سرور و هم یک کلاینت را راه‌اندازی می‌کند.

#### گزینه‌ها

| گزینه      | نوع           | توضیح                          | پیش‌فرض     |
| ---------- | ------------- | ------------------------------ | ----------- |
| `hostname` | `string`      | نام میزبان سرور                | `127.0.0.1` |
| `port`     | `number`      | پورت سرور                      | `4096`      |
| `signal`   | `AbortSignal` | سیگنال لغو برای متوقف‌سازی     | `undefined` |
| `timeout`  | `number`      | مهلت زمانی شروع سرور به میلی‌ثانیه | `5000`  |
| `config`   | `Config`      | شیء پیکربندی                   | `{}`        |

## پیکربندی

می‌توانید یک شیء پیکربندی برای سفارشی‌سازی رفتار ارسال کنید. نمونه همچنان `opencode.json` شما را برمی‌دارد، اما می‌توانید پیکربندی را به‌صورت درون‌خطی بازنویسی یا اضافه کنید:

```javascript
import { createOpencode } from "@opencode-ai/sdk"

const opencode = await createOpencode({
  hostname: "127.0.0.1",
  port: 4096,
  config: {
    model: "anthropic/claude-3-5-sonnet-20241022",
  },
})

console.log(`Server running at ${opencode.server.url}`)

opencode.server.close()
```

## فقط کلاینت

اگر همین حالا یک نمونه‌ی در حال اجرا از opencode دارید، می‌توانید یک نمونه‌ی کلاینت برای اتصال به آن بسازید:

```javascript
import { createOpencodeClient } from "@opencode-ai/sdk"

const client = createOpencodeClient({
  baseUrl: "http://localhost:4096",
})
```

#### گزینه‌ها

| گزینه           | نوع        | توضیح                            | پیش‌فرض                 |
| --------------- | ---------- | -------------------------------- | ----------------------- |
| `baseUrl`       | `string`   | نشانی URL سرور                   | `http://localhost:4096` |
| `fetch`         | `function` | پیاده‌سازی fetch سفارشی          | `globalThis.fetch`      |
| `parseAs`       | `string`   | روش تجزیه‌ی پاسخ                 | `auto`                  |
| `responseStyle` | `string`   | سبک بازگشت: `data` یا `fields`   | `fields`                |
| `throwOnError`  | `boolean`  | به‌جای بازگرداندن، خطا پرتاب کند | `false`                 |

## خروجی ساختاریافته

می‌توانید با تعیین یک `format` به‌همراه یک شِمای JSON، از مدل خروجی JSON ساختاریافته درخواست کنید. مدل از ابزار `StructuredOutput` برای بازگرداندن JSON اعتبارسنجی‌شده‌ی مطابق با شِمای شما استفاده خواهد کرد.

### استفاده‌ی پایه

```typescript
const result = await client.session.prompt({
  path: { id: sessionId },
  body: {
    parts: [{ type: "text", text: "Research Anthropic and provide company info" }],
    format: {
      type: "json_schema",
      schema: {
        type: "object",
        properties: {
          company: { type: "string", description: "Company name" },
          founded: { type: "number", description: "Year founded" },
          products: {
            type: "array",
            items: { type: "string" },
            description: "Main products",
          },
        },
        required: ["company", "founded"],
      },
    },
  },
})

// دسترسی به خروجی ساختاریافته
console.log(result.data.info.structured_output)
// { company: "Anthropic", founded: 2021, products: ["Claude", "Claude API"] }
```

### انواع قالب خروجی

| نوع           | توضیح                                                  |
| ------------- | ------------------------------------------------------ |
| `text`        | پیش‌فرض. پاسخ متنی استاندارد (بدون خروجی ساختاریافته)  |
| `json_schema` | JSON اعتبارسنجی‌شده‌ی مطابق با شِمای ارائه‌شده را برمی‌گرداند |

### قالب شِمای JSON

هنگام استفاده از `type: 'json_schema'`، موارد زیر را ارائه دهید:

| فیلد         | نوع             | توضیح                                                      |
| ------------ | --------------- | ---------------------------------------------------------- |
| `type`       | `'json_schema'` | لازم. حالت شِمای JSON را مشخص می‌کند                       |
| `schema`     | `object`        | لازم. شیء شِمای JSON که ساختار خروجی را تعریف می‌کند       |
| `retryCount` | `number`        | اختیاری. تعداد تلاش‌های مجدد اعتبارسنجی (پیش‌فرض: ۲)        |

### مدیریت خطا

اگر مدل پس از همه‌ی تلاش‌های مجدد نتواند خروجی ساختاریافته‌ی معتبر تولید کند، پاسخ شامل یک `StructuredOutputError` خواهد بود:

```typescript
if (result.data.info.error?.name === "StructuredOutputError") {
  console.error("Failed to produce structured output:", result.data.info.error.message)
  console.error("Attempts:", result.data.info.error.retries)
}
```

### بهترین شیوه‌ها

1. **توضیحات روشن ارائه دهید** در ویژگی‌های شِما تا به مدل کمک کنید بفهمد چه داده‌ای را باید استخراج کند
2. **از `required` استفاده کنید** تا مشخص کنید کدام فیلدها باید موجود باشند
3. **شِماها را متمرکز نگه دارید** - شِماهای تو‌درتوی پیچیده ممکن است پر کردن صحیح آن‌ها برای مدل دشوارتر باشد
4. **`retryCount` مناسب تنظیم کنید** - برای شِماهای پیچیده آن را افزایش دهید و برای شِماهای ساده کاهش دهید

#### نمونه‌ها

```javascript
// ساخت و مدیریت نشست‌ها
const session = await client.session.create({

    noReply: true,
    parts: [{ type: "text", text: "You are a helpful assistant." }],
  },
})
```

### فایل‌ها

| متد                       | توضیح                              | پاسخ                                                                                          |
| ------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------- |
| `find.text({ query })`    | جست‌وجوی متن در فایل‌ها            | آرایه‌ای از شیءهای مطابقت با `path`، `lines`، `line_number`، `absolute_offset`، `submatches` |
| `find.files({ query })`   | یافتن فایل‌ها و دایرکتوری‌ها با نام | `string[]` (مسیرها)                                                                          |
| `find.symbols({ query })` | یافتن نمادهای فضای کاری            | <a href={typesUrl}><code>Symbol[]</code></a>                                                |
| `file.read({ query })`    | خواندن یک فایل                     | `{ type: "raw" \| "patch", content: string }`                                               |
| `file.status({ query? })` | دریافت وضعیت فایل‌های ردیابی‌شده   | <a href={typesUrl}><code>File[]</code></a>                                                  |

`find.files` از چند فیلد اختیاری در کوئری پشتیبانی می‌کند:

- `type`: `"file"` یا `"directory"`
- `directory`: بازنویسی ریشه‌ی پروژه برای جست‌وجو
- `limit`: حداکثر نتایج (۱–۲۰۰)

---

#### نمونه‌ها

```javascript
// جست‌وجو و خواندن فایل‌ها
const textResults = await client.find.text({
  query: { pattern: "function.*opencode" },
})

const files = await client.find.files({
  query: { query: "*.ts", type: "file" },
})

const directories = await client.find.files({
  query: { query: "packages", type: "directory", limit: 20 },
})

const content = await client.file.read({
  query: { path: "src/index.ts" },
})
```
