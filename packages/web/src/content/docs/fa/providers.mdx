OpenCode از [AI SDK](https://ai-sdk.dev/) و [Models.dev](https://models.dev) برای پشتیبانی از **بیش از ۷۵ ارائه‌دهنده LLM** استفاده می‌کند و اجرای مدل‌های محلی را نیز پشتیبانی می‌کند.

برای افزودن یک ارائه‌دهنده باید:

1. کلیدهای API ارائه‌دهنده را با دستور `/connect` اضافه کنید.
2. ارائه‌دهنده را در پیکربندی OpenCode خود تنظیم کنید.

---

### اعتبارنامه‌ها

وقتی کلیدهای API یک ارائه‌دهنده را با دستور `/connect` اضافه می‌کنید، آن‌ها
در `~/.local/share/opencode/auth.json` ذخیره می‌شوند.

---

### پیکربندی

می‌توانید ارائه‌دهنده‌ها را از طریق بخش `provider` در پیکربندی OpenCode خود
سفارشی‌سازی کنید.

---

#### Base URL

می‌توانید base URL هر ارائه‌دهنده را با تنظیم گزینه `baseURL` سفارشی‌سازی کنید. این کار هنگام استفاده از سرویس‌های پراکسی یا نقاط پایانی سفارشی مفید است.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

---

#### پنهان‌کردن مدل‌ها

می‌توانید مدل‌های خاصی را با گزینه `blacklist` از انتخابگر `/models` یک ارائه‌دهنده پنهان کنید. این کار زمانی مفید است که یک ارائه‌دهنده مدل‌هایی را در دسترس قرار می‌دهد که نمی‌خواهید از آن‌ها استفاده کنید یا آن‌ها را انتخاب کنید.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "blacklist": ["claude-opus-4-20250514"]
    }
  }
}
```

گزینه معکوس `whitelist` هر مدلی را به جز مدل‌های فهرست‌شده پنهان می‌کند.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "whitelist": ["claude-sonnet-4-20250514"]
    }
  }
}
```

هر دو گزینه یک آرایه از شناسه‌های مدل می‌گیرند — همان شناسه‌هایی که در انتخابگر `/models` نمایش داده می‌شوند.

- `blacklist` مدل‌های فهرست‌شده را از انتخابگر حذف می‌کند.
- `whitelist` فقط مدل‌های فهرست‌شده را نگه می‌دارد و بقیه را پنهان می‌کند.
- می‌توانید آن‌ها را ترکیب کنید: `whitelist` مجموعه را محدود می‌کند، سپس `blacklist` موارد را از آن حذف می‌کند.

## OpenCode Zen

OpenCode Zen فهرستی از مدل‌هایی است که توسط تیم OpenCode ارائه شده‌اند و
آزمایش و تأیید شده‌اند که با OpenCode به‌خوبی کار می‌کنند. [بیشتر بدانید](/docs/zen).

:::tip
اگر تازه‌کار هستید، توصیه می‌کنیم با OpenCode Zen شروع کنید.
:::

1. دستور `/connect` را در TUI اجرا کنید، `OpenCode Zen` را انتخاب کنید و به [opencode.ai/auth](https://opencode.ai/zen) بروید.

   ```txt
   /connect
   ```

2. وارد شوید، جزئیات صورت‌حساب خود را اضافه کنید و کلید API خود را کپی کنید.

3. کلید API خود را جای‌گذاری کنید.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. دستور `/models` را در TUI اجرا کنید تا فهرست مدل‌هایی را که توصیه می‌کنیم ببینید.

   ```txt
   /models
   ```

این مانند هر ارائه‌دهنده دیگری در OpenCode کار می‌کند و استفاده از آن کاملاً اختیاری است.

### Amazon Bedrock

برای استفاده از Amazon Bedrock با OpenCode:

1. به **Model catalog** در Amazon Bedrock console بروید و
   درخواست دسترسی به مدل‌هایی که می‌خواهید را ثبت کنید.

   :::tip
   باید به مدلی که می‌خواهید در Amazon Bedrock دسترسی داشته باشید.
   :::

2. **احراز هویت را پیکربندی کنید** با استفاده از یکی از روش‌های زیر:

   ***

   #### متغیرهای محیطی (شروع سریع)

   یکی از این متغیرهای محیطی را هنگام اجرای opencode تنظیم کنید:

   ```bash
   # گزینه ۱: استفاده از کلیدهای دسترسی AWS
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # گزینه ۲: استفاده از پروفایل نام‌گذاری‌شده AWS
   AWS_PROFILE=my-profile opencode

   # گزینه ۳: استفاده از Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   یا آن‌ها را به bash profile خود اضافه کنید:

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### فایل پیکربندی (توصیه‌شده)

   برای پیکربندی مخصوص پروژه یا پایدار، از `opencode.json` استفاده کنید:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **گزینه‌های موجود:**
   - `region` - منطقه AWS (مثلاً `us-east-1`، `eu-west-1`)
   - `profile` - پروفایل نام‌گذاری‌شده AWS از `~/.aws/credentials`
   - `endpoint` - آدرس نقطه پایانی سفارشی برای نقاط پایانی VPC (نام مستعار برای گزینه عمومی `baseURL`)

   :::tip
   گزینه‌های فایل پیکربندی بر متغیرهای محیطی اولویت دارند.
   :::

   ***

   #### پیشرفته: نقاط پایانی VPC

   اگر از نقاط پایانی VPC برای Bedrock استفاده می‌کنید:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   گزینه `endpoint` نام مستعاری برای گزینه عمومی `baseURL` است که از اصطلاحات مخصوص AWS استفاده می‌کند. اگر هر دو `endpoint` و `baseURL` مشخص شده باشند، `endpoint` اولویت دارد.
   :::

   ***

   #### روش‌های احراز هویت
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: یک کاربر IAM بسازید و کلیدهای دسترسی را در AWS Console تولید کنید
   - **`AWS_PROFILE`**: از پروفایل‌های نام‌گذاری‌شده در `~/.aws/credentials` استفاده کنید. ابتدا با `aws configure --profile my-profile` یا `aws sso login` پیکربندی کنید
   - **`AWS_BEARER_TOKEN_BEDROCK`**: کلیدهای API طولانی‌مدت را از Amazon Bedrock console تولید کنید
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: برای EKS IRSA (IAM Roles for Service Accounts) یا دیگر محیط‌های Kubernetes با فدراسیون OIDC. این متغیرهای محیطی به‌طور خودکار توسط Kubernetes هنگام استفاده از حاشیه‌نویسی‌های حساب سرویس تزریق می‌شوند.

   ***

   #### اولویت احراز هویت

   Amazon Bedrock از اولویت احراز هویت زیر استفاده می‌کند:
   1. **Bearer Token** - متغیر محیطی `AWS_BEARER_TOKEN_BEDROCK` یا توکن از دستور `/connect`
   2. **AWS Credential Chain** - پروفایل، کلیدهای دسترسی، اعتبارنامه‌های مشترک، نقش‌های IAM، توکن‌های Web Identity (EKS IRSA)، فراداده نمونه

   :::note
   وقتی یک bearer token تنظیم شده باشد (از طریق `/connect` یا `AWS_BEARER_TOKEN_BEDROCK`)، بر تمام روش‌های اعتبارنامه AWS از جمله پروفایل‌های پیکربندی‌شده اولویت دارد.
   :::

3. دستور `/models` را اجرا کنید تا مدلی که می‌خواهید را انتخاب کنید.

   ```txt
   /models
   ```

:::note
برای پروفایل‌های استنتاج سفارشی، از نام مدل و ارائه‌دهنده در کلید استفاده کنید و خاصیت `id` را روی arn تنظیم کنید. این کار از کش‌گذاری صحیح اطمینان می‌دهد.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

می‌توانید opencode را برای استفاده از مدل‌های محلی از طریق [Atomic Chat](https://atomic.chat) پیکربندی کنید، یک برنامه دسکتاپ که LLMهای محلی را پشت یک سرور API سازگار با OpenAI اجرا می‌کند (نقطه پایانی پیش‌فرض `http://127.0.0.1:1337/v1`).

```json title="opencode.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (local)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

در این مثال:

- `atomic-chat` شناسه ارائه‌دهنده سفارشی است. می‌تواند هر رشته‌ای که می‌خواهید باشد.
- `npm` بسته‌ای را که برای این ارائه‌دهنده استفاده می‌شود مشخص می‌کند. اینجا، `@ai-sdk/openai-compatible` برای هر API سازگار با OpenAI استفاده می‌شود.
- `name` نام نمایشی ارائه‌دهنده در رابط کاربری است.
- `options.baseURL` نقطه پایانی سرور محلی است. میزبان و پورت را تغییر دهید تا با راه‌اندازی Atomic Chat شما مطابقت داشته باشد.
- `models` نگاشتی از شناسه‌های مدل به نام‌های نمایشی آن‌هاست. هر شناسه باید با `id` بازگردانده‌شده توسط `GET /v1/models` مطابقت داشته باشد — `curl http://127.0.0.1:1337/v1/models` را اجرا کنید تا شناسه‌هایی که در حال حاضر در Atomic Chat بارگذاری شده‌اند را فهرست کنید.

:::tip
اگر فراخوانی ابزارها به‌خوبی کار نمی‌کند، یک مدل بارگذاری‌شده با پشتیبانی قوی از فراخوانی ابزار انتخاب کنید (برای مثال، یک نسخه Qwen-Coder یا DeepSeek-Coder).
:::

### Azure OpenAI

:::note
اگر با خطاهای "I'm sorry, but I cannot assist with that request" مواجه شدید، سعی کنید فیلتر محتوا را از **DefaultV2** به **Default** در منبع Azure خود تغییر دهید.
:::

1. به [Azure portal](https://portal.azure.com/) بروید و یک منبع **Azure OpenAI** بسازید. به موارد زیر نیاز دارید:
   - **Resource name**: این بخشی از نقطه پایانی API شما می‌شود (`https://RESOURCE_NAME.openai.azure.com/`)
   - **API key**: یا `KEY 1` یا `KEY 2` از منبع شما

2. به [Azure AI Foundry](https://ai.azure.com/) بروید و یک مدل را مستقر کنید.

   :::note
   نام استقرار باید با نام مدل مطابقت داشته باشد تا opencode به‌درستی کار کند.
   :::

3. دستور `/connect` را اجرا کنید و **Azure** را جستجو کنید.

   ```txt
   /connect
   ```

4. کلید API خود را وارد کنید.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

5. نام منبع خود را به‌عنوان یک متغیر محیطی تنظیم کنید:

   ```bash
   AZURE_RESOURCE_NAME=XXX opencode
   ```

   یا آن را به bash profile خود اضافه کنید:

   ```bash title="~/.bash_profile"
   export AZURE_RESOURCE_NAME=XXX
   ```

6. دستور `/models` را اجرا کنید تا مدل مستقرشده خود را انتخاب کنید.

   ```txt
   /models
   ```

### DigitalOcean

[Inference Engine](https://docs.digitalocean.com/products/inference/) شرکت DigitalOcean دسترسی به مدل‌های متن‌باز مانند GPT-OSS، Llama، Qwen و DeepSeek و همچنین [Inference Routers](https://docs.digitalocean.com/products/genai-platform/concepts/inference-routers/) سفارشی را فراهم می‌کند که هر درخواست را به ارزان‌ترین، سریع‌ترین یا مناسب‌ترین مدل برای یک وظیفه مسیریابی می‌کنند.

OpenCode از دو روش احراز هویت پشتیبانی می‌کند:

- **OAuth (توصیه‌شده)** — به حساب DigitalOcean خود وارد شوید؛ OpenCode از توکن API DigitalOcean شما مستقیماً برای استنتاج استفاده می‌کند و Inference Routerهای شما را کشف می‌کند.
- **Model Access Key** — یک کلید موجود را از کنسول DigitalOcean جای‌گذاری کنید.

#### OAuth (توصیه‌شده)

1. دستور `/connect` را اجرا کنید و **DigitalOcean** را جستجو کنید.

   ```txt
   /connect
   ```

2. **Login with DigitalOcean** را انتخاب کنید.

   ```txt
   ┌ Select auth method
   │
   │ Login with DigitalOcean
   │ Paste Model Access Key
   └
   ```

3. مرورگر شما برای مجوزدهی به OpenCode باز می‌شود. وارد شوید و تأیید کنید.

   :::note
   OpenCode محدوده‌های OAuth با عنوان `genai:read` و `inference:query` را درخواست می‌کند. توکن API DigitalOcean شما مستقیماً برای استنتاج استفاده می‌شود — هیچ Model Access Key جداگانه‌ای ساخته نمی‌شود.
   :::

   :::note
   Inference Routerها فقط پس از OAuth در انتخابگر مدل ظاهر می‌شوند. جای‌گذاری دستی یک Model Access Key، روترها را کشف نمی‌کند.
   :::

4. دستور `/models` را اجرا کنید. Inference Routerهای شما با قالب `router:` در انتخاب مدل ظاهر می‌شوند.

   ```txt
   /models
   ```

5. برای دریافت Inference Routerهای تازه‌ساخته‌شده، دستور `/connect` را دوباره اجرا کنید و دوباره **DigitalOcean** را انتخاب کنید.

#### استفاده از یک Model Access Key

اگر ترجیح می‌دهید یک کلید را مستقیماً جای‌گذاری کنید:

1. به صفحه **Manage** در بخش Inference در [کنسول DigitalOcean](https://cloud.digitalocean.com/) بروید و یک کلید جدید بسازید.

2. دستور `/connect` را اجرا کنید و **DigitalOcean** و سپس **Paste Model Access Key** را انتخاب کنید.

   ```txt
   ┌ Enter your DigitalOcean Model Access Key
   │
   │
   └ enter
   ```

   :::note
   Inference Routerها با این روش به‌طور خودکار کشف نمی‌شوند. برای نمایش آن‌ها در انتخابگر مدل، به‌جای آن از طریق OAuth وارد شوید.
   :::

3. دستور `/models` را اجرا کنید تا یک مدل انتخاب کنید.

   ```txt
   /models
   ```

#### متغیر محیطی

به‌عنوان جایگزین، Model Access Key خود را به‌عنوان یک متغیر محیطی تنظیم کنید.

```bash frame="none"
export DIGITALOCEAN_ACCESS_TOKEN=your-model-access-key
```

#### Inference Routers

Inference Routerها به شما اجازه می‌دهند یک سیاست مسیریابی در میان چندین مدل تعریف کنید — انتخاب ارزان‌ترین، سریع‌ترین یا مناسب‌ترین مدل برای هر درخواست بر اساس وظیفه. پس از OAuth، OpenCode هر روتر را به‌صورت `router:<router-name>` در انتخابگر مدل نمایش می‌دهد.

انتخاب یک مدل روتر جایگزینی بی‌دردسر برای هر مدل دیگری است — OpenCode درخواست شما را ارسال می‌کند و DigitalOcean مدل زیربنایی را بر اساس سیاست روتر شما انتخاب می‌کند. درباره [Inference Routers](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/) بیشتر بدانید

##### مدل‌های گردش‌کار GitLab Duo Agent Platform (DAP)

مدل‌های گردش‌کار DAP یک مسیر اجرای جایگزین فراهم می‌کنند که فراخوانی‌های ابزار را
به‌جای چت وکیلی استاندارد، از طریق Duo Workflow Service (DWS) شرکت GitLab مسیریابی می‌کند.
وقتی یک مدل `duo-workflow-*` انتخاب می‌شود، OpenCode:

1. مدل‌های موجود را از فضای نام GitLab شما کشف می‌کند
2. اگر چندین مدل در دسترس باشد، یک انتخابگر ارائه می‌دهد
3. مدل انتخاب‌شده را برای راه‌اندازی‌های بعدی سریع روی دیسک کش می‌کند
4. درخواست‌های اجرای ابزار را از طریق سیستم ابزار با محدودیت مجوز OpenCode مسیریابی می‌کند

مدل‌های گردش‌کار DAP موجود از قرارداد نام‌گذاری `duo-workflow-*` پیروی می‌کنند و
به‌صورت پویا از نمونه GitLab شما کشف می‌شوند.

##### ابزارهای GitLab API (اختیاری، اما به‌شدت توصیه‌شده)

برای دسترسی به ابزارهای GitLab (merge requestها، issueها، pipelineها، CI/CD و غیره):

```json title="opencode.json"

  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-gitlab-plugin"]
}
```

این پلاگین قابلیت‌های جامع مدیریت مخزن GitLab از جمله بازبینی MRها، پیگیری issueها، نظارت بر pipelineها و موارد دیگر را فراهم می‌کند.

#### پیکربندی‌های اختیاری

در صورتی که یک ویژگی یا مدلی از Helicone را ببینید که به‌طور خودکار از طریق opencode پیکربندی نشده است، همیشه می‌توانید خودتان آن را پیکربندی کنید.

این [فهرست مدل‌های Helicone](https://helicone.ai/models) است، به آن نیاز خواهید داشت تا شناسه‌های مدل‌هایی که می‌خواهید اضافه کنید را به‌دست آورید.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // شناسه مدل (از صفحه فهرست مدل‌های Helicone)
          "name": "GPT-4o", // نام سفارشی خودتان برای مدل
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### هدرهای سفارشی

Helicone از هدرهای سفارشی برای ویژگی‌هایی مانند کش‌گذاری، پیگیری کاربر و مدیریت جلسه پشتیبانی می‌کند. آن‌ها را با استفاده از `options.headers` به پیکربندی ارائه‌دهنده خود اضافه کنید:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### پیگیری جلسه

ویژگی [Sessions](https://docs.helicone.ai/features/sessions) در Helicone به شما اجازه می‌دهد درخواست‌های مرتبط LLM را با هم گروه‌بندی کنید. از پلاگین [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session) برای ثبت خودکار هر مکالمه OpenCode به‌عنوان یک جلسه در Helicone استفاده کنید.

```bash
npm install -g opencode-helicone-session
```

آن را به پیکربندی خود اضافه کنید.

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

این پلاگین هدرهای `Helicone-Session-Id` و `Helicone-Session-Name` را در درخواست‌های شما تزریق می‌کند. در صفحه Sessions در Helicone، هر مکالمه OpenCode را به‌عنوان یک جلسه جداگانه خواهید دید.

##### هدرهای رایج Helicone

| هدر                        | توضیح                                                          |
| -------------------------- | ------------------------------------------------------------- |
| `Helicone-Cache-Enabled`   | فعال‌سازی کش‌گذاری پاسخ (`true`/`false`)                       |
| `Helicone-User-Id`         | پیگیری معیارها بر اساس کاربر                                   |
| `Helicone-Property-[Name]` | افزودن خصوصیات سفارشی (مثلاً `Helicone-Property-Environment`)  |
| `Helicone-Prompt-Id`       | مرتبط‌کردن درخواست‌ها با نسخه‌های prompt                       |

برای همه هدرهای موجود [Helicone Header Directory](https://docs.helicone.ai/helicone-headers/header-directory) را ببینید.

### Snowflake Cortex

[Snowflake Cortex](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api) به شما دسترسی به مدل‌های پیشرو (Claude، OpenAI GPT-5 و موارد دیگر) را از طریق یک API سازگار با OpenAI می‌دهد. تمام استنتاج‌ها در محدوده Snowflake اجرا می‌شوند و با اعتبارهای Snowflake صورت‌حساب می‌شوند. برای نرخ‌های هر مدل، [Snowflake Service Consumption Table](https://www.snowflake.com/legal-files/CreditConsumptionTable.pdf) را ببینید.

حساب Snowflake ندارید؟ [برای یک دوره آزمایشی رایگان ثبت‌نام کنید](https://signup.snowflake.com/?utm_source=opencode&utm_medium=docs&utm_campaign=cortex-provider).

گردش‌کار اصلی opencode برای کدنویسی، ویرایش فایل‌ها و اجرای دستورات به فراخوانی ابزار وابسته است. فقط خانواده‌های Claude و OpenAI در Snowflake Cortex از این پشتیبانی می‌کنند. ارائه‌دهنده به این خانواده‌ها محدود شده است تا از گردش‌کار اصلی پشتیبانی کند.

OpenCode از دو روش احراز هویت پشتیبانی می‌کند:

- **Browser OAuth (توصیه‌شده)** — با IdP/SSO خود وارد شوید؛ هیچ رازی برای مدیریت وجود ندارد، توکن‌ها به‌طور خودکار تازه می‌شوند.
- **Manual bearer token** — یک PAT یا JWT را از کنسول Snowflake جای‌گذاری کنید.

#### Browser OAuth (توصیه‌شده)

1. دستور `/connect` را اجرا کنید و **Snowflake Cortex** را جستجو کنید.

   ```txt
   /connect
   ```

2. **Login with Snowflake (External Browser)** را انتخاب کنید.

   ```txt
   ┌ Select auth method
   │
   │ Login with Snowflake (External Browser)
   │ Paste PAT or bearer token manually
   └
   ```

3. هنگام درخواست، [شناسه حساب](https://docs.snowflake.com/en/user-guide/admin-account-identifier) خود را وارد کنید، برای مثال `myorg-myaccount` یا `xy12345.us-east-1`.

   ```txt
   ┌ Snowflake Account Identifier
   │
   │
   └ enter
   ```

4. به‌صورت اختیاری یک نقش Snowflake برای محدودکردن دامنه جلسه وارد کنید (مثلاً `SYSADMIN`). برای استفاده از نقش پیش‌فرض خود آن را خالی بگذارید.

5. ورود را در مرورگری که باز می‌شود کامل کنید. OpenCode فراخوان OAuth را به‌طور خودکار دریافت می‌کند و توکن را ذخیره می‌کند — نیازی به کپی/جای‌گذاری نیست.

6. دستور `/models` را اجرا کنید تا یک مدل انتخاب کنید.

   ```txt
   /models
   ```

:::note
Browser OAuth از یکپارچه‌سازی امنیتی داخلی Snowflake با عنوان `SNOWFLAKE$LOCAL_APPLICATION` ([مستندات](https://docs.snowflake.com/en/user-guide/oauth-local-applications)) استفاده می‌کند که در حال ارائه به همه حساب‌هاست. برای بررسی در دسترس‌بودن در حساب خود:

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

اگر نتیجه خالی بود، تا زمانی که این یکپارچه‌سازی به حساب شما ارائه شود، از روش **Manual bearer token** زیر استفاده کنید.
:::

#### Manual bearer token

اگر ترجیح می‌دهید یک توکن را مستقیماً جای‌گذاری کنید، یا اگر `SNOWFLAKE$LOCAL_APPLICATION` هنوز در حساب شما در دسترس نیست:

1. یک [Programmatic Access Token (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) در حساب Snowflake خود تولید کنید.

2. دستور `/connect` را اجرا کنید، **Snowflake Cortex** را جستجو کنید و **Paste PAT or bearer token manually** را انتخاب کنید.

3. هنگام درخواست، [شناسه حساب](https://docs.snowflake.com/en/user-guide/admin-account-identifier) خود را وارد کنید.

4. PAT خود را جای‌گذاری کنید.

5. دستور `/models` را اجرا کنید تا یک مدل انتخاب کنید.

   ```txt
   /models
   ```

#### متغیر محیطی

برای محیط‌های CI یا بدون رابط، قبل از شروع opencode یک PAT یا JWT تنظیم کنید:

```bash
export SNOWFLAKE_ACCOUNT=myorg-myaccount
export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` فقط یک PAT یا JWT می‌پذیرد — جریان browser OAuth فقط از طریق `/connect` در دسترس است و نمی‌توان آن را از طریق یک متغیر محیطی پیکربندی کرد. `SNOWFLAKE_CORTEX_PAT` همچنان برای سازگاری با نسخه‌های قبلی پشتیبانی می‌شود.
:::

کاتالوگ مدل به‌طور خودکار فراهم می‌شود. یک `opencode.json` حداقلی تنها چیزی است که نیاز است:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "snowflake-cortex/claude-sonnet-4-6",
  "small_model": "snowflake-cortex/claude-haiku-4-5"
}
```

### xAI

سه روش برای احراز هویت: یک اشتراک SuperGrok از طریق browser OAuth، همان اشتراک SuperGrok از طریق یک جریان کد-دستگاه بدون رابط (برای VPS / SSH / Docker)، یا یک کلید API پرداخت‌به‌میزان‌مصرف از کنسول xAI.

2. **xAI Grok OAuth (SuperGrok Subscription)** را انتخاب کنید. OpenCode صفحه رضایت xAI را در مرورگر شما باز می‌کند و منتظر فراخوان روی `http://127.0.0.1:56121/callback` می‌ماند.

3. دستور `/models` را اجرا کنید تا یک مدل Grok انتخاب کنید.

   ```txt
   /models
   ```

OpenCode توکن دسترسی OAuth را به‌طور خودکار تازه می‌کند. هر طرح Grok یا X Premium که شامل دسترسی به Grok API باشد کار می‌کند؛ به یک `XAI_API_KEY` جداگانه نیاز ندارید.

#### گزینه B — کد-دستگاه SuperGrok (بدون رابط / سرور راه دور / VPS)

از این روش زمانی استفاده کنید که OpenCode در جایی اجرا می‌شود که مرورگر نمی‌تواند به ریدایرکت loopback دسترسی پیدا کند: یک VPS، یک باکس توسعه راه دور از طریق SSH، داخل Docker، در CI و غیره. هیچ پورت فراخوانی روی میزبانی که OpenCode را اجرا می‌کند باز نمی‌شود — در عوض xAI یک کد کوتاه به CLI می‌دهد که آن را در یک مرورگر روی هر دستگاه دیگری (لپ‌تاپ، تلفن، …) تایپ می‌کنید.

1. دستور `/connect` را روی میزبان راه دور اجرا کنید و **xAI** را جستجو کنید.

   ```txt
   /connect
   ```

2. **xAI Grok OAuth (Headless / Remote / VPS)** را انتخاب کنید. OpenCode یک URL تأیید و یک کد کاربری کوتاه چاپ می‌کند.

   ```txt

   ```

## ارائه‌دهنده سفارشی

برای افزودن هر ارائه‌دهنده **سازگار با OpenAI** که در دستور `/connect` فهرست نشده است:

:::tip
می‌توانید از هر ارائه‌دهنده سازگار با OpenAI با opencode استفاده کنید. اکثر ارائه‌دهنده‌های مدرن هوش مصنوعی APIهای سازگار با OpenAI ارائه می‌دهند.
:::

1. دستور `/connect` را اجرا کنید و تا **Other** به پایین اسکرول کنید.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. یک شناسه منحصربه‌فرد برای ارائه‌دهنده وارد کنید.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   یک شناسه به‌یادماندنی انتخاب کنید، از آن در فایل پیکربندی خود استفاده خواهید کرد.
   :::

3. کلید API خود را برای ارائه‌دهنده وارد کنید.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in opencode.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. فایل `opencode.json` خود را در دایرکتوری پروژه‌تان بسازید یا به‌روزرسانی کنید:

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI ProviderDisplay Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   گزینه‌های پیکربندی به این شرح هستند:
   - **npm**: بسته AI SDK که باید استفاده شود، `@ai-sdk/openai-compatible` برای ارائه‌دهنده‌های سازگار با OpenAI (برای `/v1/chat/completions`). اگر ارائه‌دهنده/مدل شما از `/v1/responses` استفاده می‌کند، از `@ai-sdk/openai` استفاده کنید.
   - **name**: نام نمایشی در رابط کاربری.
   - **models**: مدل‌های موجود.
   - **options.baseURL**: آدرس نقطه پایانی API.
   - **options.apiKey**: به‌صورت اختیاری کلید API را تنظیم کنید، اگر از auth استفاده نمی‌کنید.
   - **options.headers**: به‌صورت اختیاری هدرهای سفارشی را تنظیم کنید.

   جزئیات بیشتر درباره گزینه‌های پیشرفته در مثال زیر آمده است.

5. دستور `/models` را اجرا کنید و ارائه‌دهنده و مدل‌های سفارشی شما در فهرست انتخاب ظاهر خواهند شد.

---

##### مثال

در اینجا مثالی از تنظیم گزینه‌های `apiKey`، `headers` و `limit` مدل آورده شده است.

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI ProviderDisplay Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

جزئیات پیکربندی:

- **apiKey**: با استفاده از نحو متغیر `env` تنظیم می‌شود، [بیشتر بدانید](/docs/config#env-vars).
- **headers**: هدرهای سفارشی که با هر درخواست ارسال می‌شوند.
- **limit.context**: حداکثر توکن‌های ورودی که مدل می‌پذیرد.
- **limit.output**: حداکثر توکن‌هایی که مدل می‌تواند تولید کند.

فیلدهای `limit` به OpenCode اجازه می‌دهند بفهمد چه مقدار context برای شما باقی مانده است. ارائه‌دهنده‌های استاندارد این مقادیر را به‌طور خودکار از models.dev دریافت می‌کنند.

## عیب‌یابی

اگر در پیکربندی یک ارائه‌دهنده با مشکل مواجه هستید، موارد زیر را بررسی کنید:

1. **راه‌اندازی auth را بررسی کنید**: دستور `opencode auth list` را اجرا کنید تا ببینید آیا اعتبارنامه‌های
   ارائه‌دهنده به پیکربندی شما اضافه شده‌اند.

   این مورد برای ارائه‌دهنده‌هایی مانند Amazon Bedrock که برای auth خود به متغیرهای محیطی متکی هستند، اعمال نمی‌شود.

2. برای ارائه‌دهنده‌های سفارشی، پیکربندی opencode را بررسی کنید و:
   - مطمئن شوید شناسه ارائه‌دهنده‌ای که در دستور `/connect` استفاده شده با شناسه موجود در پیکربندی opencode شما مطابقت دارد.
   - بسته npm صحیح برای ارائه‌دهنده استفاده شده باشد. برای مثال، برای Cerebras از `@ai-sdk/cerebras` استفاده کنید. و برای همه ارائه‌دهنده‌های دیگر سازگار با OpenAI، از `@ai-sdk/openai-compatible` استفاده کنید (برای `/v1/chat/completions`)؛ اگر مدلی از `/v1/responses` استفاده می‌کند، از `@ai-sdk/openai` استفاده کنید. برای راه‌اندازی‌های ترکیبی تحت یک ارائه‌دهنده، می‌توانید برای هر مدل از طریق `provider.npm` بازنویسی کنید.
   - بررسی کنید که نقطه پایانی API صحیح در فیلد `options.baseURL` استفاده شده باشد.
