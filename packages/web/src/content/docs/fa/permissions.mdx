---

OpenCode از پیکربندی `permission` استفاده می‌کند تا تصمیم بگیرد یک اقدام مشخص باید به‌صورت خودکار اجرا شود، از شما درخواست تأیید کند، یا مسدود شود.

از نسخه‌ی `v1.1.1`، پیکربندی بولی قدیمی `tools` منسوخ شده و در `permission` ادغام شده است. پیکربندی قدیمی `tools` همچنان برای سازگاری با نسخه‌های پیشین پشتیبانی می‌شود.

---

## اقدامات

هر قاعده‌ی مجوز به یکی از این موارد می‌رسد:

- `"allow"` — اجرا بدون تأیید
- `"ask"` — درخواست تأیید
- `"deny"` — مسدودکردن اقدام

---

## پیکربندی

می‌توانید مجوزها را به‌صورت سراسری تنظیم کنید (با `*`) و ابزارهای مشخص را جایگزین کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "*": "ask",
    "bash": "allow",
    "edit": "deny"
  }
}
```

همچنین می‌توانید همه‌ی مجوزها را یک‌جا تنظیم کنید:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": "allow"
}
```

## قواعد دقیق (نحو شیء)

برای بیشتر مجوزها، می‌توانید از یک شیء برای اعمال اقدامات مختلف بر اساس ورودی ابزار استفاده کنید.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "npm *": "allow",
      "rm *": "deny",
      "grep *": "allow"
    },
    "edit": {
      "*": "deny",
      "packages/web/src/content/docs/*.mdx": "allow"
    }
  }
}
```

قواعد با مطابقت الگو ارزیابی می‌شوند و **آخرین قاعده‌ی مطابق برنده می‌شود**. یک الگوی رایج این است که قاعده‌ی فراگیر `"*"` را اول قرار دهید و قواعد مشخص‌تر را بعد از آن.

### وایلدکارت‌ها

الگوهای مجوز از مطابقت ساده‌ی وایلدکارت استفاده می‌کنند:

- `*` با صفر یا چند کاراکتر از هر نوع مطابقت دارد
- `?` دقیقاً با یک کاراکتر مطابقت دارد
- همه‌ی کاراکترهای دیگر به‌صورت تحت‌اللفظی مطابقت می‌یابند

### بسط دایرکتوری Home

می‌توانید از `~` یا `$HOME` در ابتدای یک الگو برای ارجاع به دایرکتوری home خود استفاده کنید. این به‌ویژه برای قواعد [`external_directory`](#external-directories) مفید است.

- `~/projects/*` -> `/Users/username/projects/*`
- `$HOME/projects/*` -> `/Users/username/projects/*`
- `~` -> `/Users/username`

### دایرکتوری‌های خارجی

از `external_directory` برای اجازه‌دادن به فراخوانی‌های ابزاری استفاده کنید که مسیرهای خارج از دایرکتوری کاری‌ای را که OpenCode در آن آغاز شده لمس می‌کنند. این برای هر ابزاری که مسیری را به‌عنوان ورودی می‌گیرد اعمال می‌شود (برای مثال `read`، `edit`، `glob`، `grep` و بسیاری از دستورات `bash`).

بسط home (مانند `~/...`) فقط بر نحوه‌ی نوشتن یک الگو اثر می‌گذارد. این کار یک مسیر خارجی را بخشی از فضای کاری فعلی نمی‌کند، بنابراین مسیرهای خارج از دایرکتوری کاری همچنان باید از طریق `external_directory` مجاز شوند.

برای مثال، این اجازه‌ی دسترسی به همه‌چیز زیر `~/projects/personal/` را می‌دهد:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    }
  }
}
```

هر دایرکتوری مجازشده در اینجا همان مقادیر پیش‌فرض فضای کاری فعلی را به ارث می‌برد. از آنجا که [`read` به‌صورت پیش‌فرض `allow` است](#defaults)، خواندن نیز برای ورودی‌های زیر `external_directory` مجاز است مگر اینکه جایگزین شود. وقتی یک ابزار باید در این مسیرها محدود شود، قواعد صریح اضافه کنید، مانند مسدودکردن ویرایش‌ها در حالی که خواندن حفظ می‌شود:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    },
    "edit": {
      "~/projects/personal/**": "deny"
    }
  }
}
```

فهرست را متمرکز بر مسیرهای مورد اعتماد نگه دارید و در صورت نیاز برای ابزارهای دیگر (برای مثال `bash`) قواعد allow یا deny اضافی را لایه‌بندی کنید.

## مجوزهای موجود

مجوزهای OpenCode بر اساس نام ابزار کلیدگذاری می‌شوند، به‌علاوه‌ی چند محافظ ایمنی:

- `read` — خواندن یک فایل (با مسیر فایل مطابقت می‌یابد)
- `edit` — همه‌ی تغییرات فایل (شامل `edit`، `write`، `patch`)
- `glob` — globbing فایل (با الگوی glob مطابقت می‌یابد)
- `grep` — جست‌وجوی محتوا (با الگوی regex مطابقت می‌یابد)
- `bash` — اجرای دستورات shell (با دستورات تجزیه‌شده مانند `git status --porcelain` مطابقت می‌یابد)
- `task` — راه‌اندازی زیرعامل‌ها (با نوع زیرعامل مطابقت می‌یابد)
- `skill` — بارگذاری یک مهارت (با نام مهارت مطابقت می‌یابد)
- `lsp` — اجرای پرس‌وجوهای LSP (در حال حاضر غیردقیق)
- `question` — پرسیدن سؤال از کاربر در حین اجرا
- `webfetch` — واکشی یک URL (با URL مطابقت می‌یابد)
- `websearch` — جست‌وجوی وب (با پرس‌وجو مطابقت می‌یابد)
- `external_directory` — وقتی فعال می‌شود که یک ابزار مسیرهای خارج از دایرکتوری کاری پروژه را لمس کند
- `doom_loop` — وقتی فعال می‌شود که همان فراخوانی ابزار ۳ بار با ورودی یکسان تکرار شود

## مقادیر پیش‌فرض

اگر چیزی تعیین نکنید، OpenCode از مقادیر پیش‌فرض سهل‌گیرانه آغاز می‌کند:

- بیشتر مجوزها به‌صورت پیش‌فرض `"allow"` هستند.
- `doom_loop` و `external_directory` به‌صورت پیش‌فرض `"ask"` هستند.
- `read` برابر `"allow"` است، اما فایل‌های `.env` به‌صورت پیش‌فرض رد می‌شوند:

```json title="opencode.json"
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.env.example": "allow"
    }
  }
}
```

## کاری که «Ask» انجام می‌دهد

وقتی OpenCode درخواست تأیید می‌کند، رابط کاربری سه نتیجه ارائه می‌دهد:

- `once` — تأیید فقط همین درخواست
- `always` — تأیید درخواست‌های آینده‌ای که با الگوهای پیشنهادی مطابقت دارند (برای باقی‌مانده‌ی نشست فعلی OpenCode)
- `reject` — رد درخواست

مجموعه‌ی الگوهایی که `always` تأیید می‌کند توسط ابزار ارائه می‌شود (برای مثال، تأییدهای bash معمولاً یک پیشوند دستور امن مانند `git status*` را در فهرست سفید قرار می‌دهند).

## عامل‌ها

می‌توانید مجوزها را برای هر عامل جایگزین کنید. مجوزهای عامل با پیکربندی سراسری ادغام می‌شوند و قواعد عامل اولویت دارند. [بیشتر بدانید](/docs/agents#permissions) درباره‌ی مجوزهای عامل.

:::note
برای مثال‌های دقیق‌تر مطابقت الگو، به بخش [قواعد دقیق (نحو شیء)](#granular-rules-object-syntax) در بالا مراجعه کنید.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git commit *": "deny",
      "git push *": "deny",
      "grep *": "allow"
    }
  },
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git *": "allow",
          "git commit *": "ask",
          "git push *": "deny",
          "grep *": "allow"
        }
      }
    }
  }
}
```

همچنین می‌توانید مجوزهای عامل را در Markdown پیکربندی کنید:

```markdown title="~/.config/opencode/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash: ask
  webfetch: deny
---

Only analyze code and suggest changes.
```

:::tip
برای دستورهای دارای آرگومان از مطابقت الگو استفاده کنید. `"grep *"` اجازه‌ی `grep pattern file.txt` را می‌دهد، در حالی که `"grep"` به‌تنهایی آن را مسدود می‌کند. دستورهایی مانند `git status` برای رفتار پیش‌فرض کار می‌کنند اما هنگامی که آرگومان‌ها پاس داده می‌شوند به مجوز صریح (مانند `"git status *"`) نیاز دارند.
:::
