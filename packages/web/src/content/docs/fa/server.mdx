دستور `opencode serve` یک سرور HTTP بی‌سر (headless) اجرا می‌کند که یک نقطه پایانی OpenAPI را در معرض دید قرار می‌دهد که یک کلاینت opencode می‌تواند از آن استفاده کند.

---

### استفاده

```bash
opencode serve [--port <number>] [--hostname <string>] [--cors <origin>]
```

#### گزینه‌ها

| Flag            | Description                         | Default          |
| --------------- | ----------------------------------- | ---------------- |
| `--port`        | Port to listen on                   | `4096`           |
| `--hostname`    | Hostname to listen on               | `127.0.0.1`      |
| `--mdns`        | Enable mDNS discovery               | `false`          |
| `--mdns-domain` | Custom domain name for mDNS service | `opencode.local` |
| `--cors`        | Additional browser origins to allow | `[]`             |

`--cors` را می‌توان چندین بار ارسال کرد:

```bash
opencode serve --cors http://localhost:5173 --cors https://app.example.com
```

---

### احراز هویت

متغیر `OPENCODE_SERVER_PASSWORD` را برای محافظت از سرور با احراز هویت پایه HTTP تنظیم کنید. نام کاربری به طور پیش‌فرض `opencode` است، یا `OPENCODE_SERVER_USERNAME` را برای تغییر آن تنظیم کنید. این مورد هم برای `opencode serve` و هم برای `opencode web` اعمال می‌شود.

```bash
OPENCODE_SERVER_PASSWORD=your-password opencode serve
```

---

### نحوه عملکرد

وقتی `opencode` را اجرا می‌کنید، یک TUI و یک سرور شروع می‌شود. در اینجا TUI همان کلاینتی است که با سرور صحبت می‌کند. سرور یک نقطه پایانی با مشخصات OpenAPI 3.1 را در معرض دید قرار می‌دهد. این نقطه پایانی همچنین برای تولید یک [SDK](/docs/sdk) استفاده می‌شود.

:::tip
از سرور opencode برای تعامل برنامه‌نویسی با opencode استفاده کنید.
:::

این معماری به opencode اجازه می‌دهد چندین کلاینت را پشتیبانی کند و به شما امکان می‌دهد به صورت برنامه‌نویسی با opencode تعامل داشته باشید.

می‌توانید `opencode serve` را اجرا کنید تا یک سرور مستقل شروع شود. اگر TUI opencode در حال اجرا باشد، `opencode serve` یک سرور جدید شروع می‌کند.

---

#### اتصال به یک سرور موجود

وقتی TUI را شروع می‌کنید، به طور تصادفی یک پورت و نام میزبان اختصاص می‌دهد. در عوض می‌توانید [flags](/docs/cli) را `--hostname` و `--port` ارسال کنید. سپس از این برای اتصال به سرور آن استفاده کنید.

نقطه پایانی [`/tui`](#tui) می‌تواند برای هدایت TUI از طریق سرور استفاده شود. به عنوان مثال، می‌توانید یک درخواست را از پیش پر کنید یا اجرا کنید. این تنظیم توسط افزونه‌های [IDE](/docs/ide) OpenCode استفاده می‌شود.

## مشخصات

سرور یک مشخصات OpenAPI 3.1 منتشر می‌کند که می‌توان آن را در آدرس زیر مشاهده کرد:

```
http://<hostname>:<port>/doc
```

به عنوان مثال، `http://localhost:4096/doc`. از مشخصات برای تولید کلاینت‌ها یا بازرسی انواع درخواست و پاسخ استفاده کنید. یا آن را در یک کاوشگر Swagger مشاهده کنید.

#### پارامترهای پرس‌وجوی `/find/file`

- `query` (ضروری) — رشته جستجو (تطبیق fuzzy)
- `type` (اختیاری) — محدود کردن نتایج به `"file"` یا `"directory"`
- `directory` (اختیاری) — جایگزینی ریشه پروژه برای جستجو
- `limit` (اختیاری) — حداکثر نتایج (۱ تا ۲۰۰)
- `dirs` (اختیاری) — پرچم قدیمی (`"false"` فقط پرونده‌ها را برمی‌گرداند)
