CLI مربوط به OpenCode به‌طور پیش‌فرض هنگام اجرا بدون هیچ آرگومانی، [TUI](/docs/tui) را راه‌اندازی می‌کند.

```bash
opencode
```

اما همان‌طور که در این صفحه مستند شده، دستورات را نیز می‌پذیرد. این به شما اجازه می‌دهد تا به‌صورت برنامه‌نویسی با OpenCode تعامل کنید.

```bash
opencode run "Explain how closures work in JavaScript"
```

### tui

رابط کاربری ترمینال OpenCode را راه‌اندازی کنید.

```bash
opencode [project]
```

#### پرچم‌ها

| پرچم                                        | کوتاه | توضیح                                                                    |
| ------------------------------------------- | ----- | ----------------------------------------------------------------------- |
| <nobr><code>{"--continue"}</code></nobr>    | `-c`  | ادامه آخرین جلسه                                                         |
| <nobr><code>{"--session"}</code></nobr>     | `-s`  | شناسه جلسه برای ادامه                                                    |
| <nobr><code>{"--fork"}</code></nobr>        |       | انشعاب جلسه هنگام ادامه (همراه با `--continue` یا `--session` استفاده شود) |
| <nobr><code>{"--prompt"}</code></nobr>      |       | پرامپتی که باید استفاده شود                                              |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | مدلی که باید استفاده شود به شکل provider/model                           |
| <nobr><code>{"--agent"}</code></nobr>       |       | عاملی که باید استفاده شود                                                |
| <nobr><code>{"--port"}</code></nobr>        |       | پورتی که باید روی آن گوش داده شود                                        |
| <nobr><code>{"--hostname"}</code></nobr>    |       | نام میزبانی که باید روی آن گوش داده شود                                  |
| <nobr><code>{"--mdns"}</code></nobr>        |       | فعال‌سازی کشف mDNS                                                       |
| <nobr><code>{"--mdns-domain"}</code></nobr> |       | نام دامنه سفارشی mDNS                                                    |
| <nobr><code>{"--cors"}</code></nobr>        |       | مبدأ(های) مرورگر اضافی برای مجاز کردن CORS                               |

## دستورات

CLI مربوط به OpenCode همچنین دستورات زیر را دارد.

### agent

عامل‌های OpenCode را مدیریت کنید.

```bash
opencode agent [command]
```

---

#### create

یک عامل جدید با پیکربندی سفارشی ایجاد کنید.

```bash
opencode agent create
```

این دستور شما را در ایجاد یک عامل جدید با پرامپت سیستمی سفارشی و پیکربندی مجوزها راهنمایی می‌کند. هر چیزی که اجازه ندهید، در frontmatter عامل تولیدشده رد می‌شود.

#### پرچم‌ها

| پرچم                                        | کوتاه | توضیح                                                                                                                                                                                                                       |
| ------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <nobr><code>{"--path"}</code></nobr>        |       | دایرکتوری که فایل عامل در آن نوشته شود (به‌طور پیش‌فرض بر اساس پرامپت، global یا `.opencode/agent`)                                                                                                                          |
| <nobr><code>{"--description"}</code></nobr> |       | کاری که عامل باید انجام دهد                                                                                                                                                                                                |
| <nobr><code>{"--mode"}</code></nobr>        |       | حالت عامل: `all`، `primary` یا `subagent`                                                                                                                                                                                  |
| <nobr><code>{"--permissions"}</code></nobr> |       | فهرست جداشده با کاما از مجوزهایی که باید اجازه داده شوند (پیش‌فرض: همه). موجود: `bash`، `read`، `edit`، `glob`، `grep`، `webfetch`، `task`، `todowrite`، `websearch`، `lsp`، `skill`. هر چیز حذف‌شده رد می‌شود. نام مستعار: `--tools` |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | مدلی که باید استفاده شود، به شکل `provider/model`                                                                                                                                                                          |

ارسال همه گزینه‌های `--path`، `--description`، `--mode` و `--permissions` این دستور را به‌صورت غیرتعاملی اجرا می‌کند.

### attach

یک ترمینال را به یک سرور بک‌اند OpenCode که از قبل در حال اجراست و از طریق دستورات `serve` یا `web` راه‌اندازی شده، متصل کنید.

```bash
opencode attach [url]
```

این به شما اجازه می‌دهد از TUI با یک بک‌اند راه‌دور OpenCode استفاده کنید. برای مثال:

```bash
# سرور بک‌اند را برای دسترسی وب/موبایل راه‌اندازی کنید
opencode web --port 4096 --hostname 0.0.0.0

# در ترمینال دیگری، TUI را به بک‌اند در حال اجرا متصل کنید
opencode attach http://10.20.30.40:4096
```

#### پرچم‌ها

| پرچم                                     | کوتاه | توضیح                                                                      |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--dir"}</code></nobr>      |       | دایرکتوری کاری که TUI در آن راه‌اندازی شود                                  |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | ادامه آخرین جلسه                                                           |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | شناسه جلسه برای ادامه                                                      |
| <nobr><code>{"--fork"}</code></nobr>     |       | انشعاب جلسه هنگام ادامه (همراه با `--continue` یا `--session` استفاده شود)  |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | رمز عبور احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_PASSWORD`)               |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | نام کاربری احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_USERNAME` یا `opencode`) |

### auth

دستوری برای مدیریت اطلاعات اعتبار و ورود برای ارائه‌دهندگان.

```bash
opencode auth [command]
```

---

#### login

OpenCode بر پایه فهرست ارائه‌دهندگان در [Models.dev](https://models.dev) کار می‌کند، بنابراین می‌توانید از `opencode auth login` برای پیکربندی کلیدهای API برای هر ارائه‌دهنده‌ای که بخواهید استفاده کنید. این در `~/.local/share/opencode/auth.json` ذخیره می‌شود.

```bash
opencode auth login
```

وقتی OpenCode راه‌اندازی می‌شود، ارائه‌دهندگان را از فایل اطلاعات اعتبار بارگذاری می‌کند. و اگر کلیدهایی در محیط‌های شما یا یک فایل `.env` در پروژه‌تان تعریف شده باشند نیز همان‌ها را بارگذاری می‌کند.

##### پرچم‌ها

| پرچم                                     | کوتاه | توضیح                                                |
| ---------------------------------------- | ----- | ---------------------------------------------------- |
| <nobr><code>{"--provider"}</code></nobr> | `-p`  | شناسه یا نام ارائه‌دهنده برای ورود                   |
| <nobr><code>{"--method"}</code></nobr>   | `-m`  | برچسب روش ورود برای استفاده، با رد کردن انتخاب روش    |

---

#### list

همه ارائه‌دهندگان احراز هویت‌شده را همان‌طور که در فایل اطلاعات اعتبار ذخیره شده‌اند فهرست می‌کند.

```bash
opencode auth list
```

یا نسخه کوتاه آن.

```bash
opencode auth ls
```

---

#### logout

شما را با پاک کردن یک ارائه‌دهنده از فایل اطلاعات اعتبار از آن خارج می‌کند.

```bash
opencode auth logout
```

#### list


#### auth

با یک سرور MCP دارای قابلیت OAuth احراز هویت کنید.

```bash
opencode mcp auth [name]
```

اگر نام سروری ارائه ندهید، از شما خواسته می‌شود که از میان سرورهای دارای قابلیت OAuth موجود انتخاب کنید.

همچنین می‌توانید سرورهای دارای قابلیت OAuth و وضعیت احراز هویت آن‌ها را فهرست کنید.

```bash
opencode mcp auth list
```

یا از نسخه کوتاه آن استفاده کنید.

```bash
opencode mcp auth ls
```

### models

همه مدل‌های موجود از ارائه‌دهندگان پیکربندی‌شده را فهرست کنید.

```bash
opencode models [provider]
```

این دستور همه مدل‌های موجود در سراسر ارائه‌دهندگان پیکربندی‌شده شما را به شکل `provider/model` نمایش می‌دهد.

این برای تشخیص نام دقیق مدلی که باید در [پیکربندی شما](/docs/config/) استفاده شود مفید است.

می‌توانید به‌صورت اختیاری یک شناسه ارائه‌دهنده ارسال کنید تا مدل‌ها بر اساس آن ارائه‌دهنده فیلتر شوند.

```bash
opencode models anthropic
```

#### پرچم‌ها

| پرچم                                    | توضیح                                                        |
| --------------------------------------- | ------------------------------------------------------------ |
| <nobr><code>{"--refresh"}</code></nobr> | تازه‌سازی حافظه نهان مدل‌ها از models.dev                     |
| <nobr><code>{"--verbose"}</code></nobr> | استفاده از خروجی پرجزئیات‌تر مدل (شامل فراداده‌هایی مانند هزینه‌ها) |

از پرچم `--refresh` برای به‌روزرسانی فهرست مدل‌های ذخیره‌شده در حافظه نهان استفاده کنید. این زمانی مفید است که مدل‌های جدیدی به یک ارائه‌دهنده اضافه شده‌اند و می‌خواهید آن‌ها را در OpenCode ببینید.

```bash
opencode models --refresh
```

### run

opencode را در حالت غیرتعاملی با ارسال مستقیم یک پرامپت اجرا کنید.

```bash
opencode run [message..]
```

این برای اسکریپت‌نویسی، اتوماسیون، یا زمانی که می‌خواهید بدون راه‌اندازی TUI کامل پاسخ سریعی بگیرید مفید است. برای مثال.

```bash "opencode run"
opencode run Explain the use of context in Go
```

همچنین می‌توانید به یک نمونه `opencode serve` در حال اجرا متصل شوید تا از زمان راه‌اندازی سرد سرورهای MCP در هر اجرا جلوگیری کنید:

```bash
# یک سرور بدون رابط (headless) را در یک ترمینال راه‌اندازی کنید
opencode serve

# در ترمینال دیگری، دستوراتی را اجرا کنید که به آن متصل می‌شوند
opencode run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### پرچم‌ها

| پرچم                                                         | کوتاه | توضیح                                                                      |
| ------------------------------------------------------------ | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--command"}</code></nobr>                      |       | دستوری که باید اجرا شود، از message برای آرگومان‌ها استفاده کنید            |
| <nobr><code>{"--continue"}</code></nobr>                     | `-c`  | ادامه آخرین جلسه                                                           |
| <nobr><code>{"--session"}</code></nobr>                      | `-s`  | شناسه جلسه برای ادامه                                                      |
| <nobr><code>{"--fork"}</code></nobr>                         |       | انشعاب جلسه هنگام ادامه (همراه با `--continue` یا `--session` استفاده شود)  |
| <nobr><code>{"--share"}</code></nobr>                        |       | اشتراک‌گذاری جلسه                                                          |
| <nobr><code>{"--model"}</code></nobr>                        | `-m`  | مدلی که باید استفاده شود به شکل provider/model                             |
| <nobr><code>{"--agent"}</code></nobr>                        |       | عاملی که باید استفاده شود                                                  |
| <nobr><code>{"--file"}</code></nobr>                         | `-f`  | فایل(هایی) که باید به پیام پیوست شوند                                      |
| <nobr><code>{"--format"}</code></nobr>                       |       | قالب: default (قالب‌بندی‌شده) یا json (رویدادهای JSON خام)                  |
| <nobr><code>{"--title"}</code></nobr>                        |       | عنوان جلسه (اگر مقداری ارائه نشود از پرامپت کوتاه‌شده استفاده می‌کند)       |
| <nobr><code>{"--attach"}</code></nobr>                       |       | اتصال به یک سرور opencode در حال اجرا (مثلاً http://localhost:4096)         |
| <nobr><code>{"--password"}</code></nobr>                     | `-p`  | رمز عبور احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_PASSWORD`)               |
| <nobr><code>{"--username"}</code></nobr>                     | `-u`  | نام کاربری احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_USERNAME` یا `opencode`) |
| <nobr><code>{"--dir"}</code></nobr>                          |       | دایرکتوری اجرا، یا مسیر روی سرور راه‌دور هنگام اتصال                        |
| <nobr><code>{"--port"}</code></nobr>                         |       | پورت سرور محلی (پیش‌فرض پورت تصادفی)                                       |
| <nobr><code>{"--variant"}</code></nobr>                      |       | گونه مدل (تلاش استدلالی مختص ارائه‌دهنده)                                   |
| <nobr><code>{"--thinking"}</code></nobr>                     |       | نمایش بلوک‌های تفکر                                                        |
| <nobr><code>{"--dangerously-skip-permissions"}</code></nobr> |       | تأیید خودکار مجوزهایی که به‌صراحت رد نشده‌اند (خطرناک!)                     |

### serve

یک سرور بدون رابط (headless) OpenCode را برای دسترسی به API راه‌اندازی کنید. برای رابط HTTP کامل، [مستندات سرور](/docs/server) را ببینید.

```bash
opencode serve
```

این یک سرور HTTP راه‌اندازی می‌کند که دسترسی API به قابلیت‌های opencode را بدون رابط TUI فراهم می‌کند. برای فعال‌سازی احراز هویت پایه HTTP مقدار `OPENCODE_SERVER_PASSWORD` را تنظیم کنید (نام کاربری به‌طور پیش‌فرض `opencode` است).

#### پرچم‌ها

| پرچم                                        | توضیح                                      |
| ------------------------------------------- | ------------------------------------------ |
| <nobr><code>{"--port"}</code></nobr>        | پورتی که باید روی آن گوش داده شود          |
| <nobr><code>{"--hostname"}</code></nobr>    | نام میزبانی که باید روی آن گوش داده شود    |
| <nobr><code>{"--mdns"}</code></nobr>        | فعال‌سازی کشف mDNS                         |
| <nobr><code>{"--mdns-domain"}</code></nobr> | نام دامنه سفارشی mDNS                      |
| <nobr><code>{"--cors"}</code></nobr>        | مبدأ(های) مرورگر اضافی برای مجاز کردن CORS |

### import

داده‌های جلسه را از یک فایل JSON یا URL اشتراک‌گذاری OpenCode وارد کنید.

```bash

```

### web

یک سرور بدون رابط (headless) OpenCode را همراه با یک رابط وب راه‌اندازی کنید.

```bash
opencode web
```

این یک سرور HTTP راه‌اندازی می‌کند و یک مرورگر وب را برای دسترسی به OpenCode از طریق رابط وب باز می‌کند. برای فعال‌سازی احراز هویت پایه HTTP مقدار `OPENCODE_SERVER_PASSWORD` را تنظیم کنید (نام کاربری به‌طور پیش‌فرض `opencode` است).

#### پرچم‌ها

### acp

یک سرور ACP (Agent Client Protocol) را راه‌اندازی کنید.

```bash
opencode acp
```

این دستور یک سرور ACP راه‌اندازی می‌کند که از طریق stdin/stdout با استفاده از nd-JSON ارتباط برقرار می‌کند.
