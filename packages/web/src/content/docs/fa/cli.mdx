OpenCode CLI به‌طور پیش‌فرض وقتی بدون هیچ آرگومانی اجرا شود، [TUI](/docs/tui) را آغاز می‌کند.

```bash
opencode
```

اما همچنین دستوراتی را می‌پذیرد که در این صفحه مستند شده‌اند. این به شما اجازه می‌دهد به‌صورت برنامه‌نویسی‌شده با OpenCode تعامل کنید.

```bash
opencode run "Explain how closures work in JavaScript"
```

## دستورات

OpenCode CLI همچنین دستورات زیر را دارد.

---

### agent

مدیریت عامل‌ها برای OpenCode.

```bash
opencode agent [command]
```

---

#### create

یک عامل جدید با پیکربندی سفارشی ایجاد کنید.

```bash
opencode agent create
```

این دستور شما را در ایجاد یک عامل جدید با یک درخواست سیستمی سفارشی و پیکربندی مجوز راهنمایی می‌کند. هر چیزی که اجازه ندهید در frontmatter عاملِ تولیدشده رد می‌شود.

#### Flags

| Flag                                        | Short | Description                                                                                                                                                                                                                |
| ------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <nobr><code>{"--path"}</code></nobr>        |       | فهرستی برای نوشتن پروندهٔ عامل در آن (پیش‌فرض بر اساس درخواست، سراسری یا `.opencode/agent`)                                                                                                                               |
| <nobr><code>{"--description"}</code></nobr> |       | اینکه عامل باید چه کند                                                                                                                                                                                                     |
| <nobr><code>{"--mode"}</code></nobr>        |       | حالت عامل: `all`، `primary`، یا `subagent`                                                                                                                                                                                 |
| <nobr><code>{"--permissions"}</code></nobr> |       | فهرست جداشده با ویرگول از مجوزهایی برای اجازه دادن (پیش‌فرض: همه). موجود: `bash`، `read`، `edit`، `glob`، `grep`، `webfetch`، `task`، `todowrite`، `websearch`، `lsp`، `skill`. هر چیزی که حذف شود رد می‌شود. نام مستعار: `--tools` |
| <nobr><code>{"--model"}</code></nobr>       | `-m`  | مدل برای استفاده، به فرمت `provider/model`                                                                                                                                                                                 |

عبور تمامِ `--path`، `--description`، `--mode`، و `--permissions` دستور را به‌صورت غیرتعاملی اجرا می‌کند.

### attach

یک ترمینال را به یک سرور بک‌اند OpenCode که از قبل در حال اجراست و از طریق دستورات `serve` یا `web` شروع شده است، متصل کنید.

```bash
opencode attach [url]
```

این امکان استفاده از TUI با یک بک‌اند OpenCode از راه دور را فراهم می‌کند. برای مثال:

```bash
# Start the backend server for web/mobile access
opencode web --port 4096 --hostname 0.0.0.0

# In another terminal, attach the TUI to the running backend
opencode attach http://10.20.30.40:4096
```

#### Flags

| Flag                                     | Short | Description                                                                |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--dir"}</code></nobr>      |       | فهرست کاری برای شروع TUI در آن                                             |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | ادامهٔ آخرین نشست                                                          |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | شناسهٔ نشست برای ادامه                                                     |
| <nobr><code>{"--fork"}</code></nobr>     |       | انشعاب نشست هنگام ادامه (با `--continue` یا `--session` استفاده شود)       |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | گذرواژهٔ احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_PASSWORD`)             |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | نام کاربری احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_USERNAME` یا `opencode`) |

### auth

دستوری برای مدیریت اعتبارنامه‌ها و ورود برای ارائه‌دهنده‌ها.

```bash
opencode auth [command]
```

---

#### login

OpenCode توسط فهرست ارائه‌دهنده‌ها در [Models.dev](https://models.dev) تغذیه می‌شود، بنابراین می‌توانید از `opencode auth login` برای پیکربندی کلیدهای API برای هر ارائه‌دهنده‌ای که مایلید استفاده کنید استفاده کنید. این در `~/.local/share/opencode/auth.json` ذخیره می‌شود.

```bash
opencode auth login
```

وقتی OpenCode راه‌اندازی می‌شود، ارائه‌دهنده‌ها را از پروندهٔ اعتبارنامه‌ها بارگذاری می‌کند. و اگر هر کلیدی در محیط‌هایتان یا یک پروندهٔ `.env` در پروژه‌تان تعریف شده باشد.

##### Flags

| Flag                                     | Short | Description                                          |
| ---------------------------------------- | ----- | ---------------------------------------------------- |
| <nobr><code>{"--provider"}</code></nobr> | `-p`  | شناسه یا نام ارائه‌دهنده برای ورود                     |
| <nobr><code>{"--method"}</code></nobr>   | `-m`  | برچسب روش ورود برای استفاده، رد کردن انتخاب روش      |

---

#### list

فهرست تمام ارائه‌دهنده‌های احراز هویت‌شده همان‌طور که در پروندهٔ اعتبارنامه‌ها ذخیره شده است.

```bash
opencode auth list
```

یا نسخهٔ کوتاه آن.

```bash
opencode auth ls
```

---

#### logout

خروج شما از یک ارائه‌دهنده با پاک کردن آن از پروندهٔ اعتبارنامه‌ها.

```bash
opencode auth logout
```

### mcp

مدیریت سرورهای Model Context Protocol.

```bash
opencode mcp [command]
```

---

#### add

یک سرور MCP به پیکربندی خود اضافه کنید.

```bash
opencode mcp add
```

این دستور شما را در افزودن یک سرور MCP محلی یا از راه دور راهنمایی می‌کند.

---

#### list

فهرست تمام سرورهای MCP پیکربندی‌شده و وضعیت اتصال آن‌ها.

```bash
opencode mcp list
```

یا از نسخهٔ کوتاه استفاده کنید.

```bash
opencode mcp ls
```

---

#### auth

احراز هویت با یک سرور MCP دارای OAuth.

```bash
opencode mcp auth [name]
```

اگر نام سرور را ارائه ندهید، از شما خواسته می‌شود از میان سرورهای توانا به OAuth انتخاب کنید.

همچنین می‌توانید سرورهای توانا به OAuth و وضعیت احراز هویت آن‌ها را فهرست کنید.

```bash
opencode mcp auth list
```

یا از نسخهٔ کوتاه استفاده کنید.

```bash
opencode mcp auth ls
```

---

#### logout

حذف اعتبارنامه‌های OAuth برای یک سرور MCP.

```bash
opencode mcp logout [name]
```

---

#### debug

رفع اشکال مشکلات اتصال OAuth برای یک سرور MCP.

```bash
opencode mcp debug <name>
```

### models

فهرست تمام مدل‌های موجود از ارائه‌دهنده‌های پیکربندی‌شده.

```bash
opencode models [provider]
```

این دستور تمام مدل‌های موجود در میان ارائه‌دهنده‌های پیکربندی‌شده را به فرمت `provider/model` نمایش می‌دهد.

این برای پیدا کردن نام دقیق مدل برای استفاده در [پیکربندی شما](/docs/config/) مفید است.

می‌توانید اختیاری یک شناسهٔ ارائه‌دهنده عبور دهید تا مدل‌ها را بر اساس آن ارائه‌دهنده فیلتر کنید.

```bash
opencode models anthropic
```

#### Flags

| Flag                                    | Description                                                  |
| --------------------------------------- | ------------------------------------------------------------ |
| <nobr><code>{"--refresh"}</code></nobr> | به‌روزرسانی حافظهٔ نهان مدل‌ها از models.dev                |
| <nobr><code>{"--verbose"}</code></nobr> | استفاده از خروجی مدل پرگویاتر (شامل فراداده مثل هزینه‌ها)   |

از پرچم `--refresh` برای به‌روزرسانی فهرست مدل ذخیره‌شده استفاده کنید. این وقتی مفید است که مدل‌های جدیدی به یک ارائه‌دهنده اضافه شده باشند و می‌خواهید آن‌ها را در OpenCode ببینید.

```bash
opencode models --refresh
```

### run

opencode را در حالت غیرتعاملی با عبور مستقیم یک درخواست اجرا کنید.

```bash
opencode run [message..]
```

این برای اسکریپت‌نویسی، خودکارسازی، یا وقتی که پاسخ سریعی بدون راه‌اندازی TUI کامل می‌خواهید مفید است. برای مثال.

```bash "opencode run"
opencode run Explain the use of context in Go
```

همچنین می‌توانید به یک نمونهٔ در حال اجرای `opencode serve` متصل شوید تا از زمان راه‌اندازی سرد سرور MCP در هر اجرا جلوگیری کنید:

```bash
# Start a headless server in one terminal
opencode serve

# In another terminal, run commands that attach to it
opencode run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### Flags

| Flag                                     | Short | Description                                                                |
| ---------------------------------------- | ----- | -------------------------------------------------------------------------- |
| <nobr><code>{"--command"}</code></nobr>  |       | دستور برای اجرا، برای آرگومان‌ها از message استفاده کنید                  |
| <nobr><code>{"--continue"}</code></nobr> | `-c`  | ادامهٔ آخرین نشست                                                          |
| <nobr><code>{"--session"}</code></nobr>  | `-s`  | شناسهٔ نشست برای ادامه                                                     |
| <nobr><code>{"--fork"}</code></nobr>     |       | انشعاب نشست هنگام ادامه (با `--continue` یا `--session` استفاده شود)       |
| <nobr><code>{"--share"}</code></nobr>    |       | اشتراک‌گذاری نشست                                                          |
| <nobr><code>{"--model"}</code></nobr>    | `-m`  | مدل برای استفاده به فرم provider/model                                     |
| <nobr><code>{"--agent"}</code></nobr>    |       | عامل برای استفاده                                                         |
| <nobr><code>{"--file"}</code></nobr>     | `-f`  | پرونده(ها) برای پیوست به پیام                                              |
| <nobr><code>{"--format"}</code></nobr>   |       | فرمت: default (قالب‌بندی‌شده) یا json (رویدادهای خام JSON)                |
| <nobr><code>{"--title"}</code></nobr>    |       | عنوان برای نشست (اگر مقداری داده نشود از درخواست کوتاه‌شده استفاده می‌کند) |
| <nobr><code>{"--attach"}</code></nobr>   |       | اتصال به یک سرور opencode در حال اجرا (مثل http://localhost:4096)          |
| <nobr><code>{"--password"}</code></nobr> | `-p`  | گذرواژهٔ احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_PASSWORD`)             |
| <nobr><code>{"--username"}</code></nobr> | `-u`  | نام کاربری احراز هویت پایه (پیش‌فرض `OPENCODE_SERVER_USERNAME` یا `opencode`) |
| <nobr><code>{"--dir"}</code></nobr>      |       | فهرست برای اجرا، یا مسیر روی سرور از راه دور هنگام اتصال                   |
| <nobr><code>{"--port"}</code></nobr>     |       | درگاه برای سرور محلی (پیش‌فرض درگاه تصادفی)                                |
| <nobr><code>{"--variant"}</code></nobr>  |       | گونهٔ مدل (تلاش استنتاجی ویژهٔ ارائه‌دهنده)                               |
| <nobr><code>{"--thinking"}</code></nobr> |       | نمایش بلوک‌های تفکر                                                       |
| <nobr><code>{"--auto"}</code></nobr>     |       | تأیید خودکار مجوزهایی که صراحتاً رد نشده‌اند                              |

### serve

یک سرور بی‌سر OpenCode برای دسترسی API شروع کنید. مستندات [سرور](/docs/server) را برای رابط کامل HTTP بررسی کنید.

```bash
opencode serve
```

این یک سرور HTTP راه‌اندازی می‌کند که دسترسی API به قابلیت‌های opencode بدون رابط TUI فراهم می‌کند. `OPENCODE_SERVER_PASSWORD` را تنظیم کنید تا احراز هویت پایهٔ HTTP فعال شود (نام کاربری پیش‌فرض `opencode` است).

#### Flags

| Flag                                        | Description                                |
| ------------------------------------------- | ------------------------------------------ |
| <nobr><code>{"--port"}</code></nobr>        | درگاه برای گوش دادن                        |
| <nobr><code>{"--hostname"}</code></nobr>    | نام میزبان برای گوش دادن                   |
| <nobr><code>{"--mdns"}</code></nobr>        | فعال کردن کشف mDNS                         |
| <nobr><code>{"--mdns-domain"}</code></nobr> | نام دامنهٔ سفارشی mDNS                     |
| <nobr><code>{"--cors"}</code></nobr>        | مبدأ(های) مرورگر اضافی برای مجاز کردن CORS |

### upgrade


```bash
opencode upgrade
```

```bash
opencode upgrade v0.1.48
```
