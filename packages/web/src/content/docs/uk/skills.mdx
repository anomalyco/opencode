---
title: "Навички агентів"
description: "Визначення повторюваної поведінки через SKILL.md"
---

Навички агентів дозволяють OpenCode знаходити повторювані інструкції у вашому репозиторії або домашньому каталозі.
Навички завантажуються на вимогу через вбудований інструмент `skill` — агенти бачать доступні навички та можуть завантажити повний вміст, коли це потрібно.

---

## Розміщення файлів

Створіть одну теку на назву навички та розмістіть у ній файл `SKILL.md`.
OpenCode шукає в таких місцях:

- Конфігурація проєкту: `.opencode/skills/<name>/SKILL.md`
- Глобальна конфігурація: `~/.config/opencode/skills/<name>/SKILL.md`
- Сумісність з Claude (проєкт): `.claude/skills/<name>/SKILL.md`
- Сумісність з Claude (глобально): `~/.claude/skills/<name>/SKILL.md`
- Сумісність з агентами (проєкт): `.agents/skills/<name>/SKILL.md`
- Сумісність з агентами (глобально): `~/.agents/skills/<name>/SKILL.md`

---

## Розуміння виявлення

Для шляхів у межах проєкту OpenCode піднімається від поточного робочого каталогу, доки не досягне git-робочого дерева.
Він завантажує всі відповідні `skills/*/SKILL.md` у `.opencode/` та всі відповідні `.claude/skills/*/SKILL.md` або `.agents/skills/*/SKILL.md` уздовж шляху.

Глобальні визначення також завантажуються з `~/.config/opencode/skills/*/SKILL.md`, `~/.claude/skills/*/SKILL.md` та `~/.agents/skills/*/SKILL.md`.

---

## Написання frontmatter

Кожен файл `SKILL.md` має починатися з YAML frontmatter.
Розпізнаються лише такі поля:

- `name` (обов'язкове)
- `description` (обов'язкове)
- `license` (необов'язкове)
- `compatibility` (необов'язкове)
- `metadata` (необов'язкове, мапа ключ-значення)

Невідомі поля frontmatter ігноруються.

---

## Валідація назв

`name` має відповідати таким вимогам:

- Бути довжиною 1–64 символи
- Бути в нижньому регістрі, алфавітно-цифровим, з одинарними дефісами
- Не починатися або закінчуватися на `-`
- Не містити подвійних `--`
- Відповідати назві теки, що містить `SKILL.md`

Еквівалентний регулярний вираз:

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

---

## Дотримання правил довжини

`description` має бути довжиною 1–1024 символи.
Зробіть опис достатньо конкретним, щоб агент міг правильно обрати навичку.

---

## Приклад використання

Створіть `.opencode/skills/git-release/SKILL.md` так:

```markdown
---
name: git-release
description: Створення узгоджених релізів та changelog
license: MIT
compatibility: opencode
metadata:
  audience: maintainers
  workflow: github
---

## Що я роблю

- Складаю нотатки релізу з об'єднаних PR
- Пропоную підвищення версії
- Надаю команду `gh release create` для копіювання

## Коли мене використовувати

Використовуйте це при підготовці тегованого релізу.
Ставте уточнювальні запитання, якщо цільова схема версіонування незрозуміла.
```

## Опис інструменту

OpenCode перелічує доступні навички в описі інструменту `skill`.
Кожен запис включає назву навички та опис:

```xml
<available_skills>
  <skill>
    <name>git-release</name>
    <description>Створення узгоджених релізів та changelog</description>
  </skill>
</available_skills>
```

Агент завантажує навичку викликом інструменту:

```
skill({ name: "git-release" })
```

## Налаштування дозволів

Керуйте доступом агентів до навичок за допомогою дозволів на основі шаблонів у `opencode.json`:

```json
{
  "permission": {
    "skill": {
      "*": "allow",
      "pr-review": "allow",
      "internal-*": "deny",
      "experimental-*": "ask"
    }
  }
}
```

| Дозвіл    | Поведінка                                    |
| --------- | -------------------------------------------- |
| `allow`   | Навичка завантажується негайно               |
| `deny`    | Навичка прихована від агента, доступ заборонено |
| `ask`     | Користувачу пропонується підтвердити завантаження |

Шаблони підтримують символи підстановки: `internal-*` відповідає `internal-docs`, `internal-tools` тощо.

---

## Перевизначення для окремих агентів

Надавайте окремим агентам інші дозволи, ніж глобальні.

**Для користувацьких агентів** (у frontmatter агента):

```yaml
---
permission:
  skill:
    "documents-*": "allow"
---
```

**Для вбудованих агентів** (у `opencode.json`):

```json
{
  "agent": {
    "plan": {
      "permission": {
        "skill": {
          "internal-*": "allow"
        }
      }
    }
  }
}
```

---

## Вимкнення інструменту skill

Повністю вимкніть навички для агентів, які не повинні їх використовувати:

**Для користувацьких агентів**:

```yaml
---
tools:
  skill: false
---
```

**Для вбудованих агентів**:

```json
{
  "agent": {
    "plan": {
      "tools": {
        "skill": false
      }
    }
  }
}
```

Коли вимкнено, розділ `<available_skills>` повністю опускається.

---

## Вирішення проблем із завантаженням

Якщо навичка не відображається:

1. Переконайтеся, що `SKILL.md` написано великими літерами
2. Перевірте, що frontmatter містить `name` та `description`
3. Переконайтеся, що назви навичок унікальні в усіх місцях
4. Перевірте дозволи — навички з `deny` приховані від агентів
