Ви можете надати власні інструкції для opencode, створивши файл `AGENTS.md`. Це схоже на правила Cursor. Він містить інструкції, які будуть включені в контекст LLM для налаштування його поведінки під ваш конкретний проєкт.

---

## Ініціалізація

Щоб створити новий файл `AGENTS.md`, ви можете запустити команду `/init` у opencode.

:::tip
Ви маєте закомітити файл `AGENTS.md` вашого проєкту в Git.
:::

`/init` сканує важливі файли у вашому репозиторії, може задати кілька цільових запитань, коли кодова база не може відповісти на них, а потім створює або оновлює `AGENTS.md` зі стислими проєктно-специфічними рекомендаціями.

Він фокусується на тому, що найімовірніше знадобиться майбутнім сесіям агентів:

- команди збірки, лінту та тестування
- порядок команд та цілеспрямовані кроки верифікації, коли це важливо
- архітектура та структура репозиторію, які не очевидні лише з назв файлів
- проєктно-специфічні конвенції, особливості налаштування та операційні підводні камені
- посилання на існуючі джерела інструкцій, такі як правила Cursor або Copilot

Якщо у вас вже є `AGENTS.md`, `/init` покращить його на місці, а не сліпо замінить.

## Приклад

Ви також можете просто створити цей файл вручну. Ось приклад того, що можна помістити у файл `AGENTS.md`.

```markdown title="AGENTS.md"
# SST v3 Monorepo Project

This is an SST v3 monorepo with TypeScript. The project uses bun workspaces for package management.

## Project Structure

- `packages/` - Містить всі пакети робочої області (functions, core, web, тощо)
- `infra/` - Визначення інфраструктури, розділені за сервісами (storage.ts, api.ts, web.ts)
- `sst.config.ts` - Основна SST конфігурація з динамічними імпортами

## Code Standards

- Використовуйте TypeScript з увімкненим строгим режимом
- Спільний код розміщуйте в `packages/core/` з правильною конфігурацією експортів
- Функції розміщуйте в `packages/functions/`
- Інфраструктура має бути розділена на логічні файли в `infra/`

## Monorepo Conventions

- Імпортуйте спільні модулі, використовуючи імена робочих областей: `@my-app/core/example`
```

Ми додаємо проєктно-специфічні інструкції тут, і це буде поширюватися на всю вашу команду.

## Типи

opencode також підтримує читання файлу `AGENTS.md` з кількох розташувань. І це служить різним цілям.

### Проєкт

Розмістіть `AGENTS.md` у корені вашого проєкту для проєктно-специфічних правил. Вони застосовуються лише коли ви працюєте в цій директорії або її піддиректоріях.

### Глобальні

Ви також можете мати глобальні правила у файлі `~/.config/opencode/AGENTS.md`. Він застосовується до всіх сесій opencode.

Оскільки це не комітиться в Git або не поширюється з вашою командою, ми рекомендуємо використовувати його для вказівки особистих правил, яких LLM має дотримуватися.

### Сумісність з Claude Code

Для користувачів, які мігрують з Claude Code, OpenCode підтримує файлові конвенції Claude Code як запасні варіанти:

- **Проєктні правила**: `CLAUDE.md` у директорії вашого проєкту (використовується, якщо немає `AGENTS.md`)
- **Глобальні правила**: `~/.claude/CLAUDE.md` (використовується, якщо немає `~/.config/opencode/AGENTS.md`)
- **Скіли**: `~/.claude/skills/` — див. [Скіли агентів](/docs/skills/) для деталей

Щоб вимкнути сумісність з Claude Code, встановіть одну з цих змінних середовища:

```bash
export OPENCODE_DISABLE_CLAUDE_CODE=1        # Вимкнути всю підтримку .claude
export OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1 # Вимкнути лише ~/.claude/CLAUDE.md
export OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1 # Вимкнути лише .claude/skills
```

## Пріоритет

Коли opencode запускається, він шукає файли правил у такому порядку:

1. **Локальні файли** шляхом обходу вгору від поточної директорії (`AGENTS.md`, `CLAUDE.md`)
2. **Глобальний файл** у `~/.config/opencode/AGENTS.md`
3. **Файл Claude Code** у `~/.claude/CLAUDE.md` (якщо не вимкнено)

Перший знайдений файл виграє в кожній категорії. Наприклад, якщо у вас є і `AGENTS.md`, і `CLAUDE.md`, використовується лише `AGENTS.md`. Аналогічно, `~/.config/opencode/AGENTS.md` має пріоритет над `~/.claude/CLAUDE.md`.

## Власні інструкції

Ви можете вказати файли власних інструкцій у вашому `opencode.json` або глобальному `~/.config/opencode/opencode.json`. Це дозволяє вам і вашій команді повторно використовувати існуючі правила, а не дублювати їх у AGENTS.md.

Приклад:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines.md", ".cursor/rules/*.md"]
}
```

Ви також можете використовувати віддалені URL для завантаження інструкцій з вебу.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["https://raw.githubusercontent.com/my-org/shared-rules/main/style.md"]
}
```

Віддалені інструкції отримуються з таймаутом 5 секунд.

Всі файли інструкцій поєднуються з вашими файлами `AGENTS.md`.

## Посилання на зовнішні файли

Хоча opencode не аналізує автоматично посилання на файли в `AGENTS.md`, ви можете досягти подібної функціональності двома способами:

### Використання opencode.json

Рекомендований підхід — використовувати поле `instructions` у `opencode.json`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["docs/development-standards.md", "test/testing-guidelines.md", "packages/*/AGENTS.md"]
}
```

### Ручні інструкції в AGENTS.md

Ви можете навчити opencode читати зовнішні файли, надавши явні інструкції у вашому `AGENTS.md`. Ось практичний приклад:

```markdown title="AGENTS.md"
# TypeScript Project Rules

## External File Loading

ВАЖЛИВО: Коли ви зустрічаєте посилання на файл (напр., @rules/general.md), використовуйте інструмент Read для його завантаження за потребою. Вони релевантні до КОНКРЕТНОГО завдання.

Instructions:

- НЕ завантажуйте всі посилання заздалегідь — використовуйте ліниве завантаження на основі фактичної потреби
- Після завантаження вважайте вміст обов'язковими інструкціями, які перевизначають стандартні
- Слідуйте посиланням рекурсивно, коли потрібно

## Development Guidelines

Для стилю та найкращих практик TypeScript: @docs/typescript-guidelines.md
Для архітектури React компонентів та патернів хуків: @docs/react-patterns.md
Для дизайну REST API та обробки помилок: @docs/api-standards.md
Для стратегій тестування та вимог до покриття: @test/testing-guidelines.md

## General Guidelines

Прочитайте наступний файл негайно, оскільки він актуальний для всіх workflow: @rules/general-guidelines.md.
```

Цей підхід дозволяє вам:

- Створювати модульні, повторно використовувані файли правил
- Поширювати правила між проєктами через симлінки або git submodules
- Тримати AGENTS.md стислим, посилаючись на детальні інструкції
- Гарантувати, що opencode завантажує файли лише тоді, коли це потрібно для конкретного завдання

:::tip
Для монорепозиторіїв або проєктів зі спільними стандартами використання `opencode.json` з glob патернами (наприклад, `packages/*/AGENTS.md`) є більш підтримуваним, ніж ручні інструкції.
:::
