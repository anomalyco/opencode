---
title: Дозволи
description: Контролюйте, які дії вимагають схвалення для виконання.
---

OpenCode використовує конфігурацію `permission`, щоб вирішити, чи має певна дія виконуватися автоматично, запитувати вас або бути заблокованою.

Починаючи з `v1.1.1`, застаріла булева конфігурація `tools` є нерекомендованою та була об'єднана в `permission`. Стара конфігурація `tools` все ще підтримується для зворотної сумісності.

---

## Дії

Кожне правило дозволу вирішується одним із:

- `"allow"` — виконувати без схвалення
- `"ask"` — запитувати схвалення
- `"deny"` — блокувати дію

---

## Автоматичний режим

Запустіть OpenCode з `--auto`, щоб автоматично схвалювати запити дозволів, які не заборонені явно.

```bash
opencode --auto
```

Ви також можете використовувати автоматичний режим з [`opencode run`](/docs/cli#run).

```bash
opencode run --auto "Refactor this module"
```

Явні правила `"deny"` все ще застосовуються. Автоматичний режим змінює лише запити, які інакше запитували б схвалення.

У TUI відкрийте палітру команд та виберіть **Enable auto-approve permissions** або **Disable auto-approve permissions**, щоб змінити режим. Коли автоматичний режим активний, промпт відображає приглушений індикатор `auto` поруч з поточним агентом.

---

## Конфігурація

Ви можете встановлювати дозволи глобально (за допомогою `*`) та перевизначати конкретні інструменти.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "*": "ask",
    "bash": "allow",
    "edit": "deny"
  }
}
```

Ви також можете встановити всі дозволи одночасно:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": "allow"
}
```

## Гранульовані правила (синтаксис об'єкта)

Для більшості дозволів ви можете використовувати об'єкт для застосування різних дій на основі введених даних інструмента.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "npm *": "allow",
      "rm *": "deny",
      "grep *": "allow"
    },
    "edit": {
      "*": "deny",
      "packages/web/src/content/docs/*.mdx": "allow"
    }
  }
}
```

Правила оцінюються за збігом патерну, причому **останнє співпадаюче правило виграє**. Поширеним патерном є розміщення узагальнюючого правила `"*"" першим, а більш специфічних правил після нього.

### Wildcards

Патерни дозволів використовують просте зіставлення wildcard:

- `*` відповідає нулю або більше будь-яких символів
- `?` відповідає рівно одному символу
- Всі інші символи збігаються буквально

### Розгортання домашньої директорії

Ви можете використовувати `~` або `$HOME` на початку патерну для посилання на вашу домашню директорію. Це особливо корисно для правил [`external_directory`](#зовнішні-директорії).

- `~/projects/*` -> `/Users/username/projects/*`
- `$HOME/projects/*` -> `/Users/username/projects/*`
- `~` -> `/Users/username`

### Зовнішні директорії

Використовуйте `external_directory`, щоб дозволити виклики інструментів, які торкаються шляхів за межами робочої директорії, де було запущено OpenCode. Це застосовується до будь-якого інструмента, який приймає шлях як вхідні дані (наприклад, `read`, `edit`, `glob`, `grep` та багато `bash` команд).

Розгортання домашньої директорії (наприклад, `~/...`) впливає лише на те, як написаний патерн. Воно не робить зовнішній шлях частиною поточної робочої області, тому шляхи за межами робочої директорії все одно повинні бути дозволені через `external_directory`.

Наприклад, це дозволяє доступ до всього в `~/projects/personal/`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    }
  }
}
```

Будь-яка дозволена тут директорія успадковує ті самі стандартні налаштування, що й поточна робоча область. Оскільки [`read` за замовчуванням має значення `allow`](#defaults), читання також дозволено для записів у `external_directory`, якщо не перевизначено. Додайте явні правила, коли інструмент має бути обмежений у цих шляхах, наприклад, блокування редагувань при збереженні читання:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    },
    "edit": {
      "~/projects/personal/**": "deny"
    }
  }
}
```

Тримайте список зосередженим на довірених шляхах і додавайте додаткові правила дозволу або заборони за потреби для інших інструментів (наприклад, `bash`).

## Доступні дозволи

Дозволи OpenCode ключуються за назвою інструмента, плюс кілька запобіжників:

- `read` — читання файлу (збігається з шляхом файлу)
- `edit` — всі модифікації файлів (охоплює `edit`, `write`, `patch`)
- `glob` — пошук файлів (збігається з glob патерном)
- `grep` — пошук вмісту (збігається з regex патерном)
- `bash` — запуск команд оболонки (збігається з розібраними командами, як `git status --porcelain`)
- `task` — запуск сабагентів (збігається з типом сабагента)
- `skill` — завантаження скіла (збігається з назвою скіла)
- `lsp` — запуск LSP запитів (наразі не гранульований)
- `question` — задавання питань користувачеві під час виконання
- `webfetch` — отримання URL (збігається з URL)
- `websearch` — веб-пошук (збігається з запитом)
- `external_directory` — спрацьовує, коли інструмент торкається шляхів за межами робочої директорії проєкту
- `doom_loop` — спрацьовує, коли один і той самий виклик інструмента повторюється 3 рази з однаковими вхідними даними

## Значення за замовчуванням

Якщо ви нічого не вказуєте, OpenCode починає з дозвільних значень за замовчуванням:

- Більшість дозволів за замовчуванням мають значення `"allow"`.
- `doom_loop` та `external_directory` за замовчуванням мають значення `"ask"`.
- `read` має значення `"allow"`, але файли `.env` заборонені за замовчуванням:

```json title="opencode.json"
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.env.example": "allow"
    }
  }
}
```

---

## Що робить "Ask"

Коли OpenCode запитує схвалення, інтерфейс пропонує три результати:

- `once` — схвалити лише цей запит
- `always` — схвалювати майбутні запити, що відповідають запропонованим патернам (до кінця поточної сесії OpenCode)
- `reject` — відхилити запит

Набір патернів, які `always` схвалить, надається інструментом (наприклад, схвалення bash зазвичай додає до білого списку безпечний префікс команди, як `git status*`).

## Агенти

Ви можете перевизначати дозволи для кожного агента. Дозволи агента об'єднуються з глобальною конфігурацією, і правила агента мають пріоритет. [Дізнатися більше](/docs/agents#permissions) про дозволи агентів.

:::note
Зверніться до розділу [Гранульовані правила (синтаксис об'єкта)](#гранульовані-правила-синтаксис-обєкта) вище для більш детальних прикладів зіставлення патернів.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git commit *": "deny",
      "git push *": "deny",
      "grep *": "allow"
    }
  },
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git *": "allow",
          "git commit *": "ask",
          "git push *": "deny",
          "grep *": "allow"
        }
      }
    }
  }
}
```

Ви також можете налаштовувати дозволи агентів у Markdown:

```markdown title="~/.config/opencode/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash: ask
  webfetch: deny
---

Only analyze code and suggest changes.
```

:::tip
Використовуйте зіставлення патернів для команд з аргументами. `"grep *"` дозволяє `grep pattern file.txt`, тоді як `"grep"` самостійно заблокує його. Команди на кшталт `git status` працюють для поведінки за замовчуванням, але вимагають явного дозволу (наприклад, `"git status *"`), коли передаються аргументи.
:::
