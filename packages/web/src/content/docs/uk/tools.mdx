---
title: Інструменти
description: Керуйте інструментами, які може використовувати LLM.
---

Інструменти дозволяють LLM виконувати дії у вашій кодовій базі. OpenCode постачається з набором вбудованих інструментів, але ви можете розширити його [користувацькими інструментами](/docs/custom-tools) або [MCP серверами](/docs/mcp-servers).

За замовчуванням всі інструменти **увімкнено** і не потребують дозволу для виконання. Ви можете контролювати поведінку інструментів через [дозволи](/docs/permissions).

---

## Налаштування

Використовуйте поле `permission` для контролю поведінки інструментів. Ви можете дозволити, заборонити або вимагати схвалення для кожного інструмента.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny",
    "bash": "ask",
    "webfetch": "allow"
  }
}
```

Ви також можете використовувати wildcards для контролю кількох інструментів одночасно. Наприклад, щоб вимагати схвалення для всіх інструментів з MCP сервера:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "mymcp_*": "ask"
  }
}
```

[Дізнатися більше](/docs/permissions) про налаштування дозволів.

---

## Вбудовані

Ось всі вбудовані інструменти, доступні в OpenCode.

---

### bash

Виконуйте команди оболонки у вашому проєктному середовищі.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": "allow"
  }
}
```

Цей інструмент дозволяє LLM запускати команди терміналу, такі як `npm install`, `git status` або будь-які інші команди оболонки.

---

### edit

Змінюйте існуючі файли за допомогою точних замін рядків.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

Цей інструмент виконує точне редагування файлів шляхом заміни точних збігів тексту. Це основний спосіб, яким LLM змінює код.

---

### write

Створюйте нові файли або перезаписуйте існуючі.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

Використовуйте це, щоб дозволити LLM створювати нові файли. Він перезапише існуючі файли, якщо вони вже існують.

:::note
Інструмент `write` контролюється дозволом `edit`, який охоплює всі модифікації файлів (`edit`, `write`, `apply_patch`).
:::

---

### read

Читайте вміст файлів з вашої кодової бази.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "read": "allow"
  }
}
```

Цей інструмент читає файли та повертає їхній вміст. Він підтримує читання конкретних діапазонів рядків для великих файлів.

---

### grep

Шукайте вміст файлів за допомогою регулярних виразів.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "grep": "allow"
  }
}
```

Швидкий пошук вмісту у вашій кодовій базі. Підтримує повний синтаксис регулярних виразів та фільтрацію за патернами файлів.

---

### glob

Знаходьте файли за збігом патерну.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "glob": "allow"
  }
}
```

Пошук файлів за допомогою glob патернів, таких як `**/*.js` або `src/**/*.ts`. Повертає відсортовані за часом модифікації шляхи відповідних файлів.

---

### lsp (експериментальний)

Взаємодійте з налаштованими LSP серверами для отримання функцій інтелекту коду, таких як визначення, посилання, інформація при наведенні та ієрархія викликів.

:::note
Цей інструмент доступний лише коли `OPENCODE_EXPERIMENTAL_LSP_TOOL=true` (або `OPENCODE_EXPERIMENTAL=true`).
:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "lsp": "allow"
  }
}
```

Підтримувані операції: `goToDefinition`, `findReferences`, `hover`, `documentSymbol`, `workspaceSymbol`, `goToImplementation`, `prepareCallHierarchy`, `incomingCalls` та `outgoingCalls`.

Щоб налаштувати, які LSP сервери доступні для вашого проєкту, див. [LSP сервери](/docs/lsp).

---

### apply_patch

Застосовуйте патчі до файлів.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

Цей інструмент застосовує файли патчів до вашої кодової бази. Корисно для застосування diff та патчів з різних джерел.

При роботі з хуками `tool.execute.before` або `tool.execute.after` перевіряйте `input.tool === "apply_patch"` (не `"patch"`).

`apply_patch` використовує `output.args.patchText` замість `output.args.filePath`. Шляхи вбудовані в рядки маркерів у `patchText` і є відносними до кореня проєкту (наприклад: `*** Add File: src/new-file.ts`, `*** Update File: src/existing.ts`, `*** Move to: src/renamed.ts`, `*** Delete File: src/obsolete.ts`).

:::note
Інструмент `apply_patch` контролюється дозволом `edit`, який охоплює всі модифікації файлів (`edit`, `write`, `apply_patch`).
:::

---

### skill

Завантажте [скилл](/docs/skills) (файл `SKILL.md`) та поверніть його вміст у розмову.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "skill": "allow"
  }
}
```

---

### todowrite

Керуйте списками завдань під час сесій кодування.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "todowrite": "allow"
  }
}
```

Створює та оновлює списки завдань для відстеження прогресу під час складних операцій. LLM використовує це для організації багатокрокових завдань.

:::note
Цей інструмент вимкнено для сабагентів за замовчуванням, але ви можете ввімкнути його вручну. [Дізнатися більше](/docs/agents/#permissions)
:::

---

### webfetch

Отримуйте веб-вміст.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "webfetch": "allow"
  }
}
```

Дозволяє LLM отримувати та читати веб-сторінки. Корисно для пошуку документації або дослідження онлайн-ресурсів.

---

### websearch

Шукайте інформацію в інтернеті.

:::note
Цей інструмент доступний лише при використанні провайдера OpenCode або коли змінна середовища `OPENCODE_ENABLE_EXA` встановлена в будь-яке правдиве значення (напр., `true` або `1`).

Щоб увімкнути при запуску OpenCode:

```bash
OPENCODE_ENABLE_EXA=1 opencode
```

:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "websearch": "allow"
  }
}
```

Виконує веб-пошук за допомогою Exa AI для пошуку релевантної онлайн-інформації. Корисно для дослідження тем, пошуку поточних подій або збору інформації, що виходить за межі дати навчання моделі.

API-ключ не потрібен — інструмент підключається безпосередньо до хостингового MCP сервісу Exa AI без автентифікації.

:::tip
Використовуйте `websearch`, коли потрібно знайти інформацію (пошук), і `webfetch`, коли потрібно отримати вміст з конкретної URL-адреси (отримання).
:::

---

### question

Задавайте користувачеві питання під час виконання.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "question": "allow"
  }
}
```

Цей інструмент дозволяє LLM задавати користувачеві питання під час виконання завдання. Він корисний для:

- Збору вподобань або вимог користувача
- Уточнення неоднозначних інструкцій
- Отримання рішень щодо варіантів реалізації
- Пропозиції вибору щодо напрямку роботи

Кожне питання включає заголовок, текст питання та список опцій. Користувачі можуть вибрати з наданих опцій або ввести власну відповідь. Коли є кілька питань, користувачі можуть перемикатися між ними перед відправкою всіх відповідей.

## Користувацькі інструменти

Користувацькі інструменти дозволяють визначати власні функції, які може викликати LLM. Вони визначаються у вашому файлі конфігурації та можуть виконувати довільний код.

[Дізнатися більше](/docs/custom-tools) про створення користувацьких інструментів.

---

## MCP сервери

MCP (Model Context Protocol) сервери дозволяють інтегрувати зовнішні інструменти та сервіси. Це включає доступ до баз даних, API інтеграції та сторонні сервіси.

[Дізнатися більше](/docs/mcp-servers) про налаштування MCP серверів.

---

## Внутрішні деталі

Внутрішньо такі інструменти, як `grep` та `glob`, використовують [ripgrep](https://github.com/BurntSushi/ripgrep) під капотом. За замовчуванням ripgrep поважає патерни `.gitignore`, що означає, що файли та директорії, перелічені у вашому `.gitignore`, будуть виключені з пошуку та списків.

---

### Патерни ігнорування

Щоб включити файли, які зазвичай ігноруються, створіть файл `.ignore` у корені вашого проєкту. Цей файл може явно дозволяти певні шляхи.

```text title=".ignore"
!node_modules/
!dist/
!build/
```

Наприклад, цей файл `.ignore` дозволяє ripgrep шукати всередині директорій `node_modules/`, `dist/` та `build/`, навіть якщо вони перелічені в `.gitignore`.
