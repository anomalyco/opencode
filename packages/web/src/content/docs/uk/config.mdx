Ви можете налаштовувати OpenCode за допомогою JSON-файлу конфігурації.

---

## Формат

OpenCode підтримує формати **JSON** та **JSONC** (JSON з коментарями).

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
  "autoupdate": true,
  "server": {
    "port": 4096,
  },
}
```

---

## Розташування

Ви можете розмістити конфігурацію в кількох різних місцях, і вони мають
різний порядок пріоритету.

:::note
Файли конфігурації **об'єднуються**, а не замінюються.
:::

Файли конфігурації об'єднуються, а не замінюються. Налаштування з наступних розташувань конфігурації комбінуються. Пізніші конфігурації перевизначають попередні лише для конфліктуючих ключів. Неконфліктні налаштування з усіх конфігурацій зберігаються.

Наприклад, якщо ваша глобальна конфігурація встановлює `autoupdate: true`, а конфігурація проєкту встановлює `model: "anthropic/claude-sonnet-4-5"`, остаточна конфігурація включатиме обидва налаштування.

---

### Порядок пріоритету

Джерела конфігурації завантажуються в такому порядку (пізніші джерела перевизначають попередні):

1. **Віддалена конфігурація** (з `.well-known/opencode`) — організаційні стандарти
2. **Глобальна конфігурація** (`~/.config/opencode/opencode.json`) — вподобання користувача
3. **Користувацька конфігурація** (змінна середовища `OPENCODE_CONFIG`) — користувацькі перевизначення
4. **Конфігурація проєкту** (`opencode.json` у проєкті) — налаштування для конкретного проєкту
5. **Каталоги `.opencode`** — агенти, команди, плагіни
6. **Вбудована конфігурація** (змінна середовища `OPENCODE_CONFIG_CONTENT`) — перевизначення під час виконання
7. **Керовані файли конфігурації** (`/Library/Application Support/opencode/` на macOS) — контроль адміністратора
8. **Керовані налаштування macOS** (`.mobileconfig` через MDM) — найвищий пріоритет, не можуть бути перевизначені користувачем

Це означає, що конфігурації проєктів можуть перевизначати глобальні стандарти, а глобальні конфігурації можуть перевизначати віддалені організаційні стандарти. Керовані налаштування перевизначають все.

:::note
Каталоги `.opencode` та `~/.config/opencode` використовують **назви в множині** для підкаталогів: `agents/`, `commands/`, `modes/`, `plugins/`, `skills/`, `tools/` та `themes/`. Назви в однині (наприклад, `agent/`) також підтримуються для зворотної сумісності.
:::

### Віддалена

Організації можуть надавати стандартну конфігурацію через ендпоїнт `.well-known/opencode`. Вона отримується автоматично, коли ви автентифікуєтеся з провайдером, який це підтримує.

Віддалена конфігурація завантажується першою, слугуючи базовим шаром. Всі інші джерела конфігурації (глобальна, проєктна) можуть перевизначати ці стандарти.

Наприклад, якщо ваша організація надає MCP-сервери, які вимкнені за замовчуванням:

```json title="Віддалена конфігурація з .well-known/opencode"
{
  "mcp": {
    "jira": {
      "type": "remote",
      "url": "https://jira.example.com/mcp",
      "enabled": false
    }
  }
}
```

Ви можете ввімкнути конкретні сервери у вашій локальній конфігурації:

```json title="opencode.json"
{
  "mcp": {
    "jira": {
      "type": "remote",
      "url": "https://jira.example.com/mcp",
      "enabled": true
    }
  }
}
```

---

### Глобальна

Розмістіть вашу глобальну конфігурацію OpenCode у `~/.config/opencode/opencode.json`. Використовуйте глобальну конфігурацію для загальнокористувацьких налаштувань сервера/середовища виконання, таких як провайдери, моделі та дозволи.

Для налаштувань, специфічних для TUI, використовуйте `~/.config/opencode/tui.json`.

Глобальна конфігурація перевизначає віддалені організаційні стандарти.

---

### На проєкт

Додайте `opencode.json` у корінь вашого проєкту. Конфігурація проєкту має найвищий пріоритет серед стандартних файлів конфігурації — вона перевизначає як глобальну, так і віддалену конфігурації.

Для налаштувань TUI, специфічних для проєкту, додайте `tui.json` поруч.

:::tip
Розміщуйте конфігурацію, специфічну для проєкту, в корені вашого проєкту.
:::

Коли OpenCode запускається, він спочатку шукає файл конфігурації в поточному каталозі, потім переходить до найближчого Git-каталогу.

Це також безпечно для додавання до Git і використовує ту саму схему, що й глобальна.

---

### Користувацький шлях

Вкажіть користувацький шлях до файлу конфігурації за допомогою змінної середовища `OPENCODE_CONFIG`.

```bash
export OPENCODE_CONFIG=/path/to/my/custom-config.json
opencode run "Hello world"
```

Користувацька конфігурація завантажується між глобальною та проєктною конфігураціями в порядку пріоритету.

---

### Користувацький каталог

Вкажіть користувацький каталог конфігурації за допомогою змінної
середовища `OPENCODE_CONFIG_DIR`. Цей каталог буде пошуканий на предмет агентів, команд,
режимів та плагінів так само, як і стандартний каталог `.opencode`, і повинен
дотримуватися тієї ж структури.

```bash
export OPENCODE_CONFIG_DIR=/path/to/my/config-directory
opencode run "Hello world"
```

Користувацький каталог завантажується після глобальної конфігурації та каталогів `.opencode`, тому він **може перевизначити** їхні налаштування.

---

### Керовані налаштування

Організації можуть застосовувати конфігурацію, яку користувачі не можуть перевизначити. Керовані налаштування завантажуються на найвищому рівні пріоритету.

#### Файлові

Помістіть файл `opencode.json` або `opencode.jsonc` у системний керований каталог конфігурації:

| Платформа | Шлях                                       |
| --------- | ------------------------------------------ |
| macOS     | `/Library/Application Support/opencode/`   |
| Linux     | `/etc/opencode/`                           |
| Windows   | `%ProgramData%\opencode`                   |

Ці каталоги вимагають доступу адміністратора/root для запису, тому користувачі не можуть їх змінювати.

#### Керовані налаштування macOS

На macOS OpenCode читає керовані налаштування з домену налаштувань `ai.opencode.managed`. Розгорніть `.mobileconfig` через MDM (Jamf, Kandji, FleetDM), і налаштування застосовуються автоматично.

OpenCode перевіряє ці шляхи:

1. `/Library/Managed Preferences/<user>/ai.opencode.managed.plist`
2. `/Library/Managed Preferences/ai.opencode.managed.plist`

Ключі plist відображаються безпосередньо на поля `opencode.json`. Метадані MDM (`PayloadUUID`, `PayloadType` тощо) видаляються автоматично.

**Створення `.mobileconfig`**

Використовуйте `ai.opencode.managed` як PayloadType. Ключі конфігурації OpenCode йдуть безпосередньо в словник payload:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>PayloadContent</key>
  <array>
    <dict>
      <key>PayloadType</key>
      <string>ai.opencode.managed</string>
      <key>PayloadIdentifier</key>
      <string>com.example.opencode.config</string>
      <key>PayloadUUID</key>
      <string>GENERATE-YOUR-OWN-UUID</string>
      <key>PayloadVersion</key>
      <integer>1</integer>
      <key>share</key>
      <string>disabled</string>
      <key>server</key>
      <dict>
        <key>hostname</key>
        <string>127.0.0.1</string>
      </dict>
      <key>permission</key>
      <dict>
        <key>*</key>
        <string>ask</string>
        <key>bash</key>
        <dict>
          <key>*</key>
          <string>ask</string>
          <key>rm -rf *</key>
          <string>deny</string>
        </dict>
      </dict>
    </dict>
  </array>
  <key>PayloadType</key>
  <string>Configuration</string>
  <key>PayloadIdentifier</key>
  <string>com.example.opencode</string>
  <key>PayloadUUID</key>
  <string>GENERATE-YOUR-OWN-UUID</string>
  <key>PayloadVersion</key>
  <integer>1</integer>
</dict>
</plist>
```

Згенеруйте унікальні UUID за допомогою `uuidgen`. Налаштуйте параметри відповідно до вимог вашої організації.

**Розгортання через MDM**

- **Jamf Pro:** Комп'ютери > Конфігураційні профілі > Завантажити > призначити на цільові пристрої або смарт-групи
- **FleetDM:** Додайте `.mobileconfig` до вашого gitops-репозиторію в `mdm.macos_settings.custom_settings` та виконайте `fleetctl apply`

**Перевірка на пристрої**

Двічі клацніть `.mobileconfig`, щоб встановити локально для тестування (відображається в Системні налаштування > Конфіденційність та безпека > Профілі), потім виконайте:

```bash
opencode debug config
```

Всі ключі керованих налаштувань з'являються в остаточній конфігурації і не можуть бути перевизначені конфігурацією користувача або проєкту.

## Схема

Схема конфігурації сервера/середовища виконання визначена в [**`opencode.ai/config.json`**](https://opencode.ai/config.json).

Конфігурація TUI використовує [**`opencode.ai/tui.json`**](https://opencode.ai/tui.json).

Ваш редактор повинен мати можливість валідувати та автодоповнювати на основі схеми.

---

### TUI

Використовуйте окремий файл `tui.json` (або `tui.jsonc`) для налаштувань, специфічних для TUI.

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "scroll_speed": 3,
  "scroll_acceleration": {
    "enabled": true
  },
  "diff_style": "auto",
  "mouse": true,
  "attention": {
    "enabled": true,
    "notifications": true,
    "sound": true,
    "volume": 0.4
  }
}
```

Використовуйте `OPENCODE_TUI_CONFIG`, щоб вказати на користувацький файл конфігурації TUI.

Встановіть `attention.enabled`, щоб увімкнути сповіщення робочого столу та звуки TUI. Див. [Увага TUI](/docs/tui#attention).

Застарілі ключі `theme`, `keybinds` та `tui` в `opencode.json` є застарілими та автоматично мігруються, коли це можливо.

### Сервер

Ви можете налаштувати параметри сервера для команд `opencode serve` та `opencode web` через опцію `server`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "server": {
    "port": 4096,
    "hostname": "0.0.0.0",
    "mdns": true,
    "mdnsDomain": "myproject.local",
    "cors": ["http://localhost:5173"]
  }
}
```

Доступні параметри:

- `port` — Порт для прослуховування.
- `hostname` — Ім'я хоста для прослуховування. Коли `mdns` увімкнено і ім'я хоста не встановлено, за замовчуванням `0.0.0.0`.
- `mdns` — Увімкнути mDNS виявлення сервісів. Це дозволяє іншим пристроям у мережі виявляти ваш сервер OpenCode.
- `mdnsDomain` — Користувацьке доменне ім'я для mDNS сервісу. За замовчуванням `opencode.local`. Корисно для запуску кількох екземплярів в одній мережі.
- `cors` — Додаткові джерела для дозволу CORS при використанні HTTP-сервера з браузерного клієнта. Значення мають бути повними джерелами (схема + хост + опціональний порт), наприклад, `https://app.example.com`.

[Дізнатися більше про сервер тут](/docs/server).

### Оболонка

Ви можете налаштувати оболонку, яка використовується для інтерактивного термінала, за допомогою опції `shell`. Сумісні оболонки також використовуються для викликів інструментів агента.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "shell": "pwsh"
}
```

Якщо не вказано, OpenCode автоматично виявить та використає розумний стандарт на основі вашої операційної системи (наприклад, `pwsh` або `cmd.exe` на Windows, `/bin/zsh` або `/bin/bash` на macOS/Linux). Ви можете вказати абсолютний шлях або коротку назву.

### Інструменти

Ви можете керувати інструментами, які LLM може використовувати, через опцію `tools`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": false,
    "bash": false
  }
}
```

[Дізнатися більше про інструменти тут](/docs/tools).

### Моделі

Ви можете налаштувати провайдерів та моделі, які ви хочете використовувати у вашій конфігурації OpenCode, через опції `provider`, `model` та `small_model`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {},
  "model": "anthropic/claude-sonnet-4-5",
  "small_model": "anthropic/claude-haiku-4-5"
}
```

Опція `small_model` налаштовує окрему модель для легких завдань, таких як генерація заголовків. За замовчуванням OpenCode намагається використовувати дешевшу модель, якщо вона доступна від вашого провайдера, інакше використовує вашу основну модель.

Параметри провайдера можуть включати `timeout`, `chunkTimeout` та `setCacheKey`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "timeout": 600000,
        "chunkTimeout": 30000,
        "setCacheKey": true
      }
    }
  }
}
```

- `timeout` — Таймаут запиту в мілісекундах (стандартно: 300000). Встановіть `false`, щоб вимкнути.
- `chunkTimeout` — Таймаут у мілісекундах між фрагментами потокової відповіді. Якщо жоден фрагмент не прибуває вчасно, запит переривається.
- `setCacheKey` — Гарантувати, що ключ кешу завжди встановлений для вказаного провайдера.

Ви також можете налаштувати [локальні моделі](/docs/models#local). [Дізнатися більше](/docs/models).

### Політики

Використовуйте опцію `experimental.policies`, щоб дозволити або заборонити дії OpenCode на налаштованих ресурсах. Наразі політики можуть контролювати, які провайдери OpenCode може використовувати.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "openai"
      }
    ]
  }
}
```

[Дізнатися більше про політики тут](/docs/policies).

### Вкладення зображень

OpenCode нормалізує вкладення зображень перед надсиланням їх моделі. За замовчуванням зображення змінюються, коли вони перевищують `2000x2000` пікселів або `5242880` base64 байтів.

Налаштуйте ліміти вкладень зображень за допомогою опції `attachment.image`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "attachment": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880
    }
  }
}
```

- `auto_resize` — Змінювати розмір зображень, що перевищують налаштовані ліміти, перед запитами до провайдера. Встановіть `false`, щоб відхиляти завеликі зображення.
- `max_width` — Максимальна ширина зображення в пікселях перед зміною розміру або відхиленням.
- `max_height` — Максимальна висота зображення в пікселях перед зміною розміру або відхиленням.
- `max_base64_bytes` — Максимальний розмір закодованого зображення. Це розмір корисного навантаження base64, а не оригінальний розмір файлу.

Якщо зображення все ще не підходить після зміни розміру, OpenCode пропускає завеликі зображення-результати інструментів або повертає помилку для завеликих зображень, наданих користувачем.

#### Параметри, специфічні для провайдера

Деякі провайдери підтримують додаткові параметри конфігурації, окрім стандартних налаштувань `timeout` та `apiKey`.

##### Amazon Bedrock

Amazon Bedrock підтримує специфічну для AWS конфігурацію:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1",
        "profile": "my-aws-profile",
        "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
      }
    }
  }
}
```

- `region` — AWS регіон для Bedrock (за замовчуванням змінна середовища `AWS_REGION` або `us-east-1`)
- `profile` — Іменований профіль AWS з `~/.aws/credentials` (за замовчуванням змінна середовища `AWS_PROFILE`)
- `endpoint` — Користувацький URL ендпоїнта для VPC ендпоїнтів. Це псевдонім для загальної опції `baseURL` з використанням специфічної для AWS термінології. Якщо вказані обидва, `endpoint` має перевагу.

:::note
Bearer-токени (`AWS_BEARER_TOKEN_BEDROCK` або `/connect`) мають перевагу над аутентифікацією на основі профілю. Див. [пріоритет аутентифікації](/docs/providers#authentication-precedence) для деталей.
:::

[Дізнатися більше про конфігурацію Amazon Bedrock](/docs/providers#amazon-bedrock).

### Агенти

Ви можете налаштувати спеціалізованих агентів для конкретних завдань через опцію `agent`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "code-reviewer": {
      "description": "Перевіряє код на найкращі практики та потенційні проблеми",
      "model": "anthropic/claude-sonnet-4-5",
      "prompt": "Ви рев'юер коду. Зосередьтеся на безпеці, продуктивності та підтримуваності.",
      "tools": {
        // Вимкнути інструменти модифікації файлів для агента лише для рев'ю
        "write": false,
        "edit": false,
      },
    },
  },
}
```

Ви також можете визначити агентів за допомогою файлів Markdown у `~/.config/opencode/agents/` або `.opencode/agents/`. [Дізнатися більше тут](/docs/agents).

---

### Агент за замовчуванням

Ви можете встановити агента за замовчуванням за допомогою опції `default_agent`. Це визначає, який агент використовується, коли інший явно не вказаний.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "plan"
}
```

Агент за замовчуванням повинен бути основним агентом (не субагентом). Це може бути вбудований агент, як-от `"build"` або `"plan"`, або [користувацький агент](/docs/agents), якого ви визначили. Якщо вказаний агент не існує або є субагентом, OpenCode повернеться до `"build"` з попередженням.

Це налаштування застосовується до всіх інтерфейсів: TUI, CLI (`opencode run`), десктопного застосунку та GitHub Action.

---

### Глибина субагентів

Ви можете контролювати, наскільки глибоко субагенти можуть викликати інших субагентів, за допомогою опції `subagent_depth`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "subagent_depth": 2
}
```

Стандартне значення — `1`, що дозволяє основним агентам запускати субагентів, але запобігає запуску додаткових субагентів цими субагентами. Встановіть `2`, щоб дозволити один додатковий рівень вкладених субагентів, або `0`, щоб запобігти всім запускам субагентів.

### Поширення

Ви можете налаштувати функцію [поширення](/docs/share) через опцію `share`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "share": "manual"
}
```

Це приймає:

- `"manual"` — Дозволити ручне поширення через команди (стандартно)
- `"auto"` — Автоматично поширювати нові розмови
- `"disabled"` — Повністю вимкнути поширення

За замовчуванням поширення встановлено в ручний режим, де вам потрібно явно поширювати розмови за допомогою команди `/share`.

### Команди

Ви можете налаштувати користувацькі команди для повторюваних завдань через опцію `command`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "command": {
    "test": {
      "template": "Запустити повний тестовий набір зі звітом про покриття та показати будь-які невдачі.\nЗосередитися на тестах, що падають, та запропонувати виправлення.",
      "description": "Запустити тести з покриттям",
      "agent": "build",
      "model": "anthropic/claude-haiku-4-5",
    },
    "component": {
      "template": "Створити новий React-компонент з назвою $ARGUMENTS з підтримкою TypeScript.\nВключити правильну типізацію та базову структуру.",
      "description": "Створити новий компонент",
    },
  },
}
```

Ви також можете визначити команди за допомогою файлів Markdown у `~/.config/opencode/commands/` або `.opencode/commands/`. [Дізнатися більше тут](/docs/commands).

### Комбінації клавіш

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {

  }
```

`keybinds` об'єднується з вбудованими стандартними налаштуваннями, тому вам потрібно налаштовувати лише ті комбінації, які ви хочете змінити.

### Знімки

OpenCode використовує знімки для відстеження змін файлів під час операцій агента, дозволяючи вам скасовувати та повертати зміни в межах сесії. Знімки ввімкнено за замовчуванням.

Для великих репозиторіїв або проєктів з багатьма підмодулями система знімків може спричинити повільне індексування та значне використання диска, оскільки вона відстежує всі зміни, використовуючи внутрішній git-репозиторій. Ви можете вимкнути знімки за допомогою опції `snapshot`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshot": false
}
```

Зауважте, що вимкнення знімків означає, що зміни, зроблені агентом, не можна буде відкотити через UI.

---

### Автооновлення

OpenCode автоматично завантажуватиме нові оновлення під час запуску. Ви можете вимкнути це за допомогою опції `autoupdate`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "autoupdate": false
}
```

Якщо ви не хочете оновлень, але хочете отримувати сповіщення про нову версію, встановіть `autoupdate` у `"notify"`.
Зауважте, що це працює, тільки якщо OpenCode не було встановлено за допомогою менеджера пакунків, такого як Homebrew.

### Форматери

Ви можете ввімкнути та налаштувати форматери коду через опцію `formatter`. Залиште пропущеним, щоб форматери залишалися вимкненими.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": true
}
```

Використовуйте об'єкт, щоб залишити вбудовані форматери ввімкненими, налаштовуючи перевизначення або користувацькі форматери.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": {
    "prettier": {
      "disabled": true
    },
    "custom-prettier": {
      "command": ["npx", "prettier", "--write", "$FILE"],
      "environment": {
        "NODE_ENV": "development"
      },
      "extensions": [".js", ".ts", ".jsx", ".tsx"]
    }
  }
}
```

[Дізнатися більше про форматери тут](/docs/formatters).

### Дозволи

За замовчуванням OpenCode **дозволяє всі операції** без необхідності явного схвалення. Ви можете змінити це за допомогою опції `permission`.

### Ущільнення

Ви можете контролювати поведінку ущільнення контексту через опцію `compaction`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "prune": false,
    "reserved": 10000
  }
}
```

- `auto` — Автоматично ущільнювати сесію, коли контекст заповнений (стандартно: `true`).
- `prune` — Видаляти старі результати інструментів для економії токенів (стандартно: `false`). Встановіть `true`, щоб увімкнути очищення.
- `reserved` — Буфер токенів для ущільнення. Залишає достатньо вікна, щоб уникнути переповнення під час ущільнення.

### Вимкнені провайдери

Ви можете вимкнути провайдерів, які завантажуються автоматично, через опцію `disabled_providers`. Це корисно, коли ви хочете запобігти завантаженню певних провайдерів, навіть якщо їхні облікові дані доступні.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "disabled_providers": ["openai", "gemini"]
}
```

:::note
`disabled_providers` має пріоритет над `enabled_providers`.
:::

Опція `disabled_providers` приймає масив ID провайдерів. Коли провайдер вимкнено:

- Він не буде завантажений, навіть якщо змінні середовища встановлено.
- Він не буде завантажений, навіть якщо ключі API налаштовано через команду `/connect`.
- Моделі провайдера не з'являться в списку вибору моделей.

---

### Увімкнені провайдери

Ви можете вказати список дозволених провайдерів через опцію `enabled_providers`. Якщо встановлено, лише вказані провайдери будуть увімкнені, а всі інші будуть проігноровані.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "enabled_providers": ["anthropic", "openai"]
}
```

Це корисно, коли ви хочете обмежити OpenCode використанням лише певних провайдерів, а не вимикати їх по одному.

:::note
`disabled_providers` має пріоритет над `enabled_providers`.
:::

Якщо провайдер з'являється в обох списках `enabled_providers` та `disabled_providers`, `disabled_providers` має пріоритет для зворотної сумісності.

### Експериментальне

```json title="opencode.json"

  "$schema": "https://opencode.ai/config.json",
```

## Змінні

Ви можете використовувати підстановку змінних у ваших файлах конфігурації для посилань на змінні середовища та вміст файлів.

---

### Змінні середовища

Використовуйте `{env:VARIABLE_NAME}`, щоб підставити змінні середовища:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "provider": {
    "anthropic": {
      "models": {},
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

Якщо змінна середовища не встановлена, вона буде замінена порожнім рядком.

---

### Файли

Використовуйте `{file:path/to/file}`, щоб підставити вміст файлу:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["./custom-instructions.md"],
  "provider": {
    "openai": {
      "options": {
        "apiKey": "{file:~/.secrets/openai-key}"
      }
    }
  }
}
```

Шляхи до файлів можуть бути:

- Відносними до каталогу файлу конфігурації
- Або абсолютними шляхами, що починаються з `/` або `~`

Це корисно для:

- Зберігання конфіденційних даних, таких як ключі API, в окремих файлах.
- Включення великих файлів інструкцій без захаращення вашої конфігурації.
- Поширення загальних фрагментів конфігурації між кількома файлами конфігурації.
