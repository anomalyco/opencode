OpenCode Enterprise призначений для організацій, які хочуть гарантувати, що їхній код та дані ніколи не залишають їхньої інфраструктури. Це можна зробити за допомогою централізованої конфігурації, яка інтегрується з вашим SSO та внутрішнім AI-шлюзом.

:::note
OpenCode не зберігає ваш код або контекстні дані.
:::

Щоб почати роботу з OpenCode Enterprise:

1. Проведіть внутрішнє випробування з вашою командою.
2. **<a href={enterprise}>Зв'яжіться з нами</a>** для обговорення цін та варіантів впровадження.

## Випробування

OpenCode є відкритим, з відкритим кодом, і не зберігає ваш код або контекстні дані, тому ваші розробники можуть просто [почати роботу](/docs/) та провести випробування.

---

### Обробка даних

**OpenCode не зберігає ваш код або контекстні дані.** Вся обробка відбувається локально або через прямі виклики API до вашого AI-провайдера.

Це означає, що якщо ви використовуєте провайдера, якому довіряєте, або внутрішній
AI-шлюз, ви можете безпечно використовувати OpenCode.

Єдиний виняток — опціональна функція `/share`.

---

#### Поширення розмов

Якщо користувач вмикає функцію `/share`, розмова та пов'язані з нею дані надсилаються до сервісу, який ми використовуємо для розміщення цих сторінок за адресою opencode.ai.

Дані наразі обслуговуються через нашу CDN мережу та кешуються на периферії поблизу ваших користувачів.

Ми рекомендуємо вимкнути це для вашого випробування.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "share": "disabled"
}
```

[Дізнатися більше про поширення](/docs/share).

## Розгортання

Після завершення випробування, коли ви будете готові використовувати OpenCode у
вашій організації, ви можете **<a href={enterprise}>зв'язатися з нами</a>** для обговорення
цін та варіантів впровадження.

---

### Центральна конфігурація

Ми можемо налаштувати OpenCode для використання єдиної центральної конфігурації для всієї вашої організації.

Ця централізована конфігурація може інтегруватися з вашим SSO-провайдером та гарантує, що всі користувачі мають доступ лише до вашого внутрішнього AI-шлюзу.

---

### Інтеграція SSO

Через центральну конфігурацію OpenCode може інтегруватися з SSO-провайдером вашої організації для аутентифікації.

Це дозволяє OpenCode отримувати облікові дані для вашого внутрішнього AI-шлюзу через вашу існуючу систему керування ідентифікацією.

---

### Внутрішній AI-шлюз

За допомогою центральної конфігурації OpenCode також можна налаштувати на використання лише вашого внутрішнього AI-шлюзу.

Ви також можете вимкнути всі інші AI-провайдери, гарантуючи, що всі запити проходять через затверджену інфраструктуру вашої організації.

---

### Саморозміщення

Хоча ми рекомендуємо вимкнути сторінки поширення, щоб гарантувати, що ваші дані ніколи не залишають
вашу організацію, ми також можемо допомогти вам розмістити їх самостійно на вашій інфраструктурі.

Це наразі в нашій дорожній карті. Якщо вам це цікаво, **<a href={enterprise}>дайте нам знати</a>**.

<details>
<summary>Чи можемо ми використовувати власний приватний NPM-реєстр?</summary>

OpenCode підтримує приватні npm-реєстри через вбудовану підтримку файлів `.npmrc` у Bun. Якщо ваша організація використовує приватний реєстр, наприклад JFrog Artifactory, Nexus або подібний, переконайтеся, що розробники аутентифіковані перед запуском OpenCode.

Щоб налаштувати аутентифікацію з вашим приватним реєстром:

```bash
npm login --registry=https://your-company.jfrog.io/api/npm/npm-virtual/
```

Це створить `~/.npmrc` з даними аутентифікації. OpenCode автоматично
підхопить це.

:::caution
Ви повинні бути авторизовані в приватному реєстрі перед запуском OpenCode.
:::

Крім того, ви можете вручну налаштувати файл `.npmrc`:

```bash title="~/.npmrc"
registry=https://your-company.jfrog.io/api/npm/npm-virtual/
//your-company.jfrog.io/api/npm/npm-virtual/:_authToken=${NPM_AUTH_TOKEN}
```

Розробники повинні авторизуватися в приватному реєстрі перед запуском OpenCode, щоб забезпечити можливість встановлення пакунків з вашого корпоративного реєстру.

</details>
