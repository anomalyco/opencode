OpenCode використовує [AI SDK](https://ai-sdk.dev/) та [Models.dev](https://models.dev) для підтримки **75+ LLM-провайдерів** і підтримує запуск локальних моделей.

Щоб додати провайдера, потрібно:

1. Додати ключі API для провайдера за допомогою команди `/connect`.
2. Налаштувати провайдера у вашій конфігурації OpenCode.

---

### Облікові дані

Коли ви додаєте ключі API провайдера за допомогою команди `/connect`, вони зберігаються
у `~/.local/share/opencode/auth.json`.

---

### Конфігурація

Ви можете налаштувати провайдерів через розділ `provider` у вашій конфігурації
OpenCode.

---

#### Базовий URL

Ви можете налаштувати базовий URL для будь-якого провайдера, встановивши опцію `baseURL`. Це корисно при використанні проксі-сервісів або користувацьких ендпоїнтів.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

---

#### Приховування моделей

Ви можете приховати конкретні моделі з вибору `/models` для провайдера за допомогою опції `blacklist`. Це корисно, коли провайдер показує моделі, які ви не хочете використовувати або вибирати.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "blacklist": ["claude-opus-4-20250514"]
    }
  }
}
```

Обернена опція `whitelist` приховує всі моделі, крім перелічених.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "whitelist": ["claude-sonnet-4-20250514"]
    }
  }
}
```

Обидві опції приймають масив ID моделей — тих самих ID, що показуються у виборі `/models`.

- `blacklist` видаляє перелічені моделі з вибору.
- `whitelist` залишає лише перелічені моделі та приховує решту.
- Ви можете комбінувати їх: `whitelist` звужує набір, потім `blacklist` видаляє елементи з нього.

## OpenCode Zen

OpenCode Zen — це список моделей, наданий командою OpenCode, які були
протестовані та перевірені на хорошу роботу з OpenCode. [Дізнатися більше](/docs/zen).

:::tip
Якщо ви новачок, ми рекомендуємо почати з OpenCode Zen.
:::

1. Виконайте команду `/connect` у TUI, виберіть `OpenCode Zen` та перейдіть на [opencode.ai/auth](https://opencode.ai/zen).

   ```txt
   /connect
   ```

2. Увійдіть, додайте платіжні дані та скопіюйте ваш ключ API.

3. Вставте ваш ключ API.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Виконайте `/models` у TUI, щоб побачити список моделей, які ми рекомендуємо.

   ```txt
   /models
   ```

Він працює як будь-який інший провайдер в OpenCode і є повністю опціональним.

### Amazon Bedrock

Щоб використовувати Amazon Bedrock з OpenCode:

1. Перейдіть до **Model catalog** у консолі Amazon Bedrock та запитайте
   доступ до потрібних моделей.

   :::tip
   Вам потрібно мати доступ до потрібної моделі в Amazon Bedrock.
   :::

2. **Налаштуйте аутентифікацію** за допомогою одного з наступних методів:

   ***

   #### Змінні середовища (швидкий старт)

   Встановіть одну з цих змінних середовища під час запуску opencode:

   ```bash
   # Варіант 1: Використання ключів доступу AWS
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # Варіант 2: Використання іменованого профілю AWS
   AWS_PROFILE=my-profile opencode

   # Варіант 3: Використання bearer-токена Bedrock
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   Або додайте їх до вашого bash-профілю:

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### Файл конфігурації (рекомендовано)

   Для конфігурації, специфічної для проєкту або постійної, використовуйте `opencode.json`:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **Доступні опції:**
   - `region` — AWS регіон (наприклад, `us-east-1`, `eu-west-1`)
   - `profile` — Іменований профіль AWS з `~/.aws/credentials`
   - `endpoint` — Користувацький URL ендпоїнта для VPC ендпоїнтів (псевдонім для загальної опції `baseURL`)

   :::tip
   Опції файлу конфігурації мають перевагу над змінними середовища.
   :::

   ***

   #### Просунутий: VPC ендпоїнти

   Якщо ви використовуєте VPC ендпоїнти для Bedrock:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   Опція `endpoint` є псевдонімом для загальної опції `baseURL`, використовуючи специфічну для AWS термінологію. Якщо вказані обидва `endpoint` та `baseURL`, `endpoint` має перевагу.
   :::

   ***

   #### Методи аутентифікації
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: Створіть IAM-користувача та згенеруйте ключі доступу в консолі AWS
   - **`AWS_PROFILE`**: Використовуйте іменовані профілі з `~/.aws/credentials`. Спочатку налаштуйте за допомогою `aws configure --profile my-profile` або `aws sso login`
   - **`AWS_BEARER_TOKEN_BEDROCK`**: Згенеруйте довгострокові ключі API з консолі Amazon Bedrock
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: Для EKS IRSA (IAM Roles for Service Accounts) або інших середовищ Kubernetes з OIDC-федерацією. Ці змінні середовища автоматично впроваджуються Kubernetes при використанні анотацій service account.

   ***

   #### Пріоритет аутентифікації

   Amazon Bedrock використовує наступний пріоритет аутентифікації:
   1. **Bearer Token** — змінна середовища `AWS_BEARER_TOKEN_BEDROCK` або токен з команди `/connect`
   2. **Ланцюжок облікових даних AWS** — профіль, ключі доступу, спільні облікові дані, IAM-ролі, Web Identity Tokens (EKS IRSA), метадані екземпляра

   :::note
   Коли встановлено bearer-токен (через `/connect` або `AWS_BEARER_TOKEN_BEDROCK`), він має перевагу над усіма методами облікових даних AWS, включаючи налаштовані профілі.
   :::

3. Виконайте команду `/models`, щоб вибрати потрібну модель.

   ```txt
   /models
   ```

:::note
Для користувацьких профілів інференсу використовуйте назву моделі та провайдера в ключі та встановіть властивість `id` на ARN. Це забезпечує правильне кешування.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

Ви можете налаштувати opencode для використання локальних моделей через [Atomic Chat](https://atomic.chat), десктопний застосунок, який запускає локальні LLM за допомогою API-сервера, сумісного з OpenAI (стандартний ендпоїнт `http://127.0.0.1:1337/v1`).

```json title="opencode.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (локальний)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

У цьому прикладі:

- `atomic-chat` — це ID користувацького провайдера. Це може бути будь-який рядок на ваш вибір.
- `npm` вказує пакунок для використання з цим провайдером. Тут `@ai-sdk/openai-compatible` використовується для будь-якого API, сумісного з OpenAI.
- `name` — відображувана назва провайдера в UI.
- `options.baseURL` — ендпоїнт для локального сервера. Змініть хост та порт відповідно до вашого налаштування Atomic Chat.
- `models` — це мапа ID моделей до їхніх відображуваних назв. Кожен ID має відповідати `id`, що повертається `GET /v1/models` — виконайте `curl http://127.0.0.1:1337/v1/models`, щоб перерахувати ID, які зараз завантажені в Atomic Chat.

:::tip
Якщо виклики інструментів працюють некоректно, виберіть завантажену модель із сильною підтримкою виклику інструментів (наприклад, варіант Qwen-Coder або DeepSeek-Coder).
:::

### Azure OpenAI

:::note
Якщо ви отримуєте помилки "I'm sorry, but I cannot assist with that request", спробуйте змінити фільтр вмісту з **DefaultV2** на **Default** у вашому ресурсі Azure.

2. Перейдіть до [Azure AI Foundry](https://ai.azure.com/) та розгорніть модель.

   :::note
   Ім'я розгортання має збігатися з назвою моделі для правильної роботи opencode.
   :::

3. Виконайте команду `/connect` та знайдіть **Azure**.

   ```txt
   /connect
   ```

4. Введіть ваш ключ API.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

5. Встановіть ім'я вашого ресурсу як змінну середовища:

   ```bash
   AZURE_RESOURCE_NAME=XXX opencode
   ```

   Або додайте до вашого bash-профілю:

   ```bash title="~/.bash_profile"
   export AZURE_RESOURCE_NAME=XXX
   ```

6. Виконайте команду `/models`, щоб вибрати вашу розгорнуту модель.

   ```txt

   ```

### Cloudflare AI Gateway

Cloudflare AI Gateway дозволяє отримувати доступ до моделей від OpenAI, Anthropic, Workers AI та інших через єдиний ендпоїнт. З [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) вам не потрібні окремі ключі API для кожного провайдера.

1. Перейдіть до [панелі керування Cloudflare](https://dash.cloudflare.com/), перейдіть до **AI** > **AI Gateway** та створіть новий шлюз. Запишіть ваш **Account ID** та **Gateway ID**.

2. Виконайте команду `/connect` та знайдіть **Cloudflare AI Gateway**.

   ```txt
   /connect
   ```

3. Введіть ваш **Account ID** під час запиту.

   ```txt
   ┌ Введіть ваш Cloudflare Account ID
   │
   │
   └ enter
   ```

4. Введіть ваш **Gateway ID** під час запиту.

   ```txt
   ┌ Введіть ваш Cloudflare AI Gateway ID
   │
   │
   └ enter
   ```

5. Введіть ваш **Cloudflare API token**.

   ```txt
   ┌ Gateway API token
   │
   │
   └ enter
   ```

6. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

   Ви також можете додати моделі через вашу конфігурацію opencode.

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "cloudflare-ai-gateway": {
         "models": {
           "openai/gpt-4o": {},
           "anthropic/claude-sonnet-4": {}
         }
       }
     }
   }
   ```

   Крім того, ви можете встановити змінні середовища замість використання `/connect`.

   ```bash title="~/.bash_profile"
   export CLOUDFLARE_ACCOUNT_ID=your-32-character-account-id
   export CLOUDFLARE_GATEWAY_ID=your-gateway-id
   export CLOUDFLARE_API_TOKEN=your-api-token
   ```

### DigitalOcean

DigitalOcean [Inference Engine](https://docs.digitalocean.com/products/inference/) надає доступ до відкритих моделей, таких як GPT-OSS, Llama, Qwen та DeepSeek, а також до [Inference Routers](https://docs.digitalocean.com/products/genai-platform/concepts/inference-routers/), які маршрутизують кожен запит до найдешевшої, найшвидшої або найбільш підходящої моделі для завдання.

OpenCode підтримує два методи аутентифікації:

- **OAuth (рекомендовано)** — Увійдіть у ваш обліковий запис DigitalOcean; OpenCode використовує ваш DigitalOcean API-токен безпосередньо для інференсу та виявляє ваші Inference Routers.
- **Model Access Key** — Вставте існуючий ключ з консолі DigitalOcean.

#### OAuth (рекомендовано)

1. Виконайте команду `/connect` та знайдіть **DigitalOcean**.

   ```txt
   /connect
   ```

2. Виберіть **Login with DigitalOcean**.

   ```txt
   ┌ Виберіть метод аутентифікації
   │
   │ Login with DigitalOcean
   │ Paste Model Access Key
   └
   ```

3. Ваш браузер відкриється для авторизації OpenCode. Увійдіть та підтвердьте.

   :::note
   OpenCode запитує області OAuth `genai:read` та `inference:query`. Ваш DigitalOcean API-токен використовується безпосередньо для інференсу — окремий Model Access Key не створюється.
   :::

   :::note
   Inference Routers з'являються у виборі моделей лише після OAuth. Вставлення Model Access Key вручну не виявляє роутери.
   :::

4. Виконайте команду `/models`. Ваші Inference Routers відображаються у форматі `router:` у виборі моделей.

   ```txt

   ```

5. Щоб підхопити щойно створені Inference Routers, повторно виконайте `/connect` та знову виберіть **DigitalOcean**.

#### Inference Routers

Inference Routers дозволяють визначити політику маршрутизації для кількох моделей — обираючи найдешевшу, найшвидшу або найбільш підходящу модель для кожного запиту на основі завдання. Після OAuth OpenCode показує кожен роутер як `router:<router-name>` у виборі моделей.

Вибір моделі роутера є прямою заміною будь-якої іншої моделі — OpenCode надсилає ваш запит, а DigitalOcean обирає відповідну модель на основі політики вашого роутера. Дізнайтеся більше про [Inference Routers](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/)

##### GitLab Duo Agent Platform (DAP) Workflow Models

Моделі робочих процесів DAP надають альтернативний шлях виконання, який маршрутизує виклики інструментів
через GitLab Duo Workflow Service (DWS) замість стандартного агентського чату.
Коли вибрано модель `duo-workflow-*`, OpenCode буде:

1. Виявляти доступні моделі з вашого простору імен GitLab
2. Показувати вибір, якщо доступно кілька моделей
3. Кешувати вибрану модель на диск для швидкого наступного запуску
4. Маршрутизувати запити на виконання інструментів через систему дозволів OpenCode

Доступні моделі робочих процесів DAP відповідають угоді про іменування `duo-workflow-*` та
динамічно виявляються з вашого GitLab-екземпляра.

##### GitLab API Tools (опціонально, але дуже рекомендовано)

Для доступу до інструментів GitLab (merge requests, issues, pipelines, CI/CD тощо):

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-gitlab-plugin"]
}
```

Цей плагін надає комплексні можливості керування GitLab-репозиторієм, включаючи рев'ю MR, відстеження завдань, моніторинг пайплайнів тощо.

#### Опціональні конфігурації

```jsonc title="~/.config/opencode/opencode.jsonc"

  "$schema": "https://opencode.ai/config.json",

      "name": "Helicone",
      "options": {

        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### Користувацькі заголовки

Helicone підтримує користувацькі заголовки для таких функцій, як кешування, відстеження користувачів та керування сесіями. Додайте їх до конфігурації вашого провайдера за допомогою `options.headers`:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### Відстеження сесій

Функція [Sessions](https://docs.helicone.ai/features/sessions) від Helicone дозволяє групувати пов'язані LLM-запити разом. Використовуйте плагін [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session), щоб автоматично журналювати кожну розмову OpenCode як сесію в Helicone.

```bash
npm install -g opencode-helicone-session
```

Додайте його до вашої конфігурації.

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

Плагін впроваджує заголовки `Helicone-Session-Id` та `Helicone-Session-Name` у ваші запити. На сторінці Sessions в Helicone ви побачите кожну розмову OpenCode як окрему сесію.

##### Поширені заголовки Helicone

| Заголовок                    | Опис                                                      |
| ---------------------------- | --------------------------------------------------------- |
| `Helicone-Cache-Enabled`     | Увімкнути кешування відповідей (`true`/`false`)           |
| `Helicone-User-Id`           | Відстежувати метрики за користувачем                      |
| `Helicone-Property-[Name]`   | Додати користувацькі властивості (наприклад, `Helicone-Property-Environment`) |
| `Helicone-Prompt-Id`         | Пов'язати запити з версіями підказок                      |

Перегляньте [каталог заголовків Helicone](https://docs.helicone.ai/helicone-headers/header-directory) для всіх доступних заголовків.

Немає облікового запису Snowflake? [Зареєструйтеся для безкоштовної пробної версії](https://signup.snowflake.com/?utm_source=opencode&utm_medium=docs&utm_campaign=cortex-provider).

Основний робочий процес opencode для програмування, редагування файлів та запуску команд покладається на виклик інструментів. Лише сімейства Claude та OpenAI в Snowflake Cortex підтримують це. Провайдер обмежений цими сімействами для підтримки основного робочого процесу.

OpenCode підтримує два методи аутентифікації:

- **Browser OAuth (рекомендовано)** — увійдіть з вашим IdP/SSO; без необхідності керувати секретами, токени оновлюються автоматично.
- **Ручний bearer-токен** — вставте PAT або JWT з консолі Snowflake.

#### Browser OAuth (рекомендовано)

1. Виконайте команду `/connect` та знайдіть **Snowflake Cortex**.

   ```txt
   /connect
   ```

2. Виберіть **Login with Snowflake (External Browser)**.

   ```txt
   ┌ Виберіть метод аутентифікації
   │
   │ Login with Snowflake (External Browser)
   │ Paste PAT or bearer token manually
   └
   ```

3. Введіть ваш [ідентифікатор облікового запису](https://docs.snowflake.com/en/user-guide/admin-account-identifier) під час запиту, наприклад `myorg-myaccount` або `xy12345.us-east-1`.

   ```txt
   ┌ Ідентифікатор облікового запису Snowflake
   │
   │
   └ enter
   ```

4. Опціонально введіть роль Snowflake для обмеження сесії (наприклад, `SYSADMIN`). Залиште порожнім, щоб використовувати вашу стандартну роль.

5. Завершіть вхід у браузері, що відкриється. OpenCode перехоплює зворотний виклик OAuth автоматично та зберігає токен — копіювання/вставка не потрібна.

6. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

:::note
Browser OAuth використовує вбудовану інтеграцію безпеки `SNOWFLAKE$LOCAL_APPLICATION` від Snowflake ([документація](https://docs.snowflake.com/en/user-guide/oauth-local-applications)), яка розгортається для всіх облікових записів. Щоб перевірити доступність у вашому обліковому записі:

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

Якщо результат порожній, використовуйте метод **Ручний bearer-токен** нижче, поки інтеграція розгортається у вашому обліковому записі.
:::

#### Ручний bearer-токен

Якщо ви бажаєте вставити токен безпосередньо, або якщо `SNOWFLAKE$LOCAL_APPLICATION` ще не доступний у вашому обліковому записі:

1. Згенеруйте [Programmatic Access Token (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) у вашому обліковому записі Snowflake.

2. Виконайте команду `/connect`, знайдіть **Snowflake Cortex** та виберіть **Paste PAT or bearer token manually**.

3. Введіть ваш [ідентифікатор облікового запису](https://docs.snowflake.com/en/user-guide/admin-account-identifier) під час запиту.

4. Вставте ваш PAT.

5. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

#### Змінна середовища

Для CI або безголових середовищ встановіть PAT або JWT перед запуском opencode:

```bash
export SNOWFLAKE_ACCOUNT=myorg-myaccount
export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` приймає лише PAT або JWT — потік Browser OAuth доступний лише через `/connect` і не може бути налаштований через змінну середовища. `SNOWFLAKE_CORTEX_PAT` все ще підтримується для зворотної сумісності.
:::

Каталог моделей надається автоматично. Мінімальний `opencode.json` — це все, що потрібно:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "snowflake-cortex/claude-sonnet-4-6",
  "small_model": "snowflake-cortex/claude-haiku-4-5"
}
```

### xAI

Три способи аутентифікації: підписка SuperGrok через браузерний OAuth, та ж підписка SuperGrok через безголовий потік device-code (для VPS / SSH / Docker), або ключ API з оплатою за використання з консолі xAI.

#### Варіант A — SuperGrok OAuth (вхід через браузер)

1. Виконайте команду `/connect` та знайдіть **xAI**.

   ```txt
   /connect
   ```

2. Виберіть **xAI Grok OAuth (SuperGrok Subscription)**. OpenCode відкриває екран згоди xAI у вашому браузері та чекає зворотного виклику на `http://127.0.0.1:56121/callback`.

3. Виконайте команду `/models`, щоб вибрати модель Grok.

   ```txt
   /models
   ```

OpenCode оновлює токен доступу OAuth автоматично. Будь-який план Grok або X Premium, що включає доступ до Grok API, працює; вам не потрібен окремий `XAI_API_KEY`.

#### Варіант B — SuperGrok device-code (безголовий / віддалений сервер / VPS)

Використовуйте це, коли OpenCode запущено десь, де браузер не може досягти зворотного виклику loopback: VPS, віддалена розробницька машина через SSH, всередині Docker, в CI тощо. Жоден порт зворотного виклику не відкривається на хості, де запущено OpenCode — натомість xAI надає CLI короткий код, який ви вводите в браузері на будь-якому іншому пристрої (ноутбук, телефон тощо).

1. Виконайте команду `/connect` на віддаленому хості та знайдіть **xAI**.

   ```txt
   /connect
   ```

2. Виберіть **xAI Grok OAuth (Headless / Remote / VPS)**. OpenCode виводить URL для верифікації та короткий код користувача.

   ```txt
   Відкрийте https://x.ai/device на будь-якому пристрої та введіть код: ABCD-1234
   ```

3. Відкрийте URL на пристрої, що має браузер (ваш ноутбук або телефон), введіть код та підтвердьте екран згоди. OpenCode опитує токен-ендпоїнт xAI та зберігає отримані OAuth-токени після вашого підтвердження. Оновлення токена працює так само, як у варіанті A.

#### Варіант C — Ключ API

1. Перейдіть до [консолі xAI](https://console.x.ai/), створіть обліковий запис та згенеруйте ключ API.

2. Виконайте команду `/connect` та знайдіть **xAI**.

   ```txt
   /connect
   ```

3. Виберіть **Manually enter API Key** та вставте ваш ключ API xAI.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Виконайте команду `/models`, щоб вибрати модель, наприклад _Grok Beta_.

   ```txt
   /models
   ```

## Користувацький провайдер

Щоб додати будь-якого провайдера, **сумісного з OpenAI**, якого немає в списку команди `/connect`:

:::tip
Ви можете використовувати будь-якого провайдера, сумісного з OpenAI, з opencode. Більшість сучасних AI-провайдерів пропонують API, сумісні з OpenAI.
:::

1. Виконайте команду `/connect` та прокрутіть до **Other**.

   ```bash
   $ /connect

   ┌  Додати облікові дані
   │
   ◆  Виберіть провайдера
   │  ...
   │  ● Other
   └
   ```

2. Введіть унікальний ID для провайдера.

   ```bash
   $ /connect

   ┌  Додати облікові дані
   │
   ◇  Введіть ID провайдера
   │  myprovider
   └
   ```

   :::note
   Виберіть ID, який легко запам'ятати, ви будете використовувати його у файлі конфігурації.
   :::

3. Введіть ваш ключ API для провайдера.

   ```bash
   $ /connect

   ┌  Додати облікові дані
   │
   ▲  Це лише зберігає облікові дані для myprovider - вам потрібно буде налаштувати його в opencode.json, перевірте документацію для прикладів.
   │
   ◇  Введіть ваш ключ API
   │  sk-...
   └
   ```

4. Створіть або оновіть ваш файл `opencode.json` у каталозі проєкту:

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI ProviderDisplay Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   Ось опції конфігурації:
   - **npm**: AI SDK пакунок для використання, `@ai-sdk/openai-compatible` для провайдерів, сумісних з OpenAI (для `/v1/chat/completions`). Якщо ваш провайдер/модель використовує `/v1/responses`, використовуйте `@ai-sdk/openai`.
   - **name**: Відображувана назва в UI.
   - **models**: Доступні моделі.
   - **options.baseURL**: URL API ендпоїнта.
   - **options.apiKey**: Опціонально встановіть ключ API, якщо не використовується аутентифікація.
   - **options.headers**: Опціонально встановіть користувацькі заголовки.

   Більше про розширені опції в прикладі нижче.

5. Виконайте команду `/models`, і ваш користувацький провайдер та моделі з'являться в списку вибору.

---

##### Приклад

Ось приклад встановлення опцій `apiKey`, `headers` та `limit` моделі.

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI ProviderDisplay Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

Деталі конфігурації:

- **apiKey**: Встановлюється за допомогою синтаксису змінної `env`, [дізнатися більше](/docs/config#env-vars).
- **headers**: Користувацькі заголовки, що надсилаються з кожним запитом.
- **limit.context**: Максимальна кількість вхідних токенів, яку приймає модель.
- **limit.output**: Максимальна кількість токенів, яку модель може згенерувати.

Поля `limit` дозволяють OpenCode розуміти, скільки контексту у вас залишилося. Стандартні провайдери отримують цю інформацію з models.dev автоматично.

## Вирішення проблем

Якщо у вас виникли проблеми з налаштуванням провайдера, перевірте наступне:

1. **Перевірте налаштування аутентифікації**: Виконайте `opencode auth list`, щоб побачити, чи додано облікові дані
   для провайдера до вашої конфігурації.

   Це не стосується провайдерів, таких як Amazon Bedrock, які покладаються на змінні середовища для своєї аутентифікації.

2. Для користувацьких провайдерів перевірте конфігурацію opencode та:
   - Переконайтеся, що ID провайдера, використаний у команді `/connect`, збігається з ID у вашій конфігурації opencode.
   - Переконайтеся, що використовується правильний npm-пакунок для провайдера. Наприклад, використовуйте `@ai-sdk/cerebras` для Cerebras. А для всіх інших провайдерів, сумісних з OpenAI, використовуйте `@ai-sdk/openai-compatible` (для `/v1/chat/completions`); якщо модель використовує `/v1/responses`, використовуйте `@ai-sdk/openai`. Для змішаних налаштувань в межах одного провайдера ви можете перевизначити на модель через `provider.npm`.
   - Перевірте, чи використовується правильний API-ендпоїнт у полі `options.baseURL`.
