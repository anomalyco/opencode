---
title: Політики
description: Контролюйте, які налаштовані ресурси може використовувати OpenCode.
---

Політики контролюють, чи може OpenCode виконувати дію над іменованим ресурсом. Ця функція є експериментальною та налаштовується за допомогою масиву `experimental.policies` у `opencode.json`.

Політики відрізняються від [дозволів](/docs/permissions). Дозволи контролюють, що інструменти можуть робити під час сесії, тоді як політики контролюють, чи може OpenCode використовувати ресурс, наприклад, LLM провайдера.

---

## Конфігурація

Кожен оператор політики має три поля:

- `effect` — `"allow"` або `"deny"`.
- `action` — Операція, яка контролюється.
- `resource` — ID ресурсу або wildcard патерн, до якого застосовується оператор.

Наприклад, заборона використання провайдера `openai`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "openai"
      }
    ]
  }
}
```

Провайдер, заборонений політикою, недоступний для вибору або використання моделі, навіть якщо він має облікові дані або іншим чином налаштований правильно.

---

## Доступні політики

OpenCode наразі підтримує одну дію політики:

| Дія         | Ресурс                      | Опис                           |
| -------------- | ----------------------------- | ------------------------------------- |
| `provider.use` | ID провайдера, наприклад `openai` | Дозволити або заборонити використання LLM провайдера. |

Більше дій політик може бути додано в майбутньому.

---

## Зіставлення

Поле `resource` підтримує зіставлення wildcard. Використовуйте `*` для збігу нуля або більше символів та `?` для збігу одного символу.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "company-*"
      }
    ]
  }
}
```

Це забороняє провайдерів, таких як `company-us` та `company-eu`.

---

## Порядок правил

Коли кілька операторів збігаються, останній співпадаючий оператор виграє. Розміщуйте широкі правила першими, а потім більш специфічні винятки після них.

Наприклад, дозволити лише Anthropic:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "*"
      },
      {
        "effect": "allow",
        "action": "provider.use",
        "resource": "anthropic"
      }
    ]
  }
}
```

Якщо жодна політика не збігається з провайдером, використання провайдера дозволено за замовчуванням.

Політики можуть бути встановлені як у вашій глобальній конфігурації, так і в конфігурації проєкту. Якщо політики з обох розташувань збігаються з одним провайдером, ваша глобальна політика має пріоритет над політикою проєкту. Це запобігає повторному ввімкненню провайдера, якого ви забороняєте глобально, з боку репозиторію.

## Списки провайдерів

Використовуйте політики замість старіших налаштувань `disabled_providers` та `enabled_providers` при контролі доступу до провайдерів.

Щоб замінити `disabled_providers`:

```json title="opencode.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "openai" },
      { "effect": "deny", "action": "provider.use", "resource": "google" }
    ]
  }
}
```

Щоб замінити `enabled_providers`, спочатку забороніть всіх провайдерів, а потім дозвольте вибраних після цього:

```json title="opencode.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "*" },
      { "effect": "allow", "action": "provider.use", "resource": "anthropic" },
      { "effect": "allow", "action": "provider.use", "resource": "openai" }
    ]
  }
}
```
