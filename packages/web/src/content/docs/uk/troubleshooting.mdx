description: Типові проблеми та способи їх вирішення.
---

Щоб налагодити проблеми з OpenCode, почніть з перевірки журналів та локальних даних, які він зберігає на диску.

---

## Журнали

Файли журналів записуються в:

- **macOS/Linux**: `~/.local/share/opencode/log/`
- **Windows**: Натисніть `WIN+R` та вставте `%USERPROFILE%\.local\share\opencode\log`

Файли журналів мають назви з часовими мітками (наприклад, `2025-01-09T123456.log`) і зберігаються останні 10 файлів журналів.

Ви можете встановити рівень журналювання за допомогою параметра командного рядка `--log-level`, щоб отримати більш детальну налагоджувальну інформацію. Наприклад, `opencode --log-level DEBUG`.

---

## Сховище

OpenCode зберігає дані сесій та інші дані застосунку на диску за адресою:

- **macOS/Linux**: `~/.local/share/opencode/`
- **Windows**: Натисніть `WIN+R` та вставте `%USERPROFILE%\.local\share\opencode`

Цей каталог містить:

- `auth.json` — Дані аутентифікації, такі як ключі API, OAuth-токени
- `log/` — Журнали застосунку
- `project/` — Дані, специфічні для проєкту, такі як дані сесій та повідомлень
  - Якщо проєкт знаходиться в Git-репозиторії, він зберігається в `./<project-slug>/storage/`
  - Якщо це не Git-репозиторій, він зберігається в `./global/storage/`

---

## Видалення

Щоб видалити CLI OpenCode та пов'язані з ним файли, виконайте:

```bash
opencode uninstall
```

Команда показує, що буде видалено, та запитує підтвердження. Перегляньте [довідник CLI](/docs/cli#uninstall) для параметрів збереження вашої конфігурації або даних застосунку.

Щоб видалити OpenCode Desktop, видаліть застосунок через інструменти керування застосунками вашої операційної системи.

---

## Десктопний застосунок

OpenCode Desktop запускає локальний сервер OpenCode (сайдкар `opencode-cli`) у фоновому режимі. Більшість проблем спричинені неправильно працюючим плагіном, пошкодженим кешем або неправильними налаштуваннями сервера.

### Швидкі перевірки

- Повністю закрийте та перезапустіть застосунок.
- Якщо застосунок показує екран помилки, натисніть **Restart** та скопіюйте деталі помилки.
- Тільки macOS: меню `OpenCode` -> **Reload Webview** (допомагає, якщо UI порожній/завис).

---

### Вимкнення плагінів

Якщо десктопний застосунок вилітає під час запуску, зависає або поводиться дивно, почніть з вимкнення плагінів.

#### Перевірте глобальну конфігурацію

Відкрийте ваш глобальний файл конфігурації та знайдіть ключ `plugin`.

- **macOS/Linux**: `~/.config/opencode/opencode.jsonc` (або `~/.config/opencode/opencode.json`)
- **macOS/Linux** (старі встановлення): `~/.local/share/opencode/opencode.jsonc`
- **Windows**: Натисніть `WIN+R` та вставте `%USERPROFILE%\.config\opencode\opencode.jsonc`

Якщо у вас налаштовані плагіни, тимчасово вимкніть їх, видаливши ключ або встановивши порожній масив:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [],
}
```

#### Перевірте каталоги плагінів

OpenCode також може завантажувати локальні плагіни з диска. Тимчасово перемістіть їх в інше місце (або перейменуйте папку) та перезапустіть десктопний застосунок:

- **Глобальні плагіни**
  - **macOS/Linux**: `~/.config/opencode/plugins/`
  - **Windows**: Натисніть `WIN+R` та вставте `%USERPROFILE%\.config\opencode\plugins`
- **Плагіни проєкту** (тільки якщо ви використовуєте конфігурацію на проєкт)
  - `<your-project>/.opencode/plugins/`

Якщо застосунок знову запрацює, вмикайте плагіни по одному, щоб знайти той, що спричиняє проблему.

---

### Очищення кешу

Якщо вимкнення плагінів не допомагає (або встановлення плагіна застрягло), очистіть кеш, щоб OpenCode міг його перебудувати.

1. Повністю закрийте OpenCode Desktop.
2. Видаліть каталог кешу:

- **macOS**: Finder -> `Cmd+Shift+G` -> вставте `~/.cache/opencode`
- **Linux**: видаліть `~/.cache/opencode` (або виконайте `rm -rf ~/.cache/opencode`)
- **Windows**: Натисніть `WIN+R` та вставте `%USERPROFILE%\.cache\opencode`

3. Перезапустіть OpenCode Desktop.

---

### Виправлення проблем з підключенням до сервера

OpenCode Desktop може або запускати власний локальний сервер (за замовчуванням), або підключатися до налаштованої вами URL-адреси сервера.

Якщо ви бачите діалог **"Connection Failed"** (або застосунок ніколи не проходить повз екран завантаження), перевірте наявність користувацької URL-адреси сервера.

#### Очистіть URL сервера за замовчуванням у десктопному застосунку

З головного екрана натисніть назву сервера (з індикатором статусу), щоб відкрити вибір сервера. У розділі **Default server** натисніть **Clear**.

#### Видаліть `server.port` / `server.hostname` з вашої конфігурації

Якщо ваш `opencode.json(c)` містить розділ `server`, тимчасово видаліть його та перезапустіть десктопний застосунок.

#### Перевірте змінні середовища

Якщо у вас встановлено `OPENCODE_PORT` у середовищі, десктопний застосунок спробує використати цей порт для локального сервера.

- Скиньте `OPENCODE_PORT` (або виберіть вільний порт) та перезапустіть.

---

### Linux: проблеми з Wayland / X11

На Linux деякі налаштування Wayland можуть спричиняти порожні вікна або помилки композитора.

- Якщо ви на Wayland і застосунок порожній/вилітає, спробуйте запустити з `OC_ALLOW_WAYLAND=1`.
- Якщо це погіршує ситуацію, видаліть його та спробуйте запустити в сеансі X11.

---

### Windows: середовище виконання WebView2

На Windows OpenCode Desktop потребує **WebView2 Runtime** від Microsoft Edge. Якщо застосунок відкривається з порожнім вікном або не запускається, встановіть/оновіть WebView2 та спробуйте знову.

---

### Windows: загальні проблеми з продуктивністю

Якщо ви відчуваєте повільну роботу, проблеми з доступом до файлів або терміналом на Windows, спробуйте використовувати [WSL (Підсистема Windows для Linux)](/docs/windows-wsl). WSL надає середовище Linux, яке працює більш безшовно з функціями OpenCode.

---

### Сповіщення не відображаються

OpenCode Desktop показує системні сповіщення лише коли:

- сповіщення ввімкнені для OpenCode у налаштуваннях вашої ОС, та
- вікно застосунку не зосереджене.

---

### Скидання сховища десктопного застосунку (останній засіб)

Якщо застосунок не запускається і ви не можете очистити налаштування з інтерфейсу, скиньте збережений стан десктопного застосунку.

1. Закрийте OpenCode Desktop.
2. Знайдіть та видаліть ці файли (вони знаходяться в каталозі даних застосунку OpenCode Desktop):

- `opencode.settings.dat` (URL сервера за замовчуванням у десктопному застосунку)
- `opencode.global.dat` та `opencode.workspace.*.dat` (стан UI, наприклад, нещодавні сервери/проєкти)

Щоб швидко знайти каталог:

- **macOS**: Finder -> `Cmd+Shift+G` -> `~/Library/Application Support` (потім знайдіть файли вище)
- **Linux**: знайдіть у `~/.local/share` файли вище
- **Windows**: Натисніть `WIN+R` -> `%APPDATA%` (потім знайдіть файли вище)

## Типові проблеми

Ось кілька типових проблем та способи їх вирішення.

---

### OpenCode не запускається

1. Перевірте журнали на наявність повідомлень про помилки
2. Спробуйте запустити з `--print-logs`, щоб побачити вивід у терміналі
3. Переконайтеся, що у вас остання версія за допомогою `opencode upgrade`

---

### Проблеми з аутентифікацією

1. Спробуйте повторно авторизуватися за допомогою команди `/connect` у TUI
2. Перевірте, чи ваші ключі API дійсні
3. Переконайтеся, що ваша мережа дозволяє підключення до API провайдера

---

### Модель недоступна

1. Перевірте, чи ви авторизувалися з провайдером
2. Переконайтеся, що назва моделі у вашій конфігурації правильна
3. Деякі моделі можуть вимагати спеціального доступу або підписок

Якщо ви отримуєте `ProviderModelNotFoundError`, швидше за все, ви неправильно
посилаєтеся на модель десь.
Моделі повинні посилатися так: `<providerId>/<modelId>`

Приклади:

- `openai/gpt-4.1`
- `openrouter/google/gemini-2.5-flash`
- `opencode/kimi-k2`

Щоб дізнатися, до яких моделей у вас є доступ, виконайте `opencode models`

---

### ProviderInitError

Якщо ви отримуєте ProviderInitError, ймовірно, у вас недійсна або пошкоджена конфігурація.

Щоб вирішити це:

1. Спочатку переконайтеся, що ваш провайдер налаштований правильно, дотримуючись [посібника з провайдерів](/docs/providers)
2. Якщо проблема не зникає, спробуйте очистити збережену конфігурацію:

   ```bash
   rm -rf ~/.local/share/opencode
   ```

   На Windows натисніть `WIN+R` та видаліть: `%USERPROFILE%\.local\share\opencode`

3. Повторно авторизуйтеся з вашим провайдером за допомогою команди `/connect` у TUI.

---

### AI_APICallError та проблеми з пакунками провайдера

Якщо ви отримуєте помилки виклику API, це може бути через застарілі пакунки провайдера. OpenCode динамічно встановлює пакунки провайдерів (OpenAI, Anthropic, Google тощо) за потреби та кешує їх локально.

Щоб вирішити проблеми з пакунками провайдера:

1. Очистіть кеш пакунків провайдера:

   ```bash
   rm -rf ~/.cache/opencode
   ```

   На Windows натисніть `WIN+R` та видаліть: `%USERPROFILE%\.cache\opencode`

2. Перезапустіть opencode, щоб переінсталювати останні пакунки провайдера

Це змусить opencode завантажити найновіші версії пакунків провайдера, що часто вирішує проблеми сумісності з параметрами моделей та змінами API.

---

### Копіювання/вставка не працює на Linux

Користувачам Linux потрібно мати одну з наступних утиліт для буфера обміну, щоб функція копіювання/вставки працювала:

**Для систем X11:**

```bash
apt install -y xclip
# або
apt install -y xsel
```

**Для систем Wayland:**

```bash
apt install -y wl-clipboard
```

**Для безголових середовищ:**

```bash
apt install -y xvfb
# та запустіть:
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```

OpenCode визначить, чи ви використовуєте Wayland, і надасть перевагу `wl-clipboard`, інакше він спробує знайти інструменти для буфера обміну в порядку: `xclip` та `xsel`.
