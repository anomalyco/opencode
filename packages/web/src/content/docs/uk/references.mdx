title: Ресурси

---

Ресурси (references) надають OpenCode доступ до каталогів поза поточним проєктом. Використовуйте їх, щоб зробити документацію, спільні бібліотеки, приклади або інший репозиторій доступними під час роботи.

Ресурси налаштовуються за псевдонімами у `opencode.json` або `opencode.jsonc`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Використовувати для поведінки продукту та угод щодо документації",
    },
    "sdk": {
      "repository": "anomalyco/opencode-sdk-js",
      "branch": "main",
      "description": "Використовувати для деталей реалізації JavaScript SDK",
    },
  },
}
```

---

## Локальні каталоги

Використовуйте `path` для посилання на локальний каталог.

```jsonc title="opencode.jsonc"
{
  "references": {
    "docs": {
      "path": "../docs",
    },
  },
}
```

Шляхи можуть бути:

- Відносними до файлу конфігурації, що визначає ресурс
- Абсолютними, наприклад `/home/user/docs`
- Відносними до вашого домашнього каталогу, наприклад `~/docs`

Ви також можете використовувати скорочення у вигляді рядка:

```jsonc title="opencode.jsonc"
{
  "references": {
    "docs": "../docs",
  },
}
```

## Git-репозиторії

Використовуйте `repository` для посилання на Git-репозиторій. OpenCode матеріалізує репозиторій у локальному кеші та робить вихідний код доступним як каталог ресурсу.

```jsonc title="opencode.jsonc"
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

`repository` приймає Git-URL, посилання хост/шлях та скорочення GitHub `owner/repo`. Необов'язкове поле `branch` вибирає гілку або ревізію. Без `branch` OpenCode використовує гілку за замовчуванням репозиторію.

Ви можете використовувати скорочення у вигляді рядка, якщо вам не потрібна гілка, опис чи інші параметри:

```jsonc title="opencode.jsonc"
{
  "references": {
    "effect": "Effect-TS/effect",
  },
}
```

:::note
Git-ресурси оновлюються асинхронно. Щойно налаштований репозиторій може потребувати часу для завершення клонування або оновлення.
:::

## Опис використання

Додайте `description`, щоб пояснити, коли агенту слід використовувати ресурс.

```jsonc title="opencode.jsonc"
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Використовувати при реалізації UI-компонентів або токенів дизайну",
    },
  },
}
```

OpenCode включає ресурси з описами в контекст агента. Описи мають бути короткими та достатньо конкретними, щоб розрізняти ресурси зі схожим вмістом. Ресурси без описів залишаються доступними через автодоповнення та пряме використання, але не рекламуються агентам.

---

## Приховування записів автодоповнення

Встановіть `hidden` у `true`, щоб прибрати ресурс із автодоповнення `@` у TUI.

```jsonc title="opencode.jsonc"
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Використовувати для деталей внутрішньої реалізації",
      "hidden": true,
    },
  },
}
```

`hidden` впливає лише на автодоповнення. Прихований ресурс з описом залишається включеним у контекст агента.

---

## Використання ресурсів

Налаштовані ресурси з'являються в автодоповненні `@` у TUI. Введіть `@alias`, щоб прикріпити корінь ресурсу, або `@alias/` для пошуку файлів всередині нього.

```text
Порівняйте цю реалізацію з @sdk/src/client.ts
```

Агенти також отримують розпізнані шляхи та описи налаштованих ресурсів, що мають описи, у своєму системному контексті, тому вони можуть переглянути ресурс, коли це доречно, без вашого ручного прикріплення.

OpenCode автоматично дозволяє каталогам ресурсів проходити через межі дозволів для зовнішніх каталогів. Звичайні дозволи інструментів все ще діють; наприклад, агент, який не може редагувати файли, не отримує доступ до редагування лише тому, що каталог налаштовано як ресурс.

## Поля налаштувань

| Поле          | Локальний | Git | Опис                                               |
| ------------- | --------- | --- | -------------------------------------------------- |
| `path`        | Так       | Ні  | Локальний каталог ресурсу                          |
| `repository`  | Ні        | Так | Git-URL, хост/шлях або GitHub `owner/repo`         |
| `branch`      | Ні        | Так | Необов'язкова гілка або ревізія Git                |
| `description` | Так       | Так | Інструкція, коли використовувати ресурс            |
| `hidden`      | Так       | Так | Приховати ресурс з автодоповнення `@` у TUI       |

Псевдоніми ресурсів не можуть бути порожніми або містити `/`, пробіли, зворотні лапки чи коми.
