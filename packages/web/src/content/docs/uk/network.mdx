OpenCode підтримує стандартні змінні середовища проксі та власні сертифікати для корпоративних мережевих середовищ.

---

## Проксі

OpenCode поважає стандартні змінні середовища проксі.

```bash
# HTTPS проксі (рекомендовано)
export HTTPS_PROXY=https://proxy.example.com:8080

# HTTP проксі (якщо HTTPS недоступний)
export HTTP_PROXY=http://proxy.example.com:8080

# Обхід проксі для локального сервера (обов'язково)
export NO_PROXY=localhost,127.0.0.1
```

:::caution
TUI спілкується з локальним HTTP-сервером. Ви повинні обійти проксі для цього з'єднання, щоб запобігти циклічній маршрутизації.
:::

Ви можете налаштувати порт та ім'я хоста сервера за допомогою [прапорців CLI](/docs/cli#run).

---

### Аутентифікація

Якщо ваш проксі потребує базової аутентифікації, додайте облікові дані в URL.

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

:::caution
Уникайте жорсткого кодування паролів. Використовуйте змінні середовища або безпечне сховище облікових даних.
:::

Для проксі, що потребують розширеної аутентифікації, як-от NTLM або Kerberos, розгляньте можливість використання LLM Gateway, який підтримує ваш метод аутентифікації.

---

## Власні сертифікати

Якщо ваше підприємство використовує власні CA для HTTPS-з'єднань, налаштуйте OpenCode для їх довіри.

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

Це працює як для проксі-з'єднань, так і для прямого доступу до API.
