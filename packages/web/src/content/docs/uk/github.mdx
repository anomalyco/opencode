---
title: GitHub
description: Використовуйте OpenCode в GitHub issues та pull-request.
---

OpenCode інтегрується з вашим робочим процесом GitHub. Згадайте `/opencode` або `/oc` у вашому коментарі, і OpenCode виконає завдання у вашому GitHub Actions runner.

---

## Можливості

- **Тріаж issues**: Попросіть OpenCode розібратися з issue та пояснити його вам.
- **Виправлення та впровадження**: Попросіть OpenCode виправити issue або реалізувати функцію. Він працюватиме в новій гілці та створить PR з усіма змінами.
- **Безпека**: OpenCode працює всередині ваших GitHub runner.

---

## Встановлення

Запустіть наступну команду в проєкті, який знаходиться в GitHub репозиторії:

```bash
opencode github install
```

Це проведе вас через встановлення GitHub додатка, створення workflow та налаштування секретів.

---

### Ручне налаштування

Або ви можете налаштувати це вручну.

1. **Встановіть GitHub додаток**

   Перейдіть на [**github.com/apps/opencode-agent**](https://github.com/apps/opencode-agent). Переконайтеся, що він встановлений на цільовому репозиторії.

2. **Додайте workflow**

   Додайте наступний файл workflow до `.github/workflows/opencode.yml` у вашому репозиторії. Переконайтеся, що встановлено відповідний `model` та необхідні API-ключі в `env`.

   ```yml title=".github/workflows/opencode.yml" {24,26}
   name: opencode

   on:
     issue_comment:
       types: [created]
     pull_request_review_comment:
       types: [created]

   jobs:
     opencode:
       if: |
         contains(github.event.comment.body, '/oc') ||
         contains(github.event.comment.body, '/opencode')
       runs-on: ubuntu-latest
       permissions:
         id-token: write
       steps:
          - name: Checkout repository
            uses: actions/checkout@v6
            with:
              fetch-depth: 1
              persist-credentials: false

          - name: Run OpenCode
           uses: anomalyco/opencode/github@latest
           env:
             ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
           with:
             model: anthropic/claude-sonnet-4-20250514
             # share: true
             # github_token: xxxx
   ```

3. **Збережіть API-ключі в секретах**

   У налаштуваннях вашої організації або проєкту розгорніть **Secrets and variables** ліворуч та виберіть **Actions**. Додайте необхідні API-ключі.

## Конфігурація

- `model`: Модель для використання з OpenCode. Має формат `provider/model`. Це **обов'язково**.
- `agent`: Агент для використання. Має бути первинним агентом. Використовує `default_agent` з конфігурації або `"build"`, якщо не знайдено.
- `share`: Чи поширювати сесію OpenCode. За замовчуванням **true** для публічних репозиторіїв.
- `prompt`: Опціональний кастомний промпт для перевизначення поведінки за замовчуванням. Використовуйте це, щоб налаштувати, як OpenCode обробляє запити.
- `token`: Опціональний GitHub токен доступу для виконання операцій, таких як створення коментарів, коміт змін та відкриття pull request. За замовчуванням OpenCode використовує токен доступу встановлення від GitHub додатка OpenCode, тому коміти, коментарі та pull request виглядають як такі, що надходять від додатка.

  Альтернативно, ви можете використовувати вбудований [`GITHUB_TOKEN`](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token) GitHub Actions runner без встановлення GitHub додатка OpenCode. Просто надайте необхідні дозволи у вашому workflow:

  ```yaml
  permissions:
    id-token: write
    contents: write
    pull-requests: write
    issues: write
  ```

  Ви також можете використовувати [персональні токени доступу](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)(PAT), якщо бажаєте.

## Підтримувані події

OpenCode може бути запущений наступними подіями GitHub:

| Тип події                    | Тригер                           | Деталі                                                                                                           |
| ----------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `issue_comment`               | Коментар до issue або PR              | Згадайте `/opencode` або `/oc` у коментарі. OpenCode читає контекст і може створювати гілки, відкривати PR або відповідати. |
| `pull_request_review_comment` | Коментар до конкретних рядків коду в PR | Згадайте `/opencode` або `/oc` під час рев'ю коду. OpenCode отримує шлях до файлу, номери рядків та контекст diff.   |
| `issues`                      | Issue відкрито або відредаговано                 | Автоматично запускати OpenCode при створенні або зміні issues. Вимагає `prompt`.                      |
| `pull_request`                | PR відкрито або оновлено                   | Автоматично запускати OpenCode при відкритті, синхронізації або перевідкритті PR. Корисно для автоматизованих рев'ю.      |
| `schedule`                    | Розклад на основі Cron                    | Запускати OpenCode за розкладом. Вимагає `prompt`. Результат у logs та PRs.        |
| `workflow_dispatch`           | Ручний запуск з інтерфейсу GitHub UI          | Запустити OpenCode на вимогу через вкладку Actions. Вимагає `prompt`. Результат у logs та PRs.                 |

### Приклад розкладу

Запустіть OpenCode за розкладом для виконання автоматизованих завдань:

```yaml title=".github/workflows/opencode-scheduled.yml"
name: Scheduled OpenCode Task

on:
  schedule:
    - cron: "0 9 * * 1" # Кожного понеділка о 9:00 UTC

jobs:
  opencode:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          persist-credentials: false

      - name: Run OpenCode
        uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review the codebase for any TODO comments and create a summary.
            If you find issues worth addressing, open an issue to track them.
```

Для запланованих подій `prompt` є **обов'язковим**, оскільки немає коментаря, з якого можна витягти інструкції. Заплановані workflow запускаються без контексту користувача для перевірки дозволів, тому workflow повинен надавати `contents: write` та `pull-requests: write`, якщо ви очікуєте, що OpenCode створюватиме гілки або PR.

### Приклад Pull Request

Автоматичне рев'ю PR при їх відкритті або оновленні:

```yaml title=".github/workflows/opencode-review.yml"
name: opencode-review

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
      pull-requests: read
      issues: read
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false
      - uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          use_github_token: true
          prompt: |
            Review this pull request:
            - Check for code quality issues
            - Look for potential bugs
            - Suggest improvements
```

Для подій `pull_request`, якщо `prompt` не надано, OpenCode за замовчуванням виконує рев'ю pull request.

### Приклад тріажу Issues

Автоматичний тріаж нових issues. Цей приклад фільтрує облікові записи старші 30 днів для зменшення спаму:

```yaml title=".github/workflows/opencode-triage.yml"
name: Issue Triage

on:
  issues:
    types: [opened]

jobs:
  triage:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Check account age
        id: check
        uses: actions/github-script@v7
        with:
          script: |
            const user = await github.rest.users.getByUsername({
              username: context.payload.issue.user.login
            });
            const created = new Date(user.data.created_at);
            const days = (Date.now() - created) / (1000 * 60 * 60 * 24);
            return days >= 30;
          result-encoding: string

      - uses: actions/checkout@v6
        if: steps.check.outputs.result == 'true'
        with:
          persist-credentials: false

      - uses: anomalyco/opencode/github@latest
        if: steps.check.outputs.result == 'true'
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review this issue. If there's a clear fix or relevant docs:
            - Provide documentation links
            - Add error handling guidance for code examples
            Otherwise, do not comment.
```

Для подій `issues` `prompt` є **обов'язковим**, оскільки немає коментаря, з якого можна витягти інструкції.

## Користувацькі промпти

Перевизначте промпт за замовчуванням, щоб налаштувати поведінку OpenCode для вашого workflow.

```yaml title=".github/workflows/opencode.yml"
- uses: anomalyco/opencode/github@latest
  with:
    model: anthropic/claude-sonnet-4-5
    prompt: |
      Review this pull request:
      - Check for code quality issues
      - Look for potential bugs
      - Suggest improvements
```

Це корисно для застосування конкретних критеріїв рев'ю, стандартів кодування або фокусних областей, актуальних для вашого проєкту.

## Приклади

Ось кілька прикладів використання OpenCode в GitHub.

- **Пояснити issue**

  Додайте цей коментар у GitHub issue.

  ```
  /opencode explain this issue
  ```

  OpenCode прочитає весь тред, включаючи всі коментарі, та відповість з чітким поясненням.

- **Виправити issue**

  У GitHub issue напишіть:

  ```
  /opencode fix this
  ```

  OpenCode створить нову гілку, реалізує зміни та відкриє PR зі змінами.

- **Рев'ю PR та внесення змін**

  Залиште наступний коментар на GitHub PR.

  ```
  Delete the attachment from S3 when the note is removed /oc
  ```

  OpenCode реалізує запитувану зміну та закомітить її в той самий PR.

- **Рев'ю конкретних рядків коду**

  Залиште коментар безпосередньо на рядках коду у вкладці "Files" PR. OpenCode автоматично визначає файл, номери рядків та контекст diff для надання точних відповідей.

  ```
  [Comment on specific lines in Files tab]
  /oc add error handling here
  ```

  При коментуванні конкретних рядків OpenCode отримує:
  - Точний файл, що рев'юється
  - Конкретні рядки коду
  - Навколишній контекст diff
  - Інформацію про номери рядків

  Це дозволяє робити більш цільові запити без необхідності вказувати шляхи до файлів або номери рядків вручну.
