---
title: Агенти
description: Налаштовуйте та використовуйте спеціалізованих агентів.
---

Агенти — це спеціалізовані AI-асистенти, які можна налаштувати для конкретних завдань та робочих процесів. Вони дозволяють створювати цілеспрямовані інструменти з власними промптами, моделями та доступом до інструментів.

:::tip
Використовуйте агента plan для аналізу коду та перегляду пропозицій без внесення змін до коду.
:::

Ви можете перемикатися між агентами під час сесії або викликати їх за допомогою @ згадки.

---

## Типи

У OpenCode є два типи агентів: первинні агенти та сабагенти.

---

### Первинні агенти

Первинні агенти — це основні асистенти, з якими ви безпосередньо взаємодієте. Ви можете перемикатися між ними за допомогою клавіші **Tab** або налаштованої комбінації `switch_agent`. Ці агенти обробляють вашу основну розмову. Доступ до інструментів налаштовується через дозволи — наприклад, Build має всі інструменти увімкнено, тоді як Plan обмежений.

:::tip
Ви можете використовувати клавішу **Tab**, щоб перемикатися між первинними агентами під час сесії.
:::

OpenCode постачається з двома вбудованими первинними агентами: **Build** та **Plan**. Ми
розглянемо їх нижче.

---

### Сабагенти

Сабагенти — це спеціалізовані асистенти, яких первинні агенти можуть викликати для конкретних завдань. Ви також можете викликати їх вручну за допомогою **@ згадки** у ваших повідомленнях.

OpenCode постачається з трьома вбудованими сабагентами: **General**, **Explore** та **Scout**. Ми розглянемо їх нижче.

---

## Вбудовані

OpenCode постачається з двома вбудованими первинними агентами та трьома вбудованими сабагентами.

---

### Build

_Режим_: `primary`

Build — це **стандартний** первинний агент з усіма увімкненими інструментами. Це стандартний агент для розробницької роботи, де вам потрібен повний доступ до файлових операцій та системних команд.

---

### Plan

_Режим_: `primary`

Обмежений агент, призначений для планування та аналізу. Ми використовуємо систему дозволів, щоб надати вам більше контролю та запобігти непередбаченим змінам.
За замовчуванням все наступне встановлено на `ask`:

- `file edits`: Всі записи, патчі та редагування
- `bash`: Всі bash команди

Цей агент корисний, коли ви хочете, щоб LLM аналізував код, пропонував зміни або створював плани без внесення фактичних модифікацій у вашу кодову базу.

---

### General

_Режим_: `subagent`

Універсальний агент для дослідження складних питань та виконання багатокрокових завдань. Має повний доступ до інструментів (крім todo), тому може вносити зміни до файлів, коли потрібно. Використовуйте його для запуску кількох одиниць роботи паралельно.

---

### Explore

_Режим_: `subagent`

Швидкий, лише для читання агент для дослідження кодових баз. Не може змінювати файли. Використовуйте його, коли потрібно швидко знайти файли за патернами, шукати код за ключовими словами або відповідати на питання про кодову базу.

---

### Scout

_Режим_: `subagent`

Агент лише для читання для зовнішньої документації та дослідження залежностей. Використовуйте його, коли потрібно клонувати репозиторій залежності в керований кеш OpenCode, переглянути вихідний код бібліотеки або перехресно посилатися на локальний код з upstream реалізаціями без модифікації вашої робочої області.

---

### Compaction

_Режим_: `primary`

Прихований системний агент, який ущільнює довгий контекст у менший підсумок. Він запускається автоматично, коли потрібно, і не вибирається в інтерфейсі.

---

### Title

_Режим_: `primary`

Прихований системний агент, який генерує короткі назви сесій. Він запускається автоматично і не вибирається в інтерфейсі.

---

### Summary

_Режим_: `primary`

Прихований системний агент, який створює підсумки сесій. Він запускається автоматично і не вибирається в інтерфейсі.

---

## Використання

1. Для первинних агентів використовуйте клавішу **Tab**, щоб перемикатися між ними під час сесії. Ви також можете використовувати налаштовану комбінацію `switch_agent`.

2. Сабагенти можна викликати:
   - **Автоматично** первинними агентами для спеціалізованих завдань на основі їхніх описів.
   - Вручну за допомогою **@ згадки** сабагента у вашому повідомленні. Наприклад.

     ```txt frame="none"
     @general help me search for this function
     ```

3. **Навігація між сесіями**: Коли сабагенти створюють дочірні сесії, використовуйте `session_child_first` (за замовчуванням: **\<Leader>+Down**), щоб увійти в першу дочірню сесію з батьківської.

4. Перебуваючи в дочірній сесії, використовуйте:
   - `session_child_cycle` (за замовчуванням: **Right**), щоб перейти до наступної дочірньої сесії
   - `session_child_cycle_reverse` (за замовчуванням: **Left**), щоб перейти до попередньої дочірньої сесії
   - `session_parent` (за замовчуванням: **Up**), щоб повернутися до батьківської сесії

   Це дозволяє перемикатися між основною розмовою та спеціалізованою роботою сабагента.

## Налаштування

Ви можете налаштувати вбудованих агентів або створити власних через конфігурацію. Агентів можна налаштовувати двома способами:

---

### JSON

Налаштовуйте агентів у вашому файлі конфігурації `opencode.json`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "{file:./prompts/build.txt}",
      "permission": {
        "edit": "allow",
        "bash": "allow"
      }
    },
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-haiku-4-20250514",
      "permission": {
        "edit": "deny",
        "bash": "deny"
      }
    },
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "You are a code reviewer. Focus on security, performance, and maintainability.",
      "permission": {
        "edit": "deny"
      }
    }
  }
}
```

---

### Markdown

Ви також можете визначати агентів за допомогою markdown файлів. Розмістіть їх у:

- Глобально: `~/.config/opencode/agents/`
- На проєкт: `.opencode/agents/`

```markdown title="~/.config/opencode/agents/review.md"
---
description: Reviews code for quality and best practices
mode: subagent
model: anthropic/claude-sonnet-4-20250514
temperature: 0.1
permission:
  edit: deny
  bash: deny
---

You are in code review mode. Focus on:

- Code quality and best practices
- Potential bugs and edge cases
- Performance implications
- Security considerations

Provide constructive feedback without making direct changes.
```

Ім'я markdown файлу стає ім'ям агента. Наприклад, `review.md` створює агента `review`.

---

## Опції

Розглянемо ці опції конфігурації детально.

---

### Description

Використовуйте опцію `description`, щоб надати короткий опис того, що робить агент і коли його використовувати.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "description": "Reviews code for best practices and potential issues"
    }
  }
}
```

Це **обов'язкова** опція конфігурації.

---

### Temperature

Контролюйте випадковість та креативність відповідей LLM за допомогою конфігурації `temperature`.

Нижчі значення роблять відповіді більш фокусованими та детермінованими, тоді як вищі значення підвищують креативність та варіативність.

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "temperature": 0.1
    },
    "creative": {
      "temperature": 0.8
    }
  }
}
```

Значення температури зазвичай варіюються від 0.0 до 1.0:

- **0.0-0.2**: Дуже фокусовані та детерміновані відповіді, ідеально для аналізу коду та планування
- **0.3-0.5**: Збалансовані відповіді з деякою креативністю, добре для загальних завдань розробки
- **0.6-1.0**: Більш креативні та різноманітні відповіді, корисні для мозкового штурму та дослідження

```json title="opencode.json"
{
  "agent": {
    "analyze": {
      "temperature": 0.1,
      "prompt": "{file:./prompts/analysis.txt}"
    },
    "build": {
      "temperature": 0.3
    },
    "brainstorm": {
      "temperature": 0.7,
      "prompt": "{file:./prompts/creative.txt}"
    }
  }
}
```

Якщо температура не вказана, OpenCode використовує значення за замовчуванням для конкретної моделі; зазвичай 0 для більшості моделей, 0.55 для моделей Qwen.

---

### Max steps

Контролюйте максимальну кількість агентських ітерацій, які агент може виконати, перш ніж буде змушений відповісти лише текстом. Це дозволяє користувачам, які бажають контролювати витрати, встановити ліміт на агентські дії.

Якщо це не встановлено, агент продовжить ітерувати, поки модель не вирішить зупинитися або користувач не перерве сесію.

```json title="opencode.json"
{
  "agent": {
    "quick-thinker": {
      "description": "Fast reasoning with limited iterations",
      "prompt": "You are a quick thinker. Solve problems with minimal steps.",
      "steps": 5
    }
  }
}
```

Коли ліміт досягнуто, агент отримує спеціальний системний промпт, який інструктує його відповісти підсумком своєї роботи та рекомендованими завданнями, що залишилися.

:::caution
Застаріле поле `maxSteps` є нерекомендованим. Використовуйте `steps` замість нього.
:::

---

### Disable

Встановіть значення `true`, щоб вимкнути агента.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "disable": true
    }
  }
}
```

---

### Prompt

Вкажіть файл користувацького системного промпту для цього агента за допомогою конфігурації `prompt`. Файл промпту має містити інструкції, специфічні для призначення агента.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "prompt": "{file:./prompts/code-review.txt}"
    }
  }
}
```

Цей шлях є відносним до місця розташування файлу конфігурації. Тому це працює як для глобальної конфігурації OpenCode, так і для проєктно-специфічної.

---

### Model

Використовуйте конфігурацію `model`, щоб перевизначити модель для цього агента. Корисно для використання різних моделей, оптимізованих для різних завдань. Наприклад, швидша модель для планування, більш потужна модель для реалізації.

:::tip
Якщо ви не вказуєте модель, первинні агенти використовують [глобально налаштовану модель](/docs/config#models), тоді як сабагенти використовуватимуть модель первинного агента, який викликав сабагента.
:::

```json title="opencode.json"
{
  "agent": {
    "plan": {
      "model": "anthropic/claude-haiku-4-20250514"
    }
  }
}
```

ID моделі у вашому конфігу OpenCode використовує формат `provider/model-id`. Наприклад, якщо ви використовуєте [OpenCode Zen](/docs/zen), ви б використали `opencode/gpt-5.1-codex` для GPT 5.1 Codex.

---

### Tools (нерекомендовано)

`tools` є **нерекомендованим**. Віддавайте перевагу полю [`permission`](#permissions) агента для нових конфігурацій, оновлень та більш тонкого контролю.

Дозволяє контролювати, які інструменти доступні в цьому агенту. Ви можете ввімкнути або вимкнути конкретні інструменти, встановивши їх у `true` або `false`. У конфігурації `tools` агента `true` еквівалентно дозволу `{"*": "allow"}`, а `false` еквівалентно дозволу `{"*": "deny"}`.

```json title="opencode.json" {3-6,9-12}
{
  "$schema": "https://opencode.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

:::note
Конфігурація, специфічна для агента, перевизначає глобальну конфігурацію.
:::

Ви також можете використовувати wildcards у застарілих записах `tools`, щоб контролювати кілька інструментів одночасно. Наприклад, щоб вимкнути всі інструменти з MCP сервера:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "readonly": {
      "tools": {
        "mymcp_*": false,
        "write": false,
        "edit": false
      }
    }
  }
}
```

[Дізнатися більше про інструменти](/docs/tools).

### Permissions

Ви можете налаштувати дозволи для керування тим, які дії може виконувати агент. Кожен ключ дозволу може бути встановлений на:

- `"ask"` — Запитати схвалення перед запуском інструмента
- `"allow"` — Дозволити всі операції без схвалення
- `"deny"` — Вимкнути інструмент

Доступні ключі дозволів:

| Ключ                  | Інструменти, які контролюються                                   |
| -------------------- | ---------------------------------------------------------------- |
| `read`               | `read`                                                           |
| `edit`               | `write`, `edit`, `apply_patch`                                   |
| `glob`               | `glob`                                                           |
| `grep`               | `grep`                                                           |
| `list`               | `list`                                                           |
| `bash`               | `bash`                                                           |
| `task`               | `task`                                                           |
| `external_directory` | Будь-який інструмент, що читає або записує файли за межами робочої директорії проєкту |
| `todowrite`          | `todowrite`, `todoread`                                          |
| `webfetch`           | `webfetch`                                                       |
| `websearch`          | `websearch`                                                      |
| `lsp`                | `lsp`                                                            |
| `skill`              | `skill`                                                          |
| `question`           | `question`                                                       |
| `doom_loop`          | Промпти відновлення, коли агент виглядає застряглим                     |

`read`, `edit`, `glob`, `grep`, `list`, `bash`, `task`, `external_directory`, `lsp` та `skill` приймають або скорочену дію (`"allow" | "ask" | "deny"`), або об'єкт glob/патерн → дія для тонкого контролю. Інші ключі приймають лише скорочену дію.

:::note
Ключі дозволів зіставляються як wildcard патерни з назвою базового інструмента, тому той самий синтаксис працює для вбудованих, користувацьких та MCP інструментів — наприклад, `"mymcp_*": "deny"` забороняє кожен інструмент з MCP сервера, а `"mymcp_search": "ask"` націлюється на один конкретний.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  }
}
```

Ви можете перевизначити ці дозволи для кожного агента.

```json title="opencode.json" {3-5,8-10}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny"
  },
  "agent": {
    "build": {
      "permission": {
        "edit": "ask"
      }
    }
  }
}
```

Ви також можете встановлювати дозволи в Markdown агентах.

```markdown title="~/.config/opencode/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
    "grep *": allow
  webfetch: deny
---

Only analyze code and suggest changes.
```

Ви можете встановлювати дозволи для конкретних bash команд.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git push": "ask",
          "grep *": "allow"
        }
      }
    }
  }
}
```

Це може приймати glob патерн.

```json title="opencode.json" {7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git *": "ask"
        }
      }
    }
  }
}
```

І ви також можете використовувати wildcard `*` для керування дозволами для всіх команд.
Оскільки останнє співпадаюче правило має пріоритет, розмістіть wildcard `*` першим, а специфічні правила після нього.

```json title="opencode.json" {8}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status *": "allow"
        }
      }
    }
  }
}
```

[Дізнатися більше про дозволи](/docs/permissions).

### Mode

Контролюйте режим агента за допомогою конфігурації `mode`. Опція `mode` використовується для визначення того, як агент може використовуватися.

```json title="opencode.json"
{
  "agent": {
    "review": {
      "mode": "subagent"
    }
  }
}
```

Опція `mode` може бути встановлена на `primary`, `subagent` або `all`. Якщо `mode` не вказано, за замовчуванням використовується `all`.

---

### Hidden

Сховайте сабагента з меню автодоповнення `@` за допомогою `hidden: true`. Корисно для внутрішніх сабагентів, які мають викликатися лише програмно іншими агентами через інструмент Task.

```json title="opencode.json"
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

Це впливає лише на видимість у меню автодоповнення. Приховані агенти все ще можуть викликатися моделлю через інструмент Task, якщо дозволи дозволяють.

:::note
Застосовується лише до агентів з `mode: subagent`.
:::

---

### Task permissions

Контролюйте, яких сабагентів агент може викликати через інструмент Task за допомогою `permission.task`. Використовує glob патерни для гнучкого зіставлення.

```json title="opencode.json"
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

Коли встановлено `deny`, сабагент повністю видаляється з опису інструмента Task, тому модель не намагатиметься його викликати.

:::tip
Правила оцінюються по порядку, і **останнє співпадаюче правило виграє**. У прикладі вище `orchestrator-planner` збігається і з `*` (deny) і з `orchestrator-*` (allow), але оскільки `orchestrator-*` йде після `*`, результатом є `allow`.
:::

:::tip
Користувачі завжди можуть викликати будь-якого сабагента безпосередньо через меню автодоповнення `@`, навіть якщо дозволи завдань агента забороняють це.
:::

---

### Color

Налаштуйте візуальний вигляд агента в інтерфейсі за допомогою опції `color`. Це впливає на те, як агент відображається в інтерфейсі.

Використовуйте дійсний hex колір (напр., `#FF5733`) або колір теми: `primary`, `secondary`, `accent`, `success`, `warning`, `error`, `info`.

```json title="opencode.json"
{
  "agent": {
    "creative": {
      "color": "#ff6b6b"
    },
    "code-reviewer": {
      "color": "accent"
    }
  }
}
```

---

### Top P

Контролюйте різноманітність відповідей за допомогою опції `top_p`. Альтернатива температурі для контролю випадковості.

```json title="opencode.json"
{
  "agent": {
    "brainstorm": {
      "top_p": 0.9
    }
  }
}
```

Значення варіюються від 0.0 до 1.0. Нижчі значення більш фокусовані, вищі значення більш різноманітні.

### Additional

Будь-які інші опції, які ви вказуєте в конфігурації агента, будуть **передані безпосередньо** провайдеру як опції моделі. Це дозволяє використовувати специфічні функції та параметри провайдера.

Наприклад, з моделями міркування OpenAI ви можете контролювати зусилля міркування:

```json title="opencode.json" {6,7}
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "deep-thinker": {
      "description": "Agent that uses high reasoning effort for complex problems",
      "model": "openai/gpt-5",
      "reasoningEffort": "high",
      "textVerbosity": "low"
    }
  }
}
```

Ці додаткові опції є специфічними для моделі та провайдера. Перевірте документацію вашого провайдера для доступних параметрів.

:::tip
Запустіть `opencode models`, щоб побачити список доступних моделей.
:::

## Створення агентів

Ви можете створити нових агентів за допомогою наступної команди:

```bash
opencode agent create
```

Ця інтерактивна команда:

1. Запитає, де зберегти агента; глобально або для проєкту.
2. Опис того, що агент має робити.
3. Згенерує відповідний системний промпт та ідентифікатор.
4. Дозволить вибрати, які дозволи має мати агент (все, що не вибрано, буде заборонено).
5. Нарешті, створить markdown файл з конфігурацією агента.

---

## Варіанти використання

Ось кілька поширених варіантів використання різних агентів.

- **Build agent**: Повна розробницька робота з усіма увімкненими інструментами
- **Plan agent**: Аналіз та планування без внесення змін
- **Review agent**: Рев'ю коду з доступом лише для читання та інструментами документації
- **Debug agent**: Фокус на дослідженні з увімкненими bash та read інструментами
- **Docs agent**: Написання документації з файловими операціями, але без системних команд
