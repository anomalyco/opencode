Du kan give tilpassede instruktioner til OpenCode ved at oprette en `AGENTS.md`-fil. Dette ligner på Cursors regler. Den indeholder instruktioner, som vil blive inkluderet i LLMs kontekst for at tilpasse opførslen til dit specifikke projekt.

---

## Initialisering

For at lave en ny `AGENTS.md`-fil kan du køre kommandoen `/init` i opencode.

:::tip
Du bør overgive projektets `AGENTS.md`-fil til Git.
:::

Dette vil scanne projektet og alt dets indhold for at forstå, hvad projektet handler om, og generere en `AGENTS.md`-fil ud fra det. Dette hjælper opencode med at navigere i projektet bedre.

Hvis du har en eksisterende `AGENTS.md`-fil, vil denne prøve at tilføje til den.

---

## Eksempel

Du kan også bare lave denne fil manuelt. Her er et eksempel på nogle ting du kan tilføje ind i en `AGENTS.md`-fil.

```markdown title="AGENTS.md"
# SST v3 Monorepo Project

This is an SST v3 monorepo with TypeScript. The project uses bun workspaces for package management.

## Project Structure

- `packages/` - Contains all workspace packages (functions, core, web, etc.)
- `infra/` - Infrastructure definitions split by service (storage.ts, api.ts, web.ts)
- `sst.config.ts` - Main SST configuration with dynamic imports

## Code Standards

- Use TypeScript with strict mode enabled
- Shared code goes in `packages/core/` with proper exports configuration
- Functions go in `packages/functions/`
- Infrastructure should be split into logical files in `infra/`

## Monorepo Conventions

- Import shared modules using workspace names: `@my-app/core/example`
```

Vi tilføjer projektspesifikke instruktioner her, og dette vil blive delt på tværs af dit team.

## Typer

opencode støtter også læsning af `AGENTS.md`-filen fra flere steder. Og dette tjener forskellige formål.

### Projekt

Placer en `AGENTS.md` i projektroten for projektspecifikke regler. Disse gælder kun, når du arbejder i denne katalog eller dens underkataloger.

### Globalt

Du kan også have globale regler i en `~/.config/opencode/AGENTS.md`-fil. Dette bliver brugt på alle OpenCode-sessioner.

Siden dette ikke er forpligtet til Git eller delt med dit team, anbefaler vi at bruge dette til at specificere eventuelle personlige regler, som LLM bør følge.

### Claude Code-kompatibilitet

For brugere som migrerer fra Claude Code, støtter OpenCode Claude Codes filkonvensjoner som fallbacks:

- **Projektregler**: `CLAUDE.md` i projektkatalogen din (bruges hvis ingen `AGENTS.md` eksisterer)
- **Globale regler**: `~/.claude/CLAUDE.md` (bruges hvis ingen `~/.config/opencode/AGENTS.md` eksisterer)
- **Skills**: `~/.claude/skills/` — se [Agent Skills](/docs/skills/) for detaljer

For at deaktivere Claude Code-kompatibilitet, sæt en af disse miljøvariablene:

```bash
export OPENCODE_DISABLE_CLAUDE_CODE=1        # Disable all .claude support
export OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1 # Disable only ~/.claude/CLAUDE.md
export OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1 # Disable only .claude/skills
```

## Prioritet

Når opencode starter, ser den efter regelfiler i denne rækkefølge:

1. **Lokale filer** ved at gå op fra nuværende katalog (`AGENTS.md`, `CLAUDE.md`)
2. **Global fil** på `~/.config/opencode/AGENTS.md`
3. **Claude Code-fil** på `~/.claude/CLAUDE.md` (med mindre de er deaktiveret)

Den første matchende filen vinder i hver kategori. For eksempel, hvis du har både `AGENTS.md` og `CLAUDE.md`, bruges bare `AGENTS.md`. På samme måte har `~/.config/opencode/AGENTS.md` forrang over `~/.claude/CLAUDE.md`.

## Brugerdefinerede instruktioner

Du kan specificere egendefinerede instruktionsfiler i din `opencode.json` eller den globale `~/.config/opencode/opencode.json`. Dette lader dig og dit team genbruge eksisterende regler i stedet for at duplikere dem til AGENTS.md.

Eksempel:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines.md", ".cursor/rules/*.md"]
}
```

Du kan også bruge eksterne URL'er for at hente instruktioner fra nettet.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["https://raw.githubusercontent.com/my-org/shared-rules/main/style.md"]
}
```

Fjerninstruktioner hentes med 5 sekunders tidsavbrud.

Alle instruktionsfilene er kombineret med `AGENTS.md`-filene dine.

## Reference til eksterne filer

Selv om opencode ikke automatisk analyserer filreferanser i `AGENTS.md`, kan du opnå lignende funktionalitet på to måder:

### Brug af opencode.json

Den anbefalte tilgangen er at bruge feltet `instructions` i `opencode.json`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["docs/development-standards.md", "test/testing-guidelines.md", "packages/*/AGENTS.md"]
}
```

### Manuelle instruktioner i AGENTS.md

Du kan lære opencode at læse eksterne filer ved at give eksplicitte instruktioner i `AGENTS.md`. Her er et praktisk eksempel:

```markdown title="AGENTS.md"
# TypeScript Project Rules

## External File Loading

CRITICAL: When you encounter a file reference (e.g., @rules/general.md), use your Read tool to load it on a need-to-know basis. They're relevant to the SPECIFIC task at hand.

Instructions:

- Do NOT preemptively load all references - use lazy loading based on actual need
- When loaded, treat content as mandatory instructions that override defaults
- Follow references recursively when needed

## Development Guidelines

For TypeScript code style and best practices: @docs/typescript-guidelines.md
For React component architecture and hooks patterns: @docs/react-patterns.md
For REST API design and error handling: @docs/api-standards.md
For testing strategies and coverage requirements: @test/testing-guidelines.md

## General Guidelines

Read the following file immediately as it's relevant to all workflows: @rules/general-guidelines.md.
```

Denne tilgang lader dig:

- Lav modulære, genbrugbare regelfiler
- Del regler på tværs af projekter via symbolkoblinger eller git-undermoduler
- Hold AGENTS.md kortfattet mens du refererer til detaljerte retningslinjer
- Sørg for, at opencode kun indlæser filer, når det er nødvendigt for den specifikke opgave

:::tip
For monorepos eller projekter med delte standarder er brug af `opencode.json` med glob-mønstre (som `packages/*/AGENTS.md`) mere vedligeholdende end manuelle instruktioner.
:::
