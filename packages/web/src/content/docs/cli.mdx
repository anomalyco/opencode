The CrazyCode CLI by default starts the [TUI](/docs/tui) when run without any arguments.

```bash
crazycode
```

But it also accepts commands as documented on this page. This allows you to interact with CrazyCode programmatically.

```bash
crazycode run "Explain how closures work in JavaScript"
```

---

### tui

Start the CrazyCode terminal user interface.

```bash
crazycode [project]
```

#### Flags

| Flag         | Short | Description                                |
| ------------ | ----- | ------------------------------------------ |
| `--continue` | `-c`  | Continue the last session                  |
| `--session`  | `-s`  | Session ID to continue                     |
| `--prompt`   |       | Prompt to use                              |
| `--model`    | `-m`  | Model to use in the form of provider/model |
| `--agent`    |       | Agent to use                               |
| `--port`     |       | Port to listen on                          |
| `--hostname` |       | Hostname to listen on                      |

## Commands

The CrazyCode CLI also has the following commands.

---

### agent

Manage agents for CrazyCode.

```bash
crazycode agent [command]
```

---

### attach

Attach a terminal to an already running CrazyCode backend server started via `serve` or `web` commands.

```bash
crazycode attach [url]
```

This allows using the TUI with a remote CrazyCode backend. For example:

```bash
# Start the backend server for web/mobile access
crazycode web --port 4096 --hostname 0.0.0.0

# In another terminal, attach the TUI to the running backend
crazycode attach http://10.20.30.40:4096
```

#### Flags

| Flag        | Short | Description                       |
| ----------- | ----- | --------------------------------- |
| `--dir`     |       | Working directory to start TUI in |
| `--session` | `-s`  | Session ID to continue            |

---

#### create

Create a new agent with custom configuration.

```bash
crazycode agent create
```

This command will guide you through creating a new agent with a custom system prompt and tool configuration.

---

#### list

List all available agents.

```bash
crazycode agent list
```

---

### auth

Command to manage credentials and login for providers.

```bash
crazycode auth [command]
```

---

#### login

CrazyCode is powered by the provider list at [Models.dev](https://models.dev), so you can use `crazycode auth login` to configure API keys for any provider you'd like to use. This is stored in `~/.local/share/crazycode/auth.json`.

```bash
crazycode auth login
```

When CrazyCode starts up it loads the providers from the credentials file. And if there are any keys defined in your environments or a `.env` file in your project.

---

#### list

Lists all the authenticated providers as stored in the credentials file.

```bash
crazycode auth list
```

Or the short version.

```bash
crazycode auth ls
```

---

#### logout

Logs you out of a provider by clearing it from the credentials file.

```bash
crazycode auth logout
```

---

### github

Manage the GitHub agent for repository automation.

```bash
crazycode github [command]
```

---

#### install

Install the GitHub agent in your repository.

```bash
crazycode github install
```

This sets up the necessary GitHub Actions workflow and guides you through the configuration process. [Learn more](/docs/github).

---

#### run

Run the GitHub agent. This is typically used in GitHub Actions.

```bash
crazycode github run
```

##### Flags

| Flag      | Description                            |
| --------- | -------------------------------------- |
| `--event` | GitHub mock event to run the agent for |
| `--token` | GitHub personal access token           |

---

### mcp

Manage Model Context Protocol servers.

```bash
crazycode mcp [command]
```

---

#### add

Add an MCP server to your configuration.

```bash
crazycode mcp add
```

This command will guide you through adding either a local or remote MCP server.

---

#### list

List all configured MCP servers and their connection status.

```bash
crazycode mcp list
```

Or use the short version.

```bash
crazycode mcp ls
```

---

#### auth

Authenticate with an OAuth-enabled MCP server.

```bash
crazycode mcp auth [name]
```

If you don't provide a server name, you'll be prompted to select from available OAuth-capable servers.

You can also list OAuth-capable servers and their authentication status.

```bash
crazycode mcp auth list
```

Or use the short version.

```bash
crazycode mcp auth ls
```

---

#### logout

Remove OAuth credentials for an MCP server.

```bash
crazycode mcp logout [name]
```

---

#### debug

Debug OAuth connection issues for an MCP server.

```bash
crazycode mcp debug <name>
```

### models

List all available models from configured providers.

```bash
crazycode models [provider]
```

This command displays all models available across your configured providers in the format `provider/model`.

This is useful for figuring out the exact model name to use in [your config](/docs/config/).

You can optionally pass a provider ID to filter models by that provider.

```bash
crazycode models anthropic
```

#### Flags

| Flag        | Description                                                  |
| ----------- | ------------------------------------------------------------ |
| `--refresh` | Refresh the models cache from models.dev                     |
| `--verbose` | Use more verbose model output (includes metadata like costs) |

Use the `--refresh` flag to update the cached model list. This is useful when new models have been added to a provider and you want to see them in CrazyCode.

```bash
crazycode models --refresh
```

### run

Run crazycode in non-interactive mode by passing a prompt directly.

```bash
crazycode run [message..]
```

This is useful for scripting, automation, or when you want a quick answer without launching the full TUI. For example.

```bash "crazycode run"
crazycode run Explain the use of context in Go
```

You can also attach to a running `crazycode serve` instance to avoid MCP server cold boot times on every run:

```bash
# Start a headless server in one terminal
crazycode serve

# In another terminal, run commands that attach to it
crazycode run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### Flags

| Flag         | Short | Description                                                        |
| ------------ | ----- | ------------------------------------------------------------------ |
| `--command`  |       | The command to run, use message for args                           |
| `--continue` | `-c`  | Continue the last session                                          |
| `--session`  | `-s`  | Session ID to continue                                             |
| `--share`    |       | Share the session                                                  |
| `--model`    | `-m`  | Model to use in the form of provider/model                         |
| `--agent`    |       | Agent to use                                                       |
| `--file`     | `-f`  | File(s) to attach to message                                       |
| `--format`   |       | Format: default (formatted) or json (raw JSON events)              |
| `--title`    |       | Title for the session (uses truncated prompt if no value provided) |
| `--attach`   |       | Attach to a running crazycode server (e.g., http://localhost:4096)  |
| `--port`     |       | Port for the local server (defaults to random port)                |

### serve

Start a headless CrazyCode server for API access. Check out the [server docs](/docs/server) for the full HTTP interface.

```bash
crazycode serve
```

This starts an HTTP server that provides API access to crazycode functionality without the TUI interface.

#### Flags

| Flag         | Description                                |
| ------------ | ------------------------------------------ |
| `--port`     | Port to listen on                          |
| `--hostname` | Hostname to listen on                      |
| `--mdns`     | Enable mDNS discovery                      |
| `--cors`     | Additional browser origin(s) to allow CORS |

---

### session

Manage CrazyCode sessions.

```bash
crazycode session [command]
```

---

#### list

List all CrazyCode sessions.

```bash
crazycode session list
```

##### Flags

| Flag          | Short | Description                          |
| ------------- | ----- | ------------------------------------ |
| `--max-count` | `-n`  | Limit to N most recent sessions      |
| `--format`    |       | Output format: table or json (table) |

---

### stats

Show token usage and cost statistics for your CrazyCode sessions.

```bash
crazycode stats
```

#### Flags

| Flag        | Description                                                                 |
| ----------- | --------------------------------------------------------------------------- |
| `--days`    | Show stats for the last N days (all time)                                   |
| `--tools`   | Number of tools to show (all)                                               |
| `--models`  | Show model usage breakdown (hidden by default). Pass a number to show top N |
| `--project` | Filter by project (all projects, empty string: current project)             |

---

### export

Export session data as JSON.

```bash
crazycode export [sessionID]
```

If you don't provide a session ID, you'll be prompted to select from available sessions.

---

### import

Import session data from a JSON file or CrazyCode share URL.

```bash
crazycode import <file>
```

You can import from a local file or an CrazyCode share URL.

```bash
crazycode import session.json
crazycode import https://opncd.ai/s/abc123
```

```bash

```

This starts an HTTP server and opens a web browser to access CrazyCode through a web interface.

#### Flags

| Flag         | Description                                |
| ------------ | ------------------------------------------ |
| `--port`     | Port to listen on                          |
| `--hostname` | Hostname to listen on                      |
| `--mdns`     | Enable mDNS discovery                      |
| `--cors`     | Additional browser origin(s) to allow CORS |

---

### acp

Start an ACP (Agent Client Protocol) server.

```bash
crazycode acp
```

This command starts an ACP server that communicates via stdin/stdout using nd-JSON.

#### Flags

| Flag         | Description           |
| ------------ | --------------------- |
| `--cwd`      | Working directory     |
| `--port`     | Port to listen on     |
| `--hostname` | Hostname to listen on |

---

### uninstall

Uninstall CrazyCode and remove all related files.

```bash
crazycode uninstall
```

#### Flags

| Flag            | Short | Description                                 |
| --------------- | ----- | ------------------------------------------- |
| `--keep-config` | `-c`  | Keep configuration files                    |
| `--keep-data`   | `-d`  | Keep session data and snapshots             |
| `--dry-run`     |       | Show what would be removed without removing |
| `--force`       | `-f`  | Skip confirmation prompts                   |

---

### upgrade

Updates crazycode to the latest version or a specific version.

```bash
crazycode upgrade [target]
```

To upgrade to the latest version.

```bash
crazycode upgrade
```

To upgrade to a specific version.

```bash
crazycode upgrade v0.1.48
```

#### Flags

| Flag       | Short | Description                                                       |
| ---------- | ----- | ----------------------------------------------------------------- |
| `--method` | `-m`  | The installation method that was used; curl, npm, pnpm, bun, brew |

## Environment variables

CrazyCode can be configured using environment variables.

| Variable                              | Type    | Description                                      |
| ------------------------------------- | ------- | ------------------------------------------------ |
| `CRAZYCODE_AUTO_SHARE`                 | boolean | Automatically share sessions                     |
| `CRAZYCODE_GIT_BASH_PATH`              | string  | Path to Git Bash executable on Windows           |
| `CRAZYCODE_CONFIG`                     | string  | Path to config file                              |
| `CRAZYCODE_CONFIG_DIR`                 | string  | Path to config directory                         |
| `CRAZYCODE_CONFIG_CONTENT`             | string  | Inline json config content                       |
| `CRAZYCODE_DISABLE_AUTOUPDATE`         | boolean | Disable automatic update checks                  |
| `CRAZYCODE_DISABLE_PRUNE`              | boolean | Disable pruning of old data                      |
| `CRAZYCODE_DISABLE_TERMINAL_TITLE`     | boolean | Disable automatic terminal title updates         |
| `CRAZYCODE_PERMISSION`                 | string  | Inlined json permissions config                  |
| `CRAZYCODE_DISABLE_DEFAULT_PLUGINS`    | boolean | Disable default plugins                          |
| `CRAZYCODE_DISABLE_LSP_DOWNLOAD`       | boolean | Disable automatic LSP server downloads           |
| `CRAZYCODE_ENABLE_EXPERIMENTAL_MODELS` | boolean | Enable experimental models                       |
| `CRAZYCODE_DISABLE_AUTOCOMPACT`        | boolean | Disable automatic context compaction             |
| `CRAZYCODE_DISABLE_CLAUDE_CODE`        | boolean | Disable reading from `.claude` (prompt + skills) |
| `CRAZYCODE_DISABLE_CLAUDE_CODE_PROMPT` | boolean | Disable reading `~/.claude/CLAUDE.md`            |
| `CRAZYCODE_DISABLE_CLAUDE_CODE_SKILLS` | boolean | Disable loading `.claude/skills`                 |
| `CRAZYCODE_CLIENT`                     | string  | Client identifier (defaults to `cli`)            |
| `CRAZYCODE_ENABLE_EXA`                 | boolean | Enable Exa web search tools                      |

---

### Experimental

These environment variables enable experimental features that may change or be removed.

| Variable                                        | Type    | Description                             |
| ----------------------------------------------- | ------- | --------------------------------------- |
| `CRAZYCODE_EXPERIMENTAL`                         | boolean | Enable all experimental features        |
| `CRAZYCODE_EXPERIMENTAL_ICON_DISCOVERY`          | boolean | Enable icon discovery                   |
| `CRAZYCODE_EXPERIMENTAL_DISABLE_COPY_ON_SELECT`  | boolean | Disable copy on select in TUI           |
| `CRAZYCODE_EXPERIMENTAL_BASH_MAX_OUTPUT_LENGTH`  | number  | Max output length for bash commands     |
| `CRAZYCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS` | number  | Default timeout for bash commands in ms |
| `CRAZYCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX`        | number  | Max output tokens for LLM responses     |
| `CRAZYCODE_EXPERIMENTAL_FILEWATCHER`             | boolean | Enable file watcher for entire dir      |
| `CRAZYCODE_EXPERIMENTAL_OXFMT`                   | boolean | Enable oxfmt formatter                  |
| `CRAZYCODE_EXPERIMENTAL_LSP_TOOL`                | boolean | Enable experimental LSP tool            |
