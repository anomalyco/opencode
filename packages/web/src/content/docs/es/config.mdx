---

Configure OpenCode con un archivo de configuración JSON.

---

## Formato

OpenCode admite archivos en formato JSON y JSONC (JSON con comentarios).

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Theme configuration
  "theme": "opencode",
  "model": "anthropic/claude-sonnet-4-5",
  "autoupdate": true,
}
```

---

## Ubicaciones

Coloque la configuración en una de varias ubicaciones posibles. Cada una tiene un orden de precedencia distinto.

:::note
Los archivos de configuración se **fusionan;** no se reemplazan.
:::

OpenCode combina la configuración de las ubicaciones indicadas a continuación. Las fuentes posteriores solo anulan las claves en conflicto. Los valores no conflictivos se conservan.

Por ejemplo, si la configuración global define `theme: "opencode"` y `autoupdate: true`, la configuración del proyecto define `model: "anthropic/claude-sonnet-4-5"`, lla configuración final incluirá los tres valores.

---

### Orden de precedencia

Las fuentes de configuración se cargan en este orden. Las fuentes posteriores anulan a las anteriores cuando hay conflicto::

1. **Configuración remota** (desde `.well-known/opencode`): valores predeterminados de la organización
2. **Configuración global** (`~/.config/opencode/opencode.json`): preferencias del usuario
3. **Configuración personalizada** (variable de entorno `OPENCODE_CONFIG`): anulaciones personalizadas
4. **Configuración del proyecto** (`opencode.json` en el proyecto): configuración específica del proyecto
5. Directorios **`.opencode`:** agentes, comandos, complementos
6. **Configuración en línea** (variable de entorno `OPENCODE_CONFIG_CONTENT`): anulaciones en tiempo de ejecución

Esto significa que la configuración del proyecto puede anular los valores globales, y la configuración global puede anular los valores predeterminados de la organización.

:::note
Los directorios `.opencode` y `~/.config/opencode` usan **nombres  de subdirectorios en plural** para los subdirectorios: `agents/`, `commands/`, `modes/`, `plugins/`, `skills/`, `tools/` y `themes/`. También se admiten nombres singulares, como `agent/` por compatibilidad con versiones anteriores.
:::

### Configuración remota

Permita que la organización proporcione una configuración predeterminada mediante el endpoint `.well-known/opencode`. OpenCode obtiene esta configuración automáticamente al autenticarse con un proveedor compatible.

La configuración remota se carga primero y actúa como capa base. Las demás fuentes de configuración, como la global o la del proyecto, pueden anular esos valores.

Por ejemplo, si la organización define servidores MCP deshabilitados de forma predeterminada:

```json title="Remote config from .well-known/opencode"
{
  "mcp": {
    "jira": {
      "type": "remote",
      "url": "https://jira.example.com/mcp",
      "enabled": false
    }
  }
}
```

Puede habilitar servidores específicos en la configuración local:

```json title="opencode.json"
{
  "mcp": {
    "jira": {
      "type": "remote",
      "url": "https://jira.example.com/mcp",
      "enabled": true
    }
  }
}
```

---

### Configuración global

Coloque la configuración global en `~/.config/opencode/opencode.json`.

Use esta ubicación para definir preferencias de usuario, como temas, proveedores o combinaciones de teclas.

La configuración global anula los valores predeterminados de la organización.

---

### Configuración por proyecto

Agregue un archivo `opencode.json` en la raíz del proyecto.

La configuración del proyecto tiene la mayor prioridad entre los archivos de configuración estándar. Puede anular la configuración global y la remota.

:::tip
Coloque la configuración específica del proyecto en la raíz del repositorio.
:::

Al iniciarse, OpenCode busca un archivo de configuración en el directorio actual y luego recorre el árbol hacia arriba hasta encontrar el directorio Git más cercano.

También puede versionar este archivo en Git. Usa el mismo esquema que la configuración global.

---

### Ruta personalizada

Especifique una ruta de archivo de configuración personalizada mediante la variable de entorno `OPENCODE_CONFIG`.

```bash
export OPENCODE_CONFIG=/path/to/my/custom-config.json
opencode run "Hello world"
```

La configuración personalizada se carga después de la configuración global y antes de la configuración del proyecto.

---

### Directorio personalizado

Especifique un directorio de configuración personalizado mediante la variable de entorno `OPENCODE_CONFIG_DIR`

OpenCode buscará en ese directorio agentes, comandos, modos y complementos, igual que en el directorio estándar `.opencode`. Use la misma estructura de directorios.

```bash
export OPENCODE_CONFIG_DIR=/path/to/my/config-directory
opencode run "Hello world"
```

El directorio personalizado se carga después de la configuración global y de `.opencode`, ppor lo que **puede anular** esos valores.

## Esquema

El archivo de configuración usa el esquema definido en [**`opencode.ai/config.json`**](https://opencode.ai/config.json).

El editor debería poder validar el archivo y ofrecer autocompletado según ese esquema.

### TUI

Configure opciones específicas de la TUI mediante la clave `tui`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "tui": {
    "scroll_speed": 3,
    "scroll_acceleration": {
      "enabled": true
    },
    "diff_style": "auto"
  }
}
```

Opciones disponibles:

- `scroll_acceleration.enabled`: Habilita la aceleración de desplazamiento al estilo de macOS. Tiene prioridad sobre `scroll_speed`.**
- `scroll_speed`: Define un multiplicador personalizado para la velocidad de desplazamiento. Valor predeterminado: `3`,Valor mínimo: `1`. Se ignora si `scroll_acceleration.enabled` es `true`.
- `diff_style`: Controla cómo se muestran las diferencias.`"auto"` se adapta al ancho del terminal, `"stacked"` muestra siempre una sola columna.

[Obtenga más información sobre la TUI aquí](/docs/tui).

### Servidor

Configure las opciones del servidor para los comandos `opencode serve` y `opencode web` mediante la opción `server`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "server": {
    "port": 4096,
    "hostname": "0.0.0.0",
    "mdns": true,
    "mdnsDomain": "myproject.local",
    "cors": ["http://localhost:5173"]
  }
}
```

Opciones disponibles:

- `port`: Puerto en el que escuchará el servidor.
- `hostname`: Nombre de host o dirección en la que escuchará el servidor. Si `mdns` está habilitado y no se define un valor, se usa `0.0.0.0`. 
- `mdns`: habilita el descubrimiento de servicios mediante mDNS. Esto permite que otros dispositivos de la red detecten el servidor OpenCode.
- `mdnsDomain`: nombre de dominio personalizado para el servicio mDNS. El valor predeterminado es `opencode.local`. Resulta útil al ejecutar varias instancias en la misma red.
- `cors`:orígenes adicionales permitidos para CORS cuando se usa el servidor HTTP desde un cliente basado en navegador. Use orígenes completos, con esquema, host y puerto opcional, por ejemplo: `https://app.example.com`.

[Obtenga más información sobre el servidor aquí](/docs/server).

### Modelos

Configure los proveedores y modelos mediante las opciones `provider`, `model` y `small_model`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {},
  "model": "anthropic/claude-sonnet-4-5",
  "small_model": "anthropic/claude-haiku-4-5"
}
```

La opción `small_model` define un modelo independiente para tareas ligeras, como la generación de títulos. De forma predeterminada, OpenCode intenta usar un modelo más económico si el proveedor ofrece uno. Si no existe, usa el modelo principal.

Las opciones de proveedores pueden incluir `timeout` y `setCacheKey`:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "timeout": 600000,
        "setCacheKey": true
      }
    }
  }
}
```

- `timeout`: tiempo de espera de solicitud en milisegundos (predeterminado: 300000). Use `false` para desactivarlo.
- `setCacheKey`: garantiza que siempre exista una clave de caché configurada para el proveedor indicado.

También puede configurar [modelos locales](/docs/models#local). [Obtenga Obtenga más información aquí..](/docs/models).

---

#### Opciones específicas del proveedor

Algunos proveedores admiten opciones de configuración adicionalesademás de las opciones genéricas `timeout` y `apiKey`.

##### Amazon Bedrock

Amazon Bedrock admite opciones específicas de AWS:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1",
        "profile": "my-aws-profile",
        "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
      }
    }
  }
}
```

- `region`: región de AWS para Bedrock. El valor predeterminado es la variable de entorno `AWS_REGION` o `us-east-1`
- `profile`: perfil de AWS definido en `~/.aws/credentials` (El valor predeterminado es la variable de entorno `AWS_PROFILE`)
- `endpoint`: URL personalizada para un endpoint de VPC. Es un alias de la opción genérica `baseURL`, pero usa terminología específica de AWS. Si se especifican ambas, `endpoint` tiene prioridad.

:::note
Los tokens de portador (`AWS_BEARER_TOKEN_BEDROCK` o `/connect`) tienen prioridad sobre la autenticación basada en perfil. Consulte [precedencia de autenticación](/docs/providers#authentication-precedence) para obtener más detalles.
:::

[Obtenga más información sobre la configuración de Amazon Bedrock aquí.](/docs/providers#amazon-bedrock).

### Agentes

Configure agentes especializados para tareas concretas mediante la opción `agent`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "model": "anthropic/claude-sonnet-4-5",
      "prompt": "You are a code reviewer. Focus on security, performance, and maintainability.",
      "tools": {
        // Disable file modification tools for review-only agent
        "write": false,
        "edit": false,
      },
    },
  },
}
```

También puede definir agentes utilizando archivos Markdown en `~/.config/opencode/agents/` o `.opencode/agents/`. [Obtenga más información aquí.](/docs/agents).

---

### Agente predeterminado

Configure el agente predeterminado mediante la opción `default_agent`. Esta opción determina qué agente se usa cuando no se especifica otro.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "plan"
}
```

El agente predeterminado debe ser un agente principal (no un subagente). Puede usar un agente integrado, como `"build"` o `"plan"`, o un [agente personalizado](/docs/agents) definido por usted. Si el agente indicado no existe o es un subagente, OpenCode volverá a`"build"` y mostrará una advertencia.

Esta configuración se aplica en todas las interfaces: TUI, CLI (`opencode run`), aplicación de escritorio y GitHub Action.

### Compartir

Configure la función [compartir](/docs/share) mediante lala opción `share`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "share": "manual"
}
```

Valores disponibles:

- `"manual"`: Permite compartir manualmente mediante comandos (predeterminado).
- `"auto"`: Comparte automáticamente las conversaciones nuevas.
- `"disabled"`: Desactiva por completo el uso compartido.

De forma predeterminada, OpenCode usa el modo manual, por lo que debe compartir las conversaciones explícitamente con el comando `/share`.

### Comandos

Configure comandos personalizados para tareas repetitivas mediante la opción `command`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "command": {
    "test": {
      "template": "Run the full test suite with coverage report and show any failures.\nFocus on the failing tests and suggest fixes.",
      "description": "Run tests with coverage",
      "agent": "build",
      "model": "anthropic/claude-haiku-4-5",
    },
    "component": {
      "template": "Create a new React component named $ARGUMENTS with TypeScript support.\nInclude proper typing and basic structure.",
      "description": "Create a new component",
    },
  },
}
```

También puede definir comandos mediante archivos Markdown en `~/.config/opencode/commands/` o `.opencode/commands/`. [Obtenga más información aquí.](/docs/commands).

### Actualización automática

OpenCode descarga automáticamente las actualizaciones nuevas al iniciarse. Desactive este comportamiento mediante la opción `autoupdate`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "autoupdate": false
}
```

Si no quiere instalar las actualizaciones automáticamente, pero sí desea recibir una notificación cuando haya una nueva versión disponible, configure `autoupdate` en `"notify"`.

Tenga en cuenta que esto solo funciona si OpenCode no se instaló mediante un gestor de paquetes como Homebrew.

### Permisos

De forma predeterminada, OpenCode permite todas las operaciones sin pedir aprobación explícita. Cambie este comportamiento mediante la opción `permission`.

Por ejemplo, para garantizar que las herramientas `edit` y `bash` requieran la aprobación del usuario:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",
    "bash": "ask"
  }
}
```

[Obtenga más información sobre los permisos aquí](/docs/permissions).

### Compactación

Controle el comportamiento de compactación del contexto mediante la opción `compaction`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "prune": true
  }
}
```

- `auto`: compacta automáticamente la sesión cuando el contexto se llena. (predeterminado: `true`).
- `prune`: elimina las salidas antiguas de herramientas para ahorrar tokens (predeterminado: `true`).

### Observador

Configure patrones ignorados por el observador de archivos mediante la opción `watcher`.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "watcher": {
    "ignore": ["node_modules/**", "dist/**", ".git/**"]
  }
}
```

Los patrones siguen la sintaxis global. Utilice esto para excluir directorios ruidosos de la visualización de archivos.

### Proveedores deshabilitados

Deshabilite proveedores cargados automáticamente mediante la opción `disabled_providers`. Use esta opción para impedir que se carguen determinados proveedores, incluso si sus credenciales están disponibles.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "disabled_providers": ["openai", "gemini"]
}
```

:::note
El `disabled_providers` tiene prioridad sobre `enabled_providers`.
:::

La opción `disabled_providers` acepta una lista de ID de proveedores. Cuando un proveedor está deshabilitado:

- No se cargará incluso si se establecen variables de entorno.
- No se cargará incluso si las claves API están configuradas mediante el comando `/connect`.
- sus modelos no aparecen en la lista de selección.

---

### Proveedores habilitados

Limite OpenCode a un conjunto específico de proveedores mediante la opción `enabled_providers`. Cuando se define esta opción, OpenCode solo habilita los proveedores especificados e ignora todos los demás.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "enabled_providers": ["anthropic", "openai"]
}
```

Esto resulta útil si quiere restringir OpenCode a un conjunto concreto de proveedores, en lugar de deshabilitarlos uno por uno.

:::note
El `disabled_providers` tiene prioridad sobre `enabled_providers`.
:::

Si un proveedor aparece en ambas listas, `enabled_providers` como en `disabled_providers`, el `disabled_providers` tiene prioridad para la compatibilidad con versiones anteriores.

---

### Experimental

La clave `experimental` agrupa opciones que aún están en desarrollo activo.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {}
}
```

:::caution
Las opciones experimentales no son estables. Pueden cambiar o eliminarse sin previo aviso.
:::

## Variables

Use sustitución de variables en los archivos de configuración para hacer referencia a variables de entorno y al contenido de archivos.

---

### Variables de entorno

Use `{env:VARIABLE_NAME}` para sustituir variables de entorno:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "provider": {
    "anthropic": {
      "models": {},
      "options": {
        "apiKey": "{env:ANTHROPIC_API_KEY}"
      }
    }
  }
}
```

Si la variable de entorno no está definida, se sustituye por una cadena vacía.

---

### Archivos

Use `{file:path/to/file}` para sustituir el contenido de un archivo:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["./custom-instructions.md"],
  "provider": {
    "openai": {
      "options": {
        "apiKey": "{file:~/.secrets/openai-key}"
      }
    }
  }
}
```

Las rutas de archivos pueden ser:

- Relativo al directorio del archivo de configuración
- O rutas absolutas que comienzan con `/` o `~`

Esto resulta útil para:

- Mantener datos confidenciales como claves API en archivos separados.
- Incluye archivos de instrucciones grandes sin saturar tu configuración.
- Compartir fragmentos de configuración comunes en múltiples archivos de configuración.
