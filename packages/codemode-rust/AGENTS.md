# PsychoScript (Rust)

A Rust port of OpenCode's Code Mode (`packages/codemode` in anomalyco/opencode, the reference implementation), embeddable in Rust programs with no Bun, Node or other JavaScript engine at build or run time.

## Parity with the TypeScript package

This package is a second way to run and embed the same language, not a replacement. `packages/codemode` stays, and the two packages must stay equally capable in both directions.

- A language feature, built-in or host API lands in both packages or in neither. Rust-native forms of a reference API (futures instead of Effects, closures or traits instead of services) are fine; Rust-only capabilities are not.
- Conformance expectations are always generated from `packages/codemode`; never edit them by hand. CI regenerates them and fails on any difference.
- `test262/rust-skipped.txt` lists reference-passing files Rust still fails; it may only shrink.

## Scope: minimal, targeted

In scope:

- The language subset needed by the nine reference benchmark programs (`conformance/cases/bench-*`), the plugin reducer example, and the other conformance cases.
- Pipeline: parse → compile to bytecode → stack VM. Values cross the host boundary as JSON copies (`serde_json::Value`), never shared.
- Host API in `crates/psychoscript/src/lib.rs`, the Rust form of the reference's README API: schema-described tools (sync or futures) at dotted paths with namespaces, OpenAPI tools (`openapi::from_spec` over a host `HttpClient`), the catalog and `search`, hooks, extensions with `import`/`require`, programs (`Runtime::program`), suspending and resuming runs (`Suspender`, `Runtime::resume`, idempotent and durable tools, extension `snapshot` hooks), JSON bindings, limits (`timeout_ms`, `max_tool_calls`, `max_output_bytes`), `console.log` captured into `logs`.
- Parity runs both ways: add no language feature or host API the reference lacks. Rust-native forms of reference APIs (futures for Effects, a blocking `execute`) are fine.
- `conformance/catalog.json` is generated by `bun conformance/catalog.ts` from the reference; never edit it by hand.
- `conformance/streaming.json` is generated by `bun conformance/streaming.ts` from the reference (streaming responses, which the reference has no tests for); never edit it by hand.

Out of scope: classes (rejected, like the reference), `export`, Effect integration, BigInt, Symbol beyond iterators.

## Rules

- Functional style at the API: plugins are programs over data, not objects. Do not add classes to the language.
- Unsupported syntax returns `UnsupportedSyntax` with a location; never panic on user input.
- No `unsafe` unless measured and justified in a comment.
- Dependencies: pure Rust only, and few. Justify each in the commit that adds it.
- test262 parity runs both ways: `bash test262/run.sh` must pass, and `test262/rust-skipped.txt` and `test262/reference-gaps.txt` may only shrink.
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` must pass.
- The conformance cases must also pass in round-trip mode, which saves and restores every run at each host stop and every 64 loop iterations: `PSYCHOSCRIPT_ROUNDTRIP=1 cargo test --release -p psychoscript-bench --test conformance`.
- Benchmark claims need the command, machine and numbers in `bench/RESULTS.md`.
- CI: the `unit` job of `.github/workflows/check-test.yml` runs these checks, round-trip conformance, conformance freshness, test262 and the informational bench on Linux, whenever `packages/codemode`, `packages/codemode-rust` or that workflow changed.
- Nothing in the repo mentions internal tooling, private chats, home paths, hostnames or secrets.
