Manage scheduled automations for this session.

Request: $ARGUMENTS

Use the schedule tools in the `opencode` namespace. They only see this session's schedules.

- To schedule something, call `schedule_create`:
  - `when`: `{ in: "20 minutes" }`, `{ at: "2026-10-27T09:00" }`, `{ every: "1 hour" }` or `{ cron: "0 9 * * 1-5" }` (optional with `until`, which defaults to every 30s).
  - Optional gate (`if` or `until`): `{ run: "..." }` for a zero-token shell check or `{ code: "..." }` for a Code Mode JavaScript check calling `tools.<path>(...)` statically (no `fetch`, 30s / 20 calls / 32 KB caps) and returning a boolean or `{ wake, state?, message? }`.
  - Choose one action:
    - `prompt`: instruction for a model turn. Use `target: "subagent"` for an isolated background child session, `target: "dedicated"` for one persistent background session that keeps memory across runs, or omit `target` (`"same"`) to queue a wake in this session.
    - `command` (and optional `arguments`): run a slash command such as `"morning-brief"`. Defaults to `target: "subagent"` so no kickoff prompt enters this chat.
    - `run`: execute a deterministic shell command in the session's directory with no model call.
    - `code`: execute a deterministic Code Mode JavaScript script with no model call.
  - Add `deliver: "inbox"` on background actions to record findings in the Inbox without waking this session, `deliver: "silent"` to stay quiet unless auto-paused, or `ends` (`{ after }`, `{ at }`, `{ times }`) to cap repeating runs.
- Inside a scheduled background run, call `schedule_result({ attention: "quiet" | "ready" | "needs_you", summary?, nextIn? })` to classify attention and optionally adjust the next firing cadence.
- To inspect unread findings or past runs, call `schedule_inbox`, `schedule_runs`, or `schedule_dismiss`.
- To pause, resume or delete one, find its id with `schedule_list`, then call `schedule_pause`, `schedule_resume` or `schedule_delete`.
- If the request is empty, call `schedule_list` and show this session's schedules: name, action, when, status and next run.

Reply in one line: what changed and when it next fires.
