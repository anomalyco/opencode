Review the local hiring packet before commit/push.

You are reviewing a candidate/req packet — not a git PR. Do not lead with `git diff`, `git show`, or `gh pr`. Default path is packet review under `.moks/` and related local artifacts.

Input: $ARGUMENTS

Worktree: `${path}`

## What to review

Resolve packet materials in order:

1. Paths or focus from `$ARGUMENTS` / attachments
2. Workspace: `@<slug>` / `.moks/reqs/<slug>/` — `jd.md`, `scorecard.md`, `resume.md`, `notes.md`, outreach drafts (legacy `.moks/req/` if that is the only req)
3. Session-visible local hiring file changes (Modified Files / session diffs of candidate & req artifacts)
4. Pending decision receipts via `moks status` when disposition readiness matters
5. Cwd fixtures only if no `.moks/` packet exists

Read the full files you will cite. Use skills to deepen analysis when needed:

- **score-candidate** — fit vs scorecard with evidence and path citations
- **commit-disposition** — disposition consistency and readiness to commit
- **req-context** / **draft-outreach** when JD gaps or outreach quality is in scope

## Structure the review

1. **Fit vs scorecard** — dimension scores, must-haves, deal-breakers; cite resume/JD paths
2. **Evidence gaps** — missing materials, weak claims, unverified bar items
3. **Outreach quality** — if drafts exist: accuracy, tone, overclaims; never send
4. **Disposition consistency** — recommendation matches evidence; ready for `moks commit` / risks before `moks push`
5. **Risks before push** — adverse actions need confirm; incomplete packet; conflicting notes

## Decision verbs

- Inspect: `moks status`
- Record intent: `moks commit`
- Push: `moks push` (adverse reject/offer/hire need confirm)

Do not claim ATS writes. Prefer bash for these CLIs when checking readiness.

## Escape hatch

If the user **explicitly** asks for code review and you are on the `build` agent, git/gh tooling is allowed. Otherwise stay on packet review.

## Output

- Matter-of-fact, scannable bullets or short sections
- Severity-aware: block-push risks first, then gaps, then polish
- No flattery; no invented resume facts
- End with a clear next step (fill gap / re-score / commit disposition / push)
