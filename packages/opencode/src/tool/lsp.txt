Interact with Language Server Protocol (LSP) servers to get code intelligence features.

Two families of operations are supported.

Position-based operations (require `filePath`, `line` and `character`, all 1-based):
- goToDefinition: Find where a symbol is defined
- findReferences: Find all references to a symbol
- hover: Get hover information (documentation, type info) for a symbol
- documentSymbol: Get all symbols (functions, classes, variables) in a document
- workspaceSymbol: List project-wide symbols matching a query string
- goToImplementation: Find implementations of an interface or abstract method
- prepareCallHierarchy: Get call hierarchy item at a position (functions/methods)
- incomingCalls: Find all functions/methods that call the function at a position
- outgoingCalls: Find all functions/methods called by the function at a position

Symbol-based operations (require `symbol`, a full or simple symbol name; no position needed):
- symbols: Resolve a symbol by name and show its definition location(s)
- members: List the members of a type by name
- refs: Find all references to a symbol by name
- callers: Find all call sites of a method/property by name
- implementations: Find implementations of an interface/abstract member by name
- rename: Rename a symbol by name; dry-run unless `apply=true`
- types: List types whose name matches `query` (or `symbol`)
- structure: List the solution projects (`dotnet sln list`) plus symbol containers

Symbol-based operations reuse the already-running language server for the file type,
so no extra background process is started.

Notes:
- workspaceSymbol also accepts `query`; an empty string requests all symbols.
- For rename, inspect the dry-run output before calling again with apply=true.
- LSP servers must be configured for the file type. If no server is available, an error is returned.
