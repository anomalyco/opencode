Execute Python code in a persistent REPL environment for Recursive Language Model (RLM) processing.

This tool enables you to interact with arbitrarily long contexts through code execution. The context is stored as a variable in the REPL environment, allowing you to programmatically examine, decompose, and process it.

## Environment Setup

When initialized with context, the REPL provides:
1. A `context` variable containing the input data (string or list of strings)
2. LLM query functions for recursive sub-agent calls (single and parallel)
3. Context analysis helpers for intelligent decomposition
4. Standard Python libraries and the ability to import more
5. Persistent state across code executions within the same session

## Available Functions

### LLM Query Functions

```python
# Single synchronous query
result = llm_query(prompt, ctx="")

# Parallel batch queries - spawns multiple sub-agents simultaneously
results = llm_query_parallel([
    {"prompt": "Analyze section 1", "context": chunk1},
    {"prompt": "Analyze section 2", "context": chunk2},
])

# Map a prompt over items with auto-batching
summaries = llm_map("Summarize: {item}", chunks, max_parallel=10)
```

### Context Helpers

```python
# Analyze context metadata
info = probe_context()  # Returns {type, length, lines, words, format, preview, tail}

# Smart chunking with semantic boundaries
chunks = smart_chunk(text, target_size=8000, overlap=200)

# Get LLM to plan decomposition strategy
strategy = plan_decomposition("Find security issues")
```

## How to Use

Write Python code wrapped in triple backticks with 'repl' language identifier:

```repl
# Example: Examine and process context
info = probe_context()
print(f"Context: {info['length']} chars, {info['lines']} lines")

chunks = smart_chunk(context, target_size=5000)
results = llm_map("Extract key facts: {item}", chunks)
print(f"FINAL({results})")
```

## Key Strategies

### 1. Parallel Processing (Recommended)
Use `llm_query_parallel` or `llm_map` for processing multiple chunks:
```python
chunks = smart_chunk(context)
# This spawns len(chunks) parallel sub-LLM queries:
results = llm_query_parallel([
    {"prompt": f"Analyze: {c}"} for c in chunks
])
```

### 2. Filter Before Querying
Use regex/code to reduce LLM calls:
```python
import re
relevant = [l for l in context.split('\n') if re.search(r'error', l, re.I)]
results = llm_map("Classify: {item}", relevant)
```

### 3. Hierarchical Map-Reduce
For very large contexts, use multiple stages:
```python
# Stage 1: Extract
chunks = smart_chunk(context, target_size=5000)
extractions = llm_map("Extract key points: {item}", chunks)

# Stage 2: Synthesize
final = llm_query(f"Combine findings: {extractions}")
print(f"FINAL({final})")
```

## Providing Final Answers

You MUST wrap your answer in one of these patterns:

- `print(f"FINAL(your answer)")` - Return a direct text answer
- `print(f"FINAL_VAR(variable_name)")` - Return a variable's contents

## Important Notes

- **Use parallel functions** - `llm_query_parallel` and `llm_map` are much faster
- **Model decides parallelism** - You determine chunk sizes based on data
- Output is truncated to 50K chars; use sub-queries for analysis
- Variables persist across code executions in the same session
- Always probe the context before answering queries
