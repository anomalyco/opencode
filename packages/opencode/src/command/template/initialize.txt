## Goal

Create a local hiring workspace so recruit can load req materials, score candidates, draft outreach, and record dispositions.

## Steps

1. Create directories if missing:
   - `.moks/`
   - `.moks/req/`

2. Scaffold stubs under `.moks/req/` when missing (do not overwrite non-empty files without asking):
   - `jd.md` — role title, team, level, must-haves / nice-to-haves, location
   - `scorecard.md` — dimensions and interview bar (1–5 or pass/fail)
   - `notes.md` — process notes, owners, open questions
   - Optional: `resume.md` placeholder when the user already has a candidate in mind

3. Gitignore: if a `.gitignore` exists at `${path}`, ensure a `.moks/` entry is present; add it if missing. Do not create a root `.gitignore` solely for this.

4. Fill stubs with role context from `$ARGUMENTS` or brief questions. Use the `question` tool sparingly — at most one short batch for missing **role title** and/or **team**. Prefer writing lightweight stubs over a long interview.

5. After scaffolding, run or invoke **req-context** to synthesize a structured req brief and list missing context.

## Hiring skills (use via skill tool)

- **req-context** — structured req brief from JD/notes; list gaps
- **score-candidate** — resume vs JD/scorecard with evidence citations
- **draft-outreach** — recruiter email/LinkedIn drafts; never send
- **commit-disposition** — recommend reject/offer/hire/advance; user records via decision verbs

## Decision verbs (authority)

Dispositions are receipts only until push. Prefer bash for these CLIs:

- `moks commit` — record disposition intent (local receipt)
- `moks status` — inspect pending / open commits
- `moks push` — push a committed decision (records push receipt; adverse reject/offer/hire need confirm)

Never invent ATS stage moves or claim a remote write happened.
