# OpenCode 大模型调用工具与指导 Prompt 优化报告

## 一、执行摘要

本报告对 OpenCode 项目中的所有大模型调用工具及其指导 Prompt 进行了全面审查，并提出了系统性的优化方案。

**主要发现：**
- 现有提示体系存在大量冗余，部分文件内容重复率高达80%
- 工具描述平均过长，导致不必要的 token 消耗
- 系统提示风格不统一，增加了维护难度

**优化建议：**
- 建立统一的 Prompt 架构，分层管理
- 精简工具描述，提取核心指导原则
- 消除冗余，实现提示复用

---

## 二、现状分析

### 2.1 核心组件概览

| 组件类型 | 文件数量 | 总大小 | 平均大小 |
|---------|---------|-------|---------|
| 工具描述 | 20 | ~50KB | 2.5KB |
| 系统提示 | 5 | ~50KB | 10KB |
| Agent提示 | 4 | ~4KB | 1KB |

### 2.2 当前架构问题

#### 问题1：提示冗余
- `anthropic.txt` 和 `qwen.txt` 内容高度相似
- `beast.txt` 包含大量与系统提示重复的内容
- 每个工具描述都包含通用的工具使用规则

#### 问题2：长度失控
- `bash.txt`: 9.5KB (应精简至 ~2KB)
- `todowrite.txt`: 8.8KB (应精简至 ~2KB)
- 冗长的提示增加成本，降低响应速度

#### 问题3：结构混乱
- 缺乏统一的格式标准
- 优先级标识不清晰
- 错误处理指导分散

## 三、详细优化方案

### 3.1 统一 Prompt 架构

```
src/session/prompt/
├── core.txt           # 核心原则 (所有模型共享)
├── anthropic.txt      # Claude 特定增强
├── beast.txt          # GPT 特定增强 (精简版)
├── gemini.txt         # Gemini 特定增强
└── codex_header.txt   # Codex 额外指令
```

### 3.2 工具描述优化策略

#### 3.2.1 分类重组

| 类别 | 工具示例 | 优化方向 |
|-----|---------|---------|
| 文件操作 | read, write, edit, ls | 标准化描述格式 |
| 搜索工具 | glob, grep, codesearch | 突出使用场景 |
| 执行工具 | bash, task | 强调安全规则 |
| 辅助工具 | todowrite, todoread | 精简示例数量 |

#### 3.2.2 描述模板

```markdown
# 工具描述标准模板

## 一句话描述
[工具的核心功能]

## 使用场景
- 场景1
- 场景2

## 关键约束
1. 约束1
2. 约束2

## 示例
[最多2个典型示例]
```

## 四、具体文件优化建议

### 4.1 系统提示优化

#### 4.1.1 core.txt (新建 - 核心原则)
- 提取所有系统提示的共同元素
- 建立统一的输出规范
- 定义工具使用优先级

#### 4.1.2 anthrop.txt (精简版)
- 保留 Claude 特定优化
- 移除通用规则（移至 core.txt）
- 强调thinking过程

#### 4.1.3 beast.txt (大幅精简)
- 从11KB减少至 ~3KB
- 保留GPT特定优化
- 移除与core.txt重复的内容

#### 4.1.4 gemini.txt (精简版)
- 保留Gemini特定优化
- 从15KB减少至 ~4KB
- 保持结构清晰

### 4.2 工具描述优化

#### 4.2.1 bash.txt
**当前问题：** 9.5KB，包含过详细的Git操作指南

**优化方案：**
- 保留核心命令执行指导
- 将Git操作细节移至专用文档
- 添加"重要安全规则"速查表

**优化后结构：**
```
1. 功能描述 (2行)
2. 核心约束 (5条)
3. 安全规则 (3条)
4. 典型示例 (2-3个)
```

#### 4.2.2 todowrite.txt
**当前问题：** 8.8KB，示例过多

**优化方案：**
- 保留WHEN/WHEN NOT决策逻辑
- 精简示例至核心场景
- 添加快速参考

**优化后结构：**
```
1. 功能描述
2. 使用场景 (何时使用)
3. 不使用场景 (何时避免)
4. 任务状态说明
5. 精简示例 (保留3个核心场景)
```

#### 4.2.3 其他工具描述优化

| 文件 | 当前大小 | 目标大小 | 优化重点 |
|-----|---------|---------|---------|
| glob.txt | 604B | 保持 | 保持现状 |
| grep.txt | 697B | 保持 | 保持现状 |
| task.txt | 3.5KB | 2KB | 精简Agent列表展示 |
| websearch.txt | 981B | 1.2KB | 添加日期变量说明 |
| codesearch.txt | 814B | 1KB | 突出与grep的差异 |

## 六、风险评估

| 风险 | 影响 | 缓解措施 |
|-----|-----|---------|
| 提示过于精简导致功能缺失 | 高 | 保留所有功能，移除冗余 |
| 模型特定优化丢失 | 中 | 在精简版中保留关键差异 |
| 测试覆盖不足 | 中 | 建立自动化测试验证响应质量 |

## 七、预期收益

1. **成本降低：** 预计减少30-40%的token消耗
2. **响应提速：** LLM响应时间预计提升20-30%
3. **维护简化：** 提示修改更集中，降低维护成本
4. **一致性提升：** 统一的Prompt架构减少混淆
