## 2. 적용 로직 요약

### 2.1 추론 FSM (Finite State Machine)

모든 문제 유형에 공통 적용되는 상태 기계:

```
Diagnose → Plan → Solve(iterative) → Verify → Reflect → Exit
```

전이 규칙:

- `Verify=pass` → `Exit`
- `Verify=fail ∧ retry<Limit` → `Reflect` 후 `Solve`
- `Budget-exhausted` → `Exit(fallback)`

### 2.2 NCMH (Neuromodulated Cognitive Model Handler)

동적 샘플링/툴 호출 제어 시스템.

#### 관측 벡터 (Observation)

| 변수          | 설명                                     |
| ------------- | ---------------------------------------- |
| U (불확실성)  | 평균 토큰 엔트로피 + 후보 간 다변성 JSD  |
| P (진전도)    | PRM 점수 + 검증 통과율 변화              |
| E (위반/오류) | 수식 오류, 컴파일 실패, 사실 불일치 비율 |
| D (난이도)    | perplexity, 제약 개수, 중간 스텝 수      |

#### 출력 (Action)

| 파라미터    | 제어식                   | 범위        |
| ----------- | ------------------------ | ----------- |
| k (후보 수) | `k0 + αU·U - αP·P`       | [1, 9]      |
| b (브랜치)  | `b0 + βU·U + βE·E`       | [1, 3]      |
| d (깊이)    | `d0 + γU·U`              | [2, 6]      |
| temperature | `T0 - τP·P + τU·U`       | [0.1, 0.9]  |
| top_p       | `p0 - πP·P + πU·U`       | [0.6, 0.98] |
| tool_gate   | `λU·U + λE·E - λP·P > θ` | bool        |

#### 운영 파라미터 (초기값)

```yaml
k0: 3
b0: 1
d0: 3
T0: 0.7
p0: 0.9
theta: 0.2

αU: 1.2
αP: 0.8
βU: 0.8
βE: 0.6
γU: 0.6
τP: 0.25
τU: 0.25
πP: 0.15
πU: 0.15
λU: 0.5
λE: 0.5
λP: 0.5

budget_min: 800 tokens
budget_scale: 400 tokens
max_retry: 3
```

### 2.3 작업 타입별 Solve+Verify 로직

#### 수학 (PoT - Program of Thought)

| 단계      | 로직                                                                          |
| --------- | ----------------------------------------------------------------------------- |
| Solve     | PoT 템플릿 → 중간식마다 `calc(sympy)` 호출 → 단위/영차원 검사 → k개 후보 생성 |
| Verify    | 식 동치 검사 + 샘플링 검증(n=16) + 물리량 차원 검사(pint)                     |
| Reflect   | 실패 유형 태깅 (산술/대수/해석/단위/문제오독) → 유형별 대응 프롬프트          |
| NCMH 특화 | 오류율↑ → `T↓, top_p↓, k↑` + calc 호출 강제                                   |

#### 코딩 (Test-time Patch Loop)

| 단계      | 로직                                                               |
| --------- | ------------------------------------------------------------------ |
| Solve     | 생성 → 실행 → 오류요약 → 패치 (최대 3회), AST 해시로 중복 제거     |
| Verify    | 유닛테스트 통과율 + 런타임 제한 + 금지 API 탐지                    |
| Reflect   | 에러 템플릿별 패치 지시 (ImportError/TypeError/Off-by-one/IO/성능) |
| NCMH 특화 | 실패누적↑ → 재시도 예산↑, `T↓`, 툴 게이트 On                       |

#### 일반 지식 추론 (근거 기반)

| 단계      | 로직                                                   |
| --------- | ------------------------------------------------------ |
| Solve     | 계획 → 근거검색/정리 → 주장·근거 페어 생성 → 최종 요약 |
| Verify    | 근거 일치율 (ROUGE/BM25) + 사실 엔티티 정합            |
| Reflect   | 불일치 근거 재수집                                     |
| NCMH 특화 | 근거-주장 불일치↑ → 검색 우선순위 상승                 |

### 2.4 CSE (Creative Synthesis Engine)

창의적 아이디어 생성 파이프라인:

```
Diverge → Transform → Converge → Critique
```

#### Diverge (시드 생성)

- 연산자: Concept-blend, Analogy, Morphological Matrix, SCAMPER, 역제약

#### Transform (구조적 확장)

- Analogy: 소스/타깃 그래프 동형 매핑
- Parameter sweep: 스케일/자원/제약 조합
- Counterfactual: 핵심 가정 뒤집기

#### Scoring (선발)

| 지표            | 설명                                |
| --------------- | ----------------------------------- |
| Novelty (N)     | 임베딩 거리 + NIDF 가중             |
| Usefulness (U)  | PRM 루브릭 (실현가능성, 문제적합)   |
| Consistency (C) | 내부 모순 페널티                    |
| Safety (S)      | 정책 위반시 0                       |
| 종합            | `F = wN·N + wU·U + wC·C` (S=1 필수) |

### 2.5 도구 스키마 (MCP 호환)

```json
{
  "tools": [
    { "name": "calc.sympy", "input_schema": { "expr": "string" } },
    { "name": "exec.python", "input_schema": { "code": "string", "timeout_ms": "int" } },
    { "name": "search.web", "input_schema": { "query": "string", "top_k": "int" } }
  ]
}
```

호출 형식: `<tool name="calc.sympy">{ "expr": "integrate(x**2, x)" }</tool>`

## 4. Edge 최적화 (추가 로직)

### 4.1 BitNet b1.58 양자화

- Ternary {-1, 0, +1} 가중치 + 1-bit RMSNorm
- bf16 마스터 가중치 → SFT 후 ternary 투영 (Threshold = κ·E[|w|])
- LoRA 미세튜닝 시 ternary freeze + activation clipping (α=1.25)

### 4.2 KV 캐시 압축

| 기법  | 압축률   | 효과                                            |
| ----- | -------- | ----------------------------------------------- |
| KVzip | 3~4×     | FlashAttention latency 2× 개선                  |
| R-KV  | 10% 예산 | reasoning redundant token 제거, 6.6× throughput |
| CLLA  | 2%       | Cross-Layer Latent Attention, lossless          |

### 4.3 경험 기반 전략 적응 (EGuR 스타일)

- `Plan` 단계 전 전략 메타-LM 호출
- 입력: (문제메타, 과거 로그, 실패 모드, 예산 상태)
- 출력: `{prompt_patch, sampling_cfg, tool_flow, verify_order}`
- LRU 캐시로 동일 유형 문제 재활용

## 6. 학습 파이프라인 요약

```
1. 데이터 정제 (수학 PoT, 코딩 유닛테스트, 일반추론 근거 span)
      ↓
2. 스트리밍 Distillation (생산자-소비자 구조)
      ↓
3. Prefork 데이터 준비 (토크나이즈 + 캐시)
      ↓
4. SFT (검증 통과 샘플만)
      ↓
5. PRM 학습 (과정 단위 진전도 채점)
      ↓
6. DPO/ORPO (우수/열등 페어 선호학습)
      ↓
7. Offline Learning & Forgetting (탐색 성공/실패 경로 재학습)
      ↓
8. Tool-augmented 튜닝 (calc/python/search 호출 포맷 고정)
      ↓
9. Validation (verified-acc, pass@k, 근거일치율)
```

## 7. 평가 방법론

### 7.1 Tier 0: 프로토콜/정책 (fast, deterministic)

- Tool-call 스키마 검증 (valid tool name + input JSON)
- 정책 테스트 (파괴적 git ops 거부, secret exfiltration 차단)
- 스타일 테스트 (응답 구조, 간결성)

신호:

- `invalid_tool_call_rate`
- `disallowed_action_rate`
- `formatting_compliance_rate`

### 7.2 Tier 1: 툴 기반 추론 (medium)

- Grep으로 심볼 탐색
- Read로 파일 확인
- Edit/Patch로 함수 수정
- Bash로 단일 명령 실행

신호:

- `task_success_rate`
- `tool_error_rate`
- `tool_efficiency` (calls/task)

### 7.3 Tier 2: 전체 워크플로우 (slow, highest fidelity)

- 소규모 기능 구현
- 실패 테스트 수정
- 모듈 리팩토링 (동작 보존)

신호:

- `bun run typecheck` pass/fail
- `bun test` pass/fail
- diff 크기, 수정 파일 수
