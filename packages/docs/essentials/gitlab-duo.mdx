# GitLab Duo Integration

GitLab Duo provides AI-powered coding assistance with native tool calling capabilities, seamlessly integrated into OpenCode.

## Overview

GitLab Duo offers:

- **Native Tool Calling**: Access 104 GitLab tools via natural language
- **Agentic Chat**: Powered by Claude through GitLab's Anthropic proxy
- **GitLab API Access**: Merge requests, issues, pipelines, repositories, and more
- **Self-Hosted Support**: Works with both GitLab.com and self-hosted instances

## Prerequisites

- GitLab account (Free, Premium, or Ultimate)
- Personal Access Token OR OAuth app (for enhanced security)
- For self-hosted: GitLab instance URL

## Quick Start

### Option 1: Personal Access Token (Easiest)

1. **Create a Personal Access Token**:
   - Go to [GitLab User Settings > Access Tokens](https://gitlab.com/-/user_settings/personal_access_tokens)
   - Click "Add new token"
   - Name: `OpenCode`
   - Scopes: Select `api`
   - Expiration: Set according to your security policy
   - Click "Create personal access token"
   - Copy the token (starts with `glpat-`)

2. **Set environment variable**:

   ```bash
   export GITLAB_TOKEN=glpat-xxxxxxxxxxxxxxxxxxxx
   ```

3. **Start OpenCode**:

   ```bash
   opencode
   ```

4. GitLab Duo models will automatically load (Haiku 4.5 is default)

### Option 2: OAuth (Recommended for Security)

1. **Start OpenCode**:

   ```bash
   opencode
   ```

2. **Initiate authentication**:

   ```
   /connect
   ```

3. **Select GitLab OAuth** from the menu

4. **Follow the browser authorization flow**:
   - Your browser will open to GitLab
   - Authorize OpenCode
   - Return to your terminal

5. GitLab Duo models will be available

## Self-Hosted GitLab

To use with a self-hosted GitLab instance:

```bash
export GITLAB_INSTANCE_URL=https://gitlab.company.com
export GITLAB_TOKEN=glpat-xxxxxxxxxxxxxxxxxxxx
```

Then start OpenCode as normal.

## Configuration

### Basic Configuration

Add to `~/.opencode/config.json`:

```json
{
  "provider": {
    "gitlab": {
      "options": {
        "instanceUrl": "https://gitlab.com"
      }
    }
  }
}
```

### Feature Flags

Enable experimental GitLab Duo features:

```json
{
  "provider": {
    "gitlab": {
      "options": {
        "featureFlags": {
          "duo_agent_platform_agentic_chat": true,
          "duo_agent_platform": true
        }
      }
    }
  }
}
```

### Project Override

If automatic project detection doesn't work, specify explicitly:

```json
{
  "provider": {
    "gitlab": {
      "options": {
        "project": "group/project-name"
      }
    }
  }
}
```

### Default Model Selection

Set a default model in your config:

```json
{
  "model": "gitlab/duo-chat-sonnet-4-5"
}
```

Or use environment variable:

```bash
export OPENCODE_MODEL=gitlab/duo-chat-opus-4-5
```

**Model Selection Tips**:

- **Start with Haiku** (default) for fastest responses
- **Upgrade to Sonnet** for complex code reviews and debugging
- **Use Opus** for architecture decisions and security analysis

## Troubleshooting

### "Authentication failed"

**Symptoms**: Model doesn't load or API calls fail

**Solutions**:

1. Verify token is valid:

   ```bash
   curl -H "PRIVATE-TOKEN: $GITLAB_TOKEN" https://gitlab.com/api/v4/user
   ```

2. Check token scopes include `api`

3. For OAuth, try re-authenticating with `/connect`

### "Project not found"

**Symptoms**: Tools can't find your GitLab project

**Solutions**:

1. Ensure you're in a Git repository with GitLab remote:

   ```bash
   git remote -v
   ```

2. Manually specify project in config:
   ```json
   {
     "provider": {
       "gitlab": {
         "options": {
           "project": "group/project-name"
         }
       }
     }
   }
   ```

### Tools not available

**Symptoms**: GitLab tools don't appear

**Solutions**:

1. Plugins should auto-load when authenticated
2. Verify authentication is configured
3. Check logs for plugin loading errors
4. Restart OpenCode

### Self-hosted instance issues

**Symptoms**: Can't connect to self-hosted GitLab

**Solutions**:

1. Verify instance URL format:

   ```bash
   # Correct
   export GITLAB_INSTANCE_URL=https://gitlab.example.com

   # Incorrect (no trailing slash)
   export GITLAB_INSTANCE_URL=https://gitlab.example.com/
   ```

2. Check SSL certificate is valid

3. Ensure instance is accessible from your network

## OAuth Setup (Advanced)

For custom OAuth client ID:

1. Register OAuth application:
   - Go to [GitLab Applications](https://gitlab.com/-/user_settings/applications)
   - Name: `OpenCode`
   - Redirect URI: `http://127.0.0.1:8080/callback`
   - Confidential: ✅ Yes
   - Scopes: `api`

2. Copy the Application ID

3. Set environment variable:
   ```bash
   export GITLAB_OAUTH_CLIENT_ID=your_application_id_here
   ```

## Security Best Practices

1. **Use OAuth over PAT** when possible
2. **Rotate PATs regularly** (set expiration dates)
3. **Never commit tokens** to version control
4. **Use environment variables** for sensitive data
5. **Review authorized applications** periodically in GitLab settings
6. **Limit token scopes** to minimum required (`api` scope only)

## Performance Tips

1. **Project Detection**: Specify project explicitly for faster tool execution
2. **Token Caching**: OpenCode caches tokens to reduce API calls
3. **Rate Limits**: GitLab API has rate limits; tools handle this gracefully
4. **Network**: Ensure stable connection for best performance
