# Tauri Icons

Here's the process I've been using to create icons:

- Save source image as `app-icon.png` in `packages/desktop`
- `cd` to `packages/desktop`
- Run `bun tauri icon -o src-tauri/icons/{environment}`
- Use [Image2Icon](https://img2icnsapp.com/)'s 'Big Sur Icon' preset to generate an `icon.icns` file and place it in the appropriate icons folder

The Image2Icon step is necessary as the `icon.icns` generated by `app-icon.png` does not apply the shadow/padding expected by macOS,
so app icons appear larger than expected.

Every smaller size in `icon.icns` must be a premultiplied-alpha downsample of its 1024px (`icon_512x512@2x`) image. Image2Icon's
smaller sizes had light, unpremultiplied anti-aliased edges that render as a halo on dark backgrounds, most visibly at the 64px size
macOS uses in System Settings lists. Regenerate them from the 1024px image and resync `dock.png` before committing a new `icon.icns`.

For unpackaged Electron on macOS, `app.dock.setIcon()` should use a PNG. Keep `dock.png` in each channel folder synced with the
extracted `icon_128x128@2x.png` from that channel's `icon.icns` so the dev Dock icon matches the packaged app inset.

## Tray icons

Each channel folder also holds the notification-area icon:

- `trayTemplate.png` (16×16) and `trayTemplate@2x.png` (32×32) are macOS template images: black pixels with alpha, which
  the system tints for the light and dark menu bar.
- `tray.png` (24×24) is the Linux status-area icon, drawn like `icon.png` so it reads on light and dark panels.
- Windows reuses `icon.ico`.

All three render the frame from `packages/identity/mark.svg` (outer `128,96`–`384,416`, inner hole `192,160`–`320,352`),
scaled to fill the canvas with one pixel of padding at 1× and area-averaged down from a 16× supersample so the 2–3px
stroke stays crisp. Regenerate them from that geometry when the mark changes.
