## Why

The model dialog (`packages/tui/src/component/dialog-model.tsx` and `dialog-model-twopane.tsx`) already carries several per-model footer actions (`favorite`, `hide`, `note`, plus a forthcoming `model.dialog.variant` shortcut that duplicates the post-select variant flow). Adding vision-fallback as a fifth per-model action makes the action bar hard to scan and forces the user to memorize a growing single-key mnemonic map. A text-only model that needs vision assistance today either errors out (`ERROR: Cannot read image ... (this model does not support image input).`) or requires editing `kancode.json`, which is a team-shared file that should not be silently rewritten by an interactive TUI. We need a single, discoverable per-model "edit" entry (`c`) that opens a submenu for the lesser-used operations, while keeping the high-frequency shortcuts (`ctrl+f` favorite, `h` hide) as direct one-keystroke actions, and a user-scope persistence slot for the vision fallback so it travels with the user across projects without touching `kancode.json`.

A global-only fallback (one setting shared by every text-only model) is too coarse: a user with two text-only models on different providers may want a different fallback for each. v1 supports both **a global default** and **per-model overrides** that fall back to the global when unset.

## What Changes

- **Add a consolidated per-model edit entry** — register a `model.dialog.config` command (binding `c`) on the model list. It opens a new `DialogConfig` submenu that lists `Set favorite` / `Clear favorite`, `Set hidden` / `Clear hidden`, `Note` (pushes the existing `DialogNote`; option title is `Note: <text>` when set, `Add note...` when empty), and the vision-fallback options. The submenu does NOT include a `Variants` option (variant picking is reached via the existing post-select flow).
- **Keep `ctrl+f` and `h` as direct shortcuts** — the model list's `actions[]` array retains `model.dialog.favorite` (binding `ctrl+f`, per `keybind.ts:121`) and `model.dialog.hide` (binding `h`, per `keybind.ts:122`) for high-frequency toggling. These are also dispatchable from inside `DialogConfig` for users who prefer the submenu.
- **Remove `n` from the model list and from the keymap** — the `model.dialog.note` action entry is removed from the model list, and the `model_note_edit` keybind (`n` -> `model.dialog.note`) is removed from `config/keybind.ts`. Notes are reachable only via `c` -> `Note` in `DialogConfig`.
- **Remove `v` (variant) entirely** — the `model.dialog.variant` action entry is removed from the model list, the `model_variant_list` keybind is removed, and the command ID itself is removed (no remaining trigger surface). Variant picking is reached via the post-select flow.
- **User-scope vision fallback (global + per-model)** — add two `state/model.json` fields:
  - `attachmentFallback: { providerID, modelID } | null` — the **global default**; consulted when no per-model override is set. Configured via the new `/vision-fallback` slash command (see below).
  - `modelAttachmentFallback: Record<string, { providerID, modelID } | null>` keyed by `providerID/modelID` — the **per-model override map**; an entry of `null` explicitly clears the global for that model (no fallback at all). The `fallbackFor(model)` accessor consults the per-model map first, then the global. Configured via the per-model options in `DialogConfig` (the `c` submenu on any model row).
  - Both load and persist via the existing `modelStore` + `writeJsonAtomic` path. No `kancode.json` writes.
- **`/vision-fallback` slash command** — registered in `sessionCommandList` (the same array that already hosts `/rename`, `/timeline`, `/fork`, `/compact`, `/undo`). The command opens `DialogFallback` with `commit={(target) => local.model.setAttachmentFallback(target)}`, a `current` prop showing the current global, and a `clearLabel="Clear global vision fallback"` + `onClear={clearAttachmentFallback}` row (visible only when a global is set). Aliases: `/vf`. This mirrors the discoverability of `/models`, `/sessions`, `/themes` and other global commands. The command is **not** exposed in the model list's footer action bar (that is reserved for per-model actions like favorite / hide / config).
- **`DialogConfig` exposes per-model fallback options only** — exactly one row in the vision-fallback section, drawn from a three-way branch: `No fallback needed (vision-capable)` (informational, when the model has `caps.attachment || caps.input.image || caps.input.pdf`; rendered without `disabled: true` because `DialogSelect` filters those out — pressing Enter is a no-op since there is no `onSelect`); `Set fallback vision model (<suffix>)` (when the model is text-only AND no per-model entry is set; suffix is `global: <target>` when the global is set, or omitted when no global either); or `Clear fallback vision model: <target>` (when the model is text-only AND a per-model entry is set; target is the per-model override value the action removes, or `(none)` for an explicit opt-out). To change the per-model value when one is set, the user clears first then sets (same two-step pattern as Clear favorite → Set favorite). The global default is configured via `/vision-fallback`, not from inside `DialogConfig`. There is intentionally no separate `Use global fallback (...)` status row — the row's own label carries the current state.
- **`DialogFallback` picker** — new component modeled on `dialog-variant.tsx`. Stateless, accepts a `commit` callback, a `current` target, and optional `clearLabel` + `onClear` props. When the user picks a vision model, `DialogFallback` calls `commit({ providerID, modelID })` and `dialog.pop()` (returns to the caller, e.g. `DialogConfig` or the prompt). When the user picks the clear row, `DialogFallback` calls `onClear()` and `dialog.pop()`. The slash command supplies `clearLabel` + `onClear` (so the user can clear the global from inside the picker); `DialogConfig` does NOT (it has its own `Clear` row in the submenu, so adding a second clear path inside the picker would be redundant). Esc returns to the caller without saving. The picker itself does not know whether the user is setting the global, setting a per-model override, or clearing — the caller chooses via `commit` and `onClear`.
- **`capabilityLine` learns about fallbacks** — when a model has no vision and `fallbackFor(model)` returns a target (per-model or global), the muted capability line shows the token `fallback-vision` immediately before the `+N variants` token (so a long variants list does not push it off the right edge). The target's name is not rendered in the row. Vision-capable models show `vision` regardless. The single-letter chip `c` in the action bar is the only "see your fallback" affordance. The `fallback-vision` token uses the row's default `theme.textMuted` color (same as `reasoning` / `tools` / `vision` / `+N variants`); the per-row override vs inherited distinction is only visible in the `DialogConfig` submenu's Set / Clear parentheticals, not in the row itself.
- **Set / Clear, not toggle** — the Favorite and Hide entries inside `DialogConfig` expose two mutually exclusive options (`Set favorite` / `Clear favorite` and `Set hidden` / `Clear hidden`). The action verb already conveys current state (Set = currently off, Clear = currently on), so no parenthetical is shown for these. The vision-fallback section follows the same pattern: the single visible row is `Set fallback vision model (<suffix>)` (suffix is `global: <target>` when only the global is set, or omitted when no global either) or `Clear fallback vision model: <target>` (the suffix is the per-model override value the action will remove, or `(none)` for an explicit opt-out). The Set and Clear rows are mutually exclusive — exactly one is visible at any time.
- **BREAKING for keybind overrides** — user `kancode.json` keybinds that bind a key to `model.dialog.note` or `model.dialog.variant` will fail validation after this change. The release notes call this out and suggest removing the override. The state shape change is non-breaking (additive keys with defensive loaders).

Non-goals / not in this change:

- Server-side / cross-session sync of `attachmentFallback`. This is per-user local TUI state, same scope as today's `favorite` / `hidden` / `notes`. Server-side wiring of the fallback is a separate change (touches `Protocol` / `Server` and requires `bun run generate`).
- kancode.json-level fallback configuration (`attachment.image.fallback_model` and the model-level `attachments.image.fallback_model` overrides). The schema additions are tracked in a follow-up change.
- Session-scope fallback override (per-turn override). Deferred.
- Surfacing the fallback target's name in the model row. Per the user request, the row shows only `fallback-vision`; the target is only visible inside `DialogConfig`.
- Changing the variant post-select flow (`resolveVariantApply` in `dialog-model-flow.ts`).
- Cross-provider fallback UX (key validation, "needs: OLLAMA_API_KEY" warnings). The picker lists all providers uniformly in v1.

## Capabilities

_(none — this change extends two existing capabilities; no new contract surface)_

### Modified Capabilities

- `model-user-state`: extend the persisted `state/model.json` shape with `attachmentFallback: { providerID, modelID } | null` (global default) and `modelAttachmentFallback: Record<string, { providerID, modelID } | null>` (per-model override map; active in v1). Add accessors `attachmentFallback` / `setAttachmentFallback` / `clearAttachmentFallback` / `hasAttachmentFallback` / `modelAttachmentFallback(model)` / `setModelAttachmentFallback(model, target)` / `clearModelAttachmentFallback(model)` / `fallbackFor(model)` (per-model then global). Defensive loaders and atomic-write integration as before.
- `model-selection-ui`: trim the model list's footer `actions[]` to four entries (`model.dialog.provider` / `favorite` / `hide` / `config`). Add the new `model.dialog.config` (binding `c`) entry that opens `DialogConfig`. Remove the `model.dialog.note` action entry from the model list and the `model_note_edit` keybind. Remove the `model.dialog.variant` action entry, the `model_variant_list` keybind, and the `model.dialog.variant` command ID entirely (variant picking is reached via the post-select flow). Update `capabilityLine` to render `fallback-vision` for non-vision models that have an effective fallback (per-model or global).

## Impact

- `packages/tui/src/context/local.tsx` — extend the `modelStore` type with `attachmentFallback` and `modelAttachmentFallback`; extend `save()` to write both; add defensive loaders; add `attachmentFallback` / `setAttachmentFallback` / `clearAttachmentFallback` / `hasAttachmentFallback` / `fallbackFor` accessors.
- `packages/tui/src/util/model.ts` — `capabilityLine` gains an optional `fallback` parameter and renders `fallback-vision` for non-vision models when a fallback is set.
- `packages/tui/src/util/model-row.tsx` — `modelRow`'s options interface gains an optional `fallback` field; the pure helper passes it into `capabilityLine`. No new imports. `model-row.tsx` is a pure function and cannot use `useLocal`.
- `packages/tui/src/component/dialog-config.tsx` (new) — `DialogSelect` submenu exposing `Set favorite` / `Clear favorite`, `Set hidden` / `Clear hidden`, `Note` (pushes existing `DialogNote`), and a single visible row in the vision-fallback section: either `No fallback needed (vision-capable)` (informational, when the model is vision-capable; rendered without `disabled: true` so `DialogSelect` does not filter it out), `Set fallback vision model (<suffix>)` (only when the model is text-only AND no per-model entry is set; pushes new `DialogFallback` routed to `setModelAttachmentFallback`; the suffix carries the global target when set), or `Clear fallback vision model: <target>` (only when the model is text-only AND a per-model entry is set; clears the entry directly). The three rows are mutually exclusive — exactly one is visible at any time. Per-model-only, no submenu closing after each direct toggle, no `Use global fallback (...)` status row. No `Variants` option, no global-fallback option — the global is configured via the `/vision-fallback` slash command.
- `packages/tui/src/component/dialog-fallback.tsx` (new) — `DialogSelect` listing only `input.image === true` (or `attachment === true` or `input.pdf === true`) models. Enter calls a `commit` callback supplied by the caller (the `/vision-fallback` command passes `setAttachmentFallback`; `DialogConfig` passes `setModelAttachmentFallback` for the model). Esc returns without saving. The picker is stateless about which setter to call.
- `packages/tui/src/routes/session/index.tsx` — add a `vision-fallback` entry to `sessionCommandList` (alongside `/rename`, `/timeline`, `/fork`, `/compact`, `/undo`). The entry's `slash.name` is `vision-fallback` with alias `vf`. `run` opens `DialogFallback` with `commit={(target) => local.model.setAttachmentFallback(target)}` and `current` set to the current global fallback. `dialog.clear()` is called after the pick via `DialogFallback`'s internal flow.
- `packages/tui/src/component/dialog-model.tsx` and `dialog-model-twopane.tsx` — `actions` array trimmed to four entries: `model.dialog.provider` (unchanged), `model.dialog.favorite` (binding `ctrl+f`, label toggles between `Favorite` / `Unfavorite`), `model.dialog.hide` (binding `h`, label toggles between `Hide` / `Unhide`), and `model.dialog.config` (binding `c`, `singleKey: true`, pushes `DialogConfig`). The `model.dialog.note` and `model.dialog.variant` action entries are removed. Every `modelRow(...)` / `buildModelRow(...)` call gains a `fallback: local.model.fallbackFor(model)` entry in the options object so each row reflects its own per-model override (or the inherited global).
- `packages/tui/src/util/model-row.tsx` (described above) is the central hook; `dialog-model.tsx` and `dialog-model-twopane.tsx` thread `local.model.fallbackFor(model)` into every `modelRow(...)` / `buildModelRow(...)` call.
- `packages/tui/src/config/keybind.ts` — add `model_config: keybind("c", "Edit model config")` and the corresponding command mapping `model_config: "model.dialog.config"`. Remove `model_note_edit` (binding `n`, command `model.dialog.note`) and `model_variant_list` (binding `v`, command `model.dialog.variant`) from both the keybind def block and the command mapping block. `model_favorite_toggle` (binding `ctrl+f`) and `model_hide_toggle` (binding `h`) are unchanged.
- `state/model.json` (user state) — additive `attachmentFallback: { providerID, modelID } | null` and `modelAttachmentFallback: Record<string, { providerID, modelID } | null>` keys; old files load with `null` and `{}` defaults.
- No `kancode.json` writes from the TUI. No Schema / Core / Protocol / Server / Client / SDK changes. No `bun run generate` needed. No database migrations. No `@kancode/cli` changes.
