# SOP: Developer Advocate

## قبل البدء
- راجع `5-api/api_standards.md` لفهم الـ API
- راجع `4-engineering/inner_source.md` لمبادئ open source
- راجع `4-engineering/technical_writing.md` لمعايير التوثيق

## سير العمل

### كتابة Tutorial جديد
1. اختر موضوعاً يطلبه المطورون (من التذاكر أو الـ community)
2. اكتب الـ code example كـ repo عملي (تشغيل من first clone)
3. اكتب الـ tutorial خطوة بخطوة
4. أضف screenshots / GIFs للتوضيح
5. اختبر أن الـ tutorial يعمل على بيئة نظيفة
6. انشر في: Blog + Dev.to + LinkedIn + Twitter/X
7. أضف link في الـ docs الرسمية

### إدارة Issue خارجي في Repo مفتوح
1. رحب بالمساهم الجديد خلال < 24 ساعة
2. صنّف الـ issue (bug / feature / question)
3. أضف الـ labels المناسبة
4. اسأل أسئلة توضيحية إن لزم
5. وجه المساهم إلى الـ contributing guide
6. راجع الـ PR بسرعة (أقل من 48 ساعة للرد الأول)
7. اشكر المساهم واحتفل بالـ merge

### تقديم Talk في مؤتمر
1. اختر موضوعاً مناسباً للجمهور
2. اكتب outline واجعله يوافق على الـ CFP
3. أنشئ presentation مع code demos
4. تمرّن 3 مرات على الأقل (مع فريقك)
5. قدم في المؤتمر
6. انشر الـ slides + repo + video link
7. اجمع feedback من الحضور

## القياسات
- Community PRs merged — متزايد شهرياً
- Tutorial satisfaction > 4/5
- Time to first response على الـ issues < 24 ساعة
- Blog posts published — 2+ شهرياً
- Conference talks — 4+ سنوياً
