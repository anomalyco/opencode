# SOP: Product Designer

## قبل البدء
- راجع `5-api/design_system.md` لنظام التصميم
- راجع `5-api/accessibility.md` لمعايير WCAG
- راجع `roles/13_ui_ux_designer.md` لدور مصمم UI/UX
- راجع `roles/10_product_manager.md` لدور PM

## سير العمل

### Feature Discovery
1. افهم المشكلة: Business context + User problem + Market data
2. اكتب الـ Hypothesis: "نعتقد أن... سيقود إلى... سنعرف أننا نجحنا عندما..."
3. جرّب حلولاً متعددة: ارسم 3-5 approaches
4. اختبر مع 5 مستخدمين: Concept testing
5. طوّر الحل الأفضل: Wireframes + Flows + Prototype
6. اختبر مع 8-12 مستخدمين: Usability testing
7. سلم الـ specs للـ UI/UX Designer للتفاصيل
8. تابع التنفيذ: Design review مع الـ Dev

### Design Sprint (5 أيام)
1. Understand: الخريطة، المشكلة، الـ goal
2. Diverge: Sketch solutions بشكل فردي
3. Decide: اختر الحل الأفضل صوتياً
4. Prototype: ابنِ prototype قابل للاختبار
5. Validate: اختبر مع 5 مستخدمين

### Cross-product Design Review
1. اجمع designers من جميع المنتجات
2. اعرض التصميم (context + decision + challenges)
3. اجمع feedback (ماذا يعمل، ماذا لا يعمل، ماذا يمكن أن يتحسن)
4. دوّن الـ action items
5. طوّر التصميم بناءً على الـ feedback

## القياسات
- Feature validation pass rate (تنجح في الـ testing من أول مرة) > 70%
- Design sprint velocity (عدد الـ cycles في الربع)
- Developer satisfaction مع الـ design specs > 4/5
- Design consistency عبر المنتجات (audit score) > 90%
- Time from discovery → handoff < 3 أسابيع
