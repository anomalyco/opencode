# Built-in authority audit

This audit follows registrations in [PluginInternal](./packages/core/src/plugin/internal.ts), [Tool](./packages/core/src/tool.ts), [CodeModeTool](./packages/core/src/codemode/tool.ts), and [McpTool](./packages/core/src/tool/mcp.ts). Classify additions to these catalogs against the sandbox boundary.

The OS boundary applies to agent shell commands, built-in file operations, and automatic formatter commands/probes. It does not isolate the server process, all configured capabilities, or arbitrary trusted plugin code. The macOS default grants read-only access to `/opt/homebrew/{Cellar,opt,bin,sbin,lib,include,Frameworks}`, including missing optional paths; these are protected from writes. Homebrew configuration, service data and other prefix directories receive no default read grant.

The absence of an approval prompt for a declared independent capability does not imply that the operation ran inside Seatbelt. In particular, Code Mode HTTP and configured MCP services can have broader authority than agent commands.

## Authority and lifetime

The server's host-owned sandbox settings are reused by every Location. Configured grants are pinned once across Location eviction and plugin reloads. `Sandbox.checkLocation` compares a session's canonical directory against the workspace pinned when the caller's policy was constructed; matching an additional writable root is not sufficient. Different explicit workspace/execution-host identities are refused.

The subagent leaf checks placement before model/agent changes, child creation and prompt admission. The ordinary subagent permission, parent-child ownership check and depth limit still apply. Switching agent or model does not change host policy. A moved child must be moved back explicitly or replaced with a new child in the current workspace.

`Session.create({ parentID })` derives placement from the existing parent. `SessionExecution` and `SubagentJob` remain global coordinators; they do not grant a new sandbox root. Recovery resumes the child's recorded placement, which agent-driven moves can change only through the forced workspace approval. Human/API placement changes retain their separate authority.

Shell launch policy is fixed for each invocation after hooks and approval. A running background command is not rewrapped or granted a new root when a session subsequently moves. Location teardown still owns its process/helper resources and private scratch cleanup.

Registered references grant trusted read access without changing existing write permissions. A reference inside the workspace or another writable root remains writable unless separately protected. Each confined launch resolves the current registry, including asynchronous Git checkouts; existing aliases are pinned for the Location and a changed target fails closed. OpenCode's data directory remains denied except for explicit reference roots within it, with credentials, databases and private state denied again after the reference grants. Existing processes retain the policy with which they started.

At Location startup Git reports system and global configuration origins, including active includes. These host-owned files receive individual read-only grants; repository-controlled include origins are not trusted. Existing read exclusions take precedence, and configuration values are not collected by discovery. Git configuration can itself contain sensitive information, which becomes readable through the granted files.

## Trusted host services and human operations

| Service or entry point                                                                      | Classification and retained behavior                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Automatic Git snapshot capture                                                              | Disabled while sandboxing is active, independently of the project `snapshots` setting. Capturing agent-modified files can invoke configured Git filters; it must not become an automatic host-execution path. New per-step snapshots and the undo/diff behavior that depends on them are therefore unavailable in this mode.                                                                                        |
| Git, VCS status/diff, snapshot history, worktree services                                   | Remain host services for the human-facing API/UI. They are not globally wrapped in Seatbelt. Snapshot filesystem restoration is disabled alongside capture while sandboxing is active, including for older snapshots. Built-in model tools do not expose a general VCS or snapshot API, and mutating worktree leaves are blocked before service invocation.                                                         |
| Configuration, initial instructions, skill discovery/watchers and registered plugin content | Trusted host configuration capability. Loading/reloading configured sources can read host files or fetch configured URLs. These loaders remain outside the command boundary; model-triggered read discovery uses confined bytes, and the skill leaf does not scan resource paths. The feature does not isolate a trusted loader or plugin from the files its user-selected configuration instructs it to consume. |
| Provider authentication, inference, model discovery and session titles/compaction           | Trusted server/provider traffic. These services need network and credential access independently of agent command networking. Model switching changes provider selection, not the command policy.                                                                                                                                                                                                                   |
| Shell/tool output capture, blobs, session/database storage, logs and cleanup                | Trusted, bounded harness bookkeeping at host-chosen paths. Model input cannot select an arbitrary write destination through these services. Retained output under protected host state is not automatically readable through native file tools; an approved shell escape may be needed to inspect the complete retained file.                                                                                       |
| Human-operated terminal/PTY, `Session.shell`, explicit attachments and slash commands       | Human/API capabilities. They can intentionally use host authority and are not model-facing `shell` tool invocations. The built-in subagent tool supplies text only; it does not pass file or skill attachments to prompt admission.                                                                                                                                                                                 |
| Executable plugins and configured MCP startup                                               | Trusted code/services with host authority. Plugins can register replacement tools or call host APIs. Explicitly configuring an external browser plugin is also a trusted plugin action; disabling the shipped browser plugin does not isolate arbitrary plugin code.                                                                                                                                                     |

## macOS runtime allowances

The Seatbelt profile shares runtime allowances across commands, file helpers, searches, and formatters in both read modes. These allowances support common system and toolchain operations while limiting access outside the sandbox.

| Allowance | Policy and rationale |
| --- | --- |
| `sysctl-read` | Allows specific CPU, OS, and resource-query names and the `hw.optional.` and `hw.perflevel` feature and topology prefixes. These queries can disclose machine characteristics, hostname, and load. The `sysctl.name.` and `sysctl.oidfmt.` metadata prefixes enable ordinary `sysctl` command output, but can disclose some names and types of otherwise denied keys; partial name enumeration is possible. Description and next-entry metadata are not granted. Process and routing-table values remain denied unless explicitly allowed. |
| `process-info*` | Explicitly denies process inspection by default, with an allowance for processes in the same sandbox. The explicit denial is necessary because Seatbelt's default disposition can otherwise permit access to another same-user process's arguments and environment via numeric `KERN_PROCARGS2`. Self and child inspection remain available. |
| `sysctl-write` | No grant. |
| Execution, children, and signals | Allows process execution and fork, and signals and inspection within the sandbox. Descendants inherit confinement. Signals to processes outside the sandbox are denied. Process-count, CPU, and memory quotas are not implemented. |
| Mach and IPC | Allows the named `com.apple.system.opendirectoryd.libinfo` lookup for account-name resolution. Arbitrary Mach lookup, networking, and Unix sockets are not granted. |
| Loader bootstrap | Imports Apple's `dyld-support.sb` for loader root and Cryptex reads, mappings, and required syscall and fcntl rules. The broader `system.sb` is not imported. The profile explicitly denies fcntl commands 80 and 110. |
| Filesystem metadata and devices | Allows filesystem metadata access for path traversal and stat; this can disclose names and existence, but not arbitrary file contents. Device access is limited to standard I/O needs such as null/zero, random sources, and `/dev/fd`. |
| Runtime file reads | Allows selected system and Homebrew roots. `/private/etc` and `/Library/Preferences` support runtime compatibility but are not guaranteed secret-free. Homebrew configuration and service-data roots do not receive default grants. |

The native regression fixture uses canaries in a test-owned process and positive controls outside the sandbox. Tests cover named and numeric sysctl queries, host argument and environment inspection, host signals, self and child inspection, and sysctl writes in both read modes. Runtime tests also exercise compilation, account lookup, and supported language runtimes and formatters. Optional cases skip when their runtime or Seatbelt is unavailable; `bun run test:sandbox` in `packages/core` requires the enforcement cases to run without skips.

Apple's [sysctl implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_newsysctl.c) identifies the metadata lookups as private interfaces and returns an entry's name, kind and format rather than its value. The policy relies on Seatbelt to distinguish these metadata requests from value reads; regression tests verify that distinction against the running kernel.
