Is the fork still a coding agent wearing a hiring badge?

Thesis: moks is to talent acquisition what OpenCode is to software engineering. “Code is everything” means the shape of the work ports — workspace, plan, tools, review, push — not that recruiters write software.

How to read this review

What “code is everything” actually means

We do not rebuild the harness. Session runner, permissions, MCP, skills, and plan-mode stay. We rewrite the job from “ship software” to “fill reqs with evidence.”

moks · hiring

Fill the req

Open a requisition. Plan the loop. Score and draft. Review the packet. Commit. Push to the ATS.

Already correctly ported

The v0 backlog claimed these shipped. The agents checked the code. They did.

  • Default doer is recruit. Hidden build only via --agent build or default_agent: build. Plan exit switches to recruit with hiring language.
  • Config identity is isolated. Loads only moks.json(c) and .moks/. Global dir is ~/.config/moks. Personal OpenCode files are ignored.
  • /init scaffolds .moks/reqs/<slug>/. JD, scorecard, notes, scores folder. /init-code is hidden from the slash menu.
  • /review is packet review. Explicitly not gh pr. Orchestrates score / outreach / disposition.
  • Four hiring skills exist. req-context, score-candidate, draft-outreach, commit-disposition. Plus customize-moks.
  • Decision verbs match the thesis. Dry-run default. Reject / offer / hire need --confirm on push. No ATS write. activity --days 7 exists.
  • Ashby writes denied on recruit and at the MCP host. Build also denied. Host adapter returns “use commit/push” even if config tries to allow.
  • Last @slug focuses that req. Injects JD / scorecard / notes. Last mention wins. Legacy .moks/req still works.
  • TUI decisions are operable. Human receipt list. Push picks an open commit. Score inference only if one req exists. MOKS_ENTRY set for bun dev.
  • Outreach drafts persist. draft-outreach writes .moks/reqs/<slug>/outreach/<cand>.md. /review looks there.
  • Tips are hiring-first. No more random coding-harness dump. No /share or moks serve tip.
  • Cheap identity leaks closed. serve hidden from help. Username / mDNS default moks. Theme picker labels default theme moks. PATCH /config writes moks.json. Share and websearch honor MOKS_* only.
  • LSP and formatters off unless configured. Sidebar and footer hide empty IDE chrome. Diff is kept on purpose.
  • Subagents are remolded. Explore searches req materials. General is domain-neutral. Titles/summaries are mostly hiring-native.
  • GitHub / PR / generate / console hidden from help. Still in the binary if you type them. Not on first-run help.

Thin cut — reuse slots, do not build an ATS

The harness is already transcript + composer + 42ch plugin sidebar. Fill those slots.

  • Session placeholders = home set. Pass “Score this resume / Draft outreach / Open a req with /init” into the session Prompt. Prefix can say “Work this req…” instead of “Ask anything…”.
  • One empty-state line where the spacer is. No req open · /init · @slug to focus plus /commit /push /decisions. Not a tips carousel.
  • Hide Context until tokens > 0. Cost already appears on the prompt hint after a turn. Two copies of “$0.00” is the bug.
  • Rename Modified Files → Local hiring changes. Keep the list and Diff. Do not delete session.diff.
  • Treat @slug as a Req chip. Transcript: Req @senior-backend, not Directory senior-backend.
  • Optional Desk block at sidebar order 50. Current focus, last score, pending decision count. Hide empty rows. Do not preview the JD.

After the thin cut the empty session should read:

No req open · /init · @slug to focus
Work this req… “Score this resume against the req”
Recruit · model  ·  @senior-backend   /commit /push

Do not delete Diff, invent a TA-LSP, add a packet/kanban pane, resurrect the dead session footer, or replace the prompt with an ATS form. Packet stays /review. Verbs stay slash/palette.
