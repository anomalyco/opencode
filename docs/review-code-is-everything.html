Is the fork still a coding agent wearing a hiring badge?

Thesis: moks is to talent acquisition what OpenCode is to software engineering. “Code is everything” means the shape of the work ports — workspace, plan, tools, review, push — not that recruiters write software.

The one-screen answer

Verdict

The job object is rewritten on the default path. A recruiter who opens moks gets recruit, not build. /init makes a requisition, /review reviews a packet, and moks commit / push record hiring decisions — they do not move ATS stages.

The product still feels like a coding IDE with hiring tips taped on. The persistent TUI is files, tokens, MCP, and “Modified Files.” There is no open-req chip, no hiring-book navigator, and decision dialogs dump JSON. @slug is advertised as focus but does not attach the JD.

Branding and identity isolation mostly landed (moks.json, .moks/, ~/.config/moks, MOKS_*). Remaining work is glue, not another rename sweep.

Already correctly ported

The v0 backlog claimed these shipped. The agents checked the code. They did.

  • Default doer is recruit. Hidden build only via --agent build or default_agent: build. Plan exit switches to recruit with hiring language.
  • Config identity is isolated. Loads only moks.json(c) and .moks/. Global dir is ~/.config/moks. Personal OpenCode files are ignored.
  • /init scaffolds .moks/reqs/<slug>/. JD, scorecard, notes, scores folder. /init-code is hidden from the slash menu.
  • /review is packet review. Explicitly not gh pr. Orchestrates score / outreach / disposition.
  • Four hiring skills exist. req-context, score-candidate, draft-outreach, commit-disposition. Plus customize-moks.
  • Decision verbs match the thesis. Dry-run default. Reject / offer / hire need --confirm on push. No ATS write. activity --days 7 exists.
  • Ashby writes denied on recruit. Read tools allowed; stage-change / note-create denied. Mock errors point at commit/push.
  • LSP and formatters off unless configured. Sidebar and footer hide empty IDE chrome. Diff is kept on purpose.
  • Subagents are remolded. Explore searches req materials. General is domain-neutral. Titles/summaries are mostly hiring-native.
  • GitHub / PR / generate / console hidden from help. Still in the binary if you type them. Not on first-run help.
Where a recruiter still feels a coding agent

Felt gaps — GO

These are the items that break the metaphor in use, not in a string search.

@slug does not actually focus a req

The thesis says mentioning a req loads that JD and scorecard. Today it only attaches a folder listing. Auto-attach of materials happens only if you are inside the req folder, or the book has exactly one req. Two reqs at the workspace root → empty hiring context.

High GO
Fix: last @slug (or an explicit focus) should inject that req’s JD / scorecard / notes. Stop claiming “@slug focuses” until it does.

TUI decisions look like a debugger

/commit, /push, and /decisions exist — good. They show raw JSON. Push asks you to type a dec_… id. Commit silently picks the newest score file across every req. Under bun dev, the TUI may fail to find the moks binary at all.

High GO
Fix: human list of open decisions, pick-to-push, bind score to the focused req, call verbs in-process instead of spawning a binary.

Session chrome is still an IDE

Home tips and placeholders teach hiring. The session itself is a blank prompt plus Context / MCP / Modified Files. No open-req chip. No book navigator. No packet pane. A recruiter is looking at a code editor that happens to mention “req” on the welcome screen.

GO · thin
Fix: one sidebar or home slot — open reqs from .moks/reqs, current focus, last score, pending decision. Keep Diff; rename “Modified Files” to local hiring deltas. Do not build a full ATS UI.

Outreach drafts die with the chat

draft-outreach prints email in the conversation and never writes a file. /review then looks for “outreach drafts” that do not exist. Score is the only skill that leaves a durable artifact.

GO
Fix: write .moks/reqs/<slug>/outreach/<candidate>.md. Review can then see it the way a PR sees a diff.

Tips still mostly teach a coding harness

The first six tips are hiring-correct. Then ~70 generic tips rotate at random — shell !ls, writing .ts plugins, AGENTS.md, share links. A new TA is more likely to see a coding-agent tip than /init.

GO
Fix: hiring-first rotation. Keep a handful of harness tips (connect, models, sidebar). Hide /share — share-to-OpenCode is already disabled.

/diff opens git mode · /status means two things

Diff should show last-turn / .moks/ working-tree changes, not “vs main branch.” TUI /status is system status (MCP, LSP). CLI moks status is decision receipts. Users will type the wrong one.

GO
Fix: default Diff to session / .moks. Rename TUI status to “system status.” Teach /decisions as the inspect verb.

Help still presents a coding product with extra verbs

moks --help leads with TUI + run (good) then serve, stats, export/import. Headless is supposed to be a mode, not a pillar. Hidden but fully wired: github, pr, generate, console.

GO
Fix: hide serve (and maybe stats) from help. Do not polish GitHub/PR. First help should read: TUI, run, commit, status, push, activity, mcp, providers.

Agents can still be taught the old singleton tree

Runtime scaffolds .moks/reqs/<slug>/. The customize-moks skill still draws .moks/req/ as the canonical layout. Ask it to set up a workspace and it will build the leftover path.

GO
Fix: one diagram, one path. Keep reading legacy .moks/req as fallback; stop teaching it.

Wrong-port risk if we “just add more UI.”

A full packet-review product or ATS clone would abandon the thesis. The coding analog of a file tree is a req book + diff of local artifacts, not Greenhouse-in-the-terminal. Thin focus chrome. Keep Diff. Do not invent a TA-LSP.

OpenCode still leaking into the product

Identity leaks — GO if cheap

Isolation is real for config files. A few env vars and chrome names still say OpenCode.

Personal OpenCode env can still change moks

The Flag module only reads MOKS_*. Some code bypasses it: OPENCODE_DISABLE_SHARE is dual-read, websearch flags are OpenCode-only, console token is written into the process as OPENCODE_CONSOLE_TOKEN.

GO
Fix: route leftover gates through MOKS_*. Do not honor personal OpenCode env.

Visible leftovers: username, mDNS, theme, OAuth

Basic-auth default user is opencode. Help says moks.local but default is opencode.local. Default TUI theme id is opencode. MCP OAuth consent shows opencode.ai. PATCH /config writes unread config.json. Launcher cache dir is still .opencode.

GO
Fix: moks username, moks.local, display-name the default theme, write moks.json, cache under .moks.

Shared tools still talk like a software engineer

Recruit never loads the “you are a coding agent” provider prompts — those only fire on build. But title examples still include “debug 500 / refactor user service.” Agent-create teaches code-reviewer and test-generator. The task tool offers “tests if this is engineering work.” AGENTS.md is still auto-injected into every session, including recruit — dangerous in a software repo.

GO
Fix: hiring title examples; neutralize generate.txt / task copy; stop auto-injecting AGENTS.md on the recruit path (keep for build / /init-code).

Ashby write-deny is recruit policy, not a host rule

On recruit, write tools are hidden and denied. User config can re-allow them. Hidden build has no Ashby denies. Mock is not on by default. No session test that recruit cannot call ashby_change_stage.

GO · safety
Fix: deny writes at the MCP adapter regardless of agent. One permission test. Document that moks.json must not flip this.

If we do one more wave

Recommended next cut

Make the loop felt. Then stop and measure WAU. Do not start Cloud, V2 parity, or a rename.

  1. Focus is real. @slug injects that req’s materials. Without this, a hiring book with two reqs is a coding workspace that happens to contain markdown.
  2. Decisions are operable. Human receipt list, pick-to-push, in-process verbs, score bound to the focused req. Commit / push are the authority layer. If they feel like JSON debug, the metaphor fails.
  3. Outreach is a file. Drafts land under the req so /review can see them. Score already does this. Outreach should match.
  4. Thin req chrome. Open reqs + current focus + pending decision. Reframe Diff. Reweight tips. Enough to stop feeling like VS Code. Not a new product surface.
  5. Close cheap leaks. Theme display name, auth username, mDNS, customize-moks tree, hide serve, Ashby host-level write deny, one test. Identity hygiene. Half a day, not a pillar.

Success test for this wave: an eng-TA opens a book with two reqs, types @senior-backend, scores a resume, drafts outreach, /reviews the packet, /commits reject, and /pushes with confirm — without ever seeing “Modified Files,” JSON, or a coding tip.

Do not confuse three OpenCodes.

This review is about moks (this repo). OpenCode upstream is lineage. The installed OpenCode on your machine is the tool that built this review — not the product.
