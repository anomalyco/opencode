10 Graduate criteria → Cloud

  • Partner runs a live req in the harness weekly.
  • They hit a wall: multiplayer, audit, adverse gates, or “who changed stage?”
  • Cloud turns on kernel dials — same verbs, server authority.
  • ATS remains connected; product becomes SoR for decisions (moks Cloud).
Architecture rule: Open may feel like an MCP host; it must not become a sovereign thin client we have to migrate off of.

12 Ship decision — first principles

Get the OSS TUI out. Build on it only if people use it. Ship vehicle: this repo (moks) — hard fork, company surfaces pruned. The loop is local. Remote and Cloud wait on usage.

Ship in v0

  • OSS TA harness — run in about a minute
  • TUI + headless same package
  • Hiring skills + local req book (HIRING.md + cards)
  • Git audit + confirm-on-adverse + moks push
  • Prove WAU eng-TA

Defer

  • Rooms as GTM / multiplayer SoR
  • CLI as co-equal product pillar
  • Full multi-ATS write matrix
  • Server kernel ceremony as day-0 hero
  • Lock bumps, company-narrative polish
