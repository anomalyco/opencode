4 Wedge & GTM motion

  • Who: eng-led TA, recruiting ops, technical founders — already agent-curious.
  • Motion: curl | bash / brew → Discord → design partners → enterprise seats.
  • Language: “OpenCode for hiring” publicly; “GitOps control plane” in enterprise.
  • Not day-1: entire TA industry, rip-and-replace ATS, ungated autonomous hire.
OpenCode paste: free beloved loop + local-first trust; money on org control of how agents run (and our kernel), not on locking the TUI.

5 90-day open scope

  • Ship MIT harness (TUI + headless) with hiring verbs & skills (req, candidate, scorecard, outreach draft).
  • First-class MCP read for 1–2 ATSs + notes tool.
  • Every material action appends a local decision receipt.
  • Adverse actions default to confirm; hero demo ≠ silent advance_stage.
  • Freeze shared write verbs (propose / apply / --json); TUI shells them — don’t staff a separate CLI roadmap.
  • One flagship path to Cloud: “sync this req / turn on checks.”

8 Incumbent bet

Ashby/GH unlikely to ship beloved OpenCode-class TUI soon. They will ship good-enough in-dashboard agents. We win on cross-tool + kernel + workplace — not on “they never do AI.”

9 Do / don’t

Do OSS harness; keep apply/policy authority ready for Cloud; paranoid PII defaults.
Do MIT for adoption; enterprise = SSO, allowlists, audit, seats.
Don’t Make raw vendor MCP writes the identity or the viral demo.
Don’t Optimize for acquihire architecture (single-ATS skin only).
Don’t Assume recruiter Twitter = GitHub stars. Tribe is eng-adjacent TA.
Don’t Staff CLI as a co-equal GTM pillar before kernel-on; don’t put policy/apply eligibility in the client.

10 Graduate criteria → Cloud

  • Partner runs a live req in the harness weekly.
  • They hit a wall: multiplayer, audit, adverse gates, or “who changed stage?”
  • Cloud turns on kernel dials — same verbs, server authority.
  • ATS remains connected; product becomes SoR for decisions (moks Cloud).
Architecture rule: Open may feel like an MCP host; it must not become a sovereign thin client we have to migrate off of.

12 Ship decision — first principles

Get the OSS TUI out. Build on it only if people use it. Greenfield vehicle: this repo (moks) — no prior monorepo debt. Prior experiments are reference only; not the ship path.

Ship in v0

  • OSS TA harness — run in about a minute
  • TUI + headless same package
  • Hiring skills + MCP read (1 ATS first)
  • Local decision receipts + confirm-on-adverse
  • Prove WAU eng-TA

Defer

  • Rooms as GTM / multiplayer SoR
  • CLI as co-equal product pillar
  • Full multi-ATS write matrix
  • Server kernel ceremony as day-0 hero
  • Lock bumps, company-narrative polish
v0 slice Done means
Install curl | bash / npm — one binary/name (moks)
TUI Chat + tool/status chrome (Ink / OpenTUI-class)

Edges 1 ATS MCP read (Ashby or Greenhouse)
Receipts Every material action → local JSONL
Writes Dry-run default; adverse = confirm; no silent advance_stage hero demo
Headless Same verbs with --json for agents

Out of v0: multiplayer rooms, server policy cathedral, thick watch/CI product, Postgres, dual-ATS polish.

Only metric that matters: weekly active eng-TA running a real req in the TUI. No WAU → don’t build Cloud. WAU + “who changed stage?” pain → kernel-on.
