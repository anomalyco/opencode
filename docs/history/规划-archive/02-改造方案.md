# 02 — 改造方案(fork 路线)

> ⚠️ 本方案是技术上可行的实施路径,但**是否适合分发给普通用户,请先看 03 评估**。

## 整体思路

**不动 `packages/ui/file.tsx`**(避免影响 review/diff 路径,避免破坏 `@pierre/diffs` 的复杂依赖图),只在 `packages/app/src/pages/session/file-tabs.tsx` 的 `FileTabContent` 组件里加"编辑模式切换":

- **查看态(默认)**: 走原 `renderFile()` → PierreFile 只读渲染 + 行评论叠层
- **编辑态**: 卸载 PierreFile DOM,挂 CodeMirror 6 实例,隐藏行评论,显示"保存/取消"按钮
- **保存**: 通过新增的 Tauri command 把内容 `std::fs::write` 写回磁盘,触发 useFile 缓存失效重新拉取

按用户偏好(memory: "新功能优先独立原型再合并主项目"),分 5 个阶段。

## Phase 0 — 独立 prototype(不动 opencode)

**目标**: 验证"SolidJS + CodeMirror 6 + Tauri write_file"链路可行。

**位置**: `D:\project\opencode-editable-prototype`

**步骤**:
1. `bun create solid` → 选 TypeScript template
2. `bun add @codemirror/state @codemirror/view @codemirror/commands @codemirror/lang-markdown @codemirror/lang-javascript @codemirror/language @codemirror/theme-one-dark`
3. `bun add @tauri-apps/api @tauri-apps/cli` + `bun tauri init`
4. 写一个最小页面:
   - 顶部: 一个文件路径输入框 + "加载"按钮
   - 主区: CodeMirror 6 编辑器
   - 底部: "保存"按钮 + 状态提示
5. Tauri 后端 `src-tauri/src/lib.rs` 暴露两个 command:
   ```rust
   #[tauri::command]
   fn read_text_file(path: String) -> Result<String, String> {
       std::fs::read_to_string(&path).map_err(|e| e.to_string())
   }
   #[tauri::command]
   fn write_text_file(path: String, content: String) -> Result<(), String> {
       std::fs::write(&path, content).map_err(|e| e.to_string())
   }
   ```
6. 前端 `invoke('read_text_file', { path })` / `invoke('write_text_file', ...)`

**验证点**:
- SolidJS `onMount` 里 `new EditorView({...})`,`onCleanup` 里 `view.destroy()` 不漏 DOM
- markdown 文件 `.md` 加载有高亮
- 改完保存,关闭程序后重启加载,内容已变
- 大文件(>1MB)滚动是否流畅(CodeMirror 6 默认就有虚拟化,通常没问题)

**预计时间**: 0.5-1 天(熟悉 CodeMirror 6 API 是主要成本)。

## Phase 2 — 改 `file-tabs.tsx`

**关键修改文件**: `packages/app/src/pages/session/file-tabs.tsx` 中的 `FileTabContent` 组件。

**新增局部状态**:
```tsx
const [editing, setEditing] = createSignal(false)
const [draft, setDraft] = createSignal<string | null>(null)
const dirty = () => draft() !== null && draft() !== contents()
```

**UI 变化**:
- 在 `FileTabContent` 顶部(ScrollView 上方)加一个工具条:
  - 非编辑态: `<IconButton icon="edit" onClick={() => setEditing(true)}/>`
  - 编辑态: `<IconButton icon="save" disabled={!dirty()} onClick={save}/>` + `<IconButton icon="x" onClick={cancel}/>` + dirty 圆点
- 渲染分支:
  ```tsx
  <Show when={editing()} fallback={renderFile(contents())}>
    <CodeMirrorView
      value={contents()}
      language={langFromExt(props.tab.path)}
      onChange={setDraft}
    />
  </Show>
  ```
- 编辑态需要一并隐藏行评论叠层(在 `session-side-panel.tsx` 里把 `commentedLines` / 评论 layer 在 `editing===true` 时不渲染)

**新增组件**: `packages/app/src/components/code-mirror-view.tsx`

```tsx
import { createEffect, onCleanup, onMount } from "solid-js"
import { EditorView, basicSetup } from "codemirror"
import { EditorState } from "@codemirror/state"
import { markdown } from "@codemirror/lang-markdown"
import { javascript } from "@codemirror/lang-javascript"

export function CodeMirrorView(props: {
  value: string
  language: "markdown" | "javascript" | null
  onChange: (v: string) => void
}) {
  let host!: HTMLDivElement
  let view: EditorView | null = null

  onMount(() => {
    const lang = props.language === "markdown" ? [markdown()]
              : props.language === "javascript" ? [javascript()]
              : []
    view = new EditorView({
      doc: props.value,
      extensions: [
        basicSetup,
        ...lang,
        EditorView.updateListener.of(u => {
          if (u.docChanged) props.onChange(u.state.doc.toString())
        }),
      ],
      parent: host,
    })
  })

  onCleanup(() => view?.destroy())

  return <div ref={host!} class="cm-host h-full" />
}
```

**辅助**: 加 `langFromExt(path: string)`(放 `packages/app/src/utils/`),根据扩展名返回 `"markdown" | "javascript" | null`。

**未保存切 tab 提示**: 利用现有 `dialog-*` 组件风格,在 `session-side-panel.tsx` 监听 tab 切换前 hook,如果当前 tab 处于 editing 且 dirty,弹"放弃修改 / 保存 / 取消"。

**预计代码量**: 250-450 行 TypeScript / TSX(含小工具 + 国际化文案)。

**预计时间**: 2-4 天。

## Phase 3 — 写回磁盘 + 通知 sidecar

**前端 save 逻辑**:
```ts
async function save() {
  await invoke("write_text_file", { path: props.tab.path, content: draft()! })
  setEditing(false)
  setDraft(null)
  // 让 useFile 缓存失效,重新拉
  await refetchFile(props.tab.path)
  // 通知 sidecar(如果它没有自带 fs watcher)
}
```

**后端 Rust command**(`packages/desktop/src-tauri/src/`):
```rust
#[tauri::command]
async fn write_text_file(path: String, content: String) -> Result<(), String> {
    tokio::fs::write(&path, content).await.map_err(|e| e.to_string())
}
// 在 invoke_handler! 里注册
```

**注意**:
- 不用 `tauri-plugin-fs`(它的 scope/权限模型对桌面 app 全盘文件树过于碎,自己 command 更直接)
- 保存前可加可选: 先比对 mtime,如果本地 mtime 比加载时新 → 弹冲突提示(防止 AI 同时改了同一文件)
- sidecar 那边 (`packages/opencode`) 多半已有 fs watcher,要查代码确认 — 如果有,前端不用主动通知;没有则要新增 IPC

**预计时间**: 1-2 天(主要是冲突场景测试)。

## Phase 4 — 打包 + 分发

**Windows**:
- `bun run tauri build` → 产出 `target/release/bundle/nsis/OpenCode_x.y.z_x64-setup.exe` 或 msi
- **代码签名**: 不签的话普通用户首次运行会被 SmartScreen 拦截,弹"未知发布者"红警告,极少有人敢点"仍然运行"
  - EV 代码签名证书 ¥3000-8000/年(GlobalSign / DigiCert)
  - 不能用官方 sst 的签名(会侵权)
- **替换或并存**: 备份 `D:\Program Files\OpenCode\OpenCode.exe` 后替换;或安装到 `D:\Program Files\OpenCode-Custom\` 并存

**自动更新**:
- 官方 OpenCode 有 Tauri Updater(本机有 `OpenCode-1.14.20-updater-73nDDL` 临时目录证据),指向 sst 的更新服务器
- fork 后必须**自己搭 update server**(Tauri 支持自托管 JSON manifest),否则用户永远停在你打包那一刻的版本,无法跟随上游修 bug
- 这是分发给"很多普通用户"最棘手的环节 — 见 03 详细评估

**预计时间**: 首次签名 + 自动更新搭建 3-5 天;之后每次发版 0.5 天。
