# 01 — 架构定位

> 所有源码引用基于 sst/opencode `dev` 分支 (https://github.com/sst/opencode)。本机安装版本: `D:\Program Files\OpenCode\OpenCode.exe` (1.14.20)。

## 整体技术栈

- **桌面壳**: Tauri v2 (Rust + 系统 WebView,Windows 上是 WebView2,见本机的 `EBWebView` 缓存目录 `C:\Users\yuexi\AppData\Local\ai.opencode.desktop\EBWebView`)
- **前端框架**: SolidJS + Vite + TypeScript + TailwindCSS
- **包管理**: bun + monorepo (workspaces)
- **后端 sidecar**: opencode-cli.exe (本机在 `D:\Program Files\OpenCode\opencode-cli.exe`),提供 HTTP API
- **关键前端依赖**:
  - `marked` + `marked-shiki` + `marked-katex-extension` — markdown 渲染
  - `shiki` — 语法高亮
  - `dompurify` — HTML 净化
  - `@kobalte/core` — 无样式 UI 原语
  - `virtua` — 虚拟滚动
  - **`@pierre/diffs`** — 文件 / diff 渲染引擎(**这是关键私有依赖**,后述)

## monorepo 结构

```
packages/
├── desktop/          # Tauri 壳 (Rust src-tauri/ + 前端 entry)
├── desktop-electron/ # Electron 替代实现(并存)
├── app/              # 主 UI 应用 (SolidJS) — 改动主要在这里
├── ui/               # UI 组件库(被 app 复用) — 文件查看器在这里
├── web/              # opencode 官网(Astro,跟桌面无关)
├── opencode/         # 核心 sidecar
├── sdk/              # SDK
├── plugin/           # 插件框架
├── enterprise/       # 企业版
├── slack/, identity/, function/, containers/  # 周边
└── ...
```

## 文件查看器的完整渲染链路

打开一个文件后,右侧出现的"审查 / 文件名 / +"标签栏 + 内容区,代码路径如下:

```
packages/desktop/src/index.tsx
  → 加载 @opencode-ai/app 的 AppInterface (实际就是 packages/app)
       ↓
packages/app/src/pages/session/session-side-panel.tsx
  ├─ 整个右侧面板的开关与宽度调度 (reviewOpen() / fileOpen())
  ├─ Tabs.Root 包含三类 tab:
  │    ├─ <Tabs.Content value="review">    → review-tab.tsx (diff 视图)
  │    ├─ <Tabs.Content value="context">   → SessionContextTab
  │    └─ For 每个 openedTabs() → <FileTabContent tab={tab}/>   ← 普通文件预览
       ↓
packages/app/src/pages/session/file-tabs.tsx 的 FileTabContent
  ├─ useFile() 通过 sidecar HTTP 拿文件内容
  ├─ <Switch>
  │    case loaded   → renderFile(contents())
  │    case loading  → 加载提示
  │    case error    → 错误提示
       ↓
packages/ui/src/components/file.tsx 导出的 <TextFile mode="text" file=...>
  ├─ props 类型: TextFileProps = FileOptions<T> & SharedProps<T> & {
  │      mode: "text"
  │      file: FileContents
  │      annotations?: LineAnnotation<T>[]
  │      preloadedDiff?: PreloadMultiFileDiffResult<T>
  │   }
  ├─ SharedProps 的全部回调: onLineNumberSelectionEnd / onRendered
  │   → 没有 onChange / onInput / setContent / editMode 任何编辑相关 prop
  └─ 内部:
       new PierreFile<T>(opts, workerPool)   ← @pierre/diffs
       └─ .render() 输出只读 DOM (Shiki 高亮 + virtua 虚拟滚动)
       ↓
packages/ui/src/components/line-comment.tsx 系列
  ├─ LineCommentAnchor: 绝对定位浮在文件 DOM 上(top: Npx)
  ├─ LineComment: 显示已存评论
  ├─ LineCommentAdd: "+" 按钮新建
  └─ LineCommentEditor: textarea 编辑评论本身
       → 不参与文件正文渲染
```

## 关键事实(用于评估改造可行性)

1. **`<TextFile>` 组件设计上完全只读**,接口里没有任何编辑 hook,不能通过加 prop 解决。
2. **底层 `@pierre/diffs` 是 Pierre 公司的私有 npm 包**,公开 npmjs 页面访问 403,源码不公开。它是 Pierre(GitHub PR 审查工具公司,sst 开源项目早期支持者)的 diff 渲染引擎。**fork opencode 后能不能 `bun install` 通过,取决于这个包的访问权限,见 04 风险文档**。
3. **`inline-editor.tsx`**(在 `packages/app/src/pages/layout/`)是单值字段编辑(改文件名、项目名用),**不是代码编辑器**,不能复用。
4. **`review-tab.tsx`** 用的是另一个组件 `SessionReview` 渲染 diff(见 props `diffs / diffStyle / onLineComment`),跟普通文件 tab 是不同路径,**不在改造范围内**。
5. **行评论是绝对定位叠层**,跟文件正文 DOM 通过行号坐标耦合 — 一旦正文进入编辑态,行号会变,评论锚点必然错位。所以编辑模式必须暂时隐藏评论。
