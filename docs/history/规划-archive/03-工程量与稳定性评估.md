# 03 — 工程量与稳定性评估

> 用户明确目标: **稳定可用,要分发给很多普通用户**。本文档基于这个目标做诚实评估。

## 工程量(纯代码)

| 阶段 | 内容 | 一个有经验工程师 |
|---|---|---|
| Phase 0 | 独立 prototype 验证 CodeMirror + Tauri | 0.5-1 天 |
| Phase 1 | fork 仓库 + 装环境 + 跑通现状 | 1-3 天 |
| Phase 2 | 改 file-tabs + 写 CodeMirrorView 包装 | 2-4 天 |
| Phase 3 | Rust 写文件 command + 冲突处理 | 1-2 天 |
| Phase 4 | 打包 + 签名 + 自动更新搭建 | 3-5 天(首次) |
| Phase 5 | 测试 + 跨场景回归 | 2-3 天 |
| **MVP 合计** | 能给自己用的版本 | **10-18 天 ≈ 2-3 周** |
| 持续维护 | 跟 sst 上游 rebase + 修 bug | **每月 2-5 天** |

## 工程量(分发到用户的真实成本)

光会写代码不够,分发给普通用户还要:

| 项 | 成本 | 说明 |
|---|---|---|
| EV 代码签名证书 | ¥3000-8000/年 | 不签名 Windows SmartScreen 会拦截,99% 普通用户不会点"仍然运行" |
| 自动更新服务器 | 自己搭 + 维护 | 不搭用户卡死在某一版,无法跟随上游 bug 修复 |
| 安装包托管/CDN | ¥几百-几千/月 | 200MB+ 的 Tauri 包,大量用户下载流量不便宜 |
| 用户支持 | 持续投入 | 普通用户会问各种装机问题 |
| 法务 | — | sst/opencode 是 MIT 协议,fork 合规;但你的"OpenCode 增强版"不能用人家的名字和 logo,要换 brand |

## 稳定性风险评估(逐条)

按"分发给很多普通用户"的标准打分。

### 🔴 高风险 — 长期阻塞或重大成本

#### 1. `@pierre/diffs` 私有依赖

**问题**: opencode 文件渲染核心是 `@pierre/diffs`(Pierre 公司私有 npm 包),npm 公开页 403。

**影响**: fork 后 `bun install` 大概率拉不到这个包,或者只能用过期版本。

**应对**:
- 走 Plan B: 把 file.tsx 整个换成 CodeMirror,review tab 也跟着重写 → **工程量翻倍至 4-6 周**
- 或: 想办法搞到这个包的访问权(联系 Pierre / sst,基本不会卖给个人)

**对"稳定分发"的影响**: 🔴 致命。Phase 1 第一天就可能阻塞。

#### 2. 上游迭代速度极快

**事实**: 看本机更新器残留:`OpenCode-1.4.3 → 1.4.6 → 1.4.7 → 1.4.8 → 1.4.11 → 1.14.17 → 1.14.18 → 1.14.19 → 1.14.20`,版本跨度大、迭代频繁。

**影响**: fork 后每 2-4 周就要 rebase 一次,否则 conflict 越积越多。3-6 个月不维护,基本就 rebase 不动了,只能换新版本重做改动。

**对"稳定分发"的影响**: 🔴 长期负担。如果你不打算长期投入,fork 一年后就死了。

#### 3. 自动更新通道

**事实**: 官方 opencode 用 Tauri Updater 指向 sst 的服务器,频繁推更新。

**影响**: fork 的 exe 没有更新通道,用户停在你发布那刻;或者 Tauri 仍然指向官方 server,用户某次自动更新就被覆盖回官方版,你的改动全没了。

**应对**: 自己搭 update server(技术上 Tauri 支持自托管 JSON manifest),但要持续运维。

**对"稳定分发"的影响**: 🔴 不解决就是定时炸弹。

#### 4. 代码签名

**问题**: 不签名,Windows SmartScreen 会显示红色"未知发布者"警告,需要点"更多信息 → 仍要运行" — **99% 的普通用户到这里就放弃**。

**应对**: 买 EV 代码签名证书。

**对"稳定分发"的影响**: 🔴 不签名约等于不能分发。

### 🟡 中风险 — 可控但要专门处理

#### 5. opencode 跟付费账号绑定

**事实**: opencode 商业模式包含付费账号(看到 `dialog-select-model-unpaid.tsx`、enterprise 包、identity 包),用户登录走官方服务。

**影响**: fork 是否破坏登录链路?用户的 opencode 订阅在 fork 版能不能用?需要单独验证。

**对"稳定分发"的影响**: 🟡 取决于具体登录实现,可能要额外工作。

#### 6. 编辑期间 AI 同步改文件

**场景**: 用户在编辑器里改 `foo.md`,AI 同时用 Write 工具改了 `foo.md`,谁覆盖谁?

**应对**: 保存前比 mtime,不一致弹冲突对话框。但**普通用户大概率看不懂冲突**,容易丢内容。

**对"稳定分发"的影响**: 🟡 数据丢失风险,要做好 UI 提示和自动备份。

#### 7. 大文件 / 二进制误操作

**场景**: 用户点开 200MB 的 log 或 jpg,触发编辑模式,CodeMirror 加载卡死或显示乱码。

**应对**: 加文件大小、二进制检测,超过阈值禁用编辑按钮。

**对"稳定分发"的影响**: 🟡 必须做防呆。

#### 8. 行评论锚点错位

**问题**: 评论按行号锚定,编辑改了行后评论指向错的位置。

**应对**: 编辑态隐藏评论(MVP 方案);进阶: 用 anchor 跟踪算法(类似 Git blame)。

**对"稳定分发"的影响**: 🟡 MVP 隐藏即可,但有人用了行评论再去编辑,体验断裂。

### 🟢 低风险 — 例行处理

- Solid 组件挂载/卸载内存泄漏 — 标准 onCleanup 即可
- markdown 高亮颜色与原 Shiki 主题不一致 — 取主题 token 即可
- 多 tab 同时编辑 — 每个 tab 独立 state,天然支持

## 关键判断

### 假设你只想自己用 / 给少数(<10 个)开发者用

- 工程量: 2-3 周 MVP
- 稳定性: 自己装 Rust + 自己 build,问题自己 debug
- 推荐: ✅ 可以走 fork 路线

### 假设你要稳定分发给"很多普通用户"

直接给结论:

> ❌ **不推荐 fork opencode 走这条路**。

核心理由:
1. **`@pierre/diffs` 私有依赖大概率阻塞**(Phase 1 就死)
2. **签名 + 更新服务器 + CDN 是持续成本**,折成钱年成本 ≥ ¥1-3 万
3. **跟随上游的 rebase 工作量长期吃人**(每月数天)
4. **opencode 自身在快速迭代**,你今天 fork 改的功能,可能 2 个月后官方就加了原生版本,fork 工作白做
5. **普通用户遇到任何问题(登录/支付/AI 调用)都会找你**,你接不住 sst 的客服压力

## 推荐替代路径(按推荐度排序)

### 路径 A:写一个 opencode 插件做"外部编辑器跳转" ⭐ 强烈推荐

参考 `D:\project\getbot-plugins\getbot-opencode` 的架构。

**做法**: 在 `~/.config/opencode/plugins/` 放一个 JS 插件,注册斜杠命令 `/edit`,调起本机 `code <path>` / `notepad <path>`,改完 opencode 自身的 file watcher 会刷新。

**优点**:
- 不动 opencode 本体,**官方更新自动跟随**
- 不用签名、不用打包、不用 CDN
- 实施成本: **1-2 天**
- 分发: 一个 zip,用户解压跑安装脚本(getbot-opencode 已经有现成模板)
- 普通用户的"编辑"体验 ≈ "在 VS Code 里改",熟悉度高

**缺点**: 不是"文件查看器内编辑",是"跳出去编辑"。但功能等价。

### 路径 B:给 sst 提 issue / PR

**做法**: 在 https://github.com/sst/opencode/issues 提需求,描述"Text File Viewer 加编辑模式"。

**优点**: 如果合入,所有用户都受益,不用你维护
**缺点**: 周期不可控,可能不被接受

### 路径 C:写一个独立的"伴生编辑器" app

**做法**: 单独打包一个 Tauri 小程序,跟 opencode 共享 `~/.config/opencode/` 目录,自己实现编辑保存

**优点**: 完全自主,不绑死 opencode 上游
**缺点**: 普通用户要装两个 app,体验割裂

### 路径 D:fork opencode(本文档详细描述的)

**只在以下条件全部满足时考虑**:
- 你愿意把维护这个 fork 当一个长期项目(每月投入 ≥ 2-5 天)
- 能搞定 `@pierre/diffs` 访问权,或接受重写 file.tsx 的 4-6 周成本
- 能买代码签名 + 搭更新服务器 + 承担 CDN 成本
- 能改 brand(不能用 OpenCode 名字),做用户支持

## 一行结论

**给普通用户分发,选路径 A(插件 + 外部编辑器)。fork 路线只在你愿意养一个分支项目时考虑。**
