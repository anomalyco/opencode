# 改动 B — 新建文件 / 文件夹后文件树不自动刷新

## B Context

User 反馈:在工作区里新建文件 / 文件夹后,右侧 FileTree 不显示新条目,需要手动操作(切换目录 / 折叠再展开)才能刷新出来。

## B 现状链路(已经基本就位,差最后一公里)

完整 SSE → store 链路其实**已经搭好了**,只是 Windows 路径分隔符把链路最后一步打断:

1. **server 端 watcher**(`packages/opencode/src/file/watcher.ts`):用 `@parcel/watcher` 监听工作区,文件 add / change / unlink 都会通过 Bus 发 `file.watcher.updated` 事件(payload `{file, event}`)。✓ 已工作。
2. **SSE 通道**(`packages/opencode/src/server/routes/instance/event.ts` `/event` 端点)→ 客户端 SDK(`packages/app/src/context/global-sdk.tsx:24-96`)。✓ 已工作。
3. **客户端订阅**(`packages/app/src/context/file.tsx:203-217`):`sdk.event.listen` 收事件后调 `invalidateFromWatcher`,再走 `tree.listDir(dir, { force: true })` 强制重拉父目录。✓ 已 wire。
4. **`invalidateFromWatcher`**(`packages/app/src/context/file/watcher.ts`):
   - L27 `path = ops.normalize(rawPath)` 标准化路径
   - L49 `parent = path.split("/").slice(0, -1).join("/")` 算父目录
   - L50 `if (!ops.isDirLoaded(parent)) return`
   - L52 `ops.refreshDir(parent)`

## B 根因猜想(高置信)

**`path.normalize`(`packages/app/src/context/file/path.ts:104-131`)在 Windows 上有意保留 native 分隔符(L120 注释:"Slice from original path to preserve native separators")。** 结果:
- workspace = `D:\project\foo`
- watcher event 来 `D:\project\foo\subdir\new.txt`
- normalize → strip root → `subdir\new.txt`(**反斜杠**没换成 `/`)
- watcher.ts L49 `path.split("/")` → `["subdir\new.txt"]`(只有一段)
- L49 `slice(0, -1).join("/")` → `""`
- L50 `isDirLoaded("")` 是 true(根目录永远 loaded,见 `tree-store.ts:25`)
- L52 `refreshDir("")` → 只刷新根,**不刷新 `subdir`**
- 结果:user 在子目录新建的文件,看不到刷新

这正好解释 user 说的"**有时**显示不出来"—— 在工作区根目录新建的能出来(parent 计算成 `""` 恰好对),在任何子目录新建的就不行。

## B 改动清单

### B 步骤 1:加诊断,先确认假设(2 行,临时)

**文件:** `packages/app/src/context/file/watcher.ts`

在 L24 之后插一行:
```ts
console.debug("[fs.watcher]", { rawPath, kind, normalized: ops.normalize(rawPath) })
```

在 L52(`ops.refreshDir(parent)`)之前插一行:
```ts
console.debug("[fs.watcher] refresh", { parent, isLoaded: ops.isDirLoaded(parent) })
```

`tauri build --debug` 后跑一遍新建文件,在 DevTools console(F12)看输出,**确认 `normalized` 是不是 `subdir\new.txt`、`parent` 是不是 `""`**。

> 若日志确认猜想 → 走步骤 2 修。若日志显示别的现象(比如事件压根没到 / normalized 已是正斜杠 / parent 算对但 isDirLoaded false)→ 重新评估,**不要先行 commit 修复**。

### B 步骤 2:修 watcher.ts 的 parent 计算(确认后再做)

**文件:** `packages/app/src/context/file/watcher.ts`

最小侵入修法 —— 在 watcher 这一层把分隔符规范成 `/`,**不动共享的 `path.normalize`(避免 blast radius)**:

- L27 改:
  ```ts
  const path = ops.normalize(rawPath).replace(/\\/g, "/")
  ```
- 这样 `path` 一定是 `/` 分隔。L49 `path.split("/")` 就能正确分段,parent 计算正确。
- L36-46 的 "change" 分支(用 `path` 直接当 dir key 查 `ops.node`)也跟着受益,因为 `tree.node` map 的 key 是 SDK 返回的(JSON 标准 = `/`),修复后两侧都是 `/`,lookup 不再失配。

> **不修 `path.ts:104-131` 的 normalize。** 那里的"保留 native 分隔符"被多处消费,改它要全量回归(SDK 调用 / tab URL / 显示)。watcher 这一层做局部修正,代价 1 行,blast radius = 仅这一个事件路径。

### B 步骤 3:删掉步骤 1 的 console.debug,留干净代码

> **不要忘**:`console.debug` 不在 prod build 里 noop(Tauri release 也会执行),留着会污染用户 console。
