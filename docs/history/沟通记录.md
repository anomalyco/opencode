## 2026-04-24(MVP 后 · 再后)Phase 3 Save 安全护栏完工 → MVP v1.2

### 讨论起点

User 问"可以做安装版本吗还是继续优化"。查 SignTool 状态发现本机**没装**(Windows SDK 的 Signing Tools 组件默认不带,要额外装)。评估 installer 成本 vs 继续优化价值:

- Installer 即便打出也绕不过 SmartScreen(没 EV 证书);核心收益是"添加或删除程序"可见 + 快捷方式,是包装升级
- Phase 3 的 mtime 冲突 / dirty 拦截 / 防呆是**功能稳定性升级**,是朋友真实可能踩的地雷
- 推荐 Phase 3 先,installer 后(避免重打两次)

User 选 Phase 3。

### mtime 冲突的决策矩阵讨论

在写代码前,梳理了"查看器 × 记事本"的 10 种场景组合(见 `实施状态.md` Phase 3 小节的完整矩阵),得到三个结论:

1. **核心保护场景是 3C**:editing+dirty 时记事本保存 → Save 弹 confirm 覆盖/放弃
2. **场景 3B 物理无法检测**:记事本改了但未保存到盘,mtime 不变
3. **场景 3D 会 false-positive**:记事本改了又改回同内容保存,mtime 变但内容没变(后续 content hash 可优化)

### mtime 实现方案对比 A vs B

User 问"A 事后 confirm 够吗,还是 B 提前感知(订阅 watcher)"?分析:

- A 已守住数据不丢底线(覆盖/放弃二选一);代码已写
- B 需要订阅 opencode 的 SSE `file.watcher.updated`,但 `useFile` 未对外暴露 listener,要么侵入改 context 要么自订 sidecar 的 SSE endpoint,~100+ 行成本
- B 改善的是"提前决策"(知道冲突时立刻 cancel+reload 而不是 10 分钟后),但**只对"手动+AI 并发改同一文件"高频场景值**
- 频率未知 → 先 A 发朋友圈看反馈,再决定是否投 B

**User 选 A**。
