# sdk-falsy-error-fallback-fix — changelog

## 实施细节

### `createSdkForServer` fetch 边界 wrapper

```ts
// FORK-BEGIN: 兜底 SDK 的 falsy error fallback [feat: sdk-falsy-error-fallback-fix] 2026-05-12
const baseFetch = config.fetch ?? globalThis.fetch
const wrappedFetch = (async (input: Request, init?: RequestInit) => {
  try {
    return await baseFetch(input, init)
  } catch (e) {
    const isEmpty = e == null || (typeof e === "object" && Object.keys(e as object).length === 0)
    if (isEmpty) {
      const url = typeof input === "string" ? input : input.url
      console.error("[FETCH-FALSY-REJECTION]", { url, originalError: e })
      throw new Error(`fetch returned empty rejection: ${url}`)
    }
    throw e
  }
}) as typeof baseFetch
// FORK-END

return createOpencodeClient({
  ...config,
  fetch: wrappedFetch,  // ← 关键:把 wrapped fetch 传 SDK
  ...
})
```

**关键设计**:
- 在 **fetch 边界**(用户 promise rejection 边界)拦截,**SDK 看到的 error 永远 truthy** → SDK 的 `|| {}` fallback 永远不触发 → 永远不抛空对象 → SolidJS castError 永远拿到有 message 的 Error
- 守卫自身用 try/catch 包,**guard 自己挂时 fallback 到 throw 原 e**(原 falsy 也比双重报错好)
- console.error 留 `[FETCH-FALSY-REJECTION] { url, originalError }` 证据链,下次撞同问题第一时间 console 看到具体 endpoint

### 为什么选 fetch wrapper 而不是 SDK interceptor

**初版尝试 SDK error interceptor 失败**:
```ts
const client = createOpencodeClient({...})
client.interceptors.error.use(...)  // ← TS2339: Property 'interceptors' does not exist on type 'OpencodeClient'
```

`createOpencodeClient` 返回的是 `OpencodeClient` 类(`packages/sdk/js/src/v2/client.ts:87` `return new OpencodeClient({ client })`),wrapper class 把 `client.interceptors` 隐藏不暴露。

**改用 fetch 边界**:`config.fetch` 是 createOpencodeClient 接受的标准参数,SDK 内部用 `opts.fetch ?? config.fetch ?? globalThis.fetch`。在 createSdkForServer 包一层 wrappedFetch 传 SDK = 跟 SDK 约定的扩展点,**比 interceptor 更上游**(还没进 SDK error handling 路径就拦截了)。

### 为什么不直接改 SDK generated 文件

1. **`packages/sdk/` 在 `.husky/pre-commit` 黑名单** — 需 R4 override + 本季配额已超 3 笔(5.11.4 changelog 提过),不必要打 R4 第 6 笔
2. **文件 auto-generated** — `// This file is auto-generated by @hey-api/openapi-ts`,下次 `bun run gen` regen 时所有手工 patch 全部覆盖,R2 FORK marker 也活不过

→ fork-only consumer 层落实施,**永久生效不被 regen 干掉**。
