> 版本: `v0.3.0` | 里程碑: Milestone #3
> 制定日期: `2026-05-12` | 实际发布: `2026-05-12`
> 状态: ✅ **已发布** (Git-level only, 无 npm) | P9: Release subagent 完成
> 评审: P2 通过(6 Go/1 NoGo) | P4 通过(5 Go/2 NoGo) | P5 通过(5 Go/2 NoGo, R2)

## 一、版本目标

v0.1.0 完成了字符串级品牌迁移 (opencode→octopus)，v0.2.0 做深度清理。但项目**视觉上没有任何章鱼形象**——用户看到的是几何方块字 (OPCODE 风格) 和抽象 O-ring。v0.3.0 将用户提供的章鱼 PNG 矢量化为品牌主源，系统性地替换 12 个触点的品牌资产，让 Octopus **看起来真正像一只 octopus**。

## 六、风险评估

### 高风险

| 风险 | 影响 | 概率 | 缓解 |
|------|------|:----:|------|
| **SVG 矢量化质量不足** | 章鱼在 16×16 下辨识度差 | 中 | Issue 1 制作简化剪影版 + 小尺寸测试；小尺寸使用圆角方形剪影而非完整细节版；如果 16×16 完全不可行，favicon 使用简化的章鱼头部+2触手标志 |
| **章鱼配色与现有 UI 不协调** | 主题 token 与现有 UI 组件冲突 | 低 | Issue 7 先定色板、WCAG AA 对比度校验通过后才应用到 theme.css；Issue 2 使用 token 前再次视觉验证 |
| **v0.2.0 未及时发布** | v0.3.0 依赖的代码基 (clean codebase) 不可用 | 低 | 如果 v0.2.0 延迟，v0.3.0 可先在 `dev` 分支开发，依赖时合入 v0.2.0 |
| **桌面图标批量生成脚本故障** | 270 个图标尺寸/格式/色差 | 低 | #4 由 `@platform` 提供已验证的生成脚本；先生成 1 个通道(prod)验证后再并行生成 dev/beta；脚本失败时有回滚脚本 |
| **品牌资产授权合规** | 章鱼 PNG 的版权/授权不明 | 中 | 发布前需确认 octopus.png 是否有使用限制、是否需要标注出处或取得授权 |
| **跨平台图标格式差异** | macOS 圆角裁剪、Windows 托盘单色、UWP 磁贴兼容 | 中 | 每个平台单独验证，`@platform` 需确保生成脚本符合各平台规范；macOS 使用 .icns 含 rounded-rect mask |
| **邮件客户端 SVG 兼容性** | 邮件中章鱼 SVG 可能不渲染 | 中 | 邮件使用 `<img src="logo.png">` (PNG 回退)，不依赖 SVG；确认 `logo.png` 支持 Outlook/Gmail/Apple Mail |
| **静态资源缓存失效** | 浏览器/CDN 缓存旧 O-ring logo | 低 | 所有 logo 文件使用新路径或版本化哈希名（webpack/vite 自动处理）；在 `dev` 分支上测试后发布 |
| **新旧视觉过渡期不协调** | 部分页面仍显示 O-ring，部分显示章鱼 | 低 | Wave 2 在 #1+#7 完成后一次性替换，减少中间态；发布后全仓 `rg` 验证无旧 O-ring 引用 |
| **深色/浅色模式适配** | 章鱼在深色/浅色背景下视觉效果不一致 | 低 | Issue 1 产出 dark/light 两套 SVG，确保色对比度均达标；Issue 7 的 token 同时更新 light/dark 双主题 |
| **视觉回归测试缺口** | 替换后 logo 渲染样式偏离设计意图 | 中 | Issue 2 完成后由 `@qa` 进行 Storybook 视觉回归 + 浏览器截图对比；Wave 3 桌面图标在 3 个 OS 上手动验证 |
