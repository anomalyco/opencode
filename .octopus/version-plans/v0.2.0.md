# 版本计划 v0.2.0 — Post-Migration 深度清理

> 版本: `v0.2.0` | 里程碑: Milestone #2
> 制定日期: `2026-05-12` | 计划发布: `2026-05-13`
> 状态: P7 质量门通过 | 评审: P2+P4 architect 裁定 | P7: Conditional Approve (已解决)

## 一、版本目标

v0.1.0 品牌迁移后遗留 13,039 处 opencode 引用。v0.2.0 做深度清理 + 冗余精简，让 Octopus 完全脱离 opencode 品牌残留，真正看起来像 Octopus。

## 三、前置条件（LLM Panel 评审后的新增）

### 3.0 统一替换规则 — Issue #17（所有 Issue 的前置条件）

> **LLM Panel (P2 评审) 指出**：仅靠"文件集零重叠"不足以保证安全。同一 opencode 字符串在不同 Issue 中交叉出现（代码/文档/测试/i18n），需要先冻结统一的替换规则。

**Issue #17** 产出 `.octopus/config-preview/v0.2.0-replacement-rules.md`，包含：
- 完整的替换规则映射表（原名→新名，匹配模式）
- 全面的保留清单（LLM model ID、第三方包、外部 URL、历史记录、GitHub Secrets 等）
- 符号级交叉引用检测表（哪些符号同时出现在哪些 Issue 中）
- 执行前检查清单

**所有 Issue 在开始执行前必须引用此规则文件。**

### 4.2 符号级交叉依赖分析（P2 评审补充）

文件集无重叠 ≠ 字符串无交叉。以下 `opencode` 子串同时出现在多个 Issue 的修改范围内：

| 字符串 | 涉及的 Issue | 风险说明 | 缓解 |
|--------|-------------|---------|------|
| `opencode` (普通文本) | #12, #13, #14, #15 | 各 Issue 可能用不同规则替换同一语义的 "opencode" | 统一规则文件 #17 确保替换一致性 |
| `OpenCode` (品牌名) | #12, #13, #14, #15 | 同上 | 同上 |
| `opencodeTheme` | #11, #12 | #11 改 CSS/主题，#12 改 JS/TS 中的引用 | 统一由 #11 覆盖符号引用 |
| `.opencode/` | #12, #13, #14 | 配置路径同时出现在代码和文档中 | 统一规则表保证路径替换一致 |
| `OPENCODE_*` | #12, #13, #14 | 环境变量同时出现在代码和文档中 | 统一规则表保证替换一致 |

**缓解措施**：
1. **#17 统一规则**确保所有 Issue 使用相同替换映射
2. 执行完毕后**全仓 `rg 'opencode'` 统一验证**
3. 对于 `opencodeTheme` 等跨 Issue 符号，指定 #11 为"责任 Issue"

## 七、风险评估

### 高风险

| 风险 | 影响 | 概率 | 缓解 |
|------|------|:----:|------|
| **保留引用误杀** | 外部模型 ID (`opencode/claude-opus-4-7`) 被错误替换 | 高 | Issue #17 统一保留清单 + 替换规则 + `rg` 全仓验证 + 人工抽查 |
| **符号级替换不一致** | 同一 opencode 字符串在不同 Issue 中以不同规则替换 | 中 | #17 统一规则文件确保一致性 + 执行完毕后全仓 `rg` 统一验证 |
| **#14 批量替换遗漏** | 578 篇文档中部分未处理 | 中 | #13 先确定规则，逐语言随机抽查 3 篇关键文档 |
| **#11 设计稿阻塞** | 品牌资产替换无法完成 | 中 | 先用临时占位标识，不影响其他 Issue 并行 |

`.octopus/config-preview/v0.2.0-replacement-rules.md`

- LLM Model ID（外部模型路由）
