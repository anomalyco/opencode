## Issue 1: Master SVG & Identity Suite [XS]

**核心需求**: 将 `octopus.png` (1024×1024 RGBA) 矢量化为高质量 SVG 主源，并衍生出完整的 identity 变体集。

**技术要点**:
- SVG 矢量化可使用视觉 LLM (Claude/GPT-4V) + 手工调优 path
- 必须维护 512×512 viewBox，确保缩放比例 1:1
- 所有变体需统一命名约定：`octopus-{variant}-{theme}.svg`
  - `octopus-mark-dark.svg` (深色背景)
  - `octopus-mark-light.svg` (浅色背景)
  - `octopus-mark-square.svg` (1:1 方形裁剪，用于 app icon)
  - `octopus-mono.svg` (单色，用于 CLI/水印)
  - `octopus-wordmark.svg` (章鱼 + "Octopus" 文字组合)

**架构决策**: 
- `packages/identity/` 作为主源目录，下游 Issue 从 identity 消费
- `logo.tsx` 保持内联 SVG path 架构（不改为外部引用），从 identity SVG 提取 path

**依存关系**:
| 下游 Issue | 消费资产 | 交付契约 |
|:----------:|----------|----------|
| #2 | `octopus-mark-*.svg`, `octopus-wordmark.svg` | SVG path, viewBox=512×512 |
| #3 | `octopus-mark-*.svg`, `octopus-wordmark-*.svg` | identity 变体文件 |
| #4 | `octopus-mark-square.svg` | 1:1 方形 mark |
| #5 | `octopus-mark-*.svg`, `octopus-wordmark.svg` | 用于社交卡片合成 |
| #7 | `octopus.png` 或 主 SVG | 从 artwork 取色 |

**文件影响**: ~10 文件 (`packages/identity/`)

## Issue 4: Desktop App Icons Regeneration [L]

> 分析: `@platform` 已完成 — 当前为手工流程，需写自动化脚本

**核心需求**: 基于章鱼 square mark 重新生成 prod/dev/beta 三通道的全部桌面图标。

### `@platform` 分析结论

**当前管线**: 完全手工。`scripts/copy-icons.ts` 仅做 `cp -R` 复制，无 SVG→图标渲染流程。图标由外部工具预生成后手工放入 `packages/desktop/icons/{channel}/`。

**准确的资产统计**:
- 每个通道 53 文件（不是之前估算的 ~90）
- 三通道合计 **~159 文件**（不是 ~270）
- 当前位于 L 级低端（159 < 200）

**推荐工具链**:
| 工具 | 用途 |
|------|------|
| **sharp** (npm) | 所有 PNG 尺寸缩放 |
| **png2icons** (npm) | 生成 macOS `.icns`（含 Big Sur 圆角） |
| **icon-gen** (npm) | 生成 Windows `.ico`（多分辨率） |
| Bun TypeScript 脚本 | 管线编排 (`packages/desktop/scripts/generate-icons.ts`) |

**文件清单核实**:
| 平台 | 文件 | 说明 |
|------|------|------|
| macOS | `icon.icns`, `icon.png`, `dock.png` | .icns 含多尺寸, dock 256×256 |
| Windows | `icon.ico` | 多分辨率 16×16~256×256 |
| Windows UWP | Square logo 9 尺寸 + StoreLogo | 30×30 ~ 310×310 |
| iOS | AppIcon 全套 | 20×20 @1x/2x/3x ~ 1024×1024 |
| Android | mipmap 全套 | mdpi ~ xxxhdpi |
| Android XML | `ic_launcher.xml` 等 | 保持现有 XML 不动 |

### 生成策略

1. `@feature-dev` 产出 **3 个 SVG 种子文件**：
   - `octopus-mark-square.svg` — 全细节版 (512×512, 1:1)
   - `octopus-mark-medium.svg` — 中等细节 (32×32+)
   - `octopus-mark-silhouette.svg` — 简化剪影 (16×16, 20×20, Windows 托盘, macOS menu bar)
2. `@platform` 编写 `packages/desktop/scripts/generate-icons.ts`：
   - 输入: `OCTOPUS_CHANNEL` env var + seed SVGs
   - 过程: sharp 缩放 → png2icons 生成 .icns → icon-gen 生成 .ico → fs 写入 channel dir
   - 通道差异: prod(无角标) / dev(绿色 DEV 标记) / beta(黄色 BETA 标记)
3. 先验证 prod 通道 → 确认后并行 dev/beta
4. 更新 `icons/README.md`，废弃旧手工流程文档

**文件影响**: ~159 文件 (3 通道 × 53 文件)

### P4 评审后补充

**输出文件清单 (产物矩阵)**:
| 平台 | 文件 | 尺寸 |
|------|------|------|
| macOS | `icon.icns` | 内置 16×16 ~ 512×512, Big Sur 圆角内边距(80% safe area) |
| macOS | `icon.png` | 512×512 |
| macOS | `dock.png` | 256×256 |
| Windows | `icon.ico` | 内置 16×16 + 32×32 + 48×48 + 256×256 |
| Windows UWP | `Square{30,44,71,89,107,142,150,284,310}x{...}Logo.png` | 各指定尺寸 |
| Windows UWP | `StoreLogo.png` | 50×50 |
| Windows UWP | `32x32.png`, `64x64.png`, `128x128.png`, `128x128@2x.png` | 对应尺寸 |
| iOS | `AppIcon-{size}@2x/3x.png` | 20×20 ~ 1024×1024 |
| Android | `mipmap-{density}/ic_launcher.png` | 48~192px |
| Android | `mipmap-{density}/ic_launcher_foreground.png` | 前景分离 (Adaptive icon) |
| Android | `mipmap-{density}/ic_launcher_round.png` | 圆形版 |
| Linux | 桌面入口图标 | 复用 macOS `icon.png` 对应尺寸 (无新增文件) |

**角标设计规则**:
| 通道 | 角标方式 | 16×16 策略 |
|:----:|----------|:-----------:|
| prod | 无角标 | 标准简化剪影 |
| dev | 右下角绿色 "DEV" 标记（2×4px 像素文字） | 16×16 豁免角标（太小不可读），仅 ≥32×32 显示 |
| beta | 右下角黄色 "BETA" 标记（2×4px） | 同 DEV，16×16 豁免 |

**脚本安全设计**:
- 原子写入: 先生成到临时目录 `icons/.tmp-{channel}/` → 全部成功后 `mv` 覆盖目标目录
- Dry-run 模式: `OCTOPUS_DRY_RUN=1` 仅输出待生成文件清单，不实际写入
- 回滚: 如果 `mv` 前脚本失败，目标目录保持不变；生成日志写入 `icons/.generate-log`
- 确定性输出: 脚本输出文件 hash 清单，生成后与预设 hash 对比

**macOS Big Sur 合规**:
- `.icns` 使用 png2icons `bigSur: true` 选项（自动添加圆角遮罩和内边距）
- 如果 png2icons 不符合 Apple HIG 80% safe area 规范，额外用 `sips` 后处理

**CI 集成**:
- 脚本纳入 CI 预构建步骤：v0.3.0 部署前运行一次，产出提交到版本库
- 后续无需每次 CI 运行都生成（图标是静态资产）

## Issue 6: CLI ASCII Octopus [XS]

**核心需求**: 重写 TUI 启动屏 ASCII art，使其不再拼写 "OPCODE"。

**当前状态** (`packages/octopus/src/cli/logo.ts`):
```typescript
export const logo = {
  left:  ["█▀▀█ █▀▀█ █▀▀█ █▀▀▄", "█__█ █__█ █^^^ █__█", "▀▀▀▀ █▀▀▀ ▀▀▀▀ ▀~~▀"],
  right: ["█▀▀▀ █▀▀█ █▀▀█ █▀▀█", "█___ █__█ █__█ █^^^", "▀▀▀▀ ▀▀▀▀ ▀▀▀▀ ▀▀▀▀"],
}
```
拼写 "OPCODE" (左侧 OPCO + 右侧 DEGO)。

**选项 A**: 拼 "OCTOPUS" — 保留现有块字符风格，重新排布为 7 个字母
**选项 B**: ASCII 章鱼图案 — 用字符画一个章鱼 (4 行 × 若干列)

| 维度 | 选项 A | 选项 B |
|------|--------|--------|
| 工作量 | 小 (调整字符排列) | 大 (重新设计图案) |
| 视觉冲击 | 文字可读 | 不识字但有趣 |
| 对现有交互影响 | 保持 4 行布局，涟漪动画兼容 | 布局可能变化，需调整 TUI 组件 |

**推荐**: 选项 A (拼 "OCTOPUS") 作为基础 + 如果时间允许可加单个章鱼字符 🐙 点缀

**注意**: Unicode 半块字符 (▀, ▄) + 阴影标记 (`_`, `^`, `~`, `,`) 的渲染机制需保持兼容。

**文件影响**: ~2 文件

## Issue 7: CSS Brand Palette Refresh [XS]

**核心需求**: 从章鱼 artwork 提取配色，更新 CSS 品牌色 token。

**提取目标**: 
- 从 `octopus.png` 通过视觉 LLM 分析主色调区域
- 获取: 章鱼身体主色、触手渐变色、吸盘点缀色、背景环境色

**更新范围**:
| Token 分组 | 当前值 (Light) | 当前值 (Dark) | 预期调整 |
|------------|---------------|---------------|----------|
| `--surface-brand-base` | `#dcde8d` (黄绿) | `#fab283` (暖橙) | 适配章鱼蓝紫 |
| `--icon-strong-base` | `#211E1E` | 浅色 | 可能保持不变 (主 icon 色) |
| `--icon-base` | `#656363` | 灰色 | 可能微调 |
| `--icon-weak-base` | `#CFCECD` | 灰色 | 可能微调 |

> 注意: `--icon-*-base` 影响 logo 组件的三层颜色层，改动需谨慎

**约束**: 
- Light/Dark 模式双主题必须同时更新
- WCAG AA 对比度 (4.5:1 文本, 3:1 大图标) 必须通过
- 不影响现有 UI 组件的可读性

**文件影响**: ~3 文件
