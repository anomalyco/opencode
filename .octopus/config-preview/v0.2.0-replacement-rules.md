## 一、替换规则

| `sst/opencode` | `fourbroad/octopus` | SST 部署 | infra 配置 |

### 1.2 替换原则

1. **精确匹配优先**：使用 `\bopencode\b` 词边界匹配，避免替换作为子串的引用
2. **逐文件审查**：JSON/YAML 配置文件中的 key 需人工判断是否属于品牌名
3. **i18n key 同步**：key 名中的 `opencode_` 前缀与翻译值中的 "OpenCode" 同步修改
4. **版本号不修改**：`opencode` 出现在版本号/版本名中（如 `v0.1.0-opencode`）保留或单独评估
5. **lockfile 保留**：`bun.lock` 中的 `opencode` 是 upstream 依赖锁，不修改

**原因**: Persistent user-data identifiers — modifying breaks existing desktop installations.

### 2.10 运行时契约型标识符（P3 domain agent 补充）

以下标识符属于**运行时契约**，修改需极端谨慎。所有修改必须在客户端和服务端同步完成，否则破坏运行时行为。

| 标识符类别 | 位置 | 数量 | 保留/变更 | 说明 |
|-----------|------|:---:|:--------:|------|
| `@opencode/...` Effect Context tags | `packages/octopus/` 各处 | ~93 | **变，但需整批原子替换** | DI 容器键，任意漏改导致运行时服务查找失败 |
| `x-opencode-*` HTTP headers | `packages/octopus/src/server/` + `packages/sdk/js/` + `packages/app/` | ~40 | **变，但需客户端/服务端同步** | 协议级契约，header 名 必须 3 端一致 |

| `opencode.db` 数据库文件名 | `packages/octopus/src/` | ~4 | **需提供迁移路径** | 用户数据持久化文件名 |

- 属于"变"的：必须在单个 commit/PR 中整批修改，不做渐进式

## 三、大小写敏感替换矩阵

> 此补充章节回应 LLM Panel (Claude Opus) 的 feedback。

`opencode` 及其变体在项目中有 4 种大小写形态，替换规则不同：

| 形态 | 匹配模式 | 替换规则 | 示例场景 |
|------|---------|---------|---------|
| `opencode` (全小写) | `\bopencode\b` + 非字母后缀 | → `octopus` | CLI 命令、变量名、路径名 |
| `OpenCode` (PascalCase) | `\bOpenCode\b` | → `Octopus` | 品牌名、文档标题、UI 文本 |
| `OPENCODE` (全大写) | `\bOPENCODE\b` | → `OCTOPUS` | 环境变量前缀（注意保留 `_` 后缀部分） |
| `Opencode` (首字母大写) | `\bOpencode\b` | → `Octopus` | 标题、UI 标签 |

**边界正则说明**：
- 使用 `\b` 词边界避免替换子串（如不匹配 `opencode-ai` 中的子串）
- 所有替换前应执行 dry-run：`rg -i '\bopencode\b'` 列出全部候选项

### Git 历史不可篡改声明

以下 Git 历史相关内容中的 opencode 引用**保留不修改**：
- Git commit message 中的 opencode（历史提交记录不可篡改）
- Git tag 名中的 opencode（如 `v0.1.0-opencode`）
- Git author/committer email 中的 opencode（如 `bot@opencode.ai`）
- CHANGELOG.md 中已发布版本的 opencode 引用

## 六、运行时契约执行协议

> 本节回应 P4 LLM Panel 关于"技术可行性不足"的关切。
> 三个运行时契约均有机器可定位的替换模式，v0.2.0 为预发布清理版，内部协议 breaking 可接受。

### 6.1 DI 标签原子替换协议（对应 Issue #12c）

适用于 `@opencode/...` Effect Context tags。单包内原子替换，无跨包同步。

```
1. rg '"@opencode/' packages/octopus/src packages/core/src --count
   → 确认 ~74 处（排除测试 fixture 中的 @opencode/acme 等）
2. 区分 Effect 标签 vs 测试 fixture:
   - Effect 标签: @opencode/Config, @opencode/Session 等
   - 保留不变: @opencode/acme (npm.test.ts 中的 mock)
3. sed -i 's/"@opencode\//"@octopus\//g' packages/octopus/src/core/*.ts
   → 原子替换（一次性提交，不可拆分）
4. rg '"@opencode/' packages/ → 结果为零（测试 fixture 除外）
5. bun typecheck → 编译通过
6. bun test packages/octopus/test/effect/ → DI 全服务解析通过
```

### 6.2 HTTP header 同步协议（对应 Issue #12d）

适用于 `x-opencode-*` 自定义 HTTP 头。必须 server → sdk → app 三端顺序替换，每端完成后验证。

```
=== Phase 1: Server 端（权威源） ===
1. 修改 packages/octopus/src/server/ 中所有 header 常量定义:
   x-opencode-directory → x-octopus-directory
   x-opencode-workspace → x-octopus-workspace
   x-opencode-ticket → x-octopus-ticket
   x-opencode-sync → x-octopus-sync
   x-opencode-project → x-octopus-project
   x-opencode-session → x-octopus-session
   x-opencode-request → x-octopus-request
   x-opencode-client → x-octopus-client
2. rg 'x-opencode-' packages/octopus/src/server → 结果为零
3. bun test packages/octopus/test/server/ → 全通过

=== Phase 2: SDK 端 ===
4. 同步修改 packages/sdk/js/src/client.ts + v2/client.ts 中的 header 引用
5. rg 'x-opencode-' packages/sdk/js → 结果为零
6. bun typecheck in packages/sdk/ → 通过

=== Phase 3: App 端 ===
7. 同步修改 packages/app/ 中的 header 引用
8. rg 'x-opencode-' packages/app → 结果为零
9. bun typecheck in packages/app/ → 通过

=== Phase 4: 集成验证 ===
10. 跨端一致性检查:
    rg 'x-octopus-(directory|workspace|ticket|sync|project|session|request|client)'
    → 确认 server/sdk/app 三端使用的 header 名完全一致
11. bun test packages/octopus/test/server/httpapi-* → 全通过
```

### 6.3 Deep link 迁移协议（对应 Issue #12d）

适用于 `opencode://` 协议 + `virtual:opencode-server` Vite 模块。提供双协议过渡窗口策略。

```
=== Phase 1: Desktop 端 ===
1. packages/desktop/src/main/index.ts:
   app.setAsDefaultProtocolClient("opencode")
   → app.setAsDefaultProtocolClient("octopus")
   同时保留 opencode:// 作为 fallback 接收（argv 过滤）
2. packages/desktop/src/main/index.ts:
   argv.filter(a => a.startsWith("opencode://"))
   → argv.filter(a => a.startsWith("octopus://") || a.startsWith("opencode://"))
3. 注册 octopus:// 为 OS 默认协议处理器
4. 手动验证: 桌面端运行 octopus://new-session?dir=/tmp/test

=== Phase 2: App 端 ===
5. packages/app/src/deep-links.ts:
   startsWith("opencode://") → startsWith("octopus://") || startsWith("opencode://")
6. deepLinkEvent "opencode:deep-link" → "octopus:deep-link"
7. 测试用例同步更新

=== Phase 3: Vite Virtual Module ===
8. packages/desktop/electron.vite.config.ts:
   virtual:opencode-server → virtual:octopus-server
9. packages/desktop/src/main/env.d.ts:
   declare module "virtual:opencode-server" → declare module "virtual:octopus-server"
10. 同步更新所有 import 路径
11. rg 'virtual:opencode-server' → 结果为零
```
