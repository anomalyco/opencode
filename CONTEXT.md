# Domain Glossary — unleashlive/opencode

## Core Terms

**Collab Session**
A multi-user coding context where 2 or more GitHub org members share a common LLM interaction thread, a Prompt Queue, and one or more assigned Session Repos. Persists on the server until a Driver explicitly closes and deletes it. Extends opencode's native Session primitive.

**Session** *(opencode native)*
A single LLM interaction thread — a sequence of messages, tool calls, and code changes. In solo mode, one user owns one Session. A Collab Session is built on top of this primitive and adds multi-user access, roles, and a Prompt Queue.

## Roles

**Driver**
A Collab Session participant who can: (a) compose and submit prompts directly to the LLM, and (b) approve or reject Prompt Suggestions from Contributors. Any Driver can approve any Suggestion; first approval wins. Drivers can also change any participant's role at any time.

**Contributor**
A Collab Session participant who can submit Prompt Suggestions into the pending queue but cannot execute them directly. Suggestions require Driver approval before reaching the LLM. Contributors can also vote in Vote Pool mode.

**Viewer**
A Collab Session participant with read-only access — can see all prompts, LLM responses, and code changes in real time but cannot interact with the session.

## Prompt Flow

**Prompt Suggestion**
A prompt submitted by a Contributor (or a Driver in Vote Pool mode) that sits in a pending queue until a Driver approves it (promoting it to the Prompt Queue) or rejects it.

**Prompt Queue**
The ordered list of approved prompts awaiting LLM execution within a Collab Session. Operates in one of two modes: **FIFO** or **Vote Pool**. Only one prompt executes at a time (serialized via semaphore).

**FIFO mode**
Prompt Queue mode where prompts execute in server-arrival order. First approved prompt fires first. Default mode.

**Vote Pool**
Prompt Queue mode where participants submit prompts into a shared pool and vote on which should execute next. The prompt with the highest vote score wins; ties broken by earliest submission timestamp. A Driver can trigger resolution manually or after a configurable timeout. All non-Viewer participants (Drivers + Contributors) can cast one vote per prompt.

## Session Configuration

**Session Visibility Mode**
A Driver-configured setting applied at Collab Session creation. Controls what other participants see while someone is composing a prompt:
- `submitted` — prompts visible only after submission (default)
- `typing` — others see a "{name} is typing..." indicator
- `live` — others see the current draft text in real time

**Queue Mode**
A Driver-configured setting (`fifo` | `vote`) that determines how the Prompt Queue resolves concurrent submissions.

## Infrastructure

**Session Repos**
The set of GitHub org repositories a Driver selects when creating a Collab Session. These repos are cloned on the server into `/var/opencode/workspaces/{sessionId}/` and are the only repos the LLM can read/write during the session. Participants never need local copies.

**Invite Link**
A URL generated by a Driver that grants entry to a Collab Session. Carries the invitee's pre-assigned role (Driver / Contributor / Viewer). Valid only after GitHub OAuth authentication passes org membership verification. Role can be adjusted by any Driver after the participant joins.

**Org Membership Check**
Server-side verification (via GitHub API) that an authenticating GitHub user belongs to the same GitHub organisation as the session owner. Performed at Invite Link redemption.
