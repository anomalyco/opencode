# Покупательский агент на OpenCode

Harness использует сессии и вызовы инструментов OpenCode. Выберите модель с доступом через OpenCode и поддержкой tool calling. Сборка монорепозитория для запуска профиля не требуется. Профиль проверен с OpenCode `1.18.34`.

| Инструмент | Что возвращает |
| --- | --- |
| `wb_product_link` | Ссылку на карточку Wildberries по переданному артикулу |
| `wb_compare_unit_prices` | Переданные предложения в порядке возрастания цены за единицу |

Инструменты работают локально с данными из запроса. Для поиска актуальных цен, остатков или сроков доставки потребуется отдельный источник данных. Интеграции с покупательским ИИ-ассистентом Wildberries пока нет.

## CLI

Из корня репозитория выполните команды, подставив свой идентификатор модели в формате `provider/model`.

```sh
cd integrations/wb
./opencode-wb run --model '<provider/model>' \
  'Дай ссылку на артикул 123456. Что дешевле за штуку: 2 за 300 ₽ или 4 за 400 ₽?'
```

Флаг `--format json` выводит события OpenCode, включая вызовы инструментов. Флаг `--session <id>` продолжает существующий диалог.

## HTTP

Задайте `OPENCODE_SERVER_PASSWORD` в окружении и запустите `./opencode-wb serve` из этой директории. Сервер слушает `127.0.0.1:4096`. Порт задаётся через `WB_HARNESS_PORT`. HTTP API OpenCode предназначен для доверенного локального клиента.

Создайте сессию через `POST /session` с телом `{}`. Используйте Basic Auth с именем `opencode` по умолчанию и заданным паролем. Затем отправьте `POST /session/{id}/message` с теми же данными авторизации. Идентификатор `id` из ответа на создание сессии можно повторно использовать для следующего сообщения.

```json
{
  "agent": "wb-shopping",
  "model": { "providerID": "<provider>", "modelID": "<model>" },
  "parts": [
    { "type": "text", "text": "Дай ссылку на товар с артикулом 123456" }
  ]
}
```

Ответ содержит итоговые части сообщения в массиве `parts`. Историю вызовов инструментов можно получить через `GET /session/{id}/message`. Для потоковых событий клиент может открыть `GET /event` и отправлять сообщения через `POST /session/{id}/prompt_async`.

## Добавление инструментов

Добавьте модуль в `.opencode/tools/` и разрешите его имя в `agent.wb-shopping.permission` в `.opencode/opencode.json`. Агент получает только инструменты из этого списка. Пример использует [инструменты](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/web/src/content/docs/custom-tools.mdx) и [HTTP API](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/web/src/content/docs/server.mdx) OpenCode.

## Проверка

`bun test ./smoke.test.ts` из этой директории. Тест поднимает настоящий сервер OpenCode и локальный тестовый провайдер. Он проверяет авторизацию, список доступных модели инструментов и прохождение обоих результатов через сессию.
